WebSocket Event Vocabulary

The contract between the engine and the browser is a stream of typed events over /ws/chat. The frontend's handlePipelineMessage reduces them into PipelineRunState. All events flow through one generic backend forward — new types are additive, and every branch keys on the generic type (never a workflow name).

Server → Client — filter by group

EventGroupMeaning
📼 Durable replay & heartbeats

Events are stamped with seq + event_id and persisted to run_events. A reconnecting client replays the tail from its last seen sequence. pipeline_heartbeat and pong are filtered out client-side. The pipeline_reconnected ack carries live: true|false so the client knows whether to expect a live stream or a terminal status.
