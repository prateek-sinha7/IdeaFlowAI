Infrastructure & Deployment

Flowin deploys as a single-EC2 stack on AWS (branded velocityai in infra): the backend + frontend run as Docker Compose containers pulled from ECR, while Postgres and nginx run natively on the host. Everything is Terraform-managed in a layered reference format, applied by per-environment CodeBuild runners.

Runtime topology (one EC2 instance)

🌐 Internet → nginx (host, native)
TLS terminator. Certs at /etc/letsencrypt/live/<fqdn>, renewed by certbot outside the app rebuild cycle. Proxies to the two loopback-bound containers.
▼
🐳 frontend container
Next.js standalone, 127.0.0.1:3000, 1G limit. NEXT_PUBLIC_* baked at build. Waits for backend health.
🐳 backend container
FastAPI/uvicorn, 127.0.0.1:8000, 8G limit. Volumes: /app/skills + /app/runs. 30s stop-grace to drain WS. Chromium + node baked in.
▼  host.docker.internal:5432
🐘 PostgreSQL (host, native)
On a separate encrypted EBS volume at /var/lib/postgresql (what EBS-snapshot backups capture). Bound to 127.0.0.1:5432.
Why Postgres & nginx aren't containerized

Postgres stays on the host so its data dir lives on the encrypted EBS volume the backup/DR story depends on (no extra fs/UID/fsync layer). nginx stays native because it consumes Let's Encrypt certs that renew on a different cadence than app-image rebuilds. nginx + Postgres are infrastructure; the app is the deployable.

How a deploy reaches the box

Terraform layers (infra/terraform/)

Apply order: bootstrap → shared → foundation(<env>) → app(<env>). Runs in a shared AWS Organizations account, so an account_guard aborts on the wrong account/region and account-wide resources are forbidden.

LayerStateContains
bootstraplocal, onceS3 state bucket + DynamoDB lock + KMS + account guard + CI/CD runners.
sharedremote, onceECR repos (velocityai/backend, velocityai/frontend) — promoted by tag.
foundationper-envKMS CMK, VPC + endpoints, EC2 instance-role IAM, SSM Parameter Store secrets, S3 backup bucket + AWS Backup vault.
appper-envEC2 + data EBS + EIP, DNS, the compose + deploy.env S3 objects (driven by image_tag), CloudWatch monitoring, Resource Groups.

Modules: account_guard, backups, compute, dns, ecr, iam, kms, monitoring, network, resourcegroups, secrets. Three isolated envs: dev (10.40/16), stage (10.30/16), prod (10.20/16, bare prefix). Default m6i.2xlarge, region eu-central-1.

Docker images & tooling

backend/Dockerfile

3 stages: builder (python:3.13-slim → wheels), pptx-builder (node:20 → pptxgenjs), runtime (slim + Playwright Chromium ~350MB + node). Non-root flowin (UID 10001). Entrypoint runs migrations then uvicorn.

Quality gates (pyproject.toml)

Ruff (F/E/W/B/PLE), import-linter (4 hexagonal contracts, 4/0), vulture (dead code), pytest + Hypothesis. Repo-root scanners: checkov, gitleaks, trivy, pre-commit.

Secrets never in code/CI

Terraform generates SECRET_KEY / db_password into SSM SecureStrings (project CMK); the host composes /etc/velocityai/app.env at start. The infra↔app contract is via generic env vars (DATABASE_URL, SECRET_KEY, CORS_ORIGINS), which is why the partial flowin→velocityai rebrand doesn't break anything.
