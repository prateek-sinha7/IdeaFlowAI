API & Data Model

The FastAPI app (app/main.py, title "AI SaaS Platform", v0.1.0) registers 18 routers plus the WebSocket. On startup it verifies the Alembic schema (refuses to boot in non-dev if unmigrated), restores non-terminal runs, and wires the engine→WS resume bridge.

In plain terms. This layer is the building's front door and its filing cabinet. The front door (REST + WebSocket) checks who you are and takes your requests; the filing cabinet (PostgreSQL) durably records every run, artifact, and event so history, audit, and resume all work. It is also the only layer allowed to talk to both the browser and the engine.
What it is

The FastAPI web layer (18 routers + a WebSocket) and its SQLAlchemy data model.

Why it exists

To authenticate users, own the run lifecycle, enforce ownership, and persist everything the product needs to remember.

How it works

Routers call into the kernel; additive, owner-scoped tables (every row carries owner_id + workspace_id) record runs, artifacts, events, and audit.

Core (app/core/)

config.py

Pydantic Settings. Boot-guards a weak SECRET_KEY (raises SecretKeyMisconfigured outside dev). Holds Bedrock/Anthropic config, MAX_OUTPUT_TOKENS=32768, AGENT_RECURSION_LIMIT=400, RUNS_ROOT=/app/runs, RUN_DIR_TTL_HOURS=48.

security · crypto · dependencies · entitlements

JWT encode/decode + revocation checks, field encryption, FastAPI DI (get_current_user), per-tier entitlement limits.

Data model (app/models/ — SQLAlchemy)

Additive migrations only (Alembic 0014→0022); every new table carries owner_id + workspace_id for the scope filter.
