Presentations (PPT)

Composes an executive slide deck from a brief, against an OpenDesign template + design system, and exports it. This is the "OpenDesign PPT" (od_ppt) pipeline — the agents are shared by both the ppt and od_ppt ids.

Pipeline id: ppt / od_pptAgents: 3Deliverable: pptInjects: template, design_system, craft
In plain terms. Describe the deck you want and three agents compose it — not as generic slides, but against a real design system so the colors, fonts, and spacing are on-brand. The result can be exported to a genuine PowerPoint file.
What it is

A 3-agent presentation pipeline (the OpenDesign "od_ppt" flow) that produces an executive slide deck.

Why it exists

To generate polished, on-brand decks quickly, using a chosen template + design system rather than default styling.

How it works

analyze the brief → compose against injected template / design-system / craft content → validate + re-emit the deck → export to .pptx.

The 3 agents, in order

OpenDesign injection

The PPT agents declare injects: [template, design_system, craft]. The engine loads that content (via the opendesign context provider + od_loader) and composes it into the system prompt before the agent body, so every color, font, and spacing value comes from the chosen design system's tokens.

Template

A SKILL.md-style workflow describing the deck structure (from skills/opendesign, baked to /app/opendesign).

Design system

Color/font/spacing tokens the composer must use verbatim.

Craft rules

Template-specific quality rules injected as a block.

Export to .pptx

📊 Deliverable

The deck is produced by the ppt deliverable resolver and rendered in PPTPreview. Export to a real .pptx is done via pptxgenjs — client-side in the browser, and server-side through app/services/pptx_export.py (which spawns node + pptxgenjs, baked into the backend image).

The manifest, verbatim

ppt/workflow.yaml. Note the source comment: the ppt and od_ppt agents physically declare pipeline_type: od_ppt (they're shared), so this manifest's step list is sourced from PIPELINE_AGENTS["ppt"], not from scanning agent frontmatter for a matching id — a subtlety worth knowing if you ever go looking for "ppt" in an AGENT.md file and don't find it.

Launch surface: wizard

Unlike most pipelines, ppt declares launch_surface: "wizard" — pure catalog-presentation metadata (Phase 20) telling the frontend to launch this workflow through the guided wizard flow rather than the default composer. Never read by the compiler or kernel.

8 clarify defaults

Widened from 4 (KAN-74) to also cover content_depth, data_availability, visual_style, key_sections — the dimensions that most affect whether a generated deck actually matches what the requester had in mind.

Revision

Two revision paths exist: ppt_revision (2 agents: ppt-revision-agent + ppt-revision-assembler) and od_ppt_revision (1 agent). See Revisions.
