The 22-Phase Refactor

Flowin's current shape is the result of a brownfield "strangler" refactor (spec 003-workflow-engine-decoupling) that turned a prototype-/PPT-coupled engine into the workflow-agnostic kernel described across this atlas. This is the secondary reference — the codebase is the source of truth.

In plain terms. Today's clean architecture wasn't built in one go — it was carved out of a tangled engine in 22 careful, incremental phases. The team used the "strangler" method: wrap the old code in tests, grow the new structure alongside it, switch over, then delete the old path. Never a risky big-bang rewrite. This page is a history for context; the code is the real source of truth.
What it is

The 22-phase refactor history (spec 003-workflow-engine-decoupling) that produced the current architecture.

Why it exists

To decouple a prototype-/PPT-coupled engine into a workflow-agnostic kernel without ever breaking existing behavior.

How it works

Each phase: add a safety net → extract behind an abstraction → rewire call sites → delete the old code (an exit gate) → prove SC-001.
