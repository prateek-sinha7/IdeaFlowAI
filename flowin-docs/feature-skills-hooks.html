Skills, Hooks & Guardrails

Three distinct mechanisms shape an agent's behavior by injecting content into its system prompt — plus a fourth, executable hook type that fires around lifecycle events. They come from different sources and inject in one fixed order.

Structural constraints (enforced by tests): <60 lines, plain markdown, no fenced code blocks, no frontmatter. A missing guardrail logs a warning and injects an empty block — the agent still runs.

Executable lifecycle hooks (distinct from behavioral)

audit_logger
Default lifecycle audit → hook_runs (KAN-73).
secret_scan
Blocking secret scan on writes (default).
otel_tracing
Non-blocking OTLP tracing.

These are HookHandler capabilities returning continue/warn/block. A step that declares no hooks: auto-gets audit_logger + secret_scan. They surface in the UI's Audit tab via hook_run events. The per-user Constitution (from workflow_memory) is injected last, just before the prompt body.
