Agents & Runtime

An agent is a folder with an AGENT.md file: YAML frontmatter (identity + metadata) plus a Markdown system-prompt body. There are ~80 in agents/prompts/. The runtime is how an agent becomes a running LangChain deepagents graph.

In plain terms. An "agent" is really just a Markdown file — a job description with a bit of metadata at the top. The runtime is the machinery that reads that file and turns it into a live, tool-using model with its own scratch space on disk. Keeping the agent as plain text means anyone can read or tweak what an agent does without touching Python.
What it is

The AGENT.md format (frontmatter + prompt) plus the machinery that builds a running LangChain deepagents graph from it.

Why it exists

To keep an agent's identity editable as text while the runtime uniformly handles models, tools, sandboxes, and streaming.

How it works

Load the spec → compose the prompt in a fixed order → resolve tools → build a DeepAgentRunner → map its LangGraph events onto the UI's event vocabulary.

The runner

Sandbox vs. checkpoint thread

The on-disk RunSandbox is keyed on run_id only and shared across a run's agents, so a file one writes persists for the next. The LangGraph checkpoint thread_id is per agent-invocation (f"{run_id}:{agent_id}", plus :task in the build loop).

Model selection

build_model() picks ChatAnthropic (local) or ChatBedrockConverse (prod). User-selectable per agent (Haiku 4.5 default). Timeouts + adaptive retries live in one place. See Model Policy.

Tool filtering

The library sub-agent dispatch tool (task) is always excluded so the model can't spawn its own sub-agents — the engine orchestrates fan-out. Enforced by a per-graph _ToolFilterMiddleware.

Recursion backstop

No per-agent iteration cap; AGENT_RECURSION_LIMIT = 400 is the only runaway guard. Library auto-summarization replaced the old cross-agent summarizer.

Prototype build: per-task sub-agents + Both-validation

The prototype-build step doesn't run once. The engine writes spec.md/design.md/tasks.md into the sandbox, then launches one isolated sub-agent per task. After each task it runs Both-validation — static_check (stdlib) + render_check (headless Chromium) — with a bounded fix-loop (N=2).
