Human-in-the-Loop & Clarify Gates

A run can pause and wait for a human — to answer clarifying questions before it starts, or to review/edit an intermediate artifact mid-pipeline. These pauses are durable: they survive a browser refresh or a backend restart because state lives in the LangGraph checkpointer.

A clarify + review-gate run

Two kinds of gate

Clarify gate (pre-run)

When the manifest declares clarify.mode: auto, the ClarifyEngine asks up to ~5 questions per round (from the manifest's clarify.defaults + planner-inferred gaps), emits questionnaire_ready, and pauses until submit_questionnaire arrives. "Skip all & run directly" force-proceeds.

Review gate (inter-step)

A step with gates: [human] (its AGENT.md gate: Human_Gate) pauses after the step, emitting review_gate_ready. The user can approve or edit the artifact; the edited content is folded into the run. Prototype's specify + plan steps use this.

Per-run gate selection

The client can pass gate_agent_ids in the run_pipeline payload to choose exactly which agents pause for review (the UI's ReviewGatesSection toggles). When omitted, the default is the static set of agents whose AGENT.md declares gate: Human_Gate. This lives on ExecutionContext.gate_agent_ids.

🔁 Durability & ownership

Both gate types are durable via the Postgres checkpointer, so a paused run resumes on reconnect or after a backend restart. A review-gate response is a cross-run write, so it is owner-checked (the run named in the gate key must belong to the caller) — an unknown or unowned run is denied (no existence oracle).
