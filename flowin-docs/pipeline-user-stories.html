User Stories

Turns a plain-language brief into a structured product backlog — epics, user stories in "As a / I want / So that" form, Gherkin acceptance criteria, non-functional requirements, and Fibonacci story-point estimates. Ready to paste into Jira.

In plain terms. Hand this pipeline a rough idea and get back a Jira-ready backlog. Six specialist agents work in sequence — like passing a document down a table of experts — each adding their piece: the domain, the epics, the estimates, the non-functional requirements, a review, and a final clean compile.
What it is

A 6-agent pipeline that turns a brief into a structured product backlog (epics, stories, Gherkin AC, NFRs, estimates).

Why it exists

To convert vague product ideas into estimable, review-ready requirements without a human writing every story by hand.

How it works

analyst → epics → estimates → NFRs → review → compile, all shaped by the agile guardrail; output is streamed markdown.

How it's wired

Manifest

agents/workflows/user_stories/workflow.yaml: planner: run, clarify.mode: auto with 8 defaults (target_audience, scope, priority, technology, personas, user_journeys, business_rules, compliance_security), all steps single_shot with no gates, deliverable streamed_text.

Guardrail: agile

Injected into every agent: stories in As-a/I-want/So-that form, ≥2 Given/When/Then criteria each, P0/P1/P2 priority, Fibonacci estimable, no implementation detail in AC.

📚 Why 8 clarify defaults, not 4

The manifest comment records the reasoning directly: the original 4 defaults covered only basic context, and short/vague prompts consistently came out missing the dimensions that actually determine backlog quality — personas/roles, user journeys, business rules, and compliance/integration constraints. So user_stories is one of several manifests widened from 4 to 8 clarify defaults (KAN-74). The ClarifyEngine caps each round at 5 questions, so a brief missing all 8 gets a 2-round clarify; a richer brief needs fewer.

Catalog metadata (Phase 20/22, presentation-only — never read by the compiler or kernel): user_launchable: true, display_name: "Generate product requirements", description: "Epics, user stories, and Gherkin acceptance criteria — ready for Jira."

Revision

The user_stories_revision pipeline (1 agent) re-runs over an existing backlog seeded via the previous_run provider. See Revisions.

📝 Deliverable

The final agent's streamed markdown is the deliverable (streamed_text resolver). The UI renders it via MarkdownPreview; it can be chained as context into a downstream pipeline (e.g. feed the backlog into a Prototype run).
