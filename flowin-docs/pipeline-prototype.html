Prototypes

Builds a navigable, high-fidelity single-file HTML prototype from a brief. It's the flagship pipeline and the one SC-001 was proven against — every capability it uses (per-task build loop, Both-validation, fix-loop, compaction) is declared in its manifest, not hardcoded.

The pipeline, step by step

The build step is special: per-task sub-agents

The prototype-build step uses strategy: task_loop. The engine writes spec.md/design.md/tasks.md into the sandbox, parses the task list with the heading_tasks parser, then launches one isolated sub-agent per task, each injected with a === CURRENT TASK === block. Task 1 uses write_file; every later task uses edit_file (the deepagents FilesystemBackend won't overwrite).

Both-validation + bounded fix-loop

static_check

Pure-stdlib structural checks: routes ↔ sections, the route map, handlers, is-active state, dead nav links.

render_check

Headless Chromium: clicks each nav link, verifies a <section data-page> activates, and asserts no console errors.

After each task, both run; a bounded internal fix-loop (N=2) feeds the selected issues back to the sub-agent. The fix-loop is a non-yielding coroutine, so it adds no extra UI events. Revision runs the same validation as a smart-hybrid policy seeded from the parent run.

🔒 Two human gates

prototype-specify and prototype-plan declare gates: [human] — the run pauses after each for the user to review/edit the spec and the plan before the (expensive) build begins. See HITL & Clarify Gates.
