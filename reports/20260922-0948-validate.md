### QA-PS-013 — Upload custom template "From URL" fails for some valid public URLs
- **Phase reached:** validate — completed
- **Verdict:** **CONFIRMED**, 3/3 reproductions from cold start (cycle 1: `/create/prototype`
  via login→dashboard; cycle 2: `/create/prototype` via dashboard; cycle 3: `/create/ppt` via
  dashboard). LEDGER Status set to **CONFIRMED**.
- **Trigger:** every `https://` URL fails identically, not just hexaware.com.
  `backend/app/api/prototype_templates.py:349`'s `httpx.AsyncClient()` uses default TLS
  verification (certifi's bundled CA list), which does not trust this environment's
  TLS-intercepting proxy certificate. Confirmed by running the identical httpx client code
  directly from `backend/.venv` against `example.com`, `hexaware.com` and `www.google.com` —
  all three raise `httpx.ConnectError` / `SSL: CERTIFICATE_VERIFY_FAILED: self-signed
  certificate in certificate chain`, while the same three hosts succeed via `curl` (OS trust
  store).
- **Cards minted:** [ISS-695](../.knowledge/cards/20260922-0800-ISS-695.md)
- **Tests:** none run
- **Evidence:** `evidence/qa-ps-013/attempt1-prototype-error.png`,
  `evidence/qa-ps-013/attempt3-ppt-error.png`, network trace (502 on
  `GET /api/prototype/fetch-url?url=...`, all 3 browser cycles + direct curl with bearer
  token), `backend/app/api/prototype_templates.py:349-353` and `:387-392`, direct
  `httpx.AsyncClient` repro against 3 hosts, `.knowledge/cards/20260922-0800-ISS-695.md`,
  `LEDGER.md` row 73
- **Note:** duplicate-checked against `.knowledge/INDEX.md` — ISS-343/BUG-113/FIX-396 cover a
  different, already-fixed symptom (raw Python errno text leaking into the 502 detail on
  unreachable domains). FIX-396 is why the message now reads "Could not reach that URL..."
  instead of raw errno text. ISS-695 is a new, distinct defect: the fetch now fails for URLs
  that ARE reachable, because httpx's default TLS trust store doesn't include this
  environment's intercepting-proxy CA. Reciprocal "Referenced by" edge added on FIX-396.
  Root-cause fix should set `verify=<system CA bundle/truststore.SSLContext>` or make the
  proxy's CA available to httpx, not silence the error further.
- **Tooling note (non-blocking):** card rebuild's index stage (`build_index.py`) ran clean and
  indexed ISS-695 correctly; the context stage (`build_context.py`) aborted on a pre-existing,
  unrelated Python-version bug (`Path.write_text(newline=...)` requires Python 3.10+, this box
  runs 3.9.6) — confirmed pre-existing by reading the script, not caused by this card.
