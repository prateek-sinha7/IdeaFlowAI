### 5. Key Decisions & Locked Constraints (do NOT contradict)

- **D-01 (acquisition):** an exec-granting step MUST declare `gates: [security, approval]` in its manifest; the compiler raises `CompilerError` if `tools.exec` is granted without BOTH gates. NO auto-injection — the compiled plan mirrors the authored manifest (INV-5). The SecurityGate double-checks `approval` is declared (cheap defense-in-depth). → 10-CONTEXT.md (Decisions, D-01).
- **D-02 (pause/resume):** the `approval` gate delegates to the ONE durable HITL mechanism (`ctx.runner.run_human_gate` → engine `_run_review_gate`, the human-gate precedent). NO sibling `run_approval_gate` method, NO second resume surface. `_run_review_gate` stays UNCHANGED. → 10-CONTEXT.md (D-02), 10-03-SUMMARY.md (patterns-established).
- **D-03 (first-exec memory):** subsequent exec steps in the same run don't re-prompt — a prior `gate="approval"`/`outcome=pass` `gate_events` row (read via `read_gate_events`) short-circuits to silent PASS. Durable across restarts, NO new state field, NO migration — the audit trail IS the memory. **Exec authorization is run-scoped (one approval opens exec for the whole run), not per-step** — explicitly SPEC-locked (WR-03 documented). → 10-CONTEXT.md (D-03), 10-REVIEW.md (WR-03).
- **D-04 (approval payload):** the pause payload is the exec POLICY snapshot (step/agent id, allow-list, caps, scrubbed-env note, egress-denied) — **no creds, no dynamic argv preview** (argv is constructed at exec time; the allow-list IS the honest bound). → 10-CONTEXT.md (D-04).
- **Exec profile is runtime/host-owned, NEVER manifest-tunable** — `DEFAULT_EXEC_PROFILE` lives as module constants in `local.py`; a manifest may grant `tools.exec: true` but can never widen the allow-list or raise the caps. → 10-SPEC.md (Requirement 2).
- **Trust-conditional grant ceiling:** `file`/`builtin` trust may grant exec (survives `intersect_permissions`); `user`/`db` granting exec/network/secrets → `CompilerError`. Exec is engineer-only — nothing exec-related is `user_allowed=True`. `network`/`secrets` stay OFF in the ceiling for BOTH trust levels (still runtime gate-blocked, out of scope). → 10-02-SUMMARY.md (key-decisions).
- **`network` and `secrets` remain BLOCKED at the security gate this phase** — only the exec branch was split to a conditional PASS; the network/secrets BLOCK path is byte-identical. → 10-03-SUMMARY.md (Accomplishments).
- **Three-layer enforcement, each independently testable, each dormant unless the plan grants exec:** compiler ceiling → security+approval gate → workspace policy. This dormancy is what preserves INV-3 parity (no existing manifest grants exec). → 10-PATTERNS.md (Shared Patterns).
- **Accepted residual risks (do not re-litigate):** RISK-1 — an allow-listed interpreter can still open sockets (OS-level netns enforcement is the v2 ECS seam; engineer-only exec); RISK-2 — D-04 payload discloses only policy (no creds/argv); RISK-3 — the exec-granting `sample_exec_workflow` lives under `tests/.../fixtures/` only, never a shipped/user palette. → 10-SECURITY.md (Accepted Risks Log).

### 7. Gotchas, Survivors & Carry-Forward

- **Live survivor — `exec_command` returns stdout-only (str contract).** `proc.stderr` + `proc.returncode` are passed to the recorder/audit but NOT returned. Validators therefore surface verdicts via STDOUT: `code_compile` drives an inline `python3 -c py_compile.compile(doraise=True)` driver printing `COMPILE_OK`/`COMPILE_FAIL`; `code_test` parses pytest `-q` summary; `code_lint` parses ruff `--output-format=concise`. **A future agent must NOT change `exec_command`'s return type to expose exit code without re-baselining `test_local_runtime.py` and risking a characterization re-baseline** — the stdout contract is load-bearing. → 10-04-SUMMARY.md (Decisions Made / Deviations).
- **Gotcha — `python` is NOT on the scrubbed PATH; only `python3`/`python3.11`.** The compile driver uses `python3` (both are allow-listed). → 10-04-SUMMARY.md (Issues Encountered).
- **Gotcha — `import subprocess` survives in the 3 validator files but only for the `subprocess.TimeoutExpired` exception type** — NOT for spawning. Grep for `subprocess.run(`/`subprocess.Popen(` in those files = 0. This is by design (the type-only import). → 10-VERIFICATION.md (Anti-Patterns Found).
