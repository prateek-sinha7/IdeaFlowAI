### 3. Capabilities, Modules, Schema & API Added

**Schema — REUSED table, additive migration `0021` (the milestone's FIRST new table-migration).** The chain was `0014→0020` (all `0015`–`0020` were column/data migrations on existing tables); `0021_saved_user_workflows.py` (`down_revision="0020"`) is the first migration in this milestone to touch a table for a new *feature surface* — and it does so **additively, with no `create_table`**. It adds **nullable columns** to the existing `workflows` table via `batch_alter_table` + an `ix_workflows_owner_source` index. **No new table** — this is the load-bearing INV-12 decision: the dormant `WorkflowDefinition`/`workflows` table (`backend/app/models/workflow_definition.py`; future-fitted in `0014` with `source`/`owner_id`/`workspace_id`/`manifest_json`/`version`; previously 1 dead writer, 0 readers) is REUSED for `source="user"` rows. A `user_workflows` table was explicitly REJECTED as a textbook dual-implementation violation.

> **IMPORTANT — column count evolved 2 → 3.** The SPEC/ROADMAP/21-VERIFICATION all say "**2** nullable columns" (`base_pipeline_type`, `model_overrides`). The **final landed migration adds 3** nullable columns — the post-verify review-fix pass (WR-03, commit `420cea39`) added a **dedicated `description`** column rather than overloading the user's free-text description onto `constitution_ref` (whose semantic is a workflow-memory lookup key). The final state in `backend/app/models/workflow_definition.py:41-43` and `0021_saved_user_workflows.py:38-40` is `base_pipeline_type` + `model_overrides` + `description`, all `nullable=True`. A future agent: the table carries **3** Phase-21 nullable columns, and `description` is its own column — do NOT re-overload `constitution_ref`.

**API — new owner-scoped router `backend/app/api/user_workflows.py`** (`prefix="/api/user-workflows"`): `POST ""` (validate then insert, owner-stamped `user_id=owner_id=workspace_id=current_user.id`, `source="user"`, `artifact_edges="[]"`), `GET ""` (list where `user_id==me AND source=="user"`, `updated_at.desc()`), `GET "/{id}"`, `PATCH "/{id}"` (rename/edit), `DELETE "/{id}"` (→204). Cross-owner/missing → **404** via `_owned()`. Registered in `backend/app/main.py` (`include_router(user_workflows_router)`). The `_validate_model_overrides` two-check predicate is **replicated locally** in the router (identical logic to `websocket._validate_model_overrides`) to keep the app-layer router free of a websocket-module import.

**Run-launch — REUSED, no engine/run-path edit.** Launch = replay the stored `{base_pipeline_type, agent_ids, model_overrides}` triple into the existing `run_pipeline` WS handler, which **re-validates** `agent_ids` against the LIVE `allowed_custom_agent_ids` and `model_overrides` via its own `_validate_model_overrides`. No `if saved_workflow:` fork; no new pipeline name (SC-001).

**Frontend surfaces:** `UserWorkflowSummary` + 4 CRUD fetchers (`frontend/src/lib/api.ts`); `NameWorkflowModal` (`frontend/src/components/catalog/NameWorkflowModal.tsx`, reused by Save + Rename); the "Your workflows" section + per-row kebab + "+ Create workflow" (`WorkflowCatalog.tsx`); the composer "Save workflow" button + the load-bearing `initialAgentIds`/`initialModelOverrides` preload props + guarded re-derive (`IdeaInputPage.tsx`); the `onLaunchSaved`/`savedComposition`/`handleLaunchSaved` wiring (`DashboardLayout.tsx`). **No new visual language** (UI-SPEC §1 — every node copies an existing analog: `DeleteModal`, `WorkflowHistory` kebab, catalog rows, `AgentModelPicker` loading/error/empty triad).

**Entitlements:** reused unchanged — `can_run_pipeline(tier, base_pipeline_type)` gates BOTH save (fail-fast → 403, no orphan rows) AND launch; v1 saved workflows are `custom`-based → enterprise.

### 5. Key Decisions & Locked Constraints (do NOT contradict)

- **A saved workflow is PURE DATA — `{base_pipeline_type, agent_ids, model_overrides}` — never a new pipeline name (SC-001).** The kernel knows no workflow by name; launch replays the triple through the UNCHANGED `onRun`/`handleRunPipeline`/`startPipeline`/`run_pipeline` path. No `if saved_workflow:` fork anywhere (`grep 'if (saved' == 0` in `DashboardLayout`). v1 `base_pipeline_type = "custom"` only (the table/validation support other base types; exposing them is deferred).
- **REUSE the `workflows` table — do NOT add a `user_workflows` table.** `source="user"` rows live alongside `source="file"` rows. A new table = INV-12 dual-implementation violation (explicitly REJECTED).
- **Additive-migration-only.** `0021` adds **nullable** columns + an index via `batch_alter_table`; NO alter of existing columns/constraints; `owner_id`+`workspace_id` already present (stamped on create); `artifact_edges` stays NOT NULL → user rows write `"[]"` (do NOT relax it). Reversible (up/down/up proven). **Final count = 3 nullable cols** (see §3 callout).
- **Owner-scoped CRUD — IDOR → 404, default-deny (INV-8).** Every query filters `user_id==current_user.id AND source=="user"`; cross-owner read/rename/delete returns **404** (not 403 — don't leak existence). Stamp `user_id=owner_id=workspace_id=current_user.id` (self-id convention).
- **Re-validate `agent_ids` + `model_overrides` at BOTH save AND launch (load-bearing security invariant).** Save uses the EXACT launch predicates (`allowed_custom_agent_ids`, `ModelCatalog().ids()`, `SUPPORTED_PIPELINE_TYPES`, `can_run_pipeline`) so a persisted row can never carry something launch would reject; launch re-checks against the LIVE allow-list so a since-disallowed agent/model is rejected, never smuggled. `agent_ids` must be **non-empty** (WR-02 fix: `Field(min_length=1)` → 422; no unrunnable orphan rows). Name uniqueness is **API-level per-user** (409), NOT a DB constraint (the table is shared with `source="file"` rows).
- **Entitlement deny → 403; validation → 422; duplicate name → 409** — distinct fail-fast codes; the entitlement gate runs before any insert.
- **`GET /api/workflows` (Phase 20 catalog) stays DB-free** — saved workflows are served by the SEPARATE `/api/user-workflows`; the FE merges client-side.
- **INV-3 — the 5 characterization goldens (prototype/od_prototype/prototype_revision/od_ppt/app_builder) stay byte-identical.** The new columns/router/FE never touch the run/event path; the only engine edit is the `custom`-only dead-writer removal (dormant on the non-custom goldens). **Ports & Adapters:** the router lives in `app.*` (legal `app→agents`); `lint-imports` stays **4 kept / 0 broken**.
- **No new capability grants** — `exec`/`network`/`secrets`/`spawn_subagents` stay OFF.

### 7. Gotchas, Survivors & Carry-Forward

- **Seed must resolve against `ALL_LIBRARY_AGENTS` (`LIBRARY_AGENTS ∪ CUSTOM_AGENTS`), NOT base `LIBRARY_AGENTS`.** Caught as a Rule-1 bug by the launch e2e (`569aa93d`): saved `custom` workflows reference `CUSTOM_AGENTS` ids that are ABSENT from the base `LIBRARY_AGENTS`, so resolving the seed through the base list loaded **0 agents** and the load-bearing launch silently no-op'd. The composer's own `AgentLibrary` uses the superset; the launch seed must match it. **Do not narrow this back to `LIBRARY_AGENTS`.**
- **`IdeaInputPage` has no agent-preload by default — the guarded re-derive effect is mandatory.** `pipelineAgents` is always re-derived from `LIBRARY_AGENTS.filter(type)`, which is **empty for `custom`**. The `if (initialAgentIds?.length) return;` guard is what keeps the saved seed from being clobbered on the first effect run. Removing the guard breaks launch.
- **`onSelectFeature` only carries a bare `WorkflowType`** — it cannot carry a composition; that is why a distinct `onLaunchSaved` prop + `savedComposition` state exist. `handleSelectFeature` clears the seed so a normal launch starts clean (no stale-seed bleed).
- **Playwright mock glob must be `**/api/user-workflows**` (double-star)** — a single `*` does not cross a `/`, so `/{id}` PATCH/DELETE would fall to the fixtures catch-all and silently break rename/delete.
- **`model_overrides` live in a REF** (`modelOverridesRef.current`) — read `.current` on Save; the picker has no value-prop by default (WR-01 addressed the launch-replay seed; if extending the picker, seed its internal state from the saved overrides or merge-not-replace on change).
- **Column-count drift across docs:** the SPEC/ROADMAP/21-VERIFICATION say "2 nullable columns"; the FINAL landed migration has **3** (`description` added by WR-03). Trust the code (`workflow_definition.py:41-43`, `0021:38-40`), not the planning prose, on column count.
- **`deferred-items.md`:** 2 PRE-EXISTING TS2352 errors in `frontend/e2e/fixtures/mockApi.ts` (readonly-tuple casts on `CAPABILITIES`/`MODEL_CATALOG`) — confirmed identical on HEAD, untouched by Phase 21, outside its `files_modified`, do not affect any Phase 21 gate. Owned by the e2e-fixtures cleanup task, NOT a saved-workflows concern.
- **Carry-forward (remaining WF-DB-01 scope, all explicitly deferred — `21-CONTEXT.md` `<deferred>`):** saving non-`custom` base types; sharing/marketplace; org/workspace-shared workflows; versioning beyond the existing `version` column. These are deliberate v-next, NOT gaps.
