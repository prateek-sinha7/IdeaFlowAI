### 1. Goal & Success Criteria (what was PLANNED)
Phase 4 is the **declaration + routing seam only** — it builds the manifest→compiler→`CompiledWorkflow` pipeline and makes the engine source structure (agent sequence, deliverable, clarify defaults, planner-skip) from the compiled plan, while artifacts still flow through the legacy `accumulated_outputs` mirror and **no L1–L13 kernel branch is deleted** (those are Phase 7). Concrete capability impls (Phase 7), typed `ArtifactGraph`/persistence (Phase 5/1B), model policy (Phase 6/1C), and trust flags/self-registration (Phase 8/3) are all explicitly out of scope. (→ 04-SPEC.md "Goal"/"Background"; 04-CONTEXT.md "Phase Boundary")

Must-be-TRUE criteria (→ 04-SPEC.md "Acceptance Criteria"; 04-VERIFICATION.md "Observable Truths"): a malformed manifest raises a typed error naming the field (MAN-01); the compiler is thin/no-DSL with no workflow-name branch (MAN-02/INV-1/INV-5); unknown capability refs are rejected naming the bad ref (MAN-03/INV-4); every `PIPELINE_AGENTS` pipeline + `od_*` alias runs from its `CompiledWorkflow` with no legacy dispatch fallback (MAN-04); `pipeline_type` is consumed only by the id-alias resolver for routing (MAN-05); `GET /api/workflows` + `/{id}` return manifest-derived metadata, 404 on unknown (API-01); Phase-0A snapshots + import-linter + migration-ledger stay green (INV-3/SC-001). **Depends on:** Phase 03 (token-trim 0C) — provides `od_prototype=alias→prototype` precedent + live import-linter/vulture/migration-ledger gates (→ 04-01-SUMMARY.md "requires").
