### 5. Key Decisions & Locked Constraints (do NOT contradict)
- **D-01 (provisioner + facade split):** `RuntimeEnvironment` provisions (`create_workspace`/`teardown`); `Workspace` is the fs+git+exec+`ExecutionPolicy` facade carrying `owner_id`/`workspace_id` + back-ref to its runtime. This is the ECS-swap seam (§27) — a later `EcsRuntime.create_workspace()` returns a remote-backed `Workspace` with ZERO engine change → 09-CONTEXT.md (Area A). Ports kernel-side; `LocalSandboxRuntime` app-side (touches `app.core.config.settings.RUNS_ROOT` + `app/agents/sandbox.py` disk-safety), reached via the `ctx.runner` handle, mirroring the Phase-8 Validator split → 09-RESEARCH.md (R-A).
- **D-02 (RunSandbox refold in-place):** name survives as a thin facade; call sites untouched (parity-safest). `LocalWorkspace` is the **single git-subprocess owner**; `RunSandbox` keeps the disk primitives (`root`/`path_for`) and delegates `read`/`write`/`cleanup` (wrapping a separate RunSandbox would be circular). `serialize_sandbox_deliverable` keeps its **raw-bytes** read (NOT `read_text`) for CRLF byte-equivalence — load-bearing → 09-02-SUMMARY.md / 09-PATTERNS.md (RunSandbox refold).
- **D-04 (RepoIndex):** optional, in-memory per-run, built only on `RepoSpec.index` opt-in OR `file_count > REPO_INDEX_FILE_THRESHOLD` (N6 = 2000); **grep/glob is the default search**; no new table; embeddings OUT. The build DECISION lives in the capability (`should_build_index`); the compiler only RECORDS the flag (INV-5) → 09-03-SUMMARY.md (key-decisions).
- **D-05/D-08 (ONE external-tool mechanism = MCP):** `integration_provider` is a thin DATA bridge mapping a granted `integrations` scope onto a catalog `mcp_server`'s tools via `resolve_integration_scopes()` → the EXACT `mcp_server_configs`/`mcp_exposed_tools` the MCP prewarm consumes. **NO parallel SDK path** (no PyGithub/python-gitlab/slack_sdk) — gated by grep → 09-06-SUMMARY.md (key-decisions). A future agent adding an integration must bridge MCP, not import a vendor SDK.
- **D-07 (async→sync binding):** MCP tools are bound by awaiting `McpClientAdapter.get_tools()` ONCE at the async engine run-entry (mirrors `prewarmed_constitution`), stashed on `AgentContext.prewarmed_mcp_tools`; the sync factory only reads+unions — **NO `asyncio.run`/`nest_asyncio`/`run_until_complete` in the sync factory** (double-loop hazard, gated by grep → 0) → 09-05-SUMMARY.md (key-decisions). MCP tools AUGMENT `create_deep_agent`, never replace it (INV-13).
- **Locked invariants this phase enforced:** INV-1 (kernel knows no workflow by name — branches default `main`/`work`, never a workflow-name branch; sample workflow runs with zero engine edit, SC-001); INV-3 (5-pipeline byte/event parity, `SNAPSHOT_UPDATE` UNSET, no re-baseline); INV-5 (compiler records the index flag + scopes, control flow lives in capabilities); INV-8 (default-deny ownership — `ScopedStore`, cross-owner `PermissionError`); INV-9 (exec/network/secrets default OFF, mcp/integrations default none); INV-12 (move-don't-copy deletions); INV-13 (all agents on `deepagents`; tree-sitter/mcp-adapters are libraries, not runtimes — banned-pattern green) → 09-SPEC.md (Constraints) / 09-SECURITY.md.
- **No-exec invariant (this phase):** the whole repo path runs exec OFF; `exec_command` exists in the port but `ExecutionPolicy` denies it (`PermissionError`) until N3/Phase 4B. RepoSpec/repo binding is injected at RUN ENTRY by the host (the §15 seam), NOT a manifest top-key (manifests are pure data, INV-5) → 09-04-SUMMARY.md (key-decisions).
