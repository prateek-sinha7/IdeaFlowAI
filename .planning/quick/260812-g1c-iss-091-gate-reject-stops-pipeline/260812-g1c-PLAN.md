# Quick Task 260812-g1c — ISS-091: a gate rejection must stop the pipeline

## Problem (reproduced at HEAD `c0bbb6e2`, offline, ~1 s)

Rejecting at an inline human review gate emits `pipeline_cancelled`, and then **every
remaining step still runs** and the run terminates on `pipeline_complete`.

Observed with `scratchpad/batch2/iss091_probe.py`:

```
BEFORE cancel: [... agent_complete, review_gate_ready, pipeline_cancelled]
AFTER  cancel: [wave_started, subagent_spawned x2, subagent_result x2, merge_started,
                merge_completed, wave_completed, wave_started, subagent_spawned x2,
                subagent_result x2, merge_started, merge_completed, wave_completed,
                pipeline_complete]
worker call_log: {}          <- zero model tokens spent
subagent_runs rows: [('sample-wave-worker','complete',None) x4]
wave_runs rows:     [(0,'completed'), (1,'completed')]
```

**The severity is not token spend — it is silent, permanent data loss.** The workers
short-circuit on `_run_agent`'s terminal guard (`engine.py:3329`) so they burn zero
tokens, but every no-op worker is still recorded `subagent_runs.status='complete'` and
every wave `wave_runs.status='completed'`. `wave_scheduler.py:251-256` skips completed
waves on resume. Probe 2 proves reject -> restart -> resume yields:

```
[B] worker model calls on resume: {}
[B] wave_runs after resume: [(0,'completed'), (1,'completed')]
[B] state: completed
[B] part_*.txt files for this run: []      <- the deliverable can NEVER be produced
```

## Root cause (two parts, both verified at HEAD)

1. `engine.py:2523-2530` — the dispatch loop observes **only** `agent_error`. A
   `pipeline_cancelled` arriving through the same stream is forwarded and then ignored,
   so the outer `for i, spec in enumerate(ordered_agents)` (`:2370`) advances to step i+1.
2. `engine.py:2381` — the only step-boundary termination check reads `cancel_event`, and
   a gate rejection sets **no** `cancel_event` at all. (This is why FIX-227 is orthogonal.)

The declared-gate path already has the correct handler — **WR-03**, `engine.py:2454-2479`
— whose own comment describes this defect verbatim. The inline path is its missing sibling.

**Files:** `backend/agents/execution_engine/fanout.py`,

coverage** rather than being shipped unproven.

**Verify:** the new unit tests green; `lint-imports` 4 kept / 0 broken.

## Must-haves

- `pipeline_cancelled` is the run's terminal event on a gate rejection; `pipeline_complete`
  is never emitted for such a run.
- A gate-rejected run writes **zero** `wave_runs` and **zero** `subagent_runs` rows.
- A rejected-then-resumed run still produces its deliverable.
- WR-03's declared-gate path is behaviourally unchanged.
- The kernel keys on the **generic event type** only — no workflow name, no agent-id
  literal (SC-001 / INV-1).
