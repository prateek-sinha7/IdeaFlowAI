<objective>
KAN-167. `_bootstrap_cognito_admin` (backend/app/scripts/bootstrap_admin.py:277-298)
calls `admin_create_user` first, then `admin_set_user_password`,
`admin_add_user_to_group`, and a `next(...)` `sub` extraction — all before it
returns. `create_admin` (:220, :248-249, :269-270) only knows a pool user exists
once that return value is assigned to `cognito_sub`, and gates its compensating
delete on `cognito_sub is not None`. A failure in any post-create step therefore
raises past an un-set `cognito_sub`: the local row is rolled back but the pool
user survives.

Consequence: the users table is still empty, so the next deploy runs bootstrap
again and `AdminCreateUser` fails with `UsernameExistsException`. A fresh
environment stays unreachable until an operator manually deletes or reconciles
the pool user — the migration plan's R1 risk (COGNITO-MIGRATION-PLAN.md:481).

"Fixed" means: every failure after the pool user exists best-effort deletes that
pool user, exactly once, before bootstrap reports failure — so a retry against
the still-empty database succeeds with no manual pool cleanup.
</objective>

## Fix plan

```
FILES TO CHANGE:
- backend/app/scripts/bootstrap_admin.py
  * _bootstrap_cognito_admin: wrap every step that runs AFTER admin_create_user
    (set password, add to group, sub extraction) in try/except that calls the
    existing _compensate_delete_cognito_admin(email) and re-raises. The raise is
    preserved so create_admin still rolls back and returns EXIT_ERROR with its
    existing message. admin_create_user stays OUTSIDE the try — a failure there
    created nothing to clean up.
  * Do NOT reorder the AWS calls; the smallest correct change is the guard.
  * _compensate_delete_cognito_admin: log the successful delete (operators need
    to know the pool user was removed) and widen the docstring, which currently
    claims "after a local-commit failure" and would now be wrong for two callers.
  * Update the create_admin comment that points at "the except branch's
    compensating pool-user delete" so it names both compensation sites.

- backend/tests/unit/test_bootstrap_admin.py
  * New class TestCognitoPartialProvisioningCompensation with fault injection at
    admin_set_user_password, admin_add_user_to_group, and sub extraction (a
    create response with no `sub` attribute); plus admin_create_user itself
    failing (asserts NO delete), a single-compensation assertion, a
    retry-after-compensation test, and a secret-hygiene assertion on caplog.
```

```
WHAT IS NOT CHANGING:
- The bootstrap invariant ("any row -> successful no-op"); no no-admin backfill.
- The PostgreSQL SHARE ROW EXCLUSIVE lock, re-check, and rollback ordering.
- The exit-code contract (0 / 10 / 1) remote-deploy.sh §12 branches on.
- app/core/cognito.py — no wrapper signature or behaviour change.
- The local (non-Cognito) path: byte-identical behaviour.
- permanent=True on the bootstrap password (a separate, tracked hardening item —
  deliberately NOT bundled into this fix).
- .github/scripts/remote-deploy.sh, deploy.yml, Terraform, docs.
- The single-local-break-glass-admin invariant and its script.
```

```
DELETED CODE CHECK:

  around existing calls and reuses the already-present compensation helper; no
  new module, class, or duplicated delete path.
```
