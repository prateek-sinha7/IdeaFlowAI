# Phase quick-260706-w00 Plan 01: Process Canvas Prototype Template Summary

Added one new OpenDesign prototype template — `process-canvas` — by flattening the DC-framework
`Claims Recovery POC.dc.html` into a single self-contained, genericized `example.html` plus a
`SKILL.md` with `od.mode: prototype`, picked up automatically by the loader's dir-scan with zero
engine/config edits.

## What was built

**Task 1 — `example.html`** (98,155 chars, < 110k cap). A single self-contained HTML file that
reproduces the source look verbatim (indigo `#2563eb`, green `#0f8a53`, ink `#1a2233`, soft-grid
`#f4f5f7` canvas, sidebar + 4 screens, swimlane process map, version segmented control,
decision-gate step-through, outcome-simulation scan, sign-off flow, all inline SVG icons, the
four `@keyframes`). All DC scaffolding removed (`support.js`, `<x-dc>`, `<helmet>`, `<sc-if>`,
`<sc-for>`, `{{ }}`, `data-dc-script`, `data-props`, `data-screen-label`, `hint-placeholder-*`,
Google-Fonts `<link>`s). The `DCLogic` controller (`state` / `renderVals` / handlers / `_gateT`
/ `_simT`) was re-authored as one inline vanilla-JS IIFE that actually works standalone:
sidebar screen-switch (4 views), Recommendation sub-tabs (Process/Gate/Simulate), version swap
(baseline/v1/v2) toggling nodes + routing color, drilled swimlane node → master→detail panel
(with empty-selection state), gate next/prev/auto-play(`setInterval` 1150ms, capped at 3)/reset,
sim scan (`setInterval` 34ms over 40 cells, caught set {4,11,18,25,31,37}), and sign/unsign
toggle. Repeated markup (nodes, sim cells, sidebar systems, criteria) is JS-generated from data
arrays; `data-od-id` on each top-level section (sidebar/overview/connections/recommendation/
signoff). Font swapped to a system-sans / system-mono stack (no external link).

**Task 2 — `SKILL.md`** (mirrors web-prototype schema): generic `name: Process Canvas`,
`description` block scalar, `triggers`, and an `od:` block with `mode: prototype`,
`platform: desktop`, `scenario: operations`, `preview`, `design_system.requires: true`,
`outputs.primary`, `example_prompt`, `inputs`. `od.craft` omitted (web-prototype has none).
Body = build-agent workflow (resource map, when-to-use, pre-flight/copy/reshape-data/rewrite/
self-check/emit, hard rules, output contract).

## Genericization

All claims-domain / product vocabulary stripped and re-labelled into a reusable process
workflow: Scout→Flowline, Automated Consultant→Process Studio, ContextFabric→Process Canvas;
Adjusting/Subrogation lanes→Assess/Resolve; the 5 systems→System of record/Messaging/Field
data/Case tracker/Valuation (SR/MS/FD/CT/VL); 11 steps re-titled (Intake/Eligibility check/
Assess & review/Capture & flag/Prepare & resolve/Complete & close + Flag/Handoff intake/Route
viability/Action & follow-through/Outcome & record) with identical topology (x/y/w, shapes,
kinds, system tags); 3 gate criteria→generic all-HOLDS; sample→"A-4821 · Sample work item";
metrics→neutral "42% / 6 per week", all labelled directional.
