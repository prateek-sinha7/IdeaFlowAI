<objective>
Fix the regenerate-appends bug (FIX-039): when a prototype agent is re-run (user hits "regenerate" at the plan gate), the frontend appends the new run's stream onto the previous run's, so `PrototypePipelineView.parseTasks(planAgent.output)` reads the FIRST `<tasks>` block — a regenerated 9-task plan still shows "1 Build Task".

Root cause (verified in code): `frontend/src/hooks/useWorkflow.ts` `case "agent_start"` (L225-239) flips the matched agent to `status:"running"` but does NOT reset that agent's per-run accumulators. `case "agent_chunk"` (L263-281) does `output: updated[agentIdx].output + chunk` (append). So a 2nd `agent_start` for the same agent leaves the prior `output` in place → the next run's chunks concatenate onto stale v1.

Fix: in `case "agent_start"`, when an agent (re)starts, reset THAT agent's run-scoped accumulator fields to their fresh-agent initial values before setting `status:"running"`. Regenerate then REPLACES, not appends.

Purpose: correct, non-stale prototype (and all pipeline) output on regenerate — no band-aid in the parser.
Output: a 2-3 line diff in useWorkflow.ts + a dedicated vitest + a FIX-039 FIX-REGISTER entry.
</objective>
