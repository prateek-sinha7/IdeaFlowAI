## Deviations from the investigation report

1. **The report's Option A said the ingress predicate should read through `ScopedStore`.**
   It does not. It follows `_review_gate_run_is_terminal`'s idiom instead — its own
   `_get_db()` session, no owner filter — because ownership is already established at all
   three ingresses, and filtering on `run_events.owner_id` risks a **false 409** (which
   blocks legitimate work) if that column ever diverges from `WorkflowRun.user_id`.
   Verified against `backend/dev.db`: they agree on 206,368/206,368 rows today.
2. **The report suggested also fixing the unknown-action fail-open and tightening
   `GateCommand.action`.** Not done — a distinct defect, filed as ISS-070. Note that fix is
   *not* purely additive: a lenient client would start receiving 422s.
3. **The brief mandated a new test for the True/False/True eligibility vector on the
   grounds that it has none.** That premise was wrong —
   `test_update_specs_not_offered_while_a_revision_is_in_flight` already asserts exactly
   that vector and was verified green at `d62bfe4d`. It was not duplicated. What was
   genuinely missing is the same verdict against the **real** gate (that test stubs
   `_run_review_gate` out entirely, so it proves what the engine *passes*, not what the
   gate *does*) — which is what the new vector test adds.
