# Quick task 260812-7sk

There is no way for anyone — user or operator — to stop a running build once it has
crossed a backend restart, and every un-stoppable `od_prototype` build costs 5–21M
Bedrock tokens of the owner's money. One measured run billed **7,510,082 tokens after
the API answered `cancelled: true`**.

The root cause is already proven (`scratchpad/ISS-084-ANALYSIS.md`); this plan does not
re-diagnose it. Every claim below was re-verified against the tree at `1ed94666`.

## The defect, re-verified

| claim | evidence at `1ed94666` |
|---|---|
| `_drive_resumed_stream` passes no `cancel_event` | `engine.py:8310-8332` — the kwarg is absent |
| `_execute_impl` therefore binds `None` | `engine.py:1096` `cancel_event: asyncio.Event \| None = None` |
| every guard short-circuits | `engine.py:2350`, `:2577`, `:5572`, `kernel_services.py:194/1120/1250/1324` all read `if cancel_event and …` |
| exactly two production callers of `_execute_impl` | `grep '_execute_impl('` → `engine.py:1009` (launch, threads it) + `engine.py:8310` (resume, does not) |
| the orphan mint | `run_engine.py:520-521`, `run_commands.py:436` |
| the lying ack | `run_commands.py:335-338` |

So **all four resume drivers** (`resume_run`, `_rearm_gate_run`, `_replay_clarify_run`,
`_drive_user_resume`) funnel through one function that drops the signal. One fix.

## Decision — resolve the Event AT the funnel, via an injected hook

The kernel must not import `app.api` (import-linter contract 1, currently **4 kept /
0 broken**). So the engine gains **one more injected callback**, in the same shape as
the five already there (`_resume_register_queue` / `_resume_register_task` /
`_resume_cleanup` / `_resume_milestone_sink` / `_resume_output_persist_sink`):

```
self._resume_cancel_event: Callable[[str], asyncio.Event | None] | None = None
```

wired once in `app/main.py` (the single wiring site) to `run_engine._resume_cancel_event`,
which is **get-or-create on `_CANCEL_EVENTS`** — so `_CANCEL_EVENTS[run_id] is` the object
the engine reads. One registry, one object.

Resolution happens in `_drive_resumed_stream` itself, **not** as a parameter threaded
through the four drivers: it is the single funnel, so any future resume driver inherits
the fix instead of re-opening the hole. `None` hook ⇒ `cancel_event=None` ⇒ byte/event-
identical to today (the goldens, the offline harness) — INV-3.

## Must-haves

- The cancel signal reaches the kernel on every resume-family drive.
- `_CANCEL_EVENTS[run_id]` is the same object the engine reads.
- The endpoint never claims a cancellation it did not perform.
- A cancelled run reaches a **terminal row** and the next boot does **not** re-adopt it.
- The kernel gains no `app.api` import.

## Rejected

- Unconditional `task.cancel()` as the primary fix — reintroduces the ISS-007 delivery
  race and leaves the row non-terminal (i.e. re-creates the very defect). Kept only as
  the bounded fallback, strictly after the cooperative signal had its drain budget.
- Touching the four unguarded loops (`engine.py:2492`, `:3318`, `task_loop.py:492`, the
  fan-out family) — one variable at a time; they belong with ISS-078.
