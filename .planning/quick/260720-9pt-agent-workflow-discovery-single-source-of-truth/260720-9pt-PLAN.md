<objective>
Fix ISS-035: backend agent/workflow discovery was split across two sources of truth. `get_pipeline_agents()` (registry.py) was already fully dynamic (scans `AGENT.md` via `list_agent_ids()`), but `get_all_agents_flat()`, `allowed_custom_agent_ids()` (registry.py), and `_KNOWN_WORKFLOW_IDS`/`list_workflows()` (app/api/workflows.py) all read the hand-maintained literal `PIPELINE_AGENTS` dict directly — so a new agent (or pipeline) was live for pipeline *execution* but invisible to the agent library, the custom-workflow allow-list, and `GET /api/workflows` until someone remembered to hand-edit `registry.py` (backend/CLAUDE.md's documented "Adding an Agent Step 3"). Proven live: 8 fully-formed `spec_kit` agents existed on disk, invisible everywhere except direct pipeline execution.

"Fixed" means: `PIPELINE_AGENTS` becomes a value computed once at import time from a folder scan (same function `get_pipeline_agents()` already trusted), and `_KNOWN_WORKFLOW_IDS` becomes a value computed from which pipeline types both (a) are in `SUPPORTED_PIPELINE_TYPES` and (b) have an authored `workflow.yaml` manifest. Full root-cause writeup: `.investigations/hardcoded-agents/FINDINGS.md` + `.investigations/hardcoded-agents/PLAN.md`.
</objective>
