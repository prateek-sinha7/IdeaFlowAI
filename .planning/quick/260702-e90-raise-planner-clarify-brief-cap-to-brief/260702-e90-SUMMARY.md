# Phase 260702-e90 Plan 01: Raise planner+clarify brief cap to BRIEF_MAX_CHARS (64k) Summary

Routed the SmartPlanner analyze prompt, both planner `user_request` storage sites, and the ClarifyEngine `brief_sample` through a single new `settings.BRIEF_MAX_CHARS` (64k), so realistic briefs — including a full uploaded document — reach the AI in full instead of being whittled to head[:1500]+tail[-500:] / `brief[:3000]` / `user_request[:2000]`.

## What Was Built

- **`config.py`** — added `BRIEF_MAX_CHARS: int = 64_000` immediately after `MAX_OUTPUT_TOKENS`, with a comment documenting it as the input-brief cap for SmartPlanner + ClarifyEngine, aligned with `file_extract._MAX_TEXT_CHARS` (the 64k upload cap ≈ 16k tokens for a single planner/clarify call, well within Haiku's 200k context).
- **`smart_planner.py`** — added a module-top `from app.core.config import settings` (verified no circular import). `_build_prompt` now samples only when `len(brief) > settings.BRIEF_MAX_CHARS`, using a 3/4 head + 1/4 tail budget and reporting `len(brief) - settings.BRIEF_MAX_CHARS` chars omitted. Both `user_request` storage sites (`plan()` and `_default_context`) now cap at `settings.BRIEF_MAX_CHARS` (was `brief[:3000]`).
- **`clarify_engine.py`** — added `from app.core.config import settings`; `brief_sample` now reads `user_request[:settings.BRIEF_MAX_CHARS]` with fallback `inferred_intent[:2000]` (was `user_request[:2000]` / `inferred_intent[:500]`).
- **`tests/unit/test_brief_max_chars.py`** — 4 regression tests: full ~10k brief reaches the planner uncut (no "chars omitted"); full ~10k user_request slice >2000 chars; >64k brief still head+tail sampled (marker present, prompt bounded); planner + clarify share the same 64k setting.

Untouched per scope: the OUTPUT cap `max_tokens=2048` (smart_planner 170/186/193), `inferred_intent = brief[:200]` (414), and all other truncation sites (file_extract, revision re-ingest, od_context, handoff, runs.py).

## Deviations from Plan

None — plan executed exactly as written. The preferred module-top `settings` import in `smart_planner.py` did not introduce a circular import (verified by the import smoke test), so the local-import fallback was not needed.
