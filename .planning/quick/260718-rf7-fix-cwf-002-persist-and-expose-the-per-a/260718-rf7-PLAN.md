<objective>
Fix CWF-002: persist and expose the per-agent/effective model actually used, and make
`estimated_cost_usd` non-circular. Today `WorkflowRun.model_id` (migration 0014 column,
`app/models/workflow.py:37`) has ZERO write sites, so the launch driver's cost line
`estimate_cost_usd(wr.model_id or settings.BEDROCK_INFERENCE_PROFILE_ID, ...)`
(`run_commands.py:1509-1510`) always prices at the default inference profile — a circular
default. Separately the resolved model is computed per agent (`ModelResolver.resolve`,
Phase 6) but discarded — it never reaches the `agent_complete` event or any read surface.

Three surgical changes (grounded context "FIX CWF-002"):
- (a) engine.py — stamp the resolved `model_id` onto the `agent_complete` payload (queryable
  in the live stream); it is auto-stripped by the existing `_VOLATILE_STRIP_KEYS` `model_id`
  entry, so the 5 goldens stay byte-identical (INV-3).
- (b) run_commands.py — write the run's effective `model_id` onto `WorkflowRun.model_id` in the
  launch driver's terminal DB block, BEFORE the cost computation, from the value already
  threaded as `model_id=` into `engine.execute` (`getattr(user, "preferred_model", None) or None`,
  `run_commands.py:1359`). Net: `estimate_cost_usd` resolves to the REAL model (non-circular).
- (c) runs.py — add `model_id` to `WorkflowRunResponse`; `_run_response` auto-materializes it
  for BOTH list (summary) and detail.

Purpose: make the model queryable AND cost non-circular, with zero schema/migration change and
zero golden perturbation.
Output: CWF-002 fixed; new RED->GREEN unit test; 5 goldens + single-source-grep still green.
</objective>
