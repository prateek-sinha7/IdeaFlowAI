## The decision that matters: DO NOT touch `_first_incomplete_step`

The investigation recommended replacing the predicate with an "was it interrupted?" form
(`agent_id in agent_start_events and agent_id not in agent_complete_events`). **Rejected, on
measured evidence.** That change's differential behaviour versus HEAD is exactly one set:
*an artifact producer with NO `agent_start` AND NO `agent_complete`.* Measured read-only
against the live `backend/dev.db`:

```
runs with artifacts: 14
DIFFERENTIAL SET (no agent_start AND no agent_complete): 27
  producers: [('deep-planner', 14), ('clarify-agent', 13)]
SEC 5.2 SET (agent_start present, agent_complete missing): 0
```

Two findings kill the proposal:

1. **The scenario used to justify it has never occurred, and the proposal would not fix it
   anyway.** The justification was §5.2: a lost `agent_complete` write makes a step
   permanently unskippable. Live count of that shape: **0**. And under the proposed
   predicate an agent with `agent_start` present and `agent_complete` missing is
   `_interrupted=True` → still re-run — **byte-identical to HEAD**. The proposal delivers
   nothing for the case it was argued from.
2. **Its only live differential is 27 rows, all `deep-planner` / `clarify-agent`** — and
   neither appears in any `agents/workflows/*/workflow.yaml` step list nor in
   `registry.PIPELINE_AGENTS` (verified by grep: zero hits). They are never members of
   `ordered_agents`, so `_first_incomplete_step` never evaluates them.

So the proposal changes production behaviour for **zero ordered pipeline steps**, and its
only observable effect anywhere is that the five broken fixtures go green. That is loosening
a production predicate to satisfy a test. `c71f3d9c`/FIX-121's fail-safe direction — absent
terminal evidence ⇒ re-enter, never skip — stands, and stays untouched.

## The fix, per cause

**A — repair the fixtures so they exercise the durable path (TEST-013, test-only).**

* `#1` `test_midwave_resume_does_not_reinvoke_completed_workers` and
  `#6` `test_failed_run_resumes_skips_completed_tasks` drive **`engine_a._execute_impl(...)`**
  directly (`:431`, `:3049`). The durable `_RunEventSink` is built in `execute()`
  (`engine.py:1020`, persisted at `:1065`) — `_execute_impl` never persists an event. Both
  tests call themselves end-to-end while silently skipping the durability layer they depend
  on. Drive **`execute()`** instead: instance A then writes its own `run_events`, which is
  what these two tests were always claiming to prove.
* `#2` `_build_open_review_gate_fixture` (`:1119`) and `#3`/`#4` `_build_partial_build_fixture`
  (`:1458`) hand-seed `ArtifactRef` rows only. Production writes an `agent_complete` beside
  every produced artifact. Seed it.

**B — the stub returns what production returns (TEST-013, test-only).**
`chat_narrator.persist_milestone_card` returns `(created, seq, card, reply_eid)`
(`app/agents/chat_narrator.py:287-289`). The stub at `:2642` returns a 3-tuple. The engine
already breaks on it — `resumed-stream drive failed mid-drive: not enough values to unpack
(expected 4, got 3)` at `engine.py:8509`, swallowed by the drive's `except Exception`. One
line.

**C — a `pipeline_complete` only supersedes a cancellation across an ATTEMPT boundary
(FIX-229, production).**
Durable tail behind #7, captured by probe:

```
1:review_gate_ready | 2:run_resuming | 3:workflow_validated | 4:pipeline_start
| 5:review_gate_ready | 6:pipeline_cancelled | 7:pipeline_complete   → status "completed"
```

`resume_supersedes` (`run_commands.py:602-606`) asks *"is there a `pipeline_complete` at a
higher seq?"*. The real question KAN-120 wanted is *"did a **later attempt** succeed?"*. In
the rejection case the cancel and the complete are the **same attempt** — the user rejects,
the dispatch loop falls through to the run's single `pipeline_complete` emitter — so
"higher seq" records a run the user explicitly rejected as `completed`. Fix: require an
attempt boundary (`run_resuming` / `pipeline_start`) between the last `pipeline_cancelled`
and the winning `pipeline_complete`. Root-cause level: the broken assumption is
*later-in-the-tail = later-attempt*, and it is fixed where it is made.
