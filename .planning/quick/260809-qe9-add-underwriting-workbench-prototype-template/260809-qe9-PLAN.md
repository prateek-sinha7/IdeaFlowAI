# Quick Task — Add `underwriting-workbench` prototype template

## Goal

Add a new **od_prototype** design template so users can pick "Underwriting Workbench"
in the launch wizard's template gallery. The design is converted from a reference mock
supplied by the user at `~/Downloads/Northstar Underwriting.html`.

**Purely additive.** Zero edits to engine, loader, API, registry, workflow.yaml, or
frontend — adding a template is a folder drop by design (`od_loader` dir-scans
`skills/opendesign/design-templates/`, folder name *is* the `template_id`).

## Source analysis (done — verified, not assumed)

The reference is **not** static HTML. It is a Design-Composer self-extracting bundle:

- 528 KB / 393 lines; a `<script type="__bundler/manifest">` holds 3 gzip+base64 JS
  assets (69 KB + 10.7 KB + 131.8 KB) and 16 woff2 IBM Plex font faces.
- A `<script type="__bundler/template">` holds a 139 KB escaped-HTML DC template using
  `sc-if` / `sc-for` / `{{ }}` bindings, `sc-camel-on-click`, and **all-inline styles**.
- It boots **React 18 from unpkg** and preconnects **Google Fonts**.

It therefore cannot be shipped as-is: the prototype guardrail bans CDN scripts, external
fonts, framework runtimes, and inline-style-only styling. It must be **re-authored** as a
single self-contained vanilla file.

Decoded source lives in the session scratchpad (`ns/template.html`) — not committed.

## Tasks

1. **Create `skills/opendesign/design-templates/underwriting-workbench/SKILL.md`**
   Frontmatter (`name`, `description`, `triggers`, `od.mode: prototype`,
   `od.platform: desktop`, `od.scenario: finance`, `od.design_system.requires: true`,
   `od.example_prompt`, `od.inputs` as mappings, `od.craft.requires` naming only craft
   rules that exist). Body in house style: Resource map → When to use → Screen inventory
   (data-page ↔ data-od-id) → Workflow Steps 0-5 → Hard rules → Output contract.

2. **Create `skills/opendesign/design-templates/underwriting-workbench/example.html`**
   Re-author the mock as one self-contained vanilla file:
   - 6 routed pages: `accounts`, `account`, `txn`, `submissions`, `tasks`, `reports`
   - 5-step transaction wizard (Identification / Coverage & Forms / Quote Details /
     Document / Send) with in-page sub-tab state (not routes)
   - 4 modals + toast
   - Inline styles → CSS classes + `:root` tokens; IBM Plex → system font stack;
     React state → a single `store` object.
   - Drill-down handlers use a **literal** `location.hash = '#/account'` so `account`
     and `txn` are not flagged orphan sections.

3. **Verify** — `static_check` must return `ok=True`; assert zero `http(s)://`, zero
   external `<link>`/`<script src>`, file under the 120 000-char injection cap; render
   in headless Chromium and click through every page/step/modal with zero console errors.
