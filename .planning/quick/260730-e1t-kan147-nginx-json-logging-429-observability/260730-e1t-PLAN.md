## Objective

Fix the A1 rate-limit scenario observability gap (KAN-147 / E1). nginx-generated HTTP 429 rejections (rate-limit zone exhaustion) are indistinguishable from backend 429s in the current space-delimited log format, rendering the nginx_5xx_spike alarm ineffective. The fix replaces the space-delimited log_format with JSON, adds map directives to normalize upstream_addr and status fields for CloudWatch JSON filter validity, updates the nginx_5xx metric filter pattern to JSON, adds three new 429-specific filters and alarms, adds two liveness alarms to detect silent monitoring failures, and ensures :80 server block explicitly declares the JSON format (avoiding file heterogeneity that breaks JSON filters).

Result: A1 rate-limit scenario becomes detectable; "we are throttling our own users" alarm fires within 15 minutes of sustained rejection.

## Context

- `E1.md` (`.planning/dev-sse-infra-investigations/E1.md`) — full investigation, 1,337 lines; validated on real nginx 1.24.0
- `FIX-144` — app-layer A1 mitigation (SSE in separate location with higher limits)
- Phase 29 — SSE endpoint introduced (2026-07-08); predates Phase 29, nginx config assumes short-lived requests
- Root cause: space-delimited log_format carries no $upstream_addr; nginx limit_req 429 is unqueryable by CloudWatch positional patterns

## Facts Verified During Planning

- nginx 1.24.0 supports `escape=json` (available >= 1.11.8), `$request_id` (>= 1.11.0), map directive with named captures
- `escape=json` on unset variable renders empty string, not nginx's "-" sentinel (measured on real nginx 1.24.0)
- :80 server block has no access_log directive → inherits http-level combined format → mixed-format file breaks JSON filters
- CloudWatch JSON pattern `{ $.upstream_addr = "-" }` is documented and proven in-repo (`.planning/IMPLEMENTATION-REGISTER.md` line 1520)
- Leading wildcard `*/events/stream` is documented for JSON filters; trailing wildcards proven in-repo (`/velocityai/dev/*`)
