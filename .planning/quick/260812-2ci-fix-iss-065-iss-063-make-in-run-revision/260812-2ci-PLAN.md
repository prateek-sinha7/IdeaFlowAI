# ISS-065 + ISS-063 — make in-run revisions visible

One change, because both are "a revision happened and the screen does not say so".
ISS-063's investigation warns that fixing it alone is how this family gets its **third**
counter. Frontend-only: zero backend files, zero migrations.

## The design decision — source of truth for the revision cycle count

Two candidates existed:

- **(A)** derive from the event stream — `max over agents (timesStarted) - 1`, computed
  inside the `setPipelineState` updater.
- **(B)** consume FIX-220's `revision_cycle` / `revision_in_flight`, additive on
  `review_gate_ready.data` (commit `1b786e30`).

**Chosen: (A).** Decisive evidence, from the durable log of run `d5dbc9f2` read at
`backend/dev.db`:

| seq | time | event |
|---|---|---|
| 9283 | 20:54:20 | `review_gate_ready` (analyze) — cycle 0 |
| **9285** | **20:54:51** | `agent_start` prototype-specify — **revision cycle 1 begins** |
| **13353** | **20:56:25** | first `review_gate_ready` after the revision started |

1. **Coverage.** B rides only on gate events. Between the revision starting (9285) and
   the first gate frame that could carry `revision_cycle >= 1` (13353) there is a
   **94-second window with no gate event at all**. The banner's whole job is that
   window. A lights at 9285.
2. **Lifetime.** B's pair lives on `ReviewGateData` (`useRunStateStore.ts:119-120`),
   which is per-firing and replaced by the next gate / cleared on `pipeline_start`.
   The banner must persist for the rest of the run.
3. **Replay identity.** A is a pure function of accumulated frames, so it is
   order-independent and idempotent — identical live, on the synchronous REST replay
   loop (`page.tsx:2257-2269`), and on a reconnect that replays from seq 0.
   B depends on which gate frame was seen last, and on `revision_high_water` surviving
   the resume rebuild of `ectx` (unverified).
4. **Not a dual implementation.** FIX-220 keeps its own, different job — telling apart
   three gate firings that share a `gate_key` *and* their output bytes, on the gate
   card. Different question, different surface. `specRevisionCount` ends up with
   exactly **one** writer.

## Task 2 — ISS-065: per-artifact version picker

**Files:** `src/components/results/ArtifactVersionPicker.tsx` (NEW),
`src/components/results/AgentDetailPanel.tsx`, `src/components/results/AgentThinkingTab.tsx`

`GET /api/runs/{id}/artifacts?kind=&include=content` already returns every version with
its body (verified live on `:8010`). No new endpoint, no migration.

- **NEW `ArtifactVersionPicker`** — fetches the run's artifact list on mount, filters to
  `producer_agent === agentId`, **dedupes by `content_hash`** (each artifact is written
  twice — typed kind plus a `produces` alias — so `version` does not line up; the build
  agent reaches `html_file` v23 vs `prototype-build` v11), renders `null` at `<= 1`
  version. Content is fetched **lazily on click and memoised per kind** —
  `html_file&include=content` measured at 2.89 MB.
  **`resp.artifacts ?? []` is mandatory**: `mockApi.ts:708` returns `json({})` for any
  unmatched `/api/**`, so the mocked Playwright suite would go red with a TypeError.
- **`AgentDetailPanel`** — additive optional `runId`; `viewed` state; picker in the card
  header row; output becomes `viewed?.content ?? agent.output`; reuse the existing
  `ReadOnlyVersionBanner` (INV-12 — do not write a second banner).
- **`AgentThinkingTab`** — pass `runId={runId ?? null}`; already computed at `:91`.

**Rejected hack:** adding v2/v3 to the existing "Version" chip. Different axis
(whole-run family) and contradicts locked decision D2
(`IMPLEMENTATION-REGISTER.md:2531`); `handleSelectVersion` calls `getWorkflow(memberId)`,
so an artifact-ref id would 404 into a dead control and corrupt the state feeding
`FilesTab` and `StartingPointCard`.

**Tests (RED first)**
- `src/components/results/ArtifactVersionPicker.test.tsx` — hide at <=1; dedupe by
  `content_hash`; build-agent subset shape; no content request until a click; renders
  nothing when the API returns `{}`.
- `src/components/results/AgentDetailPanel.artifactVersions.test.tsx` — selecting v1
  renders v1's content; banner shows; Back to latest restores `agent.output`.
