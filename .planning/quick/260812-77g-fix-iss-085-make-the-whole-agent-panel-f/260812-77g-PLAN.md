# Quick task 260812-77g

The ISS-065 artifact-version picker (FIX-222) only half-works. Selecting an older
version repaints the *raw output* section but leaves the prominent artifact CARDS
rendering the latest output, so the owner selected v1, saw the v3 page grid, and
concluded the picker did nothing.

Root cause is already proven by reading the code; this plan does not re-diagnose it.

## The defect

`frontend/src/components/results/AgentDetailPanel.tsx` holds **two** notions of
"what am I looking at":

| site | reads | follows the picker? |
|---|---|---|
| `:740` `shownOutput = viewed?.content ?? agent.output` | selected version | — (the correct value) |
| `:869` `<OutputPreviewSection output={shownOutput} />` | `shownOutput` | **yes** |
| `:130` `discriminateArtifact(agent.output \|\| "")` | latest | **no** |
| `:611` `parseSpecSections(agent.output)` | latest | **no** |
| `:612` `parseSpecOverview(agent.output)` | latest | **no** |
| `:687` `<AnalysisPreview content={agent.output} />` | latest | **no** |

`SettledArtifactCards` is handed the raw `agent` (`:840`) and re-derives everything
from `agent.output`. That is the dual implementation (INV-12) — one screen, two
answers.

## Decision — `discriminateArtifact` MUST key off the selected version

It picks *which renderer draws the content*. The artifact's type is a property of
**that artifact**, not of the agent: if v1 is a `<spec>` and the newest output is a
plain rewrite (or empty, because the agent is mid-re-run and FIX-039 cleared
`agent.output`), keying the type off the latest routes v1's content through the wrong
renderer or suppresses the card entirely. Pinning the type to the latest is the same
bug as ISS-085 one level up. `discriminateArtifact` is a pure content sniff, so
following the selection costs nothing.

## What stays pinned to the agent (deliberate)

`validationPassed` / `validationIssues` (the checks badge), `protoCompletedTasks` (the
task-plan rows) and `dagEdges` (the handoff line) are **run/agent state, not artifact
content** — they are not versioned anywhere in the FE. They keep coming from `agent`.
Residual noted in the summary: viewing an older `<tasks>` version still lists the
run's current task rows. Not user-reported, not in scope, registered rather than
silently fixed.
