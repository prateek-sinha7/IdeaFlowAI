<objective>
Fix CWF-001 FIX D2: the launch driver `_drive_launch_to_queue`
(`backend/app/api/run_commands.py`) mislabels errored/failed custom runs as
`completed`. It tracks `agent_error`, `pipeline_complete`, `pipeline_cancelled`
— but NOT the generic `error` event nor `pipeline_failed` — so a run that dies
with a generic `error` and no prior `agent_error` falls through the terminal
`else` (`:1442`) to `"completed"`. Its already-correct LOCK-B twin
`_drive_revision_to_queue` (`:1618-1707`) already tracks `pipeline_failed` and
defaults its terminal to `"failed"`.

Reconcile the launch driver TOWARD the revision twin (Phase 29 LOCK-B): track
the generic `error` event + `pipeline_failed`, and make the terminal status
fail-safe (a run is `completed`/`degraded` ONLY on a clean terminal; any
`error` / `pipeline_failed` / `agent_error`-without-clean-terminal → `"failed"`
+ persist `wr.error`), preserving precedence `cancelled > degraded > failed >
completed`.

Purpose: a run that actually failed at runtime must not be shown to the user as
`completed`. Closes Phase 13 IN-02/IN-03 (DB-`failed`-vs-FE-`success`
disagreement).
Output: an updated `_drive_launch_to_queue` + a RED→GREEN test pair in
`test_rest_run_launch.py`.

SCOPE FENCE — implement ONLY FIX D2. Do NOT implement FIX D1 (the compose-time
DAG satisfiability guard / producer-first pre-sort) or CWF-002 (per-agent model
persistence). Backend-only. App-layer status derivation ONLY — do NOT touch the
kernel (`engine.py` / `resolver.py`) or the compiler.
</objective>
