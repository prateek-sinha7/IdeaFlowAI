<objective>
Fix the reported bug: the prototype planner shows a waiting spinner (PlanningOverlay) while the planner runs, but the overlay disappears during the slow clarify question-generation gap, leaving a blank PreviewPanel until the questionnaire pops up.

Reuse the existing `PlanningOverlay` component. Change the single render-gate condition in `DashboardLayout.tsx` so the overlay is shown for the whole "planner or clarify still working" window (measured by `agents.length === 0`) instead of only while `plannerStatus === "running"`.

Purpose: The backend prototype event order is `planner_start -> planner_complete -> [slow clarify LLM gap] -> questionnaire_ready`. At `planner_complete`, `plannerStatus` flips to `"complete"`, so the current gate goes false and the overlay vanishes during the clarify gap. Keying the gate off `agents.length === 0` keeps the overlay up across that gap because `pipelineState.agents` stays `[]` from launch until the `pipeline_start` event seeds domain agents.

Output: A one-line condition change in `DashboardLayout.tsx`; typecheck/build green.
</objective>
