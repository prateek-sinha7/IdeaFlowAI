<objective>
BACKEND-ONLY, two independent config-gated capabilities, keeping deepagents (INV-13) and the
5 characterization goldens byte/event-identical (INV-3). No engine loop reimplementation, no
thinking-event surfacing.

PART A — Bedrock prompt caching (default ON). Prod uses `ChatBedrockConverse`; deepagents'
built-in `AnthropicPromptCachingMiddleware` fires ONLY for `ChatAnthropic`, so caching is
silently OFF on Bedrock and every build re-sends its ~45-68k fixed prefix uncached across
~300 turns. `langchain_aws` already carries the cachePoint machinery (`_apply_cache_points`,
called from `_generate`/`_stream` after popping `cache_control` from the per-call kwargs) — it
only needs a NON-EMPTY `cache_control` dict in the per-call `model_settings`. We add a
provider-agnostic `AgentMiddleware` that injects that dict on `ChatBedrockConverse` requests
only.

PART B — Extended-thinking config knob (enable-only, default OFF). A single
`THINKING_BUDGET_TOKENS` setting threads a clamped thinking budget into both provider branches
of `build_model`. Enable-only: default 0 means it never fires.

Purpose: ~55-80% cheaper billed input on Bedrock (FIX-034) + an operator knob for extended
thinking (ISS-031), with zero behavioral drift when both are at their defaults.
Output: 3 new settings, 1 new middleware (registered), thinking threading on both branches,
one new test file, FIX-034/ISS-031 register rows.
</objective>
