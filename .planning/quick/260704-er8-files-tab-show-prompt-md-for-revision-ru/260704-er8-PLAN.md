<objective>
FRONTEND-ONLY bug fix (quick). The "Files" tab renders no run-input `prompt.md`
for REVISION runs. `runInputFileRows` in `FilesTab.tsx` derives the primary
"Run input" row solely from `parseRunInput(runInput).brief`, guarded `if (brief)`.
A revision run's input parses to `revisionInstruction=<instruction>` with an EMPTY
`brief`, so a revision never gets a prompt.md (live or reopened) even though the
`input` is fully persisted and already threaded to both FilesTab mounts.

Fix: parse once into `parsed`, derive the primary content as
`parsed.revisionInstruction || parsed.brief` (instruction wins for revisions,
brief for originals — mirrors `StartingPointCard.isRevision` dispatch), and emit
the SAME `prompt.md` row guarded `if (primary)`. Filename stays `prompt.md` for
BOTH original and revision runs (product decision). Parsed-shape dispatch only —
no workflowType/run-name branch (SC-001), no new marker regex or second parser
(INV-12, reuse `parseRunInput` called once). Frontend-only, no backend, no golden.

Purpose: revision runs get a downloadable, visible record of their input like
every other run.
Output: patched `FilesTab.tsx` + extended run-input spec + FIX/ISSUES register rows.
</objective>
