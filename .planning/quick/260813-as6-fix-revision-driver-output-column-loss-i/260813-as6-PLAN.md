<objective>
The revision driver (_drive_revision_to_queue) is the dispatch path for EVERY *_revision
pipeline run -- the only one of the app layer's four terminal-persistence call sites that BUG-R03
never wired to the shared output-column mapping. Every completed revision run silently loses 7
WorkflowRun columns (output, agent_outputs, token_usage, duration, model_id,
deliverable_mimetype, deliverable_filename) even though the engine emits all of that data on
the wire and the driver receives it. Verified against the only revision that has ever completed
in this database (8a970205-5892-466a-89b0-f613b9dd021d, rate 1/1): all 7 columns NULL despite a
real deliverable existing. This defeats Analytics (a revision run is counted as $0 cost AND, as a
zero-numerator status=="completed" row, drags down avg_duration in the denominator), the Run
Detail KPI strip, GET /{id}/chain-context, and directly defeats FIX-249 (the Concierge
get_token_usage tool, shipped the same session) for every revision run.

Output: the driver fix, one RED-then-GREEN test, standing-gate re-measurement, and two
deliberately-unfixed items surfaced (not performed) for the orchestrator: the wr.error omission
and the one-row backfill decision.
</objective>
