# What was actually at risk

The 5 goldens are the project's INV-3 parity oracle. The failure mode to avoid was
**regenerating a golden to match current behaviour when the code is what is wrong** —
which permanently pins a regression as expected behaviour. So the 5 failures were
decomposed before anything was edited, and each cause adjudicated on its own evidence,
following ISS-029 (the same situation resolved correctly once before, which explicitly
**REJECTED regen-only**).

Result: **1 stale normalizer, 1 real code regression, 1 genuinely stale golden.**
Four of the five files had no problem of their own. Exactly one golden was regenerated.

# The three causes

**C1 — stale NORMALIZER (all 5 goldens). Neither golden nor engine wrong.**
`c71f3d9c` added an additive `pipeline_start.resume_offset`. It is 0 on every non-resumed
run and the harness never resumes — but a 0-valued key is still a NEW key, and the
snapshot compares whole canonical-JSON dicts. Added to `_VOLATILE_STRIP_KEYS`, the 7th
instance of a 6-precedent convention. Verified safe: `_REQUIRED_DATA_KEYS` has **no
`pipeline_start` entry at all**, so nothing is weakened, and resume-offset behaviour is
pinned directly by `test_restart_resume.py`. **Zero golden bytes touched.**

The emit-site comment at `engine.py:2049` claims *"0 on every normal (non-resumed) run →
byte/event-identical (INV-3)"*. That is **false as written** and is what misled the author
into skipping the strip step. Left in place (out of scope for this fix) but recorded here
and in the register, because it will mislead the next person too.

**C2 — a REAL REGRESSION (`prototype`, `od_prototype`). The golden was RIGHT.**
`f608e4bc` (FIX-190) appended an `accessibility` guardrail to 4 prototype-family agents.
Three of those hunks are pure `1 +` insertions; `prototype-build/AGENT.md` is `2 +-` —
the `+` line landed **on top of** `icon: "🏗️"`, deleting it, so the agent fell through to
the loader's `🤖` default. `icon` is contractual (`_REQUIRED_DATA_KEYS["agent_start"]`).
Independent sweep: **86** AGENT.md files, **exactly 1** missing an icon. Restored
byte-identical to `f608e4bc^` (verified by `diff` of the exact line). **Zero golden bytes
touched.** Regenerating here would have pinned a user-visible UI regression.

**C3 — a genuinely STALE GOLDEN (`prototype_revision`). The only file regenerated.**
`fd2ad8f1` deliberately set `planner: run → skip`. Probed whether that change might itself
be the regression: it is not (it fixes a real CR-02 defect, matches two already-live
siblings, reasoning documented inline in the manifest).

# Why the sequencing mattered

C3 was regenerated **strictly after C1**. Had it gone first, `resume_offset: 0` would have
been baked permanently into the file, coupling one of the five goldens to an FE metadata
key and diverging it from the other four. It was also done after the branch's queued engine
fixes (FIX-219 `82b5eb8c`, FIX-220 `1b786e30`) had landed, so it cannot silently absorb an
unintended event-stream change from them.

# The import contract

`task_loop.py:562` did `from agents.execution_engine.od_context import get_example_html`,
breaking the contract on **both** forbidden roots at once (`od_context.py:26` itself does
`from app.services import od_loader`). A sweep confirmed it was the only violation in the
whole capability tree.

Taken option (a), **break the import**. The port already existed and was already used
correctly by a sibling capability:

```
KernelServices.template_example()   kernel_services.py:1163
  -> ExecutionEngine._load_template_example()   engine.py:9040
    -> od_context.get_example_html()
```

Same function, same `EXAMPLE_MAX_CHARS` cap, same swallow-and-return-`None`, already inside
a `try/except`. The `hasattr(runner, "template_example")` guard mirrors
`context_providers/opendesign.py:128-135`, which exists because the unit-test fakes set only
a bare `ctx.runner`. Blast radius checked: `_write_reference_files` has one caller
(`task_loop.py:203`) and no test fake sets a `template_id`, so the seed block is inert in
tests either way.

Rejected: amending the contract (records the violation as permitted). Rejected: threading
`example_html` through the `od_context` dict (a second way to the same bytes, INV-12).
