<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| backend deliverable bytes → browser DOM | The custom-workflow HTML deliverable (`final_output`) is agent/LLM-generated, semi-trusted content rendered in the user's browser. |
| run-detail bytes → browser DOM (reopen) | Same content arriving via the history-reopen run detail. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-05 | Elevation of privilege / stored-XSS | the generic HTML deliverable iframe | mitigate | Render HTML ONLY inside an iframe with `sandbox="allow-scripts"` and explicitly NO `allow-same-origin` (reuse the PPTPreview non-od_ppt pattern). Without same-origin the framed content cannot read the parent's cookies/localStorage/DOM or call same-origin APIs — an unsandboxed or same-origin render would be stored-XSS-adjacent. The component test asserts the exact sandbox attribute (and the absence of allow-same-origin) as a blocking acceptance criterion. |
| T-18-06 | Tampering | mimetype dispatch | mitigate | Unknown/unexpected mimetypes fall to a DOWNLOAD affordance, never an inline/executed render — a hostile declared mimetype cannot force an unsafe render path. |
| T-18-07 | Spoofing (SC-001) | per-workflow FE branch | mitigate | Dispatch is on the declared mimetype, never a workflow name; the test grep-guards that no workflow-name literal (`ui_custom_proto` etc.) exists in the deliverable surface. |
| T-18-SC | Tampering | npm installs | mitigate | This plan installs NOTHING (uses the present tsc/vitest); no package-legitimacy table required. |
</threat_model>
