<objective>
ISS-021 frontend half: render ANY declared deliverable for ANY custom/unknown `pipeline_type` with ZERO per-workflow FE code — on BOTH the live preview AND the history-reopen detail view. Today the FE deliverable surface is a CLOSED dispatch keyed on hardcoded pipeline-type strings with no generic fallback, in TWO places: (1) the live path (`page.tsx` content routing + `PreviewPanel.tsx` `renderType`) and (2) the history-reopen detail view (`WorkflowHistory.tsx:264-269` `isMarkdown = isCustom` / `isPpt` / `isPrototype`, render :536-574). A custom HTML deliverable shows "Output will appear here" live, and on reopen hits `isMarkdown` → `<MarkdownPreview>` (escaped HTML). Add a GENERIC mimetype-dispatched fallback renderer (consuming the `deliverable_mimetype`/`deliverable_filename` that 18-01 now emits live, and a client-side output-shape heuristic on reopen): `text/html`→a SANDBOXED iframe, `text/markdown`→MarkdownPreview, `application/zip`/bundle→the file-bundle view; plus one generic deliverable row in the Files tab. The four known renderers are untouched (the generic path is a FALLBACK).

Purpose: SC-001 — a brand-new custom workflow renders faithfully with no FE edit, dispatching on the declared mimetype (live) / output-shape (reopen) and never a workflow name. ISS-021 has TWO render facets — the live preview AND the reopen detail view — and BOTH must be closed or the user still sees escaped HTML on reopen.

Output: event typing, a generic content channel in the dashboard (live + reopen), a generic renderer + sandboxed iframe in PreviewPanel, a generic reopen fallback in WorkflowHistory.tsx's detail view, a generic Files row, and component tests proving the dispatch + the sandbox + no-regression on both surfaces.
</objective>
