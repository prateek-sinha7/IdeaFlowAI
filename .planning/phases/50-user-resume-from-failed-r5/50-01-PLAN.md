<objective>
Ship `POST /api/runs/{id}/resume` (RESUME-18) — the "reopen & fix" headline: a terminal-FAILED
run becomes user-resumable. The endpoint is the ONLY new surface; drive is pure reuse of the
Phase 45–49 shared resume tier via `engine.resume_run`. Authorized by the LOCK-E/ND-4 supersede
record — POR §8.1 (this plan reverses the ND-4 deferral for exactly this scope; the other LOCK-E
deferrals — team-sharing/ND-12, prompt-override/ND-7, image-persistence/ND-10 — stay in force).

PINNED tension resolution (the one decision this plan locks): CONTEXT says "terminal statuses land
exactly as auto-resume does." That is unsatisfiable as written — auto-resume/`resume_run` write NO
`WorkflowRun.status` (research-verified: the only resume-path status writers are none). A bare
`create_task(resume_run)` would strand a user-resumed run at `running` forever on success AND on
arm-failure. Resolution: a THIN `_drive_user_resume` wrapper that (a) delegates 100% of drive to the
armed singleton's `resume_run` (callbacks NOT re-threaded — the hooks live on `self.*`), (b) reconciles
terminal status from the durable tail using the SAME event→status logic as the launch driver
(`_reconcile_terminal_status` — clone the LOGIC, not the event ladder), (c) flips back to `failed` on
arm-failure. This is NOT a third driver: no event ladder, no `async for ... engine.execute(`, no drain
loop. Auto-resume's own status posture is pre-existing and out of scope — do not change it.

Purpose: closes RESUME-18, the final phase of milestone v3.0. Makes a failed run first-class-resumable
at the same task/worker granularity every other interruption already recovers at.
Output: the REST endpoint + thin wrapper + reconciler + guards in `run_commands.py`; a new endpoint
battery `test_rest_resume.py`; two E2E cases appended to `test_restart_resume.py`.
</objective>
