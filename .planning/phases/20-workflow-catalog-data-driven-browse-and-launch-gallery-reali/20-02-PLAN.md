<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `GET /api/workflows` | Authenticated read (JWT via `authHeaders`) of manifest-derived discovery metadata. The catalog consumes it read-only; it is NOT a launch authority. |
| catalog row click → launch | The catalog only navigates (`onSelectFeature` → IdeaInputPage, or `router.push` to the wizard). The actual run still crosses the EXISTING tier-gated `run_pipeline` WS boundary (server-side `can_run_pipeline`). The catalog adds no new launch endpoint or trust boundary. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-05 | Elevation of Privilege | client-side two-gate filter bypass | mitigate | The FE gates (`user_launchable` ∧ `canRunPipeline`) are UX affordances, not authorization. A user bypassing them (devtools, forged fetch) still hits the EXISTING server-side `can_run_pipeline` tier gate on `run_pipeline` (20-SPEC §2). No FE-only enforcement is relied upon for security; the catalog launches through the same gated path CreationHub uses today. |
| T-20-06 | Information Disclosure | rendering raw API metadata | accept | The catalog renders only the friendly label/description already safe to show; it never exposes a new secret/PII (the endpoint returns the same ids the FE could already enumerate). UI-SPEC §4 forbids rendering the raw `name`, a presentation rule (no security impact). |
| T-20-07 | Tampering | malicious `/api/workflows` payload (XSS) | mitigate | Rows are rendered as React text children (auto-escaped) using the CreationHub JSX verbatim; the friendly label flows through React's escaping. No `dangerouslySetInnerHTML` is introduced. icon is consumed as a string key/glyph, not raw HTML. |
| T-20-SC | Tampering | npm installs | mitigate | No new npm dependency added (reuses `lucide-react`/`motion`/existing libs already present). No package-legitimacy gate required. |
</threat_model>
