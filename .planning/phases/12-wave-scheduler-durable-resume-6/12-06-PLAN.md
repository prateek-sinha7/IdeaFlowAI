<objective>
Close CR-03, CR-04 (the two mid-wave resume BLOCKERS in wave_scheduler.py), the backend half
of CR-06 (subagent events carry no wave_index), and the file-adjacent warnings WR-05
(duplicate task ids) and WR-01 (stale running wave row on resume).

- CR-04 (cross-step contamination): `_completed_wave_indices` (wave_scheduler.py:183-186) is
  built from ALL `wave_runs` rows for the run with NO `step == step_id` filter (the sibling
  subagent count IS filtered by `parent_step`). A workflow with two `wave_scheduler` steps
  (`user_allowed=True` — nothing forbids it) resuming at the second step treats the FIRST step's
  completed wave indices (0,1,…) as its own and skips its waves wholesale — those tasks never run.
- CR-03 (parallel-order data loss): the in-flight-wave skip uses `wave[_remaining_completed:]`
  (a leading-N prefix by count, lines 221-228) on the assumption "run_fanout dispatches in task
  order so the first N completed workers are the first N tasks". Waves run PARALLEL
  (`mode: parallel`, `max_parallel: 4`); completion order ≠ dispatch order. A crash after workers
  for t2 and t4 completed skips t1 and t3 (silently dropping their files forever — data loss —
  while the wave is then marked completed) and re-runs t4 (duplicate cost). `subagent_runs` carries
  NO task identity (migration 0019: parent_step, worker_agent, depth, isolation, status only), so a
  correct per-task skip is NOT derivable from the current schema.
- CR-06 backend half: `run_fanout` (fanout.py:507-526) emits `subagent_spawned`/`subagent_result`
  with `{worker, agent, isolation, depth}` — NO `wave_index`. The FE guard drops every subagent
  event, so worker leaves never render. The strategy must stamp the current `wave_index` onto the
  subagent_* events it re-yields per wave.
- WR-05: `json_tasks` accepts duplicate ids and `build_waves` (`by_id = {t.id: t for t in tasks}`,
  last-wins) silently drops the earlier task + can drive in-degrees negative.
- WR-01: on resume the strategy records a NEW running `wave_runs` row for the re-entered wave; the
  pre-crash row for that `(run, step, wave_index)` stays `running` forever, so the wave step is
  permanently classified incomplete.

Purpose: make mid-wave resume CORRECT for parallel waves (no data loss, no cross-step
contamination), give the FE the wave_index it needs to render worker leaves, and stop the
duplicate-id / stale-row corruption.

Output: a step-filtered completed-wave-index set; a whole-in-flight-wave re-run on resume
(replacing the unsafe prefix skip) with a terminal flip of the stale row; the CR-03-followup
deferral recorded durably in CONTEXT.md; wave_index stamped onto re-yielded subagent_* events; a
named duplicate-id guard in the parser + build_waves; tests that fail on each pre-fix path
(parallel completion-order ≠ dispatch order; second wave_scheduler step; duplicate id; stale
running row).
