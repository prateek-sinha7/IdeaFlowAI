<objective>
Make `Step.retry` live: add `RetryPolicy.on` (default `["transient"]`) and a SINGLE engine-side
retry wrapper around the per-step strategy dispatch site (engine.py ~1401-1403). The wrapper
activates ONLY when the compiled step declares `retry.max_attempts > 0` — absent/None is
byte-identical to today. It retries on transient-classified errors (reusing the 06-03
`_is_transient_throttle` family — one classifier home) with a patchable `backoff_seconds` sleep
seam, emitting a `step_retry` event per attempt. Before every (re-)execution it computes the
step's input content-hash and reuses an existing completed artifact keyed `(run_id, step_id,
input_hash)` (stored in the durable `run_events` payload — RESEARCH Open Q1 resolution), emitting
a `step_reused`/`step_completed` event instead of re-invoking the agent.

Purpose: RESUME-02. One mechanism serves both retry re-entries AND the restart re-runs of 12-03
(content-hash reuse is the shared key). Distinct from the validator fix-loop (content errors stay
with the fix-loop, untouched).

Output: `RetryPolicy.on`, the engine retry/reuse wrapper, the `step_retry`/`step_reused` events,
and scripted-model tests — with the 5 characterization snapshots byte/event-identical.
</objective>

| run owner → run_events reuse-lookup | The reuse-lookup must read only the run owner's events (V3/V4) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-02-REPLAY | Tampering | input_hash reuse-lookup | mitigate | The reuse-lookup reads the durable run_events via the OWNER-SCOPED `ScopedStore.read_events` (a cross-owner run resolves to ∅), so one run can never reuse another owner's completion; `input_hash` is sha256 over content-addressed upstream hashes + the resolved input — equality means genuinely identical input |
| T-12-02-HASH | Spoofing | content-hash idempotency | accept | `content_hash`/`input_hash` are sha256 for DEDUP/idempotency only, NOT an auth control (documented at graph.py:22); hash equality is never treated as an authorization check |
| T-12-02-DOS | Denial of Service | retry attempt loop | mitigate | The attempt loop is strictly bounded by the declared `max_attempts`; `backoff_seconds` is honored via `_retry_sleep`; a non-transient error breaks the loop immediately (no infinite retry); the wrapper is dormant for every step that declares no retry |
| T-12-02-SC | Tampering | npm/pip/cargo installs | mitigate | Zero external packages added (stdlib `hashlib`/`json`/`asyncio`; reuses the existing `_is_transient_throttle`). INV-13 banned-pattern gate unaffected |
</threat_model>
