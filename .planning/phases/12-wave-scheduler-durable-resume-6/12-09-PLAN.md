<objective>
Close the backend half of UAT Gap 2 (three sub-gaps a/c + the _stamp_resume_marker
NOT NULL bug). A client connected during an auto-resumed run currently never receives
the resumed tail's completion because:

  (a) resume_run / restore_non_terminal_runs never register the resumed task+queue in
      websocket._PIPELINE_TASKS / _PIPELINE_QUEUES, so reconnect_pipeline takes the
      live:false branch — the replay read returns rows-so-far and nothing afterward is
      ever delivered (no engine→WS bridge);
  (c) pipeline_reconnected.status is null — ScopedStore.get_run is scoped by the
      workspace_id recovered from run_events (non-null) while workflow_runs.workspace_id
      is NULL on rows created by the WS run path (websocket.py:1280, no workspace_id),
      so the run row never matches the scoped read;
  + _stamp_resume_marker inserts run_events with workspace_id=None (it passes
      wr.workspace_id which is NULL for WS-path rows) → run_events.workspace_id NOT NULL
      IntegrityError → the run_resuming marker is lost on every in-process auto-resume
      (warning logged each restart).

Live evidence (run E/E2): the durable log itself is correct (CR-01 seq continuation
18..28; CR-03 wave superseded+re-run; full replay after manual reload delivers
everything incl. pipeline_complete). The defect is purely the live-attach + status +
marker plumbing on auto-resume.

Constraints that bind this fix:
- INV-3/INV-12: no dual implementations; the WS-path workflow_runs.workspace_id fix
  reuses the EXISTING authz.set_run_scope seam (do not add a parallel stamper).
- Import-linter (003 §31): agents.execution_engine.engine MUST NOT import app.api
  (forbidden_modules includes app.api). The engine→WS bridge MUST be an injected
  callback (set from the app layer in app/main.py where restore_non_terminal_runs is
  already invoked), never a direct websocket import.
- Characterization parity: the legacy run_pipeline registration (_PIPELINE_TASKS at
  websocket.py:1503) and the live-attach drainer are UNCHANGED. The bridge only ADDS
  registration for auto-resumed runs; prototype/od_*/PPT event vocabulary is unchanged.
- SC-001: the bridge is workflow-agnostic (registers ANY resumed run by id; the kernel
  still knows no workflow by name).

Purpose: a reconnect during an auto-resumed run live-attaches (live:true) and receives
the full resumed tail incl. pipeline_complete; pipeline_reconnected.status is non-null
so the 12-08 FE handler can resolve a restarted run; the resume marker persists.

Output: an injected engine→WS live-task bridge; consistent workflow_runs.workspace_id
stamping; a workspace-correct resume marker; backend tests proving each.
</objective>
