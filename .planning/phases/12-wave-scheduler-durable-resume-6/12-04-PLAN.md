<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| backend run stream → FE tree state | Inbound lifecycle events must be applied idempotently (no double-apply on replay) |
| reconnecting client → after_seq | The client requests its own run's tail; ownership is enforced backend-side |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-04-DEDUP | Tampering | wave-tree event application | mitigate | Every applied event is deduped by `event_id` (a seen-set per run), so a durable replay on reconnect cannot double-apply a wave/worker entry; the panel render is a pure function of the deduped state |
| T-12-04-IDOR | Information Disclosure | after_seq replay request | mitigate (backend-enforced) | The client sends only `pipeline_run_id` + `after_seq`; the backend `reconnect_pipeline` replay is owner-scoped (`ScopedStore(owner_id=user).read_events`, 12-03 T-12-03-IDOR) so a client can never replay another owner's events regardless of the requested run id |
| T-12-04-XSS | Tampering | rendering task ids / agent names | mitigate | The panel renders task ids / agent names as React text children (JSX auto-escapes), not via `dangerouslySetInnerHTML`; no raw HTML injection from the event payload |
| T-12-04-SC | Tampering | npm/pip/cargo installs | mitigate | Zero new FE dependencies (reuses `motion/react` + lucide already present — RESEARCH Standard Stack); no package install, no legitimacy checkpoint needed |
</threat_model>
