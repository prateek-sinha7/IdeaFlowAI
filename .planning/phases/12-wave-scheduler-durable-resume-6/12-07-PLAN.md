<objective>
Close the FE half of CR-06 (worker leaves never render), CR-05 (non-wave events duplicated on
reconnect), and the file-adjacent warnings WR-03 (FE replay/dedup/wave state never reset per run)
and IN-05/IN-06 (cancelled bucketed as pending; wave groups keyed by waveIndex alone).

This plan DEPENDS ON 12-06, which stamps `wave_index` + `step` onto the `subagent_spawned`/
`subagent_result` events. Without that backend contract the FE guard has nothing to fold; with it,
this plan makes the FE consume the new fields correctly.

- CR-06 FE half: `page.tsx:222` guard `if (waveIndex === undefined) return;` drops every subagent
  event (they now carry wave_index after 12-06, so the guard passes — but the worker-leaf keying at
  page.tsx:255 `group.workers.find((wk) => wk.agent === agent)` collapses N same-agent workers into
  ONE leaf whose status flaps; `sample_wave` produces exactly this self×N shape). Key leaves by the
  `worker` index instead.
- CR-05: the FE `event_id` dedup is scoped to the `WAVE_EVENT_TYPES` branch only (page.tsx:215-218).
  The FE now sends `after_seq` on EVERY reconnect (DashboardLayout always includes it), so the backend
  replay branch is always entered; persisted-but-not-yet-drained events satisfy `seq > after_seq` and
  are delivered TWICE (replay loop + re-attached drainer). Every non-wave event (agent_chunk, tool_call,
  task_progress) flows undeduped into the legacy handlers — visibly duplicating streamed text on reconnect.
- WR-03: `lastSeqRef`, `seenEventIdsRef`, `waveGroups` are module-lifetime refs/state with NO reset on a
  new run. After run 1 reaches seq 500, run 2's events (seq 1..) never advance `lastSeqRef`, so a
  reconnect during run 2 sends `after_seq=500` → backend replays nothing → silent hang. `waveGroups`
  from the previous run also bleed into the next run's panel; `seenEventIdsRef` grows unboundedly.
- IN-05: `statusKind` (WaveTreePanel.tsx:34-42) buckets `cancelled` as `pending` (grey) instead of terminal.
- IN-06: wave groups keyed by `waveIndex` alone collide across two wave_scheduler steps; key by `step:waveIndex`.

Purpose: make the wave/subagent tree actually render its worker leaves, make durable reconnect
idempotent for ALL event types, and reset per-run state so reconnect works for every run after the first.

Output: a small pure dedup/reset helper module (`wsReplayState.ts`) with a vitest unit test proving
dedup-before-routing and per-run reset; event_id dedup hoisted to the top of the message handler (all
types) via that helper; per-run reset of the three refs/state; worker leaves keyed by worker index;
wave groups keyed by step:waveIndex; cancelled rendered terminal.
</objective>
