<objective>
Land the durable resume tier. (1) WS `reconnect_pipeline` gains an `after_seq` branch that replays
missed `run_events` (`seq > after_seq`, owner-scoped, idempotent by `event_id`) BEFORE attaching to
the live queue — and when the process was restarted (no live task) the replayed tail plus the run's
current status is the complete response. (2) `restore_non_terminal_runs` becomes a three-way startup
classifier: `waiting_for_user` re-arms its resume event (unchanged); a resumable in-flight run is
re-driven IN-PROCESS via a new `resume_run(run_id)` that rebuilds `ExecutionContext` (re-compile via
`compile_for_run` + the same rebind sequence) and re-enters the SAME per-step dispatch loop at the
first incomplete step (mid-wave via terminal `wave_runs`/`subagent_runs` rows + fragments); anything
else keeps the WR-05 abandoned->failed path verbatim. No forked execution path (INV-12).

Purpose: RESUME-03, RESUME-04, and WAVE-03 (mid-wave resume). The completed-step reuse leans on the
12-02 content-hash key; completed waves/workers are skipped via the 12-01 durable rows + Phase-11
fragments-persist-before-merge.

Output: the `after_seq` replay branch, the `resume_run` entry + three-way `restore_non_terminal_runs`,
and the reconnect + restart-simulation tests — with the 5 characterization snapshots byte/event-identical.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| reconnecting user → run_events replay | A user may only replay THEIR run's events (V3 session / V4 access control) |
| startup classifier → resumable run | Resume must not double-drive a run or resume a non-owned run |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-03-IDOR | Information Disclosure | `reconnect_pipeline` after_seq replay | mitigate | The replay reads `ScopedStore(owner_id=<reconnecting user>).read_events(...)`, so a cross-owner reconnect resolves to ∅ — a reconnecting user can only replay their own run's events (the existing websocket IDOR mitigation pattern); `after_seq` is int-coerced (non-int rejected, never reaches raw SQL) |
| T-12-03-DOUBLEDRIVE | Tampering / DoS | startup resume classification | mitigate | Classification runs ONCE at startup (single-process v1); the run is stamped with the resume marker BEFORE `asyncio.create_task(resume_run(...))` so a crash-during-resume is itself resumable and the same run is not driven twice; duplicate `wave_runs`/`subagent_runs` rows are the warning sign the restart test guards against |
| T-12-03-CROSSNODE | Tampering | distributed resume | accept | Cross-process / multi-node resume locks are explicitly OUT of scope this phase (single-node startup-only classification, N8 v1); documented as a deferred idea |
| T-12-03-RESUMESCOPE | Elevation of Privilege | resume_run principal | mitigate | `resume_run` rebuilds the ExecutionContext via the SHARED builder so the resumed run carries the SAME owner/workspace as the original (new artifacts get the original owner_id — Pitfall 2 warning sign guarded); no privilege drift |
| T-12-03-SC | Tampering | npm/pip/cargo installs | mitigate | Zero external packages added (in-process `asyncio.create_task` resume; durable reads via the existing ScopedStore). INV-13 banned-pattern gate unaffected |
</threat_model>
