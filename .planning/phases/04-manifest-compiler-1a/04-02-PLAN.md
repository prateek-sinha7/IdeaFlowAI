## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo file -> manifest loader | `workflow.yaml` is repo-authored but parsed by code; untrusted-by-shape YAML crosses into typed dataclasses |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-03 | Tampering / EoP | YAML deserialization (`load_manifest`) | mitigate | Use `yaml.safe_load` ONLY (never `yaml.load`/`FullLoader`) — prevents arbitrary-object construction RCE. Asserted by `test_safe_load` + source grep (ASVS V5). |
| T-04-04 | Tampering | DSL/expression injection via manifest keys | mitigate | Strict-key rejection: `set(data) - _ALLOWED_TOP_KEYS` raises `ManifestValidationError`; a `when:`/`if:`/`for:`/`${}` field has nowhere to live (INV-5 / D-08). No `eval` anywhere. |
| T-04-05 | Information Disclosure | validation error message | accept | Error names the offending field/key only (repo-authored config) — no secret/PII surface; this is the required MAN-01 behavior. |
| T-04-SC | Tampering | pip installs | accept | No new packages — `yaml` 6.0.3 + `python-frontmatter` 1.1.0 already installed (RESEARCH Package Legitimacy Audit). |
</threat_model>
