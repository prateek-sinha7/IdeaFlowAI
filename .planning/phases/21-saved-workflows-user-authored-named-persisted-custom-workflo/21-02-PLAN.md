<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser composer → createUserWorkflow → /api/user-workflows | the user-entered name + the composer's composition cross into persistence (server re-validates, plan 21-01) |
| catalog "Your workflows" → rename/duplicate/delete | mutations target only the caller's saved rows (server owner-scopes; FE shows only `source="user"` rows) |
| FE render of saved `name` | a stored name is rendered as a row label |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-06 | Spoofing / Information Disclosure | api.ts CRUD fetchers | mitigate | every fetcher sends `authHeaders(token)` (copied from the `admin*` analogs); the server owner-scopes (21-01) — the FE never receives another user's rows. |
| T-21-07 | Elevation | kebab Rename/Duplicate/Delete on built-in rows | mitigate | the kebab is rendered ONLY on `source="user"` rows; built-in manifest rows stay read-only (UI-SPEC §4). Even if a user forged a request, the server filters `source=='user'` → 404 (21-01 T-21-01). |
| T-21-08 | Information Disclosure (XSS) | rendering the saved `name`/`description` | mitigate | React escapes text content by default; the label is plain text (no `dangerouslySetInnerHTML`), matching the existing catalog/history rows — no raw HTML injection surface. |
| T-21-09 | Tampering | Save payload (base_pipeline_type/agent_ids/model_overrides) | mitigate | the FE sends the composer's own state; ALL validation/authority is server-side (21-01 T-21-02/03) — the client is never the security boundary. |
| T-21-SC | Tampering | npm installs | mitigate | no new npm packages (reuses framer-motion/lucide-react/@testing-library already present); no package-legitimacy checkpoint required. |
</threat_model>
