<objective>
Deliver the in-lane gate/clarify quick-actions (CHATUI-02) as standalone, presentational, callback-driven components that MIRROR the existing Steps panels (`ReviewGatePanel`, `QuestionnairePanel`) through the SAME backend channel — so a user can approve/answer from the chat lane OR from Steps, one `approve_review` / one `submit_questionnaire` either way (LIVE-STATE-CONTRACT §1).

Purpose: The live-state contract requires gate approve/redo and clarify answers to be reachable inline in the chat lane. This plan builds the compact in-lane surfaces WITHOUT re-implementing the backend channel — they take the same callback props the current full-panel overlays already receive. It carries the four post-merge gate behaviors: the FOURTH `update_specs` action (KAN-101), the terminal fence that hides actions post-terminal (KAN-100), and the client-side retained gate edit (KAN-98, since the backend never echoes edits over WS). Event-driven gates (KAN-94): the actions render only when a gate actually fired.
Output: `InlineGateActions.tsx`, `InlineClarifyActions.tsx` + suites. Mounted into the lane by plan 04.
</objective>
