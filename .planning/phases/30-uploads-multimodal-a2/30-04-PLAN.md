<objective>
Build UPLD-04 (client-side image resize) and the ND-10 frontend disposition (the honest
"image not retained" placeholder on reopen).

UPLD-04: today the attach UI (`IdeaInputPage.tsx`) reads an image File straight through
`FileReader.readAsDataURL` → base64 → the out-of-band `images` payload. A single full-res phone
photo can approach the per-image cap. Add a client-side canvas downscale BEFORE base64 so
attachments are pre-shrunk (better UX, fewer server rejections). The server caps
(`_validate_images`) remain authoritative — this is a client optimization, not a trust boundary.

ND-10 (LOCK-E): image persistence for reopen/replay is DEFERRED. The backend already stamps
chat-turn image attachments `retained: false` with no bytes. The honest frontend behavior is a
visible "image not retained" placeholder where a reopened run once had an image — NOT a broken
`<img>` and NOT durable image storage.

Purpose: right-sized uploads + an honest reopen surface, no persistence build.
Output: a `resizeImage` helper wired into the attach flow, and the not-retained placeholder in
the run-inputs card.
</objective>
