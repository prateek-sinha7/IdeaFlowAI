<objective>
Build UPLD-03: a new `context_provider:uploaded_files` capability that surfaces the text
extracted from a run's uploaded documents (staged under `.uploads/` by 30-01) as STICKY
context — present in every subsequent `agent_input` for an opted-in workflow — while the raw
bytes remain agent-`read_file`-able in the sandbox.

Critical SC-001 property: this works with ZERO engine edits. The engine's existing
`_compose_context_message` already loops `compiled.context_providers` and calls
`registry.resolve("context_provider", name).load(ectx)` under the per-agent `injects:` gate
(same path opendesign/repo ride). So opting a workflow in = manifest `context_providers:
[uploaded_files]` + agent `injects: [uploaded_files]` — no kernel change. That is the whole
point of the decoupled runtime.

Purpose: uploaded documents become durable launch/steering context any agent can lean on.
Output: the kernel-pure provider, its registry lockstep (with the drift-guard count bump), and
an end-to-end sticky proof.
</objective>
