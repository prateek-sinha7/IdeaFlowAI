<objective>
Build UPLD-01: a REST endpoint that lets a run's owner attach documents/files to an
in-flight (or reopened) run. Uploaded bytes land in the run's on-disk `RunSandbox` so
agents can `read_file` them, and extractable documents (pdf/docx/pptx) are text-extracted
at ingest and persisted to a reserved sidecar that 30-02's `uploaded_files` context
provider surfaces as sticky context.

Per POR §2 (D-07, amended): only DOCUMENTS go to the sandbox — images stay
payload-transient (already built; per-turn images are 30-03). This endpoint is
documents-only.

Purpose: give runs a durable, owner-scoped file-ingress surface without a new table
(sandbox + reserved prefix cover it — additive, no migration per Q3).
Output: `POST /api/runs/{id}/files`, a reusable extraction helper, a reserved
`.uploads/` sandbox prefix that never pollutes the deliverable, and tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → POST /api/runs/{id}/files | untrusted multipart upload (filename, mime, bytes, run id) crosses here |
| endpoint → RunSandbox disk | attacker-influenced filename/size reaches the run's disk dir |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-30-01 | Information disclosure | run ownership (IDOR) | mitigate | two-layer owner check (WorkflowRun.user_id ORM filter → 404, then default-deny ScopedStore.get_run → 404); never 403; user_id not nullable owner_id (P13/P25 precedent) |
| T-30-02 | Denial of service | multipart upload size | mitigate | per-file 10 MB cap (file_extract._MAX_FILE_BYTES), document-count cap (<=20), aggregate byte cap — all rejected (413) BEFORE any sandbox write |
| T-30-03 | Tampering | path traversal via filename | mitigate | every write goes through RunSandbox.path_for (separator-aware is_relative_to containment); reserved `.uploads/` prefix under the per-user/per-run root |
| T-30-04 | Tampering | mime/type smuggling (exec/image as doc) | mitigate | ext allow-list {pdf,docx,pptx,txt,md,csv,json} → 415 on miss; image mimes explicitly rejected (payload-transient path is 30-03) |
| T-30-05 | Information disclosure | uploaded doc leaking into the deliverable | mitigate | `.uploads/` prefix excluded from serialize_sandbox_deliverable/count (dormant on goldens, INV-3) |
| T-30-SC | Tampering | npm/pip/cargo installs | accept | no new dependencies — pypdf/python-docx/python-pptx already present (file_extract); no install task |
</threat_model>
