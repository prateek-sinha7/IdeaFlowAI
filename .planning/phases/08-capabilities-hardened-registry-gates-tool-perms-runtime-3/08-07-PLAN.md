<objective>
Stand up the executable `HookHandler` framework (D-09): bind executable hooks to lifecycle/tool-call events (`before/after_run·step·tool_call·write`, `post_task`, `pre/post_commit`, `on_validation`, `before/after_merge`, or `*`) with outcome `continue|warn|block` (blocking hooks halt the offending action) and permission gating (scanner→`read_files`, git→`git`, command→`exec`; a hook lacking its permission is not bound). Land the two LIVE canonical hooks: `secret_scan` (`before_write`/`pre_commit`, blocking, `read_files`) and `otel_tracing`/logging (`*`, non-blocking → OpenTelemetry-style spans/logs, OBS-02). Git-/exec-needing hooks are registered + permissioned but do NOT fire (git=P9, exec=P10). Every firing writes a `hook_runs` row (using the `0016` table from 08-02). The legacy prompt-only hook is the `behavioral` non-executable sub-type (shared with 08-05/F3 — `hooks/__init__.py` already declares the `behavioral` provider; this plan adds the executable sub-type alongside it).

Purpose: HOOK-01..04 + OBS-02 — hooks become executable + persisted; secret_scan is the fine-grained complement to the coarse security gate; otel_tracing delivers §23 observability. Hook firing must NOT leak events into the existing snapshots.

NOTE: OTel is an [ASSUMED] external dependency (no OTel in the tree). Task 2 gates the install behind a blocking human checkpoint OR ships the logging-only span fallback (no new dep) — Claude must NOT silently add the dependency.
Output: the HookHandler framework + firing points, secret_scan + otel_tracing canonical hooks, hook_runs persistence, and the hook tests.
</objective>
