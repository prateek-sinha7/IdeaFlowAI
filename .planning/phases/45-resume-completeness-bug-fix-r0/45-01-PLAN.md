<objective>
Fix ONE root-caused engine data-loss bug: `_first_incomplete_step` (`engine.py:5909-6007`) classifies a task-granular build step COMPLETE as soon as its FIRST per-task artifact persists — the disjunct at `engine.py:6002` (`if agent_id in produced_agents or agent_id in completed_step_events: continue`). `persist_task_html` (`kernel_services.py:1313-1339`) dual-writes an `html_file` `artifact_ref` with `producer_agent=<build agent>` after EVERY task, so `produced_agents` contains the build agent from task 1 onward; a run that crashes mid-build (task N of M, N<M) resumes with a resume offset PAST the build step -> the build is silently skipped -> truncated deliverable = real data loss on the live auto-resume path (`restore_non_terminal_runs` branch (b) -> `resume_run`).

Make completeness STRATEGY-CONDITIONAL, keyed generically on the compiled `step.strategy` / `step.task_source` (per D-locked POR §5.4/§6-R0): for `strategy == "task_loop"`, a step is complete only when `distinct(task_id for artifact_refs where producer_agent == agent_id) >= expected_total` (or a durable `step_completed`/`step_reused` event exists); `single_shot` keeps the existing disjunct byte-unchanged; `wave_scheduler` keeps its existing branch untouched. Fail-safe direction on any uncertainty is INCOMPLETE (re-run) — never skip. Prove it with a RED->GREEN restart-resume regression.
