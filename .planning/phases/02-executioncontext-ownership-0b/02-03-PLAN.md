<objective>
Add the explicit parent-run ownership check (CTX-03 / L16 / INV-8): a small, pure `assert_owns(...)` helper (candidate home `backend/agents/execution_engine/authz.py`) that raises a typed denial (`PermissionError`) when the run's `owner_id` does not own the `parent_run_id` it is seeding from. Insert the call at the `parent_run` seed block in `execute()` **BEFORE** the existing graceful-degrade `try/except` (D-07), so a cross-owner parent **raises and propagates out of `execute()`** (NOT swallowed), while a legitimate same-owner missing/TTL-swept parent still hits the graceful-degrade and proceeds unchanged. Add a cross-owner denial test (the L16 CHECK), a same-owner graceful-degrade test, and an anon-principal test. Record the L16 row in the ledger with its denial test. Zero behavior change on existing paths (CTX-05) — cross-owner is a brand-new path no 0A snapshot exercises, so raising is not a CTX-05 violation.

Purpose: This closes the L16 unenforced-ownership leak — the one substantive security fix of Phase 0B (an owner could implicitly seed from another owner's run sandbox). The helper is sited small/pure so Phase 5's store-layer scoped-query helper (AUTHZ-02) RELOCATES it as a move, not a rewrite (D-06 / INV-12).
Output: `authz.py` (`assert_owns` + denial exception), an inserted ownership check in `engine.py`, a denial test file, and the L16 ledger row recorded; 0A suite green.
</objective>

| caller (owner A) → parent_run owned by owner B | A revision run seeds spec.md/design.md/tasks.md from a `parent_run_id`; without an explicit check, owner A can read owner B's run sandbox (the L16 leak / INV-8 violation). |
