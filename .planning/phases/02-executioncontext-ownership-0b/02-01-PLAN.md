<objective>
Introduce a per-run `ExecutionContext` value object (new `backend/agents/execution_engine/context.py`) carrying the D-01 minimal field set, construct it once inside `execute()`, relocate every per-run `self._*` write off the `ExecutionEngine` singleton onto that context, and thread the context explicitly through the six read-site methods. After this plan the kernel singleton holds only its three construction-time singletons (`_resolver`, `_store`, `_state_machine`) and no per-run state — satisfying CTX-01 (state lift / L14) and CTX-02 (NFR-001 statelessness), with zero behavior change (CTX-05).

Purpose: This is the central strangler increment of Phase 0B. It removes the singleton-mutation concurrency hazard (INV-2) that blocks the fan-out/wave phases, and lays the `ExecutionContext` seam every later phase grows fields onto.
Output: `context.py` (`ExecutionContext` dataclass) + a refactored `engine.py` whose `execute()` and call tree thread an explicit `ectx` parameter; the L14 grep returns 0; 0A snapshots stay green.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → execute() | The WS layer passes `user_id` (owner principal) + run params; `execute()` is the kernel entry. |
| engine singleton ↔ concurrent runs | The `ExecutionEngine` is a process-wide singleton; concurrent/fan-out runs would share any per-run state left on `self` (the INV-2 hazard this plan removes). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | per-run state on the shared `ExecutionEngine` singleton (`self._od_context`/`_completed_tasks`/`_revision_*`/`_user_id`/`_checkpointer` etc.) | mitigate | Relocate ALL per-run state onto a per-run `ExecutionContext` threaded explicitly (D-03); after this plan no run mutates the singleton, so concurrent runs cannot read each other's `od_context`/owner/completed-tasks. Verified by the L14 grep → 0 and the statelessness grep (only `__init__` assigns instance attrs). |
| T-02-02 | Tampering | a later run overwriting an earlier run's `self._revision_*`/`_current_task_block` mid-flight (race) | mitigate | Same fix: run-scoped `ExecutionContext` instances are independent; no shared mutable run state remains on the kernel. |
| T-02-03 | Tampering | regression of behavior during the state move (silent deliverable/event drift) | mitigate | The Phase 0A characterization suite (`tests/agents/test_characterization_*.py` via `_scripted_model._drive`) is re-run as a blocking acceptance check — deliverable byte-snapshots identical + semantic event parity + `seq` contiguous (CTX-05). |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No new package installs in this plan (stdlib `dataclasses` only); no RESEARCH.md package-legitimacy audit required. |
