<objective>
P1 — THE CRUX (D3). Today `engine._apply_selections` (`engine.py:6194-6274`) overlays only `validators`/`gates`/`model`/`retry`/`injects` and DROPS `strategy`/`fanout`/`task_source`, so a composed fan-out selection never reaches the run plan. And any composed agent ABSENT from the base manifest (the COMMON case for `custom`, since `allowed_custom_agent_ids` unions all base agents) is run as a bare `single_shot` at the synthesis site (`engine.py:2285-2292`), never receiving an overlay. Fix BOTH sites:
1. Add three guarded patch lines carrying `strategy`/`fanout`/`task_source` (each fires only when the user selected it → empty path byte-identical).
2. Change `_apply_selections` to accept the run's agent ids, widen its trust-compile synth set to cover EVERY run agent, and RETURN the trust-compiled user-step map at all three exits; thread it from the single live caller (`engine.py:1463`) and consult it at the synthesis site before falling back to bare `single_shot`.

Purpose: Nothing fans out without this. This is the make-or-break, highest-care kernel change under strict byte-parity (INV-3). It reads `user_step.strategy`, which is populated only because 51-01 (P2) now emits it — hence the dependency.
Output: Extended `_apply_selections` + updated caller + synthesis-site consult in `engine.py`; engine unit coverage.

Implements FANOUT-02 (the crux) and FANOUT-06 (invariants). Per decision D3. Do NOT overlay `tools`; do NOT add steps to `compiled.steps` (membership assertion at engine.py:1701-1714 would raise).
</objective>
