<objective>
Close ISS-017: the FE Preview shows the neutral "Output will appear here" empty-state for a TERMINAL run with no content — no degraded/failed affordance. This is the FE face of ISS-016: ISS-016 (Plan 01, BE) makes the run TELL the truth (`pipeline_failed`/`status:degraded`); ISS-017 (this plan, FE) makes the FE SHOW the truth.

Root cause: `PreviewPanel.tsx:205` computes `hasContent`; `:291-294` renders the neutral empty-state whenever `!hasContent`. `page.tsx:359` only sets content when `final_output` is truthy (empty → no content), and the history-reopen gate (`handleSelectWorkflowRun`, ~:1006) only sets content when `fullRun.status === "completed"` — so a failed run sets no content and the panel shows the neutral placeholder. The only non-success affordance keys on a server `degraded` flag the empty run never carried.

Fix: when the run is TERMINAL (not streaming) AND `!hasContent`, render a degraded/failed affordance instead of the neutral empty-state — keyed on the SERVER signal: on the live path the `pipeline_failed`/`status:degraded` that ISS-016 now produces (surfaced by `useWorkflow.ts` — `agent_error`/`pipeline_failed`/degraded handlers); on the history-reopen path the persisted `fullRun.status` (`failed`/`cancelled`). Show failed-agent names + a "view details"/retry hint when present.

Per CONTEXT A2: REJECTED hack — a purely client-side `if (terminal && !finalOutput) show "failed"` with NO server signal — re-creates the IN-03 FE-vs-DB disagreement (the run may be `status:completed` in the DB), mislabels a legitimately-empty deliverable, and treats the symptom not the disease. The truthful signal must come from the server. ISS-017 cannot be fully right without ISS-016 — but this plan is FE-only and runs in parallel (Wave 1); it consumes the server signal that Plan 01 (BE) emits and that `useWorkflow` already surfaces (`degraded`) plus the additive `failed` flag this plan adds to the `pipeline_failed` handler.

Purpose: a stopped/failed run must show a failure affordance, not success chrome + an empty canvas.
Output: the additive server-signal `failed` flag on PipelineRunState + the terminal-empty affordance (live + reopen) + a component test.
</objective>
