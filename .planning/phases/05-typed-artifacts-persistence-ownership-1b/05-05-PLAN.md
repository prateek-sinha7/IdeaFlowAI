## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client → /api/runs/{id}/artifacts|events | Untrusted `{id}` + `after` query cross into the read path; another owner's run must not be readable, and `after`/`{id}` must not reach raw SQL. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5-IDOR | Information Disclosure / Elevation | both new GET handlers | mitigate | Both resolve the run via `ScopedStore.get_run` (owner-scoped); cross-owner/missing → 404, never 403 (no existence leak — runs.py:14–17). Task 2 tests assert cross-owner 404 on both (Highest-Risk Behavior 2). |
| T-5-SQLI | Tampering | `{id}` path + `after` query | mitigate | `{id}` flows into ORM `.filter()` (parameterized, not interpolated); `after` int-coerced (`after: int`) before use (RESEARCH Security Domain V5). |
| T-5-REPLAY | Tampering | `/events` replay | mitigate | Read-only, owner-scoped; rows carry idempotent `event_id`; `seq > after` ascending is deterministic (API-05). |
| T-5-CONTENT | Information Disclosure | inline `content` on `/artifacts` | mitigate | `content` excluded by default; only returned under explicit `?include=content` for the same owner (D-10) — reduces incidental exposure of large artifact bodies. |
| T-5-SC | Tampering | npm/pip/cargo installs | accept | No packages installed this phase (RESEARCH Package Legitimacy Audit — N/A). |
