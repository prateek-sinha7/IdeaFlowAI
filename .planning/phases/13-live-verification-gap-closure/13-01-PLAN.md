<objective>
Close UAT Gap 1 (finding F1, major): a manifest-declared `gates: [human]` step currently
consumes the entire `run_human_gate` delegate generator INSIDE `HumanGate.evaluate`
(collecting events into a list) and `_evaluate_gates` yields the collected events only
AFTER the gate resolves — so `review_gate_ready` reaches the WS consumer only after the
gate was already unblocked. A real UI run hangs at the first declared gate with no signal.

Fix: make declared-gate evaluation STREAMING — gate events flow to the dispatch loop
(and thus the WS consumer) the moment the delegate yields them, exactly like the working
legacy inline `_should_gate` → `_run_review_gate` path which yields ready pre-await.

Purpose: ROADMAP Phase 13 success criterion 1 — a UI client can see and approve a declared
human gate; prototype-family runs from the UI no longer hang at specify.
Output: streaming `evaluate_stream` on HumanGate + ApprovalGate, a streaming-aware
`_evaluate_gates`, and a handler-driving regression test.
</objective>
