<objective>
Close ISS-005 (`app-infra-generator` ignored its own `/api/v1` rule live) with a DETERMINISTIC backstop. The `/api/v1` standard lives only as prose in 3 AGENT.md bodies — zero code enforcement. Add a pure-stdlib `api_prefix` `Validator` capability (modeled verbatim on `spec_plan_coverage.py`) and wire it as an EVENT-FREE `post_step` on the app_builder infra-generator step, so it flags infra endpoints lacking `/api/v1` and writes a `validation_results` audit row WITHOUT adding any event to the run.

Purpose: a prompt is a flaky enforcement mechanism; a registered, declared validator is deterministic. The INV-3-CRITICAL decision is event-free post_step (NOT a `gates:[validation]` gate — the validation gate emits a `validation_warning` event → the 85-event app_builder golden has no such event → breaks parity). Prove both directions: event-free passes; gate-wired fails.

CRITICAL two-surface rule for registration: `registry.py` has TWO independent surfaces that BOTH must learn the new capabilities, or the failure is latent and only fires at runtime:
  (a) the `_KNOWN` literal set — the compiler's `is_registered` membership check (`compiler.py:384`). Adding the pairs here makes the compiler ACCEPT the manifest.
  (b) `discover()`'s `_builtin_modules` import tuple — what actually triggers `@register` at import → populates `_IMPLS`, which `resolve()` reads at runtime (called from the engine post_step seam at `engine.py:~1720` during the app_builder run). Adding the module paths here makes `resolve()` RETURN AN INSTANCE instead of raising `RuntimeError("known but has no bound impl")`.
Updating ONLY `_KNOWN` (the original blocker) makes the compiler pass but leaves `_IMPLS` empty → `resolve("post_step","api_prefix_audit")` raises at execution. BOTH surfaces must be updated together.

Output: a new validator module + a post_step shim module + their registry entries on BOTH surfaces + the manifest wiring + a unit/fault-injection test.
