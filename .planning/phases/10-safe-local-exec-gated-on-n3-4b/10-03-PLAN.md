<objective>
Build the GATE layer (tier 2 of 3) and wire the runtime workspace into the live run path (RESEARCH Pitfall 1 — first-class, not a footnote).

1. SecurityGate (profile-conditional pass): split the exec branch from network/secrets. A file/builtin-trust exec step with the `approval` gate declared (D-01 defense-in-depth) + a constrained profile PASSES; network/secrets still BLOCK (out of scope).
2. ApprovalGate (HITL delegation + first-exec memory): replace the bare `wait_human` stub with the human-gate delegation pattern — route through `ctx.runner.run_human_gate` -> engine `_run_review_gate` (the ONE durable HITL mechanism, D-02) with the D-04 policy-snapshot payload; short-circuit to silent PASS when a prior approval-pass `gate_events` row exists (D-03, durable, no new state).
3. §15 host seam: `engine.execute()` today only calls `scoped_store.create_workspace` (DB row); the runtime_env workspace is registered but never bound and `KernelServices` has no `workspace`. When the compiled plan grants exec, resolve `("runtime_env","local")`, call `create_workspace(exec=True, recorder=record_exec_run)`, bind onto `KernelServices.workspace` so validators reach it via `target.runner.workspace`.

Purpose: closes EXEC-01's GATES requirement + the runtime_env-not-wired finding. Every new behavior is gated on exec-granted so the 5 snapshots stay byte/event-identical (Pitfall 3).

Output: profile-conditional security gate; approval gate on the durable HITL machinery with first-exec memory; parameterized `run_human_gate`; `read_gate_events` handle; live workspace binding.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| compiled exec step -> security gate decision | The gate is the runtime second line after the compiler; exec passes only with profile + approval declared |
| human approver -> exec authorization (HITL) | First exec per run requires durable human sign-off; the pause survives restart (checkpointer + gate_events) |
| ctx.runner handle -> engine HITL / gate_events read | Capabilities reach the durable pause + the approval memory only via the runner handle (import purity) |
| engine run entry -> runtime workspace binding | The §15 host seam is the only place the exec-enabled workspace is provisioned, conditional on the plan granting exec |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-03-01 | Elevation of Privilege | exec request passing the gate without human sign-off | mitigate | first-exec-per-run approval pause (D-02) via the durable `_run_review_gate`; reject -> block (per N3: security + approval, stricter than security-only) |
| T-10-03-02 | Elevation of Privilege | network/secrets request slipping through the loosened exec branch | mitigate | network/secrets BLOCK path kept byte-identical; only the exec branch is split to a conditional PASS |
