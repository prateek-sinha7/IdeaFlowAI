<objective>
Add per-child task identity to `subagent_runs` so a crashed fan-out/wave run can, on resume, tell which workers already completed. Three layers plus one thread plus the ORM ctor: migration 0026 (nullable `task_id`/`worker_index`), the ORM columns, the `ScopedStore`→`KernelServices` delegate kwargs, the `fanout.py` spawn-time stamping, and the `wave_scheduler.py` request-build that carries the plan-global `t.id`.

This is the foundation the RESUME-09 skip cursor (Plan 46-04) reads from. Rows are written **at spawn** — before the crash window — following the `selections_json`/0023 persist-at-creation precedent.

Purpose: unblock identity-based per-worker resume skip (the CR-03-followup the 12-06 `wave_scheduler:207-214` comment explicitly waits on).
Output: migration 0026, two ORM columns, the two-optional-kwarg threading across `authz.py`/`kernel_services.py`/`fanout.py`, the `wave_scheduler.py` request thread, and reversibility + spawn-identity tests.
</objective>
