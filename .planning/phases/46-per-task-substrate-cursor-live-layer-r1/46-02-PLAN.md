## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| kernel → durable store | sibling `file_bundle` writes cross into Postgres via the run's own owner-scoped `ScopedStore` (default-deny, `user_id`-keyed) |
| sandbox disk → durable capture | the post-task walk reads files the agent wrote into the run's own `RunSandbox` (traversal-proof `path_for`; `.uploads/` excluded) |

No new endpoint/auth surface. The walk reads only THIS run's sandbox root; the write goes through the same `_dual_write_artifact` path prototype already uses.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-46-02-01 | Information disclosure | capturing an out-of-scope file (uploads / another run) | mitigate | Walk is rooted at `self.sandbox.root` (this run's dir only) via the traversal-proof `RunSandbox`; `_collect_deliverable_relpaths` excludes `.uploads/` (Phase-47 surface) and images are never written by the deliverable path (ND-10) |
| T-46-02-02 | Tampering | dedup mis-key overwriting a prior task's ref | mitigate | Dedup compares content_hash for the SAME `location`; each write is a monotonic new version keyed on `(run_id, kind)` — prior versions retained (immutable artifact_refs), latest wins at re-materialization |
| T-46-02-03 | Denial of service | runaway versions from unchanged siblings | mitigate | Content-hash dedup: an unchanged sibling writes nothing; a task that touched no new file writes nothing |
| T-46-02-04 | Elevation of privilege | scope widening via a cross-owner durable read for dedup | mitigate | The dedup read uses the run's own `ScopedStore`/graph (owner-scoped); no widening |
| T-46-02-SC | Tampering | npm/pip/cargo installs | accept | No new package installs; `file_bundle` reused (no vocabulary change) — no supply-chain surface added |
</threat_model>
