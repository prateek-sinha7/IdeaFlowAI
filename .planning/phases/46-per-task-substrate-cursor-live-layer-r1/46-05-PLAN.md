<objective>
Close the Phase-43 dormancy on resumed runs. Today `resume_run` calls `_execute_impl` DIRECTLY (`engine.py:6241`) with `_RunEventSink()` (no milestone_sink) + `itertools.count(start)` — it never threads `live_ectx_register`, never emits milestone cards, and has no `live_ectx_unregister` in its `finally`. So a resumed run is dead to steering, per-turn images, Concierge live context, and narrator cards. This plan makes a resumed run a first-class LIVE run by mirroring `execute()`'s callback threading (RESUME-10), and re-queues undrained steering notes at resume (RESUME-11).

- **RESUME-10:** three default-None engine hooks injected app-side (no engine→app import); `resume_run` uses `_RunEventSink(milestone_sink=...)`, replaces `itertools.count` with the DEF-43-03-1 advanceable counter + card emission, threads `live_ectx_register`, and unregisters in `finally`. Milestone-card seq drawn from the engine counter (0024 constraint) — never `append_event_next_seq`.
- **RESUME-11:** `_redrain_steering_notes(ectx)` re-derives undrained steering from durable `chat_message` rows whose `seq > max(agent_input.seq)`; no-loss (undrained survive), no-duplicate (drained have `seq < last_input_seq` → skipped).

This plan also SHAPES the callback seam the Phase-50 `POST /resume` endpoint will reuse (build now, consume in 50) — no endpoint here.
Output: the three hooks + main.py injection + the `resume_run` live-wire + `_redrain_steering_notes` + RED→GREEN tests (live-ectx-resolves + card-seq; steering no-loss/no-duplicate pair).
</objective>
