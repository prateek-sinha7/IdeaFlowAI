<objective>
Make resume skip completed work at task/worker granularity via a KERNEL-computed cursor — the CR-03-followup the `wave_scheduler.py:207-214` comment explicitly waits on, now unblocked by the Plan 46-01 `subagent_runs` identity. The kernel reads durable rows, computes the completed-identity set per step, and threads it into `strategy.run` through a dormant `ExecutionContext` field. The AGENT never decides the skip set; it still RECEIVES completed work as injected context (the existing `latest_typed_content` machinery, unchanged). Re-invocation of remaining work stays on the same `_run_agent`/`run_fanout` paths (INV-13).

- `task_loop`: skip completed task numbers (distinct `artifact_refs.task_id` for the step agent) instead of always looping from task 1.
- `wave_scheduler`: skip completed WORKERS within the first-incomplete wave (by `subagent_runs.task_id`) — identity-based, NOT the deleted-for-cause prefix-by-count skip (12-06 CR-03; that rationale is now satisfied because identity is durable). Terminal-completed waves stay skipped via the untouched `_completed_wave_indices`.

Purpose: turn Plan 46-03's correct-but-wasteful whole-wave re-run into an efficient per-worker skip, and add per-task skip for sequential builds — completed tasks/workers are never re-invoked.
Output: the dormant ectx field, the kernel-side compute + stamp, the two strategy skips, and RED→GREEN skip tests.
