<objective>
Add the missing disk half of resume. Today `_hydrate_artifacts_from_store` (`engine.py:5865-5907`) restores durable `artifact_refs` into the in-memory graph ONLY — the fresh `RunSandbox` on disk stays empty, so a resumed strategy re-reading the sandbox (e.g. the next task's skeleton read) sees nothing. Add `_rematerialize_artifacts_to_disk(ectx, sandbox)` next to hydrate that walks the latest durable file-backed refs (by `location`, `max(version)`) and writes their content back onto the sandbox BEFORE strategies re-enter — reconstructing worktree/sandbox state from `artifact_refs`, never from git.

Also close the mid-wave merge re-entry crash window: fragments already persist BEFORE the per-wave merge (`write_fragment_artifact`, `fanout.py:445-457`); if the process died between fragment-persist and merge, the wave's `wave_runs` row is still `running`. Re-materializing the in-flight wave's fragments to disk lets the EXISTING wave re-run (`wave_scheduler.py:243-262`) drive `run_fanout`→`_merge_fragments` over the recovered fragments — no second merge implementation.

Purpose: make resumed disk state faithful so the Plan 46-04 skip cursor can safely skip completed tasks/workers (their files are already back on disk).
Output: `_rematerialize_artifacts_to_disk` + the `:1350` hook + a re-materialization test + a mid-wave merge-re-entry test.
</objective>

No new endpoint/auth surface. The read is the SAME owner-scoped `store.tree(run_id)` hydrate already uses.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-46-03-01 | Information disclosure | a cross-owner row re-materializing into this run's sandbox | mitigate | The read is `ectx.scoped_store.tree(run_id)` — default-deny, keyed on the run's own `user_id`; a foreign row cannot appear in the result set → cannot reach disk (NO scope widening) |
| T-46-03-02 | Tampering | path traversal via a malicious `location` | mitigate | `sandbox.write` resolves through `path_for` which rejects any escape of the sandbox root; `.uploads/` is filtered out entirely |
| T-46-03-03 | Tampering | git treated as substrate (stale/ephemeral) | mitigate | Disk is reconstructed from `artifact_refs` ONLY, never from git (POR §3.2); worktree commits are ignored |
| T-46-03-04 | Denial of service | unbounded re-materialization | mitigate | Bounded by the run's own latest-version file-backed rows; per-row best-effort try/except; non-file kinds filtered out |
| T-46-03-SC | Tampering | npm/pip/cargo installs | accept | No new package installs — no supply-chain surface added |
</threat_model>
