## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI runner → event-snapshot test | False-green risk: a `_normalize()` that strips TOO much (e.g. drops `type` or required keys) would make the snapshot pass vacuously and miss a real event-vocabulary regression. No network/data/auth surface added. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering (false-green) | `_normalize()` over-stripping | mitigate | `_normalize()` KEEPS `type` + `_REQUIRED_DATA_KEYS` keys (presence asserted separately from the snapshot); volatile values become `VOLATILE_SENTINEL`, not deletion — so a dropped required key still fails the explicit required-keys assertion in Task 2. |
| T-02-02 | Tampering (false-green) | snapshot passing vacuously on empty events | mitigate | Task 2 asserts types ⊆ `_DOCUMENTED_EVENT_TYPES` and per-event required keys before comparing — an empty/garbage stream fails these before the equality check; 01-01 already asserts non-empty events. |
| T-02-03 | Tampering (false-green) | seq asserted by absolute value (brittle/meaningless) | mitigate | `assert_seq_contiguous()` asserts deltas == 1 (no gaps), explicitly NOT absolute values (SAFE-03) — robust across run-id changes yet catches a dropped/duplicated seq. |
| T-02-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs in this plan (test code only); no `[ASSUMED]`/`[SUS]` gate needed. |
</threat_model>
