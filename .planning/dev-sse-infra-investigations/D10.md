##### I3. Root cause — confirmed, corrected, or replaced

**Confirmed.** `SSE_STREAM_IDLE_TIMEOUT_SECONDS` has exactly one occurrence in all executable code
in the repository — its own declaration. `rg -uu 'SSE_STREAM_IDLE_TIMEOUT' .` returns 17 hits; 16
are Markdown (this dossier, the sibling investigations, four register/phase docs) and one is
`backend/app/core/config.py:133`. [V]

**The causal chain, independently re-derived:**

1. Phase 29-02 (`7020bf82`) designed the SSE down-channel and wrote a comment block describing two
   ops-facing constraints: the keepalive cadence must be short enough that an idle proxy never
   half-closes the stream, and the ingress must not buffer `text/event-stream`.
2. The first constraint is a *relation between two numbers*, one of which the application owns (the
   ping) and one of which the reverse proxy owns (the read timeout). The author expressed the
   ingress-side number as a Python constant so the relation could be read in one place.
3. `sse-starlette` accepts a `ping=` argument but has no idle-timeout parameter, and
   `_iter_sse_frames` blocks unconditionally on `await live_queue.get()` (`run_stream.py:197`, inside
   `while True:` at `:194`) — there is no `wait_for`, no deadline, nothing that could consume an
   idle-timeout value. [V] So the constant had no possible consumer at the moment it was written.
4. The keepalive made an application-side idle timeout unnecessary anyway, so nobody came back for
   it. Four register passes each judged it "harmless, opportunistic" and moved on.
5. The residual harm is exactly the comprehension cost the dossier names, and it is real: a reader
   of `config.py:119-133` sees an idle-timeout knob with a documented rationale and reasonably
   concludes the timeout story is handled in the application. It is not; it is handled in
   `infra/scripts/bootstrap-ec2.sh`, in a file the reader has no reason to open.

**Right for the right reason.** The dossier's "the ping was wired; the idle timeout was not, because
the keepalive made it unnecessary" is exactly correct, and I verified the mechanism it rests on:
`sse-starlette` runs the ping as an **independent concurrent task**, not interleaved with the body
generator — `sse_starlette/sse.py:221-246` is `async def _ping(...)` looping
`await anyio.sleep(self._ping_interval)` then sending, and `:262` starts it with
`task_group.start_soon(cancel_on_finish, lambda: self._ping(send))`. [V] That is why a stream parked
for minutes at a human review gate never goes idle on the wire, and therefore why no application
idle timeout was ever needed.

**Four corrections to the dossier's characterisation** — each one changes what a faithful

**C1 (material — it is the whole "is this safe to ship alone" question).** The dossier does not

##### I12. Shortcuts and alternatives explicitly rejected

**1. Wire it up instead of deleting it — the 29-REVIEW author's own first suggestion:**
`assert settings.SSE_KEEPALIVE_PING_SECONDS < settings.SSE_STREAM_IDLE_TIMEOUT_SECONDS` at startup.
**Rejected.** The assertion compares two Python numbers, and the number that matters is in
`/etc/nginx/sites-available/velocityai`. Nothing keeps the Python copy equal to the nginx value, so a
green assertion would certify a relation between the ping and a *fiction*. Concretely: after A1 the
real stream timeout becomes 5400s while the constant would still read 300 — the assertion passes,
having verified nothing, and now actively misleads. This is worse than the current state, because
today the constant is at least visibly inert. It also violates INV-12 by keeping a second expression
of an ops-owned value alive under the cover of a test.

**2. Enforce a real application-side idle timeout** — wrap the live drain in
`asyncio.wait_for(live_queue.get(), timeout=settings.SSE_STREAM_IDLE_TIMEOUT_SECONDS)`, the
"trivially enforceable in `_iter_sse_frames`" option `44-07-PLAN.md:112` left open. **Rejected as
actively harmful.** It would close a stream that is *legitimately* idle: a run parked at a human
review gate emits no events for as long as the human takes, and the whole point of the independent
`sse-starlette` ping task (`sse.py:262`) is that such a stream is healthy. A 300s cap would tear down
every gate-paused stream after five minutes, forcing a reconnect + full durable replay — and on a
97,694-event run (dossier A5) that replay is a 100 MB allocation. This turns a documentation defect
into a production regression. It would also need its own fail-before test, its own live proof, and
would collide with A2's fan-out rework.

**3. Delete the constant but leave the comment as-is.** **Rejected.** The comment's central sentence
is "the idle-timeout floor MUST exceed the ping", which reads as a statement about a knob the reader
can see. Remove the knob and the sentence becomes a dangling reference — the reader now hunts for a
setting that does not exist, which is a *worse* comprehension defect than the one this issue is
about. The dossier is right that the fold is part of the change, not optional tidying.

**4. Move the constant into a non-`Settings` module-level literal** (e.g. `INGRESS_IDLE_TIMEOUT = 300`
as documentation). **Rejected.** Same drift, one layer down, and now with no env override to even
pretend it is configurable. A citation to `bootstrap-ec2.sh:829` cannot silently hold a wrong value;
a literal can.

**5. Fold D10 into A1 or A2 because it is "the same file region / the same subsystem".**
**Rejected**, and the dossier rejects it first (`:1463-1465`). A1 and A2 are proven by a byte-diff of
concurrent SSE logs and a two-consumer pytest respectively. Adding a cosmetic settings deletion to
either dilutes what the reviewer is being asked to check, and makes the revert of a real bug fix drag
an unrelated comment rewrite with it.

**6. Skip the pre-flight SSM/`app.env` check because `extra="ignore"` makes it moot.** **Rejected as
a shortcut in reporting, though correct on the merits.** It is correct that the check cannot change
the decision. It is *not* correct to therefore claim the environment is clean — I could not observe
it, and the brief is explicit that an unobserved claim is `[I]`. The check stays in I5 as advisory so
someone can close the gap honestly rather than the report asserting a clean environment it never saw.

**7. Also fix the two out-of-lane findings in I11** (the stale `extra="ignore"` rationale at
`config.py:225-227`; the `class Config` deprecation at `:52`) **because we are already in the file.**
**Rejected.** The second one changes the exact mechanism this fix's safety argument depends on and
must carry its own proof. The first is a different sentence about a different setting. "While I am
here" is how a one-line deletion becomes a three-concern diff nobody can revert cleanly.

**8. Claim this fix also closes IN-02.** **Rejected as false.** Every register line pairs IN-01 with
