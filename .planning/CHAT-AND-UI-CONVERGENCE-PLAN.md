## 1. Goal

Chat becomes a **first-class lane on every workflow run** — the left column (~390px) of the redesigned run screen — in three modes: **pre-run composer** (refine brief conversationally), **mid-run steering** (interact with the running workflow), **post-run iteration** (conversational revisions in the same transcript). Plus: image upload (vision input), file/context upload (workspace + launch context, sticky for all subsequent agent calls), chat-history **compaction**, and the **run-screen redesign** to the Hexaware Run design (chat lane + Preview/Steps/Files/Audit tabs, drill-down Steps), followed by **shell convergence** (all remaining pages).

**Core constraint (inherited, non-negotiable):** zero kernel edits beyond one generic name-free seam; everything lands as registered capabilities + app-layer wiring (SC-001/INV-1); deepagents-only (INV-13); additive migrations only (Q3); the 5 characterization goldens stay byte/event-identical (INV-3); import-linter 4/0.

## 2. Locked architecture decisions

- **D-01 Transport & persistence.** New inbound WS message `chat_message` (`run_id`, `text`, `attachments[]`, client `message_id` idempotency) on the existing `/ws/chat`. Chat turns persist as `run_events` rows (new event types `chat_message`, `chat_reply`) through the single stamping boundary → seq ordering, `event_id` idempotent replay, owner+workspace default-deny, WS reconnect replay, and REST reopen (`GET /api/runs/{id}/events`) all inherited. **Zero new tables in v1.** Legacy `user_message`/`ChatRunner`/`Message`-table free-chat is untouched (frozen golden) — see ND-3.
- **D-02 Family-anchored chat.** The transcript spans the **run family**, not a single run. Each turn persists on the run active at that moment; the FE stitches the thread across parent/child runs via `GET /api/runs/{id}/family` (P25). Revisions announce in-lane ("v2 created — open in Preview →"); the version timeline stays authoritative.
- **D-03 Interaction model — one conversation with the run, three delivery classes.** (a) **Immediate** when paused (clarify answers, gate approve/reject/redo) — resolves the pause; (b) **next-dispatch steering** while agents run — honest UX: "queued — applies at the next step" (mid-generation injection is impossible: an agent invocation runs to completion); (c) **revision turn** when terminal → child run in the family. No per-agent DMs — agents are short-lived workers; the run is the durable counterpart.
- **D-04 Mechanical router first, Concierge as escalation.** A server-side app-layer router keys on run state: clarify_waiting → `set_questionnaire_responses`; gate_paused → `approve_review` (approve/reject/redo+instructions); running → steering note; terminal → `run_revision`. Zero model calls for routable turns. Free-form turns escalate to the Concierge (D-05).
- **D-05 Orchestrator = ONE implementation, per-run instances, per-workflow declaration.** A single `chat:concierge` registered capability (deepagents via the sanctioned `deep_agent_runner`, Haiku default, prompt-cached). Each run gets its own *instance* whose workflow-specificity comes from **context** (compiled manifest, artifacts, events, conversation) — never per-workflow code. Tools: **read** (run events/artifacts/steps via `ScopedStore`, owner-scoped) + **proposal-only** (`propose_steering_note`, `propose_revision`, `propose_gate_action`) — the app layer executes proposals through the same channels as the router, consequential ones behind a confirm chip. The Concierge proposes; the engine disposes. Optional per-workflow customization = declared manifest data (e.g. `chat:` key: suggestions, concierge notes), compiled as data (INV-5).
- **D-06 Steering seam (generalized Redo).** New consume-once `ectx.steering_notes` queue; `_compose_context_message` renders pending notes as a `=== USER GUIDANCE ===` block (exact `redo_directive` idiom, engine.py ~5916). **Sticky vs one-shot:** uploaded context persists for all subsequent dispatches; directives are consume-once.
- **D-07 Uploads.** `POST /api/runs/{id}/files` (multipart, two-layer owner check → 404). Images → `RunSandbox` + base64 blocks via the dormant `run_images` provider (flip its 3 switches: WS ingress passes `images=`; manifests declare `input_providers: [run_images]`; agents declare `injects: [images]` — all plumbing exists, verified). Documents → text-extraction (existing `/api/files/extract-text` internals) into sticky context **and** raw bytes into the sandbox for agent `read_file`. New `context_provider:uploaded_files` capability. Client-side image resize before upload. Launch-time attachments ride `run_pipeline` (extends the IdeaInputPage attach pattern to images).
- **D-08 Compaction is backend-owned.** New `compaction:chat_history` capability (summarize turns beyond budget, keep recent verbatim) + `context_provider:conversation` (reads chat `run_events`, compacted) for Concierge/steering contexts. deepagents `SummarizationMiddleware` covers in-graph growth. FE only displays token/context usage (P26 telemetry) + a "compact" affordance. Library research verdict confirmed: no frontend library provides compression; always backend.
- **D-09 No external chat framework.** Revive the in-repo dead chat kit (`src/components/chat/` — streaming bubbles, markdown, cursor, typing indicator, auto-scroll, edit/regenerate, working voice — raw Tailwind + motion, matching stack). Rejected: assistant-ui (would require LangGraph-server protocol — ELv2 `langgraph-api`, wrong shape for the kernel), AI Elements/shadcn kits (no Radix/shadcn base in repo), CopilotKit (CSS bleed, Cloud coupling), open-design wholesale (copy-only God-components, global-CSS model, daemon transport, path-based attachments, no voice, no gates, `od-*` brand collision). **Borrow from open-design (Apache-2.0, with attribution/NOTICE):** (1) `runtime/partial-json.ts` streaming-JSON repair (as-is); (2) `extractStreamingJsonString` live tool-arg previews; (3) tool-renderer registry pattern (registry → family card → generic fallback, try/catch isolated); (4) `buildBlocks` events→blocks coalescing reducer; (5) scroll/anchor engine + measured virtualizer (>80 msgs); (6) nonce'd deep-link-into-tabs seam (`onRequestOpenTab(tabId)` → `{name, nonce}` → `setActiveTab`); (7) `ThinkingBlock` + todo/plan progress + file-ops summary blocks; (8) `QuestionForm` as HITL form-rendering *pattern*. Anti-lessons: keep react-markdown (don't hand-roll a renderer); ship `aria-live`/`role="log"` on the streaming region from day one.
- **D-10 Reskin order.** Run screens first (Phase 32), shell after (Phases 36–38). Token layer + primitives precede any screen conversion.
- **D-11 Naming — the Catalogue fix (locked this session).** Nav becomes **Home · Library · My Workflows**. Home absorbs the launch role (hero + deliverable grid + recents — already true since P22 made the catalog the home landing). The saved-workflows page is labeled **"My Workflows"**. Component rename: `WorkflowCatalog.tsx` → `HomeLaunchGrid.tsx` (it IS the home launch grid); `SavedWorkflowsPage.tsx` stays. The word **"Catalogue" is reserved** for the future shared/org marketplace (P21 carry-forward: sharing/marketplace is deliberate v-next). Rationale: the mock uses "Catalogue" for personal saved workflows — a naming mistake (catalogue implies browsing available things); inheriting it creates a permanent user + developer trap (mock "Catalogue" ↔ product `WorkflowCatalog` show opposite content). Never wire mock pages to components by name — map by content (§9).
- **D-12 Live-state contract.** Real event → chat-lane rendering + composer mode + Steps behavior, per state. Clarify (`questionnaire_ready`) → paused card + composer-as-answer-channel + quick-reply chips (also inline in Steps); Gate (`review_gate_ready`) → paused card + approve/redo from chat card or Steps inline (one `approve_review` either way); Building (`agent_start`…) → live pipeline mini-card + steering composer + streaming Steps. Real product also handles states the mock omits: planner-running, validation/fix-loop, degraded/cancelled terminals. The transcript **accumulates** across states and revisions (mock swaps content per phase; product doesn't). The mock's phase scrubber is a demo device — excluded; a real phase indicator replaces it.

## 7. Landmines (enforced constraints — violating any breaks CI or the product)

Goldens: any new `pipeline_complete`-adjacent key → `_VOLATILE_STRIP_KEYS`; any new event type → `_DOCUMENTED_EVENT_TYPES`; chat events must never fire on golden paths. Import-linter: capabilities never import kernel/`app` — heavy-dep impls under `app/agents/**` against ports. INV-13: Concierge only via `deep_agent_runner` (banned-pattern gate). ChatRunner: don't touch `chat` pipeline agents, `test_chat_contract.py` golden, or `user_message` semantics. `_INTERNAL_PIPELINES` stays. Bedrock caching: ON since P26 (`_BedrockCachePointsMiddleware`) — do not re-diagnose; multi-turn placement is the open live check. E2E: role/text selectors survive reskin; the brittle `toHaveClass` color assertions are enumerated for fixing in Phase 32. A11y: `aria-live`/`role="log"` on streaming chat (open-design's documented failure).

## 8. Risks

(1) Mid-generation injection impossible → honest queued-UX; optional step-boundary pause gate later. (2) Multi-turn cache placement unverified → Phase 34 live check; compaction caps growth regardless. (3) Reskin blast radius (~3k hardcoded colors, navy `#1B2A4A` pervasive) → tokens+primitives first, screen-by-screen. (4) Concierge trust/cost → proposal-only + confirm chips + Haiku + per-turn metering. (5) ChatRunner collision → namespacing + ND-3. (6) Family-stitched transcript pagination at large families → windowed fetch, authoritative `/family` count (P25 precedent). (7) v1.0 close-out overlap → milestone v1.0 remains `verifying`; its consolidated live pass + `/gsd-complete-milestone` is the entry gate before v2.0 *execution* (planning proceeds now by user decision at import).
