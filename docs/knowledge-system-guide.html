  2–4 relevant cards returned to the AI agent  (~8K tokens)

5 · How /velocity-ai-analyze Works

Developer runs
/velocity-ai-analyze  →  User types a question
▼
Step 1 — Classify the question
Bug investigation? Impact analysis? Architecture question? Capability question?
▼
Step 2 — Prime the knowledge store (~12,500 tokens total)
Read in order: .knowledge/surface/ARCHITECTURE.md → .knowledge/INVARIANTS.md → .knowledge/surface/RULES.md → .knowledge/surface/INDEX.md
▼
Step 3 — Query for the task (~2–4 cards = ~8K tokens)
ctx.py "symptom words"
→ finds matching fixes/issues
ctx.py --for <file>
→ finds all rules touching a file
ctx.py --rules sse
→ decisions in force for an area
ctx.py --type issue "gate"
→ finds issues by type + keyword
▼
Step 4 — Load domain steering file (Kiro fileMatch already loaded it)
#backend-engine.md or #frontend-chat.md etc.
▼
Step 5 — Deep codebase investigation
Read source files · Search patterns · Trace call chains · Cross-reference
▼
Step 6 — Produce structured analysis report
Summary · Root cause · Trace · Impact · Recommended fix approach
▼
Step 7 — Create Jira ticket (if bug/risk found)
Only if confirmed bug (❌) or significant risk (⚠️ Medium+) not already in card store
✅ No register is ever loaded wholesale.  FIX-REGISTER.md, ISSUES-REGISTER.md, and IMPLEMENTATION-REGISTER.md are never auto-included.

6 · How /velocity-ai-fix Works

Developer runs
/velocity-ai-fix → describes the bug
▼
Step 1 — Load always-on steering
Read invariants.md + project-index.md + relevant domain file
▼
Step 2 — Prime knowledge store
ARCHITECTURE.md → INVARIANTS.md → RULES.md → INDEX.md
▼
Step 3 — Query knowledge store
ctx.py "symptom" → find prior fixes
ctx.py --for <file> → find rules
ctx.py --show FIX-NNN → read related fix
Check FIX-039 not regressed
▼
Step 4 — Deep investigation (read only)
Trace the bug. Find exact file + line.
▼
Step 5 — Root cause analysis
Write RCA before touching code
▼
Step 6 — Fix plan
State what will change before writing code
▼
Step 7 — Apply the fix
Surgical edit · Match existing patterns · No collateral cleanup
▼
Step 8 — Verify
Read changed files · Check INV-3 goldens · Check FIX-039 · Lint
Step 9 — Register the fix (3 sub-steps)
9a — Write the card
python extract.py fixes --only FIX-NNN
python build_index.py
→ creates .knowledge/cards/FIX-NNN.md
→ updates INDEX.md, index.json, links.json
9b — Add summary row to FIX-REGISTER.md
| FIX-NNN | date | description | … |
Summary row only. No detailed entry in the monolith.
9c — Update next Fix ID
Check INDEX.md header for current highest FIX-NNN
The card store IS the detailed entry, queryable via ctx.py
Result: Next developer who searches for this symptom gets the card in 2–4 results, never the monolith.

9 · ctx.py — Query Cheat Sheet

CommandWhen to useExample
ctx.py "symptom words" Before diagnosing a bug — check if it happened before ctx.py "reconnect banner" → FIX-122, ADR-0001
ctx.py --for <file> Before editing a file — find all rules and prior fixes ctx.py --for frontend/src/hooks/useRunStream.ts
ctx.py --rules <area> Find decisions in force for a domain ctx.py --rules sse → ADR-0001
ctx.py --show FIX-NNN Read the full body of a specific card ctx.py --show FIX-176
ctx.py --type issue "gate" Search issues specifically ctx.py --type issue "review gate"
ctx.py --type phase "resume" Find phase history ctx.py --type phase "prototype manifest" → PHASE-07
ctx.py --type bug "concurrent" Find QA campaign bugs ctx.py --type bug "resume" → BUG-R01..R05
check.py Verify store is fresh and cards match registers Exit 0 = clean · 1 = warnings · 2 = broken
