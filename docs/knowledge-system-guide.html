Velocity Knowledge System

How to navigate project history, architecture, decisions, and fixes using the current card store.

Current workflow: the former cache-backed query scripts and .knowledge/surface/ directory are retired. Use the /velocity commands and the current read models under .knowledge/.

Knowledge Store Layout

Cards

.knowledge/cards/ contains focused records for fixes, issues, bugs, and ADRs. Each card carries a compact summary, applicable paths/modules, constraints, and related-card links.

Index

.knowledge/INDEX.md is the first lookup surface: one linked, compact-summary line per card. Read it before opening individual cards.

Architecture

.knowledge/CONTEXT.md is the session navigation pack. ARCHITECTURE.md and architecture/MOD-*.md explain the module map and intended design.

Recommended Retrieval Flow

  1. Run /velocity prime once for the session.
  2. For a bug or symptom, use /velocity analyze <symptom>; use /velocity fix <symptom> only when a repair is requested.
  3. For a file or architecture question, use CONTEXT.md to select the relevant MOD-*.md card.
  4. Read INDEX.md, match the concern semantically against compact summaries, and open only the few linked cards that apply.
  5. Follow a card's applies_to, locked_constraints, and Related links before reading the source code that proves the conclusion.

Rules

  • Do not read or grep all cards in bulk; the index exists to keep retrieval bounded.
  • Do not load `.planning` registers wholesale. They are frozen historical fallback material only; state that fallback explicitly when you rely on it.
  • Never hand-edit generated knowledge artifacts such as INDEX.md, CONTEXT.md, state.yaml, or architecture/modules.json.
  • Open a known card by following its link in INDEX.md; there is no separate card-query CLI.
  • Legacy manual commands /velocity-ai-analyze and /velocity-ai-fix redirect to the corresponding /velocity commands.
