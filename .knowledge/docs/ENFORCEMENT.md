# Making agents actually use the store

Skill instructions are advisory. An agent under pressure will still open
`FIX-REGISTER.md`, and by then the tokens are spent. Four layers, in order of how
much they actually change behaviour.

## 1. Remove the auto-includes — mandatory, nothing else works without it

Three skills inject the registers **mechanically, before the model decides
anything**. No prompt, hook or instruction can prevent that.

| File | Line | Directive |
|---|---|---|
| `velocity-analyze/SKILL.md` | 54, 66, 77 | `#[[file:.planning/IMPLEMENTATION-REGISTER.md]]` + ISSUES + FIX |
| `velocity-fix/SKILL.md` | 40, 190 | `#[[file:…]]` and `@.planning/IMPLEMENTATION-REGISTER.md` |
| `velocity-feature/SKILL.md` | 193 | `@.planning/IMPLEMENTATION-REGISTER.md` |

Each exists in three byte-identical trees (`.agents/`, `.claude/`, `.kiro/`), so it
is a 3× edit. **This is Phase 5 and is not yet done.** Until it is, every
`/velocity-analyze` still costs ~383 K tokens regardless of anything below.

## 2. The surface redirect — the mechanism that actually works

`scripts/knowledge/register_read_gate.py` is a `PreToolUse` hook matched on **Read
and Bash**. It does two different things on purpose:

**Read → redirected, not denied.** `PreToolUse` supports `updatedInput`, which
rewrites the tool call. Every gated register becomes a read of the one entry point,
`.knowledge/surface/ENTRY.md` (2.4 KB) — the type table with counts, the areas, and
the `ctx.py` commands. `additionalContext` names the register that was asked for and
the query to start with, so the file itself does not need to vary. Nine
near-identical per-register stubs used to exist; they carried no information the
context message does not.

This matters more than it sounds. **A denial teaches an agent to route around the
gate; a redirect teaches it where to look.** The agent asked a reasonable question
and gets a useful answer, so there is nothing to work around.

**Bash → denied.** `cat`/`head`/`sed`/`awk` on a register is the obvious way around
a Read gate, and there is no input worth rewriting. `grep` and `wc` over a register
stay allowed — they are cheap and legitimate.

**Subagents are covered.** Hooks run inside Task-spawned subagents and the payload
carries `agent_id`/`agent_type`, so a fresh-context subagent hits the same redirect.

Verified behaviour:

| Call | Result |
|---|---|
| `Read .planning/FIX-REGISTER.md` | → `.knowledge/surface/ENTRY.md` |
| `Read .planning/STATE.md` (176 KB) | → `ENTRY.md`, pointed at `ARCHITECTURE.md`'s Stage section |
| `Read` same file with `limit`/`offset` | allowed — bounded reads are cheap and deliberate |
| `Read .knowledge/fixes/FIX-122.md` | allowed |
| `Bash cat .planning/FIX-REGISTER.md` | denied, with the ctx.py commands |
| `Bash sed -n 1,9999p …ISSUES-REGISTER.md` | denied |
| `Bash grep -c FIX- …` | allowed |
| subagent read (`agent_id` set) | → redirected |
| `READ_REGISTER_ANYWAY` anywhere | allowed |
| malformed hook input | allowed — **fails open**, a broken hook must never block work |

`ENTRY.md` is regenerated by `build_surface.py`, called automatically from
`build_index.py`, so its counts cannot go stale against the cards.

Gated: FIX / ISSUES / IMPLEMENTATION / TEST registers, REQUIREMENTS, the SSE and
RESUME bug logs, ROADMAP. Keep that list short; it should hurt only where it must.

### The harder option, if you want zero escapes

`permissions.deny` in settings.json is a **hard block with no override**:

```json
"deny": ["Read(./.planning/FIX-REGISTER.md)", "Read(./.planning/IMPLEMENTATION-REGISTER.md)"]
```

Deny beats allow, merges across settings scopes, and cannot be overridden. It is
stronger than the hook — and worse for daily use, because it gives the agent no
redirect and no message, and it blocks bounded reads too. Use it only if the
redirect proves insufficient.

## 3. Permission allowlist — removes the friction

```json
"Bash(python3 scripts/knowledge/ctx.py:*)"
```

Without it every query prompts, and friction pushes an agent back toward reading the
file. Cheap, and it matters more than it looks.

## 4. Sub-agents — the gap that is easy to miss

A sub-agent starts with a **fresh context** and holds none of the prime. Passing it a
file path invites a full read. Pass **card ids and findings** instead:

> Bad:  "read .planning/FIX-REGISTER.md and fix the reconnect bug"
> Good: "ADR-0001 requires terminal frames set the ref synchronously. FIX-122 and
>        BUG-015-sse are prior art. Fix X in frontend/src/hooks/useRunStream.ts."

The parent primes once; sub-agents inherit conclusions, not sources.

## Adoption note

`.claude/` is **gitignored** in this repo (`.gitignore:47`), so the settings here do
not travel with the branch. On your real branch, **merge** these keys into the
existing `.claude/settings.json` — do not overwrite it, it already has an `env` key.
The hook script itself lives in `scripts/knowledge/`, which is tracked.
