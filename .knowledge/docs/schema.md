# Card schema

The contract between the cards, the generated index, and `ctx.py`. Both humans
and the extraction skill follow this file.

## Layout

```
.knowledge/
├── cards/            THE STORE — 532 card files, one flat folder, one per record
├── surface/          ALL GENERATED by build_index.py — never hand-edit
│   ├── README.md         the read layer explained (the one hand-written file here)
│   ├── INDEX.md          primary types, one line each — the session prime
│   ├── CATALOG.md        secondary types — read on demand
│   ├── RULES.md          decisions in force
│   ├── index.json        every entry + `facets` (type/status/area counts) — for filtering
│   ├── links.json        file→cards, card→cards, backlinks
│   ├── stamp.json        freshness key
│   ├── ENTRY.md          the ONE file the read-gate serves instead of a register
│   └── ARCHITECTURE.md   CURRENT STATE — stage, enforced boundaries, ADRs in force
├── INVARIANTS.md     hand-maintained — project-wide constraints
├── sources.json      which registers are extracted, and at which git ref
├── overrides.json    hand-authored fields re-applied after every extraction
└── docs/             schema.md · PLAN.md · ENFORCEMENT.md
```

**One flat `cards/` folder, deliberately.** Splitting by type meant the same record
was reachable by two paths and `--show` had to know a card's type before it could
find it. Type is a field, not a directory.

**`surface/` is entirely generated, with one exception.** `build_index.py` overwrites
every file there except `surface/README.md`, which documents the generators and so
cannot be one of their outputs. That is also why `INVARIANTS.md`, which *is*
hand-maintained, sits outside the folder entirely.

**Every file here is history except one.** `ARCHITECTURE.md` is the store's only view
of the *present*: which milestone is open, which phase is current, which import
boundaries CI enforces, which workflows are registered, which ADRs are in force. It is
generated from `.planning/STATE.md`'s frontmatter, `backend/pyproject.toml`'s
`[tool.importlinter]` contracts, the directories actually on disk, and the decision
cards — never hand-written, because an architecture doc that is not generated is wrong
six weeks later.

Its stage section is the reason `.planning/STATE.md` is excluded from the card store
rather than carded: STATE.md changes every session, so a card would freeze it, while
regenerating keeps it current by construction. `check.py`'s `architecture vs STATE.md`
check exists because that drift is invisible to the frontmatter hash — the cards can
be perfectly fresh while the stage is a milestone behind.

## The idea in one paragraph

Every unit of project knowledge is one **card** in `cards/`, a markdown file with a
YAML header. The header is what gets loaded (≈35–45 tokens); the body is read only
when a card actually matters. Everything in `surface/` is derived from those
headers, so it cannot drift.

## Three kinds of card

| Kind | Directory | Answers | Loaded by default? |
|---|---|---|---|
| **Decision** (`type: decision`) | `.knowledge/decisions/` | "what rule constrains me here" | **Yes** — all of them, via `RULES.md` |
| **History** (`type: fix` / `issue` / `phase`) | `.knowledge/fixes/`, `issues/`, `phases/` | "has this been hit before" | No — one index line only |
| **Secondary** (`bug` / `test` / `req` / `doc` / `task`) | `bugs/`, `tests/`, `requirements/`, `docs/`, `tasks/` | "was this ever written down" | No — listed in `CATALOG.md`, searchable via `ctx` |

**Why two tiers.** All of `.planning/` is migrated so nothing is invisible, but
listing 536 cards in the always-loaded index would triple the prime and defeat the
purpose. Primary types go to `INDEX.md`; secondary types go to `CATALOG.md`, which is
read only when needed. Both are searched identically by `ctx.py`.

`doc` and `task` cards are **pointers** — summary plus path, content never copied.

The split is the whole point. A fix write-up can be 2,000 words of debugging; the
*rule* it established is one sentence. Only the rule earns permanent context.

Roughly 1 in 5 fixes yields a decision. Most do not — and forcing one is worse
than having none, because a rules file full of non-rules stops being read.

## Record shape

One JSON object per line, key order fixed for readable diffs:

```json
{"id":"FIX-122","type":"fix","status":"done","date":"2026-07-27",
 "area":["sse","frontend"],"files":["frontend/src/hooks/useRunStream.ts"],
 "summary":"Yellow \"Reconnecting\" banner …","source":".planning/FIX-REGISTER.md#fix-122",
 "produces":["ADR-0001"],"relates":["FIX-121"]}
```

The YAML frontmatter shown below is the **authoring** form — what `compact.py
--restore` produces and what you edit by hand. The fields are identical.

## Frontmatter dialect

Deliberately small — parsed by `scripts/knowledge/cards.py` with no dependencies.

```yaml
key: scalar                 # unquoted, or "quoted" if it contains : or #
key: [a, b, c]              # inline list
key:                        # block list
  - a
  - b
key: >-                     # folded — joins onto one line
  long text that wraps
  across source lines
```

Anything fancier (nested maps, anchors, multi-doc) is **not supported** and will
fail the build loudly rather than silently mis-parse.

## History card (`fix` / `issue` / `phase`)

```yaml
---
id: FIX-122                 # REQUIRED. matches filename prefix, unique across the store
type: fix                   # REQUIRED. fix | issue | phase
date: 2026-07-27            # ISO. sorts the index
status: done                # open | done | deferred | monitoring | wontfix
area: [sse, frontend]       # coarse tags — how `ctx --rules <area>` finds things
files:                      # repo-relative paths this touched. THE JOIN KEY —
  - frontend/hooks/useRunStream.ts    # links cards to each other and to the code graph
summary: >-                 # REQUIRED. the index line. see rules below
  Reconnect banner fired after cancel because React state updates lag the async
  stream reader loop; fixed by setting the non-reconnect ref synchronously.
source: .planning/FIX-REGISTER.md#fix-122   # provenance. the register is never edited
produces: [ADR-0031]        # decision this established, if any
relates: [FIX-121, ISS-015] # other cards. reverse links are generated, write each once
---

<body: the original prose, verbatim>
```

### Writing `summary:` — the field everything depends on

This one line decides whether the card is ever found. It is the *only* thing
`ctx.py` searches, and the only thing an agent sees before choosing to open a card.

- **Symptom + cause, not a title.** `"reconnect banner fired after cancel because
  React state lags the reader loop"` — not `"fix reconnect bug"`.
- **Use the words someone would search.** The observable symptom ("yellow
  banner", "stop button unresponsive") matters more than the internal name.
- **One sentence, ≤ 200 chars.** Longer means it was really two cards.
- **No filler.** Never open with "This fix…" — the type is already in the header.

If retrieval quality is poor, the summaries are wrong. Fix them before reaching
for a fancier search backend.

## Decision card (`type: decision`)

Body follows **MADR 4.0**. The header carries a **Y-statement**, because that
single sentence is what lives in every session's context.

```yaml
---
id: ADR-0031
type: decision
status: accepted            # proposed | accepted | deprecated | superseded
date: 2026-07-27
area: [sse]
y: >-                       # REQUIRED. the Y-statement — see the shape below
  In the context of SSE terminal events, facing spurious reconnect banners,
  we decided to mark the connection non-reconnecting synchronously inside the
  frame dispatcher, to achieve a quiet disconnect, accepting that detachRun
  remains only as additive insurance.
files: [frontend/hooks/useRunStream.ts]
enforced_by: [frontend/e2e/ts-f.sse.spec.ts]   # a test that fails if violated. optional but strong
supersedes: [ADR-0012]      # set together with the old card's status: superseded
derived_from: [BUG-015, FIX-121, FIX-122]      # evidence. may name non-cards
---

## Context and Problem Statement
## Considered Options
## Decision Outcome
### Consequences
### Confirmation      <!-- how we'd notice this being violated -->
```

**Y-statement shape** (one sentence, five clauses):

> In the context of **\<use case\>**, facing **\<concern\>**, we decided
> **\<option\>**, to achieve **\<quality\>**, accepting **\<downside\>**.

The `accepting` clause is not optional. A decision with no stated cost is a
description, not a decision — and it gives the reader no way to know when the
trade-off has stopped being worth it.

## What is *not* a card

- **Current state** — `.planning/STATE.md` is deliberately excluded (it changes every
  session). `check.py` lists every such exclusion with its reason; anything under
  `.planning/` that is neither carried by a card nor listed there is reported as a gap.
- **Specs** — those live in `specs/`. A decision may cite a spec; it does not restate it.
- **A fix with no lasting consequence** — it still gets a history card, but no ADR.
- **Anything the code already says plainly.** A card that restates a function is noise.

## Invariants the tooling enforces

`build_index.py` fails on any of these; `check.py` reports the softer drifts.

1. `id` present, unique, and matching the filename prefix.
2. `type` in `decision | fix | issue | phase | bug | test | req | doc | task`.
3. `summary:` (history) or `y:` (decision) present and non-empty.
4. Frontmatter parses under the dialect above.

And reported as warnings, never silently tolerated:

5. `files:` paths that no longer exist (card is making a claim about deleted code).
6. `relates`/`produces`/`supersedes` pointing at cards that do not exist.
7. Register entries not yet extracted into cards.
8. Index older than the cards.
