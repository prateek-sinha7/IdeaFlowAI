## What happened

Validated `BUG-20260828-005700-workflows-ppt-canvas` (`bug-hunter/ledger.md`), reproduced **3/3**
from a cold start (fresh `/dashboard` -> `/workflows/ppt/canvas` load each time; the failing
condition held identically on cycle 1). Conditions: `qa-admin` tier, default light theme, default
viewport, first visit each cycle (no warm cache needed) — no axis needed to be varied, this is not
timing- or state-dependent.

### Reproduction (cycle 1, representative of all three)

1. Sign in as `qa-admin`, fresh navigate to `http://localhost:3000/workflows/ppt/canvas`.
2. The right-rail Workflow tab already shows the wrong deliverable before any action: combobox
   "Streamed text — agent's raw output" (`value: streamed_text`), Output file name "output",
   Output format "Markdown (.md)" — none of which is the built-in's real
   `deliverable.strategy: "ppt"` (confirmed via `GET http://localhost:8000/api/workflows/ppt`
   returning `{"strategy": "ppt", "name": "presentation.pptx"}` in the same session).
3. Fill "Workflow name", click "Save as copy". `POST http://localhost:8000/api/user-workflows`
   returns `201` with `base_pipeline_type: "custom"`, `agent_ids` correctly listing the three PPT
   agents, but `manifest: null`.
4. The copy's own `/workflows/{id}/edit` page independently confirms the loss:
   `document.body.innerText.includes('pptx') === false`, Workflow tab still shows generic
   "Streamed text"/"output"/".md".
5. Repeated identically for cycles 2 and 3 (fresh dashboard->canvas load, new throwaway name each
   time) — same `manifest: null` result both times. `GET /api/workflows/ppt` re-checked after all
   three copies: still `{"strategy": "ppt", "name": "presentation.pptx"}`, unchanged — the
   built-in itself is never mutated, only what "Save as copy" writes for the fork is wrong.
6. All three throwaway copies deleted via `DELETE /api/user-workflows/{id}` (200/200/204).

### Root cause

`frontend/src/components/workflow/composer/ComposerPage.tsx:618-632` — the save payload only
includes a `manifest` key when `needsFullManifest(pipelineAgents)` is true, which the surrounding
comment documents as: a node carries a per-node skill, a custom prompt, or a sub-agent tree
(Spec 012 R-27/T30/T36). An unmodified "Save as copy" of a built-in — the exact path a user takes
to fork `ppt` without touching any node — has none of those, so `needsFullManifest` returns
`false` and the `manifest` key is omitted from the wire body entirely (falls through to
`selections` or `{}`). Nothing else in the save payload carries the built-in's `deliverable`
strategy or its per-step `read_files`/`write_files` tool grants, so both are silently discarded on
create. This is distinct from and more severe than [ISS-183](20260825-2115-ISS-183.md)
(`base_pipeline_type` hardcoded to `"custom"` — a label mismatch only): here the entire manifest
— tool grants and deliverable strategy — is lost, verified via direct API diff of the built-in's
manifest vs. the saved copy's `manifest: null`.

A second, compounding defect: the canvas's Workflow tab never displays the built-in's real
deliverable strategy even before any save — it always shows the generic "Streamed text" default,
so a user has no visual cue anything is about to be lost.

### Expected vs actual

Expected: the canvas's Workflow tab shows the built-in's actual deliverable strategy (or says it
cannot represent one it doesn't recognize), and "Save as copy" carries forward the full manifest —
tool grants and deliverable strategy — from the built-in it forks, so a PPTX-producing built-in
stays PPTX-producing once copied.

Actual: the Workflow tab shows a wrong "Streamed text"/output/.md deliverable throughout, and
"Save as copy" persists `manifest: null`, converting the copy into a generic streamed-text
workflow with no UI trace it was ever `ppt`-based.

## Resolution

Verified fixed in the current code on 2026-10-01 (feat/user-stories-v2 @ 3b08b2ba8) by static review: a first-pass check and an independent adversarial re-check both found every claim of this card fixed. No tests were run for this closure.

**Fixed by:** d027f16bd (bug-hunter batch, BUG-20260828-005700 / [ISS-206](20260828-1609-ISS-206.md))

**Evidence:** Claim 1 (manifest:null on built-in copy): ComposerPage.tsx:104-116 needsFullManifestOnSave returns true on !!builtinCanvasType (l.112), non-empty initialManifestSteps, or non-default runConfig. Save (l.897-905) then sends buildWorkflowManifest(...). Tool grants: backend workflows.py:535 returns manifest_steps; page.tsx:524 seeds them; manifestStepsToGateSelections (userWorkflows.ts:793-797) restores read/write_files into selections; ComposerPage.tsx:384-431 merges them. Claim 2 (Workflow tab shows streamed_text): page.tsx:537-551 maps detail.deliverable/planner/clarify into runConfig; DashboardLayout.tsx:3251 passes initialRunConfig; ComposerPage.tsx:586-589 adopts it after mount. Regression tests exist in ComposerPage.manifestPersistence.test.tsx ([ISS-196](20260828-1555-ISS-196.md)/203/206).
