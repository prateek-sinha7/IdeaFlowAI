# ISS-1086

> **INFERRED sibling** of [ISS-899](20261001-2129-ISS-899.md), derived during the QA-KB-072 analysis (2026-10-07). The quoted text and the
> code that contradicts it were READ on the working tree (branch `feat/stale-bug-fixes`, HEAD `e93aa40ed`, no `backend/` edits against
> HEAD) and are CONFIRMED. That the owner wants the example corrected, rather than left as history, is the INFERRED part.

## Condition

Anyone reading `HumanGate` to learn what happens when a client posts `action: "redo"` at a declared `gates: [human]` step that did not
opt in with `redoable: true`. This is the same wrong model that [ISS-899](20261001-2129-ISS-899.md)'s test was written against.

## What the comment says (CONFIRMED, read)

`backend/agents/capabilities/gates/human.py:41-51`:

> A step that does NOT opt in (the v1 default — most declared gates are PRE-step over the PREVIOUS step's output, a different mechanism)
> keeps the original behaviour: a stray _gate_redo (e.g. a scripted client sending action:"redo") is CONSUMED — never re-surfaced to the
> wire, never mapped to GATE_PASS.

and `human.py:173-175`: "a stray redo on the (un-wired) declared path maps to a NON-PASS outcome — GATE_WAIT_HUMAN".

The same pre-FIX-500 route is narrated in two more places (both READ):

- `backend/agents/capabilities/gates/approval.py:53-54`: "the shared _run_review_gate may now emit _gate_redo", with the consume rule
  restated at `:181` and `:200-202`. These do not give the scripted-client example, but they carry the same premise.
- `backend/tests/unit/agents/test_redo_gate_safety.py:59-60` and `:73-74`, the fake delegate that stands in for the primitive: "(as the shared
  ``_run_review_gate`` now can)" and "A scripted/malicious client sent action:"redo" → the shared primitive emits this internal signal even
  on the un-wired declared path".

## What the code does (CONFIRMED, read)

- `engine.py:12518-12538`: at a firing that published `redoable=False`, `_run_review_gate` logs "Review gate redo REFUSED", calls
  `event.clear()` and `continue`s. The `yield {"type": "_gate_redo", ...}` at `:12546` is unreachable for that firing.
- `kernel_services.py:1475` passes `redoable=bool(getattr(step, "redoable", False))` to the primitive, and `human.py:134` computes
  `redo_enabled = bool(getattr(step, "redoable", False))` from the same step. So `etype == _REDO and not redo_enabled` (the branch at
  `human.py:154-158`) can occur only if the primitive yields `_gate_redo` at a `redoable=False` firing, which `:12530-12538` forbids.
- A scripted client's redo therefore never reaches `HumanGate`. It is refused one layer below and the gate stays open. The sibling
  paragraph on `update_specs` (`human.py:52-58`) was updated for ISS-053 ("the shared primitive now refuses that action and keeps
  waiting — but this branch is what makes a signal arriving by any OTHER route safe"). The redo paragraph was not updated for FIX-500.
- The branch is still pinned, but through a fake delegate: `tests/unit/agents/test_redo_gate_safety.py:57-76` builds a
  `KernelServices`-shaped fake whose `run_human_gate` yields `_gate_redo`, and `:104-116` asserts `HumanGate` and `ApprovalGate` consume it.
  Observed on this tree: `7 passed in 5.12s` (`evidence/qa-kb-072/08-analyze-anchor-tests.txt`).

## Why the root cause implies it

[FIX-500](20260831-1644-FIX-500.md) moved the redo refusal into the shared primitive and corrected "four comments and one docstring
paragraph" in `engine.py`. It did not reach `human.py`, where the old route is narrated as current. [ISS-899](20261001-2129-ISS-899.md) is
one artifact that still assumes the old route (its test expects the consumed redo to end the drive). This comment is another.

## Expected vs actual

- Expected: the comment says the primitive refuses a redo at a non-redoable firing and keeps waiting, and that this branch is the fallback
  for a `_gate_redo` arriving by another route.
- Actual: it gives a scripted client's redo as the example that reaches the branch, and says the branch maps it to `GATE_WAIT_HUMAN`.

## What would settle it

The owner's call on whether narrated history is acceptable. This repo has precedent on both sides (see
[ISS-1079](20261007-2204-ISS-1079.md), which sets out the same question for test prose). The code facts above do not depend on it.

## Fix shape (comment-only, no behaviour change)

Reword `human.py:41-51` (and the matching sentence at `:173-175`) in place. Keep the code. For example: "A step that does NOT opt in keeps
the original behaviour: the shared primitive refuses a redo at a `redoable=False` firing and keeps waiting (ISS-090 / FIX-500), so this
gate never sees one. If a `_gate_redo` still arrived by another route it is CONSUMED here -- never re-surfaced to the wire, never mapped
to GATE_PASS." Make the matching edits at `approval.py:53-54` and in the fake's docstring and comment at
`test_redo_gate_safety.py:59-60` and `:73-74` (the fake is a stand-in for a signal arriving by another route, not for what the primitive
does at a `redoable=False` firing). Change no assertion in that test file.

Independent of [ISS-899](20261001-2129-ISS-899.md): the test fix does not touch `human.py`, so the two can land in either order.
