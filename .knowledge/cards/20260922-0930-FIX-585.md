## The six shapes

A full 68-file offline sweep read **589 passed / 57 failed**. The product
defects behind them are fixed in the commits preceding `14ce62c59`; these are
the test changes, and they recur across suites.

**Fixtures pinned by run id.** Six scenarios named a UUID that had been pruned
or — worse — reassigned by a reseed to a different run. `26a7e162` came to name
a run whose brief and status were both wrong for its scenario, failing with
`expected '10.4K', actual '13.6M'`: a message indistinguishable from the
mismatch it exists to detect. All now discover a run at runtime and skip with a
precise reason.

**A label quoted into a CSS selector.** A brief containing a double quote
produced `Unexpected token "" while parsing css selector` and took five
scenarios down at once. `21_run_families` already selected rows by index for
this reason; `06` and `18` now do too.

**Sampling a value still loading.** The chat transcript seeds one `/events`
fetch per family member (0 messages at 2s, 14 at 5s), and the Canvas deliverable
combobox sits on its `streamed_text` default until `runConfig` lands. Both were
read on a fixed timeout; both now settle first.

**A paginated list against an account-wide total.** Run history opens on 50 of
220. Four scenarios compared `len(rows)` to a chip count and failed at "50 of
220"; they now page the list in.

**Assertions that could never pass.** `assert not fetched_root` in two places —
a pinned deep link MOUNTS the family root, and `/family` is itself keyed on the
root, so fetching it is how the pin gets applied.

**Behaviour a later fix deliberately removed.** [ISS-384](20260828-2221-ISS-384.md)
replaced the generic wizard title with the saved row's own name; a scenario
asserted the generic title and so failed precisely when that fix worked. Same
shape for [ISS-622](20260831-0115-ISS-622.md) (native confirm → in-app dialog)
and `e4eecb705` ("Version v2" → "v2", and a picker now driven by git tags).

## The harness cap, and a retracted claim

`framework/api.py`'s `full()` caps a response at 200,000 characters. An earlier
revision of the analysis claimed "two endpoints return malformed JSON"; that was
the cap, not a backend defect, and the superseded trace is kept in
`INTEGRATION_TESTS.md` with a note on how it was wrong. A plausible chain read
off the source is a hypothesis.

## Self-inflicted data damage

Fixture runs launched during the sweep polluted the dataset and produced
failures resembling regressions — including a run whose status was set to
`failed` by direct `UPDATE` (no finalization record, so the lane fell back to
"Cancelled" with no composer, breaking five chat-lane scenarios) and two
`chat_message` events injected with hand-written `message_id`s the app never
mints. Hand-writing run state into the database produces fixtures that satisfy a
SQL query and are structurally incomplete to the application.

## The runner

`tests/integration/scripts/run-offline-by-file.sh` runs the suite one file at a
time with a pause between, so a sweep is readable as it goes and one file's
crash cannot take the run with it.

## What remains

Two failures, both in `03_launch_panels`, and they are ONE open product
defect — filed separately by this sync. Three further scenarios now SKIP with a
precise reason rather than failing: no completed `ppt`-family run exists
(ISS-314, ISS-199) and no run currently has an expired workspace (ISS-356).
