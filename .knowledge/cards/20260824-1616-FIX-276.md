After a loop-back completed, the UI showed `Greet [Skipped]` and reported the run as 3/4
agents — for a step that had in fact run twice.

## Root cause

The conditional gate computes `skipped_targets` as every `trigger: step` outcome other
than the one taken, and the dispatch loop emitted `agent_skipped` for all of them
unconditionally. For a FORWARD branch that is correct — the sibling genuinely never ran.
For a BACKWARD (loop) target it is a contradiction: that step already produced
`agent_complete` events on earlier passes. The UI honours the last lifecycle signal it
receives, so the later `agent_skipped` overwrote a real completion.

## Fix

Report a sibling only if it never ran:

```python
if any(r.get("agent_id") == _sib_id for r in results):
    continue
```

A2's forward branch still reports both untaken branches skipped — that is the negative
case, and the `.http` runners assert it explicitly so the guard cannot over-fire
unnoticed.
