## Reproduction

Confirmed 3/3 from a cold start (fresh navigation to `/library?tab=skills`, no soft re-click),
cycle 1:

1. Sign in as `qa-admin`, navigate to `http://localhost:3000/library?tab=skills` — 186 cards
   render on the "All" pill, matching `GET /api/skills/library` (`total_count: 186`,
   `skills.length: 186`) exactly; no cap/pagination gap at this page (distinct from the Run
   History 50/273 cap, and distinct from D-26's agent-pill mismatch, where the pill source list
   itself is wrong for 52/93 agents — here the pills are correctly derived from the categories
   actually present).
2. `document.querySelectorAll('div.cursor-pointer.p-4')` locates the `html-deck-to-pptx` card;
   its category-badge `<p class="...uppercase tracking-[0.1em] font-semibold capitalize">`
   element is present but has `textContent === ""` — every neighboring card shows its category
   in caps (e.g. "PLANNING", "TESTING").
3. Selecting the "Testing" pill (`?category=testing`) returns exactly 48 cards (48/48 of the
   skills whose `category === "testing"`); `document.body.innerText` does not contain
   `html-deck-to-pptx` — confirmed absent. Re-verified against "Research" (2/2) as a control:
   pill filtering itself works correctly for every category that has a real value.
4. Returning to "All" makes the card reappear — stable and reproducible on all 3 cycles
   (attempt 1, 2, 3), each a full fresh navigation from `/dashboard` → `/library?tab=skills`.

## Root cause

`backend/app/agents/skills_catalog.py:54` declares `category: str = ""` on the skill model and
`skills_catalog.py:112` builds it as `category=metadata.get("category", "")` — silently defaulting
to an empty string when a skill's `SKILL.md` frontmatter omits the field, with no fallback to a
derived or "uncategorized" value. `backend/skills/global/html-deck-to-pptx/SKILL.md` is the one
skill whose frontmatter has only `name` and `description` — no `category`, `display_name`, or
`tags` — unlike every sibling `SKILL.md` (e.g. `scientific-thinking-scholar-evaluation/SKILL.md`,
`kotlin-ktor-patterns/SKILL.md`), which all carry `category: <value>`. The frontend renders
whatever `category` the API returns verbatim into the badge `<p>`, and the category pills are
built only from the non-empty category values actually present in the catalog — so a skill with
`category: ""` can never match any specific pill's filter value, and is reachable only via "All"
or a direct name search. Confirmed precisely at `backend/app/api/skills.py:35`:
`categories = sorted({e.category for e in entries if e.category})` — the `if e.category` clause
is what drops the empty string out of the pill list the frontend receives.

## Blast radius

Every consumer of `GET /api/skills/library` routes through one hook,
`frontend/src/hooks/useSkillsCatalog.ts:13-32`, which forwards Redux's `state.skills.skills` and
`state.skills.skillCategories` (`frontend/src/store/slices/skillsSlice.ts:52`) verbatim — so the
empty-category defect reaches every caller of that hook, not just the reported one:

- `frontend/src/components/library/LibraryPage.tsx` (lines 249, 706, 912, 928, 954, 965) — the
  reported symptom: blank badge + unreachable-via-pill on `/library?tab=skills`.
- `frontend/src/components/workflow/composer/AgentSkillsPicker.tsx` (lines 82, 169) — an
  independent second caller with the identical filter-equality and pill-visibility mechanism;
  per its own docstring this is "the ONLY skill-attachment UI in the app" (mounted from
  `CanvasConfigRail`, the Simple-view `AgentRow`, and `AgentCapabilitiesModal`), so
  `html-deck-to-pptx` (whose empty `compatible_agents` makes it compatible with every agent) is
  unreachable via any specific category pill when attaching skills to ANY agent in the composer.
  Filed as [ISS-570](20260829-0004-ISS-570.md).
- `frontend/src/components/workflow/AgentsPopup.tsx:572` also calls `useSkillsCatalog()`, but
  only for an id→name lookup — it never reads `.category` and is NOT affected.
- `backend/app/api/user_agents.py:122-124` also calls `list_global_skills()`, but only to build a
  `known` id-set for validating a user's skill IDs — never reads `.category` and is NOT affected.
- `backend/app/api/hooks.py:33` (`events = sorted({e.event for e in entries if e.event})`) is the
  identical code shape for the Hooks catalog's `event` field. Currently latent — all 8
  `HOOK.md` files declare a real, non-empty `event` — but the mechanism would reproduce the same
  reachability gap for a hook if one ever declared `event: ""` (present but empty), since that
  passes `hooks_catalog.py`'s required-field presence check. Filed as
  [ISS-571](20260829-0004-ISS-571.md).

## Expected vs actual

Expected: every skill has a non-empty `category`, so its card shows a real badge and is reachable
through the pill corresponding to that category, like the other 185 skills.

Actual: `html-deck-to-pptx` renders with a blank category-badge line and no tag chips, and is
permanently unreachable through any of the nine specific category pills — only "All" or a name
search surfaces it.
