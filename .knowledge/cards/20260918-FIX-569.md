## The symptom

Two defects, both of which made a conditional gate's verdict meaningless —
which is the one thing a gate exists to prevent.

**A rejected build was presented as finished.** A route that exhausted
`loop_max_iterations` silently fell through to the next step. The validator had
said no; the run carried on and shipped it.

**Eight gate runs died on their own reply.** A step that produces a
`route_decision` answered correctly in 5,345 characters, and the engine then
replaced that reply with 97,468 characters of `prototype.html` on its way to the
gate. The gate halted with `malformed route_decision JSON`, after every screen
had been built and every route verified.

## Root cause 1 — loop exhaustion had one behaviour and needed two

Falling through on exhaustion is correct for a genuine convergence limit: the
loop is a "keep refining until good enough" construct, and running out of
iterations means "good enough is what we have". It is wrong for a gate: running
out means "we never got it right".

`RouteSpec` now carries `on_loop_exhausted: str = "continue"` (`plan.py:272`),
compiled and validated to `{"continue", "fail"}` (`compiler.py:1366-1369`,
allowed key added at `:172`). `"fail"` raises
`BudgetExceeded("loop_iterations", …)`.

## Root cause 2 — a blanket post-step rewrite

The `single_file` deliverable readback exists so a downstream reader sees the
built artifact instead of the tool confirmation the agent's text stream actually
carries. It fired for every step under a `single_file` deliverable.

A conditional gate is not that reader. It reads the trailing JSON object of its
source step's reply. So the readback handed it an HTML document.

The rule now (`engine.py:9577-9580`):

```python
_is_decision_step = "route_decision" in (getattr(spec, "produces", None) or [])
if (_deliv_strategy == "single_file"
        and not _is_decision_step
        and not getattr(ectx, "is_revision_workflow", False)):
    ...
```

**A step declaring `produces: ["route_decision"]` is exempt from deliverable
readback.** Lock that, because the readback is otherwise a blanket rewrite of
every step's output and it will swallow the next structured reply anyone adds.

## What this does NOT fix

This does **not** close [ISS-683](20260904-ISS-683.md). The readback still
replaces the output of every non-route step after the build, so a reviewer, a
validator or a reporting agent running after the build step still cannot report
anything of its own. Only the `route_decision` case is carved out.
