## QA-PS-014 — Run detail page shows blank "Output will appear here" with no loading indicator

Bug register: [QA-PS-014](../../BUGS.md#qa-ps-014).

### Reproduction (3/3, cold start each time)

1. **Cycle 1** — signed in as `qa-admin@flowinqa.com`, cold-navigated directly to
   `/runs/3839720c-0287-48c0-90cb-4385d910f460` (a completed `custom_revision` run).
   Screenshot taken immediately after `page.goto()` resolved: the shell (header,
   nav, back button, chat transcript with "Run summary", tabs) was already
   rendered, but the Preview tab showed only "Output will appear here" — the
   text used for a genuinely empty run. A small "Loading workspace…" toast was
   visible bottom-right. 3s later a second screenshot showed the full deliverable
   rendered. Evidence: `evidence/qa-ps-014/attempt1-immediate.png`,
   `evidence/qa-ps-014/attempt1-after3s.png`.
2. **Cycle 2** — cold-navigated directly to `/runs/f970bb7b-d8c8-483f-aa9b-c3c9053c27af`
   (a different completed run, `ex_A3_b_spanish`). Same result: shell rendered,
   Preview blank with "Output will appear here" plus the small toast. Evidence:
   `evidence/qa-ps-014/attempt2-immediate.png`.
3. **Cycle 3** — entry path varied to click-through from `/runs` (the reporter's
   exact steps: history list → click a completed row) instead of a direct URL.
   Clicked "github dashboard user story" (completed, `user_stories`) and polled
   `document.body.innerText` every 150ms for 1.2s immediately after the click.
   All 8 polls showed the blank placeholder (`blankPlaceholder: true`), and in
   this run **no "Loading workspace…" toast ever appeared** during that window —
   the Preview panel gave literally no indication anything was in flight.
   Evidence: `evidence/qa-ps-014/attempt3-polled.png` (final loaded state),
   raw poll JSON captured in the session transcript.

**Named trigger:** the run's `summary` (title, chat transcript, run metadata)
loads and renders before the run's deliverable/workspace content does — a second,
separate async fetch. During that gap, `hasContent` is `false`, and the neutral
`!hasContent` branch renders unconditionally, with no distinction from a
terminal run that truly has no output. The click-through entry path additionally
showed the small "Loading workspace…" toast is not a reliable signal (absent in
cycle 3), so there is no dependable in-panel loading affordance at all.

### Root cause

- `frontend/src/components/preview/PreviewPanel.tsx:992` —
  `hasContent = !!(effUserStoryContent || effPptContent || effPrototypeContent || pptxCode || hasGenericDeliverable)`
  is derived from content that populates asynchronously, separately from
  `RunDetailPage`'s own `summary` fetch.
- `frontend/src/components/preview/PreviewPanel.tsx:1676-1679` — the branch
  ```
  ) : !hasContent ? (
    <div className="flex items-center justify-center h-full">
      <p className="text-xs text-ink-400">Output will appear here</p>
    </div>
  ```
  fires whenever `hasContent` is false, with no separate case for "content is
  still being fetched for a terminal, non-streaming run" vs. "this run
  genuinely produced no output." `isStillRunning` (the `PreviewChrome ...
  streaming` branch just above, line ~1665) only covers a run whose pipeline
  is actively executing — it does not cover a terminal/completed run whose
  deliverable payload simply hasn't arrived at the client yet.
- `frontend/src/components/history/RunDetailPage.tsx:76,186` — `RunDetailPage`
  has its own `loading` flag and a proper skeleton (lines 186-199), but that
  flag only gates the `summary` fetch. By the time `loading` flips to `false`
  and `PreviewPanel` mounts, the deliverable-content fetch is a second,
  independent round trip the skeleton never covers.

### Expected vs actual

- **Expected:** a loading state (skeleton/spinner/progress) in the Preview
  panel while deliverable content is being fetched, replaced by the real
  content once loaded.
- **Actual:** the Preview panel renders the same "Output will appear here"
  placeholder for both "no output exists" and "output exists but hasn't
  arrived yet," with no reliable loading indicator distinguishing the two.
