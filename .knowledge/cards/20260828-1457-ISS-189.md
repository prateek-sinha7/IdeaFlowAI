# ISS-189

## Reproduction (3/3, cold start each cycle)

Each cycle: fresh navigation to `/dashboard` then `/create/ppt` (not a soft re-click of the
same screen), sign-in state carried over via existing `qa-admin` session.

- **Cycle 1:** selected "Investment Banking Pitch Book" from the template gallery, clicked
  "Use this template" in the preview modal. Result: `continueDisabled: true`,
  `designSystemMentions: 1` (only inside the pill label itself, no picker control anywhere in
  `document.body.innerText`).
- **Cycle 2:** identical steps from a fresh `/dashboard` -> `/create/ppt` navigation, then also
  filled the brief textarea with a real value via a native-setter `input` event. Result: "Add a
  brief" pill cleared, "Pick a design system" pill persisted, `continueDisabled: true`.
- **Cycle 3:** identical steps from a third independent cold navigation. Result identical:
  `continueDisabled: true`, "Pick a design system" pill present.

3/3 — CONFIRMED, no narrowing needed (deterministic, no axis variance required).

## Page / route / component

- Page: PPT wizard shell (New presentation)
- Route: `/create/ppt`
- Component: `frontend/src/components/workflow/LaunchWizard.tsx` (shared launch wizard shell
  used by prototype and PPT modes)

## Root cause

The template preview modal for "Investment Banking Pitch Book" shows an "Uses design system"
badge, and selecting it sets a requirement that the wizard's unmet-requirements pill row
renders as "Pick a design system". However, `LaunchWizard.tsx`'s design-system auto-select
logic (added in [FIX-103](20260723-FIX-103.md)) only default-selects a design system when
`prev === null && mode === "prototype"` — it is scoped exclusively to prototype mode. In PPT
mode, `selectedDsId` is never initialized for a template that declares a design-system
requirement, and no design-system picker UI is rendered anywhere in the PPT wizard for the user
to satisfy the requirement manually. The pill is thus permanently unmet and `Continue` stays
`disabled === true` regardless of a valid template + non-empty brief.

## Expected vs actual

- **Expected:** selecting any valid template plus a non-empty brief satisfies the wizard's
  requirements and enables Continue, as it does for every other PPT template (e.g. "Investor
  Pitch Deck", which carries no design-system requirement and clears its pill row entirely).
- **Actual:** for "Investment Banking Pitch Book" specifically, a "Pick a design system"
  requirement appears with no corresponding UI control, and Continue can never be enabled —
  the wizard is a permanent dead end for this template.
