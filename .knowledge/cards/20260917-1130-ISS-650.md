# ISS-650

**Bug register entry:** QA-PS-004 (`BUGS.md#qa-ps-004`, `LEDGER.md`)

## Description

On a pipeline run with multiple review gates, the concierge chat confirmation
message shown after each gate approval reads "Review approved — build
continues" for every single gate, with no agent name. When a run has 3+
review gates, the chat history shows the identical sentence 3+ times in a
row, so a user scrolling back cannot tell which approval corresponds to
which agent.

## Reproduction (3/3, cold start each time)

Launched a real `User Stories` run (`/create/user-stories`, brief "github
dashboard user story") with 3 review gates enabled: Domain Discovery Agent,
Backlog Architecture Agent, Estimation Agent. Answered the clarification
gate, then approved each of the 3 review gates in turn.

- **Cycle 1** — observed live, mid-run, immediately after approving all 3
  gates on `/runs/a7279a95-8af1-4b5d-b1d1-04c8625a9c89/stream`: chat
  transcript showed three consecutive `paragraph` nodes, each reading
  "Review approved — build continues", between "Run started" and the run's
  agent activity.
- **Cycle 2** — cold nav: `/dashboard` -> fresh `goto` of
  `/runs/a7279a95-8af1-4b5d-b1d1-04c8625a9c89` after the run reached
  `completed`. Same 3 identical lines present in the persisted chat history.
- **Cycle 3** — cold nav: `/runs` (history list) -> fresh `goto` of the same
  run detail URL. Same 3 identical lines, byte-for-byte.

Condition: does not depend on tier, theme, viewport, or timing — the text is
render-time-invariant.

## Expected vs Actual

- **Expected:** each approval message names the agent whose gate was
  approved, e.g. "Domain Discovery Agent review approved — build continues".
- **Actual:** every approval message is the literal, unconditional string
  "Review approved — build continues" — identical regardless of which gate
  or agent produced it.

## Root cause

`ResultCard.tsx` renders resolved gate cards with a hardcoded literal:

```tsx
// frontend/src/components/chat/ResultCard.tsx:141-142
kind === "gate" && message.resolved
  ? "Review approved — build continues"
```

This was introduced by FIX-178 (Phase 31/42), which added the `resolved`
flag mechanism and this fallback text specifically to replace the old
gate-box chrome — but the replacement text has no agent-name slot, unlike
the *unresolved* gate heading. FIX-123 (Phase 08) already fixed the
unresolved `GateAwaitingCard` heading to use `laneGate.agentName` instead of
the raw `run_id:agent_id` key — so the agent name is available in context at
approval time, but the resolved-card branch in `ResultCard.tsx` never
consults it. The `ChatMessage` type / `useRunChat.ts` gate-resolution path
(`case "review_gate_approved"`, `useRunChat.ts:565`) also does not carry an
`agentName` field through to the resolved rendering, so even if `ResultCard`
were changed, the message object would need to also plumb the name through.
