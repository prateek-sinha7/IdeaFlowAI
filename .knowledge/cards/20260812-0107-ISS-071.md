# ISS-071

## Title

**The "Update the Specs" affordance is advertised at EVERY gate on every non-prototype workflow.** `_update_specs_eligible` keys on `artifact_kind in {"summary"}`, and `_artifact_kind_for` falls back to `"summary"` for any agent absent from `_AGENT_KIND_MAP` — which maps only the four prototype agents. Measured over every pipeline roster: `prototype`/`od_prototype` resolve correctly (analyze alone, True; the other four False), but `od_ppt` (3/3), `user_stories` (6/6), `app_builder` (15/15) and every composed workflow advertise it at **all** gates. The in-code comment ("the ANALYZE gate only") is accurate for prototype and describes none of the others. Post-ISS-053 this is no longer a security gap — the engine now enforces exactly what was advertised — but it means those workflows offer a spec-revision affordance whose sub-pipeline re-runs three positionally-chosen agents that are not a specify/plan/analyze triple.

## Source / Evidence

Found 2026-08-12 by the ISS-053 investigation (PROBE A over every roster) and re-confirmed while fixing it (quick-260812-12t). Explicitly REJECTED as the fix for ISS-053 (report Option B): narrowing the advertisement changes nothing about enforcement, so all three harms would have survived. Filed as the separate correctness item it is. Fix shape: extend `_AGENT_KIND_MAP`, or derive the kind structurally from the manifest, so a workflow with no specify/plan/analyze triple advertises nothing — WITHOUT introducing a workflow-name literal (SC-001/INV-1).
