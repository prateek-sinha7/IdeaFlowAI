# ISS-071

## Title

**The "Update the Specs" affordance is advertised at EVERY gate on every non-prototype workflow.** `_update_specs_eligible` keys on `artifact_kind in {"summary"}`, and `_artifact_kind_for` falls back to `"summary"` for any agent absent from `_AGENT_KIND_MAP` — which maps only the four prototype agents. Measured over every pipeline roster: `prototype`/`od_prototype` resolve correctly (analyze alone, True; the other four False), but `od_ppt` (3/3), `user_stories` (6/6), `app_builder` (15/15) and every composed workflow advertise it at **all** gates. The in-code comment ("the ANALYZE gate only") is accurate for prototype and describes none of the others. Post-ISS-053 this is no longer a security gap — the engine now enforces exactly what was advertised — but it means those workflows offer a spec-revision affordance whose sub-pipeline re-runs three positionally-chosen agents that are not a specify/plan/analyze triple.

## Severity / Tag / Status (original row)

- Sev: minor
- Tag: agents
- Status: **OPEN**

## Source / Evidence

Found 2026-08-12 by the ISS-053 investigation (PROBE A over every roster) and re-confirmed while fixing it (quick-260812-12t). Explicitly REJECTED as the fix for ISS-053 (report Option B): narrowing the advertisement changes nothing about enforcement, so all three harms would have survived. Filed as the separate correctness item it is. Fix shape: extend `_AGENT_KIND_MAP`, or derive the kind structurally from the manifest, so a workflow with no specify/plan/analyze triple advertises nothing — WITHOUT introducing a workflow-name literal (SC-001/INV-1).

## Resolution

Verified fixed in the current code on 2026-10-01 (feat/user-stories-v2 @ 3b08b2ba8) by static review: a first-pass check and an independent adversarial re-check both found every claim of this card fixed. No tests were run for this closure.

**Fixed by:** b9448f84f ([FIX-223](20260812-0226-FIX-223.md))

**Evidence:** The card's one defect is that unmapped agents fall back to "summary" and "summary" was the eligible kind, so od_ppt, user_stories, app_builder and composed workflows advertised Update the Specs at every gate. In backend/agents/execution_engine/engine.py:13754 `_UPDATE_SPECS_ELIGIBLE_KINDS` is now `frozenset({"analysis"})`. Line 13723 maps only "prototype-analyze" to "analysis". `_artifact_kind_for` (line 13764) still falls back to "summary", which is no longer eligible, so unmapped agents advertise nothing. `_update_specs_eligible` (13766-13802) tests only the kind plus `revision_attempt`, with no workflow-name literal (INV-1 kept). All three gate call sites (9290, 9440, 10922) route through it. The only workflow that uses prototype-analyze is backend/agents/workflows/prototype/workflow.yaml:65. [FIX-223](20260812-0226-FIX-223.md) b9448f84f changed engine.py. I did not check the od_prototype claim, nor any other workflow that reuses the prototype-analyze id.

**Left over (outside this card's claims):** The defect is fixed in code, but the card is still marked status: open. One side effect: "analysis" is not in ARTIFACT_KINDS (backend/agents/artifacts/graph.py:52). Persisting a prototype-analyze artifact therefore logs an advisory IN-01 warning (graph.py:154) and misses typed `consumes: summary` routing, which still works by producer id. This is outside the card's claim. Workflows that never use the prototype-analyze id (prototype_v2 and the revision workflows) now offer no Update the Specs at all. I did not check whether that is intended.
