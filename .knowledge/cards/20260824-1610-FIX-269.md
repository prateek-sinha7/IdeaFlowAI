## Bug — Back always landed on the dashboard

User-reported: My Workflows -> a run -> Back landed on the Dashboard, not My Workflows.
All 5 `onBack` call sites (`WorkflowHistory`, `AccountSettings`, `AnalyticsPage`,
`IdeaInputPage`, `ComposerPage`) were wired to `handleGoHome`, which unconditionally
`router.push(routes.home())`s regardless of navigation history — there was no "one screen
back" behavior anywhere, only "go home".

**Fix:** added `handleBackNav` (`DashboardLayout.tsx`) — does the screen's own state
cleanup, then `router.back()` when `window.history.length > 1`, falling back to
`handleGoHome` only when there's no history to go back to. Rewired all 5 `onBack` sites.
`handleResumeRun`'s own `handleGoHome()` fallback call was left untouched (different code
path, not one of the 5 `onBack` props).

## Bug — no refresh / auto-refresh on run history or run detail

Neither `RunDetailPage.tsx` nor `WorkflowHistory.tsx` had any way to refresh without a
full page reload. Added a header refresh button + interval `<select>`
(Off/10s/15s/30s/1m) to both, same pattern in each: manual click and the interval both
call the same refresh function; a `Loader2` spinner replaces the refresh icon while a
fetch is in flight; a countdown counts down to the next auto-refresh.

**Own bug caught mid-implementation:** the first version reset-and-refetched atomically
in one tick (reset the countdown AND trigger the fetch in the same effect), so "0 /
reloading" was never actually visible — it looked like the countdown just silently
restarted. Fixed by splitting the ticker (a `useEffect` keyed on `[refreshMs]` only,
holds at 0, triggers nothing) from a separate trigger effect
(`if (refreshMs && secondsLeft === 0 && !isRefreshing) refreshSummary();`), with the
countdown reset to the full interval happening only inside that fetch's `.finally()`.
