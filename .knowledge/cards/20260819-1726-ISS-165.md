## Resolved per-agent model never persisted past the live stream

**Symptom:** after a run completes, there is no way to query which model an individual
agent actually ran on — not from `GET /api/runs/{id}/summary`, not from the DB.

**Root cause:** [BUG-CWF-002-custom-workflow](20260803-BUG-CWF-002-custom-workflow.md) fixed the *emission* half only — the
engine's `agent_complete` SSE event correctly carries the resolved per-agent model
(`engine.py:4977`, `"model_id": _resolved_model_id`). But `_apply_terminal_output_columns`
(`run_commands.py:2582`, the SOLE writer of `WorkflowRun.agent_outputs` for all 4
completion paths — launch, both resume entry points, and revision) never reads
`data.get("model_id")` in its `agent_complete` accumulator branch
(`run_commands.py:2651-2657`, pre-fix), so the value never lands in the persisted
`agent_outputs` JSON. Separately, `WorkflowRun.model_id` (the one column that IS
written) is populated from `getattr(user, "preferred_model", None)` — the account's
session default — completely unrelated to what `ModelResolver` actually resolved per
agent; querying it after the fact tells you nothing about the real per-agent model.

Even fixing the accumulator alone would not be enough: `runs.py`'s
`_SUMMARY_SAFE_AGENT_KEYS` allow-list (`runs.py:1243-1255`, pre-fix) filters every
agent dict returned by `/summary` and did not include `model_id`, so a correctly
persisted value would still never reach that endpoint.

**Fix:** [FIX-264](20260819-1726-FIX-264.md) (a) adds `current_agent["model_id"] = data.get("model_id")` to the
`agent_complete` accumulator in `_apply_terminal_output_columns`, and (b) adds
`"model_id"` to `_SUMMARY_SAFE_AGENT_KEYS`. Additive-only — no existing consumer reads
a fixed-shape `agent_outputs` schema. `WorkflowRun.model_id` itself is left unchanged
(redefining its semantics is a separate design question, not this bug).
