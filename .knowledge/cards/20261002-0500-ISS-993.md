# ISS-993

## What happened

Sibling of [ISS-662](20260917-1307-ISS-662.md) (register bug **QA-KB-063**), derived while
analysing why the e2e clarify probes drifted. **Marked INFERRED.** The engine path and the stored
events were read, but nobody has opened an affected run in the browser and nobody has decided what
the numbering is meant to be, so this is a lead, not a reproduced defect.

[FIX-517](20260917-1307-FIX-517.md) numbers a clarify card from the generic `round` field of its
event. That field is a counter local to ONE `ClarifyEngine.run()` call. The agent-driven path
([ADR-0047](20260918-ADR-0047.md), the `ask_user` tool) makes a NEW `run()` call for every ask, so
every ask is "round 1".

## Why the root cause implies this

ISS-662's root cause is that the e2e probes encode the old, round-less text as the lane's
vocabulary. Repairing the probes to match the numbered text assumes numbering makes consecutive
clarify cards DISTINCT. That holds only for rounds inside one `run()` call:

- `backend/agents/execution_engine/clarify_engine.py:289` sets `round_num = 0`; `:304-305` is
  `while round_num < effective_rounds:` / `round_num += 1`; the emits at `:337`
  (`questionnaire_ready`) and `:385` (`questionnaire_complete`) carry `"round": round_num`.
- `backend/agents/execution_engine/engine.py:8791-8793`, the `ask_user` fulfilment
  (`_derive_clarify`, `:8675`), calls `run(...)` with
  `max_rounds=1, replay_questions=questions, replay_round=1`. Every ask is round 1, whichever
  agent made it.
- `backend/app/agents/chat_narrator.py:167-175` turns `round: 1` into
  `Round 1: Before I build, I need to lock a few things down.` and
  `Clarifications round 1 answered`.
- The backlog workflow grants `ask_user` to four agents
  (`backend/agents/workflows/backlog/workflow.yaml` tool sets at `:553`, `:853`, `:1046`, `:1235`;
  their work files are `.clarify/solution.json`, `.clarify/api.json`, `.clarify/architect.json`,
  `.clarify/backlog.json`), and `backend/agents/workflows/prototype_v2/workflow.yaml:523` grants
  it too.

## Expected vs actual

- **Expected** ([D-21](../../tests/integration/DEFECTS-OBSERVED.md), "Expected: either one
  exchange, or two that are distinguishable from each other"): each ask reads distinctly.
- **Actual (INFERRED):** a backlog run with four asks shows four identical
  `Round 1: Before I build...` / `Clarifications round 1 answered` pairs, with different message ids.

## Why it matters to QA-KB-063

- The newest completed runs that carry clarify cards are these backlog families, so S-18-08's
  selector (`a_run_with(..., get_by_text(CLARIFY_ASK).count() > 1)`,
  `tests/integration/e2e/suites/18_chat_lane/test_chat_lane.py:287-291`) would pick one. With the
  old literal it fails with "D-21 is fixed" while the stutter is still on screen.
- A positive rewrite of S-18-08 ("each ask card has distinct text") would be red on those runs for
  THIS reason, not because of test drift. Keep the two apart, or the verifier will loop on
  QA-KB-063 for a defect it does not own.

## Decision needed (product)

Should an `ask_user` pass carry its own number (a per-run counter across passes), a label (the
agent that asked), or stay unnumbered? That is the owner's call and is not part of QA-KB-063.
Until it is made, do not change `_derive_clarify` to "fix" the numbers.

## What would settle this

Open `/runs/78e185fb-c032-4154-8552-774781b6e5df` and count the `Round 1: Before I build` cards,
or unit-test `_derive_clarify` twice against a recording `ClarifyEngine` and compare the `round`
each call emits.
