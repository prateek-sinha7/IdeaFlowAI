# ISS-065

## Title

No UI surfaces PER-ARTIFACT versions inside a run. artifact_refs durably stores every version (run d5dbc9f2 holds spec v1/v2/v3, task_list v1/v2, summary v1/v2) and GET /api/runs/{id}/artifacts already returns version per node, but the only FE caller is WorkflowHistory.tsx:303, hard-coded to kind="clarifications". The "Version v1 ▾" chip users DO see is a different axis — the whole-RUN family via getRunFamily() (parent_run_id), so three in-run revision cycles change it not at all (verified live: /family returned 0 members, no v2/v3 anywhere on the run screen). This invisibility is why FIX-217 shipped undetected — a spec was silently rewritten and nothing on screen said so. Data, API and the Concierge's list_refs/get_ref tools all already exist; this is wiring on an axis that is already there. Do NOT reuse the existing "Version" chip — two meanings on one control is what made this confusing.

Verified live 2026-08-11 on runs 6e38b9a7, 5ecb990f, d5dbc9f2. Discussed at length but never filed until now.
