## What was wrong

`BUG-20260828-021300-library-skills`. On `/library?tab=skills` one of 186 skill cards —
`html-deck-to-pptx` — rendered with a blank category-badge line and could not be reached by
clicking any of the nine category pills; only "All" or a name search surfaced it. The same
skill was equally unreachable in the composer's skill picker, which filters the same catalog
by the same equality ([ISS-570](20260829-0004-ISS-570.md)).

## Root cause

`backend/app/agents/skills_catalog.py:112` built the field as
`category=metadata.get("category", "")` — an absent `category` key in a skill's `SKILL.md`
frontmatter silently became an empty string. `backend/skills/global/html-deck-to-pptx/SKILL.md`
is the only one of the 186 skill folders whose frontmatter carries no `category:` line
(verified by scanning every `SKILL.md`), so it was the only entry with `category: ""`.

`backend/app/api/skills.py:35` then derives the pill list as
`categories = sorted({e.category for e in entries if e.category})` — the `if e.category` clause
drops the empty string, so no pill's `id` is ever `""`. Both consumers of the resulting
`GET /api/skills/library` response filter by strict equality against a pill id
(`LibraryPage.tsx:706` `s.category === skillCategory`, `AgentSkillsPicker.tsx:82`
`s.category === category`) and render the raw value into the badge, so the one skill with a
falsy category shows a blank badge and matches no pill.

`backend/app/agents/hooks_catalog.py`'s `_load_one` carried the same shape one field over: its
required-field gate tested key PRESENCE only (`missing = [f for f in required if f not in
metadata]`), so a `HOOK.md` declaring `event: ""` (or `event:` with no value, which YAML parses
as `None`) would pass the gate, survive into `list_global_hooks()`, and then drop out of
`app/api/hooks.py:33`'s `events = sorted({e.event for e in entries if e.event})` — the identical
reachability gap on the Hooks tab. Latent: all 8 real hooks declare a non-empty `event`
([ISS-571](20260829-0004-ISS-571.md)).

## What changed and why there

Two loader edits, both in the one function each catalog's entries route through — no API,
frontend or `SKILL.md` change:

- `backend/app/agents/skills_catalog.py` `_load_one` —
  `category=metadata.get("category", "")` becomes
  `category=metadata.get("category") or "uncategorized"`. `or` (not a `.get` default) so a
  present-but-empty `category: ""` is caught as well as an absent key. Every consumer reads
  this through the one `GET /api/skills/library` response and the one
  `frontend/src/hooks/useSkillsCatalog.ts` hook, so this single line fixes the Library badge,
  the Library pill filter AND `AgentSkillsPicker`'s pill filter in the Canvas rail / Simple-view
  row / agent drawer — no second frontend change. Any future folder-drop skill without a
  category inherits the same reachable default instead of reproducing the defect.
  `_get_icon_for_category("uncategorized")` falls back to `Award`, and
  `frontend/src/lib/skillIcons.ts:35` does the same, so the new pill and card get a valid icon
  with no icon-map entry.
- `backend/app/agents/hooks_catalog.py` `_load_one` — the required-field gate becomes
  `missing = [f for f in required if not str(metadata.get(f) or "").strip()]`, so a blank
  `event` (or `id`/`name`/`description`/`trigger`) is rejected with `GlobalHookError` exactly
  as an absent key already was, and `list_global_hooks()` drops the entry rather than admitting
  one no event pill can select. Per ISS-571 this is the right mirror for hooks: `event` is a
  small closed set (`PreToolUse`/`PostToolUse`/`Stop`/`SessionStart`/`SessionEnd`), not an open
  text field like a skill category, so rejection beats defaulting. Message updated to "missing
  or blank required field(s)". All 8 real hooks still load, over 4 distinct events.

Not changed: `app/api/skills.py:35` and `app/api/hooks.py:33` keep their `if e.category` /
`if e.event` clauses. With the loaders guaranteeing a non-empty value they are now no-ops, and
removing them would widen the diff without changing behaviour. `html-deck-to-pptx/SKILL.md` was
NOT given a hand-written category — choosing which of the nine existing categories it belongs
to is a content decision no card covers, and it would fix one row of data rather than the
mechanism.

## Verification in the running app

Backend reloaded (`--reload`, `*.py`); `GET /api/skills/library` as qa-admin returns
`total_count: 186`, `html-deck-to-pptx` `category: "uncategorized"`, and the derived pill list
gains `uncategorized` (11 entries including `all`). Driven in real Chrome:

- `/library?tab=skills` — the card's category badge reads `UNCATEGORIZED` (was `""`); an
  "Uncategorized" pill renders; clicking it navigates to
  `/library?tab=skills&category=uncategorized` and leaves exactly 1 card in the grid, the
  `html-deck-to-pptx` one. Control: the "Research" pill still filters to `?category=research`
  with `html-deck-to-pptx` absent.
- `/workflows/ppt/canvas` → agent node → config-rail **Skills** tab (the EDITABLE
  `AgentSkillsPicker` mount) — the "Uncategorized" pill renders enabled, and clicking it leaves
  the `html-deck-to-pptx` row visible, which is exactly the ISS-570 symptom.

## Deferred

The two e2e files above assert the right behaviour with the wrong locator/surface and cannot
XPASS as written. They were not edited here — a fixer editing a red test to green is the
inversion this repo has been bitten by before. 6-verifier owns removing the xfail markers and
should repair them in the same pass: ISS-329's second test needs a plain
`get_by_role("button", name=<label>, exact=True)` (or a `pill()` variant that tolerates a
count-less pill), and ISS-570's needs an editable mount — the composer canvas rail — rather
than the readOnly Library drawer.
