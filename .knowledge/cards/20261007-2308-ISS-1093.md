# ISS-1093

**Register source:** sibling derived during the analysis of `QA-KB-088` on 2026-10-07 (root [ISS-947](20261002-0107-ISS-947.md)). Not yet its
own bug row.

**Confidence:** CONFIRMED. Counts and test names come from running each file once, at HEAD `33d55657`. Evidence:
`evidence/qa-kb-088/08-analyze-sibling-unit-files-pytest-summary.txt`.

## Condition

The same guard as [ISS-947](20261002-0107-ISS-947.md) (`backend/tests/unit/conftest.py:90-123`, raising at `:81`), hitting two files that have
nothing to do with spec 016. Both were written before the guard existed and build their own in-memory SQLite engine
(`test_chain_projection.py:54`, `test_authz_bounded_calls.py:68` and `:88`).

| file | authored | collected | passed | setup errors |
|---|---|---|---|---|
| `tests/unit/test_chain_projection.py` | `e7305f9dd`, 2026-09-10 (sandbox-git-versioning-v2, Task 11.9) | 11 | 0 | 11 |
| `tests/unit/test_authz_bounded_calls.py` | `1e329e47b`, 2026-09-04 | 7 | 2 | 5 |

Neither file name appears in `LEDGER.md`, `BUGS.md` or `INDEX.md`.

## What is left unguarded

- `test_chain_projection.py` is the IDOR gate for the `chain_source` field of `GET /api/runs/{id}` (Requirement 21 AC 4).
  `TestChainSourceCrossOwnerAbsent` (`test_cross_owner_source_projects_as_absent`, `..._does_not_leak_id`,
  `..._does_not_leak_status`) asserts a source run owned by someone else is never partially disclosed. No other test calls
  the projection: every other `chain_source` hit in `backend/tests` is a `chain_source_run_id` seed or an engine test.
- `test_authz_bounded_calls.py` covers `ScopedStore`'s bounded off-loop calls (`agents/authz.py`). The 2 tests that pass
  (`test_blocked_call_does_not_stall_a_concurrent_coroutine`, `test_timeout_raises_store_timeout_not_empty_data`) use a fake
  session. The 5 that error need a real session: `test_assert_owns_cross_owner_raises_same_permission_error`,
  `test_assert_owns_same_owner_does_not_raise`, both `test_read_events_returns_same_rows_*` and
  `test_get_run_returns_same_row_both_modes`. `StoreTimeout` and `_run_bounded` appear in no other test file.

## Fix direction (INFERRED, not applied)

Relocate the DB-backed tests; do not loosen the guard. `test_chain_projection.py` drives the runs router, so
`backend/tests/integration/api/test_chain_projection_api.py` is the matching place. `test_authz_bounded_calls.py` tests
`agents/authz.py`, so `backend/tests/integration/agents/` mirrors its subject; its 2 fake-session tests can stay in
`tests/unit`. Check each moved file for the second fault [ISS-947](20261002-0107-ISS-947.md) found: a router mounted with only
`get_current_user` overridden answers 401 on a `get_current_principal` route. `GET /api/runs/{id}` is not one of the eight
such routes (`settings.py:336,361`; `run_commands.py:628,1780,3249,5538`; `user_workflows.py:674,955`), so the projection
tests should need no extra override. That is read from the code, not run in the integration tree.

## Not siblings (already tracked)

`tests/unit/test_restore_guard_v3.py` fails for a stale `password_hash` seed (ISS-891); `tests/unit/test_admin_privilege_race.py`
is ISS-1064. Both are already open cards.

## Why the root cause implies it

Same guard, same missing step: a unit-suite file that opens its own SQLite engine was never relocated when
`09270703b` landed. The guard's own `conftest.py` docstring (`:9-13`) counts about 45 files that were building real engines
when it landed; these two are among the ones still unmoved.

## Resolution (QA-KB-088 fix, 2026-10-07)

[FIX-758](20261007-2338-FIX-758.md) moved both files whole, test harness only; the one edit in each is the first docstring
line, which named the file's own old path.

- `tests/unit/test_chain_projection.py` -> `backend/tests/integration/api/test_chain_projection_api.py`: **11 passed**
  (was 11 setup errors). Confirmed by run: with only `get_current_user` overridden, `GET /api/runs/{id}` needs no principal
  override, as this card inferred.
- `tests/unit/test_authz_bounded_calls.py` -> `backend/tests/integration/agents/test_authz_bounded_calls_db.py`: **7 passed**
  (was 2 passed, 5 setup errors). The 2 fake-session tests moved with the rest so the suite stays one file.

Evidence: `evidence/qa-kb-088/14` (before) and `15` (after).
