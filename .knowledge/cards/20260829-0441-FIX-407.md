## What was wrong

On every Library tab, opening an item's detail view and coming back — via the
detail view's X button, its scrim, or the browser's Back button — dropped the
search text and the category pill and re-rendered the full unfiltered grid.
Reported against the Hooks tab
(`bug-hunter/ledger.md`, `BUG-20260828-093757-library-hooks-id`, 3/3 cycles);
Agents, Skills and the Back-button path were filed as siblings off the same
mechanism.

## Root cause

The state was lost on OPEN, not on close — the analysis is
[ISS-360](20260828-1917-ISS-360.md)'s "Analyzer confirmation" section and is not
re-derived here. Two halves:

1. `frontend/src/lib/routes.ts:127,129,131` (pre-fix) —
   `libraryAgent`/`librarySkill`/`libraryHook` built a BARE detail path
   (`` `/library/hooks/${slug}` ``) with no query string, while
   `routes.library` at `:121` already accepted `{tab, category}`. Pushing that
   bare path changes the `[...view]` catch-all's own segments, which remounts
   the page (`frontend/src/app/[...view]/page.tsx:3238`, this codebase's own
   confirmed finding) and reinitializes every `useState` in `LibraryPage`.
2. `frontend/src/components/library/LibraryPage.tsx:522,537,539` (pre-fix) —
   `searchQuery`/`skillSearch`/`hookSearch` were plain `useState("")` with no
   URL derivation anywhere, and there was no `search` query param in
   `routes.library`'s shape for them to derive from. So even the category
   states, which DO seed from `searchParams.get("category")` (`:520-521`), came
   back as `"all"`: the URL being navigated to no longer carried the param.

`closeDetailModal` (`:635-641`) was never the defect — it correctly threaded
whatever state it was handed, and that state had already been reset to defaults
before the X button was ever clicked.

## What changed and why there

**`frontend/src/lib/routes.ts`** — one shared `LibraryParams`
(`{tab, category, search}`) plus a `libraryQuery()` helper carrying the existing
"`agents` is the default tab, `all` the default category, so omit them"
normalization. `routes.library` now goes through that helper (and so gained
`search`), and the three item-detail builders take the same optional params and
append the same query string. Fixed in the builders, not per-caller: all three
tabs and both exit paths funnel through `routes.ts` (ADR-0018), so one change
covers the four cards.

**`frontend/src/components/library/LibraryPage.tsx`** — five edits, all on the
already-established category pattern:

- `urlSearch = searchParams.get("search") || ""` seeds all three search states,
  exactly as `urlCategory` already seeds all three category states.
- `applySearch(value)` is now the single writer of the active tab's search text:
  it sets that tab's state AND `router.replace`s the list URL with the tab's
  category alongside the new search. It is an event-handler write, never an
  effect — the T13 comment in this same file documents why a mount-observing
  URL write is not an option here. The search `<input>`'s `onChange` and all
  three `EmptyGridState onClear` buttons route through it, so the URL can never
  hold a search the user has cleared.
- The three category chips (`:760`, `:842`, `:947` pre-fix) pass the tab's
  current search along in their `router.replace`, so writing one filter no
  longer clobbers the other on the URL. This is what makes the Back button work
  ([ISS-594](20260829-0117-ISS-594.md)): Back replays the history entry
  verbatim, so the search has to be ON that entry.
- The three card-open handlers pass `{tab, category, search}` to the detail
  builders, so the remount reads the filters straight back off the detail URL.
- `closeDetailModal` threads the active tab's search back onto the list URL the
  same way it already threaded the category.

Not changed: the `Tabs onChange` URL write still omits `search` — switching tabs
legitimately switches to that tab's own (separate) search state, and no card
covers it. Pre-existing unused `ICON_TINTS` / `getInitials` in this file were
left alone.

## Verification

`page.fill` + a pill click now produce `/library?tab=hooks&category=SessionStart&search=session`;
opening a card pushes `/library/hooks/session-start?tab=hooks&category=SessionStart&search=session`;
X-close pushes the list URL back with both params; Back pops to the list entry
that already carries both.
