## What was wrong

BUG-20260828-025500-library-hooks, 3/3 in the browser: on the hook detail view
(`/library/hooks/<hook-id>`) the header "Copy" button gave no feedback of any kind — label
stayed "Copy", icon stayed the `lucide-copy` glyph, no toast, nothing new in the page text.
A user could not tell whether the copy succeeded, failed, or did anything.

The root cause was not specific to that button. Every Copy button in the app had hand-rolled
its own `navigator.clipboard.writeText` call with **no failure path at all**, in two flavours:

- **silent on rejection** — `await`/`.then()` with no `catch`: the success state is never
  reached, the rejection becomes an unhandled promise rejection visible only in devtools, and
  the button reports its default label forever. This is the reported symptom.
- **false positive** — fire-and-forget with an unconditional `setCopied(true)` on the next
  line: the button claims "Copied" for a write that never landed.

## Root cause

`frontend/src/components/library/LibraryPage.tsx:351-355` (`HookDetailModal.handleCopy`,
line numbers as of [ISS-331](20260828-1840-ISS-331.md)):

```
const handleCopy = async () => {
  await navigator.clipboard.writeText(copyText);
  setCopied(true);
  setTimeout(() => setCopied(false), 2000);
};
```

Blast radius re-grepped before editing (`grep -rn "navigator.clipboard" frontend/src`), and
ISS-331's list still holds: 12 `navigator.clipboard.writeText` call sites across 9 files, 10
of them (7 files) carrying one of the two shapes above. The grep also turned up **two call
sites the cards missed** because they use optional chaining
(`navigator.clipboard?.writeText`) — `results/artifactPreview.tsx:406` and
`preview/PreviewPanel.tsx:890` — deferred to [ISS-599](20260829-0340-ISS-599.md) rather than
changed here, since no card or test covers them.

## What changed and why there

New file `frontend/src/hooks/useClipboardCopy.ts` — one `try/catch` around
`navigator.clipboard.writeText`, returning `{ copied, failed, copy }`. `copied` only flips
after the write actually resolves (kills the false positives), `failed` is set on rejection
(kills the silence), both auto-clear after `resetMs` (default 2000, one caller passes 1500 to
keep its existing timing), and the reset timer is cleared on unmount. A missing
`navigator.clipboard` throws synchronously inside the same `try`, so it lands in `failed` too.
The hook sits beside `useEscapeToClose.ts`, which was lifted out of this same file for the same
reason (a modal behaviour every component re-wrote).

Ten call sites in seven files now call `copy(text)` and render a failure state with the same
inline label swap they already used for `copied`:

- `library/LibraryPage.tsx` — `HookDetailModal` (ISS-331) and `SkillDetailModal` (ISS-555).
  Both modals drive **two** things off one `copied` state, so the failure state is one
  `Copy failed` span in the modal header rather than a label swap on each button; the existing
  shared-`copied` behaviour is left exactly as it was.
- `results/AgentDetailPanel.tsx` — `InputPromptSection` (ISS-556), 1500ms preserved.
- `preview/AppBuilderPreview.tsx` — `CodeViewer` (ISS-557).
- `preview/MarkdownPreview.tsx` — `handleCopyAll` and `CodeBlock` (ISS-558).
- `preview/UserStoryPreview.tsx` — `handleCopy`, both render sites (ISS-559).
- `preview/PrototypePreview.tsx` — `handleCopySource` (ISS-560). Its `copyTimeoutRef` and the
  matching line in the cleanup effect were removed: this change orphaned them, the hook owns
  that timer now. `rebuildTimerRef`'s cleanup is untouched.
- `handoff/IntegrationsCard.tsx` — `handleCopyInstall` and the newly-minted-API-key copy
  button (ISS-561). The key button had no `copied` state at all (`.then(() => {})`); it now
  shows `Copied` / `Copy failed`, which matters most there because the token is shown once.

One guard in the hook rather than a patch per button: patching only `HookDetailModal` would
have left the nine siblings the cards predict. `chat/ArtifactCard.tsx` and
`chat/MessageBubble.tsx` already catch-and-log and are NOT filed as siblings by ISS-331; they
are deferred with the two optional-chaining sites to [ISS-599](20260829-0340-ISS-599.md).
