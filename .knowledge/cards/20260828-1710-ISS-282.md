## Description

Validated from bug register entry **BUG-20260828-014937-runs-id-stream**. Loading
`/runs/{id}/stream` for a run whose server status is `diverted` (confirmed via
`GET /api/runs/{id}`: `"status": "diverted"`, `completed_at` already set, `output: null`,
`deliverable_filename: null` — permanently terminal, only 2/3 agents ever ran, no
auto-resume path) auto-selects the Preview tab and renders the neutral, plain-text
"Output will appear here" placeholder — the exact same copy shown for a genuinely live,
in-progress run whose output simply has not arrived yet.

Root cause (`frontend/src/components/preview/PreviewPanel.tsx:644-654`): the
`reopenFailureSignal` computation, which decides whether to show a state-aware terminal
affordance instead of the neutral empty state, only tests:

```
reopenedRunStatus === "failed" ||
reopenedRunStatus === "cancelled" ||
reopenedRunStatus === "degraded"
```

`"diverted"` is not in this list, so `reopenFailureSignal` is `false`, `terminalFailure`
is `false`, and `showFailureAffordance` never fires for a diverted run — it falls through
to the generic `hasContent`-gated placeholder at line 1217. The sibling terminal state on
the identical route, `cancelled`, IS in the list and correctly renders an explicit,
status-aware message ("This run was cancelled — The run was stopped before producing a
deliverable..."), proving the mechanism exists and simply omits `"diverted"` as a
recognized terminal-failure-signal status.

## Reproduction (validated 2026-08-28, 3/3 cold starts, all cycles)

Each cycle from a cold start (fresh `page.goto`, no soft re-click):

1. Sign in as `qa-admin@flowinqa.com`. Navigate directly to
   `http://localhost:3000/runs/940ca699-b21b-4666-8e44-3370a08a4561/stream` (seeded
   diverted run "Ex A4 Human Divert").
2. Wait ~2s for the page to settle. The Preview tab is `[selected]` and the content pane
   shows only the plain-text paragraph "Output will appear here".
3. Confirmed via `GET /api/runs/940ca699-b21b-4666-8e44-3370a08a4561`: `status: "diverted"`,
   `completed_at` set (terminal), `output: null`, `deliverable_filename: null`.

Cycle 1: cold `page.goto` directly to the route — reproduced.
Cycle 2: navigated away to `/dashboard`, then cold `page.goto` back to the route —
reproduced identically.
Cycle 3: full hard reload (`location.reload()`) on the route — reproduced identically.

Deterministic, not a race — no axis variation was needed; the defect fires every time the
route is loaded for this diverted run.

For contrast, `/runs/a8dfa959-e233-4ddf-87ce-d9a942cefde3/stream` (a `cancelled` run) also
auto-selects Preview but correctly shows the status-aware "This run was cancelled" message,
confirming the app is capable of degrading honestly for a terminal state without a
deliverable and simply fails to do so for `diverted`.

## Expected

A run in a permanently terminal state with no deliverable (`diverted`, same as
`failed`/`cancelled`/`degraded`) should show a state-aware empty message on its Preview
tab, not the neutral "Output will appear here" copy reserved for an actively streaming
run whose output has not yet arrived.

## Actual

`reopenFailureSignal` in `PreviewPanel.tsx` does not test for `reopenedRunStatus ===
"diverted"`, so a diverted run's Preview tab renders the generic live-streaming
placeholder, giving no indication that the run is over and no output is ever coming.

## Root cause pointer

`frontend/src/components/preview/PreviewPanel.tsx:644-654` — `reopenFailureSignal`
enumerates `"failed" | "cancelled" | "degraded"` as terminal-failure-signal statuses but
omits `"diverted"`, which is likewise a permanently terminal, non-resumable status with no
deliverable. Adding `"diverted"` to this list (with copy analogous to the cancelled
affordance, e.g. "This run was diverted for human review and did not resume") would close
this per the same mechanism already proven for `cancelled`.

**SUPERSEDED by [ISS-390](20260828-2048-ISS-390.md):** the recommendation above, applied
alone, does NOT close the bug. `reopenedRunStatus` (the value `reopenFailureSignal` reads)
is gated upstream at `frontend/src/app/[...view]/page.tsx:3035-3041` to only
`"failed"/"cancelled"/"degraded"` — it is `undefined`, never `"diverted"`, by the time it
reaches this component. Both hops must change together; see ISS-390 for the full
two-part mechanism and the two further sibling call sites it found with the identical
gap.
