# ISS-970

**CONFIRMED by a test run and a file diff** (the drift itself). The consequence for the [ISS-472](20260829-0110-ISS-472.md) fix is INFERRED.
Found while analysing QA-KB-052; no ledger row, card or register mentions it (grep of `LEDGER.md`, `BUGS.md`, `INDEX.md` for `sample_subagents_parallel`, `entitlement_parity`, `TIER_PIPELINES`: nothing).

Line numbers are the working tree on 2026-10-02 (HEAD `024c03ef8`); none of the three files named in `globs` has uncommitted changes (`git status --short` is empty for them).

## What is broken

`frontend/src/lib/entitlements.ts` declares itself a "MIRROR of `backend/app/core/entitlements.py::TIER_PIPELINES`" (`:5`). The `enterprise` set ends:

```
    // file-manifest workflow: full-application user stories from a prototype (spec 021)   (:90)
    "backlog", "backlog_revision",                                                          (:91)
    // reference fan-out fixture — kept in parity with the backend map.                     (:92)
  ]),                                                                                       (:93)
```

The comment promises an entry and there is none. The backend has it: `backend/app/core/entitlements.py:89-91`, `# reference fan-out fixture — entitled so its canvas rendering can be compared against a real workflow.` then `"sample_subagents_parallel",`.

Observed 2026-10-02 (`evidence/qa-kb-052/analysis-proof.out.txt` sections 8 and 9):


basic, hexaware and pro match; only enterprise drifts, by exactly that one id.

How it happened (git): the backend entry landed in `ea2db4e02` (2026-09-04, "Entitle pdf_to_prototype and sample_subagents_parallel on the enterprise tier"). The frontend commit `1e329e47b` (2026-09-04) added a `"pdf_to_prototype"` entry plus the `// reference fan-out fixture` comment, and never the string the comment introduces. `pdf_to_prototype` is no longer in either file; the orphaned comment stayed.

## Why it matters to QA-KB-052

[ISS-472](20260829-0110-ISS-472.md)'s fix adds a hard client-side block built on `canRunPipeline(tier, effectiveType)`, exactly as `LaunchWizard.tsx:910` does after [FIX-497](20260829-0242-FIX-497.md). A hard block is only as correct as this mirror: every id the backend entitles and the mirror lacks becomes a false lock.

- `sample_subagents_parallel` is `user_launchable: true` and `is_beta: true` (`backend/agents/workflows/sample_subagents_parallel/workflow.yaml:55-56`), so the catalog tile shows "Coming Soon" and nobody reaches it by clicking.
  A direct `/create/sample_subagents_parallel` URL does reach `IdeaInputPage` today, ungated. After the ISS-472 fix, an `enterprise` account (which the backend allows) would see "Your plan does not include this deliverable." there, because `getUpgradeTier("enterprise", ...)` returns `null` when no tier lists the id (`entitlements.ts:121-127`).
- Impact today is nil (beta, fixture). It is an instance of the drift class the parity test exists to catch (its module docstring names earlier ones: `hello_html`, `custom_revision`, `od_prototype_revision`), and the lock turns each future one from "card greyed" into "route unusable".

A minor aside in the same test file: the docstring of `test_user_launchable_manifest_is_entitled_somewhere` (`test_entitlement_parity.py:120-123`) calls `sample_subagents_parallel` "launchable and entitled to nobody", which the backend (`:91`) contradicts. The case still skips correctly because the manifest is beta, so the test is unaffected; the prose is stale.

## Expected vs actual

- **Expected:** the mirror lists every id the backend lists, per tier; the parity test is green.
- **Actual:** one id is missing from `enterprise`; the test is red.

`frontend/src/lib/entitlements.ts`, enterprise set, directly under the `:92` comment: `"sample_subagents_parallel",`. Frontend only: the backend is authoritative (the file's own header, `:5`) and its entry is intentional. No test edit; the existing parity test goes green.
