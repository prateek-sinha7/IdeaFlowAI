# FIX-717

## What was wrong

This fix is for bug report QA-KB-053. The root cause is the analysis on [ISS-665](20260917-1311-ISS-665.md) (re-analysis of
2026-10-02) and its four siblings. I did not re-derive it.

- All members of a revision family share ONE sandbox, the chain root's (`run_files.py:939-940`).
- So a sandbox read with no `ref` is the live tree, which holds the NEWEST member's files.
- `resolveRunDeliverable` (`api.ts`) had no `ref` parameter. FilesTab, its "From v{n-1}" section and the header
  resolved every deliverable against the live tree.
- The row's Download, the PDF preview and the server-side Figma export also read the live tree.
- Result: an older member's Files tab named, sized and served the newest member's file under the older version's label.
  Real data is in `evidence/qa-kb-053/family-probe.out.txt`. In family `463e6c0b-…`, v2 showed 90.9 KB where its own
  file is 84.8 KB.

## What changed, and why there

Line numbers are for the working tree after the change. `PreviewPanel.tsx` and `api.ts` also carry another session's
uncommitted hunks, which were left intact: `VersionView.status`, `selectGen`, and `ArtifactNode`.

1. **The shared resolver**, which all three callers route through ([ISS-665](20260917-1311-ISS-665.md),
   [ISS-975](20261002-0346-ISS-975.md)).
   - `api.ts:1614` gains `ref?: string`.
   - `:1630` lists `getRunSandbox(token, runId, ref)`.
   - `:1646` returns `{ ...hit, ref }`.
   - `SandboxFile.ref?` is new (`:1565`).
   - At v2, `.chain/Backlog.pdf` is now the path found; it is the only copy there. Before, the live root `Backlog.pdf`
     was found, and it 404'd at the ref.
2. **FilesTab** ([ISS-665](20260917-1311-ISS-665.md), [ISS-972](20261002-0346-ISS-972.md), [ISS-974](20261002-0346-ISS-974.md)).
   New optional props, so every existing caller is unchanged:
   - `selectedRef?: string | null` (`:56`);
   - `parentGitTag?: string | null` (`:61`). The red test was written against this name, so this is the name used.

   What uses them:
   - The current-row effect resolves at `selectedRef`, with deps `[runId, isRunning, selectedRef]` (`:573-588`). A
     `null` skips reconciliation.
   - The descriptor carries the ref (`:498`), and the row's Download reads at it (`:757`). This covers every download
     surface: the hero, the rows, Download All and the cards.
   - The base section resolves only at `parentGitTag`, and keeps its derived rows without one (`:550`).
   - The Figma path reads `prototype.html` at the ref (`:859`) and captures the ref for `exportFigmaZip` (`:873`, `:1260`).
     A `null` skips the server path for the client-side walk of the member's own HTML.
3. **PreviewPanel** ([ISS-973](20261002-0346-ISS-973.md), [ISS-975](20261002-0346-ISS-975.md),
   [ISS-972](20261002-0346-ISS-972.md)).
   - `displayRef` and `activeParentGitTag` are computed once, beside `activeParentRunId` (`:874-877`).
   - The header's resolve and bundle listing now read at `displayRef` (`:1449`, `:1455`), the same tree its Download
     reads (`:1506-1507`).
   - The Download IIFE gained a `.catch` with an alert (`:1519`). Before, a failed read was a silent unhandled rejection.
   - `GenericDeliverablePreview` → `SandboxPdfPreview` gets `selectedRef={displayRef}` (`:1688`, `:231`).
   - FilesTab gets `selectedRef`, `parentGitTag` and `key={activeRunId}` (`:1950`). The key is ISS-972's hazard: the
     component stays mounted across a version switch, so an open "From v{n-1}" section kept the previous parent's rows
     under the new label.
4. **SandboxPdfPreview** ([ISS-973](20261002-0346-ISS-973.md)).
   - `selectedRef?: string | null` is forwarded to `getRunSandboxFileBlob` (`:27`).
   - `null` renders `fallback` and does not read another member's PDF (`:23`, `:40`).
5. **Figma export** ([ISS-974](20261002-0346-ISS-974.md)).
   - `figmaExporter.ts` adds `?ref=` to the request (`:43`).
   - `run_figma_export.py:723` takes `ref: str | None = None`. It validates the ref with `_validate_ref` (`:751`), reads
     `read_file_at_ref(safe_ref, "prototype.html")` (`:753`; 404 when the file is absent at that version), and renders
     from a temp file in `<sandbox>/.browser/` (`:789`). The file is unlinked in a `finally` (`:805`).
   - The card asked for "the sandbox's own scratch". I used `.browser/` because it is git-ignored (`RESERVED_PATHS`), so a
     concurrent revision's commit can never pick the file up. It also keeps relative URLs inside this user's workspace.
     The OS temp dir would let an agent-authored page frame `.` and screenshot the server's `/tmp` listing.
   - All 10 `prototype.html` files on disk are self-contained (no relative `src`/`href`), so the different render
     directory changes nothing for today's prototypes.

### Decisions the cards left open

- **Tag matches no member** ([FIX-516](20260915-1420-FIX-516.md)'s fallback, where only `sandboxSelectedRef` is set):
  `displayRef` is that tag. The Files row therefore follows the header Download and the Preview tab
  (`RefVersionPreview`), which already read that tag.
- **Tagless older member, header Download**: I kept the old live read. Disabling the button is a UX call, now tracked
  in [ISS-1051](20261002-1242-ISS-1051.md).
- **Not touched**:
  - History's chain-detail view ([ISS-1049](20261002-1242-ISS-1049.md)). It has no family data to tell an older member
    from the newest.
  - The Workspace tab of an older member's own page ([ISS-1050](20261002-1242-ISS-1050.md)). ISS-973 calls this a
    product call.
  - `FilesTab.workspaceFilename.test.tsx`'s 3-argument mock. The extra argument it drops is harmless.
  - The `refSurfaces` FilesTab stub. That file is a FIX-603 guard, and the new `PreviewPanel.memberRef` test mounts the
    real FilesTab instead.

### One existing test assertion changed

`SandboxPdfPreview.test.tsx:19` asserted `toHaveBeenCalledWith("tok", "run-1", "Backlog.pdf")` with exactly three
arguments. ISS-973's contract makes the component always forward its ref slot, so the no-ref call is now
`(…, "Backlog.pdf", undefined)`.

The assertion now includes `undefined`, with a comment. That pins "no ref → live tree". The test follows the
card-mandated call shape. It is not the app bent to the test, and the app's behaviour for that call is byte-identical:
`runSandboxFileUrl` drops an undefined ref. No other existing test was edited.
