# ISS-1161

## Description

INFERRED sibling of [ISS-1067](20261007-2030-ISS-1067.md) (bug QA-KB-125), found while analysing it. ISS-1067 reports
`PrototypePreview.tsx:389`. The same three-line idiom is copy-pasted in four more places: `new Blob([html], { type:
"text/html" })`, `URL.createObjectURL`, `window.open(url, "_blank")`. Each produces a top-level document whose origin is
the app's. A top-level tab has no `sandbox` attribute to set, so a token fix to the iframes cannot reach these.

## Why the root cause implies it

The root cause in ISS-1067 has two halves. One is the iframe token. The other is that "Open in new tab" is implemented
per component rather than once, so every copy has to remember a wrapper that none of them has. These four are the copies
the report did not name.

## Evidence

CONFIRMED, read:

1. `frontend/src/components/preview/PreviewPanel.tsx:1590-1599`, `handlePreviewOpen`. It picks `mimetype` as
   `effGenericDeliverable?.mimetype` or, for ppt and prototype, `"text/html"`, builds `new Blob([content], { type:
   mimetype })` and calls `window.open(url, "_blank")`. It is wired as `onOpen={handlePreviewOpen}` at `:1973` and drawn
   by `PreviewChrome.tsx:162-168` (`aria-label="Open the deliverable in a new tab"`). It serves every renderer except
   the two self-chromed ones (`isSelfChromedRender`, prototype and app_builder), so it covers decks and the generic
   `text/html` path. That path's in-app iframe is the T-18-05 sandbox (`PreviewPanel.tsx:278`); this button opens the very
   same HTML unsandboxed one click later.
2. `PreviewPanel.tsx:2175-2184`, `PPTTabActions.handleFullScreen`, bound at `:2207-2214` (title "Open in new tab", label
   "Full Screen") and mounted at `:1811` for ppt runs with content.
3. `frontend/src/components/history/WorkflowHistory.tsx:1003-1008`, the History detail "Full Screen" button for `isPpt`.
4. `PPTPreview.tsx:208-213`, `handleOpenFullScreen`. A grep of `PPTPreview.tsx`, `PreviewPanel.tsx` and
   `PreviewChrome.tsx` finds its definition and no use. It is dead today and one JSX line from live.

Real Chrome 151 (`evidence/qa-kb-125/analysis-1-origin-probe.txt`):

- Variant E, `window.open(blobUrl)` of the agent HTML: the new tab's top-level origin is the app's, `auth_token` is
  readable, and so is `opener.localStorage`, because the tab keeps `window.opener`
  (`analysis-3-wrapper-probe.txt`, variant E).
- Variant F, the same blob with `<meta http-equiv="Content-Security-Policy" content="sandbox allow-scripts">` inside it:
  unchanged, origin and token still the app's. A `sandbox` directive is ignored in a meta element, so that one-line fix
  does not work.
- Variant G, a script-free wrapper blob holding `<iframe sandbox="allow-scripts" srcdoc="...">`: the agent HTML sees
  origin `null`, storage and parent and opener reads throw, and `window.opener` is `null` with `noopener`
  (`analysis-3-wrapper-probe.txt`, G1 and G2).

INFERRED, not driven in the app UI: that the four sites behave as variant E. The mechanism is identical to the one the
validator drove for `PrototypePreview.tsx:389` (`evidence/qa-kb-125/03-validate-attempt2-open-in-new-tab-app-origin.png`).
What would settle it: click each button on a completed run and read `location.origin` and
`localStorage.getItem("auth_token")` in the new tab.

## Expected vs actual

- Expected: opening agent HTML in a new tab gives it an opaque origin, as the in-app generic renderer and the share link
  do.
- Actual: a top-level blob document on the app origin with the session token in reach.

## Fix direction

Route all of them through the one helper that [ISS-1067](20261007-2030-ISS-1067.md) adds to `frontend/src/lib/`
(`openAgentHtmlInNewTab`: a script-free wrapper page, `noopener`). Delete the dead `handleOpenFullScreen`. One call site
per button, no `Blob` or `window.open` left in the components.

## Test notes

Offline vitest. Spy `window.open` and capture the `Blob` passed to `URL.createObjectURL`; click each button. Before the
fix the blob text is the agent HTML itself. After it, the blob text contains `sandbox="allow-scripts"` and `srcdoc=`,
contains no `<script`, and `window.open` receives `noopener`. A source guard over `frontend/src` should fail on any
`window.open(` of a `createObjectURL` result outside the helper.

## Resolution (QA-KB-125, 2026-10-09)

Resolved by [FIX-775](20261009-1625-FIX-775.md) through the shared helper of [ISS-1067](20261007-2030-ISS-1067.md). All four openers call `openAgentHtmlInNewTab` (`PreviewPanel.tsx` `handlePreviewOpen` for `text/html` and `PPTTabActions.handleFullScreen`, `WorkflowHistory.tsx` Full Screen), and the dead `PPTPreview.handleOpenFullScreen` is deleted. The guard case "no blob URL is opened in a new tab outside openAgentHtmlInNewTab" named exactly these files at pre-fix HEAD 01777a107 (WorkflowHistory 1, PPTPreview 1, PreviewPanel 2) and passes after. Non-HTML types in `handlePreviewOpen` still open as a plain blob: see [ISS-1172](20261009-1625-ISS-1172.md).
