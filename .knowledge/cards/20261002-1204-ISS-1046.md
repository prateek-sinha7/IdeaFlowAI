# ISS-1046

**Evidence status.** INFERRED sibling of [ISS-1042](20261002-1100-ISS-1042.md) (3-analyzer, 2026-10-02, QA-KB-094). The mechanism is CONFIRMED by reading and by EXECUTING each runner's real assertion block (extracted verbatim, `evidence/qa-kb-094/assert-sim-false-negative.js`) on a synthetic stream. That it fires on a live run is INFERRED: the one live run on record (`9eb70b6e-5a70-41e8-9d5f-fbb05e11440d`) had a well-behaved model reply. What would settle it: one live run where `pick-language` answers with prose, or any run with the corrected payload and a model that deviates.

## What is wrong

Both A4 runners end with an assertion block written for the engine as it stood on 2026-08-24, and two engine changes landed the next day without a matching edit.

1. **The decision check reads the wrong thing.** Auto `:174-184` and twin `:151-161` take `decided` from `textOf('pick-language')` (the step's own model reply) and print `✓ branch matches the recorded decision` only when it equals the branch that ran, else `✗ branch X does not match decision <decided>`. Since [ADR-0026](20260825-1600-ADR-0026.md) (`0b6570b85`) the gate routes on `ask`'s artifact (`condition_agent: ask`, `workflow.yaml:111`; `conditional.py:128-131`) and `pick-language`'s reply is not an input to the route at all; ADR-0026 verified routing stays correct "with non-JSON prose, an apology, and a zero-character model reply". Executing the real assertion block on a stream where every routing check is green but `pick-language` replied `Hola` prints `pick-language decided: null  (from "Hola")` and `✗ branch spanish does not match decision null` in BOTH runners (`evidence/qa-kb-094/assert-sim-false-negative.out.txt`). The twin's header also claims its checks "read the decision the engine actually recorded" (`:21-23`); that record is the `gate_events` row, and a routed gate publishes nothing on the stream (`conditional.py:164-167`: "a routed outcome emits no SSE event — that row is the only record").
2. **The block diagnostic describes a bug that was fixed.** Auto `:199-208` and twin `:176-185` say "A blocked conditional gate does NOT halt the run ... the cursor just advances", and the message reads "the run fell through instead of routing". [ISS-170](20260824-1610-ISS-170.md) (fixed 2026-08-25, `engine.py:7373-7402`) makes a post-step conditional block end the run as `pipeline_failed`. The 02:52 log shows both on consecutive lines: `pipeline_failed`, then `✗ conditional gate BLOCKED at custom-agent:pick-language — the run fell through instead of routing`.

## Why the root cause implies it

Same drift as ISS-1042, the other half of the same files: the runners are hand-maintained mirrors of engine behaviour, nothing in CI reads them, and an engine change that moves a decision path or a failure shape needs a matching edit that no process asks for. Fixing only the payload makes the auto runner route, then leaves (1) as a flaky verdict: its pass or fail hangs on a model reply the route ignores.

## Fix

Edit the assertion blocks of the two A4 runners only.

- (1) Drop the "recorded decision" check or make it informational (no `✗`). The auto runner already asserts the branch equals the answer it sent (`EXPECT`, `:165-169`). The twin is choice-agnostic by design, so it has no expected branch to compare against and keeps "exactly one branch ran", "both untaken branches skipped" and the output check.
- (2) Say "the run FAILED at the gate" and correct the stale comment.

The same "fell through" message is in 6 other runners (`run.ex_A2_branch{,_hola,_dutch}.http:197`, `run.ex_A3_divert{,_spanish,_dutch}.http:134-137`): a one-line text edit each, out of scope here.

## Test notes

After the fix, `node evidence/qa-kb-094/assert-sim-false-negative.js <runner>` (the runner path is argv[2]) must print no `ERR` line for the stream it builds. A static guard: neither A4 runner may contain `fell through`, and no `✗` may be conditional on `textOf('pick-language')`.

## Resolution (QA-KB-094 fixer, 2026-10-07)

Resolved by [FIX-750](20261007-2108-FIX-750.md).

1. The "recorded decision" check is dropped from both runners. The auto runner keeps its `EXPECT` branch check.
   The twin stays choice-agnostic, and its header no longer claims to read a recorded decision.
2. The block line now says "the run FAILED at the gate instead of routing", with its comment rewritten for
   ISS-170 and `condition_agent: ask`.

`node evidence/qa-kb-094/assert-sim-false-negative.js` printed 1 ERR line on each runner at HEAD `6dd945b6f` and 0
after the fix. Both parametrized cases went from XFAIL to XPASS(strict). The six other runners that carry the same
"fell through" text are now tracked in [ISS-1071](20261007-2108-ISS-1071.md) (open).
