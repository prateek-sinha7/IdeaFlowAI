# ISS-653

**Bug register entry:** QA-PS-006 (`BUGS.md#qa-ps-006`, `LEDGER.md`)

## Description

On a pipeline run with multiple review gates, each pending review-gate card
in the concierge chat reads "Review required" with no agent name. When a run
has multiple gates open (sequentially or across a scroll-back of history),
every one of these prompts is byte-for-byte identical, so a user cannot tell
which agent's output is awaiting review at a given gate.

This is the sibling of **ISS-650** (root cause of register bug QA-PS-004,
same file, same `ResultCard.tsx` gate-rendering branch): where ISS-650 covers
the *resolved* ("Review approved — build continues") text, this card covers
the *unresolved* ("Review required") text one line above it in the same
ternary.

## Reproduction (3/3, cold start each time)

Live gate messages are only observable on a run currently sitting at (or
before completion, mid-gate) a pending review gate — a completed run's gates
have already flipped to the resolved branch. Used three separate
`waiting_for_user` runs already present in the system, each visited via a
fresh cold navigation (`/dashboard` -> `goto` the run URL directly, not a
click-through):

- **Cycle 1** — cold `goto` of `/runs/0ab2ba21-eb1b-42ee-bab2-e5b137ca4f8d`
  (fresh page load, no prior state). Chat transcript showed "Run started"
  followed by a gate card reading exactly "Review required", no agent name,
  with an "Open in Steps" link.
- **Cycle 2** — cold `goto` of `/runs/81bc416e-c137-4d49-82ff-f02f9f30cead`
  (different run, fresh load). Identical "Review required" text and
  structure.
- **Cycle 3** — cold `goto` of `/runs/3fcd25a9-8725-4b5d-b181-1a4d2e9fcba0`
  (third distinct run, fresh load). Identical "Review required" text and
  structure.

Condition: does not depend on tier, theme, viewport, or timing — the text is
render-time-invariant (confirmed by source read, matching ISS-650's finding
for the resolved branch). Reproduces on any run whose transcript contains an
unresolved gate card, regardless of which agent's gate it is.

## Expected vs Actual

- **Expected:** each pending review prompt names the agent that requires
  review, e.g. "Specify Agent review required" / "Plan Agent review
  required".
- **Actual:** every pending review prompt is the literal, unconditional
  string "Review required" — identical regardless of which agent's output
  triggered the gate.

## Root cause

`ResultCard.tsx`'s gate-rendering ternary (lines 139-145) hardcodes both
halves of a gate card's life-cycle with no `agentName` interpolation on
either branch:

```tsx
// frontend/src/components/chat/ResultCard.tsx:140-145
const inlineText =
  kind === "gate" && message.resolved
    ? "Review approved — build continues"     // ISS-650
    : kind === "gate"
    ? "Review required"                        // this card (ISS-653)
    : message.content;
```

Same mechanism as ISS-650: `useRunChat.ts`'s gate-resolution path does not
plumb an `agentName` field onto the `ChatMessage` object for gate turns
(neither the initial unresolved emission nor the later `resolved` flip), so
there is nothing for `ResultCard` to read even if the ternary above were
changed. `GateAwaitingCard` (the Steps-panel affordance, fixed by FIX-123)
already has `laneGate.agentName` available at the point a gate opens, so the
name exists in context earlier in the pipeline — it simply never reaches
this chat-lane literal. Fixing ISS-650's plumbing (adding `agentName` to the
gate `ChatMessage` shape via `useRunChat.ts`) is the same prerequisite this
card's fix needs; the two literals should be replaced together in one pass
over this ternary.
