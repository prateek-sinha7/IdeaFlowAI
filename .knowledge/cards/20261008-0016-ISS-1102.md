# ISS-1102

## Description

Sibling of [ISS-1101](20261008-0016-ISS-1101.md), found by running the other callers of `_ResumeHarness` one file at a time. Reproduced, so it is not a lead. Two findings in one file, both from the same root (`StepRaised` makes a scripted crash terminal, see [ISS-1101](20261008-0016-ISS-1101.md)):

1. `tests/integration/agents/test_cancel_stops_resumed_run_db.py::test_cancel_stops_a_resumed_drive_and_writes_the_terminal_row` (`:207`) is red at `:236`: `assert 'pipeline_cancelled' in ['workflow_validated']`. The log carries the same `resumed-stream drive(iss084-…) failed mid-drive: Cannot transition run … from terminal state 'failed' to 'generating'` (`evidence/qa-kb-097/analysis-04-cancel-test-at-HEAD.txt`). Its first assertion, `call_log == calls_before` ("a cancelled resume kept dispatching agents"), passes only because the drive dispatches nothing at all.
2. `test_a_cancelled_resumed_run_is_not_re_adopted_by_auto_resume` (`:251`), which its own docstring calls "THE REGRESSION GUARD" (`:252`) and the module docstring calls "the guard that matters most" (`:25-26`), is green and cannot go red any more.

## Evidence (observed 2026-10-08, HEAD `5e22d3238`; this file alone, repo untouched)

- HEAD: 1 failed, 4 passed. With the plugin of [ISS-1101](20261008-0016-ISS-1101.md) that wraps `resume_run` in `forget_run`: 5 passed. With the harness reset: 5 passed (`analysis-03-harness-reset.txt`).
- Row status after instance A (`analysis-plugins/kb097_interrupted_row.py`): both tests that call `_interrupted_run` see `status='failed'`, although its docstring says it leaves "a resumable, non-terminal run" (`:167-170`). `StepRaised` makes `StateMachine._persist` write `failed` to the row.
- Mutation (`analysis-plugins/kb097_mutant_cancel_ignored.py`: `ExecutionEngine._resolve_resume_cancel_event` returns None, i.e. the ISS-084 defect, "the resumed driver never threaded a cancel_event"): with the harness reset, 3 of 5 fail (the two wiring tests and the headline test) and the re-adoption guard stays PASSED; on HEAD without the reset the result is the same. A guard that survives the defect it names guards nothing.
- Bisect of that guard (`git archive` exports, `evidence/qa-kb-097/analysis-14-cancel-file-bisect-and-mutant.txt`): at `60bbe040d^` the file is 5 passed and, under the mutant, 4 failed, THE GUARD INCLUDED; at `60bbe040d` the file is 1 failed / 4 passed and, under the mutant, 3 failed and the guard PASSES. The commit that made the guard vacuous is the one that broke the headline test.

## Cause (CONFIRMED)

1. Finding 1: the cause of [ISS-1101](20261008-0016-ISS-1101.md). The scripted crash is terminal in the process-global state machine, the resumed drive dies at `transition(.., "generating")` (`engine.py:5739`) before it can read the cancel event, and nothing is emitted.
2. Finding 2: the guard's premise, "RED pre-fix: the cancel is ignored, the resumed drive dies on the scripted wave crash with the row still `generating`, and the restore scan picks the run straight back up" (docstring `:258-259`), stopped being true with `60bbe040d` (measured above): instance A leaves the row `failed`, and an ignored cancel makes instance B's crash a `StepRaised` too, also `failed`. Both ends are terminal, so `adopted == []` holds whatever the cancel does.

## Fix (test-only)

- Finding 1: nothing beyond the harness reset in [ISS-1101](20261008-0016-ISS-1101.md) (this file imports `_ResumeHarness` from `test_restart_resume_db`).
- Finding 2: give the guard a premise that can fail. Put the row back to `generating` after instance A exactly as `test_restart_resume_db.py:5367-5369` does, and assert what the property is about, the status of the cancelled resume itself: `row.status == "cancelled"` after `engine_b.resume_run(run_id)` (with the defect put back B crashes and ends `failed`, so this goes red). Acceptance check: re-run `kb097_mutant_cancel_ignored.py` and see the guard FAIL.

What a naive fix would break: making the scripted crash non-terminal again by special-casing it in `_guarded_step` re-opens the 48b0811e hole FIX-669 closed (a raising step must end the run with one `pipeline_failed`).
