## What was wrong

`useHooksCatalog.ts` rebuilt the `hooks: HookDef[]` array inline on every render
call (`reduxHooks.map(...)` outside any memoization), producing a new array
reference on every render even when the underlying Redux state was unchanged.
`LibraryPage.tsx`'s T15 cold-mount effect uses `HOOKS.find(h => h.id === slug)`,
which depends on a stable reference to detect when the catalog has loaded. A
permanently-new reference never produces a stable match, so a cold-link to
`/library/hooks/<id>` could leave `librarySlugAppliedRef` unset and the detail
modal unopened.

Root cause from [ISS-336](20260828-1846-ISS-336.md): sibling of ISS-232/FIX-340
for the hooks catalog. FIX-340 confirmed ISS-336 "expected to be cured" by the
preload parallelisation it shipped, but re-reading the source shows the unmemoized
array is a separate, independent problem — the effect depends on referential
equality and the `.map()` was not wrapped.

## What changed and why there

One file, `frontend/src/hooks/useHooksCatalog.ts`: wrapped the `reduxHooks.map()`
call in `useMemo([reduxHooks])`. When `state.hooks.hooks` is the same reference
(no new fetch result), `hooks` returns the same array reference. Added `useMemo`
import. This is the identical shape `useSkillsCatalog.ts` already uses — one
consistent pattern across both catalog hooks.
