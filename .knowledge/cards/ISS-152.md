# ISS-152

## Title

Every completed revision run silently lost 7 WorkflowRun output columns — the fourth caller BUG-R03 never wired. _drive_revision_to_queue (run_commands.py:2764), the app-layer dispatch path for EVERY *_revision pipeline run, wrote only status/completed_at on completion — never output, agent_outputs, token_usage, duration, model_id, deliverable_mimetype, deliverable_filename. Verified against 8a970205-5892-466a-89b0-f613b9dd021d (the only revision that had ever completed in this database — rate 1/1): all 7 NULL despite a real deliverable existing. The engine was innocent — _handle_revision already forwarded every event, including pipeline_complete's full payload, verbatim to the driver; it simply never accumulated what it received. Defeated FIX-249 (get_token_usage, shipped the same session) for every revision run, biased Analytics (revisions counted as $0 cost AND dragged down avg_duration as a zero-numerator completed row), hid the Run Detail KPI strip, and emptied GET /{id}/chain-context for anything chained off a revision. FIXED 2026-08-13 (FIX-250): wired the driver as the fourth caller of the shared _apply_terminal_output_columns mapping, mirroring the launch driver byte-for-byte. Live-proven on Bedrock: the Concierge now answers a real token/cost figure for a revision run.
