## Decision

A run owner can hand a deliverable to someone with no account by minting a share
token and sending them `/s/{token}`. This was "Option B" — an opaque capability
URL — chosen over per-recipient accounts or a signed-and-expiring asset URL.

## The boundary

`GET /s/{token}` is the only route in the system that answers without
authentication. That is the whole risk surface of this feature, so the response
is deliberately narrow: `output` and `deliverable_mimetype`, and nothing else.
A run row also carries `input`, `agent_outputs`, and user identity; none of it
is reachable through this route.

Anything that later widens that response is a change to the security boundary
and should be treated as such.

## Shape

Backend:

- migration `0040` — `share_token` (unique) and `share_expires_at` on
  `workflow_runs`; additive and nullable, so SQLite and Postgres both take it.
- `POST /api/runs/{id}/share` — owner-gated, mints a 30-day token via
  `secrets.token_urlsafe(32)`.
- `DELETE /api/runs/{id}/share` — revoke, idempotent.
- `GET /s/{token}` — unauthenticated; `Content-Type` read from
  `deliverable_mimetype` (SC-001).

Frontend:

- `next.config.ts` rewrites `/s/:token` to the backend in dev — there is no
  Next.js route handler behind that path.
- `RunHeader` renders a Share popover (public link, Copy, Revoke), loading the
  link from the API on open, and falls back to the legacy `onShare` when no
  `runId` is present. `PreviewPanel` supplies the `runId`.
