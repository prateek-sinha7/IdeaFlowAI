## Summary

INFERRED sibling of the QA-PS-023 root card, [ISS-700](20260922-1230-ISS-700.md). ISS-700's
own scope note says `single_file` "reads clean HTML off the sandbox file and is unaffected" —
true for its PRIMARY path, but `single_file` has a documented fallback branch that returns
`ctx.last_streamed` completely raw, with **no** `unwrap_artifact` call at all. That fallback is
a real, already-tracked-as-reachable code path ([ISS-184](20260825-2115-ISS-184.md) fired it
during override validation), so ISS-700's blanket "unaffected" does not hold for every
`single_file` code path — only the happy one.

## Root cause (code-traced; not yet exercised live)

`backend/agents/capabilities/deliverables/single_file.py:97-167` — `SingleFileResolver.resolve()`
has three fallback tiers:

1. `built = runner.sandbox.read(filename); if built: return built` (:132-134) — the happy path,
   genuinely unaffected (an agent-written file, not raw model chatter).
2. Revision fallback (:145-156) — when a `revision_original_html` seed exists, `looks_like_html`
   gates on the stripped/lowercased text starting with `"<!doctype"`/`"<html"` in its first 60
   chars; prose-prefixed streamed text FAILS that check and falls back to the clean seeded
   `original` instead, so this tier is incidentally safe.
3. **Forward-build fallback (:158-165)** — fires when nothing was written to `filename` AND no
   revision original exists (the exact condition [ISS-184](20260825-2115-ISS-184.md) documents:
   a shortened/overridden step list that omits the build agent):
   ```python
   if last_streamed.strip():
       logger.warning(...)
       return last_streamed
   ```
   This returns the model's raw streamed text completely unmodified — not even the narrow
   `unwrap_artifact` wrapper-strip that `streamed_text.py`/`ppt.py` at least attempt. Any
   reasoning prose the last agent emitted (with or without an `<artifact>` wrapper) reaches
   `final_output` verbatim.
- `_DEFAULT_NAME = "prototype.html"` (`single_file.py:40`) — the default deliverable filename
  for this strategy.
- `frontend/src/components/preview/PreviewPanel.tsx:217-222` — `GenericDeliverablePreview`
  only routes to the guarded `PPTPreview` when `deliverable.filename === "presentation.html"`.
  `"prototype.html"` does not match, so this falls into the same plain
  `<iframe srcDoc={...}>` branch (`PreviewPanel.tsx:223-256`) ISS-700 found unguarded — with an
  even less-cleaned string reaching it than ISS-700's own `streamed_text` case.

## Trigger

`deliverable.strategy == "single_file"` (the `prototype`/`prototype_revision` family) AND the
declared file was never written to the sandbox (e.g. an overridden/shortened step list that
skips the build agent — [ISS-184](20260825-2115-ISS-184.md)'s documented trigger) AND no
revision original was seeded AND the last agent's streamed output contains reasoning prose.

## Status

INFERRED. The missing-`unwrap_artifact`-call fact is confirmed by direct read of
`single_file.py:158-165`, and the fallback's reachability is independently corroborated by
[ISS-184](20260825-2115-ISS-184.md) having fired it during real validation. Not yet reproduced
against a live browser Preview render — that would need a `prototype`/`prototype_revision` run
whose step list omits `prototype-build` (or `prototype-build` otherwise fails to write the
file) while the last agent still streams reasoning prose.

## Fix direction (not applied — issue only)

Same shared fix as ISS-700 and [ISS-736](20260922-1404-ISS-736.md): once
`backend/agents/capabilities/deliverables/_artifact.py`'s `unwrap_artifact` (or a new sibling
helper) is hardened to slice to the first `<!DOCTYPE`/`<html` occurrence, apply it to this
fallback too — `single_file.py:165` currently returns `last_streamed` with no transform at
all, so it needs the call added, not just a stronger version of a call it already makes.
