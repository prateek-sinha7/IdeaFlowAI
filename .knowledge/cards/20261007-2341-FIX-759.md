# FIX-759

## What was wrong

This fix is for bug report QA-KB-095. The root cause is [ISS-1072](20261007-2125-ISS-1072.md)'s 2026-10-07 analysis and was not
re-derived here. Every cited line was re-read before editing.

Run `0f62f7bc` is the root of a two-member family whose newest member failed, so its own page is an "older member" and pins its
DB tag `v1` into the header resolve (`PreviewPanel.tsx:890-891`, `:1502`). Its sandbox directory is an EMPTY husk: a TTL-swept
dir re-created by the pre-FIX-727 `/sandbox/refs` ([ISS-996](20261002-0500-ISS-996.md)). Every workspace route decided expiry
with a bare `not sandbox.root.is_dir()`, which is false for an empty directory. So `list_sandbox` called the husk live
(`expired:false`), ISS-893's expiry-first guard let `_validate_ref` run, `list_tags()` answered `[]` (no `.git`), and the route
raised `400 invalid ref`. The same request on a properly swept family answers `200 expired:true`. The four sibling routes read a
husk the same way.

## What changed, and why there

- `backend/app/agents/sandbox.py:1411` gains `run_dir_expired(root: Path) -> bool`, one line:
  `return not root.is_dir() or not any(root.iterdir())`. It sits beside `sweep_expired`, the other definition of "expired".
- The five inline copies call it, each keeping its own response:
  - `run_files.py:942` `list_sandbox`: `expired = run_dir_expired(sandbox.root)`. A husk now answers `200 expired:true`, with or
    without `?ref`, so the Workspace tab says "Workspace expired" again.
  - `run_files.py:1045` zip and `:1157` file: 404 "Workspace expired" (was 400 with a ref).
  - `run_figma_export.py:746`: 404 "Workspace expired" (by read; no test drives figma on a husk).
  - `runs.py:2519` restore: 404 "Sandbox not found" (was 400 from the tag gate; by read).
- `_validate_ref`, the listing's expiry-first ordering (`run_files.py:949`), `list_tags` and `has_git` are untouched, so
  [FIX-727](20261007-1837-FIX-727.md)'s and [FIX-691](20261001-2149-FIX-691.md)'s constraints stand.

One predicate in the shared module is the root fix: every route that serves a workspace routes through it, so none can read a
husk as live again. No frontend change. `resolveRunDeliverable` (`api.ts:1614`) gets `files: []` from an expired listing,
returns null rather than throwing, and the header Download stays disabled. That is the honest state, because the workspace is gone.

## Deviation from the card's prescribed shape

ISS-1072 asked for "a read-only property next to `list_files`". It is a module function of `root` instead, still the single
definition. Two route tests drive the routes with duck-typed stub sandboxes that expose only `root`. Both replace the module's
`RunSandbox` name with a lambda: `test_iss720_ref_scoped_sizes.py` (`_Sandbox`) and `test_figma_export_ref_render_iss974.py`
(`_Sandbox`). A property, or a staticmethod reached through `RunSandbox`, raises AttributeError in both and would need two more
test edits. A function of `root` keeps both files green with no edit (6 passed, 3 passed after).

## Two test fixtures edited, assertions untouched (audit this)

ISS-1072 warned that "a directory that is only `ensure()`d now reads as expired" and named one file to grep, which has no such
case. Two other files did. Both went red with the fix, getting 404 "Workspace expired" where they assert 400 (observed,
`evidence/qa-kb-095/18-fix-fixture-edits-audit.txt` (a)):

- `test_run_files_ref_family_scope_api.py::TestRefValidationIsScopedToTheSandbox::test_an_enclosing_repo_tag_is_rejected`
  ([ISS-671](20260917-1345-ISS-671.md)). Its `_make_family_in_host_checkout` built the chain-root sandbox with `ensure()` only.
- `test_revision_routes_v3.py::TestRefParameterOnRoutes::test_ref_validation_rejects_invalid_ref` also used `sb.ensure()` only.

Neither leak reopened: the 404 comes before any git call. But with an empty fixture these tests no longer reached `_validate_ref`,
the gate both exist to guard. So each fixture now writes one payload file before the request: `notes.md` and `file.txt`, the
latter the idiom of its neighbours. Each edit carries an `ISS-1072:` comment. Assertions, ids and docstrings are unchanged. Proof
of direction (18):

- (b) With the pre-fix predicate patched back in, the edited files still pass (3 passed; 12 passed), so the edit changes nothing
  on the old code.
- (c) With the fix in and `_validate_ref` made a pass-through, both tests FAIL (404 File not found). So they still depend on the
  gate answering 400 and do not pass vacuously.

The empty-directory case itself is now pinned by the ISS-1072 test. ISS-671's original repro sandbox was itself an empty directory
(ISS-671 "Root cause"). That exact shape now answers 404 "Workspace expired" with no git call at all, stricter than the 400 it got.
