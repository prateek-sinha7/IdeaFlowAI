# ISS-1105

## Description

Sibling of [ISS-1104](20261008-0016-ISS-1104.md) (the same removed paste), found by grepping the suite for the string the removal deleted. Reproduced, so it is not a lead.

`backend/tests/unit/agents/test_agent_input_event.py::test_planning_context_injected_into_context_message` (`:127`) builds a `planning_context` dict, calls `ExecutionEngine._compose_context_message(spec, 0, agents, "test brief", planning_context, _ectx())` and asserts `"## Planning Context" in msg` (`:143`), then the intent, constraints, persona and NFR strings. It fails at `:143`. It contradicts `tests/agents/test_seam2_gate_v3.py:72`, which lists the same string among the markers that must NOT appear in a context message.

## Evidence (observed 2026-10-08, HEAD `5e22d3238`; this file alone)

- HEAD: 1 failed, 6 passed (`evidence/qa-kb-097/analysis-12-test_agent_input_event-at-HEAD.txt`).
- Bisect on `git archive` exports: `3e09aef2c^` (path then `tests/unit/test_agent_input_event.py`) 7 passed; `3e09aef2c` this test fails, the other six pass. Same commit as [ISS-1104](20261008-0016-ISS-1104.md).
- The neighbour `test_planning_context_not_injected_when_timed_out` (`:152`) asserts `"## Planning Context" not in msg` for a timed-out context; it has been vacuously green since the block was removed for every input, so it no longer detects what its docstring claims.

## Cause (CONFIRMED)

`3e09aef2c` removed the paste (`engine.py:16578-16582`, quoted in [ISS-1104](20261008-0016-ISS-1104.md)) and did not touch this test.

## Fix (test-only)

Replace the positive assertions by the contract that now holds: the composed message for agent index 0 carries the brief and none of the planning-context strings, i.e. `"## Planning Context" not in msg` and `"Build a login feature" not in msg` with `"test brief"` present. Then the timed-out neighbour can go (it adds nothing once the positive case asserts absence for a full context). Keep `test_seam2_gate_v3.py` as the pin; do not duplicate its marker list.

What a naive fix would break: re-adding the block to `_compose_context_message` (see [ISS-1104](20261008-0016-ISS-1104.md)).
