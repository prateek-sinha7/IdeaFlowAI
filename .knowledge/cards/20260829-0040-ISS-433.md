## What happened

Derived while analyzing [ISS-314](20260828-1946-ISS-314.md) (confirmed: `PreviewPanel.tsx`'s
PPT toolbar row pushes "Full Screen" completely outside a 375px viewport because its wrapper is
`flex-shrink-0` with no `flex-wrap`/`overflow-x` anywhere in the ancestor chain). The same
component family (`MOD-frontend-src-components-preview`, one of the typed first-party renderers
`PreviewPanel` dispatches to) has a second, independently-broken instance of the identical
anti-pattern in `PrototypePreview.tsx`'s "browser chrome" bar — the toolbar shown above every
`prototype`-type deliverable.

## Root cause (structural match to ISS-314, not yet measured)

`frontend/src/components/preview/PrototypePreview.tsx:502`:

```tsx
<div className="flex-shrink-0 bg-white border-b border-gray-200 px-3 py-2 flex items-center gap-2">
  <div className="flex items-center gap-1.5 flex-shrink-0">      {/* traffic-light dots, L503 */}
  <div className="flex items-center gap-2 ... min-w-0 flex-1 max-w-[200px]">  {/* URL pill, L508 */}
  <div className="flex items-center gap-1 ml-auto">               {/* right cluster, L513 */}
    {/* zoom out (L514), zoom reset (L518), zoom in (L522), divider (L527),
        Tweaks (L529-539), Source (L541-550), Open/"Full Screen"-equivalent (L552-556) */}
```

Like the confirmed `PPTTabActions` row, the outer bar (L502) sets no `flex-wrap` and no
`overflow-x`, and none of its ancestors up to `PrototypePreview`'s root (`h-full flex flex-col`,
L499) provide one either. The only shrink point is the URL pill (`min-w-0 flex-1 max-w-[200px]`,
L508) — everything else (the 3 dots, and the 7-element right cluster: 3 zoom buttons, a divider,
Tweaks, Source, Open) is fixed-width. **This right cluster has MORE elements than the
already-confirmed-broken PPTTabActions row** (which only holds Download + Full Screen), so it is
at least as likely, plausibly more likely, to overflow a 375px viewport once the URL pill has
shrunk to its own floor. A rough sum of the right cluster's rendered widths (three ~24-38px zoom
controls + a divider + three ~55-70px icon+label buttons + inter-item gaps) lands near ~320px
before the dots, padding and the URL pill's own non-text minimum are added — comfortably in the
same range as ISS-314's measured ~493px total against a 375px viewport.

## Why ISS-314's root cause implies this

ISS-314's root cause is not "PPTTabActions is broken" — it is "a toolbar row of fixed-width
buttons, wrapped only in `flex-shrink-0`/`flex-none` divs, has no responsive behavior (no wrap,
no shrink-to-fit, no overflow-x) anywhere in this module." That same construction — verified by
reading the source, not inferred from a symptom — is repeated verbatim in `PrototypePreview.tsx`,
a sibling first-party renderer in the same module, for the same category of user (anyone opening
a `prototype`-type run's Preview tab on a narrow viewport).

## Expected vs actual

- **Expected:** at narrow/mobile viewport widths, the chrome bar's trailing controls (Tweaks,
  Source, and especially "Open" — this component's "Full Screen" equivalent, `title="Open in new
  tab"`) wrap, shrink, or sit behind a horizontally scrollable container, same as the fix ISS-314
  needs.
- **Actual (unverified):** structurally identical to ISS-314's confirmed defect. Not yet measured
  with `getBoundingClientRect()`/`window.innerWidth` the way ISS-314 was.

## Disposition

**INFERRED, not reproduced.** What would confirm it: open a completed `prototype`-type run's
Preview tab, set the viewport to 375×700 (`window.innerWidth === 375`, per the
`viewportUnreliable` quirk in `bug-hunter/velocity.json` — do not trust screenshot pixels), and
read `getBoundingClientRect()` on the "Open" (and "Source"/"Tweaks") buttons the same way ISS-314
did on "Full Screen". If the same class of fix lands on `PreviewPanel.tsx`'s tab-bar row for
ISS-314, it will NOT touch this file — `PrototypePreview.tsx` is a separate component with its
own independent chrome bar, so this needs its own fix applied at `PrototypePreview.tsx:502` (or
its `ml-auto` right-cluster wrapper at L513) if reproduced.
