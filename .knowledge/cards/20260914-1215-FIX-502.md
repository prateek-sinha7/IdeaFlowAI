## What changed

Three files, all additive — no migration, no golden regeneration, no new
endpoints.

### `backend/app/api/analytics.py`

1. **`AgentRollup` model** — new field:
   ```python
   pipeline_types: list[str] = Field(default_factory=list)
   ```
   Carries the sorted list of distinct `WorkflowRun.type` values this agent
   was invoked from within the query window.

2. **`agents_acc` accumulator** — `pipeline_types` set added to the lambda:
   ```python
   defaultdict(lambda: {..., "pipeline_types": set()})
   ```

3. **Per-agent loop** — one new line after `av["cost"] += a_cost`:
   ```python
   av["pipeline_types"].add(r.type)
   ```
   `r` is the outer `WorkflowRun` row already in scope; `r.type` is the
   stored pipeline type string (generic, SC-001 — no workflow-name branch).

4. **`AgentRollup` construction** — `pipeline_types=sorted(v["pipeline_types"])`
   added to the list comprehension. Sorted for deterministic wire ordering.

### `frontend/src/lib/api.ts`

`AnalyticsAgentRollup` gained:
```typescript
pipeline_types: string[];
```
with an ISS-643/ADR-0023 JSDoc note explaining multi-pipeline agents.

### `frontend/src/components/analytics/AnalyticsPage.tsx`

1. **`agentRows`** — `pipelineTypes: a.pipeline_types ?? []` added to the
   mapped shape (the `?? []` guard handles legacy payload shapes gracefully).

2. **By Agent JSX** — the bare `<span>` name chip replaced with a flex
   wrapper:
   ```tsx
   <div className="flex items-center gap-1.5 flex-wrap">
     <span ...>{a.name}</span>
     {a.pipelineTypes.map((pt) => (
       <span key={pt} className="text-[8px] font-semibold px-1.5 py-0.5
         rounded bg-brand/10 text-brand border border-brand/20
         uppercase tracking-wide">
         {PIPELINE_LABELS[normalizeType(pt)] ?? pt}
       </span>
     ))}
   </div>
   ```
   Uses the existing `PIPELINE_LABELS` map and `normalizeType()` helper
   (already present for the By Pipeline Type section) so revision-variant
   types (`ppt_revision`) display as their base label ("Presentation").

## Why this is safe

- `AgentRollup.pipeline_types` defaults to `[]` — old callers that don't
  read it are unaffected.
- `r.type` is already on the `WorkflowRun` row read in `_aggregate`; no new
  DB query or column needed.
- No characterization golden touches `AgentRollup` — INV-3 is not at risk.
- SC-001 / INV-1 hold: the accumulation keys on `r.type` generically.
