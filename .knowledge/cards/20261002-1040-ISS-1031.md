# ISS-1031

**INFERRED in the browser. Reproduced offline in jsdom only**: a scratch probe of the real `PreviewPanel`, rows G1, G2, G7 and G9 of
`evidence/qa-kb-091/04-analyze-probes-real-tree-and-fix-variants.txt`. Derived by the analyzer while analysing QA-KB-091 ([ISS-952](20261002-0147-ISS-952.md)); nobody
reported it. An unreproduced sibling is a lead, not a defect: nothing here was driven in a browser.

Line numbers are the working tree on 2026-10-02 (HEAD `024c03ef8` plus uncommitted edits; `PreviewPanel.tsx` md5 `475f5d437872d0c205a11db8f71afa5b`), so HEAD numbers can sit
a few lines off.

## Condition

The SHELL run (the run the URL names) ended `failed` or `degraded`, and a DIFFERENT family member is pinned. The pin can be empty or carry a deliverable.
The shell status is `reopenedRunStatus` (set from `fullRun.status`, `app/[...view]/page.tsx:3311-3318`) or, on the live path, `pipelineState.failed`/`.degraded`.

Two routes put a different member under a failed shell:

1. **The ordinary one.** The newest revision failed; the user opens it, then picks an older good tagged version from the RunHeader Version menu
   (`handleVersionMenuSelect` `PreviewPanel.tsx:941-962` -> `handleSelectVersion` `:892`). The pin is written into the URL (`:915`); the shell stays the failed run.
2. A `/runs/{failedMember}/versions/{n}` URL, typed, shared or bookmarked.

## Expected vs actual

- **Expected:** a pinned version's header describes that version. A completed one gets the settled header: no failed badge, Share and Download as for any settled
  version. This is the contract [ISS-933](20261001-2231-ISS-933.md) states for the empty-pin case: "the treatment the same run gets when opened directly".
- **Actual** (probe on the real tree; distinct shell `r1` reopened `failed`, pin `root` completed):
  - **G2, pin WITH a deliverable:** header `Run failed` plus the `· partial` chip suffix, `share=0`, `download=0`. The Preview tab is in the strip, the landed tab is
    Audit, and clicking Preview shows the pin's content.
  - **G1, empty pin:** the same header (and the missing Preview tab, which is ISS-952 itself).
  - **G9, the Version-menu flow** (tagged family, shell `r1` reopened `failed`, pick `v1`, completed, with content): before the pick the header is failed with
    `share=0 download=0`; **after the pick it is still failed with `share=0 download=0`**. Control, same flow under a healthy shell: `share=1 download=1` before and after.
  - Cancelled and diverted shells do not leak: `headerFailed` excludes cancelled and diverted is not in `terminalFailure`.

## Mechanism (CONFIRMED, read)

- `PreviewPanel.tsx:1215` `const headerFailed = terminalFailure && !isCancelledTerminal;` has no `hasContent` term and no pin term. Unlike `showFailureAffordance`
  (`:1142`, `!hasContent && isTerminal && terminalFailure`) it is reachable for a pin that HAS content.
- `:1216-1222` `headerRunState` is `headerFailed ? "terminal" : hasContent ? "complete" : "idle"`: one derivation that takes `terminal` from the shell and
  `complete`/`idle` from the pin.
- `:1680` `failed={headerFailed}` reaches `RunHeader.tsx:293` `const isFailed = failed || runState === "terminal";`, which drives
  `:333` the `" · partial"` chip suffix, `:437` the failed `StatusBadge`, `:452` `{!isFailed && (` (Share) and `:528` `{isSettled && (` (Download).
  The badge reason (`PreviewPanel.tsx:1329-1331`) is the first of `failedAgentNames`, which is the SHELL's (`pipelineState?.failedAgents || ... || reopenedFailedAgents`, `:1191-1195`).
- The same header carries the PIN's version label (`activeRunId = viewingVersion?.id ?? unpinnedRunId` `:855`, then `headerVersionLabel` `:1311-1314`), so "v1" sits next to the shell's failure.
- Download is gated a second way: `:1395` `if (!activeRunId || (headerRunState !== "complete" && !sandboxSelectedRef)) return;`.
- Landing tab: with a pin that has content, `headerRunState` is "terminal", not "complete", so the default-tab effect (`:1288-1295`) never targets Preview. The pre-pin render
  already latched Audit (`autoTabbedForState`), so the user lands on Audit.
- `FilesTab`: `:1922` `runStatus={terminalFailure && !isCancelledTerminal ? "failed" : undefined}` prints the "Build incomplete" banner (`FilesTab.tsx:1082-1090`) when the pin
  has no files. **Low reach:** the Files tab is hidden from the strip (`TAB_CONFIG`, `:533-540`) and opens only through the `/runs/{id}/files` deep link.

## Why the root cause (ISS-952) implies it

ISS-952's root is shell-keyed terminal signals applied to pin-keyed content. `showFailureAffordance` is one consumer of `terminalFailure`; `headerFailed` is the other,
and it is not gated on `!hasContent`, so it is reachable for every pin. The triage sketch for QA-KB-091 (`!overrideActive` on `showFailureAffordance` and
`showDivertedAffordance` only) leaves it: variant A in the probe changes nothing on G2 or G9.

## Reverse direction (found, NOT fixed by the same change)

G7: a pin that ended `failed` or `degraded` WITH content, under a healthy shell, renders a settled header (`share=1 download=1`), while an unpinned failed run with content shows
`Run failed`, `share=0`, `download=0`. The pin's own `viewingVersion.status` is read only at `:1835-1849` (the empty-body branch) and `:911`; nothing in the header reads it.
A pin-aware badge would also want the pin's failed agents, and `VersionView` (`:573-603`) carries no `error`. Rare in practice: a failed run usually stores no output, a degraded one may.
This is a design call (should a pinned version's header say "Run failed"?), so it is recorded here rather than folded into the gate below.

## Fix (proposed, not applied)

- Direction one is fixed by the ISS-952 gate, with no extra change here: gate the four shell signals (`liveFailureSignal` `:1132`, `reopenFailureSignal` `:1137-1140`,
  `isCancelledTerminal` `:1147`, `isDivertedTerminal` `:1153`) on `shellOnScreen = viewingVersion == null || viewingVersion.id === unpinnedRunId`. Probe variants B2/C/D: G2 and G9 give
  header ok, `share=1 download=1`, landed Preview (G2). Gating only the two affordance predicates does not (variant A).
- Do NOT feed the pin's status into `terminalFailure` or `reopenedRunStatus` (locked constraint of [FIX-709](20261002-0147-FIX-709.md) and [ISS-933](20261001-2231-ISS-933.md): it drops the Preview tab and forces Audit for the whole panel).
- Direction two, if wanted: a header-only `pinFailed` from `viewingVersion.status`, with the badge reason absent or from a new `VersionView.error`.

  `Viewing v1 (read-only)` (`ReadOnlyVersionBanner.tsx`), not on `Viewing v1 · read-only`, which is `RefVersionPreview`'s and is not on screen while Audit is the landed tab.
- Control: an unpinned failed shell WITH content keeps `Run failed` and no Share/Download.
