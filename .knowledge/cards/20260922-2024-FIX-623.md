# FIX-623

## What was wrong

Bug `QA-SG-014` (`BUGS.md#qa-sg-014`): a custom workflow "always produces .md
files" whatever output format the user picks. Three cards, one missing
mechanism and one missing control:

* [ISS-770](20260922-1305-ISS-770.md) (root, live-reproduced) — the composer's
  "Output format" `<select>` travels correctly to the engine as
  `selections.__deliverable__` and `_apply_selections` patches the compiled
  `DeliverableSpec` (`engine.py:12920-12946`), but that is a **rename-only**
  lever. `StreamedTextResolver.resolve` returned the last agent's raw text
  verbatim, so run `e49b91e6-f2fe-479c-a941-75da2b53c05d` completed with
  `deliverable_filename: "output.html"` and `deliverable_mimetype:
  "text/markdown"` over 416 B of `## Task 1: …` markdown.
* [ISS-776](20260922-1557-ISS-776.md) (sibling) — the same screen's
  `single_file` + `.html` pick is worse: its case-3 fallback
  (`single_file.py:164-169`) returns the same raw text while
  `default_mimetype` infers `text/html` from the `.html` name
  (`_mimetype.py:38-46`) — an active mislabel.
* [ISS-777](20260922-1558-ISS-777.md) (sibling) — the dashboard launch screen
  (`IdeaInputPage.tsx`, mounted at `DashboardLayout.tsx:3062`) had **no**
  output-format control at all, and `resolveDispatchType`'s fallback
  (`IdeaInputPage.tsx:465`) forced `{strategy: "streamed_text", name:
  "output.md"}` for every agent combination outside its three hardcoded
  `AGENT_DELIVERABLE_MAP` groups.

## Root cause

No capability in the `("deliverable", strategy)` layer ever converted content
to match the declared extension — the format promise was made in the UI and
kept nowhere. Both text-backed resolvers ended in a raw-text return:

* `backend/agents/capabilities/deliverables/streamed_text.py:53` —
  `return strip_pre_document_prose(unwrap_artifact(last_streamed))`
* `backend/agents/capabilities/deliverables/single_file.py:169` —
  `return strip_pre_document_prose(last_streamed)`

and `frontend/src/components/workflow/IdeaInputPage.tsx:465` —
`return { type: "custom", deliverableOverride: { strategy: "streamed_text", name: "output.md", mimetype: "text/markdown" } };`

## What changed, and why there

1. **`backend/agents/capabilities/deliverables/_format.py` (new, stdlib only)** —
   `coerce_to_declared_format(text, name)`: when the DECLARED name ends in
   `.html`/`.htm` and the text is not already a document, render it as one
   (headings, fences, lists, rules, paragraphs, inline spans; everything
   HTML-escaped first). A no-op for every other name, for empty text, and for
   text that already opens `<!doctype`/`<html>` — so every prototype, revision
   and `.md` deliverable keeps its exact bytes. Same shape as the package's
   other shared helpers (`_artifact.py`, `_placeholder.py`): no `app.*`, no
   kernel import, keyed on the declared name and never on a pipeline name.
2. **`streamed_text.py` + `single_file.py`** — both raw-text returns route
   through it. One helper at the two points where every caller of either
   resolver converges, rather than a guard per launch surface.
3. **`_mimetype.py`** — `default_mimetype("streamed_text", name)` now answers
   `text/html` for an `.html`/`.htm` name, because the resolver really does
   produce a document for it. Still a pure function of the DECLARED
   strategy/name; the REJECTED content-sniff hack the module's docstring names
   is still rejected.
4. **`IdeaInputPage.tsx`** — `resolveDispatchType` returns no override for an
   unrecognized agent combination, and the screen renders an
   `aria-label="Output format"` picker (`.md` default, so an untouched launch
   is byte-identical) whose value becomes the `__deliverable__` when the map is
   silent. The picker is hidden for the three mapped groups, whose shape is not
   the user's to change there. `ComposerPage.tsx` needed no edit: its
   `runConfig?.deliverable ?? deliverableOverride` already tolerates an absent
   override, and its own CanvasView control is the source of truth.

## Interaction with FIX-612 (checked, not assumed)

The HTML wrapper is prepended to the agent's own text, and FIX-612's
completion gate measures the FINAL bytes against
`_placeholder._MAX_NARRATION_CHARS` (2000). The `<style>` block is therefore
deliberately tiny — 389 chars of total overhead, verified: a 55-char narration
wrapped to 444 chars is still flagged by `placeholder_narration_reason`.

## Deliberately NOT changed

`_check_artifact_fallback` (`engine.py:8404`) still writes the agent's raw
mid-run text to the sandbox under the deliverable filename, so
`.chain/<run_id>/output.html` (a `shutil.copy2` of that sandbox file,
`engine.py:1090-1091`) keeps the unconverted bytes. The run record — what the
Files tab and Preview render, via `deliverable_mimetype` +
`final_output`/`genericDeliverableExtension` (`FilesTab.tsx:125-136`) — is
converted. That writer belongs to [ISS-721](20260922-1242-ISS-721.md) /
[FIX-612](20260922-1838-FIX-612.md); recorded as
[ISS-838](20260922-2024-ISS-838.md) rather than fixed here.
