# ISS-1068

## Description

Found while baselining [FIX-746](20261007-2034-FIX-746.md) (QA-KB-090). Each red below is
identical, same test and same failure line, on HEAD `cec17f2f7`'s `engine.py` (run in a scratch copy
of `backend/`) and on the working tree with FIX-746, so none comes from that fix. Earlier FIX cards'
coverage blocks list them as "pre-existing, unrelated", but no open card owns them, so every fixer
in this area re-baselines them. Disposition: **open, unowned, outside QA-KB-090.** Observed runs are in
`evidence/qa-kb-090/fix-08-regression-runs.txt` and `fix-09-static-checks.txt`.

## The reds

1. **Resume offset fakes reject `compiled=`** (3 tests). `resume_run` calls
   `_compute_resume_offset(..., compiled=resumed_compiled)` (`engine.py:15733-15740`); the fakes
   have no such parameter.
   - `tests/agents/test_resume_context_v3.py`, both tests:
     `TypeError: _fake_offset() got an unexpected keyword argument 'compiled'`
   - `tests/integration/agents/test_specs_from_plan_db.py::test_resume_run_builds_display_names_for_a_real_composed_workflow`:
     `TypeError: ..._spy_offset() got an unexpected keyword argument 'compiled'`
   - Test-side fix, from the ISS-950 analysis: `async def _fake_offset(*a, **k)`.
2. **The kernel imports `app.api`** (1 test plus 1 lint-imports contract).
   `tests/integration/agents/test_resume_ws_bridge_db.py::test_engine_module_does_not_import_app_api`
   lists function-local `from app.api.runs import RevisionRootResolved, resolve_revision_root` and
   `from app.api.launch_context import ...` lines in `engine.py`. lint-imports reports
   `kernel imports only capability ports (scaffold) BROKEN`.
3. **A capability imports `app`** (1 test plus 1 lint-imports contract).
   `tests/unit/agents/test_banned_patterns.py::test_capabilities_do_not_import_kernel_or_web_layer`:
   `agents/capabilities/prototype_ui_extract.py:333: from app.agents.tools.html_extract import materialise_html`.
   lint-imports reports `agents.capabilities must not import the execution kernel or the web layer BROKEN`.
4. **A cancelled resumed drive persists no terminal event** (1 test).
   `tests/integration/agents/test_cancel_stops_resumed_run_db.py::test_cancel_stops_a_resumed_drive_and_writes_the_terminal_row`
   fails at `:236` with `assert 'pipeline_cancelled' in ['workflow_validated']`. The cause was not
   investigated. A lead only, unchecked: the same run logs
   `finalize_terminal_run: create_run_ref FAILED run=iss084-… (run_id must be a UUID ...)`, and the
   test mints non-UUID run ids (`iss084-<hex8>`).

lint-imports totals 3 kept / 2 broken; the two broken contracts are items 2 and 3. Items 2 and 3
are boundary violations in application code, so moving those imports behind a port is a design
change for whoever takes them, not a test edit.

## Update 2026-10-08 (QA-KB-097 5-fixer): item 4 is green

[ISS-1102](20261008-0016-ISS-1102.md) found the cause of item 4. It was not the non-UUID run id lead.
Instance A's scripted crash leaves the process-global `StateMachine` at terminal `failed`, so the resumed
drive's `transition(.., "generating")` is refused before it can read the cancel event. The fix is
test-only ([FIX-762](20261008-0039-FIX-762.md)): `_ResumeHarness.make_engine` resets the machine. The file
is now 5 passed (`evidence/qa-kb-097/fix-09-after-cancel-stops-resumed.txt`). Items 1-3 are unchanged.
`test_resume_ws_bridge_db.py` is still 1 failed / 3 passed and lint-imports is still 3 kept / 2 broken
(`evidence/qa-kb-097/fix-13-after-harness-importers.txt`, `fix-15c-lint-imports-compare.txt`). This card
stays open for items 1-3.
