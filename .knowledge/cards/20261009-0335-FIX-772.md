# FIX-772

**Register source:** `QA-KB-107` (`LEDGER.md`), 5-fixer, 2026-10-09. Resolves [ISS-1133](20261009-0200-ISS-1133.md) (root) and its
siblings [ISS-1134](20261009-0258-ISS-1134.md), [ISS-1135](20261009-0258-ISS-1135.md) and [ISS-1136](20261009-0258-ISS-1136.md). All four
share `backend/app/agents/model_factory.py`, so one fixer applied them together.

Line numbers are HEAD `8fb136808` plus this change. No other session had a backend change in the tree, so the whole change is
`evidence/qa-kb-107/fix-05-change.patch` (5 files; `git apply --check -R` is clean against the working tree).

## What was wrong

The root causes are on the cards and are not re-derived here.

- [ISS-1133](20261009-0200-ISS-1133.md): `preflight_check_provider` was a partial hand-copy of `build_model`'s provider chain. It mirrored only
  the `ANTHROPIC_API_KEY` rung, so an expired `AWS_BEARER_TOKEN_BEDROCK` made the launch answer 503 `model_provider_unavailable` (via
  `run_commands.py:2962`) for a run that `build_model` would have sent to Ollama.
- [ISS-1135](20261009-0258-ISS-1135.md): the same copy lacked the Mistral-fallback rung (Bedrock unconfigured and `MISTRAL_API_KEY` set).
- [ISS-1134](20261009-0258-ISS-1134.md): `SmartPlanner._build_llm` was a third copy of the chain with no override rung. Under the override, the
  planner still planned on Bedrock. With an expired token it degraded to the canned `CLARIFY_REQUIRED` default.
- [ISS-1136](20261009-0258-ISS-1136.md): `build_model` reads the flag from `backend/.env` on every call and no fixture pinned it. A checkout
  with the override on failed 31 offline unit tests. Fixing ISS-1133 would have flipped three more.

## What changed, and why there

1. **One reading of the flag**, `_local_ollama_env()` (`model_factory.py:88-107`). It returns the merged `.env` + process env when
   `USE_LOCAL_OLLAMA` is truthy, else `None`. The body is `build_model`'s old block, moved unchanged: the same merge (real env wins), the same
   truthy set, and `ENV_FILE` still imported at call time. `build_model` calls it (`:360`), keeps using the returned dict for
   `OLLAMA_MODEL` / `OLLAMA_BASE_URL` / `OLLAMA_NUM_CTX` / `OLLAMA_NUM_PREDICT`, and loses the `os` / `dotenv_values` / `ENV_FILE` imports
   that only the block used. The Bedrock bridge keeps its own `import os` (`:462`).
2. **One Bedrock predicate**, `_bedrock_configured()` (`:110-116`). This is `build_model`'s old local `bedrock_configured`, with its comment,
   now called at `:475`.
3. **The preflight mirrors the two missing rungs** (`:145-152`). It returns `(True, None)` when the override is on or `ANTHROPIC_API_KEY`
   is set (`:149`), and when `MISTRAL_API_KEY` is set and Bedrock is unconfigured (`:151`). The `not token` check stays first, so a launch
   with no token reads no file. Every caller of the preflight (`launch_run`, and `run_trigger_workflow` through `_launch_run_core`) now
   routes through the fixed function. No caller changed.
4. **The planner asks the same helper** (`smart_planner.py:348-354`). When the override is on, `_build_llm` returns
   `build_model(self.model_id, max_tokens=2048)`, as ISS-1134 proposed. Otherwise it falls through to its unchanged Anthropic and Bedrock
   exits (INV-3: the planner's `temperature=0` and its botocore config are not routed through `build_model`). The import is lazy, beside the
   `_build_bedrock_bearer_session` import it already had.
5. **Tests.**
   - ISS-1136 pin: an autouse `_local_ollama_override_off` in `backend/tests/unit/conftest.py:79-88` that sets `USE_LOCAL_OLLAMA=0`.
   - One explicit pin in `test_expired_bedrock_token_rejected_pre_mint` (`test_rest_run_launch_api.py:298`). ISS-1136 names that test: it
     asserts a Bedrock refusal, so it has to say its provider is Bedrock.
   - The card tests in `backend/tests/unit/app/test_preflight_ollama_override.py`. The test-writer's test is unchanged. I added the tests the
     cards' "Test notes" specify:
     - ISS-1133's file-only test B (`:41`), "the real assertion": the flag only in the file, as on the reporting machine.
     - ISS-1135 (`:60`).
     - ISS-1134 (`:79`) and its flag-off control (`:104`).

     I observed each one red against HEAD source before the fix.

### Where this differs from the cards, and why

- **ISS-1136 offered the root `backend/tests/conftest.py` first.** I used the unit-tier conftest instead. The live Ollama variant in
  `tests/integration/test_git_versioning_e2e.py:637-647` needs `USE_LOCAL_OLLAMA=1` from the real environment during the test. A root pin
  would send it to Bedrock, where the ISS-102 guard stops it. `RUN_LIVE_BEDROCK` e2e runs would also lose a developer's own flag. Unit tests
  can never reach a live model (the I/O guard), so a pin there is free. The one integration test that needs it got its own pin. I ran
  ISS-1136's two unrun "leads" as-is and pinned: `test_revision_analyzer_integration.py` 20 passed both ways,
  `test_chat_messages_endpoint_api.py` 31 passed both ways. Neither depends on the flag.
- **The test-writer wrote only ISS-1133's env-var test** (test A). Test A alone passes an `os.getenv`-only fix, which the ISS-1133 card calls
  the trap. Test B catches that trap, and the mutation check below proves it.

## Behaviour changes a caller can see

- `POST /api/runs`, and a conditional gate's `trigger: workflow` launch through `_launch_run_core`, no longer answer 503
  `model_provider_unavailable` over an expired bearer token in two cases: when `USE_LOCAL_OLLAMA` is on, and when Bedrock is unconfigured
  and `MISTRAL_API_KEY` is set. On this machine every launch was refused before. It now goes through.
- With the override on, the planner of the 14 `planner: run` built-ins plans on the local model. Before, it called Bedrock, or fell back to
  the canned clarify gate when the token was dead. With the override off, nothing changes.
- A unit test can no longer see the developer's `USE_LOCAL_OLLAMA`. Set it in the test.
