## What was wrong

Four parametrized rows, red since `bc0a0366e` (spec 018):

```
test_manifest_parity::test_planner_run_everywhere[playwright_smoke_test]
test_manifest_parity::test_clarify_defaults_match_engine[playwright_smoke_test]
test_id_alias_resolver::test_compiled_planner_is_run_everywhere[playwright_smoke_test]   assert 'skip' == 'run'
test_id_alias_resolver::test_compiled_clarify_defaults_match_engine_dict[…]              assert [] == [… 'priority']
```

## Root cause

`backend/agents/workflows/playwright_smoke_test/workflow.yaml:21` declares
`planner: skip` and `:24` declares `clarify.defaults: []`. Both parity traps
compute their expectation from a hand-maintained allow-list, and the manifest
was added to neither pair:

* `test_manifest_parity.py:119` `_PLANNER_SKIP_IDS` / `test_id_alias_resolver.py:270`
  `_PLANNER_SKIP_IDS` — an id absent from these is asserted to be `planner: run`.
* `test_manifest_parity.py:162` `_ENGINE_PIPELINE_DEFAULTS` / `test_id_alias_resolver.py:52`
  `_EXPECTED_CLARIFY_DEFAULTS` — an id absent from these falls to the 4-item
  `_CUSTOM_DEFAULTS` (`target_audience, key_objectives, scope, priority`).

The lists are the AUTHORED record of which manifests legitimately skip the
planner; both files say so in their own comments (*"Kept in lockstep with the
manifests — update this copy when a manifest's defaults deliberately change"*,
*"Sibling trap: keep in lockstep with …"*). Two prior additions landed the same
way and were repaired the same way: `custom_revision` (*"declares planner: skip
like its siblings but was never added here"*) and the whole `ex_A*` family
([ISS-174](20260825-0956-ISS-174.md), option 1).

## The decision the card left open

[ISS-635](20260831-0115-ISS-635.md) asks whether a smoke-test fixture is
genuinely exempt. It is, and by PROPERTY, not by name:

* Its manifest's own header says it exists *"so QA can exercise tools:[playwright]
  in under a minute instead of waiting on a multi-step pipeline"*. A deep-planner
  round-trip in front of a one-step fixture costs more than the fixture — the
  verbatim rationale already recorded for `sample_subagents_parallel` and the
  seven `ex_A*` fixtures.
* It is in the same class as those exemptions on every axis that matters:
  `user_launchable: true`, not `run_revision`-dispatched, `clarify.mode: skip`,
  one step. Nothing distinguishes it from `ex_A1_loop`.

The alternative — flipping the manifest to `planner: run` + four clarify
defaults — would have satisfied both tests while destroying the only property
the fixture exists to have. That is bending production to a stale pin, so the
exemption went where the tests already keep every other one.
