## What is suspected

INFERRED sibling of [ISS-800](20260922-1633-ISS-800.md) (QA-PS-048's root
cause), derived from reading — not yet browser-reproduced independently.

`frontend/src/components/results/AgentThinkingTab.tsx:167-180`:

```tsx
const runId = pipelineState?.pipelineRunId;
const [gateEvents, setGateEvents] = useState<GateEventRow[]>([]);
useEffect(() => {
  if (!runId) { setGateEvents([]); return; }
  let cancelled = false;
  (async () => {
    try {
      const { getRunGateEvents, getToken } = await import("@/lib/api");
      const res = await getRunGateEvents(getToken() || "", runId);
      if (!cancelled) setGateEvents(res.gate_events ?? []);
    } catch {
      if (!cancelled) setGateEvents([]);
    }
  })();
  return () => { cancelled = true; };
}, [runId]);
```

The comment above this effect (`RUNUI-06`) states it deliberately "REUSES
the existing `getRunGateEvents` endpoint (the Audit tab's source)" to drive
a "Review gate — approved" strip in the Steps tab's overview spine — a
second, independent consumer of the exact same audit projection
[ISS-800](20260922-1633-ISS-800.md) already root-caused for the Audit tab.
Identical shape: one `useEffect` keyed on a single id, `cancelled` blocking
only the post-resolution `setState`, no in-flight/StrictMode guard, and
`getRunGateEvents` itself has no dedupe (confirmed in ISS-800: it calls
`request()` directly, not the `cachedGet()` TTL cache at `api.ts:386-426`).

## Condition

Opening the Steps tab on any run whose `pipelineState?.pipelineRunId` is
set (i.e. any run with pipeline state populated — live or reopened) under
`next dev`'s default React Strict Mode.

## Expected vs actual

**Expected:** `GET /api/runs/{id}/gate-events` fires once when the Steps tab
opens.

**Actual (predicted):** it fires twice, doubled by the same
mount→cleanup→mount Strict Mode re-invoke ISS-800 confirmed 3/3 for the
Audit tab's own copy of this same effect shape — and, across a full
Preview→Steps→Files→Workspace→Audit click-through (this bug's own repro
sequence), the endpoint is hit by TWO independent components
(`AgentThinkingTab` on Steps, `AuditTab` on Audit), not one, compounding the
total gate-events call count an end-to-end network capture would show.

## Why the root cause implies this

[ISS-800](20260922-1633-ISS-800.md) root-caused the Audit tab's duplication
to "unguarded mount effect + Strict Mode double-invoke + no `cachedGet()`
routing." `AgentThinkingTab.tsx:167-180` is byte-for-byte the same shape
against the same endpoint, confirmed by direct reading — the only thing
unverified is a live network trace confirming the exact 2x count in the
browser, which is why this stays INFERRED rather than CONFIRMED.

## What would settle it

Cold-navigate to `/runs/{id}` for a run with `pipelineState` populated,
open DevTools Network filtered to `gate-events`, click the Steps tab, and
count requests — repeat 3x per this line's own validation convention.
