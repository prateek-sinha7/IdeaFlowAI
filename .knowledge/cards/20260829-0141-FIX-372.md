## What was wrong

On `/workflows`, "Workflow actions" -> "Delete" on any saved-workflow card opened a
confirmation dialog whose entire text was generic and identical for every card —
heading "Delete workflow", subtext "This cannot be undone", body "The saved workflow
will be permanently removed from your saved workflows." — with no workflow title, id or
any other identifying detail. [ISS-302](20260828-1734-ISS-302.md) recorded three
cold-start cycles on three differently-named cards producing byte-identical dialog text
in the full accessibility tree. The list routinely holds near-duplicate titles (four
"Signoff Stop-Resume Test…" cards, four "Signoff Composer Test (API)…" cards), so a
user who opened the menu on the wrong lookalike had nothing to catch the mistake with
before an irreversible delete.

## Root cause

`frontend/src/components/savedworkflows/SavedWorkflowsPage.tsx:166` —
`const [deleteConfirmId, setDeleteConfirmId] = useState<string | null>(null)`. The
identifying data was dropped at the point of capture, not lost later: the menu handler
(line 348) had the whole `row` in scope and stored only `row.id`. With nothing but an id
in state, the dialog (lines 408-444) had nothing to render, so its heading (425),
subtext (426) and body (429-431) were fully static JSX with no lookup back into
`userWorkflows`.

The correct shape already existed one function away in the same file: `onRename`
(line 346) stores the whole row (`setRenameRow(row)`) and `NameWorkflowModal` (line 402)
is handed `initialName={renameRow.name}`.

Blast radius re-checked before editing and it still holds: `grep -rn "deleteUserWorkflow"
frontend/src` returns one definition (`frontend/src/lib/api.ts:1911`), one production
call site (`SavedWorkflowsPage.tsx:221`) and three test-file mocks
(`SavedWorkflowsPage.test.tsx:33`, `HomeLaunchGrid.test.tsx:49`,
`HomeLaunchGrid.crossAccountLeak.test.tsx:30`) that never reach it —
`HomeLaunchGrid.tsx` has no delete affordance. One component, no shared function to
patch further up.

## What changed and why there

One file, 8 lines, all in `SavedWorkflowsPage.tsx` — the fix ISS-302 scoped, applied at
the point of capture rather than at the point of display:

- **line 166** — the state now holds the row:
  `const [deleteRow, setDeleteRow] = useState<UserWorkflowSummary | null>(null)`,
  mirroring `renameRow` on the next line rather than inventing a second pattern.
- **line 348** — `onDelete={() => { setOpenMenuId(null); setDeleteRow(row); }}`; the row
  was already in scope, it was simply being discarded.
- **line 218** — `handleDeleteConfirm` reads `deleteRow?.id`; the delete call itself
  (line 221) and the optimistic list filter are unchanged, so the request is identical.
- **line 430** — the body interpolates the name:
  `&quot;{deleteRow.name}&quot; will be permanently removed from your saved workflows.`
  `&quot;` and not a raw quote to match this same file's existing JSX text (lines 308,
  318).
- lines 410/413/414/433 — the four remaining `deleteConfirmId` / `setDeleteConfirmId(null)`
  references renamed. Mechanical.

Stored the row rather than deriving the name from a `userWorkflows.find(...)` lookup at
render: the lookup can miss (an id with no row renders empty quotes), and the row is
already in hand at the click. Same reason the sibling rename does it.

The **heading** was deliberately left as "Delete workflow". ISS-302's expected-behaviour
section accepts either the heading or the body carrying the title, and
`SavedWorkflowsPage.test.tsx:262` asserts `getByText("Delete workflow")` exactly — an
existing green assertion about the dialog's role, not a stale one, so there was no reason
to break it. The name goes in the body, which is unconstrained and wraps.

No shared confirmation-dialog component was extracted. ISS-302 flags the same defect
*shape* in two unrelated components ([ISS-414](20260828-2202-ISS-414.md),
[ISS-415](20260828-2202-ISS-415.md)) but explicitly records that no function all three
route through exists today; building one is a design decision, not this fix, and both
siblings are INFERRED/unreproduced with cards of their own.
