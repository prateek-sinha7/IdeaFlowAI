# ISS-129

## Title

**`run_fanout` swallows EVERY worker event, including terminal ones.** `fanout.py:414-429` iterates `runner.run_worker(...)` and forwards nothing; the loop body reads only `agent_complete` to accumulate `worker_tokens`. The in-file comment justifies this for CHUNK events (D-03, lifecycle-only), but the loop also discards `agent_error`, `pipeline_cancelled` and `review_gate_ready`. Because the durable `_RunEventSink` wraps `execute()`, an event that never leaves `_run_one` is never streamed AND never persisted — so a fan-out worker can fail, be cancelled, or open a HITL gate with no trace anywhere the user or the resume classifier can read. **This is the amplifier that turned ISS-097 from an annoyance into a silent hang**, and it is the same structural gap family as ISS-091. FIX-242 stops the gate instance (workers no longer arm one) but does NOT change what the loop forwards, so the `agent_error` / `pipeline_cancelled` half is untouched and live.

## Source / Evidence

Found 2026-08-12 by the ISS-097 investigation and confirmed at `eb12bc7e` by direct measurement (4 `_run_review_gate` entries, 0 frames on the wire). Filed rather than folded because deciding WHICH worker events must be forwarded or at least recorded is a product/vocabulary decision with real blast radius on the FE event contract and on the 5 characterization goldens — not something to settle inside a gating fix. Fix shape: decide the forwarded set (terminal + error at minimum), or record-without-forwarding into `run_events` so the durable log is complete even when the stream stays lifecycle-only.

## Resolution

Verified fixed in the current code on 2026-10-01 (feat/user-stories-v2 @ 3b08b2ba8) by static review: a first-pass check and an independent adversarial re-check both found every claim of this card fixed. No tests were run for this closure.

**Fixed by:** 5af898322 (fail-closed fan-out, agent_error/FanoutWorkerFailed) plus [FIX-242](20260812-2116-FIX-242.md) (workers arm no gates)

**Evidence:** Card claims: worker loop drops agent_error, pipeline_cancelled, review_gate_ready. Checked backend/agents/execution_engine/fanout.py. agent_error (562-566) is captured, and 602-604 marks the worker failed with error[:400] when there is no agent_complete. The error goes on the result (722-723) and is yielded as subagent_result (775/834), which is streamed and persisted. 880-882 then raises FanoutWorkerFailed, so the parent ends in pipeline_failed. Cancel: 582-588 flips the row to cancelled and re-raises, and the kernel emits pipeline_cancelled. Gate: kernel_services.py ~1190-1310 builds workers with gates=[] and invocation_gated=False ([ISS-097](20260812-1153-ISS-097.md)/[FIX-242](20260812-2116-FIX-242.md)), so none arms a gate. The engine.py pipeline_cancelled yields at 9304/9454/10938 are gate-rejection paths, which workers never reach.

**Left over (outside this card's claims):** Minor, by design. Raw worker events are still not forwarded (fanout.py:555 comment, D-03). An agent_error followed by agent_complete (timeout) and transient-retry errors (608-620, logged only) leave no event or persisted trace. Failure text is truncated to 400 chars. Card status still reads open, so the card is stale. No test was run (read-only).
