# ISS-129

## Title

**`run_fanout` swallows EVERY worker event, including terminal ones.** `fanout.py:414-429` iterates `runner.run_worker(...)` and forwards nothing; the loop body reads only `agent_complete` to accumulate `worker_tokens`. The in-file comment justifies this for CHUNK events (D-03, lifecycle-only), but the loop also discards `agent_error`, `pipeline_cancelled` and `review_gate_ready`. Because the durable `_RunEventSink` wraps `execute()`, an event that never leaves `_run_one` is never streamed AND never persisted — so a fan-out worker can fail, be cancelled, or open a HITL gate with no trace anywhere the user or the resume classifier can read. **This is the amplifier that turned ISS-097 from an annoyance into a silent hang**, and it is the same structural gap family as ISS-091. FIX-242 stops the gate instance (workers no longer arm one) but does NOT change what the loop forwards, so the `agent_error` / `pipeline_cancelled` half is untouched and live.

## Source / Evidence

Found 2026-08-12 by the ISS-097 investigation and confirmed at `eb12bc7e` by direct measurement (4 `_run_review_gate` entries, 0 frames on the wire). Filed rather than folded because deciding WHICH worker events must be forwarded or at least recorded is a product/vocabulary decision with real blast radius on the FE event contract and on the 5 characterization goldens — not something to settle inside a gating fix. Fix shape: decide the forwarded set (terminal + error at minimum), or record-without-forwarding into `run_events` so the durable log is complete even when the stream stays lifecycle-only.
