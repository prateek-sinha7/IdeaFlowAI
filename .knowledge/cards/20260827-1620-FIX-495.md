## Symptom

Decks generated by `ppt_v2` came out of the HTML→PPTX step visibly wrong:
rotation lost, boxes the wrong size, typography drifting from the source deck.

## Root cause

`ppt-code-generator` was transcribing PptxGenJS code from the deck's raw HTML and
CSS **text**, not from its rendered state. Rotation, box geometry and font
metrics are all products of layout, so reading the source meant guessing at all
three.

A second, sharper bug sat underneath: even where measurement was attempted, a
paginated deck (a JS slideshow hiding 9 of 10 slides behind `display:none`) only
ever exposed the visible slide. 90% of the deck had zero ground truth.

## Fix

**1. Ground-truth extraction** — `extract_computed_styles` in `pptx_tools.py`
headlessly renders `presentation.html` and dumps every visible element's real
position, rotation, font, fill, border and shadow to `.browser/deck-styles.json`
before the agent writes any code. It forces every `.slide` container visible
first, which is what fixes the paginated-deck blindness.

It reuses spec 018's `PlaywrightSession`; the bridge event loop moved out of
`app/agents/tools/playwright.py` into `playwright_session.py` so both modules
drive Playwright on the same loop — required once two agents in one run can share
a session.

**2. Hard gates in `render_pptx`, not prompt guidance.** A skill-doc instruction
was demonstrably not enough: verified live that the agent skipped it repeatedly
even with the instruction present. `render_pptx` now refuses to return `ok` —
returning the violation and forcing a retry — when the source has a real rotation
motif or a real rounded-corner motif that the built deck used none of.

Both gates are deliberately narrow: they fire only on a repeated, measured motif
(3 or more), never on a single incidental element.
