# ISS-1151

**Register source:** found but not fixed while fixing `QA-KB-106` ([FIX-773](20261009-0952-FIX-773.md)). It has no bug row of its own.
**INFERRED:** read from the code, not driven. The first fixer dispatch noted it as a residual on [ISS-1137](20261009-0304-ISS-1137.md).

## Condition

The user presses Run workflow, or Cmd/Ctrl+Enter, on a `/create/<type>` Input panel while `DashboardLayout`'s `connectionStatus` is not
`"connected"`, and the backend then refuses the launch. That happens just after page load, during "Reconnecting...", or after "Connection lost.".

## Why

1. `handleRunPipeline` launches only when connected. The code is `if (connectionStatus === "connected") { return onStartPipeline(...); } else {
   pendingStartOnConnectRef.current = { ... }; }` (`DashboardLayout.tsx:1846-1851`). The else branch returns `undefined`.
2. `IdeaInputPage.handleRun` releases its FIX-614 latch only when `onRun` hands back a promise that resolves to `null`
   (`IdeaInputPage.tsx:1702-1711`). `undefined` keeps the latch. [FIX-773](20261009-0952-FIX-773.md) made that choice on purpose, so that no
   outcome never means "released".
3. The connect effect fires the parked launch and discards the promise. The call is `onStartPipeline(pending.type, pending.message, ...)`
   with nothing chained (`DashboardLayout.tsx:1414-1422`).
4. A refusal there still reaches `page.tsx`'s `.catch`, so the banner shows the reason ([FIX-773](20261009-0952-FIX-773.md)). Nothing tells
   the panel, though. Run workflow and Cmd/Ctrl+Enter stay dead until a reload, which is the [ISS-1138](20261009-0304-ISS-1138.md) symptom on a
   narrower path.

The same effect also fires the parked staged-wizard, chain, history and clarify launches (`:1490`, `:1555`, `:2037`, `:2130`, `:2220`, `:2260`).
None of those panels holds a latch, so only the Input panel is affected.

## Where the fix belongs

Hand the parked launch's outcome back to the panel. Park a resolver with the params, resolve it from the effect's `onStartPipeline(...)`
promise, and make `handleRunPipeline` return a promise on both branches. Do not release in a `finally` in the panel: that reopens the
FIX-614 double-click window.

## What settles it

Run Playwright on `/create/user-stories` before the run connection reports connected. Hold the connection down so the layout shows
"Reconnecting...", and stub `POST /api/runs` to a 503 `_reject` body. Press Run workflow, then let the connection through. Check that the
banner shows, and whether Run workflow is enabled again.
