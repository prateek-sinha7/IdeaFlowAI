# ISS-1177

Sibling of [ISS-1157](20261009-1500-ISS-1157.md) (register QA-KB-116), derived from its root cause: the same seam
(`agentsFromManifest`, `frontend/src/lib/manifestAgents.ts:157`) that names a built-in step by its id also leaves every other
field the library would have supplied at `manifestStepToAgent`'s no-library-entry defaults. One of those defaults is
user-visible and is NOT repaired by restoring the name.

Confidence: the numbers are CONFIRMED (jsdom render of the real `IdeaInputPage`, live payloads, analysis-03 U1 and U2, and the
validator's own browser screenshot). That ~35s is the right expectation is INFERRED from the system roster's own pill.

## Condition

An ENABLED override of a built-in served by `IdeaInputPage` (user_stories, app_builder, mulesoft_to_springboot,
dotnet_to_azure), cold-loaded. `LaunchWizard` carries no ETA pill (its Advanced button prints only the agent count,
`LaunchWizard.tsx:1381`).

## Expected vs actual

| roster source | rendered Advanced pill (analysis-03) |
|---|---|
| `pro@velocity.ai`, no override, library roster (U2) | `6 agents · ~35s` |
| `admin@velocity.ai`, enabled override of the same six steps (U1) | `6 agents · ~6m` |

Expected: an override of the very same six steps reads the same as the system roster, or shows no estimate. Actual: a
fabricated 60 s per agent. The validator's screenshot of the cold load carries the same text
(`evidence/qa-kb-116/01-validate-attempt1-review-gates-open.png`: "6 agents · ~6m"), and `INTEGRATION_TESTS.md:228`
recorded "panel shows `6 agents · ~6m`" for an earlier e2e run, mis-triaged there as "UI-CHANGED" (that run was already in
the override state).

## Why the root cause implies it

`manifestStepToAgent` builds a no-library row with literals (`frontend/src/store/api/userWorkflows.ts:714-726`), among them
`estimated_duration: 60` (`:724`), meant as the composer's default for a blank custom agent. `decorate` keeps it:
`estimated_duration: a.estimated_duration ?? 0` (`manifestAgents.ts:150`; `??` does not replace 60). `IdeaInputPage.tsx:1929`
sums the roster (`pipelineAgents.reduce((s, a) => s + a.estimated_duration, 0)`) and `:2240` prints it, as `~Ns` under 60
and `~Nm` from 60. Six rows x 60 = 360 -> "~6m" (analysis-01 P3: "override roster: 6 rows, total est 360s"). The library
roster sums the six AGENT.md values (5 + 10 + 5 + 5 + 4 + 6 = 35) -> "~35s".

This is a regression of the same commit: before `1e329e47b` the hand-rolled projection set `estimated_duration: 0`
(`git show 1e329e47b^:frontend/src/lib/manifestAgents.ts`), and `:2240`'s `totalEstimatedTime > 0 &&` guard hid the
estimate for override rosters. The other defaults the seam leaves (icon placeholder, `has_skill: false`, description =
role) are unchanged by that commit and are not part of this card.

## Fix location

The seam (see ISS-1157). Two shapes, either keeps it to `agentsFromManifest`:

1. Resolve each built-in step through the agent library (an optional lookup forwarded to
   `manifestStepsToAgents(raw, lookup)`, the way `ComposerPage.tsx:318`, `WorkflowDetailView.tsx:36` and
   `workflowCanvasModel.ts:52` already do): real name, icon and duration, so the pill matches the system roster.
2. Resolve through the compiled `detail.steps` only (name and role) and zero the duration: restores the pre-`1e329e47b`
   behaviour (no ETA for an override roster).

A name-only fix leaves this card open. The per-agent chip in the agent drawer reads the same field
(`AgentsPopup.tsx:706`, `~{agent.estimated_duration}s`), so it shows "~60s" for each such row (INFERRED reachable).

## For the test-writer

Component tier, offline: `IdeaInputPage` with the enabled-override payload and the real library in Redux; the Advanced
button text must equal the one rendered for the same steps without an override (analysis-03 U1 vs U2). Fixtures must carry
the library's real `estimated_duration` values; the repo's IdeaInputPage fixtures use `estimated_duration: 60` for every
agent (`IdeaInputPage.iss919.test.tsx:63`), which makes the two rosters sum identically and hides this.
