## What was wrong

`CanvasNode.tsx`'s override-chip row (the strip beneath the model pill) rendered
exactly three chips — Validator, Gate, Retry — and computed exactly three booleans
(`validatorOn`, `gateOn`, `retryOn`). `grep -n "tools" CanvasNode.tsx` returned zero
matches. A canvas node with `write_files: false` (set via the config rail's Tools
tab) was visually indistinguishable from one with default tool grants until the author
re-selected the node and opened the rail's Tools tab specifically.

## Root cause

`frontend/src/components/workflow/composer/CanvasNode.tsx` — chip row — no
`toolsOn` boolean and no Tools chip.

## What changed and why there

Three additions in `CanvasNode.tsx`:

1. **Import `hasToolOverride`** from `../AgentsPopup` (it was already exported
   alongside `effectiveToolGrants` and `TOOL_GRANT_LEVERS`):
   ```ts
   import { getRole, getAgentInitials, hasToolOverride, type StepSelection } from "../AgentsPopup";
   ```

2. **`toolsOn` boolean** alongside the existing chip booleans:
   ```ts
   // ISS-382 — the chip row showed no Tools indicator; hasToolOverride returns
   // true whenever any grant deviates from the read+write default.
   const toolsOn = hasToolOverride(selection);
   ```

3. **Tools chip** appended after Retry in the chip row JSX — amber when active
   (matching Gate's amber style), muted when default:
   ```tsx
   <span
     title={toolsOn ? "Tool grants are restricted — open Config to view" : undefined}
     className={`rounded-[6px] border px-1.5 py-1 font-sans text-[9.5px] font-semibold ${
       toolsOn
         ? "border-status-amber-border bg-status-amber-fill text-status-amber"
         : "border-line-faint-row bg-surface-white text-ink-300"
     }`}
   >
     Tools
   </span>
   ```

`hasToolOverride` already handles the `undefined` selection case (returns `false`),
so no extra null-guard is needed.
