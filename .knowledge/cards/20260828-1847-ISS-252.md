## What is wrong

A FOURTH unnormalized `ppt` type check, found while grepping the blast radius
of [ISS-214](20260828-1633-ISS-214.md) (whose defect is exactly this shape in
`WorkflowHistory.tsx`). `DashboardLayout.tsx:2140` sets
`effectiveReviseType = viewedRunType ?? workflowType` — the run's RAW type, so
`"ppt_v2"` for a deck run — and two consumers then test it against the literal
`"ppt"` / `"ppt_revision"` only:

- **`:2347-2352`** `laneActiveContent` falls through both the ppt and the
  prototype arm to `userStoryContent`, so
  `deriveDeliverableFilename(effectiveReviseType, laneActiveContent, …)`
  (`:2353`) is handed the wrong slot AND a type its own ppt branch
  (`FilesTab.tsx:321`) does not match, landing on the generic
  `return fallback || "deliverable"`. With `pipelineState.deliverableFilename`
  present (the live path) the fallback masks it; on a reopened run with no
  pipeline state the chat lane's "Run summary" DeliverableCard would name the
  deck `deliverable`.
- **`:2159-2166`** `activeReviseHandler` — a `ppt_v2` run matches no arm
  (`handleRevisePpt` requires the literal `"ppt"`), and unless
  `prototypeContent` happens to be set it resolves to `undefined`, i.e. no
  revise affordance for a ppt_v2 deck.
