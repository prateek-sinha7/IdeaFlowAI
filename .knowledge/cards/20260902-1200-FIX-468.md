## What was wrong

`ComposerPage.handleRunOnce` (ComposerPage.tsx) had two call paths — the button's
`onClick` handler and `handleRunOnce` itself — neither of which checked
`pipelineAgents.length === 0` before firing `onRun`. A brand-new "Compose a custom
workflow" canvas starts with `pipelineAgents = []`, so clicking "Run once" after
typing a brief but before adding any agent dispatched `onRun("custom", brief, [],
extraParams)`. `useWorkflow.ts:88-90` omits `agent_ids` from the POST body when the
array is empty, and `run_commands.py:2695`'s `if agent_ids:` branch is False, causing
`get_pipeline_agents("custom")` to return the full 9-agent default pool — silently
launching a full run for a workflow the user had not yet composed.

`IdeaInputPage.handleRun` already carries this exact guard:
```ts
if (!ideaInput.trim() || pipelineAgents.length === 0) return;
```
`ComposerPage.handleRunOnce` had no equivalent.

## Root cause

`frontend/src/components/workflow/composer/ComposerPage.tsx` — `handleRunOnce`
and the Run once button `onClick` — no `pipelineAgents.length === 0` check before
`onRun` was called.

## What changed and why there

Two additions in `ComposerPage.tsx`:

1. **`handleRunOnce`** — early return added immediately after the `trimmed` check:
   ```ts
   if (pipelineAgents.length === 0) return;
   ```
2. **Run once `onClick`** — added a named guard branch before the `handleRunOnce`
   call that also sets the `saveError` banner so the author gets visible feedback
   (see FIX-469 for the banner; this guard fires first):
   ```ts
   if (pipelineAgents.length === 0) {
     setSaveError("Add at least one agent before running.");
     return;
   }
   ```

The Run once button's `title` and `className` `opacity-60` condition were also
extended to cover the `pipelineAgents.length === 0` case so the button's visual
state reflects the guard.

Also closes ISS-334's ComposerPage-side consequence: a transient fetch failure sets
`pipelineAgents = []` via the same dead-link path, and this same guard now blocks
the 9-agent substitution for that trigger too. The `page.tsx` unconditional-catch
root (domain 8's primary file) is escalated separately.
