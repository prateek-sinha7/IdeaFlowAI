# ISS-082

## Title

**The sibling reducer accumulators carry no identity key either — `agent_chunk` (`output: prev.output + chunk`) and `hook_run` (`hookRuns: [...prev.hookRuns, entry]`) in `useWorkflow.ts`.** FIX-225 gave the revision counter its own identity key because that number is the one users read; these two are now protected ONLY by the class-level fix (the seen-set is no longer wiped mid-replay), i.e. by an external guarantee — exactly the arrangement that failed for ISS-080. A partial double-delivery would duplicate streamed agent text or an audit row. Generalised rule the investigation drew out and worth adopting: **any reducer field that accumulates (`+= 1`, `push`, `concat`) must have a test that replays its input twice.**
