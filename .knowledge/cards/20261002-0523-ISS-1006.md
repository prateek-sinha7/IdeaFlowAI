# ISS-1006

**INFERRED. Reproduced offline in jsdom only (case R3), not in a browser.** Derived while analysing QA-KB-066 ([ISS-755](20260922-1415-ISS-755.md)); the root-cause analysis and
the offline proof are on that card ("Re-analysis (2026-10-02, QA-KB-066)") and in `evidence/qa-kb-066/`. An unreproduced
sibling is a lead, not a defect.

Line numbers are the working tree on 2026-10-02 (HEAD `024c03ef8`); `PreviewPanel.tsx`, `DashboardLayout.tsx` and
`useWorkflow.ts` carry uncommitted edits from other work (none touches clarifications), so HEAD numbers can sit a few lines off.

## Condition

A family member whose run answered one or more clarify rounds, pinned as the read-only older version while the shell holds a
different set (or none): the Version menu on a family where v1 asked its questions and v2 is a revision that asked none, or a
`/runs/{id}/versions/1` deep link, or simply a page reload after v2 completes (the shell then holds no rounds at all).

## Expected vs actual

- **Expected** (`BUGS.md#qa-kb-066`): "the Steps and Files clarify rounds follow that version (its own rounds, or none)". For a
  version that did ask questions that means its rounds: the Steps "Clarifications, n questions" card and the Files
  `clarifications.md` row.
- **Actual:** neither can ever show them. Even after [ISS-755](20260922-1415-ISS-755.md)'s one-value fix the pinned view reads
  `viewingVersion.clarifications`, which nothing sets, so a version that asked questions renders as if it asked none. Offline proof
  R3 (`evidence/qa-kb-066/analysis-proof-clarify-pin.out.txt`): the shell holds no rounds, v1's persisted rounds are served by a
  mocked `getRunArtifacts`; after pinning v1 the mock was never called (`"getRunArtifactsCalls":[]`) and "V1-OWN-Q1" never rendered.

## Why the root cause implies it

[ISS-755](20260922-1415-ISS-755.md)'s root cause is that the version-aware layer has no clarify slot, so Steps and Files fall back to raw shell
props. The slot is missing, not just unused: `VersionView` (`PreviewPanel.tsx:573-603`) carries `runInput`, `agents`,
`pipelineState`, `agentOutputs`, `genericDeliverable` and `status` but no `clarifications`; `versionViewFrom`'s `pipelineState`
(`:643-661`) omits the key; and both ways of pinning fetch only the run record (`handleSelectVersion` `:922-923`, the
`/versions/{n}` effect `:1026-1027`: `getWorkflow` then `versionViewFrom`).

The data exists and is already read elsewhere: `backend/agents/execution_engine/clarify_engine.py:1114` persists one
`kind="clarifications"` artifact per answered round (every run that goes through the ClarifyEngine), and `WorkflowHistory.tsx:446` reads it with
`getRunArtifacts(token, id, { kind: "clarifications", includeContent: true })` (`lib/api.ts:1525`) followed by
`parseClarificationArtifacts` (`lib/clarifications.ts:31`). The pin paths just never ask.

## Fix direction (not applied; INFERRED design, validated on a scratch copy)

Land with or after [ISS-755](20260922-1415-ISS-755.md)'s fix, which keys the derivation on the pin so a pinned version's rounds can only come
from the pinned version:

- A `loadVersionRounds(token, runId)` beside `versionViewFrom` (try/catch -> `[]`), awaited together with `getWorkflow` in BOTH
  pin paths and stored as `VersionView.clarifications`.
- Keep the `gen === selectGen.current` / `cancelled` guards ([ISS-758](20260922-1421-ISS-758.md)) around the single
  `setViewingVersion`: the extra fetch rides inside the same `Promise.all`, so there is no second setter to race.
- `PreviewPanel.tsx` only. Share the fetch-and-parse helper with [ISS-1008](20261002-0523-ISS-1008.md) (a reopened run wants the same data).

Scratch variant `evidence/qa-kb-066/patched/PreviewPanel.complete.tsx` (diff `PreviewPanel.complete.diff` beside it): all 7 proof
cases pass, R3 included.

## What would settle it

Open a family where v1 answered clarify rounds and the shell holds none (reload the page after v2 completes), pin v1 from the
Version menu, open Steps.

## Resolution — FIX-730 (2026-10-07)

Resolved by [FIX-730](20261007-1900-FIX-730.md), for register entry QA-KB-066, as this card's fix direction proposed.
`loadRunClarifications(token, runId)` sits beside `versionViewFrom` (`PreviewPanel.tsx:613-623`). It is awaited in one
`Promise.all` with `getWorkflow` in both pin paths (`:955`, `:1060`) and stored as `VersionView.clarifications`. The
ISS-758 `gen` / `cancelled` guards still cover the single `setViewingVersion`.

The helper stayed in `PreviewPanel.tsx`, not `lib/clarifications.ts`, because ISS-1008's load ended up in the same
file. Test: the ISS-1006 case now fails with "Expect test to fail" (the `it.fails` pass signal). The marker is left for
the 6-verifier.
