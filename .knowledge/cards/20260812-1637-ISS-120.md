# ISS-120

## Title

**Bedrock prompt caching is a single process-wide on/off switch, and on short runs it is a MEASURED net cost INCREASE.** `BEDROCK_PROMPT_CACHE_ENABLED` (`app/core/config.py:158`, default `True`) is one boolean read at call time by exactly two sites — `app/agents/deep_agent_runner.py:227` (`_BedrockCachePointsMiddleware.wrap_model_call`) and `app/agents/cached_invoke.py:71` (`_bedrock_cache_control`). There is **no per-workflow, per-step or per-agent override anywhere** (all four line numbers re-verified at `c05906c0`). Measured read-only against the live `backend/dev.db`, re-priced through the real shared `estimate_cost_usd` with 0 reconciliation mismatches across all 11 rows: **6 of 11 persisted runs cost MORE with caching on (-4.98% .. -8.86%), 1 is exactly neutral, 4 save (+58% .. +83%).** **The discriminator is run LENGTH, not workflow type** — `ec7fb984` is an `od_prototype` cancelled early (`cache_read=11,225`, `cache_write=148,379`) at **-4.98%**, while every `user_stories` run has `cache_read=0` with a non-zero `cache_write`. Mechanism: a cache entry bills at `cache_write_5m = 1.25x` the input rate (`agents/capabilities/model_catalog.py:82`, `Pricing(1e-6, 5e-6, 0.1e-6, 1.25e-6, 2e-6)`; the same 1.25x ratio holds for every catalog tier), so any turn that writes a cache entry nothing later re-reads is a pure 25% surcharge on that content. The aggregate over all 11 runs is still **+80.34%** because two long prototype runs dominate — **the fleet number hides a real per-run regression**, which is precisely what FIX-239's `estimated_cost_full_usd` now makes visible. Candidate shapes, ascending cost: (a) leave global, document it; (b) suppress the cache point when the step is declared single-turn (manifest-declared capability flag, no kernel edit, SC-001); (c) a heuristic that only writes cache points once a run has exceeded N model calls. **Do NOT key it on workflow name (INV-1).**
