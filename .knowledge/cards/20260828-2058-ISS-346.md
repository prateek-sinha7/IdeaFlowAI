# ISS-346

## Description

Found while fixing [ISS-218](20260828-1700-ISS-218.md) / [ISS-235](20260828-1830-ISS-235.md);
recorded, not fixed.

`recentRuns` is populated from `getWorkflows(token, { limit: 50 })` ->
`GET /api/runs?limit=50`. That response carries **no `input` field** —
confirmed live, its keys are `agent_count, completed_at, created_at,
deliverable_filename, deliverable_mimetype, diverted_at_step_id, duration,
error, id, parent_run_id, root_run_id, status, title, token_usage, type`.
`normalizeWorkflowRun` (`frontend/src/lib/api.ts:672`) still maps
`input: raw.input`, which is typed `string` on `WorkflowRun`
(`frontend/src/types/index.ts:387`) but is `undefined` at runtime for every
entry in that list.

So `viewedRun?.input || submittedBrief` — `runHeaderTitleFull`
(`frontend/src/components/layout/DashboardLayout.tsx:2409`, the run header
tooltip) and now `handleEditBrief` (`:2179`, [FIX-331](20260828-2056-FIX-331.md))
— **always** takes the right-hand fallback. Its first operand is dead.

That matters because `submittedBrief` is not the brief: both places that set
it keep only the FIRST LINE —

```ts
const _reopenParsed = parseRunInput(fullRun.input ?? "");
const _reopenBrief = (_reopenParsed.revisionInstruction ?? _reopenParsed.brief ?? "").split("\n")[0].trim();
setSubmittedBrief(_reopenBrief || fullRun.title || "");
```

(`frontend/src/app/[...view]/page.tsx:2776-2778`, mirrored at `:2564-2567`).

Consequences, in increasing severity:

1. The header tooltip that deliberately wants "the ORIGINAL untrimmed brief,
   not the (possibly 60-char-truncated) DB title" gets a first-line-only brief
   instead — the comment at `:2406-2408` describes behaviour the code cannot
   deliver.
2. "Edit brief & run again" pre-fills only the first line of a **multi-line**
   brief. Single-line briefs (both seeded test runs) are unaffected, which is
   why the FIX-331 tests pass.

## Expected vs Actual

- **Expected:** a consumer asking for the viewed run's own full input gets it.
- **Actual:** it silently gets the first line of it, because the only source
  that would carry the full text is absent from the list payload.

## Disposition

Open, deferred. Two candidate directions, both larger than the FIX-331 diff and
neither obviously right without a call on payload size:

- Merge the full run into `recentRuns` after `getWorkflow(token, run.id)`
  resolves in `handleSelectWorkflowRun` (`page.tsx:2735`) — the fetch already
  has `input` in hand and throws it away.
- Thread the fetched `fullRun.input` down as its own prop instead of
  overloading `submittedBrief`, which is a display string by design.

Adding `input` to the list endpoint is the third option and the worst: it would
put every run's full brief on a 50-row payload.
