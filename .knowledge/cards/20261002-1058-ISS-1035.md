# ISS-1035

Sibling of [ISS-944](20261002-0040-ISS-944.md) and the second caller of the flaw in [ISS-1034](20261002-1058-ISS-1034.md), found by the QA-KB-086
analysis on 2026-10-02. Confidence: the observation is CONFIRMED by an offline probe of the real wizard in prototype mode (no repo file was
edited); the mode-switch half is INFERRED. The decision it needs is the one stated on [ISS-1034](20261002-1058-ISS-1034.md); this card does not restate it.

## Why the root cause implies it

`LaunchWizard.tsx` carries a line-for-line copy of the pattern behind [ISS-944](20261002-0040-ISS-944.md): a `gateSelectionRef` seeded
`touched: true` (`:356`), a `handleGatesChange` that assigns whatever the section reports (`:766-767`), and a `ReviewGatesSection` mounted
beside it (`:1362`). The section reports `([], false)` on mount (`ReviewGatesSection.tsx:173-178`), so the seed is overwritten here too.
All five `LaunchWizard*.test.tsx` files mock the section, and `LaunchWizard.test.tsx:118-122` mocks it as a button that reports only when
clicked, so the seed survives in every test.

## Condition

An untouched launch from the prototype or ppt wizard: pick a template and design system, type a brief, click Continue, touch nothing in Review gates.

## Expected (as `LaunchWizard.test.tsx:148-164` pins it)

"The golden draft as the WIZARD writes it today": `buildLaunchDraft(mode, { ...inputs, gatesTouched: true, gateAgentIds: [] })`, so the draft carries
`"gateAgentIds":[]`. The comment at `LaunchWizard.tsx:352-356` says the same ("`gate_agent_ids` is ALWAYS sent ... do not revert it to false").

## Actual

The draft the real wizard writes has no `gateAgentIds` (`evidence/qa-kb-086/04-analyze-probe-launchwizard-real-section.tsx.txt`, output in `05-`):

```
RAW_DRAFT={"templateId":"kanban","designSystemId":"midnight","brief":"Build a kanban board","agentIds":["prototype-specify","prototype-plan","prototype-analyze","prototype-build","prototype-validate"]}
GOLDEN_AS_WIZARD_WRITES={"templateId":"kanban","designSystemId":"midnight","brief":"Build a kanban board","gateAgentIds":[],"agentIds":[...same five...]}
```

`buildLaunchDraft` is not at fault: `launchDraft.ts:126` is `...(gatesTouched ? { gateAgentIds } : {})`, and `touched` is false by the time the
wizard reads the ref (`LaunchWizard.tsx:1012`). Downstream agrees: `DashboardLayout.tsx:1433` and `:1503` add `gate_agent_ids` only when the
draft's `gateAgentIds !== undefined`, so the run launches with the key absent. The frozen oracle in `__fixtures__/launchContract.ts` models "the
RETIRED route-split flow, where the field was omitted while untouched" (the test's own words), which is what the wizard still does.

No `prototype` or `ppt` run exists after 2026-08-29 in the local DB, so there is no row-level corroboration for the wizard
(`evidence/qa-kb-086/07-analyze-db-select.txt`).

## INFERRED: the mode switch

`LaunchWizard.tsx:733` resets the ref to `{ ids: [], touched: true }` when the Web/Deck toggle changes, in the same handler that replaces
`pipelineAgents` (`:731`). A new agent list changes the section's `agentsKey`, which re-runs its report effect (`:173-178`) and writes
`touched: false` again. Read from the code, not probed. Settle it by toggling Web to Deck in the probe and reading the draft.

## Fix direction

Follows the decision on [ISS-1034](20261002-1058-ISS-1034.md). If the answer is "omit when untouched", the wizard changes `touched: true` to
`false` at `:356` and `:733`, rewrites the comment at `:352-356`, and `goldenAsWizardWrites` stops adding `gatesTouched: true, gateAgentIds: []`
(the tests that click the section's mock button still send `["prototype-specify"]`, `LaunchWizard.test.tsx:331-341`). If the answer is "always
send", the mount report must stop clearing `touched`, with the ids it reports preserved.
