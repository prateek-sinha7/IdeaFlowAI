# ISS-1066

## Description

Found while checking what [FIX-745](20261007-2030-FIX-745.md) costs a shared prototype. FIX-745 adds
`Content-Security-Policy: sandbox allow-scripts` to `GET /s/{token}`. Without `allow-same-origin` the document gets an
opaque origin, and any Web Storage access throws. This was observed in Chrome 151:
`evidence/qa-kb-089/fix-chrome-csp-sandbox-probe.txt`, `/html-sandbox` → `"ls":"THREW SecurityError"`.

`skills/opendesign/design-templates/live-dashboard/assets/template.html:413` runs
`let autoOn = JSON.parse(localStorage.live_dashboard_auto || "true");` at the top of its script with no try/catch, and
`:632` writes the same key the same way. In an opaque origin, line 413 throws and the rest of the script never runs.

The other storage-using templates guard it:

- `simple-deck/assets/template.html:306,341-342`, try/catch
- `replit-deck/examples/example-atlas.html:454,486-487`, try/catch
- `trading-analysis-dashboard-template/assets/template.html:214-217`, which states the contract: "scripts but not
  same-origin (Open Design's preview), so persistence is strictly best-effort and must never abort initialization".

## Where it bites (INFERRED, not driven)

The case is a prototype the od agent seeds from this template and viewed under an opaque origin. That happens on the
share link since FIX-745, and in the generic in-app renderer (`PreviewPanel.tsx:278`, `sandbox="allow-scripts"`). The
owner's own `PrototypePreview` uses `allow-scripts allow-same-origin` (`PrototypePreview.tsx:610`), so the owner would
see nothing wrong. I have not checked whether a generated prototype keeps the template's line verbatim.

## Fix direction

Guard both accesses the way the trading-analysis template does, with a try/catch get/set pair. The change is to the
template only, with no app code. FIX-745 did not make it because it is outside its cards, and skill files are edited
by the user.
