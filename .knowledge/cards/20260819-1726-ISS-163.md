## Bedrock/Anthropic extended thinking never reached the UI

**Symptom:** `THINKING_BUDGET_TOKENS` set and confirmed live (Bedrock `output_tokens`
volume and `temperature=1` consistent with real thinking spend), but the UI's Thinking
tab stayed empty and no `model thinking ...` DEBUG trace line ever appeared in the
backend log, for any agent, across a full run — confirmed against a real local log
covering `prototype-specify`/`prototype-plan`/`prototype-analyze`.

**Root cause:** `DeepAgentRunner.astream_events`'s `on_chat_model_stream` handler
(`backend/app/agents/deep_agent_runner.py:566-591`, pre-fix) extracted live reasoning
from exactly one place: `chunk.additional_kwargs.get("reasoning_content")` — the shape
`langchain_ollama` uses when `reasoning=True`. Extended thinking on the other two
providers this app uses arrives as a **content block**, never in `additional_kwargs`:

- `ChatAnthropic` (verified against the installed `langchain_anthropic` package,
  `chat_models.py:1556-1560`): `AIMessageChunk(content=[{"type": "thinking",
  "thinking": "<delta>"}])`.
- `ChatBedrockConverse` (verified against the installed `langchain_aws` package,
  `bedrock_converse.py:335` docstring example): `{"type": "reasoning_content",
  "reasoning_content": {"type": "text", "text": "<delta>"}}`.

`_extract_text()` (the function used for the visible `chunk` text) also explicitly
filters to `block.get("type") == "text"`, so these blocks were dropped silently from
both paths — no crash, no log line, just nothing yielded. Downstream, `engine.py`
(the `"thinking"` → `agent_thinking` mapping, lines 4475-4481) and the frontend
(`useWorkflow.ts:608-625`, `AgentThinkingTab`) were already fully provider-agnostic —
the entire gap was this one extraction function.

**Fix:** [FIX-262](20260819-1726-FIX-262.md) adds `_extract_thinking()` (mirrors `_extract_text()`) recognizing
both the Anthropic and Bedrock content-block shapes, called from the same
`on_chat_model_stream` handler alongside the existing Ollama check.
