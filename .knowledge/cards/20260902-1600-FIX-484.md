## What was wrong

Three sibling defects in `_reconcile_terminal_status`
(`backend/app/api/run_commands.py:~805-840`) — all variants of the same unscoped-scan
pattern first noted in [ISS-316](20260828-1952-ISS-316.md) and partially fixed by
[FIX-381](20260829-0220-FIX-381.md):

**ISS-435:** `terminal_seqs` (which drives `resume_supersedes`) included `complete_seqs`
(non-degraded completions) and `pipeline_failed` seqs, but NOT degraded `pipeline_complete`
seqs. A cancelled run whose resumed attempt ended in a degraded completion stayed stuck
reporting `"cancelled"` forever, because `resume_supersedes` short-circuited `False` — no
non-degraded completion and no `pipeline_failed` was present, so `terminal_seqs` was empty.

**ISS-436:** `degraded = any(pipeline_complete degraded) over the WHOLE tail` — no attempt
boundary. A run resumed after an earlier degraded attempt reported `"degraded"` even when
its latest attempt cleanly completed or genuinely failed.

**ISS-437 (inverse):** `failed = any(pipeline_failed) over the WHOLE tail` — same
unscoped pattern. A run resumed after an earlier failure that then cleanly completed stayed
permanently `"failed"` instead of `"completed"`.

## What changed

`backend/app/api/run_commands.py` — `_reconcile_terminal_status` only:

**ISS-435:** Added `degraded_complete_seqs` (the subset of `completes` whose
`payload_json.status == "degraded"`) and included it in `terminal_seqs`. The
attempt-boundary guard in `resume_supersedes` now covers all three outcome types: clean
completion, degraded completion, and pipeline_failed.

**ISS-436/ISS-437:** After the `cancelled and not resume_supersedes` branch, compute
`last_reattempt_seq = max(reattempt_seqs) if reattempt_seqs else 0` and filter
`current_attempt_completes = [e for e in completes if e.seq >= last_reattempt_seq]`.
Replace the whole-tail `degraded` / `failed` booleans with scoped variants:
- `degraded_current`: any degraded completion in `current_attempt_completes`
- `failed_current`: any `pipeline_failed` event with `e.seq >= last_reattempt_seq`

The status ladder now uses `degraded_current`, `current_attempt_completes`, and
`failed_current` instead of the whole-tail flags. A run with no prior attempts
(`reattempt_seqs` empty → `last_reattempt_seq = 0`) scopes to the full tail, which is the
correct degenerate case (no boundary → all events are the current attempt).
