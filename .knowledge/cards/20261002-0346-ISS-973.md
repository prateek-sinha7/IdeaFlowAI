# ISS-973

**INFERRED, not reproduced in the UI.** Derived while analysing QA-KB-053 ([ISS-665](20260917-1311-ISS-665.md)). The mechanism was read in source and the
data it acts on was read from the live API (`evidence/qa-kb-053/family-probe.out.txt`); nobody has yet opened an older member's
own page and read the row. An unreproduced sibling is a lead, not a defect.

Line numbers are the working tree on 2026-10-02 (HEAD `024c03ef8`); `PreviewPanel.tsx`, `api.ts` and `run_files.py` carry uncommitted edits from other work, so their numbers can sit a few lines off HEAD. Real-data figures come from read-only GETs against the dev backend on :8000 (admin account), saved with their script in `evidence/qa-kb-053/`.

## Condition

A family member that is NOT the newest, opened at its own URL with no `/versions/{n}` segment. That is the default way an older
run is opened: Run History and Home recents both do `onOpenRun={(run) => { onSelectWorkflowRun?.(run); setMainView("execution");
router.push(routes.runDetail(run.id)); }}` (`DashboardLayout.tsx:3053`, `:2993`), and `routes.runDetail(id)` is `/runs/{id}`
(`routes.ts:92`). Nothing is pinned. In that state (`PreviewPanel.tsx`):

- `:854-855` `unpinnedRunId = liveRunId ?? latestId` and `activeRunId = viewingVersion?.id ?? unpinnedRunId`. `liveRunId` is the
  shell's `contentSourceRunId` (`DashboardLayout.tsx:3410`), the member that was opened; `viewingVersion` is null.
- `:857` `isViewingOlder` is false, so there is no read-only banner either.
- `sandboxSelectedRef` is null. Only `handleVersionMenuSelect` (`:941-962`) and the `pinnedMember` effect (`:1008-1035`) ever set it
  non-null.

So every surface that is ref-aware only through the pin, and every surface that is not ref-aware at all, reads the live tree,
which is the NEWEST member's.

## Expected vs actual

Expected: a member's own page names, sizes and serves THAT member's deliverable, the same as the pinned path does after
[FIX-603](20260922-1440-FIX-603.md).

Actual: the Files row, the hero card and the header Download show and serve the newest member's file; a PDF deliverable previews
the newest PDF.

## Surfaces affected (read)

1. Files row, hero and Download: `FilesTab.tsx:563`, `:740`, the subject of [ISS-665](20260917-1311-ISS-665.md). Its sketched fix `selectedRef={sandboxSelectedRef}`
   is a no-op here because that value is null.
2. Header Download: `PreviewPanel.tsx:1485-1487` passes `sandboxSelectedRef ?? undefined`, which is `undefined`, so [ISS-706](20260922-1035-ISS-706.md)'s fix
   ([FIX-603](20260922-1440-FIX-603.md)) covers only the pinned path.
3. Preview of a PDF deliverable: `PreviewPanel.tsx:1663` `<GenericDeliverablePreview ... runId={activeRunId ?? undefined} />`, then
   `:223-225` `SandboxPdfPreview`, then `SandboxPdfPreview.tsx:21` `getRunSandboxFileBlob(getToken() || "", runId, path)`: the
   component has no ref parameter at all. (With a ref selected the Preview takes the `RefVersionPreview` branch instead, `PreviewPanel.tsx:1763-1779`, so this
   surface is hit only when no ref is selected: un-pinned, or pinned to a member with no tag.)
4. History's chain-detail Files tab: `WorkflowHistory.tsx:1141` mounts `<FilesTab runId={selectedRun.id} ...>` with no ref and no
   parent; reachable only through the row's "Chain" action (`WorkflowHistory.tsx:350-361`, `onOpenRun` otherwise wins), so lowest
   priority.

- Family `87e02c32-96a9-4e50-8ed0-79023d83540f`, member v5 `8f36b400-19e4-4291-944c-09e30b37fc6f` (`prototype_revision`, tag v5), opened

  `resolveRunDeliverable` reads gives 145,552 B (142.1 KB, `7fcb87f275a6`), which is v6's file.
- Backlog family `78e185fb-c032-4154-8552-774781b6e5df`, member v2 `80054fbc-71cc-42de-adeb-ae2db82eb2f2`: the PDF preview's request
  (`GET …/sandbox/file?path=Backlog.pdf`, no ref) returns 200, 23,626,760 B, sha256 `887bd75cee6b`, which is v8's PDF; v2's own copy is
  `.chain/Backlog.pdf` at ref v2, 23,010,668 B, `e8317cebb373`.

## Why the root cause implies it

[ISS-665](20260917-1311-ISS-665.md)'s mechanism is "reads default to the live tree because nothing carries the member's ref". The ref is keyed on the PIN, not on
the DISPLAYED MEMBER. [FIX-603](20260922-1440-FIX-603.md) closed the pin; nothing closes the member's own URL. This is also why ISS-665's sketched fix
(`selectedRef={sandboxSelectedRef}`) is incomplete.

## Fix direction

Derive the ref once from the displayed member in PreviewPanel and feed every consumer from it, e.g. beside `:862`:
`const activeMember = sortedMembers.find((m) => m.id === activeRunId)` and
`const displayRef = sandboxSelectedRef ?? (activeMember && activeMember.id !== latestId ? activeMember.git_tag ?? null : null)`;
pass it to FilesTab (`selectedRef`), `handleHeaderDownload` (and its deps) and `GenericDeliverablePreview` ->
`SandboxPdfPreview`. A member with no tag (real: `4eb1a2ea-b4be-400a-b53c-b63597cc52a0`, cancelled, and
`97b49f98-83bd-4ed6-8631-600bf9653905`, failed, both in family `87e02c32-…`, both with no declared deliverable) has nothing to scope
to: keep the derived row and the PDF `fallback`, never reconcile against the live tree ([ISS-697](20260922-1000-ISS-697.md)).

Open question this card does not decide: SandboxTab on the same page also reads the live tree (`selectedRef={sandboxSelectedRef}`
is null) and [FIX-604](20260922-1635-FIX-604.md) defines "Latest (live)" as the uncommitted working tree. Whether the Workspace tab of an older member's own
page should default to that member's tag is a product call; this card's claim is limited to the surfaces that present ONE
member's deliverable.

## What would confirm this

Open `/runs/8f36b400-19e4-4291-944c-09e30b37fc6f` from History, Files tab: expect 142.1 KB where 144.9 KB is right; click Download
and sha256 the file: expect `7fcb87f275a6` where v5's own is `2db5b988b2c9`. Test seam: a PreviewPanel test with a 3-member
`runFamily`, `liveRunId` = the middle member, no `pinnedVersion`, and a prop-recording FilesTab stub
(`PreviewPanel.refSurfaces.test.tsx` stubs FilesTab without recording props).

## Resolved (2026-10-02, QA-KB-053)

Fixed by [FIX-717](20261002-1243-FIX-717.md) for every surface on the shared run screen.
- PreviewPanel derives `displayRef`: the pin's tag; otherwise an older member's own `git_tag` (`null` if it has none); otherwise `undefined` for the newest member.
- `displayRef` feeds the Files row, the header resolve and the header Download, and `GenericDeliverablePreview` → `SandboxPdfPreview`.

Observed run: `SandboxPdfPreview.ref.test.tsx` went from "1 expected fail" to "Error: Expect test to fail". The marker is left for the verifier.
