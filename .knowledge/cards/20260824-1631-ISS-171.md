Found while taking spec-014's `ex_A1_loop` fixture through repeated live runs on AWS
Bedrock (`eu.anthropic.claude-haiku-4-5`).

## Symptom

Every step of `ex_A1_loop` declares `read_files: false` (verified at compile time — all
four steps report `read/write/exec = False/False/False`). Yet a single run emitted **11
`tool_call` events**, and they executed:

```
greet  read_file  /emoji-say-hello-to-me.md
check  ls         /   ->  ['/.logs/', '/emoji-say-hello-to-me.md', '/greet-say-hello-to-me.md']
check  read_file  /greet-say-hello-to-me.md
done   grep, read_file, ls
```

The `ls` result is a REAL directory listing returned to the model, so this is enforcement
failing — not the model narrating an intention it could not act on.

## Why it also breaks the fixture

The files those steps discover are the per-step `<step>-<slug>.md` artifacts
`artifact_fallback` writes. Each step spends its turn hunting for and reading the previous
step's artifact and narrating that hunt, which pollutes its output:

```
greet -> 'I need to read the file first. Let me check the directory:👋 Hello there!'
check -> 'Let me read the greeting file:I need to find the file first...'
```

`check` must emit one line of JSON. The narration means it does not, the conditional gate
fails closed, and — via the separate defect in
[ISS-170](20260824-1610-ISS-170.md) — the run advances anyway and reports success.

This is why `ex_A1_loop` fails consistently while A2/A3/A4 pass: A1 is the only fixture
whose prompts reference prior output ("Look at the greeting above", "Respond with the
greeting above"), which is what invites the file hunt.

## Where the break is

Traced end to end, and the first three layers are CORRECT:

- the compiler applies the cap and produces the right `ToolPermissions`
- `current_step` is bound correctly (`kernel_services.py`)
- `denied_tools(ctx.step_tools)` computes the right denial set (`factory.py:330`)
- it is passed to `DeepAgentRunner(denied_tools=...)` (`factory.py:389`)

**The break is inside `DeepAgentRunner`, past that hand-off** — the denial set arrives and
does not take effect. `PERMISSION_TOOLS["read_files"]` covers `read_file`, `ls`, `glob`
and `grep`, all four of which were observed executing.

## Severity

Security-adjacent. A step deliberately denied read access can enumerate and read the run
sandbox, including artifacts written by other steps in the same run. No cross-run or
cross-user access was observed — the sandbox is still per-run — but the per-step boundary
is not holding.
