With the conditional gate finally rendering, the canvas still drew no branch edges, and
`done` was marked detached — an orphan.

## Root cause

```js
if (o.trigger === "step" && o.target) routeTargets.add(o.target);   // "done"
...
const fed = routeTargets.has(a.id) || ...                            // "custom-agent:done"
```

A hand-authored manifest writes route targets BARE (`target: done`) because the engine
resolves them with a suffix fallback. The canvas has no such fallback — it works in
node-id space, the same convention `depends_on` uses. So `done` never matched, it was
never recognised as a route target, and every edge lookup missed.

## Fix

Normalise `trigger: "step"` targets to node ids when mapping manifest steps to agents.
`trigger: "workflow"` targets are WORKFLOW ids, not step ids, and are deliberately left
alone.

The general rule is recorded in [ADR-0017](20260824-1630-ADR-0017.md) — this is the third
defect caused by the same dual identity.
