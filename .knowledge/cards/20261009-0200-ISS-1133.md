# ISS-1133

Register bug `QA-KB-107` (SMOKE-2, dev-only, Low). Route: POST /api/runs (launch preflight, `run_commands.py:2960-2967`).

## Reproduction (3/3, cold python process each, offline, no browser)

Harness: set `USE_LOCAL_OLLAMA=1`, `settings.ANTHROPIC_API_KEY=""`, `settings.AWS_BEARER_TOKEN_BEDROCK` = `bedrock-api-key-` + base64 of a presigned
payload with `X-Amz-Date=20200101T000000Z&X-Amz-Expires=43200`; call `preflight_check_provider()`. All three cycles returned
`(False, 'Bedrock bearer token expired at 2020-01-01T12:00Z - rotate AWS_BEARER_TOKEN_BEDROCK and restart the backend.')`, which `launch_run` turns
into 503 `model_provider_unavailable`. Output: `evidence/qa-kb-107/01-validate-attempts1-3-preflight-output.txt`. The live HTTP path was not driven
(it would need the backend env changed); the preflight function is the sole decision point at `run_commands.py:2962`.

## Cause

`model_factory.py:113-117` early-returns only for `settings.ANTHROPIC_API_KEY`, with a comment saying it mirrors `build_model()` precedence. But
`build_model()` checks the USE_LOCAL_OLLAMA override first (`model_factory.py:323-345`, read from `.env` + `os.environ`, truthy `1/true/yes/on`)
and returns ChatOllama before the Anthropic or Bedrock branch (`:413`). The preflight therefore does not mirror the real precedence.

## Expected vs actual

Expected: with Ollama on, preflight returns `(True, None)`. Actual: 503 on the expired token, blocking the local fallback.

## Fix direction

Add the same USE_LOCAL_OLLAMA truthiness test (same dotenv_values(ENV_FILE) + os.environ merge) before the token check, ideally via one shared helper
used by both `build_model` and the preflight. Note the override is documented as temporary dev-only code.

## Analysis (analyzer, 2026-10-09)

**Confidence.** The cause and the fix location are CONFIRMED by source read and by offline probes: no browser, no run, no write, no model call. The effect on the HTTP
launch is the same function and was not re-driven. INFERRED items are marked where they occur.

### Root cause (CONFIRMED)

`preflight_check_provider` is a hand-written, partial copy of the provider chain that `build_model` runs. Its only mirrored rung is `ANTHROPIC_API_KEY`
(`backend/app/agents/model_factory.py:114-118`, comment "Mirrors build_model()'s own precedence"). `build_model` actually selects in this order:

| rung | `build_model` | preflight |
|---|---|---|
| 1 | `USE_LOCAL_OLLAMA` truthy -> `ChatOllama` (`:323-374`; flag read from `{**dotenv_values(ENV_FILE), **os.environ}` at `:335`) | missing (this bug) |
| 2 | `provider="mistral"` argument (`:383`) | n/a, the eval harness is its only caller (`config.py:9-12`) |
| 3 | `ANTHROPIC_API_KEY` -> `ChatAnthropic` (`:413`) | mirrored (`:117-118`) |
| 4 | Bedrock when a model or profile id and `AWS_REGION` are set (`:457-460`, `:482-533`) | the expiry check itself (`:119-135`) |
| 5 | Mistral fallback when Bedrock is not configured and `MISTRAL_API_KEY` is set (`:461-476`) | missing ([ISS-1135](20261009-0258-ISS-1135.md)) |
| 6 | `ModelConfigurationError` (`:477-481`) | n/a |

The single production caller, `_launch_run_core` (`backend/app/api/run_commands.py:2960-2968`), turns the preflight's `(False, message)` into
`_reject("model_provider_unavailable", ..., 503)` before any run row is minted.

Line references in the sections above were written from a quick read and sit a few lines off: the `ANTHROPIC_API_KEY` early return is `:117-118` (its comment is `:114-116`),
the `ChatOllama` return is `:367-373`, and `:413` is the Anthropic branch.

### Reproduction, extended (CONFIRMED, offline)

`evidence/qa-kb-107/analysis-02-preflight-vs-build_model-matrix.txt` runs seven provider configs with an expired token through both the preflight and `build_model`
(constructors replaced by recorders, so nothing is built and nothing leaves the process). Rows 1, 5 and 7 DIVERGE: the preflight refuses where `build_model` would build
`ChatOllama`, `ChatMistralAI` and `ChatOllama`. Row 4 shows why this hides in many setups: with `ANTHROPIC_API_KEY` set, the Anthropic early return masks the missing
Ollama rung.

### Live state on this machine (CONFIRMED for the function against the file, INFERRED for the running process)

`evidence/qa-kb-107/analysis-01-live-config.txt`: `backend/.env:47` sets `USE_LOCAL_OLLAMA=1` (in the file only, not in `os.environ`, and `settings` has no such field),
`ANTHROPIC_API_KEY` is empty, and the bearer token in the same file expired `2026-10-08T23:40:28Z`. `preflight_check_provider()` read against that config returns
`(False, 'Bedrock bearer token expired at 2026-10-08T23:40Z ...')`. A backend started from this file therefore refuses EVERY launch, for every workflow, until the token
is blanked or rotated, the key rung is set, or this is fixed. Any other bug's reproduction that needs a run on this backend will hit it. The token value was never printed.

### Blast radius

- One call site of the preflight: `run_commands.py:2962`, inside `_launch_run_core` (def `:2888`). The core has two callers: `launch_run` (`:3866`, every POST /api/runs) and
  `run_trigger_workflow` (`backend/agents/execution_engine/kernel_services.py:1669-1671`, the cross-workflow launch of a conditional gate). INFERRED for the second door:
  `engine.py:7186` awaits it with no local try/except, so a preflight `HTTPException` escapes inside the dispatch loop (an outer handler was not traced). It only
  matters when the token lapses mid-run, since the parent's own launch passed the same check.
- Frontend: nothing handles the code (`model_provider_unavailable` appears only at `run_commands.py:2965` and in one integration test). On the canvas Run once path the 503 is
  swallowed ([ISS-969](20261002-0338-ISS-969.md), validated with a stubbed `model_provider_unavailable` 503 under `QA-KB-106`: no message, Run once stays disabled), which is
  why `SMOKE-2` needed a function-level probe.
- Cosmetic: the startup banner (`backend/app/main.py:96-114`) announces `bedrock-bearer-token` while the override is on. A fourth copy of the chain that only logs; not filed.
- Not a sibling: the preflight is launch-only. Any path that does not go through `_launch_run_core` (revision mint, resume) never calls it, so the A4 early-fail does
  not cover it. That is a coverage gap in the design of [FIX-548](20260904-FIX-548.md), not something this root cause implies, and it should not ride along with this fix.

### Where the fix belongs (INFERRED, not applied)

In `model_factory.py` only, so every caller routes through it and no caller changes:

1. Pull the flag test (`:335-341`) into one helper used by `build_model` and by `preflight_check_provider`, which returns `(True, None)` first when it is on.
2. Pull `bedrock_configured` (`:457-460`) into a helper too, so the preflight can mirror rung 5 ([ISS-1135](20261009-0258-ISS-1135.md)).

Traps for a naive fix. None breaks an import-linter contract, SC-001 or INV-1; each breaks the behaviour:

- `os.getenv("USE_LOCAL_OLLAMA")` alone never sees the value on this machine, which lives only in `backend/.env`. That is the trap the comment at `:326-328` describes.
- A new `Settings` field is read once at import and goes stale against `build_model`'s per-call read, so a flip in `.env` would be honoured by one and not the other.
- A guard in `_launch_run_core` or `launch_run` leaves the shared function wrong and duplicates the override reading in the API layer.
- Skipping "whenever Bedrock is unconfigured" would flip the existing expired-token tests, which run with blank ids and no Mistral key ([ISS-1135](20261009-0258-ISS-1135.md)).

### The report's premise is only partly true (INFERRED)

The register says that with the override on "the run never touches Bedrock". `SmartPlanner` builds its own client and ignores the flag, and 14 of the 39 built-in workflows
run it ([ISS-1134](20261009-0258-ISS-1134.md)). The fix here is still right and sufficient for the launch: an expired token degrades the planner to its canned default
context (`backend/agents/planner/smart_planner.py:560-562`) and does not fail the run. It does mean the override is not airtight until that card is handled.

### Test notes (for the test-writer)

- Seam: `preflight_check_provider()` is pure and offline. Add to `TestPreflightCheckProvider` (`backend/tests/unit/app/test_model_factory.py:364`), reusing
  `_make_bearer_token` (`:322`) and the autouse `_clear_provider_settings` (`:61-74`).
- Failing test A: expired token (`issued = now - 2h`, `expires = 60`) and `monkeypatch.setenv("USE_LOCAL_OLLAMA", "1")` -> expect `(True, None)`. Today it is
  `(False, 'Bedrock bearer token expired ...')`.
- Failing test B, the real assertion: the flag only in the FILE, as on this machine. `monkeypatch.delenv("USE_LOCAL_OLLAMA", raising=False)` and
  `monkeypatch.setattr("app.core.config.ENV_FILE", tmp_path / ".env")` with `USE_LOCAL_OLLAMA=1` written to that file. `build_model` imports `ENV_FILE` at call time
  (`:333`), and the shared helper must keep doing so or this patch target stops working. An `os.getenv`-only fix passes A and fails B.
- Control C: `setenv("USE_LOCAL_OLLAMA", "0")` with the same expired token must still return `(False, ...)`, so a guard that skips unconditionally cannot pass.
  Parametrize the truthy spellings `1`, `true`, `yes`, `on` and a falsy one (`0`, `off`, empty).
- Pin the existing refusal tests or they flip on this checkout once the fix lands: the two in `TestPreflightCheckProvider` (`:397`, `:412`) and
  `tests/integration/api/test_rest_run_launch_api.py::test_expired_bedrock_token_rejected_pre_mint` (`:289`). On this checkout 31 offline tests are already red from the same
  read ([ISS-1136](20261009-0258-ISS-1136.md)); expect them until the flag is pinned, and do not read them as regressions.
- Do not start a run to verify. The function and the 503 mapping (`run_commands.py:2962-2968`) are the whole decision.
