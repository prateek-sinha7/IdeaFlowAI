## Symptom

On the dev server (not locally), the `prototype` workflow's `prototype-specify` step
ended with `agent_error` carrying `unresolvable step skill id: velocity-design`. It had
worked before: no launchable manifest declared `skills:` on `dev` until `9efb704d`
(#10, 2026-09-23) brought `skills: [velocity-design]` onto that step.

## Root cause

- `backend/agents/factory.py::_resolve_step_skills` looks every `ctx.step_skills` id up
  in `list_global_skills()` and asserts it is present.
- `backend/app/agents/skills_catalog.py` hardcoded the catalog root as
  `Path(__file__).parents[2] / "skills" / "global"`. In the image that is
  `/app/skills/global`.
- `/app/skills` is the per-user EBS bind-mount (`docker-compose.yml`), created empty by
  the deploy scripts. The image never contained the catalog anyway: the Dockerfile skipped
  `skills/` and `.dockerignore` excluded it.
- So `list_global_skills()` logged "Skills catalog directory not found" and cached `[]`
  for the life of the process, and every manifest skill id failed the assert.
- Same empty catalog, other symptoms (inferred from code, not from logs): empty Library
  Skills tab, 422 "Unknown skill ids" when saving a custom agent with a skill, and
  composer-selected skills hitting the same assert.

## Change

- `app/core/config.py`: new `GLOBAL_SKILLS_ROOT: str = ""` with a never-raising
  whitespace-stripping validator.
- `app/agents/skills_catalog.py`: `_resolve_global_skill_dir()` picks
  `settings.GLOBAL_SKILLS_ROOT` when it is a directory, otherwise the checkout default,
  once at import. The existing not-found warning is unchanged. `skill_source_dir`
  (FIX-431's sibling copy) follows the same root. Still folder-scan only, so a new skill
  folder ships with no code change.
- `backend/Dockerfile`: `ENV GLOBAL_SKILLS_ROOT=/app/builtin-skills/global`, and after the
  `chown` layer, without `--chown` (root-owned, read-only to uid 10001):
  `COPY skills/global/ ./builtin-skills/global/`, `COPY hooks/global/ ./hooks/global/`,
  `COPY pptx/ ./pptx/`. A `RUN` guard fails the build if any of those trees, or the
  OpenDesign audit script and fonts under `$OD_ROOT`, is missing.
- `backend/.dockerignore`: `!skills/global` + `!skills/global/**` after `skills/`;
  `pptx/` no longer excluded; a context-wide secret block added as the last rules.
- Same image-packaging class, fixed in the same pass:
  - `app/agents/tools/pptx_tools.py`: the audit scripts and fonts now resolve through the
    new `od_loader.od_root()`. `Path(__file__).parents[4]` was `/` in the image, so
    `render_pptx`'s gate could never pass there.
  - `app/agents/skills.py`: `pptx/skill.md` → `pptx/SKILL.md`. The lowercase name only
    resolved on case-insensitive filesystems.
- Ported verbatim from `origin/fix/testcases` (`2fbe0d9e`, `f1abf0a6`):
  - the `velocity-design` description, shortened from 352 to 154 chars under the hygiene
    limit of 200;
  - the disk-skill block in `factory._compose_system_prompt`, which `9efb704d` had
    dropped;
  - the `test_skill_prompt_baseline` default-policy pin, plus the `test_skills_hooks`,
    `test_guardrails` and `test_phase7_seam2_removal` repairs;
  - exactly two goldens (`prompt_text_only_no_skills.txt`, `prompt_disk_skill_only.txt`),
    copied byte-for-byte, not regenerated. The user approved this INV-3 exception.
- Untouched: the manifest `skills:` line, the fatal assert, everything under
  `agents/execution_engine/`, per-user `/app/skills`, every other golden.
