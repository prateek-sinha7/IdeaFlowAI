# ISS-1074

## Description

**INFERRED sibling of [ISS-745](20260922-1400-ISS-745.md) (register bug QA-KB-055). Derived from reading the same
handler; not reproduced in a browser (the analysis was static, no run was launched).**

`frontend/src/app/[...view]/page.tsx:1688-1731`, inside the same `pipeline_complete` branch ISS-745 analyses, writes the
completing run's deliverable into four page-level content slots:

```tsx
const finalOutput = data.final_output as string;
const pipelineType = data.pipeline_type as string;

if (finalOutput && pipelineType) {
  if (pipelineType === "user_stories" || ... || pipelineType === "app_builder_revision") {
    setUserStoryContent(finalOutput);
  } else if (pipelineType === "ppt" || pipelineType === "ppt_v2" || pipelineType === "ppt_revision") {
    setPptContent(finalOutput);
  } else if (pipelineType === "prototype" || ... || pipelineType === "prototype_v2_feature_revision") {
    setPrototypeContent(finalOutput);
  } else {
    setGenericDeliverable({ mimetype: ..., filename: ..., content: finalOutput });
  }
}
```

Nothing in that block reads `isForeignCompletion` (defined at `:1605-1608`) or any lineage check.
[BUG-011](20260803-BUG-011-sse.md) run-scoped only the `setContentSourceRunId` call (`:1629`); the comment at
`:1507-1510` records that this handler "intentionally saves content for ALL tab-local completions".

These slots are the on-screen body, not a cache:

- `DashboardLayout.tsx:3398-3401` hands `userStoryContent` / `pptContent` / `prototypeContent` / `genericDeliverable`
  straight to `PreviewPanel`.
- `PreviewPanel.tsx:1106-1108` renders them whenever no older version is pinned
  (`overrideActive = viewingVersion != null`, `:1100`): `effPptContent = overrideActive && renderType === "ppt" ? overrideContent : pptContent`.
- `handleSelectWorkflowRun` clears and refills the same four slots when a run is reopened
  (`page.tsx:2943-2946`, `:3265-3275`), so for a reopened run they ARE its body.

## Why the root cause implies this

ISS-745's root cause is that this handler treats "this tab received a completion" as "this belongs on the screen", with
a name-suffix test standing in for run identity. The id hijack at `:1629` is one write made under that missing check;
the four content writes at `:1688-1731` are four more made under the same missing check, and a change to
`isRevisionCompletion` / the OR at `:1629` does not reach them.

So after ISS-745 is fixed, a foreign-family revision completion leaves `contentSourceRunId` and `runFamily` on the run
being viewed (family B) but still replaces B's Preview body with A's deliverable: the version chip, header and tab
routes say B while the body is A's. That is arguably worse than the hijack, because nothing on screen signals the
mismatch. The same applies to a foreign completion that is NOT a revision (a plain run launched earlier in this tab
finishing while another run is open), which the ISS-745 predicate never covered.

## Conditions

An unpinned (Latest) view of run B, a completed run reopened from History or a deep link; a run A launched by this tab
(`tab_launched_run_ids`) whose result type maps to the same slot as B's renderType completes while B is on screen.
A pinned older version is immune (`overrideActive`).

## Expected vs actual

Expected: a completion that is not the viewed run, and not in the viewed run's family, leaves the on-screen body alone;
its deliverable is reachable by reopening it from History (the comment at `:1507-1510` already says so).
Actual: the body is replaced by A's `final_output`.

## What would settle it (INFERRED until then)

Either a browser check (open a completed prototype B unpinned, let a prototype or `prototype_revision` launched earlier
in the same tab complete, watch the Preview body change with the URL still on B) or a test that drives the handler's
content routing with two run ids. `page.tsx` cannot be mounted in vitest (see `page.iss856.test.tsx`), so the testable
form is to move the routing decision into a pure function next to `isForeignRunFrame` in
`frontend/src/lib/wsReplayState.ts` and unit-test it. No existing test pins this block: `setPptContent`,
`setPrototypeContent`, `setUserStoryContent` and `setGenericDeliverable` appear in no `*.test.*` file.

## Fix direction (not applied, issue only)

Gate the `:1688-1731` block on the SAME decision ISS-745 introduces for `:1625` and `:1629` (one shared predicate, three
call sites), keeping the launch-to-watch path byte-identical (`!isForeignCompletion` stays true for the tracked run).
Do not gate it on `isForeignFrame`: that only asks whether this tab launched the run, which is true for every run in
this scenario ([FIX-708](20261002-0144-FIX-708.md) hit the same trap in the terminal block).

## Traceability

`setPptContent`, `setUserStoryContent`, `setPrototypeContent`, `setGenericDeliverable`, `pptContent`, `final_output` and

## Resolved by FIX-752 (2026-10-07)

[FIX-752](20261007-2214-FIX-752.md) gates the four slot writes on the same `applyCompletion(sameFamily)` decision as
ISS-745's two call sites: `if (finalOutput && pipelineType && (!isForeignCompletion || sameFamily))`. The own-run
path is unchanged. Any foreign completion (revision or not) that is not in the viewed family now leaves the body
alone. The KAN-125 comment that said the handler saves content for ALL tab-local completions was corrected. The
`foreignRevisionHijack.qaKb055.source.test.ts` ISS-1074 case passes.
