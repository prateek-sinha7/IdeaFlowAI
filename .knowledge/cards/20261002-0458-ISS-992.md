## Origin

Sibling of [ISS-678](20260917-1449-ISS-678.md), derived during the analysis of register entry
**QA-KB-064** (`LEDGER.md`). It records two things the root fix has to respect. Status: the
sandbox-level behaviour is **CONFIRMED** in-process (temp dirs); the chain-admission entry points
that reach it were read but **not executed**, so the user-facing effect there is **INFERRED**.

## Condition

A chain launch (`source_workflow_run_id` set) or an in-run chain-context provider opens the source
run's sandbox through `ReadOnlySandbox`, and that sandbox has been swept (no directory) or is a
pre-v2 legacy run that never had a `.git`.

## Part 1 — the read-only handle is not read-only

- **Expected** (`ReadOnlySandbox` docstring, `sandbox.py:1720-1730`, and the comment at
  `:1751-1753`): "no `ensure()` ... without any risk of mutating it ... it must already exist".
- **Actual:** its inner `RunSandbox` is built with the default `has_git=True` (`:1754-1758`), so
  `list_prefix` (`sandbox.py:1163-1170`), `list_tags` (`:934-936`) and `resolve_ref_commit`
  (`:1836-1838`) all pass the `has_git` gate into `_ws()`, which calls `ensure()` (`:634`) and
  `mkdir`s the root. Only `read()` is safe, because it checks `path_for(...).is_file()` first
  (`:738-741`).

Probe, 2026-10-02 (`backend/.venv/bin/python`, temp `RUNS_ROOT`, root absent beforehand):

```
ReadOnlySandbox.list_prefix() on missing root -> result=[]   root_existed_before=False root_exists_after=True
ReadOnlySandbox.resolve_ref_commit() ...      -> result=None root_existed_before=False root_exists_after=True
ReadOnlySandbox.list_tags() ...               -> result=[]   root_existed_before=False root_exists_after=True
ReadOnlySandbox.read()  -> root_exists_after= False
```

Entry points (read, not run): pre-mint admission `_open_source_sandbox_or_refuse`
(`run_commands.py:5131-5171`) then `select_legacy_payload` (`sandbox.py:2196`,
`src.list_prefix(base)`) or `_select_v2_payload` (`run_commands.py:4981-4987`,
`src.resolve_ref_commit`); in-run `KernelServices.open_source_sandbox`
(`kernel_services.py:1829-1890`) and `list_chain_source_files` (`:1804`). The admission result is the
same either way, `ChainRefused("source_payload_missing")`, so the visible effect is the side effect:
the **source** run's workspace goes from expired to empty, exactly as in
[ISS-996](20261002-0500-ISS-996.md), and `.latest` is re-pointed.

## Part 2 — the trap: do not derive has_git here

The natural root fix, "derive `has_git` from `.git`", must **not** be applied to
`ReadOnlySandbox`:

- `RunSandbox.list_prefix` is gated on `has_git` (`sandbox.py:1169-1170`) although
  `LocalWorkspace.list_prefix` is a plain `os.walk` that needs no git (`local.py:1392-1397`:
  "Uses `os.walk` — does not require git").
- Legacy (pre-v2) chain sources keep their payload under `.chain/{run_id}/` and mostly have **no**
  `.git`. They are read through exactly that call: `select_legacy_payload`
  (`sandbox.py:2119-2243`, the `list_prefix` call at `:2196`).
- Probe on a real no-`.git` legacy source (a `.chain/<run_id>/` directory with `summary.md`, the
  logs file and the output):

```
ReadOnlySandbox inner has_git (default): True
list_prefix with default flag      -> [3 paths]
select_legacy_payload default flag -> FOUND
list_prefix with has_git=False     -> []
select_legacy_payload has_git=False-> None (None => ChainRefused('source_payload_missing'))
```

So the default `has_git=True` is load-bearing here. A fix that derives the flag at
`ReadOnlySandbox` turns every legacy chain admission into `source_payload_missing`.

**No test would catch it.** No test constructs a real `ReadOnlySandbox`; they build `MagicMock` or
hand-made shims (`backend/tests/agents/test_chain_exact_ref.py:369-374`, `test_rollback_safety.py`).

## Fix direction

Give `ReadOnlySandbox` an explicit missing-root guard (`if not self.root.is_dir(): return []` /
`None` in `list_prefix`, `list_tags`, `resolve_ref_commit` and the `*_at_ref` readers) instead of
reusing the flag, and/or take the `has_git` gate off `RunSandbox.list_prefix` first since it needs no
git. Write the real-disk legacy test (the probe above, as a test) **before** changing the flag
anywhere near `ReadOnlySandbox`.

## Update — 2026-10-07 ([FIX-727](20261007-1837-FIX-727.md))

Still open.

- **What changed.** `RunSandbox.list_tags` now returns `[]` before `_ws()` when the root has no `.git`
  (`sandbox.py:938`). `ReadOnlySandbox.list_tags` delegates to it (`sandbox.py:1817-1822`), so Part 1's `list_tags`
  path no longer re-creates a missing source root.
- **What did not.** `ReadOnlySandbox.list_prefix` (`:1791`, through `RunSandbox.list_prefix` `:1167`) and
  `ReadOnlySandbox.resolve_ref_commit` (`:1824`) still re-create it.
- **Part 2's trap still holds.** The `has_git` flag was not touched, so legacy `list_prefix` reads are unchanged.
