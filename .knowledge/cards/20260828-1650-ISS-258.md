## Reproduction (3/3, cold start each time)

1. Sign in as qa-admin, fresh navigate to `http://localhost:3000/create/ex_A2_branch`
   ("Branch by Language"). Confirm the launch panel reads "Advanced 5 agents" and the canvas
   has no divert node.
2. Click "Advanced 5 agents" to open "Advanced Workflow Configuration — Language Branch".
3. Click the "Pick Language" node's "Route 3 outcomes" pill (Config tab, conditional-gate route
   editor with `english`/`spanish`/`dutch` outcomes, each defaulting to Type "Step").
4. For the `english` outcome, change Type to "Workflow", click "Pick a workflow…", select
   "Spanish Greeter", confirm with "Pick workflow". A new "Spanish Greeter — Diverts run" node
   appears on the canvas.
5. Click the modal's own "Cancel" button.
6. Reopen "Advanced" (launch panel still reads "5 agents", unchanged). The canvas still shows
   the "Spanish Greeter — Diverts run" node, and the `english` outcome's Type/Target are still
   "Workflow" / "Spanish Greeter".

Reproduced identically on cycle 1, 2 and 3, each from a fresh `/create/ex_A2_branch` navigation
(not a soft re-click) — CONFIRMED, deterministic. `browser_network_requests` showed only
background `GET`s throughout every cycle's edit/Cancel/reopen sequence (`/api/workflows`,
`/api/workflows/ex_A2_branch`, `/api/agents/library`, etc.) — no `POST`/`PUT`/`PATCH` ever
fires, confirming this is un-discarded client state, not a silent server save. A full page
reload (fresh navigation, not modal close) correctly resets the panel to 5 agents / no divert
node, isolating the defect to the modal's Cancel handler.

## Root cause

`frontend/src/components/workflow/AgentsPopup.tsx:2238-2247`:

```tsx
const handleSelectionsChange = useCallback(
  (next: SelectionsMap) => {
    setLiveSelections(next);
    onSelectionsChange?.(next);
  },
  [onSelectionsChange],
);
```

This fires on every route-editor edit inside the modal (Type/Target changes propagate up
through the same `onSelectionsChange` prop chain used for gates/validators/model overrides).
`onSelectionsChange` is wired from `frontend/src/components/workflow/IdeaInputPage.tsx:1915`
straight to `handleSelectionsChange` (`IdeaInputPage.tsx:937-942`):

```tsx
const handleSelectionsChange = useCallback(
  (selections) => {
    selectionsRef.current = selections;
    ...
```

So the parent's `selectionsRef.current` — the ref the canvas reads for node rendering — is
mutated **live, as the user edits inside the modal**, not staged in a local draft. The modal's
Cancel button (`AgentsPopup.tsx:2493`, `onClick={onClose}`) is wired from
`IdeaInputPage.tsx:1882` to `onClose={() => setShowAgents(false)}` — it only toggles the
modal's own visibility. Neither `onClose` nor anything in the Cancel handler restores
`selectionsRef.current` (or `liveSelections`) to the snapshot that existed when the modal was
opened, so an edit made and never explicitly saved via "Save workflow" persists in the parent's
ref, and the canvas keeps rendering the divert node from it on reopen.

This is the same class of bug ISS-225/ISS-251 found in `selectionsRef` (a ref only ever mutated
by live edits, never seeded/reset from a known-good baseline) but a different trigger and a
different symptom: those are about `selectionsRef` starting **empty** and 422ing on Save; this
is about `selectionsRef` never being **rolled back** to its pre-open value on Cancel.

## Expected vs actual

Expected: clicking "Cancel" discards any edits made during that modal session (the `english`
outcome's Type/Target change and the resulting canvas divert node), returning the canvas and
Config panel to the state they had when the modal opened — the documented alternative to "Save
workflow".

Actual: "Cancel" closes the modal but the live-propagated `selectionsRef.current` mutation
from step 4 is never reverted, so the change and its extra canvas node persist across repeated
close/reopen cycles in the same page session, with nothing ever sent to the backend.

## Fix sketch (not applied — this card is an issue, not a fix)

Stage route/selection edits in modal-local state and only propagate to
`IdeaInputPage.selectionsRef` on "Save workflow", OR snapshot `selectionsRef.current` on open
and restore it explicitly in the Cancel handler before calling `onClose`.
