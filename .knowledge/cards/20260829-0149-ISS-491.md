## Sibling of ISS-326 — INFERRED, not yet reproduced in the browser

[ISS-326](20260828-ISS-326.md) established the root cause for `BUG-20260827-221400-dashboard`:
`WorkflowDialog.tsx` declares `role="dialog" aria-modal="true"` (lines 134-135) with zero
Escape/keydown handling anywhere in the file. Filed while grepping every `role="dialog"`
element under `frontend/src/components/workflow/` (the same module `WorkflowDialog.tsx`
belongs to) for the same gap.

`AgentCapabilitiesModal` (`frontend/src/components/workflow/AgentsPopup.tsx`, exported at
line 485) renders its panel with `role="dialog"` / `aria-modal="true"` at lines 615-616, a
backdrop `onClick={onClose}` at line 611, and a Close `<button onClick={onClose}>` at line
642 — the identical copy-pasted shell shape as `WorkflowDialog.tsx`. A whole-file grep for
`Escape`, `keydown`, `KeyboardEvent` and `addEventListener` returns exactly one hit
(`document.addEventListener("mousedown", ...)` at line 1704, an unrelated outside-click
handler) and zero for anything keyboard-related. There is no Escape/dismiss listener
anywhere in the file.

This is exactly the component [ISS-272](20260828-1852-ISS-272.md) named and explicitly
scoped OUT as "a separate investigation with a much larger blast radius": `AgentCapabilitiesModal`
is this module's shared agent-detail chrome, mounted from `LaunchWizard.tsx` (advanced agent
composer), `composer/ComposerPage.tsx` (via `AgentRow.tsx`/`CanvasConfigRail.tsx`'s "Configure"
action), `library/LibraryPage.tsx` (the agent detail drawer) and `AgentLibrary.tsx` (the
"Add agent" picker) — a much wider blast radius than `WorkflowDialog.tsx`'s single dashboard
call site.

## Expected vs actual

- **Expected:** pressing Escape while `AgentCapabilitiesModal` is open closes it, matching the
  `role="dialog"`/`aria-modal="true"` semantics already declared on the element (and matching
  the fix already shipped for the same pattern in `LibraryPage.tsx`'s two detail modals,
  [FIX-333](20260828-2131-FIX-333.md)).
- **Actual:** no code path calls `onClose` on Escape anywhere in `AgentsPopup.tsx` — only the
  backdrop click and the explicit Close button dismiss the modal.

## Why this is INFERRED, not CONFIRMED

The missing handler is confirmed by reading the component's source in full and grepping the
whole file for every keyboard-related token — there is no Escape-handling code to find. What
is NOT yet verified is a live-browser repro: open `AgentCapabilitiesModal` from any of its four
mount points, focus the dialog, press Escape, and confirm it stays open (mirroring ISS-326's
own 3-cycle reproduction on `WorkflowDialog`).

## Evidence

Source-only at filing time — no screenshots. Confirm via:
`frontend/src/components/workflow/AgentsPopup.tsx:605-616` (dialog shell + role/aria-modal),

and the file-wide grep for `Escape|keydown|KeyboardEvent|addEventListener` (one unrelated
`mousedown` hit at line 1704, nothing else).
