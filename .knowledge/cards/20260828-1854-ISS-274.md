## Reproduction (3/3, cycle 1)

Confirmed on all three cold-start attempts (fresh navigation to `/dashboard` then to the target
route, no soft re-click):

1. Sign in as `qa-admin`, cold-navigate to
   `/workflows/656ca387-e69c-474d-b7ff-5fd9eb017cc0/edit` (loads into Canvas view by default —
   "My prototype", 2 agents: Documentation Agent, Spec Writer Agent).
2. Click the "Simple" toggle button to switch views.
3. Both agent cards render an identical `Overrides` row —
   `Validator Gate Retry Skills Configure →` — confirmed via DOM read of both
   `button:contains("Configure →")` parents' `textContent`. No "Tools" pill exists in either row.
4. Click "Configure →" on either agent card. The inline "Advanced — <Agent Name>" panel opens
   with the subtitle `Validator · Gate · Model · Retry` (confirmed via regex match on
   `document.body.innerText`) followed by the Skills library. A full-text search of
   `document.body.innerText` for `"Tool grants"`, `"Read files"`, `"Write files"` and
   `"Execute commands"` returns **no match**, on every cycle, for both agents.

Ran three times from a cold start (fresh nav to `/dashboard` → the edit route → re-toggle to
Simple → re-open Configure), varying which agent's panel was opened (Documentation Agent on
cycles 1 and 3, Spec Writer Agent on cycle 2) to rule out a per-agent fluke. Identical
zero-Tools result on all three. No axis needed to be varied to name the trigger — it reproduces
unconditionally, every cold visit, either agent: **CONFIRMED, cycle 1 (and 2, and 3)**.

## Root cause

`frontend/src/components/workflow/composer/AgentRow.tsx` (Simple view's per-agent row) opens
its "Configure →" panel via the shared `AdvancedExpander` component from
`frontend/src/components/workflow/AgentsPopup.tsx` (`AgentRow.tsx:222-229`). `AdvancedExpander`
renders only the Model/Validator/Gate/Retry levers — it has no Tools sub-section anywhere in its
implementation (`grep` for `"Tool grants"`/`"Read files"`/`"Write files"`/`"Execute commands"` in
`AgentsPopup.tsx` returns nothing).

The Tools tab (three real switches: Read files, Write files, Execute commands) exists in exactly
one place in the frontend: `frontend/src/components/workflow/composer/CanvasConfigRail.tsx`,
which backs the Canvas view's per-node config rail. `AgentRow.tsx` never imports or renders
`CanvasConfigRail` — it has its own `Overrides` chip row (`AgentRow.tsx:191-207`) hardcoded to
four chips (`Validator`, `Gate`, `Retry`, `Skills`), with no fifth `Tools` chip and no wiring to
the tool-grant portion of the agent's `StepSelection`.

Net effect: a tool-grant override set in Canvas view (e.g. disabling "Write files" for one
agent) is real, persists correctly in the in-session `SelectionsMap`, and is not lost — but it
is completely invisible and unreachable from Simple view. Simple view's own editing surface for
the same agent, in the same composer session, has no path to view or set it, and gives no
indication that a restriction exists.

## Expected vs actual

- **Expected:** Simple view's "Configure →" panel exposes the same Tools grants Canvas view's
  rail does — consistent with `Overrides` already surfacing Validator/Gate/Retry/Skills as
  editable categories — or, at minimum, the `Overrides` row visibly flags when an agent carries
  a non-default tool-grant restriction set elsewhere in the same session.
- **Actual:** No Tools section anywhere in Simple view's per-agent UI. A Canvas-set restriction
  is silently invisible in Simple view — no pill, no tab, no indicator — even though Simple view
  is otherwise a full editing surface for the same workflow.

## Conditions

Reproduces on **every** cold load, both saved-workflow agents, either agent selected first — no
narrowing was required. Tier not varied (qa-admin only, per dispatch instructions — not a
tier-scoped surface). Theme not varied — the gap is structural (component-level: `AgentRow.tsx`
never imports `CanvasConfigRail`), not a rendering/CSS condition.
