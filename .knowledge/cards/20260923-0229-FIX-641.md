# FIX-641

Filed under **QA-PS-021** (`LEDGER.md` / `BUGS.md#qa-ps-021`). 6-verifier set it
`REOPENED` on 2026-09-23 because
`backend/tests/agents/test_qa_ps_027_placeholder_completion.py` failed 2/4. That file
is the test of [FIX-612](20260922-1838-FIX-612.md), one of this bug's cards. The
verifier blamed the QA-PS-021 changes to the shared completion gate
([FIX-634](20260922-2235-FIX-634.md) / [FIX-639](20260923-0148-FIX-639.md)).
**That attribution is wrong.** No QA-PS-021 code path causes the failure, and no
QA-PS-021 code was changed here.

## What was wrong

Both failures were the same sanity-check precondition, not the tests' real assertion:

- `test_native_prototype_pipeline_placeholder_output_not_marked_completed`
  ([ISS-761](20260922-1424-ISS-761.md)), old line 176
- `test_revision_pipeline_placeholder_output_not_marked_completed`
  ([ISS-762](20260922-1425-ISS-762.md)), old line 216

Each asserted `data["final_output"] == PLACEHOLDER_TEXT`: branch 3 of `single_file`
returns the agent's stream raw. Branch 3 still fires. The failing run's captured log
carries `single_file.py:166 single_file: presentation.html not written by agent —
falling back to streamed output`. What changed is its output.
[FIX-623](20260922-2024-FIX-623.md) (QA-SG-014 / ISS-776, CLOSED, verified live)
routed branch 3 through the declared-format coercion:

```python
# backend/agents/capabilities/deliverables/single_file.py:174-176
return coerce_to_declared_format(
    strip_pre_document_prose(last_streamed), filename
)
```

So a `.html` deliverable now resolves to the placeholder wrapped in an HTML document.
The assertion QA-PS-027 is about still passed. The run published `degraded`, with
`degraded_reason` "matched \"i don't have access\" in 531 characters".

FIX-612's "Known limits" had already said this would happen: QA-SG-014's tests
"require the OPPOSITE resolution: convert the CONTENT to the declared `.html` format".
FIX-623 did exactly that. Its coverage block never ran `test_qa_ps_027`, so the stale
precondition went unnoticed until now.

## Attribution: proven, not assumed

Each run was from `backend/`, on this one test file, with every other working-tree
change active:

The two QA-PS-021 changes not covered by the table cannot reach these tests:

- FIX-639's hunk is in `_handle_revision` (`engine.py:11915`). Its only caller is
  `app/api/run_commands.py:5302`. The offline `_drive` harness never calls it: there
  is no reference in `tests/agents/_scripted_model.py`.
- [FIX-608](20260922-1820-FIX-608.md)'s `tools` overlay in `_apply_selections` only
  acts on composer selections. Neither failing test passes any.

**Two earlier records got this wrong.** They are corrected here, not rewritten in place:

- The REOPEN note says a git-stash of the QA-PS-021 files left "both tests xfail
  cleanly". That stash included this test file. Stashing it restores the committed
  `xfail(strict=True)` markers, so the failures were hidden, not absent.
- [FIX-634](20260922-2235-FIX-634.md)'s coverage block called the same 2 failures
  "PRE-EXISTING … FIX-601 now grants the write tool". The cause is FIX-623, not
  FIX-601. Its proof was also a no-op. It ran `eng.dropped_section_reason = lambda
  *a, **k: None`, but `engine.py:7298-7300` imports `dropped_section_reason` locally
  on every call. Patching the engine module's attribute never reaches the gate. Patch
  `agents.capabilities.deliverables._coverage` instead (row 3 above).

## What changed and why there

One test file: `backend/tests/agents/test_qa_ps_027_placeholder_completion.py`. It
gained one import. The two preconditions (now lines 178 and 221) expect FIX-623's
branch-3 rendering of the placeholder:

```python
assert data.get("final_output", "") == coerce_to_declared_format(
    PLACEHOLDER_TEXT, "prototype.html"   # "presentation.html" in the ISS-762 test
), (...)
```

The assertion messages are unchanged, and so are the real `published_status`
assertions.

- **Why the test changed and not the app.** FIX-623's card states the contract: a
  declared `.html` name must never publish raw text as `text/html`. It was verified
  live on QA-SG-014, run `79d256c6-5e4e-437c-803d-005f4cc03cad`. The precondition was
  written before FIX-623 existed. Pinning the old raw bytes was incidental. Its own
  message states the intent, "branch-3 … fallback is what fired", and that intent is
  kept.
- **Not weakened.** The check is still an exact equality, so it fails if the declared
  file had been written. The tests also still isolate FIX-612's gate. With
  `_placeholder.placeholder_narration_reason = lambda *a, **k: None`, both fail at
  their `published_status` assertion (lines 184 and 227). This was observed.

Not touched:

- every file under `backend/agents/`
- QA-PS-021's own test file
- the QA-PS-027 verifier's earlier removal of this file's xfail markers

Found while here, not fixed: [ISS-860](20260923-0229-ISS-860.md). The ISS-761 fixture
does not model the clean task completion its docstring describes.
