## Reproduction (3/3, cold start each time)

1. Sign in as qa-admin, fresh navigate to `http://localhost:3000/create/ex_A4_human_divert`
   ("Ask a Human, Then Hand Off" from the `/create` catalog).
2. Type any non-empty text into "Brief description" — no other changes; the Advanced modal
   and Review gates panel are never opened or touched.
3. Click "Save as my version".
4. `POST /api/user-workflows` returns 422 every time, with the body:
   `{"detail":"invalid workflow manifest (workflow:My ex_A4_human_divert): step 'custom-agent'
   declares route: but is missing gates: [conditional] — gates: [conditional] is required when
   route: is declared (R-03)"}`, surfaced verbatim as a red inline string under the composer
   footer.

Reproduced on cycle 1, 2 and 3, each from a fresh `/dashboard` -> `/create/ex_A4_human_divert`
navigation with a distinct brief typed each time. Deterministic, not a race — CONFIRMED.

Register entry: `BUG-20260828-051530-create` in `bug-hunter/ledger.md`.

## Conditions

- Tier: qa-admin (not tier-specific — the trigger is "manifest step declares route without the
  user ever touching gate selections", reachable by any account).
- Entry path: catalog card click and deep link both reproduce; the manifest fetch that seeds
  `manifestSelections` runs on mount either way.
- Theme/viewport: not a factor — this is a payload-construction bug, not a render bug.
- Run state: n/a (never reaches Run).

## Root cause

`backend/agents/workflows/ex_A4_human_divert/workflow.yaml` DOES declare the gate correctly —
`pick-language` has `gates: [before-human, conditional]` alongside its `route:` block. The
seeded manifest itself is valid.

The bug is in `frontend/src/components/workflow/IdeaInputPage.tsx`. On mount, the manifest fetch
(`useEffect` around line 995) builds `manifestSelections` from the raw manifest steps' own
`gates` (line 1098-1105: `if (st.gates && st.gates.length > 0) sel[sid] = { gates: [...st.gates] }`).
This is what feeds the canvas render — merged at line 1192-1195 into a `combinedSelections` used
only for display (`manifestSelections ? { ...manifestSelections, ...(cleanSelections ?? {}) } : ...`).

`selectionsRef` (line 936) — the ref that actually gets sent to the backend — is seeded ONLY from
`cleanSelections` at mount and is otherwise mutated only by `handleSelectionsChange` (fired when
the user edits something in the Advanced popup, line 937-942) or by the override-toggle path
(lines 1428-1440). It is never assigned from `manifestSelections`. An unmodified seeded example
therefore has `selectionsRef.current === {}` when "Save as my version" is clicked.

`handleSaveAsOverride` (line 1460) calls:
```js
manifest: buildWorkflowManifest(pipelineAgents, undefined, selectionsRef.current)
```
`pipelineAgents` carries `route:` (sourced from the manifest, correctly), but `selectionsRef.current`
carries no gates for that step — so the manifest this function builds declares `route:` with
`gates: []`, which the backend's R-03 rule rejects. The canvas SHOWS the step as conditional
(because it reads `combinedSelections`, which does have the gate) while the SAVE path reads a
different, unseeded ref — that mismatch is the bug.

This is the same class of gap `FIX-285` fixed for `CanvasView`'s render-time gate lookup
(`selections[id].gates` never populated from a manifest-opened workflow's declared gates) — but
that fix only seeded the state used for rendering (`manifestSelections`/`combinedSelections`), not
`selectionsRef`, which is the value actually serialized into the save payload. Two different reads
of "the current gate selections," only one of the two got seeded.

## Expected vs actual

Expected: an unmodified seeded example whose own manifest already satisfies R-03 should save
successfully as-is, since the user made no gate-related edits.

Actual: `selectionsRef.current` stays empty until the user explicitly touches the Advanced
popup, so `buildWorkflowManifest` emits `gates: []` for `pick-language`, and the backend's own
validation of the SUBMITTED manifest 422s — even though the SOURCE manifest and the on-screen
canvas both already show `gates: [conditional]` for that step.
