## Why this is its own card

[ISS-633](20260831-0115-ISS-633.md) bundled six red tests under one title. Four
shared one real production defect, fixed by
[FIX-432](20260831-1842-FIX-432.md). These two do not: each pins a contract
production intentionally replaced, so no source change can green them without
reverting a shipped feature. This is the shape
[ISS-630](20260831-0115-ISS-630.md) already hit on the same refactor.

## Witness 1 — `test_concierge_proposal_channels.py::TestRevisionDisposal::test_confirmed_revision_mints_and_drives`

```
assert {'target': 'prototype_large_output'} != {'target': 'prototype_output'}
WARNING app.api.run_commands:3597 _classify_revision_tier: parent run parent-1
        has no output — defaulting to large
```

Two stale assumptions in the harness, both pre-refactor:

1. It stubs `app.agents.revision_analyzer.run_analyzer` (its own comment cites
   `run_commands.py:1464`). The Concierge revision path no longer calls it —
   the refactor moved the full analysis into the manifest as step 0 and left a
   one-word tier classifier, `_classify_revision_tier`
   (`app/api/run_commands.py:1449`). The stub binds nothing.
2. Its `_FakeDb.first()` returns `None` (`test_concierge_proposal_channels.py:319`),
   so `_classify_revision_tier`'s parent-output lookup
   (`run_commands.py:3592`) finds no HTML and takes the documented
   "no HTML available — default to large" arm (`run_commands.py:3595`), which
   `_REVISION_TIER_TARGET_MAP` (`run_commands.py:3535`) maps to
   `prototype_large_output`.

`prototype_output` is the PRE-tiering target. Making production emit it again
means deleting the tier classification. The harness needs a `_FakeDb` whose
parent carries `output`, plus a stub on `_classify_revision_tier` instead of
`run_analyzer` — a 4-test-writer rewrite.

## Witness 2 — `test_revision_gating.py::test_declared_revision_with_parent_seeds_after_assert_owns`

```
assert runner.reads == ["prototype.html", "spec.md", "design.md", "tasks.md"]
Left contains one more item: '.uploads/manifest.json'
```

`PreviousRunProvider.load` gained a deliberate parent-uploads seed
(`agents/capabilities/context_providers/previous_run.py:242-278`): it reads
`.uploads/manifest.json` from the parent and copies it plus its `.txt` sidecars
into the child sandbox so `uploaded_files` can surface them. The read is
best-effort and fully guarded (`except Exception: pass`).

The harness's `_RecordingRunner.read_parent_file`
(`test_revision_gating.py:136`) returns `f"content-of-{name}"` for ANY name, so
the manifest probe looks like a real hit and lands in `reads` (and would land in
`writes` too — the assertion on line 193 just fires first). The expectation
predates the feature. The fix is in the harness: either make the fake raise
`FileNotFoundError` for unknown names, or add `.uploads/manifest.json` to both
expected lists.

## Disposition

Back to **4-test-writer**, not 5-fixer. Neither witness has a source-side fix
that is not a feature revert. Both files are otherwise green today
(`test_concierge_proposal_channels.py` 18 passed / 1 xfailed;
`test_revision_gating.py` 6 passed / 1 xfailed), so the xfail markers are holding
them harmless in the meantime.
