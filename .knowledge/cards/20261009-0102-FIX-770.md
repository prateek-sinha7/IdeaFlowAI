## What was wrong

The root cause is on [ISS-1125](20261008-1540-ISS-1125.md) and is not re-derived here. `_drive_resumed_stream`, the one funnel every
resume driver reaches `_execute_impl` through, treated an attempt as failed only when the stream raised: `_terminal_seen` was read only
inside the `except`. The unsatisfiable-DAG exit of `_execute_impl` (`engine.py:5239-5249`) yields one `error` frame and returns before the
first state transition and the main `try/finally`. So the funnel saw a normal end. No `pipeline_failed`, no state change, no live terminal.

## What changed, and why there

One file, `backend/agents/execution_engine/engine.py`, in `_drive_resumed_stream` only:

1. `_stream_error = None` next to `_terminal_seen` (`:16010-16012`).
2. In the stream loop, after the `data` dict is normalised, a generic `error` frame's text is kept:
   `if event.get("type") == "error": _stream_error = data.get("error")` (`:16061-16062`).
3. An `else:` on the funnel's `try` (`:16128-16138`). It runs only when the stream ended without raising, before the `finally`. If no
   terminal was seen, it calls `_fail_resume(run_id, f"Resume failed: {_stream_error or 'the run ended without a terminal event'}",
   live_queue)`. The `except` path is untouched, so an exception is never recorded twice.

Why the funnel. All four drivers (`resume_run` and `_replay_clarify_run`, reached from `_admitted_resume`, `_rearm_gate_run` and
`_drive_user_resume`) go through it, and the restart drivers have no app wrapper that could do this instead. `_fail_resume` already appends
the one durable `pipeline_failed`, moves the state machine to `failed` (which persists `workflow_runs.status`) and pushes the live frame, and
it never raises (`engine.py:15525-15586`). Because the `else` runs before the `finally`, the output persister then reads a tail that ends in
`pipeline_failed`.

The text fallback is never used today: the analyzer read every other exit of `_execute_impl`, and `engine.py:5241` is the engine's only
generic `error` frame. Before editing, the exit list was checked against this tree: the 19 `return` lines are at the same numbers the card
gives. The fallback is there so any future terminal-less return fails visibly instead of silently.

### Where this differs from the card, and why

- **The card's "Risks for the fixer" said to give the empty-stream test fakes a terminal event. Not done.** All of them pass unchanged
  (fix-03): `test_gate_agent_ids_survives_resume.py` (6), `test_run_trace.py` (16), and two more the card did not list in
  `test_cancel_stops_resumed_run_db.py` (`_recording_impl`, 5 passed). Adding a terminal would have meant editing a test assertion, and it
  would have added a new write:
  - `RunTrace.observe` writes every event except chunk and thinking (`run_log.py:180-186`). So in `test_run_trace.py`
    the exact assertion `== ["agent_input", "tool_call", "agent_output"]` would need a fourth entry. That is editing an assertion.
  - In `test_gate_agent_ids_survives_resume.py`, `RUNS_ROOT` is not monkeypatched (`backend/.env:8` `RUNS_ROOT=../runs`). A
    `pipeline_complete` would write a trace file into the developer's runs directory.

  What is left: the guard now runs in those tests. It logs an ERROR, finds no row in the per-process test SQLite, and leaves
  `get_state_machine()` holding `failed` for their fixed ids (`run-1`, `run-x`, `resumed-run-id`). Every test that drives a run to a
  terminal without the app's `forget_run` already leaves the same kind of entry. The later users of those ids that were checked (`test_execution_engine.py`
  builds its own `StateMachine()`, `test_gates.py` uses fake engines) do not read the singleton.

### Choices the card left open

- **Reason text.** `Resume failed: <error frame text>`, the same prefix as the `except` path (`Resume failed: <exc>`). On the user path that
  becomes `.error` through `_reconcile_terminal_status`. On the restart path `.error` is still not written. That is
  [ISS-1126](20261008-1540-ISS-1126.md), untouched here (probe R1: status `failed`, `.error` the previous attempt's text).
- **The exit itself is unchanged.** The analyzer's optional complement (make `engine.py:5239-5249` also yield `pipeline_failed`) would
  change the launch and revision tiers' event contract. Not done. The launch tier already maps the frame ([BUG-CWF-001-custom-workflow](20260803-BUG-CWF-001-custom-workflow.md) D2). The revision driver's
  missing generic-`error` branch (`run_commands.py:5719-5735`, INFERRED on the card) is still open there.
- **Frontend.** No change. The lane's terminal reducer and [FIX-768](20261008-1540-FIX-768.md)'s `DashboardLayout` clear key on `pipeline_failed`, which now arrives
  after the `error` frame (probe U1 live queue: `workflow_validated`, `error`, `pipeline_failed`, sentinel).
- **Invariants kept.** No workflow-name branch in the kernel (SC-001: the new comparison is on the event type). No new import (lint-imports
  output identical to HEAD, fix-04). No migration. One `pipeline_failed` per attempt: guarded by `_terminal_seen`.
