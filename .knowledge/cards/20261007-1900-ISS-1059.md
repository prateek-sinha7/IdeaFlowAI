# ISS-1059

**INFERRED. This comes from a static read. No test or browser run reproduced it.** It was found while fixing QA-KB-066
([FIX-730](20261007-1900-FIX-730.md)). The fix deliberately left it out, because [ISS-1008](20261002-0523-ISS-1008.md)
asked for no load on the live run.

## Condition

A run answers one or more clarify rounds. The page is then reloaded, or the run is reopened, while the run is still
building (`/runs/{id}/steps` cold load, or a History click on a running run).

## What happens (INFERRED)

1. **No rounds while it builds.** After a reopen, `pipelineState.clarifications` is `[]`. `resetPipeline()` restores
   `INITIAL_STATE` (`useWorkflow.ts:133-137`), and no frame handler rebuilds rounds: `questionnaire_complete` only
   clears the form (`page.tsx:2117-2132`). FIX-730's persisted-rounds load is gated on `!isStillRunning`
   (`PreviewPanel.tsx:1229`), so Steps shows no Clarifications card and Files has no `clarifications.md` until the run
   settles.
2. **A partial list after it settles.** This happens only if the user answers another round after the reopen.
   `retainClarifyRound` makes the live list `[that round]`, numbered from 1 by `DashboardLayout.tsx:2134-2147`. Because
   FIX-730 lets non-empty live rounds win, the settled run then shows only that round. The rounds persisted before the
   reopen stay hidden.

Without a second round, the run settles with live rounds `[]`, FIX-730 loads the persisted set, and the card appears.
That is case 1 only.

## Fix direction (not applied)

Either:

- seed the live list from the persisted rounds on reopen (load them once when a reopened run's replay starts and fold
  them into `pipelineState.clarifications`), or
- let the loaded rounds win once a run settles. ClarifyEngine and `ask_user` rounds are both persisted through
  `ClarifyEngine._persist_qa` (`clarify_engine.py:375`, `:1089-1133`; `ask_user` goes through `ClarifyEngine.run`,
  `engine.py:8790-8816`), so for a settled run the persisted list is a superset of the live one, except when that
  persist write failed (it degrades with only a warning, `:1126-1133`).

The second option changes what FIX-730 renders for a run completed in this page mount, so it needs its own test.

## What would settle it

Answer a clarify round on a long-building run, reload `/runs/{id}/steps` while it is still building, and check Steps
for the Clarifications card before and after it completes.
