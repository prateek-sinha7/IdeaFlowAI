# ISS-942

I found this while running the regression neighbours of `page.tsx` for [FIX-699](20261001-2238-FIX-699.md)
(QA-KB-002). FIX-699 does not cause it: the failing assertion reads only `DashboardLayout.tsx`, and both that file and
the test are unchanged vs HEAD `024c03ef8`. I carded it because
[FIX-635](20260922-2335-FIX-635.md) recorded this file as "3 passed" and no card says otherwise, so the next fixer
would otherwise re-derive it.

## Condition

Run `frontend/src/app/[...view]/runTabShallowNav.test.ts` on its own, from `frontend/`, with
`npx vitest --run <file>`.

## Expected

All 3 cases pass. The first case pins [BUG-030](20260826-1403-BUG-030.md): a run tab switch is a shallow
`window.history.pushState`, never `router.push`.

## Actual

It shows `Tests 1 failed | 2 passed (3)`. The failing case is "BUG-030 — run tab switching stays shallow > the tab
handler pushes history directly, never through the router", with `expected 'const handlePreviewPanelTabSelect = u…'
not to contain 'router.push'` at `runTabShallowNav.test.ts:44`.

## Why: the slice's end anchor went stale, not the product

`tabSelectBody()` slices `DashboardLayout.tsx` from `const handlePreviewPanelTabSelect = useCallback(` up to the next
`}, [contentSourceRunId]);` (`runTabShallowNav.test.ts:27-29`). Commit `d027f16bd` (ISS-296, the pin riding along on
the Version menu) changed the handler's deps to `}, [contentSourceRunId, pinnedVersion]);`, so the handler now ends
at `DashboardLayout.tsx:552`. The anchor's next occurrence is `:737`. The slice therefore swallows
`handleOpenLiveRun`, whose `router.push((routeFor[tab] ?? routes.runDetail)(runId))` (`:561`) is a deliberate real
navigation for a still-running family member.

The handler itself still does what BUG-030 asks: `window.history.pushState(null, "", targetRoute)` (`:551`), and no
non-comment `router.push` inside it.

Probe (read-only, `evidence/qa-kb-002/06-runTabShallowNav-stale-anchor-probe.txt`), the same assertion run with each
end anchor:

```
"}, [contentSourceRunId]);"                end at line 737 | pushState: true | router.push: true
"}, [contentSourceRunId, pinnedVersion]);" end at line 552 | pushState: true | router.push: false
```

## Disposition

The fault is in the test, so the fix belongs in the test: end the slice at the handler's own closing. Either use
`}, [contentSourceRunId, pinnedVersion]);`, or end at the first `\n  }, [` after `start` so the next deps change
does not stale it again. Do not change `DashboardLayout.tsx`. Left open: this is outside QA-KB-002's scope, and the
standing rule forbids editing an unrelated test to get green.

Validated (QA-KB-085): 3/3 cold runs of `npx vitest --run 'src/app/[...view]/runTabShallowNav.test.ts'` fail with 1 failed | 2 passed; evidence/qa-kb-085/01..03-validate-attempt*-vitest-output.txt.

## Analysis (QA-KB-085, 2026-10-02)

Confidence: CONFIRMED for the root cause, the timeline, the blast radius and the fix. The one sibling, [ISS-1027](20261002-0703-ISS-1027.md), is INFERRED.

### Correction to the section above: two commits, and a month of green

"Went stale in `d027f16bd`" is true, but that commit did not turn the test red. It left the end anchor pointing at nothing, so the slice
silently grew from the handler's 27 lines to 204, and the test kept passing because nothing in those 204 lines called `router.push`. It went
red on 2026-09-29, when `8cf967b0f` ("open a still-running version live from the Version menu") put `handleOpenLiveRun`, with its deliberate
`router.push`, straight after the handler, inside the already-wide window. Replay of `tabSelectBody()` with its current anchor
`}, [contentSourceRunId]);` (`evidence/qa-kb-085/04-analyze-timeline-and-fix-probe.out.txt`):

| revision | window `DashboardLayout.tsx` | `router.push` in it | test |
|---|---|---|---|
| `d027f16bd^` (2026-08-29) | :471-:498, 27 lines, the handler's own close | no | green |
| `d027f16bd`, `pinnedVersion` joins the deps | :479-:683, 204 lines | no | green, silently wide |

### Root cause

`tabSelectBody()` (`runTabShallowNav.test.ts:26-38`) bounds the handler with `dashboardSource.indexOf("}, [contentSourceRunId]);", start)` (`:29`).
A dependency list is not an identity. That literal closed two hooks in `DashboardLayout.tsx`: the tab handler and the revision-family effect
(`:732-737`). When the handler's deps grew, the only match left after `start` was the effect's close at `:737`, and nothing in the test says the
window must hold exactly one hook. The product is fine: the handler ends in `window.history.pushState(null, "", targetRoute)` at `:551`, and
the window `:516-:551` holds no `router.push`.

### Blast radius

- **Callers of the broken helper:** one. `tabSelectBody()` is called only by case 1 (`runTabShallowNav.test.ts:42`). Cases 2 and 3 read
  `page.tsx` and pass.
- **Product code:** none. `handleOpenLiveRun` (`DashboardLayout.tsx:556-562`) has one caller, `PreviewPanel.tsx` `handleSelectVersion`
  (`:902-903` at HEAD, `:911-912` in the working tree), when the Version menu picks a non-terminal family member. It is a real navigation to a
  different run id, outside BUG-030's "a tab switch" scope. What that navigation does to the tab is a separate open question,
  [ISS-958](20261002-0316-ISS-958.md).
- **Consumers of the verdict:** [BUG-030](20260826-1403-BUG-030.md) still says `verification.status: passed` and "ALL GREEN"; every fix card that runs
  the `page.tsx` / `DashboardLayout.tsx` regression neighbours has had to re-derive "1 red, pre-existing"
  ([FIX-699](20261001-2238-FIX-699.md), [FIX-700](20261001-2242-FIX-700.md)); and while the case is red for the wrong reason, a real regression of
  BUG-030 (`router.push` back in the handler) cannot be told apart from the noise.
- **Same flaw elsewhere:** 7 tests in 6 files end a slice at a dependency list
  (`evidence/qa-kb-085/06-analyze-deps-anchor-census.out.txt`). Five are long lists that occur once, so they fail loudly if their hook's deps
  change. One already has a decoy: [ISS-1027](20261002-0703-ISS-1027.md).

### Fix (test only, one line)

`runTabShallowNav.test.ts:29`: replace `dashboardSource.indexOf("}, [contentSourceRunId]);", start)` with
`dashboardSource.indexOf("\n  }, [", start)`, the first top-level hook close after the handler starts. It names no dependency, so the next deps
change cannot stale it. The literal `}, [contentSourceRunId, pinnedVersion]);` also passes today, but it is the same fragile idea and fails the
next time the list changes.

Verified on copies, repo untouched (`evidence/qa-kb-085/05-analyze-scratch-vitest-ab.out.txt`):

- the repo test as it is: `1 failed | 2 passed` (reproduces);
- with the `\n  }, [` anchor: `3 passed`;
- with `router.push(targetRoute)` injected into the handler: `1 failed`, so the guard still catches the regression it exists for;
- with a new dependency added to the handler: `3 passed`.

The anchor picks the handler's own close at every revision in the table (:471-:497 before the pin, :479-:514 at `d027f16bd`, :516-:551 since), and no
line inside the handler body matches it.

Optional hardening, not needed for green: assert the window holds one hook (for example `slice.match(/\buse(Callback|Effect)\(/g)` has length 1),
so a widening can never again be silent. Do not edit `DashboardLayout.tsx` and do not move `handleOpenLiveRun` to dodge the anchor; that bends the
app to the test.
