## What broke

1. **Only agent 1 ever saw the request.** It was delivered inline to the first
   dispatched agent and written nowhere. In `ex_A2_branch` the `language` router
   is step 2 with `read_files: false`, got an empty prompt, answered
   `{"decision": "english"}` for "Halo, Hoe gaat het?" and routed to "Hello, world!".
2. **The launch wizard both uploads attachments and pastes their text into the brief**
   (`LaunchWizard.tsx`). For `prototype_v2`, whose Reading Planner is meant to open
   `.uploads/manifest.json` and extract each document, the whole corpus sat in its
   prompt next to "Please create prototype" — it wrote the finished prototype in one
   pass and never opened a file.

## Fix

- `write_user_prompt_to_sandbox()` (`launch_context.py`) writes the request to
  `.context/user-prompt.md` before step 1. A chained run's inherited
  `=== CONTEXT FROM PREVIOUS PIPELINE` block is stripped; a revision overwrites the
  file with its own request.
- Right after `compile_for_run`, if any compiled step grants the `file_extract` tool
  set, `strip_inline_attachments()` replaces the `=== Attached: … ===` blocks with a
  list of `.uploads/<name>` paths and rewrites `user-prompt.md`. Other workflows keep
  the inlined text.

## Still open

The wizard still inlines attachment text for every workflow; the backend now
neutralises it only for file_extract workflows. Skipping the inline at the source
would need the wizard to know the compiled tool sets.
