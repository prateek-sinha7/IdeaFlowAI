## What was wrong

This is bug report QA-KB-004. `scan_source_files()` in `tools/knowledge/build_architecture.py` excluded
virtualenvs only when the directory was literally named `.venv` or `venv`. Any version-suffixed
venv (`.venv312`, `.venv-3.13`, `.venv311`) was walked, and its `site-packages` files were assigned
to `MOD-backend`. In the main checkout that put nine pip and langsmith internals into
`modules.json`.

## Root cause

[BUG-129](20260918-BUG-129.md) has the full diagnosis. In short, `PY_EXCLUDE` (`:120-131`) is a set
of literal directory names. It was applied at the old `:159` as
`if PY_EXCLUDE & set(p.relative_to(REPO_ROOT).parts):`. `.venv312` is not a member of the set, so the
intersection was empty and every file under it was kept.

## Change

One file, `tools/knowledge/build_architecture.py`:

- `:134-136` adds the module-level helper `_is_venv(part)`, placed right after `PY_EXCLUDE`. It
  returns true when `part == "venv" or part.startswith(".venv")`.
- `:166-167`: the walk binds `parts = p.relative_to(REPO_ROOT).parts`, then skips the file when
  `PY_EXCLUDE & set(parts) or any(_is_venv(x) for x in parts)`.

`PY_EXCLUDE` is unchanged. Its `.venv`/`venv` entries are now redundant but harmless. `:362`
(`_backend_packages`, `p.name not in PY_EXCLUDE`) is untouched, because BUG-129's analysis ruled
it inert for venvs: it lists only directories that hold an `__init__.py`. The change uses only
the standard library, needs no new import, and is Python 3.9-safe.

## Why there

`scan_source_files()` is the one function every consumer routes through: `main()` (`:1991`),
the `_tracked_files()` fallback (`:1469`) and `tools/knowledge/status.py` `source_files()`
(`:133`, which imports it rather than re-deriving it). One guard in the walk fixes all of them.
This is the fix BUG-129's analysis accepted. It also overruled the optional `:362` edit.

## Regeneration

In this worktree (feat/user-stories-v2) no regeneration was needed. The only venv on disk is
the literal `backend/.venv`, and `--needs-rebuild` reports the map current. `modules.json` and
`MOD-backend.md` were not hand-edited or regenerated. In a checkout that has `backend/.venv312` on
disk (the main checkout, per BUG-129), the next architecture rebuild drops the nine leaked files.

The `source files covered` row of `status.py --json` read STALE (found 935, expected 936) after
the change. The 936th file is the untracked
`frontend/src/components/results/ArtifactVersionPicker.iss869.test.tsx`, which another fixer
wrote at 21:11. A diff of the scan before and after that file appeared shows it as the only
addition. That frontend file is not something this change touched or filters.
