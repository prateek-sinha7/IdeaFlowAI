# ISS-1071

**Evidence status.** The text is CONFIRMED present by grep on 2026-10-07 (QA-KB-094 fixer). That it is stale
comes from [ISS-1046](20261002-1204-ISS-1046.md)'s analysis. Since [ISS-170](20260824-1610-ISS-170.md), a POST-step
conditional block ends the run as `pipeline_failed`. It was left alone because it lies outside the line ranges the
QA-KB-094 cards named, and [FIX-750](20261007-2108-FIX-750.md) was kept to those ranges.

## What is stale

1. **"fell through" in six runners.** ISS-1046 recorded these as out of scope. Each is a one-line text edit,
   plus the comment above it in the A2 files.
   - `run.ex_A2_branch.http:194,197`
   - `run.ex_A2_branch_hola.http:194,197`
   - `run.ex_A2_branch_dutch.http:194,197`
   - `run.ex_A3_divert.http:137`
   - `run.ex_A3_divert_spanish.http:135`
   - `run.ex_A3_divert_dutch.http:134`

   Each prints `✗ conditional gate BLOCKED at … — the run fell through instead of routing`. FIX-750 changed
   the A4 pair to "the run FAILED at the gate instead of routing".
2. **ex_A4 header names, comments only.**
   - `workflow.yaml:9` and the twin's `run.ex_A4_human_gate.http:10-11` still show `gates: [human, conditional]`
     and `PRE human`. The step declares `before-human` (`workflow.yaml:107`), and its own comment
     (`:103-106`) warns that `human` now means a different gate.
   - `workflow.yaml:41` still says `artifact_type human_choice`. The edge is `route_decision`
     (`workflow.yaml:95`, ADR-0026).
   - `workflow.yaml:49-51` says that, after a bare approve, "pick-language then has no real choice to read". The
     gate reads `ask`'s placeholder itself (`condition_agent: ask`), so pick-language plays no part. The outcome
     the comment states, a block with no matching outcome, is still right.

## Disposition

Low severity, developer tooling, no runtime effect: the YAML text is comments, and the manifest's
`yaml.safe_load` is unchanged by any edit to them. The fix is a text-only edit of the lines above. No test covers
this text.
