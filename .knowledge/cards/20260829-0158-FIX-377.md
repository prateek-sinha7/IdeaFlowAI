## What was wrong

`BUG-20260828-055300-create-ex-a2-branch`: on a completely fresh `/create/ex_A4_human_gate` load,
zero interaction, the "Pick Language" step declares `gates: [before-human, conditional]` in its
manifest (`backend/agents/workflows/ex_A4_human_gate/workflow.yaml:99-105`, with `route.condition_agent: ask` at `:111`) and neither UI control
built to expose gate state showed the human-review half. The "Review gates" pill read `no gates`
with all 5 checkboxes unchecked, and the Advanced modal's Config tab for that node rendered `Gate`
as "Conditional gate" only. Reproduced 3/3 by the validator.

## Root cause

Two independent mechanisms, both confirmed to `file:line` by
[ISS-306](20260828-1745-ISS-306.md)'s "Root cause — CONFIRMED" section. Re-checked against the
working tree before editing; both still held.

**Mechanism A — the checklist's seed has no path to a manifest-declared gate.**
`ReviewGatesSection.tsx:52` (`isDefaultGated = a.gate === "Human_Gate"`) plus the `checkedIds`
initializer and its `agentsKey` re-seed effect read ONLY the saved-run `initialGateIds` prop or the
static per-AGENT.md `gate` field. A `custom-agent` step has no AGENT.md, so `AgentDef.gate` is
`null` for all 5 steps of this fixture and the manifest's `gates: [...]` array — its ONLY
declaration of a human-review pause — was never read. The `selections` prop [FIX-346](20260828-2314-FIX-346.md)
threaded in was write-only (`onSelectionsChange` from `toggle`), so the data was already in the
component and simply unused by the seed.

**Mechanism B — the one control that represents `before-human` can never match.**
`CanvasConfigRail.tsx:730-734`'s "Prompt User" toggle requires `route?.condition_agent === prev.id`,
where `prev.id` is the canvas node id `custom-agent:ask`. `normaliseRoute()` mapped
`outcomes[*].target` and `default_next` through `nodeIdOf` but never `condition_agent`, so the
manifest's bare authored value (`ask`, correct per ADR-0017) was compared raw against a normalised
id and never matched. `before-human` is deliberately excluded from the Gate combobox's option set
(`CanvasConfigRail.tsx:227-237`, by design post-ADR-0013), so this toggle was the only surface —
and it was structurally off.

## Blast radius, re-confirmed before editing

- `ReviewGatesSection` has exactly 2 render sites app-wide — `IdeaInputPage.tsx:1933` and
  `LaunchWizard.tsx:1072` — both already passing a live `selections` prop, so the seed fix lands
  once for both callers rather than per page.
- `normaliseRoute` has 2 implementations: the shared `frontend/src/lib/manifestAgents.ts:55-83`
  (used by `LaunchWizard.tsx:415,422,460` and `IdeaInputPage.tsx`'s override branch) and a still-live
  un-migrated duplicate inside `IdeaInputPage.tsx:1100-1117` — the copy that actually runs on this
  bug's repro path. Both were patched; fixing only the shared helper would have left this exact
  route broken.
- `condition_agent` consumers, all checked (`grep -rn "condition_agent" frontend/src`):
  `CanvasConfigRail.tsx` (the toggle, and the "Condition source" input, which now displays the
  normalised form — the same form the toggle itself writes at `:773`,
  `updateRoute({ condition_agent: prev!.id })`), and `store/api/userWorkflows.ts:361`
  (`deriveRouteDecisionProduces`), which resolves dually by `agent_id` AND bare `instance_id`.
  Server side accepts both forms too: `compiler.py:1597-1601` (R-27 `by_name` dual lookup) and
  `engine.py:8406-8425` (exact match, then `":<producer_agent>"` suffix fallback). So a
  round-tripped save carrying the normalised id compiles and runs identically — proven by
  `test_save_manifest_gates.py` below.

## What changed and why there

1. `frontend/src/components/workflow/ReviewGatesSection.tsx` — new module-level
   `HUMAN_REVIEW_GATES = [HUMAN_GATE, "before-human"]` and
   `isSeedGated(agent, selections)` = `isDefaultGated(agent) || selections[agent.id].gates` contains
   a human-review gate. `checkedIds`'s initializer and the `agentsKey` re-seed effect now use it via
   a memoised `seededIds`. A second effect keyed on `seedKey` (the joined `seededIds`) re-applies the
   seed when the declared set changes — required, not belt-and-braces: the workflow fetch resolves
   after mount, and the parent effect that merges `manifestSelections` into `liveSelections`
   (`IdeaInputPage.tsx:1235-1237`) runs AFTER this child's `agentsKey` effect in the same commit, so
   the one-shot seed always missed the gates by one render. That effect returns early when `touched`
   or `initialGateIdsRef.current` is set, and never calls `setTouched`, which is what keeps the seed
   display-only (INV-3) and stops a user's own toggle — which writes `human` into `selections` and so
   moves `seedKey` — from resetting `touched` or fighting the seed. `conditional`/`approval`/`security`
   are excluded so ADR-0013's `human` vs `before-human` split is not silently re-merged into one
   "human review" checkbox.
2. `frontend/src/lib/manifestAgents.ts:70-83` — `normaliseRoute` now returns
   `condition_agent: nodeIdOf.get(r.condition_agent) ?? r.condition_agent`, exactly as it already
   did for `default_next`. Idempotent: an already-composed id is not a key in the map.
3. `frontend/src/components/workflow/IdeaInputPage.tsx:1119-1121` — the same one-line normalisation
   in the un-migrated duplicate, with a comment naming the duplication. Retiring that copy in favour
   of `agentsFromManifest()` is the durable fix ISS-306 flags, but it changes more than this defect
   needs and is left to its own card.

Nothing else changed. No backend file, no test file, no migration.
