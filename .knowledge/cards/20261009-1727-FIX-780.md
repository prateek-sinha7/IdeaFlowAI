## What was wrong

The cause is on the cards and is not re-derived here. `1e329e47b` replaced the hand-rolled projection in `agentsFromManifest` with a
call to the canvas's own converter, but called it without a lookup (`manifestStepsToAgents(raw)`, `manifestAgents.ts:157` at HEAD).
Without one, `manifestStepToAgent` builds a built-in step from the composer's blank-agent literals (`userWorkflows.ts:714-726`):
`name: step.name ?? id` and `estimated_duration: 60`. Built-in steps carry no manifest `name`, and `decorate` restores role, order and
gate from the compiled step but never its name. So every roster built by the seam was labelled by agent id and summed 60 s per row:

- [ISS-1157](20261009-1500-ISS-1157.md): `/create/user-stories` under an enabled override, Review gates rows and Advanced canvas
  nodes read `domain-analyst`, so the e2e waited 30 s for "Domain Discovery Agent" (the reported "times out").
- [ISS-1175](20261009-1653-ISS-1175.md): the LaunchWizard panels (`ppt`, `prototype`, `ppt_v2`) under an enabled override, same ids.
- [ISS-1176](20261009-1653-ISS-1176.md): `ppt_v2` for every user, because its plan wins the merge and `mergePlanWithLibrary`'s
  `step.name || lib.name` never reaches the library for a name that is the non-empty id.
- [ISS-1177](20261009-1653-ISS-1177.md): the Advanced pill read "6 agents · ~6m" (6 x 60 s) where the system roster reads "~35s".

## What changed, and why there

`frontend/src/lib/manifestAgents.ts:157-176`: a `fromCompiled(id)` lookup that finds the step in `detail.steps` (the same
`agent_id` match `decorate` already uses at `:141`) and returns it as an `AgentDef` with `name: c.name || id`, the compiled role,
order and pipeline type, `icon: ""` and `estimated_duration: 0`; `:176` passes it as the converter's existing `lookup` argument:
`manifestStepsToAgents(raw, fromCompiled).map(decorate)`. This is the smallest shape the root card proposes, and it is how every other
caller of the converter already supplies names (`ComposerPage.tsx:318`, `:363`, `:428`, `WorkflowDetailView.tsx:36`,
`workflowCanvasModel.ts:52` pass a library lookup).

Why there: all five callers of the seam route through this one line (re-grepped: `IdeaInputPage.tsx:1215`, `:1780`;
`LaunchWizard.tsx:596`, `:610`, `:649`), so one edit reaches all four cards and no caller changes.

What follows from the shape, by card:

- Names: `manifestStepToAgent` spreads the lookup's row as `base`; an explicit manifest `name` still overwrites it (`:728`), and a
  custom-agent step skips the lookup (`:713`), so `prototype_v2`'s named custom steps are untouched (probe C3 green).
- [ISS-1177](20261009-1653-ISS-1177.md): `estimated_duration: 0` gives the card's accepted "shows no estimate" outcome, which is the
  pre-`1e329e47b` behaviour: `IdeaInputPage.tsx:2240`'s `totalEstimatedTime > 0 &&` hides the ETA, so the pill reads "6 agents".
  Where the plan is merged with the library (`ppt_v2`), `step.estimated_duration || lib.estimated_duration` (`LaunchWizard.tsx:201`)
  now reaches the library because 0 is falsy: observed 8 / 30 / 12 / 25 s.
- Traps the card named, all honoured: `manifestStepToAgent`'s `name: step.name ?? id` default is untouched (the Composer relies on
  it); no workflow or agent id is special-cased (SC-001); no third projection was added and the duplicate at
  `IdeaInputPage.tsx:1286-1312` is left as it is; `mergePlanWithLibrary` was not taught that `name === id` means unnamed; the e2e
  expectation was not edited; the gate sync ([ISS-247](20260828-1637-ISS-247.md)) was not touched.

Not changed: the placeholder icon. `decorate` still sets `icon: a.icon || "\u{1F9E9}"` for these rows, as it did before
`1e329e47b`; [ISS-1177](20261009-1653-ISS-1177.md) scopes it out. The fuller shape in [ISS-1157](20261009-1500-ISS-1157.md)
(forward a library lookup from the five callers, `lookup?.(id) ?? fromCompiled(id)`) is what would give override rows the
library's icon and a real ETA; no card asks for it.
