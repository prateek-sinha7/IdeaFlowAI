## What was wrong
Gap 3 of the workflow-gaps review. The compiler accepted `chain_policy` in `{refuse, degrade}`, and `plan.py` documented
`degrade` as "a missing or swept payload is tolerated". At admission, `run_commands.py::admit_chain_launch` refused
`source_payload_missing` whatever the manifest said (owner decision B5, 2026-09-14, branch deleted). The install path in
`chain_context.py` still read `chain_policy`: if the payload vanished between admission and install, `refuse` failed the
run and `degrade` continued with no context. So a manifest declaring `degrade` was refused in one place and honoured in
another. That is B30 in `specs/019-sandbox-git-versioning/bugs/GIT_VERSIONING_BUGS.md`, open since 2026-09-15. The review
classified the claim REAL but slightly too strong, because the field was inactive only at admission.
## Decision
The user approved the recommended Option A on 2026-11-03 ("go with all recommenedation ans", recorded in
`.agents/tasks/workflow-gaps/decisions.md`): remove `degrade`. This is B30's first remedy and follows B5. No shipped
manifest sets the field (0 of 39), and the Composer never writes it.
## What changed
- `compiler.py`: `_VALID_CHAIN_POLICIES = {"refuse"}` (about `:1766`), comment updated.
- `chain_context.py`: removed the `degrade` branch and the `chain_policy` variable and parameters of `_install_v2`,
  `_install_legacy`, `_emit_chain_context_unavailable` and `_resolve_install_toctou`.
- `plan.py`: the `chain_policy` comment says `refuse` is the only value. The field stays, default `"refuse"`.
- `run_commands.py`: docstrings and comments only (`ChainRefused`, `ChainAdmission`, `select_source_payload`,
  `admit_chain_launch`).
- `docs/workflow-manifest.schema.json` (untracked): enum is `["refuse"]`.
- Tests: new `test_compiler_chain_policy.py` (degrade rejected, bogus rejected, refuse accepted, default refuse).
  `test_phase3_cutover_verify.py` now uses `chain_policy="refuse"` in its fake context. Docstring-only edits in
  `test_phase5_chaining.py` and `test_chain_exact_ref.py`. No test was deleted or renamed; the `degrade` mock tests in
  `test_chain_exact_ref.py` stay and still prove admission ignores the field.
The B30 entry in `GIT_VERSIONING_BUGS.md` was not edited.
