## Symptom

The Model Details panel always showed Claude Haiku 4.5's rates regardless of which
model was selected. Selecting Sonnet 5 or Opus still showed Haiku's `$0.25/$1.25`
rates (the old rates — even Haiku's were wrong: catalog has `$1.00/$5.00`).

## Root cause

1. `backend/app/api/capabilities.py` `ModelCatalogEntry` projection stripped all
   `Pricing` fields — only `id/label/tier/cost_class/provider/context_window/user_allowed`
   were serialised. Frontend had no way to get authoritative rates from the server.
2. `frontend/src/components/analytics/AnalyticsPage.tsx` maintained a `MODEL_META`
   static map with hardcoded rates that were stale and missing 5 catalog entries.
   The fallback `MODEL_META[activeModelId] ?? MODEL_META[DEFAULT_MODEL_ID]` silently
   showed Haiku for any unmapped model.

## Fix

**`backend/app/api/capabilities.py`:**
Added `input_rate_per_1m`, `output_rate_per_1m`, `cache_read_rate_per_1m`,
`cache_write_5m_rate_per_1m` (USD per 1M tokens = `Pricing field × 1_000_000`),
and `thinking_supported: bool` (True for `sonnet-5`/`opus-4`/`opus-5` fragments)
to `ModelCatalogEntry` with `= 0.0`/`= False` defaults (additive).

**`frontend/src/lib/api.ts` and `frontend/src/store/api/capabilities.ts`:**
Added the same 5 fields as optional (`?`) to `CapabilityModelEntry` so existing test
fixtures that don't include them stay type-safe.

**`frontend/src/components/analytics/AnalyticsPage.tsx`:**
- Deleted the `MODEL_META` static const and `DEFAULT_MODEL_ID` constant.
- Added `catalogMap: Record<string, CapabilityModelEntry>` state.
- Added `getCapabilities` fetch `useEffect` that builds the map keyed by model id.
- Replaced all `MODEL_META[x]` lookups with `catalogMap[x]` throughout:
  `modelRows` name, model dropdown labels, Model Details panel rows.
- Added `formatRate()`, `formatContextWindow()`, `shortLabel()` helpers.
- Model Details panel now iterates all models in use with collapsible sections.
