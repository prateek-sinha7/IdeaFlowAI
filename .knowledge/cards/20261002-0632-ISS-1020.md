## Summary

INFERRED sibling of [ISS-915](20261001-2219-ISS-915.md) (QA-KB-082). The JavaScript steps below were replayed in Node against verbatim copies of the quoted lines (the page guard, `buildTree`, `escapeHtml`, `fileMatchesQuery`). The React render itself was not run, so each row is a lead until a jsdom or browser run settles it.

ISS-915 shows that `frontend/src/app/preview-fullscreen/page.tsx:70-71` trusts a bare cast, `JSON.parse(raw) as PreviewPayload`, and a truthiness test, `!data.files?.length`. The three payloads QA-KB-082 reproduced (`{files:'abc'}`, `{files:[null]}`, `{files:[{}]}`) all die in `buildTree` (`frontend/src/components/preview/AppBuilderPreview.tsx:93`, `:96`), which reads only `file.path`. A payload whose files carry a string `path` gets through `buildTree`, and the same unchecked cast then crashes the component at three later sites:

| payload stored under `__app_preview__` | first throw | where | when |
|---|---|---|---|
| `{"files":[{"path":"a.ts"}],"projectName":"x"}` | `file.content.split("\n")` on undefined | `AppBuilderPreview.tsx:295` (CodeViewer render). The effect at `:266-267` also throws, in `escapeHtml(file.content)` (`:176-178`) | the render after the mount effect selects `files[0]` (`:384-387`) |
| `{"files":[{"path":"a.ts","content":5}],"projectName":"x"}` | `5.split is not a function` | `:295` | same |
| `{"files":[{"path":"a.ts","content":"x"}],"projectName":{}}` | React rejects a plain object as a child | `:502` `{projectName}` | first render of the component; `page.tsx:76` has already set the tab title to `[object Object] — IDE Preview` |
| `{"files":[{"path":"a.ts","content":"x"}]}` (no `name`, the shape of the ISS-298 e2e fixture) | `name.toLowerCase()` on undefined | `:119` `fileMatchesQuery`, called from `:371` (the `visibleFiles` memo) and `:230` | the moment the user types in the "Search files..." box |

Node replay output: the path-only file gives `buildTree ok | effect :380 ok | CodeViewer :295 THROWS: Cannot read properties of undefined (reading 'split')`; the `{path, content}` file gives `... escapeHtml :267 ok | search 'x' THROWS (after user types): Cannot read properties of undefined (reading 'toLowerCase')`; a complete `ParsedFile` (`path`, `name`, `ext`, `content`, `language`) passes every step.

## Why the root cause implies it

Same unchecked cast, same narrow guard. The QA-KB-082 triage sketch and the "Where the fix belongs" example in [ISS-915](20261001-2219-ISS-915.md) both check `typeof f?.path === "string"` only. `path` is exactly the one property `buildTree` reads. The other properties the component dereferences without a fallback (`content`, and `name` once a search is typed) and the non-`files` field `projectName` stay unchecked. Applying the sketch literally closes the three reported payloads and leaves every row above crashing.

## Expected / Actual

Expected: any payload the component cannot render and use without throwing takes the same `giveUp()` exit as a missing payload (`page.tsx:57-63`).

Actual (inferred): the four rows pass the guard and throw in or after render, so the app error boundary (`frontend/src/app/error.tsx`) replaces the page.

## Constraint: do not over-tighten

`tests/integration/e2e/suites/07_run_detail/test_iss298_preview_fullscreen_quota_ignores_cache.py:25-30` seeds `{"files":[{"path":"index.html","content":"<h1>hello</h1>"}],"projectName":"Iss298Project"}`, with no `name`, `ext` or `language`, and asserts the tab title `Iss298Project — IDE Preview` at `:47`. By trace that payload renders today (title set at `page.tsx:76`, no throw until a search is typed). A guard that demands all five `ParsedFile` fields would send it to `giveUp()` and flip that title assertion ([ISS-298](20260828-1729-ISS-298.md) owns the test).

So the predicate should require what the component dereferences without a fallback (`path` and `content` as strings), sanitize `projectName` (a string, otherwise leave it undefined so the component default `"Project"` at `AppBuilderPreview.tsx:358` applies), and either default `name` from `path` at the boundary or accept the search-box crash as a residual. If the fixer chooses to require `name`, the ISS-298 fixture must change in the same edit, and the change must say why.

## Where the fix belongs

The same single guard that fixes [ISS-915](20261001-2219-ISS-915.md) (`page.tsx:70-74`): one predicate before `setPayload`, so `giveUp()` stays the only exit. Not in `AppBuilderPreview`: its other render sites pass arrays built by `parseAppBuilderFilesForIDE` (`PreviewPanel.tsx:50-112`, mounted at `:170`) and `parseFilesForIDE` (`WorkflowHistory.tsx:87-121`, mounted at `:1058` and `:1097`), and both always set `path`, `name`, `ext`, `content` and `language`. Only this page feeds the component `JSON.parse` output read from storage. Next.js restricts what a `page.tsx` may export (Next 16.3.4 generates `checkFields<Diff<{ default: Function ... }>>` for each page, `frontend/node_modules/next/dist/build/webpack/plugins/next-types-plugin/index.js:45-62`, and reports `"<name>" is not a valid Page export field`, `frontend/node_modules/next/dist/lib/typescript/diagnosticFormatter.js:84`), so keep the predicate module-private instead of exporting it for tests.

## What would move this to CONFIRMED

jsdom, the cheapest route (no spec exists for this page today): mock `next/navigation` `useRouter` to `{ replace }`, seed `sessionStorage["__app_preview__"]` with each row, use `vi.useFakeTimers()`, render `PreviewFullscreenPage`, advance 100 ms, and assert `replace` was called with `/runs` and nothing threw. For the `name` row, render the accepted payload, type into the input labelled "Search files" (`AppBuilderPreview.tsx:539`) and assert nothing throws. In a browser: `sessionStorage.setItem('__app_preview__', JSON.stringify(<row>))`, then open `/preview-fullscreen`.

## Resolution (QA-KB-082 fix, 2026-10-07)

Fixed by [FIX-739](20261007-1959-FIX-739.md), in the same single guard as ISS-915 (`page.tsx:70-95`). It follows the
"do not over-tighten" constraint above: `path` and `content` must be strings; `projectName` is kept only when it is a string,
otherwise it is left undefined and the component default `"Project"` applies; `name` is derived from `path` when it is not a
string, so the ISS-298 `{path, content}` fixture stays accepted and the search box no longer throws. The fix found one more
crash site that the table above did not list: a truthy non-string `ext` throws at `getFileIcon` (`AppBuilderPreview.tsx:69`,
`ext.toLowerCase()`). The predicate now rejects it under this card's Expected line. Verified in jsdom with a 19-case matrix,
run against the HEAD page (11 failed | 8 passed) and against the fixed page (19 passed): `evidence/qa-kb-082/fix-03-*`. Every
row in the table above is a matrix case. No repo test pins these rows: the 4-test-writer covered ISS-915 only, so
`verification` stays `manual`.
