# FIX-186

**Phase / trigger:** Phase 32 (OD wizard), ISS-051

## Description

When a user pastes a custom design system via `CustomDesignSystemModal`, the
content is lost before reaching the server. For `od_prototype`/`prototype`:
HTTP 400 `template_not_found` is returned. For `od_ppt`: the run proceeds
silently without the user's design system.

## Root Cause

`DashboardLayout.tsx` built the `extraParams` object with the key
`custom_design_system_body` (lines 342, 805, 864). `LaunchCommand`
(`run_commands.py:1466`) only declares `custom_ds_body`. Pydantic v2
`extra="ignore"` (the default) silently discards the unrecognised key —
`body.custom_ds_body` is always `None` regardless of the payload.

This is the **only** mismatched key among all 9 sibling keys in the same
`extraParams` object; all others (`template_id`, `design_system_id`,
`custom_template_body`, etc.) match exactly.

## Fix

Renamed 3 wire-key literals in `DashboardLayout.tsx`:

| Line | Before | After |
|---|---|---|
| 342 | `custom_design_system_body?: string` | `custom_ds_body?: string` |
| 805 | `{ custom_design_system_body: ... }` | `{ custom_ds_body: ... }` |
| 864 | `{ custom_design_system_body: ... }` | `{ custom_ds_body: ... }` |

The internal camelCase `customDsBody` state/prop names throughout
`LaunchWizard.tsx`, `launchDraft.ts`, `dashboard/page.tsx` are unchanged —
only the outbound JSON object key literals changed.
