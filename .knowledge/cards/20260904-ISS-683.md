## The gap

`single_file` reads the built deliverable back so it can be surfaced. That
readback then stands in for EVERY later agent's output, so any step running
after the build — a reviewer, a validator, a reporting agent — has its own
result overwritten by the deliverable.

Commit `127b20a3d` recorded this alongside the conditional-gate JSON parse
defect; the latter was fixed as [FIX-526](20260901-2232-FIX-526.md), this one was left.

## Reproduction (QA-KB-022, validated 2026-10-01, static, 3/3)

Static check, three cold runs, no browser. `backend/agents/execution_engine/engine.py:10622-10626`
guards the readback with only `_deliv_strategy == "single_file"`, `not _is_decision_step`
and `not is_revision_workflow`, then replaces output when
`len(file_from_disk) > len(output)` (:10629). There is no comparison with the file's
pre-step content, so any step after the build whose text is shorter than prototype.html
(reviewer, validator, reporter) has its output replaced by the HTML. Confirmed on every
attempt. `tests/agents/test_deliverable_readback_gate.py` (3 passed) covers only the
decision-step exemption, not this case. Tracked as QA-KB-022.

## Analysis (analyzer pass, QA-KB-022, 2026-10-01)

Line numbers are as of 2026-10-01 ~21:27 on a shared working tree where other agents were editing
`engine.py` (only below line 12995), `task_loop.py` and `run_commands.py` at the same time; the quoted
code and symbol names are the stable anchors.

### What this card got right, and two corrections

Right: the substitution is unscoped to the step that produced the file. Corrections:

1. The defect is in the engine, not the resolver. The `applies_to.globs` above named
   `single_file.py`, but the resolver reads the file from disk first
   (`backend/agents/capabilities/deliverables/single_file.py:141`) and is not involved. The
   substitution is `backend/agents/execution_engine/engine.py:10616-10636`. The resolver's
   docstring (`single_file.py:24-26`, "This also absorbs the L10 readback") is stale: the engine
   kept its own copy.
2. The QA-KB-022 reproduction step "inspect the agent's recorded output in the run record" does
   not show it. `WorkflowRun.agent_outputs` is built from `agent_chunk` events
   (`backend/app/api/run_commands.py:3986-3988`, the `agent_chunk` branch of the terminal-columns mapper), so it keeps the reply. The corrupted surfaces
   are listed under Blast radius.

### Root cause (CONFIRMED, read at file:line)

`backend/agents/execution_engine/engine.py:10616-10636` (quoted abridged), inside
`ExecutionEngine._run_agent` (:9178), after the step's text is joined
(`output = "".join(output_chunks)`, :10571):

```python
_deliv = getattr(ectx, "deliverable", None)
_deliv_strategy = getattr(_deliv, "strategy", None)
_is_decision_step = "route_decision" in (getattr(spec, "produces", None) or [])
if (
    _deliv_strategy == "single_file"
    and not _is_decision_step
    and not getattr(ectx, "is_revision_workflow", False)
):
    _deliv_name = getattr(_deliv, "name", None) or "prototype.html"
    file_from_disk = sandbox.read(_deliv_name)
    if file_from_disk and len(file_from_disk) > len(output):
        ...
        output = file_from_disk
```

One mechanism: the substitution is a function of the file's state, not of whether THIS step
produced it. The intent (comment :10593-10615) is "prefer the deliverable over the tool
confirmation" for the step that wrote the file. Once the file exists, every later step whose
reply is shorter gets the file as its output. The only carve-out is the decision step (:10618),
added when the same readback killed conditional gates; the compiler already forces every gate
source to declare `produces: ["route_decision"]` (`backend/agents/workflows/compiler.py:1861`),
so that exemption has no gap.

How it got here: before commit `1d9234bfa` (07-05) the block was
`if pipeline_type in ("od_prototype", "prototype"): html_from_disk = sandbox.read("prototype.html")`
with the same length test, also unscoped to the step. 07-05 swapped the workflow-name gate for
the declared strategy and kept the breadth for byte parity (INV-3), so every `single_file`
workflow, including composed ones, inherited it. It became visible when commit `127b20a3d`'s
12-step composed run had real steps after the build.

### Fix (where it belongs, and the agreed minimal fix: ACCEPTED, with refinements)

Where: only the block above. A guard in the shared funnel is a smaller diff than any per-caller
check, and no caller needs a change.

What (tested in memory, 12 lines): snapshot the declared file before the step streams, and replace
the output only when the file differs from that snapshot.

```python
# directly above `output_chunks: list[str] = []` (engine.py:10025), inside the redo loop's try
_pre_step_deliverable = None
try:
    _pd = getattr(ectx, "deliverable", None)
    if getattr(_pd, "strategy", None) == "single_file":
        _pre_step_deliverable = sandbox.read(getattr(_pd, "name", None) or "prototype.html")
except Exception:  # noqa: BLE001 — a read failure must not abort the step
    _pre_step_deliverable = None
# ... at the readback (engine.py:10628)
if file_from_disk and file_from_disk != _pre_step_deliverable and len(file_from_disk) > len(output):
```

Refinements to the agreed note:

1. Snapshot per iteration, not per call: the redo loop, loop-back revisits and `task_loop`
   iterations each re-enter the body, so it goes inside the loop, before the stream starts.
2. The pre-read must be exception-safe and only for `single_file`: `LocalWorkspace.read_file` is
   strict UTF-8 (`backend/app/agents/runtime/local.py:344`), so a binary deliverable name would
   fail the step before it runs. Same idiom as `backend/agents/capabilities/strategies/task_loop.py:386-390`
   and `:444-447`, which already detect "did this step edit the deliverable" by comparing snapshots.
3. Keep every existing conjunct verbatim, including `len(file_from_disk) > len(output)`,
   `not _is_decision_step` and `not is_revision_workflow`. `tests/agents/test_deliverable_readback_gate.py`
   slices the source from the FIRST `_deliv = getattr(ectx, "deliverable", None)` to
   `output = file_from_disk` and asserts those fragments; do not introduce an earlier line with that
   text.
4. Line refs in the agreed note: the resolver call is `engine.py:7811`, not :7830. No change there.

Why this over deriving "wrote it" from the step's own `write_file`/`edit_file` events: it is
path-agnostic (no `/prototype.html` vs `prototype.html` normalisation), knows no tool name, adds no
import, and has precedent in this tree.

What it leaves (stated so "fixed" is not over-claimed):

- A step that EDITS the file is still replaced: [ISS-894](20261001-2123-ISS-894.md). This is the
  prototype_v2 Validator and Presenter whenever they change anything. Verify this fix with a step
  that only reads.
- Two concurrent steps writing the declared file on the shared sandbox could be misattributed to
  each other (the agreed note's edge). No shipped manifest has two concurrent writers of it.
- A writer whose reply is longer than the file keeps its reply (the length conjunct stays).

## Resolution (QA-KB-022 fix, 2026-10-01): [FIX-697](20261001-2237-FIX-697.md)

The guard in "Fix" above was applied as written: a per-iteration, exception-safe
`_pre_step_deliverable` snapshot directly above `output_chunks: list[str] = []`, and
`file_from_disk != _pre_step_deliverable` added to the readback, with every existing conjunct kept.
`test_deliverable_readback_scope.py` now shows `[XPASS(strict)]` (the pass signal), and the strict
marker stays for the verifier. One assertion in that test was corrected, and the correction is
justified by this card: `typed[1:]` also selected the writer's own step artifact, which must be the
file, so it is now scoped to the reviewer's typed writes. The golden delta is exactly the four
numbers predicted above. [ISS-894](20261001-2123-ISS-894.md), the editing-step residual, stays open.
Details and coverage are in [FIX-697](20261001-2237-FIX-697.md).
