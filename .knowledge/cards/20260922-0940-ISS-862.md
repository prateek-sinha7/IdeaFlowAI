## Measured directly in the browser

`/create/ex_A2_branch`, `language` node, Config tab:

```
before:  Type = step
action:  select_option("Workflow")      # succeeds, no error
after:   Type = step                    # reverted; all three outcomes unchanged
         workflow-target-button count: 0
```

The select is controlled by `outcome.trigger`, so a value that snaps back means
the write never reached state.

## How far it is diagnosed

The write path is wired end to end — every link exists:

```
CanvasConfigRail  updateOutcome()      -> onRouteChange?.(agent.id, applyOutcomePatch(...))
CanvasView        handleRouteChange()  -> onTreeChange?.(mapAgentInTree(pipelineAgents, id, ...))
AgentsPopup       handleTreeChange()   -> onReorder?.(next)
IdeaInputPage     handleReorderAgents  -> setPipelineAgents(reordered)
```

`applyOutcomePatch` itself is correct — it merges `{...prevOutcome, ...patch}`.
Every hop is an OPTIONAL call (`?.`), so any unwired link fails silently, but
all four are wired at both mounts (`IdeaInputPage:2149`, `LaunchWizard:1444`).

**Not diagnosed past that point.**

## The next thing to check

Whether the `route` the rail READS comes from the same list `setPipelineAgents`
writes. `IdeaInputPage` maintains `manifestAgents` with **qualified** ids
(`custom-agent:ask`, `IdeaInputPage:~1199`) alongside `pipelineAgents` whose ids
are **bare**, and `mapAgentInTree` keys on an exact id match — the same
qualified-vs-bare split that made the Prompt User toggle read OFF in
[ISS-306](20260828-1745-ISS-306.md), fixed on the toggle's side only.

## What it blocks

[ISS-258](20260828-1650-ISS-258.md) cannot be exercised at all: its scenario has
to MAKE a route edit before it can test that Cancel discards it. These are the
2 failures that remain in the offline suite after `14ce62c59`.

## Test-side problems fixed on the way, which were NOT this defect

- `canvas-node-custom-agent:language` → `canvas-node-language`. `CanvasNode`
  renders `canvas-node-{agent.id}` with the bare instance id.
- `[data-testid="tab-config"]` → `get_by_role("tab", name="Config")`. The rail
  tabs are role-based and carry no testids, and a Playwright click on a selector
  matching nothing is not an error — so the panel never opened and the failure
  surfaced one step later.
- `get_by_label("Type")` → `get_by_label("Type", exact=True)`. `get_by_label`
  matches a substring and the Config tab has since gained a "Node type" select,
  so `.first` resolved to that and spent 30s against a select with no
  "Workflow" option.
