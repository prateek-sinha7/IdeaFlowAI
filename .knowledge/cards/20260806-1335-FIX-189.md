# FIX-189

**Phase / trigger:** KAN-75 (entitlements), Phase 44-07 (REST launch), ISS-055

## Description

Any authenticated user can launch any pipeline regardless of tier. `can_run_pipeline`
from `entitlements.py` was only called at the workflow-save path (`user_workflows.py:274`).
The two functions that actually mint a `WorkflowRun` — `launch_run` and
`_mint_revision_row` — never imported or called it.

## Root Cause

`run_commands.py` was built as the REST successor to the deleted `websocket.py`
(Phase 44-07). The entitlement catalog in `entitlements.py` predates all REST launch
work and was never wired into it. `current_user.tier` was never read in the launch path.
Independent proof: `_FakeUser` in `test_rest_run_launch.py` had no `tier` attribute —
if `launch_run` touched tier, every test would raise `AttributeError`.

## Fix

**A1 — `launch_run` (`run_commands.py` after line 1630):**
- Added `from app.core.entitlements import can_run_pipeline` to top-level imports
- Added tier gate immediately after `_resolve_launch_agents(body)`, before agent_ids block
- Uses raw `pipeline_type` (not `base_pipeline_type`) — `TIER_PIPELINES` has `"od_prototype"`
  and `"prototype"` as distinct keys; alias-collapsed value would mis-key od_prototype launches

**A2 — `_mint_revision_row` (`run_commands.py` after line 2225):**
- Added tier gate after `revision_pipeline_type` is computed, before `get_pipeline_agents`
  or any DB write — fail fast, no orphan rows
- Single insertion covers all 3 production call sites: `create_revision` (line 2376),
  `CHANNEL_REVISION` in `post_message` (line 1200), Concierge `"revision"` disposal (line 988)

**B — `entitlements.py`:**
- Added `"hexaware"` tier to `TIER_PIPELINES`:
  `{user_stories, user_stories_revision, prototype, prototype_revision, od_prototype}`
- Updated `Tier` Literal, `TIER_LABELS`, and `UPGRADE_PATH`
- `basic` tier unchanged — every new signup defaults to `basic`; narrowing it would break all existing users

**C — `test_rest_run_launch.py`:**
- Added `tier: str = "enterprise"` to `_FakeUser.__init__` — default `"enterprise"` ensures
  all existing tests pass unchanged (enterprise grants all pipelines)

## Test Results

23/25 tests pass (same as unmodified baseline). 2 pre-existing failures unrelated to this
fix (`test_unsatisfiable_custom_composition_rejected_pre_mint` and
`test_owned_source_links_the_child`) were failing before this fix and remain unchanged.
