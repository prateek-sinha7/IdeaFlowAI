## What happened

[ISS-323](20260828-1810-ISS-323.md)'s root cause — an over-permissive heading/bold regex plus a
`hasDot`-only guard that lets a documentation heading like `### Via Node.js` become a phantom
project "file" — is not limited to the live Preview tab's `parseAppBuilderFilesForIDE`
(`PreviewPanel.tsx`). `frontend/src/components/history/WorkflowHistory.tsx` carries a third,
independently written fork of the identical parser, reachable by reopening a completed run from
Workflow History / "My Workflows" rather than from the live run screen.

## Root cause (INFERRED — mechanism confirmed by reading code; not yet reproduced against a live run)

`frontend/src/components/history/WorkflowHistory.tsx:74-105` (`parseFilesForIDE`) duplicates the
same three regex formats and guard as `PreviewPanel.tsx:46-105` and
[ISS-483](20260829-0133-ISS-483.md)'s `FilesTab.tsx:196-258`, under yet another set of local names:

- `r1` (`WorkflowHistory.tsx:95`) — the safe ```` ```filename: ```` format.
- `r2` (`WorkflowHistory.tsx:99`) — `/###\s+([\w./\-@][^\n]*\.\w+)\s*\n```[^\n]*\n([\s\S]*?)```/g`,
  identical to the broken `headerRegex` in [ISS-323](20260828-1810-ISS-323.md).
- `r3` (`WorkflowHistory.tsx:102`) — see [ISS-485](20260829-0133-ISS-485.md), the same unbounded
  bold-heading character class.
- `add` (`WorkflowHistory.tsx:85-93`) — the same dot-only check at line 89:
  `if (!name.includes(".") && !/^(Dockerfile|Makefile|Procfile)$/i.test(name)) return;`.

This fork feeds the shared `AppBuilderPreview` component (the SAME Explorer/CodeViewer/
`handleDownload`/`handleDownloadZip` from [ISS-323](20260828-1810-ISS-323.md), in
`frontend/src/components/preview/AppBuilderPreview.tsx`) from two call sites on the reopened-run
detail view:

- `ideFiles` (`WorkflowHistory.tsx:486-498`, calling `parseFilesForIDE` at lines 495 and 498) →
  `<AppBuilderPreview files={ideFiles} projectName={ideProjectName} onRevise={undefined} />`
  (`WorkflowHistory.tsx:838`) — the reopened App Builder run branch.
- `genericBundleFiles` (`WorkflowHistory.tsx:582` —
  `isGenericBundle && selectedOutput ? parseFilesForIDE(selectedOutput) : []`) →
  `<AppBuilderPreview files={genericBundleFiles} projectName={ideProjectName} />`
  (`WorkflowHistory.tsx:877`) — the "generic bundle" branch, which (per this repo's SC-001
  dispatch-on-shape convention) can be reached by any `pipeline_type` whose deliverable renders
  through the generic-bundle path, not only `app_builder`.

Once either array contains a phantom `ParsedFile`, every downstream consequence documented in
[ISS-323](20260828-1810-ISS-323.md) — phantom Explorer entry, wrong file count, malformed
extensionless per-file download, polluted "Download ZIP" — applies identically, because both
render through the same `AppBuilderPreview` component. The surface is different: reopening a
historical run from Workflow History, not the live Preview tab or its `/preview-fullscreen`
popout — neither of which this fork's call sites are covered by
[ISS-323](20260828-1810-ISS-323.md)'s `applies_to.globs`.

## Conditions

- Page: Workflow History / "My Workflows" — reopened-run detail view, App Builder or
  generic-bundle branch
- Trigger: same markdown shape as [ISS-323](20260828-1810-ISS-323.md) present in the reopened
  run's agent output / selected output
- Account/tier: not tier-specific
- Reproduction not yet attempted here — mark this INFERRED until a completed run with a matching
  heading is reopened from Workflow History and its Explorer/Download is exercised, mirroring
  [ISS-323](20260828-1810-ISS-323.md)'s validation method.

## Expected vs actual

**Expected:** reopening a completed run from Workflow History shows only real project files in
its Explorer, and any per-file/ZIP download saves real files.

**Actual (inferred):** the same phantom-file listing/naming/ZIP-pollution defect as
[ISS-323](20260828-1810-ISS-323.md) reproduces on the reopened-run detail view, for both the
App Builder and generic-bundle branches.
