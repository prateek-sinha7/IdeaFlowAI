## Symptom

```
test_filtering_by_type_narrows_the_list[Presentation]        TimeoutError 30000ms
test_the_chip_label_and_its_url_value_are_different_words    TimeoutError 30000ms
test_refresh_re_reads_without_losing_filters                 TimeoutError 30000ms
test_an_unrecognised_type_shows_an_empty_list_rather_than_an_error
  AssertionError: the Presentation chip now reads zero as well — the
  contradiction D-15 records has gone, so re-read that defect before
  changing this test
```

## The bucketing is correct

`filterBucketFor` (`RevisionFamilyView.tsx:100`) maps every type to one of the
four framework bases or `custom`, and `WorkflowHistory.tsx` drops a chip whose
count is zero (`if (type !== "all" && count === 0) return null`). A ppt run
would still bucket to `ppt`. **Their absence is a data fact, not a bucketing
bug.**

## Decision needed

If presentation runs are supposed to exist in this history, this is a
data-loss finding and the four tests are right to fail. If not, they need a
type that still has runs. The fourth test's own message says to re-read D-15
before touching it — do that first.
