## What happened

On the orphaned legacy workflow builder at `/workflow` (unlinked from
`frontend/src/lib/routes.ts` — not the same page as `/workflows/new` or the
composer), the "Run Workflow" button enables as soon as the "Describe your
idea" textarea has any non-empty text, even while "Workflow Agents (0)" shows
zero agents attached. Clicking the enabled button produces no observable
effect at all: no navigation, no toast, no console message, and critically no
network request of any kind fires (verified via `browser_network_requests`
diff, not just a visual read) — no run is created.

## Reproduction (3/3, cold start every cycle)

Each cycle: fresh navigation `/dashboard` -> `/workflow` (not a soft re-click
of the same screen), confirm `Workflow Agents (0)` and `Run Workflow`
`disabled` attribute present, type distinct non-empty brief text, confirm
`button.disabled === false` via direct DOM read, snapshot the network request
list, click, re-snapshot the network request list and console.

- **Cycle 1:** brief "zz-hunt-cycle1 validator repro cold start attempt one
  for run workflow zero agents" — button became enabled with 0 agents; click
  produced 0 new network requests (36 requests before and after, last request
  unchanged `GET /api/runs?limit=50`), no console entry, URL stayed
  `/workflow`.
- **Cycle 2:** brief "zz-hunt-cycle2 ..." — identical: enabled at 0 agents,
  0 new requests on click.
- **Cycle 3:** brief "zz-hunt-cycle3 ..." — identical: enabled at 0 agents,
  0 new requests on click.

No axis variation was needed — this reproduces on every cold cycle with no
special timing, account, theme, or viewport condition. Tier: `qa-admin`,
default light/dark theme (unmodified), default viewport, first visit to the
route each cycle (localStorage session pre-existing, page itself always
cold-loaded).

## Expected vs actual

**Expected:** "Run Workflow" should stay disabled (or clicking it should
surface a validation message, e.g. "Add at least one agent") while zero
agents are attached, since a 0-agent workflow cannot meaningfully run. At
minimum, a click on an enabled button should do *something* observable.

**Actual:** the button's `disabled` state is gated purely on the brief
textarea's content and never on the agent count displayed next to it, and the
click handler is a complete, silent no-op on this route — zero network
activity, zero UI feedback.

## Root cause

`frontend/src/components/workflow/WorkflowView.tsx`:

- Line 473: `disabled={!ideaInput.trim()}` on the "Run Workflow"
  `motion.button` — checks only `ideaInput.trim()`, never
  `pipelineAgents.length`, even though "Workflow Agents (N)" derives its
  displayed count from that same `pipelineAgents` array a few lines above.
- Lines 161-167, `handleRun`:
  ```
  const handleRun = () => {
    if (!ideaInput.trim()) return;
    if (onStartPipeline) {
      const agentIds = pipelineAgents.map((a) => a.id);
      onStartPipeline(selectedType, ideaInput.trim(), agentIds);
    }
  };
  ```
  `onStartPipeline` is guarded by an `if`, so on the orphaned `/workflow`
  route — where nothing wires this prop — the handler runs, the guard fails
  silently, and nothing happens: no request, no error, no feedback. Even with
  the prop wired, the function has no floor on `agentIds.length`, so a
  0-agent run would still be dispatched.
