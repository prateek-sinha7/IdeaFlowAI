# FIX-684

Register entry **QA-KB-009** (root `LEDGER.md` / `BUGS.md`). The root card is [ISS-160](20260813-1300-ISS-160.md);
the siblings are [ISS-879](20261001-2111-ISS-879.md) (`ppt_v2`), [ISS-880](20261001-2111-ISS-880.md) (tier
classification) and [ISS-881](20261001-2111-ISS-881.md) (`REVISION_BASE_MAP`). Root causes come from those cards
and were not re-derived; the code was re-read at the cited lines before editing. Line numbers are post-change
unless marked (pre).

## What was wrong

`post_message`'s `CHANNEL_REVISION` branch derived the revision target by hand:
`target_artifact_type = dispatch.target_artifact_type or f"{wr_type}_output"` (`run_commands.py:2018`, pre).
When the parent run is itself a revision, `wr_type` already ends in `_revision`, so `_mint_revision_row` derived
`<x>_revision_revision`, which has no manifest and no roster: HTTP 400 `revision_unsupported` from the existence
gate (not the 403 `pipeline_not_entitled` the bug report names; ISS-160 Corrections). The Concierge disposal path
already carried the base mapping (`run_commands.py:1640-1648`, pre), so the two fallbacks disagreed.
A `ppt_v2` parent failed on both fallbacks (`ppt_v2_output` gives `ppt_v2_revision`, which does not exist), while
the UI revises a `ppt_v2` deck as `ppt_output`.

## What changed

- `backend/app/api/run_commands.py:1472-1498`: new private `_revision_base_type(wr_type)`. The disposal block is
  moved into it unchanged (tiered prototype types, Depth v2 type, generic `removesuffix("_revision")`; the
  `endswith` / `else` pair collapses into one `removesuffix`, which is a no-op without the suffix), plus one line
  for ISS-879: `ppt_v2` gives `ppt`.
- `run_commands.py:1658`: the disposal path calls the helper (`base_type = _revision_base_type(wr_type)`).
- `run_commands.py:2028-2030`: `CHANNEL_REVISION` falls back to `f"{_revision_base_type(wr_type)}_output"`. The
  TARGET is fixed upstream, so the minted row (`_mint_revision_row`), the driver and the engine, which each
  re-derive the pipeline from the same `target_artifact_type`, agree; nothing under `agents/execution_engine/`
  was touched (SC-001 / INV-1).
- `run_commands.py:1535`: the `_dispose_concierge_proposal` docstring said it "Reuses REVISION_BASE_MAP (via
  _mint_revision_row)", which was never true (ISS-881); it now names `_revision_base_type`.
- `backend/agents/registry.py:155`: `REVISION_BASE_MAP` gains `"backlog_revision": "backlog"` (ISS-881).
- `backend/tests/unit/agents/test_registry_helpers.py:99`: `backlog_revision` joins `_COMPOSED_REVISION_PIPELINES`.
  Adding the map row made `test_revision_allow_list_is_own_agents_only[backlog_revision]` fail with "expected a
  non-empty allow-list for 'backlog_revision'" (observed). `backlog_revision` is a composed manifest
  (`custom-agent` steps) with an empty `PIPELINE_AGENTS` roster, like the two v2 revisions already in that set;
  ISS-881's fix direction names this exact change. Classifying it there also runs
  `test_composed_revision_allow_list_is_empty[backlog_revision]`, which passes.
- `backend/tests/integration/api/test_chat_messages_endpoint_api.py:533`: new
  `TestRouting::test_ppt_v2_parent_revises_through_ppt_revision`, strict xfail, the regression test ISS-879's
  TEST COVERAGE asked for and the test-writer did not add (the parametrized test carries an ISS-879 marker but no
  `ppt_v2` case). Added before the source change and observed red first: 400 `revision_unsupported` naming
  `'ppt_v2_revision'`.

Helper chosen as a verbatim extraction, ISS-160's preferred form. The map-first form it also allows was not used:
`REVISION_BASE_MAP` stays read by tests only. Equivalence probe (scratch, not committed), the helper against the
pre-change disposal block over 47 pipeline types (every `agents/workflows/` id, `PIPELINE_AGENTS` key and map
key): the only type that differs is `ppt_v2`; no type derives `<x>_revision_revision` or a missing revision
pipeline; all 10 `REVISION_BASE_MAP` entries equal the helper's result.

## Not fixed here

[ISS-880](20261001-2111-ISS-880.md) stays open: it is a product decision (its own "Decision needed" section).
With this fix the chat-turn channel succeeds for the tiered parents but lands them on the smallest tier:
`prototype_large_revision` / `prototype_feature_revision` give `prototype_revision`, and
`prototype_v2_feature_revision` (Depth) gives `prototype_v2_revision` (Fast). The parametrized test asserts a
child is minted, not its tier, so its XPASS is not evidence for ISS-880.
