`ex_A1_loop`'s `check` step routes `retry -> greet` when the greeting has no joke. On
every pass `greet` produced the same 12-character output and the loop ran to its cap and
failed closed.

## Root cause

A backward jump re-dispatches the target through the normal path, which rebuilds its
context message from scratch. `greet` therefore saw `context_sources: []` on pass 2 —
byte-identical to pass 1. Nothing carried the reason it was being asked again, so an
identical prompt produced an identical answer, deterministically. The loop could never
converge; it could only exhaust `loop_max_iterations`.

Proven by diffing `check`'s `context_message` between a passing and a failing run: byte
identical.

## Fix (R-28)

`RouteOutcome` gained an optional `feedback: str | None`, type-checked by the compiler
(a non-string raises a `CompilerError` naming the outcome). On a backward jump the engine
stashes it in `ectx.pending_route_feedback[target]` together with the pass number, the cap
and the deciding step's output; `_compose_context_message` emits it as a retry block and
POPS it, so it is delivered exactly once.

The authored instruction lives on the OUTCOME, not in the target's prompt — deliberately.
Baking "include a joke" into `greet` was tried first and made the mechanism
unfalsifiable: pass 2 would produce a joke whether or not the feedback ever arrived.

See [ADR-0015](20260824-1630-ADR-0015.md) for the routing model this extends.
