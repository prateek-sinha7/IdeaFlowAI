## What was wrong

`ChainContextProvider` was registered in the capability registry and
unit-tested in isolation, but none of the three chainable manifests
(`prototype`, `ppt_v2`, `user_stories`) declared `chain_context` in their
`context_providers:` list.

The engine's `_seed_workflow_context` loop at `engine.py:13812` iterates
`compiled.context_providers` verbatim — if `chain_context` is not in the
list, `provider.load()` is never called.  Every chained run therefore started
with an empty `.context/`, giving its first agent no `summary.md`, no
`logs.jsonl`, and no source deliverable to read.

The bug failed silently because the dispatch loop swallows
`KeyError`/`RuntimeError` (`engine.py:13816-13817`), and the provider itself
returns `{}` on every guard path rather than raising.

Root cause card: [BUG-125](20260915-1301-BUG-125.md).

This fix depended on [FIX-514](20260915-1400-FIX-514.md) (B24) landing first:
adding `chain_context` to `prototype` and `ppt_v2` before `_atomic_write_context_dir`
was fixed would have destroyed their `.context/design/` and
`.context/selections.json` on every chained run.

## What changed

**`prototype/workflow.yaml`** — `chain_context` appended after `opendesign`:
```yaml
context_providers:
- opendesign
- chain_context   # added
```

**`ppt_v2/workflow.yaml`** — same:
```yaml
context_providers:
- opendesign
- chain_context   # added
```

**`user_stories/workflow.yaml`** — empty list replaced:
```yaml
context_providers:
- chain_context   # was []
```

**`test_chain_manifest_wiring.py`** (new) — 7 tests (6 pass, 1 skip):
- `test_chainable_manifest_declares_chain_context_provider` × 3 — compiles
  each chainable workflow and asserts `chain_context` is in
  `compiled.context_providers`. Also acts as a compiler gate: an unknown
  provider name raises `CompilerError` at `compiler.py:322`.
- `test_chain_context_comes_after_opendesign_when_both_declared` × 3 —
  asserts `chain_context` index > `opendesign` index. Skipped for
  `user_stories` (correct — it doesn't declare `opendesign`).
- `test_non_chainable_manifests_need_not_declare_chain_context` — confirms
  `custom` compiles without `chain_context` and doesn't declare `chains_from`.
