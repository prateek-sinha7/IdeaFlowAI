## What was wrong

On `/analytics`, hovering a Daily Activity bar showed the raw JS integer —
`Aug 24: 2364478` — while every other number on the page (KPI tiles, By Pipeline
Type, By Model, Token Breakdown) is routed through `formatTokens()` and renders as
`2.4M` / `554.0K`. Pure presentation defect; the underlying `daily[].total_tokens`
value was correct. Reported as `BUG-20260828-102900-analytics-r2`.

## Root cause

`frontend/src/components/analytics/charts/BarChart.tsx:85-89` composes the per-bar
tooltip as `d.tip ?? `${d.label}: ${d.value}`` — a deliberate raw-value fallback for
callers that supply no `tip` (`BarDatum.tip`, `BarChart.tsx:39`, is the extension
point). The only production caller, `frontend/src/components/analytics/AnalyticsPage.tsx`,
built `dailyData` (`:246-250`) with `label`/`value`/`runs` and never set `tip`, so the
Daily Activity series alone bypassed the page's own `formatTokens()`
(`AnalyticsPage.tsx:64-67`) and hit the raw default.

## What changed and why there

`frontend/src/components/analytics/AnalyticsPage.tsx:246-257` — `dailyData` now sets
the existing `tip` field:

```tsx
tip: d.total_tokens > 0 ? `${label}: ${formatTokens(d.total_tokens)}` : undefined,
```

Fixed at the caller, not in `BarChart.tsx`, because `BarChart` is documented in its own
header as a generic presentation primitive with no formatting opinion (SC-001/INV-1:
data-prop driven, no domain branch), and `formatTokens()` — the knowledge of what these
numbers mean — already lives in `AnalyticsPage`. Blast radius re-checked before editing:
`grep -rn "BarChart" frontend/src/` still shows exactly one production JSX usage
(`AnalyticsPage.tsx:411`), so this caller-side fix covers every affected path.

The `> 0` guard preserves `BarChart`'s runs-only fallback tooltip (`Aug 24: 3 runs`),
shown when a period has zero tokens; run counts render as plain integers everywhere else
on this page (`AnalyticsPage.tsx:383`, `:476`, `:514`), so that branch is correct as-is.
For a day with 0 tokens inside a series that does have tokens, the output is unchanged
either way (`formatTokens(0) === "0"`).
