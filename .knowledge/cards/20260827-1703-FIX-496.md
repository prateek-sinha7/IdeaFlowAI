## Symptom

`prototype-validate` and `prototype-revision-analyzer` ran fine on local dev and
failed on production with a Bedrock `ValidationException`.

## Root cause

Both declare `model: us.anthropic.claude-sonnet-5` in their `AGENT.md`. The `us.`
CRIS (cross-region inference) prefix is only valid in US regions. Local dev runs
`us-east-2`; production runs `eu-central-1`, where that model id does not exist.

## Fix (GEO-01)

`backend/agents/model_policy.py` gains `_normalize_geo_prefix()`, which swaps the
geo prefix (`us.` / `eu.` / `au.` / `apac.`) to match `settings.AWS_REGION`
before the resolved model id reaches `build_model`.

It is called at the **end** of `ModelResolver.resolve()` — after the D-02
precedence chain and after catalog validation — so it applies to every tier
transparently:

```
Local (us-east-2):   us.anthropic.claude-sonnet-5 -> unchanged
Prod  (eu-central-1): us.anthropic.claude-sonnet-5 -> eu.anthropic.claude-sonnet-5
```

No `AGENT.md` changes are needed, and that is the point: one manifest is correct
in both environments.

Also:

- `model_catalog.py` — added `eu.anthropic.claude-sonnet-5` so the EU variant is
  catalog-valid for manual overrides and fallback chains.
- `_region_override` parameter on `ModelResolver` and `_normalize_geo_prefix`
  for hermetic unit testing without patching settings.
