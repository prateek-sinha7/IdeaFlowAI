## What was wrong

[ISS-470](20260828-2310-ISS-470.md), the sibling [FIX-382](20260829-0223-FIX-382.md)
identified but deliberately left open: `upsert_github_pat` carried the identical
commit-then-refresh-then-respond-from-the-refreshed-object shape that
[ISS-319](20260828-1804-ISS-319.md) proved in `update_preferences`.

Two concurrent `PUT /api/settings/github-pat` calls for the same user write one
`UserGithubCredential` row (unique on `user_id`). If request B's `commit()` lands
between request A's own `commit()` and its `db.refresh(row)`, A's `200` body
reports **B's** `github_username` and `scopes` — the GitHub account belonging to a
different PAT than the one A submitted. The UI's "what was saved" line
(`IntegrationsCard.tsx`) then shows a login the user never pasted a token for,
with no error anywhere.

## Root cause

`backend/app/api/settings.py:168-181` (`upsert_github_pat`), before this fix:

```python
db.commit()
db.refresh(row)
return GithubPATResponse(
    github_username=row.github_username,   # <-- re-read of the ROW, post-refresh
    scopes=row.scopes,                     # <-- ditto
    last_4=pat[-4:],
    created_at=row.created_at,
    updated_at=row.updated_at,
)
```

The two identity fields were read back off the row after `refresh()` re-read it
from the database, instead of from `gh_user`/`scopes_header` — the values
`GET https://api.github.com/user` had just returned for THIS request's PAT and
which this request wrote to the row at `settings.py:158-166`.

## What changed, and why there

`backend/app/api/settings.py` only — the one file
[ISS-470](20260828-2310-ISS-470.md)'s `applies_to.globs` names. Two expressions:
`github_username=gh_user`, `scopes=scopes_header`. A short `# ISS-470:` comment
above the return records why, matching the file's existing `# ISS-292:` /
`# ISS-319:` convention, so the re-read is not reintroduced as a
"simplification" later. This is exactly the fix ISS-470's card and
[FIX-382](20260829-0223-FIX-382.md) § "Not fixed by this card" proposed:
"source `github_username`/`scopes` from the already-fetched local
`gh_user`/`scopes_header`".

**No shared helper was introduced**, for the reason
[ISS-319](20260828-1804-ISS-319.md) already settled: the sites carrying this
shape inline different response models, and a helper for call sites that share
no return type would be a bigger diff than the one-line changes.

**Re-grepped `db.refresh(` across `backend/app/api/settings.py` before editing** —
three sites, and the card's blast radius still holds:

- `:169` `upsert_github_pat` — this fix.
- `:251` `create_api_key` — NOT this defect. The refreshed row is a brand-new
  `UserApiKey` this request just inserted; no other request shares it, and the
  returned `token` is the local `plaintext`. Left alone.
- `:352` `update_preferences` — already fixed by
  [FIX-382](20260829-0223-FIX-382.md).

**Nothing about what gets PERSISTED changed**; only what gets REPORTED. The
loser's row write is still overwritten — accepted last-write-wins, per the locked
constraint above. `get_github_pat_status` (`settings.py:180-204`) reads the
persisted row and was never part of this defect.

## Not fixed by this card

[ISS-471](20260828-2310-ISS-471.md) — `admin.py`'s `update_user_tier` /
`update_user_role`, whose `_to_response(user, db)` reads `user.tier` /
`user.is_admin` post-refresh. `admin.py` is outside this card's
`applies_to.globs` and is a separate fix assignment.
