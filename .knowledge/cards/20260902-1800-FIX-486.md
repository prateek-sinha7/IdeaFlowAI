## Symptom

`pytest tests/unit/test_register_password_echo.py` reported:

```
FAILED tests/unit/test_register_password_echo.py::test_a_too_short_password_is_never_echoed_back_in_the_422_body
[XPASS(strict)] ISS-257 unfixed
```

The test itself was passing — the password was not being echoed back — but the decorator
`@pytest.mark.xfail(reason="ISS-257 unfixed", strict=True)` instructed pytest to treat
an unexpected pass as a hard failure. This is `strict=True`'s intended behaviour: it
enforces that a known-broken test stays broken, and alerts when a fix lands without the
marker being cleaned up.

ISS-257 was resolved by [FIX-332](20260828-1915-FIX-332.md) (the `RequestValidationError`
redacting handler on `app.main`) and confirmed in domain 15 by
[FIX-430](20260831-1827-FIX-430.md) (the fixture rewrite that mounts the real `app.main`
instead of a bare `FastAPI()`). The xfail marker in `test_register_password_echo.py` was
never cleaned up after those fixes landed.

## Root cause

`backend/tests/unit/test_register_password_echo.py` lines 67–69 (pre-fix):

```python
@pytest.mark.issue("ISS-257")
@pytest.mark.xfail(reason="ISS-257 unfixed", strict=True)
def test_a_too_short_password_is_never_echoed_back_in_the_422_body(client):
```

## Fix

`xfail` decorator removed; `@pytest.mark.issue` retained for traceability:

```python
@pytest.mark.issue("ISS-257")
def test_a_too_short_password_is_never_echoed_back_in_the_422_body(client):
```

No test logic, assertion, or fixture changed.
