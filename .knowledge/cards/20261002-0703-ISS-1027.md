# ISS-1027

Latent sibling of [ISS-942](20261001-2241-ISS-942.md), found by the QA-KB-085 analysis on 2026-10-02. Confidence: the mechanism is CONFIRMED (run on
scratch copies; the repo test and `page.tsx` were not edited). The trigger is INFERRED: no dependency change to the auth-check effect has
happened yet, so nothing is red today and there is nothing for a validator to reproduce.

## Why the root cause implies it

[ISS-942](20261001-2241-ISS-942.md)'s flaw is not that `pinnedVersion` was added. A test ended its source slice at a hook's dependency list, and a
dependency list is not an identity: the same literal closes other hooks, so the first match after `start` is the intended close only until
the intended hook's deps change. I counted every test that ends a slice at a dependency list
(`evidence/qa-kb-085/06-analyze-deps-anchor-census.out.txt`): 7 anchors in 6 files. Five are long lists that occur once, so a change to the
intended hook makes `indexOf` return -1 and the `expect(end).toBeGreaterThan(start)` that follows fails loudly. One is ISS-942 itself.
This is the seventh, and its literal already has a decoy.

## Condition

`authEffectGuard.iss844.source.test.ts:35` sets `const endMarker = "}, [router, dispatch]);"` and slices `page.tsx` from
`// Auth check on mount` to the first match. `page.tsx` holds two. Line numbers differ between HEAD and the shared working tree, which
carries other uncommitted `page.tsx` edits:

| | HEAD 024c03ef8 | working tree, 2026-10-02 |
|---|---|---|
| start marker `// Auth check on mount` | :921 | :932 |
| first match, the auth-check effect's own close | :949 | :960 |
| second match, a different effect | :3417 | :3440 |

## Expected

The slice ends at the auth-check effect's own close, whatever that effect's dependencies are.

## Actual (latent)

Today the window is 28 lines and correct, and the test is green because the ISS-844 guard exists (`signedInDispatchedRef`, working tree
`page.tsx:947-950`). If the effect's deps ever change (say `[router, dispatch, searchParams]`), the first match moves to the second effect
and the window grows to 2,508 lines. The test's guard check, `/\.current\s*\)\s*return;/` or `/\.current\s*=\s*true;/`, then finds
`.current = true;` in unrelated code, so a later removal of the ISS-844 guard would still pass.

Scratch copies (`evidence/qa-kb-085/05-analyze-scratch-vitest-ab.out.txt`, produced by `evidence/qa-kb-085/analysis-scratch-vitest.sh`):

| `page.tsx` copy | window the test sees | result |
|---|---|---|
| real | 28 lines | pass |
| deps changed | 2,508 lines | pass (nothing to detect yet) |
| ISS-844 guard removed | 25 lines | FAIL, as designed |
| guard removed and deps changed | 2,505 lines | PASS: the guard is gone and nobody sees it |

## Fix direction

Test only. End the slice at the effect's own close, whatever its dependency list says: `src.indexOf("\n  }, [", start)`. The effect sits at
the top level of the component, two-space indent, exactly like the handler in [ISS-942](20261001-2241-ISS-942.md). Do not touch `page.tsx`. Optional, and the
same as ISS-942's hardening: assert that the window holds one `useEffect(`, so a widening can never again be silent.

## Why this is a card and not a bug

Nothing is red. It is carded so the fix to ISS-942 is applied to both anchors in one pass, instead of the next dependency edit
rediscovering it.

## Resolution (QA-KB-085 fix, 2026-10-07)

Fixed test-only by [FIX-741](20261007-2009-FIX-741.md), in the same pass as [ISS-942](20261001-2241-ISS-942.md), as the Fix direction above prescribes.
`authEffectGuard.iss844.source.test.ts:37`'s `endMarker` is now `"\n  }, ["`, and `:45` asserts exactly one `useEffect(` under
the existing Sanity comment. `page.tsx` is unchanged. The test stays `1 passed` on the real `page.tsx`. On scratch copies, the
case this card predicted, guard removed and deps changed, went from `1 passed` with the old test to `1 failed` with the fixed
one. With the guard removed and the deps list dropped, the fixed test fails on the one-`useEffect(` count
(`evidence/qa-kb-085/09-fix-mutant-probe.out.txt`, rows B4 and B5).
