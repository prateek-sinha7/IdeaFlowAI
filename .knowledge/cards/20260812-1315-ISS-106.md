# ISS-106

## Title

**The graceful-shutdown budget is bounded only in its drain steps; the final pool close is unbounded, so the documented worst case is not a worst case.** `close_checkpointer()` awaits `pool_to_close.close()` with no timeout (`checkpointer.py:140-144`). It is step 4 of `shutdown_run_infrastructure()`, i.e. it runs AFTER the 24s of bounded waits FIX-234 documented, and it sits between the application and process exit. A Postgres pool that is slow to close (an in-flight statement, a wedged socket, a server that stops responding) therefore pushes the total past `stop_grace_period` (30s, `docker-compose.yml:75`) and docker SIGKILLs mid-teardown — the exact failure the budget exists to prevent, with the shutdown summary never logged. `TEST-018`'s `test_production_teardown_budget_fits_inside_stop_grace_period` cannot catch this: it sums the configured drains, and there is no knob for this wait to appear in. **Fix shape:** wrap step 4 in `asyncio.wait_for(..., timeout=<new setting>)` and include that setting in the arithmetic guard, so the budget test covers the whole path rather than the part that happens to be configurable. The close is already non-raising and latches `_closed` before touching the pool, so a timeout would leave consistent process state.

## Source / Evidence

Recorded rather than fixed because bounding it is a behaviour change to the production shutdown path, which is not what ISS-088 authorised; the config comment and the budget test now both state the limitation explicitly instead of implying a total.

## Resolution

Fixed by [FIX-428](20260831-1816-FIX-428.md) (2026-08-31). `close_checkpointer()` now
awaits `pool_to_close.close()` under `asyncio.wait_for(settings.SHUTDOWN_CHECKPOINTER_CLOSE_SECONDS)`
(default 1.0s) with a dedicated `except asyncio.TimeoutError` arm, and that setting is a
term in both the `config.py` budget comment (24s -> 25s worst case) and
`_teardown_budget_seconds()` in `tests/unit/test_shutdown_reachability.py`, so the whole
path is now inside the arithmetic rather than only the configurable part. Proven by
`backend/tests/unit/test_checkpointer_shutdown_budget.py::test_close_checkpointer_is_bounded_when_pool_close_hangs`
(hanging pool, XPASS(strict) on the fix).

Note on this card's evidence: the `docker-compose.yml:75` pointer for the 30s
`stop_grace_period` is stale — that file no longer exists in the repo, and commit
732adc245 deleted both `_stop_grace_period_seconds()` and
`test_production_teardown_budget_fits_inside_stop_grace_period` because of it (leaving
orphaned statements after the `return` in `_teardown_budget_seconds`). The defect itself
was exactly as described; only the ceiling's citation had moved.
