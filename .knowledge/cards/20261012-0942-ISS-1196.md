# ISS-1196

**INFERRED** sibling of [ISS-1195](20261012-0942-ISS-1195.md) (register entry `QA-KB-117`). Code-confirmed and computed offline from source; not yet reproduced as a rendered text assertion.

## Condition

Any account entitled to `ppt_v2`, `prototype_v2` or `backlog` that opens `/settings/usage`: basic (`ppt_v2`), hexaware (`prototype_v2`, `backlog`), pro and enterprise (all three).

## Expected vs actual

Expected: each workflow the home catalog offers as an enabled card ("Pitch an idea (Depth)", "Prototype from documents (Depth)", "Write backlog from prototype and documents") has a counterpart under Deliverable access, so the two surfaces agree. Actual: none of the three appears; the grid shows only tiles whose id is a key of the 8-entry `PIPELINE_DISPLAY`.

## Why the root cause implies it

Same line as the reported bug: `frontend/src/components/settings/AccountSettings.tsx:87` `.filter(p => PIPELINE_DISPLAY[p])`. The map (`:65-74`) has no key for `ppt_v2`, `prototype_v2` or `backlog`, while `frontend/src/lib/entitlements.ts` entitles them (`ppt_v2` on basic, pro, enterprise; `prototype_v2` and `backlog` on hexaware, pro, enterprise) and their manifests are `user_launchable: true`, `is_beta: false` (`backend/agents/workflows/ppt_v2/workflow.yaml:36,40`, `prototype_v2/workflow.yaml:13-14`, `backlog/workflow.yaml:58-59`). Per tier, from `evidence/qa-kb-117/analysis-projection.out.txt`: basic omits `ppt_v2`; hexaware omits `backlog` and `prototype_v2`; pro and enterprise omit all three.

The enterprise validator run already shows both sides: the catalog's first screen lists the three cards (`evidence/qa-kb-117/03-validate-attempt2-dashboard-catalog-full.png`) and the Deliverable access grid lists none (`04-validate-attempt2-usage-omits-branch.png`).

## Open question (not for this card to decide)

The grid predates these workflows (map from 2026-05-19, ppt_v2 `70665bbcb` 2026-08-27, prototype_v2 `73796dbd0` 2026-09-18, backlog `756f9bd8e` 2026-09-29) and could be read as listing deliverable TYPES ("Presentation" covers both decks). The catalog gives each its own card, title and description, so under the owner's goal ("so the two surfaces agree") they disagree. If the grid is made catalog-driven (ISS-1195, full option) this closes with it; if ISS-1195 ships as the examples-only group, this stays open.

## What would settle it

A render of the Usage tab per tier with the catalog preloaded (the offline test described on ISS-1195), or `document.body.innerText` of `/settings/usage` as `pro@velocity.ai` not containing "Pitch an idea (Depth)" while `/dashboard` shows it enabled.

## Fix (FIX-785, 5-fixer, 2026-10-12)

Resolved by the shared derivation in [FIX-785](20261012-1013-FIX-785.md) (`splitCatalog` / `catalogAccess` in `frontend/src/lib/entitlements.ts`). The grid is catalog-driven, so `ppt_v2`, `prototype_v2` and `backlog` are listed for every tier entitled to them, labelled by `display_name`. Case `ISS-1196` in `AccountSettings.iss1195.test.tsx` now reports "Expect test to fail" (XPASS). Raw output: `evidence/qa-kb-117/fix-01-vitest-runs.txt`.
