## What was wrong

`BUG-20260828-080047-runs-id-steps`: on a run's Steps tab, expanding an agent row's "Tool calls"
panel shows a collapsed one-line summary per call (`<tool_name>  <args preview>  ok`). Any tool
argument whose value was an array or plain object rendered as literal `[object Object]` text —
`write_todos`' `todos` array (items of `{content, status}`) showed as
`todos: [object Object],[object`. Confirmed 3/3 on cold start, on all three `write_todos` calls in
the reproduction run. The expanded "Arguments" panel a few lines below renders the same data
correctly as pretty-printed JSON, so the data was intact and only this preview was broken.

## Root cause

`frontend/src/components/results/AgentDetailPanel.tsx:413` (card says `:412`; the line moved by one
in the working tree, same expression, verified by `grep -rn "String(v)" frontend/src` returning
exactly this one hit):

```tsx
{Object.entries(tc.args || {}).map(([k, v]) => `${k}: ${String(v).slice(0, 24)}`).join(", ") || "no args"}
```

`ToolCallEntry.args` is `Record<string, unknown>` (`frontend/src/types/index.ts:803-808`), so `v` is
not necessarily a string. `String(v)` on a plain object yields `[object Object]`; on an array of
objects `Array.prototype.toString()` coerces each element and joins with commas, giving
`[object Object],[object Object],...`, which `.slice(0, 24)` truncates to the
`[object Object],[object` seen in the UI. Primitives coerce fine, which is why the sibling
`write_file` call's string arguments always rendered correctly.

## What changed and why there

One file, two hunks, both inside `ToolCallsSection`:

- **Added** `argPreview(v: unknown): string` immediately above `ToolCallsSection`
  (`AgentDetailPanel.tsx:382-388`) — returns strings unchanged (preserving today's behaviour for
  the args that already rendered correctly, and avoiding the JSON quotes `JSON.stringify` would add
  around them), otherwise `JSON.stringify(v) ?? String(v)` in a `try/catch`. The `??` covers
  `undefined`, for which `JSON.stringify` returns `undefined` rather than a string; the `catch`
  covers a circular structure. This mirrors the precedent already in this codebase at
  `frontend/src/components/results/AuditTab.tsx:105` (`argvSummary`), rather than inventing a new
  shape.
- **Changed** the preview expression to `${k}: ${argPreview(v).slice(0, 24)}`. Truncation stays at
  24 chars and still happens after stringification, so the row's layout is unchanged.

Fixed here because this is where every collapsed tool-call preview routes through: `String(v)`
occurs exactly once in `frontend/src/`, `ToolCallsSection` has exactly one call site
(`AgentDetailPanel.tsx:1101`), and that call site is gated only on `agent.toolCalls.length > 0`
with no `isRunning` check — which is exactly why the single-line change closes
[ISS-585](20260829-0256-ISS-585.md) (live/generating run) as well as
[ISS-355](20260828-2105-ISS-355.md) (completed run) with no run-state-specific code. Live SSE
`tool_call` events (`frontend/src/hooks/useWorkflow.ts:1057-1064`) build the identical
`ToolCallEntry` shape, so both paths hit the fixed expression.

`AttachedSkillsSection` / `AttachedHooksSection` visually mirror this row layout but read fixed
string fields rather than doing `Object.entries` + coercion — checked, no sibling change needed.
