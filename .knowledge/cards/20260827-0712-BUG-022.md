## Two independent defects, and both matter

**1. The dashboard offers an action the auth layer forbids.** Nothing in the
grant path consults the break-glass invariant, so the UI is a button that
violates a rule enforced elsewhere. Either the grant is refused with an
explanation, or the invariant tolerates more than one local admin. It cannot
stay as it is — the current state is a UI affordance whose success is a
system-wide outage.

**2. The failure is reported as the wrong thing.** A user sees "session
expired". It did not expire; there is no session that would work, for any
admin, until a row is changed in the database. The diagnostic exists only in a
server-side log line, so the person who can read it is the person already
locked out of the machine's admin surface.

The second defect is what made this cost hours rather than minutes. The
symptom is indistinguishable from a genuine token problem, and it sits behind
a plausible red herring — two uvicorn servers were briefly bound to port 8000
with different `SECRET_KEY`s, which explains 401s perfectly and was not the
cause.

## If sign-in fails again, check both

    lsof -nP -iTCP:8000 -sTCP:LISTEN     -- expect one server plus its reload child
    select email from users where is_admin  -- expect exactly one row
