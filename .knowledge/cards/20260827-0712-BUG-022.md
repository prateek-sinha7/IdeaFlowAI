## Two independent defects, and both matter

**1. The dashboard offers an action the auth layer forbids.** Nothing in the
grant path consults the break-glass invariant, so the UI is a button that
violates a rule enforced elsewhere. Either the grant is refused with an
explanation, or the invariant tolerates more than one local admin. It cannot
stay as it is — the current state is a UI affordance whose success is a
system-wide outage.

**2. The failure is reported as the wrong thing.** A user sees "session
expired". It did not expire; there is no session that would work, for any
admin, until a row is changed in the database. The diagnostic exists only in a
server-side log line, so the person who can read it is the person already
locked out of the machine's admin surface.

The second defect is what made this cost hours rather than minutes. The
symptom is indistinguishable from a genuine token problem, and it sits behind
a plausible red herring — two uvicorn servers were briefly bound to port 8000
with different `SECRET_KEY`s, which explains 401s perfectly and was not the
cause.

## If sign-in fails again, check both

    lsof -nP -iTCP:8000 -sTCP:LISTEN     -- expect one server plus its reload child
    select email from users where is_admin  -- expect exactly one row

## Resolution

Verified fixed in the current code on 2026-10-01 (feat/user-stories-v2 @ 3b08b2ba8) by static review: a first-pass check and an independent adversarial re-check both found every claim of this card fixed. No tests were run for this closure.

**Fixed by:** b2a621f84 (Fix/cognito login, #8) — git log -S shows it removed break_glass_invariant_violated

**Evidence:** The card's two defects both stem from the break-glass single-local-admin invariant in resolve_principal. That invariant no longer exists. backend/app/core/identity.py:1-40 says local bcrypt/HS256 auth and the break-glass exemption are removed, so verify_credential accepts only Cognito RS256 tokens. identity.py resolve_principal (~l.128-175) is a lookup by cognito_sub plus a status check, with no admin count. A grep of app/ finds no break_glass_invariant_violated or unexpected_local_admin_count, and no admin count in identity.py, dependencies.py or provisioning.py. Defect 1: a second admin can no longer disable auth. admin.py:351-419 (change_role) goes through cognito_admin. Defect 2: the outage that produced the misleading 401 is gone. dependencies.py:82 still returns a flat 401, but only for genuinely invalid tokens.

**Left over (outside this card's claims):** none. Minor caveat: test_t6_two_admins_in_cognito only checks is_last_admin. It does not show that auth works with two admins, so that conclusion rests on reading the code. Also, app/api/auth.py still mentions "local/break-glass accounts" in comments and docstrings (lines 693, 888, 1054). Those are stale text only.
