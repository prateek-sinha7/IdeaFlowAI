# ISS-659

## Title

The Prototype pipeline (`prototype` / `prototype_revision` / `prototype_large_revision` /
`prototype_feature_revision`) routes through the exact same `withWorkspaceFile()` override
that QA-PS-007 ([ISS-651](20260917-1200-ISS-651.md)) found for `ppt`, and its on-disk
deliverable is equally a fixed, non-topic-derived filename — so the same collapse to a
generic name is expected here too.

## Status: INFERRED — not yet reproduced

Filed from the root cause of QA-PS-007, not from an independent reproduction. Whoever picks
this up should confirm it live before treating it as a confirmed defect (see "What would
confirm this" below).

## Why QA-PS-007's root cause implies this

QA-PS-007's root cause ([ISS-651](20260917-1200-ISS-651.md)) is two compounding facts: (1)
the backend agents write the deck to a **hardcoded, non-topic-derived** on-disk filename, and
(2) `withWorkspaceFile()` (`frontend/src/components/results/FilesTab.tsx:451-462`)
unconditionally replaces the content-derived row name with that raw on-disk basename. Both
halves reproduce identically for the prototype pipeline:

1. **Backend half — confirmed by direct read**, mirroring `ppt-composer`'s
   `presentation.html`:
   - `backend/agents/prompts/prototype-build/AGENT.md:62-64` — "Write the result to
     `prototype.html`" / `write_file(file_path="prototype.html", content=<full html>)`,
     for every task in the per-task build loop, never interpolated with the run's topic.
   - `backend/agents/execution_engine/engine.py` falls back to the literal string
     `"prototype.html"` in at least 8 places (e.g. lines 7666, 8719, 8792, 8988, 9104, 9786,
     11408, 14182) — the engine itself treats this as the fixed, known deliverable name for
     every prototype run.
   - `backend/CLAUDE.md`'s own Data Flow section documents this as intentional: "deliverable
     read back from the RunSandbox disk: - prototype/revision: `prototype.html`."

2. **Frontend half — confirmed by direct read**, the same call site QA-PS-007 traced:
   `frontend/src/components/results/FilesTab.tsx:657-666` applies `withWorkspaceFile` to
   `derivedFiles[0]` for **any** `workflowType`, gated only by excluding the
   `prototype-figma-json` **companion** row (line 664: `if (firstRow.id !==
   "prototype-figma-json")`) — the primary `prototype-html` row (built at
   `FilesTab.tsx:424-431`, which DOES correctly parse the deck's own `<title>` tag into a
   topic-derived name) is not excluded and gets the same unconditional override.

## Expected (once reproduced)

A completed prototype run's Files tab entry and Download filename reflect the prototype's own
title/topic, e.g. `expense-tracker-prototype.html`.

## Actual (inferred, not yet observed)

The Files tab entry and downloaded filename for a prototype run are always `prototype.html`,
regardless of the prototype's actual product/topic name — the content-derived name computed
at `FilesTab.tsx:427-429` is silently discarded the same way QA-PS-007 describes for `ppt`.

## What would confirm this

1. Sign in as `qa-admin@flowinqa.com`, open a completed `prototype` (or `prototype_revision`)
   run whose generated `<title>` is not the literal default.
2. Open the Files tab and read the Final Output filename.
3. Click Download and check the saved filename.
4. If both show `prototype.html` instead of a topic-derived name, this is confirmed.
