# FIX-783

**Register source:** `QA-KB-124` (`LEDGER.md`), 5-fixer second pass, 2026-10-09. This fix resolves the root
[ISS-1156](20261009-1445-ISS-1156.md) and the sibling [ISS-1182](20261009-1708-ISS-1182.md). It follows the root card's
"Re-analysis", items 1 and 2, as written. The whole change is in `evidence/qa-kb-124/fix-02-change.diff`: two files, +18/-1,
and 12 of the added lines are comments. `factory.py` and `engine.py` are byte-identical at `4a2be7e27`, `06e45b9cc` and
`465b43b8d`. The change is uncommitted in the working tree.

## What was wrong

This section is taken from the root card, not re-derived. `_compose_system_prompt` appends `## How to deliver ... Call
write_file with path <step>-<topic>.md` to every custom-agent step that holds `write_file` (`factory.py:727` at HEAD). A
conditional gate parses only its decision step's reply (`conditional.py:226-258`). A write-granted decision step obeyed
the block. This happened on admin's stored `ex_A1_loop` override and would also happen on a Composer step left at the
default grants. The step wrote `{"decision": "retry"}` to a file and replied in prose. The gate found no outcome, and the
run failed with "Check's conditional gate had nowhere to route".

The first fix pass found the card's original predicate inert. `"route_decision" in spec.produces` never fires at run time
because `create_runner` reloads the spec by id (`factory.py:350`). For `custom-agent:<id>`, that returns the blank template,
which declares no `produces` (`loader.py:164-167`). The step's declared `produces` exists only on the engine's overlaid
spec (`_specs_from_plan`, `engine.py:4033-4035`).

## What changed, and where

- **`backend/agents/factory.py`.** A new `AgentContext.step_produces: list[str]` field (default `[]`, `:158-163`), placed
  beside the other per-step fields. At the delivery block (`:733-740`), the block is skipped when `route_decision` is in
  `spec.produces + ctx.step_produces`. The union follows the existing merge of `step_injects` with `spec.injects`
  (`:608-610`).
- **`backend/agents/execution_engine/engine.py:9855-9858`.** The `AgentContext(...)` built in `_run_agent` passes
  `step_produces=list(getattr(spec, "produces", None) or [])`. That is the same `spec` that `_is_decision_step` (`:10672`)
  and the typed artifact write (`:10801`) read, so the three cannot disagree. Every dispatch of a decision step goes
  through this one construction: serial dispatch, loop re-entry, resume, the route trigger and the throttle retry, which
  reuses `ctx` (`:10504`).

This is a prompt change. The block that caused the failure is a prompt template, and the engine edit only carries one fact
the engine already holds. It adds no import. It adds no `pipeline_type` or `spec.id` branch.

**Who it touches.** Only a step that is both a decision source and write-granted. None of the shipped decision steps
holds a write grant (`evidence/qa-kb-124/analysis-10-builtin-decision-step-grants.txt`). The characterization goldens give
identical results before and after the change (below).

**Not done here:**

- The optional `## How to answer` sentence (re-analysis item 3) was skipped. It is INFERRED, and nothing measured it.
  Omitting the block is what the test and the probe measure. Add the sentence if a live Haiku run shows a write-granted
  decision step still writing its decision to a file.
- The other `AgentContext(` sites keep the default `[]`: `kernel_services.py:2134` (the validation fix loop),
  `chat_runner.py:131` and `evals/minimal/run.py`. None of them can be a gate's decision source.
- These siblings stay open and are not part of this change:
  - [ISS-1181](20261009-1708-ISS-1181.md): the frontend grant flip in `userWorkflows.ts:335-345`. It has no test, and its
    globs overlap QA-KB-116's ISS-1157.
  - [ISS-1183](20261009-1708-ISS-1183.md): nine enabled override rows on admin (data and test hygiene).
  - [ISS-1192](20261009-1832-ISS-1192.md): a looped write-granted step cannot overwrite its pass-1 delivery file on pass 2.
    It is reachable now that the gate routes.
  - [ISS-1128](20261008-2134-ISS-1128.md): save drops `produces`/`consumes`.

## Live acceptance (for the 6-verifier, from the root card)

`gate_blocked` row. Do not require `completed` or a meaningful `greeting.md` from the stored copy, because ISS-1128,
ISS-1181 and ISS-1192 still apply to it.
