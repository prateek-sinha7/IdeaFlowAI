# ISS-965

**INFERRED, not reproduced.** Derived while analysing QA-KB-050 ([BUG-025](20260827-BUG-025.md)). Every link below was
read in source; what has not happened is anyone driving the screen and reading the result. An unreproduced sibling is a
lead, not a defect.

Line numbers are the working tree on 2026-10-02 (HEAD `024c03ef8`). `ComposerPage.tsx`, `AgentsPopup.tsx`,
`DashboardLayout.tsx`, `page.tsx` and `SavedWorkflowsPage.tsx` carry uncommitted edits from other work, so their numbers
can be a few higher than at HEAD; `CanvasNode.tsx`, `AgentRow.tsx`, `CanvasView.tsx` and `AgentLibrary.tsx` are clean
against HEAD. The shared mechanism (the composer reads DashboardLayout's `workflowType`, which is `user_stories` on every
composer route except a built-in's canvas) is proved in [BUG-025](20260827-BUG-025.md)'s analysis section and in
`evidence/qa-kb-050/`; it is not repeated here.

## Condition

A custom composition near the root-agent cap while the composer holds the shared `workflowType` instead of `custom`.

## Why the root cause implies it (each step read)

- `ComposerPage.tsx:650-654`: `defaultAgentIds` is the id set of library agents whose `pipeline_type` matches `workflowType`;
  `optionalCount` is the roster minus that set; `canAddMore = optionalCount < MAX_OPTIONAL` (`treeLayout.ts:13`, 16).
- `ComposerPage.tsx:716-717`: `addAgent` re-checks with the same exemption (`const currentOptional = prev.filter((a) => !defaultAgentIds.has(a.id)).length;
  if (currentOptional >= MAX_OPTIONAL) return prev;`).
- `useAgentLibrary` (`frontend/src/hooks/useAgentLibrary.ts:28-36`) builds `libraryAgents` from every agent that is **not** custom,
  so with `workflowType === "custom"` the set is empty and the cap counts every root agent. With the stale `user_stories` the six
  user_stories agents are exempt, so the effective cap is 22, not 16.
- The exemption is right for a built-in's canvas (the roster the built-in came with is not "added"); it is wrong for a custom
  composition. `canvasPipelineType` ([BUG-025](20260827-BUG-025.md) fix) gives both for free.

Severity is low: the cap is a frontend-only guardrail (`ComposerPage.tsx:193-199`, "nothing on the backend caps root-step
count"), and reaching it needs 16 root agents.

## Expected vs actual

- **Expected:** a custom composition stops accepting root agents at 16 and the Add control shows "Maximum 16 root agents are allowed".
- **Actual (derived):** with `user_stories` agents on the canvas the limit moves up by their count.

## Why this is INFERRED, and what settles it
