## What was wrong

`SkillManager.tsx`'s `deleteSkill` callback (the "Delete" button at `:221`, rendered when
`skillContent` is non-empty) fired `DELETE /api/agents/skills/{agentId}` immediately on click
with zero confirmation — the identical anti-pattern ISS-320 documented for the Constitution
"Clear" button. The backend delete is a hard delete with no undo.

## What changed and why there

`frontend/src/components/workflow/SkillManager.tsx` — one early return added at the top of
`deleteSkill`, before any state or network call:

```tsx
if (!window.confirm(
  "Delete this agent's saved skill? This permanently removes the SKILL.md that is prepended to every run."
)) return;
```

Same `window.confirm` pattern FIX-385 used in `AccountSettings.tsx:handleDelete`. Placed in the
handler (not the button), so every future caller inherits the guard. The autouse
`dismiss_native_dialogs` fixture in the e2e suite will dismiss this dialog, making "Delete" a
no-op in e2e tests unless the test explicitly accepts it — same consequence as noted in FIX-385
for `AccountSettings`.
