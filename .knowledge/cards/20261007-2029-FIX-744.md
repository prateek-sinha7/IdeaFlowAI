# FIX-744

This fix closes bug report QA-KB-087. The root causes come from the cards and are not re-derived here:
[ISS-945](20261002-0053-ISS-945.md) is the root, and [ISS-1036](20261002-1117-ISS-1036.md),
[ISS-1039](20261002-1131-ISS-1039.md) and [ISS-1040](20261002-1131-ISS-1040.md) are the siblings fixed with it. The fifth card,
[ISS-1041](20261002-1133-ISS-1041.md), was not applied here; see "Not done here" below. Only frontend tests changed: no product
source, backend, engine, migration or import-linter surface is touched. The diff is `evidence/qa-kb-087/fix-08-diff.txt`: 9 lines
in 3 test files.

## What was wrong

Each case below is an `it.fails` case that stopped in its own harness before it reached its behavioural assertion. So each one
read "expected fail" whatever the app did, and could never show the XPASS that marks its bug fixed.

- **ISS-945.** `AccountSettings.iss372.test.tsx:16` mocked `getConstitution` in memory, and `:83` then waited on
  `waitFor(() => expect(fetch).toHaveBeenCalled())`. The real load is `getConstitution(token)` (`AccountSettings.tsx:626`), and it
  never reaches `fetch`. Only Save (`:647`) and Clear (`:680`) do, and no case clicks either. The case therefore timed out after
  about 1.2 s on every tree. Before the fix it ran as "1 expected fail" in 1203 ms (`fix-01-before.txt`, B1).
- **ISS-1036.** The same `:16` resolved `{ content: "" }`, so the guard's saved value was always `""`. The not-dirty-after-load
  assertion (now `:84`) could not fail. A load that forgets `setLoadedValue(loaded)` (`AccountSettings.tsx:635`) passed with
  ISS-945's fix alone (`fix-03`, `only945_m1`: 1 passed).
- **ISS-1039.** In `LibraryPage.copyFeedback.test.tsx:27`, the `next/navigation` factory defined `useParams: () => ({})` as a plain
  arrow. That made `vi.mocked(useParams).mockReturnValue(...)` at `:98` and `:117` a `TypeError`. With the markers removed, both
  cases fail at `:98:26` and `:117:26` (`fix-05`, `lib_head_marker_off_real`). FIX-395's "Copy failed" feedback had shipped long
  before.
- **ISS-1040.** `IntegrationsCard.copyFeedback.test.tsx:94` scoped `within()` to `.closest("div")` of the "New key — copy now"
  title. That is the title div itself (`IntegrationsCard.tsx:383`), and it holds no button. With the marker removed, the case
  throws `Unable to find an accessible element with the role "button"` at `:96:21` (`fix-05`, `int_head_marker_off_real`).

## What changed, and why there

Each defect was in the case's own harness, so each fix is there. Every card prescribed the edit and locked the product file as
correct. This is the legitimate kind of test edit: the cards established that the HARNESS was wrong, not the expected behaviour.
Every repaired case was then shown to fail against a mutant of the behaviour it guards. A green run alone is not that proof.

- `AccountSettings.iss372.test.tsx`
  - ISS-945: deleted `:83` (`waitFor` on `fetch`), and swapped the now-unused `waitFor` in the `:9` import for `act`.
    `it.fails(` became `it(` on `:78`.
  - ISS-1036: `:16` now resolves `{ content: "saved rules" }`. `await act(async () => {});` replaces `:83`, between
    `findByRole("textbox")` and the negative assertion, so the parent's `onUnsavedChange` effect has flushed before the case
    reads it.
  - The file is byte-identical to the analyzer's measured variant `d2_nonempty_act`
    (`evidence/qa-kb-087/scratch/d2_nonempty_act.test.tsx.txt`), apart from that variant's two scratch-harness rewrites (the import
    path and `__dirname`).
  - The deleted `:83` asserted on a channel the file's own mock removes. It was a synchronization step, not a product claim:
    `findByRole` only resolves once the load has settled, because the textarea renders only after `.finally(() => setLoading(false))`.
- `LibraryPage.copyFeedback.test.tsx`
  - ISS-1039: `:27` is now `useParams: vi.fn(() => ({}))`, and `it.fails(` became `it(` on `:91` and `:113`.
- `IntegrationsCard.copyFeedback.test.tsx`
  - ISS-1040: `:94` now uses `.parentElement!`, which is the banner container (`IntegrationsCard.tsx:382`), and `it.fails(`
    became `it(` on `:72`.

The `it.fails` -> `it` flips on these case lines are part of each card's prescribed fix. Each repaired case is its own proof. The
red test the 4-test-writer left for ISS-945 is a separate file, `AccountSettings.iss372.meta.test.ts`, and its two `it.fails`
markers are left for the 6-verifier, as the line requires.
