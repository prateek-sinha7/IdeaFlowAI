# ISS-841

## Description

[ISS-813](20260922-1854-ISS-813.md) was filed INFERRED — "not yet reproduced or
measured — filed as a lead, not a confirmed defect", and its own § *Expected vs
actual* says "Actual: unmeasured … Settling it needs a `next dev` network
capture on both routes". This card is that capture. **It does not reproduce.**

The 5-fixer built the guard ISS-813 prescribes (an in-flight promise Map inside
`userWorkflowsApi.get()`, keyed by id + token), measured no difference, and
**reverted it** rather than leave a speculative guard in the tree. Nothing under
`frontend/src/store/api/` changed for QA-PS-041.

## Evidence

Playwright (`channel="chrome"`, fresh context, `auth_token` injected so the
first render is already authenticated), dev server on :3000, backend on :8000.
Counted with `performance.getEntriesByType('resource')`, which is scoped to the
**current document** and so cannot borrow a request from a previous page.

| route | guard present | row fetches in that document |
|---|---|---|
| `/workflows/a7c7df2e-…` (cold `goto`) | yes | **1** (`1913.4 → 2016.7ms`) |
| `/workflows/a7c7df2e-…` (cold `goto`) | **reverted** | **1** (`1836.8 → 1958.3ms`) |
| `/workflows/a7c7df2e-…/edit` (cold `goto`) | reverted | **1** (`1729.9 → 1832.4ms`) |

Same number with and without the guard, on both routes ISS-813 names. The
mechanism ISS-813 reasoned from is real elsewhere — it is exactly what
[FIX-627](20260922-2050-FIX-627.md) fixed for the LIST endpoint on the same bug
(2 → 1) — but these three single-row effects
(`frontend/src/app/[...view]/page.tsx:3777` `/edit`, `:3833` `/workflows/{id}`,
`:3923` `/workflows/{id}/run`) do not double in this build.

Note the blast radius moved since ISS-813 was written: it names two effects,
there are now **three** (`grep -n "\.get(workflowId)" 'frontend/src/app/[...view]/page.tsx'`
→ 3777, 3833, 3923). Any future fix still belongs in `userWorkflowsApi.get()`
for that reason.

## Why the two tests read 2x anyway

`test_workflow_detail_view_fetches_the_row_once` and its `/edit` twin both do:

```python
wid = workflow_id(page, L.OVERRIDE_TITLE)   # ← ends by CLICKING "Edit"
requests = _collect_requests(page)          # ← listener attaches HERE
page.goto(f"/workflows/{wid}")
```

`workflow_id()` (`suites/05_saved_workflows/test_saved_workflows.py:65-75`)
navigates to `/workflows/{wid}/edit` by clicking the kebab item and returns as
soon as `page.wait_for_url("**/workflows/*/edit")` matches — which is **before**
that page's own mount effect has fired its `GET /api/user-workflows/{wid}`. The
listener then attaches, the edit page's single fetch lands under it, and
`page.goto` starts a new document that fetches the same URL once more. Two
documents, one fetch each, counted as one page's two.

Replaying the test's exact sequence and splitting by document:

```
page.on("request") across the whole window:
     104.9ms  http://localhost:8000/api/user-workflows/a7c7df2e-…   ← /edit document
     978.7ms  http://localhost:8000/api/user-workflows/a7c7df2e-…   ← /workflows/{id} document
resource entries of the FINAL document only:
     758.6 -> 1607.4  http://localhost:8000/api/user-workflows/a7c7df2e-…   (ONE)
```

## The Duplicate test

Unrelated to ISS-813 but found in the same pass, and the reason
`test_reopening_duplicate_menu_mid_request_does_not_double_post` stays red even
though [FIX-627](20260922-2050-FIX-627.md) fixes what it describes: its throttle
is `time.sleep(2)` inside a **sync** Playwright route handler
(`test_qa_ps_041_workflows_duplicate_requests.py:100-105`). A sync route handler
runs on the driver thread, so the sleep blocks the very `wait_for_timeout(300)`
and second click that are supposed to overlap the first POST — by the time the
second Duplicate is clicked, the first request has already settled and the
in-flight guard has correctly cleared. Two POSTs then are two separate intents,
not the race.

Replaying the identical steps through the **async** API, where
`await asyncio.sleep(2)` in the handler leaves the driver free:

```
guard reverted (git stash) → POSTs: 2
guard in place             → POSTs: 1
```

## Disposition

Not a code defect. Two outcomes are available and both are someone else's call:

- **ISS-813** — settle as non-reproducing (supersede it with this card) and drop
  its two tests, or keep it open for the client-side-nav entry path, which this
  capture did NOT cover (both measurements are hard `goto`s, the same entry path
  the tests themselves use).
- **The three tests** — the 4-test-writer's to re-scope, not the 5-fixer's: the
  two row tests need their listener attached after the `/edit` page has settled
  (or the id read from the API rather than from a click-through), and the
  Duplicate test needs a delay that does not block the driver. **No test was
  edited for this card.**
