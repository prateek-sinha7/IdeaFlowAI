# ADR-0006: Per-step skill scoping is enforced by pruning, not wiping

## Context and Problem Statement

Spec 012 R-01 gives each step its own `skills:` list. The runner stages those into
`<sandbox>/skills/<id>/SKILL.md`, and deepagents advertises whatever it finds by scanning
that directory.

The sandbox is **shared across every step of a run** — that is deliberate, it is how
files written by one agent reach the next. Staging only ever wrote; nothing removed a
previous step's directories. So per-step scoping was advisory, not enforced: a later step
could read a `SKILL.md` off disk that was never attached to it.

This is not hypothetical. In a live run of `sample_subagents`, the `fact` step browsed the
directory, found the `emoji` skill left behind by the previous step, and emitted a bare
emoji instead of a fact. The step's own `skills: [playful-tone]` was ignored in favour of
a leftover.

## Considered Options

1. **`shutil.rmtree` the whole `skills/` directory at the start of every `stage_skills`
   call**, then write this step's set.
2. **Prune only directories not in this step's attached set**, leaving re-attached skills
   untouched on disk.
3. **Give each step its own subdirectory** (`skills/<step>/<id>/SKILL.md`) and point
   deepagents at the per-step path.

## Decision Outcome

**Option 2.**

```python
_attached_ids = {(p.get("id") or p.get("name")) for p in attached_skills}
_attached_ids.discard(None)
stale = [d for d in resolved_skills_dir.iterdir()
         if d.is_dir() and d.name not in _attached_ids]
for d in stale:
    shutil.rmtree(d, ignore_errors=True)
```

Option 1 was implemented first and **broke idempotency**: staging the same set twice must
not rewrite `SKILL.md`, which `test_create_runner_skill_staging_is_idempotent` asserts. A
blanket wipe rewrites every file on every step. Pruning preserves the contract — a skill
attached again keeps its existing file untouched.

Option 3 is cleaner in principle and was rejected as too large for this change: it moves
the `sources=[...]` path deepagents is given, which is a runner-contract change affecting
every agent, not just composed ones.

The prune runs **before** the no-skills-attached early return, deliberately. With nothing
attached the attached-id set is empty, every directory is stale, and the step correctly
inherits nothing.

## Consequences

**Positive.** R-01 is enforced rather than advertised. The observed emoji-for-a-fact
failure cannot recur. Idempotency holds, so the existing test still passes unchanged.

**Negative — the prune set is per-step, which is wrong under concurrency.** If two steps
ever run at the same time, step A (skills `[x]`) computes every directory *not* `x` as
stale and deletes `y` while step B is writing or advertising it; symmetrically B deletes
`x`. Whichever call lands last wins, and the loser's skill vanishes silently —
`ignore_errors=True` means no exception is raised. `RunSandbox` (`sandbox.py:138-163`) has
no locking at all.

This is inert today because the engine's step loop is strictly serial, and it is recorded
here rather than fixed because the fix depends on a concept that does not exist yet: the
prune set must become the **union of the whole wave's** attached skills. A lock would not
help — it would serialize a prune set that is still wrong.

**This is a hard prerequisite for step-level parallelism**, not a follow-up to it. See
`specs/012-per-agent-skills-custom-agents/reports/step-fanout.md`.

**Neutral.** Pruning is best-effort — wrapped in a bare `except` and `ignore_errors=True`,
because staging must never raise into a run. A prune that fails leaves a stale skill
readable, degrading to the old behaviour rather than failing the step.

## Confirmation

`tests/agents/test_create_runner.py` covers staging, including
`test_create_runner_skill_staging_is_idempotent` which is what ruled out Option 1. 44
tests pass in that file.

**Gap:** no test asserts the prune itself — that a step with `skills: [b]` cannot see a
`SKILL.md` staged by a prior step with `skills: [a]`. That is the regression this ADR
exists for, and it is currently proven only by the live run that surfaced it.
