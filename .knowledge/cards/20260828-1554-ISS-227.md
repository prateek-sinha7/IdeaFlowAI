## Root cause

`frontend/src/proxy.ts` (Next.js middleware, matcher `/workflow/create`) reads the raw
`mode` query param and redirects with:

```ts
return NextResponse.redirect(new URL(`/create/${mode}`, request.url));
```

(`frontend/src/proxy.ts:10`). `mode` is passed through unsanitized into a template string
that is then handed to `new URL(...)`. `URL` resolves `..`/`%2e%2e%2f` path-traversal
segments in the pathname it is given, so a `mode` value containing a traversal segment
causes the constructed URL to resolve **outside** `/create/*` entirely — into whatever real
route the traversal happens to point at. Against a nonexistent target this only reaches the
app's own 404 (`../ppt` → `/ppt`), but against a real route it reaches that route directly:
`?mode=../admin` (and its percent-encoded form `?mode=%2e%2e%2fadmin`) redirects straight
into the live `/admin` console, which then renders for real and fires a genuine
`GET /api/admin/users` → `200 OK`.

## Reproduction (3/3, cycle 1)

All three cold-start cycles reproduced on the first attempt (cycle 1 of 3), from a
fresh, independent navigation each time — no timing/entry-path/account/theme axis needed:

1. Signed in as qa-admin (session confirmed via `!!localStorage.getItem('auth_token')`).
2. Navigate directly to `http://localhost:3000/workflow/create?mode=../admin`.
   `location.href` settles on `http://localhost:3000/admin`; the real Admin Dashboard
   renders (user table with 4 rows, stat tiles); `GET http://localhost:8000/api/admin/users`
   returns `200 OK`.
3. Cycle 2: navigated back to `/dashboard` first (full independent nav, not a soft re-click),
   then repeated step 2 — identical result, `location.href` → `/admin`, admin page renders,
   `200 OK` on `/api/admin/users` confirmed again via `browser_network_requests`.
4. Cycle 3: navigated back to `/dashboard`, then used the percent-encoded equivalent
   `http://localhost:3000/workflow/create?mode=%2e%2e%2fadmin` — identical result,
   `location.href` → `/admin`, admin console renders.

Conditions: tier qa-admin (enterprise + isAdmin), light theme (default), standard viewport,
deep-link entry path (direct URL navigation, not click-through), fresh and long-lived
sessions both produce the same result (no session-age dependency observed).

## Expected vs Actual

**Expected:** `/workflow/create?mode=<value>` should only ever navigate within its own
scope — to `/create/<sanitized-value>` (rejecting or stripping path-traversal segments) or
to a "mode not found" state. It must never construct a navigation target resolving outside
`/create/*`.

**Actual:** A `mode` value containing `../` or `%2e%2e%2f` escapes the `/create` namespace.
Against `/admin` specifically this lands on the live admin console with a successful
backend call — this session was already admin so it did not observe an authorization
bypass, but the underlying flaw (query-param-driven client-side navigation escaping its
intended namespace into unrelated, unrequested application routes, including a sensitive
one) is a genuine defect independent of whether every possible destination happens to be
separately guarded.
