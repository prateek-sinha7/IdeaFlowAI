## What is suspected

[ISS-190](20260828-1501-ISS-190.md) root-caused the `/create/prototype` permanent-blank-page bug
to `frontend/src/app/[...view]/page.tsx:3701`'s `if (!mounted || !isAuthenticated) { return
null; }` — the FIRST render-level `return` in the whole `DashboardPage` component, confirmed by
reading every top-level `if`/`return` between the function's start (`:344`) and that line. Both
`mounted` (`:416`, flipped by a `useEffect` with empty deps at `:490-492`) and `isAuthenticated`
(`:431`, flipped only inside the mount effect at `:806-827`, deps `[router, dispatch]`) are set
exactly once per component lifetime and never again.

Per ADR-0018, `[...view]/page.tsx` is the ONE catch-all every one of the app's 34 screens renders
behind — `/dashboard`, `/library`, `/settings/*`, `/history`, `/analytics`, etc. all reach line
`:3701` before any screen-specific branch. Nothing in that gate, or anywhere else in the file, is
specific to `/create/prototype` or to the wizard. The gate is upstream of the route.

## Condition

- Land on ANY route served by `[...view]/page.tsx` other than `/create/prototype`/`/create/ppt`
  (e.g. `/dashboard`, `/library`, `/settings/profile`) — normal render.
- Browser **Back** to a prior in-app route, then browser **Forward** back to the original route
  (the same sequence [ISS-190](20260828-1501-ISS-190.md) used, substituting the target route).

## Expected vs actual

- **Expected:** Forward re-renders that screen exactly as a fresh visit would, same as every
  other screen is assumed to behave.
- **Actual (predicted):** the same permanently blank body / raw un-executed RSC stream signature
  documented in [ISS-190](20260828-1501-ISS-190.md), on a route that has nothing to do with the
  prototype wizard — because the failing gate is shared code, not prototype-specific code.

## Why the root cause implies this

ISS-190's mechanism is entirely about `DashboardPage`'s own mount lifecycle (`mounted`,
`isAuthenticated`), not about anything the prototype wizard renders once past the gate. The gate
sits before the `parsedView.screen` branch that decides WHICH screen to show
(`frontend/src/app/[...view]/page.tsx:3710` onward). A defect in code that runs identically for
every screen, and produces a symptom keyed only to remount timing, has no route-specific reason
to spare any other screen — `/create/prototype` is simply the first one the hunter's route
sweep happened to land the Back/Forward sequence on.

**Marked INFERRED**: no route besides `/create/prototype` has actually been driven through this
sequence yet. What would confirm it: repeat ISS-190's exact repro
(`bug-hunter/velocity.json` recipe, Back then Forward with real `page.goBack()`/`page.goForward()`)
against `/dashboard` or `/library` instead, 3 cycles, cold start each time.
