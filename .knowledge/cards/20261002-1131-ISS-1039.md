# ISS-1039

Sibling of [ISS-945](20261002-0053-ISS-945.md), found by the QA-KB-087 analysis on 2026-10-02. The analysis ran every `it.fails` file in
`frontend/src` (26 files, 52 xfail cases) with the marker removed, on copies outside the repo, and read where each case really fails
(`evidence/qa-kb-087/07-analyze-itfails-scan.txt`). Confidence: CONFIRMED by that run; no repo file was edited. A validator re-run is
still pending.

## Why the root cause implies it

[ISS-945](20261002-0053-ISS-945.md) is an `it.fails` case that never reaches its behavioural assertion, so it can never show the XPASS
that marks its bug fixed. This file is the second place where the same is true because of the case's own setup.
[ISS-600](20260829-0341-ISS-600.md) found the original harness defect (an empty `useParams` closes the detail modal before the Copy
click lands), and [FIX-453](20260901-1600-FIX-453.md) applied the repair: a per-test
`vi.mocked(useParams).mockReturnValue({ view: [...] })` at `:98` and `:117`. It left the factory's own `useParams: () => ({})` at `:27`
a plain arrow, and a plain arrow has no `mockReturnValue`.

## Condition

Remove `it.fails` from either case (on a copy; the repo file stays) and run it.

## Expected

The case reaches `expect(screen.queryByText(/fail|error|couldn.?t/i)).toBeInTheDocument()` and passes, because the app now shows
"Copy failed" when `writeText` rejects: the `useClipboardCopy` hook from [FIX-395](20260829-0338-FIX-395.md), rendered at
`LibraryPage.tsx:249` and `:369`. [ISS-331](20260828-1840-ISS-331.md) and [ISS-555](20260829-0208-ISS-555.md) are both resolved.

## Actual

`TypeError: vi.mocked(...).mockReturnValue is not a function` at `LibraryPage.copyFeedback.test.tsx:98:26` and `:117:26`, 3 ms and 0 ms
into the case. Under `it.fails` both read "expected fail" (the shipped file, run in place, is green), so the Copy feedback has no
working regression guard, and the note in FIX-453 that the markers stay "because ISS-331 / ISS-555 are not fixed here" is out of date.

## Evidence

`evidence/qa-kb-087/08-analyze-itfails-wrong-reason-probes.txt`, section S-A: marker removed gives `Tests 2 failed (2)` with the two
TypeErrors above; with the one-line fix below it gives `Tests 2 passed (2)`.

## Fix direction

Test file only; `LibraryPage.tsx` is correct and stays untouched.

1. In the `vi.mock("next/navigation")` factory change `useParams: () => ({})` (`:27`) to `useParams: vi.fn(() => ({}))`.
2. `it.fails(` to `it(` on both cases (`:91` and `:113`).

For the 4-test-writer: a source meta-lock as for QA-KB-071 (`frontend/src/app/[...view]/terminalReopenReconcileLock.meta.test.ts`):
the file must not contain `vi.mocked(useParams)` while its factory defines `useParams: () =>`, and no `it.fails(` may remain on the
two titles. When this closes, append a one-line resolved note to FIX-453 and ISS-600; do not rewrite them.

## Resolution (QA-KB-087 fix, 2026-10-07)

Fixed test-only by [FIX-744](20261007-2029-FIX-744.md), as the fix direction above prescribes. `:27` is now
`useParams: vi.fn(() => ({}))`, and `it.fails(` became `it(` on `:91` and `:113`. `LibraryPage.tsx` is untouched.

- Marker off at HEAD: 2 `TypeError`s at `:98:26` and `:117:26`.
- With the fix: `2 passed`, both on a scratch copy and in place.
- With the fix, against a `LibraryPage` whose Copy-failed feedback is removed: both cases fail at the `toBeInTheDocument()`
  assertion (`:108`, `:123`), so they guard ISS-331 and ISS-555 again.

Evidence: `evidence/qa-kb-087/fix-05-probe-iss1039-iss1040.txt` and `fix-02-after.txt` A4. The one-line notes for FIX-453 and
ISS-600 that this card asks for "when this closes" are left to the verifier.
