# ISS-1045

**Evidence status.** INFERRED sibling of [ISS-1042](20261002-1100-ISS-1042.md) (3-analyzer, 2026-10-02, QA-KB-094). The defective string is CONFIRMED by reading `tools/api/runs/run.ex_A4_human_gate.http:95`. That pasting it blocks a run is INFERRED from the identical server path ISS-1042 reproduced: nobody has pasted this hint against a live run. What would settle it: answer a paused `ex_A4_human_gate` run with exactly the printed body and read `gate_blocked` then `pipeline_failed`. The offline equivalent, `evidence/qa-kb-094/probe-offline-bare-word-vs-json.py` case A, already shows that outcome for the same `edited_content`.

## What is wrong

When the interactive runner reaches the human gate it prints a box for the person at the keyboard (`run.ex_A4_human_gate.http:87-96`):

    Answer in the UI, or paste this (swap the language):
      curl -s -X POST <api>/api/runs/<id>/gate \
        -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
        -d '{"gate_key":"<key>","action":"approve","edited_content":"spanish"}'     (:95)

`ex_A4_human_gate` routes on `condition_agent: ask` (`workflow.yaml:111`), so the human's edit IS the routing decision, and `ConditionalGate._read_decision` (`conditional.py:208-267`) only accepts the JSON object `{"decision": "<outcome>"}` ([ADR-0026](20260825-1600-ADR-0026.md); the UI chips send exactly that, `InlineGateActions.tsx:320`). "Swap the language" invites `english` or `dutch`, each as bare as `spanish`.

## Expected vs actual

Expected: the pasted command routes the run to the language chosen, and the script's choice-agnostic assertions (`:109-196`) pass for any of the three. Actual: the edit lands on `ask` as the raw word, the gate returns `GATE_BLOCK` ("no matching route outcome and no default_next"), the run ends `pipeline_failed`, and the assertions print `✗ expected exactly one branch, got 0` and `✗ pipeline_complete not found`. The UI path offered in the same box is fine.

## Why the root cause implies it

Same drift as ISS-1042, second caller. The decision source moved to the human's raw edit in `0b6570b85` (2026-08-25) and neither `.http` runner was updated (both last touched 2026-08-24, `c9ec0149c`). The twin differs only in that its bare word is printed for a human to paste instead of POSTed by the script, so fixing the auto runner alone would leave it behind.

## Fix

Print the JSON-encoded decision object as the `edited_content`, and say in the box that the answer is a decision object, not a word. The body passes through three escaping layers (a JS single-quoted string, shell single quotes, a JSON string holding JSON), so the printed text must read `"edited_content":"{\"decision\":\"spanish\"}"` and the JS source needs those backslashes doubled. Keep `edited_content` and `decision` on one line so the static check described in [ISS-1042](20261002-1100-ISS-1042.md) can read this file too. Land it with ISS-1042's fix (one commit, runner files only); no engine change.

## Test notes

No separate live test is needed: ISS-1042's static test iterates both runner files. A regex over this file must tolerate the `\"` and `\'` escapes inside the JS string at `:95`.

## Resolution (QA-KB-094 fixer, 2026-10-07)

Resolved by [FIX-750](20261007-2108-FIX-750.md).

- The hint at `run.ex_A4_human_gate.http:97` now prints `"edited_content":"{\"decision\":\"spanish\"}"`.
- The box text at `:94` tells the human to keep the `{"decision": ...}` object, because a bare word blocks the gate.

The hint is built with a `String.raw` template, not the doubled backslashes proposed above. The printed text is
byte-identical, checked by evaluating the real line in Node: `edited_content` parses to `{"decision":"spanish"}`.
The test's `_edits` regex cannot read the doubled form; FIX-750 records the detail.
`test_interactive_runner_hint_prints_json_decision` went from XFAIL to XPASS(strict).
