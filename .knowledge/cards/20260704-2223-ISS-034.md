# ISS-034

## Title

Optional dollar-savings — surface cache $ saved. Backend would emit `estimated_cost_full_usd` (cost as-if-uncached) → FE shows "saved $Y (Z%)". Needs a backend add-on (per-model rates live backend-side per INV-12); explicitly NOT built in FIX-037 (which shows only the cache token count + %).

## Severity / Tag / Status (original row)

- Sev: minor
- Tag: product
- Status: **RESOLVED** by FIX-239 (quick-260812-mq5, 2026-08-12) — backend half + SIGNED Analytics line; no per-run badge

## Source / Evidence

Split out of quick-260704-uvs (FIX-037); companion to FIX-036/ISS-032. **BLOCKED-BY / DESIGN CORRECTION (2026-08-12, recorded during quick-260812-9tq):** (a) **Depends on ISS-033.** A "saved $Y" computed from a token base that is missing the fix-loop, the Concierge and the handoff agents publishes a precise-looking figure wrong in a direction the user cannot see — worse than showing nothing, because it invites trust. The *percentage* is fairly robust (numerator and denominator scale together); the *dollar* figure is not. Part A landed as FIX-230; the residual is ISS-092. (b) **The naive spec would render a WRONG-SIGNED number.** Computed across every run in the live `dev.db`: on **7 of 9 runs the saving is NEGATIVE** (−5.0% to −8.9%). Every `user_stories` run has `cache_read = 0` with a non-zero `cache_write` — its agents are single-turn text-only, so each writes a cache entry and nothing ever reads it back, and Haiku's `cache_write_5m` is **1.25×** the input rate. Hand-verified on `a7dba362`: `(3183·1e-6 + 40170·5e-6 + 86976·1.25e-6)·1.1 = $0.344028` (matches the persisted value) vs `$0.320110` uncached. The `+80.6%` aggregate is carried entirely by two long prototype runs and is NOT representative. So the FE contract must render a **signed delta** with an explicit negative case — never "saved $Y (Z%)". (c) Backend shape is unchanged and still small: one extra `estimate_cost_usd(model_id, input_tokens=_tok_in, output_tokens=_tok_out)` call at each of the two cost sites, plus `"estimated_cost_full_usd"` added to `_VOLATILE_STRIP_KEYS` exactly as FIX-036 did for the four cache keys (golden-neutral, no regeneration). (d) Falls out for free: prompt caching is a **measured net cost increase** on single-turn workflows, so `BEDROCK_PROMPT_CACHE_ENABLED` arguably belongs per-step rather than global.
