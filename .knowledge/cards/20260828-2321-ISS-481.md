## Sibling of ISS-320 (INFERRED — not yet reproduced)

Filed while analyzing **BUG-20260828-095800-settings-constitution-r2** (root card
[ISS-320](20260828-1802-ISS-320.md): the Constitution "Clear" button fires an immediate,
unconfirmed `DELETE` on click). This is a third and fourth instance of the identical
anti-pattern — two destructive backend calls, both wired directly to a button's `onClick`
with no `window.confirm`, no modal, no two-step gate — in a third component. (`SkillManager`
is the second instance, filed as [ISS-480](20260828-2320-ISS-480.md).)

## Why the root cause implies this

Confirmed via direct read: `grep -n "confirm(" frontend/src/components/handoff/IntegrationsCard.tsx`
returns no matches — the whole file has zero confirmation gates, matching the app-wide
absence already established for [ISS-480](20260828-2320-ISS-480.md) (`window.confirm` appears
exactly once in the entire frontend, and it is a navigation guard, not a delete confirmation).

Two independent destructive call sites in this one component share the flaw:

- `handleDeletePat` (`frontend/src/components/handoff/IntegrationsCard.tsx:123-139`) calls
  `deleteGithubPat(token)` synchronously, then `setPatStatus(null)` on success. Wired to
  `onClick={handleDeletePat}` at `:245` ("Remove" button), rendered whenever a PAT is
  currently connected.
- `handleRevoke` (`frontend/src/components/handoff/IntegrationsCard.tsx:161-176`) calls
  `revokeApiKey(token, id)` synchronously for a specific key. Wired to
  `onClick={() => handleRevoke(k.id)}` at `:360`, rendered per listed API key.

Both remove account-level credentials permanently and immediately on a single click, with no
opportunity to cancel.

## Expected vs actual

**Expected:** removing a connected GitHub PAT, or revoking an API key — both irreversible,
account-wide, security-relevant actions — require an explicit confirmation step before the
`DELETE` fires, consistent with the fix expected for ISS-320.

**Actual (inferred, unverified):** clicking "Remove" next to the connected PAT, or the revoke
control next to a listed API key, should delete/revoke on the backend immediately with no
confirmation dialog, exactly as ISS-320 describes for the Constitution "Clear" button.

## What would settle it

Reproduce in the browser: on `/flowin-handoff`, connect a GitHub PAT and click "Remove" (or
create an API key and click its revoke control), and confirm no confirmation prompt appears
before the `DELETE`/revoke call fires.

## Where a fix belongs

Same gap as ISS-320 and [ISS-480](20260828-2320-ISS-480.md): no shared confirm-before-destroy
primitive exists in `frontend/src/components/ui/` for any of these four call sites (Constitution
clear, skill delete, PAT remove, API-key revoke) to route through. A fix scoped to only one
component leaves the others broken.
