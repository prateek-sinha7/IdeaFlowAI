# FIX-615

Fixes **QA-PS-028** — `LEDGER.md` / `BUGS.md#qa-ps-028`. Resolves
[ISS-730](20260922-1343-ISS-730.md) (root, reproduced),
[ISS-772](20260922-1512-ISS-772.md) and [ISS-773](20260922-1512-ISS-773.md)
(inferred siblings).

## What was wrong

A final compiling/aggregation step (`backlog-compiler`, step 6/6 of
`user_stories`) reads every prior step's `.agents/NN-*.md` output and compiles the
deliverable. When it dropped an entire epic, nothing anywhere noticed: its own
`Total Epics` counter counted only what it kept, the step raised nothing, and
`pipeline_complete` published `"completed"` under a green "Done" badge. The user
downloads a backlog missing content they watched `epic-architect` produce, with no
signal at any layer. Reproduced on run `e2903536` (BUGS.md) and on two independent
DB cycles in [ISS-730](20260922-1343-ISS-730.md).

## Root cause — two layers, both confirmed by direct read

**1. Engine (the shared gate).** `_execute_impl`'s terminal completion block is the
ONE place every pipeline type's status converges. Pre-fix it flipped to
`"degraded"` on exactly four signals, and a compiling step that returns normally
after omitting a section trips none of them:

- `_unrecovered_agents` — built from `ectx.failed_invocations`, i.e. invocations
  that RAISED (`engine.py:7381-7400`).
- `ectx.budget_degraded_reasons` — a budget/loop cap (`engine.py:7415-7420`).
- `ectx.last_commit_blocked` — a blocked pre-commit hook (`engine.py:7426-7427`).
- `placeholder_narration_reason(final_output)` — the CONTENT signal
  [ISS-721](20260922-1242-ISS-721.md) added at `engine.py:7450`. It is bounded to
  `len(text) <= 2000` by design (`_placeholder.py:_MAX_NARRATION_CHARS`), so it
  structurally cannot see QA-PS-028's shape: a 19,581-char, well-formed compiled
  document that is merely missing one section. ISS-730's fix direction named this
  gap explicitly.

**2. Prompt.** `backend/agents/prompts/backlog-compiler/AGENT.md` (pre-fix) carried
only prose — `"Include ALL epics and stories from previous agents"` — with no
requirement to enumerate what it read against what it wrote. The three
`*-sdlc-governance` agents share that exact shape
([ISS-772](20260922-1512-ISS-772.md)), and `user-story-revision-agent` recomputes
its Backlog Summary totals from whatever seed it is handed with no completeness
check ([ISS-773](20260922-1512-ISS-773.md)).

## What changed and why there

**`backend/agents/capabilities/deliverables/_coverage.py` (new, 100 lines).**
`dropped_section_reason(deliverable, sources)` — the sibling of `_placeholder.py`,
same module family, same doctrine (a false positive flips a user-visible success
badge, so the check is narrow by construction, not a general output-quality
judgement). It flags a source only when all three hold:

- the source has >= `_MIN_SECTIONS` (3) top-level ATX sections — "top level" is the
  shallowest heading depth in that document, so a source led by `##` still works;
- the deliverable reproduces >= 2/3 of them VERBATIM (integer math,
  `kept * 3 >= total * 2`) — the bound that keeps a compiler which paraphrases or
  renames everything from tripping it, because low coverage means synthesising, not
  copying;
- at least one sibling title is absent.

Only top-level sections count: a compiler legitimately rewrites, merges and
re-levels sub-headings, but a whole section vanishing while its siblings survive
verbatim is the reproduced defect. Stdlib-only (`re`) so the kernel can call it
without crossing an import-linter boundary, exactly as `_placeholder.py` does.

**`backend/agents/execution_engine/engine.py:7460-7490`** — the check, placed in the
SAME shared gate beside the four signals above. Its `sources` are the DECLARED
upstream sources of the step that produced the deliverable: the compiling spec is
`results[-1]["agent_id"]`, and upstream outputs are selected by the same
`produces`∩`consumes` registry routing `_filter_consumed_outputs`
(`engine.py:14910-14922`) already uses — read off `results` (always populated)
rather than the typed artifact graph. SC-001 holds: no `pipeline_type` or `spec.id`
branch, so one guard covers `backlog-compiler`, all three `*-sdlc-governance`
agents and any future step of that shape. `engine.py:7512` escalates
`published_status` alongside `_placeholder_reason`, because the finalizer runs in
the `finally` ABOVE — before the deliverable is resolved — and structurally cannot
carry either content signal.

**Four `AGENT.md` bodies** — the prompt layer ISS-730 asks for, which raises the
model's own bar but is explicitly not a substitute for the engine check:
`backlog-compiler` (enumerate every source file and its epic titles before writing;
`Total Epics` must equal the `# Epic:` heading count), `app-`/`dotnet-`/
`mulesoft-sdlc-governance` (one bullet added to each `OUTPUT CONTRACT`), and
`user-story-revision-agent` (verify the seeded backlog's own summary totals match
what is actually present before recomputing them). Frontmatter untouched on all
five — `test_contract_agents_frontmatter_frozen` pins three of them.

## Coverage-check behaviour (observed, `_coverage.py` driven directly)

```
FLAG   drop 1 of 3 (the bug)  -> "reproduces 2 of 3 top-level sections from
                                  upstream agent 'epic-architect' verbatim but
                                  omits 'epic: c' with no note of the omission"
FLAG   drop 1 of 4
quiet  all 3 kept                      quiet  source has no headings
quiet  kept 1 of 3 (synthesising)      quiet  no declared sources
quiet  source has only 2 sections      quiet  non-text deliverable (dict)
quiet  re-levelled H1->H2 kept         quiet  case/bold-insensitive kept
quiet  drop 2 of 4 (below the 2/3 floor)
```
