## What's broken

`test_the_files_tab_shows_the_pinned_versions_own_deliverable` (marked
`@pytest.mark.issue("ISS-300")`) in
`tests/integration/e2e/suites/21_run_families_and_versions/test_iss_230_version_pin_survives_tab_switch.py:95-115`
fails against a Files tab that is rendering the CORRECT pinned-version
deliverable:

```
AssertionError: Final output does not report the pinned v2 deliverable (83.5 KB):
'\n\nluxury-asset-marketplace-jets-yachts-car.html\n\nHTML (.html) · 83.6 KB · validated\n\n…'
```

The file's constants (`:26-27`) are

```python
V1_SIZE = "241.6 KB"   # 247,394 chars / 1024
V2_SIZE = "83.5 KB"    # 85,529 chars / 1024
```

and their comment says they were derived from the runs' `.output` **character**
lengths. `FilesTab` sizes every row as `formatSize(utf8Bytes(content))`
(`FilesTab.tsx:104,117,237,394,402,419,427,547,573,650`), and both deliverables
contain non-ASCII characters, so the real byte lengths — confirmed directly from
`GET /api/runs/{id}` — are 247,691 B (**241.9 KB**) and 85,624 B (**83.6 KB**).
Every displayed size is one tenth of a KB above the constant it is compared to.

Both assertions in the test are affected: the `V2_SIZE in final` check fails,
and the `V1_SIZE not in final` check now passes for the wrong reason (it would
not catch a genuine regression back to the root run's deliverable, because it
is looking for a string the app never renders either).

## Condition

Any run of that test file. Reproduced twice on 2026-08-29 at commit
`78e4500a3`: once with [FIX-411](20260829-1646-FIX-411.md) applied, once with
`frontend/src/components/preview/PreviewPanel.tsx` restored from `HEAD` — the
same failure, the same rendered `83.6 KB`. It is not a regression from that fix
and it is not a product defect; the UI figure is right and the fixture is stale.

## Expected vs actual

**Expected:** the constants describe what `formatSize(utf8Bytes(output))`
renders — `241.9 KB` / `83.6 KB` — so the assertion proves the pinned version's
own deliverable is on screen.

**Actual:** the constants describe `len(output) / 1024`, so the positive
assertion can never hold and the negative one is vacuous.

## Disposition

DEFERRED — found while regression-checking
[FIX-411](20260829-1646-FIX-411.md), outside that fix's cards. Left for whoever
owns the ISS-230/ISS-300 suite: correcting a test constant is a change to a test
file, and this bug line's rule is that application code is never bent to a test
and a red assertion is never edited just because it is red — the direction has
to be decided by someone holding the ISS-300 card, not by the fixer who
happened to run it.
