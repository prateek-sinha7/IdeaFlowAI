## The test, not the app

[FIX-403](20260829-0216-FIX-403.md) routed `LibraryPage`'s `SkillDetailModal` through the shared
`react-markdown` renderer, which is exactly what [ISS-591](20260829-0114-ISS-591.md) asked for. The
regression test's first assertion confirms it:

```tsx
expect(dialog.querySelector("strong, b")).not.toBeNull();   // PASSES after FIX-403
expect(/\*\*bold\*\*/.test(dialog.textContent ?? "")).toBe(false);   // FAILS, and always will
```

Observed by running the file with the `it.fails` marker stripped:
`AssertionError: expected true to be false` at
`LibraryPage.skillMarkdown.test.tsx:95` — line 94 (the `<strong>` check) had already passed.

The second assertion scans `dialog.textContent` — the **whole** `[role=dialog]`. That dialog contains
two sibling sections by design:

1. the "Formatted content" block (`LibraryPage.tsx:259-267`), now rendered markdown, and
2. the "SKILL.md content" block (`LibraryPage.tsx:270-287`), a labelled raw `<pre>{skill.content}</pre>`
   source view with its own "Copy" button.

Section 2 is the feature working: it is meant to show `**bold**` as literal characters.
`ISS-591`'s own Evidence section names it approvingly — "`:321-323` (the raw `<pre>` block that DOES
still exist here as a fallback, unlike `AgentSkillsPicker.tsx`'s modal which has ONLY that)". So the
only way to satisfy assertion 2 as written is to delete a deliberate, card-endorsed affordance. The
app was not bent to the test.

## What to change

Scope assertion 2 to the section the test's own title names ("in the **Formatted content** section"),
not the whole dialog — e.g. query within the formatted block rather than `dialog.textContent`, which
needs a `data-testid` on that container (`LibraryPage.tsx:266`) since it has no accessible role today.
Assertion 1 already carries the real signal and needs no change.

Until then `ISS-591` stays `open`: its fix is applied in
`frontend/src/components/library/LibraryPage.tsx`, but its `verification.test_files` cannot confirm it.
