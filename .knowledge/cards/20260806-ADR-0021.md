Local JWT authentication was replaced with Amazon Cognito. Recorded here at merge time
because the change arrived with no ADR and touches every authenticated request path.

## The decision

Cognito owns identity and group membership. The application keeps its own `users` row
(migration 0031 adds `cognito_sub`, `auth_provider`, `tokens_valid_from`,
`roles_synced_at`), so local/break-glass accounts still work — `auth_provider` defaults
to `'local'`.

**The browser still carries one bearer.** The Cognito refresh token is stored
server-side, encrypted (0032). `refreshAccessToken()` sends the CURRENT access token and
receives a fresh one, so the `getToken()`/`setToken()` seam the whole frontend is built
on did not change shape.

## Why this shape

Access tokens are short-lived (~60 min), so a mid-session 401 is usually an aged token
rather than an ended session. `fetchWithAuth` therefore tries ONE refresh, single-flighted
so a burst of simultaneous 401s mints only one, and only calls `handleSessionExpiry()`
when that refresh fails. Reversing that order logs users out roughly hourly.

MFA is TOTP or email OTP (1b6ebe4f2); `mfa_verified_at` (0034) is a session-bound proof
timestamp for the admin gate. Post-login routing sends everyone — admins included — to
`/dashboard`, returning to a `?redirect=` target only when it passes the internal-path
allowlist in `isSafeRedirectPath` (the open-redirect guard).
