## Root cause
`pipeline_complete.status = degraded` was set from `_unrecovered_agents`, built by exact triple membership
(agent_id, task_number, visit_count). A step that failed at visit 1 and completed at visit 2 stayed in the set, so the
run published `degraded` despite a valid `agent_complete`. `_drive_revision_to_queue` and `_reconcile_terminal_status`
had no cross-check against `agent_complete` events at all.

## Evidence level
The code locations above were read on 2026-11-07. Test counts (v3 regression 4, v4 engine visit-count 3, api
false-positive 7, INV-3 unchanged) are from commit `f4d0a1e96`'s message and were not re-run; `test_files` is empty
because the commit message names suites by label, not by path.
