# ISS-1024

Sibling of [ISS-908](20261001-2204-ISS-908.md) (QA-KB-080), derived from its provenance: the commit that made `wave_scheduler` a second `event_queue` caller (`1e329e47b`, 2026-09-04) updated the
fakes on its own line but not the prose that enumerates who passes the queue. Sibling status is INFERRED by the line's convention (derived, not a failing run); the textual contradiction itself is CONFIRMED by reading
both sides. Prose only, nothing executes differently.

## What the prose says, and what the code does

| where (HEAD `024c03ef8`; `git blame`) | says | the code |
|---|---|---|
| `backend/agents/execution_engine/kernel_services.py:1178-1181` (`24332e0c5`, 2026-08-14) | `event_queue` is for "a caller like parallel_group ... None for every other caller today (fanout_batch, wave_scheduler, the engine tool-result path) — unchanged, byte-identical." | `_fanout_wave_stream.py:71-73` passes `event_queue=child_events` for every wave (`wave_scheduler.py` is its only caller) |
| `backend/agents/execution_engine/fanout.py:354-358` (`24332e0c5`) | "(e.g. `parallel_group`). None (every other caller today) is a no-op — byte-identical." | same call; the weaker of the two, since "e.g." leaves room, but "every other caller" is no longer true |
| `backend/agents/capabilities/strategies/_fanout_stream.py:9-11` (`1e329e47b`) | "`parallel_group` had that merge inline; the wave scheduler needs exactly the same thing, so it lives here once." | `wave_scheduler.py:43` imports `stream_wave_fanout` from `_fanout_wave_stream.py`, whose own docstring (`:10-12`) says it is "a wave-specific COPY of `_fanout_stream.py`'s merge loop"; `wave_scheduler` never imports `_fanout_stream` |

The first two predate the wave change and were never revisited; the third was written in the same commit that contradicts it.

## Why it matters (one line)

These are where the next author learns who passes the queue. Reading the first one, a person writing a fake for a wave test concludes the wave scheduler sends no `event_queue` and writes the narrow
signature that is [ISS-908](20261001-2204-ISS-908.md).

## Fix (proposed, not applied)

Edit the three docstrings only: name `parallel_group` AND `wave_scheduler` as the `event_queue` callers (and `fanout_batch` plus the engine tool-result path as the ones that omit it), and say in `_fanout_stream.py`
that the wave scheduler keeps its own copy in `_fanout_wave_stream.py`. No behaviour changes, no test. The two near-identical merge loops themselves are a design choice recorded in `_fanout_wave_stream.py:10-12`, not part of this card.

## Resolution (QA-KB-080 fix, 2026-10-07)

Fixed by [FIX-737](20261007-1957-FIX-737.md). Prose only, the three sites above:

- `kernel_services.py:1177-1182` and `fanout.py:354-359` now name `parallel_group` and `wave_scheduler` as the callers that
  pass a queue, and `fanout_batch` plus the engine tool-result path as the ones that pass None.
- `_fanout_stream.py:10-12` now says the wave scheduler keeps its own copy, with wave identity stamping, in
  `_fanout_wave_stream.py`.
- The same false claim in the side-channel comment (`fanout.py:569-572`) was corrected in the same edit. That is
  [ISS-1062](20261007-1927-ISS-1062.md).
- Verified by reading (manual card): the executable AST of all three files is identical to HEAD
  (`evidence/qa-kb-080/fix-10-ast-equality.py` and `.out.txt`), so nothing executes differently.
