## Root cause (5-fixer, 2026-08-31) — ONE defect, four witnesses

The sequencing note above was half right: this was never six defects. Four of the
six are one line.

`_handle_revision` passes `execute()` an EMPTY roster on purpose since the
revision-pipeline-refactor (`engine.py:7962`, `agents: list = []`) so the roster
is rebuilt from the compiled manifest. The post-dispatch FR-014 chain-link-1
write 100 lines below still read that local:

```python
producer_agent=agents[-1].id,     # engine.py:8058 — agents is [] → IndexError
```

`IndexError("list index out of range")` is caught by the write block's own
`except Exception`, converted into `state_restoration_failed` and returned from —
so **no revision ever persisted its exact-kind ref**, and the FE-contract tests
saw the swallowed exception text on the wire. Both symptoms in this card's title
are the same line.

Fixed by [FIX-432](20260831-1842-FIX-432.md): the producer is read off the
compiled plan (`_compiled_revision.steps[-1].agent_id`), the same source
`execute()` rebuilds the roster from.
