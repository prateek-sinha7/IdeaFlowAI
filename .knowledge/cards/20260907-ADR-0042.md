## Decision

World state is delivered as files. Control is delivered as text.

| Input | Where it lives | How it arrives |
|---|---|---|
| uploaded files | `.uploads/<file>` + `.txt` sidecar | the agent reads it |
| design system, craft, template, wizard selections | `.context/design/…`, `.context/selections.json` | the agent reads it |
| upstream agent outputs | `.agents/NN-<agent>.md`, step-ordered | the agent reads it |
| previous revision's spec / tasks / prototype | the shared family tree | the agent reads it |
| planner analysis | `PLANNER.md`, written after the clarify merge | the agent reads it |
| chain payload | `.context/summary.md`, `logs.jsonl`, `<output>` | the agent reads it |

Everything else — the brief, retry feedback, a REVISE directive, the current
task, validation errors, steering — is a control payload, goes in the message,
and goes only to the agent it is about.

## Why this shape

Pasting world state made every agent's message a function of how many
documents a user uploaded. Five uploads meant five documents in every
declaring agent's prompt, whether or not that agent needed them. It also made
the prompt unauditable: what an agent "knew" was assembled at dispatch and
never written down.

Files invert both. The context is on disk before the run starts, the same
bytes every agent sees, and it is committed — so what an agent could read at
step 4 is recoverable later.

## Consequences

- An agent with no tools that needs a file input must be granted `read_files`.
- A prompt that names a path the read allowlist refuses is **inert** — it will
  produce an agent that makes no tool call and returns nothing. Check the
  allowlist and the prompt together, never separately.
- The old composition path is deleted, not gated. There is no fallback to
  pasting.
