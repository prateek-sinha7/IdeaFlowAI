## Symptom

"By Model" rows showed "0 runs" for Haiku 4.5 and Sonnet 5, even though those models
had significant token volume and correct costs. Only "Unknown" showed a non-zero run
count.

## Root cause

`backend/app/api/analytics.py` `_aggregate` post-loop merge:

The `models_agent` accumulator tracked `count_agent` (incremented per agent occurrence,
not per distinct run). The merge logic initialised `models[agent_model_key]["count"] = 0`
for models that only appeared at the agent level. The run count was never subsequently
updated — so the `ModelRollup` emitted `count=0`.

## Fix

Changed `models_agent` default factory from `{"count_agent": 0, ...}` to
`{"run_ids": set(), ...}`. In the inner loop:
```python
mm["run_ids"].add(r.id)   # distinct runs per model
```

In the post-loop merge:
```python
distinct_run_count = len(av["run_ids"])
if agent_model_key not in models:
    models[agent_model_key]["count"] = distinct_run_count
elif models[agent_model_key]["count"] == 0:
    models[agent_model_key]["count"] = distinct_run_count
# When run-level count > 0, leave it unchanged — it is already correct
```
