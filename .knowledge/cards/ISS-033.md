# ISS-033

## Title

The row below was STALE for a month and is corrected here. Original finding: SmartPlanner + ClarifyEngine + the handoff Test/Compliance agents call the model DIRECTLY (not via the shared cached deep-agent runner), so those calls get NO Bedrock prompt caching (the FIX-034 middleware runs only in the runner path) AND their tokens are UNCOUNTED in run cost. Correction 1 — most of it was already fixed on 2026-07-15 and the row never said so. Phase 43 plan 04 built exactly the proposed shared cached-invoke helper: backend/app/agents/cached_invoke.py (commit 0aa2072c) and routed four sites (commit 8518f29b). The aux fold is live-proven, not merely unit-tested — on the user_stories runs a4bec7e1 / a7dba362 / caa5d175 the pipeline_complete totals exceed the sum of the agent_complete events by exactly the planner + clarify spend (+2,104 / +2,002 / +2,091 input). Nothing in the card store caught the drift either. Correction 2 — the true call-site count is 9, not the 3 filed, and three were unknown to anyone: handoff/test_agent.py:156 (raw .ainvoke — uncached AND uncounted; 43-04 routed classifier.py by mistake), engine.py _run_validation_fix_loop (the internal drain continued past every usage), and chat/concierge.py:365 (discards usage; input unbounded). Correction 3 — severity is understated at minor. Quantified: the fix-loop alone hides ~929,000 input tokens on the live run fa66227a = 6.9% of that run's input, +$0.176 of a reported $2.550; the two cost sites additionally disagree by exactly the results.pop()ed specify+plan+analyze trio (70,346 tok on 5ecb990f, 123,137 on 6e38b9a7 ≈ 3.3%); handoff runs are 100% invisible (no cost surface exists). Every uncounted path is an UNDER-report — there is no over-report anywhere. Part A (FIX-230) closes the two measurable, safely-foldable sites: TestAgent → cached_invoke, and the fix-loop usage → the existing aux_token_usage fold.
