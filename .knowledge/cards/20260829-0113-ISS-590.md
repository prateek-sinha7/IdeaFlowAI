## Sibling of ISS-359 - INFERRED, not yet reproduced beyond the Composer

[ISS-359](20260828-1918-ISS-359.md) / `BUG-20260828-093400-library-skills-id-r2` established the root
cause: `AgentSkillsPicker.tsx`'s `detailSkill` modal renders `detailSkill.content` inside a bare
`<pre>` (`AgentSkillsPicker.tsx:280-283`) with zero markdown parsing. The validator's 3 reproduction
cycles all went through the Composer **Canvas** view (`/workflows/new` -> "click the agent node to
open its config panel" -> Skills tab), which mounts the picker via `CanvasConfigRail.tsx:468`.

The broken `<pre>` lives INSIDE `AgentSkillsPicker.tsx` itself, not in anything a caller passes in, and
the "View details" `Info` button that opens it (`AgentSkillsPicker.tsx:208-216`,
`onClick={() => setDetailSkill(s)}`) carries no `readOnly` gate - only the Add/Remove toggle button
does (`AgentSkillsPicker.tsx:226`, `disabled={readOnly}`). So every other mount of the same component
reaches the identical broken modal, confirmed by grepping every caller (not just the one path the bug
report named):

```
grep -rn "AgentSkillsPicker" frontend/src/ | grep -v '\.test\.\|__tests__'
```

Three more JSX mount sites of `<AgentSkillsPicker`, none exercised by the original hunt/validation:

- `frontend/src/components/workflow/composer/AgentRow.tsx:267` - the Composer **Simple view**'s
  per-agent row (`<AgentSkillsPicker agent={agent} onSkillsChange={onSkillsChange} />`, `readOnly`
  omitted -> `false`). Same `/workflows/new` URL as the confirmed bug, different view toggle.
- `frontend/src/components/workflow/AgentsPopup.tsx:870` - `AgentCapabilitiesModal`'s Skills tab
  (`<AgentSkillsPicker agent={skillsAgent} onSkillsChange={effectiveOnSkillsChange}
  readOnly={!onSkillsChange} />`). This one wrapper is itself mounted from two more pages:
  - `frontend/src/components/library/LibraryPage.tsx:1035` - the Library agent drawer
    (`/library/agents/<id>` -> Skills tab). No `onSkillsChange` is passed at this mount (per the
    `ISS-318` comment at `LibraryPage.tsx:1045-1050`), so `readOnly=true` here - but `readOnly` does
    not gate the Info button, so "View details" still opens the same raw `<pre>`.
  - `frontend/src/components/workflow/AgentLibrary.tsx:349` - the "Add agent" library popup
    (`onSkillsChange={onSkillsChange}` passed at line 353, `readOnly=false`), itself reachable from
    `composer/ComposerPage.tsx:1406`, `WorkflowView.tsx:556`, `AgentsPopup.tsx:2697` and
    `app/workflow/page.tsx:67`.

## Expected vs actual

**Expected:** "View details" on a skill renders formatted HTML from every surface that mounts
`AgentSkillsPicker`, matching `/library/skills/<id>`.

**Actual (inferred):** the same unrendered `#`/`##` markdown source shows in the Composer Simple view,
the Library agent drawer, and the "Add agent" popup, wherever a skill's "View details" is clicked -
not just the Canvas config rail the original report exercised.

## Why this is INFERRED, not CONFIRMED

The shared mechanism is confirmed by reading `AgentSkillsPicker.tsx` in full: the `detailSkill` modal
(lines 251-290) and its `<pre>` (lines 280-283) render unconditionally on which caller mounted the
component, and none of the three call sites above pass any prop that would change that rendering. What
is NOT yet verified is a live-browser repro from any of the three - open a skill's "View details" from
`AgentRow.tsx`'s row, from `/library/agents/<id>`'s Skills tab, and from the "Add agent" popup, and
confirm `dialog.querySelectorAll('h1,h2,h3,h4').length === 0` in each, mirroring ISS-359's own
3-cycle method.

## Fix should land once, not three more times

Patching only the reported path (the Canvas rail) leaves these three call sites broken; patching each
call site separately means four copies of the same fix drifting apart. Because the broken markup is
inside `AgentSkillsPicker.tsx` itself and every caller only supplies `agent`/`onSkillsChange`/
`readOnly`, the fix belongs entirely inside `AgentSkillsPicker.tsx`'s `detailSkill` block - every one
of the four call sites (plus the two indirect `AgentCapabilitiesModal` mounts) then inherits it
automatically, with no caller edit required.
