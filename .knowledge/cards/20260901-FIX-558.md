## Related

## What was wrong

When a composed workflow crashed and was resumed, the engine would rebuild the
roster by calling `get_pipeline_agents("custom")` — the generic custom pipeline —
instead of re-running the user's actual workflow. A live example burned ~597K tokens
on four agents the user never composed.

## The fix (commit 127b20a3d)

- Store the raw manifest on `workflow_runs.manifest_json` (migration 0040) at launch
  time, alongside a `_trust` flag ("user" for Composer/inline, "db" for saved rows).
- On resume, retrieve and recompile that manifest so the same workflow runs end to end.
- Fail closed: if the manifest no longer compiles (e.g., a skill was deleted), abort
  the resume instead of falling back to the generic roster.
- Registry/file-pipeline runs store NULL (unchanged behavior) and resume via the
  registry/file path exactly as before.
