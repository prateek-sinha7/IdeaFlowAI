# ISS-104

## Title

**Stale line-number citations in the shutdown-path comments — each points at code that has since moved, and a fixer following them lands in the wrong place.** `backend/docker-entrypoint.sh:27` cites `docker-compose.yml:138` for `stop_grace_period`, which is at `docker-compose.yml:75`. `backend/app/api/run_shutdown.py:30` cites `engine.py:5263` for the `NON_TERMINAL` set, which is at `engine.py:5838-5841` (the same wrong cite appears on the ISS-089 row as `engine.py:5710-5713`). `run_shutdown.py:97-98` cites `run_commands.py:1401` for the Concierge hold and `:1356` for the durable `chat_reply` persist. `run_shutdown.py:275` cites `run_commands.py:2155` / `:2473` for the driver terminal writes; the `CancelledError` handlers are at `:2424-2435` and `:2654-2659`. Filed rather than folded into FIX-234: they are in files that change touched, but they are a separate class of defect (documentation drift) and fixing them inside a behaviour change would blur the diff. The equivalent cite inside the block FIX-234 was mandated to rewrite (`config.py:197` → `docker-compose.yml:75`) WAS corrected there.

### Verdict on the card above

The diagnosis ("each cite points at code that has since moved") is **CONFIRMED**. The scope is not what the card, the QA-KB-042 report or the three xfail tests say. They cover **4** stale line numbers (`run_commands.py` `:1401 :1356 :2155 :2473`). The shutdown-path comment set holds **24** (CONFIRMED): 15 of the 17 line numbers in `run_shutdown.py`, 1 in `docker-entrypoint.sh`, 2 in `config.py`, plus 6 inbound cites to `run_shutdown.py` in `tests/unit/services/test_shutdown_reachability.py:267-272`. One of this card's original items is already fixed: `engine.py:5263` was replaced by the symbol name `NON_TERMINAL_RUN_STATUSES` in `8d84b1a69` ([FIX-243](20260812-2140-FIX-243.md)), see `run_shutdown.py:33`. The rest are still stale, and the card's own positions drifted too: `run_shutdown.py:275` and `:97-98` are now `:283-285` and `:99-101`, because later comment edits in the same file shifted them.

### Root cause (CONFIRMED)

A comment locates code by an absolute `file:line` in a file that keeps changing, and nothing ties the comment to its target. The numbers were right when written; they decayed.

1. **Right at authoring.** All of them were written in one commit, `78613ca08` (2026-07-31, KAN-151). At that commit `engine.py:1032` is `await sink.persist(`; each of the eight engine.py boundary cites (`:1943 :2287 :2514 :3621 :4437 :4566 :5012 :5155`) is a `cancel_event` check; `model_factory.py:112` is `read_timeout=600,`; `run_commands.py:1401` is `NEVER cancel it on`; `docker-compose.yml:138` is `stop_grace_period: 30s`. Four were already 2-5 lines off at that commit (`:1347 :1356 :2155 :2473`; INFERRED cause: copied from the KAN-151 investigation notes, which the Source section above says had already drifted).
2. **Then the files moved.** Since `78613ca08`: `run_commands.py` 2,607 -> 5,973 lines (67 commits), `engine.py` 8,480 -> 16,850 (75 commits), `docker-compose.yml` 192 -> 114 (3 commits). The same anchor went `run_commands.py:1401` -> `:1659` (at `9df9c1c8`, when this card was filed) -> `:2407` now. `docker-compose.yml:138` is past end-of-file.
3. **By line number 0 of 15 cites resolve; by symbol 15 of 15 do.** For the 15 authoring-time cites into `engine.py`, `run_commands.py` and `model_factory.py`, no line number lands on the cited code today, yet the enclosing method each one sat in at `78613ca08` still exists under the same name (`evidence/qa-kb-042/07-analyze-symbol-stability.txt`). Symbol citations would not have drifted at all.
4. **The guard does not read the comments.** `test_run_shutdown_stale_citations.py` hardcodes `1401 / 1356 / 2155 / 2473` (`:35`, `:44`, `:53-54`) and asserts what those lines hold; it never opens `run_shutdown.py`. It covers 4 of the 24, and tests 2 and 3 are stricter than the cites ever were: at `78613ca08` line 1356 was a comment and 2155 was `finally:`, so they would have failed on day one. Reproduced here: `3 xfailed`; with `--runxfail` each fails with a plain `AssertionError` on the unrelated line, not an `IndexError` or import error (`evidence/qa-kb-042/04-analyze-runxfail-output.txt`).

### Fix

**Where it belongs.** There is no shared function; the "callers" are comment sites. The shared change is (1) one convention, cite the enclosing symbol (plus a quoted anchor phrase where a symbol is too coarse), never `file:line`, applied to every site in the table in one comment/docstring-only change, and (2) one guard that reads the comments. `run_commands.py`, `engine.py` and `model_factory.py` are NOT edited: every anchor already exists.

**The agreed minimal fix (BUGS.md Notes) is partly ACCEPTED, partly OVERRULED.**

- ACCEPTED: replace each stale cite, and "cite symbol names instead of line numbers", promoted from "the better fix" to THE fix. It resolved 15 of 15 where line numbers resolved 0 of 15, and [FIX-243](20260812-2140-FIX-243.md) already did exactly this to one cite in this file.
- OVERRULED, "update the line numbers in the test and remove the xfail markers": re-pointing leaves the test pinning absolute lines (today `2407`, `2256`, `4388`, `5831`) of a 5,973-line file that took 67 commits in two months. INFERRED: it goes red on the first unrelated edit above those lines (the anchor itself moved 1401 -> 1659 -> 2407). That swaps one documentation defect for a recurring CI failure on unrelated PRs. Settle it in a scratch copy of the tree, never the real one: re-point, add one line above line 2256 of `run_commands.py`, rerun.
- OVERRULED, its list: it names four numbers and "the current NON_TERMINAL line in engine.py" (that cite is already gone). It omits 11 of the 15 stale numbers in `run_shutdown.py` (`:31 :101 :279-280 :283`), every site in `config.py` and `test_shutdown_reachability.py`, and for `docker-entrypoint.sh:27` it substitutes another line number that decays the same way (the compose file shrank 192 -> 114).

**Do not carry forward `read_timeout=600`** (`run_shutdown.py:238` and `:283`): it has been 1800 since [FIX-657](20260930-1723-FIX-657.md). Tracked as [ISS-888](20261001-2114-ISS-888.md), done in the same pass.

**Guard.** Rewrite `backend/tests/unit/test_run_shutdown_stale_citations.py`. Read files as text or with `ast`; never import `app.*` or `agents.*` (heavy imports, and a DB-bound pytest plugin exists in this repo).

1. Keep the three tests' names and intent; drop the strict xfail and the hardcoded numbers; assert that each ANCHOR the comments now name exists in the cited file: `"NEVER cancel it on"` and `'type="chat_reply"'` in `run_commands.py`; `def post_message`, `def _drive_launch_to_queue`, `def _drive_revision_to_queue`; `stop_grace_period` in `docker-compose.yml`; `read_timeout` in `model_factory.py`; the six engine method names. A rename then fails a test instead of rotting. This is the idiom `tests/unit/services/test_shutdown_reachability.py` already uses ("Single sources of truth - parsed, never hardcoded").
2. Add one lint: no `name.ext:NNN` or bare `:NNNN` cite in `run_shutdown.py`, `docker-entrypoint.sh` and `config.py`'s shutdown block. Today it reports 11 + 1 + 4 offending lines, which is the RED state. `config.py:297` and `:345` are valid cites, but the rule is zero line numbers, so they are converted too.

Optional: one line in `backend/CLAUDE.md` ("cite symbols, not line numbers, in comments"). No such rule exists today, and agents write most of these comments.

**Sequencing hazards for the fixer**

- Strict xfail: when the comments are fixed the three `xfail(strict=True)` markers must be removed in the same change, or the file fails with XPASS(strict). The reverse also bites: if the markers stay and the tests keep pinning old numbers, they "xfail" forever and the card looks closed while nothing is verified. The verifier must see the positive assertions pass, not just a green file.
- Editing `run_shutdown.py` shifts every line below the edit. Convert `test_shutdown_reachability.py:267-273` in the same change.
- QA-KB-043 edits the same file (an optional comment above `run_shutdown.py:147`, and its notes cite `:147-152`). The two changes shift each other's line numbers; resolve by symbol (`shutdown_run_infrastructure` step 2), not by line.

**Siblings (INFERRED, unvalidated):** [ISS-885](20261001-2114-ISS-885.md), the same drift in the `run_engine.py` / `run_stream.py` docstrings (21 stale cite sites, all read); [ISS-888](20261001-2114-ISS-888.md), the stale value `read_timeout=600` (the value drifted, not the position; FIX-657 changed it yesterday).

**Still INFERRED:** (a) that a re-pointed test goes red on unrelated edits (reasoned from churn; settle in a scratch copy as above); (b) that the docstring's list of cooperative-cancel boundaries is meant to be exhaustive: `TaskLoopStrategy.run` (`agents/capabilities/strategies/task_loop.py`) and `fanout._check_cancel` (`agents/execution_engine/fanout.py`) also observe `cancel_event` (CONFIRMED at the time of analysis; line numbers deliberately omitted, other fixes are editing these files) and are not in the list, so write "among others" or add them; (c) that the four 2-5 line offsets at authoring came from the investigation notes.
