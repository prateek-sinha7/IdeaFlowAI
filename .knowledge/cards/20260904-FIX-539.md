## Related

## What was wrong

On resume, cancel/fail markers from the previous attempt were not stripped, 
so the open gate would incorrectly reopen gates that had already been resolved. 
Reopening a run and immediately re-resolving it would yield different gate 
states than the first completion.

## The fix (commit 1e329e47b)

- Strip this run's own cancel/fail markers before deriving the open gate (A3).
- Skip any gate whose exact key already has a durable approval (A20).
- This makes resume idempotent: the same gate states result from multiple 
  re-opens and re-resolutions.

Pinned by test_resume_gate_idempotency.py verifying that cancel/fail markers 
are stripped and existing approvals are respected on resume.
