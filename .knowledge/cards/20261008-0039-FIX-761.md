# FIX-761

## What was wrong

This fix is for bug report QA-KB-097. The root cause is the 2026-10-08 analysis on
[ISS-1099](20261008-0016-ISS-1099.md) and [ISS-1100](20261008-0016-ISS-1100.md). It was not re-derived here. Every cited line was
re-read at HEAD `ffac38246` before editing.

Two `ScopedStore` methods still opened their session with a helper that no longer exists:

- `write_provenance_audit` (`backend/agents/authz.py:1245`): `session, owned = self._acquire()` at `:1266`
- `update_wave_run_merge_state` (`authz.py:1528`): the same line at `:1548`

`1e329e47b` (A16) deleted `_acquire` and moved every method onto `_run_bounded` (`authz.py:120`). `e7305f9dd` was written on a
branch without A16 and added these two methods. Merge `4ebd98e8f` joined them with no conflict. Every call raised
`AttributeError: 'ScopedStore' object has no attribute '_acquire'`. The callers' best-effort handlers swallowed it
(`kernel_services.py:527`, `:753`), so `wave_runs.merge_*` was never written (0 of 73 dev rows) and no engine-written
`run_provenance_audits` row exists. The report's `kernel_services.py:754` is the `logger.warning` of that handler.

## What changed, and why there

`backend/agents/authz.py` only. In each method the body moves into `_body(session)`, and the method returns
`await self._run_bounded("<method name>", _body, run_id=run_id)`. That is the shape `record_wave_run` (`:1473`),
`update_wave_run` (`:1507`) and `read_wave_runs` (`:1566`) already use. Nothing else in the methods changed: the same scope filter
(`_scope_owner_ws`), the same latest-row lookup, the same principal stamped on the audit row, the same commit.

The store method is the one path every caller goes through:

- `KernelServices.record_provenance_audit` (`kernel_services.py:490`). Called by `ProvenanceAuditObserver` and by
  `chain_context._write_chain_payload_installed_audit`.
- `KernelServices.update_wave_run_merge_state` (`kernel_services.py:727`). Called by `fanout._persist_merge_state` for every merge
  outcome.

A grep at HEAD found no other caller and no other `self._acquire()` in the repo, only comments in three test files. So one change
in the store fixes every caller. The callers' handlers stay as they are, per the cards' locked constraints.

Rejected, per the cards:

- An `_acquire` shim. It brings back the unbounded session open on the event loop that A16 removed.
- A getattr or AttributeError guard. That hides the hole a third time.
- A raw `SessionLocal()` in `kernel_services.py`. That breaks AUTHZ-01, which makes `ScopedStore` the one read/write path.
