## Live output card disappears once a provider streams thinking

**Symptom:** once [ISS-163](20260819-1726-ISS-163.md)'s fix made Bedrock/Anthropic thinking actually stream to
the UI, the live *output* stream that used to be visible while an agent was running
stopped showing entirely — nothing appeared until the agent completed, at which point
the settled output view took over. The underlying `agent.output` state was never
missing (the `agent_chunk` reducer in `useWorkflow.ts` kept appending to it the whole
time) — it just stopped being rendered.

**Root cause:** `AgentDetailPanel.tsx:1034-1035` (pre-fix):

```jsx
{reasoning.trim().length > 0 && <ReasoningCard text={reasoning} live={isRunning} />}
{reasoning.trim().length === 0 && isRunning && <ReasoningCard text={agent.output || ""} live label="Output" />}
```

The second line — the ONLY thing rendering live output — was written for a world where
`reasoning` (thinking) was always empty (Haiku, no thinking stream): it used
`agent.output` as a fallback specifically so a running agent didn't show a blank
cursor. The two conditions are mutually exclusive by construction. Once a provider
actually streams thinking, `reasoning.trim().length > 0` flips true, and the fallback
condition on the second line permanently loses — the live output card never renders
again for that agent's run, regardless of how much text streams into `agent.output`.

**Fix:** [FIX-265](20260819-1726-FIX-265.md) drops the `reasoning.trim().length === 0 &&` clause from the
second condition, leaving `isRunning` as its sole gate — Reasoning and Output can now
render simultaneously (Reasoning first, Output directly below, matching JSX order).
The live Output card still disappears once `isRunning` goes false, at which point the
pre-existing settled-output view (`SettledArtifactCards`/`OutputPreviewSection`,
unchanged) is the sole output view — exactly today's post-completion behavior,
untouched.
