# FIX-781

**Register source:** `QA-KB-120` (`LEDGER.md`), 5-fixer, 2026-10-09. Resolves [ISS-1159](20261009-1530-ISS-1159.md) (root) and
[ISS-1179](20261009-1659-ISS-1179.md) (the test double). [ISS-1178](20261009-1659-ISS-1178.md) stays open: its fix waits on an

Line numbers are HEAD `179239efa` plus this change. None of the four files the cards name changed between the analysis HEAD
`9cd0d6c5a` and `179239efa`. The whole change is `evidence/qa-kb-120/fix-03-change.patch`:
`backend/agents/execution_engine/engine.py` +8/-3 and `backend/tests/agents/test_finalizer_v2.py` +3/-2.

## What was wrong

From the root card, not re-derived here. `build_flat_payload` fixes `_allowlist` from the declared names before it writes anything
(`engine.py:1555`). When the declared output does not materialize (file absent, copy raising, empty `streamed_text`, empty `ppt`,
empty `serialized_sandbox` bundle), only a `logger.debug` notes it, and `.chain/<output>` stays in the allowlist. `stage_exact`
(`:1762`) then runs one `git add --force -- <3 paths>` (`local.py:1434`). Git exits 128 on the pathspec that matches nothing, stages
nothing, and `:1766-1770` logs `stage_exact failed` at WARN with the `CalledProcessError` traceback. That happened on the first
terminal pass of every such run. The finalizer's metadata-only snapshot, which runs `reset_index` first, hid the damage but not the
noise. The text form already had this prune (`:1679`, "not staged, so stage_exact never names a missing file"). The output did not.

[ISS-1179](20261009-1659-ISS-1179.md): the shared double `FakeSandbox.stage_exact` ran one `git add` per path. Three green tests
therefore walked that failure, and the staged set of a payload built through the double depended on `PYTHONHASHSEED`.

## What changed, and why there

- `engine.py:1661-1664`, in the root card's exact shape: after the output-copy `try / except`,
  `if _output_basename and not _materialized: _allowlist = _allowlist - {f".chain/{_output_basename}"}`. It sits after the whole
  block, so the `except` path is covered along with the other four. This is the one place that knows what was written, and all three
  consumers of the allowlist route through it:
  - the stale reconciliation (`:1744`) now untracks a `.chain/<output>` that an earlier snapshot tracked. The index shows the same
    staged deletion `git add` produced before (probe `[3]`).
  - `stage_exact` (`:1762`) is given only files that exist.
  - the returned `Payload.allowlist` names only what was written. It is also the `force_add` of `commit_in_sandbox` (`:2428`,
    `:2475`).
- `engine.py:381-384`: the `Payload` docstring no longer says "exactly three". The allowlist is `payload_allowlist(...)` minus any
  output or text form that was not written (the card's trap list).
- `tests/agents/test_finalizer_v2.py:181-184`: `FakeSandbox.stage_exact` is one `_run_git("add", "--force", "--", *paths)`, behind
  the same `if paths` guard as `LocalWorkspace.stage_exact`. This is test infrastructure, changed because ISS-1179 asks for it ("Do it
  in the change that adds the ISS-1159 red test"). It makes the double stricter, never looser, and no assertion was edited.

Not changed, per the cards:

- `stage_exact` stays strict on both `RunSandbox` and `LocalWorkspace`.
- The finalizer and the strings it keys on (`no_declared_output`; `output_not_materialized`, which becomes
  `output_unmaterializable`) are untouched.
- The committed metadata-only snapshot is unchanged: `.chain/summary.md` alone, `degraded`, no tag.
- No `app.*` import, no `Workspace` protocol method, no workflow-name branch.

`logs.jsonl` and `summary.md` still have unreconciled allowlist entries. That is [ISS-1178](20261009-1659-ISS-1178.md):
reconciling them would change a published outcome, and the owner has not chosen one yet.

  and `test_finalizer_v2.py` is a test file.

  23 such finalizations ([ISS-1159](20261009-1530-ISS-1159.md), `analysis-03`). Once the backend has reloaded this change, such a run
  logs `build_flat_payload: output file not found` at DEBUG and no `stage_exact failed`.
