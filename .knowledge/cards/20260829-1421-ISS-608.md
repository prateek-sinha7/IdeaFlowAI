## What is suspected

[ISS-606](20260829-1412-ISS-606.md) root-caused the Steps tab / FilesTab agent-outputs-list
symptom (`BUG-20260829-135100-runs-id-versions` in `bug-hunter/ledger.md`) to `agents`/
`pipelineState`/`agentOutputs` never being swapped for a version-pin override, unlike
`effUserStoryContent`/`effPptContent`/`effPrototypeContent` (`PreviewPanel.tsx:656-658`). Those
are the tabs where NOTHING is pin-aware. Reading the OTHER two tabs — the ones that already
look pin-aware because their primary content/runId is fixed — shows the same raw
`agentOutputs`/`pipelineState.agents` still leaking into a SECOND, smaller surface on each:

- **Preview tab, `app_builder` workflows** — `FIRST_PARTY_RENDERERS.app_builder`
  (`PreviewPanel.tsx:1083-1086`) correctly passes `effUserStoryContent` (version-pinned) as
  `content`, but also passes raw `agentOutputs={agentOutputs}` to `AppBuilderIDEPreview`. That
  component merges BOTH into its rendered file tree: `agentOutputs` supplies the code-producing
  agents' files (`PreviewPanel.tsx:137-148`, filtered by `CODE_PRODUCING_AGENT_IDS`) and even
  the derived `projectName` (`:159-161`, searches `agentOutputs` for the `material-analyzer`
  agent's output), while `content` supplies only the final-agent scan (`:152-154`). So a pinned
  version's IDE file tree is a MIX of that version's own final output and the LIVE/root run's
  intermediate agent files.
- **Preview tab, generic/custom deliverables** — `GenericDeliverablePreview`
  (`PreviewPanel.tsx:204-213`, mounted at `:1160` and `:1186`) is likewise handed raw
  `agentOutputs={agentOutputs}` alongside the deliverable itself.
- **Workspace tab** — `agentNameById` (`PreviewPanel.tsx:773-776`) is built as
  `{ ...reopenedAgentNameById, ...buildAgentNameById(pipelineState?.agents) }` — neither branch
  reads `viewingVersion`. `SandboxTab` (the Workspace tab body) uses it at `SandboxTab.tsx:1047`
  (`agentNameById?.[id] ?? prettifyAgentId(id)`) to label which agent produced each workspace
  file. `workspaceRunId` itself IS pin-aware (`PreviewPanel.tsx:753`: `viewingVersion?.id ??
  pipelineState?.pipelineRunId ?? activeRunId ?? null` — the pin wins), so the Workspace tab
  browses the CORRECT run's files, but may label them with the WRONG (live/root) run's agent
  names whenever the pinned version's agent roster differs from the live run's.

## Condition

A version pin (`/runs/{id}/versions/{v}/...`) is active AND either (a) the pinned family is an
`app_builder` workflow with the Preview tab open, (b) a generic/custom deliverable with the
Preview tab open, or (c) the Workspace tab is open on a family whose pinned version's agents
differ from the live/root run's agents (different ids, different count, or the same id doing
different work across versions).

## Expected vs actual

**Expected:** every value `AppBuilderIDEPreview`/`GenericDeliverablePreview`/`SandboxTab`
render for a pinned version should derive from that version's own run record, matching the same
version the surrounding tab's primary content already reflects.

**Actual (predicted):** the file tree/project name (app_builder) and generic-deliverable
agent-output lookups stay sourced from the live/root run regardless of the pin; the Workspace
tab's agent-id-to-name labels do the same, independent of whether `workspaceRunId` itself is
already correct.

## Why the root cause implies this

Same mechanism ISS-606 names, one layer further: `PreviewPanel.tsx` overrides
`userStoryContent`/`pptContent`/`prototypeContent` for a pin but never `agentOutputs`/
`pipelineState.agents`, and both of those raw values are threaded into more places than the two
call sites ISS-606 already covers. Fixing this alongside ISS-606 and
[ISS-609](20260829-1420-ISS-609.md) (the Audit tab) at the same `PreviewPanel.tsx` chokepoint —
one `effAgentOutputs`/`effAgents` computed once, next to the existing `eff*` content values — closes
all three together, and is a smaller diff than patching `AppBuilderIDEPreview`,
`GenericDeliverablePreview` and the `agentNameById` merge as three separate call sites.

**Marked INFERRED**: confirmed entirely by reading `PreviewPanel.tsx` (lines 111-165, 204-213,
656-658, 753, 773-776, 1083-1086, 1160, 1186) and `SandboxTab.tsx:859-875,1047`. Not
independently browser-verified: this session's reproduction used a `user_stories`-type family
(`77f74563-.../ef86e750-...`), which never mounts `AppBuilderIDEPreview` and has no Workspace-tab
agent-name mismatch to observe. What would settle it: repeat with an `app_builder`-type run
family whose two versions have different agent rosters, cold-navigate the Preview and Workspace
tabs at each version URL, and compare the rendered file tree / agent-name labels against each
version's own `GET /api/runs/{id}` record.
