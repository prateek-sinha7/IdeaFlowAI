# ISS-1056

Found during [FIX-727](20261007-1837-FIX-727.md) (QA-KB-064), and caused by it. It was not fixed there because no card
asked for a test edit.

## What happens (CONFIRMED by reading, 2026-10-07)

`backend/tests/agents/test_phase4_tagging.py::TestRunSandboxTagDelegation::test_list_tags_returns_empty_on_workspace_error`
builds `RunSandbox.__new__(RunSandbox)` with `has_git = True` and `root = tmp_path`, which has no `.git`. It then
patches `_ws` to return a workspace whose `list_tags` raises `RuntimeError`, and asserts the result is `[]`.

Since FIX-727, `RunSandbox.list_tags` returns `[]` at `backend/app/agents/sandbox.py:938` whenever the root has no
`.git`, so it never builds the workspace. The test still passes (41 passed in the FIX-727 regression run), but it no
longer exercises the `try/except` at `sandbox.py:943-946`. That `except` swallows a workspace error into `[]`. No other
test covers it for `RunSandbox`; `test_list_tags_returns_empty_list_on_git_error` covers `LocalWorkspace.list_tags`,
not the sandbox facade.

## Fix

Test-only: add `(tmp_path / ".git").mkdir()` before the call, so the guard passes and the mocked error is reached. The
assertion stays as it is. No application change.
