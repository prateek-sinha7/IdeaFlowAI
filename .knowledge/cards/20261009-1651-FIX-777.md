# FIX-777

**Register source:** `QA-KB-110` (`LEDGER.md`), 5-fixer, 2026-10-09. Resolves [ISS-1154](20261009-1340-ISS-1154.md) (root) and its
sibling [ISS-1171](20261009-1624-ISS-1171.md). Base is HEAD `9cd0d6c5a`; line numbers are that HEAD plus this change. Frontend only:
one file, `frontend/src/components/layout/DashboardLayout.tsx`.

## What was wrong

The root cause is on [ISS-1154](20261009-1340-ISS-1154.md) and is not re-derived here. `handleEditBrief.openComposerWith` handed the
brief to the composer through two channels, and the one every non-wizard type used did not survive the navigation it triggered:

- `setPendingHomeBrief(...)` is component state (`useState(undefined)`, no storage read, was `:1594`). The following
  `router.push(createRouteForType(...))` to `/create/<type>` remounts `DashboardLayout`; the new instance starts with
  `pendingHomeBrief === undefined`, and `IdeaInputPage` seeds its textarea once at mount from
  `initialInput={savedComposition?.brief ?? pendingHomeBrief}`. Empty composer for `ex_*`, `backlog`, `user_stories(_v2)`,
  `app_builder`, `custom`.
- The sessionStorage slot was chosen from `baseWorkflowType(effectiveReviseType)` while the route was built from
  `effectiveReviseType`. For `ppt_revision`, `prototype_revision` and `prototype_v2_revision` that staged `ppt.draft` /
  `prototype.draft` for a wizard the push never opened (`/create/<x>_revision` is the plain panel), leaving it for whatever wizard
  mounted next ([ISS-1171](20261009-1624-ISS-1171.md)).

## What changed, and why there

The card's probed shape (`evidence/qa-kb-110/analysis-02`): one function and one initializer, not the callers.

1. **Read side, `DashboardLayout.tsx:1594-1602`.** `pendingHomeBrief`'s `useState` gets a read-only initializer over
   `sessionStorage["idea.draft"]` (`JSON.parse(...)?.brief || undefined`, `typeof window` guard and `try/catch` as the file's other
   storage reads), plus `useEffect(() => { sessionStorage.removeItem("idea.draft"); }, [])`. This is the only reader the
   non-wizard channel has (`IdeaInputPage`'s single mount site, `:3206`), so every destination that renders `IdeaInputPage` inside
   `DashboardLayout` gets it.
2. **Write side, `openComposerWith`, `:2412-2436`.** The slot table is indexed by `effectiveReviseType` (the value
   `createRouteForType` uses two lines later) instead of its base, and defaults to `"idea.draft"`, so the write is unconditional:
   `{ prototype, prototype_v2, ppt, ppt_v2 }[effectiveReviseType as string] ?? "idea.draft"`. The `as string` is the same `string`
   index the old `reviseBase` gave; indexing with the `WorkflowType` union raised TS2339 for every non-table member.
   `reviseBase` was orphaned by this and removed; `baseWorkflowType` is still imported for its four other callers.
3. Two comments that stated the premise this corrects ("every other type stays in this component's input view") now say the
   destination is a remounted copy that reads `idea.draft`.

`setPendingHomeBrief(editedBrief)` stays: it covers the old instance's optimistic `setMainView("input")` render before the push lands.
Wizard rows are byte-identical in behaviour: for those four types `effectiveReviseType === baseWorkflowType(effectiveReviseType)`.

Not changed, deliberately: `RunChatLane` (a one-line click), `IdeaInputPage` (cannot know where a brief came from), `page.tsx` and
`routes.ts` (the card's URL-carried alternative; refresh-survival was not required). `handleHomeSelectFeature` has the same
state-before-push shape but `homeBrief` is always empty since FIX-181, so it is unreachable (ISS-1154 blast radius).
