# ISS-357

## What is wrong

`backend/tests/unit/test_register_password_echo.py` proves
[ISS-257](20260828-1817-ISS-257.md): a too-short password must not be echoed in
`POST /api/auth/register`'s 422 body. Its assertion is right and unchanged. Its
**fixture** is not:

```python
app = FastAPI()
app.include_router(auth_router)
```

[ISS-257](20260828-1817-ISS-257.md)'s own root cause is "`app/main.py` registers
no `RequestValidationError` handler" — a property of the application object. A
test that constructs a *different* application object can never observe a
handler registered on `app.main.app`, so the fix ([FIX-332](20260828-1915-FIX-332.md))
landed and the test still reports `1 xfailed`. The same fixture would also
report green against a hypothetical fix that only patched `auth_router`, which
would leave `settings.py`'s PAT leak ([ISS-224](20260828-1735-ISS-224.md))
open — so the harness can neither confirm the real fix nor reject a wrong one.

Verified, running app, after FIX-332:

```
POST /api/auth/register {"email":"nobody@example.com","password":"short7!"}
→ 422 {"detail":[{"type":"string_too_short","loc":["body","password"],
       "msg":"String should have at least 8 characters","ctx":{"min_length":8}}]}
```

No `input` key. The behaviour is fixed; only this test cannot see it.

## Why it was not fixed in the same pass

Editing a test so the code passes is the inversion this repo has already been
burned by, so the file was left alone. It also cuts against a stated local
convention — `tests/unit/test_shutdown_reachability.py:65` says "Deliberately
NOT an import of `app.main`: booting the real application runs …" — so
switching the fixture to the real app is a call for whoever owns the unit tier,
not a side effect of a bug fix.

## What would resolve it

Either point the fixture at the real application (`from app.main import app`,
with `dependency_overrides[get_db]` as today), or move the assertion into the
integration tier where a real app is already booted. Then the test XPASSes and
[ISS-257](20260828-1817-ISS-257.md) can carry `verification.type: test`.
