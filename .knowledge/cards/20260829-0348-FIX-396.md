## What was wrong

On `/create/prototype` (Template tab -> "Upload custom" -> "From URL"), pasting a
syntactically valid but unresolvable domain and clicking "Fetch" painted the backend's raw
Python socket exception text straight into the modal's inline error:

```
URL fetch failed: [Errno 8] nodename nor servname provided, or not known
```

`GET /api/prototype/fetch-url?url=...` answered `502` with
`{"detail":"URL fetch failed: [Errno 8] nodename nor servname provided, or not known"}`,
and `CustomTemplateModal.tsx:110` rendered that `detail` verbatim. The same modal is also
mounted on `/create/ppt` ([ISS-584](20260829-0243-ISS-584.md)), so both routes leaked the
same OS-level detail. Contrast the malformed-URL path, which already returned an
app-authored message ("URL must start with http:// or https://") — the friendly path
existed and was simply bypassed whenever the failure came from the network fetch itself.

## Root cause

`backend/app/api/prototype_templates.py`, `fetch_url_for_template`, final exception clause
at `:387-389` (pre-fix):

```python
except Exception as exc:
    logger.warning("fetch-url failed for %s: %s", url, exc)
    raise HTTPException(status_code=502, detail=f"URL fetch failed: {exc}")
```

The `f"...{exc}"` interpolation put `str(exc)` into the HTTP `detail` with no translation.
That clause is the catch-all sitting after two already-safe handlers —
`httpx.TimeoutException` (`:380-381`, fixed message) and `httpx.HTTPStatusError`
(`:382-386`, interpolates only the numeric status) — so every remaining failure from
`client.get(url, ...)` (`:349-353`) landed there. A DNS failure arrives as an
`httpx.ConnectError` wrapping the OS resolver's `socket.gaierror`, whose `str()` is exactly
the observed errno text. `_is_private_url` (`:305-318`) is not involved: it swallows its own
resolution errors and returns `False`.

## What changed and why there

One edit, `backend/app/api/prototype_templates.py:387-392` — the catch-all's `detail` is now
a fixed, user-safe string, with the existing `logger.warning(..., exc)` untouched so the raw
exception is still available server-side:

```python
except Exception as exc:
    logger.warning("fetch-url failed for %s: %s", url, exc)
    raise HTTPException(
        status_code=502,
        detail="Could not reach that URL. Check the address and try again.",
    )
```

This endpoint is the single chokepoint for every caller, re-confirmed by grep at fix time:
`CustomTemplateModal.tsx:105` (the only live caller, rendered from BOTH
`prototype/TemplateGallery.tsx:88` and `ppt/PPTTemplateGallery.tsx:88` — one shared
component, not a fork) and `frontend/src/store/api/prototype.ts:60`
(`prototypeApi.fetchUrl`, still zero callers in `frontend/src`, dead code today). Fixing the
server means no frontend file needed to change and both routes plus any future caller are
covered at once. No frontend edit was made.
