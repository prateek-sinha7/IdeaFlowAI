## The symptom

An operator follows the command table in `skills/velocity/cli.md` — any row of
it — and the rebuild dies partway through with

```
TypeError: write_text() got an unexpected keyword argument 'newline'
```

raised from inside `build_context`. Nothing in that message says "wrong
interpreter", so the natural reading is that the knowledge tooling is broken.

## Root cause

One line. `tools/knowledge/build_context.py:431`:

```python
OUT_PATH.write_text(body, encoding='utf-8', newline='\n')
```

`newline=` was added to `Path.write_text` in Python 3.10. It is the **only**
write in the whole pipeline that carries it — `build_index.py:46`,
`apply_summaries.py:131` and `build_architecture.py:720`, `:724`, `:1983` all
call `write_text(content, encoding="utf-8")` and nothing else. It arrived in
`9d7bd554f` (*docs(knowledge): sync to 4a6e8993, add FIX-503/504, refresh 6
domain cards*).

Every documented entry point spells the interpreter as a bare `python3`:

- all eleven rows of the command table in `skills/velocity/cli.md:12-22`, plus
  the inline examples at `:40-41`, `:55` and the sub-skill table at `:168-172`;
- `.pre-commit-config.yaml:176`, `entry: python3 tools/knowledge/rebuild_knowledge.py --hook`
  under `language: system`, which resolves `python3` from `PATH` — and its own
  manual-run instruction at `:183`.

On this machine `which -a python3` puts `/usr/bin/python3` first, and that is
3.9.6. Reproduced read-only:

```
$ /usr/bin/python3 -c "Path(...).write_text('a', encoding='utf-8', newline='\n')"
FAILS: write_text() got an unexpected keyword argument 'newline'
```

`rebuild_knowledge.py` spawns every stage with `sys.executable`
(`run_stage` at :82, `_run` at :165), so whichever interpreter the operator
typed is inherited by all four stages — and by `hook_mode()`'s phase 3, which
re-enters this same script with `--skip-architecture`.

Nothing else in the tooling needs 3.10: `py_compile` under `/usr/bin/python3`
succeeds for all eight scripts in `tools/knowledge/` (the allocation brief said
nine; `prompts/` is a directory, not a script). This single runtime kwarg is
the entire 3.10+ dependency.

## Why the ordering makes it worse than a crash

`STAGES` is `architecture, index, context, validate`. `index` writes
`INDEX.md` and `state.yaml` (`build_index.py:25-26`, `:333`, `:379`) **before**
`context` runs. So when `context` dies:

- `INDEX.md` and the `state.yaml` watermark are already rewritten,
- `CONTEXT.md` is still the old one,
- `validate` — the stage that certifies coherence — is never reached.

That is precisely the state the `rebuild_knowledge.py` docstring (lines 3-5)
promises cannot happen: *"a single command that cannot be run half-way or in
the wrong order"*.

The blast window is widest on the path the routine verbs actually take.
`prime.md` and `book-keeping.md` both run `--skip-architecture`, where `index`
is stage 1 and `context` is stage 2 — the crash lands immediately after the
only irreversible writes.

In `--hook` mode it also fails the commit at phase 3 without the `_git_add`
that would have staged the regenerated files, so the half-applied store is left
unstaged in the tree.

## Why this is reachable now

[BUG-031](20260827-BUG-031.md) got the knowledge hook re-gated to
`stages: [manual]`, so `git commit` no longer fires the rebuild. The rebuild is
now something an operator types by hand from that command table — which is
exactly the invocation that picks the wrong interpreter.

## What a fix must do

Two independent defects, both worth closing:

1. **Drop the kwarg** at `build_context.py:431`, or spell the interpreter as
   `backend/.venv/bin/python` everywhere `cli.md` and `.pre-commit-config.yaml`
   say `python3`. Dropping the kwarg is the smaller change and loses nothing —
   POSIX text mode already writes `\n` unchanged. Note that `validate_links.py`
   is already run with `backend/.venv/bin/python` in practice, which is why the
   validator appears healthy while the rebuild is not.
2. **Make the ordering survivable.** A stage failure after `index` should
   either roll the watermark back or refuse to leave `state.yaml` advanced
   while `CONTEXT.md` is stale. Fixing only (1) leaves the next 3.10-only API
   free to reproduce this.

## Analysis 2026-10-02 (QA-KB-051)

Re-analysed from the current tree (branch `feat/user-stories-v2`, HEAD `024c03ef8`). `rebuild_knowledge.py`, `build_context.py` and
`build_index.py` are clean against HEAD; the only uncommitted edits under `tools/knowledge/` are `build_architecture.py` and `status.py`.
The reproduction mode is Test, so no browser was opened. The card's root cause holds, line for line. This section adds an executed
reproduction, corrects two pieces of the fix, widens the blast radius and files one sibling.

### Root cause (CONFIRMED)

1. `tools/knowledge/build_context.py:431` is `OUT_PATH.write_text(body, encoding='utf-8', newline='\n')`. `Path.write_text` has no `newline`
   parameter before 3.10. `inspect.signature` on this machine: `/usr/bin/python3` 3.9.6 gives `(self, data, encoding=None, errors=None)`;
   3.10.20, 3.11.15, 3.12.13 and 3.13.14 all end in `newline=None`
   (`evidence/qa-kb-051/analysis-write_text-signature-by-version.out.txt`). A bare `python3` in this shell is the Xcode stub:
   `which -a python3` lists `/usr/bin/python3` first.
2. **Executed end to end in a throwaway copy** (`evidence/qa-kb-051/analysis-sandbox-repro.sh`, transcript
   `analysis-sandbox-repro.out.txt`; the real tree is never written). One card added, cards-only rebuild under 3.9.6:

   | moment | INDEX.md | state.yaml `cards_count` | CONTEXT.md `cards_indexed` |
   | --- | --- | --- | --- |
   | converged under 3.13 | 1698 | 1698 | 1698 |
   | after the 3.9.6 run (exit 1, `TypeError` at `build_context.py:431`, `Aborted at stage 'context'`) | 1699 | 1699 | **1698** |
   | sandbox copy patched, 3.9.6 re-run (exit 0) | 1700 | 1700 | 1700 |

   `validate` never ran in the failing run, and passes after the patch (18410 links, 0 broken).
3. **It is the only 3.10+ dependency on the cards-only path, executed rather than inferred.** The card could only assert this with
   `py_compile`, because the failing run never reaches `validate`. Under 3.9.6, read-only
   (`evidence/qa-kb-051/analysis-py39-read-only-tool-matrix.out.txt`): `validate_links.py` (18406 links, 0 broken), `status.py`,
   `normalize_card_ids.py --check`, `apply_summaries.py --check` and `build_architecture.py --check` (stage 1 of the full rebuild, 28 s)
   all run. A grep of `tools/knowledge/*.py` for the known 3.10 and later additions (the kwarg, `match`, `zip(strict=)`, `pairwise`,
   `slots=`, `tomllib` and the like) finds only `:431`. The patched sandbox pipeline passing under 3.9.6 settles the cards-only path; the
   full rebuild's `architecture` stage was run only in `--check` mode.
4. **State-dependent, which is why it hides.** `build_context.py:426-430` returns before the write when the new body equals the pack on
   disk. Run on the unchanged live tree under 3.9.6 it printed `Wrote ... (unchanged)` and exited 0. The `TypeError` appears the first time
   the body changes: a card added, a card status flipped (the open/active column), or a new commit (`built_from_commit` is HEAD, `:403`).
   That is exactly the moment after a `book-keeping` write.
5. **The dry-run cannot see it.** `rebuild_knowledge.py --check --skip-architecture` under 3.9.6 skips `index` and `context` and prints
   `--check complete.` with exit 0 while the real run crashes. `cli.md:82` documents that limit.

### What the card and the triage sketch (`BUGS.md#qa-kb-051`) missed

- **"Drop `newline='\n'`, it loses nothing" holds on POSIX only.** The kwarg arrived in `9d7bd554f` (2026-09-15, "Fix Windows cp1252
  encoding issues in build_architecture.py and build_context.py"), whose diff replaces every line of the file; the later merge
  `1d95275b4e` says "build_context.py: repaired CRLF/mojibake". A Windows skill variant exists (`skills/velocity-win`). Without the kwarg,
  Windows text mode writes CRLF. The intent is INFERRED and Windows was not run. `OUT_PATH.write_bytes(body.encode("utf-8"))` is valid on
  3.9, writes LF on every OS, and is the form that was verified in the sandbox.
- **The triage sketch's "snapshot INDEX.md and state.yaml before the index stage and restore them if context or validate fails" is wrong in two places.** (a) Not on
  `validate`: `skills/velocity/book-keeping.md:206` says a non-zero exit from `validate` does not fail a card write ("it fails on ANY broken
  link in `.knowledge/` — including ones that predate your card"), so restoring would undo a correct index because of an unrelated broken link.
  (b) `build_index.py`'s docstring (`:1-7`) says it "writes only INDEX.md and state.yaml. Never touches cards", but
  `write_related_blocks(cards)` (`:308`, `:204-253`) rewrites each card's `## Related` block, so the index stage also leaves card files
  behind. Those rewrites are idempotent and harmless; a snapshot design still has to know about them.
- **With `--set-sync-point` the index stage also moves the sync watermark** (`rebuild_knowledge.py:324`, `build_index.py:375-381`) before
  `context` runs. Reproduced in the sandbox and filed as [ISS-971](20261002-0342-ISS-971.md).
- **`context` does not depend on what `index` wrote.** `build_context.py:372` (`state = load_state()`) is the only use of `state` in
  `main()`, and its value is never read; it is a precondition check (`:163-198`). The comment at `rebuild_knowledge.py:15-18` justifies the
  order by `modules.json` and the MOD cards, which belong to `architecture`. That leaves an ordering fix smaller than a rollback (see Fix).
- **The abort message is the one `cli.md:76` warns about.** `rebuild_knowledge.py:326` prints
  `Aborted at stage 'context'. Nothing further was run.` and does not say that `index` already wrote.

### Fix (where it belongs)

1. **`tools/knowledge/build_context.py:431`**, the one line every caller routes through: `OUT_PATH.write_bytes(body.encode("utf-8"))`. No
   doc, hook or interpreter edit is needed; every `python3` spelling above works again. This alone meets the report's Expected (the
   rebuild completes under bare `python3`).
2. **`tools/knowledge/rebuild_knowledge.py:main()` (`:322-331`)**, the single owner of stage order (`hook_mode()` re-enters it), for the
   card's second defect. Three options, lightest first; only (b) and (c) keep `INDEX.md` and `state.yaml` from running ahead of
   `CONTEXT.md`:
   - (a) Legibility only: at `:326` name the stages that already wrote ("index wrote INDEX.md and state.yaml and was not rolled back; re-run,
     the stages are idempotent"). It stops the misreport `cli.md:76` warns about and leaves the files advanced.
   - (b) Run `context` before `index`. A `context` failure then leaves `INDEX.md`, `state.yaml` and the watermark untouched, and
     [ISS-971](20261002-0342-ISS-971.md) closes with it. It needs the `load_state()` precondition relaxed (`build_context.py:163-198`) and
     touches the `cli.md:58-60` diagram, `7-closer.md:88` and the comment at `rebuild_knowledge.py:15-18`. The mirror image (`index`
     failing after `context` wrote) remains. INFERRED that nothing else depends on the order; the fixer should check.
   - (c) A real rollback of the files the failed run wrote, honouring the two constraints above (never on `validate`; snapshots outside
     `.knowledge/`). Heaviest; only worth it if the full rebuild (35 hand-prose MOD cards plus `modules.json`) must be atomic too.
3. Do not add an interpreter version guard as the fix. After (1) the cards-only path runs on 3.9.6, so a guard would only protect against
   the next 3.10-only API; the durable protection is the regression test below.

## Resolution 2026-10-02 (QA-KB-051)

  `OUT_PATH.write_bytes(body.encode('utf-8'))`. Under `/usr/bin/python3` 3.9.6 the cards-only rebuild now completes, and
  the output is byte-identical to what the old call wrote under 3.13.
- **Not fixed: the second defect,** "Make the ordering survivable". It is deferred to

  for it.
- **Not fixed: the watermark sibling.** [ISS-971](20261002-0342-ISS-971.md) is still open.
