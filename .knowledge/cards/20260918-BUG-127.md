## The symptom

An operator follows the command table in `skills/velocity/cli.md` — any row of
it — and the rebuild dies partway through with

```
TypeError: write_text() got an unexpected keyword argument 'newline'
```

raised from inside `build_context`. Nothing in that message says "wrong
interpreter", so the natural reading is that the knowledge tooling is broken.

## Root cause

One line. `tools/knowledge/build_context.py:431`:

```python
OUT_PATH.write_text(body, encoding='utf-8', newline='\n')
```

`newline=` was added to `Path.write_text` in Python 3.10. It is the **only**
write in the whole pipeline that carries it — `build_index.py:46`,
`apply_summaries.py:131` and `build_architecture.py:720`, `:724`, `:1983` all
call `write_text(content, encoding="utf-8")` and nothing else. It arrived in
`9d7bd554f` (*docs(knowledge): sync to 4a6e8993, add FIX-503/504, refresh 6
domain cards*).

Every documented entry point spells the interpreter as a bare `python3`:

- all eleven rows of the command table in `skills/velocity/cli.md:12-22`, plus
  the inline examples at `:40-41`, `:55` and the sub-skill table at `:168-172`;
- `.pre-commit-config.yaml:176`, `entry: python3 tools/knowledge/rebuild_knowledge.py --hook`
  under `language: system`, which resolves `python3` from `PATH` — and its own
  manual-run instruction at `:183`.

On this machine `which -a python3` puts `/usr/bin/python3` first, and that is
3.9.6. Reproduced read-only:

```
$ /usr/bin/python3 -c "Path(...).write_text('a', encoding='utf-8', newline='\n')"
FAILS: write_text() got an unexpected keyword argument 'newline'
```

`rebuild_knowledge.py` spawns every stage with `sys.executable`
(`run_stage` at :82, `_run` at :165), so whichever interpreter the operator
typed is inherited by all four stages — and by `hook_mode()`'s phase 3, which
re-enters this same script with `--skip-architecture`.

Nothing else in the tooling needs 3.10: `py_compile` under `/usr/bin/python3`
succeeds for all eight scripts in `tools/knowledge/` (the allocation brief said
nine; `prompts/` is a directory, not a script). This single runtime kwarg is
the entire 3.10+ dependency.

## Why the ordering makes it worse than a crash

`STAGES` is `architecture, index, context, validate`. `index` writes
`INDEX.md` and `state.yaml` (`build_index.py:25-26`, `:333`, `:379`) **before**
`context` runs. So when `context` dies:

- `INDEX.md` and the `state.yaml` watermark are already rewritten,
- `CONTEXT.md` is still the old one,
- `validate` — the stage that certifies coherence — is never reached.

That is precisely the state the `rebuild_knowledge.py` docstring (lines 3-5)
promises cannot happen: *"a single command that cannot be run half-way or in
the wrong order"*.

The blast window is widest on the path the routine verbs actually take.
`prime.md` and `book-keeping.md` both run `--skip-architecture`, where `index`
is stage 1 and `context` is stage 2 — the crash lands immediately after the
only irreversible writes.

In `--hook` mode it also fails the commit at phase 3 without the `_git_add`
that would have staged the regenerated files, so the half-applied store is left
unstaged in the tree.

## Why this is reachable now

[BUG-031](20260827-BUG-031.md) got the knowledge hook re-gated to
`stages: [manual]`, so `git commit` no longer fires the rebuild. The rebuild is
now something an operator types by hand from that command table — which is
exactly the invocation that picks the wrong interpreter.

## What a fix must do

Two independent defects, both worth closing:

1. **Drop the kwarg** at `build_context.py:431`, or spell the interpreter as
   `backend/.venv/bin/python` everywhere `cli.md` and `.pre-commit-config.yaml`
   say `python3`. Dropping the kwarg is the smaller change and loses nothing —
   POSIX text mode already writes `\n` unchanged. Note that `validate_links.py`
   is already run with `backend/.venv/bin/python` in practice, which is why the
   validator appears healthy while the rebuild is not.
2. **Make the ordering survivable.** A stage failure after `index` should
   either roll the watermark back or refuse to leave `state.yaml` advanced
   while `CONTEXT.md` is stale. Fixing only (1) leaves the next 3.10-only API
   free to reproduce this.
