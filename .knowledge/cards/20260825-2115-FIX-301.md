## Symptom

The ppt deliverable opened with ```` ```html ```` instead of `<!DOCTYPE html>`, so
`sanitize_carousel_deck_html`, `strip_pre_slide_body_text` and `unwrap_artifact` all operated on a
string that did not start where they expected. Preview: "Invalid presentation output".

## Root cause

Nothing in the ppt chain stripped a markdown fence. `unwrap_artifact` handles an
`<artifact>` wrapper only; there was no fence equivalent anywhere in
`agents/capabilities/deliverables/`.

## Fix

`strip_code_fence` in `_artifact.py`, wired in **two** places:

- `deliverables/ppt.py` — first in the transform chain, before the sanitize
- `execution_engine/engine.py` — the mid-stream sanitize, so `ppt-validator` consumes a
  fence-free `ppt-composer` artifact rather than being handed a fenced blob to "validate"

Deliberately narrow: only a fence at position 0 (after leading whitespace), and its closing
partner only when present — an unterminated fence from a truncated generation is still salvaged.
