## What happened (sibling of ISS-222)

Filed while analyzing `BUG-20260828-025521-library-hooks` ("Hook cards on the Hooks tab are not
keyboard-operable"). [ISS-222](20260828-1534-ISS-222.md)'s root cause is
`frontend/src/components/library/LibraryPage.tsx:914-920`: the Hooks grid renders
`<Card onClick={...} className="... cursor-pointer ...">` with no `tabIndex`, no
`role="button"`, and no `onKeyDown`. `Card` (`frontend/src/components/ui/Card.tsx:15-29`) is a
plain `<div {...rest}>` wrapper — it adds none of that by default, so any caller that attaches
`onClick` must supply the keyboard affordances itself. ISS-222 already flagged that "the same
unguarded-`onClick`-`Card` pattern is also used one map up for the Skills tab's cards" but only
asserted the Hooks tab.

Reading the Agents grid confirms the pattern extends to a second tab: `LibraryPage.tsx:735-758`
(`filteredAgents.map((agent) => { ... return (<Card key={...} onClick={...} className={...
cursor-pointer ...}> ... `) })`). `onClick` (line 741) opens the agent's capabilities via
`setSelectedAgent(...)` + `router.push(routes.libraryAgent(agent.id))`; `className` carries
`cursor-pointer` (line 756) for launchable agents. The whole block (740-758) has no `tabIndex`,
`role`, or `onKeyDown` — confirmed by direct read of every line in that range.

Tab, from the category-filter pills, therefore skips the entire Agents card grid exactly as
ISS-222 documents for Hooks: none of the agent cards is keyboard-reachable, so the "Configure →"
affordance shown on each card has no keyboard path. This holds for both launchable agents and
`BETA_WORKFLOWS`-gated ("Coming Soon", `cursor-not-allowed`) agents alike — the beta/disabled
guard lives inside the `onClick` handler's body (`if (!BETA_WORKFLOWS.has(...))`), not on the
element itself, so it changes what a click *does*, not whether the card is reachable by keyboard.

## Why the root cause implies this

ISS-222 states the flaw as a repeated pattern across the file's tabs, not a Hooks-only one-off.
The Agents grid is the same `Card` + bare `onClick` shape, in the same file, missing the exact
same three attributes — this is "other callers with the same flaw," not a different mechanism.

## Confidence

CONFIRMED mechanism — `LibraryPage.tsx:735-758` read directly, no `tabIndex`/`role`/`onKeyDown`
anywhere in the block. INFERRED as a live defect: not yet reproduced with a real keyboard press
or DOM query the way ISS-222 was (3/3 cold-start cycles, one with Playwright
`page.keyboard.press('Tab')`). Settling it: on `/library` (Agents tab, default), run
`document.querySelectorAll('.cursor-pointer')` inside the Agents grid and check `tabindex`/`role`
on each result, or Tab from the category pills and confirm focus never lands on a card.
