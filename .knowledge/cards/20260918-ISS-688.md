## The gap

Two distinct failure modes were observed in one workflow, both closable only by
a per-step model pin, and neither catchable by any existing guard.

**1. A machine-parsed output became prose.** `fi-planner` narrated its plan
instead of writing `build/tasks.json`, so the task parser had nothing to read
and the run died at step one. The same prompt on the same model had succeeded an
hour earlier — a capability coin-flip, not a prompt bug.
[FIX-545](20260904-FIX-545.md) prefers the on-disk task file over the narrating
reply, but that cannot help when the file is never written at all.

**2. A verbatim output was "improved".** `fi-readers` REWROTE a Data
Dictionary. `CUST-REQ; MTR-FAIL; COMPLIANCE; LEAK-RPT; NO-ACCESS-RETRY` came
back as eight invented prose labels; four fabricated values shipped into the
deliverable and not one real code survived. A Sonnet step downstream cannot
recover values it was never handed. That is silent data corruption reaching the
customer-visible artifact **while the run reports success**.

The prompt gap is worth recording on its own: the reader prompt said "keep every
fact", and only the Screenshots block forbade vagueness. Nothing forbade
REWRITING a value — and a model will happily tidy a code list into readable
English while obeying "keep every fact".

## The mechanism

`ModelResolver.resolve` (`backend/agents/model_policy.py`) applies the D-02
precedence: override > `step.model` > `AgentSpec.model` > workflow model >
session model id > **5b, the global Haiku default**
(`settings.BEDROCK_INFERENCE_PROFILE_ID`, seeded onto `ectx.model_resolver` in
`ExecutionEngine.execute`). A step with no `model:` line lands on 5b, silently.
See [ISS-164](20260819-1726-ISS-164.md) / [FIX-263](20260819-1726-FIX-263.md)
for the per-step tier itself.

Note on the evidence trail: ISS-164's summary places this at
`engine.py:4156 _resolve_model`. That line number is stale in the current tree —
`_resolve_model` now sits at `engine.py:7733` and only delegates to
`ectx.model_resolver.resolve(spec, step)`; the tier-5b default lives in
`ModelResolver.resolve` and is seeded around `engine.py:4908`.

## What was done, and why it does not close the issue

`73796dbd0` pinned 5 of `prototype_v2`'s 11 steps to
`eu.anthropic.claude-sonnet-4-6` — `fi-planner`, `fi-readers`, `pb-spec`,
`pb-design`, `pb-validate` — and added a Phase 2 rule to the `fi-readers`
prompt:

> An option list, code list, range or format spec is COPIED, never described.
> Reproduce it character for character - same case, same separators, same
> order. [...] Adding an option the source does not list, dropping one, or
> renaming one is a defect, not a tidy-up.

The corrected run (`26a7e162`) was verified in the browser to show the real
codes. But the pins are mitigations for two specific steps. The class of defect
is unguarded: nothing anywhere requires a pin on a step whose output is parsed
as JSON or must be reproduced verbatim, so the next one written will default to
Haiku exactly like these did. The remaining 6 unpinned `prototype_v2` steps and
every other manifest in the tree are in that same position.
