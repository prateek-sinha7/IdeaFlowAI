# ISS-1132

**Register source:** found by the `QA-KB-105` 5-fixer on 2026-10-09 while running the resume-tier test files for
[FIX-770](20261009-0102-FIX-770.md). It is not that bug's. No bug row.

## Observed (offline)

`backend/tests/unit/agents/workflows/test_specs_from_plan.py::test_resume_paths_call_the_shared_helper_not_a_bare_comprehension` fails
the same way at HEAD `eb84ce544` (a `git archive` copy, engine unmodified) and with FIX-770 applied:

```
E       AssertionError: expected _specs_from_plan(compiled.steps) at all 3 known call sites (execute, resume_run, _derive_offset);
        found 2. If a call site was legitimately removed, lower this bound deliberately — do not delete the test.
E       assert 2 >= 3
```

Evidence: `evidence/qa-kb-105/fix-04-baseline-at-head-and-lint-imports.txt` (HEAD) and `evidence/qa-kb-105/fix-03-regression-files-pytest.txt`
(with the change). The other 5 tests in the file pass.

## Mechanism (CONFIRMED by reading)

The test (`test_specs_from_plan.py:121-142`) makes two checks. First, the banned FIX-266 pattern
`[load_agent_spec(s.agent_id) for s in compiled.steps]` must not appear. That check passes. Second, it counts the literal text
`self._specs_from_plan(compiled.steps)` and requires at least 3. Today `engine.py` has that exact text twice (`:5027`, `:16480` in the
working tree of 2026-10-09). The resume drivers still call the shared helper, under other variable names:
`self._specs_from_plan(resumed_compiled.steps)` and `self._specs_from_plan(plan_steps)` in `resume_run`, and the same pair in
`_replay_clarify_run`. So the display-name overlay FIX-266 protects is still applied. Only the ratchet's anchor text is out of date.

`resumed_compiled.steps` came in with `127b20a3d` and `f23625911` (`git log -S"resumed_compiled.steps"`). When the count first fell below 3
is not established. FIX-768's 17-file set did not include this file.

## Disposition

Open, for the test's owner. The test itself says what to do: "lower this bound deliberately — do not delete the test". The other choice is
to count `self._specs_from_plan(` over any steps expression. Engine code does not change either way. Not fixed in FIX-770, because changing
an assertion is outside a fixer's remit there.
