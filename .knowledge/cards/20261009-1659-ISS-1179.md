# ISS-1179

**Register source:** sibling derived during the `QA-KB-120` analysis on 2026-10-09 (root [ISS-1159](20261009-1530-ISS-1159.md)). Not its own bug row. It is the test-tier half of "why was this never caught".

**Confidence.** CONFIRMED offline: `evidence/qa-kb-120/analysis-05-probe-fakesandbox-hash-order.txt` (8 hash seeds, 4 different staged sets) and `evidence/qa-kb-120/analysis-06-existing-tests-walk-the-failing-path.txt` (three existing tests, all green, each logging the `stage_exact failed` warning). INFERRED: which of the other importers of the double depend on the divergence. Only the unmaterialized-output path was traced.

## Condition

A test that builds a payload for an unmaterialized output against `FakeSandbox` (`backend/tests/agents/test_finalizer_v2.py:116-235`) instead of a real `RunSandbox`. The shared double is imported by `test_nameless_deliverable_v3.py`, `test_revision_ordinal_v3.py`, `test_rollback_safety.py`, `test_serialized_sandbox_payload_v3.py`, `test_streamed_text_payload_parity.py`, `test_streamed_text_payload_v3.py`, `test_version_family_v5.py`, `backend/tests/unit/agents/test_phase3_cutover_verify.py` and `backend/tests/agents/characterization/_normalize.py` (a grep of the import line, not a trace of what each one stages).

## Mechanism

- Production: `LocalWorkspace.stage_exact` is one `self._git("add", "--force", "--", *paths)` (`local.py:1426-1434`). Git validates every pathspec before it stages, so one missing path stages nothing (`evidence/qa-kb-120/analysis-01-git-add-semantics.txt`, case A).
- Double: `FakeSandbox.stage_exact` runs one `git add` per path and stops at the first failure (`test_finalizer_v2.py:181-183`).
- `build_flat_payload` hands it `list(_allowlist)` (`engine.py:1757`), a frozenset of `str`, so the order follows `PYTHONHASHSEED`. After the same call the double has staged none, one or both of the two files that exist. `analysis-05`, seeds 0 to 7: `[]` three times, `['.chain/logs.jsonl']` twice, `['.chain/summary.md']` once, both twice. The real workspace always gives `[]`.

## Effect

1. Three existing tests walk the QA-KB-120 failure and pass: `TestBuildFlatPayload::test_payload_materialized_false_when_output_absent` (`:2094`), `TestMetadataOnlySnapshot::test_c2_output_unmaterializable_yields_metadata_only` (`:750`) and `test_c5_prior_run_stale_chain_path_untracked_tree_clean` (`:815`). None asserts on the staged entries or on a log record, and `build_flat_payload` swallows the error, so the suite is blind to it.
2. A red test for [ISS-1159](20261009-1530-ISS-1159.md) written on the double that asserts "`logs.jsonl` and `summary.md` are staged" is red for six seeds and accidentally GREEN for two (seeds 3 and 7) before any fix. A red test that is sometimes green is not a red test.
3. The double raises a `RuntimeError` that carries git's stderr (`_run_git`, `test_finalizer_v2.py:98`: "fatal: pathspec ... did not match any files"), while the production `_git` raises a bare `CalledProcessError` (`local.py:385-404`: output is captured, and stderr stays on the exception object, out of the logged message). The test logs are more informative than the real one.

## Expected vs actual

Expected: the double behaves like the primitive it stands for, one `git add --force -- *paths`. Actual: one process per path.

## Fix direction (INFERRED, not applied)

Test-only. Either make `FakeSandbox.stage_exact` a single `_run_git("add", "--force", "--", *paths, cwd=self.root)`, or build the payload tests on a real `RunSandbox` as `backend/tests/unit/app/test_binary_deliverable.py:96-108` does. Do it in the change that adds the ISS-1159 red test, because it decides whether that test is reliably red. Then run each importer listed above, one file at a time: a double that now fails the way git does may expose a test that relied on the partial staging.

## Test notes

`PYTHONHASHSEED=0` through `7`, `./.venv/bin/python -m pytest <the new test> -q -p no:cacheprovider` from `backend/`, is the cheap way to prove the new red test is red for every seed. Tests under `backend/tests/agents/` are not covered by the unit I/O guard; under `backend/tests/unit/` a real-git test needs `@pytest.mark.allow_io("reason")` (`backend/tests/unit/conftest.py:17`, `:103-145`).
