# FIX-765

Resolves [ISS-896](20261001-2127-ISS-896.md) (QA-KB-099, root) and its sibling [ISS-1109](20261008-1410-ISS-1109.md).
The analysis on those cards was used as written. It was not re-derived. Test files and one comment changed. No product code changed.

## What was wrong

Two unit-tier tests died before their first assertion with `tests.unit.conftest.UnitIsolationError`:

- `test_sigterm_reaches_the_lifespan_shutdown_half_while_a_stream_is_live` (`backend/tests/unit/services/test_shutdown_reachability.py`).
  This is the end-to-end proof for [ISS-088](20260812-0604-ISS-088.md). It was refused at its `subprocess.Popen(` of uvicorn
  (now `:190`), and it would also have been refused at its two `socket.create_connection(("127.0.0.1", port))` calls (`:135`, `:149`).
- `TestV2EventTypesAreEmittedByTheirProducers::test_run_finalization_failed_is_emitted_on_a_degraded_finalization`
  (`backend/tests/unit/agents/test_phase3_cutover_verify.py`). This test checks the Req 20 AC 5 event contract. It was refused at
  `['git', 'init', '-b', 'main']`, which it reaches through `_setup_sandbox`, imported from `backend/tests/agents/test_finalizer_v2.py`.

## Root cause (from the cards, confirmed by re-running)

The autouse `_unit_io_guard` (`backend/tests/unit/conftest.py:90-91`) returns early only for a node with an `allow_io` marker
(`get_closest_marker("allow_io")` at `:118`). For every other node it replaces `subprocess.Popen.__init__` with `_deny_popen` (`:127`).
It also replaces `socket.socket.connect` / `connect_ex` with `_deny_connect` (`:152`, patched in at `:170-171`). Commit `09270703b`
added the guard and, in the same commit, moved both test files into `tests/unit/`. Neither test carried the marker. The guard is
correct and is shared by every unit test. The fault is that these two tests lack the annotation.

## What changed, and why there

1. `backend/tests/unit/services/test_shutdown_reachability.py:156-163`. An audit note and an `allow_io` marker were added on top of the
   SIGTERM test's decorator stack. The wording is the one [ISS-896](20261001-2127-ISS-896.md) recommends, re-wrapped to 88 columns
   with no words changed:
   reason `"ISS-088 end-to-end proof: spawns a real uvicorn subprocess, talks to it over 127.0.0.1 sockets and sends it a real SIGTERM;
   nothing outside this process tree and loopback"`. The test body is unchanged. The test-writer's `issue` and `xfail(strict=True)`
   markers (`:164-165`) are still in place for the 6-verifier.
2. `backend/tests/unit/agents/test_phase3_cutover_verify.py:496-503`. An audit note and an `allow_io` marker were added on the one
   test method, as [ISS-1109](20261008-1410-ISS-1109.md) directs. The reason is `"drives the real finalizer against a real git sandbox in
   tmp_path; spawns only git, inside tmp_path; no database or network"`. The audit note gives the real cost of the alternative:
   moving the test also means moving the real-git helpers out of the legacy `tests/agents/test_finalizer_v2.py`. It does not claim
   a migration plan exists.
3. `backend/app/main.py:412`. The lifespan comment named `tests/unit/test_shutdown_reachability.py`, a path that has not existed
   since the move. It now names `tests/unit/services/test_shutdown_reachability.py`. This is a comment only, and the ISS-896 card asks for it.

Why a marker and not a guard change: a carve-out in the guard would weaken it for about 4,000 unit tests, and ISS-1109's locked constraint
forbids one. Why a marker and not a move: both cards recommend the marker as the smaller diff. The same family already uses it:
`tests/unit/app/test_run_stream_pool_leak.py`, which the reachability test's own docstring names, plus `test_run_sandbox_api.py`
and `test_ci_bounded_runner.py`. A move would also have to repoint both hard-coded paths in
`test_run_shutdown_stale_citations.py` and keep `parents[4]` resolving to the repo root.

The blast radius was re-checked (`fix-06`). `grep -rn "_setup_sandbox\|test_finalizer_v2 import" backend/tests/unit` still finds only
the ISS-1109 test. The other readers of `test_phase3_cutover_verify.py` import module names (`_DOCUMENTED_EVENT_TYPES` and the
helpers), which are unchanged. No test counts `allow_io` markers: the README's and `test_unit_io_guard.py`'s "exactly ONE" claims are
prose that nothing enforces.

## Are the reasons true? (I/O recorder probe)

`allow_io` lifts all three guard layers, so each reason was checked. A scratch plugin recorded every DB connect, socket connect
and spawn while the two marked tests ran. It never denies anything, and it imports neither `app` nor the engine
(`evidence/qa-kb-099/fix-plugins/io_recorder_probe.py`):

- SIGTERM test: 1 spawn (`<venv>/python -m uvicorn reachability_probe_app:app ...`), 4 socket connects, all to `127.0.0.1`, and 0 DB connects.
- Finalizer test: 17 spawns, all `git` (`init`, `config`, `add`, `commit`, `diff`, `rev-parse`, `update-ref`, `reset`, `ls-files`),
  0 socket connects and 0 DB connects.

Evidence: `evidence/qa-kb-099/fix-04-io-recorder-probe-allow-io-reasons.txt`.

  were not counted.
