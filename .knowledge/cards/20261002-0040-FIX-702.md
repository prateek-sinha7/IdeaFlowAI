## What was wrong

This is bug report QA-KB-014. The root cause comes from [ISS-371](20260828-2140-ISS-371.md) and is not re-derived here.

[FIX-352](20260828-2346-FIX-352.md) put the Back guard in DashboardLayout's shared `handleBackNav`
(`DashboardLayout.tsx:1875-1889`, `if (hasUnsavedWork.current) { setConfirmingBackNav(true); return; }`) and wired
only ComposerPage into it. IdeaInputPage serves `/create/user-stories` and the other non-wizard `/create/<type>` routes.
It had no `onUnsavedChange` prop, and its mount passed none. While it was mounted, nothing set
`hasUnsavedWork.current = true`, so Back always took the unguarded `goBackOr` branch. The validator reproduced this 3/3
(`evidence/qa-kb-014/01..06-*.png`).

## What changed, and why there

Line numbers are as of this fix, in the uncommitted tree. Two files are touched, at the two points the card named. The
guard itself is unchanged, because FIX-352 locked it in place.

1. `IdeaInputPage.tsx:778-780`: a new optional prop, `onUnsavedChange?: (dirty: boolean) => void`, destructured at
   `:962`.
2. `:959-960` and `:1014-1030`: `rosterKey` (the roster's ids, joined) and two baselines held in state. `briefBaseline`
   starts at `initialInput ?? ""`. `rosterBaseline` starts at the lazily initialised roster. `hasUnsavedWork` is derived
   in render, and is true when the brief differs, the roster ids differ, or a file or image is attached. One effect
   reports it and cleans up with `() => onUnsavedChange?.(false)`. This is the same contract as ComposerPage's reporter
   (`ComposerPage.tsx:374-379`).
3. Analyzer amendment (a). The roster-seed effect moves the roster baseline in the same callback as each programmatic
   `setPipelineAgents`:
   - `:1388`, the saved-ids restore once the library loads;
   - `:1399`, a custom workflow starting blank;
   - `:1430-1435`, the library, manifest or override roster.

   These seeds land after mount with no user action. Without the move, an untouched page reads as dirty. Both setters
   run inside one effect callback, so React batches them, and no render sees a moved roster with an old baseline.
4. Analyzer amendment (b). Both save paths move both baselines after the server accepts: `handleSaveWorkflow`
   `:1723-1725` and `handleSaveAsOverride` `:1810-1812`. Unlike Run, Save keeps the page mounted.
5. Analyzer recommendation. Attachments count as unsaved while present (`attachedFiles` and `attachedImages`,
   `:1025-1026`): only the user adds them, and no save keeps them. `stagedUploads` is not counted separately. Every
   entry in it belongs to an `attachedFiles` entry, and `removeFile` drops both (`:618-627`).
6. `DashboardLayout.tsx:3162`: `onUnsavedChange={handleUnsavedChange}` on the `<IdeaInputPage>` mount, next to
   `onBack={handleBackNav}`.

The remaining roster writers are user actions, so they correctly read as dirty: `setPipelineAgents` at `:1832` (add),
`:1867` (remove), `:1871` (reorder) and `:2125` ("Add N missing"). `ideaInput` is written only by the textarea (`:1948`)
and by dictation (`:1545`).

Not changed:
- the guard (`DashboardLayout.tsx:1847-1889`);
- its in-app dialog (`:3479-3517`, "Leave without saving?", "Stay", "Leave anyway");
- the Back button (`IdeaInputPage.tsx:1907`, still `onClick={onBack}`).

There is no `window.confirm` (S-19-17) and no new dependency.

## Test added, and why

`IdeaInputPage.iss371.rebaseline.test.tsx` is new, with 3 plain `it` tests and no marker. The shipped `it.fails` file
preloads the agent library, so its roster never moves after mount. With every rebaseline call removed, its three bodies
still pass (`evidence/qa-kb-014/09-fix-variant-proof.txt` §C). It cannot tell this fix from the naive mount-time
baseline that ISS-371's analysis warns about.

The new file covers the three "For the test-writer" cases the shipped file leaves out:
- a cold library whose roster arrives from a mocked `getWorkflowDetail` after mount, which must never report true;
- a successful Save, which must report false;
- unmount, which must report false.

It fails 3/3 against HEAD's component and 2/3 against the naive variant (`09-fix-variant-proof.txt` §A and §B).
