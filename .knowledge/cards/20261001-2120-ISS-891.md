# ISS-891

Register entry: **QA-KB-027** (`BUGS.md`). Sibling of [ISS-724](20260922-1246-ISS-724.md) (root): it is that
card's second fault (fixture drift) seen in files the first fault (the unit I/O guard) does not reach.
Derived from the root cause, then **CONFIRMED by running every file below**, one file per invocation, on 2026-10-01.

## Condition

`User` no longer accepts `password_hash`. The model's own comment (`backend/app/models/user.py:46-50`) records the
Cognito-only migration (0038): `cognito_sub` is NOT NULL, unique, and the identity mapping (`:51`).
`git log -S password_hash -- backend/app/models/user.py` ends at `b2a621f84` ("Fix/cognito login (#8)", 2026-09-17),
and `grep -rn password_hash backend/app` finds nothing. Any test that builds `User(..., password_hash=...)`
raises at fixture setup:

```
TypeError: 'password_hash' is an invalid keyword argument for User
```

## Expected vs actual

- **Expected**: a test that seeds a user builds one the current model accepts, and the test runs.
- **Actual**: 11 files still pass the removed kwarg and do not run.

## Why the root cause implies this

The root card's `env` + `_seed_user` block is copy-pasted: `grep -rln "def _seed_user" backend/tests` finds 24
copies. 17 were moved to `cognito_sub=...` when the model changed, 1 (`test_ttl_sweep_loop_v3.py`) calls the shared
factory, and 6 were not (`test_restore_guard_v3`, `test_revision_routes_v3`, `test_gate_redo_enforcement`,
`test_duplicate_context_guard`, `test_run_files_ref_family_scope`, `test_sandbox_ref_scoped_endpoints`); five more
files build `User` inline with the stale kwarg. Four of those eleven are the revision/restore/Workspace guards this
bug is about. INFERRED: the missed copies were cloned from an older template (`test_revision_routes_v3.py` is
2026-09-12, before the model change).

## Fix — where it belongs

One seed, not eleven edits. `tests/factories/user_factory.py::create_user(session, email, password, *, tier, is_admin,
cognito_sub)` is the repo's own "shared helper for creating Cognito-backed users in tests" (its docstring), yet only 6
test files import it while 24 define their own `_seed_user` and 35 files set `cognito_sub=` themselves (grep).

- Minimal: replace `password_hash="x"` with `cognito_sub=str(uuid.uuid4())` at the call sites above (the pattern
  already in `tests/integration/api/test_run_files_upload_api.py::_seed_user`).
- Better: call `create_user(db, email, "x")` so the next model change is one edit.
- Do **not** re-add `password_hash` to `User` (that revives the local-password path the Cognito migration removed),
  and do not touch `tests/unit/conftest.py` (that is the root card's separate, placement fault).

`test_sandbox_ref_scoped_endpoints.py` and `test_run_files_ref_family_scope.py` were relocated to
`backend/tests/integration/api/` with the swap and pass (see [ISS-724](20260922-1246-ISS-724.md) and
