## What happened

Six of the app's 8 global hooks render a "Compatible agents" section on their
`/library/hooks/<hookId>` detail page listing one or more agent ids that do not
correspond to any real agent in the 94-agent Agents library
(`GET /api/agents/library`). The chips are plain non-interactive `<div>`s (no
`<a>`, no `onClick`, `cursor: auto`), so a user has no way to discover the
mismatch from the UI — the fictional agent name is simply presented as fact.

Reproduced 3/3 from a cold start (fresh navigation to `/library/hooks/<id>`
each time, no soft re-click):

- **Cycle 1** — `http://localhost:3000/library/hooks/post-design-quality`:
  Compatible agents chips render `app-ux-design, html-prototype-builder,
  prototype-polisher, ppt-slide-architect`. Cross-checked against
  `GET /api/agents/library` (94 ids, fetched fresh each cycle): only
  `app-ux-design` exists. `html-prototype-builder`, `prototype-polisher`,
  `ppt-slide-architect` are absent from the full agent list.
- **Cycle 2** — `http://localhost:3000/library/hooks/session-start` (fresh
  navigation via `/dashboard` first): chips render `domain-analyst,
  requirements-analyst, app-user-stories, epic-architect,
  app-code-generator`. `requirements-analyst` is absent from the agent list
  (`hasRequirementsAnalyst: false`); the closest real agent is
  `chat-requirements` (`hasChatRequirements: true`). The same fictional id
  also appears in the page's own "How to use" step 3 prose ("Best suited for:
  domain-analyst, requirements-analyst, app-user-stories and more.").
- **Cycle 3** — `http://localhost:3000/library/hooks/stop-console-log` (fresh
  navigation via `/dashboard` first): chips render `app-code-generator,
  app-feature-implementation, html-prototype-builder`. `html-prototype-builder`
  is absent from the agent list.

Conditions: `qa-admin` tier, light theme (default), deep link entry each
cycle, no prior navigation state carried over. No account/theme/viewport
variation was needed — this is unconditional per affected hook, not
timing- or state-dependent.

## Root cause

`backend/app/agents/hooks_catalog.py` loads each hook from
`backend/hooks/global/{hook_id}/HOOK.md`, taking `compatible_agents` straight
from that file's YAML frontmatter (`hooks_catalog.py:103`,
`compatible_agents=list(metadata.get("compatible_agents", []))`) with no
validation against the live agent catalog. The frontend
(`frontend/src/hooks/useHooksCatalog.ts`, rendered by
`LibraryPage.tsx`) renders that array verbatim as static chips. The defect is
stale/incorrect seed data in the `HOOK.md` frontmatter files (referencing
agent ids — `html-prototype-builder`, `prototype-polisher`,
`ppt-slide-architect`, `requirements-analyst` — that were apparently renamed
or removed from the agent catalog without the hooks' frontmatter being
updated), not a frontend rendering bug.

## Expected vs actual

**Expected:** every id in a hook's `compatible_agents` list resolves to a real
agent in `GET /api/agents/library`.

**Actual:** `post-design-quality`, `session-start`, `stop-session-end`,
`stop-console-log`, `stop-format-typecheck` (5+ of 8 hooks per the register
entry) list one or more nonexistent agent ids, presented as non-interactive
plain text with no way for a user to detect the mismatch short of
independently querying the API.
