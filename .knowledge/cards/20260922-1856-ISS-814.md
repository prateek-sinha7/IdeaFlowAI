# ISS-814

## Description

Deferred finding from [FIX-615](20260922-1854-FIX-615.md) (QA-PS-028). Six tests
across three files were already failing on the working tree when that fix started,
for two causes unrelated to it and to each other. Recorded so the next session
reads this instead of re-deriving whether a red gate is its own regression.

Baseline SHA: `cae0c8adf`. FIX-615 touched `engine.py`, a new
`agents/capabilities/deliverables/_coverage.py`, and five `AGENT.md` bodies —
none of which can reach any of the assertions below.

## A. The no-tools preamble — 5 failures, 2 files

`backend/agents/factory.py:530` defines the anti-fabrication block, and
`:569` assigns it:

```python
_NO_TOOLS_PREAMBLE = """## Tool Availability

You have NO tools in this session. You must NEVER emit tool-call syntax of any
...
        blocks["tool_availability"] = _NO_TOOLS_PREAMBLE
```

**`test_skill_prompt_baseline.py`** — 2 failed. Both goldens compose
`domain-analyst` with `no_tools=True`; the golden
`characterization/golden/prompt_text_only_no_skills.txt` opens with
`## Tool Availability`, the composed prompt now opens with `## Guardrail`:

```
E   assert b'## Guardrai...der 400 words' == b'## Tool Ava...der 400 words'
E     At index 3 diff: b'G' != b'T'
```

**`test_prompt_contracts.py::test_sdlc_governance_anti_fabrication_contract`** —
3 failed (`app-`, `dotnet-`, `mulesoft-sdlc-governance`), all on
`assert "You have NO tools" in body`, where `body = load_agent_spec(id).prompt_body`.

### Why this is not FIX-615's

- `backend/agents/factory.py` is CLEAN at `cae0c8adf` (`git status --porcelain
  backend/agents/factory.py` → empty) and is not in FIX-615's diff.
- `domain-analyst/AGENT.md` is not in FIX-615's diff either.
- The literal the governance test wants was already absent at `cae0c8adf`:

```
$ for a in app dotnet mulesoft; do git show HEAD:backend/agents/prompts/$a-sdlc-governance/AGENT.md | grep -c "You have NO tools"; done
0
0
0
```

FIX-615's only edit to those three files ADDS one `OUTPUT CONTRACT` bullet; an
insertion cannot remove a string that was already at count 0.

## B. SC-001 banned literal in an engine docstring — 1 failure

`test_banned_patterns.py::TestSC001RevisionPipelineCompliance::test_no_revision_pipeline_names_in_kernel`:

```
E   Offenders:
E       agents/execution_engine/engine.py:891: with a ``prototype_revision`` child and a ``custom_revision`` child tagged
```

The hit is prose inside a docstring, not a dispatch branch, but the guard greps
for the literal. Byte-identical and at the SAME line number at `cae0c8adf`:

```
$ git show HEAD:backend/agents/execution_engine/engine.py | grep -n "prototype_revision\`\` child"
891:    with a ``prototype_revision`` child and a ``custom_revision`` child tagged
$ grep -n "prototype_revision\`\` child" backend/agents/execution_engine/engine.py
891:    with a ``prototype_revision`` child and a ``custom_revision`` child tagged
```

FIX-615's engine edits are at `:7293` and `:7454-7503` — thousands of lines below,
and they shifted no line at or before 891.

## Disposition

Not fixed here — outside QA-PS-028's cards, and (A) in particular needs whoever
owns the prompt-composition change to say whether the preamble was removed
deliberately (in which case three goldens and one contract test need
re-baselining, a product/spec decision) or dropped by accident (in which case it
is a real regression in the agent prompt contract). (B) is a one-word docstring
edit but belongs to whoever owns that SC-001 guard's scope.
