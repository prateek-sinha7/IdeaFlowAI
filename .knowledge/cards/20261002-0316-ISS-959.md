# ISS-959

## What happened

INFERRED sibling of [BUG-024](20260827-BUG-024.md) (QA-KB-049), the history case. Not reproduced in a browser.

The rewrite in BUG-024 is a `router.push` (`frontend/src/components/layout/DashboardLayout.tsx:855`), so it adds a
history entry. After a cold load the stack is `[..., /runs/R/audit, /runs/R/stream]`. Pressing Back:

1. Goes to `/runs/R/audit`. A back navigation across a `router.push` entry changes the `[...view]` params and remounts
   `page.tsx` (the comments at `frontend/src/app/[...view]/page.tsx:3492-3498`, [FIX-298](20260825-FIX-298.md); only the
   shallow `pushState` tab switches of [BUG-030](20260826-1403-BUG-030.md) avoid the remount).
2. The new mount runs T7 for `/audit`. `runConnection.liveRunIds` still holds `R` (its `attachRun` ran), so T7 takes
   the fast path at `page.tsx:3511-3528` and calls `runStore.switchViewTo(runId)`. The store keeps in-flight runs across
   a remount (`frontend/src/hooks/useRunStateStore.ts:343-345`: only entries with `!isRunning` are deleted on unmount),
   so the viewed `pipelineState` is `R`'s running state again.
3. That changes the funnel effect's deps (`DashboardLayout.tsx:903`) from the fresh mount's idle state, so it pushes
   `/runs/R/stream` again, on top of the forward history.

Expected: Back leaves the generating run's page.
Actual (INFERRED): Back lands on `/audit` for a moment and is thrown forward to `/stream`; a second Back does the same.

## Root cause (CONFIRMED by source read; the behaviour is INFERRED)

Same effect as BUG-024, `DashboardLayout.tsx:854-856`. This card is the consequence of that rewrite being a push rather
than a replace.

## What settles it

Live tier only, because it needs a run in flight (the same fixture problem as `S-14-07`): cold-load
`/runs/{id}/audit` of a generating run, call `page.go_back()`, and assert the URL is not `/runs/{id}/stream`.

## Fixed by the root fix?

Yes: with no push there is no extra entry. Swapping `router.push` for `router.replace` at `:855` would remove the trap
but keep the tab forced, so it is not a fix for BUG-024.

## TEST COVERAGE — ISS-959

Open card, nothing changed for it. Source read on 2026-10-02 of `DashboardLayout.tsx`, `page.tsx` and
`useRunStateStore.ts` in the working tree. Nothing executed.

## Fixed — QA-KB-049 (fixer, 2026-10-02): [FIX-712](20261002-1155-FIX-712.md)

A cold load of a live run's own URL no longer pushes, so there is no extra `/stream` history entry to bounce back
from. `frontend/src/components/layout/DashboardLayout.bug024.test.tsx` proves the no-push half offline: 12 passed with the fix, 9 failed with the guard removed. The Back
gesture itself is live-tier only and was not driven. The 6-verifier's browser re-run covers it.
