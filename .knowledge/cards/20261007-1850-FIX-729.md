# FIX-729

## What was wrong

This fix is for register entry QA-KB-069. The root cause comes from the 2026-10-02 analysis on
[ISS-895](20261001-2126-ISS-895.md) and its sibling [ISS-1011](20261002-0544-ISS-1011.md). It was not re-derived
here. Every cited line was re-read in the working tree before editing, and every line number still matched.

Both defects are the same flaw: a `vi.mock("@/lib/api", () => ({ ... }))` factory is a closed set, and vitest throws
when code reads an export the set does not contain.

- **[ISS-895](20261001-2126-ISS-895.md), the bug's own file.**
  - `AgentDetailPanel.artifactVersions.test.tsx:16-19` returned only `getRunArtifacts` and `getToken`.
  - Since `3b4f02819`, the mount effect at `AgentDetailPanel.tsx:1321-1332` calls `getCapabilities(token)` (`:1325`)
    whenever `getToken()` is truthy.
  - The property read threw synchronously inside the effect, before the `.catch` at `:1330` existed.
  - Result: all 10 tests failed (fix-01).
- **[ISS-1011](20261002-0544-ISS-1011.md), the sibling.**
  - `RunHeader.tsx:308` destructures `getRunSandboxRefs` inside `import("@/lib/api").then(...)`.
  - The only `.catch` (`:313`) hangs off the inner `getRunSandboxRefs(...)` chain. The outer chain (`:308-314`) had no
    handler, so with a closed factory the destructuring throw became an unhandled rejection.
  - vitest counts an unhandled rejection as an error and exits 1, even when every assertion passes.
  - The comment at `:301-303` says the opposite: "a caller whose @/lib/api test mock omits getRunSandboxRefs gets a
    swallowed rejection here".
  - Observed before the fix (fix-02):

    | file | tests | Errors | exit |
    |---|---|---|---|
    | `PreviewPanel.revisionChip` | 2 passed | 2 | 1 |
    | `PreviewPanel.versionChip` | 5 failed | 5 | 1 |
    | `PreviewPanel.test` | 1 failed, 18 passed | 8 | 1 |

## What changed, and why there

Two lines in total. The complete diff is in `evidence/qa-kb-069/fix-08-diff.txt`.

1. **`frontend/src/components/results/AgentDetailPanel.artifactVersions.test.tsx:19` (ISS-895, test-only).**
   - The factory gains `getCapabilities: async () => ({ capabilities: [], model_catalog: [] }),`. This is the line
     ISS-895's analysis named.
   - **No assertion changed.** The test's expectations are untouched; only its mock was incomplete.
   - Why not production: ISS-895 shows production is correct. `getCapabilities` is an `export async function`
     (`api.ts:2272`), so only the strict mock can throw synchronously. A guard in `AgentDetailPanel.tsx` would bend
     the app to the test.
   - Why not an `importOriginal` spread: the real `getCapabilities` would make a network call under
     `getToken: () => "test-token"`.
2. **`frontend/src/components/preview/RunHeader.tsx:314` (ISS-1011, production, one line).**
   - `});` becomes `}).catch(() => {});`, which gives the outer chain a terminal handler. This is option 1 of ISS-1011
     ("Production, one line (recommended)").
   - **Direction check, because this is a non-test file.** The app is aligned to its own written contract (the
     comment at `:301-303`), not bent to a test. Nothing a user sees changes:
     - In production the outer chain can only reject if the dynamic import itself fails.
     - That rejection was unhandled before, and the effect did not set tags then either.
     - Tags stay at their last value, exactly as before. Only the unhandled-rejection report is gone.
   - Why here and not in the three test factories (option 2): this is the one place every caller routes through. The
     fixer's re-grep found **five** test files that import `PreviewPanel` with a closed factory that lacks
     `getRunSandboxRefs`. They are the three in ISS-1011 plus `PreviewPanel.workspaceDuringRun.test.tsx` and
     `PreviewPanel.phantomFile.test.tsx`. The analyzer's 2026-10-02 sweep recorded those two as exiting 0, so they do
     not reach the throwing destructure today. The fixer ran them only after the fix (fix-09). A per-factory fix
     would leave them one prop change away from the same failure, and option 2 would also have left the comment at
     `:301-303` false.

Blast radius, re-grepped in the working tree on 2026-10-07:

- `getRunSandboxRefs` has exactly one non-test consumer, `RunHeader.tsx:308-311` (`api.ts:1730` defines it).
- `getCapabilities`'s production callers were not touched.

## Deliberately not done

- **[ISS-1012](20261002-0544-ISS-1012.md) stays open and untouched.** Its six failures are still there after this fix,
  now with no `Errors` line:
  - `PreviewPanel.versionChip`: 5 failed. The lookups are at `:105`, `:119`, `:144`, `:170` and `:180`.
  - `PreviewPanel.test`: 1 failed, at `:152`. See fix-05.

  These failures are label lookups for "Version vN, choose version", which `RunHeader` stopped rendering in
  `24f112706`. Rewriting the six lookups (ISS-1012's default reading) would not make the file green, for two reasons:
  - `PreviewPanel.versionChip.test.tsx` specifies the retired family-based "Live version chip (B3 / D5)". Its options
    are run-family members, and picking one fetches the version via `getWorkflow`.
  - It also specifies keyboard navigation: ArrowUp, Enter, and Escape closing the menu and returning focus.
    `grep -n "ArrowUp\|ArrowDown\|Escape\|onKeyDown" RunHeader.tsx` finds no handler in today's `VersionMenu`.

  So there are only two ways to make it pass: drop expected keyboard and accessible-name behaviour from the test,
  or add it to the app. Each is the UX/accessibility decision ISS-1012 already names. Neither is a fix this bug's
  cards authorize. The U1 tag-based menu is already covered by the maintained `RunHeader.test.tsx`, which is green:
  14 passed (fix-06). A note with this finding is appended to ISS-1012.
- **No `getRunSandboxRefs` stubs** were added to the PreviewPanel factories (ISS-1011 option 2). Option 1 makes them
  unnecessary.
- **Pre-existing eslint errors in `RunHeader.tsx` were left alone.** They are identical at HEAD and in the working tree
  (fix-07), and none is on the changed line:
  - `:289` `'copied'` is unused.
  - `:306` calls setState synchronously in an effect.
  - `:336` `'handleShare'` is unused.

  `.github/workflows/ci.yml` has no eslint step.
