## Change

- `DashboardLayout.handleReviseBacklog` posts `{target_artifact_type: "backlog_output", instruction}` to the revisions endpoint, attaches the new run and calls `onRevisionLaunched`. The revise dispatch picks it for `backlog` and `backlog_revision` runs, before the prototype branch. Before this a backlog run fell into the prototype branch.
- `backlog` and `backlog_revision` get run types, sidebar labels and plan entitlements matching the backend.
- A plain chat turn can launch a revision (the Concierge starts a backlog revision without a proposal to confirm). `RunConnectionProvider.sendCommand` reads `revision_run_id` at the top level too, and the dashboard's chat send seam passes `onRevisionLaunched`, so the view follows the new run.
