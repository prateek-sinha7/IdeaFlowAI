# ISS-731

Sibling of [ISS-694](20260922-0918-ISS-694.md) (register: **QA-PS-012**,
`LEDGER.md` / `BUGS.md#qa-ps-012`), filed by the 3-analyzer while deriving
ISS-694's blast radius.

## What happened

ISS-694 traced the "No template" mislabel to a hardcoded literal inside
`NoTemplateCard`, a function defined and used only inside
`frontend/src/components/workflow/prototype/TemplateGallery.tsx`. That
component is not exclusive to the prototype-creation wizard: it is also
rendered by `DesignPickerModal.tsx`, the shared design-selection surface for
a composed/custom workflow, so the same wrong label reaches two more
production pages through that second render site.

## Root cause

Mechanism — CONFIRMED by direct read. Live reproduction — INFERRED, not yet
exercised in a browser.

`frontend/src/components/workflow/composer/DesignPickerModal.tsx:294-302`:

```tsx
) : (
  <TemplateGallery
    templates={webTemplates}
    selectedId={value.templateId}
    onSelect={handleSelectTemplate}
    onSelectCustomTemplate={handleSelectCustomTemplate}
    selectedCustomTemplateId={value.customTemplateBody ? value.templateId : null}
  />
)}
```

This branch renders whenever `designMode !== "deck"` (the `"web"` case,
also the documented default — see the caption immediately above it at
`DesignPickerModal.tsx:282-284`: "Optional — leave it unpicked to build on a
blank canvas."). `<TemplateGallery>` is the exact same exported component
`WizardStepper.tsx` uses for `/create/prototype` (ISS-694's reported route),
so it renders the identical `NoTemplateCard` with the identical hardcoded
`"No template"` string at `TemplateGallery.tsx:358`.

`DesignPickerModal` itself is mounted from two real production call sites
(confirmed by direct read, not grepped-and-assumed):

- `frontend/src/components/workflow/IdeaInputPage.tsx:2160-2170` — rendered
  when `designDeclared` is true, `designMode` read from
  `catalogRow?.design_mode ?? "web"` (`IdeaInputPage.tsx:1405`).
- `frontend/src/components/workflow/composer/ComposerPage.tsx:1668-1677` —
  same gate, `designMode` read from `runConfig?.designMode ?? "web"`
  (`ComposerPage.tsx:451`).

Blast radius grep run: `grep -rln "<TemplateGallery" frontend/src` returns
exactly three files — `WizardStepper.tsx`, `DesignPickerModal.tsx`, and
`TemplateGallery.reskin.test.tsx` (a test, not a production render). No
other caller exists, so this is the complete list of real call sites: the
one ISS-694 already reported plus this one.

Ruled out while tracing this: the PPT wizard
(`frontend/src/components/workflow/ppt/PPTTemplateGallery.tsx`) has no
blank-canvas/default card at all (`grep -n "blank\|Blank\|default\|Default"`
on that file matches nothing relevant), so there is no third sibling there.
No downstream surface re-displays the selection's name after picking it
(grepped `WizardStepper.tsx`, `DesignPickerModal.tsx`, `IdeaInputPage.tsx`,
`ComposerPage.tsx` for `templateId === null` / `selectedId === null` / "No
template" — no matches beyond the card itself), so the defect does not leak
into a launch summary, run detail, or persisted run metadata. The backend's
`no_template` flag (e.g. `backend/agents/execution_engine/od_context.py:149`)
is an internal field name, never rendered to a user, so it is out of scope.

## Why this is INFERRED, not CONFIRMED

The component-reuse mechanism above was read directly from source (file:line
quoted). What is NOT yet done is a live browser pass reaching
`DesignPickerModal` in its `"web"` mode from either `IdeaInputPage` or
`ComposerPage` and screenshotting the same "No template" text — ISS-694's
own 3-cycle reproduction only exercised `/create/prototype`. Settle this by
opening a workflow whose catalog entry declares an `opendesign` context
provider with a non-"deck" design mode, opening its Design step, and
confirming the first card's label.

## Expected vs actual

- **Expected:** the blank-canvas card in `DesignPickerModal`'s Web
  design-mode step reads "Default Template" / "Blank canvas", same as
  ISS-694's expectation for the prototype wizard.
- **Actual (inferred from code, not yet screenshotted):** reads "No
  template" / "Blank canvas" — identical wrong copy, same component.

## Fix

Belongs in exactly one place: `TemplateGallery.tsx:358`, the literal inside
`NoTemplateCard`. Change `"No template"` to `"Default Template"` there and
both real call sites (`WizardStepper.tsx` directly, `DesignPickerModal.tsx`
and therefore `IdeaInputPage.tsx` + `ComposerPage.tsx` transitively) pick up
the fix with no per-caller patch. Also update
`frontend/src/components/workflow/prototype/TemplateGallery.reskin.test.tsx:90`,
which pins today's wrong text via `screen.getByText("No template")` and will
fail the moment the label changes.
