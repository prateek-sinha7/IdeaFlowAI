# ISS-145

## Title

Frontend test-suite baselines recorded elsewhere in this repo are stale by roughly an order of magnitude — re-baseline before gating any future fix on suite colour. Prior handoff/memory documentation records the frontend vitest baseline as "~8 known reds" and the mocked Playwright e2e suite as "132/0". Measured fresh during quick-260813-1b1, independently TWICE (once by the fix's executor, once by the orchestrating agent, both figures identical): vitest is 147 failed / 894 passed / 1041 total, 29 failed test files out of 126; the mocked e2e baseline (page.tsx reverted to pre-fix) is 34 failed / 108 passed / 43 skipped. Spot-checked one vitest failure (contentSourceRunScope.source.test.ts, an assertion about pipeline_complete/isForeignCompletion, unrelated to FIX-247) and confirmed by direct grep that its expected string is absent from page.tsx both at HEAD and at d2d2da53, two commits before the fix landed — so that failure pre-dates the task entirely. WorkflowHistory.test.tsx fails with a live-looking TypeError: Cannot read properties of undefined (reading 'length') at WorkflowHistory.tsx:207 (runs.length on an undefined runs prop) — a real, unrelated regression somewhere on this branch. Several other files fail 100% of their own tests (PreviewPanel.test.tsx, PreviewPanel.genericDeliverable.test.tsx, RunConnectionProvider.test.tsx), which points at a shared module-level/harness cause rather than dozens of independent defects. Fix shape: a dedicated investigation pass to re-baseline both suites (ideally diffing against a known-good historical commit to find when and how the drift happened), then update whatever memory/handoff docs currently claim the stale figures.

Measured directly during quick-260813-1b1's regression sweep.
