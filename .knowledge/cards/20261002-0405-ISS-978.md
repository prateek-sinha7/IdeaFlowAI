# ISS-978

**CONFIRMED** (reproduced through the real router, `evidence/qa-kb-054/test_probe_launch.py`, output in `evidence/qa-kb-054/output.txt`). Found while analysing QA-KB-054 ([ISS-687](20260918-ISS-687.md)).

## Condition

`POST /api/runs` for a custom-agent file workflow with `custom-agent:<instance_id>` ids in `agent_ids`, by a user who has no saved override.

## Expected / actual

Expected: an accurate message (or, once ISS-687 lands, no error for the workflow's own roster).

Actual, verbatim for `prototype_v2`:

    Invalid agent_ids for 'prototype_v2': ['custom-agent:fi-planner', 'custom-agent:fi-readers'].
    ['custom-agent:fi-planner', 'custom-agent:fi-readers'] came from a blank custom-agent step in your
    saved override of 'prototype_v2' — it has no agent file to run. Open the workflow in Advanced,
    remove or replace that step, and save.

There is no override and no blank step. The ids are the workflow's own compiled steps (`compile_for_run("prototype_v2").steps`), and the same text comes back for `backlog`. The user is sent to repair something that does not exist.

## Root cause

`backend/app/api/run_commands.py:3534-3536` collects `_stale = [aid for aid in rejected if aid.startswith(CUSTOM_AGENT_PREFIX)]`, and `:3538-3544` appends the override sentence when `_stale` is non-empty. [FIX-438](20260831-1954-FIX-438.md)'s compact_summary states the premise: "A rejected custom-agent:<instance> id can only have come from a saved override step with no AGENT.md". That held while custom-agent ids only reached registered-agent pipelines. For a file workflow built from custom-agent steps the same prefix is the workflow's own roster ([ISS-687](20260918-ISS-687.md)).

## What persists after ISS-687's fix

Own ids that exactly equal the plan are normalised away and never reach this message. A *modified* roster (an id removed or added) still does, and would still be told to look for a saved override. The sentence must fire only for `custom-agent:` ids that are NOT members of the base pipeline's own compiled plan (ISS-182's real case: `user_stories` + `custom-agent:legacy-stale-1`). For plan members it should say the workflow's steps are fixed by its manifest and point at Save as copy / the override, not blame a saved override.

## Guard

ISS-182's behaviour must stay intact. Its test is dead, see [ISS-977](20261002-0405-ISS-977.md); repair that first.
