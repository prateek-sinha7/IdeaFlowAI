> **Analyzed 2026-10-02 (register entry QA-KB-064).** The root cause below stands. Two statements
> in "Impact after FIX-522" do not: restore does not reach `commit_all` on a sandbox with no `.git`,
> and the engine's own run path **is** affected. Corrections, the current line numbers and the fix
> location are in "Analysis — QA-KB-064" at the foot of this card.

## Origin

Split out of [ISS-671](20260917-1345-ISS-671.md) when [FIX-522](20260917-1449-FIX-522.md) resolved
it. ISS-671 called this "a secondary gap worth closing too ... a robustness improvement, not
required for this fix". FIX-522 did not change it, so it is recorded here as an open item.

## What is wrong

- `RunSandbox.__init__` defaults `has_git=True` (`backend/app/agents/sandbox.py:546`).
- Every read-path API caller builds `RunSandbox(user_id, chain_root_id, runs_root=...)` with no
  `has_git=` argument: `backend/app/api/run_files.py:663, 698, 792, 889`, and the restore endpoint
  at `backend/app/api/runs.py:2427`.
- `RunSandbox.list_tags` (`sandbox.py:896`) and the other git-backed delegations gate only on the
  flag, never on `(self.root / ".git").is_dir()`.

ISS-671 counted 87 of 103 local `runs/` directories with no `.git`. Every API-built sandbox over
one of them is still treated as a git repo.

## Impact after FIX-522

With the ceiling, a git call on such a sandbox now fails closed ("not a git repository") rather
than reaching the enclosing checkout, so there is no data exposure and no host write. What is left
is confined to the API construction sites listed above:

- git subprocesses are spawned that cannot succeed;
- a `RunSandbox.commit_all` reached from them (restore, `runs.py:2443` onward) raises a raw
  `CalledProcessError` from `git add -A` rather than taking its documented "sandbox is not a git
  repo" warning branch.

The engine's own run path is NOT affected. At sandbox open, `engine.py:3983-3999` calls
`git_init_sandbox` and flips `sandbox.has_git = False` if init fails, so fan-out isolation (keyed on
`has_git`) sees an accurate flag there.

Not reproduced; traced by reading.

## Disposition

Open, low severity. Derive `has_git` from the real `.git` at construction, or check it at the
delegation seam, then add a test.

## Analysis — QA-KB-064 (2026-10-02)

Register entry QA-KB-064 (`LEDGER.md`). Method: static read of the code plus offline in-process
probes (temp directories, in-memory SQLite, no live DB, no server, no browser). **CONFIRMED** means
a `file:line` I read, or a probe I ran. Nothing below is inferred unless it says so.

### Root cause — CONFIRMED

`RunSandbox.__init__` takes `has_git: bool = True` (`backend/app/agents/sandbox.py:564`) and stores
it verbatim (`self.has_git: bool = has_git`, `:614`). The class never reconciles the flag with the
disk; the one place meant to (`engine.py:4429`) cannot fire ([ISS-997](20261002-0500-ISS-997.md)).
No construction site outside the engine passes `has_git`, so every API-built sandbox claims to be a
git repository whether or not a `.git`, or even the directory, exists. Probe A1: a default-built
sandbox over a directory with no `.git` reports `has_git=True`.

### What it actually costs — corrections to "Impact after FIX-522"

1. **A doomed git subprocess per call, CONFIRMED.** `list_tags()` is the single gate for
   `GET /sandbox/refs`, `_validate_ref` (`run_files.py:846-883`) and `_validate_tag_for_restore`
   (`runs.py:2392-2412`). With the flag true it reaches `_ws()` and runs `git tag --list`, which
   exits 128 under FIX-522's ceiling; `LocalWorkspace.list_tags` swallows that
   (`local.py:907-912`), so the answer is `[]`. Probes B1 / B2: one git call with the flag true,
   zero with `has_git=False`.
2. **A missing directory is re-created, CONFIRMED.** `_ws()` calls `ensure()` (`sandbox.py:634`),
   so the same call on a TTL-swept run `mkdir`s the sandbox: [ISS-996](20261002-0500-ISS-996.md).
3. **The statement "restore ... raises a raw `CalledProcessError`" is wrong for the endpoint.**
   - `restore_version` validates the tag first (`runs.py:2527`). On a sandbox with no `.git`,
     `list_tags()` is `[]`, so it answers **HTTP 400 `invalid_ref`** before
     `detect_persistent_git_state` (`:2575`), `materialize_tree_at_ref` (`:2608`) or
     `commit_in_sandbox` (`:2648`). Probe D1.
   - Even past the gate, `commit_in_sandbox` stages inside its own `try/except` and returns
     `blocked=True, block_reason="staging_failed"` (`engine.py:613-638`), which `restore_version`
     answers with `outcome="blocked"` (`runs.py:2661-2676`). Probe E1.
   - The raw `CalledProcessError` exists only on a direct `RunSandbox.commit_all(...)` with
     `paths=None` (`git add -A`, `local.py:846`; probe C1). With `paths=[]`, the one shape the only
     production caller uses (`engine.py:811`), it is `GitCommandError` (`local.py:873`).
   - The "sandbox is not a git repo" warning branch in `RunSandbox.commit_all`
     (`sandbox.py:867-876`) is **unreachable** for a missing `.git` since FIX-522: a no-change result
     needs a working repository. The register's expected "restore takes the not-a-git-repo branch"
     cannot be met at that seam; only the `has_git=False` early return (`:862-863`, returns `""`) is
     a non-raising non-git result.
   - The FIX-522 guard pins the raise as the **desired** fail-closed behaviour:
     `backend/tests/integration/api/test_run_files_ref_family_scope_api.py:232-263` builds a
     default-flag `RunSandbox` over a repo-less directory and asserts that `commit_all` and
     `materialize_tree_at_ref` both raise.
4. **"The engine's own run path is NOT affected" is wrong.** The flip at `engine.py:4429` is
   unreachable for a git failure: [ISS-997](20261002-0500-ISS-997.md).
5. **The cross-run read handle has the same flag and a different trap:**
   [ISS-992](20261002-0458-ISS-992.md).

Current line numbers (the card above cites stale ones): `sandbox.py:546` is now `:564` / `:614`;
`run_files.py:663, 698, 792, 889` are now `:905, :940, :1043, :1155`; `runs.py:2427` is now `:2511`
and `:2443` is `:2648`; `sandbox.py:896` (`list_tags`) is `:923-942`; `engine.py:3983-3999` is
`:4412-4429`.

`ReadOnlySandbox.resolve_ref_commit` (`:1836`) and the engine's own `has_git` checks
(`engine.py:599, :911, :1743, :1867, :1891, :1965, :2176, :2402, :2479, :2510, :4455`). Fan-out reads
`LocalWorkspace.has_git`, a **separate copy** snapshotted when `_ws()` is first built
(`local.py:328`, `sandbox.py:635-642`, `fanout.py:335`).

### Where the fix belongs

In `backend/app/agents/sandbox.py`, the owner of the flag:

1. Add one way to open an **existing** sandbox, for example
   `RunSandbox.for_existing(user_id, sandbox_root_id, *, current_run_id=None, runs_root=None)`:
   construct, then set `has_git = (root / ".git").exists()` **before any `_ws()` call** (`_ws()`
   snapshots the flag). Use `.exists()`, not `.is_dir()`: it is `git_init_sandbox`'s own idempotency
   test (`local.py:711`) and covers a worktree-style `.git` file.
2. Use it at exactly the five sites marked **yes** above.
3. A prototype of step 2, not applied to the source (a factory monkeypatched over
   `run_files.RunSandbox` that sets the flag from `.git`) turns the swept-run probe in
   [ISS-996](20261002-0500-ISS-996.md) from `expired: False` back to `expired: True`, with no
   directory created.

### Invariants and traps for the fixer

- **Do not derive in `RunSandbox.__init__` or change its default.** The engine builds the sandbox
  with the default and then calls `git_init_sandbox()`, which is itself gated on the flag
  (`sandbox.py:1045-1046`): a derived `False` skips `git init` for every new run, so nothing is ever
  versioned. The default also keeps INV-3 (goldens) byte-identical.
- **Do not make `commit_all` / `materialize_tree_at_ref` short-circuit on a missing `.git` for a
  default-built sandbox.** The FIX-522 guard above asserts they raise, and it is green today.
- **Do not touch `ReadOnlySandbox` with this fix.** Legacy chain sources have no `.git` and are read
  through the has_git-gated, git-free `list_prefix`; deriving the flag there turns every legacy chain
  admission into `source_payload_missing` ([ISS-992](20261002-0458-ISS-992.md)). No test would catch it.
- **Keep `engine.py` free of new module-level `app.*` imports** (import-linter contract 4/0,
  `engine.py:595-597`); the engine-side reconcile belongs in `RunSandbox.git_init_sandbox`.
- The `Workspace` port stays shut (three import-linter contracts): `for_existing` lives on
  `RunSandbox`, not on the Protocol. SC-001 and INV-1 are not touched.

### Test notes

- **Do not write a test expecting `POST /restore` to raise `CalledProcessError`.** It is unreachable
  through the endpoint (correction 3).
- **Implementation-agnostic, red today:** over a sandbox whose directory exists with no `.git`,
  `GET /api/runs/{id}/sandbox/refs`, `GET /sandbox?ref=v1` and
  `_validate_tag_for_restore("v1", sandbox)` each run exactly one `git tag --list` today and should
  run none. Count calls with a wrapper over `app.agents.runtime.local.LocalWorkspace._git`
  (probe B1: patch the class attribute, append `args`, delegate). Plus the swept-run scenario in
  [ISS-996](20261002-0500-ISS-996.md).
- **Seam level:** `for_existing` over a temp dir with no `.git`: `has_git is False`,
  `list_tags() == []` with zero git calls, `commit_all("m") == ""`; over a `git init`-ed dir:
  `has_git is True`.
- **Fixture:** the `env` fixture and `_seed_user` / `_seed_run` helpers of
  `test_run_files_ref_family_scope_api.py:45-128`. It mounts only the `run_files` router, so test the
  restore gate through `_validate_tag_for_restore` (a plain function, `runs.py:2392`).
- One file at a time, offline. `RunSandbox.root` is `.resolve()`d, so temp paths resolve through
  `/private` on macOS.

## Resolution — FIX-727 (2026-10-07)

Resolved by [FIX-727](20261007-1837-FIX-727.md), for register entry QA-KB-064. The root cause above stands. The fix
location differs from "Where the fix belongs":

- **The fix.** `RunSandbox.list_tags` now returns `[]` before `_ws()` when `(root / ".git")` does not exist
  (`sandbox.py:938`). That is the "check it at the delegation seam" option from this card's Disposition. No
  `for_existing` helper was added.
- **Why: the test.** This card's red test builds the restore gate's sandbox with the bare constructor, so a helper
  used only at the call sites cannot make it pass.
- **Why: the blast radius moved.** `run_figma_export.py:744` now reaches `list_tags` through `_validate_ref` (ISS-974,
  `:751`). That is a sixth site the five-site list did not have.
- **Constraints kept.** Every constraint in "Invariants and traps" holds:
  - `__init__` and its default are untouched.
  - `commit_all` and `materialize_tree_at_ref` still raise.
  - `ReadOnlySandbox`'s flag is untouched.
  - No `engine.py` edit.
- **What is left.** An API-built sandbox's `has_git` attribute still reads `True` without a `.git`. Nothing on those
  routes reads it once the tag gate answers `[]`.

Tests:

- `test_run_sandbox_has_git_derived_api.py`: 2 XPASS(strict). The markers are left for the 6-verifier.
- [ISS-996](20261002-0500-ISS-996.md) is resolved by the same change and has its own new test.
- [ISS-997](20261002-0500-ISS-997.md) and [ISS-992](20261002-0458-ISS-992.md) stay open.
