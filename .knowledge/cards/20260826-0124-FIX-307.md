## What happened

`render_check` is the HTML render validator — it drives headless Chromium over a
generated page and reports console errors, uncaught exceptions, nav failures and
nav coverage. It had stopped reporting anything at all, on every call, and did so
silently.

## Root cause

`backend/app/agents/render_check.py:199-206`. The `async with async_playwright()`
block contained ONLY the launch; the `try:` that opens the page was dedented one
level, so it ran AFTER the context manager had exited and torn the browser down:

```python
try:
    async with async_playwright() as pw:
        try:
            browser = await pw.chromium.launch(args=["--no-sandbox"])
        except Exception as exc:
            return RenderResult(ok=True, available=False, ...)
    try:                                  # <-- outside the `async with`
        page = await browser.new_page()   # <-- browser already closed
```

Every call therefore raised `Browser.new_page: Target page, context or browser has
been closed`. That exception is caught by the function's own harness-error arm and
appended to `page_errors` as a string, so nothing crashed — the validator just
returned zero real findings while looking like it had run.

The fix is an indentation change: lines 206-253 move inside the `async with`. A
comment now records why, so the block is not "tidied" back out.
