## What was wrong

Bug report QA-KB-003. `python3 tools/knowledge/status.py` printed
`branch: feat/user-stories-v2 @ ---`, followed by a stray `id:` line. With
`--json`, the `head` field held 2000 characters of `DOMAIN-workspace-isolation`
markdown where the 40-character commit sha should be.

## Root cause

[BUG-128](20260918-BUG-128.md) has the full diagnosis. Inside `main()`:

- `tools/knowledge/status.py:144` sets `head = git("rev-parse", "HEAD")`.
  This is the commit the report describes.
- `:319`, inside `for card in sorted(arch_dir.glob("DOMAIN-*.md"))`, reassigned
  the same name: `head = card.read_text(encoding="utf-8", errors="replace")[:2000]`.
  The only reader of that value was the `re.findall(...)` call at `:321`.
- `:342` (`"head": head`) and `:355` (`@ {(head or '?')[:8]}`) both run after
  the loop, so they got the text of the last DOMAIN card instead of the sha.

## Change

This is the minimal fix from the bug report and the analysis: two lines in
`tools/knowledge/status.py`, with no change in line count.

- `:319` `head = card.read_text(...)[:2000]` became `text = card.read_text(...)[:2000]`
- `:321` `..., head, re.M))` became `..., text, re.M))`

`:144`, `:342` and `:355` are unchanged. `text` clashes with nothing in
`main()`: the only other `text` in the file is the `text=True` keyword argument
at `:37`, inside `git()`.

## Why there

Renaming at the line that overwrote `head` fixes both readers at once.
Re-reading the sha at `:342`/`:355` instead would leave `head` holding card
text for any later reader and hide the cause.

Nothing imports `status.py`. A grep of `tools/`, `tests/` and `backend/tests/`
finds only its own docstring, and the test runs it as a subprocess. It is the
only `status.py` in the repo. QA-KB-026 ([ISS-693](20260918-ISS-693.md)) edits
`:329-335` of the same function. This fix keeps the line count the same, so
the two can land in either order.
