## Symptom

[FIX-306](20260825-2115-FIX-306.md) stopped the composer OFFERING the file-less blank
`custom-agent` template to an override of a built-in. Rows saved before it are untouched: they
still resolve, still render in Advanced, and still fail every launch with

```
400 {"error":"Invalid agent_ids for 'ppt': ['custom-agent:1845dxd-wy6v9o']","code":"invalid_agent_ids"}
```

The caller has no way to tell that id came from THEIR saved override rather than a malformed
request they made, and no indication of where to go fix it. That is
[ISS-182](20260825-2115-ISS-182.md).

## Root cause

`backend/app/api/run_commands.py:2707` — the launch allow-list rejection formatted one message for
two very different causes: an id the client genuinely made up, and a synthetic
`custom-agent:<instance_id>` step that a saved override put in the payload. The second can never
be in `allowed_custom_agent_ids(base)` by construction (no `AGENT.md` on disk — FIX-306's root
cause), so it is not a client error at all; it is a stale row reporting itself as one.

## Decision and fix

The allow-list is **not** widened — its docstring records the reverted KAN-75 cross-pipeline
bypass, and FIX-306 already settled that an override reuses built-in agents only. Only the message
changes, at the ONE launch-time site every `agent_ids`-shaped launch routes through
(`FILE_PIPELINE` and `USER_WORKFLOW_FLAT` both; `USER_WORKFLOW_MANIFEST` has no flat list and is
untouched). Rejected ids carrying `CUSTOM_AGENT_PREFIX` — the existing single-source-of-truth
constant from `agents/workflows/artifacts.py`, not a re-spelled literal — get a second sentence
naming them and pointing at the override in Advanced.

Chosen from the two dispositions ISS-182 offered ("a validation sweep flagging affected rows, or a
launch-time message"): the message, because it fires on the exact request that fails, needs no
migration and no sweep over other users' rows, and is what the card's test asserts.

`rejected_agent_ids`, the status code, and the pre-mint position are all unchanged — no caller
that keys on the code or the id list is affected.
