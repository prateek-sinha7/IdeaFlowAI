# FIX-298

**Trigger:** Post-015 regression — launching any workflow or opening a run via history / Jump
Back In / header banner / notification shows a blank execution screen on
`/runs/{id}/stream`.

## Symptom

After spec-015 (`frontend-routing`) landed, every workflow launch and every navigation to a
run's stream URL produced a blank execution view:
- Run chat lane (left panel) showed only a static "Run summary" card with no live state.
- "Analysing your brief / Preparing your questions" text never appeared.
- Steps tab showed no agents and no progress.
- Preview tab showed "Output will appear here" regardless of run state.
- All tab clicks were no-ops.

## Root cause

`DashboardLayout`'s `pipelineState.isRunning` effect (`~line 722`) calls
`router.push(routes.runStream(runId))` when a new run starts. This **remounts**
`frontend/src/app/[...view]/page.tsx` entirely — Next.js does not preserve a
catch-all page's own instance across a client-side navigation to a new URL under
the same catch-all. Every `useState` in the page resets.

The T11 cold-mount effect (the one that re-attaches the live SSE stream on
`/runs/{id}/stream`) has a fast path for this exact case: when
`runConnection.liveRunIds.includes(runId)` is true (the run is already attached —
it was launched from this tab moments ago), it skips `handleSelectWorkflowRun` to
avoid racing the backend's not-yet-committed write. This is correct.

But the fast path only re-seeded the two refs (`activelyBuildingRunIdRef`,
`trackedRunIdRef`) and replayed durable events. It was missing three React state
setters that both `handleSelectWorkflowRun` and `handleSwitchToLiveRun` always
call after pointing the refs:

| Missing call | Effect of absence |
|---|---|
| `setContentSourceRunId(runId)` | Stays `null` → `RunChatLane` renders the idle/blank state; `handlePreviewPanelTabSelect` bails immediately; `effectiveReviseType` is wrong; the "Analysing your brief" text never appears |
| `runStore.switchViewTo(runId)` | Store viewport stays on previous run (or null) → `displayedPipelineState` stays empty even after durable replay restores agents in `useWorkflow`, because the FIX-201 pipelineState sync bridge has `if (runId !== runStore.viewedRunId) return` |
| `setActivePipelineRunId(runId)` | Stays `null` → `useRunChat` targets the wrong run |

Additionally `setContentSourceRunType` was missing, leaving `effectiveReviseType`
(and therefore `PreviewPanel`'s renderer dispatch) pointing at the stale type.

## Why it worked before spec-015

Before 015, launching a workflow called `setMainView("execution")` in-memory — no
`router.push`, no page remount, no useState wipe. `contentSourceRunId` and the rest
were set normally by the launch flow and survived.

## Fix

In the T11 `useEffect`'s `liveRunIds` fast path, immediately after re-seeding the
refs, add:

```typescript
setContentSourceRunId(runId);
setActivePipelineRunId(runId);
runStore.switchViewTo(runId);
const liveRunEntry = recentRuns.find((r) => r.id === runId);
if (liveRunEntry?.type) setContentSourceRunType(liveRunEntry.type);
```

These are exactly the same calls `handleSwitchToLiveRun` makes when switching to
a live run via the header badge/notification.

## Blast radius

- **One file changed**: `frontend/src/app/[...view]/page.tsx`
- **No other files needed changing**: purely additive state setters inside an
  existing guard.
- No backend changes, no new dependencies, no invariant violations.

## Files changed

- `frontend/src/app/[...view]/page.tsx` — added 4 state setters + seedRunChatTranscript in T11 liveRunIds fast path
- `frontend/src/components/layout/DashboardLayout.tsx` — `onViewRunningPipeline` and `onGoToPipeline` now call `onSwitchToLiveRun` before `router.push` so state is pre-set synchronously before the remount

## Verification

Run the dev server (`npm run dev` from `frontend/`) and:
1. Launch any workflow from the home screen — the stream URL should load with the
   Steps tab auto-selected, the "Analysing your brief" text visible, and agents
   appearing as they run.
2. Click a completed run from Run History — should navigate to the stream URL and
   show the correct run state.
3. Use the header "Jump back in" banner on an active run — should navigate and show
   live progress.
4. Run `npm test -- --testPathPattern=liveRunSwitch` to confirm the FIX-201 tests
   still pass.
