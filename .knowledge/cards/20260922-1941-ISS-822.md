# ISS-822

## Description

INFERRED sibling of [ISS-819](20260922-1940-ISS-819.md) (QA-PS-043). The
composer/canvas feature has two entry paths that each independently seed
themselves from `getWorkflowDetail` — opening a SAVED workflow
(`ComposerPage.tsx`) and opening a BUILT-IN workflow's canvas
(`page.tsx`'s `workflow-canvas` screen branch) — and both share the same
no-guard mount-effect shape the root cause implies every caller has.
Grouped in one card because they are the same user-facing feature (the
composer canvas) reached two ways, not two unrelated surfaces.

## What was read

`frontend/src/components/workflow/composer/ComposerPage.tsx:598-629`:

```tsx
useEffect(() => {
  if (!workflowId) { setDeclaredCapabilities(undefined); return; }
  let cancelled = false;
  const jwt = getToken();
  if (!jwt) return;
  getWorkflowDetail(jwt, workflowId)          // :606
    .then((detail) => { if (cancelled) return; /* map to declaredCapabilities */ });
}, [workflowId]);
```

`frontend/src/app/[...view]/page.tsx:484-...` (the built-in canvas seed):

```tsx
const builtinCanvasType = builtinCanvasTypeFor(parsedView);
useEffect(() => {
  if (!isAuthenticated || !builtinCanvasType) return;
  let cancelled = false;
  (async () => {
    const { getWorkflowDetail, getToken } = await import("@/lib/api");
    const jwt = getToken();
    if (!jwt) return;
    const detail = await getWorkflowDetail(jwt, builtinCanvasType);   // :492
    if (cancelled) return;
    setInitialSavedComposition({ /* ... */ });
  })();
}, [isAuthenticated, builtinCanvasType]);
```

Both use only a `cancelled` flag, no in-flight guard on the fetch itself —
the identical shape [ISS-819](20260922-1940-ISS-819.md) confirmed for
`IdeaInputPage.tsx`.

## Why this is worth a card

Opening either a saved workflow's composer or a built-in's canvas view for
the first time pays the same duplicate-request cost QA-PS-043 reports for
the create wizard — two real HTTP requests, plus whatever the composer's own
render-before-second-response gap looks like. Filed as INFERRED: the CODE
gap is confirmed by direct read on both paths; no live capture of opening
either composer surface was taken for this card.

## Expected vs actual (to be measured)

- Expected: `GET /api/workflows/{id}` fires once when either composer
  surface first mounts for a given workflow.
- Predicted actual: twice, from whichever of the two effects is active,
  doubled by StrictMode.

## Where the fix belongs

Not here. Same shared fix as [ISS-819](20260922-1940-ISS-819.md) and
[ISS-820](20260922-1941-ISS-820.md)/[ISS-821](20260922-1941-ISS-821.md): a
keyed in-flight guard on `getWorkflowDetail()` in
`frontend/src/lib/api.ts`, mirroring [FIX-616](20260922-1923-FIX-616.md).
Neither `ComposerPage.tsx` nor `page.tsx` needs a local edit.
