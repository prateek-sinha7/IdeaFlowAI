## The gap

Two branches fixed the same defect independently and the merge kept both. The
verdict is now decided by one of them while the other's explanation sits above
it, dead and mislabelled.

`f23625911` (this branch) and [FIX-484](20260902-1600-FIX-484.md) both attacked
`_reconcile_terminal_status`'s unscoped degraded flag. Merge `4ebd98e8f` took
both.

## What is dead

`run_commands.py:815-819`:

```python
_latest_complete = max(completes, key=lambda e: e.seq) if completes else None
degraded = bool(
    _latest_complete is not None
    and isinstance(_latest_complete.payload_json, dict)
    and _latest_complete.payload_json.get("status") == "degraded"
)
```

`degraded` is assigned and never read. Verified by walking every `degraded`
occurrence in `run_commands.py` between `:819` and `:960`: after the assignment
the only names that appear are `degraded_complete_seqs`, `degraded_current`,
`degraded_agents`, `degraded_reason` and string literals `"degraded"`. The bare
local is never one of them.

## What actually decides the verdict

FIX-484's reattempt-boundary scan, at `:888-901`:

```python
last_reattempt_seq = max(reattempt_seqs) if reattempt_seqs else 0
current_attempt_completes = [e for e in completes if e.seq >= last_reattempt_seq]
degraded_current = any(... == "degraded" for e in current_attempt_completes)
...
if degraded_current:
    new_status = "degraded"
```

So the surviving semantics are "any degraded completion at or after the last
reattempt boundary" (ISS-436 / ISS-437 scoping), NOT "the latest completion by
seq".

## Why this bites

An 11-line comment block above the dead local explains the last-by-seq mechanism
in detail — the mechanism that no longer runs — and labels itself **FIX-247**.
[FIX-247](20260813-0205-FIX-247.md) is a real card, titled *"Stop at the clarify
gate cancelled the run, but the screen never repainted"*. It is about the live
terminal handler clearing legacy React state. It has nothing to do with terminal
status reconciliation.

So anyone debugging a wrong `degraded` verdict reads a confident explanation of
dead code, follows its card reference, and lands in the frontend.

## What to do

Either delete the dead local together with its comment, or keep it and delete
FIX-484's duplicate. Both are defensible; having both is not. The two must not
each claim to own the verdict.
