**BUG-20260828-001720-workflow-create-prototype**) is reproduced correctly and its

`frontend/src/components/workflow/composer/ComposerPage.tsx:418-436`. That effect is real
(confirmed below) but it is NOT in the render path this bug's route takes, and editing it

## Root cause (CONFIRMED — every line below was read)

1. `frontend/src/app/[...view]/page.tsx:130-131` — `initialMainViewFor`'s `"create-workflow"`
   case (the screen `/create/{slug}` parses to — confirmed via
   `frontend/src/lib/routes.ts:262`, `{ screen: 'create-workflow', pipelineType:
   decodeURIComponent(mode) }` for any `mode` that isn't the four special-cased literals
   `ppt`/`prototype`/`app`/`user-stories`) returns MainView **`"input"`**, not `"composer"`.
2. `frontend/src/components/layout/DashboardLayout.tsx:2882-2909` — `mainView === "input"`
   renders `<IdeaInputPage workflowId={workflowType} .../>`. `ComposerPage` only renders for
   `mainView === "composer"` (line 2918), which `/create/{slug}` never produces.
3. `frontend/src/components/workflow/IdeaInputPage.tsx:1012` — the effect fetches
   `getWorkflowDetail(jwt, workflowId)` (→ `GET /api/workflows/{workflowId}`, 404s for
   "nonsense").
4. `frontend/src/components/workflow/IdeaInputPage.tsx:1172-1181` — the `.catch()`:
   ```ts
   .catch(() => {
     if (!cancelled) {
       setDeclaredCapabilities(undefined);
       setManifestAgents(undefined);
       setManifestSelections(undefined);
       setManifestRawSteps(undefined);
     }
   });
   ```
   Comment above it: "Unknown id (404) or transient error ⇒ treat as 'nothing declared': leave
   it undefined so the strip simply does not render (no noisy UI)." No error/not-found state
   of any kind is set here or anywhere else in this file for this fetch.
5. `frontend/src/components/workflow/IdeaInputPage.tsx:1228-1264` — the roster-derivation
   effect. For `effectiveType` `"nonsense"`: `fromLibrary = LIBRARY_AGENTS.filter(a =>
   agentMatchesPipelineType(a.pipeline_type, effectiveType))` is empty (no `AGENT.md` declares
   that pipeline_type). `libraryIsComplete = fromLibrary.length > 0 && ...` is `false`.
   `systemRoster = libraryIsComplete ? fromLibrary : (manifestAgents ?? fromLibrary)` =
   `undefined ?? []` = `[]` (line 1259), because step 4 left `manifestAgents` `undefined`.
   `setPipelineAgents(systemRoster)` (line 1260-1264) → `pipelineAgents` is permanently `[]`.
6. `frontend/src/components/workflow/IdeaInputPage.tsx:1649,1664,1675,1678-1679` — "Save
   workflow", "Save as my version" and Run are each `disabled={pipelineAgents.length === 0 ||
   ...}`, and the Run button's own label becomes `"Add agents first"` when
   `pipelineAgents.length === 0`. Nothing in this file re-derives `pipelineAgents` from the
   brief text, so typing a brief (as the validator confirmed) cannot change this.

The exact console signature in ISS-253's reproduction — `[wf] 4. roster for {slug}
{fromLibrary: 0, fromManifest: 0, using: manifest}` — is `console.log("[wf] 4. roster for",
...)` at `IdeaInputPage.tsx:1239`, confirmed to exist ONLY in this file (grepped, one match).
That log line was already, on its own, sufficient to identify the component; the validator's
prose citation just named the other one.

## Fix — what changes, and where it belongs

`frontend/src/lib/api.ts:93-104` — `ApiError` already carries `status: number`. No caller of
`getWorkflowDetail` currently branches on it; every `.catch()` in this family (rows above)
treats every failure — a genuine 404 or a transient network/5xx blip — identically.

1. **Primary fix, in `IdeaInputPage.tsx`'s existing catch (1172-1181) and roster effect
   (1228-1264):** set a new, VISIBLE error/not-found state (mirroring the `saveError` state
   this same file already has and renders at line 1689-1691) when the fetch fails AND
   `fromLibrary` is empty — i.e., exactly the condition that leaves `pipelineAgents` at `[]`
   with no recovery path. Render it next to the Run button so "Add agents first" is no longer
   the ONLY, silent signal.
2. **Shared piece, so every caller routes through the same check:** add a small predicate
   (e.g. `isNotFoundError(e): boolean => e instanceof ApiError && e.status === 404`) to
   `api.ts` and use it in every catch in the table above that currently swallows
   unconditionally, so "doesn't exist" and "transient failure" stop being handled identically
   everywhere they are checked. This is the smaller-diff option since `ApiError` is already
   shared; it does not by itself add the missing UI — that is still per-component (see
   [ISS-375](20260828-2147-ISS-375.md) for why the distinction matters).
3. Do **not** change `ComposerPage.tsx:410-439` — that swallow is correct for its narrower,
   optional purpose (the SURF-03 capability strip) and is not part of this defect.
4. `page.tsx:452-499`'s matching swallow belongs to [ISS-299](20260828-1730-ISS-299.md), a
   different, already-tracked bug — do not fold its fix into this card's diff.
