# ISS-977

**CONFIRMED.** Found while analysing QA-KB-054 ([ISS-687](20260918-ISS-687.md)); reproduced by running pytest collection on the file (output in `evidence/qa-kb-054/output.txt`). Test-infra defect, adjacent to the root cause rather than implied by it, filed because the fix to ISS-687 edits the exact block this test guards.

## Condition

Collect `backend/tests/unit/test_iss182_stale_override_agent_ids.py`.

## Expected / actual

Expected: the test runs and pins the ISS-182 behaviour.

Actual (executed, `cd backend && .venv/bin/python -m pytest tests/unit/test_iss182_stale_override_agent_ids.py --collect-only -q`):

    ImportError: cannot import name '_post_launch' from 'tests.unit.api.test_rest_run_launch'
    no tests collected, 1 error

## Root cause

`test_iss182_stale_override_agent_ids.py:21-26` imports `_post_launch, _run_count, _seed_user, env` from `tests.unit.api.test_rest_run_launch`. That module (231 lines) now holds only the pure declared-signal od_context tests (`_launch_body`); its docstring says the endpoint half "lives in `tests/integration/api/test_rest_run_launch_api.py`", which is where all four names are defined: `env` (:90), `_seed_user` (:139), `_run_count` (:167), `_post_launch` (:177). The unit/integration split moved the harness and left this importer behind. [FIX-438](20260831-1954-FIX-438.md)'s coverage block cites "33 tests in test_rest_run_launch.py", the pre-split layout.

## Why it matters for ISS-687

The behaviour this test pins is the one an allow-list change is most likely to break, and it is a **FILE_PIPELINE** request, not USER_WORKFLOW_FLAT: `pipeline_type="user_stories"`, `agent_ids=["custom-agent:legacy-stale-1", "domain-analyst"]`, no `user_workflow_id` (`test_iss182_stale_override_agent_ids.py:36-54`). It expects 400 `invalid_agent_ids` whose message names the saved override.

The behaviour itself still holds today. `evidence/qa-kb-054/test_probe_iss182_guard_behaviour.py` replays the same request on the live integration harness: `400 invalid_agent_ids | override sentence present: True | rejected: ['custom-agent:legacy-stale-1'] | runs: 0`. Only the guard is dead.

The triage sketch in BUGS.md for QA-KB-054 (strip `custom-agent:`-prefixed ids when `launch_source is FILE_PIPELINE`) would turn that request into a launch of `['domain-analyst']`, and no test would go red. [ISS-182](20260825-2115-ISS-182.md) (status resolved) and [FIX-438](20260831-1954-FIX-438.md) (verification passed) both list this file as their only proof.

## Fix

Test-only. Re-point the import at `tests.integration.api.test_rest_run_launch_api` and move the test beside that harness (its docstring: "rejected PRE-MINT" is a claim about absent rows, checkable only by counting real rows). Do it BEFORE the ISS-687 fix lands so that fix runs against a live guard.
