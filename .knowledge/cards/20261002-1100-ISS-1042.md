## Report

BUG-ID QA-KB-094 (validator, 2026-10-02). Static defect, confirmed 3/3 by cold re-reading the three files; no browser involved.

## Reproduction

1. `tools/api/runs/run.ex_A4_human_gate_auto.http:90-95` sends `"action": "approve", "edited_content": "spanish"`.
2. The human gate replaces `ask`'s artifact with that string; `pick-language` has `route.condition_agent: ask`.
3. `backend/agents/capabilities/gates/conditional.py:_read_decision` (:234-258) does `json.loads(content)`, falls back to `_trailing_json_object`, which returns None unless the reply ends with `}`. `spanish` yields None, so no outcome matches; with no `default_next` the gate returns GATE_BLOCK (:186-198).
4. The offline test proves the intended payload: `backend/tests/agents/test_conditional_human_gate_source_t26.py:187` uses `'{"decision": "spanish"}'`.

## Expected vs actual

Expected: the script answers with `{"decision": "spanish"}` so `say-hola` runs. Actual: `gate_blocked`; the script's own assertions (:129-) report the run fell through. The auto script's header ("approve + edited_content") never mentions JSON.

## Conditions

Developer tooling only, tier-independent. The interactive twin `run.ex_A4_human_gate.http:95` prints the same bare-word `curl` hint for the human to copy, so it misleads equally.

## Fix

Send `"edited_content": "{\"decision\": \"spanish\"}"` in the auto script (and fix log line :100 and the :95 hint in the twin).

## Analysis (3-analyzer, 2026-10-02, QA-KB-094)

Anchors are from the working tree of `feat/user-stories-v2` @ `024c03ef`. `engine.py`, `kernel_services.py` and `run_commands.py` carry uncommitted edits, so their line numbers may shift; the gate, the fixture, both runners, T26 and `InlineGateActions.tsx` match HEAD.

**ROOT CAUSE (CONFIRMED: read, reproduced on a live run row by row, and reproduced offline).** The gate's decision source changed and its only two scripted clients did not.

1. Since `0b6570b85` (2026-08-25, [ADR-0026](20260825-1600-ADR-0026.md)) the fixture declares `route.condition_agent: ask` (`workflow.yaml:111`). `ConditionalGate.evaluate` therefore reads `ask`'s latest typed artifact (`conditional.py:128-131`, `_read_decision` `:208-267`) and requires JSON: `json.loads` (`:235`), then `_trailing_json_object` (`:252`), which returns `None` unless the text ends in `}` (`:74-75`).
2. The human's answer reaches that artifact unchanged. `POST /gate` stores `edited_content` verbatim (`run_commands.py:329-336`, field at `:139`), `_run_review_gate` yields it as `_gate_edited` (`engine.py:12599-12600`), `HumanGate` threads it as `detail["edited_content"]` (`human.py:159-168`, `:197-198`), and `_apply_declared_gate_edit` writes it as the next version of the PREVIOUS step's artifact (`engine.py:11903-11913`, `content=edited`). `_latest_typed_content("ask")` serves that max-version content (`engine.py:13950-13996`).
3. `run.ex_A4_human_gate_auto.http:94` sends `"edited_content": "spanish"`. `json.loads("spanish")` raises, the trailing-object fallback returns `None`, no outcome matches, and the route has no `default_next` (`workflow.yaml:116`), so the gate returns `GATE_BLOCK` (`conditional.py:185-206`). The post-step loop turns that into `pipeline_failed` (`engine.py:6754-6759`, `:7373-7402`, [ISS-170](20260824-1610-ISS-170.md)) and no branch runs.

**Why only the runners broke.** Before `0b6570b85` the manifest had no `condition_agent`, so the gate read `pick-language`'s own reply and the model mapped the human's bare word to `{"decision": ...}` (ISS-170 records 4/4 live runs routing on typed bare words). The change took the model out of the decision path on purpose. Two commits 32 seconds apart on 2026-08-25 moved the answer contract: `6210e0160` (UI chips, `InlineGateActions.tsx:320`) and `0b6570b85` (fixture, `kernel_services.py`, `test_gates.py`). Neither touched the runners, which were last edited the day before (`c9ec0149c`). ADR-0026's consequences list no consumers and nothing in CI reads the runners, so the drift stood for at least 38 days until the 2026-10-02 run exposed it.

**Evidence.**
- Run log `tools/api/runs/logs/ex_A4_human_gate_auto/20261002-025201.log`, run `9eb70b6e-5a70-41e8-9d5f-fbb05e11440d`: `review_gate_ready` printed `{"prompt": ..., "choices": ["english", "spanish", "dutch"]}`, the script answered `"spanish"`, then `pipeline_failed`, `✗ expected exactly one branch, got 0`, `✗ pipeline_complete not found`.
- DB, SELECT only (`evidence/qa-kb-094/analyze-db-select.txt`): `workflow_runs.status = 'failed'`; `gate_events`: `human | pass | {"edited": true}` then `conditional | block | {"decision": null, "reason": "no matching route outcome and no default_next"}`; `artifact_refs`: `custom-agent:ask` `summary` v2 = `'spanish'` (`derived_from` set: the raw edit) while `custom-agent:pick-language` `route_decision` v2 = `'{"decision":"spanish"}'` is valid JSON and was never read.
- Offline (`evidence/qa-kb-094/probe-offline-bare-word-vs-json.py`, scripted model, hermetic sqlite): `edited_content='spanish'` gives `gate_blocked` then `pipeline_failed` with no branch started; `'{"decision": "spanish"}'` starts `say-hola` and ends `pipeline_complete`.
- `backend/tests/agents/test_conditional_human_gate_source_t26.py`: 2 passed in 2.67 s on this tree. Line 187 is the JSON payload; the bare-approve test pins the fail-closed half.

**The server is right; do not change it.** Strict JSON is the documented contract (`specs/014-conditional-gates/contracts/manifest-route-schema.md:60-68`), ISS-170 records a leniency attempt that was "deliberately reverted" on the user's instruction, and `_trailing_json_object`'s docstring (`conditional.py:59-66`) pins `{"decision": "english"}Hello! ...` as fail-closed.

**FIX PLACEMENT.** Client side, in the two runner files. The engine, the gate and the manifest logic stay as they are.

1. `run.ex_A4_human_gate_auto.http:91-95`: `"edited_content": "{\"decision\": \"spanish\"}"` (a JSON string holding the decision object), the same payload the UI sends. Keep `edited_content` and `decision` on ONE line so a static test can read it. Update the log line at `:100` and the header (`:3-8`).
2. `run.ex_A4_human_gate.http:95`: see [ISS-1045](20261002-1204-ISS-1045.md) (same fix, tracked on its own so it can be checked on its own).
3. Correct the fixture header (`workflow.yaml:9-13`, `:25-26`, `:32-35`), which still says `condition_agent` is "deliberately ABSENT" and that `pick-language` routes on "the line it just generated". That text is what a runner author copies, and the runners' own headers repeat it. Comments only.

Do NOT: loosen `_read_decision` or `_trailing_json_object`; normalise the edit in `/gate` or `_apply_declared_gate_edit` (a rule keyed on a workflow id would break INV-1 / SC-001, and one keyed on the published choices is an API-contract change); add a `default_next` to the fixture (T26 pins the block).
