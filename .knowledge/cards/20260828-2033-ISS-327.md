# ISS-327

## Title

Saved-workflow detail view (`/workflows/{id}`) lists agents by raw internal slug instead of the
friendly display name used everywhere else in the app.

## Reproduction (3/3, cycle 1)

Reproduced on all 3 cold-start attempts, deterministic — first attempt already failed, no
narrowing needed.

1. Signed in as `qa-admin@flowinqa.com` (already-persisted session, `auth_token` present).
2. Cold-navigated directly to `http://localhost:3000/workflows/656ca387-e69c-474d-b7ff-5fd9eb017cc0`
   ("My prototype", a seeded saved workflow).
3. Cycle 1: navigated straight to the URL. Agent roster rendered `documentation-agent` and
   `prototype-specify` verbatim.
4. Cycle 2: navigated to `/dashboard` first, then back to the same `/workflows/{id}` URL (fresh
   route entry, not a soft re-click). Identical raw-slug rendering.
5. Cycle 3: navigated to `about:blank` then back to the same URL (full cold load). Identical
   raw-slug rendering. Screenshot: `bug-hunter/evidence/workflows-id/_scratch/cycle3-detail-raw-slugs.png`.
6. Clicked "Edit" on the same workflow (`/workflows/{id}/edit`, Composer view) and confirmed the
   identical two agent ids render as "Documentation" / "API & Technical Writing" and
   "Spec Writer" / "Specification & Architecture" there — same ids, same session, resolved names.

## Expected vs Actual

- **Expected:** the detail view resolves each `agent_id` to the same friendly display name (and
  ideally role subtitle) the Library page and this workflow's own Composer/Edit view already show
  for the identical agents.
- **Actual:** the detail view renders the raw `agent_ids` array values verbatim with no lookup.

## Root cause

`frontend/src/components/savedworkflows/WorkflowDetailView.tsx`:

- Line 29: `const agentIds = workflow.agent_ids ?? [];` — pulls the raw id array straight off
  `UserWorkflowSummary`, no name/role resolution step.
- Lines ~52-56:
  ```tsx
  {agentIds.map((id) => (
    <li key={id} className="text-[12.5px] text-ink-700 bg-surface-warm rounded-[8px] px-3 py-2">
      {id}
    </li>
  ))}
  ```
  renders `{id}` directly — the raw slug — with no id-to-display-name map, unlike the Composer
  canvas (`/workflows/{id}/edit`) and the Library page, which both have that mapping available
  and use it for the identical agent ids.

This is a genuinely new gap in `WorkflowDetailView.tsx` — not the same defect as the already-
fixed [ISS-024](20260614-0619-ISS-024.md), which was a different component (the terminal-failure
Preview affordance) and is `status: done`.
