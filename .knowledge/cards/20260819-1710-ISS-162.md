# ISS-162

## What was found

While validating a UI change to `LaneRunHeader.tsx` (clamp the run title to 2 lines, show full text on hover), the hover tooltip was found broken in three compounding ways on a real run (`01fd07cb-3faf-4ad7-9085-20452887c104`, a `Cancelled` prototype run):

1. On a reopened/settled run, the tooltip showed the SAME trimmed text as the visible clamped title, not the original brief — no way to actually read the full brief via hover.
2. Once the correct full text was wired in, most of it was still unreachable: the tooltip box was `overflow-y-auto` but also `pointer-events-none`, so nothing past ~320px could be scrolled to.
3. The tooltip was visually clipped at the boundary between the left (chat/lane) and right (preview) panes — cut off mid-word with no indication more text existed.

## Disposition

Fixed in the same pass — see [FIX-261](20260819-1710-FIX-261.md) for the root-cause chain and the code change (full-text threading via `viewedRun.input`, and a `document.body` portal to escape the pane's `overflow-hidden` ancestor).
