## Related

## What was wrong

The engine has always emitted `visit_count` on both `agent_start` and
`agent_complete` events to track step revisits. The frontend's reducer never
read it, so a conditional-route loop-back left the re-entered step as "running"
underneath later steps still marked "done" — an impossible pipeline state. The
progress counter never came back down. Observed live, run fafea1bc: Coverage
Check (index 8) routed back to the Synthesizer (index 7). After the engine
restart, Document Ingest re-dispatched at index 0 while the Synthesizer was
still showing "Writing…" from the killed pass — two steps rendering as
in-flight at once.

## The fix (commit 97717eb9f)

- The reducer now reads `visit_count` from `agent_start` and `agent_complete`
  events.
- When a step revisits (visit_count increases), every step after it is reset to
  idle; the pipeline resets to a valid state.
- The progress counter (completedCount) decreases when a revisit occurs,
  reflecting only the current pass.
