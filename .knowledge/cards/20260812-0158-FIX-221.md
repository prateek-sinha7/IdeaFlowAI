## Description

The violet "Spec Revision Cycle N" banner was dead on every path for od_prototype, not merely absent on reload as ISS-063 filed it. FIX-164's arming predicate (page.tsx:1646) required EVERY agent in the roster to be "done" while the run was still isRunning, but the update_specs gate sits on prototype-analyze, agent 2 of 5 — prototype-build/prototype-validate are still "idle", and the only three sites that assign status:"done" to the rest also set isRunning:false in the same update. The arm was structurally unsatisfiable, so the counter never left 0 in ANY session. Two further sufficient mechanisms sat behind it: the detector read pipelineAgentsRef, refreshed only by a post-commit effect, so it was frozen for the whole synchronous REST replay loop (page.tsx:2257-2269); and the trailing resume pipeline_start (run d5dbc9f2 seq 24791, same run id) landed LAST on every replay and zeroed the counter. Dead since 219702a4 (2026-08-03), on the flagship workflow, with zero test coverage.

## Root cause

A modelling decision, not a mechanism: FIX-163/164 modelled "a revision is happening" as live-session state assembled by a detector — an arm/consume state machine over refs — rather than as a property derivable from the accumulated event history. Once the answer depends on transient arming, correctness depends on scheduling (which frame arrives when, whether React committed in between), and every replay path is a different schedule. The three failures are one root cause seen from three angles.
