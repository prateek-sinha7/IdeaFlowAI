# FIX-741

Bug report QA-KB-085. The root cause, timeline and blast radius are [ISS-942](20261001-2241-ISS-942.md)'s analysis, and the
latent twin is [ISS-1027](20261002-0703-ISS-1027.md). They are not re-derived here. Frontend tests only: no product source,
backend, engine, migration or import-linter surface is touched.

## What was wrong

Two grep-style source tests bounded the code they inspect with a hook's dependency list.

- `runTabShallowNav.test.ts:29` (HEAD): `dashboardSource.indexOf("}, [contentSourceRunId]);", start)`. Since `d027f16bd` the
  tab handler closes with `}, [contentSourceRunId, pinnedVersion]);` (`DashboardLayout.tsx:553` in today's tree), so the first
  match is the revision-family effect's close at `:742`. The slice ran `:517-:742` and swallowed `handleOpenLiveRun`'s
  deliberate `router.push` (`:562`, added by `8cf967b0f`). Case 1 failed with `expected 'const handlePreviewPanelTabSelect = u…'
  not to contain 'router.push'`, although the handler itself only calls `window.history.pushState` (`:552`).
- `authEffectGuard.iss844.source.test.ts:35` (HEAD): `const endMarker = "}, [router, dispatch]);"`. The test was green, but
  `page.tsx` closes two effects with that literal (`:960` and `:3440` in today's tree). A deps edit on the auth-check effect
  would widen the slice to about 2,500 lines. There an unrelated `.current = true;` satisfies the guard check, so removing the
  ISS-844 guard would still pass.

## What changed, and why there

The defect is in the tests' slice boundary, not in the product, so the fix lives in the tests. Both cards lock that in their
`locked_constraints`: the fix is test-only, and reshaping product code to fit an anchor would be app-bent-to-test. No assertion
about product behaviour changed. Case 1 still requires `window.history.pushState` and forbids `router.push`, and the ISS-844
test still requires the one-shot guard.

- **End anchor (both files).** The new anchor is `indexOf("\n  }, [", start)`: the first top-level hook close after the start
  marker. It names no dependency, so a deps change cannot move it. The hook bodies sit at four-space indent, so nothing inside
  them matches. Today it lands on `DashboardLayout.tsx:553` and `page.tsx:960`, each hook's own close.
- **One-hook assertion (both files).** This is the cards' optional hardening. I took it because the defect class is a *silent*
  widening: the slice sat 204 lines wide for a month before anything noticed.
  - `runTabShallowNav.test.ts:33` asserts that the raw window holds exactly one `useCallback(`/`useEffect(`.
  - `authEffectGuard.iss844.source.test.ts:45` asserts exactly one `useEffect(`. It sits under the existing "Sanity" comment
    and completes that comment's stated purpose: the two existing sanity checks only catch a window that is too short.

Diff: `evidence/qa-kb-085/10-fix-diff.txt`. `DashboardLayout.tsx` and `page.tsx` are not in it. While this fix ran, a concurrent
session edited `page.tsx:3483` (ISS-1026). That edit is not part of this card, and it moves neither anchor.
