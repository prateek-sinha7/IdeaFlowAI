# ISS-820

## Description

INFERRED sibling of [ISS-819](20260922-1940-ISS-819.md) (QA-PS-043). ISS-819's
root cause is that `getWorkflowDetail()` has no in-flight dedupe, so ANY
unguarded mount effect calling it doubles under React StrictMode — a
"missing guard on the shared function" root cause implies every OTHER
mount-effect caller of `getWorkflowDetail` has the same exposure, not just
`IdeaInputPage.tsx`. `LaunchWizard.tsx` is the component that actually
renders `/create/ppt` and `/create/prototype` (per
`initialMainViewFor`'s own comment in `page.tsx`: "`/create/ppt`... routes
to a separate wizard page", i.e. NOT through `IdeaInputPage`), so this is
the first call site worth checking.

## What was read

`frontend/src/components/workflow/LaunchWizard.tsx:490-566`:

```tsx
useEffect(() => {
  let cancelled = false;
  setOverrideInfo(null);
  setPlanAgents(null);
  // ...reset other state...
  setDeclaredRunConfig(undefined);

  getWorkflowDetail(token, pipeline)        // :507
    .then((detail) => {
      if (cancelled) return;
      setDeclaredRunConfig({ /* ... */ });
      // ...
    });
  return () => { cancelled = true; };
}, [authChecked, mode, handleSelectionsChange]);
```

Same shape as [ISS-819](20260922-1940-ISS-819.md)'s `IdeaInputPage.tsx`
finding: a `cancelled` flag that blocks a state update post-unmount, no
in-flight guard on the fetch itself. `pipeline` is `MODE_CONFIG[mode]
.agentPipeline` — for `mode: "ppt"` that resolves to the `ppt` workflow id,
making `getWorkflowDetail(token, pipeline)` the literal
`GET /api/workflows/ppt` call.

## Why this is worth a card

QA-PS-044 (`BUGS.md#qa-ps-044`, ledger status still `CONFIRMED`, not yet
analyzed) reports `GET /api/ppt` fired 2x on `/create/ppt` load, filed
against [ISS-794](20260922-1827-ISS-794.md) — a card about a DIFFERENT
effect (`page.tsx`'s unguarded auth-check). Nothing in the corpus yet traces
the `/api/ppt` config-endpoint duplicate specifically. This effect is the
most direct candidate: same file that renders the route, same missing-guard
shape already confirmed for the sibling wizard. Filed as INFERRED — the CODE
gap is confirmed by direct read; the `/create/ppt` reproduction itself is
QA-PS-044's own analysis to run, not repeated here.

## Expected vs actual (to be measured on `/create/ppt`)

- Expected: `GET /api/workflows/ppt` fires once per cold load.
- Predicted actual: twice, from this one effect, doubled by StrictMode —
  matching QA-PS-044's own reported "GET /api/ppt x2".

## Where the fix belongs

Not here. [ISS-819](20260922-1940-ISS-819.md) already names the fix
location: a keyed in-flight guard on `getWorkflowDetail()` itself
(`frontend/src/lib/api.ts`), mirroring
[FIX-616](20260922-1923-FIX-616.md)'s `getWorkflows()` treatment. That one
change closes this call site too — `LaunchWizard.tsx:507` needs no local
edit.
