## What is broken

`_atomic_write_context_dir` in `chain_context.py` replaces the entire
`.context/` directory rather than merging its three payload files into it.
Any workflow that declares both `opendesign` and `chain_context` as context
providers would lose its OpenDesign seed — `.context/design/` and
`.context/selections.json` — the moment the chain payload installs, because
those files are written at sandbox open (engine.py:4130, `write_od_context_to_sandbox`)
long before the provider loop runs at engine.py:5382.

**Latent today only because BUG-125 (B23) means the copier never executes.**
It becomes live the instant BUG-125 is fixed. `user_stories` (whose
`context_providers` list is empty) is not affected — it has no opendesign
seed to overwrite. `prototype` and `ppt_v2` both declare `opendesign` and
are the two workflows most likely to be used as chain sources, so they are
the ones at risk.

The three payload files (`summary.md`, `logs.jsonl`, the declared
deliverable) do not collide with `design/` or `selections.json`, so merging
is both correct and safe.

## Root cause — CONFIRMED

`backend/agents/capabilities/context_providers/chain_context.py:490`
(inside `_atomic_write_context_dir`):

```python
# Atomic swap: remove existing dest if present, then rename staging.
if dest_dir.exists():
    import shutil as _shutil
    _shutil.rmtree(str(dest_dir))   # ← wipes ALL of .context/

staging.rename(dest_dir)            # ← staging has only 3 payload files
```

`dest_dir` is `base_path / ".context"` — the full `.context/` directory
(resolved at chain_context.py:228 from `_CONTEXT_DEST_PREFIX = ".context"`
at line 83). The staging directory contains only the three flat payload
files. After the rename, every file under `.context/` that was NOT in
staging is gone.

The collision:

- `engine.py:4130` — `write_od_context_to_sandbox` writes
  `.context/design/` and `.context/selections.json` at sandbox open, before
  `_seed_workflow_context` is called.
- `engine.py:5382` — `_seed_workflow_context` runs the provider loop. If
  `chain_context` is in the list, `_atomic_write_context_dir` fires and
  `rmtree`s `.context/`, deleting what `write_od_context_to_sandbox` just
  wrote.

## Fix plan

Replace the whole-directory swap in `_atomic_write_context_dir` with a
per-file atomic write. The staging dance exists to provide atomicity — that
property is preserved by staging each file individually and renaming each
one into place, rather than staging the whole directory and renaming it.

**New `_atomic_write_context_dir` strategy:**

```python
def _atomic_write_context_dir(
    dest_dir: _pathlib.Path,
    file_bytes: dict[str, bytes],
) -> None:
    """Atomically MERGE ``file_bytes`` into ``dest_dir``.

    Writes each file to a temp sibling, then renames it into dest_dir,
    preserving any pre-existing files (e.g. .context/design/ written by
    the opendesign provider). Per-file atomicity is maintained; the
    wholesale rmtree+rename is removed.
    """
    dest_dir.mkdir(parents=True, exist_ok=True)
    parent = dest_dir.parent

    for name, data in file_bytes.items():
        dest_file = dest_dir / name
        # Write to a temp sibling of the destination file.
        fd, tmp_path_str = _tempfile.mkstemp(
            prefix=f".{name}-staging-",
            dir=str(parent),
        )
        tmp_path = _pathlib.Path(tmp_path_str)
        try:
            with _os.fdopen(fd, "wb") as fh:
                fh.write(data)
            tmp_path.replace(dest_file)   # atomic on POSIX; os.replace on Windows
            tmp_path = None               # replace succeeded
        except Exception:
            if tmp_path is not None and tmp_path.exists():
                try:
                    tmp_path.unlink()
                except Exception:
                    pass
            raise
```

Key properties preserved:
- Each file write is atomic (temp + replace, same atomicity guarantee as
  the original staging dance, scoped per file instead of per directory).
- Pre-existing files under `.context/` (`.context/design/`,
  `.context/selections.json`) are untouched.
- A failure mid-loop leaves previously written payload files in place and
  rolls back only the failed file's temp — the same best-effort contract
  the original had.

**Test to add** (`test_chain_context_v3.py` or new file):

```python
def test_atomic_write_merges_not_replaces(tmp_path):
    """Existing files under dest_dir survive _atomic_write_context_dir."""
    dest = tmp_path / ".context"
    dest.mkdir()
    (dest / "design").mkdir()
    (dest / "design" / "tokens.json").write_bytes(b'{"color":"red"}')
    (dest / "selections.json").write_bytes(b'{"template":"hero"}')

    _atomic_write_context_dir(dest, {
        "summary.md": b"# Summary",
        "logs.jsonl": b'{"step":1}',
        "prototype.html": b"<html/>",
    })

    # Payload files written
    assert (dest / "summary.md").read_bytes() == b"# Summary"
    assert (dest / "logs.jsonl").read_bytes() == b'{"step":1}'
    assert (dest / "prototype.html").read_bytes() == b"<html/>"

    # OpenDesign seed files preserved
    assert (dest / "design" / "tokens.json").read_bytes() == b'{"color":"red"}'
    assert (dest / "selections.json").read_bytes() == b'{"template":"hero"}'
```

No manifest changes are needed for this fix alone — it unblocks BUG-125's
manifest edits.
