## Symptom

Some agents showed `model_id: "unknown"` in `agent_outputs` even on recent runs with a
configured model, causing a non-zero "Unknown" row in the analytics "By Model" breakdown.

## Root cause

`backend/app/agents/model_factory.py` `model_identifier(llm)`:

```python
def model_identifier(llm) -> str:
    return (
        getattr(llm, "model_id", None)
        or getattr(llm, "model", None)
        or getattr(llm, "model_name", None)
        or "unknown"           # ← literal string stored verbatim
    )
```

`backend/app/agents/deep_agent_runner.py`:

```python
self.model_id: str = model_identifier(self._model)
```

When `model` is a string (e.g. "eu.anthropic.claude-sonnet-5") it is already known
before building the LangChain object — no attribute probe needed. When `model` is
None and the object probe fails, the settings-configured inference profile is the
correct fallback.

## Fix

`backend/app/agents/deep_agent_runner.py` — replaced the single
`model_identifier(self._model)` call with a three-tier fallback:

```python
if isinstance(model, str) and model:
    self.model_id: str = model                      # already known — no probe
else:
    resolved = model_identifier(self._model)
    if resolved == "unknown":
        resolved = (
            settings.BEDROCK_INFERENCE_PROFILE_ID
            or settings.BEDROCK_MODEL_ID
            or "unknown"
        )
    self.model_id = resolved
```

`settings` was already imported in `deep_agent_runner.py` — no new import required.
