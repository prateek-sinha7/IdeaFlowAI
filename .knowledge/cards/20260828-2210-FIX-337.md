## What was wrong

Opening any seeded conditional-gate example from `/create` — `ex_A4_human_divert`
("Ask a Human, Then Hand Off"), `ex_A1_loop`, `ex_A2_branch`, `ex_A3_divert`,
`ex_A4_human_gate` — typing a brief, touching nothing else and clicking
"Save as my version" failed outright with a raw backend string under the composer
footer:

```
invalid workflow manifest (workflow:My ex_A4_human_divert): step 'custom-agent'
declares route: but is missing gates: [conditional] — gates: [conditional] is
required when route: is declared (R-03)
```

`POST /api/user-workflows` -> 422, every time, from a cold load, with no user
edit anywhere near a gate. Recorded as `BUG-20260828-051530-create` in
`bug-hunter/ledger.md`; root cause in [ISS-225](20260828-1541-ISS-225.md),
sibling coverage in [ISS-254](20260828-1810-ISS-254.md).

## Root cause

`frontend/src/components/workflow/IdeaInputPage.tsx` holds the manifest's declared
gates in TWO places and only seeded one of them.

The manifest fetch builds `manifestSelections` from the raw steps' own `gates`
(`IdeaInputPage.tsx:1098-1105`) and merges it into `mergedInitialSelections`
(`:1190-1196`), which is DISPLAY state — it is what makes the canvas draw
`pick-language` as a conditional diamond.

`selectionsRef` (`:936`) is the value the save path actually serialises. It is
seeded only from `cleanSelections` and mutated only by `handleSelectionsChange`
(`:937-942`) or the override toggle (`:1428-1440`); it is never assigned from
`manifestSelections`. On an untouched page `selectionsRef.current === {}`.

`handleSaveAsOverride` (`:1460-1478`) passed that empty ref straight through:

```ts
manifest: buildWorkflowManifest(pipelineAgents, undefined, selectionsRef.current)
```

`agentToManifestStep` (`frontend/src/store/api/userWorkflows.ts:236`) writes
`step.gates = selections?.[agent.id]?.gates ?? []`, while `step.route` comes off
the `AgentDef` (correctly sourced from the manifest). So the POSTed manifest
declared `route:` with `gates: []` — precisely the shape
`WorkflowCompiler._compile_step`'s R-03 cross-field check rejects
(`backend/agents/workflows/compiler.py:966-970`), reached at save time through
`_compile_check_manifest` (`backend/app/api/user_workflows.py:78-133`, `trust="db"`).

The canvas SHOWED the gate and the save DROPPED it because the two read different
maps. [FIX-285](20260824-1621-FIX-285.md) seeded the render-side map; this is the
save-side half of the same gap.

Confirmed out-of-band before editing: compiling the exact manifest the FE builds,
with and without the merge, against the real `build_manifest_from_dict` +
`_WORKFLOW_COMPILER.compile(trust="db")` pair —

```
[BEFORE (gates: [])]                REJECTED: ... (R-03)
[AFTER  (gates merged from manifest)] COMPILED OK
```

## What changed and why there

One call site, `handleSaveAsOverride` in
`frontend/src/components/workflow/IdeaInputPage.tsx`:

```ts
const saveSelections = { ...(manifestSelections ?? {}), ...selectionsRef.current };
```

fed to `buildWorkflowManifest(...)` and to `setOverrideSelections(...)`, with
`manifestSelections` added to the `useCallback` deps.

- **Manifest first, ref second** — same precedence `mergedInitialSelections`
  already uses two hundred lines above, so a lever the user actually edited still
  wins over the manifest's declaration.
- **At the save call site, NOT in `selectionsRef` itself.** `handleRun` relies on
  the ref being empty to omit `selections` from an untouched launch payload
  (INV-3); seeding the ref would change every launch body.
- **`setOverrideSelections(saveSelections)` too**, so toggling the override off
  and back on (`handleToggleOverride` restores `selectionsRef.current` from
  `overrideSelections`) does not re-arm the same 422 inside one session.
- Fixes all five examples at once because none of them has a bespoke code path —
  they render through the same component and the same button
  (`effectiveType !== "custom" && workflowId`, `:1661`).

Deliberately NOT touched:

- `handleSaveWorkflow` (`:1382-1418`). The register's own proposed fix scopes its
  merge as "pending ISS-263", and merging there is measurably a REGRESSION: the
  selections path synthesises a step list with no `route:`
  (`backend/agents/workflows/selections.py:81-155` — `route` is in neither
  `_LEVER_KEYS` nor the verbatim-projection loop), so `gates: [conditional]`
  alone trips R-03 from the other direction on all five examples. Measured, not
  assumed. See [ISS-381](20260828-2210-ISS-381.md).
- `LaunchWizard.tsx:738`, the identical `handleSaveAsOverride`. It has no
  `manifestSelections` equivalent — it never fetches raw manifest steps into a
  gate map — and only `prototype`/`ppt` reach it, neither of which declares
  `route:`. Nothing to merge, no R-03 exposure.
