## What was wrong

On any built-in `/create/<mode>` launch panel, opening "Advanced N agents" with no agent node
selected shows the right rail's Workflow tab with all six of its controls — Smart planning,
Confirm requirements first, Deliverable strategy, Output file name, Output format, Internet
access — rendered `disabled`, with no lock icon, no `title`, no `aria-describedby` and no
explanatory copy. A user could not tell deliberate read-only state from a broken or
still-loading control. Reproduced 3/3 by the validator; register entry
`BUG-20260828-000600-create-user-stories`.

## Root cause

`frontend/src/components/workflow/composer/CanvasView.tsx` used the presence of the
`onRunConfigChange` / `onCapabilitiesChange` props as the sole signal for BOTH "is this editable"
and "should the user be told why not", and only ever wired the first:

- Smart planning `disabled={!onRunConfigChange}` (line 1643 pre-fix)
- Confirm requirements first `disabled={!onRunConfigChange}` (1658)
- Deliverable strategy `disabled={!onRunConfigChange}` (1687)
- Output file name `disabled={!onRunConfigChange}` (1722)
- Output format `disabled={!onRunConfigChange || formatLocked}` (1738)
- Internet access `disabled={!onCapabilitiesChange}` (1769)
- "Reset to default" `disabled={!onRunConfigChange && !onCapabilitiesChange}` (2249) — the
  seventh control, in the rail's TAB HEADER rather than in `workflowSettingsSection`, filed
  separately as [ISS-368](20260828-1927-ISS-368.md)

Neither prop exists on `AgentsPopupProps` at all (`AgentsPopup.tsx:43-146`, documented as
deliberate at lines 71-80), and `AgentsPopup.tsx:2449` renders `<CanvasView>` with no way to
forward them — so every popup render of the rail is read-only. The gap is structural in
`AgentsPopup`, not per-caller: both of its callers, `LaunchWizard.tsx:1112` (every built-in
`/create/<mode>`) and `IdeaInputPage.tsx:1870` (compose-from-scratch), hit the identical state.
`ComposerPage.tsx:1135-1137` forwards both callbacks, so the full-page Composer was never
affected. Full analysis on [ISS-246](20260828-1657-ISS-246.md).

## What changed, and why there

`frontend/src/components/workflow/composer/CanvasView.tsx`, +31 lines, no deletions:

1. One derived reason, next to `formatLocked` where the rest of the rail's gating is computed:
   ```tsx
   const LOCKED_NOTE_ID = "workflow-settings-locked-note";
   const runConfigLockedNote = onRunConfigChange ? undefined : LOCKED_NOTE_ID;
   const capabilitiesLockedNote = onCapabilitiesChange ? undefined : LOCKED_NOTE_ID;
   ```
2. `workflowSettingsSection` renders a visible note at its head whenever either is locked:
   "Read-only — these run settings come from this workflow's own configuration and cannot be
   changed here."
3. Each gated control points at that note: `aria-describedby={runConfigLockedNote}` on the three
   `<select>`/`<input>` controls, a new optional `describedBy` prop on the local `Toggle`
   (forwarded to its `aria-describedby`) for the three switches, and — for
   [ISS-368](20260828-1927-ISS-368.md) — an inline `aria-describedby` on the tab-header "Reset to
   default" button mirroring its own `!onRunConfigChange && !onCapabilitiesChange` condition,
   since that button is rendered outside `workflowSettingsSection` and a fix confined to that
   section would not have reached it.

Placed in `CanvasView` and not in `LaunchWizard`/`AgentsPopup` because `CanvasView` is where the
`disabled` gate itself lives — the single point every caller routes through, so
compose-from-scratch (`IdeaInputPage`) gets the same explanation as the launch panel from one
edit. The alternative — forwarding the callbacks from `AgentsPopup` — would make a built-in's
declared workflow-level config editable from the launch panel, which
[ADR-0027](20260825-2115-ADR-0027.md) ("a user override overlays STEPS only, never the
workflow-level fields") rules out; the read-only behaviour is intentional and is preserved
exactly. `ComposerPage` passes both callbacks, so both note constants are `undefined` there and
the Composer renders byte-identically — no note, no `aria-describedby`.

Copy deliberately promises no escape hatch ("cannot be changed here", not "save your own version
to edit them"), because per ADR-0027 a saved override would not carry these fields either.

`aria-describedby` over `title`: it is the accessible-description channel a screen reader
announces on a disabled control, it binds to copy that is visibly on screen rather than a
hover-only native tooltip (which Chrome renders inconsistently on disabled form controls), and it
reuses the "disabled + visible reason" pairing `CanvasConfigRail.tsx:600-610` already ships for
its "Execute commands" toggle.

## Not fixed here (pre-existing, flagged)

- Output format's OTHER gate, `formatLocked` (`formatOptions.length <= 1`, e.g.
  `serialized_sandbox` offering only `.zip`), still disables silently in the editable Composer
  where `runConfigLockedNote` is `undefined`. Different reason, different surface, not in
  [ISS-246](20260828-1657-ISS-246.md)'s scope; never observed being reported as confusing, so no
  card written.
- `npx eslint` on the changed file: 0 errors, 14 `react-hooks/static-components` warnings, all
  pre-existing (`Toggle`, `InfoHint`, `CapTip` et al. are defined during render); this change
  added no new component.
