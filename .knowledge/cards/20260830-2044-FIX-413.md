## Summary

All three were defects in test code or dead application code. No application behavior changed.

### ISS-613 — byte-vs-character size constants

**What was wrong:** `test_the_files_tab_shows_the_pinned_versions_own_deliverable` failed against correct output. The test's `V1_SIZE`/`V2_SIZE` constants were computed from CHARACTER counts (`len(output) / 1024`) but the Files tab renders UTF-8 BYTES (`formatSize(utf8Bytes(...))`). Both deliverables contain non-ASCII characters, so every rendered size is one tenth of a KB above the constant.

**What changed:** Constants recomputed as UTF-8 bytes — `247,691 B` → `"241.9 KB"`, `85,624 B` → `"83.6 KB"`. The test assertion still fails on a pin regression (it asserts v2's size present AND v1's absent), so it remains a regression guard.

**File:** `tests/integration/e2e/suites/21_run_families_and_versions/test_iss_230_version_pin_survives_tab_switch.py:26-27`

### ISS-614 — dead DeepLinkTarget.anchor

**What was wrong:** `DeepLinkTarget.anchor` was parsed end-to-end by `useRunChat.parseDeepLink` with zero application readers. Confirmed by `grep -rn '\.anchor\b' frontend/src/` (excluding tests) returning no matches. [FIX-412](20260829-1703-FIX-412.md) solved the real defect via `pipeline_run_id` instead, leaving `anchor` as dead weight.

**What changed:** Field deleted from `DeepLinkTarget` (`frontend/src/types/index.ts:75-90`) and its parsing removed from `useRunChat.parseDeepLink` (`frontend/src/hooks/useRunChat.ts:280-299`). Two fixtures in `frontend/src/components/chat/ResultCard.test.tsx` updated to match.

**Files:** `frontend/src/types/index.ts`, `frontend/src/hooks/useRunChat.ts`, `frontend/src/components/chat/ResultCard.test.tsx`

### ISS-615 — unsatisfiable network-proxy assertion

**What was wrong:** `test_back_to_latest_from_pinned_middle_version_reaches_true_latest` asserted `assert not fetched_root_instead`, which cannot pass. The addressing scheme `/runs/{rootId}/versions/{v}/{tab}` keeps the root in the base segment by design, so a bare `GET /api/runs/{rootId}` fires on ANY route change as a shell side effect. The assertion was a proxy for "the root's data was rendered", but the proxy is wrong under this contract — the root is always fetched, and what is RENDERED is decided by the pin.

**What changed:** Replaced with a direct assertion on what the user sees: `assert page.url.endswith("/versions/5/steps")`. The replacement was proven real: `handleBackToLatest` was temporarily changed to use `unpinnedRunId`, the assertion FAILED with the root URL, and the change was reverted (verified: `PreviewPanel.tsx:707` uses `latestId`).

**File:** `tests/integration/e2e/suites/21_run_families_and_versions/test_iss_607_610_611_612_base_route_revision_unreachable.py`
