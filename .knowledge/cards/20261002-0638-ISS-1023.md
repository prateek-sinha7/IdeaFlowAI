# ISS-1023

Adjacent sibling of [ISS-908](20261001-2204-ISS-908.md) (QA-KB-080), CONFIRMED by a run (observed, not inferred). Same mechanism, a different method of the same runner handle, and the other
half of the same Stop guard set: [FIX-425](20260831-1804-FIX-425.md) named `test_fanout_cancel.py` among its regression guards ("the kernel cancel boundary still sees the CancelledError", 9 passed on 2026-08-31).
Found by baselining the neighbours of the ISS-908 guard before proposing the fix; the five failures are already listed in `UNIT-TESTS.md:298-302` (rows 265-269) but have no card.

## What happens (CONFIRMED, observed 2026-10-02, HEAD `024c03ef8`)

`cd backend && .venv/bin/python -m pytest tests/unit/agents/test_fanout_cancel.py -q -p no:cacheprovider` gives `5 failed, 4 passed`. The five:
`test_cancel_mid_parallel_marks_rows_cancelled_and_tears_down` ("some allocated isolated workspaces were NOT torn down on cancel (leak)"), `test_cancel_mid_parallel_zero_workspace_residue`
(`leaked isolated workspaces after cancel: [0, 1, 2, 3]`), `test_non_worker_exception_cancels_siblings_and_flips_rows`, `test_cancel_between_sequential_workers_stops_next_spawn`,
`test_cancel_before_merge_preserves_fragments_and_skips_merge` (the last three `assert False` on the teardown check).

The captured log carries the cause, once per workspace:
`WARNING agents.execution_engine.fanout:fanout.py:1775 fan-out workspace teardown failed: _CancelRunner.teardown_isolated_workspace() got an unexpected keyword argument 'delete_branch'`.

## Root cause (CONFIRMED, file:line read)

- Kernel call: `backend/agents/execution_engine/fanout.py:1771`, `await teardown(base_workspace, ws, delete_branch=delete_branch)`, inside `_teardown_allocated(runner, base_workspace, allocated, *, delete_branch: bool = True)` (`:1749-1775`).
  The cancel path computes `delete_branch=not _cancel_active` (`:919-924`): retain the branch when a fan-out is cancelled (Requirement 28).
- Real handle: `kernel_services.py:919-921`, `teardown_isolated_workspace(self, base_workspace, worker_ws, *, delete_branch: bool = True)`.
- Fake: `backend/tests/unit/agents/test_fanout_cancel.py:86`, `async def teardown_isolated_workspace(self, base_workspace, worker_ws):`. No `delete_branch`, no `**kw`.
- The `TypeError` never surfaces: `fanout.py:1774-1775` is a best-effort `except Exception as exc: logger.warning("fan-out workspace teardown failed: %s", exc)` (INV-3, cleanup never breaks the run).
  The fake's `torn_down` list therefore stays empty and each test fails on its own assertion, one step removed from the cause.
- Introduced by `24f112706` (2026-09-09, "git-backed run versioning and run chaining"), which added the `delete_branch` parameter and the pass-through and did not widen this fake.
  `tests/agents/test_cancel_paths_v3.py:385` is the compliant shape: `teardown_isolated_workspace(self, base_workspace, ws, *, delete_branch=True)`.

## The product path holds (CONFIRMED)

The real handle accepts the keyword, and `tests/agents/test_phase6_sandbox_versioning.py -k teardown_isolated_workspace_passes_delete_branch` gives `1 passed` (it asserts the forwarding on the cancel path and the happy path).
Only the fake lags. With the fake widened IN MEMORY (`evidence/qa-kb-080/analysis_pytest_probe_plugin_teardown.py`, no file edited) the same file gives `9 passed`
(`evidence/qa-kb-080/analysis-pytest-probe-plugin-teardown.out.txt`), so the missing keyword is the sole cause of all five.

## Fix (proposed, not applied)

Test-only, one line at `backend/tests/unit/agents/test_fanout_cancel.py:86`:
`async def teardown_isolated_workspace(self, base_workspace, worker_ws, *, delete_branch=True):`.
Optional, in the same edit: record the flag on the fake, so the retain-on-cancel contract (`delete_branch=False` on the cancel path) is asserted here and not only against the real handle in `test_phase6_sandbox_versioning.py`.
Do not change `fanout.py` to drop the keyword (retention on cancel is deliberate) and do not stop swallowing the teardown error (INV-3).

## Why it belongs with ISS-908

Both are one defect class on one seam: a hand-rolled fake of a `KernelServices` method pins yesterday's keywords, and the Stop guards for a fan-out are the tests that notice last because they sit behind a best-effort path.
The family-ending guard proposed in [ISS-1022](20261002-0638-ISS-1022.md) would have caught both.

## Resolution (QA-KB-080 fix, 2026-10-07)

Fixed by [FIX-737](20261007-1957-FIX-737.md), test-only, as proposed above.
`test_fanout_cancel.py:86-88` is now
`async def teardown_isolated_workspace(self, base_workspace, worker_ws, *, delete_branch=True):`, wrapped as `ruff format` wraps it.

- Observed: `5 failed, 4 passed` before, with 12 `fan-out workspace teardown failed: ... 'delete_branch'` warnings across the
  five tests. After: `9 passed` and no such warning (`evidence/qa-kb-080/fix-02-before-fanout-cancel.txt`,
  `fix-04-after-fanout-cancel.txt`).
- `fanout.py` still passes `delete_branch` (`:1773`) and still swallows teardown errors (`:1776-1777`, INV-3). The optional
  retain-on-cancel assertion on this fake was not added. That contract is pinned against the real handle by
  `tests/agents/test_phase6_sandbox_versioning.py -k teardown_isolated_workspace_passes_delete_branch`.
