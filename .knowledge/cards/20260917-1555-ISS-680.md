# ISS-680

## Status: found by the 5-fixer, not fixed, not reproduced live

[FIX-523](20260917-1555-FIX-523.md) keeps a background run's roster across a client-side
navigation. It cannot do so across a full page reload, which [ISS-679](20260917-1522-ISS-679.md)
point 6 names as a second trigger. This card records that gap, so a reload showing "0 of N agents"
is not taken as QA-PS-002 coming back.

## Mechanism (read in code, line numbers as of FIX-523)

1. A reload re-evaluates `useRunStateStore.ts`, so `runStates` (`:263`) starts empty.
2. `RunConnectionProvider` reattaches each tab-launched live run from its saved cursor
   (`afterSeq: readCursor(runId)`, `RunConnectionProvider.tsx:214`), so `pipeline_start` is not
   delivered again.
3. With no roster, `agent_complete` is a no-op (`useWorkflow.ts:705-706`), and
   `runAgentsCompletedMap` (`page.tsx:3912-3918`) feeds 0 to `AppHeader.tsx:204`.
4. Only the run named in the URL is replayed on mount (T7/T11, `page.tsx:3242, 3420`). Clicking a
   panel row replays that run too (`handleSwitchToLiveRun`, `page.tsx:2663`). No path replays a
   run that stays in the background.

## Why it was not fixed with FIX-523

The obvious fix is to replay `getRunEvents` for every live, tab-launched run with an empty roster,
through `runStore.handleFrame`. That has a side effect nobody has designed for:

- `handleFrame` makes a replayed `pipeline_start` the viewed run whenever no run is viewed
  (`useRunStateStore.ts:437`, the launch-window fallback). On `/dashboard` after a reload, no run is
  viewed.
- The projected `pipelineState.isRunning` then fires DashboardLayout's effect, which calls
  `router.push(routes.runStream(incomingRunId))` (`DashboardLayout.tsx:781, 812`). The user would
  be taken from the dashboard to the first rehydrated run.

A safe rehydrate needs a replay entry point that never adopts the viewport, or a server-side
completed-agent count on `GET /api/runs` (the API-contract option already listed for
[ISS-675](20260917-1447-ISS-675.md)). Neither was covered by ISS-679's recommendation, and FIX-523
did not choose between them.

## What would confirm this live

1. Launch two runs from one tab, and wait until each has finished at least one agent.
2. From `/dashboard`, reload the page.
3. Open the bell panel or the "N Running" dropdown: expect "0 of N" for both runs.
4. For contrast, press Home instead of reloading. After FIX-523 the counts are right.
