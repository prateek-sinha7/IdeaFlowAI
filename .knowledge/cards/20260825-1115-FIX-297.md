## Symptoms

On any workflow carrying a `conditional` gate: nodes overlapped, a node
rendered off-canvas at `y = -88`, a new agent added at the end landed
mid-chain, and the first node rendered visually detached. Gate-free chains were
always fine, which is why this surfaced only with spec 014's fixtures.

## Root causes

**1. Backward route target made its predecessor a leaf** —
`CanvasView.tsx`, `routeTargetIds`. Every `trigger:"step"` target was collected
regardless of direction; `hasChainEdge()` then returned false for any such
node, which BOTH suppressed its incoming chain edge AND satisfied the
`leafAdds` filter for its array predecessor. Correct for a FORWARD branch
target (reachable only via the amber route edge); wrong for a BACKWARD loop
target, which is entered normally on the first pass — stated in
`backend/agents/workflows/ex_A1_loop/workflow.yaml`. In A1
(`emoji -> greet -> check -> done`, `retry -> greet`) this drew no
`emoji -> greet` edge and gave `emoji` a spurious leaf "+" whose
`insertBeforeId` spliced new nodes at index 1.
Fixed by restricting `routeTargetIds` to forward targets (target index >
source index).

**2. External workflow node fell back to `START_X`** —
`externalSlotById` used `columnX.get(slot.col) ?? START_X`. `START_X` is the
LEFTMOST column, so a gate whose outcomes were all `trigger:"workflow"` (no
step target to anchor the column) rendered its divert node left of its own
gate, on top of an earlier node. Fixed by deriving x from the gate's column.

**3. `slot.row` received a CENTRE where a TOP was expected** — the fan
placement loop did `const row = y + member.height / 2` while `y` already walked
the TOP edge, and `slot.row` is consumed as a top everywhere
(`NODE_Y + slot.row` at both the root-node and external-node sites). Every
member was pushed down by its own half-height; because members have DIFFERENT
heights, they were pushed by different amounts and the gap between them
collapsed. THIS was the overlap.

**4. Separation used an ESTIMATE instead of the measured height** —
`getNodeHeight()` returned `ROOT_H_EST` (176) for every root agent. Real cards
measure 243. Pitch came out 240 (`176 + ROW_GAP 64`) where 307 was needed, so
every same-height fan pair under-separated by 67px. Fans only looked correct on
shapes whose cards happened to render short enough — a 5-outcome fan collapsed
immediately with 5 overlaps. Fixed to `max(cardH, ROOT_H_EST)`, where
`cardH = rowPortOffset * 2` is the DOM-measured height already passed in; the
gate-centre calculation uses the same value so fans stay centred.

**5. `loop_max_iterations` displayed but never persisted** —
`CanvasConfigRail.tsx` showed "Max loop count 5" on a backward-jump outcome as
a disabled input; the saved route carried only `{trigger, target}`. A
canvas-authored loop therefore had no R-07 fail-closed cap. Made editable and
persisted. The first fix introduced a regression — `parseInt("")` on a cleared
field wrote `loop_max_iterations: null` WITH THE KEY PRESENT, which defeats
`compiler.py:1216`'s `raw_route.get(..., 5)` (that only defaults on an ABSENT
key), sets the plain-dataclass `RouteSpec.loop_max_iterations` (`plan.py:262`)
to `None`, and makes `engine.py:3107`'s `_visits >= _loop_max` raise a
TypeError mid-run. Guarded so only a finite integer >= 1 is written.

**6. A conditional gate counted as a "review gate"** — the composer header
badge counted any gate. Per [ADR-0013](20260824-1630-ADR-0013.md) only `human`
and `before-human` are review gates; `conditional` routes, it does not pause.
Filtered, and pluralised.

## Also done: the reason this kept regressing

`CanvasView.test.tsx` contained a ~200-line REPLICA of the layout algorithm
(`computeCanvasLayout`) plus its own constants — `NODE_GAP = 20`,
`ROW_GAP = 16` against real values of 96 and 64. Every layout test exercised
the replica, never `CanvasView.tsx`, so three separate engineers reported green
suites over a visibly broken canvas. The algorithm was extracted to
`graphLayout.ts` (`computeRootLayout`, pure) and BOTH the component and the
test now import it, constants included.

## Verification method

Measured on the running app in real Chrome via `getBoundingClientRect`,
computing pairwise box intersection across every rendered node — not from unit
tests, which had already proven unreliable here. Six saved workflows: A1 retry
loop, A2 three-way branch, A3 workflow handoff, A4 human gate, a 12-node
3-level nested stress test, and a 14-node/5-gate case including a 5-wide fan
and two gates converging on one node. Zero intersections and no negative
coordinates in all six after the fix.
