## Render the live Reasoning and Output cards simultaneously

Fixes [ISS-166](20260819-1726-ISS-166.md) — see that card for the root cause.

**Change** (`frontend/src/components/results/AgentDetailPanel.tsx:1034-1035`):

```jsx
// before
{reasoning.trim().length > 0 && <ReasoningCard text={reasoning} live={isRunning} />}
{reasoning.trim().length === 0 && isRunning && <ReasoningCard text={agent.output || ""} live label="Output" />}
// after
{reasoning.trim().length > 0 && <ReasoningCard text={reasoning} live={isRunning} />}
{isRunning && <ReasoningCard text={agent.output || ""} live label="Output" />}
```

Desired/confirmed behavior, keyed on run state:
- **While running, before output starts:** Reasoning only (unchanged from before).
- **While running, output streaming (with or without concurrent thinking):**
  Reasoning renders first (live or already settled), Output renders directly below it,
  live — both independently, since `isRunning` gates Output and
  `reasoning.trim().length > 0` gates Reasoning with no cross-dependency.
- **Once done:** the live Output card stops rendering (`isRunning` false); the
  pre-existing settled-output view (`SettledArtifactCards`/`OutputPreviewSection`,
  untouched, same position as before) becomes the sole output view. Reasoning stays
  visible (no longer live) since `thinkingText` persists independently of `isRunning`.

`ReasoningCard` is a plain function component with its own local `useState` per
instance, so rendering two of them side by side carries no shared-state risk.
