# FIX-764

Bug report QA-KB-098. The root cause and blast radius come from the analysis on [ISS-1063](20261007-1940-ISS-1063.md) and
are not re-derived here. The change is to one test file. No production module changed.

## What was wrong

`TestPerRunPathsDistinct::test_revision_browser_dir_writer_driven` saved `playwright_tools._SANDBOX`
(`backend/tests/agents/test_per_run_paths_v3.py:427`) and wrote it back in its `finally` (`:444`). That module global no
longer exists: [FIX-567](20260918-FIX-567.md) (`5af898322`) moved the binding into the `_SANDBOX_VAR` / `_AGENT_KEY_VAR`
ContextVars (`backend/app/agents/tools/playwright.py:46-51`, written by `bind_sandbox` at `:67-68`). The test was written
on `feat/git-versioning` against the old shape, and merge `4ebd98e8f` combined the two without a textual conflict. So the
test died on `AttributeError` at `:427`, before it reached the browser or its own documented skip. That also fails the
`backend-offline` CI job (`.github/workflows/ci.yml:336-337`), which collects the node.

## What changed, and why there

Two deletions in `backend/tests/agents/test_per_run_paths_v3.py`, as the card prescribes:

- `_orig_sandbox = playwright_tools._SANDBOX` (old `:427`), and
- `playwright_tools._SANDBOX = _orig_sandbox` (old `:444`).

The `try` / `finally` with `playwright_tools.playwright_close.invoke({})` stays. It is real cleanup: the root and revision
bindings share one browser session keyed by the sandbox directory name. Every assertion is untouched.

**This is a test edit, and only because the card says the test pinned a name that production deleted on purpose.** The app
is right: the FIX-567 lock forbids putting the global back. No restore replaces the deleted one. `bind_sandbox` writes
ContextVars, and a write inside an `async def` test stays inside that test's task. The analysis showed this with a shim;
`fix-04` below shows it again on the fixed test, with no shim.

## Not changed, on purpose

- `backend/app/agents/tools/playwright.py`: no `_SANDBOX` alias, no shim (FIX-567 lock on ISS-1063).
- The pptx save/restore in the same file (`:313`, `:323`) is correct today, because `pptx_tools` still owns the global. It
  is the next stale pin, carded as [ISS-1108](20261008-0123-ISS-1108.md).
- The three INFERRED siblings stay `open`: [ISS-1106](20261008-0123-ISS-1106.md) (a revision's `.logs` / `.browser` /
  `.verify` land in the root's paths), [ISS-1107](20261008-0123-ISS-1107.md) (a revision's browser session is released by
  the wrong key) and [ISS-1108](20261008-0123-ISS-1108.md) (pptx_tools and file_extract_tools still bind a process-wide
  global). Each has `verification.status: pending`, no test file, and a fix direction marked "only once reproduced".
  ISS-1106 also carries the ADR-0040 directory-key trap. This fix does not touch them.
- Placement: the test drives real Chromium from `tests/agents/`, which `backend/tests/README.md` rule 8 would put under
  `tests/integration/`. The card leaves the move to the legacy-folder migration, and so does this fix.
- No `xfail` marker exists on this test, so the 6-verifier has none to remove. The red test was the defect itself; the test
  phase added nothing.
