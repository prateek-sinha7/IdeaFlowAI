## What was wrong

Bug report QA-KB-006. The root cause and blast radius come from the analysis cards. They are not re-derived here.

- [ISS-128](20260812-2046-ISS-128.md) is the root card. `ArtifactStore.set_review_response` took `approved` and
  `action` as two separate inputs and defaulted `action` to `"approve"` whatever `approved` said
  (`backend/agents/artifact_store/store.py:143`, pre-change). The three production reject branches pass only
  `approved=False`: `backend/app/api/run_commands.py:325-327` (POST /gate), `:1599` (the Concierge `gate_action`
  disposal) and `:1965` (POST /messages, CHANNEL_GATE). Every rejection was therefore recorded as
  `{'approved': False, ..., 'action': 'approve'}`. Three test-infra callers had the same omission:
  `backend/tests/agents/live_harness.py:438` and `:487`, and
  `backend/tests/integration/agents/test_declared_gate_streaming.py:565`.
- [ISS-865](20261001-2105-ISS-865.md) is the sibling. The approve branch of `resolve_gate`
  (`run_commands.py:329-335`) forwards a client's `approved: false` under a hardcoded `action="approve"`. That stores
  the same contradiction, by a path that passes `action` explicitly.

The record is the in-memory review response. The `store.py` module docstring says it is "intentionally NOT
DB-backed". Its only reader is `engine.py:12457`, which keys on `approved`. A rejection always rejected; only the
stored label was wrong. ISS-128 rates the severity trivial.

## What changed, and why there

One hunk in `set_review_response`, `backend/agents/artifact_store/store.py`:

- `:143`: the default is now `action: str | None = None`. It was `"approve"`.
- `:160-161`: `if action in (None, "approve", "reject"): action = "approve" if approved else "reject"` runs before
  the record is built. `"redo"` and `"update_specs"` are stored as given.
- The docstring sentence claiming every caller stays "byte-identical" was false after this change. A statement of
  the rule replaces it.

Every writer goes through the store. One hunk therefore covers the three reject ingresses, the ISS-865 path and the
test-infra callers. ISS-128's analysis chose this placement ("Placement OVERRULED ... Fix it at the shared seam").
`run_commands.py` is not edited.

One deliberate widening of the card text:

- ISS-128 proposed deriving only an omitted action.
- ISS-865 noted that an omitted-only rule would not reach its path ("this branch passes `action` explicitly").
  It proposed a one-line edit at `run_commands.py:330-335`.
- This fix also derives the two binary labels. The label becomes a function of `approved`, which is the root cause
  as ISS-865 states it, so ISS-865 is fixed from the store too.
- The change stays out of `run_commands.py`, which QA-KB-009 and QA-KB-036 are editing in the same shared tree.
- The mirror case, `action="reject"` with `approved=True`, now records `"approve"`, which is what the engine enforces.
  No production caller sends that pair.

Behaviour is unchanged:

- The engine reads `action` only to compare it with `"redo"` (`engine.py:12470`) and `"update_specs"` (`:12505`).
  The decision is `approved` (`:12551`, `:12561-12562`).
- Per the ISS-128 analysis, `agents/capabilities/gates/human.py` never reads the stored action, and no event payload
  carries it, so INV-3 goldens cannot move.
- POST /gate still returns the request's `action` in its response (`run_commands.py:342`). Only the stored record
  changed.

Not changed:

- `resolve_gate`'s `if/elif` chain, which `backend/tests/unit/api/test_rest_gate_commands.py:48` pins.
- Every call site in `run_commands.py`.
- The strict `xfail` markers. They are left for the 6-verifier.
