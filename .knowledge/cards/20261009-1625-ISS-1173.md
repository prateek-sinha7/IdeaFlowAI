# ISS-1173

## Description

Seen while running the regression files for [FIX-775](20261009-1625-FIX-775.md). It is not caused by that fix and was
not investigated.

`cd frontend && npx vitest --run src/components/results/SandboxTab.test.tsx` reports "4 failed | 35 passed (39)". All
four failures are inside `describe("fenceAgentPayloads")`:

- unwraps a fence whose WHOLE body is a prose wrapper (the agent fenced its own markdown)
- leaves a fence that NAMES a language alone, even around a wrapper
- leaves a fence with anything outside the wrapper alone
- never reaches inside an existing fence

The same file at HEAD `01777a107`, from a `git archive` export run with the same `node_modules`, gives the identical
"4 failed | 35 passed (39)" and the same four names. FIX-775 changes `SandboxTab.tsx` in two places only: the import
block, and the HTML preview iframe's `srcDoc`/`sandbox` (`:74`, `:1654-1656`). It does not touch `fenceAgentPayloads`.
Raw output: `evidence/qa-kb-125/fix-2-regression-runs.txt`.

Two of the assertion diffs, verbatim from the run:

- `SandboxTab.test.tsx:221`: input `"# Task Planner Agent\n\n```\n<tasks>\n## Task 1\n**Goal**: ship..."`, expected the
  output not to contain a fence; received `# Task Planner Agent`, then an empty fence (two fence lines), then
  `## Task 1` / `**Goal**: ship` below it.
- `SandboxTab.test.tsx:231`: input ` ```js\n<tasks>\nconst a = 1;\n</tasks>\n``` ` expected back unchanged; received
  ` ```js\n```\n\n\nconst a = 1;\n\n `.

In both, the `<tasks>`/`</tasks>` lines are removed and the fence is closed early. Not established: whether the function
or the four tests are out of date (`git log` shows neither file changed since `f9df3737c`, 2026-09-29), and since when
they are red.

## Expected vs actual

- Expected: the four `fenceAgentPayloads` cases pass, or the tests are corrected if the behaviour changed on purpose.
- Actual: red at HEAD `01777a107`.
