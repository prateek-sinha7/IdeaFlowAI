## What happened

Second sibling of [ISS-199](20260828-1600-ISS-199.md) (root card for
BUG-20260828-012900-runs-id-files), found while grepping every caller of the
same broken helper. `FilesTab.tsx`'s collapsed "From v{n-1}" base-version
section (B3 / POR §5 D6) lazily fetches a revision's PARENT run on first
expand and re-derives its file list via the SAME module-level helper the root
card already flags:

```
FilesTab.tsx:436-440:
  const rows = deriveDeliverableFiles(parentRun.type, {
    userStoryContent: parentRun.output,
    pptContent: parentRun.output,
    prototypeContent: parentRun.output,
  });
```

This is a THIRD call site for the pattern ISS-199 and
[ISS-214](20260828-1633-ISS-214.md) already flag, and it passes
`parentRun.type` **raw** — never normalized to `"ppt"` the way
`PreviewPanel.tsx:578`'s `renderType` normalizes `ppt_v2`. If the parent run
of a revision is a `ppt_v2` run, `parentRun.type === "ppt_v2"` matches none of
`deriveDeliverableFiles`'s branches (`FilesTab.tsx:392` requires the literal
`"ppt"` / `"ppt_revision"` strings), so `rows` comes back `[]`. Unlike the
main call site (`FilesTab.tsx:547`), this one has no `genericDeliverable`
fallback wired in at all (`handleToggleBase`, `FilesTab.tsx:424-448`, never
receives or threads one) — so the base-version section renders with **zero**
file rows for a `ppt_v2` parent, silently, rather than the mislabeled tmp-file
row ISS-199 reports for the current run, or the genericized row ISS-214
reports for the History browser.

## Root cause

Same root cause as ISS-199 (no reconciliation against the run's workspace
listing / declared deliverable) reached through a third caller
(`FilesTab.tsx:436-440` itself) that reuses the identical `deriveDeliverableFiles`
helper — and inherits the `ppt_v2` string-matching gap ISS-214 also found, one
level worse: no generic-deliverable fallback exists at this call site at all,
so the failure is silence, not a mislabel.

## Expected vs actual

- **Expected:** expanding "From v{n-1}" on a revision of a `ppt_v2` deck shows
  that base version's Final output (once ISS-199 is fixed: its declared
  `presentation.html`).
- **Actual (INFERRED — code-traced, not yet click-verified in the browser):**
  a `ppt_v2` parent run shows a base-version section with zero file rows —
  `deriveDeliverableFiles("ppt_v2", ...)` returns `[]` and no fallback runs at
  this call site.

## Why the root cause implies this

Covers the analyzer's "adjacent state" check — the same broken derivation
applied to a DIFFERENT run (a revision's parent/base version) via a THIRD
caller. Shares ISS-199's and ISS-214's root cause and reproduces ISS-214's
`ppt_v2` string-matching gap, but its failure shape is distinct from both:
not a mislabeled tmp file (root card) and not a genericized row (ISS-214),
but total silence — no row at all, so a user expanding this section for a
ppt_v2 base version sees an empty list with no indication anything was
produced.

## What would confirm it

Launch (or locate) a `ppt_v2` run, request a revision of it, open the
revision's Files tab, expand "From v{n-1}", and check whether the
base-version section lists any file for the `ppt_v2` parent.
