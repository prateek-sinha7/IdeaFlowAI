## What was wrong

Bug report QA-KB-027. The root cause and blast radius come from the four analysis cards; they are not re-derived
here. The product half of [ISS-724](20260922-1246-ISS-724.md) was already fixed by
[FIX-601](20260922-1319-FIX-601.md). What stayed open was the guard, plus one product defect found while probing.

- [ISS-724](20260922-1246-ISS-724.md) (root): the one test file written to guard Workspace content under a pinned
  ref, `backend/tests/unit/test_sandbox_ref_scoped_endpoints.py`, never ran. It sat in `tests/unit/`, whose autouse
  `_unit_io_guard` (`backend/tests/unit/conftest.py:91`) refuses a DB connection and a subprocess, and behind that its
  `_seed_user` passed `User(..., password_hash="x")` (`:95`). Pre-change: `1 xfailed, 5 errors`. Its ISS-697 strict
  xfail reported `x` only because setup errored.
- [ISS-891](20261001-2120-ISS-891.md): the same removed kwarg in 11 test files. `User` has had no `password_hash`
  since the Cognito-only migration, and `cognito_sub` is NOT NULL (`backend/app/models/user.py:51`), so each raised
  `TypeError: 'password_hash' is an invalid keyword argument for User` at setup.
- [ISS-892](20261001-2120-ISS-892.md): `backend/tests/unit/test_run_files_ref_family_scope.py`, the verification file
  of [FIX-522](20260917-1449-FIX-522.md), [ISS-671](20260917-1345-ISS-671.md) and
  [ISS-672](20260917-1350-ISS-672.md), hit both faults. Pre-change: `1 failed, 2 errors`.
- [ISS-893](20261001-2120-ISS-893.md): `list_sandbox` computed `expired = not sandbox.root.is_dir()`
  (`backend/app/api/run_files.py:941`) and then, when `ref` was set, called `_validate_ref` first. A swept sandbox
  has no tags, so `ref not in valid_tags` (`:878`) raised `400 invalid ref` and the listing's `expired` flag could
  never be returned under a pinned ref.

## What changed, and why there

**ISS-893 (product, one guard).** `backend/app/api/run_files.py:948` is now `if ref is not None and not expired:`
(was `if ref is not None:` at `:945`), plus a three-line comment. A swept sandbox with a ref falls through to the
live branch (`:982`), whose `sandbox.list_files()` returns `([], False)` for a missing root
(`backend/app/agents/sandbox.py:768`), so the response is `200 {run_id, expired: true, truncated: false, files: []}`.
`list_sandbox` is the only route with this ordering, so the guard goes there. Expiry-first is the established
contract, not a new decision:

- the route's own docstring (`run_files.py:922-925`): "`expired` is the real signal for a TTL-swept run ... The UI
  renders a 'workspace expired' state on it";
- the ref branch already returns `"expired": expired` (`:976`), so it was meant to carry the flag;
- both sibling ref routes check the directory before `_validate_ref`: `download_sandbox_zip` (`:1044`) and
  `read_sandbox_file` (`:1156`) raise `404 Workspace expired` first;
- the frontend type `SandboxListing` (`frontend/src/lib/api.ts:1564-1571`) has no `ref` field, and
  `SandboxTab.tsx:1170-1185` calls `setExpired(res.expired)` only on a 200. No frontend change is needed.

Security is unchanged. When the sandbox is gone, the ref is never validated and never reaches git: the live branch
runs `list_files()` only. A live sandbox still validates every ref (unknown ref and tagless sandbox stay 400).

**ISS-724 (test only).** `backend/tests/integration/api/test_sandbox_ref_scoped_endpoints_api.py`, which the test
phase created as the relocated home (4 edge cases plus the ISS-893 pin), now also holds the six tests of the dead unit
file. Their class names, test names, docstrings and assertion messages are unchanged. Only the plumbing changed: the
file's `env` fixture already seeds a `cognito_sub` user and the run, and now also yields `Session`; a
`_make_tagged_sandbox(env, *, versions)` helper replaces the old one; and `_set_db_git_tag` replaces the two inline
`git_tag` writes. One docstring cross-reference was renamed to `test_run_files_ref_family_scope_api.py`. The dead
`backend/tests/unit/test_sandbox_ref_scoped_endpoints.py` was deleted (plain `rm`, no git operation) once every test
name was confirmed present in the new file.

**ISS-892 (test only).** Moved `backend/tests/unit/test_run_files_ref_family_scope.py` to
`backend/tests/integration/api/test_run_files_ref_family_scope_api.py` (plain `mv`). Two lines changed: the
docstring's own path and the seed (`cognito_sub=str(uuid.uuid4())`). `_assert_nearest_repo_is` is kept, so every git
call still lands in the throwaway outer repo under `tmp_path`.

**ISS-891 (test only).** One line per file, `password_hash="x"` became `cognito_sub=...`:

- `str(uuid.uuid4())` (module-level `uuid`) in `backend/tests/agents/test_revision_routes_v3.py:90`,
  `backend/tests/agents/test_restore_guard_v3.py:114` and `backend/tests/integration/test_gate_redo_enforcement.py:83`;

  constant `OWNER` per in-memory DB and import no `uuid`;
