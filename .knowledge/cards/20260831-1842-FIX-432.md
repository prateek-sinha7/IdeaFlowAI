## What was wrong

Every revision run — WS `run_revision`, REST `POST /runs/{id}/revisions` and the
Concierge path, all three of which funnel through the single
`_drive_revision_to_queue` → `engine._handle_revision` chokepoint
(`app/api/run_commands.py:3835`) — completed its dispatch, then failed to persist
the revised deliverable under its exact target kind, and emitted

```
state_restoration_failed  {"error": "list index out of range", …}
```

instead. FR-014 **chain link 1** (the exact-kind ref a revision-of-revision
resolves its parent original from) was therefore never written by any revision;
only the generic `kind="deliverable"` chain-link-2 ref survived.

## Root cause — `backend/agents/execution_engine/engine.py:8058`

The `revision-pipeline-refactor` changed `_handle_revision` to hand `execute()`
an EMPTY roster on purpose (`engine.py:7962`, `agents: list = []`) so `execute()`
rebuilds the roster from the compiled manifest via
`_specs_from_plan(compiled.steps)` — required because
`prototype-revision-analyzer` declares its own private `pipeline_type` and is
absent from `PIPELINE_AGENTS["prototype_revision"]`.

The post-dispatch lineage write 100 lines below was left reading that same local:

```python
producer_agent=agents[-1].id,      # agents is [] → IndexError
```

`agents[-1]` on the empty list raises `IndexError("list index out of range")`,
which the block's own `except Exception` arm catches, converts into a
`state_restoration_failed` event and `return`s from — so the failure was
swallowed into a WS event and never reached a log or a test that read the
exception. One orphaned line, one silently skipped write, on the ONE path all
three revision entry points share.

## What changed and why there

`engine.py:7948` binds the fail-fast compile that already ran:

```python
_compiled_revision = compile_for_run(revision_pipeline_type)
```

and `engine.py:8058` reads the producer off it:

```python
producer_agent=_compiled_revision.steps[-1].agent_id,
```

Fixed at the write site rather than by re-populating `agents`: the empty roster
is the refactor's deliberate contract with `execute()`, and re-filling it would
re-introduce the skipped-step-0 bug it was introduced to close. The compiled plan
is the SAME source `execute()` rebuilds the roster from, so the value is the
agent that actually ran last — including for `prototype_revision`, whose plan and
registry orders disagree ([ISS-631](20260831-0115-ISS-631.md)) but agree on the
last element.

SC-001 holds: the producer is data-derived from the compiled manifest, no
workflow name or agent-id literal enters the kernel. No imports added.
