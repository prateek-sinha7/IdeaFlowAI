## Description

Clicking a notification in the notification panel or toast always navigated
to the most recently viewed run rather than the run associated with that
notification entry.

## Root Cause

`markCompleted` passed `undefined` as `workflowRunId` — `onViewResults`
received undefined, skipped the id-based navigation, and fell back to a
type-based search over `recentRuns` which returned the most recent run of
that type regardless of which run completed.

Background run completions also never stamped `workflowRunId` on their
notification entries.

Older notifications (from before this fix) had no `workflowRunId` stored
in localStorage, so they couldn't navigate correctly either.

## Fix

- `markCompleted` now passes `pipelineState.pipelineRunId` as `workflowRunId`
- Background run completions stamp `workflowRunId` when setting `backgroundCompletedRunId`
- `onViewResults` fetches run by id via `getWorkflow` when not found in `recentRuns`
  (older runs that have fallen off the recents window)
- Storage key bumped v2→v3 to purge legacy entries that lack `workflowRunId`
  (they could never navigate correctly)
