## Symptom

A skill declared on a manifest step — `skills: [joke]` on a `workflow.yaml`
step — was staged into the run sandbox and counted in `estimated_tokens`, but
the run page's "Advertised skills" card never rendered for it. A skill attached
through the UI displayed correctly; a manifest-declared one was invisible.

Observed on `ex_A4_human_gate` with `skills: [joke]` on its first step: the
staging log read `staged: ['joke']` while the persisted `run_event` carried
`attached_skills: []` beside `estimated_tokens: 530`. The token count was
always right — only the names were dropped.

The degradation was silent: no empty card, no console error, the word "skill"
absent from the panel entirely. That is why it went unnoticed.

## Root cause

Two seams that never met.

`agent_skills` built its payload from `displayed_skills`, which is the
RUN-attached set and is empty for a per-step skill. A manifest's `skills:`
travels the separate `step_skills` seam (`Step.skills` -> `ctx.step_skills` ->
`factory._resolve_step_skills`) into the factory, which resolves and stages it.

The staged result was already on `ctx.skills_delivery` and the event already
read that object — but only for `skills_load_errors` and `estimated_tokens`.
`SkillsDelivery.staged` carries skill IDS alone, and the payload needs name +
content, so `.staged` was used solely in a warning log.

## Fix

`agents/factory.py` keeps the resolved skill dicts it hands to `stage_skills`
on the ctx as `skills_resolved` — the same D-03 per-run-state seam
`skills_delivery` already uses:

    _skills = _resolve_step_skills(ctx.step_skills) if ctx.step_skills else ctx.attached_skills
    ctx.skills_resolved = list(_skills or [])

`engine.py` advertises those, falling back to `displayed_skills` when no step
skills are declared, so a run with only UI-attached skills emits a
byte-identical payload:

    _advertised = list(getattr(ctx, "skills_resolved", None) or displayed_skills)

## Verification

Confirmed after the fix on run `b563e2f5`: the card renders with count 1, name
"joke", ~530 tok, expanding to the full SKILL.md body.

Tests, each file run individually: test_gates 46, test_composer_skills_delivery
9, test_create_runner 22, test_skill_directive_block 4,
test_skill_prompt_baseline 2, test_skills_text_only_deliverable 2 — all green.

## Note on scope

Staging still writes only a skill's ROOT `SKILL.md`
(`app/agents/skill_staging.py`) and none of its sibling reference files. That
is a separate, unfixed limitation — this card is only about the advertisement
of what WAS staged.
