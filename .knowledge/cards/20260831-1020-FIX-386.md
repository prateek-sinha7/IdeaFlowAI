## What was wrong

`AccountSettings.tsx` renders the `{section === "constitution" && <ConstitutionSection />}` guard at line 487. When the user clicked a different tab, the `Tabs onChange` handler at line 228-234 called `setSection(next)` unconditionally, which immediately turned the guard false and unmounted `ConstitutionSection`. The component held its draft (`content` state) locally, so unmounting discarded the draft with zero warning. Remounting the Constitution tab re-fetched from the backend, showing only the last-saved value, not the lost draft — identical destructive outcome to ISS-320's "Clear" button, but reached via a different code path.

## Root cause

Two intertwined issues in `frontend/src/components/settings/AccountSettings.tsx`:

1. **Lines 228-234 (Tabs onChange):** The handler never checked whether the Constitution tab held unsaved content before calling `setSection(next)` — no dirty check, no confirmation.
2. **Lines 507ff (ConstitutionSection):** The draft was held in the component's own `useState("content")` instead of being lifted to the parent, so the parent's onChange handler could not see it.

## What changed and why there

**1. Lifted `content` + last-loaded value state to parent (lines 106-107)**

Added two parent-level states:
- `constitutionContent` — the current draft (what the user is typing)
- `constitutionLoadedValue` — what was last loaded from the backend

This allows the parent's Tabs onChange to compare them and detect dirty state.

**2. Added dirty-check confirmation gate in Tabs onChange (lines 236-241)**

Before calling `setSection(next)`, added:
```tsx
if (section === "constitution" && constitutionContent !== constitutionLoadedValue) {
  if (!window.confirm(
    "You have unsaved changes to your constitution. Discard them?"
  )) return;
}
```

The gate uses `window.confirm` (same as FIX-385's handleDelete) rather than a modal, so it:
- Surfaces as a native dialog the e2e test expects
- Mirrors the existing pattern the codebase already uses
- Needs no new component

If the user dismisses, returns early WITHOUT calling `setSection`, so the Tabs component never unmounts, the draft stays in local state, and clicking back to Constitution still has it.

**3. Passed lifted state to ConstitutionSection (lines 488-494)**

The component now receives `content`, `setContent`, `loadedValue`, `setLoadedValue` as props instead of managing its own local state for content.

**4. Updated ConstitutionSection signature and hooks (lines 516-535)**

- Added `ConstitutionSectionProps` interface
- Changed function signature to destructure props
- Updated `useEffect` to set BOTH `content` and `loadedValue` when the backend fetch lands
- Added both to the dependency array so React tracks them

**5. Updated handleSave (lines 552-553)**

On success, now calls `setLoadedValue(content.trim())` so `content === loadedValue` clears the dirty flag — the next tab switch will not prompt.

**6. Updated handleDelete (lines 587-589)**

On success, now calls both `setContent("")` and `setLoadedValue("")` so the dirty check stays in sync.

## Why here, not elsewhere

`ConstitutionSection` is the only section whose draft lives in local component state. The other sections' pending values (`pendingModel` for AI Model, password fields for Profile) are already at the parent level, so they don't have this unmount-and-lose-it problem. Constitution was the outlier because its draft was never meant to be persisted immediately (unlike settings that auto-save) — the edit is intentionally local until "Save constitution" is clicked. Lifting it to the parent lets the Tabs onChange see it.

## Verification

**TypeScript:** `npx tsc --noEmit` passes on the modified file with no diagnostics.

**Frontend development environment ready:** The dev server on `:3000` is running. The test framework (`pytest-playwright`) is not installed in the subagent environment, so **e2e test verification is deferred** — the test must be run in an environment with the framework dependencies installed.

**Manual inspection confirms the fix logic:**
- Dirty check: `constitutionContent !== constitutionLoadedValue` correctly identifies unsaved drafts
- Confirmation gate: `window.confirm(...)` matches the FIX-385 pattern and the Gherkin scenario that expects a native dialog
- Early return: `return;` before `setSection` prevents unmount-and-discard
- State sync: `handleSave` and `handleDelete` update `loadedValue` so dirty flag clears after backend success

## Test coverage

The failing test `test_switching_tabs_away_from_constitution_requires_confirmation_for_unsaved_draft` expects:
1. Type an unsaved draft into Constitution
2. Click a different tab (Profile)
3. A confirm dialog appears with a message mentioning unsaved/draft
4. Dismiss the dialog
5. Verify the Profile tab did not load (the confirm was not skipped) and the Constitution draft is still there when you click back

This fix satisfies all five steps. The test is currently marked `xfail(strict=True)` because ISS-482 was unfixed. With this change, the test should transition from xfail to GREEN.

## Consequence for the e2e suite

Like FIX-385, this fix adds a dialog that the `dismiss_native_dialogs` autouse fixture dismisses in other tests. Any test that switches tabs away from Constitution will now hit and dismiss the confirm. Today, no such paths exist in the test suite except the one this fix targets, so there is no cascade. If such a path is added later, that test will need to either accept() the dialog or start in a non-Constitution tab.
