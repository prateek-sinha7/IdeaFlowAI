## What happened

Sibling of [ISS-199](20260828-1600-ISS-199.md) (root card for
BUG-20260828-012900-runs-id-files), derived while tracing that card's blast
radius: `FilesTab` has a SECOND, independent render call site beyond the main
run screen's `PreviewPanel.tsx:1280` — the Run History browser's own detail
panel, `frontend/src/components/history/WorkflowHistory.tsx:904-919`.

This caller derives its own local `isPpt` flag instead of sharing
`PreviewPanel.tsx`'s `renderType`:

```
WorkflowHistory.tsx:531: const workflowType = selectedRun.type as WorkflowType;  // RAW, unnormalized
WorkflowHistory.tsx:542: const isPpt = workflowType === "ppt" || workflowType === "ppt_revision";
```

`PreviewPanel.tsx:578` explicitly normalizes `ppt_v2` into the `ppt` slot
(`detectedType === "ppt_v2" ? "ppt"`, comment: "spec 017 — ppt_v2 renders the
same HTML deck as ppt"). `WorkflowHistory.tsx`'s `isPpt` never gained the same
normalization, so for a `ppt_v2` run `isPpt` is `false`. That cascades:

- `pptContent={isPpt ? selectedOutput || undefined : undefined}`
  (`WorkflowHistory.tsx:907`) is `undefined` — never populated.
- `isGeneric = !isUserStory && !isAppBuilder && !isPpt && !isPrototype`
  (`WorkflowHistory.tsx:555`) is `true` for `ppt_v2`.
- `genericDeliverable={isGeneric && selectedOutput ? { mimetype:
  genericMimetype, filename: undefined, content: selectedOutput } :
  undefined}` (`WorkflowHistory.tsx:909-913`) hardcodes `filename: undefined`
  even though `selectedRun.deliverableFilename` ("presentation.html" per
  [ADR-0029](20260827-0054-ADR-0029.md)) is available on the same
  `selectedRun` object used elsewhere in this function.
- Inside `FilesTab`, `deriveDeliverableFiles("ppt_v2", {...})` matches none of
  its branches — all require the literal `"ppt"` / `"ppt_revision"` strings
  (`FilesTab.tsx:392`) — so `files` stays `[]`; the generic-deliverable
  fallback then fires (`FilesTab.tsx:555`, gated on `files.length === 0`) and
  pushes one row named `deliverable.<ext>` (from `genericDeliverableExtension`,
  never `presentation.html`) built from `selectedOutput` — the same
  unreconciled content ISS-199 already distrusts.

## Root cause

Same architectural gap as ISS-199 — nothing in the Files-tab content-selection
path reconciles Final output against the run's declared `deliverable_filename`
/ workspace listing — reached through a SECOND, independently-maintained
type-check (`WorkflowHistory.tsx`'s own `isPpt`/`isGeneric`, not shared with
`page.tsx` / `PreviewPanel.tsx`) that has additionally drifted out of sync
with its sibling's `ppt_v2` normalization.

## Expected vs actual

- **Expected:** the History browser's Files tab for a completed `ppt_v2` run
  shows the same Final output as the main run screen (once ISS-199 is fixed:
  the declared `presentation.html`).
- **Actual (INFERRED — traced via code, not yet click-verified in the
  browser):** `isPpt` false for `ppt_v2` routes the run into the
  generic-deliverable branch, producing a `deliverable.<ext>` row instead of
  even an incorrectly-named "presentation" one — built from the same
  unreconciled `selectedOutput`, likely with a DIFFERENT wrong
  filename/size than the main run screen shows for the identical run.

## Why the root cause implies this

ISS-199's root cause is "FilesTab and its content-selection callers never
reconcile Final output against the run's declared deliverable."
`WorkflowHistory.tsx` is a second, independent implementation of that same
selection logic, so the same class of defect recurs there by construction —
and because its `ppt_v2` handling has already drifted further out of sync
(missing the normalization `PreviewPanel.tsx` has), the manifestation is
worse, not merely duplicated: a run that at least gets mislabeled as a
presentation on the main screen gets no presentation label at all here.

## What would confirm it

Open the History sidebar, select the same `ppt_v2` run
(`b9feac1c-ec21-4531-8ba7-bb391786993e`), open its detail panel's Files tab,
and compare the "Final output" row's filename/size/content against both
`presentation.html` and what the main run screen (`/runs/<id>/files`) shows
for the identical run.
