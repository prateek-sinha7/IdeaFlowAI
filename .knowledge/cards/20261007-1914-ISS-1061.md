## Analysis (QA-KB-097, 2026-10-08)

Analyzed by the 3-analyzer. **The four tests are red for three independent reasons, and none of them is the resume engine mis-resuming on a path a user reaches.** The one real product defect on the report, the `ScopedStore._acquire` AttributeError, is not why any of the four fails. Observed on HEAD `5e22d3238`, `cd backend && .venv/bin/python -m pytest <node ids> -q`, one file at a time, in-memory SQLite. The experiments are pytest plugins (`evidence/qa-kb-097/analysis-plugins/`) and `git archive` exports run in a scratch dir; the repo was not touched. Output files: `evidence/qa-kb-097/analysis-*.txt`.

What the report's four symptoms mean (all CONFIRMED by reading plus experiment):

- "a wave worker is skipped" and "a failed run can't resume": not reachable through `POST /api/runs/{id}/resume`. The endpoint clears the state machine entry (`run_commands.py:745`, step 6b, FIX-105) and a restart starts empty. They reproduce only where the harness resumes in the process that ran instance A. With the entry cleared the three tests pass: wave-1 workers `c` and `d` run, all four files appear, the status reconciles to `completed` (`analysis-02-sm-evict-4-tests.txt`).
- "clarification answers are dropped": not dropped. A resumed run rebuilds `PLANNER.md` from the rehydrated context and the file contains the answer (`analysis-11-planner-md-on-resume.txt`); only the old inline paste is gone, deliberately (Phase Z, `engine.py:16578-16582`).
- "`ScopedStore._acquire` AttributeError": real, two methods, silent loss of audit data ( [ISS-1099](20261008-0016-ISS-1099.md), [ISS-1100](20261008-0016-ISS-1100.md) ). The raise is `authz.py:1548` and `:1266`, swallowed at `kernel_services.py:753` and `:527`.
