## Summary

INFERRED sibling of the QA-PS-023 root card, [ISS-700](20260922-1230-ISS-700.md). ISS-700
found that the `streamed_text` resolver's `unwrap_artifact` only strips a literal
`<artifact>…</artifact>` wrapper, so reasoning prose the model emits before its HTML (with
no wrapper) passes through unchanged and renders inside the Preview iframe before the
deliverable. ISS-700 explicitly checked and ruled out `single_file`/prototype ("reads clean
HTML off the sandbox file and is unaffected") but never checked the `ppt` strategy — this
card fills that gap.

## Root cause (code-traced across every hop; not yet exercised live)

- `backend/agents/capabilities/deliverables/ppt.py:74-78` — `PptResolver.resolve()` ends in
  `unwrap_artifact(strip_pre_slide_body_text(sanitize_carousel_deck_html(strip_code_fence(last_streamed))))`.
  `strip_pre_slide_body_text` (`_artifact.py:79-181`) only removes content between the
  `<body...>` tag and the first slide anchor (`body_end = body_tag_match.end()`,
  `after_body = html[body_end:]`) — it never inspects anything before `<!DOCTYPE html>` /
  `<head>`. `unwrap_artifact` (`_artifact.py:19-38`) only strips a literal `<artifact>`
  wrapper. Neither transform touches free-form prose that precedes the whole document with
  no wrapper — the identical gap ISS-700 found in `streamed_text`.
- `backend/agents/workflows/ppt/workflow.yaml:42-43` — the base `ppt` workflow (not `ppt_v2`)
  declares `deliverable: {strategy: ppt, name: presentation.pptx}`.
- `backend/agents/capabilities/deliverables/_mimetype.py:33` —
  `_STRATEGY_MIMETYPES["ppt"] = "text/html"`: mimetype is forced to `text/html` regardless of
  the declared `.pptx` name.
- `frontend/src/components/preview/PreviewPanel.tsx:217-222` — `GenericDeliverablePreview`
  routes `text/html` content to the styled `PPTPreview` ONLY
  `if (deliverable.filename === "presentation.html")`. Base `ppt`'s filename is
  `presentation.pptx`, so it falls through to the plain
  `<iframe srcDoc={withDarkIframeDefault(content, ...)}>` branch (`PreviewPanel.tsx:223-256`)
  — the SAME unguarded render path ISS-700 found for `streamed_text`, and NOT `PPTPreview`,
  whose own DOCTYPE-slice (`PPTPreview.tsx:151-179`, with an explicit comment about exactly
  this class of leak) is the only frontend safeguard against unstripped preamble text.
- `ppt_v2` (`backend/agents/workflows/ppt_v2/workflow.yaml:52-53`,
  `deliverable: {strategy: single_file, name: presentation.html}`) is NOT affected: it reads
  a file the agent actually wrote via `write_file` (not raw streamed text), and its filename
  routes to the guarded `PPTPreview`.

## Trigger

`deliverable.strategy == "ppt"` (the base, non-v2 workflow only — confirmed still live:
`backend/agents/workflows/ppt/workflow.yaml` comments say "Base `ppt` deliberately untouched
(pinned by `test_ppt_v2_manifest.py::test_ppt_is_byte_identical_to_its_own_manifest`)") AND
the final agent's (`ppt-validator`) streamed output contains narrative text before its HTML
with no `<artifact>` wrapper — the same model-behavior trigger ISS-700 documents.

## Status

INFERRED. The chain is confirmed by direct read at every hop (resolver, manifest, mimetype
default, frontend route, `PPTPreview`'s filename-scoped guard), matching ISS-700's own
confidence bar, but no live or resolver-level (`PptResolver` fed a prose+HTML string, mirroring
ISS-700's `StreamedTextResolver` repro) reproduction has been run yet. That direct-resolver
repro is what would confirm it.

## Fix direction (not applied — issue only)

Same fix location as ISS-700: harden the shared `unwrap_artifact` (or add a sibling helper) in
`backend/agents/capabilities/deliverables/_artifact.py` to slice to the first
`<!DOCTYPE`/`<html` occurrence (or treat unwrapped-but-HTML-shaped output as a producer error)
so both `streamed_text.py` and `ppt.py` inherit the fix from the one shared module — no
per-caller patch, and no new PreviewPanel-side guard needed.
