## Why this is worse than a stuck button

The canvas is the only place the composition exists before it is saved. An
author who adds a wrong agent has no way back except reloading, which discards
every other thing configured on the canvas alongside it. The cost of the defect
scales with how much work preceded the mistake.

## The invisible-disabled compounding

`disabled:opacity-0` was presumably chosen so a locked control does not clutter
a canvas full of core steps. The effect on this path is that there is nothing
on screen to explain why removal does not work — the `title` attribute is
attached to an element with zero opacity, so the hover that would reveal it
never happens. Greying the control instead would at least make the lock legible
while the underlying source-of-truth bug is fixed.
