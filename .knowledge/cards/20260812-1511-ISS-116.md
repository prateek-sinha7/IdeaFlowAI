# ISS-116

## Title

**The governance-checks verdict badge is DEAD CODE, not merely un-versioned.** `checksPassed` requires `validationPassed === true` (`AgentDetailPanel.tsx:145`), which only `case "gate_passed"` sets (`useWorkflow.ts:1078`). **`gate_passed` has ZERO producers in the entire backend — including tests.** The GATE_PASS path calls `write_gate_event` (`agents/capabilities/gates/write.py:20-30`), which writes a `gate_events` DB row and returns `GateOutcome(outcome=GATE_PASS)` carrying **no `events=[]` list**, so nothing reaches the wire; there is no dynamic `f"gate_{...}"` construction either. `validator_result` likewise has ZERO producers (one docstring mention, `app/api/capabilities.py:37`), so `checksIssueCount` is always 0. **Net effect: the green "Passed" chip can never render and the amber chip always reads "Review"** — a constant string on every analysis agent of every run. Only `gate_blocked` is real (3 producers: `gates/validation.py:133`, `gates/security.py:108`/`:174`), and `run_events` holds **0 rows** of any of the three across 232,023 events. Decide whether to wire a `gate_passed` emission or delete the branch; do NOT version-thread a field nothing populates.
