## What was wrong

The IDE file explorer's "Search files" box filtered leaf files only. Four consequences,
one omission behind all of them — `searchQuery` was read in exactly one place in the
component, the leaf branch of `FileTreeNode`:

- [ISS-332](20260828-2041-ISS-332.md) — a folder with zero matching descendants stayed
  visible and expandable, and expanded to literally nothing.
- [ISS-332](20260828-2041-ISS-332.md) — the sidebar footer read the raw `files` prop, so
  "4 files · 0.1 KB total" contradicted a list filtered down to one row.
- [ISS-501](20260829-0006-ISS-501.md) — folder *expansion* was equally independent of the
  query, so a match inside a collapsed non-top-level folder rendered nothing and read as
  "no results".
- [ISS-502](20260829-0006-ISS-502.md) — at the zero-match boundary the whole tree stayed
  on screen as dead folders, with no empty state anywhere in the component.

## Root cause

`frontend/src/components/preview/AppBuilderPreview.tsx`:

- `FileTreeNode`'s folder branch (pre-fix line 169) returned unconditionally. The only
  match gate lived in the leaf branch beneath it (pre-fix lines 202-203):
  `const matchesSearch = !searchQuery || node.name...; if (!matchesSearch) return null;`
  A folder never consulted `searchQuery`, so nothing pruned it.
- `isExpanded` (pre-fix line 173) came solely from `expandedPaths`, which is written only
  by the mount effect (top-level segments — lines 346-358), manual `onToggle`, and
  Expand/Collapse all. No code path let a search open a folder, and a collapsed folder
  never renders its children (line 185), so its descendants never reached the leaf gate.
- The footer (pre-fix line 556) computed `{files.length} files · {files.reduce(...)}` from
  the unfiltered prop, with no `searchQuery` dependency at all.
- The tree region (pre-fix lines 538-551) mapped `tree` unconditionally — no branch for
  "nothing visible".

## What changed and why there

One file. All four mount points of this component — `app/preview-fullscreen/page.tsx:118`,
`components/preview/PreviewPanel.tsx:167` (inside `AppBuilderIDEPreview`), and
`components/history/WorkflowHistory.tsx:842` / `:881` (the `isAppBuilder` and
`isGenericBundle` branches of the reopen modal) — render the identical component with no
prop that varies the search behaviour, so the guard belongs here and nowhere else. That is
[ISS-500](20260829-0006-ISS-500.md) in full: there is no per-caller variant to patch.
Re-grepped at fix time (`grep -rn "AppBuilderPreview" frontend/src`): still exactly those
four; `results/FilesTab.tsx` and `results/SandboxTab.tsx` only mention it in comments.
`FileTreeNode` and the `aria-label="Search files"` input exist in this file alone.

1. Two module-level helpers next to `buildTree`: `fileMatchesQuery(name, query)` (the leaf
   predicate, lifted verbatim) and `hasMatchingDescendant(node, query)` (recursive; a file
   answers with `fileMatchesQuery`, a folder with `.some()` over its children). One
   definition of "matches" for folders and files — two would drift apart again.
2. Folder branch: `if (!hasMatchingDescendant(node, searchQuery)) return null;`. With an
   empty query `fileMatchesQuery` is `true`, so an unsearched tree is unchanged — except
   for a folder holding no files at all, which `buildTree` cannot produce (folders are
   only created along a file's path).
3. `isExpanded = expandedPaths.has(node.path) || !!searchQuery` — a search opens every
   surviving folder in render only. Deliberately NOT a `useEffect` writing `expandedPaths`:
   this leaves the user's own expand/collapse state intact underneath, so clearing the box
   restores exactly the tree they had. Fixes ISS-501 in one term.
4. `visibleFiles` memo (`searchQuery ? files.filter(...) : files`) now feeds the footer's
   count and KB sum, and gates a `No files match your search` empty state that replaces
   the tree when a query matches nothing (ISS-502). With no query the memo is the `files`
   identity, so the unsearched footer is byte-identical to before.

with only that one query disambiguated to `getAllByText`, the file passes. The test was left
untouched — an assertion is not edited because it is red.
