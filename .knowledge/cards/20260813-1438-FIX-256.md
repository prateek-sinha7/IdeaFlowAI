## Description

The FIX-201 legacy→store bridge could resurrect a stood-down run, and dev shipped a second never-called mechanism beside it. Closes ISS-138 (open since 2026-08-12) and ISS-157.

## Root cause

The bridge ran updatePipelineState(runId, () => snapshot) — a WHOLESALE replace. activelyBuildingRunIdRef is only ever assigned, never cleared, and reopening a run from history assigns it (page.tsx:2226), so a TERMINAL run reaches the bridge while the legacy container still carries isRunning:true from a terminal-less replay. Live evidence (quick-260812-wir): the store flipped back to isRunning:true ~4s after being set false with no handleFrame involved; it cost a real false-green during FIX-245. dev's FIX-220 rAF-coalesced the loop but left the replace intact, and added syncPipelineStateOnly — never called, and justified by a FALSE premise ("handleFrame projects on every SSE frame"; it returns early before any projection on waveIndex === undefined and on !pipelineFrameTypes.includes(msg.type)).
