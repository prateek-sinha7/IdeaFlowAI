## What was wrong

Taken from the root card, not re-derived. The owner kept the expiry-only, no-network launch preflight (2026-10-09,
option a), so a key that decodes as unexpired but that Bedrock has revoked is accepted at launch and rejected at the first
model call. The runner turns that rejection into `str(exc)` (`deep_agent_runner.py:1415-1416`), and the engine maps it to
the user's sentence through `_sanitize_agent_error`, which walks `_AGENT_ERROR_CATEGORIES` with the first match winning.
That table had no row for "the API key itself is bad":

- `An error occurred (AccessDeniedException|AccessDenied) ... API Key invalid` matched the broad credential row through
  its `"accessdenied"` needle and returned `_CREDENTIAL_AGENT_ERROR`, which blames "the run's cloud session" and never says
  API key, invalid, revoked or rotate (persisted on runs `eb1d7551` and `95cb5ace`).
- `An error occurred (403) ... API Key invalid` (botocore takes the code from the HTTP status when the response has no
  error-type header) matched nothing and returned the generic "The model rejected this request."

FIX-657's run-stop compared the step's error to `_CREDENTIAL_AGENT_ERROR` by equality and stamped that constant on the
`pipeline_failed`, so any new message for this case would also have let the run continue to every later step against the
same dead key.

## What changed, and where

All in `backend/agents/execution_engine/engine.py`, the one funnel every agent step, fan-out worker, resume and persisted
`workflow_runs.error` reads from:

- **`:200-207`**: a new literal `_INVALID_KEY_AGENT_ERROR`: "The model could not be reached — the provider rejected its
  API key (invalid, revoked or expired). Rotate the key (Bedrock: AWS_BEARER_TOKEN_BEDROCK) and restart the backend."
  The copy is the root card's suggestion, which mirrors the preflight's own remedy (`model_factory.py:166-169`, "rotate
  AWS_BEARER_TOKEN_BEDROCK and restart the backend"). The restart is accurate: the key is read from `settings` at
  startup (`model_factory.py:142`, `:470-473`). It is 173 characters, under the 400-character cut in `fanout.py:604-606`,
  and does not match the frontend's security-gate regex (`StepsOverviewSpine.tsx:364`).
- **`:215-219`**: `_CREDENTIAL_AGENT_ERRORS = frozenset({_CREDENTIAL_AGENT_ERROR, _INVALID_KEY_AGENT_ERROR})`, the set
  of messages that stop the run.
- **`:239-242`**: a new row `("api key invalid", "invalid api key", "api key is invalid") -> _INVALID_KEY_AGENT_ERROR`,
  placed directly above the credential row. It matches on the message text, not the error code, so it holds for all
  three wire shapes (AccessDeniedException, AccessDenied, bare 403).
- **`:6550`, `:6558-6560`, `:6605`** (FIX-657 run-stop): equality became membership in `_CREDENTIAL_AGENT_ERRORS`, the
  matching event's own message is kept in `_credential_error`, and the `pipeline_failed` carries it instead of the
  hardcoded constant. For the existing credential message this is byte-identical (same string).

Left alone on purpose: `preflight_check_provider` (owner decision), `TRANSIENT_AGENT_ERRORS` (the new copy is not
retryable, so a fan-out worker carrying it fails at once), `_CREDENTIAL_AGENT_ERROR`'s text and mapping (pinned by
`test_credential_failure_stops_run.py:60` and `test_image_payload_guard.py:213`). No import was added, and no
`pipeline_type ==` or `spec.id ==` branch. The needles are generic vocabulary. The env-var name appears only in the copy;
the engine already reads `BEDROCK_*` settings, and the only kernel source guard bans name branches, not literals.

Safety of the membership test: `x in frozenset` hashes `x`, where `==` did not. Every `agent_error` that reaches this
loop carries a `str` error (`str(exc)`, f-strings or literals at `engine.py:6541`, `:7391`, `:10585`, `:10638`,
`:11149`, `:11182`, `:14397`, `assemble_step.py:904`, `backlog_assemble.py:2029`, `publish_step.py:147`). The NDJSON
adapter consumes engine output and does not feed this loop.

**Not done here** (siblings stay `open`, none has a test, all are INFERRED):

- [ISS-1202](20261012-0944-ISS-1202.md): a rejected `ANTHROPIC_API_KEY` (`authentication_error`, `invalid x-api-key`)
  still gets the generic message (probe: GENERIC). The card makes widening beyond Bedrock the owner's call, and the owner
  decision was scoped to Bedrock. If wanted, it is two needles on the row added here, plus a copy that does not name a
  Bedrock env var.
- [ISS-1200](20261012-0944-ISS-1200.md): the planner and clarify calls swallow the rejection before the first agent step.
- [ISS-1201](20261012-0944-ISS-1201.md): the run-lane concierge echoes the raw exception text.
- The root card's test notes asked for `test_fanout.py:1018-1025` to be extended with the new copy. The test stage did
  not do it, and the fixer does not edit tests. Parity is shown by the probe (`fix-02-probe.txt`): not transient, under 400
  characters, so `fanout.py:610` fails the worker at once.

model call. If one is available: launch any workflow, then read the first step's `agent_error` and the run's
`pipeline_failed`. Both should carry the new copy, the run should have exactly one `agent_start`, and
`workflow_runs.error` should equal the copy. The server log line at `engine.py` (`runner surfaced an error event ...
raw=...`) settles the root card's INFERRED wire shape.
