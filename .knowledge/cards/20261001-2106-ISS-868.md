# ISS-868

**Evidence status.** CONFIRMED: read at `backend/agents/artifact_store/store.py:192-220` and reproduced by an in-process probe (2026-10-01). This is an **incidental finding, NOT a sibling of ISS-128**. It surfaced while checking whether the mislabelled ISS-128 record is evicted at run end. It has a different root cause and a different fix, it is out of scope for the QA-KB-006 fix, and it must not be folded into it.

## What is wrong

[FIX-152](20260730-1825-FIX-152.md) D4 states the problem as "three module-global dicts (`_resume_events`, `_questionnaire_responses`, `_questionnaire_force_proceed`) ... had no eviction path", and its Files table says `forget_run` "pops all three dicts and all `review:{run_id}*` event keys". The implementation (`store.py:192-220`) pops:

- `_questionnaire_responses[run_id]`, the clarify answers keyed by the bare run id;
- `_questionnaire_force_proceed[run_id]`;
- `_resume_events[run_id]` and, in the `stale_keys` loop (`:213-219`), every `_resume_events` key equal to `review:{run_id}` or starting with `review:{run_id}:`.

The `stale_keys` comprehension iterates `self._resume_events` only. The review RESPONSES live in `_questionnaire_responses` under the same `review:{gate_key}` key (`store.py:155-157`) and are never popped.

## Probe

    s = ArtifactStore(); await s.set_review_response("run-x:agent-a:0", approved=False)
    s.forget_run("run-x")
    before: response [{'approved': False, 'edited_content': None, 'action': 'approve', 'instructions': None}]   events ['review:run-x:agent-a:0']
    after:  response [{'approved': False, 'edited_content': None, 'action': 'approve', 'instructions': None}]   events []

## Impact

Memory only: one small dict per gate resolution for the lifetime of the process. Not a correctness hazard today, because the sole reader (`backend/agents/execution_engine/engine.py:12457`) runs only after `set_review_response` has overwritten the slot and set the event, and `_run_review_gate` re-arms with `event.clear()` (`engine.py:12376`), so a stale entry is never consumed. It does keep a mislabelled ISS-128 record alive after its run ends. `ArtifactStore.forget_run` has no unit test (`grep -rn forget_run backend/tests` finds only the StateMachine's, `test_restart_resume_db.py:5349`), which is how the gap shipped.

## Fix

In `ArtifactStore.forget_run`, also drop the matching keys from `_questionnaire_responses`, using the same predicate (`k == f"review:{run_id}" or k.startswith(f"review:{run_id}:")`) over `list(self._questionnaire_responses)`. The only caller is `run_engine.py:136` (`_cleanup_pipeline`), so no other path is affected.

## Test notes

A new unit test beside `backend/tests/unit/app/test_artifact_store.py`: `set_review_response("run-1:a:0", ...)`, `forget_run("run-1")`, assert `get_review_response("run-1:a:0") is None`, and that a different run's key survives.

## Analysis (3-analyzer, 2026-10-02, QA-KB-068)

Anchors below are from the working tree of `feat/user-stories-v2` @ `024c03ef`. `store.py`, `engine.py` and
`run_engine.py` carry uncommitted edits (store.py's is [FIX-687](20261001-2130-FIX-687.md)'s
`set_review_response` change), which moved every anchor quoted above: `forget_run` is now `store.py:198-226`
(was `:192-220`), the review write is `:162-163` (was `:155-157`), the engine reader is `engine.py:12481` (was
`:12457`) and its re-arm is `:12400` (was `:12376`). The fix phase must re-anchor; it will shift again.

**ROOT CAUSE (CONFIRMED, read and re-probed).** Two registries share the `review:` key space and the eviction
covers one of them.

- Writer: `store.py:162-163`, `key = f"review:{gate_key}"` then `self._questionnaire_responses[key] = [...]`.
  Its event is `_resume_events[key]` (`:133-135`).
- Evictor: `store.py:211` pops `_questionnaire_responses` by the bare `run_id` only. The review scan at
  `:218-225` iterates `self._resume_events` and nothing else.
- Probe on the current tree: four `set_review_response` calls (`run-x:agent-a:0`, `run-x:agent-b:2`,
  `run-xy:agent-a:0`, `run-y:agent-a:0`), one `set_questionnaire_responses("run-x", ..., skip_clarification=True)`,
  then `forget_run("run-x")`:

      AFTER responses     : ['review:run-x:agent-a:0', 'review:run-x:agent-b:2', 'review:run-xy:agent-a:0', 'review:run-y:agent-a:0']
      AFTER events        : ['review:run-xy:agent-a:0', 'review:run-y:agent-a:0']
      AFTER force_proceed : []
      get_review_response('run-x:agent-a:0') -> {'approved': False, 'edited_content': None, 'action': 'reject', 'instructions': None}

  The bare clarify slot, the force-proceed flag and every review EVENT go; every review RESPONSE stays. The
  lookalike runs `run-xy` and `run-y` are untouched by the event scan, so the colon-terminated prefix is the
  right predicate to reuse.

**BLAST RADIUS (CONFIRMED by grep, every consumer).** `store.py` is 244 lines and holds exactly three dicts, so
the whole eviction contract is this matrix and one cell is missing:

| registry | bare `run_id` key (clarify) | `review:{run_id}:...` key (gate) |
|---|---|---|
| `_resume_events` | popped `:214` | popped `:218-225` |
| `_questionnaire_responses` | popped `:211` | NOT popped (this bug) |
| `_questionnaire_force_proceed` | popped `:212` | never written |

- Writers of the leaking slot: `set_review_response`, reached from three ingresses: `resolve_gate`
  (`run_commands.py:308`, `:319`, `:326`, `:331`), the Concierge `gate_action` disposal (`:1599`, `:1606`, `:1613`,
  `:1615`) and `post_message`'s gate channel (`:1947`, `:1955`, `:1962`, `:1964`).
- One key shape: `engine.py:12396`, `gate_key = f"{pipeline_run_id}:{agent_id}:{visit_count}"`, is the only
  construction in production, and every gate kind (inline, declared `human`/`approval` through `run_human_gate`,
  fan-out `human_gate`, the `update_specs` re-open) goes through `_run_review_gate`. One prefix covers all of them.
- Only reader: `get_review_response`, called at `engine.py:12481`.
- Only caller of `ArtifactStore.forget_run`: `run_engine.py:136` in `_cleanup_pipeline`. That function is reached
  from `run_commands.py:4464` (launch driver `finally`), `:5888` (revision driver `finally`), `run_engine.py:211`
  (`_is_run_live` self-heal of a `done()` task) and, through the hook injected at `main.py:161`, from 14
  `engine._fire_resume_cleanup` sites (`engine.py:12986`, `:15552`, `:15630`, `:15679`, `:15693`, `:15702`,
  `:16018`, `:16080`, `:16132`, `:16150`, `:16164`, `:16172`, `:16189`, `:16208`). I read all 17: each runs after
  the run's driver ended, or before one started, never while a gate waiter is parked.
- Tests that read `_questionnaire_responses["review:..."]` (`test_rest_gate_commands_api.py:160`,
  `test_chat_messages_endpoint_api.py:379,400,422`, `test_update_specs_ingress_fence_api.py:182`,
  `test_attach_replay_matrix_api.py:650`) read it straight after the ingress and before any cleanup, so the fix
  does not break them.

**Impact refinement (CONFIRMED, one number INFERRED).** "One small dict per gate resolution" understates what is
retained. `set_review_response` stores the caller's `edited_content` and `instructions` verbatim (`store.py:163-170`)
and `GateCommand` bounds neither (`run_commands.py:139-141`: `edited_content: str | None`, `instructions: str | None`,
`analysis_report: str | None`). What outlives the run is the user's edited spec/plan text and any `update_specs`
analysis report, one slot per `(run, agent, visit)` (a redo overwrites its slot), until process exit. INFERRED:
the typical size, which depends on how long users' edited deliverables are. Still memory only, still never consumed
(next paragraph); the only read is the engine's, by exact key. Severity stays Low.

**Why a stale entry is inert (CONFIRMED, agrees with the card).** `_run_review_gate` re-arms with `event.clear()`
(`engine.py:12400`) before emitting, reads only after `await event.wait()` (`:12479-12481`), and
`set_review_response` writes the response before `event.set()` (`store.py:163`, `:171-172`). The only code that sets
a review event is `set_review_response`: `get_review_event` has two production callers (`engine.py:12399`,
`:12725`) and both only `clear()`.

**Evicting at run end is sufficient (CONFIRMED).** All three ingresses require an armed event before they write
(`resolve_gate` `run_commands.py:296`, Concierge `:1581`, `post_message` `:1904`, each through
`review_event_pending`), and run-end eviction removes that event, so a late click gets 404 `gate_not_pending`
and cannot re-create a review entry.

**FIX PLACEMENT.** Inside `ArtifactStore.forget_run`, the one function every run-end path reaches (INV-12 as
FIX-152 applied it: one `forget_run` per class, called from the one `_cleanup_pipeline`). Smallest diff, one
predicate over both registries instead of a second copy of the comprehension (verified in a scratch subclass:
other runs and the `run-xy` lookalike survive, a second call and a never-seen id are no-ops):

    review_key = f"review:{run_id}"
    review_prefix = f"{review_key}:"
    for registry in (self._resume_events, self._questionnaire_responses):
        for k in [k for k in registry if k == review_key or k.startswith(review_prefix)]:
            registry.pop(k, None)

Constraints, each one a way to break something with a plausible-looking fix:

1. **Run end only.** `engine.py:12482-12485` defaults an absent response to approval: `approved =
   response.get("approved", True) if response else True`, `action ... else "approve"`. Today an absent response
   cannot reach it, because nothing removes a slot while a waiter is parked. Consume-on-read in
   `get_review_response`, a pop in an ingress, or any per-gate eviction would turn a rejection into an approval
   (the fail-open that [ISS-053](20260811-2101-ISS-053.md), [ISS-070](20260812-0107-ISS-070.md) and
   [ISS-090](20260812-0632-ISS-090.md) close elsewhere). `forget_run` is safe only because of the 17-site audit above.
2. **Stay inside `ArtifactStore`.** Do not reach into `_questionnaire_responses` from the app layer; IN-02 removed
   exactly that private-dict peek (`run_commands.py:174-177`).
3. **Iterate over a copy.** The loop pops from the dict it scans, and `_cleanup_pipeline` discards every exception
   from `forget_run` with a bare `pass` (`run_engine.py:137-138`), so a `RuntimeError: dictionary changed size
   during iteration` would be invisible. See [ISS-1003](20261002-0516-ISS-1003.md).
4. **Fix the docstring** (`store.py:199-206`), which says the eviction keeps "the three singleton dicts" bounded.
