# ISS-933

## Title

**INFERRED sibling of [ISS-154](20260813-0819-ISS-154.md): a pinned read-only version's own failed / cancelled / degraded / diverted status never reaches `PreviewPanel`'s terminal affordance, so the pinned view of a run that ended badly looks like an empty settled run.**

## Provenance (read this first)

Derived by the analyzer from the root cause of [ISS-154](20260813-0819-ISS-154.md) while analysing QA-KB-044; nobody reported it.

- CONFIRMED (code read, plus a component probe on the unpatched source, `evidence/qa-kb-044/05-analyze-path-probes-unpatched.txt` probe B3): the terminal-state signals are keyed on the shell's props, and the pinned run's status is dropped.
- INFERRED (not executed): the render in a real browser on the live rows below, and the lane/tab consequences of the fix.
- What settles the INFERRED part: sign in as `admin@velocity.ai`, open `/runs/87e02c32-96a9-4e50-8ed0-79023d83540f/versions/4` (v4, `failed`, `output` NULL) and `/versions/3` (v3, `cancelled`, `output` NULL), then open the same runs directly (`/runs/97b49f98-83bd-4ed6-8631-600bf9653905`, `/runs/4eb1a2ea-b4be-400a-b53c-b63597cc52a0`). Predicted: direct open shows the failure/cancel treatment; the pinned view shows an empty Preview under the read-only banner and nothing that says the run failed or was cancelled.

## Condition

A family member that ended `failed`, `cancelled`, `degraded` or `diverted` with no stored output is opened as a PINNED version: the `/runs/{root}/versions/{n}` URL (the pin effect, `PreviewPanel.tsx:999-1025`) or a chat result card (`handleSelectVersion`, `:1264-1270`). Such a member usually has `git_tag = NULL` (finalize tags best-effort, [ISS-697](20260922-1000-ISS-697.md)), so it is not in the Version menu and the pin URL is the only way to it. Live rows: family `87e02c32-96a9-4e50-8ed0-79023d83540f` v3 `4eb1a2ea-...` (cancelled) and v4 `97b49f98-...` (failed), both `git_tag` NULL, both older than the completed v5/v6; family `78e185fb-c032-4154-8552-774781b6e5df` v6 `0924fe8a-...` (cancelled).

## Expected vs actual

- Expected: the treatment the same run gets when opened directly: the "This run was cancelled" / "did not complete successfully" / "diverted" copy of `DegradedRunAffordance` (`PreviewPanel.tsx:687-766`). The file's own contract says so: a terminal run with no content shows a failure affordance keyed on the SERVER status, never the neutral copy (comment `:1111-1119`, [ISS-017](20260613-1437-ISS-017.md); the diverted carve-out is [ISS-390](20260828-2048-ISS-390.md)).
- Actual (CONFIRMED on the unpatched source, probe B3): the neutral "Output will appear here" and no affordance copy. After the [ISS-154](20260813-0819-ISS-154.md) fix the line reads "No deliverable was saved for this version": true, but it still does not say the run failed or was cancelled, while the Steps tab of the same pinned view does show `failed` for a failed member (`versionViewFrom` sets `pipelineState.failed`, `:655`, passed through `effPipelineState`, `:1930`, and read at `StepsOverviewSpine.tsx:421-423`).

## Why the root cause (ISS-154) implies it

[ISS-154](20260813-0819-ISS-154.md)'s root is that the pinned view carries no status of its own and every branch ahead of the placeholder is keyed on the shell: `liveFailureSignal` reads the raw `pipelineState` (`:1122`), `reopenFailureSignal` / `isCancelledTerminal` / `isDivertedTerminal` read `reopenedRunStatus` (`:1127-1130`, `:1137`, `:1143`), so `showFailureAffordance` (`:1132`) and `showDivertedAffordance` (`:1144`) are false for a pinned run whenever the shell run itself is healthy (the family root, completed). ISS-154's fix adds `VersionView.status` for the copy; this card is the other consumer of the same missing field.

## Fix (proposed, not applied)

Needs `VersionView.status` from [ISS-154](20260813-0819-ISS-154.md)'s fix. Then, inside the `!hasContent` branch only, choose the cancelled / diverted / failed `DegradedRunAffordance` copy from `viewingVersion.status`.

- Do NOT feed the pinned status into `reopenedRunStatus` / `terminalFailure`: `terminalFailureNoDeliverable` (`:1154`) drops the Preview tab and `defaultTabDiscriminator` (`:1250`) forces Audit for the WHOLE panel, wrong for an older version viewed under a healthy latest run.
- Pass `onRetry={undefined}` while `overrideActive`: the component's retry button is `onRevisePrototype || onRevisePpt || ...` (`:1796`), which revises the LIVE run, and revise actions are deliberately suppressed in the read-only view (`:1543-1544`).
- Product call at fix time: status-specific copy only (cheap) versus the full affordance block. Not escalated: either satisfies the file's contract.

## Test conditions

Same harness as [ISS-154](20260813-0819-ISS-154.md) (deep-link pin via the `pinnedVersion` prop, members without `git_tag`, full `@/lib/api` mock). Pinned `failed` / `cancelled` / `diverted` run with `output` NULL renders the matching affordance copy, no retry button, the Preview tab is still present, and the live content is untouched. Control: a pinned `completed` run with output is unchanged.

## Resolution (QA-KB-044, fixer, 2026-10-02)

Resolved by [FIX-709](20261002-0147-FIX-709.md). Inside the pinned-only branch that sits ahead of
the neutral copy, a pinned `failed`, `degraded`, `cancelled` or `diverted` version with no stored
output renders `DegradedRunAffordance`, with `cancelled`/`diverted` taken from `viewingVersion.status`.
The product call went to the full affordance block, without `onRetry` and without `failedAgents`.
The Preview tab stays. The shell signals (`reopenedRunStatus`, `terminalFailure`) are untouched, as
this card required.

`PreviewPanel.olderVersionNullOutput.test.tsx`: the four ISS-933 cases pass, and they fail against
the HEAD `024c03ef8` copy. The reverse direction, where the shell's own bad status outranks an empty
pin, is [ISS-952](20261002-0147-ISS-952.md) (open). The browser part of this card stays INFERRED until
the verifier opens `/runs/87e02c32-96a9-4e50-8ed0-79023d83540f/versions/3` and `/versions/4`.
