## Related

## Decision (commit 97717eb9f)

The OpenDesign injection (template SKILL.md, seed HTML, DESIGN.md, craft rules)
was reachable only by the built-in prototype and deck pipelines. A Composer
workflow can now declare `context_providers: [opendesign]` and choose a
template and design system at run time through a two-tab picker ("+ Attach
design" beside "+ Attach file" in Canvas and Simple).

- `opendesign` gains `user_allowed=True`; the other four providers stay
  trusted-only, so ADR-0027's trust wall is narrowed by exactly one provider.
- `resolve_launch_od_context` takes the declared providers and no-ops when
  opendesign is absent.
- A composed workflow has no static pipeline identity, so the loader family is
  derived from the picked template's `mode`, gated on `custom`.
- `design_mode` (web/deck) is stored on the manifest for the picker only.

## Consequences

The backend cannot detect "opendesign declared but nothing picked" in the
Case 3 launch path (agents is None, so `missing_template_context` is skipped);
the frontend blocks the run and opens the picker instead (backend gap left open, not carded).
