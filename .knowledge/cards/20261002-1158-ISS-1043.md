# ISS-1043

Noted, and left unfiled, by the analysis behind [ISS-965](20261002-0319-ISS-965.md) ("Unrelated and not filed"). It is
filed here by [FIX-713](20261002-1158-FIX-713.md) so it does not live only inside another card's body. Read in source;
not driven in the browser.

## What is wrong

Spec 019 raised the root-agent cap for a composition from 8 to 16: `export const MAX_OPTIONAL = 16;`
(`frontend/src/components/workflow/composer/treeLayout.ts:13`). The Canvas view's cap tooltips interpolate the constant:
`` `Maximum ${MAX_OPTIONAL} root agents are allowed` `` (`CanvasView.tsx:2472`, `:2523`).

The Simple view's tooltip on the same control is a literal (`ComposerPage.tsx:1616`, working tree 2026-10-02):

    Maximum 8 root agents are allowed

It renders only when `!canAddMore`, that is at 16 root agents. So an author who reaches the cap in the Simple view is
told the limit is 8, and the Canvas view says 16.

## Expected vs actual

- **Expected:** both views name the real cap, 16.
- **Actual:** the Simple view says 8.

## Where the fix belongs

`ComposerPage.tsx:1616`: interpolate `MAX_OPTIONAL` as CanvasView does. The constant is already imported
(`ComposerPage.tsx:12`) and already drives `canAddMore` (`:661`). Frontend only. Severity is low because the cap
logic itself is right, and only the copy is stale.

## For the test-writer

Render `ComposerPage` in the Simple view with 16 non-default root agents (`ComposerPage.bug025.test.tsx`'s ISS-965
case builds such a roster), then assert the tooltip reads "Maximum 16 root agents are allowed".
