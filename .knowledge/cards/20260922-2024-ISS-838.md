## Description

Found while fixing `QA-SG-014` ([FIX-623](20260922-2024-FIX-623.md)); deferred,
not fixed, because it belongs to a different mechanism and a different card's
file.

Two different bodies of bytes end up called "the deliverable":

* the **run record** — `pipeline_complete.final_output` +
  `deliverable_mimetype`, produced by the deliverable resolver
  (`engine.py:7191-7199`). This is what the Files tab and Preview render
  (`FilesTab.tsx:125-136` dispatches on the mimetype). FIX-623 fixed this one.
* the **sandbox file** — `_check_artifact_fallback` writes the agent's raw
  streamed text to the declared deliverable filename mid-run
  (`engine.py:8404`, `sandbox.write(filename, output or "")`), and
  `_write_chain_payload` copies that file verbatim into
  `.chain/{run_id}/<name>` (`engine.py:1090-1091`,
  `shutil.copy2(_src, full_chain_dir / Path(_deliv_name).name)`).

So a custom run with Output format = HTML now reports `text/html` and renders
real markup, while `.chain/{run_id}/output.html` on disk still holds the
unconverted markdown the fallback wrote — the exact bytes ISS-770's cycle-2
evidence inspected (run `e49b91e6-f2fe-479c-a941-75da2b53c05d`). Any consumer
that chains from `.chain/` rather than from the run record sees the old shape.

## What would confirm or refute it

A custom-workflow run with the composer's Output format set to HTML: compare
`GET /api/runs/<id>`'s `final_output` (expected: `<!DOCTYPE html>…`) against
the sandbox's `.chain/<run_id>/output.html` (expected, today: raw markdown).

## Notes

Not fixed in FIX-623 on purpose: the writer is `_check_artifact_fallback`,
which belongs to [ISS-721](20260922-1242-ISS-721.md) /
[FIX-612](20260922-1838-FIX-612.md), and it sits in
`backend/agents/execution_engine/engine.py` — outside the
`("deliverable", strategy)` capability layer that ISS-770 names as the fix
site, and a file another fix was concurrently applied to. Whoever picks this
up should decide whether the fallback writer should render the declared format
too, or whether `_write_chain_payload` should prefer the resolved
`final_output` over the sandbox file.
