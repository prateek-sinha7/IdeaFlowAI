## Related

## What was wrong

A deep agent (prototype-validate) took nine 1280x720 screenshots via
`playwright_take_screenshot`, then re-read each PNG. The image-payload guard
was designed to bound this: it cached images on read and evicted the oldest when
the cache exceeded its ceiling (keep=2). However, its placeholder text told the
model "re-read it if you need to look at it again". With three pages needed and
a cache of two, each new read evicted the oldest image, and the model's analysis
sent it straight back for the first one. Observed live: one reader cycled the
same three PNGs 122 times until the provider refused the request.

## The fix (commit 97717eb9f)

- The placeholder now states the image was already seen and must not be
  re-read, removing the prompt to revisit the same path.
- Repeat reads of one path collapse to a single retained block; the guard
  maintains one copy per unique path, never duplicates.
