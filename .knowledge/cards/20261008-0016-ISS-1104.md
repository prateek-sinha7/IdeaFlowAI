# ISS-1104

## Description

`backend/tests/integration/agents/test_restart_resume_db.py::test_resume_dispatch_carries_rehydrated_planning_context` (`:4928`) is red at `:5027`:

```
AssertionError: D2: a resumed dispatch must carry the user's clarification answers; got:
  === ORIGINAL USER REQUEST ===
  Run the wave workflow.
  === END REQUEST ===
assert 'SPINNAKER-SENTINEL' in '=== ORIGINAL USER REQUEST ===\nRun the wave workflow.\n=== END REQUEST ==='
```

It spies `_compose_context_message` and asserts the planner intent and the user's clarification answer are in the first composed message. The report reads that as "clarification answers are dropped on resume". They are not dropped; the channel the test looks at no longer exists.

## Evidence (observed 2026-10-08, HEAD `5e22d3238`; one file at a time, repo untouched)

- The resumed run DOES carry the answers, through the sandbox file. A spy on `RunSandbox.write` (`evidence/qa-kb-097/analysis-plugins/kb097_plannermd.py`, `analysis-11-planner-md-on-resume.txt`) captures the `PLANNER.md` the resumed run writes: `**Inferred Intent**: PLANNER-INTENT-SENTINEL: a governed claims-intake workbench`, `**Explicit Constraints**:` / `- Which deployment target? → SPINNAKER-SENTINEL`, `**Implicit Constraints**:` / `- IMPLICIT-SENTINEL: must stay auditable`; the file is still on disk after the test and contains `SPINNAKER-SENTINEL`.
- Bisect on `git archive` exports (scratch dir): `3e09aef2c^` (2026-09-10) all four tests of [ISS-1061](20261007-1914-ISS-1061.md) PASS (a stub `bcrypt` is needed to import that old tree under today's venv); `3e09aef2c` ("feat(sandbox): file-based agent context, family-scoped versioning, chain admission", 2026-09-12) this test FAILS with the message above (`analysis-08…`, `analysis-09…`). Its sibling stale test is [ISS-1105](20261008-0016-ISS-1105.md).
- The suite itself says the paste is gone: `tests/agents/test_seam2_gate_v3.py:72` lists `"## Planning Context"` among the `_WORLD_MARKERS` that must be absent from a context message.
- The unit test next to it was adapted and this one was not: `test_rehydrate_planning_context_rebuilds_planner_and_answers` (`:4830`) guards its message assertions with `if not _is_migrated:` (`:4915-4924`) because "domain-analyst is a migrated agent"; since the paste is gone for every agent that guard makes the unit test assert nothing about the message, and the integration test, which uses a default-policy fixture agent, is the one that cannot hide it.

## Cause (CONFIRMED)

`3e09aef2c` deleted the block that pasted the planning context into the per-agent message; the replacement is a comment in `_compose_context_message`:

```python
# backend/agents/execution_engine/engine.py:16578-16582
        # [Phase Z / GAPS §0.3, FR-030 row 10] World block — REMOVED. The "Planning
        # Context" paste (Deep Planner analysis: inferred intent/constraints/NFRs/
        # personas/quality targets/domain insights) was gated off for a migrated
        # agent at Step 0 and had no remaining default-policy agent to fire for once
        # Phase M finished; a migrated agent reads PLANNER.md itself instead.
```

On a resume the skip-planner branch still rehydrates the context (`engine.py:5415-5419`, `_rehydrate_planning_context`) and the dispatch loop still writes it to `PLANNER.md` (`:5681-5734`, `sandbox.write("PLANNER.md", …)`), so the delivery to the agent is intact. The test was not touched by `3e09aef2c` and has been red since (the ISS-1013 analysis of 2026-10-02 already saw it red and ruled it out of its own cause).

## Fix (test-only)

In `test_restart_resume_db.py`, `test_resume_dispatch_carries_rehydrated_planning_context`: read `RunSandbox(owner, run_id).root / "PLANNER.md"` after the resume (the same helper `test_failed_run_resumes_skips_completed_tasks` uses to look at the sandbox at `:3659-3661`) and assert `_REHYDRATE_ANSWER`, `_REHYDRATE_INTENT` and the absence of the `user_message[:200]` stub intent THERE; keep the `composed` spy only to prove a dispatch happened. Also drop or rewrite the `if not _is_migrated:` block at `:4915-4924`: it asserts nothing for the agent it loads and would fail for any other.

What a naive fix would break: putting the paste back into `_compose_context_message` violates the Phase Z contract (brief to agent 1 only, Requirement 13 AC 4), fails `test_seam2_gate_v3.py`, and changes the byte-pinned prompts (INV-3, characterization goldens).
