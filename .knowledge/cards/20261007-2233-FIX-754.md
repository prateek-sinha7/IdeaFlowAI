# FIX-754

Fixes QA-KB-074 (register `LEDGER.md`, detail `BUGS.md#qa-kb-074`). Resolves the root card
[ISS-901](20261001-2140-ISS-901.md) and its test-prose sibling [ISS-1079](20261007-2204-ISS-1079.md). The
architecture-doc sibling [ISS-1080](20261007-2204-ISS-1080.md) stays open: the DOMAIN card is the user's own and
the line never edits it (its locked constraint). This fix is the precondition that card names ("land ISS-901
first").

## What was wrong

[FIX-688](20261001-2140-FIX-688.md) changed `ScopedStore.append_event_next_seq` from a whole-log `read_events`
per attempt to one keyed `event_id` lookup plus one `_max_event_seq` probe. The method's cost was restated in four
docstrings, and FIX-688 updated only the method's own ("that would add two index probes per event"). Three source
docstrings and two test comments still gave the dead whole-log cost, in the present tense.

## Root cause (ISS-901's analysis, re-checked on this tree before editing)

Before the edit, the analyzer's stale-prose probe (`evidence/qa-kb-074/probe_stale_prose_sites.py`) still matched
the card's blast radius: 3 source sites, 3 lines in 2 test files, and 1 DOMAIN card. The anchor text was at:

- `backend/agents/authz.py:476-478`, `read_events_of_types`: "engine resume and this class's own
  ``append_event_next_seq`` seq allocation"
- `backend/agents/authz.py:595-598`, `_max_event_seq`: "run) and is why the engine sink cannot allocate through
  :meth:`append_event_next_seq`."
- `backend/agents/execution_engine/engine.py:13085-13088`, `_stamp_resume_marker`: "that allocator re-reads EVERY
  row of the run per attempt ... which is the same cost that rules it out for the engine sink."
- `backend/tests/agents/test_resume_marker_seq_allocation.py:3-9`, module docstring: "that method still derives
  the next seq via ``read_events(run_id, after_seq=0)``"
- `backend/tests/integration/agents/test_resume_marker_workspace_db.py:221-223`, the section (4) comment: "After
  the fix (routing through ``ScopedStore.append_event_next_seq``)"

There is no shared function to guard. The claim was restated at each site, so each site is where the fix lands.

## What changed, and why there

Prose only, no behaviour change. Each passage keeps the part that is still true and loses the dead cost. No hunk
adds a new statement of the method's cost: the only statement stays in its own docstring, which this fix does not
touch.

1. `authz.py` `read_events_of_types`: `append_event_next_seq` is no longer listed as a `read_events` caller. The
   conclusion stays: never cap `read_events`, the replay primitive behind SSE resume, the events API and engine
   resume. The next two lines were re-wrapped to keep the file's ~90-column width.
2. `authz.py` `_max_event_seq`: the clause "and is why the engine sink cannot allocate through
   :meth:`append_event_next_seq`" is gone. The contrast with `read_events` (materialises every row, a 36k-row run)
   stays.
3. `engine.py` `_stamp_resume_marker`: the cost claim is gone. The idempotency reason (the marker mints a fresh
   `event_id`, so it never needs the `(run_id, event_id)` no-op) stays as the only reason.
4. `test_resume_marker_seq_allocation.py` module docstring ([ISS-1079](20261007-2204-ISS-1079.md)): reframed as
   ISS-125 history. It says what the marker used to do, what it rides now (`_max_event_seq` plus
   `append_event_at_or_after`, [FIX-499](20260831-1641-FIX-499.md)), and that `append_event_next_seq` no longer
   reads the log (FIX-688). The test body and its name are unchanged; FIX-499 quotes the name.
5. `test_resume_marker_workspace_db.py` section (4) comment ([ISS-1079](20261007-2204-ISS-1079.md)): names the
   allocator the marker rides now (FIX-499) in place of `append_event_next_seq`.

Hunks 4 and 5 are in test files. They change comments only, as ISS-1079's fix shape asks ("Reword in place; leave
the test bodies and names alone"). No assertion changed.

## Not changed

- `append_event_next_seq`'s own docstring: already correct.
- [ISS-1080](20261007-2204-ISS-1080.md), `.knowledge/architecture/DOMAIN-durable-state-resume.md:395-399`: the
  user's own DOMAIN card. After this fix it is the only site the stale-prose probe reports (1 hit over 1271 files,

- `test_resume_seed_bounded_aggregate.py:1-8` narrates its pre-fix defect but names its ISS cards on line 1, so it
  reads as history. ISS-901's analysis did not count it either.
