## Sibling of ISS-274 — INFERRED, not yet reproduced in the browser

[ISS-274](20260828-1854-ISS-274.md) established the root cause for the Composer Simple
view's "Configure →" panel: it opens `AdvancedExpander`
(`frontend/src/components/workflow/AgentsPopup.tsx:1774-2184`), whose subtitle is hardcoded
`Validator · Gate · Model · Retry` (`AgentsPopup.tsx:1883`) — no Tools row — even though
`StepSelection.tools` (the shared field Canvas view's `CanvasConfigRail` writes through) is
present in the exact same `SelectionsMap` shape. A whole-file grep for `"Tool grants"`,
`"Read files"`, `"Write files"`, `"Execute commands"` in `AgentsPopup.tsx` returns no match
at all (re-confirmed for this card).

Grepping every other renderer of that shared shape (`validatorOn`/`retryOn`/`gateOn`,
`applyLeverPatch`) turns up a SECOND, independent per-agent lever surface with the
identical gap: `ConfigLeversFlat` (`frontend/src/components/workflow/AgentsPopup.tsx:1620-1772`),
which backs the "Config" tab of `AgentCapabilitiesModal`
(`AgentsPopup.tsx:476-872`). Its own tab body is introduced by the comment "Config tab —
per-agent configuration levers (Model · Validator · Gate · Retry) shown FLAT" (`AgentsPopup.tsx:732-735`)
and its JSX (`AgentsPopup.tsx:1700-1771`) renders exactly four lever rows — Model,
Validator, Gate (pre/post checkboxes), Retry — and nothing for Tools. `ConfigLeversFlat`
shares the same `applyLeverPatch` reducer `AdvancedExpander` and `CanvasConfigRail` use
(`AgentsPopup.tsx:1640-1647`), so a `tools` value already present on the incoming
`SelectionsMap` would survive edits to the other levers (the reducer spreads `current`
before applying the patch) — it is just never rendered or offered for editing here either.

`AgentCapabilitiesModal` is mounted from two call sites, confirmed by grep:
- `frontend/src/components/library/LibraryPage.tsx:1001` — the Library page's per-agent
  detail drawer. Here `initialSelections`/`onSelectionsChange` ARE wired
  (`LibraryPage.tsx:1010-1013`), but only to a page-local `useRef`
  (`savedSelectionsRef`, `LibraryPage.tsx:637`) that never round-trips into any saved
  workflow — so today this call site cannot yet hide a REAL persisted override the way
  ISS-274's Composer case does.
- `frontend/src/components/workflow/AgentLibrary.tsx:335` — the "Add agent" picker modal
  used across Composer/LaunchWizard/IdeaInputPage. Here `onSelectionsChange` is not even
  passed (only `onSkillsChange`), so the Config tab's lever edits are entirely local and
  discarded when the modal closes, Tools or not.

## Expected vs actual

- **Expected:** if a per-agent config surface exposes Validator/Gate/Retry as editable
  levers over the shared `StepSelection` shape, it should expose Tools the same way Canvas
  view's rail does — or the surface should make clear Tools grants live elsewhere.
- **Actual:** `ConfigLeversFlat` renders the same four levers as `AdvancedExpander` and
  omits Tools identically, confirmed by reading its full JSX body
  (`AgentsPopup.tsx:1700-1771`) — no Tools row, tab, or reference to `sel.tools` anywhere
  in the component.

## Why this is INFERRED, not CONFIRMED

The missing Tools UI itself is confirmed by reading the component's source in full — there
is no Tools-rendering code to find. What is NOT yet verified is a live-browser repro
demonstrating a REAL persisted override being hidden through this specific surface today,
given the caller-wiring nuance above (neither current call site round-trips a `tools`
value into a saved workflow). This is filed as a lead for the next validation cycle: open
`AgentCapabilitiesModal`'s Config tab (via the Library page's agent detail drawer, or the
"Add agent" modal) and confirm no Tools section is offered, matching ISS-274's own
Reproduction steps 3-5 adapted to this surface.
