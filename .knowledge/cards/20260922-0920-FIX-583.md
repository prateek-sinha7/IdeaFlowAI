## The symptom

[ISS-622](20260831-0115-ISS-622.md). A native browser dialog is unstyled,
unpositioned and unreachable by anything that inspects the page. The product had
already moved away from them everywhere except four destructive actions:
deleting a PAT, revoking an API key, deleting a skill, and leaving the
Constitution tab with an unsaved draft.

## What changed

Each becomes a `role="dialog"` with an explicit Cancel, matching the pattern
already used for the composer's unsaved-changes prompt. S-19-17's claim — that
the product shows no native dialogs outside the download affordances — now
holds.

The Constitution case needed its draft state lifted out of
`ConstitutionSection`'s local `useState` into the parent, so the tab handler can
see whether a draft is dirty **before** unmounting the component that holds it.

## Downstream

An offline integration scenario asserted the native `confirm` and so failed
precisely when this fix worked; it was repaired in the same sweep
(`14ce62c59`).
