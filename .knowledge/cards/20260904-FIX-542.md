## Related

## What was wrong

Prototype steps frequently omit user journeys that are mentioned in the input 
specs. There was no deterministic post-build validation to detect missing 
journeys before returning the prototype.

## The fix (commit 1e329e47b)

- New deterministic validator: `journeys_coverage`.
- Parses input spec documents to extract declared user journeys.
- Checks prototype for evidence that each journey is implemented.
- CRITICAL finding if any journey is missing.
- No model call: pure logic over input and output text/HTML.

Pinned by test_validator_journeys_coverage.py with fixtures covering good 
and bad journey implementations.
