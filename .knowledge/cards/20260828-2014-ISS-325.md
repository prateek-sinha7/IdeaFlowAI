## Observed

While running the sibling suite as a regression guard for
[FIX-328](20260828-2014-FIX-328.md):

```
suites/21_run_families_and_versions/test_run_families_and_versions.py \
  ::test_the_family_counts_as_one_against_a_filter_chip[chromium]   FAIL  33.4s

playwright._impl._errors.TimeoutError: Locator.inner_text: Timeout 30000ms exceeded.
Call log:
  - waiting for get_by_role("button", name=re.compile(r"^Presentation\s*\d")).first
```

Every other test in that file passed in the same run (S-21-04, S-21-06 ×3, S-21-10,
S-21-11).

## Why it is filed rather than fixed

- The test exercises only the run-history list at `/runs` — chip counts vs row
  counts. FIX-328 touches the run-DETAIL route/version-pin path and nothing on
  `/runs`.
- `frontend/src/components/history/WorkflowHistory.tsx` was concurrently modified in
  the working tree by another agent when this was observed, so the more likely owner
  is that change, not FIX-328.
- The test's own docstring scopes its assertion explicitly:

  > "`baseWorkflowType` strips the `_revision` suffix, so the chips count FAMILIES
  > while the headline counts runs. **With every family size 1** the two agree, and
  > this asserts that agreement — the day they diverge, either a family appeared
  > (good, write S-21-01) or the chip stopped collapsing revisions (bad)."

  This dataset now contains a genuine 2-member family
  (`77f74563-fa19-4f0b-84fd-d0224f89a54a` + `ef86e750-bbcd-404f-855a-fb0d5bee63f5`),
  so the "every family size 1" premise is already false. The docstring names the
  remedy for the good branch: write S-21-01.

**"Pre-existing" is NOT claimed** — it was not re-baselined at a pre-change SHA. It
needs one of: a re-baseline at the pre-change commit, or the S-21-01 the docstring
asks for.

## Resolution

Verified fixed in the current code on 2026-10-01 (feat/user-stories-v2 @ 3b08b2ba8) by static review: a first-pass check and an independent adversarial re-check both found every claim of this card fixed. No tests were run for this closure.

**Fixed by:** 14ce62c59 (test rewrite and _load_all); the chip_count absent-chip handling is in the current tree, origin commit not pinned

**Evidence:** Card claims: (1) RH.chip_count times out on absent `Presentation N` chip; (2) test asserted named==rows==All, premise "every family size 1" broken. (1) run_history.py:58-72 chip_count returns 0 when chip.count()==0, no wait/timeout (WorkflowHistory.tsx:1281 hides zero chips). (2) test_run_families_and_versions.py:301-332 rewritten: _load_all (l.319, defined l.96) pages all rows, collapsed=sum(n-1), asserts named==rows and rows==total-collapsed; docstring l.305-313 states the premise change. **Left over (outside this card's claims):** none in code. The card's verification is still manual/pending and the test was not run here (read-only). The card status field still says open.
