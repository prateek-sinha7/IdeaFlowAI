# ISS-155

## Title

**The od_prototype / od_ppt staging guards no longer require a brief, and now DISAGREE with the consumption guards.** dev's FIX-216c removed `\|\| !draft.brief` from `frontend/src/app/dashboard/page.tsx:426` (od_prototype) and `:463` (od_ppt), on the rationale that the wizard's `canContinue` already validated it. The two CONSUMPTION guards at `:1788` and `:1859` still require a brief. Net effect: an empty-brief chained run stages and fires on the direct path, but if the user reloads before SSE connects, the sessionStorage-fallback path silently `return`s and the run never starts — a "works, unless you reload" asymmetry. Separately, an od_prototype build is the 5–21M-token pipeline (measured ceiling 37.3M), so relaxing a launch-side validation on it deserves a deliberate decision rather than inheritance.

## Severity / Tag / Status (original row)

- Sev: major
- Tag: frontend,product
- Status: **FIXED** — FIX-255 (2026-08-13, commits `0279fae8` + `d0dc1f49`). Fixed at all three layers rather than one: the ingress refuses an empty/whitespace `message` pre-mint (`empty_brief`), `canContinue` now validates what `handleLaunch` actually consumes (`brief.trim() \|\| chainContextBlock?.trim()`), and all four staging/consumption guards agree so the reload path can no longer reach a different verdict. TEST-034 (3), seen RED — the empty brief returned **200 OK and minted a run**. **LIVE-VERIFIED**: 400 `empty_brief` with run rows 46→46, and the wizard discriminates (no context block → "Add a brief" + Continue disabled; with one → Continue enabled, dev's UX preserved). Side effect: repaired dev's tsc break, 4 errors → 2.
