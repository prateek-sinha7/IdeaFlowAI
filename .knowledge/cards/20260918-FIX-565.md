## The symptom

Two failed runs each named the wrong layer, and both cost debugging time
chasing it.

**Run 17de7ccb.** A Validator drove a browser for 133 model turns and 142 tool
nodes — 12 of them real `edit_file` fixes — then LangGraph's step counter hit
`AGENT_RECURSION_LIMIT` and raised `GraphRecursionError`. The client was told
"The model rejected this request." That is wrong twice: Bedrock rejected
nothing, and the agent was *working*, not looping.

**The screen plan.** Twice an Architect completed "successfully" having written
none of its three files. The run then died one step later, inside Builders, on
`build/screens.json is not valid JSON` — a credential-shaped message for a
missing-file problem. That is the second mislabel of this shape.

## The root cause

`_sanitize_agent_error` maps the runner's `str(exc)` through
`_AGENT_ERROR_CATEGORIES` (engine.py:186) and falls through to a generic
message. The generic message was the catch-all for ANY uncategorised runner
error, so a step budget running out, a content refusal and an auth fault were
all indistinguishable from the outside.

For the screen plan, nothing checked the Architect's output at the moment it was
produced. `screens.json` was only read one step later, by the task parser that
needed it.

## What changed, and the constraint that survived

A named category for the budget case:

```
("recursion limit", "graphrecursionerror", "recursion_limit") →
  "The agent ran out of steps before finishing — it reached the graph's step
   limit (recursion_limit) partway through its work, so it was cut off rather
   than refused."
```

The safety design is unchanged and is the reason the generic message exists at
all: raw provider text is **tested** against substrings and **never echoed**,
and every branch returns a hardcoded literal. A non-throttle Bedrock fault can
carry provider ARNs, region, model id and internal config; the raw string stays
in the server log. The constraint guards PROVIDER faults — a LangGraph
`GraphRecursionError` is our own framework's error, so naming it leaks nothing.
That distinction is what makes this branch allowable; it is not a licence to
widen what gets echoed.

`AGENT_RECURSION_LIMIT` went 400 → 1000 (`config.py:316`). At 400 the
"runaway-loop backstop" had quietly become a work ceiling: a 32-screen browser
walk legitimately needs more turns than a runaway loop does.

## Documentation drift

`backend/CLAUDE.md:179` still documents the limit as 400. Verified stale against
`config.py:316`, which is 1000.

## screens_plan_coverage

A new kernel-side `Validator`, pure stdlib, registered in the capability
registry. It reads `spec.md` and `build/screens.json` directly off
`target.runner.sandbox.root` (the same D-04 handle reach `fragment_field_coverage`
uses — they are sibling files, not the run's declared deliverable).

A spec heading of the shape `### <id> — <Name>` (em dash, not hyphen) declares
one screen. That pattern deliberately excludes `### UC-<n> — …` use-case
headings (uppercase `UC` never matches the lowercase-anchored id pattern) and
`### Flow <n>: …` headings (no em dash at all).

`build/screens.json` is parsed through `screen_inventory.parse_inventory`, the
single source of truth for that file's shape — the validator does not
re-implement JSON or fence parsing.

Every issue is P0 and **names the concrete missing screen ids**, because a
`fix: {max_attempts: N}` re-dispatch can only act on feedback that says which
screens are absent. Severity maps through the single imported `map_severity`
(VALID-03).

Verified against a real 32-screen `spec.md` and a real 25-screen `screens.json`.
