# FIX-260

**Phase / trigger:** commit `ef74d0472`, 2026-08-17.

## Description

Form inputs across the frontend (admin settings, account settings, chat,
preview panels, the workflow Composer, history, catalog, sidebar, and more)
lacked `id`/`name`/`aria-label` attributes. This fails WCAG label
association (a screen reader cannot associate a visible label with its
input) and breaks browser/password-manager autofill, which keys off
`name`/`id`, not visible text.

## Fix

Added `id`/`name`/`aria-label` to inputs across 43 files. No behavioral
change — pure accessibility/semantics attributes on existing form elements.
Concentrated in: `admin/page.tsx`, `settings/AccountSettings.tsx`,
`workflow/composer/*` (Composer's own agent config forms), `chat/*`,
`preview/*`, `history/WorkflowHistory.tsx`, `catalog/NameWorkflowModal.tsx`,
and several prototype/design-system modal forms.

## Files changed

43 files under `frontend/src/`. Representative spread: `app/admin/page.tsx`,
`components/settings/AccountSettings.tsx`, `components/chat/{ChatInput,
InlineGateActions,MessageBubble,RunChatLane}.tsx`,
`components/workflow/composer/{AgentSkillsPicker,CanvasConfigRail,
CanvasNode,CanvasView,ComposerPage}.tsx`,
`components/preview/{AppBuilderPreview,MarkdownPreview,PPTPreview,
PrototypePreview,TweaksPanel,UserStoryPreview}.tsx`,
`components/history/WorkflowHistory.tsx`,
`components/catalog/NameWorkflowModal.tsx`. Full list in commit
`ef74d0472`.
