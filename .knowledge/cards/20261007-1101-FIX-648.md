## What changed

**File:** `backend/app/api/run_commands.py`

In `_drive_launch_to_queue`, the `elif degraded_failed_agents is not None:` branch was
extended with a cross-check against `raw_events` before writing the DB status:

```python
# BEFORE
elif degraded_failed_agents is not None:
    wr.status = "degraded"
    wr.error = (
        first_agent_error_msg
        or degraded_reason_msg
        or "degraded: agent(s) failed: " + ", ".join(degraded_failed_agents)
    )

# AFTER (ISS-872 / FIX-648 — R-09 safety net)
elif degraded_failed_agents is not None:
    _agent_complete_ids = {
        data.get("agent_id")
        for utype, data in raw_events
        if utype == "agent_complete"
    }
    _truly_failed = [
        a for a in degraded_failed_agents if a not in _agent_complete_ids
    ]
    if not _truly_failed:
        wr.status = "completed"
        wr.error = None
    else:
        wr.status = "degraded"
        wr.error = (
            first_agent_error_msg
            or degraded_reason_msg
            or "degraded: agent(s) failed: " + ", ".join(_truly_failed)
        )
```

## Why this is safe

`raw_events` is populated from the **same live stream** that `engine.execute()` yields.
An `agent_complete` event in `raw_events` is authoritative proof that the agent produced
output during THIS run. If an agent appears in `degraded_failed_agents` but ALSO has an
`agent_complete` event, the engine's `_unrecovered_agents` computation is a false
positive. Overriding to "completed" matches the observable reality.

**Genuine degraded runs are unchanged:** if any agent in `degraded_failed_agents` has NO
`agent_complete` event in `raw_events`, it is truly unrecovered. The run stays "degraded"
and the error message names only the truly-failed agents.
