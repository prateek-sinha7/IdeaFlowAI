# FIX-720

## Provenance

This fix is for bug report QA-KB-057 (`BUGS.md#qa-kb-057`). The root cause is the 2026-10-02 analysis on
[ISS-905](20261001-2149-ISS-905.md) and its sibling [ISS-981](20261002-0409-ISS-981.md). It was not re-derived here.

The edits were made by the first fix pass on 2026-10-02. Its runs are `evidence/qa-kb-057/05`-`09`. That line run halted
on expired credentials before the pass wrote a card or moved the ledger row, so the row stayed `TESTED`. The edits then
landed in HEAD inside `14a675db4` ("not_stable changes for stale fix cards"), together with other bugs' hunks.

This pass was re-dispatched on 2026-10-07 and made no source or test edit. It checked the tree against both cards and
re-ran everything below. It also wrote this card and the ledger row. `git status` shows `run_commands.py` and both test
files unmodified against HEAD `afdeefa03`.

## What was wrong

- **[ISS-905](20261001-2149-ISS-905.md) Fault 1: every test got 401.** `launch_run` takes
  `auth: tuple[User, Principal] = Depends(get_current_principal)` (`backend/app/api/run_commands.py:3243`), but the
  fixture overrode only `get_current_user`. The result was 8 × `401 {"detail":"Not authenticated"}`.
- **ISS-905 Fault 2: six tests got 422.** `user_stories` declares `chains_from: true`
  (`backend/agents/workflows/user_stories/workflow.yaml:35`), so a bare seeded source row is refused by admission
  through the legacy selector. That gave 6 × `422 source_payload_missing`. The product is right here and the fixture
  was stale.
- **ISS-905, a constraint the analysis added.** Admission opens the source's sandbox. Without a pinned `RUNS_ROOT`,
  every launch that reaches it writes into the real `runs/` directory.
- **[ISS-981](20261002-0409-ISS-981.md) A: refused launches left an orphan audit row.** The endpoint-level copy of the
  guard in `launch_run` wrote a `run_id="pending"` audit row before every gate. Only the code after
  `_launch_run_core` returned ever backfilled it, so a launch refused at admission left the row orphaned.
- **ISS-981 B: block-only messages were recorded as stripped, twice.** When the message was only the block, both
  copies fell back to the original content but still logged `outcome="stripped"`. Because the endpoint fallback kept
  the marker, the `_launch_run_core` copy then wrote a second row.

## What changed, and why there

1. **`backend/app/api/run_commands.py`: four hunks for ISS-981, all inside the guard.**
   - `:2983-2996` in `_launch_run_core`: the content is replaced only when `_stripped_content` is non-empty. It now
     records `_strip_audit_source` and no longer writes a row before the mint.
   - `:3098-3124` in `_launch_run_core`: after the mint, it writes one `legacy_context_block_stripped` row with
     `run_id=workflow_run.id`, on the mint's own `db` session. This is best-effort: a failure rolls back and logs a
     warning, the same way the `chain_source_selected` row just above it is handled.
   - `:3406-3408` in `launch_run`: the endpoint-level copy is gone, along with its pending row and its fallback. A
     comment now points at the core copy.
   - The endpoint's backfill after `_launch_run_core` returns is gone too.

   **Why the guard lives in `_launch_run_core`.** That is where the run is minted, so it is the one place the row can be
   written after the outcome is known, in the mint's transaction. `launch_run` is its only HTTP caller and already
   passes `request_source_workflow_run_id=body.source_workflow_run_id` (`:3842`). That covers the declaration-gate
   case, where admission zeroes the source id, which is what the endpoint copy was written for. The other caller,
   `run_trigger_workflow` (`backend/agents/execution_engine/kernel_services.py:1664`), passes
   `source_workflow_run_id=None` (`:1679`) and is unaffected.

   **This departs from the card's suggestion.** ISS-981 said to "drop one of the two copies" and suggested removing the
   core copy together with its parameter. This fix removed the endpoint copy instead:
   - Keeping the core copy leaves the parameter and its signature test unchanged.
     `test_launch_run_core_is_plain_async_function_decoupled_from_fastapi` (`test_rest_run_launch_api.py:1046`) still
     passes.
   - No gate behaves differently. Between the old endpoint strip and the core call, `content` is read only by the
     ISS-155 empty-brief gate, `if not (content or "").strip():` (`:3426`). The strip could never change that gate's
     outcome, because the old copy fell back to the original content whenever stripping left nothing.
2. **`backend/tests/integration/api/test_duplicate_context_guard_api.py`: ISS-905, test-only as the card specifies.**
   ISS-905 says "Fix (test only, proposed)" and "the product is correct", so these test edits follow the card. They do
   not bend the test to the code.
   - It overrides `get_current_principal` (`:114-119`), as `test_rest_run_launch_api.py` does.
   - It pins `settings.RUNS_ROOT` to `tmp_path` (`:86-87`).
   - A new `_seed_chain_source` (`:174-181`) builds the minimal admissible source the analysis verified: the bare row
     plus `.chain/<id>/summary.md`. The six tests that send a source id use it. `_seed_source_run` stays the bare row,
     and its docstring now says that bare row gets refused.
   - Two assertions that were weaker than their test names now check that the marker survives in the persisted input
     (`:347-348`, `:364-365`).
   - `test_strip_audit_row_recorded` now asserts exactly one row (`:285-288`). This pins the ISS-981 happy path.
3. **`backend/tests/integration/api/test_duplicate_context_guard_audit_api.py`** is the ISS-981 test file. Case A: a
   refused launch leaves no strip row. Case B: a block-only message records zero rows.
4. **`frontend/e2e/tests/ts-v2-chain-versioning.spec.ts:8`**: the comment now names the moved test path (ISS-905
   step 3).

The `xfail(strict=True)` markers are still on both test files. The 6-verifier removes them.

## Deliberately NOT changed

- **Whether a block-only chained message should keep its block.** This is the product half of ISS-981 B and is now
  recorded as [ISS-1052](20261007-1754-ISS-1052.md) (open). Behaviour is unchanged: the block is kept. The only
  difference is that no false audit row is written.
- **`workspace_id` on the strip row.** It is still `workspace_id_override or ""`, which the core copy always wrote. No
  card covers it.
- **Spec traceability tables that name the old test path.** These are `GIT_VERSIONING_GAP.md:272` and
  `gap-closure-review.md:140, :608`. The card calls them dated snapshots, so they were left alone.
- **Sibling cards.** [ISS-947](20261002-0107-ISS-947.md) (open) has the same Fault 1 class in another file.
  [ISS-949](20261002-0107-ISS-949.md) (open) covers the stale foreign/unknown-source tests in
  `test_rest_run_launch_api.py`, which are 2 of that file's 4 reds below. Both belong to their own bugs.
- **The other `run_commands.py` hunks in `14a675db4`.** They belong to other fixes (ISS-936, ISS-160, ISS-689,
  ISS-687/978, QA-KB-017).
