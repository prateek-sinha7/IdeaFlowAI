# ISS-776

## Description

Sibling of [ISS-770](20260922-1305-ISS-770.md) (bug `QA-SG-014`,
`BUGS.md#qa-sg-014`), derived from its root cause rather than independently
reproduced live.

ISS-770 confirmed the composer's "Output format" control is rename-only for
`streamed_text`, and that strategy's resolver always returns raw agent text
so its hardcoded `text/markdown` mimetype default is at least *honest*. This
card is the adjacent case: the SAME "Output format" `<select>`
(`frontend/src/components/workflow/composer/CanvasView.tsx:1950-1964`) also
offers `.html`/`.md` under the **`single_file`** deliverable strategy
(`FORMAT_OPTIONS.single_file`, `CanvasView.tsx:1796-1799`), and the
"Deliverable" strategy dropdown that picks `single_file` in the first place
(`CanvasView.tsx:1895-1907`, `name="deliverable-strategy"`) is a plain,
user-editable `<select>` in the full composer — nothing here is read-only.

Unlike `streamed_text`, `single_file`'s resolver (`SingleFileResolver.resolve`,
`backend/agents/capabilities/deliverables/single_file.py:99-146`) tries to
read the *declared filename* back from the sandbox first
(`runner.sandbox.read(filename)`, `:132`). That only returns real content
when some step in the workflow actually wrote that exact file — true for the
native `prototype` pipeline's `prototype-build` agent (which is
tool-equipped and prompted to write `prototype.html`), but the custom
composer lets a user pick `single_file` + rename the file to `whatever.html`
paired with **arbitrary** agents (e.g. a documentation/market-research
agent) that have no instruction to write to that filename at all. When
nothing wrote it, the resolver falls through to case (3)
(`single_file.py:143-146`):

```python
if last_streamed.strip():
    logger.warning(
        "single_file: %s not written by agent — falling back to streamed output",
        filename,
    )
    return last_streamed
```

— the same raw last-agent text ISS-770 documents for `streamed_text`. The
difference, and why this is its own card rather than a duplicate: the
**mimetype** default is computed differently. `single_file`'s
`default_mimetype` (`single_file.py:92-95`) calls
`_infer_from_name(name)` (`_mimetype.py:38-46`), which maps the `.html`
*extension alone* to `text/html` — it has no way to know the bytes it is
describing are actually the case-3 fallback. So where ISS-770's
`streamed_text` case reports `text/markdown` for markdown bytes (correct,
if unhelpful), this case can report **`text/html` for markdown/plain-text
bytes** — an active mislabel, not just an unmet format promise. (Contrast:
`streamed_text`'s own default is hardcoded to `text/markdown`
unconditionally — `_mimetype.py:26-31`, `_STRATEGY_MIMETYPES["streamed_text"]`
— deliberately, per `engine.py:7287-7291`'s WR-01 comment, so it never lies
the way this path can.)

## Expected vs Actual

- Expected: a `deliverable_mimetype` of `text/html` on a completed run means
  the bytes actually are HTML markup.
- Actual (inferred, not yet reproduced live): selecting **Deliverable:
  Single file** + **Output format: HTML (.html)** in the custom composer,
  with no selected agent configured/tooled to write the declared filename,
  produces a completed run whose `final_output`/`.chain/<name>` bytes are
  the last agent's raw streamed text (markdown or plain prose), while
  `deliverable_mimetype` reports `text/html` — worse than ISS-770's
  `streamed_text` case, which at least reports the true type.

## What would confirm or refute it

A live run: composer with Deliverable = Single file, Output format = HTML,
one non-prototype agent (e.g. Documentation Agent), no filename-writing
step. `GET /api/runs/<id>` should show `deliverable_mimetype: "text/html"`
and `.chain/<name>` bytes with no HTML tags, mirroring ISS-770's cycle 2/3
evidence but for `single_file` instead of `streamed_text`.

## Notes

Root-caused, not independently reproduced — per the analyzer role's
instruction to mark every derived sibling `INFERRED` until reproduced. The
fix belongs in the same place ISS-770's does: either the composer stops
offering `.html` for a strategy/agent combination that cannot guarantee HTML
content, or the deliverable-resolver layer gains a real format-conversion
capability. A partial fix that only touches `streamed_text` (ISS-770) would
leave this `single_file` path — reachable from the exact same screen —
still mislabeling its output.
