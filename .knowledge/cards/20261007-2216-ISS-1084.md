# ISS-1084

**Register source:** `QA-KB-076` in root `LEDGER.md` / `BUGS.md` (sibling, derived during its analysis on 2026-10-07).
**Root card:** [ISS-903](20261001-2145-ISS-903.md) holds the mechanism (the guard's world is hand-listed and narrower than its claim). This card is the boundary case: when the hand-listed world shrinks, the guard says nothing.

**Claim status: INFERRED (sibling).** The mechanism is CONFIRMED by reading `test_run_shutdown_stale_citations.py:36-38`. That it ever bites is INFERRED: no scanned file has gone missing yet. The move precedent below is CONFIRMED from `git log --follow`.

## What is wrong

```python
    hits = []
    for path in _SCANNED:
        if not path.exists():
            continue
```

(`backend/tests/unit/test_run_shutdown_stale_citations.py:35-38`). A scanned path that no longer exists is skipped with no message, and nothing asserts that at least one file, or all six, were read. If every path vanished the test would still pass with `hits == []`.

The other test in the same file disagrees about what a missing file means. `test_shutdown_comment_read_timeout_matches_model_factory` calls `.read_text()` on `model_factory.py` and `run_shutdown.py` with no existence check, so a move there raises `FileNotFoundError` loudly.

**Precedent, CONFIRMED:** `09270703b` (2026-09-22, "Fix/testcases (#9)") moved two test files: `tests/unit/test_shutdown_reachability.py` to `tests/unit/services/` (rename R099) and `tests/unit/test_run_shutdown.py` to `tests/unit/app/` (R100). `_SCANNED` carries the new path today. The moved file's own docstring does not: lines 1 and 3 of `test_shutdown_reachability.py` still name the old paths (`evidence/qa-kb-076/03-analyze-baseline-runs-and-moves.txt`). So a path written in text does not follow a move, and a path list that is not checked would not either. Had `_SCANNED` kept the old path after that commit, the guard would have gone on passing while scanning nothing for that file.

## Why the root cause implies it

Boundary and empty input. [ISS-903](20261001-2145-ISS-903.md) is a guard that sees less than it claims. This is the same shape taken to its limit: when its list is out of date the guard sees nothing, and reports it as a pass.

## Expected vs actual

- Expected: a moved or deleted scanned file fails the test with the path named, so someone updates `_SCANNED`.
- Actual: the file is skipped and the guard stays green.

## Fix

Replace the `continue` with an assertion in `backend/tests/unit/test_run_shutdown_stale_citations.py`:

```python
assert path.exists(), f"scanned file moved or deleted: {path}"
```

One line, no discovery logic. ponytail: `_SCANNED` stays a hand list, and the ceiling is that someone must add a new shutdown-path file to it by hand. A glob over `backend/app/api/run_*.py` would remove that, at the price of scanning files nobody converted.

## Test notes (for the test-writer)

- The lint is a test function, so it cannot be called with a different list. Factor the scan into a helper over a list of paths (the same helper [ISS-903](20261001-2145-ISS-903.md)'s notes ask for), then assert the helper raises on a `tmp_path / "gone.py"`.
- Never delete or rename a real scanned file to reproduce this. Monkeypatching `_SCANNED` to a temp list is enough.
