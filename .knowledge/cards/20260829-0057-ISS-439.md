# ISS-439

**Register source:** analyzer pass on `BUG-20260828-085400-runs-failed` in
`bug-hunter/ledger.md` (root card [ISS-317](20260828-1755-ISS-317.md)).

## Why the root cause implies this

Same shared-array mechanism as [ISS-438](20260829-0056-ISS-438.md) (see that card for
the full `useWorkflow.ts:446-468` merge trace: a resume carries an agent's pre-resume
`status`/`error` forward verbatim via `{ ...existing, ...identity }` at `:457-458`, only
cleared by that agent's own next `agent_start`, `:573-594`). This card is a THIRD,
independent reader of the same polluted array, reached by clicking into the specific
stale agent rather than just viewing the summary.

`StepsOverviewSpine`'s `onOpenAgent` prop (wired from `AgentThinkingTab.tsx:311`,
`onOpenAgent={(id) => { setSelectedAgentId(id); setSelectedTaskIndex(null); }}`) is how a
user opens any agent row — including the one that still carries `status: "error"` — from
the Steps tab shown in the very bug report (`StepsOverviewSpine.tsx:484-495` renders
these rows as `navigable` whenever `!isIdle && !isSkipped`, and an `"error"` status is
both). Selecting it renders `AgentDetailPanel` (`AgentThinkingTab.tsx:274-302`):

```ts
// AgentDetailPanel.tsx:945-947
const isRunning = agent.status === "running" || agent.status === "thinking";
const isDone = agent.status === "done";
const isError = agent.status === "error";
```

`agent` here is `selectedAgent`, sourced from the SAME `pipelineState.agents` array
(`AgentThinkingTab.tsx:299`, `agents={agents}`) — so `isError` reads the identical stale
field ISS-317 and ISS-438 already trace to `useWorkflow.ts:457-458`.

## Expected vs actual (predicted, not yet observed)

- **Expected:** opening the detail view of an agent that is about to re-run (or already
  running again) in a resumed pipeline shows its CURRENT state, not an error banner left
  over from the attempt the resume just superseded.
- **Predicted actual:** `isError` stays `true` for that specific agent's detail panel —
  plausibly rendering a stale error message/banner — until its own `agent_start` event
  arrives and resets `status`/`error` (`useWorkflow.ts:573-594`).

## Status

**INFERRED — not independently reproduced.** Derived from source (the merge site and
this consumer site were both read directly), not from a browser repro cycle. What would
confirm it: repeat [ISS-317](20260828-1755-ISS-317.md)'s cold-start protocol, and while
the run is confirmed `generating`, click the previously-failed agent's row in the Steps
tab and check `AgentDetailPanel` for a lingering error state/banner.

## Fix

Same shared seam as [ISS-438](20260829-0056-ISS-438.md) — `useWorkflow.ts`'s
`pipeline_start` merge (`:457-458`), not a per-component patch in `AgentDetailPanel.tsx`
or `StepsOverviewSpine.tsx`. Resetting the stale `status`/`error` at the one place that
produces `pipelineState.agents` fixes this card, ISS-438, and the originally reported
label at once.
