# ADR-0012: Composer tool grants are fixed, not author-editable

## Context and Problem Statement

The Composer's Tools tab offered four per-node toggles. A live Topic Page workflow
declared `write_files: false` on all five steps; all five wrote files. Tracing every
consumer of `step.tools` showed why:

| Grant | Enforced? | What "off" actually did |
|---|---|---|
| `read_files` | Partially | Did **not** block reading — the native `read_file` tool is bound regardless. It only stopped the secret-scan hook binding (`hooks/base.py`) |
| `write_files` | No | Intersects custom tool *providers* only; none is write-privileged. The native `write_file` is bound via `exclude_builtin=False` |
| `exec` | No | No hook declares it. Worse: the compiler rejects the grant for `db`-trust manifests |
| `spawn_subagents` | Engine-side only | Real ceiling in `engine.py::_consume_spawn_subagents`, but unreachable — the compiler rejects the grant for `db` trust |

Two of the four were not merely inert. `trust="db"` is absent from
`compiler._TRUSTED_SOURCES`, so granting `exec` or `spawn_subagents` produces a manifest
the compiler refuses. Before save-time validation existed that surfaced at run time; with
`_compile_check_manifest` in place it is a 422 on save. **Their only possible effect was to
make the workflow unsaveable.**

And `read_files: false` inverted its own label: a user tightening permissions was silently
disabling secret scanning while the agent kept reading.

## Decision

The grants are **fixed values, not author choices**:

```
read_files       true    required by the artifact contract; "off" only lost secret scanning
write_files      true    required by the artifact contract (ADR-0011)
exec             false   engineer-only; rejected for db-trust manifests
spawn_subagents  false   engine's dispatch decision, never a per-node grant
```

`spawn_subagents` is removed from the Tools tab entirely. The others render as fixed,
disabled indicators so a reader can still see what the agent may do. The two adjacent
levers the engine does not honour for composed steps — fan-out over a list, and retry on
failure — are disabled on the same grounds but left visible, so an already-saved value
still reads back rather than becoming invisible and unclearable.

## Rationale

**`write_files` has no coherent "off".** Every composed step must write exactly one file —
its artifact, which the next step's roster points at (ADR-0011). A step that cannot write
cannot take part in a handoff. Enforcing `false` would break the workflow; leaving it
unenforced made the manifest lie.

**Correcting the manifest beats adding enforcement.** The honest statement is
`write_files: true` — that is what every step does and must do. Building real enforcement
means carving out an exception for the step's own artifact: a new feature with a new
failure mode, not a fix.

**A control that cannot be honoured is worse than no control.** The author sets it, assumes
it took effect, and debugs the wrong thing later.

## Consequences

**Positive.** The manifest now describes the runtime. No Composer control can produce an
unsaveable workflow. Steps previously saved with `read_files: false` regain secret scanning.

**Negative — per-step privilege scoping is gone as a product surface.** There is no way to
express "this step may not write arbitrary files". The fields remain in the manifest schema
and the engine keeps its `spawn_subagents` ceiling, so an engineer-authored (`file`/`builtin`
trust) manifest can still use them; only the user-facing palette is closed.

**Existing manifests are unaffected at runtime**, since none of these flags changed
behaviour. Only the values newly serialised differ.

## Alternatives considered

**Make the grants real.** Constrain `write_file` to the step's own artifact and unbind the
rest. Deferred, not rejected — it is the correct long-term shape, but it is a feature with
its own failure mode (a step writing a legitimate scratch file now errors).

**Hide the tab.** Rejected: the reader loses the ability to see what an agent may do, and
already-saved values become invisible.

## Confirmation

`userWorkflows.test.ts` pins the serialised grants. The compiler's own rejection of
`exec`/`spawn_subagents` for `db`-trust manifests (`compiler.py`, `_TRUSTED_SOURCES`) is the
backstop: if the palette ever re-opens these, save fails loudly rather than at run time.
