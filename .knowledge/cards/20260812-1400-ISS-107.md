# ISS-107

## Title

**`hook_run`'s payload never reaches the reducer, so the only live consumer of `hookRuns` is structurally dead.** `dashboard/page.tsx:915` dispatches `{ type: msg.type, ...(msg.data

## Severity / Tag / Status (original row)

- Sev: minor
- Tag: frontend
- Status: **OPEN** (found during quick-260812-iqh / FIX-235)

## Source / Evidence

(none recorded)

## Reproduction (QA-KB-005, validated 2026-10-01)

Reproduced 3/3 from cold start (fresh vitest process each time, no browser). Throwaway test fed
`runFrames([{type:"hook_run", hook:"secret_scan", event:"before_write", outcome:"block"}])` through
`handlePipelineMessage` (frontend/src/hooks/useWorkflow.ts:1702-1714). Result every time:
`hookRuns[0] = {hook:"audit_logger", event:"", outcome:"continue", detail:{}}`; assertion
`expected 'continue' to be 'block'`. Cause: the frame is flat (payload spread onto the frame), but
line 1703 reads only `msg.data`, falling back to `{}`. The existing accumulators test only asserts
`hookRuns.length`, so it never saw this. Severity per QA-KB-005: High.
Evidence: evidence/qa-kb-005/01-validate-attempt1-vitest-output.txt (02, 03 likewise).

## Analysis (QA-KB-005, analyzer 2026-10-01)

**Verdict.** The reducer-level root cause below is CONFIRMED and the agreed one-line fix is ACCEPTED. But this card's
framing ("the payload never reaches the reducer") is truer than its mechanism: in the running app the frame never
reaches the reducer at all, so this defect is **latent today** and the agreed fix changes no behavior in the app.
Two sibling cards carry the layers it was masking: [ISS-870](20261001-2107-ISS-870.md) and
[ISS-871](20261001-2107-ISS-871.md).

### Root cause — CONFIRMED (file:line read)

`case "hook_run"` reads its payload only from `msg.data`:

```ts
// frontend/src/hooks/useWorkflow.ts:1702-1710
case "hook_run": {
  const hookData = (msg.data as Record<string, unknown>) || {};
  const entry = {
    hook: (hookData.hook as string) || "audit_logger",
    event: (hookData.event as string) || "",
    outcome: (hookData.outcome as string) || "continue",
    detail: (hookData as HookRunEntry["detail"]) ?? null,
    created_at: (hookData.timestamp as string) || new Date().toISOString(),
  };
```

The route that feeds the reducer spreads `data` onto the frame and drops the `data` key:

```ts
// frontend/src/app/[...view]/page.tsx:1569-1574
if (!isForeignFrame && isForActiveRun) {
  handlePipelineMsgRef.current?.({
    type: msg.type,
    ...(msg.data as Record<string, unknown> || {}),
  });
}
```

so `hookData` is `{}` and every field takes its default: `hook "audit_logger"`, `event ""`, `outcome "continue"`,
`detail {}`, `created_at` the client clock. Reproduced 3/3 above; the validator's output line is
`{"hook":"audit_logger","event":"","outcome":"continue","detail":{},...}`.

Why this case is the outlier: nine other reducer cases read `(msg.data as Record<string, unknown>) || msg`
(`useWorkflow.ts:1720, 1740, 1763, 1861, 1872, 1907, 1922, 1991, 2002`) and two more read both shapes (`:718`, `:1414`).
`hook_run` is the lone `|| {}`. It was written 2026-06-23 by KAN-73 (`7d49bf90e`, see
[FIX-018](20260623-FIX-018.md)) against the nested shape the backend queues (`kernel_services.py:561`,
`{"type": "hook_run", "data": data}`), seven weeks after the page flatten landed (`274c755b5`, 2026-05-05). The
[ISS-082](20260812-0351-ISS-082.md) identity gate was later built on the flat shape (`useWorkflow.ts:254-258,281-292` read
`msg.event_id` at top level), and `useWorkflow.accumulators.test.ts:172-174` even documents "Flat ... this is exactly
what reaches the reducer", but its `hookRuns` row asserts only `read: (s) => s.hookRuns?.length` (`:183`), which is how
the payload loss was never seen.

### Correction to this card's original claim — CONFIRMED

The original row (`.planning/ISSUES-REGISTER.md:165`, a frozen archive; the card carries only the truncated title)
says "the reducer is reached ONLY through the flattening path". That path is itself gated: `page.tsx:1344`
`if (pipelineTypes.includes(msg.type)) {` encloses the dispatch, and `"hook_run"` is in neither `pipelineTypes`
(`:1312-1343`) nor `useRunStateStore`'s `pipelineFrameTypes` (`:531-567`); `hook_run` occurs zero times in `page.tsx`,
`useRunStateStore.ts` and `wsReplayState.ts`. The earlier verification drove the reducer directly with both shapes and
never checked that a live frame gets there. Detail and proof: [ISS-870](20261001-2107-ISS-870.md).

Severity: the sweep rated QA-KB-005 High. With the case unreachable live there is no user-visible effect today, so this
card's original `minor` stands until [ISS-870](20261001-2107-ISS-870.md) opens the path.

### Blast radius — CONFIRMED by grep

- Callers of `handlePipelineMessage` (non-test): `useWorkflow().handleMessage` (`useWorkflow.ts:141`, used only at
  `page.tsx:1570`) and `useRunStateStore.handleFrame` (`:584`, which hands the reducer BOTH shapes,
  `{ type, ...msg, ...msg.data }` at `:573`). Tests drive it through `__fixtures__/reducerHarness.ts`. The handoff
  feature has its own separate reducer (`useHandoffPipelineState`) and is not affected.
- Consumers of `pipelineState.hookRuns`: `RunChatLane.deriveSecurityBullets` (`RunChatLane.tsx:469`, filters
  `outcome === "block"` and `hook` matching `/secret|scan/i`, so it never matches a defaulted row) and the dormant
  `AuditTab` prop (`PreviewPanel.tsx:1974`; `AuditTab.tsx:46-51` says the tab no longer reads it). Nothing else reads it.
- Live emitters (`emit_hook_event`, four callers). What the fix does to a real frame: `audit_logger` step markers and the
  tool_call / tool_result audit rows go from `{hook "audit_logger", event "", detail {}}` to the right `event`, the full
  `detail` (agent_name, summary, severity, tool, args_summary) and the server `timestamp` as `created_at`; `hook` and
  `outcome` already matched by default for those three. The behavioral run-entry rows stay mislabelled (no `hook`/`event`
  key on the wire, they carry `hook_name`/`event_type`); that is [ISS-871](20261001-2107-ISS-871.md).
- Other reducer cases with the same flaw: none (see the nine `|| msg` sites above).

### Fix — accepted, and where it belongs

Accept the agreed fix: `useWorkflow.ts:1703` `|| {}` becomes `|| msg`, matching the nine sibling cases (the proposed
`|| (msg as Record<string, unknown>)` is equivalent). It belongs in the shared reducer, not in a caller: every caller,
and any future one, routes through it, whereas changing `page.tsx:1570` to also pass `data` would leave the reducer's
contract fragile and diverge from the nine siblings. The store path already supplies both shapes, so the `||` fallback
is safe there. "Strip `type` from `detail`" (the optional note) is not worth doing: `detail` already carries `event_id`
and nothing reads either.

Amended: the proposed vitest case asserts only `outcome`. Assert all five fields (`hook`, `event`, `outcome`, `detail`,
`created_at`) on both the flat shape and the nested `{type, data}` shape, because the existing registry row passed on
`length` alone.

Sequence: land this fix BEFORE [ISS-870](20261001-2107-ISS-870.md). Opening the allowlist first would fill `hookRuns`
with all-default rows.

What the fix will NOT do: revive `deriveSecurityBullets` or change anything in the browser. See
[ISS-870](20261001-2107-ISS-870.md) (frame never routed) and [ISS-871](20261001-2107-ISS-871.md) (no live
secret_scan emitter). Do not report QA-KB-005 as verified in the UI; verify at reducer level.

### CONFIRMED vs INFERRED

- CONFIRMED: the shape mismatch (above), the nine-versus-one idiom count, both allowlists lacking `hook_run`, the four
  emitters and their payload keys, the consumer filter, the history of the two commits.
- INFERRED: that no live frame is observed being dropped (no run was launched, which this line forbids), and that the
  allowlist omission is an oversight rather than a decision (no card records intent). The source-text and store-level
  tests in [ISS-870](20261001-2107-ISS-870.md) settle the first.

## Fix (2026-10-01)

Fixed by [FIX-683](20261001-2128-FIX-683.md). `useWorkflow.ts:1689` now reads
`(msg.data as Record<string, unknown>) || msg`, the idiom of the nine sibling cases, with a one-line comment at `:1688`.
It landed before the [ISS-870](20261001-2107-ISS-870.md) allowlist change, as sequenced above. In
`useWorkflow.pipelineError.test.ts`, the `it.fails` case "keeps all five fields from a flat frame (the shape page.tsx
sends)" now reports "Error: Expect test to fail", so its assertions pass. The nested-shape control stays green, and
`useWorkflow.accumulators.test.ts` is 46/46. The marker is left for the 6-verifier. Nothing changes in the browser
yet, because [ISS-871](20261001-2107-ISS-871.md) is still open and no live row matches the chat-lane filter.
