# ISS-1181

**Register source:** sibling derived during the `QA-KB-124` analysis on 2026-10-09 (root [ISS-1156](20261009-1445-ISS-1156.md)). Not its own bug row.
It is the WRITER half of that root: the run failed because the stored override granted `write_file` to steps the built-in declares tool-free, and this is the line that wrote the grant.

**Confidence:** CONFIRMED for the payload. The real serializer (`buildWorkflowManifest`, `agentsFromManifest`, `manifestStepsToGateSelections`) was run offline over the built-in's own steps for each roster seed (`evidence/qa-kb-124/analysis-05-serializer-grants-by-seed.txt`), and seed (a) reproduces the stored row `bdf009f2-8545-4579-81a3-96391402b713` on every key that matters (`analysis-01-override-row-bdf009f2.json`). INFERRED: which OTHER built-ins change behaviour because of it. The QA-KB-103 matrix (`evidence/qa-kb-103/analysis-07-all-builtins-unchanged-save-matrix.txt`, header line 5) states that it ignored `tools`, so every "201 faithful" in it is silent on grants.

## Condition

Any save or inline run that goes through `agentsToManifestSteps` for a step whose loaded manifest declares `tools.read_files` and/or `tools.write_files` as `false`, with no `selections[id].tools` entry. That is every unchanged "Save as my version" except the Composer canvas's own save:

| seed | where | selections it passes | ex_A1_loop result |
|---|---|---|---|
| (a) IdeaInputPage hand-rolled `manifestAgents` | `IdeaInputPage.tsx:1286-1312` | gates only (`:1278-1285`) | tools true/true; greet.produces, check.consumes, done.consumes and three depends_on lost |
| (b) `agentsFromManifest`, the shared seam and ISS-1128's fix direction (a) | `manifestAgents.ts:115-126`, `:161` | gates only (`collectGates`) | tools true/true; every edge kept |
| (c) Composer canvas | `ComposerPage.tsx:388-401`, `userWorkflows.ts:780-799` | gates, plus tools when they deviate from read+write | faithful, tools false/false |

## Cause

`frontend/src/store/api/userWorkflows.ts:335-345`:

    const grants = selections?.[agent.id]?.tools;
    step.tools = {
      ...agent.tools,
      read_files: grants?.read_files ?? true,
      write_files: grants?.write_files ?? true,
      exec: false,

`agent.tools` is spread first and carries the loaded `false`; `read_files` and `write_files` are then assigned `selection ?? true`, which skips the loaded value. The comment above it ("default ON (an untouched step serialises exactly as it did before the Tools tab became editable)") is right for a NEW composer node and wrong for a loaded one. The canvas hides the defect by seeding `selections[id].tools` from the manifest (`manifestStepsToGateSelections`, `userWorkflows.ts:793-799`); `agentsFromManifest` and IdeaInputPage seed gates only.

## Expected vs actual

Expected: an unchanged save stores the built-in's own grants ([ISS-1128](20261008-2134-ISS-1128.md) "Expected": an unchanged save "stores the built-in's own plan, so its version runs like the built-in until the user changes something"). Actual: 201, and read+write on every step. Only the engine's reaction shows it: with `write_files` true the factory appends the `## How to deliver` block (`factory.py:727`), and with `read_files` true `_compose_context_message` stops pasting `consumes` (`engine.py:16753`). Both are what broke the decision step in the root card.

## Why the root cause implies it

The root run failed on a stored copy that granted write to a tool-free step. Something wrote that grant, and this line does it on two of the three seeds. Fixing only the roster seed (ISS-1128 direction a, retire the hand-rolled projection) leaves it in place: seed (b) keeps every edge and still flips the grants.

## Fix direction (INFERRED, not applied)

In the shared function: `read_files: grants?.read_files ?? agent.tools?.read_files ?? true`, and the same for `write_files`. An explicit selection wins, then the loaded grant, then the default for a new node. That one change covers every caller of `agentsToManifestSteps`: IdeaInputPage (`:1829`), LaunchWizard (`:1054`), ComposerPage save (`:920`) and ComposerPage inline Run once (`:1161`). Not a per-surface fix that seeds `tools` into each page's selections.
