introduced by `c9ec0149c` adding the fixtures.

## Symptom

```
test_manifest_parity.py     15 failed, 37 passed
test_id_alias_resolver.py   15 failed, 96 passed
```

The same two contracts, checked twice — once from the manifest, once from the compiled
plan:

```
test_planner_run_everywhere[ex_A1_loop]           ex_A1_loop must declare planner: run
test_compiled_planner_is_run_everywhere[ex_A1_loop]   assert 'skip' == 'run'
test_clarify_defaults_match_engine[ex_A1_loop]    clarify.defaults must reproduce the pinned copy
test_compiled_clarify_defaults_match_engine_dict[ex_A1_loop]
                                                  assert [] == ['target_audience', ..., 'priority']
```

15 = 7 fixtures x 2 contracts, + `sc001-test-fixture` failing the clarify half only (that
one predates this branch).

## Root cause

Not a bug in either side — a design collision. The `ex_A*` fixtures are deliberately
minimal: they declare `planner: skip` and empty `clarify.defaults` because an example
demonstrating one gate should not drag a planner pass and a clarification round through
every run. The parity contracts were written before an "examples" family existed and
assert the production shape of EVERY manifest on disk.

## Disposition — needs a product decision

1. **Exempt the `ex_*` family** in both contracts (an explicit skip list, or a
   `family: example` marker in the manifest the tests read). Keeps the fixtures minimal,
   which is the point of them.
2. **Make the fixtures conform** — add `planner: run` and the pinned `clarify.defaults`.
   Makes every example run a planner and a clarify round it does not need.

Option 1 is the smaller lie, but it weakens a contract deliberately written as
"everywhere". Whichever is chosen should be recorded as an ADR, since the next fixture
family will hit this again.
