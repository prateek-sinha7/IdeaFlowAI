# ISS-153

## Title

**A failed revision run shows the user no reason at all.** `_persist_terminal_status` inside `_drive_revision_to_queue` (`run_commands.py:2764`, ~line 2803) has NO `error` parameter — unlike the launch driver's failure branches (`_drive_launch_to_queue`), which always set `wr.error` alongside `wr.status = "failed"`. Every revision row in this database that has ever reached a terminal non-completed state carries `error IS NULL`, including genuinely failed ones, while failed non-revision runs carry real messages (e.g. `'The model rejected this request.'`). The three terminal branches that would need it: the `ValueError` branch (validation failure), the generic `Exception` branch (runtime failure), and the status-ladder's implicit fail-safe else. Proper fix: thread an `error: str \| None` parameter through `_persist_terminal_status` and set `swr.error = error` alongside the existing `status`/`completed_at` writes, populated from the same `str(exc)` / `error_msg` values already available at each call site.
