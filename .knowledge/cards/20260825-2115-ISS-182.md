[FIX-306](20260825-2115-FIX-306.md) stops NEW overrides containing the file-less blank template. It
does nothing about rows already saved.

Such a row still resolves, still renders in Advanced, and still fails every launch with
`invalid_agent_ids`. The only one known to have existed was repaired by hand during validation;
any other user's is untouched.

**Disposition:** resolved by [FIX-438](20260831-1954-FIX-438.md), which took the second option —
the launch-time message. `run_commands.py:2707` now detects a rejected `custom-agent:<instance_id>`
(which can only have come from a saved step, never from something the caller typed) and names it
plus the override to repair, instead of a bare 400. The allow-list itself is unchanged; the sweep
over other users' rows was not needed, since the message fires on the exact request that fails.
