# ISS-1175

Sibling of [ISS-1157](20261009-1500-ISS-1157.md) (register QA-KB-116), derived from its root cause: the one seam that turns a
workflow payload into roster rows, `agentsFromManifest` (`frontend/src/lib/manifestAgents.ts:157`), names a name-less built-in
step by its agent id. ISS-1157 is the IdeaInputPage surface (`/create/user-stories`, `app_builder`, `mulesoft_to_springboot`,
`dotnet_to_azure`). This card is the other host of the same seam, `LaunchWizard`, which serves `/workflow/create?mode=ppt`,
`prototype`, `prototype_v2` and `ppt_v2`.

Confidence: CONFIRMED at the component tier (jsdom render of the real `LaunchWizard` and `ReviewGatesSection` fed the live
payloads); not yet observed in a browser.

## Condition

A user holds an ENABLED override of one of those built-ins and cold-loads its wizard. Live state on :8000 (2026-10-09,
`evidence/qa-kb-116/analysis-02-live-override-state.txt`): `admin@velocity.ai` has `is_overridden: true` for `ppt`,
`prototype` and `ppt_v2` (rows created by the e2e suite); `pro@velocity.ai` has none.

## Expected vs actual

Expected (what a user without an override sees, and what the same page showed right after "Save as my version"): the
Review gates checklist, the Advanced roster and the canvas node titles read "Presentation Strategist Agent", "Deck Engineer
Agent", "Deck QA Agent". Actual, `/workflow/create?mode=ppt` with the admin payload:

| mode | rendered Review gates rows (analysis-03, U4 and U6) |
|---|---|
| ppt, override | `ppt-brief-analyst`, `ppt-composer`, `ppt-validator` |
| ppt_v2, override | `ppt-brief-analyst`, `ppt-composer`, `ppt-deck-qa-v2`, `ppt-code-generator` |
| prototype, override (function level, analysis-01 P7) | `prototype-specify`, `prototype-plan`, `prototype-analyze`, `prototype-build`, `prototype-validate` |
| ppt, no override (control, U5) | `Presentation Strategist Agent`, `Deck Engineer Agent`, `Deck QA Agent` |

## Why the root cause implies it

`frontend/src/components/workflow/LaunchWizard.tsx:609-616` takes the override rows from the seam and installs them whole:

```tsx
if (detail.is_overridden) {
  const proj = agentsFromManifest(detail, pipeline);
  setOverrideAgents(proj.agents);
  ...
  if (proj.agents.length > 0) setPipelineAgents(proj.agents);
```

The toggle path does the same twice: `:641` (`setPipelineAgents(overrideAgents)`, rows cached from the call above) and
`:649-652` (a saved-but-off override fetched on demand). `ReviewGatesSection` (`agents={pipelineAgents}`,
`LaunchWizard.tsx:1467`) prints `{agent.name}` (`ReviewGatesSection.tsx:251`), and `AgentsPopup` builds its canvas model
from `workflowCanvasModel(planManifestSteps, agents)` using the roster as the lookup (`AgentsPopup.tsx:2653`), so the
canvas inherits the ids. The seam defect is the same: `manifestStepsToAgents(raw)` with no lookup
(`manifestAgents.ts:157`) -> `name: step.name ?? id` (`userWorkflows.ts:718`), and `decorate` never restores the compiled
step's `name`, which the payload does carry (`steps[].name`).

`prototype_v2` is NOT affected: its eleven steps are custom-agent instances with explicit manifest names ("Reading
Planner", "Readers", ...; analysis-01 P6 and C3).

## Fix location

Not in `LaunchWizard`: fix `agentsFromManifest` (see ISS-1157). All three override call sites (`:610`, `:649`) and the plan
call site (`:596`, ISS-1176) then change with no edit here.

## For the test-writer

(`name: id, role: "Test Agent"`), so a label that degrades to the id is indistinguishable from a correct one. Use real names.
Ready-made red/green pair with the live payloads: `evidence/qa-kb-116/analysis-plugins/uiRoster.probe.test.tsx` (U6 red,
U5 control). Scaffold for a repo-resident test: `frontend/src/components/workflow/LaunchWizard.iss917.test.tsx` (its

named `steps[]`).
