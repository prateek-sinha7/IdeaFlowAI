# FIX-474

## What Was Wrong

When a user reopened a completed (terminal) run in the chat history view,
`seedTranscript` would seed the transcript and then auto-resolve cards that
should not remain actionable. However, the auto-resolve guard only covered
`cardKind === "gate"`. Narrator `clarify` cards (e.g. "Answer in Steps"
affordances) were excluded, so they remained unresolved and visually actionable
even on a finished run where no clarification is possible.

## Root Cause

`frontend/src/hooks/useRunChat.ts` — `seedTranscript` callback, `if (isTerminalRun)` block:

```ts
// Before (broken):
m.cardKind === "gate" && !m.resolved ? { ...m, resolved: true } : m
```

The condition only matched `"gate"` kind. Narrator `clarify` cards — written by
`chat_narrator.py` as a `CARD_CLARIFY` row and surfaced in the transcript as a
`ChatMessage` with `cardKind: "clarify"` — were not matched and thus kept their
`resolved: false` default, rendering an actionable UI element on a closed run.

FIX-245 already addressed the adjacent PANEL surface (clearing `questionnaireData`
on terminal reopen), but the chat CARD surface in the transcript was a separate
issue filed as ISS-141.

## What Changed and Why

**File:** `frontend/src/hooks/useRunChat.ts`  
**Location:** `seedTranscript` → `if (isTerminalRun)` block

```ts
// After (fixed):
(m.cardKind === "gate" || m.cardKind === "clarify") && !m.resolved
  ? { ...m, resolved: true }
  : m
```

Added `|| m.cardKind === "clarify"` to the existing condition. This is the
correct location: all callers of `seedTranscript` that set `isTerminalRun: true`
route through this single guard, so fixing it here fixes all paths (history-reopen
and family-seed). No other call sites need changes.

The fix is generic — keyed on `cardKind` string, never on any workflow name,
pipeline type, or agent id (SC-001/INV-1 compliant). The `resolved` flag is
checked first to avoid overwriting already-resolved cards (idempotent).
