## Description

**INFERRED sibling of [ISS-390](20260828-2048-ISS-390.md)** (root cause of
BUG-20260828-014937-runs-id-stream) — derived by grepping every caller sharing the
`status === "failed" || status === "cancelled" || status === "degraded"` triad. Not yet
independently reproduced in a browser; this is a code-read lead, not a confirmed
defect.

`frontend/src/components/history/RunDetailPage.tsx:230-234` — the summary column
mounted as the left panel of the Run History library's selected-run view (via
`WorkflowHistory.tsx:608`, SHELL-03's single source for the KPI strip, agent breakdown
and failure banner):

```ts
const terminalFailure =
  summary.status === "failed" ||
  summary.status === "cancelled" ||
  summary.status === "degraded";
const cancelled = summary.status === "cancelled";
```

Used at `RunDetailPage.tsx:373-382` (Agents tab): `terminalFailure ? <DegradedRunAffordance
failedAgents={...} agentNameById={...} cancelled={cancelled} /> : summary.agents.length
> 0 ? <plain agent list> : ...`. For a diverted run — terminal, `terminalFailure` false,
but `summary.agents.length > 0` (the seeded repro run has 2/3 agents that actually ran)
— this takes the plain-list branch: the two agents that ran render exactly as they
would for an ordinary successful run, with no indication the pipeline stopped for good
at a divert point and the 3rd agent never ran. `DegradedRunAffordance` (the component
that would carry that explanation) never mounts for this status.

This is the same triad ISS-390/[ISS-282](20260828-1710-ISS-282.md) found in
`PreviewPanel.tsx:696-699` and [ISS-391](20260828-2049-ISS-391.md) found in
`WorkflowHistory.tsx:593-596` — a fourth hand-copied instance of the identical
`failed || cancelled || degraded` literal, none of them updated when `"diverted"`
joined the terminal vocabulary.

## Reproduction (not yet run — for the next validator/test-writer)

1. Sign in as qa-admin. Open the Run History library, select the seeded diverted run
   "Ex A4 Human Divert" (`940ca699-b21b-4666-8e44-3370a08a4561`). Its summary column is
   `RunDetailPage` (confirm via `GET /api/runs/940ca699-b21b-4666-8e44-3370a08a4561`:
   `status: "diverted"`, 2 entries under `agent_outputs`).
2. Open the Agents tab in the summary column.
3. Expected if this reproduces: the two agents that ran are listed as plain
   completed-looking entries, with no amber/failure banner and no mention that the run
   diverted or that a third agent never ran.
4. Contrast: the same tab for a `failed`/`cancelled`/`degraded` run with no content
   should show `DegradedRunAffordance` instead of the plain list.

## What would settle it

`RunDetailPage.test.tsx` already exists (`frontend/src/components/history/`) but has no
`diverted`-status case per a targeted grep of that file — adding one that asserts
`DegradedRunAffordance` (or a diverted-specific equivalent) does NOT mount, and the
plain-list branch renders instead, would confirm this without a browser.
