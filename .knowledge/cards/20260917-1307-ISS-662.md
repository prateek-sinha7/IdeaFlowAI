## Fixed (QA-KB-063, 2026-10-07)

Fixed by [FIX-726](20261007-1833-FIX-726.md), as "Where the fix belongs" prescribes. Only tests
and specs changed; the narrator did not. `run_detail.CLARIFY_ANSWERED`
(`re.compile(r"Clarifications( round \d+)? answered", re.I)`) is now the one definition. S-23-45
searches with it. S-18-08 uses it and stays an inverted guard on text identity (constraints 2
and 3). The Gherkin at `18-chat-lane.feature.md` and `22-handoff-and-gates.feature.md` quotes the
numbered texts, and D-21 is annotated as narrowed. Observed:
`test_e2e_clarify_probes_numbered.py` 3 XPASS(strict); S-18-08 went from failed
"(4 asks, 0 answers) — D-21 is fixed" to passed on `/runs/b40eabd0-d7e2-4bc2-bc42-99ef6a147bff`.
Evidence is in `evidence/qa-kb-063/`.

## What is stale

[FIX-517](20260917-1307-FIX-517.md) (register bug QA-PS-003) numbers the concierge chat's clarify cards:
`questionnaire_complete` now reads `Clarifications round N answered`, and
`questionnaire_ready` reads `Round N: Before I build, I need to lock a few things down.`
Three e2e-tier artifacts still encode the old round-less text:

- [test_controls_inventory.py](../../tests/integration/e2e/suites/23_controls_inventory/test_controls_inventory.py)
  lines 625-627: S-23-45 opens the newest run and checks `"Clarifications answered" in body`,
  skipping when it is absent. A run recorded after the fix reads `Clarifications round 1 answered`,
  so the scenario **skips instead of asserting**. Coverage is lost silently; no test goes red.
- [test_chat_lane.py](../../tests/integration/e2e/suites/18_chat_lane/test_chat_lane.py)
  lines 33-34 and 228-257: S-18-08 is the inverted `@defect` guard for D-21, which is this
  defect. It counts `CLARIFY_ANSWERED = "Clarifications answered"`. Once the completed run it
  selects was recorded after the fix, it fails with "D-21 is fixed; rewrite this as the spec's S-18-08".
  That flip is by design, and the test needs rewriting when it happens.
- [18-chat-lane.feature.md](../../tests/integration/screens/18-chat-lane.feature.md)
  lines 212-223: the S-18-08 Gherkin still says `"Clarifications answered" appears once`.
  A two-round run now shows two distinct numbered cards.

S-18-07 (the `CLARIFY_ASK` substring probe) still matches, because the round prefix keeps the
old sentence verbatim.

## Why it was not fixed with FIX-517

Neither of the cards that fix resolved names these files. They are browser-tier tests, and
rewriting an inverted defect guard is a spec decision. `chat_reply` rows are persisted at emit
time, so runs recorded before the fix keep the old text. Until a post-fix run is the one these
probes select, they stay green on the seeded QA runs.

## Disposition

Open. This is not part of QA-PS-003's verification. Resolve it once the three artifacts above
are rewritten for numbered rounds.

### Where the fix belongs

Tests and specs only. Reverting the narrator would bend the app to the tests: FIX-517 locked
"numbers clarify cards from the GENERIC `round` payload field only" and "An event with no `round` ...
keeps the pre-fix text byte-for-byte", and QA-PS-003 is CLOSED. Define the vocabulary ONCE in
`tests/integration/e2e/framework/locators/run_detail.py`. It already holds `ANSWER_IN_STEPS` (`:31`)
and compiled regexes such as `ARTIFACTS_PANE` (`:71`), and both tests already import it (`RD` in
`test_controls_inventory.py:38`, `L` in `test_chat_lane.py:25`):

```python
CLARIFY_ANSWERED = re.compile(r"Clarifications( round \d+)? answered", re.I)
```

Use `page.get_by_text(L.CLARIFY_ANSWERED)` in S-18-08 and `RD.CLARIFY_ANSWERED.search(body)` in
S-23-45, so the next narrator wording change is a one-line edit. `re.I` also covers the
`N clarifications answered` branch at `chat_narrator.py:169`, which no live producer reaches: the only
`questionnaire_complete` emit (`clarify_engine.py:380`) sends no count.

### Constraints a correct fix must respect

1. Accept BOTH shapes. Rows persisted before FIX-517 keep the round-less text, so a numbered-only
   probe turns S-23-45 back into a skip on older data.
2. S-18-08's count-only assertion goes vacuous once the regex matches numbered text: a correctly
   fixed two-round run also has two asks and two answers. A guard that stays inverted must compare
   TEXT identity (`len(set(texts)) < len(texts)`), not counts.
3. Do not flip S-18-08 into a positive "every ask is distinct" test while
   [ISS-993](20261002-0500-ISS-993.md) is open. On today's data it is red for that reason (agent
   `ask_user` passes all read "Round 1"), and the verifier would loop on QA-KB-063. Preferred now:
   keep it an inverted `@defect` guard (`tests/integration/e2e/pytest.ini:36`, "asserts today's
   wrong behaviour, not the desired one") on text identity, make the failure message say "D-21 is
   fixed" only when the texts really differ, rewrite the Gherkin at `18-chat-lane.feature.md:212-223`
   to say what is observed now, and annotate D-21 as narrowed. When the product numbers `ask_user`
   passes the guard flips and is rewritten as the spec's S-18-08, as its message already says.
4. Keep the scenario ids. `tests/integration/capture/_scenarios.py` links spec and test by `S-NN-NN` alone.
5. The triage sketch's S-23-45 regex is right (add `re.I`); its S-18-08 sketch ("one numbered card
   per round, distinct text and ids") only fits a single clarify pass (see 3).
