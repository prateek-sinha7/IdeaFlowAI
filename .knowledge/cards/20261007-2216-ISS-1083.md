# ISS-1083

**Register source:** `QA-KB-076` in root `LEDGER.md` / `BUGS.md` (sibling, derived during its analysis on 2026-10-07).
**Root card:** [ISS-903](20261001-2145-ISS-903.md) holds the mechanism (the guard sees only the cite shapes and files it was hand-listed with) and the fix. This card is the "other callers" case: cites that point INTO the guarded modules from files the guard does not read.

**Claim status: INFERRED (sibling).** I read every cited line below in the current tree (`evidence/qa-kb-076/04-analyze-inbound-stale-cites.txt`) and each one holds something other than what the citing comment says. No validator has reproduced it as a failing test, and QA-KB-076 does not report it.

## What is wrong

The guard scans six files for cites written FROM them (`_SCANNED`, `test_run_shutdown_stale_citations.py:17-24`). A cite written in any other file, pointing at one of those modules, is invisible to it. [ISS-104](20260812-1312-ISS-104.md) counted inbound cites as part of its blast radius (six of them sat in `test_shutdown_reachability.py`, a scanned file). Six more sit outside the list:

| Citing site | Cites | What the cited line holds at HEAD | Name instead |
|---|---|---|---|
| `backend/tests/unit/test_checkpointer_shutdown_budget.py:55` | `checkpointer.py:140-144` ("no internal timeout wrapper") | `:140` closes the docstring, `:141` is `global _checkpointer, _pool, _closed`, `:144` is `_closed = True`; the `asyncio.wait_for(` is at `:152` | `close_checkpointer`'s `asyncio.wait_for(pool.close(), ...)` |
| `backend/tests/integration/api/test_sse_stream_api.py:902` | `run_stream.py:197` (`await live_queue.get()`) | a bare `#` comment line; the call is at `:542`, inside `_iter_sse_frames` | `_iter_sse_frames`'s `await live_queue.get()` |
| `backend/tests/integration/api/test_sse_stream_api.py:903` | `run_stream.py:281` ("the endpoint bound the queue OBJECT") | `run_id,` inside the slow-revocation `logger.warning(` | `stream_run_events`, before the generator body runs |
| `backend/agents/authz.py:445` | `run_stream.py:251-265` (the SESSION-LESS `ScopedStore`) | the `FAIL CLOSED` revocation-check docstring down to `timeout=_REVOCATION_CHECK_TIMEOUT_SECONDS,` | `stream_run_events`'s `stream_store = ScopedStore(` |
| `backend/tests/conftest.py:197-198` | `app/core/config.py:130` (`AWS_REGION`), `:123` (`BEDROCK_INFERENCE_PROFILE_ID`), `:118` (`BEDROCK_MODEL_ID`) | `:123` is `# out to.`, `:130` is a comment, `:118` is blank; the settings are at `:149`, `:142`, `:124` | the three `Settings` fields by name |
| `backend/tests/unit/app/test_iss102_live_model_guard.py:5` | `app/core/config.py:118/:123/:130` | the same three lines | the same three names |

Two of these repeat pointers the earlier cards already found stale. `run_stream.py:197` is the pointer [ISS-885](20261001-2114-ISS-885.md) found stale at `run_engine.py:93`, and `checkpointer.py:140-152` is the pointer ISS-104 found stale in the reachability test's budget table. [FIX-690](20261001-2145-FIX-690.md) converted both inside the scanned files. The same drifted targets survive, copied, in files the guard never opens.

Scale, not a defect count: the same broad pattern finds 191 lines in 56 files under `backend/app` and `backend/agents` that the guard does not scan. ISS-885 treated that wider set as unverified leads and said not to sweep it. These six are the part of it that I verified.

## Why the root cause implies it

[ISS-903](20261001-2145-ISS-903.md)'s mechanism is a guard whose world is hand-listed. `_SCANNED` is read for outbound cites only, so a cite into a guarded module is covered only when the citing file happens to be on the list. Copy-pasted pointers move on to files that are not.

## Expected vs actual

- Expected: no file under `backend/` cites a line number of a guarded module.
- Actual: six cites in five files point at unrelated lines, so a reader following one lands in the wrong place, the harm ISS-104 names.

## Fix

1. Convert the six sites to the names in the last column. Comment and message-string edits only, no behaviour change. `authz.py` is kernel-side (`backend/agents/`), and the edit is a docstring line, so INV-1 and SC-001 are untouched.
2. Decide the guard's reach. A bounded option that stays inside ISS-885's "do not sweep" line: one extra lint asserting that no file under `backend/` (excluding `.venv`) matches `<basename>\.(py|sh) ?:\d+` for the guarded basenames `run_shutdown`, `run_engine`, `run_stream`, `checkpointer`, `docker-entrypoint`, `test_shutdown_reachability`, and `core/config` (qualified, because a bare `config.py` also matches uvicorn's). Today it reports exactly the six sites (greps over py, sh, yml, md and toml files in `evidence/qa-kb-076/04-analyze-inbound-stale-cites.txt`), so it goes red, then green after step 1. Not doing step 2 is acceptable; say so on the card.
