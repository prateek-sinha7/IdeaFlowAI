## Why it was invisible to the theme

Dark mode is a token swap - `:root[data-theme="dark"]` redefines `--color-*`,
and every surface that reads a token follows. A component that writes
`bg-white` or `#1B2A4A` directly is not participating in that mechanism at all,
so it is not "wrong in dark mode" so much as outside it. The Discovery tab
looked correct for as long as nobody switched themes, which is exactly why it
survived to here.

The corollary is the deliberate exclusion list: the modal overlays and
`DesignSpecView` also carry hardcoded colours, and those are correct. The test
is not "is this class a literal" but "is this surface supposed to track the
theme". Overlay chrome sitting on a dark scrim, and a panel designed to be dark,
both answer no.
