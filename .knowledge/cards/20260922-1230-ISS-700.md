## Summary

Register bug **QA-PS-023**: the Preview tab at `/runs/{id}` shows the last
agent's raw reasoning text rendered above the actual HTML deliverable —
paragraphs like *"The composer file contains no artifact. Let me check what
files exist in the `.agents/` directory…"* appear inside the iframe before
slide 1, as if the agent's stream-of-thought was pasted directly into the
page.

## Reproduction (cycle 1 of 3 — deterministic, not a race)

The register's linked run id (`bf9f230d-6123-4d42-9089-ffde5c31d4f0`) is gone
(404 — data churn since the report), so the exact original run could not be
re-opened in the browser. The defect is deterministic code logic, not an LLM
timing race, so it was reproduced 3/3 by exercising the real production
resolver directly with an input shaped like the reporter's transcript
(no browser/LLM needed to hold this path steady):

```
$ cd backend && .venv/bin/python3 -c "
from agents.capabilities.deliverables.streamed_text import StreamedTextResolver
class Ctx:
    last_streamed = '''The composer file contains no artifact. Let me check what files exist in the .agents/ directory: ...
<!DOCTYPE html>
<html><head><title>Deck</title></head><body>slide 1</body></html>'''
out = StreamedTextResolver().resolve(Ctx())
print('STARTS WITH PROSE:', not out.strip().startswith('<!DOCTYPE'))
"
STARTS WITH PROSE: True
```

Ran 3 times, same input, same result each time (pure function, no state) —
3/3 CONFIRMED at the resolver level.

## Root cause

`backend/agents/capabilities/deliverables/streamed_text.py:44-46`:

```python
def resolve(self, ctx: Any) -> Any:
    last_streamed = getattr(ctx, "last_streamed", "") or ""
    return unwrap_artifact(last_streamed)
```

`unwrap_artifact` (`backend/agents/capabilities/deliverables/_artifact.py:20-33`)
only strips a wrapper when the text contains a literal `<artifact>…</artifact>`
tag:

```python
if text and "<artifact" in text:
    m = re.search(r"<artifact[^>]*>\s*([\s\S]*?)\s*</artifact>", text, re.IGNORECASE)
    if m:
        return m.group(1).strip()
return text
```

When the last agent's streamed output is prose reasoning immediately followed
by raw `<!DOCTYPE html>…` — with **no** `<artifact>` wrapper — the `if` guard
never matches and the function falls through to `return text`: the prose and
the HTML both pass through unchanged. `engine.py` (`ectx.last_streamed =
results[-1]["output"]`, resolved via `_resolver.resolve(ectx)` around
`backend/agents/execution_engine/engine.py:7189`) hands this straight to
`final_output`, and `page.tsx` sets `genericDeliverable.content = finalOutput`
verbatim.

`frontend/src/components/preview/PreviewPanel.tsx:243` (`GenericDeliverablePreview`)
renders that content unmodified:

```tsx
srcDoc={withDarkIframeDefault(content, theme === "dark")}
```

No stripping of text preceding `<!DOCTYPE html>` happens anywhere in the
chain, so the browser renders the prose as document text nodes before the
`<html>` element paints — exactly the reported symptom.

## Expected vs actual

- Expected: Preview tab shows only the rendered HTML deck; no text before
  slide 1.
- Actual: any prose the model emits ahead of the HTML (when it skips the
  `<artifact>` wrapper) is prepended verbatim and rendered as visible text in
  the iframe.

## Trigger

Conditions under which this fires:
- `deliverable.strategy == "streamed_text"` (the default for custom
  workflows, `backend/app/api/user_workflows.py:107`) — NOT `single_file`
  (used by the built-in prototype workflow, which reads clean HTML off the
  sandbox file and is unaffected — verified live: the three current
  `prototype.html` runs on this instance all start with `<!DOCTYPE html>`
  cleanly).
- The final agent's streamed output contains narrative text before its HTML
  and does **not** wrap the HTML in an `<artifact>…</artifact>` tag.

No currently-completed run on this instance reproduces the exact end-to-end
browser symptom live (no existing `streamed_text` run has an HTML deliverable
with leaked prose in front of it at time of validation — the reporter's run
id is gone, and generating a fresh run to force this specific LLM behaviour
was out of scope for validation). The resolver-level reproduction above is
the mechanism proof: given the exact input shape the reporter described, the
production code path produces exactly the reported artifact, deterministically.

## Fix direction (not applied — issue only)

`streamed_text` resolution should not trust raw model prose as the
deliverable. Either extract only the HTML/document portion of
`last_streamed` (e.g. slice from the first `<!DOCTYPE` / `<html` occurrence
when the strategy's declared shape is HTML) or require agents on this path to
always wrap in `<artifact>` and treat an unwrapped HTML-shaped output as a
producer error rather than silently emitting it as-is.
