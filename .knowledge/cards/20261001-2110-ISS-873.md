# ISS-873

> **INFERRED sibling** of [ISS-639](20260831-1645-ISS-639.md), derived during the QA-KB-045 analysis (2026-10-01). The code and the substitution below were READ and EXECUTED offline; the boot-time cost of this exact call site was not measured end to end (see "What would settle it").

## Condition

`restore_non_terminal_runs` (`engine.py:12582`) calls `_is_resumable_in_flight(wr)` once per non-terminal `workflow_runs` row at backend start: from branch (a) (`engine.py:12690`, only when a durable open gate was derived) and branch (b) (`engine.py:12761`). There is no other non-test caller (`grep -rn _is_resumable_in_flight backend/ --include='*.py'`).

## Code (CONFIRMED, read in the working tree of branch feat/user-stories-v2)

`engine.py:12993-12998`:

```python
store = ScopedStore(owner_id=owner_id, workspace_id=wr.workspace_id)
# Any persisted step state => resumable. read_events(after_seq=0) returns the
# whole durable tail; a single row is enough evidence.
if await store.read_events(wr.id, after_seq=0):
    return True
```

The comment states the requirement (ONE row is enough) and the call materialises EVERY row (`authz.py:401-414`, `query.order_by(RunEvent.seq.asc()).all()`) to answer a boolean.

## Expected vs actual

- **Expected:** a bounded probe, `if (await store._max_event_seq(wr.id)) > 0: return True`: one `SELECT max(seq)` served by `uq_run_events_scope_seq` (an Index Only Scan Backward, about 1 ms on the largest local run).
- **Actual:** the run's whole log is read, sorted and turned into ORM objects. On the local corpus that is 2.2-7.0 s per run at 37k-137k rows (two measured passes of the same `read_events` path; evidence below), once per non-terminal run, serially, inside the boot scan.

## Why the root cause implies it

Same idiom as [ISS-639](20260831-1645-ISS-639.md): a whole-log `read_events(after_seq=0)` used to derive ONE scalar where the bounded `ScopedStore._max_event_seq` is an exact substitute, in the same restart tier and the same file. The scalar here is a boolean.

Exactness (CONFIRMED by execution): `read_events(after_seq=0)` returns rows with `seq > 0`, so `bool(read_events(...))` is true iff some in-scope row has `seq > 0`, which holds iff `max(seq) > 0`. Over 8 scope/run cases (own scope, a second workspace, a second owner, `workspace_id=None`, unknown workspace, unknown owner, empty run, missing run) the two forms agreed in every case.

## A consequence worth knowing (INFERRED)

The probe sits in `try: ... except Exception: return False` (`engine.py:13003-13004`, commented "no durable substrate (offline) -> not resumable"). A `StoreTimeout` (`authz.py:78`, a `RuntimeError`; bound `_STORE_CALL_TIMEOUT_SECONDS = 10.0`, `authz.py:74`) would therefore read as "not resumable", and for branch (b) the classifier falls through to branch (c), which marks the run `failed` ("Run abandoned: backend restarted ...", `engine.py:12863-12874`) instead of resuming it. The measured idle-box reads (2.2-7.0 s) are inside the 10 s bound, so this is not shown to fire today; it is the margin the bounded probe removes. Branch (a) is gentler: a False leaves the gate un-armed ("harmless park", `engine.py:12758-12760`).

## Fix shape

One line at `engine.py:12997`: `if (await store._max_event_seq(wr.id)) > 0:`. Keep the `except Exception: return False` degrade as is. It is a separate proof obligation from [ISS-639](20260831-1645-ISS-639.md) (a different function and a different caller set, covered by the branch (a)/(b)/(c) tests in `tests/integration/agents/test_restart_resume_db.py`), so it is filed separately, though one diff can carry both.

## What would settle it

- A counting test in the style of `backend/tests/agents/test_resume_marker_seq_allocation.py`: seed a non-terminal run with a few events, wrap `ScopedStore.read_events`, call `engine._is_resumable_in_flight(wr)`. Expect 0 `read_events(after_seq=0)` calls and a `True` result (today: 1 call).
- For the consequence paragraph: make a session-less store's read exceed `agents.authz._STORE_CALL_TIMEOUT_SECONDS` (monkeypatch it low plus a slow read) and assert the run is not abandoned.

## Fix (2026-10-01)

Fixed by [FIX-688](20261001-2140-FIX-688.md) with the one-line shape above:
`if (await store._max_event_seq(wr.id)) > 0:` (`engine.py:12997`). The two-line comment above it, which described
the replaced call, was updated. The `except Exception: return False` degrade is untouched. With `_max_event_seq`
raising `RuntimeError`, or the real `StoreTimeout`, the probe still returns False.

On a seeded fixture, the old form, the new form and the classifier result agree for own-scope rows (True),
other-scope rows only (False) and no rows (False) (`evidence/qa-kb-045/04-fix-probe-degrade-and-equivalence.txt`).
`test_is_resumable_in_flight_probe_is_bounded` now reports `XPASS(strict)`, and the marker is left for the
6-verifier.

The `StoreTimeout` consequence paragraph has no test of its own. The probe it describes is now the bounded
aggregate.
