# BUG-009 — od_ppt can complete with an empty deck output (LV-02 recurrence)


### BUG-009 — od_ppt can complete with an empty deck output (LV-02 recurrence)  [🟠 major] [ROOT-CAUSED]

- **Found:** 2026-07-16 · backend root-cause investigation (upstream of BUG-003's blank Preview + no-op revise) · surface: `od_ppt` pipeline deliverable persist (`WorkflowRun.output`). Live shape: a `completed` od_ppt run whose `wr.output` is empty/`NULL` (deck never persisted), so the FE Preview is blank and the reopen-revise silently no-ops (BUG-003).

- **Symptom:** An `od_ppt` run finishes with `status="completed"` but `wr.output` is empty (or non-deck narration text). No `presentation.pptx` deliverable is persisted; no `kind="deliverable"` artifact_ref is written, so the FR-014 revision chain also has no parent deck to revise. Intermittent — the same manifest/agents produce a correct 18k-char deck on most runs (Phase-15 live proof, register 1605) and an empty/narration deliverable on others.

- **Root cause (investigation agent — read `.planning/IMPLEMENTATION-REGISTER.md` global to EOF incl. LV-02 refs 79/1487/1495/1512/1553/1559/1594/1605 + `.planning/SSE-QA-BUG-LOG.md` BUG-003; traced the deck pipeline end-to-end in source + git-blame):**

  - **The deliverable is defined as the LAST agent's stream, and the last agent is a QA validator that must re-emit the entire deck.** od_ppt's manifest declares `deliverable: strategy: ppt, name: presentation.pptx` (`backend/agents/workflows/od_ppt/workflow.yaml:11-13`) and three steps `od-ppt-brief-analyst → od-ppt-composer → od-ppt-validator`, the **validator LAST** (order 3) (`workflow.yaml:16-25`). The engine binds `ectx.last_streamed = results[-1]["output"]` (`backend/agents/execution_engine/engine.py:2395`) — `results[-1]` is the last step = **od-ppt-validator**. Then `final_output = _resolver.resolve(ectx)` (`engine.py:2406`) routes to the `ppt` resolver.

  - **The `ppt` resolver reads ONLY the validator's stream** (`backend/agents/capabilities/deliverables/ppt.py:63-65`): `return unwrap_artifact(sanitize_carousel_deck_html(ctx.last_streamed))`. `unwrap_artifact` is **first-match** over `<artifact[^>]*>…</artifact>` and **passes the text through unchanged when there is no `<artifact>`** (`backend/agents/capabilities/deliverables/_artifact.py:34-38`). The resolver never reads the sandbox and never looks at any earlier agent's stream.

  - **Why `final_output` is empty/non-deck (the actual LV-02 mechanism — a SOFT prompt contract on the last agent, three failure shapes):** the validator (`od-ppt-validator/AGENT.md`) carries a Phase-15 `## OUTPUT CONTRACT — NON-NEGOTIABLE` (`AGENT.md:23-38`) demanding it begin with `<artifact` and re-emit the complete deck. That is a *prompt instruction on a cheap live model (Haiku), not a hard guarantee.* On a non-compliant completion the resolver yields non-deck/empty:
    - **(a) narration, no artifact** → `unwrap_artifact` finds no `<artifact>` and returns the QA narration verbatim → `final_output` is non-empty but NOT a deck (the 2026-06-12 LV-02 shape: a 1,350-char QA report won over the 21k deck; register 1495).
    - **(b) empty assistant stream → strictly EMPTY output** → the validator declares `tools: [workspace]` (`AGENT.md:17-18`), so it can emit an all-tool-call turn (`write_file` the deck to the sandbox) and stream *no* assistant text → `results[-1]["output"] == ""` → `ectx.last_streamed == ""` → `final_output == ""`. The resolver reads the stream, **not** the sandbox, so the disk deck is discarded. This is BUG-003's observed empty `fullRun.output`.
    - **(c) leading status artifact** → a first `<artifact>…status…</artifact>` before the deck artifact → first-match `unwrap_artifact` extracts the status blob, not the deck (register 1595 warns of exactly this).

  - **The engine's only fallback does NOT catch it.** `engine.py:2407-2413` falls back to `streamed_text` **only when `final_output is None`**. `PptResolver.resolve` returns a **string** (possibly `""`), never `None` — so the empty case bypasses the fallback entirely.

  - **The empty deliverable then fails to persist and poisons the revision chain.** `final_output` rides `pipeline_complete` → read at `backend/app/api/run_commands.py:1416` → persisted only under `if final_output: wr.output = final_output` (`run_commands.py:1445-1446`), so an empty `final_output` leaves `wr.output` unset. In the engine, `if final_output and results:` (`engine.py:2428`) likewise **skips the `kind="deliverable"` artifact_ref write**, so a later `run_revision` (FR-014) has no parent deck (the server-side reason BUG-003's revise no-ops even on the REST path).

  - **A valid deck exists one stream earlier and is thrown away.** The od-ppt-composer (Deck Engineer, step 2) streams the complete deck wrapped in a single `<artifact>` as its contract (`backend/agents/prompts/od-ppt-composer/AGENT.md:50-52, 104-117`) and declares `produces: [od-ppt-composer]` (`AGENT.md:18-19`). The engine therefore captures the composer's deck in TWO durable places at resolution time: `results[-2]["output"]` (a local, `engine.py:3664`) **and** a typed `ArtifactRef` `kind="od-ppt-composer"` in `ectx.artifacts` (`engine.py:3651-3660`, reachable via `ectx.artifacts.tree(ectx.run_id)` — the engine already scans that tree at `engine.py:2441`). The `ppt` resolver consults **neither**. So the validator is a **single point of failure between a good deck and the deliverable.**

  - **Classification — PROMPT-RELIABILITY, not a parser bug.** The parser (`unwrap_artifact`/`sanitize_carousel_deck_html`, ppt.py/_artifact.py) behaves exactly per contract: given a compliant validator stream it yields the deck (Phase-15 live-resolved an 18,661-char deck, register 1605). The defect is that the *deliverable-producing agent is an LLM QA pass that unreliably re-streams a ~20k-char deck.* Phase 15 mitigated it with a prompt contract; a prompt contract is inherently non-deterministic and **recurs** (BUG-003, 2026-07-16, states this outright). The `tools: [workspace]` grant is an aggravator specific to the strict-EMPTY shape (b).

  - **Golden blind spot (why offline never catches it).** The characterization scripted model drives od-ppt-validator as **text-only** and always emits the deck as one `<artifact>` (`tests/agents/_scripted_model.py:293-296, 323-340` — note it literally comments the validator as "text-only (no filesystem tools)", contradicting the live `tools: [workspace]`). So the od_ppt golden can never reproduce shapes (a)/(b)/(c); LV-02 is a live-only escape.

  - **Pre-existing verdict — PRE-EXISTING and a KNOWN, deliberately prompt-only-mitigated failure mode (LV-02); NOT introduced by the feat/ui-2 / SSE work.** `git blame`: the ppt resolver's stream-only `resolve` = `d677944dd` (imran-hex, **2026-06-08**, Phase 7); the persist guard `if final_output:` (`run_commands.py:1445`) = `3d951b2da` (imran-hex, **2026-07-08**, Phase 29 era); the engine `last_streamed = results[-1]` binding = Phase 7. The validator output contract was added by Phase 15 (**2026-06-13**) and then **re-touched again** by `262496c6` "fix: PPT pipeline preview generation and display" (Prateek Sinha, **2026-06-18**, which also changed +24 lines of `engine.py` and the brief-analyst AGENT.md). Despite two prompt iterations the failure recurs live — confirming the mitigation is soft. Same LV-02 the register tracks as "closed by Phase 15 but recurs" (register 1512).

- **Fix (PROPOSED — investigation only, NOT applied; respects the READ-ONLY locks on `ppt.py`/`_artifact.py`, register 1594):**

  There is a genuine tension: register 1559/1594 **LOCK** the LV-02 remedy to "the validator's output contract" and explicitly REJECT a `deliverable: ppt` resolver fallback. But a prompt contract **cannot be a hard guarantee** (it is what already recurs). So the two options trade off compliance vs. certainty:

  1. **PRIMARY (lock-compliant, ships now, but SOFT — does not fully guarantee the deck).** Harden the validator toward a strict pass-through in `backend/agents/prompts/od-ppt-validator/AGENT.md`:
     - Remove `workspace` from `tools:` (`AGENT.md:17-18`) → make it **text-only**, eliminating failure shape (b) (it can no longer sink the deck to disk and stream nothing; all output is forced into the stream). This also realigns the live agent with the scripted golden's own "text-only" assumption (`_scripted_model.py:293`). ⚠ Note register 1593 cautions against "normalizing" this intentional `tools: [workspace]` (RESEARCH Pitfall 4) — reversing it is a conscious decision to make here, justified because the validator makes no legitimate use of the workspace (it only re-emits text).
     - Keep/strengthen the begin-with-`<artifact` + exactly-ONE-artifact clauses (already present, `AGENT.md:25-38`) to bound shapes (a)/(c).
     - **Limit:** shapes (a)/(c) remain possible on any live model — this reduces recurrence, it does not eliminate it. Not a hard guarantee.

  2. **DURABLE (the only option that makes the deck a HARD guarantee) — a NEW opt-in deliverable resolver, ZERO kernel/locked-file edits.** Add `backend/agents/capabilities/deliverables/ppt_guarded.py` registered as `@register("deliverable", "ppt_guarded")`, and flip **one manifest line** `backend/agents/workflows/od_ppt/workflow.yaml:12` `strategy: ppt` → `strategy: ppt_guarded`. The engine already routes any declared strategy via `registry.resolve("deliverable", compiled.deliverable.strategy)` (`engine.py:2405`) — no kernel edit. The new resolver:
     - `deck = unwrap_artifact(sanitize_carousel_deck_html(ctx.last_streamed))` by **importing** the locked helpers from `_artifact.py` read-only (import is allowed; the files are not edited);
     - returns `deck` when it is a real deck (`<!DOCTYPE html` / `<section` present) → **byte-identical to `ppt` on the happy path**;
     - else recovers the deck from `ctx.artifacts.tree(ctx.run_id)` — the most-recent earlier artifact that unwraps to a deck (the composer's `od-ppt-composer` ref, `engine.py:3651-3660`) — a **structural** deck-shape match, no workflow-name/agent-id branch in the kernel (SC-001/INV-1 safe).
     - **INV-3 stays green:** the od_ppt characterization golden's scripted validator always emits a proper `<artifact>` deck, so `ppt_guarded` returns byte-identical output to `ppt`; the fallback branch only fires on the live bug shape the golden never produces (re-run the targeted characterization battery to prove `git status --porcelain golden/` is empty).
     - **Honest caveat:** this partially revisits the register-1559/1594 LOCK (which pinned the fix to the prompt and rejected a resolver fallback). It differs from the rejected form in that it is a NEW registered capability (not an edit to `ppt.py`/`_artifact.py` and not a kernel change) and preserves INV-3 — but the lock owner should sign off on reversing that decision before applying.

  - **Do NOT:** edit `ppt.py`/`_artifact.py` (READ-ONLY, register 1594); add a `if final_output is None`→also-empty branch or a deck scan inside the kernel resolution block (`engine.py:2405-2413`) — that is the register-rejected engine-side change and is golden-sensitive; or "fix" it purely by enlarging the validator prompt again (already done twice, still recurs).
  - **Optional (architectural, larger — out of minimal scope):** stop making a QA agent the deliverable producer at all — e.g. give the validator `revises_existing`/sandbox-edit semantics so the deliverable is read from the composer-written + validator-edited sandbox file rather than re-streamed. Removes the re-emit fragility entirely but is a manifest+strategy change, not minimal.

- **Verify (fail-before / pass-after — proposed):**
  1. **Fail-before:** drive the real od_ppt engine with a scripted validator that emits (a) QA narration with no `<artifact>`, (b) an empty assistant stream, and (c) a leading status artifact; assert `final_output`/`wr.output` is empty or non-deck and **no** `kind="deliverable"` ref is written (`engine.py:2428`). (Extend `tests/agents/test_prompt_contracts.py`'s LV-02 composition test, which currently only pins the *compliant* path.)
  2. **Pass-after (option 2):** same three scripted validators through `strategy: ppt_guarded` → `final_output` is the composer's deck (`<section …>` present) every time; `wr.output` persisted; deliverable ref written; a subsequent `od_ppt_output` revision resolves a real parent deck.
  3. **No-regression / INV-3:** re-run the targeted characterization battery — the 5 goldens stay byte-identical (`git status --porcelain golden/` empty); a compliant validator still yields the identical deck bytes as `strategy: ppt`.
  4. **Live:** one real-Haiku od_ppt run under the failure conditions (or repeated runs) → Preview renders the deck, `wr.output` non-empty, revise fires (closes the BUG-003 upstream).
