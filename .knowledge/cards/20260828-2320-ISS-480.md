## Sibling of ISS-320 (INFERRED — not yet reproduced)

Filed while analyzing **BUG-20260828-095800-settings-constitution-r2** (root card
[ISS-320](20260828-1802-ISS-320.md): the Constitution "Clear" button fires an immediate,
unconfirmed `DELETE` on click). This is a second, independent instance of the identical
anti-pattern in a different component: a destructive, irreversible backend delete wired
directly to a button's `onClick` with no `window.confirm`, no modal, no two-step gate.

## Why the root cause implies this

`grep -rn "window.confirm" frontend/src` returns exactly one hit in the entire frontend
(`DashboardLayout.tsx:1717`, an unsaved-changes *navigation* guard — not a delete
confirmation). No destructive-delete call site in the app has a confirmation gate; ISS-320
is not an isolated oversight in one component, it is the absence of any shared
confirm-before-destroy primitive.

`SkillManager.tsx`'s `deleteSkill` (`frontend/src/components/workflow/SkillManager.tsx:99-114`)
fires `DELETE ${ENV.API_URL}/api/agents/skills/${agentId}` synchronously inside a `try` with
no confirmation step, then does `setSkillContent(""); setIsEditing(false)` on success. It is
wired to the "Delete" button's `onClick={deleteSkill}` at `SkillManager.tsx:221`, rendered
whenever `skillContent` is non-empty (`:219`) — i.e. whenever there is a saved SKILL.md to
lose. Confirmed via direct read: no `confirm(` anywhere in this file
(`grep -n "confirm(" frontend/src/components/workflow/SkillManager.tsx` → no matches).

## Expected vs actual

**Expected:** deleting an agent's saved skill document — an irreversible backend write with
no undo — requires an explicit confirmation step before the `DELETE` fires, consistent with
the fix expected for ISS-320.

**Actual (inferred, unverified):** clicking "Delete" in the Skill Editor should delete the
skill on the backend immediately, with no confirmation dialog, exactly as ISS-320 describes
for the Constitution "Clear" button.

## What would settle it

Reproduce in the browser: open the Skill Editor for an agent with a saved skill, click
"Delete", and confirm no confirmation prompt appears before `DELETE
/api/agents/skills/{agentId}` fires and the editor empties.

## Where a fix belongs

Both this and ISS-320 point at the same gap: there is no shared confirm-before-destroy
primitive in `frontend/src/components/ui/` for any of these call sites to route through. A
fix that adds a `window.confirm`/modal only inside `AccountSettings.tsx` leaves this call
site (and [ISS-481](20260828-2321-ISS-481.md)) broken. See ISS-320's analysis for the
recommended shared-component placement.
