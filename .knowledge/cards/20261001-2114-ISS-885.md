## Why the root cause implies it

Same mechanism as [ISS-104](20260812-1312-ISS-104.md): absolute line numbers into `run_commands.py` (2,607 -> 5,973 lines since 2026-07-31) and `engine.py` (8,480 -> 16,850), with no tie between the comment and its target. These particular docstrings carry the claims a maintainer must re-verify before touching teardown (which driver paths send the `None` sentinel; which sites register a queue and its task with no `await` between them), so a wrong pointer costs more here than in a log message.

## Expected vs actual

- Expected: each cite names something that still exists (`_drive_launch_to_queue`'s `finally`, `ExecutionEngine._drive_resumed_stream`, `resume_run_endpoint`), so it survives edits above it.
- Actual: 21 cite sites in these two files point at unrelated lines, removed functions or a missing file.

## Fix

Same convention and change style as ISS-104, in a separate docstring-only diff (ISS-104's own text keeps documentation drift out of behaviour changes): replace each `file:line` with the enclosing symbol (`_drive_launch_to_queue` / `_drive_revision_to_queue` `finally`; `ExecutionEngine._drive_resumed_stream`; `resume_run_endpoint`; the registration sites by function name; `ScopedStore` for the authz pair) and delete the number. No behaviour change.

The pattern is wider than this card: a read-only scan of non-test backend source finds 99 `name.ext:NNN` cites in 33 files (`evidence/qa-kb-042/06-analyze-cites-repo-wide.txt`). Only the files named here and in ISS-104 were verified; the rest are unverified leads, not claimed defects. Do not sweep them under this card.

## Test notes (for the test-writer)

No behavioural test exists for a docstring. If a guard is wanted, extend the text-scan lint ISS-104 adds (read files as text, never import `app.*`) to `run_engine.py` and `run_stream.py` after their cites are converted; before that it fails on the ~21 sites above, which is its RED state.
