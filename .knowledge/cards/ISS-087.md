# ISS-087

## Title

The un-versioned halves of the agent-detail cards do not follow the artifact version picker. The mechanism was real: deriveArtifactCardModel took protoCompletedTasks (the "Task plan · N planned" rows), validationPassed/validationIssues (the checks badge) and dagEdges (the handoff) from run state, so selecting an older <tasks> version showed that version's card TYPE with the run's CURRENT task rows. CORRECTION 1 — the impact claim was backwards. "The task-planner agent produces one version on most runs" is false: measured on backend/dev.db, prototype-plan has 6 run-groups and 5 are multi-version (prototype-specify 5/6, prototype-build 5/5). The picker is visible on most prototype runs. CORRECTION 2 — F1/F2 were mis-cited as the remedy. Neither mentions protoCompletedTasks or dagEdges; F1 is a run-scoped aggregate on a table with no artifact/version column and F2 serves the PAGES card. Neither could ever have fixed this. CORRECTION 3 — the row understated the defect. protoCompletedTasks is the BUILD agent's *completed*-task stream, so a card labelled "planned" rendered the number *completed* — wrong at the latest version, with no picker involved: run d5dbc9f2's plan holds 7 tasks and the card rendered "6 planned". CLOSED AS NOT-A-DEFECT — dagEdges. A DAG handoff edge is a property of the run's workflow graph and is constant within the run (one workflow_validated frame); selecting an older artifact does not change who consumes it. No work is owed. FIXED (owner decision D1): the card now parses the <tasks> body on screen via parseTasks, EXTRACTED from TasksPreview (artifactPreview.tsx:80-104) rather than written a third time (INV-12). This repairs the latest-version defect and the picker defect together. The validation badge was NOT version-threaded — it is DEAD, see ISS-116.
