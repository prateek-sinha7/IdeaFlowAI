# ISS-066

## Title

Register drift: `ISS-054`..`ISS-061` have NO rows in `ISSUES-REGISTER.md`, yet those ids are live in FIX-190/192/193/194/195 rows, in cards, and in commit messages. ~~`ISS-055` is a free gap inside a used range.~~ **CORRECTION (2026-08-12): that clause was WRONG. `ISS-055` is NOT free** — it is the tier-entitlement-bypass defect closed by FIX-189 (KAN-161, commit `d2ddc73a`), cited in `backend/app/core/entitlements.py:14`, `backend/app/api/run_commands.py:1722,2326` and `.knowledge/cards/FIX-189.md:17`. Acting on the original clause would have re-issued a live id and caused a second ISS-050-class collision. The four-source sweep found **all 8** ids (054-061) in use, none free. Consequence: a register-only "next id" lookup returns a number that is already taken — which is exactly how ISS-050 was re-issued for an unrelated defect on 2026-08-11 and had to be renumbered to ISS-064. Backfill the missing rows (or record why they are absent) so the register is once again a usable allocator.
