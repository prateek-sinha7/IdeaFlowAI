## What happened

Four admin endpoints answered an unauthenticated request with **403**. Every other
authentication failure in `app/core/dependencies.py` — bad signature, EXPIRED
token, missing subject, no matching user — answers **401** through
`_credentials_exception` (`dependencies.py:50-52`). Only the missing-header case
was different, and it was different because of a framework default, not a decision.

## Root cause

`backend/app/core/dependencies.py:32` — `bearer_scheme = HTTPBearer()`. FastAPI's
`HTTPBearer` raises `403 Forbidden` when the `Authorization` header is absent or is
not a `Bearer` credential. RFC 7235 separates the two: absent or unparseable
credentials are 401 plus a `WWW-Authenticate` challenge; 403 is
authenticated-but-not-permitted.

## The fix

A one-place override rather than five. `auto_error=False` would have pushed a
`None` check into each of the five `Depends(bearer_scheme)` call sites; subclassing
keeps them byte-identical:

```python
class _BearerScheme(HTTPBearer):
    async def __call__(self, request: Request) -> HTTPAuthorizationCredentials | None:
        try:
            return await super().__call__(request)
        except HTTPException as exc:
            if exc.status_code == status.HTTP_403_FORBIDDEN:
                raise HTTPException(
                    status_code=status.HTTP_401_UNAUTHORIZED,
                    detail=exc.detail,
                    headers={"WWW-Authenticate": "Bearer"},
                ) from exc
            raise
```

## Contract-change check

This changes an API status code, so the consumers were checked rather than assumed:

- `frontend/src/hooks/useRunStream.ts:355` already branches on
  `res.status === 401 || res.status === 403` — unaffected.
- `frontend/src/app/[...view]/page.tsx` (three sites) branches on
  `err.status === 403 || err.status === 404` for cross-owner / not-found on a
  specific resource. Those 403s come from ownership checks, not from a missing
  header, so they are untouched by this change.
- The two other backend test files that assert 403 (`test_user_workflows.py`,
  `test_rest_run_launch.py`) were re-run and stay green — their 403s are
  authorization, not authentication.
