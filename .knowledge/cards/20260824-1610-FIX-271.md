## Bug — ComposerPage could mount with zero agents (race)

Same class of bug as an earlier-fixed `LaunchWizard` issue: `pipelineAgents`'s lazy
`useState` initializer (which maps `initialAgentIds`/manifest steps to `AgentDef`s via
`ALL_LIBRARY_AGENTS.find(...)`) could run before `ALL_LIBRARY_AGENTS` was populated,
silently producing an empty agent list with no retry.

**Fix:** added a `resyncedAgentsFromLibrary` ref + a `useEffect` (right after the
`pipelineAgents` lazy-init) that re-runs the `manifestStepsToAgents`/`initialAgentIds`
mapping exactly once, the first time `ALL_LIBRARY_AGENTS` becomes non-empty.

## Cleanup — dead `ExternalPipelineCard`

`ExternalPipelineCard` (`CanvasNode.tsx`) was superseded by `ExternalWorkflowNode` (the
live, wired-up sibling) and never removed. Deleted the component and its now-orphaned
imports (`next/link`'s `Link`, `@/lib/routes`'s `routes`); fixed a stale
`ExternalPipelineCard (T36)` comment in `CanvasView.tsx` to reference
`ExternalWorkflowNode` instead. Confirmed `resolveWorkflowTarget`/`EXTERNAL_NODE_W` remain
in active use elsewhere before deleting.
