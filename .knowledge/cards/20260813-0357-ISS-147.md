# ISS-147

## Title

**`pipeline_complete` is missing from `useRunStream.ts`'s non-live-close terminal list, so a completed run's stream reconnects when it should settle quietly — DOC-ADR-0001's own predicted failure mode, realized.** `frontend/src/hooks/useRunStream.ts:301` — `if (type === "pipeline_cancelled" \|\| type === "pipeline_failed")` — sets `sawNonLiveAttachRef.current = true` for those two types only. `pipeline_complete` is not a member, even though the backend's OWN `_STREAM_TERMINAL_TYPES` (`run_stream.py:79`) treats it as an equally-terminal stream-closer. So when the server closes the stream after draining `pipeline_complete`, the client's close-branch evaluates `sawNonLiveAttachRef === false` and schedules a reconnect exactly as it would for a genuine live drop. DOC-ADR-0001 (`.knowledge/cards/DOC-ADR-0001.md`) is this EXACT decision, and its own "Negative consequence" section predicts this precisely: *"the terminal-frame list is maintained by hand. A new terminal frame type that is not added to that branch reintroduces the banner, and the symptom will look like a UI bug rather than a dispatcher omission."* This is the TRIGGER for ISS-146/FIX-248's duplicate-card defect, not the defect itself — the unnecessary reconnect is what exposes the durable-replay identity gap FIX-248 fixes. It is a **near-miss, not a proven-safe gap**: `detachRun`'s "additive insurance" (`page.tsx:967-980`, DOC-ADR-0001 itself calls this NOT the mechanism) usually unmounts the connection before a reconnect can happen, but it is defeated whenever the run's id is ALSO in `RunConnectionProvider`'s `autoIdsRef` — armed by an `online`/`visibilitychange` wake firing while the run is still active (`RunConnectionProvider.tsx:236,259-300,319-322`), which is exactly what a mid-run network blip does, and exactly why the live DROP=1/DROP=0 A/B differs. **Fix shape:** add `pipeline_complete` to the `useRunStream.ts:301` conditional, matching the backend's own terminal vocabulary; per DOC-ADR-0001, verify with one test per terminal frame type (mirroring its existing A1/A2 pattern) — the ADR's own "Coverage gap" note already flags that the `pipeline_cancelled`/`pipeline_failed` half is untested too.
