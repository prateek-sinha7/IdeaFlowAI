## Summary

INFERRED sibling of [ISS-915](20261001-2219-ISS-915.md) (QA-KB-082), read from source and not reproduced. ISS-915's flaw is that a type assertion stands in for validation and the `try/catch` guards the parse, not the shape. The same one-line pattern, `raw ? (JSON.parse(raw) as T[]) : []`, sits in three storage readers whose result reaches render code as an array:

| reader | storage | consumers that dereference the result at render |
|---|---|---|
| `loadCustomTemplates`, `frontend/src/components/workflow/prototype/CustomTemplateModal.tsx:20-28` (cast at `:24`) | localStorage `prototype.customTemplates` | `TemplateGallery.tsx:46` (effect, then state): `:118` `.length`, `:189` and `:227` `.map`. `PPTTemplateGallery.tsx:51`: `:112` `.length`, `:164` and `:183` `.map`. `saveCustomTemplate` / `deleteCustomTemplate` (`CustomTemplateModal.tsx:31`, `:36`): `.filter` |
| `loadCustomDesignSystems`, `frontend/src/components/workflow/prototype/CustomDesignSystemModal.tsx:18-26` (cast at `:22`) | localStorage `flowin.custom_design_systems` | `DesignSystemPicker.tsx:39` (effect, then state): `:47` `.find` inside a `useMemo`, `:85` `.filter`, `:221` `.length`, `:294` `.map` |
| `readCache`, `frontend/src/components/catalog/HomeLaunchGrid.tsx:60-68` (cast at `:64`) | sessionStorage `vlc_home_recents_v1:<user id>` | `:181-185` `useState` initializer (render phase), then `:424` `recents.length`, `:432` `recents.map` |

Each `try/catch` wraps only `JSON.parse`. Any value `JSON.parse` accepts is returned as `T[]`: `{}`, `"x"`, `5` or `true` have no `.map` / `.filter` / `.find` (TypeError at the consumer), `null` has no `.length`, and `[null]` crashes on the first element dereference (`ct.id`, `s.id`, `run.status`).

## Why the root cause implies it

Same mechanism as [ISS-915](20261001-2219-ISS-915.md): the declared type is compile-time only, and nothing at runtime checks that stored data is an array of objects. The codebase already has the correct pattern next to it: `frontend/src/app/[...view]/page.tsx:702-703` and `frontend/src/providers/RunConnectionProvider.tsx:338-339` test `Array.isArray(ids)` after the parse, and `frontend/src/lib/navigation.ts:52` (`readBackOrigin`) checks each field it returns. Not every storage reader is affected: `useNotifications.ts:32` and `:82` and the wizard draft readers (`LaunchWizard.tsx:416`, `[...view]/page.tsx:970`, `:1016`) throw inside their own `try`, so a wrong shape is swallowed there.

## Expected / Actual

Expected: a stored value that is not an array of the declared element shape reads as `[]` (an empty custom-template list, no recents), the same as a missing or unparseable value.

Actual (inferred): the pickers throw at render and the app error boundary replaces the page. Because the two custom-item keys live in localStorage and no code path removes them (grep for `localStorage.removeItem` / `.clear` finds only the notification, token and chain-context keys), a bad value survives reloads, new tabs and sign-out until site data is cleared. `prototype.customTemplates` and `flowin.custom_design_systems` carry no schema version in the key (unlike `flowin.notifications.v3` and `vlc_home_recents_v1`), so a future shape change would reach this path without a migration; no past shape change is evidenced (`git log -S` finds one introducing commit per key). The realistic trigger today is a hand-edited value, the same condition as ISS-915, so severity is Low.

## Where the fix belongs

In the three readers, not in each consumer. `loadCustomTemplates` and `loadCustomDesignSystems` are the shared functions behind four consumer components and two mutators, so one guard each covers every caller: `const v = JSON.parse(raw); return Array.isArray(v) ? v : [];`, optionally filtering elements to objects carrying the string fields the consumers read (`id`, `name`, `sourceRef`). The same two lines apply to `readCache`, which is only consulted when no live recents exist at mount (`HomeLaunchGrid.tsx:182-184`), so it has the lowest exposure of the three. No new helper is needed for three call sites.

## What would move this to CONFIRMED

In a signed-in tab set `localStorage.setItem('prototype.customTemplates', '{}')` (then `'null'`), open the prototype wizard at `/create/prototype`, and reach the Template step. Predicted: the error boundary. Repeat with `localStorage.setItem('flowin.custom_design_systems', '{}')` for the design-system picker, and with `sessionStorage.setItem('vlc_home_recents_v1:<sub>', '"x"')` for the dashboard. A jsdom test per loader is cheaper: seed the key, call the loader, expect `[]`.
