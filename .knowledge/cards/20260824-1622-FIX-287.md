Even with the manifest-derived gates computed correctly, the canvas still showed no
conditional — the popup never received them.

## Root cause

```js
const [liveSelections, setLiveSelections] = useState(initialSelections ?? {});
```

A `useState` initializer runs ONCE, at mount. `AgentsPopup` is rendered unconditionally
(`isOpen` only toggles visibility), so it mounts with the page — while the manifest fetch
is still in flight. The seed that arrives a moment later never enters its state.

## Fix

Key the popup on whether the manifest has landed
(`` key={`${effectiveType}:${manifestSelections ? "seeded" : "pending"}`} ``), so the
initializer re-runs exactly once with the real seed. The flag only flips
undefined → set, and the popup is closed when it does.

One of four instances of this shape found in a single session — state seeded by a
`useState` initializer or a one-shot effect, fed by data that arrives asynchronously. See
also [FIX-289](20260824-1623-FIX-289.md).
