## What happened

INFERRED sibling of [ISS-331](20260828-1840-ISS-331.md), derived from a
source-code read while analyzing that bug — not yet independently driven
live in a browser.

`CodeViewer` (the file-content pane of the App Builder deliverable preview)
in `frontend/src/components/preview/AppBuilderPreview.tsx` has its own Copy
button with the same false-positive variant as
[ISS-556](20260829-0208-ISS-556.md).

## Root cause (confirmed by direct read — false-positive variant)

`frontend/src/components/preview/AppBuilderPreview.tsx:240-246`:

```
const handleCopy = () => {
  if (file) {
    navigator.clipboard.writeText(file.content);
    setCopied(true);
    setTimeout(() => setCopied(false), 2000);
  }
};
```

Fire-and-forget: `navigator.clipboard.writeText(file.content)` is not
awaited, has no `.then()`/`.catch()`, and `setCopied(true)` runs
unconditionally right after it. Same missing-error-handling mechanism as
[ISS-331](20260828-1840-ISS-331.md) (no failure path exists at all), same
false-positive shape as [ISS-556](20260829-0208-ISS-556.md): the button
claims "Copied" even on a silently failed write.

**What would confirm this live:** open an App Builder run's Files preview,
select a file, click Copy, and verify with a clipboard write-interception
whether the content actually landed when the write is made to fail.
