# ISS-140

## Title

**The LIVE terminal path cleared only the legacy React state, never the run store — and it WAS user-visible: a Stop at the clarify gate cancelled the run, but the screen never repainted.** The lane stayed on "Clarifying" with Stop still armed and the clarify questionnaire still submittable, on a run the backend had genuinely already cancelled. `page.tsx:1196-1201` called `setReviewGateData(null)` / `setQuestionnaireData(null)` / `setActivePipelineRunId(null)`, but the lane reads the STORE (`page.tsx:2731`, `questionnaireData={runStore.viewed.questionnaireData}`). **THE FILED TEXT WAS WRONG AND IS CORRECTED HERE.** It claimed the defect was "currently MASKED by the `isRunning` conjunct in `runLaneState`, so not user-visible today". `laneClarifyOpen` (`DashboardLayout.tsx:1862`) has **no `isRunning` conjunct at all** — it is the ONE branch of the `runLaneState` ternary (`DashboardLayout.tsx:1864-1871`) not AND-ed with it, deliberately, because clarify precedes `pipeline_start` — and it is evaluated BEFORE the terminal branch, so a lingering store `questionnaireData` OUTRANKED the terminal markers the same cancelled frame had already applied correctly. The masking claim only ever held for the **`reviewGateData`** half of this row (which correctly IS masked, by the gate branch's own `&& isPipelineRunning`), never for the `questionnaireData` half — the actual live, user-visible cause all along. Disproven twice: once by source reading, once by live browser reproduction.

## Source / Evidence

Verified during the ISS-126 investigation (quick-260812-wir). Not folded into FIX-245: that fix covers the REOPEN path; this is the live path and needs its own live proof. **FIXED 2026-08-13 (FIX-247), with that live proof:** the reachable live block now does `if (frameRunId) runStore.update(frameRunId, { questionnaireData: null })` inside the existing run-scoping `if (!isForeignFrame)` guard (`page.tsx:1206`). **`reviewGateData` is deliberately NOT added to the store patch** — that half genuinely is masked, and clearing it would erase the historical gate card from a reopened transcript, which `terminalReopenReconcile.source.test.ts` already locks against. `activePipelineRunId` likewise not added: no store write for it exists, and none is needed once `questionnaireData` is cleared. Proven by TS-R-05 (seen RED independently twice, identical failure both times: lane stuck at "Clarifying", `data-status-tone="running"`, timeout waiting for /Cancelled/) plus two fresh cheap live Bedrock runs sampled at t+3s/8s/15s/25s after Stop — FIXPROBE (clarify armed) and GATEPROBE (review gate armed, the regression control) both settle to "Cancelled" with no Stop, no clarify submit and no gate actions.
