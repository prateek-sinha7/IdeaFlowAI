# ISS-1136

**Register source:** sibling derived during the `QA-KB-107` analysis on 2026-10-09 (root [ISS-1133](20261009-0200-ISS-1133.md)). Not its own bug row.

**Confidence:** CONFIRMED by running each file once, as-is and with the flag pinned off (offline unit tier, one file at a time, this tree at HEAD `6028b75e6`, branch
`feat/stale-bug-fixes`, nothing edited). The pinned run is the control, so "pre-existing" here rests on a measurement, not a label
(`evidence/qa-kb-107/analysis-05-offline-tests-env-sensitivity.txt`).

|---|---|---|
| `backend/tests/unit/app/test_model_factory.py` | 25 failed, 18 passed | 43 passed |

31 failures. The first reads `Expected 'ChatAnthropic' to have been called once. Called 0 times.`: `build_model` returned `ChatOllama` before reaching the branch under test.
The pinned run passes every one of them, which is what ties the rest to the same cause.

Not run: the integration files that also mock a constructor and call `build_model` (`tests/integration/agents/test_revision_analyzer_integration.py`,
`tests/integration/api/test_chat_messages_endpoint_api.py`) and `tests/agents/live_harness.py`. Leads, not findings.

## Condition

- `build_model` re-reads the flag on every call: `{**dotenv_values(ENV_FILE), **os.environ}` (`backend/app/agents/model_factory.py:335`), truthy values `1`, `true`, `yes`,
  `on` (`:336-341`). `ENV_FILE` is `backend/.env` (`backend/app/core/config.py:68`), and `backend/.env:47` sets `USE_LOCAL_OLLAMA=1` on this checkout.
- No fixture pins it. `_clear_provider_settings` (`backend/tests/unit/app/test_model_factory.py:61-74`) blanks the provider settings but not the flag, and
  `backend/tests/conftest.py` does not mention it. The only test file that names the flag is a live-gated e2e (`tests/integration/test_git_versioning_e2e.py`).
- `os.environ` wins over the file in that merge, so `USE_LOCAL_OLLAMA=0` in the real environment is a complete pin.

## Expected vs actual

Expected: the offline tier gives the same result on every checkout, whatever a developer keeps in `backend/.env`. Actual: on a checkout with the dev override enabled,
four unit files are red for a reason that has nothing to do with the code under test.

## Why the root cause implies it

The override is a call-time read of a file, with no seam. Anything that exercises provider selection is machine-dependent: `build_model` today, and the preflight once
[ISS-1133](20261009-0200-ISS-1133.md) is fixed. At that point three more tests flip on such a checkout, because they assert the very refusal the fix removes when the
flag is on:

- `test_model_factory.py::TestPreflightCheckProvider::test_expired_token_rejects_with_actionable_message` (`:397`)
- `test_model_factory.py::TestPreflightCheckProvider::test_token_within_skew_window_rejects` (`:412`)
- `tests/integration/api/test_rest_run_launch_api.py::test_expired_bedrock_token_rejected_pre_mint` (`:289`; not run here)

They pass today only because the preflight ignores the flag.

## Fix direction (INFERRED, not applied)

One autouse fixture that sets `USE_LOCAL_OLLAMA=0` through `monkeypatch.setenv`, in `backend/tests/conftest.py` (reaches every file) or, narrower, in
`_clear_provider_settings`. A test that wants the override sets it to `1` itself. No product code changes. The override-on tests for [ISS-1133](20261009-0200-ISS-1133.md)
then set the flag explicitly, and the expired-token tests stay correct on every machine.
