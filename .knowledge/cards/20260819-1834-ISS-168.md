## Confirmed the Canvas-selected model actually reaches the Bedrock API call

**Question investigated:** does a model id picked on the Canvas per-agent model picker
actually translate to the model Bedrock is invoked with, or does it get lost/ignored
somewhere in the chain?

**Finding — CONFIRMED working, no defect:** traced the full path end to end —
`CanvasConfigRail.tsx`'s picker writes into the `selections`/`model_overrides` payload
→ ingress-validated (`_validate_model_overrides`, `WorkflowCompiler.compile(trust="user")`)
→ `ModelResolver.resolve()` (`model_policy.py`) → `engine.py`'s per-agent dispatch sets
`ctx.model` → `factory.create_runner` → `DeepAgentRunner` → `build_model(model=...)`
(`model_factory.py`) → `ChatBedrockConverse(model=model_id, ...)`. Verified directly
against the installed `langchain_aws` package that `ChatBedrockConverse`'s real field
is `model_id`, aliased to the constructor kwarg `model` (so the alias resolves
correctly, not just by name match). Catalog ids (`model_catalog.py`) are already full
Bedrock inference-profile strings, so there is no id-format translation step to fail.
Independently corroborated by [BUG-CWF-002-custom-workflow](20260803-BUG-CWF-002-custom-workflow.md)'s live-proven fix: a
completed run's `agent_complete.model_id` read back exactly the resolved catalog id,
proving the resolved model was the one actually invoked, not merely computed.

**One separate, unconfirmed risk noted (not a defect in this chain):** catalog ids are
all `eu.`-prefixed cross-region inference profiles; `deploy.yml` validates that the
*default* `BEDROCK_INFERENCE_PROFILE_ID` matches the deploy region's geography, but
does not apply the same check to the catalog list a Canvas selection draws from. Only
relevant if this app is ever deployed outside the EU geography group — flagged, not
filed as its own issue since there is no evidence of intent to do so.

**Superseded finding:** this investigation preceded and is distinct from
[ISS-164](20260819-1726-ISS-164.md) (per-step `model` selection never reaching `ModelResolver` at the engine
dispatch call site) — that was a real defect in a *different* part of the same overall
chain, found in a later session on the same day, not a contradiction of this one.
