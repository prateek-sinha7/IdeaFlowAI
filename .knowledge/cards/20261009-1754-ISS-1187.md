# ISS-1187

Sibling of [ISS-1158](20261009-1510-ISS-1158.md) (register entry QA-KB-122). Derived from its root cause, not yet run. This is the largest piece of the "12 tests" item and the register does not see it. Filed 2026-10-09 by the analyzer.

## Condition

`disposable_user.make()` returns `{"id", "email", "password"}` where `password` is `accounts.PASSWORD` (`tests/integration/e2e/conftest.py:461`, docstring `:434`). That value was only ever true because the old endpoint set it (`AdminSetUserPassword`, permanent). Creation is invitation-only now, so the account has no known password. Four tests sign in as the account they create:

| test | sign-in line |
|---|---|
| S-10-13 `test_a_user_with_no_runs_sees_an_empty_state` | `suites/10_analytics/test_analytics.py:283` |
| S-11-20 `test_changing_another_users_tier_takes_effect` | `suites/11_admin/test_admin.py:589` |
| S-12-11 `test_the_notifications_panel_opens_with_an_empty_state` | `suites/12_shell_nav/test_shell_nav.py:214` |
| S-17-09 `test_a_hexaware_user_gains_prototype_and_loses_presentations` | `suites/17_theme_and_tiers/test_theme_and_tiers.py:294` |

## Why no credential exists (CONFIRMED by reading)

- `CreateUserRequest` has `email`, `tier`, `is_admin` and nothing else (`backend/app/api/admin.py:173-194`).
- `invite_user` could take an admin-supplied temporary password (`backend/app/core/cognito_admin.py:297`) but the route never passes one (`admin.py:458-461`); with none, Cognito generates it and emails it (`backend/app/core/cognito.py:421-423`).
- `reset-password` never returns one ("internally generated, never exposed to the admin", `admin.py:517`; the response is `{"status": "temporary_password_set"}`, `:555`).
- The seeded accounts get a permanent password out of band: `backend/scripts/seed_test_users.py:97-99` ("Permanent so the seeded account is immediately usable - an E2E run cannot answer a NEW_PASSWORD_REQUIRED challenge interactively"). The e2e venv has no AWS client (`tests/integration/e2e/requirements.txt`: pytest, pytest-playwright, pytest-timeout, pytest-json-report).

## Expected vs actual

Expected: a disposable account the test can sign in as. Actual after the POST body is fixed (INFERRED, not run): `POST /api/admin/users` answers 201, then `/login` with that email and the shared password is refused or lands on the NEW_PASSWORD_REQUIRED challenge, and `page.wait_for_url("**/dashboard")` times out.

## Options (test infrastructure, not a product decision)

1. Give the fixture the seed script's primitive: after the create, `cognito.admin_set_user_password(email, PASSWORD, permanent=True)`. Needs boto3, the pool id and an AWS profile in the e2e environment, and the fixture then depends on the same credentials the seed script does.
2. Seed the states these tests need. S-10-13 and S-12-11 need an account that never ran anything; S-17-09 needs a `hexaware` tier account (`flowin-tier-hexaware` exists, `entitlements.py:183`, but `seed_test_users.py:65` `_TIER_TO_GROUP` maps basic, pro and enterprise only). S-11-20 checks what the user sees after a tier change; without a credential it can only assert the admin-side result (the row and the stored tier), which is a weaker test than the one it replaces.
3. Re-scope the four to API-level assertions and keep the browser sign-in for the seeded accounts.

Not allowed: a password field back on `CreateUserRequest`, a test-only create endpoint, or `is_admin=True` on a disposable account. Those undo the mass-assignment hardening the model docstring records (`admin.py:183-187`).

## Traps

- Every `make()` asks Cognito to email an invitation to `e2e-<hex>@velocity.ai` (`cognito.py:421-423`) and creates a real pool user; teardown deletes the user (`conftest.py:466-467`), not the mail. Ten callers, eleven test ids.
- The fixture is not the only copy of the body: S-24-12 re-types it inline (`test_api_contract.py:342-347`). Have `make()` also return the created row so that test can stop posting its own.

## Confidence

CONFIRMED by reading: the fixture, the four sign-in lines, and every backend fact above. INFERRED, not run: the exact way the sign-in fails. Settle by fixing the body, running S-12-11 alone against the live stack and reading the failure.
