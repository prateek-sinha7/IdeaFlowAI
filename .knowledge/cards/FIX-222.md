## Description

No UI surfaced PER-ARTIFACT versions inside a run. artifact_refs durably stores every version and GET /api/runs/{id}/artifacts?kind=X&include=content already returns each one WITH its body — verified live on :8010 (run d5dbc9f2: spec v1/v2/v3 at 30081/36729/40052 chars, one call, HTTP 200) — but the only FE caller was WorkflowHistory.tsx:303, pinned to kind="clarifications". Worse, the evidence is actively destroyed in FE state: useWorkflow.ts resets an agent's output to "" on every agent_start (FIX-039), so the moment the spec agent re-runs during an update_specs cycle the only in-memory copy of v1 is gone and the panel shows v3 with no label and no way back. This invisibility is why FIX-217 shipped undetected.

## Root cause

A gap between two axes that were never distinguished on screen: the only version control users had is the run-header chip, which walks the run FAMILY (parent_run_id) per locked decision D2. Three in-run revision cycles move that chip not at all, so the product taught users that "Version" means something it does not, and the axis that DID change (artifact_refs.version, per (run_id, kind)) had no control at all. Data, API and read-scope all already existed; only the consumer was missing.
