## Description

Clicking "Run Again" on a cancelled `user_stories` run (or any pipeline) showed
"Spec Revision Cycle 1" in the Steps tab immediately after the first agent started,
even though no `update_specs` action was taken.

## Root Cause

In `handlePipelineMessage`, the `pipeline_start` case:

```typescript
agentStartEventIds: isSameRunReannounce ? (prev.agentStartEventIds ?? {}) : {},
```

`isSameRunReannounce = prev.pipelineRunId === pipelineRunIdFromStart` — true when
the backend resumes the **same run_id** (which "Run Again" does).

When the run was cancelled, `agentStartEventIds["domain-analyst"]` already contained
one identity from the cancelled execution. "Run Again" arrived with the same run_id
→ `isSameRunReannounce=true` → the old ids were carried into the resumed run.

On the first `agent_start` of the resumed run, a second identity was appended →
`agentStartEventIds["domain-analyst"].length === 2` → `deriveSpecRevisionCount`
returned `2 - 1 = 1` → "Spec Revision Cycle 1" banner.

## Fix

The carry-over predicate was broadened too much — it should only carry
`agentStartEventIds` when reconnecting to a **live run** (SSE reconnect
mid-run, `prev.isRunning=true`), not when resuming from a terminal state
(`prev.isRunning=false` — cancelled/failed).

```typescript
// Before:
agentStartEventIds: isSameRunReannounce ? (prev.agentStartEventIds ?? {}) : {},

// After (FIX-222):
agentStartEventIds: (isSameRunReannounce && prev.isRunning) ? (prev.agentStartEventIds ?? {}) : {},
```

This preserves the correct behaviour for:
- **Live SSE reconnect** during a genuine `update_specs` cycle: `isRunning=true` → ids carried → count correctly shows Cycle N
- **History reopen** (durable replay): `isSameRunReannounce=false` → ids cleared
- **Run Again from cancelled/failed**: `isRunning=false` → ids cleared → no spurious banner
