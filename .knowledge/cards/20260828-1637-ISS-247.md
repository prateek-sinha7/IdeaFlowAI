## What happened

On `/create/app` (the simple launch panel, mislabeled "User Stories" per known D-01),
checking an agent in the top-level "Review gates" checklist popover correctly updates that
control's own pill ("Review gates — 1 agent pause for review") and persists across
close/reopen — but the same agent's `Gate` combobox in the Advanced modal's per-agent Config
tab still reads "No gate" selected, in the same page session, with no save/submit step
between the two controls. Reproduced 3/3 from a cold `/create/app` load (cycle 1, cycle 2,
and cycle 3 after a transient popover-state revert unrelated to this defect — see Attempts
below). BUG-20260828-000100-create-app in the bug-hunter register documents the original find.

### Reproduction that worked (cycle 3, most careful run)

1. Fresh `/create/app` load, confirmed "Review gates" pill reads "no gates", all 6 checklist
   checkboxes unchecked.
2. Click "Review gates" pill to open the checklist popover.
3. Click the "Domain Discovery Agent" row to check it — confirmed via snapshot: pill updates
   to "Review gates — 1 agent pause for review", checkbox is `[checked]`.
4. Click elsewhere (not Escape) to close the popover without navigating — re-verified the
   pill still reads "1 agent pause for review" (state persists in this component instance).
5. Click "Advanced" to open "Advanced Workflow Configuration — User Stories".
6. Click the Domain Discovery Agent node on the canvas, then its "Config" tab.
7. Observe the `Gate` combobox: `option "No gate" [selected]` — not "Human gate" — despite
   the Review gates checklist (same page, same session) reporting this exact agent as
   gated.

All three cold-start cycles produced the identical result. No timing, tier, theme, or
account variation was needed — this is a structural disconnect between two pieces of state,
not a race.

## Root cause

Two entirely separate state representations exist for "does this agent's step pause for
human review", and nothing in the composer syncs them:

- `ReviewGatesSection.tsx` (`frontend/src/components/workflow/ReviewGatesSection.tsx`)
  tracks a local `checkedIds: Set<string>` and reports it upward via
  `onChange(gateAgentIds, touched)` (line 36, 83-86). This flows into
  `IdeaInputPage.tsx`/`LaunchWizard.tsx` as `gateSelectionRef.current`, which is submitted
  to the backend as a top-level `gate_agent_ids` field on the run-launch payload
  (`IdeaInputPage.tsx:1343`, `LaunchWizard.tsx:690,783`) — entirely separate from any
  per-agent workflow-definition field.
- `CanvasConfigRail.tsx` (`frontend/src/components/workflow/composer/CanvasConfigRail.tsx`,
  ~line 248-276) reads/writes the selected agent's own `gates: string[]` array
  (`sel.gates`/`agent.gates`) via `patch({ gates: [...] })`. The `Gate` combobox at line 683
  ("No gate" option) reflects `chosenGate`, derived purely from `declared = sel.gates ?? []`
  — it never reads `gateAgentIds`/`checkedIds` from `ReviewGatesSection`, and checking an
  agent in that checklist never calls `patch({ gates: [...] })` for the corresponding node.

Confirmed the composer notably does NOT send `gate_agent_ids` at launch at all
(`ComposerPage.tsx:853,871` — "a composer workflow declares its [gates via node config],
gate_agent_ids is deliberately NOT sent"), which means on `/create/app` the checklist's
"1 agent pause for review" claim is even more clearly a display-only artifact disconnected
from what the Advanced modal (and the actual run) will honor.

## Expected vs actual

Expected: checking an agent in the Review gates checklist and viewing that same agent's Gate
setting in the Advanced modal should show a consistent state (e.g. "Human gate" selected),
since both controls purport to describe the same "does this step pause for review" property
on the same in-session workflow configuration.

Actual: the checklist and the Advanced modal Config panel report contradictory values for the
identical agent within the same page load — checklist says gated, Config combobox says
"No gate" — because they are backed by disjoint state (`gateAgentIds` vs. `agent.gates`)
with no synchronization between them.
