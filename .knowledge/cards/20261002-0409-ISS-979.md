# ISS-979

## Description

Sibling of [ISS-791](20260922-1823-ISS-791.md) (bug QA-KB-056, `BUGS.md#qa-kb-056`),
derived from its root cause by the 3-analyzer and then **reproduced offline** — function
level, the real `build_flat_payload`, not yet by a committed test or a live run.

**Condition.** A run whose compiled deliverable is `strategy: streamed_text`, whose
DECLARED name ends in `.html` / `.htm`, and whose last agent emits text that is not already
an HTML document (markdown). The composer's "Output format = HTML" pick is exactly this: it
sends `selections.__deliverable__ = {strategy: "streamed_text", name: "output.html"}`
([ISS-770](20260922-1305-ISS-770.md)), and `ectx.deliverable` is the patched spec
(`engine.py:5029-5035`: `compiled, ... = self._apply_selections(...)` then
`ectx.deliverable = compiled.deliverable`).

**Expected.** The bytes materialized into `.chain/output.html` equal the deliverable the
run reports (`final_output`): the HTML document `StreamedTextResolver.resolve` renders with
`coerce_to_declared_format` (`streamed_text.py:59-61`, `_format.py:60`).

**Actual.** `.chain/output.html` holds the agent's raw markdown byte for byte
(`engine.py:1489-1491`, written at `engine.py:1610-1614`), under an `.html` name. The run
record and the Preview of the latest version show the rendered document.

## Why the root cause implies it

[ISS-791](20260922-1823-ISS-791.md)'s mechanism is that the `streamed_text` block of
`build_flat_payload` copies `ectx.last_streamed` instead of calling the resolver. When
[FIX-623](20260922-2024-FIX-623.md) added `coerce_to_declared_format` to the resolver — two
hours after ISS-791 was filed — it touched nothing under `execution_engine/` (its own
"Deliberately NOT changed" section), so the divergence widened from two transforms to
three. The "minimal alternative" in `BUGS.md#qa-kb-056`
(`strip_pre_document_prose(unwrap_artifact(raw))`) mirrors only the two transforms ISS-791
names and **leaves this case open** — which is why it has its own card and its own test.

It is also the most reachable trigger of the whole family: it needs no cooperation from the
model. Every `custom` run launched with Output format = HTML takes it, whereas the
wrapper/preamble case of ISS-791 needs the last agent to emit an `<artifact>` wrapper or
prose ahead of a bare document.

## Reproduction (executed 2026-10-02, offline)

`evidence/qa-kb-056/analysis-proof-build_flat_payload.py` (stdout kept in
`analysis-proof-build_flat_payload.out.txt`), case B:

```
declared name        : output.html
last_streamed        : '# Title\n\nbody text\n'
resolver output      : '<!DOCTYPE html>\n<html lang="en">\n<head>\n ... <h1>Title</h1>\n<p>body text</p>\n</body>\n</html>\n'
payload.materialized : True  chainable=True
materialized bytes   : '# Title\n\nbody text\n'
payload == resolver  : False
```

Control, case D (`user_stories.md`, plain markdown): `payload == resolver : True` — all
three transforms are no-ops for a `.md` name, which is why nothing visible broke for the
markdown workflows.

## Consumers that inherit it

The same set as the blast radius in [ISS-791](20260922-1823-ISS-791.md): the git terminal
snapshot and `vN` tag, `chain_context` into a downstream run, the header Download button,
the Files-tab row, and the pinned-version Preview (`PreviewPanel.tsx:1453-1467`, rendered at
`:1763-1780`), which reads `.chain/output.html` at the pinned ref.

## Relation to ISS-838 (open)

[ISS-838](20260922-2024-ISS-838.md) describes this symptom (".chain holds unconverted
markdown under an .html name even when the run record is correct") but names a mechanism
that is **not the live one for `streamed_text`**:

- `_write_chain_payload` (`engine.py:1115`), which `shutil.copy2`s a sandbox file into
  `.chain/{run_id}/`, has no production caller — only tests import it. `finalize_terminal_run`
  replaced `_fire_post_run` (comment at `engine.py:7624-7625`) and writes the flat `.chain/`
  through `build_flat_payload` (`engine.py:2323`).
- For `streamed_text`, `_check_artifact_fallback` never writes the declared name:
  `_deliverable_filename_override` returns a name only when `strategy == "single_file"`
  (`engine.py:9080-9103`), so the fallback writes the per-step `artifact_name(...)` file and
  `sandbox.root / "output.html"` stays absent — which is exactly why the raw `last_streamed`
  branch (`engine.py:1481-1491`) is the one that runs.

This card therefore carries the live mechanism for `streamed_text`. It does **not**
supersede ISS-838: what may remain of that card is the `single_file` case (the fallback
plants raw text under the declared `.html` name, and both `SingleFileResolver.resolve` step
(1) and the payload copy read it raw) — INFERRED from reading, not executed.

## Fix pointer

The same single change as ISS-791 (see its "Analysis" section): materialize from
`_CAPABILITY_REGISTRY.resolve("deliverable", "streamed_text").resolve(ectx)` instead of from
`last_streamed`; that applies all three transforms at once. Not the two-call mirror.
