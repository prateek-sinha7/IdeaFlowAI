# ISS-870

Found while tracing the blast radius of QA-KB-005 ([ISS-107](20260812-1400-ISS-107.md)). **Confidence: INFERRED** as a
sibling — every file:line below was read and is CONFIRMED, but nobody has watched a live run drop the frame
(no run was launched; the line forbids it). Settle it with the tests under "What would settle it".

## Condition

Any live run in which the engine emits a `hook_run` frame: the `audit_logger` hook's `before_step` / `after_step`
markers, the engine's tool_call / tool_result audit rows, and the run-entry behavioral-guideline rows (the four
`emit_hook_event` callers — see the emitter sibling [ISS-871](20261001-2107-ISS-871.md)).

## Expected

The frame reaches `handlePipelineMessage`'s `case "hook_run"` (`frontend/src/hooks/useWorkflow.ts:1702`) and grows
`pipelineState.hookRuns`. That is what KAN-73 ([FIX-018](20260623-FIX-018.md): "`useWorkflow.ts` already handles
`case "hook_run":` and appends to `pipelineState.hookRuns`") and `RunChatLane.deriveSecurityBullets`
(`RunChatLane.tsx:468`, "Secret-scan blocks from live hook_run events (pipelineState.hookRuns)") both assume.

## Actual

The frame is dropped before the reducer on both live routes. CONFIRMED by reading:

- `handleWebSocketMessage` (`frontend/src/app/[...view]/page.tsx`) gates its whole reducer dispatch on
  `if (pipelineTypes.includes(msg.type)) {` (`:1344`; the block closes at `:1858`). The array (`:1312-1343`) does not
  contain `"hook_run"`. The dispatch `handlePipelineMsgRef.current?.({ type: msg.type, ...(msg.data ...) })`
  (`:1569-1574`) and `runStoreHandleFrameRef.current(...)` (`:1565-1567`) are both inside that block. A `hook_run`
  skips it and falls to the legacy `switch (msg.type)` (`:1860-2218`), which has no `hook_run` case and no `default`.
- `useRunStateStore.handleFrame` has its own allowlist, `pipelineFrameTypes` (`frontend/src/hooks/useRunStateStore.ts:531-567`),
  followed by `if (!pipelineFrameTypes.includes(msg.type)) return;` (`:569`). No `hook_run` there either.
- `handleFrame` has exactly two non-test callers, both in `page.tsx` (`:1297` wave block, `:1566` the allowlisted block),
  and `useWorkflow().handleMessage` is bound to `handlePipelineMsgRef` only at `page.tsx:2296` and called only at `:1570`.
  `grep -rn "hookRuns"` over `frontend/src` (non-test) finds exactly one writer, the reducer (`useWorkflow.ts:1713`,
  reset at `:826`).
- `hook_run` is also absent from `AGENT_SCOPED_FRAME_TYPES` (`frontend/src/lib/wsReplayState.ts:136-151`).

Proof that the omission is total (run 2026-10-01 in the worktree):

```
page.tsx          pipelineTypes array     lines 1312-1343  hook_run occurrences: 0   (whole file: 0)
useRunStateStore  pipelineFrameTypes array lines 531-567   hook_run occurrences: 0   (whole file: 0)
wsReplayState.ts                                           hook_run occurrences: 0
git log -S'hook_run' -- frontend/src/app                   (no commits)
```

History: the page allowlist as of KAN-73's own commit (`7d49bf90e`, 2026-06-23, `dashboard/page.tsx:341-359`) already
lacked `hook_run`. KAN-73 added the reducer case and touched no routing file, so the path was never connected.
Backend transport is fine: `kernel_services.py:561` queues `{"type": "hook_run", "data": ...}` and
`run_stream.py:542-558` forwards it as an SSE `{type, data}` frame; `useRunStream` drops only the `pipeline_heartbeat` /
`pong` keepalives (`useRunStream.ts:269`) and otherwise stamps `_sourceRunId` and forwards every type.

Result: `pipelineState.hookRuns` is `[]` for the whole run, so the payload-loss defect QA-KB-005 describes is not
observable in the running app, only at reducer level.

## Why the root cause implies it

[ISS-107](20260812-1400-ISS-107.md)'s shape mismatch can only matter if a frame arrives. Tracing the arrival path to size the
blast radius found that none does. The earlier investigator verified "the reducer is reached ONLY through the
flattening path" at reducer level (`.planning/ISSUES-REGISTER.md:165`, a frozen archive; the card carries only the
truncated title) and never checked that the flattening path admits the type. Same trap class as
[ISS-117](20260812-1511-ISS-117.md) / [FIX-454](20260901-1600-FIX-454.md) (the store allowlist omitted
`validator_result` / `gate_passed` / `gate_blocked`) and [ISS-139](20260813-0005-ISS-139.md) (the page `pipelineTypes`
returns before a later switch arm).

## What would settle it

- Source-text test in the repo's existing convention (`frontend/src/app/[...view]/terminalReopenReconcile.source.test.ts:92-99`
  slices the `pipelineTypes` array text and asserts membership): assert `"hook_run"` appears in both arrays.
- Store-level test, in the style of `frontend/src/hooks/useRunStateStore.gateReplay.test.ts`
  (`renderHook(() => useRunStateStore())`, then `act(() => result.current.handleFrame(runId, { type: "hook_run", data: { ... } }))`):
  `pipelineState.hookRuns` stays at length 0 today and is 1 after the fix. (`reducerHarness.ts` drives the reducer directly,
  so it cannot see the allowlist; it is the right driver for the QA-KB-005 test, not this one.)

## Fix direction

Add `"hook_run"` to `pipelineTypes` (`page.tsx`) and to `pipelineFrameTypes` (`useRunStateStore.ts`), and decide
`AGENT_SCOPED_FRAME_TYPES` membership (the layer-1/2 guards at `page.tsx:1525-1558` already scope the dispatch by
`_sourceRunId`, but the foreign-agent drop at `:1116-1121` would not apply to it).

**Sequence AFTER the QA-KB-005 reducer fix.** Opening the gate first would fill `hookRuns` with all-default rows.

**Decide first whether live `hookRuns` is wanted at all.** `AuditTab` has not read it since it moved to the three
plan-03 endpoints (`AuditTab.tsx:46-51`, "Dormant legacy prop"), which leaves `RunChatLane.deriveSecurityBullets` as
the only reader, and that reader cannot fire for a secret scan regardless (see [ISS-871](20261001-2107-ISS-871.md)). Intent is not
recorded anywhere I could find, so this is a lead, not a verdict. Not escalated: it is a scope call for whoever fixes it.

## Fix (2026-10-01)

Fixed by [FIX-683](20261001-2128-FIX-683.md), after the [ISS-107](20260812-1400-ISS-107.md) reducer fix. `"hook_run"` is
now in `pipelineTypes` (`page.tsx:1341-1343`) and `pipelineFrameTypes` (`useRunStateStore.ts:567-569`).
`AGENT_SCOPED_FRAME_TYPES` was left unchanged. Its contract (`wsReplayState.ts:120-135`) covers agent-keyed frames
that change per-agent state, while `hook_run` appends a run-level row, and the run-id guards (`page.tsx:1528-1561`)
already scope both dispatches. On the "is live hookRuns wanted" question: the QA-KB-005 dispatch named both
allowlists, and KAN-73 ([FIX-018](20260623-FIX-018.md)) states the intent. Both `it.fails` cases now report "Expect
test to fail", so their assertions pass: "a hook_run frame appends a hookRuns row" in
`useRunStateStore.staleFailedAgents.test.ts`, and "lists hook_run" in `terminalReopenReconcile.source.test.ts`.
That file's five ISS-126 failures pre-date this work and are carded as [ISS-898](20261001-2128-ISS-898.md). The
markers are left for the 6-verifier.
