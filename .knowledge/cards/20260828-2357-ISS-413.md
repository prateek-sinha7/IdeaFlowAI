## What is left

[FIX-354](20260828-2357-FIX-354.md) stopped the lane header lying ("just now"
for a day-old run) in two places: the engine now stamps the run's real
`created_at` on `pipeline_start`, and the reducer
(`frontend/src/hooks/useWorkflow.ts:511`) no longer substitutes the client clock
when a frame omits it.

That backend stamp cannot reach backwards. Every run whose durable
`pipeline_start` row was persisted BEFORE the fix replays with no timestamp, so
`pipelineState.createdAt` stays undefined, `formatRelativeAge(undefined)`
returns `""`, and `LaneRunHeader.tsx:257`'s `metaParts.filter(Boolean)` drops
the segment: the header reads `18m 54s · 3.1M tokens` with no age at all. That
is the intended, card-sanctioned outcome of FIX-354 — a graceful blank instead
of a wrong value — but it is still a missing label on every historical run.

## Why it was not fixed in the same pass

The data is already on disk. `run_events.created_at`
(`backend/app/models/run_event.py:72`) is a NOT NULL column stamped on every
durable row, and the `pipeline_start` row's value IS the run's start time. But
`GET /api/runs/{id}/events` (`backend/app/api/runs.py:1080-1091`) projects only
`seq`, `event_id`, `type` and `payload_json`, and
`frontend/src/lib/api.ts:970-979` builds `DurableFrame` from exactly those. So
the replay has the timestamp available one column away and never sees it.

Surfacing it means a new field on a public API response plus a `DurableFrame`
shape change — outside what [ISS-276](20260828-1700-ISS-276.md) scoped, and a
design call (which timestamp is authoritative for a replayed frame: the row's
own `created_at`, or the payload's?) rather than a fix. Deferred rather than
decided unilaterally.

## Disposition

Open, low severity — cosmetic, and only for runs recorded before FIX-354. Two
plausible shapes, both additive:

1. Add `created_at` to the `get_run_events` projection and merge it into
   `DurableFrame.data` the way `event_id`/`seq` already are (`api.ts:978`),
   letting the row's own stamp be the fallback the reducer reads. Fixes every
   historical run of every event type at once.
2. Have `LaneRunHeader`'s settled branch take the run's `created_at` from the
   DB-backed run record the page already fetches — the source the version
   picker (`frontend/src/components/preview/RunHeader.tsx:156`) uses and gets
   right. Narrower, but leaves `pipelineState.createdAt` blank for any future
   consumer.
