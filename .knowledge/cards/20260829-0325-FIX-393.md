## What was wrong

`BUG-20260828-041815-login-expired-1`. Submitting the sign-in form on `/login?expired=1`
with invalid credentials rendered a visible "Invalid email or password." banner that carried
no `role`, no `aria-live` (own or inherited up to `<html>`), and never received focus — a
screen-reader user got no notification that the attempt failed, in violation of WCAG 4.1.3
(Status Messages). Validated 3/3 cold starts across both mouse-click and Enter-key submit.

## Root cause

Not a broken shared function — three separately hand-rolled inline JSX banners in one file,
none routed through a shared component, all with the identical missing-attribute shape (a
conditionally rendered `motion.div`/`div` styled `text-status-failed`, no `role`, no
`aria-live`):

- `frontend/src/app/login/page.tsx:261` — `isExpired` session-expiry banner
  ([ISS-574](20260829-0220-ISS-574.md)), present at first paint of the full
  `window.location.href` navigation `handleSessionExpiry()` performs
  (`frontend/src/lib/api.ts:175-179`).
- `frontend/src/app/login/page.tsx:271` — `LoginForm`'s `error` banner, the reported path
  ([ISS-337](20260828-1900-ISS-337.md)).
- `frontend/src/app/login/page.tsx:446` — `ChallengeForm`'s own `error` banner
  ([ISS-575](20260829-0220-ISS-575.md)), hit on MFA / new-password validation and API
  failures.

`frontend/src/components/ui/` has no generic alert/banner primitive this page could have
used. The codebase already knows the pattern elsewhere
(`components/settings/SecuritySection.tsx:169` `aria-live="polite"`,
`components/workflow/AgentsPopup.tsx:2659` `role="alert"`) — `login/page.tsx` never got it.

## What changed and why there

`role="alert"` added to all three blocks in `frontend/src/app/login/page.tsx`, and nothing
else. `role="alert"` implies `aria-live="assertive"` + `aria-atomic="true"`, so the two
reactively-injected banners are announced on DOM insertion with no explicit focus
management, which is why no `.focus()` call was added.

Fix location per [ISS-337](20260828-1900-ISS-337.md)'s fix-location note: inside this file,
not a new `components/ui/` primitive. Blast radius was re-verified before editing and still
holds — `login/page.tsx` is a router leaf (`imported_by: []`, `MOD-frontend-src-app`), the
only two other references to it in `frontend/src` are prose comments in `lib/api.ts:130,181`,
and `register/page.tsx` renders no form of its own. So three sites in one file is the whole
surface; there is no shared caller upstream to guard instead.

A local wrapper component (the card's stated alternative) was NOT built — three usages in one
file is not enough repetition to justify one, and it is a strictly larger diff than three
attributes for identical behaviour.

## Deferred

[ISS-574](20260829-0220-ISS-574.md)'s banner is the one case where `role="alert"` alone is
weaker: it is in the DOM at parse time of a full-navigation load rather than inserted after
mount, and parse-time `role="alert"` announcement is less consistent across screen readers.
`role="alert"` satisfies WCAG 4.1.3 and the card's stated fix; the focus-management
alternative ISS-337 mentions as "worth" considering for that one banner was not added — it
needs a real screen-reader session to judge, which no card covers.
