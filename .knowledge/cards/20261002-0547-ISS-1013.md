# ISS-1013

## Description

Sibling of [ISS-900](20261001-2132-ISS-900.md) (QA-KB-073), found while bounding its blast radius. No bug report names
these two tests; [ISS-949](20261002-0107-ISS-949.md) (QA-KB-061, cause C) covers the same fault in the two launch-file
tests and never looked at this file.

`backend/tests/integration/agents/test_restart_resume_db.py::test_apply_terminal_output_columns_populates_all_columns`
(`:4088`) and `::test_apply_terminal_output_columns_captures_per_agent_model_id` (`:4181`) call
`_apply_terminal_output_columns` directly with a `(event_type, data)` list. Both raise
`TypeError: the JSON object must be str, bytes or bytearray, not NoneType` at `json.loads(wr.agent_outputs)` (`:4166`,
`:4216`): `agent_outputs` is NULL.

Status: CONFIRMED (observed red, bisected, and the fix probed). Filed as a sibling because the root cause of
[ISS-900](20261001-2132-ISS-900.md) implies it; it was reproduced here, so it is not a lead.

## Cause (CONFIRMED)

Same mechanism as [ISS-900](20261001-2132-ISS-900.md). `_apply_terminal_output_columns` (`backend/app/api/run_commands.py:3919`)
opens one row per `(agent_id, task_id)` (`:3949`, `:3958`) and appends a closed row only `if row.get("agent_id")`
(`:4028`, `:4033`). Both tests give `agent_start` an `agent_id` and leave it off the rest: `agent_chunk` (`:4109`, `:4130`,
`:4194`) and `agent_complete` (`:4111-4120`, `:4132-4141`, `:4195-4204`). Those land on a `(None, "")` row that is dropped, and
`:4046` never writes `agent_outputs`. The keying arrived in `77b52bb3d`
([FIX-652](20260929-1022-FIX-652.md)); the real engine stamps `agent_id` on every one of these events (see the
analysis in [ISS-900](20261001-2132-ISS-900.md)), so the tests are the stale side.

**A second layer, in the first test only.** Its `agent_complete` events carry `cache_read_tokens` (10 and 0) but no
`usage_version`. `normalize_usage` (`backend/agents/capabilities/token_usage.py:63-64`) reads a record without
`usage_version == 2` as pre-v2 (cache reads inside `input_tokens`) and subtracts them, so `total_input_tokens` is 290, not the
asserted 300 (`:4173`). The engine stamps `usage_version` on every `agent_complete` (`backend/agents/execution_engine/engine.py:10911`).
Adding `agent_id` alone fixes the second test and leaves the first failing at `assert (290 == 300)`, which would read as a
different bug. Observed on the scratch probe.

**Why it matters.** The docstring of `test_user_resume_persists_output_columns` (`:4533-4538`) hands the per-agent columns of
[BUG-R03-resume](20260803-BUG-R03-resume.md) (`agent_outputs`, `token_usage`, `duration`) to the first of these tests as their
deterministic coverage in this file, and the second pins the per-agent `model_id` capture of
[ISS-165](20260819-1726-ISS-165.md). Both have been red since 2026-09-29. The mapping itself is still guarded at unit level by
`backend/tests/unit/app/test_run_row_token_usage.py` (3 passed), so this is a coverage gap in the resume file, not a product defect.

## Fix (test-only, no change to `run_commands.py`)

In `backend/tests/integration/agents/test_restart_resume_db.py`:

- `test_apply_terminal_output_columns_populates_all_columns`: add `"agent_id"` (`"domain-analyst"`, then `"backlog-compiler"`) to the
  two `agent_chunk` tuples and the two `agent_complete` dicts, and `"usage_version": 2` (import `USAGE_VERSION` from
  `agents.capabilities.token_usage`) to both `agent_complete` dicts. Keep every assertion: with the version stamped, 300 / 130 / 430
  and `total_cache_read_tokens == 10` hold in the current meaning.
- `test_apply_terminal_output_columns_captures_per_agent_model_id`: add `"agent_id": "prototype-build"` to the `agent_chunk` and the
  `agent_complete`.

Probe (a scratch copy of the working tree, repo untouched): with exactly those edits both tests pass and the file goes from 6
failed to 4 failed, the four unrelated ones above.

Scheduling: [ISS-902](20261001-2144-ISS-902.md) (QA-KB-075) edits comments in the same file (`:4318-4377`); the two edits do not
overlap, but run them serially. [ISS-900](20261001-2132-ISS-900.md) owns the revisions-file test and
[ISS-949](20261002-0107-ISS-949.md) the launch-file pair; this card owns only the two tests named here.

What a naive fix would break: making the collector tolerate an id-less event (a restored "current agent" slot) re-breaks
parallel-member attribution, pinned by `test_run_row_token_usage.py::test_every_parallel_member_keeps_its_own_row`, and a second
inline mapping violates INV-12.
