## What was wrong

Task parsers would parse task definitions from the model's reply text, which 
often included narration BEFORE the structured JSON answer. This wasted tokens 
on narration and required parsing over an unpredictable order.

## The fix (commit 1e329e47b)

- Task parsers now check for on-disk task file FIRST (A2).
- If the file exists, read it directly (deterministic, no narration tokens).
- Only fall back to parsing the narrating reply if on-disk file is missing.
- Reduces token waste from model narration that precedes the structured answer.

Pinned by test_json_tasks.py verifying that on-disk files are preferred and 
narration is skipped when files are present.
