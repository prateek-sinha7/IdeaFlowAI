## What was wrong

`BUG-20260827-221400-dashboard` — on `/dashboard`, the "Inspect &lt;card title&gt; details"
button on a catalog card opens `WorkflowDialog`, and Escape did nothing. The dialog stayed
open, the page stayed dimmed behind the backdrop, and the only way out was the Close (X)
button (or a backdrop click). Reproduced 3/3 by 2-validator on two different cards.

## Root cause

`frontend/src/components/workflow/WorkflowDialog.tsx` declares `role="dialog"` /
`aria-modal="true"` (lines 134-135 pre-change) but had no keyboard handling anywhere in the
file — `grep -n "Escape\|onKeyDown\|keydown"` returned zero matches. Its only `useEffect`
(line 63) is the `getWorkflowDetail` / `getCapabilities` data fetch. Dismissal ran through
exactly two paths, the backdrop `onClick={onClose}` and the Close button's `onClick={onClose}`.

`WorkflowDialog` has one production caller,
`frontend/src/components/catalog/HomeLaunchGrid.tsx:392`
(`{inspectId && <WorkflowDialog workflowId={inspectId} onClose={() => setInspectId(null)} />}`),
re-confirmed by grepping every `.ts`/`.tsx` reference before editing — the caller already
passes a correct `onClose`, so **`HomeLaunchGrid.tsx` needed no change** even though
[ISS-326](20260828-ISS-326.md) scopes it in. The missing handler was entirely inside the
dialog.

## What changed, and why there

Two files, ~10 net lines.

1. **`frontend/src/hooks/useEscapeToClose.ts` (new)** — a document-level `keydown` listener
   that calls `onClose()` on Escape, with an `enabled` flag. This is the location the
   register's proposed fix names: the same effect was already written by hand in
   `components/workflow/prototype/TemplateDetailModal.tsx:29-38` and file-locally in
   `library/LibraryPage.tsx`'s `useDetailModalKeyboard` ([FIX-333](20260828-2131-FIX-333.md)),
   and re-omitted in three more `role="dialog"` shells in this module. Putting it in
   `hooks/` means the next modal calls one hook instead of copy-pasting a fourth effect.
2. **`WorkflowDialog.tsx`** — one import and one call, `useEscapeToClose(onClose, open)`,
   placed with the other hooks above the `if (!open) return null;` early return (hooks may not
   sit below it). `open` is passed as `enabled` because the component exports a controlled
   `open` prop and returns `null` when it is false: a hidden dialog must not swallow Escape
   from whatever is actually on screen. No other line of the component changed.

`useEscapeToClose` deliberately does **only** Escape — no focus-on-open, no Tab trap.
`useDetailModalKeyboard` also focuses its panel because [ISS-272](20260828-1852-ISS-272.md)
asked for it; [ISS-326](20260828-ISS-326.md) asks for Escape and nothing else, and neither
`TemplateDetailModal` nor `DesignSystemDetailModal` traps Tab either.
