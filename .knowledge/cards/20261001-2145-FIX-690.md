# FIX-690

## What was wrong

Bug report QA-KB-042. The root cause and the inventory of stale sites come from the analysis cards. They are not
re-derived here.

- [ISS-104](20260812-1312-ISS-104.md) (root): the shutdown-path comments located code by absolute `file:line`
  in `run_commands.py` and `engine.py`, which have since doubled in size. Nothing tied a comment to its target, so
  every number decayed. Examples: `run_shutdown.py` cited `run_commands.py:1401` for the "NEVER cancel it on"
  comment and `engine.py:1032` for the per-event persist. `docker-entrypoint.sh` cited `docker-compose.yml:138`,
  which is past the end of that 114-line file.
- [ISS-885](20261001-2114-ISS-885.md): the same drift in the `run_engine.py` docstrings (`_cleanup_pipeline`,
  `_is_run_live`, `_resolve_owned_parent_run_id`) and in `run_stream.py`.
- [ISS-888](20261001-2114-ISS-888.md): two `run_shutdown.py` docstrings said `read_timeout=600` ("up to ten
  minutes"). Since [FIX-657](20260930-1723-FIX-657.md), `build_model` sets 1800.

## What changed, and why there

There is no shared function: the "callers" are comment sites. The fix applies one convention at every site in
the cards' inventories, plus the extra sites the guard scans. Each site names the enclosing symbol, or a quoted
anchor phrase where the symbol is too coarse, and its number is deleted. Every replacement symbol was checked
against the current tree with `grep`/`ast` before it was written. `run_commands.py`, `engine.py` and
`model_factory.py` are not edited: every anchor already exists there.

- `backend/app/api/run_shutdown.py`: the module docstring now names "the `app/agents/checkpointer.py` module
  docstring" and "`ExecutionEngine.execute`'s per-event `sink.persist(...)`". The step 1 comment names
  `post_message` and `_drive`'s second `try`. The step 4 comment names the checkpointer docstring. The
  `_drain_then_cancel` docstring says "a full Bedrock `read_timeout` away - see `build_model`" with no number
  (ISS-888). The `stop_pipeline_drivers` docstring names each cooperative-cancel boundary by method:
  `_run_agent`, `_execute_impl`, `_run_review_gate`, `_run_validation_fix_loop`,
  `_run_spec_revision_sub_pipeline`, plus `TaskLoopStrategy.run` and `fanout._check_cancel` ("among others",
  per the ISS-104 analysis). It also names the terminal write as `_drive_launch_to_queue` /
  `_drive_revision_to_queue` (after `pipeline_cancelled`, or in `except asyncio.CancelledError`). The
  QA-KB-043 block (`runs_left_for_boot_restore`, ISS-872) is byte-identical.
- `backend/app/api/run_engine.py`:
  - The sentinel paths are now named as the `finally` of `_drive_launch_to_queue`,
    `_drive_revision_to_queue` and `engine._drive_resumed_stream`.
  - The seven queue+task registration sites are named: `resume_run_endpoint`, `_dispose_concierge_proposal`,
    `post_message`, `_launch_run_core`, `create_revision`, and both resume branches of
    `restore_non_terminal_runs`. The authoring commit `0db4a343c` resolves its numbers to exactly these
    functions. A scan of each queue-to-task span today finds no `await`.
  - The `object()`-sentinel cite now points at `tests/integration/api/test_rest_resume_api.py`'s
    `test_resume_already_running_409`.
  - The atomicity cite now points at the "Ordering pin" in `resume_run_endpoint`'s docstring.
  - The cancel-event-before-queue site is now `_launch_run_core`.
  - `assert_owns` is now cited as `ScopedStore.assert_owns`.
- `run_engine.py`, `_resolve_owned_parent_run_id` docstring: the change goes beyond the card's table. The two
  cited handlers (`_handle_workflow_execution`, `_handle_revision_execution`) no longer exist. The claim that
  "both parent-link ingress sites route through this resolver" was also no longer true. Today only
  `_launch_run_core` calls it. `create_revision` loads the parent with its own inline
  `WorkflowRun.id == run_id, WorkflowRun.user_id == current_user.id` filter. The docstring now says exactly
  that, comment only.
- `backend/app/api/run_stream.py`:
  - The `websocket.py:1157` provenance now reads "the deleted WebSocket transport".
  - `gate_pendency.py:53-62` is now `gate_pendency.py` (zero-line-number convention).
  - The `authz.py` pair now names `ScopedStore`.
  - `run_commands.py:758` is now `run_commands.py`, after the `post_message` idiom the sentence already names.
- `backend/app/core/config.py`:
  - `stop_grace_period` now cites "the backend service in docker-compose.yml".
  - The test path is now `tests/unit/services/test_shutdown_reachability.py`.
  - The chat_reply cite is now "`_drive` inside `run_commands.post_message`".
  - The resume cite is now `resume_run_endpoint`.
  - `server.py:326-330` is now uvicorn's `capture_signals`.
  - The metrics-adapter comment now says "NOT the Bedrock model clients' long read_timeout" (ISS-888).
- `backend/app/services/host_metrics.py`: the same ISS-888 disambiguation in the `_client` docstring.
- `backend/docker-entrypoint.sh`: `docker-compose.yml:138` became "the backend service in docker-compose.yml".
- `backend/tests/unit/services/test_shutdown_reachability.py`: comments and docstring only, no assertion
  touched. Two scope reasons apply. The ISS-104 card names the teardown-budget table and asks for its conversion
  "in the same change". The guard scans this file. The table's rows now read `run_shutdown.py step 1` /
  `step 1 escalation` / `step 2b` / `step 2b escalation` (the same wording as the `config.py` table), then
  `_drain_then_cancel first/second wait` and `close_checkpointer's wait_for`. `run_stream.py:421` (twice, in a
  duplicated comment block) became `stream_run_events`.

Not changed, on purpose: the guard test and its strict `xfail` markers (left for the 6-verifier); the optional
`backend/CLAUDE.md` rule the ISS-104 analysis floated; the 99 repo-wide cites outside these files, which ISS-885
says not to sweep under this card. Cites the guard does not see, and the drift left in
`test_shutdown_reachability.py`, are recorded as [ISS-903](20261001-2145-ISS-903.md).
