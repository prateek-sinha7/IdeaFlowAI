# ISS-1116

**Register source:** deferred by [FIX-766](20261008-1444-FIX-766.md) (QA-KB-100). [ISS-1111](20261008-1415-ISS-1111.md)'s fix direction
asked for these lines to be corrected "with the same change". They were left alone so the security diff stays reviewable.
This card holds that leftover work. No behaviour is wrong; the documentation is.

**Confidence:** CONFIRMED by reading at HEAD `d284eb258`. `_TRUSTED_SOURCES = frozenset({"file", "builtin", "db"})`
(`compiler.py:228`, commit `ea2db4e02`, [ADR-0039](20260904-1424-ADR-0039.md)) and `TRUSTED_TRUST_LEVELS` (`permission_caps.py:75`)
both hold `db`.

## Condition

`grep -n "user/db\|user\`\`/\`\`db\|\`\`user\`\` or \`\`db\`\`"` over the three files lists the statements that still treat `db`
as untrusted:

| file:line | says |
|---|---|
| `compiler.py:313-314` | `compile()` docstring: "``user`` or ``db`` are UNTRUSTED" |
| `compiler.py:499` | `_check_trust` docstring: "an untrusted (``user``/``db``) manifest" |
| `compiler.py:1017-1018` | grant path: "A user/db manifest granting any of them is a CompilerError" |
| `compiler.py:241`, `:250`, `:367-368`, `:447-451`, `:468` | Limits: "a user/db manifest may only LOWER" |
| `compiler.py:1558`, `:1589` | MCP: "(user/db) manifest the server MUST be user_allowed" |
| `engine.py:5911-5912` | "a user/db manifest can never provision the exec workspace" |
| `_exec_support.py:54-55` | the same sentence |
| `compiler.py:475`, `:511`, `:1594` | **runtime error strings**: "a user/db manifest may not reference it (CAP-03)" and similar |

## Why it matters

[ISS-1092](20261007-2308-ISS-1092.md) is what this wording costs. The override merge was written in `732adc245`, when `db` meant
untrusted. `ea2db4e02` changed the constant and left these sentences behind. A reader who trusts the `compile()` docstring
still believes `trust="db"` applies CAP-03. The `exec` statements (`engine.py`, `_exec_support.py`) are the premise of the
run-scoped exec grant (WR-03). For a Composer row they have been false since ADR-0039. Whether that should stay true for lower
tiers is the open decision in [ISS-1114](20261008-1415-ISS-1114.md).

## Fix direction (not applied)

Rewrite the docstrings and comments to say that only `user` is untrusted and `db` is trusted since ADR-0039 (Composer rows). Name
the override exception: an override's steps compile at `user` through `compile_override_steps` (FIX-766). Treat the three
runtime error strings separately. Grep the tests for them before changing a word, because a test may assert on the text.
Settle [ISS-1114](20261008-1415-ISS-1114.md) first, or write the exec sentences so they stay true whichever way it goes.
