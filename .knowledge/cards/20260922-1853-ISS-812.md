This portion (`runs?limit=50` x2, `workflows` x2) is the already-cataloged

**New, on clicking the Config tab specifically** (not present on initial

```
GET /api/capabilities      — 2x  (NEW — genuinely distinct endpoint from the

                                    and only fires from this tab)
```

### Expected

Opening the Config tab fires `GET /api/capabilities` once — `ConfigLeversFlat`
has exactly ONE call site of `useAgentCapabilities` (`AgentsPopup.tsx:1730`,
rendered once at `AgentsPopup.tsx:775`), so a single request is what the
component tree implies.

### Root cause — traced

`useAgentCapabilities` (`AgentsPopup.tsx:1530`) runs a plain
`useEffect(..., [token])` (`:1539-1544`) that calls `fetchCapabilities(jwt)`
(aliased `getCapabilities` from `frontend/src/lib/api.ts`, imported
`AgentsPopup.tsx:24`) with no in-flight request cache. `ConfigLeversFlat`
(`AgentsPopup.tsx:1717`) has only ONE call site of this hook
(`:1730`), so the doubled request is not the multi-call-site pattern
[ISS-796](20260922-1825-ISS-796.md) documents for the composer's
`CanvasView`/`CanvasConfigRail` — it is the SAME single-call-site double-fire
shape already diagnosed for other consumers of ungated effects in this app
(React 18 dev StrictMode double-invoking the mount effect). `getCapabilities`
in `frontend/src/lib/api.ts` has no module-level de-dup keyed by URL+token,
so nothing collapses the second call.

### Fix — not applied (validation only)

Same direction as [ISS-782](20260922-1610-ISS-782.md)/[ISS-796](20260922-1825-ISS-796.md):
give `getCapabilities` in `frontend/src/lib/api.ts` a shared in-flight-request
cache keyed by URL+token. That single change also collapses this card's
duplicate, `ISS-796`'s composer duplicates, and any other caller, without
touching `useAgentCapabilities` or `ConfigLeversFlat` individually.
