## What was wrong

A cold `/dashboard` load fetched the same three payloads twice each —
`GET /api/analytics/summary?range=all`, `GET /api/runs?limit=50` and
`GET /api/workflows` — and the third of those was wasted even on a single,
non-doubled call.

Three distinct mechanisms, one per card:

- **[ISS-784](20260922-1812-ISS-784.md)** — `HomeLaunchGrid.tsx:200-213`'s
  mount-only `fetchAnalytics` effect (empty deps, no in-flight guard, no
  cache) doubled by React StrictMode's dev mount→unmount→remount.
- **[ISS-808](20260922-1850-ISS-808.md)** — `frontend/src/app/[...view]/page.tsx`'s
  `[isAuthenticated]` effect (the 990-1007 range the card was written
  against), which calls `getWorkflows(token, { limit: 50 })` — i.e. literally
  `GET /api/runs?limit=50` — with no guard, doubled the same way. This card
  also corrected [ISS-784](20260922-1812-ISS-784.md)'s guess that
  `reduxRecentRuns` was the source; that is a separate `limit=6` call.
- **[ISS-807](20260922-1852-ISS-807.md)** — the `getWorkflowDefinitions()`
  call in that same effect fed a `homeWorkflows` prop `DashboardLayout`
  destructures at `:458` and never reads, so the whole 22 KB round trip was
  discarded on every route (`[...view]` is the catch-all).
- **[ISS-811](20260922-1854-ISS-811.md)** — INFERRED, never reproduced: that
  the `analytics/summary` doubling would also recur on a WARM revisit, since
  `DashboardLayout.tsx:2872` mounts `HomeLaunchGrid` only while
  `mainView === "home"`.

## What changed and why there

**No application source was changed by this card.** All three confirmed
mechanisms were already closed, in the working tree, by two fixes that landed
on the shared seam for sibling bugs — which is exactly where
[ISS-808](20260922-1850-ISS-808.md) said the fix belonged
("`frontend/src/lib/api.ts`'s shared `fetchWithAuth()`/`request()` layer"):

- [FIX-617](20260922-1935-FIX-617.md) added `cachedGet()`
  (`frontend/src/lib/api.ts:410`, keyed `${token}\0${path}`,
  `SHARED_GET_TTL_MS = 30_000`) and routed `getAnalyticsSummary`
  (`api.ts:997`) through it — closing
  [ISS-784](20260922-1812-ISS-784.md) — and deleted the dead
  `getWorkflowDefinitions` prefetch from `page.tsx` (a comment marking its
  removal now sits at `page.tsx:1032-1039`) — closing
  [ISS-807](20260922-1852-ISS-807.md).
- [FIX-616](20260922-1923-FIX-616.md) added the `inFlightWorkflows`
  single-flight Map to `getWorkflows()` (`api.ts:871-894`), so StrictMode's
  second invocation — measured 1-3 ms behind the first — shares the open
  promise instead of opening a second request. That closes
  [ISS-808](20260922-1850-ISS-808.md).

This card's job was to verify that, which it did: three of the four tests
XPASS against the running app (see coverage block). Re-fixing any of it would
have been a second guard on a seam that already has one.

**The one file this card changed** is the test, and only
[ISS-811](20260922-1854-ISS-811.md)'s case:
`tests/integration/e2e/suites/02_home_catalog/test_qa_ps_039_dashboard_duplicate_requests.py:131`,
`assert count == 1` → `assert count <= 1`.

The app was NOT bent to the test; the test's exact number was bent to the
card. Observed, with `--runxfail` so the real assertion surfaced:

```
AssertionError: expected one call to /api/analytics/summary on the warm revisit,
saw 0 — requests: ['http://localhost:3000/dashboard?_rsc=12qg9',
'http://localhost:3000/favicon.ico?favicon.0x3dzn~oxb6tn.ico',
'http://localhost:8000/api/runs?limit=50']
assert 0 == 1
```

Zero, not two. The inferred doubling does not occur, and the reason it does
not is the fix [ISS-811](20260922-1854-ISS-811.md) itself prescribed — its
"Impact if confirmed" section asks for "a cache/dedup layer keyed by request
..., not ... component-local state that resets every remount". A 30 s cache
necessarily answers a revisit inside its TTL from memory, with no request at
all. So `== 1` asserted a number the card's own prescribed remedy rules out,
while the defect the card actually names — the test's own docstring says
"not twice" — is the DOUBLING. `<= 1` is that intent, and it is also the
only stable form: `SETTLE_MS` is env-tunable (`E2E_SETTLE_MS`, default 5000),
so at ~10 s into a 30 s TTL the strict-equality version flips between 0 and 1
on wall-clock timing alone.

client-side Library→Home toggle. It is a single call, not a duplicate, no
card in this bug covers it, and `/api/runs` is deliberately excluded from

[FIX-617](20260922-1935-FIX-617.md)). Left alone; noted for whoever owns
QA-PS-040.
