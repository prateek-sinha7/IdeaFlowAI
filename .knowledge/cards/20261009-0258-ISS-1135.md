# ISS-1135

**Register source:** sibling derived during the `QA-KB-107` analysis on 2026-10-09 (root [ISS-1133](20261009-0200-ISS-1133.md)). Not its own bug row.

**Confidence:** the mechanism is CONFIRMED by an offline probe, rows 5 and 7 of `evidence/qa-kb-107/analysis-02-preflight-vs-build_model-matrix.txt` (constructors
replaced by recorders, no network): `preflight=REFUSE`, `build_model=ChatMistralAI`. INFERRED: that any real environment is configured this way, and the HTTP
launch (not driven). The reach is narrow, see "Condition".

## Condition

- `build_model` treats Bedrock as configured only when a model or profile id AND `AWS_REGION` are set (`backend/app/agents/model_factory.py:457-460`). When it is not,
  and `MISTRAL_API_KEY` is set, it returns `ChatMistralAI` (`:461-476`) and never touches Bedrock. `config.py:105-111` documents this as the third-tier fallback,
  "only when neither ANTHROPIC_API_KEY nor Bedrock resolves".
- `preflight_check_provider` has no such rung. After the `ANTHROPIC_API_KEY` early return (`:117-118`) it decodes `settings.AWS_BEARER_TOKEN_BEDROCK` and refuses when
  it is past its expiry (`:119-135`), whatever `build_model` would do next.
- Reach: `Settings` ships non-empty defaults (`BEDROCK_MODEL_ID` `config.py:124`, `BEDROCK_INFERENCE_PROFILE_ID` `:142`, `AWS_REGION` `:149`), so Bedrock counts as
  configured out of the box. The Mistral rung needs an operator to blank both ids or the region on purpose and to leave a stale bearer token in the environment. The unit
  fixture `_clear_provider_settings` does exactly that blanking (`backend/tests/unit/app/test_model_factory.py:61-74`).

## Expected vs actual

Expected: a Mistral-only configuration launches, as `build_model` would serve it. Actual: 503 `model_provider_unavailable` with "Bedrock bearer token expired ...
rotate AWS_BEARER_TOKEN_BEDROCK", for a provider the run never uses.

## Why the root cause implies it

Same partial copy of the chain as [ISS-1133](20261009-0200-ISS-1133.md), the other missing rung. It is a separate card because a fix that only adds the Ollama guard
leaves it open, and because it carries a trap for the fix (below).

## Fix direction (INFERRED, not applied)

Extract `bedrock_configured` (`model_factory.py:457-460`) into one helper that both `build_model` and the preflight call, and in the preflight return `(True, None)`
when Bedrock is not configured AND `MISTRAL_API_KEY` is set. Mirror rung 5 exactly. Do not skip "whenever Bedrock is unconfigured": the existing expired-token tests
(`test_model_factory.py:397-423`) run with the fixture's blanked ids and no Mistral key, and they must keep refusing.

Row 6 of the matrix (nothing configured at all) refuses with a token message while `build_model` would raise `ModelConfigurationError`. Both fail and the message
blames the wrong thing. That is a separate question and not part of this card.

## Test notes

In `TestPreflightCheckProvider`: expired token, `settings.MISTRAL_API_KEY = "m"`, Bedrock ids blank (the autouse fixture already does it), flag pinned off with
`monkeypatch.setenv("USE_LOCAL_OLLAMA", "0")`. Expect `(True, None)`; today it is `(False, ...)`. Control: the same without the Mistral key must stay `(False, ...)`,
so a guard that skips everything cannot pass. See [ISS-1136](20261009-0258-ISS-1136.md) for why the flag must be pinned.
