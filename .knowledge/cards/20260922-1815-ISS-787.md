## What happened

Register entry: QA-PS-040. Reported 2026-09-17: opening `/library` fired 5
requests (64 KB) including a duplicated `GET /api/me` and an unused
`GET /api/runs?limit=50` (37 KB) that the Library page never displays (no run
history/recents section on this page).

Re-validated 2026-09-22 against the current app (`feat/git-versioning`
branch). The exact endpoint names have moved since the report was filed, but
the core defect — duplicate/unnecessary XHRs firing on every Library cold
load — reproduces exactly as described.

### Reproduction (3/3 cold starts, cycle 1 already showed it)

1. Sign in as `qa-admin@flowinqa.com` / `flowin-e2e-pass`.
2. Cold-navigate (`about:blank` → `http://localhost:3000/library`), never a
   soft in-app nav.
3. Inspect XHR/fetch network requests.

No narrowing was needed — no tier, theme, timing or viewport axis flips this;
it fires on every attempt, identically, 3/3.

### Expected

Per the original report, `/library` should fire roughly 2 requests: the
workflow/agent/skill/hook catalog and one current-user identity call.

### Actual — observed 2026-09-22, all three cold-start attempts identical

```
GET /api/runs?limit=6         — 1x  (unused; Library shows no run history)
GET /api/auth/me              — 1x  (renamed from /api/me; NOT duplicated
                                       as the original report claimed)
GET /api/runs?limit=50        — 2x  (DUPLICATE, unused on Library)
GET /api/workflows            — 2x  (DUPLICATE)
GET /api/agents/library       — 1x  (catalog now split into three calls,
GET /api/skills/library       — 1x   additional to /api/workflows, not
GET /api/hooks/library        — 1x   present when the report was filed)
```

The `/api/runs?limit=50` duplication is a genuine double backend call, not a
display artifact of the observation tooling: the two responses carry distinct
`x-request-id` headers (`b7368dd8f8d34476bbfbf118028a6984` vs
`eccc411eec984c56bb7bd25f5720c827`) with identical `x-total-count: 318` and
`content-length: 29703`.

So: `/api/me` is no longer duplicated (app fixed or renamed away that part),
but `/api/runs?limit=50` and `/api/workflows` are now each duplicated instead,
and `/api/runs?limit=6` is an additional unused call not present in the
original report. Net effect — wasted/redundant network traffic on every
Library page load — is the same defect, just relocated to different
endpoints as the app evolved.

### Root cause — not traced (analyze phase)

Not investigated here. Likely candidates worth checking first: a page-level
effect firing twice (React StrictMode double-invoke in dev, or two
independent components each calling the same RTK Query endpoint without
request de-duplication) somewhere in `frontend/src/components/library/`; the
`/api/runs` calls (limit=50 and limit=6) may come from a shared layout/sidebar
component (e.g. `DashboardLayout`) mounted alongside the Library page rather
than from Library code itself — check whether they also fire on other routes.
`frontend/src/store/api/workflows.ts` and `frontend/src/store/api/runs.ts`
are the RTK Query endpoint definitions to trace call sites from.
