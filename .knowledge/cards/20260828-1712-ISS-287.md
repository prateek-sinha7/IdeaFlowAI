# ISS-287

**Root-cause mechanism superseded by [ISS-392](20260828-2250-ISS-392.md):** the Root Cause
section below claims `LibraryPage` mounts `AgentsPopup`'s `AgentCapabilitiesModal` WITHOUT an
`onSelectionsChange` prop. Reading the current call site (`LibraryPage.tsx:1040-1043`) shows this
is wrong — `onSelectionsChange` IS supplied; it only ever reaches a non-durable in-memory
`useRef` (`savedSelectionsRef`), because no caller of `AgentCapabilitiesModal` has a backend
endpoint to call for this data at all (`AgentsPopup.tsx:732-735` and two sibling comments say so
explicitly). See ISS-392 for the corrected mechanism and full file:line trail. This
reproduction (3/3, cold start every cycle), its evidence, and its no-network-call findings are
unaffected and remain the basis for `BUG-20260828-025950-library-agents-id`'s confirmed status.

## Title

Library agent detail's Config tab "Save agent" button silently discards a Model/Validator/Gate/
Retry override with no network request, on `/library/agents/<agentId>`.

## Reproduction (3/3, cold start every cycle)

Reproduced on **cycle 1, cycle 2, and cycle 3**, each from a cold navigation (not a soft
re-click):

- Cycle 1: deep-link cold load to `/library/agents/material-analyzer`, no prior state.
- Cycle 2: cold load to `/library`, click through the "Architecture Agent" card's
  "Configure →" affordance (per `libraryAgentCardNeedsConfigureClick` quirk) to reach the same
  drawer/route.
- Cycle 3: deep-link cold load to `/library/agents/material-analyzer` again, this time selecting
  a different override value ("Claude Opus 4.5" instead of "Claude Sonnet 4.5") to rule out a
  value-specific fluke.

Steps per cycle:
1. Sign in as qa-admin (session already established).
2. Navigate to `/library/agents/material-analyzer` (directly or via Configure →).
3. Click the "Config" tab in the drawer.
4. Open the "Model for Architecture Agent" combobox and select a non-Default option.
5. Click "Save agent".
6. Inspect `browser_network_requests` since the click.

**Result every cycle:** zero PUT/POST/PATCH requests to any `/api/agents/*` or config endpoint.
The only network activity is the routine `GET /library?_rsc=...` from the drawer closing and
navigating back to `/library`. Re-opening the agent detail (cold reload, cycle 1) shows the
Model reverted to "Default" — the edit never survived past the drawer closing.

## Expected vs Actual

**Expected:** either the override is actually persisted (a network call fires and the value
survives a reload), or the Library's read-only agent-detail view does not present editable
Model/Validator/Gate/Retry controls behind a "Save agent" button that implies the change takes
effect.

**Actual:** the click makes no API call, discards the edit, and closes the drawer with a
"✓ Saved" flash and no error — success-looking UI for a change that was never persisted anywhere.

## Root cause

`frontend/src/components/workflow/AgentsPopup.tsx:774-793` — the "Save agent" button's `onClick`
calls `onSelectionsChange?.(localSelections)` then closes the drawer. That is the ENTIRE
persistence path: there is no `fetch`/API call anywhere in this handler.

`onSelectionsChange` is optional and only wired to something real when the *caller* wires it —
e.g. inside the workflow composer, where the parent persists selections into workflow state.
`AgentsPopup.tsx:531-534` documents this explicitly:

```
// Local per-agent selections state for the Config tab when the caller does
// not supply onSelectionsChange (e.g. LibraryPage drawer). Merges with the
// prop-driven path so AdvancedExpander always renders in the Config tab.
```

`/library/agents/<agentId>` is rendered by `LibraryPage`, which mounts `AgentsPopup` WITHOUT an
`onSelectionsChange` prop (the comment names this exact call site). So
`effectiveOnSelectionsChange` (`AgentsPopup.tsx:538-541`) only calls `setLocalSelections` —
updating the drawer's own transient React state — and the optional `onSelectionsChange?.()` is a
no-op. Nothing writes to any parent ref, localStorage, or the backend. The moment the drawer
unmounts (drawer close, or a cold reload), `localSelections` is gone.

This is distinct from the already-fixed `ISS-046` (stale `model_overrides` on save-to-catalogue,
fixed 2026-07-10) and from `ISS-167`/`ISS-258` (AgentsPopup's outer workflow-save footer button
and route-editor `onSelectionsChange` wiring, respectively) — those cover different call sites
and a different button. This defect is specific to the Library drawer's Config-tab "Save agent"
button having no persistence wiring at all.
