# ISS-860

Found while writing [FIX-641](20260923-0229-FIX-641.md). Not fixed there. It is a
test-fixture defect in a CLOSED bug's file (QA-PS-027), and QA-PS-021 did not ask
for it.

## What is wrong

`test_native_prototype_pipeline_placeholder_output_not_marked_completed`
([ISS-761](20260922-1424-ISS-761.md)) says its build agent "only streams placeholder
text, then reports the task complete". The harness does not do that:

- `_prototype_placeholder_scripts` gives `prototype-build` exactly ONE
  `_ScriptedTurn`, and that turn carries a `report_task_complete` tool call.
- `ScriptedFakeChatModel._next_turn` (`tests/agents/_scripted_model.py`) returns
  `turns[idx] if idx < len(turns) else turns[-1]`. Once the script runs out, the model
  replays that tool-call turn forever.
- The graph never reaches a stop condition. The captured log of the test shows
  `deep_agent_runner.py:1298 DeepAgentRunner.astream_events failed: Recursion limit of
  1000 reached`, followed by `engine.py:9586 Agent prototype-build: runner surfaced an
  error event — marking failed (no completion)`.

So the scenario being tested is "the build agent errored", not "the build agent
cleanly reported completion without writing". Each run also spends about 10 s on the
1000-step loop.

## Why it is low severity

The test still proves what it exists to prove. With FIX-612's gate neutralised
(`agents.capabilities.deliverables._placeholder.placeholder_narration_reason =
lambda *a, **k: None`), the test fails at its `published_status` assertion. That was
observed during FIX-641. The failed build agent does not publish a degraded status
in this harness, because the test stubs `finalize_terminal_run` with a clean record.
The placeholder gate is the only thing that degrades the run.

## Fix direction (not applied)

Give `prototype-build` a second, text-only `_ScriptedTurn` after the tool-call turn,
so the graph stops cleanly. Then re-check the test's `final_output` precondition.
Branch 3 reads `ctx.last_streamed`, so the expected value may shift with the change.

## Analysis (QA-KB-039, analyzer, 2026-10-01)

**Verdict: the root cause above is CONFIRMED against the tree as it stands (HEAD `024c03ef8`;
every file cited below is unmodified versus HEAD). Its meaning does not change, so nothing is
superseded.** Four details above have drifted and are corrected here rather than rewritten in
place: the recursion limit is now 2500 (`backend/app/core/config.py:402`); the cited lines
moved (`deep_agent_runner.py:1415`, `engine.py:10535`); a run costs 35-96 s, not ~10 s; and
"does not publish a degraded status" is true of `published_status` only (point 5).

### Root cause: CONFIRMED (each cite opened and read)

1. **Fixture.** `backend/tests/agents/test_qa_ps_027_placeholder_completion.py:138-153`:
   `_prototype_placeholder_scripts("prototype-build")` returns a one-element list. Its only
   `_ScriptedTurn` has `texts=[PLACEHOLDER_TEXT]` and a `report_task_complete` tool call.
2. **Harness.** `backend/tests/agents/_scripted_model.py:166`:
   `turn = turns[idx] if idx < len(turns) else turns[-1]`. After the script runs out the LAST turn
   repeats. This is the deliberate "proven recipe", unchanged since the harness's first commit
   (`030820bef`, 2026-06-04, then in `_parity_driver.py`), so it is not a regression. It is
   harmless when the last turn is text-only (a text-only AI message ends the graph) and a
   runaway when the last turn carries a tool call.
3. **Loop.** The tools node runs `report_task_complete`, the model is called again, `_next_turn`
   replays the same tool-call turn, and the graph never receives the text-only message that
   stops it. It runs until `AGENT_RECURSION_LIMIT` (`config.py:402` = 2500, applied at
   `backend/app/agents/deep_agent_runner.py:1002`): 833 replays in one run.
4. **Failure path.** `deep_agent_runner.py:1415` logs the `GraphRecursionError` and yields
   `{"type": "error"}`. The engine's error arm (`backend/agents/execution_engine/engine.py`, from
   `if agent_errored:` at `:10531`, warning at `:10535`) marks `prototype-build` failed, records the
   (agent, task) failure pair (`:10560`) and returns before `results.append`. Per-task validation
   then logs "wrote no prototype.html — skipping validation" (`:11206`), the task loop finishes
   and `prototype-validate` runs.
5. **Why a pass hid it.** The test stubs `finalize_terminal_run` with a clean record (`:53-73`,
   `:171`) and asserts only `published_status` (`:184`). `engine.py:8150-8161` takes `_s5_pub`
   from that record, and only `_placeholder_reason or _dropped_reason` escalates it. The failed
   build agent does set `status="degraded"` and `agents_failed` (`engine.py:8032-8035`), but
   nothing asserts them. So the pass is driven by [FIX-612](20260922-1838-FIX-612.md)'s gate (the
   right signal) over a run that is "build agent failed", not the docstring's "build agent
   cleanly reports completion".

### Where the fix belongs: the agreed fix is ACCEPTED

In `_prototype_placeholder_scripts` (`test_qa_ps_027_placeholder_completion.py:138-153`), append
after the `report_task_complete` turn: `_ScriptedTurn(texts=["Task complete."], usage=(5, 3))`.
Keep the validate script streaming `PLACEHOLDER_TEXT`: `single_file.py:170-181` (branch 3) reads
`ctx.last_streamed`, the last agent to run, which is validate. Constraints for the fixer: no
application-code change (fixture/test scope); leave the exact-equality precondition and the
`published_status` assertions as they are ([FIX-641](20260923-0229-FIX-641.md) locked both).

Not recommended: guarding `_next_turn` in the shared harness. One of 34 tool-calling turns
violates the convention, so the guard would protect a single fixture while changing the replay
semantics ~60 files rely on, and it would not reach the three private copies. The bug is scoped
to the fixture.
