# FIX-736

Bug report QA-KB-077. The root cause and blast radius come from the analysis cards. They are not re-derived here, except
for one layer the analysis did not reach, called out under ISS-1019 below. Every change is to tests, test fixtures or test
documentation. No production module changed.

## What was wrong

All three cards share one mechanism. `b2a621f84` (2026-09-17, Cognito-only sign-in, migration 0038) removed a local-auth
surface, and the tests of that surface survived. The unit I/O guard from `09270703b` (2026-09-22) then hid the staleness
behind a setup error.

- [ISS-904](20261001-2149-ISS-904.md) (root): `backend/tests/unit/test_iss401_reset_password_message.py` built the break-glass
  `User(cognito_sub=None, auth_provider="local", password_hash=...)` and expected a 409 that `reset_user_password`
  (`backend/app/api/admin.py:502-545`) no longer has. It failed four layers deep: guard, seed `TypeError`, request-body
  `ValidationError`, deleted 409. Its subject is gone.
- [ISS-1017](20261002-0617-ISS-1017.md): `test_register_password_echo.py` (ISS-257) and `..._fixture_mounts_real_app.py`
  (ISS-357) posted to `POST /api/auth/register`, which answers 404. Their guarantee is still live: the 422 redaction handler
  `_validation_error_handler` (`backend/app/main.py:539`, [FIX-332](20260828-1915-FIX-332.md)). Nothing else pinned it
  offline. A live spec, the contract snapshot, the contract feature file and three comments still described a 403 route.
- [ISS-1019](20261002-0617-ISS-1019.md): seven test files built `User` without the NOT NULL `cognito_sub`
  (`backend/app/models/user.py:51`).

## What changed, and why there

**ISS-904: delete.** `rm backend/tests/unit/test_iss401_reset_password_message.py`, as the card directs (no relocation, no
reseed). The Cognito reset path stays covered by `TestPasswordResetAtomicity`
(`tests/integration/api/test_admin_privilege_atomicity_api.py:230-295`, 3 passed before and after). The test phase's pin
`tests/unit/test_user_seed_kwargs_are_columns.py` now XPASSes (strict).

**ISS-1017: re-point the guarantee, then retire the dead vehicles.**

- New `backend/tests/unit/app/test_main.py`. The path follows the README mirror rule for `app/main.py`. The test mounts the real
  `app.main.app` with `get_current_user` and `get_db` overridden, and does not enter the lifespan. It sends
  `PUT /api/settings/github-pat {"pat": "short7!"}` (`GithubPATRequest.pat`, `min_length=10`, `settings.py:71`) and asserts a
  422 that does not contain the value. It passes under the unit I/O guard. It is not vacuous: with FastAPI's
  `request_validation_exception_handler` swapped in for the custom one, the same test function fails and the body carries
  `"input":"short7!"` (`evidence/qa-kb-077/fix-02-mutant-check-script.py`, output in `fix-02-mutant-check-output.txt`). Of the card's two options,
  re-point was chosen. Retire-only would have left the live e2e test as the sole guard.
- `rm` of both register files.
- The stale consumers the card listed, all edited so the docs describe the route as removed:

**ISS-1019: seed, and one layer the analysis did not reach.**

- `cognito_sub=str(uuid.uuid4())` added to the four seeds in `tests/agents/test_per_run_paths_v3.py:118`,
  `test_version_family_v5.py:101` and `test_revision_ordinal_v3.py:335,422`. All three files already import `uuid` at module level.
- **Layer 2, found here and not in the card.** With the seed alone, `test_version_family_v5.py` (2) and
  `test_revision_ordinal_v3.py` (2) still failed: `assert 'degraded' == 'completed'`. `finalize_terminal_run` logged
  `tag DB mapping FAILED after 2 attempts ... rolling back tag` (`engine.py:2678`), then
  `attempt.degrade("tag_mapping_failed")`. The cause is the scripted harness. `09270703b` made `_prepare_engine_run` replace
  `app.models.database.SessionLocal` with a raiser by default (`offline_db=True`, `tests/agents/_scripted_model.py:931`).
  Before that commit the harness patched no SessionLocal. That commit moved one caller to `offline_db=False`
  (`test_run_revision_fe_contract.py`). It missed these two, which were already red on NOT NULL. Their own comments say the
  engine must see the rows they seed in the real hermetic DB (`test_revision_ordinal_v3.py:323-327`), and the harness
  docstring names exactly this case for `offline_db=False`. So the three real-finalization drives now pass `offline_db=False`.
  Assertions are untouched. Evidence: `evidence/qa-kb-077/fix-05-layer2-offline-db-seam.txt`. This is test-only and uses the
  harness's documented opt-out. It is recorded on ISS-1019 so the analysis there is no longer short a layer.
- Unit files, probed before choosing (`evidence/qa-kb-077/fix-06-unit-race-pins-probe.txt`):
  - moved with `mv` to `tests/integration/api/` (README rule 7, FIX-691's `_api` naming), seed added:
