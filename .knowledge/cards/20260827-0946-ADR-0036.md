## Decision

Agents can be granted a browser. The tool set is
`playwright_navigate`, `playwright_snapshot`, `playwright_click`,
`playwright_type`, `playwright_take_screenshot`, `playwright_console_messages`,
`playwright_wait_for`, `playwright_evaluate`, `playwright_close`, bound per run
through `RunSandbox` in the same shape spec 017's pptx set uses: the capability
provider emits string keys (import-clean of `app.*`), the factory resolves them.

Granting is one line of `AGENT.md` frontmatter — currently on `ppt-deck-qa-v2`
and `prototype-validate`. `user_allowed=False`, so a user cannot select it in the
composer; only a file manifest can grant it.

## Lifecycle

`PlaywrightSession` (`app/agents/playwright_session.py`) owns it: lazy launch,
**one browser per run, one BrowserContext per agent**.

Two constraints here are load-bearing and non-obvious:

- **It is released from a `finally:` in `ExecutionEngine.execute()`** covering
  every exit path including `GeneratorExit`. `engine.py` had no such block
  before, so a run's browser could outlive the run itself.
- **It is never `async with`.** That pattern is exactly what
  [FIX-307](20260826-0124-FIX-307.md) fixed: it tears the browser down between
  tool calls, which destroys the persistent-session-across-tool-calls guarantee
  this whole feature is built on.

## URL policy

`resolve_url_policy` governs what `playwright_navigate` may open, from
`BROWSER_URL_POLICY` (default `file,localhost`).

This was fixed during live validation: a `file://` URI *has* a scheme, so it fell
into the http(s)-only branch and was refused even when `file` was in the policy.
Only bare paths ever reached the sandbox-resolution branch. Both forms are
handled now.

## Tool contract

Every tool returns actionable text and never raises — including when Chromium is
unavailable on the host. An agent gets a message it can act on, not a traceback.

## Note on exclude_builtin

`exclude_builtin=False` is what keeps `prototype-validate`'s native filesystem
tools alive (spec 018 FR-003). It declared no tools before this change, so a
default-exclude would have silently stripped them. Verified live via
`test_create_runner.py`.
