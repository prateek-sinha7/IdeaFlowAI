# ISS-102

## Title

Three offline unit tests attempt a REAL Bedrock model call; they only 'pass as failures' because the SSO token was expired. tests/unit/test_chat_messages_endpoint.py::TestRouting::{test_clarify_waiting_routes_to_answers_seam, test_gate_paused_routes_to_gate_seam_approve, test_terminal_routes_to_revision} do NOT monkeypatch run_commands._resolve_concierge (unlike TestConciergeStreaming, which does), so the endpoint resolves the real ConciergeCapability, whose ctx carries model=None → build_model() → ChatBedrockConverse. Observed verbatim: DeepAgentRunner.astream_events failed: An error occurred (ExpiredTokenException) when calling the ConverseStream operation — four attempts per run. The cost today is zero only because the credentials are stale; on a machine with a fresh aws sso login these tests spend real money every time the suite runs, and the three are already red for an unrelated reason, so nobody looks at their output. Suggested fix: monkeypatch _resolve_concierge in TestRouting exactly as TestConciergeStreaming already does, and add a suite-level guard that fails any offline test which reaches build_model().

Found 2026-08-12 during quick-260812-gsf. Attributed by running the classes separately: -k TestRouting → 4 ExpiredToken log lines, -k ChatUsage (the new tests) → 0. Pre-existing — this task's own tests never reach a model.
