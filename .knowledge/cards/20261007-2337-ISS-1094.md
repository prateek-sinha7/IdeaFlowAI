# ISS-1094

**Register source:** found by the 5-fixer for `QA-KB-088` on 2026-10-07, while applying [FIX-758](20261007-2338-FIX-758.md).
When filed: not yet its own bug row, not analyzed, nothing changed for it. It is now bug row `QA-KB-101`, analyzed 2026-10-08;
see "Analysis" at the foot of this card. The sections between are the card as filed, kept as written.

## Condition

[FIX-758](20261007-2338-FIX-758.md) moved `tests/unit/api/test_workflows_api.py` to
`backend/tests/integration/api/test_workflows_api.py` (byte-identical) so the unit I/O guard stops erroring it at setup
([ISS-1091](20261007-2308-ISS-1091.md)). Once it ran, 52 of its 53 tests passed and one failed:

```
FAILED tests/integration/api/test_workflows_api.py::TestList::test_list_carries_launchable_flags
E   AssertionError: prototype must carry its authored display_name verbatim (got 'Build an interactive prototype (Fast)')
```

(`evidence/qa-kb-088/15-fix-sibling-files-after-pytest-summary.txt`)

## Expected vs actual (CONFIRMED by a probe, not by the test alone)

The test's `authored` dict (`backend/tests/integration/api/test_workflows_api.py:215-222`) asserts each catalog row's
`display_name` verbatim. A probe of `GET /api/workflows` through the same harness
(`evidence/qa-kb-088/16-fix-found-stale-display-name-probe.txt`, source `16b-...probe.py.txt`) gives:

| id | asserted (`:217-218`) | served | manifest |
|---|---|---|---|
| `prototype` | `Build an interactive prototype` | `Build an interactive prototype (Fast)` | `backend/agents/workflows/prototype/workflow.yaml:5` |
| `ppt` | `Pitch an idea` | `Pitch an idea (Fast)` | `backend/agents/workflows/ppt/workflow.yaml:22` |

The other five labels the test checks (`user_stories`, `app_builder`, `mulesoft_to_springboot`, `dotnet_to_azure`, `custom`)
match. The loop stops at the first mismatch, so the pytest output names only `prototype`.

## Why it was invisible

Timeline (git, this tree): the unit I/O guard landed `09270703b` (2026-09-22) and from then on every client test in the
file errored at setup. `1a1b720b7` (2026-09-25, "feat(dashboard): split the catalog into Start from / Engine examples /
Coming Soon, with user-facing names") then renamed both labels; its message lists "prototype -> 'Build an interactive
prototype (Fast)'" and "ppt / ppt_v2 -> 'Pitch an idea (Fast)' / ..." and updates the e2e locators and suites, but this
file could not go red, so it was not updated.

## Disposition when filed (2026-10-07)

Open. INFERRED (from that commit message, not decided here): the manifests are the intended side and the two expected
strings in the test are stale, which would make the repair a test-only change at `:217-218`. The 5-fixer rule forbids
editing an assertion because it is red, so this was filed instead of changed. Analysis should confirm the rename is the
product's intent (for example against `HomeLaunchGrid.categories.test.ts` and the e2e catalog suite the same commit
edited) before anyone touches the test.

## Analysis (2026-10-08, QA-KB-101, HEAD 7adb69a3f)

Verdict: test-side drift. The manifests are the intended side and the product is right. The card stays open until the two
literals are edited. Evidence is under `evidence/qa-kb-101/analysis-01` to `analysis-05`; every `file:line` below was read.

### Root cause (CONFIRMED by source read, and by two runs at HEAD)

The API serves a manifest's explicit `display_name` verbatim: `backend/app/api/workflows.py:398`,
`display_name=(manifest.display_name if manifest else None)`, under a comment (`:392-397`) that forbids any coalescing.
`test_list_carries_launchable_flags` pins six such labels as hand-typed literals in the `authored` dict,
`backend/tests/integration/api/test_workflows_api.py:215-222`. Two of them, `:217` and `:218`, are the text from before
`1a1b720b7` (2026-09-25, [FIX-645](20260925-1201-FIX-645.md)) renamed `backend/agents/workflows/prototype/workflow.yaml:5` to
"Build an interactive prototype (Fast)" and `backend/agents/workflows/ppt/workflow.yaml:22` to "Pitch an idea (Fast)". The assertion
at `:225` fails. The whole file at HEAD: `1 failed, 52 passed in 28.42s` (`analysis-01`).

Nobody updated the literals because the guard hid the file. `09270703b` (2026-09-22, an ancestor of `1a1b720b7`) made 49 of the
file's 53 tests error at setup (`evidence/qa-kb-088/14-fix-sibling-files-before-pytest-summary.txt`), so the renamer's test run could
not show it; the rename commit edited 11 e2e and spec files and added one frontend test, and not this file (`analysis-04`,
sections 3 and 5). [FIX-758](20261007-2338-FIX-758.md) (`1d49a7c2f`, 2026-10-07) moved the file out of the guard's reach and the
stale text surfaced.

### The question this card left open is settled: the manifests are the intended side (CONFIRMED)

1. `1a1b720b7`'s own message states it: "prototype -> 'Build an interactive prototype (Fast)'", "ppt / ppt_v2 -> 'Pitch an idea
   (Fast)' / 'Pitch an idea (Detailed)'", "Only display_name/description changed" (`analysis-04`, section 6).
2. [FIX-645](20260925-1201-FIX-645.md) records it as a decision with a locked constraint ("Only display_name/description changed;
   short_name ... is untouched") and names the e2e catalog suite as its verification.
3. Three independent artifacts agree on "(Fast)": the manifests, the e2e launchable list
   (`tests/integration/e2e/framework/locators/home_catalog.py:52,54`) and the screens spec table
   (`tests/integration/screens/02-home-catalog.feature.md:46,48`). The only dissenter is this test.
4. A later rename shows the manifests are the side people actively edit: `87903ab3b` (2026-10-01) changed the two v2 labels from
   "(Detailed)" to "(Depth)" and says so in its message. Nobody has asked for the old text back.
5. No spec makes display names a stable contract: `specs/016-workflow-overrides/plan.md:175` says "Only the id is stable" and `:177`
   "The name stays free text."

This card named `HomeLaunchGrid.categories.test.ts` as possible evidence. It is not: it tests `isExampleWorkflow` on ids and pins no
label. The evidence is items 1 to 4. The product owner has already decided, in `1a1b720b7` and `87903ab3b`, so this is not a
decision for the owner and is not escalated.

### Both lines must change in one edit (CONFIRMED by replay)

The loop at `:223-229` raises at the first mismatch, in dict order: `user_stories`, `prototype`, `ppt`, `app_builder`,
`mulesoft_to_springboot`, `dotnet_to_azure`. With only `:217` fixed it goes red on `:218`
(`analysis-02`: "with ONLY `prototype` fixed -> still red: ['ppt']"). With both fixed every other key already matches, including the
separate `custom` assertion at `:231-235`.

### Fix, and where it belongs: the test only

- Edit `backend/tests/integration/api/test_workflows_api.py:217-218` to `"prototype": "Build an interactive prototype (Fast)"` and
  `"ppt": "Pitch an idea (Fast)"`. Proven in a scratch copy outside the repo with exactly those two edits: `53 passed in 19.08s`
  (`analysis-03`), against `1 failed, 52 passed` for the file as it is (`analysis-01`).
- There is no shared function to fix. The one route every consumer of the label uses, `workflows.py:398`, is right.
- Optional, not required: derive the expected label from `backend/agents/workflows/<id>/workflow.yaml` instead of retyping it. That
  keeps the contract this test names (an authored row carries its manifest label verbatim and is never coalesced to the title-cased id,
  `workflows.py:392-397`) and never rots, at the price of no longer catching an accidental label edit. Literals are this file's
  established pattern (six of them), so the two-line edit is the smaller change. The fixer picks.

Do not:

- Revert the manifests' " (Fast)" to satisfy the test. That undoes FIX-645's locked constraint and breaks the e2e suite and screens
  spec that expect "(Fast)".
- Make the API strip or normalise suffixes. `workflows.py:392-397` requires the manifest's explicit label.
- Touch `tests/unit/conftest.py::_unit_io_guard`. It is unrelated and [FIX-758](20261007-2338-FIX-758.md) locks it.
