# ISS-1057

Found during [FIX-727](20261007-1837-FIX-727.md)'s regression run (QA-KB-064). It is not caused by FIX-727 and was not
fixed there, because it is outside that bug.

## What fails (CONFIRMED, observed 2026-10-07)

`backend/tests/agents/test_family_lock.py::TestRestoreLockTimeout::test_upload_handler_timeout_returns_409` fails with
`AssertionError: upload_files must catch FamilyLockTimeout`. The file reports 1 failed, 25 passed, both with FIX-727 and
with the pre-fix `list_tags` patched back in (`evidence/qa-kb-064/fix-05-regression-after.txt`,
`fix-06-regression-baseline-prefix.txt`). `run_files.py` has no uncommitted change, so the failure is at HEAD
`ea5cd2f63`.

## Why (CONFIRMED by reading)

- The test (`test_family_lock.py:1097-1118`) checks `inspect.getsource(upload_files)` for `FamilyLockTimeout` and for
  `409`.
- `upload_files` (`backend/app/api/run_files.py:606`) no longer holds the lock itself. It calls `_persist_documents`
  (`:649`, defined at `:413`), and that function catches `FamilyLockTimeout` and raises `HTTP_409_CONFLICT` with a
  generic detail (`:456-460`). `git log -S _persist_documents` points to `127b20a3d` as the commit that introduced the
  helper.
- INFERRED, not executed: the HTTP behaviour the test guards is intact. The test just reads the wrong function.

## Fix direction

Test-only: point the source check at `_persist_documents`, or better, replace it with a behavioural test that makes
`family_lock` raise `FamilyLockTimeout` and asserts a 409. Do not move the `except` back into `upload_files` to satisfy
the grep, because `_persist_documents` is also reached from `run_files.py:375`.
