## Root cause

The ISS-230 fixture introduced a revision family (root `77f74563` + one revision). A family row opens its LATEST MEMBER when clicked. Four tests selected `completed[0]` or `.first` from the flat row list without checking for multi-version families, landing on revision members whose data differed from what the tests expected.

## What changed per test

### S-06-04 `test_type_filter_counts_sum_to_the_total`
Dropped `all_count == L.total(page)`. The "All" chip counts families; `L.total()` counts runs. They diverge when a revision family exists. Kept `named == all_count` (every family claimed by a type chip) with updated comment.

### S-06-14 `test_opening_a_row_lands_on_that_run`
Replaced `.first` pick with inline `evaluate_all` JS query filtered to `n==1` and `status==completed`. Clicks by index. Added `@pytest.mark.issue("ISS-628")`.

### S-07-04 (via `a_completed_run()`)
Updated `a_completed_run()` body to use the same inline `evaluate_all` query filtered to `n==1` and `status==completed`. Signature unchanged — all callers benefit.

### S-13-11 `test_a_nonexistent_artifact_version_falls_back_to_v1_without_saying_so`
Replaced `completed[0]` match-and-click with inline `evaluate_all` query filtered to `n==1` and `status==completed`. Added `@pytest.mark.issue("ISS-628")`.

## Blast radius

Test-only changes. No app source touched. `a_completed_run()` body change benefits S-07-01 through S-07-25 with no breaking signature change.
