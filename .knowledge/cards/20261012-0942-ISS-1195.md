Tree `/Users/bilala/Developer/Projects/VELOCITY-AI-worktrees/feat-user-stories-v2`, branch `feat/stale-bug-fixes` at `84bfd539c` (HEAD moves as other bugs commit); `git status --short` is empty for every file cited below. `status.py` reports 235 commits since the last sync, so the knowledge base was a lead only: every claim below was read from source, or computed offline from source by `evidence/qa-kb-117/analysis-projection.py` (output beside it, `analysis-projection.out.txt`; no app code executed, no browser, no backend call).

**Verdict.** Root cause CONFIRMED. One mechanism, one line: the grid keeps a tile only if a hand-written display map has a key for it.

### Root cause (CONFIRMED)

1. The grid renders `frontend/src/components/settings/AccountSettings.tsx:509` `getBasePipelines(userTier).map(p => ...)` and takes each label from `PIPELINE_DISPLAY[p].label` (`:512`).
2. `:85-88`:
   ```ts
   function getBasePipelines(tier: Tier): string[] {
     const all = Array.from(TIER_PIPELINES[tier]);
     return all.filter(p => !p.endsWith("_revision")).filter(p => PIPELINE_DISPLAY[p]);
   }
   ```
   The second `.filter` is the drop. An id that is entitled, launchable and offered by the catalog still vanishes if `PIPELINE_DISPLAY` has no key for it.
3. `PIPELINE_DISPLAY` (`:65-74`) has exactly eight keys: `user_stories`, `ppt`, `prototype`, `app_builder`, `custom`, `migration`, `mulesoft_to_springboot`, `dotnet_to_azure`. `git blame -L64,74` attributes all ten lines of the declaration (`:65-74`) to `925121744` (2026-05-19, the original tier-gating commit): the map has not changed since the day it was written.
4. `ex_A2_branch` is entitled: `frontend/src/lib/entitlements.ts:79` (enterprise set), and on the authoritative side `backend/app/core/entitlements.py:78`. It passes the first `.filter` (no `_revision` suffix) and dies on the second. The same happens to `ex_A1_loop`, `ex_A4_human_gate`, `ex_A4_human_divert`, `ex_A3_divert`, `ex_A3_b_spanish`, `ex_A3_c_dutch` (`entitlements.ts:79-85`) and `ex_playwright_smoke_test` (`:89`).
5. The home catalog never consults a label map. `frontend/src/components/catalog/HomeLaunchGrid.tsx`: the list is the live manifest catalog `state.global.workflows` (GET /api/workflows) filtered by `w.user_launchable` (`:155-158`), split into product / Engine examples / Coming Soon by `!w.is_beta`, `isExampleWorkflow(w.id)` and `w.is_beta` (`:290-292`, classifier `:102-103`); the label is `row.display_name ?? getWorkflowLabel(row.id)` (`:296`); the lock is `!isBeta && canRunPipeline(userTier, type)` (`:306`); the group is rendered at `:383-399` (`<h3>Engine examples</h3>` at `:389`). A new launchable manifest appears there with zero frontend edits (the layout's own comment, `DashboardLayout.tsx:3005-3008`). The grid needs one frontend edit per workflow and nobody makes it.
6. The manifests agree with the catalog's reading: `backend/agents/workflows/ex_A2_branch/workflow.yaml:21-24` is `id: ex_A2_branch`, `user_launchable: true`, `is_beta: false`, `display_name: "Branch on a decision"`; the endpoint returns every compiled manifest with no tier filter (`backend/app/api/workflows.py:345`, fields `:164-166`, `:390-391`).

### How it drifted (CONFIRMED by `git log`)

The map is from 2026-05-19 and never moved. The frontend entitlement list it filters kept growing, each addition fixing only the catalog's lock state (`git log -S` on `frontend/src/lib/entitlements.ts`): the ex_A* fixtures (`c9ec0149c`, 2026-08-24), `ppt_v2` (`70665bbcb`, 2026-08-27), `prototype_v2` (`73796dbd0`, 2026-09-18), `backlog` (`756f9bd8e`, 2026-09-29), and the playwright smoke test, entitled under its old name per spec 018 and renamed `ex_playwright_smoke_test` in `380457f99` (2026-09-25). [BUG-097](20260829-1508-BUG-097.md) (2026-08-28) described the basic grid as "2 of 8 types ... accurate against TIER_PIPELINES", so the grid was being read as a list of deliverable TYPES while the catalog shows one card per workflow. Nothing could catch the drift: `backend/tests/unit/services/test_entitlement_parity.py` documents "three hand-maintained lists" (backend `TIER_PIPELINES`, frontend `TIER_PIPELINES`, manifests on disk). The display map is a fourth and no test reads it. No frontend unit test asserts the grid's contents either: none of the five AccountSettings test files opens the Usage tab's grid (they check the tab label and ids, e.g. `AccountSettings.test.tsx:83-113`). The only coverage is e2e (S-09-09/10, S-17-07/08/09), and S-17-08 pins the omission itself (`:253` `assert "Branch on a decision" not in page.evaluate(...)`).

## Fix (FIX-785, 5-fixer, 2026-10-12)

Applied as "Route both surfaces through one function" above. The base tiles keep their labels, so no label call was made. `frontend/src/lib/entitlements.ts` gained `isExampleWorkflow`, moved here from `HomeLaunchGrid.tsx` (which re-exports it), plus `splitCatalog(workflows)` and `catalogAccess(workflows, tier)`. `HomeLaunchGrid.tsx` now splits its rows with `splitCatalog`. The Usage tab's new `DeliverableAccessGrid` (`AccountSettings.tsx`) lists `catalogAccess(state.global.workflows, tier)` and shows the examples in an always-open "Engine examples" group. A label comes from `PIPELINE_DISPLAY` when the id has one, otherwise from `display_name ?? getWorkflowLabel(id)`. Until the catalog has loaded, the grid shows the old tiles (hazard 2). Hazard 1 is avoided because the store read mounts only with the Usage tab. Hazard 5 is avoided because the helpers sit below `TIER_PIPELINES`: the parity test gives 61 passed, 45 skipped. Hazard 4 is avoided because e2e S-17-08 reads the expected set off the catalog. `frontend/src/components/settings/AccountSettings.iss1195.test.tsx`: all four cases now report "Expect test to fail" (XPASS); before the change, 4 expected fail. Detail and coverage are in [FIX-785](20261012-1013-FIX-785.md); raw output is in `evidence/qa-kb-117/fix-01-vitest-runs.txt`.
