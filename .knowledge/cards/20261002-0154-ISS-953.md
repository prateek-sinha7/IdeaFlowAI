# ISS-953

The QA-KB-041 fixer's regression run found this ([FIX-710](20261002-0154-FIX-710.md)). FIX-710 did not cause it and
does not fix it.

## Actual

In `frontend/src/components/history/WorkflowHistory.test.tsx`, the describe block at `:354` is "WorkflowHistory — chain
affordance reachable despite onOpenRun (T3-chaining-reachable)". Its case at `:371`, "the row's Chain menu action reaches
the chain panel (bypassing onOpenRun) and fires onChainPipeline with the source run id", fails with
`TestingLibraryElementError: Unable to find role="menuitem" and name /chain/i`. The file result is
`Tests  1 failed | 16 passed (17)`.

## Why

The Chain item was removed on purpose, in dfd167387 (2026-09-22), "fix(history): drop the Chain action, and name ppt_v2
in saved workflows". [FIX-584](20260922-0925-FIX-584.md) records the removal, and its locked constraint says: "The
run-actions RowMenu carries only actions that act on the ROW. The removed "Chain" item existed solely to reach the
internal detail view's "Suggested next steps" panel, a screen no normal user path mounts."

The test came in with e4eecb705 (2026-09-12, "reachable chaining"). It was not removed along with the item. At HEAD
024c03ef8, RowMenu has one `role="menuitem"`, Delete (`RevisionFamilyView.tsx:476`), and `WorkflowHistory.tsx` renders
none.

## Evidence

- The failure is the same against git HEAD 024c03ef8 copies of `WorkflowHistory.tsx`, `RevisionFamilyView.tsx` and
  `RunDetailPage.tsx`, run from a scratch vitest config, so it predates FIX-710. The log is
  `evidence/qa-kb-041/13-fix-regression-one-file-at-a-time.txt` and the config is
  `evidence/qa-kb-041/15-fix-probe-sources/vitest.hist.config.ts.txt`.
- The failure was noted twice before, with no card: in the coverage block of [FIX-616](20260922-1923-FIX-616.md)
  (2026-09-22) and in [FIX-709](20261002-0147-FIX-709.md) (2026-10-02).

## Fix direction

This needs a test-only change: either delete that one case, or rewrite it to assert the contract after FIX-584 (the
run-actions menu offers Delete only). The test owner decides which. The application stays as it is, because FIX-584
removed the item on purpose.

## Analysis (QA-KB-092, 2026-10-02)

Read-only analysis of the working tree over HEAD 024c03ef8. Everything marked CONFIRMED was read or run here.

**Reproduced (CONFIRMED).** `cd frontend && npx vitest run src/components/history/WorkflowHistory.test.tsx`, twice:
`Test Files  1 failed (1)`, `Tests  1 failed | 16 passed (17)`. The failing case is the one at `:371`;
`TestingLibraryElementError: Unable to find role="menuitem" and name /chain/i` is raised at
`WorkflowHistory.test.tsx:384`, about 1.0 s in (the default `findBy` timeout). The click on "Run actions" at `:383`
succeeds, so the menu opens and simply has no Chain item. The failure is deterministic: DOM only, every fetch mocked,
and the file replaces `AnimatePresence` with a pass-through (`:121-135`), so the menu renders synchronously. No timing
flake in either the red or the fixed case.

**Root cause (CONFIRMED), one mechanism: a removal that the compiler could not see.**

1. `e4eecb705` (2026-09-12) added, in one commit, the "Chain" `menuitem` in `RowMenu`, `handleChainAffordance`
   (`handleSelectRun(run, { forChain: true })`), the wiring `onChainClick={onChainPipeline ? handleChainAffordance :
   undefined}`, and this test case. The item rendered only when `onChainPipeline` was passed.
2. `dfd167387` (FIX-584, 2026-09-22) deleted the item, `handleChainAffordance`, RowMenu's `run`/`onChainClick` props
   and FamilyGroupCard's `onChainClick` (`git show dfd167387`). It did not touch the test file:
   `git log dfd167387..HEAD -- frontend/src/components/history/WorkflowHistory.test.tsx` is empty.
3. At HEAD, `RowMenu` renders exactly one `role="menuitem"`, Delete (`RevisionFamilyView.tsx:476` at HEAD, `:477` in the
   working tree). All three `RowMenu` call sites pass only `runId, openMenuId, onToggleMenu, onDeleteClick`
   (`RevisionFamilyView.tsx:621, 688, 734`). So the query at `WorkflowHistory.test.tsx:384` cannot resolve.
4. Nothing flagged it. The query is a string, so `tsc` is silent, and FIX-584's own card has `verification.type: none`
   and "Frontend tests: none added". Three later cards saw the red case only inside coverage blocks:
   [FIX-616](20260922-1923-FIX-616.md), [FIX-709](20261002-0147-FIX-709.md) and [FIX-710](20261002-0154-FIX-710.md).

**Not a product decision (CONFIRMED).** The removal is deliberate and the capability survives. FIX-584's locked
constraint and commit message say so, and chaining is still offered from the run screen: `RunChatLane.tsx:1163-1172`
(chips from `chainInto(baseWorkflowType(runType))`) and `DashboardLayout.tsx:2736-2746` (`laneSuggestions` ->
`handleChainPipeline`). The History row item was a second way into a pane that has no production route: the only render
site, `DashboardLayout.tsx:3034-3053`, always passes `onOpenRun`. Spec 019 FR-021 is a backend gate on a declared manifest
flag (`specs/019-sandbox-git-versioning/spec.md:444`), not a History-row affordance, so no spec requires the item. The
app is right and the test is stale. Restoring the item to turn the test green would bend the app to the test and break
FIX-584's locked constraint.

**Where the fix belongs.** Only `frontend/src/components/history/WorkflowHistory.test.tsx`, `:346-394`. Rewrite the
case; do not delete it, because deleting leaves FIX-584's locked constraint with no guard. Rewrite it so the assertion
cannot pass vacuously:

- Render exactly as production does (`DashboardLayout.tsx:3034-3053`): `<WorkflowHistory onOpenRun={...}
  onChainPipeline={...} />`. The old item showed only when `onChainPipeline` was passed, so a render without it would
  pass even if the item came back.
- Open "Run actions", then `await screen.findByRole("menuitem", { name: /delete/i })` so the menu is proven open.
- Assert `screen.getAllByRole("menuitem")` has length 1, and `screen.queryByRole("menuitem", { name: /chain/i })` is
  null. Drop the `onChainPipeline` and "Suggested next steps" assertions: `renderAndOpenRun` cases at `:281-345` already
  cover the panel and stay green.
- Fix the comments at `:187-189` and `:346-353` and the describe title so they say FIX-584 removed the Chain item.
  Result: 17 of 17, with the post-FIX-584 contract named.

**For the test-writer.** The failing test already exists: it is the case at `:371`, which fails today for the reason
above. No new failing test is needed. The rewritten guard asserts the post-FIX-584 contract, so it passes as soon as it is
written; that is expected for a stale-test fix.
