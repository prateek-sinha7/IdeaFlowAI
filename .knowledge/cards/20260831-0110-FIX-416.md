## What changed

**A row reader, in one page pass.** A row's `aria-label` is a free-text brief
excerpt — quoting it back into a selector breaks on the first apostrophe, and
several briefs carry one. So `_rows(page)` returns `(index, aria-label, version
count)` and everything scopes by INDEX afterwards.

The badge query is `span[aria-label$=" versions"]`, and the `span` qualifier is
load-bearing: the toggle BUTTON is labelled `"Show versions"`, which ends in
the same suffix. Matching it yielded `parseInt("Show versions")` → `NaN`, and
every row silently read as a family of one — the fix looked like it had failed
when it had only mis-selected.

**S-21-01/02/03 written for real**, as the failure message instructed. Collapse
is asserted as the gap between the two counts the page itself reports (family
rows vs the `N runs` headline). The badge test pins that its accessible name
(`"2 versions"`) and its painted text (`"v2"`) differ — which is the whole point
of that scenario. Expansion checks the member rows are absent before the click
and are `Version 1..N` in order after it.

**S-21-04 inverted into a two-way assertion** — a row with no badge must not
call itself `(latest version)`, AND a row that does must carry one.

**`a_run()` now skips family rows**, so S-21-10 and S-21-11 get the
single-version run their scenarios name.

**`chip_count` returns 0 for an absent chip** instead of spending a 30s locator
timeout to discover there are no runs of that type. A chip that vanished while
its families exist is still caught, because those families keep being counted
in the rows.
