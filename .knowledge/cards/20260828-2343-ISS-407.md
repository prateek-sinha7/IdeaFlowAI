## Reproduction (QA-KB-032, validated 2026-10-01)

Reproduced 3/3 from cold start (browser lane1, admin@velocity.ai, no `runId`/`error` query): sessionStorage `__app_preview__` (1) absent, (2) corrupt JSON `{bad json`, (3) `{"files":[]}` — in every case /preview-fullscreen redirected to /runs after ~100ms with no error or explanation. Code unchanged at page.tsx giveUp() `router.replace(routes.runHistory())`.
Evidence: evidence/qa-kb-032/01-validate-attempt1-after-redirect-missing.png, 02-...-corrupt.png, 03-...-emptyfiles.png

## Analysis (QA-KB-032, 3-analyzer, 2026-10-01)

**Verdict.** Root cause CONFIRMED. Fix direction ESCALATED: a spec acceptance criterion and a passing test document the redirect as intended, so whether it is a defect is a product ruling (`WONTFIX.md#qa-kb-032`). Nothing below has been applied.

### Root cause (CONFIRMED, read in the working tree)

`frontend/src/app/preview-fullscreen/page.tsx:57-63`:

```tsx
const giveUp = () => {
  if (quota) {
    setState("quota");
    return;
  }
  router.replace(routes.runHistory());
};
```

`giveUp()` is the one exit for all three unusable-payload cases: no stored value (`!raw`, :66-69), empty `files` (:71-74) and a `JSON.parse` throw (:78-80). `PageState` (:14) is `"checking" | "loading" | "ready" | "quota"`, so the page has no state in which to explain a missing payload, and the render ladder (:86-129) ends in `return null`. The redirect is the only thing it can do. (This card's earlier summary cited `:58-72`; that predates [FIX-369](20260829-0114-FIX-369.md), which folded the three inline redirects into `giveUp()`. The mechanism is unchanged.)

### How it got this way (CONFIRMED, git and spec)

- Original page, `847f4c1f3` (2026-05-15): `type PageState = "loading" | "ready" | "error" | "quota"` (:22) and an `"error"` panel (:89-109) reading "No preview data found / Click the Full Screen button ... don't navigate here directly" with a "Close tab" button.
- Spec 015 task T18 turned the page into a retired-path redirect. Its acceptance criterion: "If `/preview-fullscreen` cannot resolve a run id, it redirects to `/runs` rather than erroring — and that fallback is documented in the file" (`specs/015-frontend-routing/tasks.md:647`; same wording in `test.md:200-201`; success criterion SC-004, `spec.md:228-229`).
- The 015 audit found the real Full Screen button (which sends no `runId`) broken and restored the sessionStorage render path, but not the error state (`tasks.md:97`; `887ccfe96` still has three `router.replace(routes.runHistory())`, at :59, :64 and :71). FIX-369 kept the redirect on purpose ("exactly the pre-existing behaviour for each path").
- The docblock (:27-29) and scenario S-16-06 (`tests/integration/screens/16-pages-outside-routes.feature.md:145-149`, test `tests/integration/e2e/suites/16_pages_outside_routes/test_pages_outside_routes.py:213-221`) both record the redirect as the intended fallback. [BUG-082](20260829-1508-BUG-082.md) recorded S-16-06 passing on 2026-08-29; the 2026-10-01 validation above confirms the behaviour it asserts. Not re-run in this analysis.

So the report is accurate about behaviour (3/3 above), but its expectation contradicts a written acceptance criterion. Both sides have documentation: the audit itself (`tasks.md:97`) calls "silently redirects to Run History" the symptom of a blocker when the live button hit it.

### Blast radius (CONFIRMED by grep)

- Consumer: this page only. `__app_preview__` is read at page.tsx:65 and written at `AppBuilderPreview.tsx:441`; `/preview-fullscreen` is opened only at `AppBuilderPreview.tsx:444` and `:449`.
- Reach: the Full Screen button (`AppBuilderPreview.tsx:507`) ships with every `<AppBuilderPreview>` site: `PreviewPanel.tsx:170`, `WorkflowHistory.tsx:1053` and `:1092`. The page cannot tell a pasted or bookmarked URL from a Full Screen handoff that failed (both arrive bare), so both get the same silent redirect.
- No sibling silent redirect: the other `routes.runHistory()` callers are plain navigation (`workflow/page.tsx:68`, `DashboardLayout.tsx:430`, `:2944`, `:2949`).
- Pinned by tests and docs: S-16-06 (feature :145-149 and :48; test :213-221), `tests/integration/PAGES.md:137`, `tests/integration/capture/p55-preview-fullscreen-bare-redirect.json`, `specs/015-frontend-routing/tasks.md:647`, `test.md:200-201`. No vitest spec exists for the page.
- Sibling: one, [ISS-915](20261001-2219-ISS-915.md) (INFERRED): a wrong-shape payload passes the guard at :71 and crashes `AppBuilderPreview` at render. It is independent of the ruling.

### Where the fix belongs, and the agreed minimal fix

All three exits already funnel through `giveUp()`, so the change lives there and in `PageState`: no per-exit patch and no producer change. The agreed fix in BUGS.md (add `"missing"` to `PageState`; `giveUp()` sets it instead of redirecting; a render block modelled on the quota block with an `AlertCircle`, a "Preview not available" heading, a line saying the preview data expired or was not found, and a `Link` to `routes.runHistory()`; update the docblock at :27-29) is correct and minimal **if the ruling is the in-place panel**. I accept it, with two amendments: keep the quota branch first in `giveUp()` so FIX-369's precedence is unchanged, and use a real heading element, since `tests/integration/PAGES.md:136` records the quota block as having "no heading element, no way back". `router` and `routes` stay imported (both still used for the `runId` redirect at :42); `Link` from `next/link` is the one new import.

It is not the only design. The app already redirects with a notice for session expiry (`routes.login({ expired: true })`, `routes.ts:48`, rendered at `login/page.tsx:273-280`), but `routes.runHistory()` (`routes.ts:84`, `{ type?, sort? }`) has no notice channel, so that variant adds a route-contract change ([ADR-0018](20260824-1631-ADR-0018.md)) and a banner on Run History.

### Invariants

NONE at risk for the in-place panel (frontend only: no kernel, registry, SC-001 or import-linter contract). The redirect-plus-notice variant touches `routes.ts`, the single URL source.

### For the test-writer (after the ruling)

If the ruling is the panel, S-16-06 must be inverted in the same change (it asserts `wait_for_url("**/runs")`). A failing test for the three exits is cheap in jsdom (render the page with `useRouter` mocked, seed or clear `__app_preview__`, advance fake timers 100 ms) or in Playwright (`add_init_script` to seed `{bad json` or `{"files":[]}` before `goto("/preview-fullscreen")`).
