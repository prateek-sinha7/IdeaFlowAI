# FIX-293

## What happened

The run-lane header's title (`LaneRunHeader.tsx`) rendered the run's brief unclamped at 20px with no truncation, filling the whole left pane. Per request it was changed to a 2-line-clamped, smaller (13px) title with the full text on hover — mirroring the `InfoHint` hover-box pattern `CanvasConfigRail.tsx` uses on the per-agent Config tab. Three defects surfaced while validating that change against a real run:

1. **Tooltip repeated the same trimmed text** (not the original brief) on a reopened/settled run. `DashboardLayout.tsx`'s `runHeaderTitle` prefers the short DB `title` column (`cleanLatestTitle`) over `submittedBrief`, and `submittedBrief` is populated only for a just-launched LIVE run (`DashboardLayout.tsx:210`) — empty on reopen. The tooltip, fed that same short value, had nothing more to show.
2. **Tooltip content was unreachable** even once the correct full text was threaded in: the box combined `pointer-events-none` with `overflow-y-auto` — a box that cannot receive mouse events cannot be scrolled, so anything past ~320px of text was simply inaccessible.
3. **Tooltip was visually clipped at the pane divider**: `DashboardLayout.tsx:2546`'s left execution column is `overflow-hidden` (it owns its own scroll). An ancestor's `overflow: hidden/auto/scroll` clips ALL descendants at its own boundary — including absolutely-positioned ones — regardless of `z-index`. z-index only orders paint among elements that survive the clip; it cannot rescue a clipped element.

## Root cause

Layered: (1) the short-title-wins fallback ordering in `DashboardLayout.tsx:2040` had no separate "full text" channel; (2) `pointer-events-none` on a scrollable tooltip is self-defeating; (3) a CSS-only `group`/`group-hover` tooltip cannot escape an `overflow-hidden` ancestor — there is no CSS property that un-clips a descendant short of changing the ancestor's own overflow, which was not viable here since that ancestor owns real scroll for the chat transcript.

## Fix

`frontend/src/components/chat/LaneRunHeader.tsx`:
- New `TitleWithTooltip` component (line 173) replaces the in-place `group`/`group-hover` box. It renders the clamped `<p>` trigger and, on `onMouseEnter`, computes the trigger's `getBoundingClientRect()` and renders the full-text box via `createPortal(..., document.body)` with `position: fixed`, `z-[1000]`, `max-h-[60vh]` + `overflow-y-auto` (now actually scrollable — no `pointer-events-none`).
- New `runTitleFull?: string` prop (line 226), independent of the clamped `runTitle`; falls back to `runTitle` when a caller has no separate full text.

`frontend/src/components/chat/RunChatLane.tsx`: threads `runTitleFull` (line 232) down to `LaneRunHeader`, falling back to `firstUserTurn` (line 2147) the same way the existing `runTitle` prop does.

`frontend/src/components/layout/DashboardLayout.tsx`: new `runHeaderTitleFull` (line 2057) = `viewedRun.input || submittedBrief` — `viewedRun.input` is the reopened run's actual `run.input` DB column (unrestricted length), the correct source for a settled/reopened run; `submittedBrief` remains the fallback for a just-launched live run. Passed as `runTitleFull` (line 2587).
