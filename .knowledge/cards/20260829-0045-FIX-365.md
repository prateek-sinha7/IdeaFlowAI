## What was wrong

`BUG-20260828-001100-create-ex-a2-branch` was REOPENED after
[FIX-349](20260828-2324-FIX-349.md). The original defect — the Advanced modal's
"Cancel" not discarding a conditional-gate outcome's route edit — was fixed, but the fix
introduced a worse failure than the one it cured: running
`suites/03_launch_panels/test_iss258_advanced_modal_cancel_discards_route_edit.py` three
times, 2 of 3 runs reopened the modal on **`0 agents`** with no `Pick Language` node at
all. The cancelled route edit was gone, but so was every other agent — data loss, where
the original bug was only an un-discarded edit. The verifier's screenshots
(`tests/integration/test-runs/2026-08-28T23-39-local/` and `…T23-31-local/`) both show
"0 AGENTS" on reopen.

## Root cause

`frontend/src/components/workflow/AgentsPopup.tsx:2377-2384` (as FIX-349 left it):

```tsx
const openSnapshot = useRef<{ agents: AgentDef[]; selections: SelectionsMap } | null>(null);
useEffect(() => {
  if (isOpen) openSnapshot.current = { agents, selections: liveSelections };
  // eslint-disable-next-line react-hooks/exhaustive-deps
}, [isOpen]);
```

The dependency list is `[isOpen]` alone, so the snapshot is taken at the instant `isOpen`
flips true and never again. But the host does not have its roster yet at that instant.
`frontend/src/components/workflow/IdeaInputPage.tsx:1231-1298` derives `pipelineAgents`
inside a `useEffect` whose deps are
`[LIBRARY_AGENTS, effectiveType, initialAgentIds, ALL_LIBRARY_AGENTS, manifestAgents, showOverride, overrideAgents]`
— it **re-runs when the manifest fetch lands**, which for a composed fixture like
`ex_A2_branch` is the only source of the roster at all (`fromLibrary` is empty for it, so
`systemRoster = manifestAgents ?? fromLibrary`, i.e. `[]` until the fetch resolves —
`IdeaInputPage.tsx:1289-1296`).

So opening the modal before that fetch resolves snapshots `agents: []`. `handleCancel`
then re-emits it — `onReorder?.(snapshot.agents)` → `IdeaInputPage.tsx:1585-1587`
`setPipelineAgents(reordered)` — and every agent is gone. The automated test opens
Advanced 352ms after `page.goto` (per that run's `steps.json`), which is why it hit 2/3
there and never in FIX-349's slower manual verification.

## What changed, and why there

`frontend/src/components/workflow/AgentsPopup.tsx`, one file — the same shared component
FIX-349 chose, for the same reason ([ISS-363](20260828-2129-ISS-363.md)'s "where the fix
belongs"): two production hosts, no bespoke path in either.

The snapshot is now **staged at the first modal-initiated write**, not on the open edge:

```tsx
const openSnapshot = useRef<{ agents: AgentDef[]; selections: SelectionsMap } | null>(null);
const stageEdit = useCallback(() => {
  if (!openSnapshot.current) openSnapshot.current = { agents, selections: liveSelections };
}, [agents, liveSelections]);
useEffect(() => {
  if (!isOpen) openSnapshot.current = null;
}, [isOpen]);
```

`stageEdit()` reads the LIVE `agents`/`liveSelections` at the moment of the write, so by
construction it captures the tree the user is actually editing — it cannot capture a
roster that has not arrived, because a user cannot edit a tree that is not rendered. The
`[isOpen]` effect now only CLEARS on close, so each session starts fresh (a session ended
by "Save workflow" or "Open in full canvas" keeps its edit, exactly as before).

Every in-modal write to host state routes through it:

- `handleTreeChange` (new, `:2398-2404`) wraps `onReorder` and is what
  `<CanvasView onTreeChange=…>` (`:2633`) now receives — the route/outcome editor
  (`CanvasConfigRail.tsx:295` → `CanvasView.tsx:748-751`), rename, reorder, reparent and
  the detach reconciler all land here.
- `handleSelectionsChange` (`:2387-2393`) — the per-agent levers.
- `handleRemove` (`:2459-2463`) — `onRemoveAgent`.
- the `AgentLibrary` `onAddAgent` closure (`:2705-2711`) and `addSubAgent` (`:2469-2476`,
  now via `handleTreeChange`) — adds, which reach the host through a functional
  `setPipelineAgents` the modal cannot predict, so they stage explicitly.

`handleCancel` is otherwise unchanged from FIX-349 (restore, then `onClose()`), with one
added line: `openSnapshot.current = null` runs LAST, because the restore goes through
`handleSelectionsChange`, which would otherwise re-arm the snapshot with the edit being
undone.

`if (snapshot)` now also carries real meaning: an open/close cycle with no edit leaves the
ref null, so Cancel re-emits nothing at all. That is strictly stronger than FIX-349's
identity-equality argument, which still called both host setStates.
