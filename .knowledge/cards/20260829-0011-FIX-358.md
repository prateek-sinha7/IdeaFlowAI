## What was wrong

`/runs/{id}/preview/full` is the dedicated route whose whole purpose is forcing the
Preview tab open. Cold-navigated for a `failed` run that produced no deliverable, it
silently auto-selected the **Audit** tab and rendered its full governance/security
trail — no banner, no message, nothing on the page saying a Preview had been requested
and was unavailable. Validated 3/3 against run `826d09f0-21b0-4b8f-a79f-843fc5c82adb`
([ISS-285](20260828-1745-ISS-285.md), register entry
`BUG-20260828-014416-runs-id-preview-full`). The cancelled-run case one state over on
this same route already degraded honestly ("This run was cancelled / The run was
stopped before producing a deliverable"), which is what made the failed case's silent
substitution a defect rather than a design.

## Root cause

Two halves of one mechanism, both confirmed by [ISS-285](20260828-1745-ISS-285.md)'s
analyzer pass and re-checked against the working tree before this change:

1. **The route's intent was discarded.** `reopenTabFor`
   (`frontend/src/app/[...view]/page.tsx:236-253` pre-change) is a `switch` over
   `ParsedView["screen"]` with five cases — `run-steps`, `run-steps-agent`,
   `run-files`, `run-workspace`, `run-audit`. `run-preview-full` was not one of them,
   so it hit `default: return undefined`, and BOTH call sites gate on the value being
   truthy (`if (openTab) …` on the warm path, `if (tab) runTabDeepLink.requestOpenTab(tab)`
   inside the cold path's `.finally()`). No deep-link nonce was ever minted for this
   route, so `PreviewPanel` never learned which route it was serving.

2. **The generic per-state default then won.** With no deep link,
   `PreviewPanel.tsx`'s merged deep-link/default-tab effect falls to its state ternary,
   where `defaultTabDiscriminator === "failed"` maps straight to `"audit"` — correct for
   the plain run screen (Phase 42-03 §D drops the Preview tab and defaults a
   terminal-failed run to Audit) and wrong for the one route that explicitly asked for
   Preview. Nothing rendered an explanation because, from the panel's point of view,
   nothing unusual had happened.

## What changed and why there

Both halves are fixed at the single point every caller routes through — `reopenTabFor`
has exactly two callers and `PreviewPanel` has exactly one JSX mount
(`DashboardLayout.tsx:3127`), so no per-route duplication was needed or added.

- **`frontend/src/app/[...view]/page.tsx`** — `reopenTabFor` gains
  `case "run-preview-full": return "preview";` and `"preview"` joins its return type.
  Both call sites now mint a real deep-link nonce for this route, on the warm path and
  the cold path alike. The doc comment, which claimed `run-preview-full` "uses the
  panel's default", is corrected in place — it was describing the bug.
- **`frontend/src/components/preview/PreviewPanel.tsx`** — the Preview tab's content
  branch was gated on `showCancelledAffordance || showDivertedAffordance`; it is now
  gated on `showFailureAffordance || showDivertedAffordance`. `showFailureAffordance`
  is exactly `showCancelledAffordance || terminalFailureNoDeliverable`, so this adds
  the failed case and changes nothing else; the existing `cancelled` / `diverted` props
  still select which copy `DegradedRunAffordance` renders. That component is the app's
  own answer for "terminal, no deliverable" and is already what the cancelled branch of
  this same route shows — reused rather than reinvented.

Net effect on `/runs/{id}/preview/full` for a terminal-failed run with no deliverable:
the deep link forces `activeTab = "preview"`, the tab bar highlights nothing (the
Preview tab is still dropped from `visibleTabs`, per Phase 42-03), and the pane reads
"This run did not complete successfully / No deliverable was produced. The run ended in
a failed or degraded state." `AuditTab` is not rendered at all, so the zero-record
boundary [ISS-389](20260828-2234-ISS-389.md) describes cannot surface "No audit records
yet" in a requested Preview's place. A still-building run now lands on Preview's own
"Building your deliverable…" placeholder rather than Steps
([ISS-388](20260828-2234-ISS-388.md)'s branch of the same ternary).

**Not changed:** the plain run screen. With no deep link the discriminator ternary is
untouched, so a terminal-failed `/runs/{id}` still drops Preview and defaults to Audit
exactly as Phase 42-03 §D specifies — asserted by the existing
`PreviewPanel.degraded.test.tsx` suite, which stays green.
