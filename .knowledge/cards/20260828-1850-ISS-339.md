## What happened

A full/cold browser navigation to bare `/settings` correctly receives a server-level redirect
(defined in `frontend/next.config.ts:27-28`, `source: "/settings"` → `destination:
"/settings/profile"`) and lands on the profile tab. But a client-side SPA transition to the
identical path — `window.history.pushState({}, '', '/settings')` followed by a `popstate` event,
which is exactly what any in-app `navigate('/settings')` call or `<Link to="/settings">` would
trigger — does not replicate that redirect. The client router's parser
(`frontend/src/lib/routes.ts:401-403`) explicitly returns `{ screen: 'unknown' }` for a bare
`/settings` path with no tab segment, with a comment acknowledging the gap: `// /settings with
no tab — could redirect to profile, but we'll parse as unknown`. `[...view]/page.tsx` then
renders the full "Page not found" 404 screen for the `unknown` screen, with the URL bar frozen
on `/settings`.

This is BUG-20260828-042311-settings from `bug-hunter/ledger.md`.

## Reproduction (3/3, cycle 1)

Reproduced on every cycle (cold restart to `/dashboard` then simulated client-side transition),
3 out of 3 attempts, using account qa-admin@flowinqa.com:

1. Cold navigate to `http://localhost:3000/dashboard` (fresh page load).
2. In the page context: `window.history.pushState({}, '', '/settings');
   window.dispatchEvent(new PopStateEvent('popstate'))`.
3. URL stays `/settings`; page renders the full "Page not found." 404 screen (heading "Not
   found", "The page you're looking for doesn't exist or has been moved.").
4. A fresh full navigation to `http://localhost:3000/settings` in the same session correctly
   redirects to `http://localhost:3000/settings/profile` (server-level `next.config.ts` rewrite
   engaged, confirming the redirect logic exists but is unreachable from client routing).

No axis variance was needed — the defect reproduced identically on the first cold cycle and
every cycle after, with no timing/account/theme dependency observed (also confirmed on qa-basic
in the original hunter report).

## Root cause

Two routing layers disagree on `/settings` with no tab segment:

- `frontend/next.config.ts:27-28` — Next.js server-level `redirects()` rule: `/settings` →
  `/settings/profile`. Applies only to full/cold navigations (SSR/document requests), never to
  client-side history transitions.
- `frontend/src/lib/routes.ts:401-403` — the client parser used by
  `frontend/src/app/[...view]/page.tsx` for every SPA transition. When `head === 'settings'` and
  `segments.length === 1`, it returns `{ screen: 'unknown' }` by design (per the inline comment),
  rather than mirroring the redirect. `page.tsx` renders the honest 404 for `screen: 'unknown'`.

Expected: a client-side transition to `/settings` should resolve to the same destination as a
cold load of the identical URL — the destination should not depend on how the URL was reached.

Actual: client-side navigation renders 404 and leaves the URL on `/settings`; cold navigation to
the same path redirects successfully.
