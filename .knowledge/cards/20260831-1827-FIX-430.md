# FIX-430

Register source: `ISS-357` in `.kiro/bug-fix-workflow/domains/15-backend-other.md`.

## What was wrong

[FIX-332](20260828-1915-FIX-332.md) fixed the 422 value-echo with **one
app-level handler** — `@app.exception_handler(RequestValidationError)` at
`backend/app/main.py:331`. That is a property of the application *object*.

`backend/tests/unit/test_register_password_echo.py:51-52` built a different
object:

```python
app = FastAPI()
app.include_router(auth_router)
```

A bare `FastAPI()` carries FastAPI's own **default** `RequestValidationError`
handler, which serialises Pydantic's shape verbatim — `input` included. So the
one test that exists to prove [ISS-257](20260828-1817-ISS-257.md) kept
reporting `1 xfailed` after the behaviour was fixed, and — the worse half —
would have reported exactly the same against a wrong fix that patched only
`auth_router`. The harness could neither confirm the real fix nor reject a bad
one ([ISS-357](20260828-1915-ISS-357.md)).

## What changed and why there

Both fixtures — the ISS-257 test and the ISS-357 guard, which mirrors it
verbatim by design — now import the real application inside the fixture:

- `backend/tests/unit/test_register_password_echo.py:51-58` and
  `backend/tests/unit/test_register_password_echo_fixture_mounts_real_app.py:58-60`
  replace `FastAPI()` + `include_router(auth_router)` with a late
  `from app.main import app`. The in-memory-SQLite engine and
  `dependency_overrides[get_db]` are unchanged; the assertions are byte-identical.
- The client is **not** entered as a context manager any more:
  `TestClient(app)` instead of `with TestClient(app) as …`. Entering it runs the
  lifespan, and booting the real application runs `restore_non_terminal_runs()`
  against the real database — the exact side effect
  `backend/tests/unit/test_shutdown_reachability.py:65` warns the unit tier away
  from. Starlette spins a portal per request outside the context manager, so the
  request path (middleware + exception handlers) is fully exercised without
  startup. Confirmed: the run logs carry `CORS allow_origins=…` (import-time)
  but no `🚀 Starting VelocityAI Backend` (lifespan).
- `from fastapi import FastAPI` and `from app.api.auth import router as auth_router`
  were orphaned by that change in both files and removed. The model imports
  (`User`, `RevokedToken`, …) stay — `Base.metadata.create_all` still needs them.
- Two stale docstring sentences that asserted `app/main.py` registers **no**
  `RequestValidationError` handler (true when written, false since FIX-332) now
  point at `app/main.py:331`.

Only the harness moved. No assertion, no application code, and no `xfail`
marker was touched — the markers are the 6-verifier's to remove.

The harness is now discriminating, which was the point: with the handler popped
off the real app, the same request raises
`RequestValidationError: [{… 'input': 'short7!' …}]`; with it in place the body
is `{"detail":[{"type":"string_too_short","loc":["body","password"],
"msg":"String should have at least 8 characters","ctx":{"min_length":8}}]}`.
