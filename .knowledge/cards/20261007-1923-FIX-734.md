# FIX-734

## What was wrong

This fix is for bug report QA-KB-079 ("Payload-seq test does not guard copy-not-mutate, 2-hop re-stamp or exhaustion").
The root cause and the blast radius come from the 2026-10-02 analysis on [ISS-907](20261001-2200-ISS-907.md) and its
sibling [ISS-1025](20261002-0645-ISS-1025.md). They were not re-derived here. The quoted source lines were re-read on the
working tree before editing (branch `feat/user-stories-v2`, HEAD `6b2ff041e`); they had shifted 24 lines in `engine.py`
since the analysis and are given here at their current numbers.

Both cards describe regression-guard gaps. The product code is correct.

- **[ISS-907](20261001-2200-ISS-907.md).** `test_run_events_payload_seq_db.py` held only the two ISS-135 repro tests.
  Each asserts the stored row after exactly one collision hop. So none of the contracts
  [FIX-692](20261001-2200-FIX-692.md) gave `ScopedStore.append_event_at_or_after` (`backend/agents/authz.py:613-674`) was
  pinned:
  - re-stamp a COPY, never the caller's dict, on every hop, and only a payload that carries `seq`
    (`:669`, `payload_json = {**payload_json, "seq": attempt_seq}`);
  - retry only when the tail explains the rejection (`:662`, `if tail < attempt_seq: raise`);
  - on exhaustion, re-raise the DB's own `IntegrityError` (`:674`, `raise last_rejection`).

  Observed in this phase, with the six newer cases deselected (`fix-09`): the pair kills H (no re-stamp, the ISS-135
  bug), and mutants A, B, C, D, E and F all pass.
- **[ISS-1025](20261002-0645-ISS-1025.md).** `ExecutionEngine._drive_resumed_stream` (`engine.py:15856`) is the shared
  re-entry stream of every restart driver. It re-stamps the landed seq onto the frame it pushes to `live_queue` and
  advances its allocator: `if actual_seq is not None and actual_seq != seq: data["seq"] = actual_seq ...`
  (`engine.py:15975-15978`). No test made that path collide. With the new twin deselected (`fix-08`), mutant T (that
  block deleted) passes all 9 existing tests in `test_run_events_db.py`. Mutant U (the same deletion in `execute()`,
  `:4220-4223`) fails `test_execute_restamps_seq_onto_the_frame_it_yields`.

## What changed, and why there

- **ISS-907. No file was edited in this phase.** The six cases the card's table asks for were already in
  `test_run_events_payload_seq_db.py` when the phase began. They arrived in commit `14a675db4` (2026-10-06), written by
  the QA-KB-079 test phase from the analyzer's validated template (`evidence/qa-kb-079/05-...`). That phase ran them
  under mutants A and B only (`reports/20261002-0941-triage.md:57`: "red only under mutants A and B (C-F, H not
  re-run)"). This phase ran the whole matrix. Each case, with the mutants it kills (`fix-01`):

  | test | line | killed by |
  |---|---|---|
  | `test_retry_restamps_a_copy_and_leaves_the_callers_dict_alone` | `:113` | A, H |
  | `test_two_hop_retry_restamps_the_final_landed_seq` | `:125` | B, H |
  | `test_exhaustion_raises_the_dbs_own_rejection_and_keeps_the_callers_seq` | `:138` | A, C, F |
  | `test_sink_degrades_on_exhaustion_and_the_live_frame_keeps_its_seq` | `:152` | A, C, F |
  | `test_payload_without_a_seq_key_is_stored_untouched_on_a_retry` | `:181` | D |
  | `test_a_rejection_no_tail_explains_is_not_retried` | `:193` | E |

  This is the matrix the ISS-907 table predicted, cell for cell.
- **ISS-1025. One test was added:**
  `test_resume_driver_restamps_live_frame_and_stored_payload_after_a_collision`, at `test_run_events_db.py:422-487`.
  It sits beside `test_execute_restamps_seq_onto_the_frame_it_yields`, which is where the card places it.
  - **Why this phase wrote it.** The test phase did not add it (`reports/20261002-0941-triage.md:57`: "ISS-1025 test not
    added"). The card's fix is this test and nothing else. The card's globs name this file.
  - **What it does.** It drives the real driver with the same scripted `_execute_impl` and the same chat-lane write as
    the `execute()` twin. Then it reads the frames off `live_queue` and asserts three things:
    - the collision happened: chat row at 2, `pipeline_cancelled` at 3, `agent_chunk` at 4;
    - for every engine event, live frame seq == row seq == stored payload seq;
    - the stored side is read after `db_session.expire_all()`.
  - **Where it came from.** It is the analyzer's validated scratch (`evidence/qa-kb-079/06-...`) with four
    adaptations:
    - it seeds the run with the file's own `_seed_run` helper;
    - it carries `@pytest.mark.asyncio`, like its neighbours;
    - its marker is `ISS-1025`, which is what the card asks for (the scratch carried `ISS-907`);
    - it monkeypatches `settings.RUNS_ROOT` to `tmp_path`, because the driver builds a `RunTrace` under it. That follows
      the card's own note and the idiom at `tests/agents/test_run_trace.py:290`. Without it, the test would write a log
      into the repo's `runs/` (`backend/.env` sets `RUNS_ROOT=../runs`).

## Test changes, stated explicitly

This is a test-only fix, because both cards place their fix in a test file. No application file was edited:
`git diff --stat -- backend/agents backend/app backend/tools` is empty (`fix-07`). No existing test or assertion was
changed. The diff is the 68 added lines in `test_run_events_db.py` (`fix-04`).

The cases carry no `xfail` marker because they pass on the shipped code by design. There is no marker for the
6-verifier to remove.

## Deliberately not done

- **Mutant P.** It is equivalent. It passes all 8 cases (`fix-01`), as the ISS-907 analysis predicted.
- **The "optional tightening, no card" in ISS-907.** It would make `test_execute_wrapper_stored_payload_seq_matches_row`
  assert that a collision happened. Neither card asks for it. The plugin's hop count shows the test does reach 1 hop
  today.
- **The exhaustion of `append_event_next_seq` (`authz.py:588-590`).** No test reaches it either. The analyzer observed
  this and chose not to card it, because it is a different function with its own contract and no payload seq.
- **The end-to-end consequence ISS-1025 infers.** That is Last-Event-ID corruption on a browser reconnect to a resumed
  run that took a chat turn mid-stream. It stays INFERRED, and no run was started. The twin settles the code path only.
