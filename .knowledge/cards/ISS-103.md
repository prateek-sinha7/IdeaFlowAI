# ISS-103

## Title

Ctrl-C already cancels in-flight runs — by an uncontrolled path that runs AFTER the checkpointer pool is closed — while kill/docker stop does not. The two signals take different teardown paths, and only one of them is the one the code reasons about. uvicorn/server.py:312-330's capture_signals() restores each signal's ORIGINAL disposition and then calls signal.raise_signal(captured_signal) — still inside serve(), i.e. still inside asyncio.run(...) (server.py:64-66). For SIGTERM the restored disposition is the default, so the process dies right there: asyncio.run never returns, Runner.close() → _cancel_all_tasks(loop) (asyncio/runners.py:193-201) never runs, and no pipeline driver is ever cancelled. For SIGINT the restored handler raises KeyboardInterrupt in Python, which unwinds through asyncio.run normally — so _cancel_all_tasks DOES run, every registered driver task is cancelled, and each one's except asyncio.CancelledError handler (run_commands.py:2424-2435 launch, :2654-2659 revision) writes wr.status = "cancelled". Consequences. (a) A developer pressing Ctrl-C has always been cancelling their in-flight runs, regardless of SHUTDOWN_STOP_RUNS — undocumented anywhere. (b) That cancel happens AFTER the lifespan has completed, i.e. after close_checkpointer() has closed the pool, so any driver whose unwind path touches get_checkpointer() hits RuntimeError (checkpointer.py:41-49); the two handlers above use the sync SQLAlchemy session so this is a latent hazard rather than an observed crash, but nothing bounds what else runs there. (c) _cancel_all_tasks gathers with no timeout (loop.run_until_complete(gather(...))), so a driver that does not unwind promptly hangs the process past every documented budget — outside stop_grace_period's accounting entirely. Fix shape: decide whether SIGINT should behave as SIGTERM does (bring the cancel inside the lifespan where its ordering is controlled) and document whichever is chosen; the SHUTDOWN_STOP_RUNS=True path already does this deterministically and in the right order.

## Source / evidence

Settled empirically during quick-260812-hsx on a throwaway uvicorn (port 8099), not inferred: a probe modelling the driver task + handler recorded NO driver_wrote_status_cancelled / driver_finally under SIGTERM and BOTH under SIGINT; a no-uvicorn control (isolate_cancel_all_tasks.py) confirmed plain asyncio.run DOES run the handler (cancelled: False); and a variant stamping a marker after server.run() returns never wrote it, proving server.run() does not return. Mechanism then read in the installed uvicorn==0.34.0 source.
