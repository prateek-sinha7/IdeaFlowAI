# ISS-083

## Title

**A third, dormant counter in the spec-revision family: `ResultCard.tsx:97-100,119` renders `Revising spec — cycle {cycle ?? 1}` for the `spec_revision` card kind and NOTHING passes `cycle`** (`grep -rn "cycle={" src` → no non-test hit), so that chat card would print "cycle 1" forever. Not a regression and not user-visible today, but this family has already produced two dead counters (ISS-039's and FIX-164's). Wire it from the same single source the banner now uses (`runStore.viewed.specRevisionCount`) rather than reintroducing a local count.

## Severity / Tag / Status (original row)

- Sev: trivial
- Tag: frontend
- Status: **RESOLVED** by FIX-236 (quick-260812-jn9, `0312a0af`, 2026-08-12) — **the row's FACTS were right and its FIX was WRONG; the proposed wiring was REJECTED and nothing was wired.** The prop was not a gap but a **duplicate**: the header rendered `` `Revising spec — cycle ${cycle ?? 1}` `` while the body rendered the backend narrator's own text (`chat_narrator.py:157`), so had the card ever mounted it would have printed "cycle 1" directly above "cycle 2" — INV-12, and the superseded copy was **deleted, not extended**. Four grounds for the rejection, each re-verified: **(1)** the entire `spec_revision` card kind is unreachable end-to-end — `chat_narrator._revision_index` keys on `spec_revision_attempt`/`revision_index` and those strings appear as quoted dict keys **only at `:112`/`:114`, the reader itself**, so `attempt` is always 0 (**0 `spec_revision` cards across 232,023 durable events over 14 runs, 52 of which prove spec revisions demonstrably happened**); **(2)** the dormancy is DELIBERATE and LOCKED — `IMPLEMENTATION-REGISTER.md:4214` records FIX-220 misnaming its keys *specifically* to avoid waking this reader; **(3)** the same line forbids the proposed action outright (*"must CONSUME `revision_cycle`, not invent a third counter"*) and the per-card value already rides the wire twice (`text` + `deep_link.target`); **(4)** `specRevisionCount` is the run's CURRENT count while a chat card is a HISTORICAL entry, so every card in a transcript would repaint with the live number. Also: **the row's cited `97-100,119` was stale at both ends** — the doc block opens at `:96` and it misses the destructure at `:103`, which any fix must touch. The card KIND is deliberately KEPT (cross-stack contract, parked on purpose) and its unreachability filed as **ISS-111**. Family correction: this is the **fifth** dead counter, not the third the row claims.
