## What happened

[ISS-323](20260828-1810-ISS-323.md) documents that `PreviewPanel.tsx`'s `parseAppBuilderFilesForIDE`
mis-parses a markdown `###` subheading (e.g. `### Via Node.js`) immediately followed by a fenced
code block as a phantom project file, because `headerRegex` and the `addFile` guard (`hasDot`)
only check for a dot in the last path segment, not whether the text is actually a plausible file
path. That mechanism is not confined to the Preview tab: `frontend/src/components/results/FilesTab.tsx`
carries an independent, byte-for-byte duplicate of the same three-format regex parser and the same
guard, reachable from a completely different UI surface — the Results/Files tab's App Builder
"project.zip" download row.

## Root cause (INFERRED — mechanism confirmed by reading code; not yet reproduced against a live run)

`frontend/src/components/results/FilesTab.tsx:196-258` (`parseCodeFiles`, aliased as
`parseAppBuilderFiles` at line 256-258) duplicates `PreviewPanel.tsx:46-105`
(`parseAppBuilderFilesForIDE`) line-for-line:

- `filenameRegex` (`FilesTab.tsx:240`) — safe; requires an explicit ```` ```filename: ```` marker.
- `headerRegex` (`FilesTab.tsx:245`) — `/###\s+([\w./\-@][^\n]*\.\w+)\s*\n```[^\n]*\n([\s\S]*?)```/g`,
  identical to the broken regex in [ISS-323](20260828-1810-ISS-323.md).
- `boldRegex` (`FilesTab.tsx:249`) — see [ISS-485](20260829-0133-ISS-485.md), same unbounded
  character class as `headerRegex`.
- `addFile` (`FilesTab.tsx:218-224`) — the same `hasDot = name.includes(".")` guard
  (`FilesTab.tsx:222`) that accepts `"Via Node.js"` purely because of the dot in "Node.js".

This duplicate parser is exercised at two points inside the App Builder branch of `FilesTab`:

- `FilesTab.tsx:585` — `const finalCodeFiles = parseAppBuilderFiles(userStoryContent);`, run
  in the render body to decide whether `appBuilderCodeFiles.length > 0` (`FilesTab.tsx:595`)
  renders the collapsed "project.zip" row (labelled `` `All ${appBuilderCodeFiles.length} code
  files (ZIP)` `` at line 600) versus the single-markdown fallback (line 609-613) — a phantom-only
  "code file" set could flip this branch and mislabel the row's file count.
- `FilesTab.tsx:690` — inside `handleDownload`'s `file.id === "project-zip"` branch,
  `const allCode = parseAppBuilderFiles(userStoryContent);` re-parses the same content, and
  `FilesTab.tsx:693` — `if (!seen.has(f.type)) { zip.file(f.type, f.content); seen.add(f.type); }`
  — zips every parsed entry verbatim, including the phantom, using its raw parsed "path"
  (`f.type`, e.g. `"Via Node.js"`) as the in-archive entry name.

So the same malformed, extensionless, space-containing entry that [ISS-323](20260828-1810-ISS-323.md)
found in the Preview tab's per-file download and "Download ZIP" would also land inside the
`project.zip` downloaded from the **Results > Files tab** — a separate UI surface
([MOD-frontend-src-components-results](../architecture/MOD-frontend-src-components-results.md))
that the original hunt/validation never opened; only the Preview tab and its `/preview-fullscreen`
popout were exercised.

## Conditions

- Page: `/runs/<id>` — Results tab, "Files" sub-tab, App Builder run
- Trigger: the same markdown shape as [ISS-323](20260828-1810-ISS-323.md) — a `###` (or bold,
  [ISS-485](20260829-0133-ISS-485.md)) heading whose text contains a dot-plus-word-chars substring,
  directly followed by a fenced code block, present in `userStoryContent` (the final agent's output)
  or a code-producing agent's output
- Account/tier: not tier-specific — same client-side parsing regardless of tier
- Reproduction not yet attempted here — mark this INFERRED until a run with a matching heading is
  opened on the Files tab and its "project.zip" is downloaded and inspected (`unzip -l`), mirroring
  [ISS-323](20260828-1810-ISS-323.md)'s validation method.

## Expected vs actual

**Expected:** `project.zip` downloaded from the Results/Files tab contains only real generated
project files.

**Actual (inferred):** `project.zip` also contains the phantom entry (e.g. a top-level, extensionless
`"Via Node.js"` file), and the row's displayed file count/size may be inflated by phantom-only
entries when no other code file exists in the run.
