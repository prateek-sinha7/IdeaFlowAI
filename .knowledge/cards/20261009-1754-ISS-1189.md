# ISS-1189

Sibling of [ISS-1158](20261009-1510-ISS-1158.md) (register entry QA-KB-122). Its fix is already written down, in the UNREPRODUCIBLE verdict for QA-KB-118, but no card or register row owns doing it. Filed 2026-10-09 by the analyzer.

## Condition

`suites/07_run_detail/test_iss802_steps_agent_artifacts_duplicate_request.py:71` counts every request whose URL contains `/api/runs/{run_id}/artifacts` and asserts `<= 1` (`:73-76`). The page now makes two different calls on that prefix:

- `GET /api/runs/{id}/artifacts` - the version list (`ArtifactVersionPicker.tsx:123-127`). This is the call [ISS-802](20260922-1638-ISS-802.md) was about (two identical copies under StrictMode); [FIX-636](20260922-2352-FIX-636.md) fixed it.
- `GET /api/runs/{id}/artifacts?kind=clarifications&include=content` - the run's persisted clarify rounds (`frontend/src/components/preview/PreviewPanel.tsx:617-620`, `loadRunClarifications`), added by `5336d910c` (2026-10-07, "fix(QA-KB-066): a pinned version shows its own clarify rounds", [ISS-1006](20261002-0523-ISS-1006.md) / [ISS-1008](20261002-0523-ISS-1008.md)).

The 2026-10-09 rerun names both: `len([...?kind=clarifications&include=content, .../artifacts]) == 2` (`rerun/07_run_detail.log:102,104`, quoted in `evidence/qa-kb-122/analysis-07-validate-bugs-log-excerpts.txt`); QA-KB-118's three attempts saw the same pair.

## Why the root cause implies it

An intentional app change (a second, different read) against a test that matches by URL substring, in a commit that touched no e2e file (`analysis-01-git-timeline.txt`: 0 of 18). QA-KB-118 reproduced the app side three times and found the version-list request fires once per attempt (UNREPRODUCIBLE.md#qa-kb-118); the report's "fetches artifacts twice" counts two different calls as one duplicated call.

## Expected vs actual

Expected: the test fails if the version-list request is sent twice, and only then. Actual: it fails on the clarifications read, which is a different request.

## Fix direction (test-side only)

- Count the bare list URL only: `u.split("?")[0].endswith(f"/api/runs/{run_id}/artifacts") and "kind=" not in u` (or compare the query string explicitly), keep `<= 1`.
- Optionally pin the new read too, at most once per page load (QA-KB-118 observed it fires once on `/steps` and `/audit` with no agent open, so it is page-level).
- Do not change the app on this card. Merging the two reads into one request is a separate performance decision (QA-KB-118 says the same). No other e2e test matches on this prefix (`grep -n /artifacts` over `suites/` and `framework/`: the only other hits are 401/403/404 ownership probes in `13_errors/test_errors.py:343` and `24_api_contract/test_api_contract.py:596`).

## Confidence

CONFIRMED by reading both sides and by the validator's three attempts (UNREPRODUCIBLE.md#qa-kb-118, evidence `evidence/qa-kb-118/`). INFERRED, not run: that the test passes with the filter, which needs a live run.
