## What was wrong

`/settings/ai-model` let a basic-tier account select and persist the two
premium models (Claude Opus 4.5 / 4.6). Confirmed 3/3 by the validator on
register entry `BUG-20260828-031200-settings-ai-model`, and not cosmetic: the
persisted `user.preferred_model` is read at 8 sites in
`backend/app/api/run_commands.py` (most concretely `run_commands.py:3251`'s
`engine.execute(..., model_id=getattr(user, "preferred_model", None) or None,
...)`), so an unauthorised selection drives real Bedrock model choice and
premium billing on every subsequent run.

## Root cause

No model-tier entitlement concept existed anywhere in the codebase.
`backend/app/core/entitlements.py` mapped tier -> allowed *pipeline types*
(`TIER_PIPELINES` / `can_run_pipeline`) and had no analog for models, so:

- `backend/app/api/settings.py:340` (`update_preferences`) validated
  `payload.preferred_model` against `_VALID_MODEL_IDS` (settings.py:58 —
  `set(ModelCatalog().ids())`, the full 9-model catalog) and never read
  `user.tier` at all.
- `backend/app/api/settings.py:306-313` (`get_preferences`) returned the same
  full `AVAILABLE_MODELS` projection to every tier.

Full analysis, blast radius and file:line evidence:
[ISS-292](20260828-1918-ISS-292.md).

## What changed and why there

**`backend/app/core/entitlements.py`** — added `TIER_MODEL_COST_CLASSES` and
`can_use_model(user_tier, model_id) -> tuple[bool, str]` directly beside
`TIER_PIPELINES` / `can_run_pipeline`, the existing single source of truth for
tier gating. The table is keyed off `ModelEntry.cost_class`
(`cheap`/`standard`/`premium`) — the canonical axis — not the display `tier`
string, and reads fail-closed through the same
`.get(user_tier, [...]["basic"])` fallback `can_run_pipeline` uses. Policy as
committed: `basic` = `{cheap, standard}`; `hexaware`/`pro`/`enterprise` = all
three. Unknown model ids return `(True, "")` on purpose so catalog membership
stays the caller's 422 and never turns into a misleading "upgrade your plan"
403. The module now imports `agents.capabilities.model_catalog.ModelCatalog`
(the INV-12 single model list); `app -> agents.capabilities` is the permitted
direction (only `agents.capabilities -> app` is forbidden), and
`lint-imports` confirms that contract still holds.

**`backend/app/api/settings.py`** — `update_preferences` now calls
`can_use_model(user.tier, model_id)` after the existing `_VALID_MODEL_IDS`
check and raises `HTTPException(403, detail=reason)` when it fails, mirroring
`can_run_pipeline`'s 403 convention at launch (`run_commands.py:2225`). This is
the single write path behind every reader of `user.preferred_model`, so all 8
`run_commands.py` consumers inherit the fix without a per-caller guard: they
can no longer observe an unauthorised value, because it is never stored.

### Deliberately NOT changed

- **`get_preferences` still returns the full catalog.** ISS-292's proposed fix
  suggested filtering `AVAILABLE_MODELS` by tier, but the failing test the
  4-test-writer left for this card asserts an Opus option IS offered
  (`assert opus, "no Opus (powerful-tier) option offered at all"`) before it
  exercises save-and-reload — filtering would make that guard fail and read as
  "unfixed". Filtering would also leave any account whose stored
  `preferred_model` is no longer in its own list rendering a `<select>` with no
  matching option. Visibility is not the security boundary; persistence is.
- **`frontend/src/components/settings/AccountSettings.tsx` is untouched.**
  Disabling the non-entitled `<option>`s (the `HomeLaunchGrid.tsx:288`
  `disabled={!allowed}` precedent) is incompatible with the same test:
  Playwright's `selectOptions` returns `error:optionnotenabled` for a disabled
  `<option>` (verified in the installed driver bundle,
  `playwright/driver/package/lib/coreBundle.js`), so the test would time out
  rather than pass. The 403's `detail` already surfaces verbatim in the page's
  existing error banner via `ApiError` (`frontend/src/lib/api.ts:346`) —
  "This model requires Pro or higher. Upgrade your plan to unlock it." The
  missing pre-emptive lock affordance is filed as
  [ISS-430](20260829-0029-ISS-430.md).
- **`_validate_model_overrides` (`run_engine.py:547-607`) is untouched** — the
  sibling caller with the identical gap, filed as
  [ISS-398](20260828-2106-ISS-398.md) and owned by a different card. The shared
  helper it needs now exists; wiring it is that card's fix, not this one's.
