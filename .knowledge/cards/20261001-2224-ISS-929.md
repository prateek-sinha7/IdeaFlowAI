# ISS-929

Derived from the QA-KB-041 analysis of [BUG-104](20260829-1508-BUG-104.md). **Confidence: INFERRED** for real browsers. The
mechanism is CONFIRMED on the live source and reproduced offline in jsdom (below); nobody has run it in Safari or Firefox.

## Condition

The notifications bell in the app header (`button[aria-label="Notifications"]`, `aria-haspopup="dialog"`, component
`NotificationPanel`), opened by a click that does not focus the bell (Safari and Firefox on macOS do not focus a `<button>`
on click; a programmatic `.click()` does not either), then Escape pressed.

## Expected

Escape closes the panel and returns focus to the bell, as `NotificationPanel.a11y.test.tsx:64-75` states.

## Actual

The panel stays open and `aria-expanded` stays `"true"`.

## Why the root cause implies it

[BUG-104](20260829-1508-BUG-104.md): Escape is bound with a React `onKeyDown` on the wrapper element, so it only counts
keydowns that start inside the wrapper. A keydown targets `document.activeElement`; with the bell unfocused that is BODY.

```tsx
// NotificationPanel.tsx:234-240
const handleKeyDown = (e: React.KeyboardEvent) => {
  if (e.key === "Escape" && open) {
    e.stopPropagation();
    setOpen(false);
    bellRef.current?.focus();
  }
};
// NotificationPanel.tsx:252
<div className="relative" ref={panelRef} onKeyDown={handleKeyDown}>
```

Nothing moves focus into the panel on open (the only `.focus()` in the file is the bell refocus at `:238`, inside this
handler). Outside click works because it is a document `mousedown` listener (`:224-232`).

## Evidence (offline, jsdom; nothing under `frontend/src` was created or edited)

`evidence/qa-kb-041/08-analyze-probe-output.txt`, source `07-analyze-probe-notif-header.test.tsx.txt`:

| case | activeElement after the click | after Escape |
|---|---|---|
| CONTROL, `user.click(bell)` (focuses, like Chrome) | the bell | panel closes, bell focused |
| REPRO, `fireEvent.click(bell)` (never focuses) | BODY | `aria-expanded = true`, `role="dialog"` still present |

Why existing coverage cannot see it: `NotificationPanel.a11y.test.tsx:64-75` opens the panel with `user.click(bell)`, which
focuses the button, so it only ever exercises the working case.

## Reach (INFERRED)

Safari and Firefox on macOS, and any input path that opens the panel without focusing the bell. Chrome on every OS and a
panel opened from the keyboard are unaffected. The bell is in the header on every page.

## What would settle it

Real Safari or Firefox (macOS): open the bell with the mouse, press Escape. Or in Chrome DevTools:
`document.querySelector('[aria-label="Notifications"]').click()`, then press Escape.

## Fix direction

Same as [BUG-104](20260829-1508-BUG-104.md): drop the wrapper handler (`:234-240` and the `onKeyDown` prop at `:252`) and call
the shared hook from [FIX-388](20260829-0053-FIX-388.md), gated on the panel being open:
`useEscapeToClose(() => { setOpen(false); bellRef.current?.focus(); }, open)` (`frontend/src/hooks/useEscapeToClose.ts`).
Keep the `enabled` argument.

## Resolution (QA-KB-041, fixer, 2026-10-02)

[FIX-710](20261002-0154-FIX-710.md) applies the "Fix direction" above as written.
`NotificationPanel.tsx:237` now reads `useEscapeToClose(() => { setOpen(false); bellRef.current?.focus(); }, open);`.
`handleKeyDown` is deleted, and the wrapper at `:249` no longer carries `onKeyDown`.

**The test file was corrected, and that is disclosed in FIX-710.** `NotificationPanel.escape.test.tsx` checked
`queryByRole("dialog")` for null synchronously after Escape. The panel leaves through a 0.15s `AnimatePresence` exit
(`:268-276`), so with the fix in place the test still reported "1 expected fail". A probe showed that straight after
Escape, `aria-expanded` was `false`, focus was on the bell, and the dialog was still mounted.

The check now runs inside `waitFor`, matching `NotificationPanel.a11y.test.tsx:71-73`, which this card cites as the
expected behaviour. Against the pre-fix panel the corrected test is red: a `waitFor` timeout after about 1.02s. On the
fixed tree it XPASSes in 3 of 3 runs. The marker is left for the verifier.
