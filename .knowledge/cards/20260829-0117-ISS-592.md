## Sibling of ISS-360 — same mechanism, Agents tab

The analyzer pass on `BUG-20260828-093757-library-hooks-id` traced the reported Hooks-tab reset to
a mechanism that lives in `routes.ts` plus a page-level remount, not in the Hooks tab specifically
— see [ISS-360](20260828-1917-ISS-360.md)'s "Analyzer confirmation" section for the full chain.
The Agents tab shares the identical shape. Not independently reproduced in a browser this pass
(INFERRED).

## Mechanism (same as ISS-360, different call site)

1. `frontend/src/components/library/LibraryPage.tsx:828` — clicking an agent card calls
   `router.push(routes.libraryAgent(agent.id))`.
2. `frontend/src/lib/routes.ts:127` — `libraryAgent: (slug) => \`/library/agents/${slug}\`` builds
   a bare path, no query string: the current `activeCategory` / `searchQuery` are not encoded in
   the URL being navigated to (contrast `routes.ts:121`'s `library()`, which DOES accept
   `tab`/`category`).
3. That `router.push` remounts the whole `DashboardPage` tree — a confirmed, tested finding at
   `frontend/src/app/[...view]/page.tsx:3238` ("T9's router.push remounts THIS page component
   ... confirmed live: a fresh render-instance id appears right after router.push"), the same
   catch-all page every screen in the app mounts under. The remount reinitializes every `useState`
   in `LibraryPage`, including `searchQuery` (`:522`, plain `useState("")`, no URL-derivation at
   all) and `activeCategory` (`:521`, `useState(urlCategory)` — a one-shot mount-time read of
   `searchParams.get("category")`, now empty since the target URL carried none).
4. `closeDetailModal` (`:635-641`) reads the ALREADY-reset `activeCategory` when the user closes
   the detail view (its Agents-branch fallthrough: `mainTab === "skills" ? ... : mainTab ===
   "hooks" ? ... : activeCategory`) and pushes `routes.library({tab: "agents", category:
   activeCategory})` — now `"all"` — so the URL loses the filter, and the search box was already
   empty from the moment the detail view opened.

## Expected vs actual

Expected: closing an agent's detail view (`AgentCapabilitiesModal`, opened via
`routes.libraryAgent`, `onClose={closeDetailModal}` at `LibraryPage.tsx:1038`) returns to the
Agents tab with the same search text and category filter the user had active before opening it.

Actual (inferred, not yet reproduced live): both are lost, identically to
[ISS-360](20260828-1917-ISS-360.md)'s Hooks-tab reproduction — search box empty, category pill
reset to "All", full unfiltered agent grid shown.

## Why this is INFERRED, not CONFIRMED

The mechanism is confirmed by direct reads of all cited files/lines — nothing here is speculative
about the code. What is not yet verified is a live browser reproduction on the Agents tab
specifically (search a term, pick a category pill, open an agent card, close it, check the
URL/search box/pill). [ISS-360](20260828-1917-ISS-360.md)'s own validator reproduced only the
Hooks tab, 3/3 cycles.
