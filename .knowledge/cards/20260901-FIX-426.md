## Root cause (shared by all four tests)

The ISS-230 fixture introduced a revision family: a root run (`77f74563`) plus
one revision. A **family row opens its LATEST MEMBER** when clicked —
the revision — whose brief, workflow type, and artifact metadata differ from the
root row's aria-label and expected text.

Four tests all selected `completed[0]` or `.first` from the flat row list
without checking whether the row was a family-of-one or a multi-version family.
When the family row sorted to position 0 (or was simply first), the test
navigated to the revision member, whose data did not match what the test
expected.

**Pattern already proven by FIX-416** — `_rows()` in suite 21 classifies each
row by the presence of a `span[aria-label$=" versions"]` badge. Rows without
the badge are families of one; rows with the badge are multi-version families.

## What changed per test

### S-06-04 `test_type_filter_counts_sum_to_the_total`

Dropped the `all_count == L.total(page)` assertion. The "All" chip counts
**families** (one row per root); `L.total()` counts **runs** (root + members).
They diverge whenever a multi-version family exists. The meaningful invariant
is `named == all_count` (every family is claimed by a type chip) — kept as-is
and updated the comment.

### S-06-14 `test_opening_a_row_lands_on_that_run`

Replaced the `.first` pick with an inline `evaluate_all` JS query (the same
`_rows()` shape as FIX-416) filtered to `n == 1` and `status == completed`.
Now clicks by index and asserts the brief from that specific row's aria-label.
Added `@pytest.mark.issue("ISS-628")`.

### S-07-04 (via `a_completed_run()`) `test_switching_tabs_does_not_wipe_run_state`

Updated `a_completed_run()` body to use the same inline `evaluate_all` query
filtered to `n == 1` and `status == completed`, click by index. Signature
unchanged — all other callers in suite 07 (S-07-01/02/03/04/05/06/…) benefit
automatically.

### S-13-11 `test_a_nonexistent_artifact_version_falls_back_to_v1_without_saying_so`

Replaced the `completed[0]` aria-label match-and-click with an inline
`evaluate_all` query filtered to `n == 1` and `status == completed`, click by
index. Added `@pytest.mark.issue("ISS-628")`.

## Blast radius

Test-only changes. No app source touched. `a_completed_run()` body changed
in suite 07 — its callers (S-07-01 through S-07-11) all benefit from the
tighter selection; none depend on it selecting a multi-version row.
