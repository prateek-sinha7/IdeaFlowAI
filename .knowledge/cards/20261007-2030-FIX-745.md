# FIX-745

Bug report QA-KB-089 (Low). The root cause and fix direction come from the root card
[ISS-948](20261002-0107-ISS-948.md) and its two INFERRED siblings [ISS-1037](20261002-1117-ISS-1037.md) and
[ISS-1038](20261002-1117-ISS-1038.md). They are not re-derived here. This is one coherent fix with one mechanism.
`GET /s/{token}` ([ADR-0035](20260828-0644-ADR-0035.md)) was registered in `main.py` and the Next rewrite. It was never
added to the other places that must know about a public path: the contract allow-list, the nginx location map, the
rewrite's handling of an empty build value, and the response's own isolation.

## What was wrong

- **ISS-948.** `backend/app/main.py:625` registers `@app.get("/s/{token}")` with no auth dependency, by design.
  `backend/tests/security/public_routes_allowlist.txt` had no `/s/` line, so
  `test_route_contract.py:170` failed and named `GET /s/{token}`, and only that route.
- **ISS-1037.** The production nginx site template in `infra/scripts/reconcile-host-config.sh` had no `/s/` location,
  so the request fell to `location /` and reached the frontend. `frontend/next.config.ts:15` used `??`. The
  production image is built with `NEXT_PUBLIC_API_URL=""`, so the destination became `/s/:token`, a self-rewrite.
- **ISS-1038.** The comment at `main.py:664-665` promises a CSP sandbox. The `share_headers` dict set none. The link
  opens on the application origin, where `auth_token` sits in `localStorage`.

## What changed, and why there

1. `public_routes_allowlist.txt`: one new section and one line, using the card's text verbatim. Each clause was
   re-checked on this tree: `secrets.token_urlsafe(32)` at `runs.py:2284`, `_SHARE_TTL_DAYS = 30` at `:2160`,
   and `get_shared_run_by_token` returning `None` for a missing or expired token at `:2322-2337`. There is no HEAD
   line, because the route registers none. The test file, `_AUTH_DEPENDENCIES` and the route are all untouched.
2. `main.py:667-668`: `share_headers` gains `"Content-Security-Policy": "sandbox allow-scripts"` plus one comment
   line. The header is route-owned, so it holds in dev, which has no nginx, as well as in production. The token
   set matches the in-app HTML renderer's `sandbox="allow-scripts"` (`PreviewPanel.tsx:278`, the T-18-05
   contract), so a deliverable that runs in that preview also runs on the share link. It applies to every branch,
   PDF included: in Chrome 151 a PDF renders identically with and without the header (see evidence). The new
   comment deliberately does not contain the word "sandbox". The static guard checks that word anywhere in the dict
   block, so a comment containing it would let the guard pass with the value reverted (see the mutant probe).
3. `reconcile-host-config.sh`: a `location /s/` block after `/install/`, containing `proxy_pass
   http://velocityai_backend` and the proxy-headers include. It has no `add_header`, because one would drop the
   server-level HSTS, nosniff and CSP headers (D3). It is a prefix location, so the "only one regex location" test
   still holds. The script already runs `nginx -t` before `systemctl reload nginx` (`:384-387`).
4. `next.config.ts:15`: `??` became `||`, and in the comment above it "absent" became "absent or empty". An empty
   value now resolves like an unset one, which is how `env.ts:31-32` already handles it. In production, nginx now
   sends `/s/` to FastAPI before Next sees it.
5. `test_nginx_site_template.py`: one new test, `test_share_link_location_proxies_to_the_backend`. ISS-1037's test
   notes ask for this check and the file is in its globs, but the test-writer did not write it. I watched it fail
   before editing the template.

## Not covered

- Not probed: Firefox and Safari rendering a PDF under the CSP sandbox. Playwright's firefox and webkit builds are
  not installed here.
- `nginx -t` was not run, because there is no nginx here. The block copies the existing `/install/` shape, and the
  reconcile script validates the config before it reloads.
- Production takes the change only after the host config is reconciled and the frontend image is rebuilt.
- No app browser run. One cycle would settle it: mint a share on a completed run, open `/s/<token>`, and expect
  the deliverable with response header `Content-Security-Policy: sandbox allow-scripts`. `main.py` reloads under
  `--reload`, and `next dev` restarts itself on a `next.config.ts` change.
- `location /s/` has no `limit_req`, while `/install/` does. ISS-1037 prescribed none. The lookup is one indexed
  query, and a 256-bit token cannot be enumerated.

## Found, not fixed

- [ISS-1066](20261007-2030-ISS-1066.md): the live-dashboard design template reads `localStorage` unguarded at init.
  A prototype seeded from it would abort under this sandbox.
- [ISS-1067](20261007-2030-ISS-1067.md): the in-app prototype and OD deck previews pair `allow-scripts` with
  `allow-same-origin`, and Open in new tab loads the blob URL with no sandbox at all. That is the same exposure
  ISS-1038 removed from the share link.
