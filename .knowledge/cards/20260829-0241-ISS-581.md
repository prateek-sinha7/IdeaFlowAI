## Found while fixing ISS-320

With [FIX-385](20260829-0241-FIX-385.md) applied, the unconfirmed "Clear" no
longer deletes anything — the post-click `GET /api/settings/constitution`
returned the saved value in all 3 runs, where the validator saw `null` 3/3
before. The test still reports `xfail` because it cannot reach a state where
its own assertion is meaningful. Two independent defects, neither in the fix:

## 1. The typed marker is never persisted (product race)

`test_clear_constitution_requires_confirmation_before_deleting` does
`editor.fill(marker)` → click Save → expect "Constitution saved", then asserts
the persisted content equals `marker`. In all 3 runs the persisted content was
the account's PREVIOUS value, and the screenshot taken immediately after the
save (`01-iss320-saved.png`) shows the textarea holding that previous value at
44/4000 chars — the fill had already been undone before Save read `content`.

`ConstitutionSection`'s mount effect
(`frontend/src/components/settings/AccountSettings.tsx:514-527`) issues
`GET /api/settings/constitution` and calls `setContent(data.content || "")` on
the response. Instrumenting the page shows the request firing **twice** (React
StrictMode double-invokes the effect in dev), and the textarea only mounts once
the FIRST response has landed — so anything typed between the two responses is
silently reverted by the second `setContent`. In a warm browser context the
second response beats the first keystroke and nothing is lost; in the test's
cold, freshly-created context it does not. Same failure shape as the AI-model
tab's documented "the fetch sets `pendingModel` as well, so an early selection
is silently UNDONE" (`test_settings.py:34-45`) — that one is worked around in
the test, this one is not.

Under production (no StrictMode) the effect runs once, so the window is much
narrower, but it is not closed: any user who types before the single mount GET
resolves has their text replaced.

## 2. The test's dialog handler duplicates the autouse dismisser

`conftest.py:279` registers an autouse `dismiss_native_dialogs` fixture that
attaches `page.on("dialog", …dismiss())` to every page. The test attaches a
SECOND identical handler. Both fire; the loser raises

```
playwright._impl._errors.Error: Dialog.dismiss: Cannot dismiss dialog which is
already handled!
```

which fails the run outright rather than xfailing it (observed on run 2 of 3;
runs 1 and 3 xfailed on the assertion instead). The fixture's docstring claims
"Handlers registered later by a test take precedence" — Playwright has no such
precedence; every registered handler is invoked.

## Disposition

Not fixed here — this is test-and-fixture territory, and 5-fixer does not edit
a test to make its own fix pass. The narrower product half (a late mount
response overwriting user input in `ConstitutionSection`) is a real defect on
its own and can be fixed independently of the test, e.g. by ignoring a
response that arrives after the editor has been edited.
