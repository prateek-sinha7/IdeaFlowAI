## What was wrong

BUG-20260827-221730-library: on `/library`, typing a search term that matches
nothing left the whole content area blank — no text, no icon, no affordance —
on all three tabs. Reproduced 3/3 by the validator (Agents via `/library`,
Skills via `/library?tab=skills`, Hooks via `/library?tab=hooks`); the category
pills stayed visible and the static header count line
(`94 agents · 186 skills · 8 hooks · …`) never changed, so nothing on screen
signalled that a search had even run.

## Root cause

`frontend/src/components/library/LibraryPage.tsx` — each of the three grids was
a two-branch ternary keyed only on the fetch status:

```
{agentsStatus === "loading" ? <skeletons> : filteredAgents.map(...)}
```

at `:783` (agents), `:867` (skills, over `activeSkills`) and `:964` (hooks).
`filteredAgents` (`:601`), `filteredSkills`/`activeSkills` (`:620-628`) and
`filteredHooks` (`:631`) each correctly narrow to `[]` when nothing matches, and
`[].map()` correctly renders nothing — there was no `length === 0` branch
anywhere in the file to render instead. Client-side filtering was never the
defect; the missing third branch was.

## What changed and why there

One file, one new local component plus three one-line branches:

- `EmptyGridState` (`LibraryPage.tsx:180`) — a `col-span-full` cell rendering
  ``No {noun} match “{query}”`` (or `No {noun} found` when there is no query)
  and a **Clear search** button that resets that tab's own search state.
- The three grid ternaries gain a middle branch, keyed on the array's LENGTH:
  agents `:805` (`filteredAgents.length === 0`), skills `:891`, hooks `:993`.

It lives inside `LibraryPage.tsx` rather than in `components/ui`, per
[ISS-231](20260828-1630-ISS-231.md)'s fix location: every other empty state in
this codebase is local to its own component (`AgentLibrary.tsx:229`,
`AgentsPopup.tsx:987`), and `LibraryPage` has exactly one consumer
(`DashboardLayout.tsx:10`, `mainView === "library"`), so no other route can
reach the defect. One shared component called three times, rather than three
pasted blocks: all three grids already shared the same ternary shape, and a
guard that differs per call site is how two of the three drift later.

Keyed on `length`, deliberately not on "is there search text" — a category or
event pill that filters down to zero reaches the identical unguarded map with
an empty search box, so a search-keyed guard would silently miss it (that is
[ISS-335](20260828-2040-ISS-335.md)'s trigger).

The skills branch tests `filteredSkills.length === 0`, not `activeSkills`
(the array that grid maps): when only beta skills match, the "Coming Soon" grid
below (`:932`) still renders them, so the area is not blank and a
"No skills match" line above it would contradict the cards under it. Commented
in place.

## Not fixed here (still open)

- [ISS-335](20260828-2040-ISS-335.md) — category/event filter with no search
  text. Same three call sites, same file; the length-keyed branch this card
  adds is the mechanism that path needs, but it was not exercised by any test
  run here, so the card stays open for its own verification rather than being
  claimed on inference.
- [ISS-330](20260828-2041-ISS-330.md) — a *failed* catalog fetch
  (`status === "failed"`) still falls through the same ternary, and now lands on
  `No agents found` instead of a blank grid. That is wrong messaging for an
  error, not an empty result: it needs its own `status === "failed"` branch with
  a retry affordance, which is outside this card's scope and stays open.
