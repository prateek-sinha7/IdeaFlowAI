## What was wrong

### 1. `IntegrationsCard.copyFeedback.test.tsx` — API-key copy button (ISS-561 / ISS-600)

```ts
const copyButtons = screen.getAllByRole("button").filter((b) => !b.textContent?.trim());
fireEvent.click(copyButtons[0]);
```

The GitHub PAT section renders before the API keys section. Its show/hide password toggle (`IntegrationsCard.tsx:266–273`, an icon-only `<button type="button">`) is the FIRST text-free button in the DOM. The test toggled password visibility instead of clicking the key copy button, so the clipboard was never touched.

### 2. `LibraryPage.copyFeedback.test.tsx` — both ISS-331 and ISS-555

`useParams: () => ({})` made `LibraryPage`'s URL slug `null`. The T16 effect at `LibraryPage.tsx:643–665` calls `setSelectedHook(null)` / `setSelectedSkill(null)` when the slug is null — so immediately after `setSelectedHook(hook)` fired from the card click, the effect re-ran and closed the modal. The copy button was found via `findByRole` but was detached from React's tree by the time `fireEvent.click` landed; `writeText` calls = 0.

## What changed and why there

### Fix 1 — `IntegrationsCard.copyFeedback.test.tsx`

Added `within` import and scoped the copy-button selector to the "New key — copy now" container:

```ts
import { render, screen, fireEvent, waitFor, within } from "@testing-library/react";

// In the test body, replace:
//   fireEvent.click(copyButtons[0]);
// with:
const keyBanner = screen.getByText("New key — copy now").closest("div")!;
const { getAllByRole: getAllInBanner } = within(keyBanner);
const copyBtn = getAllInBanner("button").filter((b) => !b.textContent?.trim())[0]
  ?? copyButtons[copyButtons.length - 1];
fireEvent.click(copyBtn);
```

This correctly resolves to the key copy button regardless of how many other text-free buttons exist elsewhere on the page.

### Fix 2 — `LibraryPage.copyFeedback.test.tsx`

Both describe blocks now override `useParams` to return a deep-link path matching the modal they're testing:

```ts
const { useParams } = await import("next/navigation");
// For hooks test:
vi.mocked(useParams).mockReturnValue({ view: ["library", "hooks", MOCK_HOOK.id] });
// For skills test:
vi.mocked(useParams).mockReturnValue({ view: ["library", "skills", MOCK_SKILL.id] });
```

With a non-null slug, `librarySlug` is truthy, the T16 effect does not fire `setSelectedHook(null)`, and the modal stays mounted through the click. The card/tab clicks that were used to open the modal are removed (the URL already opens the correct detail view on mount).

Both `it.fails` markers are retained — the application-side clipboard feedback defects are not fixed here.
