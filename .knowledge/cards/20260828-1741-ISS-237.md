# ISS-237

**Register source:** sibling derived while analyzing `BUG-20260828-015930-runs-cancelled`
(root card [ISS-220](20260828-1712-ISS-220.md)) in `bug-hunter/ledger.md`.

## Why the root cause implies this

Same shared-code argument as [ISS-236](20260828-1740-ISS-236.md) (see that card for the
full mechanism trace, confirmed on [ISS-220](20260828-1712-ISS-220.md)):
`frontend/src/components/chat/RunChatLane.tsx`'s degraded terminal card ("Completed with
issues") also calls the shared `relaunch(...)` helper —

```
// RunChatLane.tsx:1845-1867
if (pipelineState?.degraded) {
  ...
  {relaunch("Run again")}
```

— which renders a button whose `onClick` is `() => onRelaunch?.()` (`RunChatLane.tsx:1699`),
wired from `DashboardLayout.tsx:3012` (`onRelaunch={handleResumeRun}`) to the exact same
`handleResumeRun` (`DashboardLayout.tsx:2253-2311`) as the cancelled and failed cases.
`handleResumeRun` has no branch on the originating terminal marker (cancelled/failed/
degraded) — it resolves `runId` generically and calls `postResume` →
`runConnection.attachRun` regardless. The backend's own resume-eligibility error message
(quoted in the register's `BUG-20260828-020430-runs-diverted` entry) confirms `degraded`
is accepted alongside `failed`/`cancelled`: `"only failed, degraded, or cancelled runs are
resumable"`. So the same `isRunning`-effect → `router.push` → `page.tsx` remount →
subscribe-gap (`page.tsx:2196-2206` vs. the unbuffered fan-out at
`RunConnectionProvider.tsx:331-339`) chain is reachable from this third entry point too.

## Expected vs actual (predicted, not yet observed)

- **Expected:** clicking "Run again" on a degraded run's detail page resumes the
  pipeline and the live `/stream` view tracks the backend's events in near-real-time.
- **Predicted actual:** same timing-dependent freeze class as ISS-220 — a fast-enough
  subsequent terminal event (another `pipeline_failed`/`pipeline_complete`/
  `pipeline_degraded`) landing inside the remount's subscribe gap leaves the live view
  stuck on stale pre-remount state until a manual reload.

## Status

**INFERRED — not reproduced.** Derived from the shared-code argument above, not an
independent repro cycle. What would confirm it: seed a `degraded` run, click "Run again"
from its detail page, and repeat ISS-220's cold-start reproduction protocol.

## Fix

Same shared seam as [ISS-220](20260828-1712-ISS-220.md) and [ISS-236](20260828-1740-ISS-236.md)
— not a per-button patch. See ISS-220 for the proposed direction.
