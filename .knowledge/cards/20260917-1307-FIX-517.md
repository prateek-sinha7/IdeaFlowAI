## What was wrong

This is register bug **QA-PS-003**. On a User Stories run with two clarification rounds, the
concierge chat showed `Before I build, I need to lock a few things down.` and
`Clarifications answered` once per round, word for word, so the transcript could not tell
round 1 from round 2. The root cause is in [ISS-645](20260917-1000-ISS-645.md). Its sibling
[ISS-646](20260917-1030-ISS-646.md) covers the same gap on the question card.

## Root cause

- `backend/app/agents/chat_narrator.py:161-169` (pre-fix): the `_CLARIFY_EVENTS` branch of
  `_classify()` built its text from `question_count`/`questions` alone and never read a round.
  In production the `questionnaire_complete` payload carries no count, so the text fell back to
  the constant `Clarifications answered` every time. The `questionnaire_ready` branch returned a
  constant too.
- `backend/agents/execution_engine/clarify_engine.py:342-352` (pre-fix): the
  `questionnaire_complete` emit sent only `pipeline_run_id`, `responses`, `updated_gate` and
  `timestamp`. `questionnaire_ready` (`:294-305`) already carried `round: round_num`.

## What changed, and why there

1. `clarify_engine.py:349`: added `"round": round_num` to the `questionnaire_complete` data,
   mirroring `questionnaire_ready`. `ClarifyEngine.run` is the event's only producer under `backend/`.
2. `chat_narrator.py:165-175`: `_classify()` now reads `data.get("round")`. If it is present,
   `questionnaire_complete` reads `Clarifications round N answered`, the text the register entry
   expects, and `questionnaire_ready` reads `Round N: Before I build, I need to lock a few things down.`
   If it is absent, the text is byte-identical to before. Rows persisted before the fix therefore
   render unchanged, and the pre-existing fixed-string assertion in
   `test_clarify_card_from_questionnaire_ready` still holds with no test edit.

`_classify()` is the one function every caller routes through. The engine milestone sink
(`app/main.py:162-165`) and both launch drivers (`app/api/run_commands.py:3613`, `:4984`) inject
`persist_milestone_card`, which calls `project_milestone_card`, which calls `_classify`. The
frontend renders a clarify card's text verbatim (`frontend/src/components/chat/ResultCard.tsx:140-145`,
`message.content`), so the frontend needed no change.

Left alone on purpose: the deep-link target `clarify:{anchor}` stays round-agnostic. Card
idempotency keys on the source event id (`_reply_event_id`, `chat_narrator.py:323`), and nothing
in the backend or frontend parses or dedups on that target, so it has no visible effect. The
question-card copy is a prefix, so the old sentence survives verbatim for substring probes.

Only new runs get numbered cards. `chat_reply` rows are persisted at emit time, so runs recorded
before this fix keep the old identical text.

Invariants: SC-001 holds; `grep "if pipeline_type ==\|if spec.id ==" backend/agents/execution_engine/`
returns 0. No import was added, no migration touched, and no golden carries a questionnaire event.
