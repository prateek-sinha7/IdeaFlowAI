## The symptom

`validate_links.py`, run read-only, reports:

```
Card filenames checked: 1253
Card cross-refs checked: 3210
Total local links checked: 14428
Resolved: 14427
Broken: 1
  .knowledge/architecture/files/backend/alembic/versions/0040_run_manifest_json.py.md
```

The card points at a source file that no longer exists. Both
`feat/file-extract-tools` and `feat/git-versioning` minted a `0040`; the merge
`4ebd98e8f` renumbered the manifest migration to
`backend/alembic/versions/0047_run_manifest_json.py`, and `0040` is now held by
`0040_workflow_run_share_token.py`. No `0047` card was ever created —
`.knowledge/architecture/files/backend/alembic/versions/` stops at
`0046_run_provenance_audit_outcome.py.md` while still carrying **both**
`0040_*.md` files. The orphan was added alongside the original migration in
`127b20a3d`.

`validate` is the LAST stage of `rebuild_knowledge.py` — the thing that
certifies the store is coherent. It therefore fails on every full run, which
trains the operator to read its output as noise.

## The finding is not "delete the stale card"

Deleting it fixes today. The shape is what needs recording.

The only code in the entire pipeline that removes an orphaned file card is the
prune block in `write_file_cards()` at
`tools/knowledge/build_architecture.py:906-926`:

```python
live = {str(out_root / (f + ".md")) for f in files}
...
        stale.unlink()
```

commented in place as *"the only unlink() in the whole pipeline"*. It is called
from exactly one site, `build_architecture.py:2180`, inside the full
architecture run.

But `skills/velocity/cli.md` routes both routine card-writing verbs through the
cards-only rebuild:

- `cli.md:15` — **the cards-only rebuild** = `rebuild_knowledge.py --skip-architecture`
- `cli.md:172` — `book-keeping.md`: *"after writing a card: `rebuild_knowledge.py --skip-architecture`"*
- `prime.md`'s own final step lands on the same flag.

And `--skip-architecture` exists precisely because that stage is expensive
(`rebuild_knowledge.py` docstring, lines 28-30: pydeps and dependency-cruiser
over the whole codebase, ~1-2 min).

So the common path:

- **can never prune** — the only prune is in the stage it skips, and
- **still runs `validate`** — `STAGES` is `architecture, index, context,
  validate`, and only the first is skipped.

It fails on exactly the damage it was structurally unable to repair. The
pre-commit hook does not close the gap either: phase 2's
`build_architecture.py --refresh-affected` returns before `write_file_cards()`
is reached (`:1906-1921`), and phase 3 re-enters `rebuild_knowledge.py
--skip-architecture`.

Self-healing is impossible unless the operator already knows to run the
expensive stage by hand — and the validator's message names the stale *card*,
not the stage that would remove it.

## Why it will recur

Any file rename or deletion reproduces this identically: the source moves, the
cheap rebuild leaves the old card, `validate` breaks, and nothing on the
routine path can clear it.

[FIX-295](20260824-2100-FIX-295.md) already cards the alembic-side half of this
exact renumber class (two migrations claiming one revision after a merge). The
knowledge-store half — the orphan card the renumber leaves behind — has no card
at all until this one.

## Options

- Move the prune out of `write_file_cards()` into something the cards-only path
  can run cheaply (it needs only the live file list, not the extractors), keeping
  the `PreserveError` guard for `MOD-*`/`DOMAIN-*` intact.
- Or have `validate` name the remedy — "run the architecture stage to prune" —
  instead of only naming the broken card.
- Either way, create the missing `0047_run_manifest_json.py.md` card and drop
  the `0040_run_manifest_json.py.md` orphan.
