## Description

Supersedes [ISS-282](20260828-1710-ISS-282.md). Validated bug
**BUG-20260828-014937-runs-id-stream** (diverted run's Preview tab shows the live
"waiting for output" placeholder instead of a terminal-aware message) has a TWO-part
root cause, not the one part ISS-282 named. ISS-282 is factually correct about
`PreviewPanel.tsx:696-699` (`reopenFailureSignal` omits `"diverted"`), but its closing
recommendation — "Adding `diverted` to this list ... would close this" — is FALSE as
written, because the prop that check reads, `reopenedRunStatus`, can never actually
equal `"diverted"` in the first place. A fixer who applies only ISS-282's recommended
edit would re-test and find the bug still reproduces.

**The real first-failure point is one hop upstream, in the function that seeds
`reopenedRunStatus` for the reopen path:**

`frontend/src/app/[...view]/page.tsx:3035-3041` (inside `handleSelectWorkflowRun`,
the same handler that hydrates a direct `/runs/{id}/stream` cold navigation — confirmed
called from that route's effect at `page.tsx:3255` and `page.tsx:3460`):

```ts
setReopenedRunStatus(
  fullRun.status === "failed" ||
    fullRun.status === "cancelled" ||
    fullRun.status === "degraded"
    ? fullRun.status
    : undefined,
);
```

`"diverted"` is not in this ternary's condition, so for a diverted run this always
evaluates to `undefined`. Grepping every `setReopenedRunStatus(` call site in the file
(`page.tsx:2720`, `:3035`, `:3931`) confirms this is the ONLY call that ever sets a
non-`undefined` value — the other two are pre-fetch/reset points that always clear it to
`undefined`. `reopenedRunStatus` therefore has an effective runtime range of
`"failed" | "cancelled" | "degraded" | undefined` **project-wide**, never `"diverted"`,
regardless of what `PreviewPanel.tsx`'s own list tests for.

The value then flows unmodified: `page.tsx:3843` → `<DashboardLayout
reopenedRunStatus={reopenedRunStatus}>` → `DashboardLayout.tsx:3129` → `<PreviewPanel
reopenedRunStatus={reopenedRunStatus}>` → `PreviewPanel.tsx:696-699`'s
`reopenFailureSignal` check. No intermediate site re-derives or widens it.

**Why this gate excluded `"diverted"` at all (context, not an excuse):** unlike
failed/cancelled/degraded, a diverted run is not a *failure* — folding it into
`reopenFailureSignal` unchanged would misuse the generic amber
`DegradedRunAffordance` copy ("agents failed") for a run that actually succeeded up to
its divert point. The gate's omission was directionally reasonable (don't mislabel a
divert as a failure) but incomplete: nothing was ever added to give diverted its OWN
terminal-explanatory branch, the same way `isCancelledTerminal` already carved out
distinct copy for `"cancelled"` (`PreviewPanel.tsx:706-719`).

## Where the fix belongs

Both hops must change together, or the fix is a no-op:

1. `page.tsx:3035-3041` — thread `"diverted"` through (either add it to this ternary's
   condition, or stop pre-filtering here and pass `fullRun.status` through whenever it
   is one of the app's known terminal-with-no-content statuses).
2. `PreviewPanel.tsx:696-706` — recognize `"diverted"` as its own case, parallel to
   `isCancelledTerminal`, with copy that says the run diverted and will not resume (not
   the generic failed/degraded affordance copy) — this is the fix ISS-282 already
   sketched, still valid for ITS half of the mechanism.

The identical `failed || cancelled || degraded` triad, hand-duplicated with no shared
helper, also appears in two more reopen-surface call sites unrelated to this route —
see the sibling cards [ISS-391](20260828-2049-ISS-391.md) and
[ISS-395](20260828-2050-ISS-395.md). A single shared predicate/list (e.g.
`REOPEN_FAILURE_STATUSES`, imported everywhere this triad is hand-copied) would make
adding a future terminal status a one-line change instead of four hand-synced edits —
consistent with how `REOPEN_TERMINAL_STATUSES` (`page.tsx:86`) and
`TERMINAL_MARKER_BY_STATUS` (`useWorkflow.ts:324-330`) already centralize the broader
terminal vocabulary and already correctly include `"diverted"`.

**Ruled out as blast radius:** `useWorkflow.ts`'s `TERMINAL_MARKER_BY_STATUS` (live-run
path) and `RevisionFamilyView.tsx`'s `statusDotClass` (history-list status dot) both
already special-case `"diverted"` correctly — read directly, not affected. The backend's
own canonical `TERMINAL_RUN_STATUSES` (`backend/agents/execution_engine/engine.py:503`)
already includes `"diverted"` — this is a frontend-only gap.
