# ISS-149

## Title

Five more Concierge answer-gaps have no tool, mirroring the shape FIX-249 just fixed for tokens/cost. (1) Deliverable FILENAME — asked what file a run produced, the Concierge gives the artifact's TITLE, never workflow_runs.deliverable_filename; list_artifacts (concierge.py:792-801) projects ArtifactRef rows and ArtifactRef (app/models/artifact_ref.py) has no filename column to project. (2) Cache read/write token counts — TokenUsageSummary.tsx renders cacheReadTokens/cacheWriteTokens; the new get_token_usage tool (FIX-249) deliberately excludes them (asserted by an exact-key-set test, test_get_token_usage_omits_cache_and_model_fields) to keep that fix narrow. (3) Model used — concierge.py's RESPONSE RULES still forbids "model names" (unchanged by FIX-249); TokenUsageSummary.tsx's MODEL_SHORT_NAMES map shows the model is already user-facing elsewhere. Whether the Concierge should be allowed to name it is an OPEN PRODUCT QUESTION FIX-249 deliberately did not decide — resolving it would also need a model_id source the new tool does not surface. (4) Total run duration — no Concierge tool surfaces it, and see ISS-150 for the fact that this repo currently has TWO disagreeing numbers for "how long did this run take". None of these were fixed here on purpose — FIX-249's tool was scoped narrowly to the exact question the investigation reproduced live (tokens/cost) plus a general honesty rule so the model at least admits a blind spot instead of inventing a product limitation for these five, rather than widening the tool surface speculatively.

## Source / evidence

Surfaced during the FIX-249 investigation/fix (quick-260813-5qr); items 1 and 3 were explicitly identified by the original investigation, items 2 and 4 by this fix's own scoping decisions.
