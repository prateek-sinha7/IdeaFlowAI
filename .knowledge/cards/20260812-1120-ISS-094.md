# ISS-094

## Title

**3 reds in `tests/agents/test_gates.py` — hand-rolled context doubles drifted from the real engine contract on an ATTRIBUTE, so no signature guard can catch them.** Measured offline at `fab9b646` and again after FIX-231: **3 failed / 39 passed**, unchanged, in 0.7 s — not flaky, not environment-gated (no Postgres/Bedrock/Chromium gate fires). Failing ids: `test_raising_hitl_gate_blocks_and_stops_gate_evaluation`, `test_engine_sentinel_carries_human_gate_edit_detail`, `test_apply_declared_gate_edit_rewrites_upstream_artifact_and_result`. Two distinct symptoms: `engine.py:6955` in `_latest_typed_ref_id` does `for ref in ectx.artifacts.tree(ectx.run_id)` → **`AttributeError: '_Ectx' object has no attribute 'artifacts'`** (the file's local `_Ectx` stub at `test_gates.py:939` sets only `scoped_store`, while `_apply_declared_gate_edit` → `_latest_typed_ref_id` now reads `ectx.artifacts`), and two × **`AttributeError: '_Ctx' object has no attribute 'gate_agent_ids'`**. **Same defect family as ISS-074** — a hand-rolled test double that silently fell behind the real contract — **but the drifting surface is an attribute, not a parameter, so FIX-231's `test_gate_stub_signature_drift.py` guard does NOT and cannot catch it.** An analogous attribute-conformance guard over `_Ectx`/`_Ctx` doubles is the family-ending move, and is the reason this is worth a row rather than a one-line stub patch. **Do NOT just add the missing attributes without checking what the engine now expects them to contain** — a double that returns an empty `artifacts` tree would make these tests green while asserting nothing. Prior art: acknowledged in prose inside the **ISS-078** row (*"Also observed, unregistered: 3 pre-existing reds in `tests/agents/test_gates.py` … present at `99fcf4a2`, unrelated to ISS-078, in no register row I could find"*) but never given a row of its own — this is that row.
