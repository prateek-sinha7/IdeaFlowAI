## Symptom

`/create/user_stories` offered only "Save workflow" and "Run workflow" — no **"Save as my
version"**. Spec 016 shipped believing it covered every built-in; it covered two.

## Root cause

`LaunchWizard`'s `MODE_CONFIG` is typed:

```ts
savePipeline: "prototype" | "ppt";
```

Only `/create/ppt` and `/create/prototype` render `LaunchWizard` — the component the spec-016
override UI was built into. `user_stories`, `app_builder`, `mulesoft_to_springboot` and
`dotnet_to_azure` all render `IdeaInputPage`, which had no override state, no toggle, no save.

## Fix

Full override path added to `IdeaInputPage`:

- override state (`overrideInfo`, `overrideAgents`, `overrideSelections`, `showOverride`)
- capture off the **existing** `getWorkflowDetail` effect — no second request
- roster precedence decided **inside** the roster effect (that effect re-runs when
  `manifestAgents` lands from the same fetch, so a separate apply would race it and the library
  roster would sometimes win)
- `handleToggleOverride`, `handleSaveAsOverride`, the "Save as my version" button, and the
  "Use my version" checkbox props
- hidden for `custom`, which is the fork surface and has no built-in to override
