## Related

## What was wrong

Loop-cap exhaustion on a backward route (e.g., task loop reaching max 
iterations) was treated as a fatal error, raising immediately and failing 
the run. There was no recognition that exhaustion could be a natural 
convergence signal.

## The fix (commit 1e329e47b)

- Suppress the raise on loop-cap exhaustion; record the exhaustion reason.
- Continue the run (fail-open on iteration exhaustion).
- Emit a warning event only if the run ends with no deliverable.
- If a deliverable exists, the run is considered recovered and no warning is emitted.

Pinned by test_loop_cap_warning_not_degraded.py verifying that loop 
exhaustion does not degrade the run status when a deliverable is present.
