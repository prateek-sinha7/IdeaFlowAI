# ISS-098

## Title

A mid-wave CancelledError leaves its wave_runs row stuck at running forever. wave_scheduler.py:340 catches except Exception: to flip the in-flight wave's row terminal, but asyncio.CancelledError has inherited from BaseException since Python 3.8, so it is not caught and the row is never updated. Reachable on every Stop-during-a-wave (probe-confirmed that Stop does raise CancelledError through run_fanout). Why it is only trivial: WR-01's stale-row sweep (wave_scheduler.py:304-313) flips such rows superseded on the next resume, so the durable record self-corrects and no resume decision is made on the stale value. The visible cost is a wave_runs row reading running for a run that is plainly terminal — misleading to anyone reading the table directly. Fix is one token: except BaseException: (re-raising) or an explicit except asyncio.CancelledError: arm beside the existing one.
