# ISS-1152

**Register source:** found while running regression tests for `QA-KB-106` ([FIX-773](20261009-0952-FIX-773.md)). This is about test
infrastructure, not product behaviour. It has no bug row. The file matched a grep for `onStartPipeline`, but it tests `WorkflowView`'s own
`onStartPipeline` prop. `WorkflowView.tsx` imports none of the five files FIX-773 changed.

## Observed on 2026-10-09 (macOS, node v22.23.1, vitest 4.1.11), from `frontend/`

- `npx vitest run src/components/workflow/WorkflowView.attachmentRemove.test.tsx` on the working tree gave no result after about 10 minutes
  (started 09:31:31, then killed). A second try had a 5-minute cap (`perl -e 'alarm 300; exec @ARGV'`, 09:43:26 to 09:48:26) and also gave
  no result.
- The same command on a `git archive HEAD` copy of `frontend/` (HEAD `ed1eebf45`, `node_modules` symlinked) prints
  ` RUN  v4.1.11 ...` and then stops. There was still no result after 183 s.
- In the same session, 73 other vitest files each finished in seconds. They cover DashboardLayout, ComposerPage, IdeaInputPage, the
  `page.tsx` source locks and `lib/api` (`evidence/qa-kb-106/fix-08-vitest-one-file-at-a-time.txt`).
- Another session's Playwright sweep was running on the machine at the same time, so CPU contention is not ruled out. It did not stop
  the other 73 files.

So the stall is not caused by FIX-773: it happens on HEAD too. It is also not proven to be pre-existing on an idle machine.

## Not traced

It is not known which test in the file stalls, or whether vitest stalls while collecting it (`WorkflowView.tsx` imports `PipelineGraph`,
`AgentLibrary`, `useAgentLibrary` and `useSpeechRecognition`). To settle it, run
`npx vitest run <file> --reporter=verbose --testTimeout=20000` on an idle machine. A per-test timeout names the test that stalls. No
output at all points at collection or imports.
