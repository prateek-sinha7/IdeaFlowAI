## Sibling of ISS-326 — INFERRED, not yet reproduced in the browser

[ISS-326](20260828-ISS-326.md) established the root cause for `BUG-20260827-221400-dashboard`:
`WorkflowDialog.tsx` declares `role="dialog" aria-modal="true"` with zero Escape/keydown
handling anywhere in the file. Filed while grepping every `role="dialog"` element under
`frontend/src/components/workflow/` (the same module `WorkflowDialog.tsx` belongs to) for the
same gap.

`composer/AgentSkillsPicker.tsx` — "the ONLY skill-attachment UI in the app" per its own doc
comment (lines 26-30) — carries a `detailSkill` state (line 126) that opens a "View details"
popup for a single skill: an `aria-label="View {name} details"` button per skill row
(lines 208-212, `onClick={() => setDetailSkill(s)}`) opens a `role="dialog"
aria-modal="true"` panel (lines 251-289) with a backdrop `onClick={() => setDetailSkill(null)}`
(line 254) and a Close `<button onClick={() => setDetailSkill(null)}>` (line 267) — the
identical copy-pasted shell shape as `WorkflowDialog.tsx`. A whole-file grep for `Escape`,
`keydown`, `KeyboardEvent` and `addEventListener` returns zero matches anywhere in the file.

Because this component is shared rather than page-specific, the gap is reachable from three
independent embedding surfaces (confirmed by grep, not inferred): `AgentCapabilitiesModal`'s
Skills tab (`AgentsPopup.tsx:870`), the Composer Simple view's per-agent row
(`composer/AgentRow.tsx:267`), and the Composer Canvas view's config rail
(`composer/CanvasConfigRail.tsx:468`) — so the same missing handler surfaces in at least three
different journeys, not just one.

## Expected vs actual

- **Expected:** pressing Escape while the skill-detail popup is open closes it, matching the
  `role="dialog"`/`aria-modal="true"` semantics already declared on the element.
- **Actual:** no code path calls `setDetailSkill(null)` on Escape anywhere in the file — only
  the backdrop click and the explicit Close button dismiss it.

## Why this is INFERRED, not CONFIRMED

The missing handler is confirmed by reading the component's source in full and grepping the
whole file for every keyboard-related token — there is no Escape-handling code to find. What
is NOT yet verified is a live-browser repro from any of the three embedding surfaces: open a
skill's detail popup, press Escape, and confirm it stays open (mirroring ISS-326's own 3-cycle
reproduction on `WorkflowDialog`).
