# ISS-077

## Title

**`ArtifactNode`'s TypeScript declaration disagrees with the wire shape on three fields.** `frontend/src/lib/api.ts:602-604` declares `derived_from: string[]` and `children: string[]`, but the backend returns `derived_from: string \| null` (`runs.py:920`) and `children: ArtifactNode[]` (`runs.py:921`); `task_id` is declared `string` but is `null` on every row observed. Nothing reads those three fields today — `WorkflowHistory.tsx:303` and the new `ArtifactVersionPicker` both use only `kind` / `version` / `content_hash` / `producer_agent` / `id` / `content` — so nothing is broken, but the first consumer of the lineage tree will be type-checked against a lie and will write `.map()` over a nullable string. The same file's docstring also cites `runs.py:590-608` for the node shape, which has drifted; the real `_node` is `runs.py:907-925`.

- Sev: minor
- Tag: frontend
- Status: **OPEN**

## Source / Evidence

Found 2026-08-12 during the ISS-065 investigation and deliberately NOT fixed while implementing FIX-222 — it is unrelated to the version picker and folding it in would have widened a scoped diff for no test coverage. One-line change plus a docstring correction.

Static reproduction, 3/3 cold re-runs (grep/read, no browser). Current locations: `frontend/src/store/api/runs.ts:45,51,52` and `frontend/src/lib/api.ts:1502,1508,1509` declare `task_id: string`, `derived_from: string[]`, `children: string[]`. Wire: `backend/app/api/runs.py:1383,1390,1391` (`_node`) sends `r.task_id` (column nullable, `artifact_ref.py:39`), `r.derived_from` (nullable single-FK string, `artifact_ref.py:45`) and `children: []` later filled with `ArtifactNode` dicts (`runs.py:1451`). The same defect is duplicated in both TS files; backend also sends `retention`, undeclared. api.ts docstring still cites stale `runs.py:590-608`. Condition: none, deterministic, code-level. Evidence: `evidence/qa-kb-029/01-validate-static-ts-vs-wire-mismatch.txt`.

## Analysis (QA-KB-029, 2026-10-01)

Read-only analysis of the current code and of real rows. Transcript, queries and the harness: `evidence/qa-kb-029/02-analyze-wire-shape-and-picker-undercount.txt`.

### Root cause (CONFIRMED)

The frontend `ArtifactNode` was authored against the wrong shape and has never matched the wire. The backend lineage tree (nested `children`, nullable `derived_from`, `retention`) landed on 2026-06-08 in `2f8acbe9a` (`backend/app/api/runs.py:1366-1453`, `_node` at `:1377-1395`); the TS type landed 25 days later in `4a9ba1220` (`feat(260702-wwx)`) with `task_id: string`, `derived_from: string[]`, `children: string[]` and no `retention`. It did not drift, it started wrong. Nothing could have caught it: the endpoint has no `response_model` (`runs.py:1456`), the `frontend/src/lib` types are hand-mirrored by design (module card `MOD-frontend-src-lib`, "Why this shape"), and the one fixture that exercises the route (`frontend/src/lib/api.getRunArtifacts.test.ts:42-43`) is an untyped literal that itself carries the stale `derived_from: []`.

The backend shape is the intended contract, pinned by `backend/tests/integration/api/test_runs_api_artifacts_api.py:176-193` (`root["children"][0]["id"] == "B"`, `child["derived_from"] == "A"`, `"retention" in root`). The TS is what is wrong; no product decision is involved.

Wire versus declaration, per field:

| field | wire (file:line) | TS today | correct TS |
|---|---|---|---|
| `task_id` | `runs.py:1383`; nullable column `artifact_ref.py:39`; null on 1896 of 1963 rows, a string on 67 | `string` | `string \| null` |
| `derived_from` | `runs.py:1390`; nullable FK `artifact_ref.py:45`; a parent RUN's artifact id on 13 of the 15 rows where it is set | `string[]` | `string \| null` |
| `children` | `runs.py:1391`, filled at `:1451` with node dicts | `string[]` | `ArtifactNode[]` |
| `retention` | `runs.py:1387`; non-null column `artifact_ref.py:49-51`; `run_ttl` on all 1963 rows | not declared | `string` |

`id`, `kind`, `producer_step`, `producer_agent`, `content_hash`, `version`, `visibility`, `location`, `parents` and the optional `content` already match.

### Corrections to the original text of this card (meaning unchanged, so no supersession)

1. "`task_id` ... is `null` on every row observed" was true of the runs seen in August; today it is `null` on 96.6% of rows and a string on the 67 task-loop rows. The declared `string` is still wrong; the right type is `string | null`.
2. The citations are stale: `api.ts:602-604` is now `api.ts:1497-1511`; `runs.py:907-925` / `:920-921` is now `runs.py:1377-1395` / `:1390-1391`. A second declaration exists at `frontend/src/store/api/runs.ts:40-54`.
3. "Nothing reads those three fields today ... so nothing is broken" holds for the three FIELDS (grep of non-test `frontend/src`: only the two declarations) but no longer for the TREE: the live consumer `ArtifactVersionPicker` ignores the nesting that the wrong type hides. See [ISS-869](20261001-2106-ISS-869.md).

### Blast radius (every caller found by grep)

- `frontend/src/lib/api.ts:1497` `ArtifactNode`, `:1513` `RunArtifactsResponse`, `:1521` `getRunArtifacts`: the LIVE declaration.
- `frontend/src/store/api/runs.ts:40,56,125` duplicate declaration plus `runsApi.artifacts`: reachable only through `store/api/api.ts:22,40`, which no file imports (`grep -rn "store/api/api" frontend/src` is empty; nobody calls `runsApi.*`). Dead today, but a second hand-maintained copy.
- Consumers of the live type: `ArtifactVersionPicker.tsx` (reads `producer_agent`, `content_hash`, `id`, `kind`, `version`, `content`, but iterates only the top level, see ISS-869) and `WorkflowHistory.tsx:441` via `parseClarificationArtifacts` (reads `content` only; flat is safe because `clarifications` rows never carry `derived_from`).
- No non-test code reads `.derived_from`, `.children`, `.task_id` or `.retention` of an `ArtifactNode`.
- Stale line citations in source: `api.ts:1495` (`runs.py:590-608`), `ArtifactVersionPicker.tsx:266` and `ArtifactVersionPicker.test.tsx:29` (`runs.py:907-925`).

### Fix: accept the agreed minimal fix, with four amendments

Accepted as agreed: `task_id: string | null; derived_from: string | null; children: ArtifactNode[];` in `frontend/src/lib/api.ts`.

1. Add `retention: string` as REQUIRED, not optional: it is on every node (`runs.py:1387`, non-null column).
2. Do not retype the copy in `frontend/src/store/api/runs.ts`. Delete its local `ArtifactNode` / `RunArtifactsResponse` and re-export them with `import type` / `export type { ... } from "@/lib/api"`. Precedent: `frontend/src/store/api/admin.ts:2` (`import type { AdminUser } from "@/lib/api"`); `store/api/http.ts:14` already depends on `@/lib/api`; no boundary rule forbids it. One declaration means the drift cannot recur; "change both" would leave two copies to rot.
3. Replace the stale `runs.py:590-608` cite with the function name (`_build_lineage_tree._node` in `backend/app/api/runs.py`), which does not rot, and add one-line JSDoc on `derived_from` ("id of the version this one supersedes; may be a PARENT run's artifact and then absent from this response") and on `children` ("nested nodes derived from this one, not ids"). Same for the two `runs.py:907-925` cites.
4. Correct the fixture `frontend/src/lib/api.getRunArtifacts.test.ts:42-43` (`derived_from: []` to `null`, add `retention`).

Do NOT add a backend `response_model` or otherwise change the endpoint: the wire is the pinned contract and that would be an API change.

### Acceptance-gate caveat

`tsc --noEmit` is red at this commit: exit 1 with 13 errors in 7 unrelated test files (`AnalyticsPage`, `DashboardLayout.chain`, `WorkflowHistory.modelChip`, `PreviewPanel.liveVersion`, `AgentDetailPanel.waveWorkerStatus`, `useWorkflow.imagePayload`, `RunConnectionProvider`), none in non-test code and none naming `ArtifactNode`. "Verify with `tsc --noEmit`" therefore cannot mean exit 0. Use: no new errors versus those 13, and zero errors that mention `ArtifactNode`, `lib/api.ts` or `store/api/runs.ts`. Vitest has no `typecheck` mode here (`frontend/vitest.config.ts`), so an `expectTypeOf` test would pass vacuously; a regression test must be a type-assignment file compiled by `tsc` (for example a node literal with `task_id: null, derived_from: "a", children: [child], retention: "run_ttl"` assigned to `ArtifactNode`, run through a one-file tsconfig that extends `frontend/tsconfig.json`). It fails today on all four fields.
