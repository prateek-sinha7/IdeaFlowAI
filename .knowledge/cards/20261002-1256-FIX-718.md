# FIX-718

## What was wrong

This fix is for bug report QA-KB-056. The root cause comes from the 2026-10-02 analysis on
[ISS-791](20260922-1823-ISS-791.md) and its two siblings. I did not re-derive it.

- `build_flat_payload` re-derives every strategy's bytes from `ectx` by hand. It has to, because the finalizer
  runs in the `finally` before `final_output` is resolved.
- The `streamed_text` branch copied `ectx.last_streamed` verbatim (pre-change `engine.py:1489-1491`):
  `_raw_streamed = getattr(ectx, "last_streamed", "") or ""; if _raw_streamed: _streamed_text = _raw_streamed`.
- `StreamedTextResolver.resolve` (`streamed_text.py:50-61`) applies three transforms: `unwrap_artifact`, then
  `strip_pre_document_prose`, then `coerce_to_declared_format`. The branch applied none of them.
- So the bytes in `.chain/<name>` drifted from the deliverable the run reports, in three ways:
  - **[ISS-791](20260922-1823-ISS-791.md):** an `<artifact>` wrapper or reasoning prose ahead of the document stayed
    in the payload.
  - **[ISS-979](20261002-0409-ISS-979.md):** a composer-picked `.html` deliverable was materialized as raw markdown
    under an `.html` name.
  - **[ISS-980](20261002-0409-ISS-980.md):** the claim was tested on the RAW bytes. So a wrapper-only stream
    (`<artifact>\n</artifact>`) published `completed` and minted `v1`, although its resolved deliverable was empty.
- Every consumer of `.chain/<name>` read those bytes: the git terminal snapshot and `vN` tag, `chain_context` into a
  downstream run, the header Download, the Files-tab row and the pinned-version Preview.

## What changed, and why there

There is one change, at `backend/agents/execution_engine/engine.py:1486-1503` (working-tree line numbers). It sits in
the function every consumer above reads through. `build_flat_payload` has one production caller,
`finalize_terminal_run` (`engine.py:2335`). The consumers were not touched.

```python
try:
    _resolved = _CAPABILITY_REGISTRY.resolve(
        "deliverable", "streamed_text"
    ).resolve(ectx)
    if _resolved:
        _streamed_text = _resolved
except Exception:  # noqa: BLE001 — best-effort, falls back to unmaterialized
    logger.warning(...)
```

- **Resolver, not a two-call mirror.** The `strip_pre_document_prose(unwrap_artifact(raw))` alternative in
  `BUGS.md#qa-kb-056` would have left [ISS-979](20261002-0409-ISS-979.md) open. It would also have added a third
  hand-copied chain. The terminal block already resolves the same way (`engine.py:7830-7838`), and
  `_CAPABILITY_REGISTRY` is already a module global, so no import was added.
- **Emptiness is tested after the transforms.** That is the rule the `ppt` branch already applies.
- **Preserved:** the disk-file-wins precedence (`engine.py:1484`), the best-effort contract and the allowlist.
- **`engine.py:1623`:** a one-line comment correction. The branch now writes the *resolved* `ectx.last_streamed`.
- The other uncommitted hunks in `engine.py` belong to other sessions and were left intact. They are at `:5019`,
  `:10045` and everything after.

**Behaviour changes. Both are the point of the fix; neither is incidental.**

1. A `streamed_text` run with an `.html`/`.htm` declared name now stores the rendered HTML document in `.chain/<name>`.
   It used to store the agent's markdown.
2. A stream that resolves to empty, for example `<artifact></artifact>`, now publishes `degraded`
   (`output_unmaterializable`) with no tag. It used to publish `completed` and mint `v1`.

A `.md` deliverable with plain markdown is byte-identical, because all three transforms are no-ops for it.

## Deliberately NOT changed

- **The `ppt` branch (`engine.py:1519-1546`).** The analysis lists collapsing it onto `resolve("deliverable", "ppt")`
  as optional. Its hand-copied chain is in parity with `PptResolver.resolve` today, and no card's test needs the
  change, so it was left alone to keep the diff surgical.
- **`single_file` and `serialized_sandbox`.** Per the card, `SingleFileResolver.resolve` can write to the sandbox,
  which a finalizer must not trigger. The bundle also has to be computed before the staging dir exists.
- **[ISS-838](20260922-2024-ISS-838.md)** stays open. What remains of it is the `single_file` case, which is not on
  this path.
- **The stale `DOMAIN-deliverables-and-artifacts.md` prose** listed in [ISS-791](20260922-1823-ISS-791.md) §8. DOMAIN
  cards are hand-owned. This is reported, not edited.
