# ISS-1119

**Register source:** sibling derived during the `QA-KB-102` analysis on 2026-10-08 (root [ISS-1103](20261008-0016-ISS-1103.md)). Not its own bug row.

**Confidence:** CONFIRMED by an offline, in-process probe of the real engine (`evidence/qa-kb-102/analysis-04-silent-resume-endpoint-probe.txt`, scenario D). A real backend restart was not driven. That a deploy is what makes a persisted manifest stop compiling is INFERRED.

## Condition

The backend restarts (every deploy does) while a run is `running` or `generating` with durable step state. `restore_non_terminal_runs` branch (b) (`engine.py:12809-12910`) classifies it resumable (`_is_resumable_in_flight`, `:13036-13053`: `compile_for_run(wr.type)` succeeds and at least one durable row exists), stamps a `run_resuming` marker, and spawns `_admitted_resume`, which calls `resume_run` directly (`:12868`). For a composed run `resume_run` recompiles `workflow_runs.manifest_json` at the trust it launched with. If that no longer compiles it logs a WARNING, calls `_fire_resume_cleanup` and returns (`:15642-15653`). The other bare returns of [ISS-1103](20261008-0016-ISS-1103.md) behave the same, and `_drive_resumed_stream` swallows a pre-dispatch fault (`:16030-16031`).

## Expected vs actual

Expected: the principle `restore_non_terminal_runs` already applies to a run it cannot resume. Branch (c) (`engine.py:12911-12922`, the WR-05 message) fails the row loudly "so it is not a phantom-live row", and [DOMAIN-durable-state-resume](../architecture/DOMAIN-durable-state-resume.md) ("The abandon path") names the failure mode this avoids: "a row that looks live with no driver behind it".

Actual, from the probe (a run seeded `running`, composed, its manifest naming an unknown deliverable resolver, two `restore_non_terminal_runs` scans):

```
before  status='running'  error=None  run_events: 1:pipeline_start, 2:agent_start
scan 1  status='running'  error=None  run_events: ..., 3:run_resuming
        WARNING resume_run(..): persisted manifest failed to recompile (unknown deliverable ...) - refusing to resume with a substitute roster
scan 2  status='running'  error=None  run_events: ..., 3:run_resuming, 4:run_resuming
```

A row that reads `running`, with no driver, no error, and one more marker per restart. Nothing reconciles it. The wrapper that does (`_drive_user_resume`) is not on this path. `_apply_terminal_output_columns` "writes NO `status` / `error` ... the engine state machine on restart" (its docstring), and the state machine writes `workflow_runs.status` only on a transition (`state_machine.py:109-129`) that `_execute_impl` never reached.

The owner can end it: Stop on a run with no live driver writes `cancelled` (`run_commands.py:477-547`, ISS-089). Resuming it again meets the same wall.

INFERRED, not probed: the sandbox sweep protects every non-terminal family (the sweep loop in `app/main.py`), so a ghost row pins its sandbox for as long as it stays `running`; and the "N Running" badge counts it.

## Why the root cause implies it

Same missing failure channel ([ISS-1103](20261008-0016-ISS-1103.md)). This is the harsher case: the user-resume path at least reconciles the row to `failed`; the restart path has nothing between `resume_run` and the row.

## Fix direction (INFERRED, not applied)

The root card's engine helper must end a refused or failed auto-resume with the state machine's `failed` transition (it persists `workflow_runs.status`) plus the terminal event, as every in-engine failure branch does (`engine.py:7514`, `:7553`, `:7579`, `:7603`). A fix that only raises from `resume_run` leaves this path with an unretrieved task exception and the same `running` row. The red test is scenario D with one more assertion: after the second scan there is still one marker, not two.

## Resolution (5-fixer, QA-KB-102, 2026-10-08)

Resolved by [FIX-768](20261008-1540-FIX-768.md). The helper's state-machine `failed` transition persists `workflow_runs.status`, which ends the ghost. Scenario D after the fix: `failed`, one `pipeline_failed`, and one `run_resuming` over two scans (`evidence/qa-kb-102/fix-02-end-state-probe.txt`). The restart path still writes no `.error`: [ISS-1126](20261008-1540-ISS-1126.md).
