# ISS-1019

Adjacent to [ISS-904](20261001-2149-ISS-904.md), observed (not INFERRED): found while bounding that card's second layer (a seed the model no longer accepts).
Same commit, `b2a621f84`, whose migration 0038 made `users.cognito_sub` NOT NULL (`backend/app/models/user.py:51`), and the same family
as [ISS-891](20261001-2120-ISS-891.md), which fixed `password_hash=` in 11 files and so missed these seeds: they omit `cognito_sub` instead of passing a removed
kwarg. A different mechanism from ISS-904 (no deleted subject here; the tests are right and their seed is stale), so the disposition
is the opposite: fix the seed, keep the test.

## What happens (CONFIRMED, observed 2026-10-02, shipped working tree)

Evidence: `evidence/qa-kb-077/04-analyze-layers-under-the-guard.txt` section 6 (the scan script) and `evidence/qa-kb-077/05-analyze-sibling-probes.txt` sections 7 (the runs) and 8 (the full scan output).

## Fix direction (test-only)

As [FIX-691](20261001-2149-FIX-691.md) did: `cognito_sub=str(uuid.uuid4())` at each seed, one line per seed (or `tests/factories/user_factory.py::create_user`).
The four unit files also need the move to `tests/integration/<mirror>/` that the guard asks for (README rule 7), then a `--runxfail`
pass to see what the two race pins really say; leave their strict markers for the verifier, as FIX-691 did. Do not make `cognito_sub`
nullable and do not touch `tests/unit/conftest.py`.

## Resolution (QA-KB-077 fix, 2026-10-07)

Fixed by [FIX-736](20261007-1940-FIX-736.md) for five of the seven files. The other two are carded as
[ISS-1064](20261007-1940-ISS-1064.md).

- **Seeds.** `cognito_sub=str(uuid.uuid4())` went into the three agents-tier files (`:118`, `:101`, `:335`, `:422`). Two unit
  files were moved to `tests/integration/api/` with the seed added: `test_settings_api_key_whitespace_name_api.py` (1 passed)
  and `test_settings_github_pat_race_api.py` (`[XPASS(strict)]`; ISS-470 is resolved, and the marker is left for the verifier).
- **A layer this card did not list.** With the seed alone, `test_version_family_v5.py` (2) and `test_revision_ordinal_v3.py`
  (2) still failed, now on `published_status='degraded'`. `09270703b` made the scripted harness replace `SessionLocal` with a
  raiser by default (`offline_db=True`, `tests/agents/_scripted_model.py:931`), so `finalize_terminal_run` degrades on
  `tag_mapping_failed`. These two files seed the real hermetic DB and need the engine to see it, so their drives now pass
  `offline_db=False`, the harness's documented opt-out. Results: 2 passed and 8 passed. Evidence:
  `evidence/qa-kb-077/fix-05-layer2-offline-db-seam.txt`.
- **Still red in `test_per_run_paths_v3.py`:** one test, the `_SANDBOX` AttributeError this card already called a different
  fault. Now 1 failed, 4 passed (was 3 failed, 2 passed). Carded as [ISS-1063](20261007-1940-ISS-1063.md).
- **Not touched:** `test_admin_privilege_race.py`. Reviving it calls the real Cognito pool (`AdminListGroupsForUser` was
  observed), so it needs boto3 mocks first. Also not touched: `test_settings_preferences_race.py`, which
  [ISS-937](20261001-2231-ISS-937.md) (QA-KB-083) names in its globs; that fix must rewrite its `update_preferences` call
  sites, so the seed and the move belong in the same edit. With only the seed fixed, it passes outside the guard today.
  Both are carded as [ISS-1064](20261007-1940-ISS-1064.md).
