## What was wrong

Bug QA-KB-015, validated 3/3 (`evidence/qa-kb-015/01..06`): on `/settings/profile`, typing into
"Current password" and clicking the header Back button went straight to `/dashboard` with no
dialog, and the typed value was gone on return. The same exit also dropped an unsaved model pick
and, per [ISS-921](20261001-2222-ISS-921.md), an unsaved Constitution draft.

## Root cause (from [ISS-372](20260828-2141-ISS-372.md), re-checked before editing)

The guard existed and worked; AccountSettings never fed it.

- `frontend/src/components/layout/DashboardLayout.tsx:1875-1880`: `handleBackNav` opens the
  in-app "Leave without saving?" dialog only `if (hasUnsavedWork.current)`, and
  `hasUnsavedWork` is written only by `handleUnsavedChange` (`:1847-1850`).
- `frontend/src/components/settings/AccountSettings.tsx` (HEAD `:30-47,87`): the props were
  `{ onBack, initialSection }`; nothing ever reported dirty state.
- `DashboardLayout.tsx:3117` (the only mount) passed `initialSection` and `onBack` only.

Blast radius re-checked: `AccountSettings` has one mount (`DashboardLayout.tsx:3117`); its other
importers (`AppHeader.tsx:29`, `app/[...view]/page.tsx:26`) import only the `SettingsSection` type.

## What changed, and why there

The wiring belongs on the page: only the page knows its own dirty state, and the shared handler
and dialog already exist. `handleBackNav` and the dialog are untouched (FIX-352's locked
constraint), and no `confirm(` was added (S-19-17).

1. `AccountSettings.tsx:47-49,90` — optional `onUnsavedChange?: (dirty: boolean) => void` prop,
   destructured.
2. `AccountSettings.tsx:124-137` — `hasUnsavedWork` = any password field non-empty, or
   `pendingModel !== selectedModel`, or `constitutionDirty`; reported by
   `useEffect(() => { onUnsavedChange?.(hasUnsavedWork); return () => onUnsavedChange?.(false); }, ...)`,
   the same reporter shape as `ComposerPage.tsx:374-379` and `IdeaInputPage.tsx:1027-1030`. No
   baseline ref is needed: each value is compared with what is saved, and the async loads set both
   sides in the same update (`:169-170` model, ConstitutionSection's `.then` for the draft).
3. [ISS-921](20261001-2222-ISS-921.md) trap 1 — `constitutionDirty` compares TRIMMED values
   (`:129`), because Save stores `content.trim()` as the loaded value (`:654`) and leaves the draft
   untrimmed. The ISS-482 tab guard (`:273`) now reads the same `constitutionDirty`, so it no longer
   misfires after saving a draft with surrounding whitespace.
4. [ISS-921](20261001-2222-ISS-921.md) trap 2 — `commitDiscardConstitution` (`:139-147`) resets
   the draft with `setConstitutionContent(constitutionLoadedValue)`, so Back after "Discard" does
   not ask about a draft the user already threw away.
5. `DashboardLayout.tsx:3117` — `onUnsavedChange={handleUnsavedChange}` on the mount.

The other `DashboardLayout.tsx` hunk in the working tree (`:3162`, IdeaInputPage) is
[FIX-702](20261002-0040-FIX-702.md)'s, not this fix's.
