## Analysis addendum (QA-KB-086, 2026-10-02)

Read this before "Why". The red and the test-only fix stand. One sentence in "Why" is true only for this test, and it changes how the fix
should be worded.

**Re-measured.** Same failure on the working tree: `designPicker.test.tsx:159:25`, 1 failed | 1 passed
(`evidence/qa-kb-086/01-analyze-vitest-red.txt`). The test was authored in `1e329e47b`, which does not contain `3de9d05b2`, and
`3de9d05b2` does not contain it; both are ancestors of HEAD (`evidence/qa-kb-086/08-analyze-code-quotes.txt`, git facts).

**What "Why" leaves out.** "`onRun` always gets `gate_agent_ids: []`" and "The app does what `602296cc8` says it should" hold only while
`ReviewGatesSection` is mocked inert, as it is here. With the real section mounted, the section reports `([], false)` on mount
(`ReviewGatesSection.tsx:110`, `:173-178`, pinned by `ReviewGatesSection.test.tsx:128-135`), `handleGatesChange`
(`IdeaInputPage.tsx:1040-1042`) stores it over the page default, and an untouched Run sends no `gate_agent_ids` at all. Probe with the real
section: `extraParams` is `undefined` untouched, and `{ gate_agent_ids: ["reading-planner"], ... }` after ticking one gate
(`evidence/qa-kb-086/05-analyze-probe-observed-output.txt`). So the `:159` assertion describes what the real page does; it fails only because
the mock removes the thing that overwrites the default. The wizard behaves the same way ([ISS-1035](20261002-1058-ISS-1035.md)).

**What that changes about the fix.**

- Keep it test-only and make it take no side. Replace `:159` with `expect(extraParams ?? {}).not.toHaveProperty("template_id");` and
  `expect(extraParams ?? {}).not.toHaveProperty("design_system_id");`. Do not use `toEqual({ gate_agent_ids: [] })`: it would add a fourth
  test pinning a payload the real UI never sends. Both forms pass on a scratch copy
  (`evidence/qa-kb-086/06-analyze-proposed-fix-validation.txt`).
- Do not rewrite the comment at `IdeaInputPage.tsx:1034-1038` ("Untouched ⇒ we omit `gate_agent_ids`") in this fix. It describes the real
  runtime; only the initial `touched: true` literal under it contradicts it. That is the open decision on
  [ISS-1034](20261002-1058-ISS-1034.md).
- Test-side blast radius: this is the only test in `frontend/src` that asserts `extraParams` is undefined. The three that read the same
  argument (`IdeaInputPage.selections`, `.modelOverrides`, `.imageInput`) were updated for the default flip and are green.

## What is red

`frontend/src/components/workflow/IdeaInputPage.designPicker.test.tsx`, test "does not offer the picker for a workflow
that never declares opendesign", fails at `:159` (`expect(extraParams).toBeUndefined();`) with
`AssertionError: expected { gate_agent_ids: [] } to be undefined`. The file reads 1 failed | 1 passed.

Measured 2026-10-02 by the QA-KB-014 fixer on the working tree and again against HEAD `024c03ef8`'s
`IdeaInputPage.tsx`, with the same result (`evidence/qa-kb-014/10-fix-neighbour-tests.txt`).
[FIX-614](20260922-1850-FIX-614.md) (2026-09-22) and [FIX-698](20261001-2237-FIX-698.md) already met it and called it
pre-existing, but nobody carded it, so every fixer touching IdeaInputPage re-measures it.

## Why

- The test mocks `./ReviewGatesSection` to `() => null` (`designPicker.test.tsx:46-47`). The section never reports
  through `onChange`, so `handleRun` sends the page's own default.
- That default is `gateSelectionRef = useRef({ ids: [], touched: true })` (`IdeaInputPage.tsx:1039`). "Touched" means
  "send the explicit array", so `extraParams` is `{ gate_agent_ids: [] }`.
- The default became `touched: true` in `602296cc8` / `3de9d05b2` (2026-08-28, "feat: remove prototype review gate
  defaults — user opts in explicitly"), whose message says "LaunchWizard/IdeaInputPage: always send gate_agent_ids
  (touched=true) so an empty selection is explicit, not absent".
- The test was written in `1e329e47b` (2026-09-04) against a copy where the default was still `touched: false`
  (`git show 1e329e47b:frontend/src/components/workflow/IdeaInputPage.tsx`, line 972). There `extraParams` was
  undefined. It went red when the two lines of history met.

The app does what `602296cc8` says it should. The assertion is stale. The comment above the ref
(`IdeaInputPage.tsx:1034-1038`, "Untouched ⇒ we omit `gate_agent_ids`") describes the old default too.

## Disposition

Open. This needs a test-only change, outside FIX-702's card. Keep what the test is for, which is that no `template_id` or
`design_system_id` goes out without opendesign, and stop asserting the gate payload. For example, assert
`extraParams ?? {}` has neither property, or assert `toEqual({ gate_agent_ids: [] })`. Flipping the app default back
to `touched: false` would undo `602296cc8`. If the product owner wants gates omitted while the control is untouched,
that is a product decision and does not belong in a test fix.

## Resolution (QA-KB-086 fix, 2026-10-07)

Fixed test-only by [FIX-740](20261007-2008-FIX-740.md), in the form the addendum above prescribes. In
`IdeaInputPage.designPicker.test.tsx`, `expect(extraParams).toBeUndefined();` (`:161` after the test-writer's `it.fails` lines)
became `expect(extraParams ?? {}).not.toHaveProperty("template_id");` and `...("design_system_id");`. `IdeaInputPage.tsx` is
unchanged, and so is its comment (now `:1043-1047`). The file went from `1 passed | 1 expected fail` to `1 passed | 1 failed`
with "Expect test to fail" ([XPASS(strict)]), and the `it.fails` marker is left for the verifier. Scratch probes: the fixed body
alone gives `2 passed`, and each new line goes red against a page mutant that leaks its param (`evidence/qa-kb-086/fix-0*`).
[ISS-1034](20261002-1058-ISS-1034.md) and [ISS-1035](20261002-1058-ISS-1035.md) stay open. This fix does not decide them.
