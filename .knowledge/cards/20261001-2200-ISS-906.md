# ISS-906

Found while recording golden coverage for the QA-KB-007 fix ([FIX-692](20261001-2200-FIX-692.md)).
[FIX-688](20261001-2140-FIX-688.md) hit the same two failures earlier the same day and recorded them as unrelated, without a card.

## Condition

`backend/tests/contract/agents/test_characterization_app_builder.py` fails 2 of 2, and both failures are one diff:

- `test_app_builder_deliverable_byte_snapshot`: "app_builder.txt: deliverable bytes diverged from the committed
  golden (len now=88, golden=120)", the SAFE-01 byte tripwire.
- `test_app_builder_event_snapshot`: "app_builder normalized event stream diverged from the committed golden"
  (SAFE-02). First diff at index 95, the `pipeline_complete` frame: its `final_output` lacks the golden's leading
  `filename: .family.lock` block. Both sides carry `status: degraded`; `assert_seq_contiguous` passes before it.

## Cause

- `backend/tests/agents/characterization/golden/app_builder.txt` opens with a `.family.lock` file block, and
  `app_builder.events.json` / `app_builder.wsframes.json` carry the same `final_output`. All three were last written
  at `e7305f9dd` (2026-09-10, sandbox-git-versioning-v2).
- `backend/app/agents/sandbox.py:68` lists `".family.lock",  # revision-family lock file (family_lock_path) — engine
  plumbing` among the files never served as a deliverable. That line arrived in `f9df3737c` (2026-09-29, "feat(workspace):
  list and serve every sandbox file; 64 MB read cap"; [FIX-647](20260929-1024-FIX-647.md): "`.family.lock` is never a deliverable"),
  which did not regenerate the goldens.
- `git merge-base --is-ancestor`: `e7305f9dd` precedes `f9df3737c`, an ancestor of HEAD `024c03ef8`. Neither the
  goldens nor `sandbox.py` is modified in the working tree, so the file is red at HEAD and no uncommitted fix
  caused it.

Impact: the app_builder SAFE-01 / SAFE-02 tripwires are permanently red, so a real app_builder deliverable or
event-stream regression is masked by a known failure.

## Disposition

Open. Fix shape: regenerate with `SNAPSHOT_UPDATE=1` and review that the only diff is the dropped `.family.lock`
block in `app_builder.txt`, `app_builder.events.json` and `app_builder.wsframes.json`. Not done here: the QA-KB-007
dispatch confines its fixer to `append_event_at_or_after`.

Evidence: `evidence/qa-kb-007/05-fix-tests-and-constraint-checks.txt` (golden runs, failure lines, the probe showing the QA-KB-007 change never ran in this test).

## Analysis (2026-10-02, bug QA-KB-078)

The root cause above holds: **CONFIRMED**, re-read and re-run in this tree (`feat/user-stories-v2` @ `024c03ef8`). The
original text is left as written; what it missed or got slightly wrong is recorded here.

**Mechanism, end to end.**

1. At sandbox open, `engine.py:4461` runs `with _family_lock(disk_principal, _chain_root_id):` for every git-enabled
   sandbox. `sandbox.py:505` (`os.open(str(lock_path), os.O_CREAT | os.O_RDWR, 0o600)`) creates an empty `.family.lock` at
   the path built in `sandbox.py:411`, which is the same directory as `RunSandbox.root` (`sandbox.py:602`). A probe of
   `_drive("app_builder")` saw exactly one `family_lock` caller (`engine.py:4461`) and a 0-byte `.family.lock` next to
   `README.md`, `src/app.py`, `.gitignore` and `PLANNER.md`.
2. The deliverable resolver reaches the walk through `serialized_sandbox.py:49-50` into `serialize_sandbox_deliverable`
   (`sandbox.py:1627`). Before `f9df3737c` the walk emitted that empty file as a `filename: .family.lock` block. Now
   `is_deliverable_relpath` returns False for it (`sandbox.py:1580`, exclude set from `:68`) and
   `_collect_deliverable_relpaths` skips it (`sandbox.py:1620`).
3. The product side is deliberate and pinned, so this is not a product question and needs no escalation:
   [FIX-647](20260929-1024-FIX-647.md) carries the locked constraint ".family.lock is never a deliverable";
   `backend/tests/unit/agents/test_sandbox_deliverable.py:205` (`test_family_lock_is_never_a_deliverable`) passes; and
   `DOMAIN-workspace-isolation` says `.family.lock` is "excluded from the deliverable walk and from `WorkflowRun.output`".
   The goldens recorded a leak, not a decision. The earlier blanket sign-off (B7, 2026-09-14, "all 11 re-pinned goldens",
   `specs/019-sandbox-git-versioning/bugs/GIT_VERSIONING_BUGS.md:42`) predates FIX-647 and its recorded summary never
   mentions `.family.lock`.

**Corrections to the Cause section above.**

- Only `app_builder.txt` was last written at `e7305f9dd` (2026-09-10). `app_builder.events.json` and
  `app_builder.wsframes.json` were last written at `bd3ca6e68` (2026-09-12, "test(golden): re-pin characterization snapshots
  after the context change"; its message says the diffs were not yet human-reviewed). `git merge-base --is-ancestor`
  confirms `e7305f9dd` < `bd3ca6e68` < `f9df3737c` < HEAD, so all three still predate `f9df3737c`, whose file list names no
  golden.
- "Both tests" understates the blast radius. A third test, [ISS-1014](20261002-0605-ISS-1014.md)
  (`tests/integration/agents/test_wire_parity.py::test_wire_parity_matches_golden[app_builder]`), fails on the same payload,
  and the fix shape above would not repair it: `app_builder.wsframes.json` is written only by
  `test_wire_parity.py::_record_golden`, not by `test_characterization_app_builder.py`.

**Fix scope, verified read-only (nothing was written into the repo).** The exact serialisation `SNAPSHOT_UPDATE=1` uses
was re-derived and diffed against the three committed goldens. `app_builder.txt`: 120 -> 88 bytes, one hunk, the first four
lines (the block, its empty body and the blank line). `app_builder.events.json` (29523 -> 29487 bytes) and
`app_builder.wsframes.json` (34423 -> 34387 bytes): one line each, `:1013` and `:1204`; parsed, exactly one leaf differs,
`$[95].data.final_output`, in each of the 100-event streams. So "the only diff is the dropped `.family.lock` block" is true.
Two scoped invocations regenerate all three:

    cd backend
    SNAPSHOT_UPDATE=1 .venv/bin/python -m pytest tests/contract/agents/test_characterization_app_builder.py -p no:cacheprovider
    SNAPSHOT_UPDATE=1 .venv/bin/python -m pytest tests/integration/agents/test_wire_parity.py -k app_builder -p no:cacheprovider

then both again with `SNAPSHOT_UPDATE` unset (expect 2 passed and 5 passed).

**What a naive fix breaks.**

- Reverting `sandbox.py:68` re-opens the leak [FIX-647](20260929-1024-FIX-647.md) closed and fails
  `test_family_lock_is_never_a_deliverable`.
- `SNAPSHOT_UPDATE=1` over the golden directory, or over `tests/agents`, also rewrites `prototype.events.json` and
  `prototype.wsframes.json` (carrying another session's uncommitted `output_length` edit at analysis time) and would bless
  the unrelated drift in [ISS-1015](20261002-0605-ISS-1015.md) without review.
- Leaving `SNAPSHOT_UPDATE` exported: `backend/tests/agents/test_phase7_seam2_removal.py:710`
  (`test_snapshot_update_is_not_set`) fails by design, and `.github/workflows/ci.yml:300` sets `SNAPSHOT_UPDATE: ""` and
  hashes the golden tree before (`:324`) and after (`:355`) the offline partition, so goldens must be committed, never
  regenerated in CI.

## Resolution — FIX-735 (2026-10-07)

Resolved by [FIX-735](20261007-1927-FIX-735.md). Only test data changed, and `sandbox.py` was not edited. `app_builder.txt`
and `app_builder.events.json` were regenerated with `SNAPSHOT_UPDATE=1` on `test_characterization_app_builder.py`, and
`app_builder.wsframes.json` through [ISS-1014](20261002-0605-ISS-1014.md)'s scoped wire-parity invocation. Each diff
is exactly what this card predicted. `app_builder.txt` went from 120 to 88 bytes, losing its first four lines. Each JSON
file changed on one line (`:1013` and `:1204`), and parsed, only the leaf `$[95].data.final_output` differs. The file
now reports 2 failed as `[XPASS(strict)] ISS-906 unfixed`; with `--runxfail` it reports 2 passed. The marker is left for
the 6-verifier. Evidence: `evidence/qa-kb-078/fix-01`, `fix-02`, `fix-05`, `fix-09`, `fix-12`.
