# ADR-0019

## Decision

In the context of session expiry being handled ad hoc at each network call site, facing
nine or more separate instance-level gaps found one at a time across multiple independent
verification passes, we decided to centralise it in a single guarded wrapper —
`authedFetch()` — to achieve the behaviour structurally, accepting that a new call site
using a bare `fetch` silently reopens the hole.

**Area:** frontend, auth

## Why this is recorded as a decision rather than a fix

The instance-by-instance approach did not fail once; it failed repeatedly, and each
verification pass rediscovered the SAME defect class at a new call site. That pattern —
independent checks converging on one recurring shape — is the signal that the fix belongs
at the boundary rather than at the symptom. The card exists so the next person adding a
network call knows the wrapper is the contract, not a convenience.
