## Symptom

The Steps tab showed no indication of which model an agent was using. Nothing
appeared while the agent ran; the information only became available once the run
had finished.

## Root cause

`ExecutionEngine` called `_resolve_model` **after** yielding `agent_start`, so
the resolved `model_id` was only ever attached to `agent_complete`. A running
agent therefore had no model to display, and the frontend carried no field for
it at all.

## Fix

Backend — `backend/agents/execution_engine/engine.py`: call `_resolve_model`
before the `agent_start` yield so `model_id` is emitted on `agent_start` as well
as `agent_complete`.

Frontend:

- `hooks/useWorkflow.ts` — write `modelId` from both `agent_start` and
  `agent_complete` events.
- `components/results/AgentDetailPanel.tsx` — `MODEL_LABELS` map,
  `resolveModelLabel()`, and the chip render.
- `components/history/WorkflowHistory.tsx` — thread `model_id` through
  `detailAgentOutputs` / `thinkingAgents` so a reopened historical run shows the
  chip too.
- `types/index.ts` — `AgentRunState.modelId`.
- `lib/api.ts` — `RunSummaryAgent.model_id`.

## INV-3

`model_id` is already in `_VOLATILE_STRIP_KEYS`, so emitting it one event earlier
does not change any characterization golden. Confirmed unchanged.
