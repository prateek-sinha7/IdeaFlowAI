# ISS-1197

**INFERRED** inverse of [ISS-1195](20261012-0942-ISS-1195.md) (register entry `QA-KB-117`). The grid tiles are on the validator's screenshot; the catalog side is read from code and manifests, no screenshot shows the collapsed Coming Soon section.

## Condition

An enterprise account (the only tier entitled to these ids) opening `/settings/usage`.

## Expected vs actual

Expected: Deliverable access names only what the plan can actually run, as the home catalog does. Actual: three tiles carry a green check that the catalog contradicts.

| grid tile | id | what the catalog does with it |
|---|---|---|
| Mulesoft Migration | `mulesoft_to_springboot` | `user_launchable: true`, `is_beta: true` (`backend/agents/workflows/mulesoft_to_springboot/workflow.yaml:3-4`): under the collapsed "Coming Soon", "not yet available on any plan", never actionable (`HomeLaunchGrid.tsx:292, 304-306, 403-418`) |
| .NET Migration | `dotnet_to_azure` | same, `dotnet_to_azure/workflow.yaml:3-4` |
| Platform Workflows | `migration` | no manifest, so absent from `GET /api/workflows` and from the catalog; the only card for it is in `CreationHub.tsx:21`, which is not mounted (`DashboardLayout.tsx:3005-3008` says the hard-coded `CreationHub.WORKFLOWS` array no longer drives the home); `entitlements.ts:69-75` calls it "a UI meta-grouping, not a launchable pipeline" |

## Why the root cause implies it

The grid is a hand-kept projection, so it can disagree in both directions. `AccountSettings.tsx:87` keeps any entitled id that has a `PIPELINE_DISPLAY` key (`:65-74`) and never asks whether the catalog enables it (`user_launchable` and not `is_beta`). The offline projection reports, for enterprise, "grid lists, catalog does not enable: dotnet_to_azure, migration, mulesoft_to_springboot" (`evidence/qa-kb-117/analysis-projection.out.txt`). Screenshot `evidence/qa-kb-117/04-validate-attempt2-usage-omits-branch.png` shows all three tiles with checks.

## Open question (not for this card to decide)

Whether the plan page should advertise Coming Soon capabilities is a product call. A fully catalog-driven grid (ISS-1195, full option) drops all three tiles; the examples-only fix leaves them. If they go, update the expected enterprise list in `tests/integration/screens/17-theme-and-tiers.feature.md:84-87`.

## What would settle it

The catalog's Coming Soon summary on `/dashboard` as enterprise ("N not yet available on any plan") listing "MuleSoft to Spring Boot" and ".NET to Azure", read next to `/settings/usage` listing them as access.

## Fix (FIX-785, 5-fixer, 2026-10-12)

Resolved by the shared derivation in [FIX-785](20261012-1013-FIX-785.md) (`splitCatalog` / `catalogAccess` in `frontend/src/lib/entitlements.ts`). The grid lists only rows the catalog enables (`user_launchable` and not `is_beta`, through `catalogAccess`). Mulesoft Migration and .NET Migration (beta) and Platform Workflows (no manifest) are no longer listed as Enterprise access. `17-theme-and-tiers.feature.md`'s per-tier paragraph was rewritten to match. Case `ISS-1197` now reports "Expect test to fail" (XPASS). Raw output: `evidence/qa-kb-117/fix-01-vitest-runs.txt`.
