## What was wrong

`BUG-20260828-054500-create-user-stories`: on `/create/user-stories`, opening Advanced -> Agents
-> "+ Add agent" opened `AgentLibrary` already defaulted to the **User Stories** category tab,
which rendered "No agents found" immediately, with or without a search term. Every other tab was
populated. That copy reads as "this category has no agents at all", which is false — the category
holds 6 agents and all 6 are already on the canvas.

## Root cause

`frontend/src/components/workflow/AgentLibrary.tsx`

- `:86` — `const [activeCategory, setActiveCategory] = useState(currentPipelineType || "all")`
  defaults the dialog to the current pipeline's own category.
- `:104-117` (pre-fix) — one `ALL_AGENTS.filter` fused five gates, including
  `notAlreadyAdded = isCustomAgentTemplate(agent) || !existingAgentIds.includes(agent.id)`.
- `:229-232` (pre-fix) — the empty state was unconditional: `filteredAgents.length === 0`
  rendered the literal `"No agents found"`.

Both hosts that pass a real `currentPipelineType` seed the canvas from 100% of that type's own
catalog on a fresh load (`IdeaInputPage.tsx:902`, `LaunchWizard.tsx:147-148`), so
`existingAgentIds` already contains every agent the defaulted tab could offer. The tab is empty
by construction — correct behaviour (you cannot re-add an agent already on the canvas) reported
through the wrong message, because the fused filter left no way to tell "this category holds
nothing" from "this category is fully added".

## What changed and why there

One file, in the shared component all 4 call sites route through (`app/workflow/page.tsx:67`,
`WorkflowView.tsx:556`, `composer/ComposerPage.tsx:1401`, `AgentsPopup.tsx:2697`) — not in any
host, so it closes the defect for every pipeline type and both affected hosts at once.

1. Split the fused filter in two: `categoryAgents` applies category / search / `notHidden` /
   `templateAllowed`; `filteredAgents` then drops the `existingAgentIds` members off that result.
   Same predicates, same order, same rendered list — the split only exposes the count the empty
   state needs. The `templateAllowed` and category-count source lines pinned by
   `overrideAgentPool.source.test.ts` are preserved verbatim.
2. `allAlreadyAdded = filteredAgents.length === 0 && categoryAgents.length > 0` drives
   `emptyMessage`: `All <Category> agents are already on your canvas` (label from `CATEGORIES`,
   omitted on the "All" tab -> "All agents are already on your canvas"), falling back to the
   original `"No agents found"` for a category that genuinely holds nothing.

Deliberately NOT changed: the `:86` default-category line. Re-defaulting to "All" would hide the
correctly-highlighted own-category tab and would not fix the message itself.
[ISS-420](20260829-0021-ISS-420.md) — an unrecognized `currentPipelineType` such as `"migration"`
highlighting no tab at all — still needs that line guarded and stays open; this card does not
resolve it.
