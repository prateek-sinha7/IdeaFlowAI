## What changed

The listing now classifies every file (`text` / `image` / `pdf` / `binary`) and
flags whether it is a deliverable, so the client renders images and PDFs inline
instead of offering only a download, and can group without a second copy of the
exclude list.

## Why the predicate is shared

`_collect_deliverable_relpaths` and the API listing were two answers to the same
question. A copy of `_DELIVERABLE_EXCLUDE` on the client would drift the moment
the backend added an entry — the workspace would keep advertising a file the
deliverable walk had already stopped counting.
