# FIX-775

Bug report QA-KB-125 (High, security). The root cause, blast radius and fix direction come from the root card
[ISS-1067](20261007-2030-ISS-1067.md) and its three siblings [ISS-1160](20261009-1553-ISS-1160.md),
[ISS-1161](20261009-1553-ISS-1161.md) and [ISS-1162](20261009-1553-ISS-1162.md). They are not re-derived here. This is
one coherent fix with one mechanism: no single place decided how agent-authored HTML is framed or opened, so each viewer
typed its own sandbox string and each "Open in new tab" hand-rolled `new Blob` + `URL.createObjectURL` + `window.open`.

## What was wrong (pre-fix HEAD 01777a107)

- **ISS-1067.** `PrototypePreview.tsx` built a `blob:` URL of the agent HTML (`:356-365`), framed it with
  `sandbox="allow-scripts allow-same-origin"` (`:610`), and `handleOpenInNewTab` called `window.open(blobUrl, "_blank")`
  (`:389`). A blob URL carries its creator's origin, so the agent script ran on the app origin and could read
  `localStorage.auth_token`. The validator drove it 3 of 3 on run `4f3ebe40-8384-467c-9255-322eaf0fc183`.
- **ISS-1160.** `PPTPreview.tsx:33` fixed `isOdPpt = true`, so the deck iframe was always a same-origin srcdoc
  (`:252`), and `PreviewPanel.tsx:246-248` sent any `presentation.html` generic deliverable into it, around the T-18-05
  sandbox.
- **ISS-1161.** Four more top-level blob openers: `PreviewPanel.tsx` `handlePreviewOpen` (HTML included) and
  `PPTTabActions.handleFullScreen`, the History "Full Screen" button (`WorkflowHistory.tsx:1003-1008`), and a dead
  `PPTPreview.handleOpenFullScreen` (`:208-213`).
- **ISS-1162.** A srcdoc document resolves `#fragment` links against the parent URL, and a blob frame without
  `allow-same-origin` ignores hash navigation. That is why `allow-same-origin` was put back in May (`77228e567`).

## What changed, and why there

1. **New `frontend/src/lib/agentHtml.ts`**, the one place every caller routes through:
   `AGENT_HTML_SANDBOX = "allow-scripts"`; `frameableAgentHtml(html)` inserts `<base href="about:srcdoc">` right after
   `<head ...>`, else after `<html ...>`, else after the doctype (never before it, which would force quirks mode), else
   first; it is idempotent. `openAgentHtmlInNewTab(html)` writes the wrapper the analysis measured (probe variant G2,
   `evidence/qa-kb-125/analysis-3-wrapper-probe.txt`): no script of its own, one `<iframe sandbox="allow-scripts"
   srcdoc="...">` whose value escapes `&` then `"` (the probe's `esc_attr`), opened `noopener,noreferrer`, revoked after
   5 s like the openers it replaces.
2. **`PrototypePreview.tsx`.** The blob state and effect became a `frame` state `{ key, srcDoc }` set in the same effect.
   The key is a counter, so every Tweaks rebuild remounts the iframe as `key={blobUrl}` did. This follows the card's
   constraint that Chrome blanks a frame whose srcdoc is rewritten after mount. The iframe is `srcDoc={frame.srcDoc}`
   with `sandbox={AGENT_HTML_SANDBOX}` (`:602-609`); the dead `iframeRef` is gone; Open calls
   `openAgentHtmlInNewTab(frame.srcDoc)` (`:387`).
3. **`PPTPreview.tsx`.** `isOdPpt`, its comment and every ternary on it (sandbox, style, className, the ref-callback
   guard) are deleted; the iframe is `srcDoc={frameableAgentHtml(htmlContent)}` with the constant (`:239-241`). The dead
   `handleOpenFullScreen` is deleted. `presentation.html` from the generic path is therefore sandboxed too, with no
   `PreviewPanel` change needed for ISS-1160.
4. **`PreviewPanel.tsx`.** The generic `text/html` iframe frames `frameableAgentHtml(withDarkIframeDefault(...))` with
   the constant (`:276-279`), so the base precedes the dark default style. `handlePreviewOpen` sends `text/html` through
   the helper (`:1598-1601`); other types keep the plain blob (`:1602-1605`, see
   [ISS-1172](20261009-1625-ISS-1172.md)). `PPTTabActions.handleFullScreen` calls the helper (`:2187`). The T-18-05
   header comment no longer cites the dead "PPTPreview non-od_ppt pattern".
5. **`WorkflowHistory.tsx`.** The History "Full Screen" button calls the helper (`:1005`); the generic HTML reopen
   iframe frames `frameableAgentHtml(selectedOutput)` with the constant (`:1081-1084`).
6. **`SandboxTab.tsx`.** The workspace HTML preview frames `frameableAgentHtml(stripStaticPreviewFallback(content))` with
   the constant (`:1654-1656`), for ISS-1162.
7. **`frontend/eslint-suppressions.json`.** PPTPreview `@typescript-eslint/no-unused-vars` count 5 → 4. The deleted dead
   handler was one of the five suppressed unused variables. Left unpruned, `npx eslint
   src/components/preview/PPTPreview.tsx` exits 2 ("There are suppressions left that do not occur anymore"); pruned, it
   exits 0, as it did at HEAD.
8. **New `frontend/src/lib/agentHtml.test.ts`, written by the fixer.** The card's Fix section lists the source guard as
   part of the fix, and its test notes 4 and 5 (and ISS-1162's) ask for helper unit tests. The test-writer wrote only
   `PrototypePreview.sandbox.test.tsx`. Three helper cases cover base placement (`<head>`, `<html>` without `<head>`,
   doctype only, bare fragment, `<header>` not mistaken for `<head>`) and idempotence. One wrapper case parses the blob
   and checks one iframe with the exact sandbox, an srcdoc that round-trips to the framed agent HTML byte for byte, no
   `<script>` element, and `noopener,noreferrer`. Two guard cases read every non-test `.ts`/`.tsx` under
   `frontend/src` with comments stripped: no `allow-same-origin` outside `DesignSystemDetailModal.tsx`, and no file that
   creates blob URLs calls `window.open` more often than an explicit allowance.

Deliberately not changed:

- `DesignSystemDetailModal.tsx:218` keeps `allow-same-origin` and its `window.open` (`:100`). The ISS-1067 analysis
  classes that frame as repo-owned content (the static `components.html`, or `generateDesignSystemPreviewHtml`, which
  emits no `<script>`), so it is hardening, not a live exposure. The guard allow-lists it with that reason.
- The template galleries (`TemplateCard.tsx:123`, `TemplateGallery.tsx:520`, `TemplateDetailModal.tsx:159`,
  `PPTTemplateGallery.tsx:357,468`) keep the literal `sandbox="allow-scripts"`. They are already opaque and frame repo
  templates; the card's "one spelling" switch would be a no-behaviour edit, and the guard already fails any of them that
  gains `allow-same-origin`.
- `backend/app/run_files.py:752` says the deck preview's srcdoc "is sandboxed". The card flagged that as false for
  PPTPreview until the fix; it is true now, so no edit.
- [ISS-1066](20261007-2030-ISS-1066.md) (`live-dashboard/assets/template.html:413`, unguarded `localStorage`) is a
  skill/template file, the owner's to edit, so it is untouched. Now that the in-app prototype preview is an opaque
  origin, a prototype seeded from that template aborts its init script in-app as well as on the share link. **Flag to
  the owner.**
- SC-001: the helper takes HTML and knows no workflow name; dispatch stays on `mimetype` and `filename`. No route, no
  backend file and no migration changed.

## What the 6-verifier has to see in real Chrome (jsdom cannot)

No backend file changed, so no restart is needed; the Next dev server on :3000 hot-reloads the frontend. The
behavioural check is the one the card names. On completed run `4f3ebe40-8384-467c-9255-322eaf0fc183` Preview, the
`Prototype Preview` iframe has `sandbox="allow-scripts"`, a `srcdoc` and no `blob:` `src`, and
`iframe.contentWindow.localStorage` throws. Hash routing inside the prototype still works. "Open in new tab" gives a
tab whose top-level document is the wrapper with no script of its own; the inner frame's origin is `null` and
`window.opener` is `null`. Run `0f62f7bc-d3a2-4748-8004-0b534e1741ae` (generic renderer) is the control.

Not measured: Firefox and Safari (the `about:srcdoc` base, and a `noopener` blob tab). Known cost (ISS-1162 caveat): in
deck, generic and workspace frames, relative and protocol-relative URLs inside agent HTML no longer resolve against the
app URL. The prototype blob frame already behaved that way.
