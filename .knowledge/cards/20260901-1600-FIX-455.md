## What was wrong

`AgentThinkingTab.tsx:84–85` declared `selectedAgentId` and `selectedTaskIndex` as plain `useState`. Every writer — `onOpenAgent` (`:295`), `onOpenTask` (`:282`), and the two `onBack` resets — touched only component state:

```tsx
onOpenAgent={(id) => { setSelectedAgentId(id); setSelectedTaskIndex(null); }}
```

No `router.push`, no `window.history.pushState`. Because no browser history entry was created on agent/task selection, pressing Back after drilling into an agent did not return to the overview spine — it navigated to whatever page or route preceded the Steps tab being opened, skipping the Steps level the user was just at.

## Root cause

`selectedAgentId`/`selectedTaskIndex` were pure in-memory component state — the same mechanism ISS-277 already named for the out-direction (shareability). This card records the distinct, independently-observable consequence: Back-button semantics.

## What changed and why there

Added `useSafeRouter` and `useSafePathname` helper hooks at module level to safely wrap Next.js navigation hooks that throw when no App Router is mounted (unit test contexts):

```ts
function useSafeRouter(): { push: (url: string) => void; back: () => void } {
  try {
    return useRouter(); // eslint-disable-line react-hooks/rules-of-hooks
  } catch {
    return { push: () => {}, back: () => {} };
  }
}
```

Inside the component, `onOpenAgent` now pushes a shallow URL with an `?agent=<id>` query param:

```tsx
onOpenAgent={(id) => {
  setSelectedAgentId(id);
  setSelectedTaskIndex(null);
  router.push(`${pathname}?agent=${encodeURIComponent(id)}`);
}}
```

`onOpenTask` similarly pushes `?agent=<id>&task=<i>`. Both `onBack` handlers call `router.back()` so the browser history entry is consumed correctly.

The query params are shallow history hints — `AgentThinkingTab` does not parse them back on render (ISS-277 owns the parse path). They exist solely to create a distinct history entry so Back works.
