# ISS-143

## Title

**The header "N Running" pill goes stale after a live cancel.** `AppHeader.tsx` derives the pill from `recentRuns` (`LIVE_STATUSES.has(r.status)`, which includes `waiting_for_user`), and `recentRuns` is refreshed by `getWorkflows(...)` at many call sites in `page.tsx` — but there is **NO refresh in the `pipeline_cancelled`/`pipeline_failed` handling arm**, and no polling timer. So after a cancel the pill keeps counting the just-cancelled run as "Running" until the next unrelated `recentRuns` refresh or a page reload. **Confirmed independent of the clarify-repaint defect FIX-247 fixes:** it reproduces identically on a clean review-gate cancel — the GATEPROBE control run in that same task showed a stale "2 Running"/"3 Running" pill even though that run's lane correctly repainted to Cancelled. **Fix shape:** add a `getWorkflows(...)` -> `setRecentRuns(...)` refresh call to the cancelled arm, mirroring the pattern already used at other `page.tsx` call sites (e.g. `page.tsx:1170-1186`).
