# FIX-524

## What was wrong

Register bug **QA-PS-009**. On `/analytics`, the Model Details card for Claude Sonnet 5 showed
`Thinking: Adaptive (effort: max)`. The product decision on [ISS-667](20260917-1320-ISS-667.md)
(2026-09-17) keeps the row, because Sonnet 5 does run with adaptive thinking. Only the
"(effort: max)" part is false.

## Root cause (pre-fix line numbers)

- `frontend/src/components/analytics/AnalyticsPage.tsx:829` rendered the literal string
  `Adaptive (effort: max)` for every catalog entry where `entry.thinking_supported` is true (the
  gate is at `:826`). Nothing in the text came from the model.
- The app never sends an effort value. `build_model` builds `thinking` as
  `{"type": _thinking_type(model_id), "budget_tokens": budget}` on the Anthropic path
  (`backend/app/agents/model_factory.py:139`). On the Bedrock path it builds `{"type": t_type}`
  and adds `budget_tokens` only when the type is `enabled` (`:196-200`). No `effort` key exists
  anywhere in that code. [FIX-501](20260907-FIX-501.md) reverted the `effort` field on both paths.

## What changed, and why there

- `AnalyticsPage.tsx:829`: `Adaptive (effort: max)` is now `Adaptive`. That is the whole diff.
- This line is the only place the text is rendered. In `frontend/src`, `thinking_supported` has
  one reader, `AnalyticsPage.tsx:826`; the other two hits are type declarations
  (`lib/api.ts:1659`, `store/api/capabilities.ts:26`). So the one-line change fixes the text for
  every catalog model that shows the row today: Sonnet 5 US and EU, Opus 4.5 and Opus 4.6
  (`backend/agents/capabilities/model_catalog.py:134, 152, 180, 192`).
- Left alone, as the decision requires: `_THINKING_FRAGMENTS` (`backend/app/api/capabilities.py:169`),
  `_ADAPTIVE_THINKING_MODEL_FRAGMENTS` (`model_factory.py:123`), and the row itself. No effort
  parameter was added.
- [FIX-491](20260907-1239-FIX-491.md)'s locked constraint still holds: model metadata comes from
  `/api/capabilities`, and no model-id list was added to the frontend.

## Not fixed here

- [ISS-668](20260917-1325-ISS-668.md): Opus 4.5 and 4.6 still show `Adaptive`, but at runtime they
  get `enabled` thinking (`model_factory.py:126`). Its test in `AnalyticsPage.test.tsx` is still
  red. The fixer escalated it for a product decision (`ESCALATIONS.md#qa-ps-009`), for two
  reasons:
  - The test's catalog fixture has no per-model thinking type, and neither does the Sonnet 5
    fixture. The only way both tests pass is a frontend model-id list, which FIX-491's constraint
    forbids.
  - The card leaves open whether the row should be hidden or say "Enabled".
- Comments that still claim effort is set, not changed because they are outside the decided
  scope: `backend/app/api/capabilities.py:165-166` says the fragments mean
  `effort="max" in build_model`, and `frontend/src/lib/api.ts:1658` describes the flag as
  "adaptive/extended".
