## What happened

Deferred finding from [FIX-395](20260829-0338-FIX-395.md), which routed 10 of the app's
clipboard-copy call sites through the new `frontend/src/hooks/useClipboardCopy.ts`. Four were
left alone, for two different reasons.

**Two that catch but stay silent to the user** — these are the pair
[ISS-331](20260828-1840-ISS-331.md) deliberately did NOT file as siblings, because they don't
share its unhandled-rejection mechanism:

- `frontend/src/components/chat/ArtifactCard.tsx:62-74`
- `frontend/src/components/chat/MessageBubble.tsx:171-176`

Both wrap `await navigator.clipboard.writeText(...)` in a `try/catch` and `console.error` on
failure. Better hygiene than the sites FIX-395 changed, but `console.error` reaches only
someone with devtools open — the button still shows nothing to the user when the write fails.

**Two the ISS-331 blast radius missed entirely.** ISS-331 grepped
`navigator.clipboard.writeText`; these use optional chaining, so the pattern did not match
them (found by re-grepping `navigator.clipboard` while applying FIX-395):

- `frontend/src/components/results/artifactPreview.tsx:406` — `navigator.clipboard?.writeText(content);`
- `frontend/src/components/preview/PreviewPanel.tsx:890` — `void navigator.clipboard?.writeText(link);`

Both are fire-and-forget with no `catch`, i.e. the same class as the sites FIX-395 fixed.
Neither was read for its surrounding success-state UI, so whether each is a "silent" or a
"false positive" variant is INFERRED from the call line alone, not confirmed.

## Disposition

Not fixed in FIX-395: no ISS card claimed them and no test covers them, so changing them would
have been untested churn outside that fix's cards. The mechanical work is small — each becomes
`const { copied, failed, copy } = useClipboardCopy();` plus a failure branch in the label — and
`useClipboardCopy` already exists, so this is a follow-up, not a design question.

## What would confirm it

Read the four call sites' surrounding render code, then drive each surface with
`navigator.clipboard.writeText` stubbed to reject (the protocol FIX-395's tests use) and check
whether anything user-visible changes.
