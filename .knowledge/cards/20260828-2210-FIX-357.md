## What was wrong

Loading `/runs/940ca699-b21b-4666-8e44-3370a08a4561/stream` — a run whose server status is
`diverted`, with `completed_at` set, `output: null`, `deliverable_filename: null` and only 2
of 3 agents ever run — auto-selected the Preview tab and rendered the plain-text placeholder
"Output will appear here". That is the identical copy a genuinely live, in-progress run shows
while its first output chunk has not arrived, so it implies output is still coming. Nothing
further will ever arrive: the run handed off at its divert point and cannot auto-resume.
BUG-20260828-014937-runs-id-stream, 3/3 cold starts.

The sibling terminal state on the same route — `cancelled` — already degrades honestly ("This
run was cancelled — The run was stopped before producing a deliverable"), which is what proved
the mechanism existed and simply omitted `"diverted"`.

## Root cause

Two gates in series, both required — this is the correction
[ISS-390](20260828-2048-ISS-390.md) made to [ISS-282](20260828-1710-ISS-282.md), whose
recommended one-line edit would have been a no-op on its own:

1. `frontend/src/app/[...view]/page.tsx:3035-3041` (inside `handleSelectWorkflowRun`, the
   handler that also hydrates a direct `/runs/{id}/stream` cold navigation) narrowed the value
   before it ever left the page:

   ```ts
   setReopenedRunStatus(
     fullRun.status === "failed" ||
       fullRun.status === "cancelled" ||
       fullRun.status === "degraded"
       ? fullRun.status
       : undefined,
   );
   ```

   This is the only one of the three `setReopenedRunStatus(` call sites that ever sets a
   non-`undefined` value (`:2720` and `:3931` both clear it), so `reopenedRunStatus` had an
   effective project-wide runtime range of `"failed" | "cancelled" | "degraded" | undefined`
   — never `"diverted"`.

2. `frontend/src/components/preview/PreviewPanel.tsx:704-707` — `reopenFailureSignal` tests
   the same hand-copied triad, so `showFailureAffordance` never fired and the render fell
   through to the `!hasContent` placeholder at `:1272`.

The same `failed || cancelled || degraded` literal, hand-duplicated with no shared helper,
recurred in two further reopen surfaces: `WorkflowHistory.tsx:593-596`
([ISS-391](20260828-2049-ISS-391.md)) and `RunDetailPage.tsx:230-233`
([ISS-395](20260828-2050-ISS-395.md)). Blast radius re-grepped before editing — a fresh
`grep` for the triad across `frontend/src` returned exactly those three sites plus the
page.tsx ternary, so the cards still held. Only line numbers had drifted (page.tsx's
`DashboardLayout` prop `3843 -> 3864`) from other uncommitted work in the tree.

## What changed and why there

`frontend/src/app/[...view]/page.tsx` — `"diverted"` added to the `setReopenedRunStatus`
ternary. This is where all callers route through: the direct `/stream` cold-nav effect
(`:3255`, `:3460`) and the history-reopen path both land in `handleSelectWorkflowRun`, so one
edit here supplies every downstream consumer. `applyTerminalStatus` already handles
`"diverted"` (`useWorkflow.ts:324-330` maps it to `null` — terminal, no failure marker), so
the value widening is safe for the `page.tsx:2181-2200` terminality bridge it also feeds.

`frontend/src/components/preview/PreviewPanel.tsx`:

- `isDivertedTerminal` / `showDivertedAffordance` added as their OWN signals next to
  `isCancelledTerminal`, deliberately NOT folded into `reopenFailureSignal`. Folding it in
  would have set `headerFailed` (`:767`), flipped `terminalFailureNoDeliverable` (`:724`) and
  so DROPPED the Preview tab entirely with the default tab falling to Audit — mislabelling a
  successful-up-to-its-divert-point run as failed, and contradicting the ISS-390 test's own
  assertion that the Preview tab stays selected. The `cancelled` carve-out shape is followed
  exactly.
- The render branch at `:1254` gained `|| showDivertedAffordance`. Its first operand was
  concurrently widened from `showCancelledAffordance` to `showFailureAffordance` by
  [FIX-358](20260829-0011-FIX-358.md) (ISS-285, same file, same line, uncommitted in the same
  tree) — the two compose correctly: `showFailureAffordance` is false for a diverted run, so
  the diverted clause is what carries it, and both `cancelled` and `diverted` props are false
  for a plain failed run so it still gets the generic copy. All suites re-run green on the
  merged tree.
- `DegradedRunAffordance` gained an optional `diverted` prop that swaps only the DETAIL line
  ("The run was diverted to another workflow and will not resume. No deliverable was produced
  here.") for the inaccurate "The run ended in a failed or degraded state." The headline stays
  "This run did not complete successfully", which is true of a diverted run and is what
  `RunDetailPage.iss395.test.tsx` asserts.

`frontend/src/components/history/WorkflowHistory.tsx:593-597` and
`frontend/src/components/history/RunDetailPage.tsx:230-234` — `"diverted"` added to both
triads, and `RunDetailPage` passes the new `diverted` flag down so the affordance it mounts
carries the accurate copy rather than the failed/degraded line. Here the semantics genuinely
are "same as the other three": History's right column suppresses its neutral empty state
because the summary column explains the absence, and the summary column now actually does.

**Not changed, and deliberately.** ISS-390 also suggests extracting a shared
`REOPEN_FAILURE_STATUSES` constant across the four sites. It was skipped: the four sites do
NOT share one predicate once `"diverted"` is honest about itself — PreviewPanel needs it out
of the failure signal while the other two need it in, so a single shared set would have to be
re-narrowed at the PreviewPanel call site anyway, and adopting it there costs five edits
(`headerFailed`, `terminalFailureNoDeliverable`, `showCancelledAffordance`, the FilesTab
`runStatus` at `:1336`) against the two this fix needed. The affordance's amber
`AlertTriangle` icon is also unchanged — the cards scope this to copy, and re-toning the
icon for a non-failure terminal state is a design decision no card covers.
