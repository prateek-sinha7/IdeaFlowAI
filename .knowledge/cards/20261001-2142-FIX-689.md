## What was wrong

Bug report QA-KB-036. The root cause and blast radius come from the analysis cards. They are not re-derived here.

- [ISS-689](20260918-ISS-689.md) is the root card. Merge `4ebd98e8f` combined two independent re-scopings of
  `_reconcile_terminal_status` (`backend/app/api/run_commands.py`): the attempt-boundary ladder of
  [FIX-484](20260902-1600-FIX-484.md) (`degraded_current` / `failed_current`) and the last-by-seq
  `degraded = bool(...)` of `f23625911`. The ladder kept FIX-484's reads, so two locals became Store-only:
  `failed = any(e.type == "pipeline_failed" for e in events)` (pre-change `:838`) and `degraded = bool(...)`
  (`:851-855`). A 10-line comment above them (`:840-849`) explained the dead last-by-seq rule and labelled itself
  `FIX-247`, the frontend clarify-gate repaint fix. The docstring (`:804-806`) and a "backwards-compat" comment
  (`:942-944`) described the same dead mechanism, and the `_UNSET_ERROR` comment (`:1031`) carried the same wrong label.
- [ISS-886](20261001-2114-ISS-886.md) is the test-gap sibling. Nothing pinned FIX-484's three scopings or the
  degraded error text. The test-writer added `test_reconcile_fix484_boundary_scoping` (T5-T7) and
  `test_reconcile_degraded_persists_error_text` (3 cases) to
  `backend/tests/integration/agents/test_restart_resume_db.py`. No production change was needed for it.
- [ISS-887](20261001-2114-ISS-887.md) is the label sibling. Two test docstrings in that file (`:4380`, `:4422`) cited
  `FIX-247`, and the first explained the dead last-by-seq rule.

Nothing misbehaved at runtime: the dead locals were function-local and the live ladder was correct. The cost was
diagnostic, plus the trap of the BUGS.md "agreed minimal fix", which would have deleted `_latest_complete` too.

## What changed, and why there

Every edit sits inside the one function all callers route through: `_drive_user_resume`
(`run_commands.py:792`) and the stop/shutdown path (`run_shutdown.py:344-346`). No caller changed. Edits were
anchored on quoted code, not line numbers (concurrent fixers have hunks from `:1472` down in the same file).

`backend/app/api/run_commands.py`, `_reconcile_terminal_status`:

1. Deleted `failed = any(e.type == "pipeline_failed" for e in events)`. Dead since FIX-484.
2. Deleted the 10-line `# FIX-247: the degraded verdict must track only the LATEST pipeline_complete ...` comment.
3. Deleted `degraded = bool(_latest_complete is not None and ...)`.
4. KEPT `_latest_complete = max(completes, key=lambda e: e.seq) if completes else None` (now `:842`), under a
   two-line comment saying it only sources the degraded error text and that the verdict is `degraded_current`.
   Its reader at `:970-971` derives `WorkflowRun.error`. The optional move of the assignment into the degraded
   branch (ISS-689 item 2, INFERRED and never run) was not made.
5. Deleted the false 3-line comment above `if degraded_current:` ("keep the unscoped variables for
   backwards-compat with the `_persist_resume_output_columns` call below"). That callee takes the event list,
   not a flag.
6. The docstring now states the live rule: a degraded `pipeline_complete` at or after the last attempt boundary
   (`run_resuming` / `pipeline_start`) → `degraded`; a `pipeline_complete` at or after it with no
   `pipeline_failed` at or after it → `completed`.

Outside the function, the `_UNSET_ERROR` sentinel comment (now `:1015`) cites `run 4bdf9398` in place of `FIX-247`.
No id was invented for it (ISS-689 item 7).

`backend/tests/integration/agents/test_restart_resume_db.py` (ISS-887; docstrings only, no assertion touched):
`test_reconcile_degraded_tracks_latest_completion_only` now cites run 4bdf9398 and FIX-484 and states the boundary
rule; `test_reconcile_clears_stale_error_on_clean_completion` drops its `FIX-247:` prefix.

`backend/tests/unit/test_run_commands_dead_locals.py` is a test-infrastructure repair, NOT an assertion change.
It is flagged here for audit. I added `@pytest.mark.allow_io("runs ruff on run_commands.py as a black-box subprocess")`.
Without it, `tests/unit/conftest.py:127-136` raises `UnitIsolationError` on the `subprocess.run`, so ruff never
ran. The strict xfail was satisfied by the isolation guard whatever the code said, and the test reported
`1 xfailed` both before and after the production fix. `allow_io` is the conftest's registered opt-out
(`backend/pyproject.toml:172`; precedent `backend/tests/unit/test_status_head_sha.py:20`). The assertion
(`ruff check app/api/run_commands.py --select F841,F821` exits 0) is unchanged, and it discriminates:

- The identical invocation on HEAD's text
  (`git show HEAD:backend/app/api/run_commands.py | .venv/bin/python -m ruff check --select F841,F821 --output-format concise --stdin-filename app/api/run_commands.py -`)
  exits 1 with `F841 Local variable failed` at `:838:9` and `F841 Local variable degraded` at `:851:9`.
