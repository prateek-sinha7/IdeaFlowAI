## Why this must also be broken

[ISS-363](20260828-2129-ISS-363.md)'s root cause is in the shared `AgentsPopup` component, not in
`IdeaInputPage.tsx` specifically. `AgentsPopup` has exactly two production callers
(`grep -rn "<AgentsPopup" frontend/src/ --include="*.tsx"` — `IdeaInputPage.tsx:1870` and
`LaunchWizard.tsx:1112`; the only other hits are 4 render calls in
`AgentsPopup.reskin.test.tsx`, a test file). `LaunchWizard.tsx` wires the exact same broken shape
as `IdeaInputPage.tsx`:

```tsx
// LaunchWizard.tsx:1126
onClose={() => setShowAgents(false)}
```
```tsx
// LaunchWizard.tsx:1156 (onReorder), handler at :577
onReorder={handleReorderAgents}   // -> setPipelineAgents(reordered)
```
```tsx
// LaunchWizard.tsx:1159 (onSelectionsChange), handler at :580-582
onSelectionsChange={handleSelectionsChange}   // -> selectionsRef.current = s
```

Same Cancel wiring, same unstaged `pipelineAgents` state (`LaunchWizard.tsx:205`), same unstaged
`selectionsRef` (`LaunchWizard.tsx:242`). Nothing in `LaunchWizard.tsx` adds a snapshot or a
Cancel-time restore that `IdeaInputPage.tsx` lacks. `LaunchWizard` mounts at `/workflow/create`
(`frontend/src/app/workflow/create/page.tsx:24`) and at the ppt/prototype branch of
`/workflows/{id}/run` (`frontend/src/app/[...view]/page.tsx:3774`) — routes the original bug
report never exercised, since it drove `/create/ex_A2_branch`, which mounts `IdeaInputPage` via
`DashboardLayout.tsx:2891`.

## Expected vs actual

**Expected:** Cancel inside the Advanced modal discards in-session edits identically regardless
of which page opened it.

**Actual (INFERRED — not yet independently reproduced):** any workflow reachable through
`LaunchWizard` whose steps include a conditional-gate route (or any lever/roster edit — see
[ISS-364](20260828-2130-ISS-364.md), [ISS-365](20260828-2131-ISS-365.md)) should show the
identical persist-after-Cancel behavior at `/workflow/create` or a ppt/prototype
`/workflows/{id}/run`, since the wiring is byte-for-byte the same broken shape.

## What would confirm or refute this

Navigate to `/workflow/create`, open "Advanced", make an edit (any of the three channels above),
click Cancel, reopen — same assertions as [ISS-258](20260828-1650-ISS-258.md)'s repro. Note:
`LaunchWizard.tsx:1118` sets `allowCustomAgentTemplate={false}`, and the built-in pipelines it
serves may not all ship a step with `route:` — if none currently do, the route-editor variant of
this card cannot be exercised there today (though the lever/roster variants still apply to any
LaunchWizard-hosted pipeline). Confirm which `MODE_CONFIG` pipelines declare `route:` in their
`workflow.yaml` before concluding a route-specific miss refutes the mechanism, since the CODE
path is shared even if a given pipeline's DATA never reaches a `route:` step through this host.

## Where the fix belongs

Identical to [ISS-363](20260828-2129-ISS-363.md) — inside `AgentsPopup.tsx`. Because both hosts
call the same component the same way, the single staged-draft-with-restore-on-Cancel fix there
closes this sibling for free; `LaunchWizard.tsx` needs no bespoke change.
