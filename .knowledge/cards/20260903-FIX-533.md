## Related

## What was wrong

Six status utilities generated no CSS at all. The ramp's fill/border pairs
existed as raw CSS variables in both themes but were never mapped into
`@theme`, so `bg-status-amber-fill` and its siblings produced a transparent
background and a default-grey border at 63 call sites across 11 files. In light
mode this was barely visible; in dark mode the tinted panels were simply
absent.

## The fix (commit 3e6fcb93c)

Register the ten pairs in `@theme`. Verified in dark mode: every class
resolves, including the `/50` and `/40` opacity modifiers, and every real
pairing clears WCAG AA.
