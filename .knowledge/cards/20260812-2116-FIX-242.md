## Description

A gated fan-out step parked the run at a review gate nobody could see, discover or resolve (ISS-097). _should_gate (engine.py:4908-4925) is a per-INVOCATION predicate on spec.id; gate_agent_ids is a per-STEP selection — the UI says "Checked agents pause the pipeline for your review after they finish" (ReviewGatesSection.tsx:128-129). Identical readings until fan-out made one step produce N invocations of one agent id (fanout.py:95-96 resolves agent: self to step.agent_id). The originally-filed prediction — "N simultaneous gates, each awaiting a human" — was wrong in the direction that matters. Every worker's review_gate_ready is consumed and DISCARDED by fanout.py:414-429, whose loop reads only agent_complete for token accounting and forwards nothing. Zero frames reached the SSE stream, zero rows reached durable run_events, derive_open_gate returned (None, None), and the run stopped dead with workflow_runs.status = waiting_for_user indefinitely; all N workers shared ONE gate key f"{run_id}:{agent_id}" (engine.py:5705), so they were N arms of one slot. MEASURED, not reasoned (sample_wave, single-wave plan, 4 workers, gate_agent_ids=["sample-wave-worker"] at eb12bc7e): _run_review_gate entered 4×, 1 gate key, 0 frames on the wire, HUNG at the 20 s timeout; control with [] completes. Fix: ONE keyword-only invocation-scope flag invocation_gated, threaded from the two kernel sites that create non-step invocations — run_worker (kernel_services.py, the only non-test caller, grep-verified) and run_merge_agent (identical invisible-hang shape: its events are consumed with a bare pass) — through run_agent into _run_agent, reaching all THREE inline gate sites (restart re-entry :3447, revision re-open :3563, live post-stream :4499). INV-12: the existing predicate is narrowed IN PLACE (return invocation_gated and selected), both original branches preserved verbatim; no second gating rule was added, so nothing is superseded and nothing is left to delete. Default True ⇒ every step-shaped invocation byte-unchanged. Three designs evaluated and REJECTED — recorded so they are not retried: (a) making _should_gate read step.gates CANNOT work — kernel_services.py:992-993 reuses the PARENT step object, gates included, whenever the worker is agent: self with no isolated workspace (exactly the offline and shared_read path); it is also a different mechanism (step-boundary _evaluate_gates), and wiring both to one source is the dual implementation INV-12 forbids. (b) Parking the flag on ExecutionContext RACES — N workers share ONE ectx under asyncio.gather, so a save/restore field could be cleared by worker A's finally while worker B is mid-flight (INV-2). (c) Renaming worker agent ids breaks _spec_for, the allowed_workers allow-list, fragment artifact provenance and the wave resume cursor. Deliberate residual, filed not folded: engine.py:2470 still passes inline_gated=self._should_gate(spec, ectx) at the step boundary, so a fan-out step that BOTH declares gates:[human] AND has its agent ticked now dedupes its declared gate against an inline gate that no longer fires — ISS-131. Left byte-unchanged on purpose so the INV-3 dormancy argument stayed exact; correcting it needs the strategy to declare whether it runs its agent inline, which the kernel must not infer from a capability-name list. Also filed rather than folded: ISS-129 (the fanout.py:414-429 blanket worker-event swallow — the amplifier, still live for agent_error/pipeline_cancelled), ISS-130 (shared-ectx scratch mutation under parallel fan-out — believed safe only because _run_agent consumes the scratch before its first await, believed but NOT verified), ISS-132 (the task-loop sibling — N *visible* sequential gates; suppressing it is a product decision, not a defect with one answer). Test-double repairs required by the signature change, and turned into coverage: test_fanout.py's run_worker double and test_merge_conflict.py's new merge double now ASSERT invocation_gated is False; three _run_agent doubles in test_pipeline_failure_semantics.py pinned a stale positional arity and now absorb additive params. test_gate_stub_signature_drift.py — the AST guard that exists for exactly this defect family — caught a first attempt that patched _run_review_gate at CLASS level with an unbindable signature; the test was rewritten to the file's dominant instance-patch idiom with *a, **kw, and the guard is green.

## Root cause

gate_agent_ids was designed as a per-STEP selection and implemented as a per-INVOCATION predicate on spec.id. Those two readings were the same thing for every workflow that existed when the selector shipped, because every step invoked its agent exactly once. Fan-out (Phase 11) and the task loop broke that equivalence and nothing re-derived the gate rule; the gates=[] on the worker step view (kernel_services.py:1001) reads as "this worker has no gates" and is a false reassurance — it suppresses only the DECLARED path, never the inline one, which never sees a step at all.
