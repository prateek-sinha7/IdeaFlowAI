## Description

A second "Update the Specs" at the RE-OPENED analyze gate was a silent no-op — the gate closed, instantly re-opened on identical content, no revision ran, and the build proceeded from the unrevised spec (defect B); and a nested revision pass minted DUPLICATE :rev1 checkpoint threads while zeroing the outer pass's counter and analysis report mid-flight (defect A)

## Root cause

(B) Of the three _gate_update_specs branches only two called the sub-pipeline; the third — the pending-re-open short-circuit — merely re-seeded spec_revision_pending_output and breaked. It was written to CLOSE a revision, not to start one, and the FE sends the analyzer's own output as the report (InlineGateActions.tsx:163), so the re-opened gate showed identical content and the no-op was invisible. (A) spec_revision_attempt is a per-_run_agent LOCAL, so the analyze re-run inside a pass — itself gated, and _run_review_gate acts on action == "update_specs" without ever consulting update_specs_eligible — re-entered the consumer with its own counter at 1; both levels published index 1 and minted the same :rev{N}. The sub-pipeline's finally then cleared to zero rather than restoring, stripping the outer pass while it was still on the stack.
