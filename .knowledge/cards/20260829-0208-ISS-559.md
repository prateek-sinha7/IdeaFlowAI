## What happened

INFERRED sibling of [ISS-331](20260828-1840-ISS-331.md), derived from a
source-code read while analyzing that bug — not yet independently driven
live in a browser.

`frontend/src/components/preview/UserStoryPreview.tsx` (the user-stories
deliverable preview) has its own "Copy MD" buttons (two render sites in the
JSX share one handler) with the same false-positive variant already found in
[ISS-556](20260829-0208-ISS-556.md), [ISS-557](20260829-0208-ISS-557.md) and
[ISS-558](20260829-0208-ISS-558.md).

## Root cause (confirmed by direct read — false-positive variant)

`frontend/src/components/preview/UserStoryPreview.tsx:47-51`:

```
const handleCopy = () => {
  navigator.clipboard.writeText(content);
  setCopied(true);
  setTimeout(() => setCopied(false), 2000);
};
```

Fire-and-forget: not awaited, no `.then()`/`.catch()`, `setCopied(true)`
unconditional. Same missing-error-handling mechanism as
[ISS-331](20260828-1840-ISS-331.md); same false-positive shape as the other
preview-surface siblings — the button claims "Copied" even when the write
silently failed.

**What would confirm this live:** open a user-stories run's preview, click
either "Copy MD" button, and verify with a clipboard write-interception
whether content actually lands when the write is made to fail.
