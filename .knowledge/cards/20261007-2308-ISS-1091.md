# ISS-1091

**Register source:** sibling derived during the analysis of `QA-KB-088` on 2026-10-07 (root [ISS-947](20261002-0107-ISS-947.md)). Not yet its own bug row.

**Confidence:** CONFIRMED. Every count below comes from running the file once, at HEAD `33d55657`; the files cited are unchanged through `2254c5ef5`. Evidence: `evidence/qa-kb-088/08-analyze-sibling-unit-files-pytest-summary.txt`.

## Condition

Spec 016 (commit `732adc245`, 2026-08-26) wrote three DB-backed test files into `tests/unit/`: the e2e file that
[ISS-947](20261002-0107-ISS-947.md) is about, the piece-level `test_workflow_override.py`, and a SQLite `db_session` added to
`test_workflows_api.py` (that file now lives under `tests/unit/api/`). The unit suite's autouse `_unit_io_guard`
(`backend/tests/unit/conftest.py:90-123`, added by `09270703b` on 2026-09-22) raises `UnitIsolationError` (`:81`) on any
DBAPI connection, SQLite included. [ISS-947](20261002-0107-ISS-947.md) tracks only the e2e file. The other two are not tracked anywhere:
no hit for either file name in `LEDGER.md`, `BUGS.md` or `INDEX.md`.

## Expected vs actual

Expected: both files collect and run offline, as their docstrings promise ("Offline", "in-memory SQLite").

| file | collected | passed | failed | setup errors |
|---|---|---|---|---|
| `tests/unit/test_workflow_override.py` | 23 | 6 | 1 | 16 |
| `tests/unit/api/test_workflows_api.py` | 53 | 4 | 0 | 49 |

All 65 errors are the same `UnitIsolationError` from `conftest.py:81`, raised at fixture setup by `create_engine("sqlite://")`
in the `db` fixture (`test_workflow_override.py:44-57`) and the `db_session` fixture (`test_workflows_api.py:48`). The one
failure in `test_workflow_override.py` is not a setup error and has a different cause: see
[ISS-1092](20261007-2308-ISS-1092.md).

## What is left unguarded

- `resolve_override` / `find_override` (`backend/app/api/_workflow_override.py`) are the owner-scoped lookup shared by the
  screen (`workflows.py:456`) and the run (`run_commands.py:3609`). Their tests are the 16 errors, including the AUTHZ-01
  cross-owner case `test_never_returns_another_users_override` (`test_workflow_override.py:104`) and
  `test_find_override_is_still_owner_scoped` (`:136`). No other test calls either function (grep of `backend/tests`:
  only these two dead files plus the e2e file).
- `TestList` and `TestGetAnd404` in `test_workflows_api.py` pin `GET /api/workflows` and `GET /api/workflows/{id}`
  (API-01), including `test_get_unknown_id_is_404` and `test_get_path_traversal_id_is_404` (the T-04-13 path-traversal
  mitigation) and `test_get_each_known_id_compiles`. The 4 tests that still pass are `TestKnownWorkflowIdsDiscovery`, which
  uses no client.
- The e2e file ([ISS-947](20261002-0107-ISS-947.md)) is the only other test of the lookup and it errors too, so today nothing exercises
  the override read path at all.

## Fix direction (INFERRED, not applied)

Same as [ISS-947](20261002-0107-ISS-947.md): relocate, do not loosen the guard (`test_unit_io_guard.py:30-34` pins that an in-memory SQLite
engine is refused). The harness shape already runs green in the integration tree
(`tests/integration/api/test_user_workflows_api.py`: 39 passed on 2026-10-07).

- `test_workflow_override.py`: the 16 DB-backed tests (`resolve_override`, `find_override`, `override_steps`) move to
  `backend/tests/integration/api/`; the `merge_override_steps` tests need no DB and can stay in `tests/unit`.
- `test_workflows_api.py`: its module docstring says the DB exists "ONLY for spec 016's workflow-override read" and that every
  test runs against an empty overrides table. Either move `TestList` and `TestGetAnd404` with the `db_session` and
  `client` fixtures to `backend/tests/integration/api/`, or replace the SQLite session with a mock. A bare
  `MagicMock(spec=Session)` is not enough: `find_override` runs a query chain, so `.first()` returns a truthy mock and
  every request would read as "an override exists". Relocation is the safer choice.
- Name: five files relocated for this same guard gained an `_api` suffix (`test_duplicate_context_guard_api.py`,
  `test_run_files_ref_family_scope_api.py`, `test_sandbox_ref_scoped_endpoints_api.py`,
  `test_settings_preferences_race_api.py`, `test_settings_api_key_whitespace_name_api.py`). It is a convention; no test
  enforces it.
- Do not reach for `@pytest.mark.allow_io`: `conftest.py` calls every such mark "a test that is not really a unit test".

## Why the root cause implies it

[ISS-947](20261002-0107-ISS-947.md)'s first fault is "a file in `tests/unit/` opens its own SQLite engine". These two files share its
author, its commit, its fixture shape and its date. They differ only in never having been listed.

## Resolution (QA-KB-088 fix, 2026-10-07)

[FIX-758](20261007-2338-FIX-758.md) relocated both files, test harness only (plain `mv` / a verbatim split, nothing else in
the moved tests changed):

- `tests/unit/test_workflow_override.py`: the `resolve_override`, `find_override` and `override_steps` sections, with
  `_FakeUser`, the `db` fixture and `_seed`, now live in `backend/tests/integration/api/test_workflow_override_api.py`:
  **17 passed** (the 16 former setup errors plus `test_override_steps_of_none_is_none`). The `merge_override_steps` section
  stays in the unit file: 5 passed, 1 failed, and that failure is [ISS-1092](20261007-2308-ISS-1092.md)'s
  `test_a_not_user_allowed_gate_is_rejected` (now `:115-122`), red before and after, not this card.
- `tests/unit/api/test_workflows_api.py` moved whole and byte-identical to `backend/tests/integration/api/test_workflows_api.py`:
  **52 passed, 1 failed** (was 4 passed, 49 errors). The failure is `TestList::test_list_carries_launchable_flags`, whose
  expected labels at `:217-218` predate the catalog rename in `1a1b720b7`; filed as [ISS-1094](20261007-2337-ISS-1094.md) and
  NOT edited here.

So the owner-scoped lookup (including `test_never_returns_another_users_override` and
`test_find_override_is_still_owner_scoped`) and the `/api/workflows` contract (including both path-traversal 404 tests)
run again. Evidence: `evidence/qa-kb-088/14` (before) and `15` (after).
