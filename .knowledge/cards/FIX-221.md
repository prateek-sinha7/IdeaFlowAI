## Description

When confirming a Concierge-proposed revision on an `od_prototype` run, the
revision run was created but immediately failed with no events — the chat showed
"Starting revision..." but the run was marked failed with no agents running.

## Root Cause (2 gaps)

**Gap 1 — od_prototype_output → od_prototype_revision has no agents:**

The Concierge's `propose_revision` tool stores `target="od_prototype_output"` in
the durable proposal params. When confirmed, `_dispose_concierge_proposal` reads
`target="od_prototype_output"` and passes it to `_handle_revision`. That function
derives `revision_pipeline_type = "od_prototype_revision"` → no registered agents
→ raises `ValueError("No revision pipeline registered for od_prototype_output")`.

The `_OD_FALLBACK_MAP` logic (FIX-216b) only applied when `params.get("target")`
was EMPTY (fallback derivation path). When the Concierge explicitly stored a target,
the fallback was bypassed entirely. The ValueError fired inside an `asyncio.create_task`
background task, got logged as ERROR but the buffer window missed it — the run
appeared to start then silently fail.

**Gap 2 — workspace_id NOT NULL constraint:**

`_mint_revision_row` created the child `WorkflowRun` without `workspace_id`.
The `run_events` table requires `workspace_id NOT NULL` (migration 0026). When
the engine's `_stamp_resume_marker` tried to write the first `run_events` row
for the revision, the constraint fired with `workspace_id=None` → write failed
→ run had zero events → SSE opened at `after_seq=0` and closed immediately
with `reason=sentinel`.

## Fix

**Gap 1:** Added `_OD_TARGET_REMAP = {"od_prototype_output": "prototype_output"}`
applied unconditionally after reading `target` from params in
`_dispose_concierge_proposal`. This maps `od_prototype_output → prototype_output`
→ `prototype_revision` pipeline (2 agents: revision + validation). Applied
regardless of whether target came from params (Concierge-stored) or fallback.
`od_ppt_output` is excluded since `od_ppt_revision` has agents and is entitled.

**Gap 2:** Look up parent run's `workspace_id` in `_mint_revision_row` and
inherit it on the child revision `WorkflowRun`:
```python
parent_wr = db.query(WorkflowRun).filter(WorkflowRun.id == parent_run_id).first()
parent_workspace_id = getattr(parent_wr, "workspace_id", None) if parent_wr else None
wr = WorkflowRun(..., workspace_id=parent_workspace_id, ...)
```
