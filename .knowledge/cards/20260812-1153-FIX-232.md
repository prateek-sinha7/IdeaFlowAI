# FIX-232

## Description

Rejecting at a review gate did not stop the run — every remaining step still ran, the run reported pipeline_complete, and the fake complete/completed rows it left behind made a later resume skip every wave and produce NOTHING. Fixed by giving the dispatch loop a terminal-event observation symmetric to its existing agent_error one, ending in return; plus defence-in-depth at the single fan-out cancel boundary.

## Root cause

Two parts. (a) The dispatch loop (engine.py:2523) observed ONLY agent_error. The inline gate's reject handler cancels the run, yields pipeline_cancelled and returns — but a generator return only ends THAT step, so the terminal event was forwarded and ignored and the outer per-step loop advanced to step i+1, falling through to the sole pipeline_complete emitter. (b) The only step-boundary termination check (engine.py:2381) reads cancel_event, which a gate rejection never sets — which is why FIX-227 was orthogonal. The damage was never token spend (every post-rejection worker short-circuits on _run_agent's terminal guard at :3329 and bills zero): it was the DURABLE RECORD. Each no-op worker was written subagent_runs='complete' and each wave wave_runs='completed', and wave_scheduler.py:251-256 skips completed waves on resume — so reject → restart → resume skipped both waves, produced zero files and recorded the run completed. Silent, permanent loss of a fan-out run's entire output. The fix is the exact sibling of the declared-gate handler WR-03 (engine.py:2454-2479), whose own comment describes this defect verbatim. return, not break — break falls through to the Step-5 terminal block which still emits pipeline_complete. Predates ISS-078/FIX-227/228/229; byte-identical at 3e80fcc4 (2026-07-19).
