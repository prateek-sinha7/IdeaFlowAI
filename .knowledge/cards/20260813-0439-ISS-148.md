# ISS-148

## Title

**The Concierge confidently denied that token usage or cost data exists for a run, and referred the user to support — while the exact number was rendered in the same viewport.** Asked "how many tokens did this run use in total, and what did it cost?", it answered that the product "does not expose billing or token usage metrics" — a false claim: `LaneRunHeader.tsx` renders the same run's token count inches away, and `workflow_runs.token_usage` (`app/models/workflow.py:36`) already holds the full figure as JSON. **Root cause, both confirmed by direct code read.** (1) `concierge.py:898` (pre-fix) literally forbade the model from exposing "token counts" in its RESPONSE RULES, paired with a `:893-895` denial template ("if asked for these, say they are not available") the model over-applied from the neighboring internal-identifiers rule. (2) No tool existed that could have answered even without that rule — `_read_tools` (`:867-870`, pre-fix) returned exactly 7 read tools, none touching `workflow_runs.token_usage`. **Decisive evidence (per the original investigation; not independently re-observed this session — Bedrock unreachable):** on run `5ecb990f-2c80-4752-a615-2bed3280387a`, `chat_usage` rows show the token/cost question answered in a SINGLE bare model turn — 4,816 input tokens, 0 cache-read, zero tool calls — versus 9,937-12,781 input tokens with cache reads for sibling questions that DID use a tool in the same session. The refusal came from the prompt reciting itself, not from a tool returning nothing. **A second instance of the same failure mode fired in the same investigation and was initially graded correct:** asked what FILE the run produced, the Concierge gave the document TITLE, never `workflow_runs.deliverable_filename`, because `list_artifacts` (`concierge.py:792-801`) projects `ArtifactRef` rows and `ArtifactRef` (`app/models/artifact_ref.py`) carries no filename column — filed separately as ISS-149, deliberately not fixed here. **FIXED 2026-08-13 (FIX-249), both halves:** a new narrow `get_token_usage` tool (excluding cache read/write, `model_id`, and the uncached-counterfactual cost by design — those remain gaps, ISS-149) plus removal of the `token counts,` prohibition and a new standing honesty rule ("if no tool of yours can answer, say so and stop — never claim what the product does or does not support, never redirect to billing/support") that closes the same failure MODE for the other gaps still without a tool. Severity MAJOR: a confident falsehood about the product's own capability, contradicted by the same viewport; the subject is cost, this repo's most cost-sensitive number; and it is a failure mode licensed by the prompt for ANY gap, not one bad answer — precedent ISS-140 was likewise re-severitied minor → major on this branch when its "not user-visible" claim was disproven. **Live verification BLOCKED, not completed** — see FIX-249's Status column; confirmed 3 independent ways across 2 sessions, unrelated to this fix.
