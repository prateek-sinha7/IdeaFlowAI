## The symptom

`tools/knowledge/status.py` prints a header line that is supposed to say which
commit and which checkout the report describes. It says this instead:

```
tree:   /Users/bilala/Developer/Projects/VELOCITY-AI-worktrees/feat-pdf-workflow
branch: feat/pdf-workflow @ ---
id:    last sync 2026-09-15 (4a6e8993)
```

The sha is `---` and the next line begins with a stray `id:`. `--json` shows
what is actually in the field: roughly 2000 characters of
`DOMAIN-workspace-isolation` frontmatter and generated body, sitting where an
8-character sha belongs.

Reproduced on HEAD `73796dbd0`, both output modes.

## Root cause

One name, two meanings, twenty lines apart.

`status.py:144` binds the report's identity:

```python
head = git("rev-parse", "HEAD")
```

`status.py:319`, inside `for card in sorted(arch_dir.glob("DOMAIN-*.md"))`,
rebinds it as a scratch buffer for the card text the signature regex scans:

```python
head = card.read_text(encoding="utf-8", errors="replace")[:2000]
```

Python has no block scope, so the loop variable *is* the module-level one. Both
consumers run after the loop and both get the last DOMAIN card read — `:342`
emits it as the JSON `"head"`, `:355` slices `[:8]` off it and prints `---`
(the opening frontmatter delimiter) plus whatever the rest of the line held.

The shadowing arrived with the domain-prose block in `70d4d63b2`. That commit
added the loop; it did not touch line 144, so nothing in the diff looked wrong.

## Why it matters

The header line is the only thing distinguishing one checkout's report from
another's, and `status.py` deliberately prints a `NOTE: N other checkout(s) of
this repo exist` block right below it so a reader can tell genuine drift from a
different branch. Without a real sha, that whole comparison is guesswork.

The JSON field is worse: anything reading `head` programmatically gets 2KB of
markdown where it expects a sha, with no error to notice.

## Fix

Rename the loop variable at `:319` (and its two uses at `:321`). Nothing else
moves.

## Note on the evidence

The staleness sweep recorded the reproduction as `branch:
feat/file-extract-tools`; re-running it here prints `branch: feat/pdf-workflow`,
and the other checkout is `feat/git-versioning @ f3f4bbaf`. The branch name is
incidental — the `@ ---` and the orphan `id:` line reproduce identically.
