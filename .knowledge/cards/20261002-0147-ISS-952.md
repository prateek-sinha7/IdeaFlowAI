# ISS-952

## Provenance

The QA-KB-044 fixer found this while writing [FIX-709](20261002-0147-FIX-709.md). Nobody reported
it.

- **CONFIRMED** by a component probe on the patched tree. It rendered the real `PreviewPanel`
  with a scratch test, and the output is in
  `evidence/qa-kb-044/11-fix-shell-precedence-probe.txt`.
- **INFERRED**: that it is reachable in the browser. Nothing was driven in the UI.

This is the reverse direction of [ISS-933](20261001-2231-ISS-933.md):

- ISS-933: the pinned run's status never reached the affordance. FIX-709 fixed that.
- This card: the SHELL run's status reaches the pinned view and wins.

## Condition

The panel shows a pinned version with no stored output (`hasContent` false), while the shell run
is itself terminal with a bad status. For a reopened run that status is `reopenedRunStatus` in
`cancelled`/`failed`/`degraded`/`diverted`; for a live run it is `pipelineState.failed`/`.degraded`.

The branches ahead of FIX-709's pinned branch read only the shell:

- `showFailureAffordance = !hasContent && isTerminal && terminalFailure`;
- `showDivertedAffordance`;
- `terminalFailureNoDeliverable` (the `visibleTabs` drop).

Because `hasContent` is computed from the pinned content, all of them fire for an empty pin.

## Probe (patched tree, pinned `completed` with `output: null`, shell status varied)

```
shell=undefined | tabs=["Preview","Steps","Workspace","Audit"] | distinct=true  | cancelledCopy=false | failedCopy=false
shell=completed | tabs=["Preview","Steps","Workspace","Audit"] | distinct=true  | cancelledCopy=false | failedCopy=false
shell=cancelled | tabs=["Preview","Steps","Workspace","Audit"] | distinct=false | cancelledCopy=true  | failedCopy=false
shell=failed    | tabs=["Steps","Workspace","Audit"]           | distinct=false | cancelledCopy=false | failedCopy=false
shell=diverted  | tabs=["Preview","Steps","Workspace","Audit"] | distinct=false | cancelledCopy=false | failedCopy=true
```

What the probe shows for a pinned version that completed:

- Under a cancelled shell it reads "This run was cancelled".
- Under a diverted shell it reads "did not complete successfully".
- Under a failed shell the Preview tab disappears.

## Reachability (INFERRED)

The shell is the run named in the URL. For `run-version`, `contentSourceRunId` returns
`parsed.runId`, and `setReopenedRunStatus` takes that run's status in `app/[...view]/page.tsx`.

The shell is therefore bad-ended in two cases:

- A member that ended badly is opened directly, then another tagless member is pinned through a
  chat result card (`handleSelectVersion`).
- A hand-typed `/runs/{member}/versions/{n}` URL.

Candidate live rows from `evidence/qa-kb-044/07-analyze-live-data-select-only.txt` (none of
these was opened):

- `/runs/4eb1a2ea-b4be-400a-b53c-b63597cc52a0/versions/4`. The shell is v3, `cancelled`, and the
  pin is v4, `failed`. Predicted: "This run was cancelled".
- `/runs/97b49f98-83bd-4ed6-8631-600bf9653905/versions/3`. The shell is v4, `failed`, and the pin
  is v3, `cancelled`. Predicted: no Preview tab, Audit default.

The route through the family root, `/runs/87e02c32-.../versions/{3,4}`, is not affected, because
the root is `completed`.

## Why it is not fixed in FIX-709

- It is outside [ISS-154](20260813-0819-ISS-154.md) and ISS-933. ISS-933 explicitly leaves the
  shell signals alone.
- Gating the shell signals on the pin changes tab visibility and the default tab
  (`terminalFailureNoDeliverable`, `defaultTabDiscriminator`), and that needs its own analysis.

## Fix (proposed, not applied; needs analysis first)

- Make the shell-keyed affordances and the failed-tab drop inapplicable while `overrideActive`.
  Candidates are `!overrideActive` in `showFailureAffordance`, `showDivertedAffordance` and
  `terminalFailureNoDeliverable`.
- Then let the FIX-709 branch decide the pinned copy.
- Check the effect on `headerFailed` and the default-tab logic before choosing.

## Test conditions

Use the same harness as `PreviewPanel.olderVersionNullOutput.test.tsx` (pin via the
`pinnedVersion` prop, tagless members, the full `@/lib/api` mock), and add
`reopenedRunStatus="cancelled" | "failed" | "diverted"` on the shell:

- A pinned `completed` version with `output: null` renders "No deliverable was saved for this
  version", and the Preview tab is present.
- A pinned `failed` version renders "did not complete successfully", not the cancelled copy.
- Control: the unpinned shell keeps its own affordance and tab set.


## Analysis (QA-KB-091, analyzer, 2026-10-02)

QA-KB-091 (Low, `/runs/{member}/versions/{n}`) was logged against this card, which stays the root card. Its reproduction is a component test; the validator saw it fail 3 of 3
(`evidence/qa-kb-091/01..03`). This analysis re-read the code, probed the real `PreviewPanel` offline and validated candidate fixes on scratch copies. **No application source or test was edited.**
Evidence: `evidence/qa-kb-091/` files 04, 05, 06 and the `scratch-*` sources. Line numbers are the working tree on 2026-10-02 (`PreviewPanel.tsx` md5 `475f5d437872d0c205a11db8f71afa5b`; HEAD `024c03ef8` plus uncommitted edits,
FIX-709 among them), so HEAD numbers can sit a few lines off.

### Root cause (CONFIRMED: code read, and offline probes of the real component, rows G1-G9)

One mechanism: **`hasContent` is PIN-keyed, and every terminal-state signal ahead of the pinned branch is SHELL-keyed.**

- PIN-keyed: `hasContent` (`:1119`) is built from the `eff*` slots (`:1068-1087`), which follow `viewingVersion`.
- SHELL-keyed: `isStillRunning` (`:1130`), `liveFailureSignal` (`:1132`, `pipelineState.failed/.degraded`), `reopenFailureSignal` (`:1137-1140`), `isCancelledTerminal` (`:1147`) and `isDivertedTerminal`
  (`:1153`) read the raw `isStreaming` / `pipelineState` / `reopenedRunStatus` props. `reopenedRunStatus` is the status of the run the URL names (`app/[...view]/page.tsx:3311-3318`; `reopenedRunIdFor` returns `parsed.runId` for `run-version`, `:208-222`), not of the pinned member.
- Neither `showFailureAffordance` (`:1142`, `!hasContent && isTerminal && terminalFailure`) nor `showDivertedAffordance` (`:1154`) has a term for `overrideActive` (`:1066`) or `viewingVersion`.
  An empty pin makes `!hasContent` true, so both fire for the SHELL's status.
- The Preview-tab branch order is `:1781` shell failure/diverted -> `:1810` streaming -> `:1823` loading -> `:1835` FIX-709's pinned branch -> `:1853` neutral, so the pinned branch is reached only when no shell
  signal fires. [FIX-709](20261002-0147-FIX-709.md) put the pinned branch directly ahead of the neutral one and left every shell signal untouched (its "Deliberately not changed").

The three reported symptoms, each traced:

1. **Cancelled shell.** `reopenFailureSignal` includes "cancelled" -> `showFailureAffordance` -> branch `:1781` -> `DegradedRunAffordance cancelled={isCancelledTerminal}` (`:1807`) -> "This run was cancelled".
   (`showCancelledAffordance`, `:1167`, is a dead constant: nothing reads it.)
2. **Failed or degraded shell.** `terminalFailureNoDeliverable` (`:1164`) is true -> `visibleTabs` drops Preview (`:1185-1187`) and `defaultTabDiscriminator` (`:1260`) forces Audit (`:1291`). `headerFailed` (`:1215`) also
   fires: header "Run failed", Share and Download gone (sibling [ISS-1031](20261002-1040-ISS-1031.md)).
3. **Diverted shell.** `showDivertedAffordance` -> `:1781` -> `DegradedRunAffordance diverted={isDivertedTerminal}` -> "did not complete successfully".

The live path behaves the same: a shell with `pipelineState.failed` or `.degraded` and an empty pin drops the Preview tab (row G8).

**The report's reproduction, as written, models the wrong state.** Extending `pin()` in `olderVersionNullOutput.test.tsx` renders `liveRunId="root"` with `pinnedVersion="1"`, and `members[0]` is `root`: the pin IS the
shell, and one run id carries two contradictory statuses (`getWorkflow` says completed, `reopenedRunStatus` says cancelled). Row G6 reproduces the symptom in that shape, but only a gate on ANY pin turns it green. The app's
state has a DISTINCT shell: use `liveRunId="r1"` (v2) with `pinnedVersion="1"`.

### Fix (recommended; validated on scratch copies, NOT applied)

**Where:** at the four signal definitions in `PreviewPanel.tsx`, not at their consumers. One predicate, defined beside `overrideActive` (`:1066`):

```ts
// The shell signals describe the run the SHELL shows (unpinnedRunId, :854). They stop applying only when a DIFFERENT run is pinned.
const shellOnScreen = viewingVersion == null || viewingVersion.id === unpinnedRunId;
const liveFailureSignal = shellOnScreen && !!(pipelineState?.failed || pipelineState?.degraded);
const reopenFailureSignal = shellOnScreen && (reopenedRunStatus === "failed" || reopenedRunStatus === "cancelled" || reopenedRunStatus === "degraded");
const isCancelledTerminal = shellOnScreen && reopenedRunStatus === "cancelled";
const isDivertedTerminal = shellOnScreen && reopenedRunStatus === "diverted";
// and, for the generating-shell sibling (ISS-1032), at :1810:  ) : isStillRunning && shellOnScreen ? (
```

Every reader in the table routes through those four values, so this one gate also settles the header, Share/Download and the Files banner. It is the "variant C" of `evidence/qa-kb-091/06-analyze-candidate-fix-diffs.txt`.

**Why not the triage sketch** (`!overrideActive &&` on `showFailureAffordance` and `showDivertedAffordance` only; variant A): it restores the Preview tab and the copy, but `headerFailed` is not derived from `showFailureAffordance`, so the
header still reads "Run failed · partial" with Share/Download gone (G1, G2, G9), and the default tab stays Audit.

**Why "foreign pin" and not `!overrideActive`:** `handleSelectVersion` already defines "the pin is the shell" as `memberId === unpinnedRunId` and drops the pin (`:916`), but the URL-pin effect (`:1008-1035`) does not, so
`/runs/{member}/versions/{its own n}` gives `viewingVersion.id === unpinnedRunId`. For that self-pin the shell IS what is on screen. Row G4: today it renders exactly like the unpinned run. A gate on any pin (variants A and B1)
changes it: B1 shows a Preview tab and a settled header, with Share and Download enabled, on a failed run.
