## Why this must also be broken

[ISS-363](20260828-2129-ISS-363.md)'s confirmed root cause is that `pipelineAgents` — the state
array both the modal's embedded canvas and the host page render from — is mutated live by any
`onReorder` call, and the modal's Cancel button never restores it. `onReorder` is not exclusive to
route edits: `AgentsPopup.tsx:2462` wires the SAME `onTreeChange={onReorder}` for every tree edit
`CanvasView` exposes (`CanvasView.tsx:634-635` comment: "every edit round-trips through
`onTreeChange`, the SAME `pipelineAgents` state Save persists") — add-sub-agent (:655), rename
(:659), remove (:662), skills change (:666), root-step move (:686), route change (:750), prompt
edit (:753), and drag-reparent (:1170, :1177) all funnel through it identically.

`AgentsPopup` additionally exposes its own top-level `onAddAgent`/`onRemoveAgent`/`onReorder`
props (agent-library "+" add, roster remove, drag-reorder), wired in both hosts to handlers that
write `pipelineAgents` with no staging and no Cancel-time rollback:

```tsx
// IdeaInputPage.tsx:1501-1542 (wired at :1910-1912)
const handleAddAgent = useCallback((agent, insertBeforeId) => {
  setPipelineAgents((prev) => { /* ...splice, renumber... */ });
}, [...]);
const handleRemoveAgent = useCallback((agentId) => {
  setPipelineAgents((prev) => prev.filter((a) => a.id !== agentId));
}, []);
const handleReorderAgents = useCallback((reordered) => {
  setPipelineAgents(reordered);
}, []);
```

`LaunchWizard.tsx:551-577` mirrors the same three handlers over its own `pipelineAgents` state.
Nothing about these three differs mechanically from the route-editor write `onRouteChange` makes
through the identical `onTreeChange`/`onReorder` chain — they are the same broken function, called
from a different UI affordance (the roster list / agent-library "+" button / drag handle instead
of the route pill).

## Expected vs actual

**Expected:** adding an agent, removing an agent, or dragging the roster into a new order inside
the Advanced modal, then clicking Cancel, should leave the roster exactly as it was when the
modal opened.

**Actual (INFERRED — not yet independently reproduced):** the roster change should persist across
Cancel + reopen, visibly changing the launch panel's "N agents" count and the background canvas,
for the same reason the route-outcome edit does.

## What would confirm or refute this

From `/create/ex_A2_branch` (or any workflow with a removable/optional agent), open "Advanced",
remove one optional agent (or drag-reorder two root steps), click Cancel, reopen. A miss (the
roster reverts) would mean `onAddAgent`/`onRemoveAgent`/`onReorder` have a rollback this analysis
did not find, and would refute this card without affecting [ISS-363](20260828-2129-ISS-363.md)'s
route-editor finding, since both write the same state through the same prop but are invoked from
different call sites.

## Where the fix belongs

Identical to [ISS-363](20260828-2129-ISS-363.md) — inside `AgentsPopup.tsx`'s staged-draft layer.
Since `onAddAgent`/`onRemoveAgent`/`onReorder` (including the canvas's `onTreeChange`) all
resolve to the SAME host-level `pipelineAgents` write, the single snapshot-and-restore-on-Cancel
fix [ISS-363](20260828-2129-ISS-363.md) proposes covers this sibling for free — no separate
handling per affordance is needed once `AgentsPopup` stops forwarding every edit straight through
to the host on every keystroke.
