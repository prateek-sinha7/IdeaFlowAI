## Symptom

On an open run, clicking **Steps** showed **Preview** first, sat there for about a
second, then jumped to Steps with a visible jerk. Reported for every tab —
Steps, Files, Workspace, Audit — not one of them.

## Root cause

A run tab click was a full router navigation.

`DashboardLayout.handlePreviewPanelTabSelect` (`frontend/src/components/layout/DashboardLayout.tsx:471`)
mapped the clicked tab id onto a route and called `router.push(targetRoute)`. That
changes the `[...view]` catch-all's params, and Next does not preserve a dynamic
route's page instance across that — **`page.tsx` remounts** (already documented at
`frontend/src/app/[...view]/page.tsx:3109`, "confirmed live", and the mechanism
behind [FIX-302](20260825-2115-FIX-302.md)).

The remount wipes every page-local run state — `pipelineState`, `contentSourceRunType`,
`submittedBrief`, `trackedRunIdRef` — so the cold-mount effect's
`if (runId === trackedRunIdRef.current) return` guard misses and it re-runs
`handleSelectWorkflowRun` in full. Two consequences stack into the jerk:

1. The freshly-mounted `PreviewPanel` starts on its own default,
   `useState<PanelTab>("preview")` (`PreviewPanel.tsx:492`) — hence Preview.
2. The clicked tab is only re-applied by the deep-link nonce, minted in that
   fetch's `.finally()` (`page.tsx:3163`) — hence the ~1s wait and the jump.

So the flash was not a CSS/animation problem at all: the panel was genuinely
being destroyed and rebuilt, and the requested tab deliberately waited on a
network round-trip that a client-side tab switch never needed.

## Blast radius

- **All five run tabs** (Preview/Steps/Files/Workspace/Audit) — one handler, one
  choke point, which is why the report covered every tab.
- **The full run re-fetch per click**: `getWorkflow` + `getRunEvents` durable
  replay on every tab switch, and for a live run the re-seed branch at
  `page.tsx:3117` replayed the whole event log again.
- **The Workspace tab "disappears on click" glitch** seen while building spec 017
  phase 2 is the same defect — `SandboxTab` mounted, then was torn down with the
  page.
- **[FIX-302](20260825-2115-FIX-302.md)** patched the *consequences* of this
  remount (re-seed refs, rehydrate brief/type from sessionStorage, replay durable
  events). Those paths still stand and are still needed for the launch-time
  remount; this card removes the remount for the tab-click case, which is what
  drove most of them.
- Not affected: every other `router.push` in the app. A screen change (home,
  history, library, settings, composer) is a real navigation and a remount there
  is correct.

## What was fixed

1. **`DashboardLayout.tsx:483`** — the tab handler now does
   `window.history.pushState(null, "", targetRoute)` instead of `router.push`, and
   no-ops when the path already matches. Next patches `pushState`
   (`next/dist/client/components/app-router.js:252`) to update `usePathname` /
   `useSearchParams` while leaving the router tree alone, so the URL stays
   shareable and refreshable with no remount and no refetch. `router` dropped
   from the callback's deps.
2. **`page.tsx:352`** — `viewSegments` now derives from `usePathname()` instead of
   `useParams()`. `useParams` is fed by the router tree, which `pushState`
   deliberately does not touch, so params-derived routing would have gone stale on
   every tab switch and on the back/forward after it. Segments are split from the
   pathname and `decodeURIComponent`d to match what `useParams` returned.
3. **`page.tsx:3107`** — the "already tracked, skip the fetch" early return now
   mints the deep-link tab before returning, mapping `run-detail` to `"preview"`
   *in that branch only*. Without a remount this is the only branch a tab click or
   a back/forward reaches. The cold-mount path keeps its `.finally()` timing on
   purpose: minting the nonce before the fetch lands would let the state-keyed
   default-tab effect stomp it back to Preview once `headerRunState` flips (the
   exact race documented in `PreviewPanel.tsx`'s merged effect).
