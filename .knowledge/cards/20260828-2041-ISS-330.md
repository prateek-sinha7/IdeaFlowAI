## Root cause (traced, same mechanism as ISS-231)

`state.agents.status` (and the equivalent skills/hooks slices) is typed
`"idle" | "loading" | "succeeded" | "failed"` (`frontend/src/store/slices/agentsSlice.ts:9`).
`LibraryPage.tsx` reads all three into `agentsStatus`/`skillsStatus`/`hooksStatus`
(`LibraryPage.tsx:431-433`), but every render-site ternary in the file special-cases **only**
`=== "loading"`:

- `LibraryPage.tsx:732` — `agentsStatus === "loading" ? <skeletons> : filteredAgents.map(...)`
- `LibraryPage.tsx:793` / `815` — `skillsStatus === "loading" ? <skeletons> : ...`
- `LibraryPage.tsx:893` / `911` — `hooksStatus === "loading" ? <skeletons> : ...`

Every other status value — `"idle"`, `"succeeded"`, and specifically `"failed"` — falls through to
the exact same bare `.map()` over whatever the slice's data array currently holds. On a failed
fetch that array is typically still empty (the thunk never populated it), so this hits the
identical missing `length === 0` branch [ISS-231](20260828-1630-ISS-231.md) already proved exists
at `LibraryPage.tsx:735`/`818`/`914` — except here the cause is a network/API failure, not a
legitimate zero-result filter.

## Expected vs actual

- **Expected:** a failed `GET /api/agents/library` (or the skills/hooks equivalent) shows explicit
  error messaging, distinguishable from both the loading skeleton and a legitimate zero-result
  empty state.
- **Actual (inferred):** the grid renders exactly the same blank content area as ISS-231's
  zero-result case, with nothing distinguishing "the fetch failed" from "your search matched
  nothing."

## Why the root cause implies this

ISS-231's own "Actual" section already names this ambiguity without resolving it: "A user cannot
tell whether the app is broken, still loading, or genuinely has zero matches." The reported bug
proves the "genuinely zero matches" leg. Reading the code shows the "app is broken" leg (fetch
`failed`) shares the identical render path — only `"loading"` is ever special-cased, so `"failed"`
inherits the same blank-page symptom, for a materially worse reason: the data never arrived at
all, not just an empty filter result. A fix that adds a `length === 0` empty-state branch but
still does not branch on `status === "failed"` would leave this leg silently broken.

## Reproduction (to confirm)

1. Block or force-fail `GET /api/agents/library` (devtools request blocking, or a backend-down
   window) before loading `/library`.
2. Load `/library` (Agents tab).
3. Expect: same blank grid as ISS-231, no error text/icon/retry affordance.
4. Repeat for the skills/hooks endpoints on their respective tabs.
