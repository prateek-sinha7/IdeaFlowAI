## What was wrong

`PrototypePreview.tsx`'s browser-chrome bar — the row holding the macOS-style dots,
URL pill, zoom trio, divider, Tweaks, Source and Open buttons — was a non-wrapping
flex line with no `flex-wrap` or `overflow-x` anywhere in its ancestor chain.
[ISS-433](20260829-0040-ISS-433.md) identified this as the same anti-pattern
[ISS-314](20260828-1946-ISS-314.md) confirmed on `PreviewPanel.tsx:1203`: at a
375 px viewport the content box is narrower than its children and the overflow
controls leave the viewport with no pointer or touch path to reach them.

## Root cause

`PrototypePreview.tsx` (the "browser chrome" section of `PrototypePreview`):

```tsx
// Before
<div className="flex-shrink-0 bg-white border-b border-gray-200 px-3 py-2 flex items-center gap-2">
```

No `flex-wrap` on this container; no `overflow-x` fallback. All right-side buttons
(`Tweaks`, `Source`, `Open`) can push past the viewport edge at narrow widths.

## What changed and why there

One word added to the outer browser-chrome div — `flex-wrap` — replicating the
exact shape of [FIX-378](20260829-0207-FIX-378.md) on `PreviewPanel.tsx:1203`:

```tsx
// After
<div className="flex-shrink-0 bg-white border-b border-gray-200 px-3 py-2 flex flex-wrap items-center gap-2">
```

At any viewport where all children fit on one line the rendering is byte-identical
to before. Below that threshold the right-side button cluster wraps to a second
line and stays within the viewport. `gap-2` already provides the 8 px row gap the
wrap needs — no additional spacing token required.

Nothing else changed. No backend file, no test, no migration, no import edge.
