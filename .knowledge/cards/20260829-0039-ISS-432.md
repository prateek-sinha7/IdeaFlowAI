## Resolution

Verified fixed in the current code on 2026-10-01 (feat/user-stories-v2 @ 3b08b2ba8) by static review: a first-pass check and an independent adversarial re-check both found every claim of this card fixed. No tests were run for this closure.

**Fixed by:** [FIX-375](20260829-0151-FIX-375.md) (commit d027f16bd)

**Evidence:** ComposerPage.tsx:1368-1381: Save onClick is the only handleSave call site (grep: only line 1381). If !name.trim() it calls setSaveError("Name the workflow first, then save.") and focuses the input. The saveError banner renders at :1666-1669 (text-status-failed). Every composer route (/workflows/new, /edit via initialName at DashboardLayout.tsx:3248, built-in save-as-copy) mounts this same component, so all share the guard. Nothing is lost on an empty name because it returns before any request, and the edit route's unsaved canvas state stays in place. The commit that added the string is d027f16bd.

**Left over (outside this card's claims):** None blocking. Minor: the banner stays until the next save attempt even after the user types a name (cosmetic). The card file still says status: open. I found no "Name the workflow" assertion in ComposerPage.test.tsx, though [FIX-375](20260829-0151-FIX-375.md) lists it as a test file.
