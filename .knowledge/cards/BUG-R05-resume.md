### BUG-R05 — od_prototype restart-resume of a run parked at the SPEC review gate re-runs the WHOLE pipeline from clarify instead of re-entering the gate: the resume offset is legitimately 0 (the gated agent `prototype-specify` is step INDEX 0), but `_execute_impl`'s "am I resuming?" predicate is `_resuming = _resume_from > 0`, which reads offset 0 as a FRESH start — so the planner + auto-clarifier re-run and the ClarifyEngine re-parks the run BEFORE the 49-02 gate-reentry sentinel block is ever reached (offset 0 is OVERLOADED: "start at step 0 fresh" vs "re-enter step 0's open gate")  [severity 🟠 moderate] [FIXED ✅]
- **Found by:** R-C gate-resume re-test post-`e1866317` on 2026-07-19 · run id `43a0d562-a0b5-4aed-b523-5b96d4007a0b` (od_prototype, parked at the spec review gate `prototype-specify`; clarify already answered + spec agent already completed). Same offset-0 + re-clarify reproduced on two other parked od_prototype gate runs (`26299240...`, `0139f9de...`) on the SAME restart. **DOWNSTREAM of / UNMASKED by the BUG-R01/R02 alias fix (commit `e1866317`)** — that fix removed the empty-roster bail (old `resume_run:7304-7308`) so `resume_run` now REACHES the offset/re-entry code this bug lives in.
- **Symptom:** `kill -9` + bare-uvicorn restart of a run parked at the spec gate (pre-restart durable events include `questionnaire_ready`×1 → `questionnaire_complete` [clarify answered], `agent_complete`[prototype-specify], `review_gate_ready`[prototype-specify]; event count 3789). Restore logged `resume_run(43a0d562...): resuming pipeline=od_prototype at step offset 0/5`. The difference is the OFFSET (user_stories 2/6 > 0; od_prototype spec-gate 0/5), NOT the pipeline identity.
- **Expected:** Phase 49 SC-2/SC-3 + design-draft §5.5: a step with a produced artifact + an OPEN review gate is the resume point and must be re-entered IN GATE MODE — re-emit `review_gate_ready`, re-arm the waiter, do NOT re-run the agent, do NOT re-clarify. (BUG-R02 is the sibling that black-holed the SAME `prototype-specify` gate before `e1866317`; this is the next defect on that path.)

  - **Why offset 0 then re-runs the whole preamble — the OVERLOADED predicate (THE ROOT CAUSE).** `resume_run` drives `_execute_impl` with `_resume_from=0, _is_resume=True` (`engine.py:7406-7419`).
