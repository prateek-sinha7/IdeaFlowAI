# ISS-1065

Noticed while [FIX-736](20261007-1940-FIX-736.md) removed the dead `POST /api/auth/register` entry from
`tests/integration/capture/API-CONTRACT.json` ([ISS-1017](20261002-0617-ISS-1017.md)). Open and not analyzed. Everything below
was read or run offline. The live tier was not run.

## 1. The snapshot scenarios cannot fail (read)

`tests/integration/e2e/suites/24_api_contract/test_api_contract.py`, `regenerate()`:

```python
out = subprocess.run([sys.executable, str(CAPTURE / "_api.py"), "--json"], capture_output=True, ...)
assert out.returncode == 0, ...
return json.loads(SNAPSHOT.read_text())
```

`_api.py --json` only prints to stdout (`print(json.dumps(endpoints, indent=2))`; it writes no file). `regenerate()` throws
that output away and re-reads the committed snapshot. So S-24-01 (inventory matches), S-24-02 (no endpoint loses its
authentication) and S-24-03 (public list) each compare the snapshot with itself. INFERRED: they pass whatever the source
says. Presumably the fix is `json.loads(out.stdout)`.

## 2. The snapshot has drifted, and nothing flagged it (run)

`python3 tests/integration/capture/_api.py --json`, diffed against the committed snapshot after FIX-736:

- added in source, not in the snapshot (10): `DELETE /api/runs/{workflow_id}/share`, `GET /api/admin/capacity`,
  `GET /api/runs/{run_id}/sandbox/refs`, `POST /api/admin/users/{user_id}/disable`, `POST /api/admin/users/{user_id}/enable`,
  `POST /api/runs/uploads/stage`, `POST /api/runs/{run_id}/figma-export`, `POST /api/runs/{run_id}/restore`,
  `POST /api/runs/{workflow_id}/share`, `POST /api/user-workflows/{workflow_id}/sync-from-file`;
- changed (4): `PATCH /api/user-workflows/{workflow_id}`, `POST /api/runs/{run_id}/messages`, `POST /api/runs/{run_id}/resume`,
  `POST /api/runs/{run_id}/revisions`;
- removed: none. The one stale removal, `POST /api/auth/register`, was taken out by FIX-736.

Evidence: `evidence/qa-kb-077/fix-04-static-checks.txt`.

## 3. The generator misreads principal-authenticated routes as public (read)

The four "changed" rows flip `auth` from `user` to `public` in the fresh output. `_api.py::auth_of` matches
`get_current_admin|require_admin|admin_user`, then `get_current_user|current_user|get_current_active`. It has no pattern for
`get_current_principal`. Those four handlers take it, for example
`backend/app/api/run_commands.py:628`, `auth: tuple[User, Principal] = Depends(get_current_principal)`. So the routes are
authenticated, and the generator reports them as public.

If section 1 were fixed alone, S-24-02 would turn red with four false "lost their authentication" reports. The generator
needs the principal dependency before the snapshot is regenerated. `24-api-contract.feature.md` also needs its counts redone
(it describes the 110-endpoint snapshot; S-24-02's "84 user" was already stale before FIX-736).
