## What was lost

`My presentation` — `da92b4a4-7eff-41b5-9b9a-205cfa1616d9`

```
agent_ids:  [ppt-brief-analyst, ppt-composer, ppt-validator]   # report-generator gone
created_at: 2026-08-25T17:44:26     updated_at: 2026-08-29T12:17:40
```

The base `ppt` manifest is exactly those three
(`agents/workflows/ppt/workflow.yaml`), so the row now carries no override at
all. It was updated during the weekend bug-hunt window; the same database holds
41 saved workflows including hunt artefacts (`Bug Validate PPT Copy C1/C2`,
`PPT Save Flow Test 2`, `QA Gate Reject Test`).

## What it blocks

- `05_saved_workflows::test_a_saved_overrides_run_panel_reports_the_base_agent_count`
  (D-05) — roster 4 vs panel 3 is the whole defect; with both at 3 there is
  nothing to observe. It now SKIPS with this reason named.
- `04_composer_canvas::test_editing_a_saved_workflow_loads_its_steps` — `3 == 4`.

## Decision needed, not code

Adding `report-generator` back to that saved workflow makes both run again with
no test change — D-05's skip is written to lift by itself. The alternative is
re-pointing the tests at a different override. **Someone must choose**; neither
is a fix an engineer should make unilaterally, and no other saved workflow in
the database currently carries a roster that differs from its base.
