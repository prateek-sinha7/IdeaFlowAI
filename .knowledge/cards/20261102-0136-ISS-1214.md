## What is broken

`_frame_parts` in `backend/app/api/run_figma_frames.py` runs only when a frame is uploaded.
Frames uploaded before commit `17f4f4f5d` were stored as one file and are not rewritten.
An agent that reads such a frame gets one of two results:
- a frame over 8000 px per side, or over 5 MB as base64, is replaced by the guard placeholder;
- a frame between 2000 and 8000 px per side, or between 3.75 MB and the limit, is sent whole.

## Evidence

Stated in the fix workflow's `report.md` (`.agents/tasks/fix-image-size/report.md`), which
records that frames uploaded before the change are not rewritten. Not reproduced on a
stored frame.

## Disposition

Open. Options:
1. Re-tile on read, which needs a separate path that keeps the original file unchanged.
2. Ask users to re-upload affected frames.
3. Leave as is and accept the placeholder for the largest frames.

The 2,000 px-per-side case also overlaps with ISS-1213, which covers requests with more than 20 images.
