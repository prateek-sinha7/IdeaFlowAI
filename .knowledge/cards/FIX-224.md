## Description

During an active pipeline run, the agent progress circles in the Steps panel
and the agent input/output live views flickered rapidly.

## Root Cause

In `useRunStateStore.handleFrame`, after every SSE frame:

```typescript
const fakeSetState = (updater) => {
  const prev = entry.pipelineState;
  const next = typeof updater === "function" ? updater(prev) : updater;
  entry.pipelineState = next;  // always a new object from the reducer
};
handlePipelineMessage(flatMsg, fakeSetState, agentStartTimes);
// ...
project({ ...entry });  // always a new outer object
```

The `project()` function's bail-out:
```typescript
if (prev.pipelineState === state.pipelineState && ...) return prev;
```

**Never fired** because:
1. `fakeSetState` always stores a new object into `entry.pipelineState` (the reducer's
   functional updater always returns `{ ...prev, ... }`)
2. `project({ ...entry })` always creates a new outer object

So `prev.pipelineState !== state.pipelineState` on every call → `setViewedState` fires
on every single SSE frame → React re-renders the entire component tree at SSE frame rate
(dozens per second during active streaming) → flickering.

## Fix

Added `lastProjectedPipelineStateRef` — a ref tracking the last `entry.pipelineState`
reference that was passed to `project()`. Before calling `project()` in `handleFrame`,
check if `entry.pipelineState !== lastProjectedPipelineStateRef.current`:

- If **different** (reducer produced a new object → real state change): update ref + call `project()`
- If **same** (reducer returned `prev` unchanged → idempotent re-delivery): skip `project()`

Also reset the ref in `switchViewTo` so the new run's state is always projected fresh.

This means `setViewedState` only fires when `pipelineState` genuinely changed — once per
SSE frame that actually mutates state, not on every frame unconditionally.
