# ISS-1014

Sibling of [ISS-906](20261001-2200-ISS-906.md) (bug QA-KB-078), found while grepping every consumer of the stale
`app_builder` goldens. Confidence: **CONFIRMED** (reproduced and diffed, not inferred).

## Condition

`backend/tests/integration/agents/test_wire_parity.py::test_wire_parity_matches_golden[app_builder]` fails at HEAD
`024c03ef8`. Running that one file: `1 failed, 4 passed in 22.39s`; `[prototype]`, `[ppt]`, `[prototype_revision]` and
`test_wire_parity_gate_is_non_vacuous` pass. The assertion is `WIRE PARITY DRIFT: the run_events->SSE projection diverged
from the recorded WS frame sequence` (`_sse_projection.py:208`); the two 100-frame type sequences are identical, so only a
payload differs.

## Cause

Same stale payload as [ISS-906](20261001-2200-ISS-906.md), third consumer. `golden/app_builder.wsframes.json:1204` is
`"final_output": "```filename: .family.lock\n\n```\n\n```filename: README.md\n# Generated App ..."`, while
`is_deliverable_relpath` (`sandbox.py:1580`) has dropped that block since `f9df3737c` added `.family.lock` to
`_DELIVERABLE_EXCLUDE` (`sandbox.py:68`; [FIX-647](20260929-1024-FIX-647.md)). The golden was last written at `bd3ca6e68`
(2026-09-12), before `f9df3737c` (2026-09-29); `git merge-base --is-ancestor` confirms the order.

Read-only re-derivation of what `SNAPSHOT_UPDATE=1` would write: `_drive("app_builder")` ->
`ws_frame_from_engine_event(ev, section="app_builder")` -> `_canonical_order(_normalize(...))` -> the writer's own
`json.dumps(data, indent=2, sort_keys=True, ensure_ascii=False)` (`_normalize.py:394`), diffed against the committed file,
nothing written into the repo. Result: ONE differing leaf (`$[95].data.final_output`), ONE differing line (:1204),
34423 -> 34387 bytes. Nothing else in the 100 frames moved.

## Why the QA-KB-078 fix sketch misses it

The sketch regenerates by running `SNAPSHOT_UPDATE=1` on `test_characterization_app_builder.py`. That file writes only
`app_builder.txt` (`:42`) and `app_builder.events.json` (`:71`). `app_builder.wsframes.json` is written only by
`test_wire_parity.py::_record_golden` (`:80-89`, called under SNAPSHOT_UPDATE at `:114`). Done literally, the sketch leaves
`app_builder.wsframes.json` stale and this test red, and the "both tests" wording in ISS-906 / QA-KB-078 hides that.

## Disposition

Open. Fix shape (test data only, `sandbox.py` untouched):

    cd backend
    SNAPSHOT_UPDATE=1 .venv/bin/python -m pytest tests/integration/agents/test_wire_parity.py -k app_builder -p no:cacheprovider

then re-run the file with `SNAPSHOT_UPDATE` unset. Expected `git diff`: one changed line in
`golden/app_builder.wsframes.json`. Keep `-k app_builder`: at analysis time (2026-10-02) `prototype.wsframes.json` carried
another session's uncommitted `output_length` edit, which an unscoped regeneration would overwrite. Land it together with
the ISS-906 regeneration so the three `app_builder` goldens move as one.

Evidence: run of `tests/integration/agents/test_wire_parity.py` (1 failed, 4 passed, 22.39 s); the read-only byte diff
above; `test_wire_parity.py:114` `_record_golden(pipeline, ws_frames)`; `test_characterization_app_builder.py:42,71`.
