## Origin

Sibling of [ISS-678](20260917-1449-ISS-678.md), derived during the analysis of register entry
**QA-KB-064** (`LEDGER.md`). ISS-678's root cause is that `RunSandbox.has_git` is asserted by the
constructor (default `True`) and never reconciled with the disk. This card is the part of that
flaw a user can see. Status: **CONFIRMED** end to end in-process (in-memory SQLite + `TestClient`,
temp `RUNS_ROOT`, no live DB, no server). Not driven through the browser.

## Condition

A run whose sandbox directory was removed by the TTL sweeper (`sweep_expired`,
`backend/app/agents/sandbox.py:1407-1465`, `RUN_DIR_TTL_HOURS = 168`) is opened on the run-detail
page.

## Expected vs actual

- **Expected:** the Files tab keeps saying "Workspace expired". `GET /api/runs/{id}/sandbox` returns
  `expired: true` (its documented meaning, `run_files.py:920-925`) for as long as the directory is
  gone, and nothing on a read path creates it.
- **Actual:** the version-dropdown feed `GET /api/runs/{id}/sandbox/refs` creates an empty
  sandbox directory. Every later `GET /sandbox` returns `expired: false, files: []`, and the Files
  tab shows an empty workspace instead of "Workspace expired" (`SandboxTab.tsx:1174` `setExpired`,
  `:1310-1313` the expired empty state). The new directory carries a fresh mtime, so the sweeper
  will not remove it for another 168 hours. `<RUNS_ROOT>/<user>/.latest` is also re-pointed at the
  dead run.

## Why the root cause implies it

[ISS-678](20260917-1449-ISS-678.md): an API-built `RunSandbox` claims `has_git=True` whether or not
the directory, let alone a `.git`, exists. With the flag true, `list_tags()` is allowed through to
the workspace, and building the workspace creates the directory.

## Mechanism (read, then probed)

1. `RunHeader.tsx:304-316` calls `getRunSandboxRefs` on mount for **every** run state, so every
   run-detail view of a swept run fires the request.
2. `list_sandbox_refs` (`backend/app/api/run_files.py:886-911`) resolves the chain root and builds
   `RunSandbox(current_user.id, _chain_root_id, runs_root=settings.RUNS_ROOT)` (`:905`) with the
   default `has_git=True`. It has **no** `sandbox.root.is_dir()` check before `list_tags_fn()`
   (`:906-910`).
3. `RunSandbox.list_tags` (`sandbox.py:934-936`): `if not self.has_git: return []`, otherwise
   `getattr(self._ws(), "list_tags", None)`.
4. `RunSandbox._ws` (`sandbox.py:628-643`) calls `self.ensure()` first (`:634`).
   `ensure` runs `self.root.mkdir(parents=True, exist_ok=True)` (`:683`) and `_repoint_latest()`
   (`:688`). `LocalWorkspace.__init__` calls `sandbox.ensure()` again (`local.py:321`).

The other ref-aware routes are not affected, because each checks the directory first:
`list_sandbox` (`run_files.py:941`, and the `expired` check before `_validate_ref` at `:948`, which
is [ISS-893](20261001-2120-ISS-893.md)'s fix), `download_sandbox_zip` (`:1044`),
`read_sandbox_file` (`:1156`) and `restore_version` (`runs.py:2518`). `/sandbox/refs` is the only one
with no guard.

## Evidence (probe, 2026-10-02)

`backend/.venv/bin/python` from `backend/`, with the `env` fixture shape of
`backend/tests/integration/api/test_run_files_ref_family_scope_api.py:45-85`:

```
sandbox dir exists before any call (a TTL-swept run): False
1. GET /sandbox        -> 200 {'expired': True, 'files': []}
   dir exists: False
2. GET /sandbox/refs   -> 200 []
   dir exists: True | .latest -> 3586e487-c47c-45aa-8b82-ba295a31d255
3. GET /sandbox again  -> 200 {'expired': False, 'files': []}
RESULT: 'Workspace expired' signal lost after GET /sandbox/refs: True
```

Seam level: `RunSandbox("u", "swept-run", runs_root=...).list_tags()` on a non-existent root returns
`[]` and leaves the directory behind; the same call with `has_git=False` leaves it absent.

**Fix prototype, not applied to source.** Replacing `run_files.RunSandbox` with a factory that sets
`sb.has_git = (sb.root / ".git").exists()` right after construction turns step 2 into
`dir exists: False | .latest -> None` and step 3 into `expired: True`.

## Fix direction

Same change as the root card: derive `has_git` from the disk for API-built read-side sandboxes
(for example `RunSandbox.for_existing(...)`, set before any `_ws()` call because `_ws()` snapshots
the flag into `LocalWorkspace.has_git`, `sandbox.py:635-642`). A derived `False` makes `list_tags()`
return `[]` before `_ws()` is reached. An early `refs: []` return when `not sandbox.root.is_dir()`
in `list_sandbox_refs` is a cheap belt-and-braces guard and also fixes this card on its own.

Do **not** fix it by making `ensure()` conditional: the engine depends on `ensure()` creating the
root (`engine.py:4404`), and `LocalWorkspace.__init__` calls it too.

## Resolution — FIX-727 (2026-10-07)

Resolved by [FIX-727](20261007-1837-FIX-727.md), the root card's fix. `RunSandbox.list_tags` now returns `[]` before
`_ws()` when `(root / ".git")` does not exist (`sandbox.py:938`), so `GET /sandbox/refs` on a swept run never builds
the workspace. Nothing is created, `.latest` is not re-pointed, and `GET /sandbox` stays `expired: true`. No frontend
change was needed.

The test is `backend/tests/integration/api/test_sandbox_refs_swept_run_api.py`, the "Test notes" snippet above plus a
`.latest` assertion:

- On the pre-fix code it failed with "GET /sandbox/refs re-created the swept sandbox directory".
- After the fix it passes (`evidence/qa-kb-064/fix-01`, `fix-04`, `fix-08`).
