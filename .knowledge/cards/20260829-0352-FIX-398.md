## What was wrong

`BUG-20260828-050900-settings-profile`: on `/settings/profile`'s Password card, "Current
password" and "New password" each rendered an eye-icon button that flipped the input between
`type="password"` and `type="text"`; "Confirm new password" — the field whose only job is letting
the user check they retyped correctly — had none and could never be revealed. Reproduced 3/3 on
cold loads, no axis needed.

## Root cause

Not a typo in one field: the reveal affordance was **opt-in per call site**, because
`frontend/src/components/ui/` had no masked-input primitive. Each password `<input>` in the app
hand-rolled its own `show*` boolean and eye button, so whether a field got one depended entirely
on whether that call site's author wired it.

- `frontend/src/components/settings/AccountSettings.tsx:98-99` — `showCurrent` / `showNew` state,
  toggle buttons at `:292-294` and `:304-306`; the confirm input at `:309-314` was hardcoded
  `type="password"` with no matching `showConfirm` and no button ([ISS-338](20260828-2050-ISS-338.md)).
- `frontend/src/app/login/page.tsx:455-485` — the Cognito `NEW_PASSWORD_REQUIRED` ChallengeForm's
  "New password" and "Confirm password", both hardcoded `type="password"`; the file imported no
  `Eye`/`EyeOff` at all ([ISS-576](20260829-0218-ISS-576.md)).
- `frontend/src/app/admin/page.tsx:494-499` — the "Create New User" modal's Password field, same
  absence ([ISS-577](20260829-0219-ISS-577.md)).

## What changed and why there

**New:** `frontend/src/components/ui/PasswordInput.tsx` — a primitive that owns its own `show`
state, spreads the caller's props onto the input, and renders the toggle as the input's immediate
next sibling inside a `relative` wrapper. It appends `pr-10` to the caller's `className` so the
icon never overlaps text, and carries an `aria-label` ("Show password" / "Hide password") because
the button is icon-only. The button styling is lifted verbatim from the AccountSettings toggle it
replaces, so the two fields that already had one look unchanged.

Fixing it here rather than adding a `showConfirm` to `AccountSettings.tsx` is what makes the two
sibling cards go green with no further edits: the reveal is now structural, and a future password
field gets it by construction rather than by remembering.

**Rewired to it (six fields, no behaviour change beyond the toggle):**

- `AccountSettings.tsx` — all three password fields; `showCurrent`/`showNew` state and the
  `Eye`/`EyeOff` import removed as orphaned by the change (`grep` confirms no other use in the
  file).
- `login/page.tsx` — ChallengeForm's "New password" and "Confirm password"; `required`,
  `autoComplete`, `minLength={12}` and the placeholder all carry through unchanged.
- `admin/page.tsx` — the create-user "Password" field.

The main sign-in password field at `login/page.tsx:303-317` was deliberately **not** converted —
no card covers it and its Lock-icon wrapper is a different shape. Filed as
[ISS-602](20260829-0353-ISS-602.md) rather than folded in silently.
