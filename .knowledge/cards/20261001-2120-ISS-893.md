# ISS-893

Register entry: **QA-KB-027** (`BUGS.md`). Sibling of [ISS-724](20260922-1246-ISS-724.md) (root), found by
actually exercising the "fresh sandbox edge case unverified" item rather than guessing at it. API behaviour is
**CONFIRMED** (code read plus a route-level probe against real git); the user-visible reachability is **INFERRED**.

## Condition

A run family whose sandbox directory has been TTL-swept (`RUN_DIR_TTL_HOURS = 168`, `backend/app/core/config.py:406`),
viewed with a version tag pinned, so the Workspace tab asks for `GET /api/runs/{id}/sandbox?ref=vN`.

## Expected vs actual

- **Expected**: the same "Workspace expired" outcome the other two ref-scoped endpoints give, and the
  `expired: true` signal `list_sandbox` is documented to return (its docstring: "`expired` is the real signal for a
  TTL-swept run ... The UI renders a 'workspace expired' state on it rather than a bare empty tree").
- **Actual**: `400 {"detail": "invalid ref"}`.

| state of the sandbox | `GET /sandbox/file?ref=` | `GET /sandbox/zip?ref=` | `GET /sandbox?ref=` (listing) |
|---|---|---|---|
| swept (directory removed) | 404 Workspace expired | 404 Workspace expired | **400 invalid ref** |
| git-initialised, no tags yet | 400 invalid ref | 400 invalid ref | 400 invalid ref |

Probe: scratch test outside the repo, real `RunSandbox` + real git + `TestClient`; the swept row is `shutil.rmtree` of
the sandbox root after tagging. Output: `C expired file/zip/listing: 404 404 400 {"detail":"invalid ref"}`.

## Root cause — CONFIRMED (read)

`list_sandbox` computes `expired = not sandbox.root.is_dir()` at `backend/app/api/run_files.py:941`, then, when
`ref` is set, validates it before consulting `expired` (`:945-946`, `safe_ref = _validate_ref(ref, sandbox)`).
`_validate_ref` is fail-closed (`:872-882`): a swept sandbox has no tags, so `ref not in valid_tags` (`:878`) is
true and it raises 400. The other two endpoints check the directory first:
`download_sandbox_zip` `:1041-1044` and `read_sandbox_file` `:1153-1156` both raise `404 "Workspace expired"` before
`_validate_ref` (`:1053`, `:1163`). So under a pinned ref the listing's `expired` flag can never be returned.

Frontend consequence (CONFIRMED by reading): `SandboxTab.tsx:1170-1185` calls `getRunSandbox(token, runId,
selectedRef)`; `setExpired(res.expired)` (`:1174`) runs only on a 200, and the `.catch` (`:1185`) sets
`setListError(err.message)`. A pinned version of a swept family therefore shows a list error instead of the
"Workspace expired" empty state that [ISS-356](20260828-1910-ISS-356.md) / [FIX-404](20260829-0418-FIX-404.md) tuned.

Reachability (INFERRED): `sandboxSelectedRef` starts `null` and is set only when the user picks a tag in the
VersionMenu (`PreviewPanel.tsx:808`), so this needs a family older than 7 days with a non-latest version selected.

## Why the root cause implies this

[ISS-724](20260922-1246-ISS-724.md) is a coverage gap on the pinned-ref routes. The ref branches re-implement the live
branches' guards one by one, and no test combined a pinned ref with an expired workspace: `tests/unit/test_run_sandbox_api.py`
covers expiry without a ref (28 passed) and every ref test uses a live sandbox.

## Fix — where it belongs

`list_sandbox` is the only caller of this ordering, and the fix is one guard in it:
`if ref is not None and not expired:` so an expired workspace falls through to the live branch
(`run_files.py:979-1001`), which already returns `{expired: true, files: []}` and which the frontend already renders.
A 404 like the siblings would also be correct at the API but would not reach `setExpired`; the guard form needs no
frontend change. Pin it with an `xfail(strict=True)` test (`ref=v1` on a swept sandbox expects 200 and `expired: true`)
so it flips to XPASS when fixed.

Same pattern, **not filed** (INFERRED from reading, not probed): the ref branch of `read_sandbox_file`
(`:1162-1196`) has no counterpart of the live branch's `_SANDBOX_MAX_READ_BYTES` 413 (`:1215-1223`).
[ISS-704](20260922-1234-ISS-704.md) closed only the zip cap.

## Fix (2026-10-01)

Fixed by [FIX-691](20261001-2149-FIX-691.md) with the guard proposed above: `backend/app/api/run_files.py:948` is now
`if ref is not None and not expired:`. A swept sandbox under any ref answers `200 {expired: true, files: []}` from
the live branch, which the frontend already renders; a live sandbox still validates every ref. Observed: the strict
pin `test_pinned_ref_listing_of_swept_sandbox_is_expired_payload` reports XPASS(strict). The marker is left for the
6-verifier.
