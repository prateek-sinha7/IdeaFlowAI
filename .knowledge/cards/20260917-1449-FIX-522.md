## What was wrong

This is register bug **QA-PS-008** (`/runs/{id}`). The version dropdown listed `Latest (live)`
plus seven tags (`v0.2.0`, `v0.0.2`, `v0.0.1`, `pre-rebase-safety`, `pre-fixes-reset`,
`deploy-prod-20260603-014226`, `deploy-prod-20260603-012557`). Those are the Flowin source
checkout's own tags. Picking one left Preview on `Loading {tag}…`. The corrected root cause is
[ISS-671](20260917-1345-ISS-671.md), which supersedes [ISS-652](20260917-1244-ISS-652.md) and
[ISS-663](20260917-1310-ISS-663.md).

The same mechanism had two more effects:

- `GET /sandbox`, `/sandbox/zip` and `/sandbox/file` with `?ref=<host tag>` served the host
  checkout's own tree.
- The restore write path ([ISS-672](20260917-1350-ISS-672.md)) ran `git add -A` and `git commit`
  against the host checkout.

## Root cause

`backend/app/agents/runtime/local.py:372-390` (pre-fix): `_git()` passed only `cwd=self._root`
and `env=env` (`None` means inherit). The three direct `subprocess.check_output` readers had no
`env` at all:

- `read_file_at_ref` (`:1062`)
- `list_files_at_ref` (`:1081`)
- `archive_at_ref` (`:1104`)

When the sandbox root has no `.git`, git's repository discovery walks upward. It then uses
whatever checkout encloses `RUNS_ROOT`, which is `../runs`, inside the repo, locally.
`RunSandbox.list_tags` (`backend/app/agents/sandbox.py:896`) gates only on the `has_git` flag.
Every API caller leaves that flag at its default, `True`.

## What changed, and why there

- `local.py:372-377`: a new `_git_env(env)` returns the inherited environment, or the one the
  caller passed, with `GIT_CEILING_DIRECTORIES=str(self._root.parent)` added.
- `local.py:395`: `_git` passes `env=self._git_env(env)`. The `GIT_ALLOW_PROTOCOL` env that
  `clone_repo` builds is merged, not replaced.
- `local.py:1073`, `:1094` and `:1117`: the three direct readers pass `env=self._git_env()`.

**Why here.** `LocalWorkspace` is the single owner of every sandbox git subprocess. Every caller
in ISS-671's blast radius routes through these four call sites:

- `GET /{run_id}/sandbox/refs` (`backend/app/api/run_files.py:663`).
- `_validate_ref` (`run_files.py:604`), which gates `/sandbox`, `/sandbox/zip` and
  `/sandbox/file`.
- `POST /{run_id}/restore`: `_validate_tag_for_restore` (`backend/app/api/runs.py:2308`), then
  `materialize_tree_at_ref` and `commit_all` (from `:2443`).
- `_validate_ref_against_tags` (`sandbox.py:1846`), the legacy chain read.
- finalize's tag-failure diagnostic (`backend/agents/execution_engine/engine.py:2351`).

No API, sandbox or engine file changed. One guard at the owner covers every caller.

**What the ceiling does.** Git now checks only the sandbox root itself:

- A sandbox with its own `.git` behaves exactly as before. So does a worktree child, whose root
  holds a `.git` file.
- A sandbox without `.git` gets `not a git repository`. Every caller already treats that as
  fail-closed: `list_tags` returns `[]`, so every ref is rejected with 400, restore validation
  rejects every tag, and `commit_all` raises.

`_root` is always absolute, because `RunSandbox.root` and `_ChildSandbox.root` are both
`.resolve()`d. That matters: git silently ignores a relative ceiling entry.

For the QA family, `/sandbox/refs` now returns `[]`, so `RunHeader` keeps its static chip. With no
non-live entry in the menu, the Preview hang cannot be reached from it.

This checkout has 0 commits authored by `Flowin Runtime` (`git log --all --author`), so the write
hazard had not fired here.

## Test change, made on the card's instruction

`backend/tests/unit/test_run_files_ref_family_scope.py` was written for the superseded
ISS-652/ISS-663 theory: a stray tag inside the sandbox's own repo. That scenario never exercises
git's upward search. [ISS-671](20260917-1345-ISS-671.md) says the file "needs a rewrite to a
sandbox with **no** `.git`, nested inside a tagged outer repo fixture". It was rewritten that way.
The change follows the card; it was not made to turn a red test green.

- **Fixture.** A throwaway outer repo at `tmp_path`, tagged `deploy-prod-leaked`, with `RUNS_ROOT`
  inside it. The chain root is never `git init`-ed. A guard asserts that the nearest repo above
  the sandbox is the throwaway one before any sandbox git call runs.
- **Assertions keep their intent.** `refs` must be exactly empty. The old expectation was
  `{v1, v2}`, but those tags cannot exist without a `.git`. The leaked ref must get 400.
- **New test.** ISS-672's write-path test follows that card's "confirm safely" recipe.
- **Markers.** `xfail(strict=True)` is left in place for the verifier.

Pre-fix run with `--runxfail`, observed:

1. `refs == {'deploy-prod-leaked'}`
2. `200` with body `b'<h1>host checkout</h1>'`
3. The outer repo's `HEAD` moved from `638b84cd` to `1c679a28`: `commit_all` committed into the
   enclosing repo.
