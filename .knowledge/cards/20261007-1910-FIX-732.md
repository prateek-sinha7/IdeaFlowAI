# FIX-732

Bug: QA-KB-073. Resolves [ISS-900](20261001-2132-ISS-900.md) (root) and [ISS-1013](20261002-0547-ISS-1013.md) (sibling).
Test-only. No product code changed.

## What was wrong

Three tests call the shared event-to-column mapping `_apply_terminal_output_columns`
(`backend/app/api/run_commands.py:3854`) with hand-written events, and all three failed with
`TypeError: the JSON object must be str, bytes or bytearray, not NoneType` at `json.loads(...agent_outputs)`:

- `backend/tests/integration/api/test_rest_revisions_api.py::test_driver_happy_path_persists_output_columns` (the reported test)
- `backend/tests/integration/agents/test_restart_resume_db.py::test_apply_terminal_output_columns_populates_all_columns`
- `backend/tests/integration/agents/test_restart_resume_db.py::test_apply_terminal_output_columns_captures_per_agent_model_id`

## Root cause (from the cards, re-checked on this tree)

The collector keeps one open row per `(agent_id, task_id)` (`_row`, `run_commands.py:3893-3909`) and appends a closed
row on `agent_complete` only `if row.get("agent_id")` (`run_commands.py:3963`). `wr.agent_outputs` is written only when
that list is non-empty (`if agent_outputs_collector:`, a few lines below). The stubs put `agent_id` on `agent_start` and
nowhere else, so `agent_chunk` and `agent_complete` landed on a `(None, "")` row that was closed and dropped. The keying
came in with `77b52bb3d` ([FIX-652](20260929-1022-FIX-652.md)); before it, a single "current agent" slot let id-less events
inherit the open agent. The engine stamps `agent_id` on every one of these events, so the stubs were the stale side
(full analysis in [ISS-900](20261001-2132-ISS-900.md)).

The first resume-file test had a second fault. Its `agent_complete` events carried `cache_read_tokens` but no
`usage_version`, so `normalize_usage` (`backend/agents/capabilities/token_usage.py:63`) treated them as pre-v2 and took the
cache reads out of input: 290, not the asserted 300. The engine stamps `usage_version` on every `agent_complete`.

## What changed

- `backend/tests/integration/agents/test_restart_resume_db.py` ([ISS-1013](20261002-0547-ISS-1013.md)):
  - `test_apply_terminal_output_columns_populates_all_columns`: `agent_id` (`domain-analyst`, then `backlog-compiler`) on both
    `agent_chunk` tuples and both `agent_complete` dicts; `"usage_version": USAGE_VERSION` on both `agent_complete` dicts, with
    `USAGE_VERSION` imported locally from `agents.capabilities.token_usage`. Every assertion kept (300 / 130 / 430, cache reads 10).
  - `test_apply_terminal_output_columns_captures_per_agent_model_id`: `agent_id: prototype-build` on the `agent_chunk` and the
    `agent_complete`.
- `backend/tests/integration/api/test_rest_revisions_api.py` ([ISS-900](20261001-2132-ISS-900.md)): **not edited here.** The
  same two keys were already added by [FIX-722](20261007-1809-FIX-722.md) (QA-KB-061, commit `afa86af79`), as ISS-900 planned
  for whichever fixer came second. This card only verifies it.

The fix belongs in the stubs because they are the only side that drifted from the emit contract. Letting the collector
accept id-less events would bring back the "current agent" slot and lose parallel wave members again (run c4cbd381 kept
55 of 63 workers), and a second inline mapping would break INV-12.

Diff (my hunks only): `evidence/qa-kb-073/fix-04-diff.txt`.
