## What was wrong

`useState(currentPipelineType || "all")` at `AgentLibrary.tsx:86` accepted any non-empty
string as the default active category. A `currentPipelineType` of `"migration"` — a
sub-pipeline type unknown to `CATEGORIES_FALLBACK` — set `activeCategory` to `"migration"`,
which no category tab matched. The result: no tab highlighted, the panel opened on an empty
list with "No agents found" — reported as ISS-420 (via IdeaInputPage) and ISS-421 (via
LaunchWizard). FIX-376 fixed the empty-state *message* but not the bad *default*.

## What changed and why there

`frontend/src/components/workflow/AgentLibrary.tsx`:

Before the `useState` call, a `KNOWN_CATEGORY_IDS` Set is built from `CATEGORIES_FALLBACK`
(the static canonical list of pipeline-type ids). The initializer now guards:

```tsx
const KNOWN_CATEGORY_IDS = new Set(CATEGORIES_FALLBACK.map(c => c.id));
const [activeCategory, setActiveCategory] = useState(
  currentPipelineType && KNOWN_CATEGORY_IDS.has(currentPipelineType)
    ? currentPipelineType
    : "all",
);
```

`CATEGORIES_FALLBACK` was chosen over the dynamically-derived `CATEGORIES` because `useState`
initializers run before the component body derives `CATEGORIES` — using the static constant
is always available and never stale. Both "all" and "custom" are in `CATEGORIES_FALLBACK` and
remain valid defaults.

Fix is in the shared component, so it covers every caller (both IdeaInputPage and LaunchWizard
pass `currentPipelineType` through the same prop).
