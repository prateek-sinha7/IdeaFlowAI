## What was wrong

The test account's run history holds **zero ppt-family runs**, so
`WorkflowHistory.tsx` never renders the Presentation chip
(`if (type !== "all" && count === 0) return null`, line 1047).
Four tests hard-coded `"Presentation"` / `"ppt"` as their test target and timed out waiting for a chip that was never rendered.

`filterBucketFor` correctly buckets ppt runs to `ppt`; their absence is a data fact, not a bucketing bug (confirmed in ISS-625). D-15 was re-read before touching S-06-08.

## Root cause — file:line

`tests/integration/e2e/suites/06_run_history/test_run_history.py`
— hard-coded `"Presentation"` / `"ppt"` references in four tests that unconditionally click or count a chip that `WorkflowHistory.tsx` withholds when its family count is zero.

## What changed

**File:** `tests/integration/e2e/suites/06_run_history/test_run_history.py`

1. **S-06-05** — added `pytest.skip` guard when `expected == 0`. Self-healing if ppt runs reappear.
2. **S-06-07** — retargeted from `"Presentation"`/`"ppt"` to `"User Stories"`/`"user_stories"`. Intent preserved: label differs from URL value.
3. **S-06-08** — retargeted from `?type=presentation` to `?type=user+stories`. D-15 contradiction now demonstrated against user_stories chip.
4. **S-06-13** — retargeted from `"Presentation"`/`"ppt"` to `"User Stories"`/`"user_stories"`.

No app source touched. No locator file touched.

## Why user_stories

Available on every tier; guaranteed to have history in any seeded account; "User Stories" (label) vs `user_stories` (URL param) preserves S-06-07's intent.
