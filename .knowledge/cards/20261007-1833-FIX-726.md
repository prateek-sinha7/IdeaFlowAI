# FIX-726

Register bug **QA-KB-063** (`BUGS.md#qa-kb-063`). Test and spec files only. No application
code changed, so no restart is needed.

## What was wrong

[FIX-517](20260917-1307-FIX-517.md) numbered the narrator's clarify cards
(`backend/app/agents/chat_narrator.py:167-175`). The answer card now reads
`Clarifications round N answered` and the ask reads `Round N: Before I build, ...`. The e2e
probes and the Gherkin still quoted the old round-less answer text:

- S-23-45, `test_controls_inventory.py:643,645`, searched `body` for the exact old literal.
  On a run with numbered rounds it skipped instead of asserting.
- S-18-08, `test_chat_lane.py:34`, counted the literal through `get_by_text`. It found 0 answers
  on runs whose answers are numbered, and failed with a false "D-21 is fixed".
- `18-chat-lane.feature.md:58-59` (vocabulary) and `:218-219` (S-18-08), and
  `22-handoff-and-gates.feature.md:353,362` (S-22-23, S-22-24, sibling
  [ISS-995](20261002-0500-ISS-995.md)), described the round-less wording only.

Root cause, as [ISS-662](20260917-1307-ISS-662.md) recorded it: browser-tier artifacts froze the
narrator's pre-FIX-517 wording as their vocabulary, and FIX-517 did not name those files.

## What changed and why there

1. `tests/integration/e2e/framework/locators/run_detail.py`: added the one shared constant
   `CLARIFY_ANSWERED = re.compile(r"Clarifications( round \d+)? answered", re.I)` next to
   `ANSWER_IN_STEPS`. Both suites already import this module (`RD`, `L`), so the next wording
   change is a one-line edit. It accepts both shapes, because rows persisted before FIX-517
   keep the round-less text (ISS-662 constraint 1). `re.I` also covers the
   `N clarifications answered` branch.
2. S-23-45: the two literal checks became `RD.CLARIFY_ANSWERED.search(body)`.
3. S-18-08: the local `CLARIFY_ANSWERED` constant was removed and the test uses
   `L.CLARIFY_ANSWERED`. The guard now collects `all_inner_texts()` instead of counts. Since
   FIX-517, two genuine rounds also show two asks and two answers, so a count cannot tell rounds
   from a repeat (ISS-662 constraint 2). The test first requires more than one ask and more than
   one answer. That message points at the vocabulary, not at D-21. It then asserts that both
   halves repeat word for word. "D-21 is fixed" now appears only when the texts really differ
   (constraint 3). The guard stays inverted because [ISS-993](20261002-0500-ISS-993.md) is open:
   every agent `ask_user` pass still reads "Round 1".
4. `18-chat-lane.feature.md`: the vocabulary rows were rewritten as `Round <n>: ...` and
   `Clarifications round <n> answered`, with one line on pre-FIX-517 rows. The S-18-08 Given/Then
   lines were rewritten for text identity, and its comment now says what is observed today.
5. `22-handoff-and-gates.feature.md:353,362`: S-22-23 and S-22-24 quote the numbered texts
   ([ISS-995](20261002-0500-ISS-995.md)).
6. `DEFECTS-OBSERVED.md` D-21 is annotated **NARROWED by FIX-517**. The dated report below that
   annotation is unchanged.

Left as they were, per ISS-662's blast radius: the narrative mentions of past captures
(`07-run-detail.feature.md:31-33`, `22-handoff-and-gates.feature.md:60`), `GAPS.md:260`,
`capture/*.json` and the D-21 transcript block. All are dated records of behaviour before the fix.
S-18-07's `CLARIFY_ASK` was not touched either: it is a substring of the numbered ask.
