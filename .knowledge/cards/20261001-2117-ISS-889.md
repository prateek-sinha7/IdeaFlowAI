# Live Pipeline mini ignores prefers-reduced-motion (second panel next to the settled strip)

Sibling of QA-KB-001 and its root card [BUG-018-GROUNDED-CONTEXT](20260717-1903-BUG-018-GROUNDED-CONTEXT.md). The QA-KB-001 validator spotted it ("a second unconditional 0.22s transition at RunChatLane.tsx:2144"); the analyzer read it and reproduced it on the real component.

**Evidence level:** CONFIRMED by static read AND by running the real, unmodified `RunChatLane` in a jsdom harness with `matchMedia` stubbed to reduce. NOT yet observed in a real browser. What would settle it: Chrome DevTools > Rendering > "Emulate CSS media feature prefers-reduced-motion: reduce", then collapse the Pipeline mini on a building run and watch the 220 ms height/opacity tween.

## Condition

The OS or DevTools reports `prefers-reduced-motion: reduce`. A run is `building` with at least one agent, so `renderTranscriptFooter()` returns the live Pipeline mini (RunChatLane.tsx:2114-2160). The user clicks the `Pipeline · N agents` header (`data-testid="lane-pipeline-mini-toggle"`), or sends a chat message: the `replyPending` effect at RunChatLane.tsx:1224-1226 collapses it automatically, so a reduced-motion user sees the tween without touching the toggle.

## Expected vs actual

- Expected: the panel opens and closes instantly (transition duration 0).
- Actual: height and opacity tween over 0.22 s.

## Root cause (CONFIRMED)

`RunChatLane.tsx:2141-2147`, the body under the toggle:

```tsx
<motion.div
  initial={false}
  animate={{ height: pipelineMiniCollapsed ? 0 : "auto", opacity: pipelineMiniCollapsed ? 0 : 1 }}
  transition={{ duration: 0.22, ease: "easeOut" }}
  className="overflow-hidden"
  aria-hidden={pipelineMiniCollapsed}
>
```

The transition is a constant and nothing reads the OS preference. The library does not read it either by default: `reducedMotion` defaults to `"never"` (`framer-motion/dist/es/context/MotionConfigContext.mjs:10`, applied per element at `motion-dom/dist/es/render/VisualElement.mjs:206-207`). Same mechanism as the settled strip at `RunChatLane.tsx:821-831`, which is the BUG-018 deliverable.

Origin: commit `5818cdcca` (2026-08-11, "FIX-210..212 / ui-2") added `pipelineMiniCollapsed` (RunChatLane.tsx:1213) and this panel by copying the strip's idiom from `23a7cd2ad` (2026-07-17, BUG-018 Part B). It is not a BUG-018 deliverable, so that card's Part B gate requirement never covered it. These are the only two `duration: 0.22` literals in the frontend (grep of `frontend/src`, non-test).

## Observed

Real `RunChatLane`, `runState: "building"`, 5 agents, OS preference stubbed to reduce (`useReducedMotion()` returned true). After clicking `lane-pipeline-mini-toggle` (aria-expanded false) the panel's inline opacity, sampled every ~12 ms, read 0.93, 0.74, 0.62, 0.51, 0.41, 0.32, 0.24, 0.16 and so on down to 0.00 at about 222 ms. The settled strip behaved the same way (0.21, 0.99, 1.00).

## Fix

Gate it in the same change as the root card; fixing the strip and leaving this panel means the footer still animates while a run is building. The hook cannot live inside `renderTranscriptFooter()`. Either route both panels through one local `CollapsePanel` component that calls `useReducedMotion()` (recommended; the type-checked code is in the root card's analysis), or call `useReducedMotion()` at the top of `RunChatLane` next to `pipelineMiniCollapsed` (RunChatLane.tsx:1213) and use `reduce ? { duration: 0 } : { duration: 0.22, ease: "easeOut" }` at :2144.

## Test notes

- The deterministic RED/GREEN recipe is in the root card ("For the test-writer"). For this panel the assertion target is `screen.getByTestId("lane-pipeline-mini-toggle").nextElementSibling`.
- At-risk existing test: `RunChatLane.fix192.test.tsx:59-69` mocks `motion/react` with only `motion` and `AnimatePresence`. A top-level `useReducedMotion()` in `RunChatLane` makes all 14 tests in that file fail with `[vitest] No "useReducedMotion" export is defined on the "motion/react" mock` (observed on a scratch copy). Hooks inside the panel components do not: 81 of 81 existing RunChatLane tests passed with that mock unchanged.

## Fixed (QA-KB-001 fix phase, 2026-10-01): [FIX-686](20261001-2130-FIX-686.md)

Fixed in the same change as the strip, using the recommended shape: the live panel is now `<CollapsePanel open={!pipelineMiniCollapsed} aria-hidden={pipelineMiniCollapsed}>` (`RunChatLane.tsx:2166-2175`), and `CollapsePanel` (`:760-786`) calls `useReducedMotion()` and transitions with `{ duration: 0 }` under reduce. `RunChatLane.reducedMotion.test.tsx` "ISS-889: live Pipeline mini is instant when OS=reduce" flipped: its `it.fails` now reports "Expect test to fail", meaning the assertion passes. The guard "live Pipeline mini keeps the 0.22s tween when OS does not request reduce" stays green. `RunChatLane.fix192.test.tsx` passes 14/14 with its mock unchanged.
