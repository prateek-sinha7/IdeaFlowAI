# ISS-1034

Sibling of [ISS-944](20261002-0040-ISS-944.md), found by the QA-KB-086 analysis on 2026-10-02. Confidence: the observation is CONFIRMED
(offline probes that mount the real components; no repo file was edited). Whether it is a DEFECT is a product decision, stated at the end.
"FIX-323" in this card is the `.planning` id that commit `3de9d05b2` carries; the `.knowledge` card FIX-323 is an unrelated LoginForm fix.

## Why the root cause implies it

[ISS-944](20261002-0040-ISS-944.md) is red because its test replaces `ReviewGatesSection` with `() => null`, which removes the one thing that
overwrites the page's `gateSelectionRef` default. Eleven of the thirteen `IdeaInputPage.*.test.tsx` files do the same
(`grep -l 'vi.mock(".*ReviewGatesSection' IdeaInputPage*.test.tsx`; only `iss766` and `iss777` do not), so no unit test ever sees the real
page-plus-section wiring. Four of them assert on `extraParams`: three pin `{ gate_agent_ids: [] }`, one (the red one) pins `undefined`. They
cannot all be right, and the unit layer cannot say which describes the product.

## Condition

An untouched Run on `IdeaInputPage`, for every workflow it hosts. The section mounts unless `isMigrationMeta && !migrationChoice`
(`IdeaInputPage.tsx:2225`), and `handleRun` returns early in that state anyway (`:1569`).

## Expected (the FIX-323 contract as written)

Commit `3de9d05b2` ("always send gate_agent_ids (touched=true) so an empty selection is explicit, not absent"), the comment at
`LaunchWizard.tsx:352-356` ("`gate_agent_ids` is ALWAYS sent ... do not revert it to false") and three unit tests ("FIX-323 — the wizard now
ALWAYS sends `gate_agent_ids`": `IdeaInputPage.selections.test.tsx:192-198`, `IdeaInputPage.modelOverrides.test.tsx:138-144`,
`IdeaInputPage.imageInput.test.tsx:131-137`) say an untouched Run sends `gate_agent_ids: []`.

## Actual

An untouched Run sends no `gate_agent_ids`. `ReviewGatesSection` starts `touched` false (`ReviewGatesSection.tsx:110`) and reports
`onChange(ordered, touched)` from an effect that runs on mount (`:173-178`; `ReviewGatesSection.test.tsx:128-135` pins "first onChange
reports empty gate ids with touched=false"). `handleGatesChange` (`IdeaInputPage.tsx:1040-1042`) assigns whatever it is handed into
`gateSelectionRef`, replacing the `{ ids: [], touched: true }` default (`:1039`) before the user can click Run. `handleRun` then omits the
key (`:1592`, `:1646-1649`). At HEAD `024c03ef8` the same lines are `:1015`, `:1622`; the working tree carries 24 other uncommitted lines above them.

Probe with the real section inside the real page (`evidence/qa-kb-086/05-analyze-probe-observed-output.txt`, sources in `03-`):

| Run | `extraParams` the page hands `onRun` |
|---|---|
| untouched | `undefined` |
| one gate ticked | `{ gate_agent_ids: ["reading-planner"], selections: { "reading-planner": { gates: ["human"] } } }` |

Two more witnesses that already agree with the probe, neither run by this analysis. The Playwright specs drive the real UI:
`ts-g.review-gates.spec.ts:161-169` (TS-G-03b, "run without touching the section → gate_agent_ids omitted") and
`ts-h.trigger-contract.spec.ts:44-47` (TS-H-01: no `gate_agent_ids`, exactly four keys). And the local DB holds 55 runs, none with an explicit
`gate_agent_ids_json` list, 16 of them `prototype_v2` (`evidence/qa-kb-086/07-analyze-db-select.txt`). The DB is corroboration only: a row cannot
say which surface launched it.

## Why FIX-323's intent never showed

The same commit deleted the static `gate: Human_Gate` from the prototype AGENT.md files and `gates:` from prototype's workflow.yaml. For
prototype, omitted (`None`) and `[]` therefore both mean "no gates", and nothing user-visible differed. Only `clarify-agent` still declares a
static `Human_Gate` (`grep -rn "Human_Gate" backend/agents/prompts` returns only `clarify-agent/AGENT.md:12`), and manifests that declare a
human-review gate are rare (`before-human` at `ex_A4_human_gate/workflow.yaml:99-104` and `ex_A4_human_divert/workflow.yaml:85-90`).

## Why the choice matters to the engine

A present list is exhaustive. `engine.py:11469-11475` (`_should_gate`): `gate_ids is not None` gates a step iff `spec.id in gate_ids`, else the
AGENT.md static rule. `engine.py:11726-11731`: a declared `human` / `before-human` gate is skipped when `gate_agent_ids` is not None and the
step's agent is not in it. `backend/app/models/workflow.py:140-147` documents the three values: NULL = static defaults, `[]` = no gates this
run, non-empty = exactly these.

## Decision needed (product)

Which contract is intended for an untouched launch from IdeaInputPage: omit, or an explicit `[]`?

1. **Omit when untouched.** What runs today. It matches both Playwright specs, the section's own header contract
   (`ReviewGatesSection.tsx:17-20`) and the section's display, which since ISS-247 seeds checked boxes from manifest-declared gates. Fix:
   `touched: false` at `IdeaInputPage.tsx:1039` (and `LaunchWizard.tsx:356`, `:733`, see [ISS-1035](20261002-1058-ISS-1035.md)); the three unit tests
   assert no `gate_agent_ids`; the `LaunchWizard.tsx:352-356` comment and the "ALWAYS sends" comments in those tests go. The red assertion in
   [ISS-944](20261002-0040-ISS-944.md) is then correct as written.
2. **Always send** (the FIX-323 intent). Fix: stop the mount report from clearing `touched` while keeping the ids it reports. Trap: if the page
   forces `touched` true but discards the report, it sends `[]` while a manifest-declared gate shows checked, and `engine.py:11726-11731`
   then skips that gate. Cost: TS-G-03b and TS-H-01 flip; the header contract at `ReviewGatesSection.tsx:17-20` and the comments at
   `IdeaInputPage.tsx:1034-1038`, `:1589-1591` and `DashboardLayout.tsx:1779-1781` change; and INV-3's "byte-identical payload when nothing is
   opted into" no longer holds for untouched launches.
