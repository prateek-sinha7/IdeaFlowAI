# ISS-994

## What happened

Sibling of [ISS-662](20260917-1307-ISS-662.md) (register bug **QA-KB-063**), derived while
analysing the S-23-45 skip. **Marked INFERRED**: this is a static read; the test was not run and
nobody has shown a run where it passes with the card missing.

ISS-662 says S-23-45 "skips instead of asserting" once the lane text is numbered. Repairing the
literal turns that skip into an assertion, but the assertion is a copy of the test's own guard, and
it targets a different surface from the scenario it implements.

## Why the root cause implies this

The same three lines hold both the drift and this gap,
`tests/integration/e2e/suites/23_controls_inventory/test_controls_inventory.py:642-645`:

```python
body = page.evaluate("() => document.body.innerText")
if "Clarifications answered" not in body:
    pytest.skip("this run asked for no clarifications")
assert "Clarifications answered" in body
```

- Line 645 can only execute when line 643's condition was false, so it holds by construction.
  The test cannot fail; at best it skips.
- The Gherkin it implements, `tests/integration/screens/23-controls-inventory.feature.md:575-578`,
  reads `Then a card labelled "Clarifications, <n>" summarises them`, and inventory section 10
  (`:152`) names "`ClarificationsCard`'s `Clarifications, <n>`". That card is
  `frontend/src/components/results/ClarificationsCard.tsx`, whose button at `:47` carries the
  `aria-label` template `Clarifications, <questionCount> question(s)`. It is mounted by the Steps
  overview (`frontend/src/components/results/StepsOverviewSpine.tsx:593`), not by the lane.
- The test reads `document.body.innerText` of the run page's default tab. `innerText` carries
  neither attributes nor the Steps-only card, so even a green run proves the lane narrator wrote a
  note, not that a count is summarised anywhere.
- The skip is invisible to the progress ledger: `tests/integration/capture/_scenarios.py:53` and
  `:126` count only a static `@pytest.mark.skip(reason=...)`. A runtime `pytest.skip()` leaves
  S-23-45 listed as implemented and running (`tests/integration/docs/PROGRESS.md:589`,
  `| ok | S-23-45 |`).
- The run it opens is `RH.ROW.first` (`:636-637`), the newest run of ANY type. On 2026-10-02 that
  is `d091ed54-18c7-49fb-8d6f-5d3466f27f1b` (ex_A1_loop, no clarifications), so the skip is
  currently legitimate and would equally hide a real regression.

## Expected vs actual

- **Expected:** S-23-45 selects a run that has clarification rounds, opens the Steps tab
  (`tab-thinking`) and asserts the card by its label (`Clarifications, <n> question(s)`).
- **Actual (INFERRED):** it passes or skips on lane text alone and can never go red.

## Consequence for the QA-KB-063 fix

A regex-only repair of the literal (`Clarifications( round \d+)? answered`) is necessary and
sufficient to stop the drift, but leaves a test that cannot fail on the claim in its title. If the
fixer touches S-23-45 it should, in the same edit, select a run with clarifications the way
S-18-07 does (`a_run_with`) and replace the tautology with
`expect(page.get_by_label(re.compile(r"^Clarifications, \d+ questions?$"))).to_be_visible()`
on the Steps tab. Whether S-23-45 should check the lane note or the card is a spec choice; the
Gherkin says the card.

## What would settle this

Run `test_clarifications_are_summarised_with_a_count` against a run whose lane shows
`Clarifications round 1 answered` but whose Steps tab renders no clarifications card (a run with
no persisted rounds): after the literal fix it passes while the scenario's claim is false.

## Fixer note (QA-KB-063, 2026-10-07): still open, the proposed rewrite needs re-analysis

[FIX-726](20261007-1833-FIX-726.md) did not apply this card's rewrite. It touched S-23-45 only to
swap the literal for `RD.CLARIFY_ANSWERED` (`test_controls_inventory.py:643,645`). The
skip-then-same-assert shape described above still stands. The rewrite was left out because, on
today's data, its selector would turn S-23-45 red for a reason in the test, not the product:

- Selecting "the way S-18-07 does" (`a_run_with` plus a lane-text predicate) reads the lane. The
  lane seeds from the run's whole revision family (`test_chat_lane.py:59-61`). On 2026-10-07
  that same predicate in S-18-08 picked `/runs/b40eabd0-d7e2-4bc2-bc42-99ef6a147bff`, a
  backlog revision (`tests/integration/test-runs/2026-10-07T18-30-qa-kb-063-fix-after-s18-08-rerun/`,
  `steps.json` url).
- That revision has no clarification rounds of its own.
  `GET /api/runs/b40eabd0-d7e2-4bc2-bc42-99ef6a147bff/artifacts?kind=clarifications` returns 0
  artifacts, while its root `78e185fb-c032-4154-8552-774781b6e5df` returns 4
  (`evidence/qa-kb-063/fix-10-clarification-artifacts-by-run.txt`). The four clarify pairs its
  lane shows belong to that root (`evidence/qa-kb-063/fix-07-family-clarify-texts.txt`).
- `ClarificationsCard` gets its rounds from `getRunArtifacts(token, selectedRun.id, { kind:
  "clarifications", includeContent: true })`
  (`frontend/src/components/history/WorkflowHistory.tsx:436-450`). That query is keyed on the
  open run, so the Steps card renders nothing on that revision. This is by design: each version
  has its own clarify history, while the lane narrates the family.

A rewrite therefore needs a run predicate scoped to the run's OWN rounds, so that a missing
`Clarifications, <n>` card is a real failure. Candidates: a family root, or the run's own
`kind=clarifications` artifacts read through `framework/api.py`. The open question this card
already names is unchanged: should S-23-45 check the lane note or the card?
