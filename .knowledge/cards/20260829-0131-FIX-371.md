## What was wrong

`BUG-20260828-050115-library`: 30 of the Agents tab's 94 catalog entries are rendered as
disabled "Coming Soon" cards (`opacity-60 cursor-not-allowed`, no `Configure →`, no working
`onClick`), yet cold-loading `/library/agents/{that-id}` opened the identical, fully interactive
detail drawer as a released agent — Overview/Skills/Hooks tabs plus a live Config tab with
Model/Validator/Gate/Retry controls and an enabled "Save agent" button. The catalog's gating was
click-only; the route enforced nothing.

## Root cause

`frontend/src/components/library/LibraryPage.tsx:589-614` — the T15 (015-frontend-routing,
FR-006) cold-mount URL-seed effect. It is the ONE entry point for every direct-URL, bookmark,
shared-link and browser-history open of a Library detail item, and it opened the drawer purely on
an id match:

- agents branch (`:591-597`): `ALL_AGENTS_COMBINED.find(a => a.id === slug)` → `setSelectedAgent`,
  with no `BETA_WORKFLOWS.has(getPrimaryPipelineType(agent.pipeline_type))` check — the exact
  check the grid card's own `onClick` (`:815`) already performs. Two independent paths into the
  same `setSelectedAgent` state, the gate enforced in only one.
- skills branch (`:598-604`): the identical omission against `skill.isBeta`
  ([ISS-416](20260828-2210-ISS-416.md)). `SKILLS` (`:498`) is the unfiltered catalog, and the
  "Coming Soon" skills grid (`:939-961`) renders its cards with no `onClick` at all.

The hooks branch (`:605-611`) was checked and is NOT a sibling: the hooks grid applies no
`isBeta` filter, so every hook is clickable and there is no click-gate for a URL to bypass.
`frontend/src/components/workflow/AgentLibrary.tsx:68`'s duplicated `BETA_WORKFLOWS` set was also
ruled out — that component has no URL-seed entry point (it opens from a local `isOpen` prop).

## What changed and why there

One hunk, inside that same effect — the shared choke point, so no caller had to change and the
already-correct grid handlers were left alone:

- agents branch: when `BETA_WORKFLOWS.has(getPrimaryPipelineType(agent.pipeline_type))`, call
  `router.replace(routes.library({ tab: "agents" }))` instead of `setSelectedAgent(...)`.
- skills branch: when `skill.isBeta`, call `router.replace(routes.library({ tab: "skills" }))`
  instead of `setSelectedSkill(...)`.

`router.replace` (not `push`) resolves the open question [ISS-303](20260828-1935-ISS-303.md) left
for the fixer: simply skipping the `setSelectedX` call would leave the URL parked on a detail path
that renders nothing — the silent-fallback shape [FIX-340](20260828-2230-FIX-340.md) already had to
fix once — and `push` would trap the Back button by re-redirecting on every return. `replace` drops
the unreachable URL from history and lands the user on the listing, which is one of the two
outcomes the card's own "Expected" sanctions. `setMainTab` still runs first, so the redirect lands
on the right tab. `notFound()` (the existing treatment for an unknown slug, `:729`) was deliberately
NOT reused — a "Coming Soon" agent exists, it is just not released, and the test asserts the Library
listing stays rendered.
