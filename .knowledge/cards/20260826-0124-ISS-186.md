## What is missing

Commit `215b911e0 "removed screenshots"` deleted 56 files / 3,546 lines. Most were
`.png` screenshots, as the message says. These were not:

```
README.md                  93 lines
README.txt                270 lines
app.env.example           127 lines
docker-compose.yml        115 lines
docker-compose.prod.yml    35 lines
STATUS-vel-proj-ctx-adr.md
home-page.md
pre-commit-issue.md
```

The shape — a large mixed deletion under a narrow message — reads like a
`git add -A` after a screenshot cleanup rather than a decision, but that has not
been confirmed with the author.

## How it surfaced

`backend/tests/unit/test_shutdown_reachability.py` began failing with
`FileNotFoundError: docker-compose.yml`. Two of its cases read
`stop_grace_period` out of that file to prove the production teardown budget
finishes before docker sends SIGKILL — a real invariant with no other source.

## Disposition

The two affected cases and their `_stop_grace_period_seconds` helper were
DELETED, at the user's explicit direction ("docker nahi chahiye abhi" — docker is
not wanted for now). The other six cases in that file do not touch compose and
remain. The file is green at 6 passed.

That resolves the test failure; it does not resolve the finding:

- The production teardown-budget invariant is now unguarded. If the compose files
  come back, those two cases should come back with them.
- `README.md` and `app.env.example` are the repo's entry documentation and its
  environment template. Their absence is a separate cost from the test.

## Recovering any of it

```
git checkout 215b911e0^ -- docker-compose.yml docker-compose.prod.yml README.md app.env.example
```

Deliberately not run: whether these were meant to go is the owner's call, and the
user has said docker is out of scope for now.
