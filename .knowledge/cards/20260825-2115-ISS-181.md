<!-- /RELATED -->

Two independent validators guard an override and they do not agree.

- **Save / merge:** `merge_override_steps` compiles the row's steps with `WorkflowCompiler` at
  `trust="db"`. A 2-step `prototype` override (`documentation-agent`, `prototype-build`) passed.
- **Launch:** `presort_specs` (`app/api/composition_order.py`) additionally checks
  produces/consumes. The same override was rejected:

```
422 Workflow DAG is unsatisfiable: Agent 'prototype-build' consumes 'prototype-plan'
    but no agent in the workflow produces it.
```

So an override **saves cleanly, renders in Advanced, and 422s at launch** — the user finds out
only when they run it. Same failure class as [FIX-306](20260825-2115-FIX-306.md), different
validator.

**Disposition:** open. The DAG check should run at save time so the canvas can say "this step
needs X". Spec: `specs/016-workflow-overrides/spec.md` §6 G-2.
