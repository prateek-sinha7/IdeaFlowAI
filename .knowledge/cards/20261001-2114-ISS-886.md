## Description

Sibling of [ISS-689](20260918-ISS-689.md) (bug QA-KB-036), derived from its root cause rather than reported independently.

ISS-689's defect, two mechanisms for the degraded verdict inside one function, survived a merge because nothing in the test suite can tell the mechanisms apart. [FIX-484](20260902-1600-FIX-484.md) fixed three defects in `_reconcile_terminal_status`: [ISS-435](20260828-2253-ISS-435.md) (a degraded completion in a resumed attempt must supersede an earlier cancellation), [ISS-436](20260828-2253-ISS-436.md) (degraded scoped to the last attempt boundary) and [ISS-437](20260828-2253-ISS-437.md) (failed scoped to the last attempt boundary). Its card records "No new xfail tests were added", and its `verification.test_files` names `backend/tests/agents/test_restart_resume.py`, which does not exist at HEAD (the reconcile tests live in `backend/tests/integration/agents/test_restart_resume_db.py`). `grep -rn -E 'ISS-43[567]|FIX-484' backend/tests --include='*.py'` returns nothing.

The existing reconcile tests (`test_reconcile_degraded_tracks_latest_completion_only` with 4 tails, `test_reconcile_clears_stale_error_on_clean_completion`, `test_reconcile_supersedes_only_across_an_attempt_boundary` with 3 tails, `test_reconcile_later_attempt_failure_supersedes_earlier_cancellation`) all stay green when each FIX-484 change is reverted on a scratch copy of `run_commands.py`. Status persisted by `_reconcile_terminal_status` for seven tails, run through that file's own harness (the run is seeded `generating`, so `generating` below means the reconcile persisted nothing):

| tail | correct | current code | ISS-689 option 2 (keep last-by-seq `degraded`) | ISS-435 change reverted | BUGS.md agreed fix |
|---|---|---|---|---|---|
| T1 degraded, then clean resume | completed | completed | completed | completed | completed |
| T2 clean, then degraded resume | degraded | degraded | degraded | degraded | generating |
| T3 degraded only | degraded | degraded | degraded | degraded | generating |
| T4 no completion at all | failed | failed | failed | failed | failed |
| T5 degraded, then the resume FAILS (ISS-436) | failed | failed | **degraded** | failed | failed |
| T6 failed, then clean resume (ISS-437) | completed | completed | **failed** | completed | completed |
| T7 cancelled, then degraded resume (ISS-435) | degraded | degraded | degraded | **cancelled** | generating |

T1-T4 are the shape of the four tails in `test_reconcile_degraded_tracks_latest_completion_only`: every mechanism agrees on them, so they cannot discriminate. `-k reconcile` selects 16 tests in that file (9 of them exercise `_reconcile_terminal_status`); all 16 pass under option 2 and under the ISS-435 revert. The BUGS.md agreed fix fails 2 of them, only through the status assertion.

## Why the root cause implies this

ISS-689's root cause is an unreconciled double fix: two mechanisms decide one verdict and the code kept both. That could only go unnoticed if every test tail yields the same status under both, which is what T1-T4 show. The same blind spot would let ISS-689's second option ("keep it and delete FIX-484's duplicate") land silently: it passes 16 of 16 and reintroduces ISS-436 and ISS-437.

The error text has the same gap. The remaining reader of `_latest_complete` (`run_commands.py:984-999`) derives the degraded `WorkflowRun.error` from `degraded_reason` / `agents_failed`. No test asserts it for a degraded verdict: `grep -rn "degraded: agent(s) failed" backend/tests` is empty, and `test_reconcile_clears_stale_error_on_clean_completion` only asserts `None` for a clean completion. A failure there is swallowed by the best-effort `except Exception` (`:1016-1018`), so the only thing that caught the agreed fix was a status assertion that happens to read the same row.

## What the missing tests are

Add them to `backend/tests/integration/agents/test_restart_resume_db.py` beside `test_reconcile_degraded_tracks_latest_completion_only`, reusing its harness (`_make_session`, `_seed_workflow_run`, `_ResumeHarness`, `_wire_user_resume_drive`; offline in-memory SQLite, and `tests/conftest.py` pins `DATABASE_URL` to a temp file). Payload used: `{"status": "degraded", "agents_failed": ["x"], "degraded_reason": "x failed"}`.

- T5 (ISS-436): `pipeline_start 1, pipeline_complete{degraded} 2, run_resuming 3, pipeline_start 4, agent_error 5, pipeline_failed 6` expects `failed`. RED under option 2 (`degraded`).
- T6 (ISS-437): `pipeline_start 1, pipeline_failed 2, run_resuming 3, pipeline_start 4, pipeline_complete 5` expects `completed`. RED under option 2 (`failed`).
- T7 (ISS-435): `pipeline_start 1, pipeline_cancelled 2, run_resuming 3, pipeline_start 4, pipeline_complete{degraded} 5` expects `degraded`. RED when `degraded_complete_seqs` is dropped from `terminal_seqs` (`cancelled`).
- Error text: for T3 (`pipeline_start 1, pipeline_complete{degraded} 2`) assert `row.error == "x failed"`, plus the `agents_failed`-only fallback (`"degraded: agent(s) failed: x"`) and the `agent_error` precedence. RED (status `generating`, error `None`) if `_latest_complete` is deleted.
