## The contradiction

`21-run-families-and-versions.feature.md` S-21-07 says:

> When I cold-load "/runs/{id}" — Then a region labelled "Workflow versions" is shown

That region is `VersionTimeline`, rendered only by `RunDetailPage`. But
`WorkflowHistory.handleSelectRun` returns early through `onOpenRun` for every
tap, so the internal detail is unreachable — the code says so itself:

> BUG-002: route the tap into the shared run screen (parity with Home-recents)
> instead of the divergent internal RunDetailPage. Carry-over: … retiring the
> internal detail (INV-3) is a follow-up.

On `/runs/{id}` the user gets `PreviewPanel` + `RunHeader`, whose version
control is a **menu** (`button[aria-haspopup='listbox']`), not a timeline
region.

## Consequence

S-21-07/08/09 are skipped with this reason recorded rather than written against
a surface the app never renders. S-21-11 ("a single-version run shows no
timeline") passes trivially for the same reason — it asserts an absence that is
guaranteed.

## Decision needed

Either the spec is wrong (rewrite the three scenarios against the Version menu,
which IS covered by the ISS-230/296/607 tests) or the app is (finish INV-3 and
mount one surface). Nobody should write code until that is answered.
