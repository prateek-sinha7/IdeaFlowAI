## Bug

`run_fanout` keyed a worker's checkpoint thread by its slot index, which restarts every wave. The next task on a slot replayed the previous task's conversation, so one cut-off reply (run 3976f8ce, Bedrock: empty message content) failed every later task on that slot.

## Fix

The thread key uses `worker["task_id"]`, falling back to the slot index when there is no task id. A resume of the same task still reuses its own thread.
