# ISS-858

Seen while running regression files for [FIX-639](20260923-0148-FIX-639.md). It is
not related to that change, which touches neither file.

## Observed

`cd backend && python3.11 -m pytest tests/agents/test_migration_ledger.py -q -p no:randomly`
gave `1 failed, 22 passed, 7 skipped`:

```
FAILED tests/agents/test_migration_ledger.py::test_deleted_pattern_absent_from_backend[F1-blocks\.append]
E   AssertionError: F1: banned pattern is back in backend/ (move-don't-copy violation):
E     .../backend/agents/capabilities/input_providers/pdf_pages.py:202:  blocks.append(
```

`pdf_pages.py` has no working-tree change (`git status --porcelain` on it is empty).
Its history is `16b45d106` ("feat(pdf): materialise a PDF into pages an agent can
read") and `5d2c98e01` ("feat(tools): extract text from PDF, Word, Excel and
PowerPoint uploads"). So the failure is on committed code.

## Likely a name collision (not confirmed)

F1 guards the deleted prompt-block assembly. `pdf_pages.py:202` appends a multimodal
**image** content block (`{"type": "image", "source_type": "base64", …}`) to a local
list that happens to be named `blocks`. That is the same kind of false positive the
test already excludes for `evals/`. See `test_migration_ledger.py:187-192`, which says
F1 "fired on `evals/minimal/run.py` … a false positive that made a real guard look
permanently broken".

## Disposition

Open, needs triage. There are two options, and one of them has to be chosen:

- narrow the F1 pattern, or exclude the input-provider file with a comment like the
  `evals/` one
- rename the local list in `pdf_pages.py`

Until then this guard stays red on every run of the file, and that can hide a real
regression.

**Triaged 2026-10-01: the name collision is confirmed and the rename option is chosen.
See "Analysis (QA-KB-038 analyze)" below.**

## Analysis (QA-KB-038 analyze, 2026-10-01)

**Verdict: a false positive from a name collision, not a regression of F1. The guard is a bare,
unanchored token grep over all of `backend/`, and `pdf_pages.py` (spec 019) uses the same generic
identifier for a different thing. The two-reviewer rename is accepted as the fix; nothing is
overruled.**

### Root cause (CONFIRMED, each line below was opened and read)

1. The F1 gate is the regex `blocks\.append` with no word boundary and no path or construct
   qualifier. `specs/003-workflow-engine-decoupling/migration-ledger.md:83`:
   ``| F1 | prompt-assembly inline order `factory.py:174-255` | `PromptAssemblyPolicy` (§6/§30) | 3 | `blocks\.append` | ☑ | |``.
   The plan words the intent as "inline `blocks.append` ordering replaced by the policy"
   (`specs/003-workflow-engine-decoupling/plan.md:1019`). What it targeted was the system-prompt
   string list `_compose_system_prompt` used to build, deleted in `096712e00` (2026-06-09): `blocks:
   list[str] = []`, `blocks.append(f"## Guardrail: {guardrail_name}\n\n{content}")`, ...,
   `return "\n\n".join(blocks)`.
2. The test runs that regex line by line over every `*.py` under all of `backend/` (tests, comments
   and docstrings included; only `evals/` and venv/cache dirs are skipped).
   `backend/tests/unit/agents/test_migration_ledger.py:228`:
   `res = _portable_grep(pattern, scope, exclude_dir="evals")`; F1 is not in `_KERNEL_SCOPED_ITEMS`
   (`:99-101`), so `_scope_for("F1")` returns `_BACKEND` (`:104-106`). It fires on any
   `<anything>blocks.append`.
3. `backend/agents/capabilities/input_providers/pdf_pages.py`, added 2026-08-28 by `16b45d106`
   (80 days after the ratchet armed), declares `blocks: list = []` in `_blocks_for_document`
   (`:130`), appends one `{"type": "image", "source_type": "base64", ...}` dict per page image
   (`:202`, the only hit tree-wide) and returns the list (`:224`).

### Why it is not a regression (CONFIRMED)

- The `InputContentProvider` port is defined as image/binary blocks that "ride into the agent's
  model dispatch content-list, never the text prompt" (`backend/agents/capabilities/base.py:97-110`).
  `pdf_pages` is a registered `input_provider` (`agents/capabilities/registry.py:123`) whose output is
  consumed by the kernel's `_compose_input_blocks` (`engine.py:16738`, called at `:9687`). That
  method has its own `blocks: list = []` (`engine.py:16762`) filled with `blocks.extend(loaded or [])`
  (`:16777`). The only reason it does not trip F1 is `.extend` versus `.append`.
- System-prompt assembly is still owned by the policy: `factory.py:581`
  `blocks: dict[str, object] = {}` (item assignment, no append) and `factory.py:762`
  `composed = policy.assemble(blocks, ctx)`. The F1 move is intact.

### Blast radius (CONFIRMED unless marked)

- One hit tree-wide. Today's run, whole file, cwd `backend/`:
  `.venv/bin/python -m pytest tests/unit/agents/test_migration_ledger.py -q -p no:cacheprovider -p no:randomly`
  -> `1 failed, 22 passed, 7 skipped`; the failure message lists exactly one match
  (`pdf_pages.py:202`). No other checked grep row is red.
- CI: the test is unmarked, and `pytest ... --collect-only -m "not live and not requires_api_key and
  not requires_postgres and not requires_postgres_populated_migration"` still selects
  `test_deleted_pattern_absent_from_backend[F1-blocks\.append]`. That is the marker expression of the
  `backend-offline` job (`.github/workflows/ci.yml:336-343`), so the job fails on this test for any
  commit containing `pdf_pages.py` (INFERRED from the workflow config; CI run history not inspected).
- No runtime effect. `tests/agents/test_pdf_pages_provider.py` -> `15 passed`.
  `_blocks_for_document` is referenced only inside `pdf_pages.py` (call at `:114`, definition at `:122`).

### Fix: accept the agreed minimal fix (CONFIRMED sufficient by simulation, not yet applied)

In `pdf_pages.py`, inside `_blocks_for_document` only, rename the local `blocks` to `images` at three
places: `:130` the declaration, `:202` the append, `:224` the return. Leave `load()`'s own `blocks`
(`:83`, `.extend` at `:114`, `return` at `:120`) alone; it does not match.

- Simulation on an in-memory copy of the file (no source edit): baseline hits `[(202, 'blocks.append(')]`;
  after renaming to `images` hits `[]` and the file still parses; after renaming to `page_blocks`
  the hit stays at line 202 (`page_blocks.append(`). `images` collides with no identifier in the file
  (it only appears in prose and as the `"images"` manifest key). `blocks` and `images` are both 6
  characters, so formatting and line widths do not change.
- Why this and not the alternatives. It is the smallest diff, leaves the spec ledger and the test
  untouched so the ratchet keeps full strength, and follows `096712e00`, which kept F1 clean by
  rewording backend code "off the literal blocks.append token". Excluding `input_providers/` in
  the test (as `evals/` is) would hide future real regressions in that package. Narrowing the regex
  would edit a closed spec's ledger, and a line grep cannot tell `:202` from the deleted calls
  because its argument starts on the next line.
- Pitfall for the fixer: the scan is line-based and includes comments and docstrings, so no comment
  may spell the contiguous token (`blocks` immediately followed by `.append`). No comment is needed;
  if someone renames it back, the guard fails loudly.
- Proof, no new test needed: the failing test already exists, is deterministic, and is the
  regression guard. After the rename the same command must read `0 failed, 23 passed, 7 skipped`
  (expected; INFERRED until applied, the simulation shows zero hits) and
  `tests/agents/test_pdf_pages_provider.py` must stay `15 passed`.

### Siblings: none minted

Nothing else matches the gate (one hit tree-wide) and no other ledger row is red, so no sibling is
reproducible or implied beyond this line. Leads only (INFERRED, deliberately not filed):

- Recurrence: any future legitimate `<name>blocks.append` in `backend/` re-trips F1. The likeliest
  source is another `input_provider` copied from `pdf_pages.py` (its docstring says "Copy the shape of
  run_images.py"); renaming the local in `pdf_pages.py` also removes the trap from the file most likely
  to be copied.
- A token grep also has false negatives (a re-introduced inline assembly under another variable name
  would pass F1). That is the ledger's designed trade-off, not a defect of this ticket.
- Metadata drift fixed in this card: the test moved from `backend/tests/agents/` to
  `backend/tests/unit/agents/`; `applies_to.globs` and `verification` now name the real path, and
  `verification.status` is `failed` because the guard is red today.

## Resolution (QA-KB-038 fix, 2026-10-01)

Resolved by [FIX-671](20261001-2111-FIX-671.md). The rename to `images` was applied at
`pdf_pages.py:130/:202/:224` exactly as the analysis specified. Observed results (cwd `backend/`):

- the F1 param went from `1 failed, 26 deselected` to `1 passed, 26 deselected`
- the whole `test_migration_ledger.py` run gave `23 passed, 7 skipped`
- `tests/agents/test_pdf_pages_provider.py` gave `15 passed`
