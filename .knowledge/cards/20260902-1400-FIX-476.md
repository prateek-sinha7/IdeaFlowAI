## What was wrong

**ISS-491:** `AgentCapabilitiesModal` (`AgentsPopup.tsx:485`) declared `role="dialog"` /
`aria-modal="true"` with no keyboard handler anywhere — exactly the gap FIX-388 closed for
`WorkflowDialog`. FIX-388's `useEscapeToClose` hook already existed; ISS-491 needed two lines.

**ISS-399:** The "Suggested hooks" filter inside `AgentCapabilitiesModal` was:
```tsx
HOOKS.filter(h => h.compatible_agents.includes(agent.id)).slice(0, 3)
```
After FIX-360 cleaned stale agent ids from the backend, hooks whose entire
`compatible_agents` list was stale were left with an empty array — which the plain
`.includes()` never matches, so those hooks silently suggested for nobody. The sibling
filter for skills (`AgentSkillsPicker.tsx:71`) already treats an empty list as "suggest
to everyone" (R-33 safety default). The hooks filter now matches that contract.

## What changed and why there

`frontend/src/components/workflow/AgentsPopup.tsx`:

1. Added `import { useEscapeToClose } from "@/hooks/useEscapeToClose"` to the existing
   `import { useCallback, useEffect, useMemo, useRef, useState } from "react"` line.
2. Inside `AgentCapabilitiesModal`, before the return: `useEscapeToClose(onClose)`.
   Placed with the other hooks above the JSX.
3. `suggestedHooks` filter changed from:
   `HOOKS.filter(h => h.compatible_agents.includes(agent.id)).slice(0, 3)`
   to:
   `HOOKS.filter(h => !h.compatible_agents?.length || h.compatible_agents.includes(agent.id)).slice(0, 3)`

Both changes are in `AgentCapabilitiesModal`, the one component all four mount sites
(LaunchWizard, IdeaInputPage, LibraryPage, AgentLibrary) route through.
