# FIX-740

Bug report QA-KB-086. The root cause and the fix come from [ISS-944](20261002-0040-ISS-944.md), including its 2026-10-02
analysis addendum, and are not re-derived here. This is a **test-only** change, made because the card says the assertion
misstates the expected behaviour. No production source, backend, engine, migration or import-linter surface is touched.

## What was wrong

`IdeaInputPage.designPicker.test.tsx`, test "does not offer the picker for a workflow that never declares opendesign", ended
with `expect(extraParams).toBeUndefined();` (`:159` when carded, `:161` after the 4-test-writer added the `it.fails` marker and
its comment at `:148-149`). It failed with `AssertionError: expected { gate_agent_ids: [] } to be undefined`.

- The test mocks `./ReviewGatesSection` to `() => null` (`:46-48`), so nothing reports through `onChange` and the page keeps its
  own default, `gateSelectionRef = useRef({ ids: [], touched: true })` (`IdeaInputPage.tsx:1048`, `:1039` on the card).
- `handleRun` then sends `{ gate_agent_ids: [] }` (`:1614`, `:1668-1671`, `...(touched ? { gate_agent_ids: ids } : {})`).
- The assertion predates that default: the test was authored in `1e329e47b`, which does not contain the `touched: true` flip of
  `3de9d05b2`. With the real section mounted, the page sends `undefined` untouched (ISS-944 addendum probe), so the old
  assertion described the real UI and failed only under the mock.

## What changed, and why there

`frontend/src/components/workflow/IdeaInputPage.designPicker.test.tsx:161`, one line became two, in the exact form ISS-944
prescribes ("Keep it test-only and make it take no side"):

```diff
-    expect(extraParams).toBeUndefined();
+    expect(extraParams ?? {}).not.toHaveProperty("template_id");
+    expect(extraParams ?? {}).not.toHaveProperty("design_system_id");
```

- The test is about the design params. The page builds them in `designLaunchParams`, whose first line is
  `if (!designDeclared) return {};` (`IdeaInputPage.tsx:1506`). The new lines pin exactly that and nothing else.
- Why not the app: the card rules out flipping the default back to `touched: false` (it would undo `3de9d05b2` / `602296cc8`
  and decide [ISS-1034](20261002-1058-ISS-1034.md) inside a test fix).
- Why not `toEqual({ gate_agent_ids: [] })`: the card rules that out too, because it would add a fourth unit test pinning a
  payload the real UI never sends.
- Left alone, per the card: the comment at `IdeaInputPage.tsx:1043-1047` ("Untouched ⇒ we omit `gate_agent_ids`"). It
  describes the real runtime. Only the `touched: true` literal under it contradicts it, and that is ISS-1034's decision.
- The `it.fails` marker and its comment (`:148-149`) stay in place for the 6-verifier to remove.

Blast radius, re-checked on the working tree: `grep -rn "extraParams).toBeUndefined" frontend/src` matched only
`designPicker.test.tsx:161` before the fix. The three sibling tests that read the same argument (`IdeaInputPage.selections`,
`.modelOverrides`, `.imageInput`) pin `{ gate_agent_ids: [] }`. They belong to ISS-1034 and are untouched.
