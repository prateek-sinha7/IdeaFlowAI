## Description

The 5 characterization event goldens — the project's INV-3 parity oracle — had been red on dev for weeks, so INV-3 could only be checked by diffing failure counts against a hand-captured baseline. Root-caused to exactly 3 causes (proven exhaustive by counterfactual: undoing all 3 makes every one of the 5 files byte-identical), each adjudicated separately per the ISS-029 method. C1 (all 5) — STALE NORMALIZER, not a stale golden: c71f3d9c added an additive pipeline_start.resume_offset; it is 0 on every non-resumed run and the harness never resumes, but a key whose value is 0 is still a NEW key and the snapshot compares whole canonical-JSON dicts. C2 (prototype, od_prototype) — a REAL REGRESSION; the golden was RIGHT: f608e4bc (FIX-190) appended an accessibility guardrail to 4 prototype-family agents, and in prototype-build/AGENT.md the + line landed ON TOP OF icon: "🏗️" (the other 3 files are pure 1 + insertions; this one is 2 +-), so the agent fell through to the loader's 🤖 default — a user-visible UI regression in pipeline_start.agents[] + both agent_starts that config review, code review and CI all missed. C3 (prototype_revision) — a genuinely STALE GOLDEN: fd2ad8f1 (FIX-185) deliberately set planner: skip, removing planner_start/planner_complete/gate_status.

## Root cause

C1: the author of c71f3d9c skipped the project's mandatory 3rd step for an additive parity-neutral key (6 prior precedents in _VOLATILE_STRIP_KEYS), and the emit-site comment asserts "0 on every normal run → byte/event-identical (INV-3)", which is FALSE as written and is what misled them. C2: a text-editor clobber, not a decision — sweep proved prototype-build was the ONLY 1 of 86 AGENT.md files missing an icon. C3: the manifest change was correct and tested; only the golden was never regenerated.
