# ISS-1032

**INFERRED in the browser. Reproduced offline in jsdom only**: a scratch probe of the real `PreviewPanel`, rows G3 and G5 of
`evidence/qa-kb-091/04-analyze-probes-real-tree-and-fix-variants.txt`. Derived by the analyzer while analysing QA-KB-091 ([ISS-952](20261002-0147-ISS-952.md)): the "adjacent state" of
the same root cause (the shell GENERATING instead of ended badly). Nobody reported it. Nothing was driven in a browser.

Line numbers are the working tree on 2026-10-02 (HEAD `024c03ef8` plus uncommitted edits; `PreviewPanel.tsx` md5 `475f5d437872d0c205a11db8f71afa5b`).

## Condition

The shell run is streaming (`isStreaming` true or `pipelineState.isRunning`), and a DIFFERENT, terminal family member with no stored output is pinned, with no git tag selected
(`sandboxSelectedRef` null). Both `failed`/`cancelled`/`degraded`/`diverted` members and a `completed` one with null output reach it.

## Expected vs actual

- **Expected:** the Preview tab shows the pinned version's own copy: "No deliverable was saved for this version" for a completed pin, the `DegradedRunAffordance` copy for one that ended
  badly (the branch [FIX-709](20261002-0147-FIX-709.md) added).
- **Actual** (probe, real tree; distinct shell `r1` streaming, pin `root`):
  - pin `failed`, output null: after clicking Preview the body is **"Building your deliverable…"**;
  - pin `completed`, output null: the same;
  - pin `completed` WITH content: the pin's content renders (inside the streaming chrome; the probe does not read the chrome);
  - control G5, the unpinned streaming shell with no content: "Building your deliverable…" (correct; must stay).

## Mechanism (CONFIRMED, read)

- `PreviewPanel.tsx:1130` `const isStillRunning = !!(isStreaming || pipelineState?.isRunning);` reads the SHELL props. `hasContent` (`:1119`) reads the pin.
- The Preview-tab chain is `:1781` shell failure/diverted -> **`:1810` `) : isStillRunning ? (`** -> `:1823` `isLoadingRunData` -> `:1835` the pinned branch -> `:1853` neutral.
  The streaming branch renders `<PreviewChrome ... streaming>{hasContent ? renderDeliverable() : ... "Building your deliverable…" ...}` (`:1814-1822`), so it answers for a pin
  that has nothing to show before the pinned branch is reached.
- [FIX-709](20261002-0147-FIX-709.md) listed `isStillRunning` among the branches ahead of its own ("Every branch ahead of it is keyed on the SHELL's props") and changed none of them; ISS-952 covers only the two failure predicates.

## Reachability (INFERRED)

- `handleSelectVersion` (`:892-930`) diverts only a member that is itself still RUNNING to `onOpenLiveRun` (`:911-914`); a terminal member is pinned whatever the shell is doing.
  The URL-pin effect (`:1008-1035`) has no guard either.
- The file treats pinning during a run as normal: `:974-992` (an explicit pin "mid-review" while a revision completes) and `:1764-1766` ("regardless of the live run's own state
  (a later revision may still be running)", for the tagged path).
- The tagged Version-menu path is unaffected: `RefVersionPreview` (`:1763`) is the first branch. A member that ended failed or cancelled usually has `git_tag` NULL ([ISS-697](20260922-1000-ISS-697.md), [ISS-933](20261001-2231-ISS-933.md)), so
  it is reached through a chat result card or a pin URL, which is exactly the route that hits the streaming branch.

## Fix (proposed, not applied)

One term at `:1810`: `) : isStillRunning && shellOnScreen ? (`, with `shellOnScreen = viewingVersion == null || viewingVersion.id === unpinnedRunId` defined once for the ISS-952 gate.
Probe variant C: G3 gives the failed copy for a failed pin and "No deliverable was saved for this version" for a completed one; G5 is unchanged; the 21 existing PreviewPanel unit-test files
are identical to the baseline (`evidence/qa-kb-091/05-analyze-regression-existing-preview-tests.txt`).

Left alone on purpose: the header's "building" state and `isStillRunning`'s other readers. The Version menu is meant to stay usable while a revision runs (`RunHeader.tsx:415-419`), so a header that
describes the live run is by design.

## Test conditions

- pin `completed`, output null: expect "No deliverable was saved for this version".
- Controls: unpinned `isStreaming` shell with no content keeps "Building your deliverable…"; pin WITH content renders the content; a pinned member that is itself `running` keeps the neutral copy (the `TERMINAL_RUN_STATUSES` guard at `:1835`).

## Not assessed
