# FIX-782

**Register source:** `QA-KB-122` (`LEDGER.md`), 5-fixer, 2026-10-09, at HEAD `76cd62b41`. Resolves the root
[ISS-1158](20261009-1510-ISS-1158.md) and its five siblings [ISS-1185](20261009-1754-ISS-1185.md),

`tests/integration`, +286/-255. No file outside `tests/integration` changed.

## What was wrong

This is taken from the root card, not re-derived. The live e2e tier copies facts about the app as literals: a request body, UI
strings, tab names, bug-status xfail markers and database ids. Five intentional commits changed those facts. Each one updated its
unit-tier twin and touched no e2e file. On 2026-10-09 the full offline run showed 68 failures, 37 of them from this family.

## What changed, and where

Each literal was changed in the shared piece every caller goes through.

- **Admin create, ISS-1158.** The body in `disposable_user.make()` (`conftest.py:475-495`) drops `"password"`. That body is
  shared by 11 test ids. `make()` also returns the 201 body as `row`. S-24-12 (`test_api_contract.py:326`) now uses it, which
  removes its inline copy of the body and its own delete. Its old "no password in the response" check had nothing left to
  check, so it was removed with the copy.
- **Credential, ISS-1187.** This is option 1 of the card. `make(..., signs_in=True)` calls `_give_password`
  (`conftest.py:421`), which runs `cognito.admin_set_user_password(email, PASSWORD, permanent=True)` in `backend/.venv`.
  It is the same primitive `seed_test_users.py:99` uses for the seeded accounts, and it uses the same pool id and AWS
  credentials. The password goes in on stdin, and no new package is added to the e2e venv. The four tests that sign in as the
  new account pass `signs_in=True`: S-10-13, S-11-20, S-12-11 and S-17-09. The other seven `make()` callers do not touch AWS.
  Options 2 and 3 were rejected:
  - Option 2, seeding the accounts, needs a hexaware seed group and accounts that stay fresh. It cannot keep S-11-20's
    sign-in half.
  - Option 3, API-level checks, cannot read another user's analytics or catalog without that user's token.

  The e2e README now names the dependency. Not done, as the locked constraints require: no password field on
  `CreateUserRequest`, no test-only endpoint, no `is_admin=True`.
- **Invitation dialog, ISS-1185.** `framework/locators/admin.py:23-24` holds `CREATE_DIALOG` ("Create New User") and
  `SEND_INVITATION` ("Send Invitation"), in one place. S-11-15, ISS-295 and ISS-324 no longer fill a password field and now click
  "Send Invitation". The ISS-577 show/hide-toggle test is retired, because the field it tested no longer exists. ISS-577 stays
  `resolved` as history.
- **Reset contract, ISS-1186.**
  - S-11-17 (`test_admin.py:401`) POSTs `{}`, as the admin screen does (`api.ts:2123`). It asserts 200 and a body equal to
    `{"status": "temporary_password_set"}`, so no credential can come back.
  - S-11-18 (`test_admin.py:427`, now "A reset that names a password is refused") asserts 422 `extra_forbidden` for
    `new_password` plus `permanent`.
  - The break-glass refusal text and the deleted response field are gone.
  - `framework/api.py:101` used to send no body for `{}`, because the check was `if body`. It now checks `is not None`.
    FastAPI answers a missing body for an empty model with a 422 `missing` (checked offline). The only other caller that
    passes `{}`, S-22-05, posts to `/api/handoff/{token}/start`, which declares no body.
- **Catalog label.** "(Depth)" replaces "(Detailed)" at `home_catalog.py:53`, `test_home_catalog.py:135` and
  `test_pipeline_smoke.py:38`, and in the six spec lines ISS-1115 lists.
- **Composer rail.** `composer.py:52` has `Data` instead of `Hooks`. The S-04-10 caption regex is now
  `AI agent · step 1 of \d` (`test_composer_canvas.py:271`, the step kind from `stepKind.ts`). The spec is
  `04-composer-canvas.feature.md:57-58,189-190`.
- **Strict xfails.** The marker line is deleted for ISS-796, ISS-923, ISS-1033 and ISS-190, and for ISS-213 with a comment
  (`test_run_history_pagination.py:186-189`) that names [ISS-219](20260828-1706-ISS-219.md). The oracle is the XPASS(strict) lines
  in `evidence/qa-kb-122/analysis-07-validate-bugs-log-excerpts.txt`, from the 2026-10-09 run on this worktree. The app commits
  since that run do not touch those five surfaces.
- **Workspace listing, S-24-25.** The test is inverted to f9df3737c's contract and renamed to its unit twin's name,
  `test_a_listed_reserved_file_is_readable`. A listed `.uploads/` or `.logs/` file must answer 200. The test skips when the
  run's workspace holds none. The spec is `24-api-contract.feature.md:559-565`.
- **Pinned ids, ISS-1158 and ISS-1188.** All 12 literals are gone.
  - Suite 21 calls `a_revised_family(page)` (`test_run_families_and_versions.py:184`). It returns the newest family with a
    parent from `GET /api/runs?limit=100`, skips divert roots, and reads the members from `/family` in `revision_index` order.
    v2 is `members[1]`, which is the member `PreviewPanel` pins for `/versions/2`. The unused `MID_FAMILY_*` constants went
    with the other literals.
  - ISS-285, ISS-313 and ISS-390 discover a failed run with no deliverable, a completed run with a mimetype but no filename,
    and a diverted run.
  - ISS-228 finds "My prototype" by name.
- **ISS-802 URL filter, ISS-1189.** The test counts only the bare version-list URL
  (`test_iss802_steps_agent_artifacts_duplicate_request.py:73`), so the `?kind=clarifications` read is no longer counted.

`evidence/qa-kb-122/fix-01-discovery-dry-run.txt` replays the discovery predicates in SQL against the dev database. It ran

## For the 6-verifier

These changes turn some tests from red to green. They also let some tests fail for real reasons:

- Suite 21 now runs against `78e185fb`, the family QA-KB-111 reopened on. ISS-606, ISS-609 and ISS-230 may fail because the pin
  is ignored on a cold load. That is QA-KB-111's defect, not drift. ISS-1188 says to mark them xfail for QA-KB-111 only once
  they are seen failing for that reason.
- ISS-285 and ISS-390 used to pass without exercising anything. They now exercise real runs.
- `test_iss228` can now flip.
- [ISS-1186](20261009-1754-ISS-1186.md) and [ISS-1187](20261009-1754-ISS-1187.md) inferred their live outcomes and did not
  run them. These need the live stack, one file at a time: `11_admin` (S-11-15/17/18/20, ISS-295, ISS-324), `24_api_contract`,
  `10_analytics`, `12_shell_nav`, `17_theme_and_tiers`, `19_toasts_and_dialogs`, `21_*`, `07_*`, `05_*`, `06`, `04`, `02`.
- `_give_password` needs the backend AWS credentials to be valid. On an expired login it fails with the subprocess stderr. That
  is an environment problem, not a code one.

Not changed:

- `framework/api.py`'s `request()` keeps its `if body` check. It has no `{}` caller.
- The other fourteen strict-xfail tests that ISS-1158 lists as still XFAIL need a `--runxfail` live run each.
- [ISS-1033](20261002-1055-ISS-1033.md) still says `open` although its marker is removed here. It belongs to QA-KB-060.
