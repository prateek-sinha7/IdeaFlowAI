## What happened

On `/library?tab=hooks`, the only way to open a hook's detail (trigger, event,
compatible agents) is to click one of the 8 hook cards. Those cards are the
`Card` component with an `onClick` handler and `className="p-4 ... cursor-pointer
group"` — no `tabindex`, no `role="button"`, no `onKeyDown` for Enter/Space.
Root cause is `frontend/src/components/library/LibraryPage.tsx:914-920`
(`filteredHooks.map(...)`, the `<Card key={hook.id} onClick={...}>` block).

The same unguarded-`onClick`-`Card` pattern is also used one map up for the
Skills tab's cards (`LibraryPage.tsx:820-826`), but this card only asserts the
Hooks tab, which is the reported bug — the Skills tab was not indpendently
verified and is not claimed here.

## Reproduction (3/3, cycle 1)

Validating BUG-20260828-025521-library-hooks (`bug-hunter/ledger.md`). Signed
in as qa-admin, cold navigation (`/dashboard` → `/library?tab=hooks`) on every
cycle:

1. `document.querySelectorAll('.cursor-pointer.p-4')` returns all 8 cards;
   every one has `tabindex: null`, `role: null`, `onkeydown: false`. Identical
   on cycles 1, 2 and 3 (fresh cold nav each time).
2. Cycle 2 additionally verified via **real keyboard `Tab` key presses**
   (Playwright `page.keyboard.press('Tab')`, not a synthetic `KeyboardEvent`
   dispatch): starting from `input[name='library-search']`, Tab moves through
   the Agents/Skills/Hooks tab buttons and the 5 category-filter pills, then
   lands on `document.body` — no card in the grid ever receives focus.

No axis variation was needed; identical across all 3 cold-start cycles,
default qa-admin tier, light theme, first visit each time.

## Expected vs actual

Expected: each hook card reachable via Tab and activatable via Enter/Space
(rendered as a `<button>`, or `role="button" tabindex="0"` plus a keydown
handler), matching the page's own "tap any item to see its capabilities" copy.

Actual: the entire 8-card grid is invisible to keyboard/assistive-tech
navigation; hook detail is reachable only by mouse/touch click.
