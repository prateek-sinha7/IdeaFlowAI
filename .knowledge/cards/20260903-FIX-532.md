## Related

## What was wrong

`useTheme` renders `"light"` once before its effect reads the real
`data-theme`, so in dark mode the deliverable iframe mounted with the LIGHT
document and had its `srcdoc` attribute rewritten roughly 40 ms later. Chrome
painted nothing. Measured on run `b0642e0f`: iframe added `srcdoc=72,792`, then
`attr:srcdoc 72,874`, one `load` event, blank — while a fresh element with
identical attributes rendered fine.

Only custom/unknown deliverables reach this renderer, which is why the
prototype (blob URL) and ppt (its own path) previews never went blank.

## The fix (commit 3e6fcb93c)

The iframe is keyed on the theme, so a theme resolution remounts it. That makes
the normal path do what users had been achieving manually by switching to
Markdown and back.
