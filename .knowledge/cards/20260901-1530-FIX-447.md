## What was wrong

`PreviewPanel.appBuilderSearch.test.tsx` is the ISS-500 regression test. After
[FIX-394](20260829-0127-FIX-394.md) fixed the folder-pruning defect, the
substantive assertion —
`expect(screen.queryByText("styles")).not.toBeInTheDocument()` — passed, but
the test remained in the "expected fail" state because the trailing sanity check
then threw a `TestingLibraryElementError`:

> `Found multiple elements with the text: app.js`

The fixture has `src/app.js` as `files[0]`, and `AppBuilderPreview`'s mount
effect auto-opens `files[0]` as an editor tab, rendering "app.js" twice — once
as the tree row, once as the tab label. `getByText` throws on multiple matches;
`getAllByText` does not.

## Root cause

```tsx
// Before — throws when "app.js" appears in both the tree row and the tab label
expect(screen.getByText("app.js")).toBeInTheDocument();
```

## What changed and why there

One line in the test, using `getAllByText` to tolerate the duplicate without
changing the assertion's intent (confirm "app.js" is visible):

```tsx
// After — works correctly when the editor tab also carries the filename
expect(screen.getAllByText("app.js").length).toBeGreaterThan(0);
```

The `it.fails` marker and the `queryByText("styles")` assertion are unchanged.
The test now XPASSes (vitest reports "Expect test to fail" — the strict-xfail
signal that the fix works). The `it.fails` marker is left in place for the
6-verifier to remove after independent confirmation, per workflow protocol.
