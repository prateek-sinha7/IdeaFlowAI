## Description

Two model call-sites spent the owner's money without it appearing in the run's reported cost. (1) The validation fix-loop re-invokes the build sub-agent on a …:fixN thread and drains its stream INTERNALLY; the drain was a bare continue, so every usage event was discarded — measured on the live run fa66227a that is ~929,000 input tokens, 6.9% of the run's input (+$0.176 of $2.550), and it recurs on every run whose validation fails. (2) handoff/TestAgent.analyse still called llm.ainvoke raw: neither Bedrock-cached nor counted — up to ~8k repo tree + N×10k test files per call. This is a Phase 43-04 MISS, not a new regression: that plan's own wording, "handoff Test(classifier)", mistook classifier.py (the coding-vs-test router) for test_agent.py (the real Test agent), so it routed the wrong module and closed. Part A of ISS-033 only — the Concierge/handoff *unbounded-input* half is ISS-092.

## Root cause

(1) _run_validation_fix_loop had no way to report usage: the loop is a non-yielding coroutine (it must re-emit nothing, so the UI shows ONE build per task), and the only accumulator reachable from it — results — is the wrong one, because agents_completed = len(results) would turn each fix attempt into a phantom agent. The right accumulator, aux_token_usage (43-04), was simply never threaded down. (2) 43-04 routed by plan wording rather than by call-site: a grep for the raw ainvoke would have caught it, a grep for "Test agent" did not.
