# FIX-605

Fixes QA-PS-012 (register: `LEDGER.md`, detail: `BUGS.md#qa-ps-012`).
Resolves [ISS-694](20260922-0918-ISS-694.md) (root cause) and
[ISS-731](20260922-1348-ISS-731.md) (sibling render site) — one change cures
both, because both cards trace to the same literal in the same shared
component.

## What was wrong

The prototype wizard's template grid (`/create/prototype`, "Configure your
prototype" step) rendered its first card — pre-selected by default, sitting
alongside 48 named templates — labeled **"No template"** / "Blank canvas".
The copy describes the *absence* of a selection, while the card is in fact
the wizard's *default* starting point, so the label contradicted its own
behaviour. Severity Low: copy-only, no functional break.

## Root cause

`frontend/src/components/workflow/prototype/TemplateGallery.tsx:358`, inside
`NoTemplateCard` (added under KAN-87, per the comment at line 328):

```tsx
<span className="block truncate text-[11px] font-medium text-ink-800 leading-tight">
  No template
</span>
```

The label was a hardcoded literal, not derived from any data source.

## What changed and why there

The literal `"No template"` became `"Default Template"` at
`TemplateGallery.tsx:358`, and nowhere else. That single line is where every
caller routes through, which is why the fix belongs there rather than in the
call sites:

- `WizardStepper.tsx:168` — `/create/prototype`, the route QA-PS-012 reported.
- `DesignPickerModal.tsx:295` — the `designMode !== "deck"` ("web") branch,
  the shared design picker, itself mounted from `IdeaInputPage.tsx:2160-2170`
  and `ComposerPage.tsx:1668-1677`.

Blast radius re-verified at fix time, not taken on trust:
`grep -rn "<TemplateGallery" frontend/src` returns exactly those two
production render sites plus test files, confirming ISS-731's analysis still
held. Both pick the fix up transitively with no per-caller patch.

One companion edit, named explicitly in ISS-731's Fix section:
`TemplateGallery.reskin.test.tsx:90` used `screen.getByText("No template")` as
the **locator** for the click target (its assertion is
`expect(onSelect).toHaveBeenCalledWith(null)` — behaviour, not copy). The
locator string was retargeted to `"Default Template"`. The test's assertion
was not weakened or changed; only the query that finds the element to click.

## Deliberately not changed

The backend's `no_template` flag (e.g.
`backend/agents/execution_engine/od_context.py:149`) is an internal field
name that is never rendered to a user — out of scope per ISS-731, and left
alone. No backend file was touched.
