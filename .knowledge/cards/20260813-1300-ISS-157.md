# ISS-157

## Title

**`syncPipelineStateOnly` is added to the run store, exported on the interface, and never called** — dev's FIX-220 register row says "for future use". The rAF fix it ships alongside still calls `runStore.updatePipelineState`. A dead abstraction is exactly what INV-12 forbids.

## Severity / Tag / Status (original row)

- Sev: minor
- Tag: frontend
- Status: **FIXED** — FIX-256 (2026-08-13, commit `d0dc1f49`). `syncPipelineStateOnly` DELETED — never called, a second mechanism for what the rAF coalescing already does (INV-12), and its stated premise was false: it justified skipping `project()` because "handleFrame projects on every SSE frame", but handleFrame returns early before any projection on `waveIndex === undefined` and on `!pipelineFrameTypes.includes(msg.type)`, so wiring it would have silently dropped UI updates. A tombstone comment records why. TEST-035 locks the deletion on CODE, not on the bare name, so the tombstone survives.

## Source / Evidence

`frontend/src/hooks/useRunStateStore.ts:225` (interface), `:463` (impl), `:516` (export). A repo-wide grep finds no call site.
