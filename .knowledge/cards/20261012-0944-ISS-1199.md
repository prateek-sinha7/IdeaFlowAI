# ISS-1199

**Register source:** `QA-KB-121` (Medium, route POST /api/runs), analyzed 2026-10-12 by the 3-analyzer. Root card.

**What the owner already decided** (`BUGS.md`, section QA-KB-121, "Owner decision" 2026-10-09, option a): keep the expiry-only, no-network preflight
(no live Bedrock probe). Improve the failure the user sees when Bedrock rejects the key at the first model call (AccessDenied "API Key invalid"): a clear
message that the Bedrock API key is invalid or revoked and must be rotated, not a generic provider error. Only local dev uses the temporary rotated key;
production uses a persisted key, so keep the change small and dev-friendly. This card therefore does NOT treat "the preflight passes a revoked key" as the
defect. The defect is the message.

**Confidence.** CONFIRMED by source read, by SELECT-only DB rows, and by offline probes that run the REAL `_sanitize_agent_error` source (extracted with `ast`
from `engine.py`) against botocore-built exceptions: what the user sees today, and every line that produces and consumes it. No browser, no run and no model
call was made. INFERRED, marked where it occurs: the exact code and message Bedrock sends for the rejected key (not on disk anywhere; see "Settling the
INFERRED parts") and which persisted run is the reported one.

## What the user sees today (CONFIRMED)

A run launched with a key Bedrock rejects is accepted and fails in 2 to 4 seconds on its first model step. Persisted proof (SELECT-only, `evidence/qa-kb-121/analysis-03-db-rows.txt`):

- Run `eb1d7551-cfc8-4265-8b06-154128cc124a`, type `ex_A1_loop`, created 2026-10-09 11:12:20Z, `status=failed`, 4 agents declared. Events: seq 4 `agent_start`
  (`custom-agent:emoji`, model `eu.anthropic.claude-haiku-4-5-20251001-v1:0`), seq 7 `agent_error`, seq 8 `pipeline_failed` with `total_duration 2.15`,
  `agents_completed 0`, `agents_failed ["custom-agent:emoji"]`. Both carry `"error": "The model could not be reached — a provider credential or permission
  problem (the run's cloud session may have expired)."`, and `workflow_runs.error` is the same sentence. Only one `agent_start` exists although 4 agents are declared, which is the FIX-657
  run-stop's signature.
- Run `95cb5ace-29be-4e04-bcc6-c73f3379eb2c` (`ex_A1_loop`, 2026-10-09 17:16:55Z, 3.77 s) shows the identical three rows. Its cause is not recorded; it is listed
  only as a second occurrence of the same text.
- Timeline fit (INFERRED, the report cites no run id): the report was logged "Found at 2026-10-09 13:17" local, which is 11:17Z (server clock CEST, UTC+2);
  `eb1d7551` completed at 11:12:23Z. At 11:41:56Z the same workflow (`9a931a7a`, QA-KB-124) got past the model call and failed later at the check step's gate,

The sentence is the constant `_CREDENTIAL_AGENT_ERROR` (`engine.py:196-199`). It tells the user about a "cloud session" and never says API key, invalid,
revoked or rotate. The UI shows it verbatim: `useWorkflow.ts:1212-1245` stores it as `agent.error`, `AgentDetailPanel.tsx:1581-1584` renders `{agent.error}`.

## Root cause (CONFIRMED)

One mechanism: the only classifier between a provider's rejection and the user is a closed substring table that has no row for "the API key itself is bad".

1. **The preflight cannot see revocation, by design.** `preflight_check_provider` decodes the bearer token's own expiry and nothing else
   (`model_factory.py:153-170`: `expiry = decode_bedrock_bearer_token_expiry(token)` ... `if now >= expiry - skew:`); its docstring says anything more "would mean a live
   model call on every launch" (`:126-134`). A token that decodes as unexpired but is revoked passes. Owner: keep.
2. **The first model call fails and the runner swallows it into a string.** `AccessDeniedException` is a PERMANENT code (`backend/agents/model_policy.py:448-458`), so
   `_is_transient_throttle` is False and nothing retries it (botocore does not retry it either, `model_factory.py:531-539`). `DeepAgentRunner` then does
   `logger.exception(...)` and `yield {"type": "error", "error": str(exc)}` (`deep_agent_runner.py:1415-1416`).
3. **The engine turns that string into the user's sentence.** The `error` arm does `agent_error_message = _sanitize_agent_error(agent_error_raw)` on the first 500 characters
   (`engine.py:10425-10432`) and emits it as the step's `agent_error` (`engine.py:10615-10622`). The raw text goes only to the server log (`engine.py:10589-10595`).
4. **`_sanitize_agent_error` (`engine.py:278-295`) walks `_AGENT_ERROR_CATEGORIES` (`:220-275`), first match wins, and no row is about the key.** An
   `AccessDeniedException ... API Key invalid` is caught only by the broad credential row through the needle `"accessdenied"` (`:231-247`) and returns
   `_CREDENTIAL_AGENT_ERROR`. Probe case A: `str(exc)` = `An error occurred (AccessDeniedException) when calling the ConverseStream operation: API Key invalid` gives the
   cloud-session sentence. Probe case F (code spelled `AccessDenied`, as the register title writes it) gives the same.
5. **If botocore finds no error type, nothing matches at all.** For a rest-json response without an `x-amzn-errortype` header, botocore takes the code from the HTTP status
   (`botocore/parsers.py`, `BaseJSONParser._do_error_parse`: `code = body.get('__type', response_code and str(response_code))`). Probe case B: `str(exc)` =
   `An error occurred (403) when calling the ConverseStream operation: API Key invalid` matches none of the 12 credential needles and falls through to
   `_GENERIC_AGENT_ERROR_MESSAGE` = "The model rejected this request." (`engine.py:179`, returned at `:295`). That is the literal "generic provider error".
6. **The same string drives the run-stop.** FIX-657's rule compares by equality: `if event.get("data", {}).get("error") == _CREDENTIAL_AGENT_ERROR:` (`engine.py:6540`), and the
   resulting `pipeline_failed` hardcodes the constant: `"error": _CREDENTIAL_AGENT_ERROR,` (`engine.py:6586`).

So the one signal the user gets, given the preflight is expiry-only, names the wrong credential (a cloud session) and gives no remedy.

## Where the fix belongs (INFERRED: recommendation, not applied)

In `backend/agents/execution_engine/engine.py` only. The funnel is one function, so one change reaches every caller above.

1. Add a literal, for example `_INVALID_KEY_AGENT_ERROR`, beside `_CREDENTIAL_AGENT_ERROR` (`:196`). Intent from the owner: the API key is invalid or revoked and must be
   rotated. Suggested copy, mirroring the preflight's own wording at `model_factory.py:166-169` and the eval harness hint at `backend/evals/minimal/run-aws.sh:79-82`:
   "The model could not be reached — the provider rejected its API key (invalid, revoked or expired). Rotate the key (Bedrock: AWS_BEARER_TOKEN_BEDROCK) and restart the
   backend." The owner or fixer confirms the final copy.
2. Add one row to `_AGENT_ERROR_CATEGORIES` immediately ABOVE the credential row (`:231`), because the first match wins (`:292-294`). Match on the MESSAGE text, not the code,
   so it holds for all three wire shapes in the probe: `"api key invalid"`, `"invalid api key"`, `"api key is invalid"`, and the Anthropic wording ([ISS-1202](20261012-0944-ISS-1202.md)).
3. Make the run-stop recognise the new literal: replace the equality at `:6540` with membership in a small frozenset of credential-class messages, remember the failing
   step's own message, and put THAT on the `pipeline_failed` at `:6586` instead of the constant. Without this the run does not stop at the first step.

Leave alone: `preflight_check_provider` (owner decision), `TRANSIENT_AGENT_ERRORS`, `_CREDENTIAL_AGENT_ERROR` and its mapping for `ExpiredTokenException`.

If a second caller should share the classification ([ISS-1201](20261012-0944-ISS-1201.md)), the pure function can move to a leaf module both sides may import (app may import the kernel, never the reverse).

## Traps for a naive fix (invariants at risk)

- **FIX-657's locked constraint.** Adding a new literal in the table and nothing else makes `engine.py:6540` miss it, so the run goes on to every later step against the same
  dead key (the run 715c1279 failure in [FIX-657](20260930-1723-FIX-657.md)). The existing test only proves the constant stops the run.
- **Do not import `app.agents.llm_errors` into the engine** ("mirror `map_exception`" is what the WR-02 comment suggests). The kernel must not import `app.*` (import-linter;
  already 2 contracts broken, see [FIX-772](20261009-0335-FIX-772.md) and [ISS-1068](20261007-2034-ISS-1068.md)), and the engine holds only a string, never the `ClientError`
  (`DOMAIN-agent-runtime`, "The engine does not reuse `map_exception`"). Also, `map_exception` is exact-code, so code `AccessDenied` or `403` falls to "Something went
  wrong. Please try again." with a Try Again button (probe cases B and F), which is worse.
- **Do not add a provider or workflow name to the NEEDLES**: the comment at `engine.py:287-289` says matching is on generic fault vocabulary (SC-001, INV-1). The copy may
  name the env var; no guard test forbids it, but the kernel stays provider-neutral if the copy says "the provider's API key".
- **Leak guard (WR-02).** The new branch returns a hardcoded literal; never format the raw text into it.
- **Frontend regex.** `StepsOverviewSpine.tsx:362-365` renders a "Blocked by the security gate" card when an agent error matches
  `/security.*gate|blocked.*security|exec.*denied|exec.*off|secret.*scan|secret.*blocked|credential.*blocked|hook.*block/i`. The copy must not match it (no "blocked").
- **Do not change `_CREDENTIAL_AGENT_ERROR`'s text or mapping**: `test_credential_failure_stops_run.py:60` and `test_image_payload_guard.py:213,231` pin it.
- **Goldens:** the scripted golden model never raises, so the new branch is dormant there (INV-3).
