# ISS-641

## Title

**The graceful-shutdown budget has an arithmetic helper and no assertion.** Commit
`732adc245` removed `docker-compose.yml` from the repo and, with it, deleted
`_stop_grace_period_seconds()`, `test_production_teardown_budget_fits_inside_stop_grace_period`
and the `def` + body head of `test_production_leaves_shutdown_stop_runs_off` from
`backend/tests/unit/test_shutdown_reachability.py`. What is left is the tail of the second
test, now sitting **after** `return total` inside `_teardown_budget_seconds()`
(`test_shutdown_reachability.py:256-262`): unreachable, referencing an undefined `prod` and a
deleted `_stop_grace_period_seconds`, so it neither runs nor fails. The file's own docstring
still advertises "3. the teardown budget still fits inside docker's `stop_grace_period`" and
`_teardown_budget_seconds()` now has **no live caller at all** — the budget is documented,
computed, and asserted nowhere.

Consequence: raising `SHUTDOWN_CONCIERGE_DRAIN_SECONDS` / `SHUTDOWN_TASK_DRAIN_SECONDS` /
`SHUTDOWN_CHECKPOINTER_CLOSE_SECONDS` past the container's stop deadline is caught by nothing.
That guard is exactly what [ISS-106](20260812-1315-ISS-106.md) asked the new setting to be
visible to, so [FIX-428](20260831-1816-FIX-428.md) added the term to a function that currently
runs only if the test is restored.

**Fix shape:** decide where the ceiling now lives (the repo declares no `stop_grace_period` and
no ECS `stopTimeout`, so today it is docker's/ECS's implicit default rather than a checked-in
number), then restore the two tests against that source and delete the orphaned lines. Naming
the ceiling explicitly in infra is the part that needs a decision, not the test.

## Source / Evidence

Found by 5-fixer while fixing [ISS-106](20260812-1315-ISS-106.md) (2026-08-31). `git show
732adc245 -- backend/tests/unit/test_shutdown_reachability.py` shows the three deletions in one
hunk; `grep -rn "stop_grace_period" docker-compose.yml infra/` finds the file absent and only a
prose mention in `infra/terraform/RUNBOOK.md:433`; `grep -rn "stopTimeout" infra/ backend/`
returns nothing. Not fixed with FIX-428 because restoring the assertion requires choosing the
ceiling's new source of truth, which no card authorises.

## Resolution

Verified fixed in the current code on 2026-10-01 (feat/user-stories-v2 @ 3b08b2ba8) by static review: a first-pass check and an independent adversarial re-check both found every claim of this card fixed. No tests were run for this closure.

**Fixed by:** Not pinned down. 08c5ebb17 (the checker's SHA) is a dev merge dated 2026-08-20, earlier than the card's 2026-08-31 date. docker-compose.yml was last touched in b2a621f84 and the test file in 1d95275b4 (merge of origin/dev into feat/stable). The restoring commit is probably one of those.

**Evidence:** The file is at backend/tests/unit/services/test_shutdown_reachability.py. The card's path (tests/unit/) is stale. Claims checked in the current source:
1. `_stop_grace_period_seconds()` exists (l.70) and reads stop_grace_period from docker-compose.yml.
2. docker-compose.yml exists in the repo with `stop_grace_period: 30s` (l.75). The card's "file deleted" premise no longer holds.
3. `_teardown_budget_seconds()` (l.262-294) ends in `return total`, with no orphaned code after it.
4. It has live callers at l.300 and l.333.
5. `test_production_teardown_budget_fits_inside_stop_grace_period` (l.297) and `test_production_leaves_shutdown_stop_runs_off` (l.308, with `prod = Settings(...)` at l.316) are present.
6. By my arithmetic from the defaults in backend/app/core/config.py:318-326 and the `--timeout-graceful-shutdown 5` in backend/docker-entrypoint.sh:35, the budget is 5+10+3+3+3+1 = 25s, under the 30s ceiling. I did not run the tests.

**Left over (outside this card's claims):** none. Only the card is stale: status is still open, and the globs path and the "no stop_grace_period declared" wording are outdated. The ceiling is now declared in docker-compose.yml and checked. The file's docstring (l.19) still matches the tests, so nothing needs fixing there.
