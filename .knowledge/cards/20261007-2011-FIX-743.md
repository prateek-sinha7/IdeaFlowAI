# FIX-743

Bug report QA-KB-084 (Low), sibling card. The root cause and the fix direction come from
[ISS-1026](20261002-0700-ISS-1026.md) and are not re-derived here. The parser half of the bug,
[ISS-941](20261001-2240-ISS-941.md), is fixed by [FIX-742](20261007-2011-FIX-742.md). The two are independent and touch
different files. Frontend only.

## What was wrong

A tab click made while pinned changes the URL shallowly (`window.history.pushState`), and so does the Back/forward that
follows it. No remount happens, so the only branch they reach is the tracked-run branch of the T7 effect in
`frontend/src/app/[...view]/page.tsx`. That branch picked the tab with
`reopenTabFor(parsedView.screen) ?? (parsedView.screen === "run-detail" ? "preview" : undefined)`. The pinned Preview URL
`/runs/{id}/versions/{v}` parses to `run-version`, and neither side of that expression names it. So `openTab` was
`undefined`, no tab was requested, and the panel stayed on Steps under a Preview URL.

## What changed, and why there

`page.tsx:3489`: the fallback now reads
`parsedView.screen === "run-detail" || parsedView.screen === "run-version" ? "preview" : undefined`. Two comment lines
(`:3486-3487`) say why. This is the ISS-1026 fix direction, applied as written:

- `run-version` was NOT added to `reopenTabFor`. That function also serves the cold-open path, where a still-building run
  must keep its state-derived Steps default (the comment at `:3483-3485`).
- The two strings that `runTabShallowNav.test.ts` pins in this branch are unchanged.

The new comment deliberately does not contain the literal `run-version`. The ISS-1026 test slices this branch and matches
`/run-version[\s\S]*"preview"/`, so a comment containing that word would satisfy the test even with the code reverted.
