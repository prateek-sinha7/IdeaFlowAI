## What was wrong

`_apply_terminal_output_columns` (`backend/app/api/run_commands.py`) is the sole writer of
the `token_usage` column for every completion path (launch, revision, resume). It derived
totals by re-summing `agent_outputs_collector` — the list of `agent_complete` events. The
engine also folds aux token spend (SmartPlanner, clarify one-shot, validation fix-loop
sub-agent) into the `pipeline_complete` event's own `total_input_tokens` /
`total_output_tokens` fields via `aux_token_usage`. None of those aux tokens appear in
any `agent_complete` event, so every run that used those paths persistently undercounted
its `token_usage` — and Analytics, which reads that column, underreported KPI tiles /
daily charts / per-model breakdowns by the same delta (~7,503 tokens on the confirmed
run `a0693fcd-...`).

## What changed

`backend/app/api/run_commands.py` — `_apply_terminal_output_columns` only:

1. Three `_pc_total_input / _pc_total_output / _pc_total_tokens` variables initialized to
   `None` before the event loop.
2. In the `pipeline_complete` branch: capture `data.get("total_input_tokens")` /
   `data.get("total_output_tokens")` / `data.get("total_tokens")` into those variables.
3. After the agent_outputs_collector re-sum: compare `_pc_in + _pc_out` against
   `total_input + total_output` and prefer the larger pair. A missing / bad field
   degrades to the legacy re-sum (try/except, INV-3).

No other function changed. The fix applies automatically to all four callers of
`_apply_terminal_output_columns` (launch driver, both resume entry points, revision driver)
because they are all the SAME function (INV-12).

## Test coverage

`backend/tests/agents/test_restart_resume.py` — 109 passed (16.98s). The existing
`test_apply_terminal_output_columns_populates_all_columns` test covers the function's
column-population contract and passed without modification, confirming the override logic
does not break existing completions that carry no aux spend (the `_pc_in + _pc_out == 0`
branch degrades to the re-sum).
