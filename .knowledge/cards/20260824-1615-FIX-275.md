A step re-entered by a loop-back never showed a visit count anywhere, and the gate-key
fold that keeps a re-entered step's gate from colliding with its own earlier firing was
inert.

## Root cause

The dual-identity trap. A composed step has an authored `instance_id` (`greet`) and a
composed runtime id (`custom-agent:greet`). The backward-jump arm WROTE
`step_visit_counts` under the authored id — it had the raw route target in hand — while
every reader used the composed spec id. The lookup always missed, so the count read 0
forever.

Nothing failed loudly: a 0 is a legitimate value, so the gate-key fold and the completion
record simply behaved as though the step had never been revisited.

## Fix (R-08)

Both the read and the write now key on `ordered_agents[_route_index].id` — the composed
id — so they cannot diverge again.

The identity rule this violated is recorded in [ADR-0017](20260824-1630-ADR-0017.md).
