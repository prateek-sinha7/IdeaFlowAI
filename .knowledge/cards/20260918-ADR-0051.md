## Decision

Each long-lived branch mints card IDs from its own floor:

| line | branch | FIX | ISS |
|---|---|---|---|
| bug-fixer | `feat/git-versioning` | `FIX-600+` | `ISS-700+` |
| document/prototype work | `feat/pdf-workflow` | below `600` | below `700` |

Agents keep taking family max + 1. The floor only clamps where that count starts.

## The problem this solves

Card IDs are minted by reading the highest number in the family from
`.knowledge/cards/` and adding one:

```
ls .knowledge/cards/*-FIX-*.md | grep -oE 'FIX-[0-9]+' | sort -t- -k2 -n | tail -1
```

That store is **branch-local**. Two branches working between merges each see only
their own cards, so both correctly compute the same "next free" number and both
hand it out — to entirely unrelated work.

This is not a hygiene failure. Every agent followed the rule; the rule reads a
value that cannot see the other branch.

## Why git never warns you

Card filenames carry a datetime prefix, so the two copies of one ID are two
different filenames:

```
20260904-ISS-644.md        this branch — single_file readback replaces later output
20260917-0930-ISS-644.md   bug-fixer   — notification panel shows "0 of N agents"
```

Different names, so **both merge cleanly with no conflict**. Nothing in the merge
output mentions it. The knowledge base then holds two cards claiming one ID, and
`build_index.py` re-resolves every reference by ID on each rebuild — so roughly
1,300 cross-references resolve to whichever file is found first, silently, and a
rebuild does not repair it because a rebuild is what propagates it.

## Why the obvious fixes do not work

**Tightening max + 1 changes nothing.** It is already correct. Its input is the
problem.

**`normalize_card_ids.py` cannot repair a collision.** It treats a duplicate id
as fatal and aborts before writing anything. That is deliberate — it normalises a
scheme, it does not arbitrate ownership. Every collision resolution so far has
been a purpose-built rewrite.

**A rebuild makes it worse, not better.** Links resolve by ID, so duplicate IDs
survive a rebuild and cross-wire on every subsequent one.

## History

| merge | collisions | resolution |
|---|---|---|
| first | 49 (`ADR-0035/0036`, `FIX-323..369`, `ISS-188/189`) | renumbered to `FIX-517..561` / `ADR-0043-0044` / `ISS-644-645`; 973 references rewritten across 310 files |
| second | 20 (`FIX-517..524`, `ISS-644..655`) | renumbered to `FIX-571..578` / `ISS-682..693` |

Note what the first resolution did: it moved this branch into `FIX-517..561`,
which is precisely the band the bug-fixer line then minted into. **Resolving a
collision without agreeing a floor manufactures the next one.** That is the whole
argument for this decision.

## How to resolve a collision, when one still happens

1. **Pick the side that moves by counting inbound references, not by seniority.**
   A card whose ID is encoded in test *filenames* (`DashboardLayout.iss644.test.tsx`,
   `AppHeader.iss647.test.tsx`) or cited in a live register (`LEDGER.md`, `BUGS.md`)
   is expensive — renaming it means renaming test files and rewriting card↔test
   backlinks. A card referenced only inside `.knowledge/` is cheap.

2. **Rewrite on the link target filename, never the bare id.** This is the trap.
   A bare `ISS-644` in prose cannot be attributed to a branch, so a bare-id
   substitution pass also rewrites the *other* branch's references to its *own*
   cards — producing a link whose label reads `ISS-691` while its target still
   reads `20260917-1050-ISS-653.md`. Observed during the second merge: 47 of the
   other branch's cards were altered and 30+ links left mismatched before the pass
   was reverted and redone keyed on the target.

3. **Verify with `validate_links.py`, and check label/target agreement separately.**
   A broken link fails the rebuild loudly; a link pointing at the *wrong existing
   file* does not. The second merge finished at 15,398/15,398 resolved, 0 broken,
   0 duplicate IDs, 0 label/target mismatches.

## Why a floor rather than better tooling

A shared counter needs a shared store, which is the thing two divergent branches
do not have. A lock needs a coordinator. A pre-commit check catches a collision
only once both sides are already in one tree, which is after the cheap moment to
fix it has passed.

Two numbers, written down, cost nothing and need no tooling at all. The failure
they prevent is not "someone picked a bad number" — it is two correct processes
reading the same incomplete view.
