# ISS-821

## Description

INFERRED sibling of [ISS-819](20260922-1940-ISS-819.md) (QA-PS-043). Same
"any unguarded mount effect calling `getWorkflowDetail` doubles under
StrictMode" root cause, checked against the one remaining surface that opens
on a user action (a dialog `open` flip) rather than a route change — the
first fire of a prop-gated effect is still a first mount as far as
StrictMode is concerned, so the same double-invoke applies.

## What was read

`frontend/src/components/workflow/WorkflowDialog.tsx:69-101`:

```tsx
useEffect(() => {
  if (!open) return;
  let cancelled = false;
  const jwt = token ?? getToken();
  if (!jwt) { setError("Not authenticated."); setLoading(false); return; }
  setLoading(true);
  Promise.all([getWorkflowDetail(jwt, workflowId), fetchCapabilities(jwt)])  // :79
    .then(([wf, palette]) => {
      if (cancelled) return;
      setDetail(wf);
      // ...
    });
  return () => { cancelled = true; };
}, [open, workflowId, token]);
```

Identical shape: a `cancelled` flag that blocks the state update, nothing
that stops the fetch itself or dedupes a concurrent identical call. Bundles
`fetchCapabilities(jwt)` in the same `Promise.all` — that call has the same
exposure but is a separate function outside this card's `applies_to`.

## Why this is worth a card

Every place `WorkflowDialog` is opened (a "view workflow" action elsewhere
in the app) pays this cost on first open per mount — two real HTTP requests
where one is expected, plus whatever loading-state flicker the second
resolution causes. Filed as INFERRED: the CODE gap is confirmed by direct
read; no live capture of opening this dialog was taken for this card.

## Expected vs actual (to be measured)

- Expected: `GET /api/workflows/{id}` and `GET /api/capabilities` each fire
  once when the dialog first opens for a given `workflowId`.
- Predicted actual: twice each, from this one effect, doubled by StrictMode.

## Where the fix belongs

Not here. Same shared fix as [ISS-819](20260922-1940-ISS-819.md): a keyed
in-flight guard on `getWorkflowDetail()` in `frontend/src/lib/api.ts`,
mirroring [FIX-616](20260922-1923-FIX-616.md). `fetchCapabilities()` would
need the identical treatment separately if its own duplication is ever
confirmed — out of scope here since this card's `applies_to` is
`getWorkflowDetail` only.
