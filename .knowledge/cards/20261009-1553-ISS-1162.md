# ISS-1162

## Description

INFERRED sibling of [ISS-1067](20261007-2030-ISS-1067.md) (bug QA-KB-125), found while measuring what removing
`allow-same-origin` costs. ISS-1067's Disposition left that open: "removing `allow-same-origin` may break in-app deck or
prototype behaviour, which is a decision for analysis". It does break it, and the same break already exists on the
viewers that are sandboxed correctly.

## Why the root cause implies it

`PrototypePreview.tsx` moved from `srcDoc` to a `blob:` URL with `allow-same-origin` in commit `77228e567`
(2026-05-20), whose comment says it "makes window.location.hash writable and hashchange events fire, enabling the SPA hash
router in the generated prototype HTML". That was a real problem and a wrong fix: it solved navigation by giving the
document the app's origin. Any correct fix of ISS-1067 has to solve navigation another way, or prototypes regress.

## Evidence

CONFIRMED in real Chrome 151 (`evidence/qa-kb-125/analysis-2-nav-probe.txt`, `analysis-1-origin-probe.txt`,
`analysis-4-history-base-probe.txt`), against a stub parent at `http://app.test/runs/abc` (route interception, no server).
The document under test is a small generated SPA: two `<a href="#...">` links, a `hashchange` listener.

| shape | origin | `<a href="#/p2">` click | `location.hash =` | `history.replaceState/pushState("#...")` |
|---|---|---|---|---|
| A blob, `allow-scripts allow-same-origin` (PrototypePreview today) | app | works, hashchange fires | works | works |
| B blob, `allow-scripts` | null | silent no-op, hash stays empty | silent no-op, no event | replaceState works |
| C srcdoc, both tokens (PPTPreview today) | app | frame loads the parent URL | works | throws SecurityError |
| D srcdoc, `allow-scripts` (generic renderer, History, SandboxTab) | null | frame loads the parent URL | works | throws SecurityError |
| H D plus `<base href="about:srcdoc">` first in `<head>` | null | works, hashchange fires | works | works |
| I http page with response header `Content-Security-Policy: sandbox allow-scripts` (the share link) | null | works | works | not measured |

Rows C and D: after the click the frame URL is `http://app.test/runs/abc#/p2`, so the deliverable is gone and the app
itself is loaded inside the iframe. The cause is the base URL: a srcdoc document resolves `#/p2` against the parent's
URL, which is not the document's own URL (`about:srcdoc`), so it is a navigation, not a fragment jump.

The sites that hit rows C and D today, all read: `PreviewPanel.tsx:252-279` (generic `text/html`),
`WorkflowHistory.tsx:1082-1089`, `SandboxTab.tsx:1652-1658` (workspace HTML preview), `PPTPreview.tsx:248-261`. Generated
decks and prototypes use JS navigation or hash links, and the OD templates call `history.replaceState` unguarded in
`html-ppt/assets/runtime.js:239`, `flowai-live-dashboard-template/assets/template.html:316`,
`html-ppt/templates/layout-showcase.html:37` and `html-ppt/templates/single-page/code.html:23` (the `deck-stage.js:483`
copies are try/catch).

INFERRED, not driven in the app UI: that a real deliverable shows this. What would settle it: open a completed generic
`text/html` deliverable that contains `<a href="#section">` and click the link. Also unmeasured: what the real app does
when it is loaded inside the opaque frame (login redirect, framing headers).

## Expected vs actual

- Expected: a `#fragment` link inside a previewed document scrolls or routes inside that document.
- Actual: srcdoc frames navigate to the parent URL; blob frames without `allow-same-origin` do nothing.

## Fix direction

Inject `<base href="about:srcdoc">` as the first child of `<head>` before setting `srcDoc` (row H). It restores anchors,
`location.hash`, `hashchange`, `popstate` and the History API with an opaque origin, in one place, so it belongs in the
shared helper of [ISS-1067](20261007-2030-ISS-1067.md) and is used by every srcdoc site. It also lets PrototypePreview
leave `blob:` and `allow-same-origin` together.

Caveats, not all measured. Under that base, relative and protocol-relative URLs stop resolving (row H in
`analysis-4-history-base-probe.txt`: `img.src` stays `//app.test/pixel.png`). A blob document already behaves that way, so
PrototypePreview loses nothing; decks and generic HTML that use a protocol-relative URL would. None of the repo's OD
templates or design systems does (grep: 0 matches), so the exposure is LLM-authored output only (INFERRED). An agent
document that declares its own `<base>` needs the injection to come first. Firefox and Safari were not probed.

## Test notes

Unit-test the helper in vitest: base inserted first in `<head>`, inserted when there is no `<head>`, not duplicated on a
second pass. JSDOM cannot reproduce the navigation, so the behavioural check is the real-Chrome probe
`analysis-2-nav-probe.py` row H, rerun by the verifier through the real UI on a prototype with hash routing.

## Resolution (QA-KB-125, 2026-10-09)

Resolved by [FIX-775](20261009-1625-FIX-775.md) through the shared helper of [ISS-1067](20261007-2030-ISS-1067.md). `frameableAgentHtml` inserts `<base href="about:srcdoc">` after `<head ...>`, else after `<html ...>`, else after the doctype, else first, and is idempotent. It is applied at every srcdoc site: `PrototypePreview.tsx`, `PPTPreview.tsx`, the generic `text/html` iframe in `PreviewPanel.tsx`, the History reopen iframe in `WorkflowHistory.tsx`, `SandboxTab.tsx`, and the new-tab wrapper. Helper unit tests in `frontend/src/lib/agentHtml.test.ts`; the navigation itself (probe row H) is for the verifier in real Chrome.
