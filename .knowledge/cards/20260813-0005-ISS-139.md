# ISS-139

## Title

**`page.tsx`'s `case "pipeline_cancelled": case "pipeline_failed":` switch arm was UNREACHABLE dead code (~`:1527-1562`).** Both types are members of `pipelineTypes`, and that branch `return`s before the `switch` is ever entered — so the arm's `runStore.update(termSrcRunId, {reviewGateData:null, questionnaireData:null})`, its `setLastCancelledRunId`, its `detachRunRef` release and its `setActivePipelineRunId(null)` never ran. A fix applied there would silently have done nothing. Verified by reading the control flow, and it had been pinned by a test in `terminalReopenReconcile.source.test.ts` asserting the ISS-126 fix is NOT inside it. Deleting it needed care: `setLastCancelledRunId` and the `detachRunRef` release may be genuinely wanted on the LIVE terminal path, in which case they belong in the reachable block, not this one.

- Sev: trivial

## Source / Evidence

Verified during the ISS-126 investigation; the trap is that the arm reads exactly like the right place to fix ISS-126. **FIXED 2026-08-13 (FIX-247):** the entire 36-line arm is DELETED, and the care this row asked for was taken — its two genuinely live-relevant effects (`setLastCancelledRunId`, `detachRunRef.current?.()`) are RESCUED onto the reachable live-handler path, **the first time either has ever executed on a live cancel**. The other effects were not rescued: `questionnaireData` is now cleared by the live block on its own account (ISS-140), `reviewGateData` deliberately is NOT (see ISS-140), and `setActivePipelineRunId(null)` was already being called there. **TWO source-lock tests had pinned this dead arm and were GREEN while pinning code that had never once executed** — `terminalReopenReconcile.source.test.ts` (known, from TEST-029) and `liveRunSwitch.fix201.test.ts` (a SECOND lock on the same dead string, unanticipated, found only mid-execution). Both reconciled TIGHTER, never relaxed. **The general lesson: a source lock satisfied only by unreachable code proves nothing about behaviour.**
