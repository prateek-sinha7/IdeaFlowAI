## Sibling of

This is a derived sibling of [ISS-329](20260828-1838-ISS-329.md), filed during root-cause
analysis of `BUG-20260828-021300-library-skills`. Not independently reproduced in the browser
yet — traced end-to-end through the code that is actually on disk, which is as far as static
analysis can confirm; a browser pass would only need to attach any agent's Skills and click a
category pill.

## Why the root cause implies this

[ISS-329](20260828-1838-ISS-329.md)'s root cause is two-part: `backend/app/agents/skills_catalog.py:112`
defaults a skill's `category` to `""` when its `SKILL.md` frontmatter omits the field, and
`backend/app/api/skills.py:35` (`categories = sorted({e.category for e in entries if e.category})`)
explicitly excludes any falsy category from the pill list `GET /api/skills/library` returns. Both
of ISS-329's confirmed frontend symptoms (blank badge, unreachable-via-pill) were read off
`frontend/src/components/library/LibraryPage.tsx` — but that is not the only consumer of this
data.

`frontend/src/hooks/useSkillsCatalog.ts:13-32` is the ONE hook every skill-attachment surface
reads through — it forwards `state.skills.skills` (populated by `skillsSlice.ts` verbatim from
the same `GET /api/skills/library` response) and `state.skills.skillCategories` (the same
already-filtered pill list) with no additional filtering of its own.

`frontend/src/components/workflow/composer/AgentSkillsPicker.tsx` is a second, independent
consumer of that hook (`useSkillsCatalog()` at line 60) — and per its own docstring (lines 27-31)
it is "the ONLY skill-attachment UI in the app": the Canvas view's `CanvasConfigRail`, the Simple
view's `AgentRow`, and the agent inspector drawer (`AgentCapabilitiesModal`) all render this same
component. It reproduces both halves of ISS-329's mechanism independently:

- **Filter equality**: `AgentSkillsPicker.tsx:82` — `const inCategory = category === "all" || s.category === category;` — a skill whose `category` is `""` can never equal any pill's non-empty `id`, identical to `LibraryPage.tsx:706`'s `s.category === skillCategory`.
- **Pill visibility gate**: `AgentSkillsPicker.tsx:169` — `CATEGORIES.filter((c) => c.id === "all" || compatible.some((s) => s.category === c.id))` — reads the same pre-filtered `CATEGORIES` list, so there is no pill whose `id` is `""` to click in the first place.

`html-deck-to-pptx/SKILL.md` (confirmed read) declares no `compatible_agents` key, so
`skills_catalog.py:112`'s `compatible_agents=list(metadata.get("compatible_agents", []))`
defaults it to `[]`. `AgentSkillsPicker.tsx:66-74`'s own contract (documented at line 35: "Absent/
empty `compatible_agents` means compatible with everything (R-33)") therefore includes this
skill in `compatible` for every non-custom agent (and every custom agent, unconditionally, line
68). The pill row only renders when `CATEGORIES.length > 1 && compatible.length > 6`
(line 166) — true for essentially any agent, since the global catalog is 186 skills. So a user
attaching skills to ANY agent — via the canvas rail, the simple-view row, or the drawer — who
clicks a specific category pill instead of leaving "all" selected, cannot find or attach
`html-deck-to-pptx`, exactly mirroring ISS-329's Library-page symptom but on the composer surface
where skills are actually attached to a run.

## Expected vs actual

Expected: every skill, including `html-deck-to-pptx`, is reachable through the category pill
that would normally correspond to it (or a real "uncategorized" pill), consistent with every
other skill, in every surface that filters the same catalog by category.

Actual (INFERRED from the code both surfaces share — not yet clicked through in the browser):
`html-deck-to-pptx` is absent from `AgentSkillsPicker`'s visible list whenever any category pill
other than "all" is selected, for every agent in the Canvas rail, the Simple-view row, and the
`AgentCapabilitiesModal` drawer — reachable only via "all" (the default) or the search box.

## What would confirm or refute this

Open the composer (Canvas or Simple view), open any non-custom agent's Skills picker, click any
category pill other than the default "all", and confirm `html-deck-to-pptx` is present in the
unfiltered list but absent once a specific pill is active — mirroring ISS-329's steps 5-6 exactly,
on this surface instead of `/library?tab=skills`.

## Fix

Belongs in the same place as [ISS-329](20260828-1838-ISS-329.md)'s fix: the shared loader
`backend/app/agents/skills_catalog.py:112` (`_load_one`). A single change there — defaulting a
missing `category` to a real non-empty value instead of `""` — reaches every consumer through
the one `GET /api/skills/library` response and the one `useSkillsCatalog()` hook, so it fixes
`LibraryPage.tsx`'s badge and pill filter AND `AgentSkillsPicker.tsx`'s pill filter without a
second, separate frontend change in the composer.
