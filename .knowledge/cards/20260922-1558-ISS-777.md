# ISS-777

## Description

Sibling of [ISS-770](20260922-1305-ISS-770.md) (bug `QA-SG-014`,
`BUGS.md#qa-sg-014`), derived from its root cause rather than independently
reproduced live.

ISS-770 reproduced the format mismatch through the full canvas composer
(`ComposerPage.tsx` → `CanvasView.tsx`'s "Output format" `<select>`). This
card is about the OTHER live launch surface that reaches the same
`selections.__deliverable__` mechanism with no format picker at all:
`frontend/src/components/workflow/IdeaInputPage.tsx`, confirmed reachable —
`frontend/src/components/layout/DashboardLayout.tsx:3062` mounts
`<IdeaInputPage>` as the app's home/dashboard "compose a workflow" launch
screen (not dead code).

`IdeaInputPage.tsx:422-448` (`AGENT_DELIVERABLE_MAP`) hardcodes exactly
three agent-id groups (prototype agents, user-story agents, PPT agents) to
fixed, correctly-typed deliverable shapes (each includes an explicit
`mimetype`, e.g. `{strategy: "single_file", name: "prototype.html",
mimetype: "text/html"}` at `:430`). `resolveDispatchType`
(`IdeaInputPage.tsx:450-465`) matches the user's selected agents against
those three groups; its fallback for every other combination is
unconditional (`:465`):

```ts
return { type: "custom", deliverableOverride: { strategy: "streamed_text", name: "output.md", mimetype: "text/markdown" } };
```

Nowhere in `IdeaInputPage.tsx` does an `aria-label="Output format"` control,
or any other deliverable-shape input, exist — that string appears exactly
once in the whole `frontend/src/components/workflow/` tree, inside
`composer/CanvasView.tsx`, a component `IdeaInputPage.tsx` does not render.
So a user composing a workflow from this screen with e.g. a
security-audit + documentation agent combination (outside all three
hardcoded groups) has **no UI element to request anything other than
markdown** — the run is silently forced to `output.md` regardless of intent,
which is the same user-visible complaint QA-SG-014 raises ("always produces
.md files"), reached through a different code path than the one ISS-770
already proved.

This also explains a related wiring detail worth recording here rather than
re-opening ISS-770: `ComposerPage.tsx:1017` calls the SAME
`resolveDispatchType` for its own fallback
(`ComposerPage.tsx:1048`: `effectiveDeliverable = runConfig?.deliverable ??
deliverableOverride`), and that fallback IS honestly mimetyped
(`:465` above) — but it is silently discarded the instant the user touches
CanvasView's Output-format control, because `runConfig?.deliverable` (no
`mimetype` field, freely renamed) then wins the `??`. `IdeaInputPage.tsx`
has no such fallback available to discard — the hardcoded map is the only
mechanism it has, so its users are strictly worse off: not a broken promise
(ISS-770), but no promise at all.

## Expected vs Actual

- Expected: a user composing a custom workflow from the dashboard's "idea
  input" screen with agents outside the three known groups can request
  (or at least is told they're getting) a specific output format.
- Actual (inferred, not yet reproduced live): no such control exists; the
  run always launches with `streamed_text`/`output.md`, silently, for any
  agent selection outside `AGENT_DELIVERABLE_MAP`'s three hardcoded groups.

## What would confirm or refute it

A live run from `/dashboard` (not `/workflows/new`): pick a non-prototype,
non-user-story, non-PPT agent combination (e.g. security-audit-agent +
documentation-agent) and launch. `GET /api/runs/<id>` should show
`deliverable_filename: "output.md"` / `deliverable_mimetype:
"text/markdown"` regardless of any stated intent in the brief, with no
Output Format control ever having been shown in the launch UI.
