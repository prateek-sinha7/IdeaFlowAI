# ISS-1049

**Deferred, not fixed.** This is surface 4 of [ISS-973](20261002-0346-ISS-973.md), the one surface [FIX-717](20261002-1243-FIX-717.md)
left alone. Found by reading code during the QA-KB-053 fix. It has not been reproduced in the UI.

## Condition

An older member of a revision family, opened through History's row menu **"Chain"** action. That action sets
`opts.forChain`, which skips the `onOpenRun` redirect (`WorkflowHistory.tsx:357-360`), so History renders its own
detail view instead of the shared run screen. A plain row click goes to the shared run screen, which
[FIX-717](20261002-1243-FIX-717.md) fixed.

## Mechanism (read)

- `WorkflowHistory.tsx:1141` mounts `<FilesTab runId={selectedRun.id} ...>` with no `selectedRef` and no `parentRunId`.
  FilesTab then resolves its row against the live tree, `resolveRunDeliverable(token, runId, undefined, undefined)`.
  Every family member shares one sandbox, and its live tree holds the NEWEST member's files.
- `WorkflowHistory.tsx:1105` mounts `<SandboxPdfPreview runId={selectedRun.id} path={selectedRun.deliverableFilename} ...>`
  with no `selectedRef`, so it reads the newest member's PDF too.
- The view has no `runFamily`, so it cannot tell an older member from the newest. That is why FIX-717 did not
  change it. PreviewPanel derives `displayRef` from `sortedMembers` and `latestId`; nothing equivalent exists here.

## Fix direction

The detail view needs the member's tag, plus whether the member is the newest. The tag is `FamilyMember.git_tag`
from `GET /api/runs/{id}/family`. With those two values it can pass `selectedRef` exactly as PreviewPanel's
`displayRef` does (`PreviewPanel.tsx:874`):
- the member's tag for an older member;
- `null` for an older member that has no tag, so the derived row stands;
- `undefined` for the newest member.
