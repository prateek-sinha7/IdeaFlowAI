## What was wrong

Five test files build their own `create_engine("sqlite://", ...)` inside `backend/tests/unit/`. Since `09270703b`
(2026-09-22) the unit suite's autouse `_unit_io_guard` (`backend/tests/unit/conftest.py:90-123`) listens on `Engine`
`connect` and raises `UnitIsolationError` (`:81`) for every DBAPI connection, in-memory SQLite included. So these tests
errored at fixture setup and ran nowhere (re-measured before the change,
`evidence/qa-kb-088/14-fix-sibling-files-before-pytest-summary.txt` and the bug's own repro run):

| file (before) | setup errors | what went untested |
|---|---|---|
| `tests/unit/test_workflow_override_e2e.py` | 7 of 7 | the spec-016 override round trip over HTTP |
| `tests/unit/test_workflow_override.py` | 16 of 23 | `resolve_override` / `find_override` owner scoping (AUTHZ-01) |
| `tests/unit/api/test_workflows_api.py` | 49 of 53 | the `GET /api/workflows` contract (API-01), the path-traversal 404 |
| `tests/unit/test_chain_projection.py` | 11 of 11 | the `chain_source` cross-owner IDOR gate of `GET /api/runs/{id}` |
| `tests/unit/test_authz_bounded_calls.py` | 5 of 7 | `ScopedStore.assert_owns` denial and the bounded reads |

88 tests in all. Behind the guard, the e2e file hid a second fault: its `api` fixture overrode only `get_current_user`,
while `POST /api/user-workflows` (`backend/app/api/user_workflows.py:674`) and `PATCH /{id}` (`:955`) depend on
`get_current_principal`, so every save would answer 401; and two of its seven tests discarded the save result and would
pass anyway (ISS-947 analysis, variant V0).

## What changed, and why there

Placement is the defect, so the fix is placement. The guard is right and stays exactly as it is
(`tests/unit/test_unit_io_guard.py:30-34` pins that it refuses in-memory SQLite). No `allow_io` marker. Files were moved
with plain `mv` (no git index operation); the user owns git.

- **ISS-947.** `tests/unit/test_workflow_override_e2e.py` -> `backend/tests/integration/api/test_workflow_override_e2e_api.py`
  (`_api` suffix, as the five earlier relocations for this guard). In the moved file, exactly the card's three items:
  - the principal override, `:45-50`, `app.dependency_overrides[get_current_principal] = lambda: (state["user"], principal_for(state["user"]))`,
    imports at `:22` and `:24`; the pattern of `tests/integration/api/test_user_workflows_api.py:88-104`. The lambda reads
    `state["user"]` lazily, so `test_another_users_override_is_invisible` still switches identity;
  - `_save_override` asserts `status_code == 201` (`:85`) before returning the response;
  - `test_workflow_level_fields_still_come_from_the_file` asserts `after["is_overridden"] is True` (`:120`), and
    `test_another_users_override_is_invisible` asserts the owner sees the override before switching user (`:172`).
  Everything else in the file is unchanged.
- **ISS-1091.** `tests/unit/test_workflow_override.py` was split at its own section boundary. The `resolve_override`,
  `find_override` and `override_steps` sections, with `_FakeUser`, the `db` fixture and `_seed`, moved verbatim to
  `backend/tests/integration/api/test_workflow_override_api.py` (new docstring, the imports they need). The
  `merge_override_steps` section stays in the unit file, which needs no DB; its docstring gained a pointer to the moved half
  and the imports the move orphaned were removed (the pre-existing unused `import dataclasses` was left as found).
  `tests/unit/api/test_workflows_api.py` moved whole and byte-identical to `backend/tests/integration/api/test_workflows_api.py`:
  the card allowed either a partial or a full move, and the whole file is the router's contract (its 4 non-DB discovery
  tests run unchanged there).
- **ISS-1093.** `tests/unit/test_chain_projection.py` -> `backend/tests/integration/api/test_chain_projection_api.py`, and
  `tests/unit/test_authz_bounded_calls.py` -> `backend/tests/integration/agents/test_authz_bounded_calls_db.py` (`_db`, as
  that folder names DB-backed files). Whole-file moves: the card allowed the 2 fake-session tests to stay or go, and moving
  them keeps one file. The only edit in each is the first docstring line, which named the file's own old path.

Blast radius, re-checked by `grep -rln "create_engine\|sessionmaker" backend/tests/unit/` before editing: besides these
five and `conftest.py`/`test_unit_io_guard.py`, four files carry `@pytest.mark.allow_io` (`app/test_run_stream_pool_leak.py`,
`test_revision_workspace_mode.py`, `test_run_sandbox_api.py`, `test_upload_html.py`), `services/test_user_workflows_selections.py`
builds an engine with no marker yet ran green (23 passed, not investigated), and `test_restore_guard_v3.py` (ISS-891) and
`test_admin_privilege_race.py` (ISS-1064) are tracked elsewhere. None of those was touched. The analyzer's other claim, that
fault 2 (the missing principal override) has exactly one live instance, was not re-derived.
