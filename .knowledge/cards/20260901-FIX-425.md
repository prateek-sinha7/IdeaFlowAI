## What was wrong

`test_a_last_streamed_built_in_refuses_an_append_after_final_step_slot`
(S-04-15) called `expect(page.get_by_text(L.LAST_STEP_GUARD)).to_be_visible()`
immediately after loading the canvas. The guard text lives inside a `CapTip`
tooltip — a `<span role="tooltip">` styled `opacity-0` by default, with
`group-hover:opacity-100` on the parent `<span class="group">`.

Playwright's `to_be_visible()` checks **computed opacity**: an element at
`opacity: 0` is NOT considered visible even if it is in the DOM and not
`display:none`. The test therefore failed with
`"Locator expected to be visible"` as soon as the page rendered correctly —
no bug in the app.

**Root cause** `tests/integration/e2e/suites/04_composer_canvas/test_composer_canvas.py`
around the two-line visibility assertion in S-04-15.

## What changed

Before the `expect(page.get_by_text(L.LAST_STEP_GUARD)).to_be_visible()`
call, added a hover on the last `ADD_AGENT` button
(`page.locator(L.ADD_AGENT).last.hover()`).

The last `ADD_AGENT` slot is the add-after-final-step button that the
`CapTip` wraps.  Hovering triggers the CSS `group-hover:opacity-100`
transition, after which `to_be_visible()` passes.

The disabled-button assertion (`expect(page.locator(L.move_later(last))).to_be_disabled()`)
was not changed — it does not involve opacity.
