## Symptom

A conditional gate authored on the composer canvas never rendered its outcome
chips. The human got a plain free-text review box instead — or, depending on
the value sent, no gate at all.

## Root cause

`ComposerPage` sent `gate_agent_ids` on launch. **No non-null value is correct
for a composer workflow**, and the two wrong values fail differently:

- **Step INCLUDED** — `_should_gate` becomes true, so the declared gate is
  deduped away under WR-02 and the INLINE post-step gate runs instead. That
  path never publishes the `choices` payload (see
  [ADR-0026](20260825-1600-ADR-0026.md)), so the chips cannot render.
- **Step EXCLUDED** — the gate is skipped outright.

Only `None` leaves the declared `before-human` gate to fire.

## Fix

`ComposerPage` no longer sends `gate_agent_ids` at all.

Alongside it, the gate authoring controls were corrected to match the
post-ADR-0013 vocabulary:

- The gate control is a single-select dropdown: **Human** or **Conditional**.
  `before-human` is deliberately NOT an option — post-ADR-0013 it is a distinct
  gate, not an alias for `human`. `human` reviews a step's OWN output after it
  runs; `before-human` reviews the PREVIOUS step's output before it runs. Only
  the latter puts the human's edit where a route can read it.
- A separate **Prompt User** toggle owns `before-human` outright and is its
  only writer. It is offered only under a conditional gate, and emits
  `before-human` FIRST so the gates array matches `ex_A4_human_gate` exactly.
- Per-step tool grants can now be set fully off, matching the fixture.

## Measured side effect

Turning tool grants fully off on A4 collapsed 135s of `read_file`/`glob`
thrashing to 9s, once a step that had nothing to read stopped being handed
tools to look with. Related to but distinct from
[ISS-171](20260824-1631-ISS-171.md), which is about denial not being ENFORCED;
this is about not GRANTING in the first place.
