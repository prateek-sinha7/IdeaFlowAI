## What was wrong

`BUG-20260828-025521-library-hooks` — hook cards on `/library?tab=hooks` could
not be reached or activated with a keyboard. Four ISS cards traced the same
mechanism across the page:

- [ISS-222](20260828-1534-ISS-222.md) — Hooks grid, `LibraryPage.tsx:914-920`.
- [ISS-270](20260828-1850-ISS-270.md) — Agents grid, `LibraryPage.tsx:740-758`.
- [ISS-271](20260828-1851-ISS-271.md) — Skills tab's active-skills grid, `LibraryPage.tsx:821-827`.
- [ISS-272](20260828-1852-ISS-272.md) — both in-file detail modals, `SkillDetailModal`
  (`LibraryPage.tsx:138`) and `HookDetailModal` (`LibraryPage.tsx:280`).

## Root cause

`Card` (`frontend/src/components/ui/Card.tsx:15-29`) is a plain
`<div {...rest}>` — it forwards `onClick` and adds nothing else. Every caller
that hangs an `onClick` on it therefore has to supply `tabIndex`, `role` and a
keydown activation path itself, and all three `LibraryPage.tsx` grids omitted
all three. `grep -n "Escape\|keydown\|role=\"dialog\"\|aria-modal\|focus()"`
over the whole 978-line file returned zero matches, so the modal those cards
open had no keyboard dismiss path and no dialog semantics either — fixing only
the cards would have moved the dead end one step later in the same journey.

`Card.tsx` was deliberately NOT changed: its contract (a non-semantic surface
primitive) is relied on by 11 other modules, and all four cards scope the
defect to `LibraryPage.tsx`.

## What changed, and why there

One file, `frontend/src/components/library/LibraryPage.tsx`, two new file-local
helpers next to the existing ones so all five call sites route through them
rather than five copy-pasted blocks:

- `CARD_KEYBOARD_PROPS` — `role="button"`, `tabIndex: 0`, and an `onKeyDown`
  that maps Enter/Space onto `e.currentTarget.click()`. Forwarding to the
  element's own click keeps activation defined in exactly one place per grid,
  so the existing `onClick` bodies are untouched. Spread into the Hooks grid,
  the active-Skills grid, and (conditionally) the Agents grid.
- `useDetailModalKeyboard(onClose)` — a document-level Escape listener plus a
  panel ref focused on mount, returning the ref. Called by both
  `SkillDetailModal` and `HookDetailModal`; each scrim also gained
  `role="dialog"`, `aria-modal="true"` and an `aria-label`, and each panel
  `ref` + `tabIndex={-1}`. This is the shape
  `components/workflow/prototype/TemplateDetailModal.tsx:29-38,64-66` already
  uses, reused rather than reinvented.

**Deliberate scope decisions, both traceable to the cards:**

1. **Beta agent cards get no keyboard affordance.** Their `onClick` body is
   guarded by `if (!BETA_WORKFLOWS.has(...))`, so a click is already a no-op;
   the spread is therefore conditional on that same expression. A focus stop
   that does nothing is worse than none, and it matches what
   [ISS-271](20260828-1851-ISS-271.md) records for the beta *skill* cards,
   which carry no `onClick` at all and are correctly left inert.
2. **No Tab focus trap.** [ISS-272](20260828-1852-ISS-272.md) notes Tab is not
   trapped inside the dialog; neither is it in `TemplateDetailModal` or
   `DesignSystemDetailModal`, the repo's two established detail modals. Escape,
   dialog role and focus-on-open are what the card's test asserts and what the
   repo's own modal contract provides — a trap would be a new pattern, not a
   fix.

### Note on `suites/08_library/test_library.py`

Run twice against this change (24 scenarios each). Both runs were partially red
but with **different, non-overlapping** failure sets — run 1 failed
`switching_a_tab_updates_the_url`, `category_counts_sum_to_the_all_count`,
`search_is_scoped_to_the_active_tab`, `each_tab_is_addressable_by_query_param[hooks]`;
run 2 failed `deep_linking_a_detail_view_works_cold` and
`each_agent_drawer_tab_shows_its_own_content[Config]`. Run 1's aria snapshot
shows `0 agents · 0 skills · 0 hooks` with "Loading workspace…" still on screen,
i.e. the catalogs never loaded. Both of run 2's failures PASS when re-run alone
(`-k "deep_linking or (drawer_tab and Config)"` → 2/2 PASS). This is a
catalog-load flake under parallel load, not a regression: the change adds
attributes and handlers only and cannot make a fetch return zero rows.
