# ISS-110

## Title

**`hookRuns` has no per-run boundary in the reducer.** `pipeline_start` spreads `...prev` and never clears it; only `startPipeline` / `resetPipeline` do. So run A's hook rows can survive into run B's `useWorkflow.pipelineState`, and the FIX-201 bridge at `page.tsx:1665` copies that whole object into the NEW run's store entry. Containment today comes from the per-run store, and ISS-082 added a per-run reset for the frame-identity cursor on the same `isSameRunReannounce` predicate — so the shape of the fix is already in place beside it and this is a one-line addition. Deliberately NOT folded into FIX-235: unobserved, and ISS-107 means the field currently drives nothing on screen, so fixing it blind would be unverifiable. Sequence it AFTER ISS-107.
