# ISS-130

## Title

**`KernelServices.run_agent` mutates SHARED `ExecutionContext` scratch while N fan-out workers run concurrently.** `kernel_services.py:1254-1291` (now `:1267-1304`) sets and restores `build_task_number`, `build_task_total`, `current_task_block`, `current_prototype_skeleton` and `current_step` on the ONE per-run `ectx` — but under `run_fanout`'s parallel `asyncio.gather` those N coroutines share that single object, so the save/restore is a classic interleaving hazard: worker A's `finally` can restore values while worker B is still mid-flight. **Contamination was NOT observed** — across five instrumented runs every worker wrote its correct distinct file — and the believed reason is that `_run_agent` consumes the scratch before its first `await`, which would make the mutation atomic w.r.t. the event loop. **That was NOT verified**, and it is an undocumented, unenforced invariant: adding any `await` earlier in `_run_agent` would silently break every parallel fan-out with cross-contaminated task blocks.
