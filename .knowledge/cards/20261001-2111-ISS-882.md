# ISS-882

Derived from the QA-KB-019 analysis of [ISS-579](20260829-0234-ISS-579.md). **Confidence: INFERRED.** The mechanism is
CONFIRMED on the live source (below); whether any saved workflow actually holds such a brief is not.

## Condition

A saved workflow whose `selections._wizard.brief` contains a `[Attached: <name>]` marker where `<name>` contains `]`
(for example `report].pdf`), shown on the My Workflows page (`SavedWorkflowsPage`).

## Expected

The card's brief preview shows only the user's own words: the whole marker is removed.

## Actual

`cleanBrief` (`frontend/src/components/savedworkflows/SavedWorkflowsPage.tsx:59-73`) strips the marker with

```ts
.replace(/\[Attached:[^\]]*\]/g, "")   // :64
```

`[^\]]*` stops at the first `]`. `[Attached: my].txt]` loses only `[Attached: my]`, and what is left is `.txt]`. That is
non-empty, so `cleanBrief` returns it (`:66`, `if (stripped) return stripped;`) and the card renders it as the brief
(`:376-381`) instead of the empty state. Run on the live function (`evidence/qa-kb-019/03-analyze-probe-output.txt`,
harness `evidence/qa-kb-019/02-analyze-probe-live-source-extract.cjs`, which extracts `cleanBrief` from the source file at run time):

| input | output |
|---|---|
| `idea\n\n[Attached: a.txt]` | `idea` |
| `idea\n\n[Attached: my].txt]` | `idea\n\n.txt]` |
| `idea\n\n[Attached: a, b].txt]` | `idea\n\n.txt]` |
| `[Attached: my].txt]` | `.txt]` |

A `, ` in the name is harmless here (this reader never splits the block); only `]` matters.

## Why the root cause implies it

Same mechanism the QA-KB-019 analysis found in `stripAttachmentMarker` (`WorkflowView.tsx:88`, see
[ISS-579](20260829-0234-ISS-579.md)): a bracket-delimited marker whose payload is a filename, matched with a character class
that excludes the delimiter while the payload may contain it. This is a second parser of the same format in a different file,
so fixing the WorkflowView helper does not touch it. [FIX-400](20260829-0402-FIX-400.md)'s "Blast radius verified" paragraph
called this reader "unaffected"; that held for the remove-handler bug it fixed, but it did not consider delimiter
characters inside names.

## Reach (INFERRED)

No live code path writes a marker into a brief this page can show: the only writer of `[Attached: ...]` left in
`frontend/src` is `WorkflowView.tsx:354`, and that page does not save workflows (it forwards its text to `/create?...&message=`,
see [ISS-579](20260829-0234-ISS-579.md)). The regex is a legacy-data reader. It arrived with KAN-75 (commit `b59e9ad2b`),
whose message says the Save workflow button stores the wizard brief in `selections._wizard`, and whose diff has
`IdeaInputPage.tsx:561,564` and the ppt/prototype templates pages writing `\n\n[Attached: ${f.name}]` into that brief state
(`git grep -n "\[Attached" b59e9ad2b -- frontend/src`). So the exposure is persisted briefs from those builds whose attached
filename contained `]`. That chain is read from the commit, not observed on a database row.

## What would settle it

Either a saved-workflow row whose `selections._wizard.brief` holds `[Attached: ` with a `]` inside the name, opened on My
Workflows; or an offline unit test: render `SavedWorkflowsPage` with a stubbed row (or export `cleanBrief`) and assert the
preview for `idea\n\n[Attached: my].txt]` is `idea`.

## Fix direction

One token at `SavedWorkflowsPage.tsx:64`: end the marker at a `]` that is followed by whitespace or the end of the text,
`/\[Attached:[^\n]*?\](?=\s|$)/g`. Checked in the analyzer probe on six inputs (single marker, `]` in the name, `, ` and `]`,
text after the marker, two markers, and a user-typed `[this]` bracket that must survive): 6/6. It is display-only, so an
approximate end is acceptable (a name containing `] ` would still stop early). Do not couple it to the WorkflowView fix:
different file, different consumer, and a shared marker module is not worth a new file for one regex.

## Fix (QA-KB-019, 2026-10-01)

Resolved by [FIX-694](20261001-2207-FIX-694.md). `cleanBrief` (`SavedWorkflowsPage.tsx:64`) now strips
`/\[Attached:[^\n]*?\](?=\s|$)/g`, the fix direction above. `idea\n\n[Attached: my].txt]` previews as `idea`. A
user-typed `[this]` bracket and the `=== Attached ===` blocks are unaffected: 8 of 8 cases
(`evidence/qa-kb-019/05-fix-cleanBrief-cases-post-fix.txt`). `SavedWorkflowsPage.cleanBrief.test.tsx`: the
`it.fails` case flipped.
