## What happened (sibling of ISS-222)

Filed while analyzing `BUG-20260828-025521-library-hooks` ("Hook cards on the Hooks tab are not
keyboard-operable"). [ISS-222](20260828-1534-ISS-222.md)'s root cause,
`frontend/src/components/library/LibraryPage.tsx:914-920`, is a `<Card onClick={...}
className="... cursor-pointer ...">` with no `tabIndex`/`role`/`onKeyDown` — `Card`
(`frontend/src/components/ui/Card.tsx:15-29`) is a plain, non-semantic `<div {...rest}>`, so the
caller must add keyboard affordances itself. ISS-222's own body already names this exact grid as
suspect ("The same unguarded-`onClick`-`Card` pattern is also used one map up for the Skills
tab's cards ... but this card only asserts the Hooks tab").

Reading it confirms the pattern: `LibraryPage.tsx:818-848` (`activeSkills.map((skill) => { ...
return (<Card key={skill.id} onClick={...} className="p-4 hover:border-line-control
transition-colors cursor-pointer group"> ...) })`). `onClick` (lines 822-825) sets
`setSelectedSkill(skill)` and pushes `routes.librarySkill(skill.id)`; the block (821-827) has no
`tabIndex`, `role`, or `onKeyDown`, confirmed by direct read. Tab, from the skill category pills,
skips the entire active-skills grid the same way ISS-222 documents for Hooks.

**Scope note — the "Coming Soon" beta-skills grid is NOT part of this claim.** A second grid
renders `betaSkills.map(...)` (`LibraryPage.tsx:859-883`) with `className="p-4 opacity-60
cursor-not-allowed"` and **no `onClick` prop at all** — those cards are genuinely inert display
elements, not a broken interactive affordance, so there is nothing to make keyboard-operable
there.

## Why the root cause implies this

Same reasoning as [ISS-270](20260828-1850-ISS-270.md) (the Agents-tab sibling): ISS-222 names
this as a pattern repeated across the file's tabs, and the active-skills grid is the same `Card`
+ bare `onClick` shape with the identical three attributes missing — "other callers with the same
flaw," confirmed by reading the code, not assumed from the Hooks-tab report alone.

## Confidence

CONFIRMED mechanism — `LibraryPage.tsx:818-848` read directly. INFERRED as a live defect: not
reproduced with a real keyboard press or DOM query the way ISS-222 was. Settling it: on
`/library?tab=skills`, run `document.querySelectorAll('.cursor-pointer')` inside the active-skills
grid and check `tabindex`/`role`, or Tab from the category pills and confirm focus never lands on
a skill card.
