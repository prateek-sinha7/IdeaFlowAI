# ISS-1108

## Description

INFERRED sibling of [ISS-1063](20261007-1940-ISS-1063.md) (QA-KB-098). [FIX-567](20260918-FIX-567.md) moved the playwright tools' sandbox binding from a module global to a ContextVar because "concurrent wave workers share one agent_id, so a global is overwritten by whichever worker bound last". The two other sandbox-bound tool modules bound by the same factory seam were left on the old pattern, and it is the same hazard: `pptx_tools._SANDBOX` (`pptx_tools.py:70`, set by `bind_sandbox` at `:89-92`) and `file_extract_tools._SANDBOX` (`file_extract_tools.py:159`, set at `:162-165`). Whether two runs or two workers can actually interleave bind and tool call is not demonstrated; that is what the test below settles.

## Why the root cause of QA-KB-098 implies it

ISS-1063 is what a binding refactor leaves behind when only one of three sibling modules is migrated: a pin on the old shape. Two consequences follow from the same cause.

1. The hazard FIX-567 fixed is still open in the other two modules. Nothing in them mitigates it: the factory binds once at runner composition (`factory.py:1267` pptx, `:1304` file_extract; the comments at `factory.py:1254-1257` and `:1291-1294` say the sandbox is "bound onto the module rather than passed"), and the tools read the global at CALL time (`pptx_tools.py:216`, `:230`, `:259`, `:271`, `:278`, `:298`, `:326`, `:485`; `file_extract_tools.py:174`, `:243`, `:305`, `:1074`, `:1391`, `:1489`, `:1660`). Concurrent runs in one backend process are real in this product ([FIX-153](20260730-2031-FIX-153.md): "Concurrent runs' review gates overwrote each other").
2. The next stale pin is already written. `test_per_run_paths_v3.py:313` and `:323` save and restore `pptx_tools._SANDBOX` exactly as `:427` and `:444` did for playwright, and it passes today only because pptx still has the global. The full list of pins on these two globals is 11 sites in 5 files: `test_per_run_paths_v3.py` (`:313`, `:323`), `test_pptx_tools.py` (`:54`, `:101`, `:140`, `:282`), `test_verify_layout.py` (`:339`, `:362`), `test_file_extract_tools.py` (`:71`, `:444`), `test_html_extract.py` (`:74`). Migrating either module breaks all of its pins the same way.

## What is INFERRED, and what settles it

Whether interleaving is reachable. Settle with a deterministic offline test, no engine and no browser: in two asyncio tasks bind two different sandboxes through `bind_sandbox`, yield once, then have each task call `pptx_tools._pptx_path()` (or `file_extract_tools._resolve_path(".uploads/x.pdf")`) and assert each resolves inside ITS OWN sandbox. Today both resolve into whichever sandbox bound last. If the real call order in the engine makes the bind and the tool call atomic per task (nothing yields between them), the hazard is not reachable and this card closes as not reproducible; the pin-migration risk in point 2 still stands for whoever migrates the modules.

If it is reachable the impact is cross-run: a tool reads or writes a different run's sandbox, and for `file_extract_tools` that includes another user's uploads (`file_extract_tools.py:247`, `:309`). That is why this is rated medium and flagged security-relevant, but it is a race, not a certainty, and nothing here has been driven.

## Fix direction (only once reproduced)

Same shape as [FIX-567](20260918-FIX-567.md): a ContextVar per module (or one shared helper next to `bind_sandbox`), with the module-level reads replaced by `.get()`. The factory call sites already go through `bind_sandbox`, so the production diff is confined to the two tool modules. FIX-567's propagation rule applies unchanged: the bind must run in the task that runs the tool, which the factory seam already guarantees for playwright. The 11 test pins migrate in the same change; for an `async def` test a plain `bind_sandbox(...)` needs no restore, because the ContextVar write stays inside the test's task (verified for playwright in `evidence/qa-kb-098/analysis-03-probe-contextvar-leak.txt`).
