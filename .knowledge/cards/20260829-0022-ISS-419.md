## What happened (inferred from confirmed code, not yet reproduced against a `gates: [human]`-only fixture)

[ISS-306](20260828-1745-ISS-306.md) root-caused Mechanism A of the `/create/ex_A4_human_gate`
fresh-load defect: `ReviewGatesSection.tsx:52`'s `isDefaultGated = (a) => a.gate ===
"Human_Gate"` and its `checkedIds` seed (`:92-96`, `:103-114`) read ONLY the static per-AGENT.md
`gate` field (or a saved run's `initialGateIds`) — never the manifest's per-step `gates: [...]`
array (the ADR-0013 vocabulary: `human`, `before-human`, `conditional`, `approval`, `security`).
ISS-306's own repro happened to use a step declaring `[before-human, conditional]`, so it reads
as a "before-human is dropped" defect. Reading `isDefaultGated`'s full body shows the gap is not
specific to `before-human` at all: `checkedIds`'s seed has ZERO code path to `sel.gates` /
`selections[id].gates` / the raw manifest `st.gates`, for ANY gate name. A `custom-agent` step
declaring plain `gates: [human]` alone (the ordinary POST-step human-review gate, with no
`conditional` involved) would be equally invisible in the Review-gates checklist on a fresh
load, because `custom-agent` instances have no AGENT.md and therefore no static `gate` field —
their only declaration of "this step pauses for human review" is the per-step `gates` array this
seed never reads.

## Why the root cause implies this

ISS-306's Mechanism A root cause is that `checkedIds`'s seed has no code path to the manifest's
per-step `gates` array at all — the fix has to add one. That absence is a property of the
`isDefaultGated`/`initialGateIds` seed logic itself, not of the specific gate name
`before-human`. Any composed workflow step whose human-review declaration lives exclusively in
`gates: [...]` (true of every `custom-agent` step, since none carry an AGENT.md `gate` field)
hits the identical blank seed regardless of which gate name(s) it declares — `human` alone,
`approval`, `security`, or any combination.

## Expected vs actual (predicted)

Expected: a fresh load of a workflow whose manifest declares a `custom-agent` step with
`gates: [human]` (no `conditional`, no `before-human`) should show that step checked in the
Review-gates checklist, since the step genuinely pauses for human review.

Actual (predicted, unverified): the checklist shows that step unchecked / "no gates", identical
to ISS-306's `before-human` case, because `isDefaultGated` never inspects `gates` for any value.

## What would confirm or refute this

Find or construct a fixture with a `custom-agent` step declaring `gates: [human]` alone (no
`conditional`), load its `/create/<id>` panel fresh, and open the Review-gates checklist.
Unchecked confirms this card; checked refutes it (meaning some other seed path exists that
ISS-306's file:line trace did not surface).
