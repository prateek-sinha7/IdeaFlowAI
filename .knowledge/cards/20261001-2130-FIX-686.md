# FIX-686

## What was wrong

This is bug report QA-KB-001 (`/runs/{id}`). With `prefers-reduced-motion: reduce` on, the settled "Run summary" strip still opened and
closed with a 220 ms height and opacity tween. The live Pipeline mini on a building run did the same
([ISS-889](20261001-2117-ISS-889.md)). That panel also collapses by itself on every chat send, so a
user sees the tween without clicking anything.
[BUG-018-GROUNDED-CONTEXT](20260717-1903-BUG-018-GROUNDED-CONTEXT.md) Part B required this gate
("MUST be gated by `prefers-reduced-motion: reduce`"), but it was never built.

## Root cause

This comes from the root card's analysis. Line numbers are as of HEAD 024c03ef8, before this edit.

- `motion` 12.38.0 sets `reducedMotion: "never"` by default
  (`framer-motion/dist/es/context/MotionConfigContext.mjs:10`), so a bare `motion.div` never reads
  the OS setting. The app never opted in. At the start of this fix phase,
  `grep -rn -i -E "prefers-reduced-motion|useReducedMotion|MotionConfig|reducedMotion" frontend/src`
  found nothing outside the new test file (exit 1).
- `RunChatLane.tsx:35` imported only `{ motion }`. The settled strip panel (`:821-831`) and the live
  Pipeline mini panel (`:2141-2147`) each had a fixed
  `transition={{ duration: 0.22, ease: "easeOut" }}` (`:829`, `:2144`). These were the only two such
  literals in `frontend/src`.

## Change

Only `frontend/src/components/chat/RunChatLane.tsx` changed. Lines below are after the edit.

- `:35` now also imports `useReducedMotion`.
- `:760-786` add a local `CollapsePanel`. It calls `useReducedMotion()` and renders the same
  `motion.div` as before: `initial={false}`, height and opacity driven by `open`, and
  `overflow-hidden`. Its transition is
  `transition={reduce ? { duration: 0 } : { duration: 0.22, ease: "easeOut" }}`. It passes `id`,
  `role`, `inert`, `aria-hidden` and `data-testid` through.
- `:849-870`: the settled strip panel is now
  `<CollapsePanel id={panelId} data-testid="lane-adornments" role="region" aria-hidden={!open} inert={!open ? true : undefined} open={open}>`.
- `:2166-2175`: the live panel is now
  `<CollapsePanel open={!pipelineMiniCollapsed} aria-hidden={pipelineMiniCollapsed}>`.

`CollapsePanel` renders the `motion.div` itself with no wrapper, so the DOM does not change. With
reduce off, both panels tween exactly as before. `motion` stays imported because `CollapsePanel`
(`:776`) and the four dot loops (`:360`, `:1736`, `:2060`, `:2125`) still use it.

## Why there

- `renderTranscriptFooter()` is a plain function, so a hook cannot go inside its branches. Both
  panels now render through the one component that owns the gate. This is variant Y in the root
  card's analysis.
- Variant X put the hook in `SettledSummaryStrip` and a second `useReducedMotion()` at the top of
  `RunChatLane`. The analysis saw it fail all 14 tests in `RunChatLane.fix192.test.tsx`, whose
  `motion/react` mock (`:59-69`) does not export `useReducedMotion`, so X would have meant editing
  that mock. Under Y the hook runs only when a panel mounts. `fix192` mocks `ChatPanel`, so no panel
  mounts there and its mock stays untouched.
- The gate is `{ duration: 0 }` on each panel rather than `<MotionConfig reducedMotion="user">`.
  That setting skips height (a positional key) but still tweens opacity, so the panel would snap
  open and then fade in over 220 ms. The root card's analysis table shows both behaviours.

## Not addressed

- [ISS-890](20261001-2117-ISS-890.md) (open): no reduced-motion policy exists anywhere else in the
  app. That covers the other 49 `motion/react` files, the infinite opacity pulses (including the
  four dot loops and the `animate-pulse` dot in this file), the `globals.css` keyframes, the Tailwind
  `animate-*`/`transition*` utilities and smooth scroll. No policy has been chosen, so the card
  stays open. When one is, `CollapsePanel` is the single place to wire it in for RunChatLane's
  collapse panels.
- The `SettledSummaryStrip` docblock still says the strip "animates open via the house motion/react
  idiom". That is still true through `CollapsePanel`, so it was not edited.
