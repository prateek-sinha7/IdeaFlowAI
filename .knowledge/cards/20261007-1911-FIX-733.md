# FIX-733

## What was wrong

This fix is for bug report QA-KB-075 ("Test comments explain degraded verdict with dead latest-completion-wins rule").
The root cause and the blast radius come from the 2026-10-02 analysis on [ISS-902](20261001-2144-ISS-902.md) and its
sibling [ISS-1016](20261002-0606-ISS-1016.md). They were not re-derived here. Every quoted line was re-read on the
working tree before editing (branch `feat/user-stories-v2`, HEAD `b898a3b97`).

- **[ISS-902](20261001-2144-ISS-902.md).** Two parametrize comments on `test_reconcile_degraded_tracks_latest_completion_only`
  in `backend/tests/integration/agents/test_restart_resume_db.py` still explained the tails with the last-by-seq rule
  that commit `f23625911` added. FIX-484's boundary scan won merge `4ebd98e8f`, and [FIX-689](20261001-2142-FIX-689.md)
  reworded only the docstring. The two comments were "The LATEST / pipeline_complete must decide, not ..." (old
  `:4318-4319`) and "latest-wins cuts / the other way too." (old `:4334-4335`). The four tails give the same verdict
  under the live and the dead rule, so nothing went red.
- **[ISS-1016](20261002-0606-ISS-1016.md).** The `completed` rung of `_reconcile_terminal_status`
  (`run_commands.py:932`, `elif current_attempt_completes and not failed_current:`) had no tail that goes red when only
  that rung is un-scoped. The analyzer measured 22 of 22 `-k reconcile` tests green under that variant. The comment
  above tail 4 named "a resume that stopped again before producing any new terminal event", but tail 4 builds a single
  attempt.

## What changed, and why there

All changes are in one test file, `backend/tests/integration/agents/test_restart_resume_db.py`. Every edit was anchored
on the quoted old text, because QA-KB-073's fixer was editing the same file at the same time. Line numbers below are the
new file at the time of writing.

- **`:4330-4332` (ISS-902, hunk 1).** "The LATEST / pipeline_complete must decide, not ..." now reads "Only a degraded /
  pipeline_complete at or after the last attempt boundary (run_resuming / / pipeline_start, FIX-484) counts, not "was
  ANY completion ever degraded"." This is the analyzer's probed wording.
- **`:4347-4348` (ISS-902, hunk 2).** "a LATER degraded one — latest-wins cuts / the other way too." now reads "a LATER
  attempt that ends degraded — / that completion is at or after the last attempt boundary, so it counts too."
- **`:4377-4378` (ISS-1016, the card's optional clause).** Two comment lines were added under tail 4's comment: "One
  attempt here; the resumed form, after an earlier completion, is T8/T9 of test_reconcile_fix484_boundary_scoping
  (ISS-1016)." Tail 4 itself is unchanged.
- **`:6121`.** `@pytest.mark.issue("ISS-1016")` was added beside the existing `ISS-886` marker on
  `test_reconcile_fix484_boundary_scoping`.
- **`:6159-6188`.** Two cases from the ISS-1016 card were added verbatim, both expecting `"failed"`:
  - **T8.** `pipeline_start 1, pipeline_complete{_DEG} 2, run_resuming 3, pipeline_start 4, agent_start 5`.
  - **T9.** The same tail with a clean completion at 2.

  The `ids=` list went from one line to one id per line, the same layout as the `ids=` list of the degraded test
  above. Otherwise the line would be about 190 characters.

The name `test_reconcile_degraded_tracks_latest_completion_only` is kept, as ISS-902's analysis decided.

## Test changes, stated explicitly

This fix edits a test file only, and only because both cards place their fix there. ISS-902's defect is the comment
text, and ISS-1016's fix is the missing tails. No assertion that existed before was changed. Neither the expected
values of tails 1-4 nor those of T5-T7 were touched.

The 4-test-writer's guard, `backend/tests/unit/test_reconcile_degraded_test_comments.py`, was not edited. Its
`xfail(strict=True)` marker is left for the 6-verifier.

ISS-1016 came to this phase with no test file (`test_files: []`). Its fix IS the two tails, and they pass on the shipped
code by design (a regression lock, the same shape as ISS-886's T5-T7). So they carry no xfail marker. To show they are
not vacuous, the fix was run under the analyzer's scratch variants of `_reconcile_terminal_status`, swapped in memory:
T8 and T9 go red under both. That output is below.

## Deliberately not done

- **No rename** of `test_reconcile_degraded_tracks_latest_completion_only`. The reasons are in ISS-902's "Decision"
  section.
- **No edit to `backend/app/api/run_commands.py`.** The live ladder is already correct, and both cards forbid it.
- **ISS-1016's production sequence is still INFERRED.** That sequence is a Stop on a resumed run whose first attempt
  completed, landing on the D2 fail-safe. No run was started; the tails pin the reconcile verdict for that durable
  tail.
- **The hunks at `:4095-4209` are not part of this change.** They are in
  `test_apply_terminal_output_columns_populates_all_columns` / `..._captures_per_agent_model_id` and belong to
  QA-KB-073's fixer ([ISS-900](20261001-2132-ISS-900.md) / [ISS-1013](20261002-0547-ISS-1013.md)), which was working in
  the same file at the same time.
