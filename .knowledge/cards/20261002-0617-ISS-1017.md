# ISS-1017

Sibling of [ISS-904](20261001-2149-ISS-904.md) by mechanism, found on the QA-KB-077 sweep. `b2a621f84` ("Fix/cognito login (#8)", 2026-09-17) deleted a
local-auth surface (here `POST /api/auth/register`), the tests of that surface survived, and the unit I/O guard added later
(`09270703b`, 2026-09-22) hides the staleness behind a setup error. Unlike ISS-904 the guarantee these tests carry is still live,
so the disposition is the opposite: keep the guarantee, change the vehicle.

## What happens (CONFIRMED, observed 2026-10-02, shipped working tree)

Evidence: `evidence/qa-kb-077/04-analyze-layers-under-the-guard.txt` section 4 and `evidence/qa-kb-077/05-analyze-sibling-probes.txt`.

- `backend/tests/unit/test_register_password_echo.py` ([ISS-257](20260828-1817-ISS-257.md)) and `backend/tests/unit/test_register_password_echo_fixture_mounts_real_app.py`
  ([ISS-357](20260828-1915-ISS-357.md)): 1 error each. `UnitIsolationError` from `tests/unit/conftest.py:81`, raised by the fixture's own
  `create_engine("sqlite:///:memory:")` (`:34` and `:41`).
- Run outside `tests/unit` (copies in the scratchpad, no guard), both bodies fail on `assert resp.status_code == 422` with
  `404 {"detail":"Not Found"}`. `POST /api/auth/register` is not a route on `app.main.app`. `b2a621f84` removed it (`git show
  b2a621f84:backend/app/api/auth.py` has no `"/register"`) and `RegisterRequest` with it; `grep RegisterRequest backend/app` finds
  only the docstring at `backend/app/main.py:546`.

These are dead guards, not red tests of a bug: no edit to the app can make them pass.

## Why it matters (CONFIRMED by an in-process mutant probe; no repo file edited)

The redaction handler `_validation_error_handler` (`backend/app/main.py:539-556`, [FIX-332](20260828-1915-FIX-332.md)) is live and works on a route that still
exists: `PUT /api/settings/github-pat` with `{"pat": "short7!"}` (`GithubPATRequest.pat`, `min_length=10`,
`backend/app/api/settings.py:70-71`) answers 422 and the value is not in the body. With FastAPI's stock handler substituted for it,
the same request returns `"input":"short7!"` inside `detail[]`.

No offline test notices that substitution: `grep` over `backend/tests` finds the redaction asserted only in the two files above.
What is left is the live Playwright test `tests/integration/e2e/suites/16_pages_outside_routes/test_pages_outside_routes.py:514`
(oversize PAT; needs a running, signed-in app) and `frontend/src/lib/api.errorEcho.test.ts`, which pins the frontend parser
(ISS-256), not the handler. FIX-332's locked constraint, "A 422 body never carries the value that failed validation (Pydantic's
detail[].input)", is unguarded offline, while FIX-332, ISS-257 and ISS-357 list the dead file as passing verification.

## Fix direction (test-only; no source change)

- Keep the guarantee and re-point it. One test that mounts the real `app.main.app` (ISS-357's point: a bare `FastAPI()` can never
  see `main.py:539`), sends a too-short credential to a route that still exists, and asserts 422 with the value absent from the body.
  `PUT /api/settings/github-pat` is the route the handler's own docstring names (`main.py:545`). The test must go red under the
  mutant: replace `app.exception_handlers[RequestValidationError]` with
  `fastapi.exception_handlers.request_validation_exception_handler`.
- It can stay in `tests/unit/`. A scratch version (auth and `get_db` overridden by stubs, so body validation fails before the route
  body runs; no engine, no lifespan) passed under a verbatim copy of `tests/unit/conftest.py`, and its mutant twin showed the leak
  (`evidence/qa-kb-077/05-analyze-sibling-probes.txt` section 6). If the test ever opens an engine it belongs in `tests/integration/api/`
  (README rule 7).
- Then delete the two register files (plain `rm`) and fix the INFERRED rows above. Do not relocate the register files as they are: they
  would fail on the 404.
- Retire-only is the cheaper option if the owner accepts the live test at `:514` as the sole guard. That is a test-strategy call, not a
  product one; the fix should say which was chosen.

## Resolution (QA-KB-077 fix, 2026-10-07)

Fixed by [FIX-736](20261007-1940-FIX-736.md). Of the two options above, **re-point** was chosen, not retire-only.

- `backend/tests/unit/app/test_main.py` mounts the real `app.main.app` (auth and `get_db` stubbed, no lifespan) and sends
  `PUT /api/settings/github-pat {"pat": "short7!"}`. It gets a 422 without the value: `1 passed` under the unit I/O guard. With
  FastAPI's `request_validation_exception_handler` swapped in for `main.py:539`, the same test function fails and the body
  carries `"input":"short7!"` (`evidence/qa-kb-077/fix-02-mutant-check-script.py`, `fix-02-mutant-check-output.txt`).
- Both register files were deleted with `rm`. `verification.test_files` here, and on FIX-332, ISS-257 and ISS-357, now names the
  new file.
- The INFERRED consumers above were edited as listed: S-24-05 asserts 404, the snapshot entry was removed, the feature file's
  rows and counts were updated, and the three comments were corrected. S-24-05 is live tier and was not run.
- Left: the handler docstring at `backend/app/main.py:546` still cites `RegisterRequest.password` as an example. It is docstring
  only, and `main.py` is in QA-KB-089's globs, so it was not edited concurrently. The leftover is noted on
  [ISS-1018](20261002-0617-ISS-1018.md). While editing the snapshot, the contract checks were found to be vacuous; that is carded
  as [ISS-1065](20261007-1940-ISS-1065.md).
- Also left, outside this card: `backend/tests/agents/test_ttl_sweep_loop_v3.py:37` still cites the deleted
  `test_register_password_echo_fixture_mounts_real_app.py` as an example of the isolated-engine workaround. It is a docstring
  pointer to a deleted file, recorded here instead of edited, as FIX-691 did for its own stale pointer.
