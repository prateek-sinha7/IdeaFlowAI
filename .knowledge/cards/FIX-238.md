## Description

The offline unit suite made REAL, billable AWS Bedrock calls, and nothing in the repo could have stopped it (ISS-102). Two tests in tests/unit/test_chat_messages_endpoint.py::TestRouting did not monkeypatch run_commands._resolve_concierge (unlike all three sibling classes), so the endpoint resolved the REAL ConciergeCapability, whose ctx carries model=None → build_model() → ChatBedrockConverse → a live ConverseStream call. Verbatim before the fix: DeepAgentRunner.astream_events failed: An error occurred (ExpiredTokenException) when calling the ConverseStream operation. Two parts. (1) TestRouting gains a class-placed autouse fixture running the byte-identical sibling call monkeypatch.setattr(rc_module, "_resolve_concierge", lambda: fake) — class-wide, not per-test, because only 2 of the 8 methods reach the seam today and a patch on the other 6 would be dead code (INV-12). (2) The real deliverable: backend/tests/conftest.py gains an autouse guard that makes constructing a live provider client a loud failure naming the offending nodeid. The chokepoint is the three provider CLASSES, not build_model — established, not assumed. agents/planner/smart_planner.py:173/:189/:196 builds its client WITHOUT build_model, and deepagents.create_deep_agent(model="anthropic:...") builds ChatAnthropic via langchain's init_chat_model; a build_model guard would have missed 6 of the 10 offending tests and been defeated anyway by the by-value from app.agents.model_factory import build_model imports at deep_agent_runner.py:58 / cached_invoke.py:44. The guard patches __init__ and never the class object, so isinstance (deep_agent_runner._maybe_apply:234, cached_invoke:79) and object.__new__ (test_bedrock_cache_and_thinking._bedrock_instance) keep working. Its exception derives from BaseException, not Exception — run_commands.py:1513 and deep_agent_runner.py:586 are bare except Exception, which is exactly how the original ExpiredTokenException became a log line instead of a failure; an Exception-derived guard would have been swallowed on the very path it polices. Three allowances only: RUN_LIVE_BEDROCK=1, the requires_api_key marker, and exact-nodeid membership in _CONSTRUCTS_BUT_NEVER_INVOKES (8 verified construct-only tests, filed as ISS-118 rather than silently patched). The two tests remain RED — deliberately (ISS-119): they assert the superseded pre-safety routing contract, and reconciling that is an owner decision, not a side effect of a money fix.

## Root cause

Nothing anywhere asserted that an offline test may not reach a live model, and the suite has no offline-by-default state: AWS_REGION, BEDROCK_INFERENCE_PROFILE_ID and BEDROCK_MODEL_ID are hardcoded CODE defaults (app/core/config.py:130/:123/:118) with no backend/.env, so unsetting env vars cannot make build_model() offline. The only thing that ever stood between this suite and a bill was whether AWS credentials happened to resolve — and they now do.
