## ISS-405 — What was wrong

`frontend/src/app/admin/page.tsx` rendered the avatar initial as
`{user.email[0].toUpperCase()}` for every row in the users table. If an empty-string
email ever reached the DB (possible via a direct API call that bypasses the
client-side guard), `""[0]` is `undefined`, and `.toUpperCase()` on `undefined`
throws `TypeError`, crashing the entire `/admin` table render into the root
`error.tsx` fallback.

## ISS-405 — Fix

```tsx
// Before
{user.email[0].toUpperCase()}

// After
{(user.email || "?")[0].toUpperCase()}
```

## ISS-415 — What was wrong

The delete-confirmation dialog stored only `user.id` in `deleteConfirm` state and
displayed a generic "Delete user?" heading with no identification of which user would
be deleted — an admin could accidentally delete the wrong account.

## ISS-415 — Fix

- `deleteConfirm` state type changed from `string | null` to
  `{ id: string; email: string } | null`.
- `setDeleteConfirm(user.id)` → `setDeleteConfirm({ id: user.id, email: user.email })`.
- Dialog now renders `<p>{deleteConfirm.email}</p>` beneath the heading.
- `handleDeleteUser(deleteConfirm)` → `handleDeleteUser(deleteConfirm.id)`.
