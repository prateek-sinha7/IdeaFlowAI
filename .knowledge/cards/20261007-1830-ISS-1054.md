# ISS-1054

Found during [FIX-725](20261007-1830-FIX-725.md)'s regression run (QA-KB-065) and not fixed there, because it is
outside that bug. [FIX-697](20261001-2237-FIX-697.md) had already listed the same test as failing, but without
measuring it at HEAD or filing a card.

## What fails (CONFIRMED, observed 2026-10-07)

`backend/tests/agents/test_mechanical_publish_step.py::test_engine_runs_mechanical_publish_step_end_to_end` fails at
`:301`, `assert completes[0]["data"].get("status") != "degraded"`. The result is the same with HEAD `ea5cd2f63`'s
`engine.py` and with FIX-725 applied: 13 passed, 1 failed (`evidence/qa-kb-065/fix-03-regression-after-fix.txt`,
`evidence/qa-kb-065/fix-04-publish-e2e-degraded-with-HEAD-engine.txt`). The other assertions in the test pass. The
publish step emits the draft and bills 0 tokens.

## Why (CONFIRMED by the lines and the captured log, except where marked)

- `backend/tests/agents/_scripted_model.py:994`: `run_id = f"harness-{pipeline_type}-{_uuid.uuid4().hex[:8]}"`.
- `backend/app/agents/runtime/local.py:940-943` accepts only `[0-9a-fA-F-]+` and otherwise raises
  `ValueError("run_id must be a UUID (hex digits and hyphens only): ...")`.
- `finalize_terminal_run` catches that error at `backend/agents/execution_engine/engine.py:2602-2608`, logs
  `finalize_terminal_run: create_run_ref FAILED run=harness-ex_publish_step-<hex> (run_id must be a UUID ...)` (seen
  in every run of the test), and calls `attempt.degrade("ref_creation_failed")`.
- INFERRED: that degrade is what sets `pipeline_complete.status` to `degraded`. It is the only degrade-level error in
  the captured log.

A production run id is a UUID, so this is a test-fixture defect, not a product one.

[ISS-684](20260918-ISS-684.md) and [ISS-1004](20261002-0522-ISS-1004.md) put the same "degraded" in an out-of-pytest
probe down to a sandbox `git add .chain/...` exit 128. Inside pytest, the cause seen is the run-ref failure above.

## Where a fix belongs

Probably the harness rather than the engine: mint a UUID-shaped `run_id` in `_prepare_engine_run`. It must stay
unique per call, because the state machine is a process-wide singleton (see the comment at `_scripted_model.py:990-992`).
INFERRED: any other harness-driven test that asserts `status != "degraded"` is red for the same reason. Grep for
that assertion before fixing.
