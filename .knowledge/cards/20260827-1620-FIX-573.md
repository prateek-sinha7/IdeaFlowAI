## The shape of the gap

A deck is HTML plus CSS plus a layout engine. `ppt-code-generator` was given the
first two and asked to produce something that matches the third. Rotation,
real box geometry after flex/grid resolution, and actual font metrics are all
properties of the *rendered* document — reading the source means inferring
them, and the deck lost exactly those three things on the way to `.pptx`.

The fix is to stop inferring: render the deck headlessly, dump every visible
element's resolved position, rotation, font, fill, border and shadow to
`.browser/deck-styles.json`, and hand the agent measurements.

## The finding worth carrying forward

**A prompt instruction was not enough, and that was verified rather than
assumed.** The agent skipped the skill-doc instruction repeatedly with the
instruction present. So the check moved into `render_pptx`, which now returns
the violation instead of `"ok"` — the retry is forced by the tool's return
value, not requested by the prompt. This is the same principle FIX-321 already
locked in for verification generally: the gate belongs inside the build.

Both gates are deliberately conservative. They compare the *source's* measured
motifs against the *built deck's* and fire only when a motif appearing 3+ times
in the source appears nowhere in the output. A deck with one rotated sticker
does not trip them, and neither does a run where ground-truth extraction never
happened.

## Why .eot, of all formats

Google Fonts' legacy CSS API serves EOT directly when asked with an old-IE
user agent, so the 46-font library was a one-time fetch with no format
conversion step. `verify_layout.py`'s font-safety check now treats an
embeddable font as safe alongside the built-in Office set — without that, every
real typeface would have been reported as a hazard.
