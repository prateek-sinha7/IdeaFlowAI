# ISS-789

## Description

Opening `/admin` via a client-side (SPA) navigation — account menu →
"Admin Dashboard" — fires `GET /api/auth/me` and `GET /api/admin/users`
TWICE each. A full page load / deep link to `/admin` (browser reload, typed
URL) fires each exactly once. Confirmed for bug **QA-PS-042** (see
`LEDGER.md` / `BUGS.md#qa-ps-042`).

## Reproduction

Cycle 1 — deep link / full reload (`page.goto` to `/admin`), 3x: 1x
`auth/me`, 1x `admin/users` every time — NOT reproduced.

Cycle 2 — SPA click-through (`/dashboard` → Account menu →
"Admin Dashboard"), 3x: 2x `auth/me`, 2x `admin/users` every time —
reproduced 3/3.

Verified precisely with `performance.clearResourceTimings()` immediately
before the click, then `performance.getEntriesByType('resource')` after the
route settled — the MCP `browser_network_requests` log does not reset
across same-origin SPA navigations in this environment, so raw counts read
from it can look inflated by carried-over entries from the prior page (same
caveat already documented in ISS-784).

**Trigger (named): entry path.** SPA/client-side navigation into `/admin`
duplicates the boot fetch pair; a hard page load does not. React 18
StrictMode (`next dev`, no `reactStrictMode: false` in `next.config.ts`)
double-mounts a component in dev, and `admin/page.tsx`'s boot `useEffect`
has no in-flight guard, `AbortController`, or cache, so the double mount
fires two live GETs each of `/api/auth/me` and `/api/admin/users`. Why this
surfaces on the soft-nav path specifically but not on a fresh document load
is environment-specific (Next.js App Router segment-mount behaviour differs
between a genuine document load and a client-router push), but the
soft-nav reproduction itself is 100% consistent across all 3 cycles.

Same missing-guard shape as **ISS-784** (`HomeLaunchGrid.tsx` on
`/dashboard`, StrictMode double-invoke explicitly diagnosed), **ISS-781**
(`/settings`) and **ISS-783** (`/runs`) — none of those three cover
`/admin`'s route/component, so this is not a duplicate of them.

## Root cause

`frontend/src/app/admin/page.tsx:176-193` — the mount effect:

```tsx
useEffect(() => {
  const token = getToken();
  if (!token) { router.replace(buildLoginRedirect()); return; }

  getMe(token).then(user => {
    if (!user.is_admin) { router.replace(routes.dashboard()); return; }
    setCurrentUserId(user.id);
    loadUsers(token);
  }).catch((err: unknown) => {
    if (err instanceof ApiError && err.status === 401) return;
    router.replace(buildLoginRedirect());
  });
}, [router, loadUsers]);
```

No abort controller, in-flight `useRef` guard, or request cache — every
mount (including the StrictMode double-mount that this environment surfaces
on a client-side route transition into `/admin`) fires a fresh
`getMe` + `adminListUsers` pair.
