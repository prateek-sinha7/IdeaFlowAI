# FIX-710

## What was wrong

The bug is QA-KB-041. On `/workflows`, open a card's "Workflow actions" (⋮) menu with a click that does not focus the
trigger, then press Escape. The menu stays open and `aria-expanded` stays `"true"`. Safari and Firefox on macOS do not
focus a `<button>` on click; the validator emulated that with a JS `.click()` in Chrome. The root card is
[BUG-104](20260829-1508-BUG-104.md). Five siblings have the same shape:
[ISS-928](20261001-2224-ISS-928.md) (header account menu), [ISS-929](20261001-2224-ISS-929.md) (notifications bell),
[ISS-930](20261001-2224-ISS-930.md) (admin tier dropdown), [ISS-931](20261001-2224-ISS-931.md) (history "Run actions"),
and [ISS-932](20261001-2224-ISS-932.md). ISS-932 is the Delete-workflow confirm. It fails in every browser, because the
menu item that opens it unmounts and focus falls to BODY.

## Root cause (from the cards, re-checked before editing)

Each popup bound Escape with a React `onKeyDown` on its wrapper element. A keydown is dispatched to
`document.activeElement` and bubbles up from there. With focus on BODY the event never enters the wrapper, so the
handler never runs. Nothing moved focus into any of these popups when it opened. At HEAD 024c03ef8 the handlers were:

- `SavedWorkflowsPage.tsx:101-109` (KebabMenu `handleKeyDown` plus the wrapper prop)
- `SavedWorkflowsPage.tsx:421` (the scrim `onKeyDown`)
- `AppHeader.tsx:174-182` and `:529`
- `NotificationPanel.tsx:234-240` and `:252`
- `admin/page.tsx:85`
- `RevisionFamilyView.tsx:446-451`

The blast radius was re-checked by grep before this card was written. `useEscapeToClose` had three callers
(`WorkflowDialog.tsx:67`, `AgentsPopup.tsx:618`, `AgentSkillsPicker.tsx:137`). They are untouched, and so is the hook.
`KebabMenu` and `RowMenu` are module-local. `FamilyGroupCard` has one consumer, `WorkflowHistory.tsx:1448`.

## What changed, and why there

The fix lives in the shared mechanism. [FIX-388](20260829-0053-FIX-388.md)'s `useEscapeToClose(onClose, enabled)` already
registers a `document` keydown listener and fires on Escape wherever focus is. Each site now calls that hook, gated on
its own open state, and the wrapper handler is deleted. The hook is not edited. Each focus return is a closure at the
call site, as BUG-104 recommends.

| site | now | gate |
|---|---|---|
| KebabMenu ([BUG-104](20260829-1508-BUG-104.md)) | `SavedWorkflowsPage.tsx:105` `useEscapeToClose(() => { onClose(); triggerRef.current?.focus(); }, isOpen)`, wrapper `:107` has no `onKeyDown` | `isOpen` |
| Delete confirm ([ISS-932](20261001-2224-ISS-932.md)) | `SavedWorkflowsPage.tsx:172` `useEscapeToClose(() => setDeleteRow(null), deleteRow !== null)`, scrim `:421` keeps only `onClick` | `deleteRow !== null` |
| account menu ([ISS-928](20261001-2224-ISS-928.md)) | `AppHeader.tsx:178` `useEscapeToClose(() => { setProfileOpen(false); triggerRef.current?.focus(); }, profileOpen)`, wrapper `:525` | `profileOpen` |
| bell ([ISS-929](20261001-2224-ISS-929.md)) | `NotificationPanel.tsx:237` `useEscapeToClose(() => { setOpen(false); bellRef.current?.focus(); }, open)`, wrapper `:249` | `open` |
| tier dropdown ([ISS-930](20261001-2224-ISS-930.md)) | `admin/page.tsx:71` `useEscapeToClose(() => setOpen(false), open)`, wrapper `:87-89` | `open` |
| Run actions ([ISS-931](20261001-2224-ISS-931.md)) | `RevisionFamilyView.tsx:449` `useEscapeToClose(() => onToggleMenu(runId), isOpen)`, wrapper `:451-453` | `isOpen` |

Each file also gained one `import { useEscapeToClose } from "@/hooks/useEscapeToClose";`. Nothing was orphaned: the
removed handlers used `React.KeyboardEvent` through the global type namespace, and no file imported `React` for it.

Why nothing replaces the old `e.stopPropagation()`:

- The modals this page opens from the kebab mount only after the menu has closed (`setOpenMenuId(null)` before
  `setRenameRow` / `setDeleteRow`), so no other Escape listener is live while a kebab menu is open (BUG-104, point 4).
- Expanding a family renders the root run's RowMenu twice: once in the card header, once as v1. Both listeners then fire
  on Escape, and both call `onToggleMenu(root.id)`. `WorkflowHistory.tsx:1456` computes the new state from its render
  closure (`openMenuId === id ? null : id`), not from a functional update, so both calls set `null`. The menu closes; it
  does not toggle back open.

This was a frontend-only change. No backend, kernel, registry or migration surface was touched, so SC-001 and the
import-linter contracts are not in play.

## Test correction: ISS-928, ISS-929, ISS-930 and ISS-931 test files (disclosed)

**These four test files were edited, each in the same small way. No application line was changed to satisfy a test.**

Each test asserted that the popup node was gone synchronously, straight after `await user.keyboard("{Escape}")`:
`expect(screen.queryByRole("menu"|"dialog")).toBeNull()`. That assertion is now
`await waitFor(() => expect(screen.queryByRole(...)).toBeNull())`, and `waitFor` was added to the import where it was
missing. The `it.fails` markers and every other assertion are unchanged. The `aria-expanded` checks still run
synchronously.

Why this change counts as legitimate and not as editing a test to make it pass:

1. **The cards define the expected behaviour by pointing at tests that wait.** ISS-928's Expected cites
   `AppHeader.a11y.test.tsx:147-158`, which waits at `:154-156`. ISS-929 cites `NotificationPanel.a11y.test.tsx:64-75`,
   which waits at `:71-73`. ISS-930 cites `admin.reskin.test.tsx:161-176`, which waits at `:175`. ISS-931's CONTROL
   evidence comes from the analyzer probe, which waits at `07-analyze-probe-rowmenu.test.tsx.txt:41`. The new tests
   misstated that expectation by requiring a synchronous unmount.
2. **No correct implementation can satisfy the synchronous check deterministically.** All four popups render inside
   `<AnimatePresence>` with an `exit` animation (`AppHeader.tsx:543-550` 0.12s, `NotificationPanel.tsx:268-276` 0.15s,
   `admin/page.tsx:100-109` 0.1s, `RevisionFamilyView.tsx:464-471` 0.1s). The exiting node stays mounted until that
   animation ends. On the PRE-FIX code, with the focused click the a11y tests certify as working, the state right after
   Escape was `aria-expanded = false` with the node still in the DOM, for the bell, the admin menu and the account menu
   (`11-fix-prefix-head-control-and-corrected.txt`).
3. **It is a race, not a behaviour.** On an unchanged tree, `AppHeader.escape.test.tsx` gave XPASS, then expected fail,
   then XPASS across consecutive runs. The bell probe printed `dialog present = true` at 01:40 and `false` at 01:51, and
   the pre-fix rowmenu control printed `true` in one run and `false` in the next. `aria-expanded` flipped to `"false"`
   in every run (`09-` and `10-fix-*.txt`).
4. **The corrected tests still catch the bug.** Run as plain `it` against the git HEAD copies of the four components,
   all four corrected bodies FAIL. Bell, admin and account menu fail on a `waitFor` timeout, about 1.02-1.04s with the
   node still present. RowMenu fails at once with `aria-expanded` still `"true"` (`11-fix-*.txt`). On the fixed tree they
   XPASS 3 runs out of 3 (`12-fix-*.txt`).

`SavedWorkflowsPage.escape.test.tsx` (BUG-104, ISS-932) was not touched. It mocks `AnimatePresence` as a fragment, so its
synchronous checks are deterministic, and it XPASSed 3 runs out of 3 both before and after.

## Deliberately not changed

- **`useEscapeToClose.ts`.** BUG-104 suggested an optional `returnFocusTo` ref parameter for when all four menus land
  together. Three call sites with a two-statement closure are not worth the extra parameter, so the hook keeps its three
  original callers untouched.
- **The adjacent popups that never bound Escape at all.** These are the header "N Running" dropdown
  (`AppHeader.tsx:404-419`), `RunHeader`'s VersionMenu, `AgentsPopup`'s `ConfigLeverSelect` and `NameWorkflowModal`.
  They have a different root cause, listed under BUG-104 "Adjacent" and left for a hunter. `RunHeader.tsx` was not
  touched.
- **The multi-line `<div\n className=...\n>` that remains in `admin/page.tsx:87-89` and `RevisionFamilyView.tsx:451-453`**
  once the `onKeyDown` line is deleted. Collapsing it would be a pure reformat.
- **The unused `waitFor` import in `SavedWorkflowsPage.escape.test.tsx:5`.** It predates this change and nothing here
  orphaned it.
- **[ISS-953](20261002-0154-ISS-953.md).** A stale test (see above). It is test-only and outside this bug.
