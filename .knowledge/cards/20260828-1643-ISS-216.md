## Description

Found while verifying [FIX-324](20260828-1641-FIX-324.md) and deliberately not fixed —
the files belong to the test author, and editing a test to make a fix look clean is the
inversion this line exists to prevent.

`cd frontend && npx tsc --noEmit -p tsconfig.json` reports 10 lines / 7 distinct errors.
One (`.next/types/validator.ts:105` — missing `src/app/prompt-gallery/page.js`) predates
this work. The other six all sit in the two test files written for
`BUG-20260827-234030-create`:

```
src/components/catalog/HomeLaunchGrid.crossAccountLeak.test.tsx(24,73): TS2554: Expected 0 arguments, but got 1.
src/components/catalog/HomeLaunchGrid.crossAccountLeak.test.tsx(25,61): TS2554: Expected 0 arguments, but got 1.
src/components/catalog/HomeLaunchGrid.crossAccountLeak.test.tsx(26,82): TS2554: Expected 0 arguments, but got 2.
src/components/catalog/HomeLaunchGrid.crossAccountLeak.test.tsx(27,80): TS2554: Expected 0 arguments, but got 2.
src/store/listenerMiddleware.test.ts(37,7):  TS2353: 'auth' does not exist in type 'Reducer<...>'  (preloadedState)
src/store/listenerMiddleware.test.ts(44,5):  TS2322: middleware Tuple has 2 elements, target allows 1
```

The first four are `vi.fn(() => ...)` mocks declared with no parameters but called with
the arguments the real `@/lib/api` helpers take. The last two are `configureStore`
generics: the partial `preloadedState` and the `.prepend(listenerMiddleware.middleware)`
tuple do not line up with the inferred root state.

Vitest does not typecheck, so all three tests run and behave correctly — this is a CI /
editor-noise defect, not a behavioural one.

## Expected

`npx tsc --noEmit` in `frontend/` reports only the pre-existing `.next/types` error.

## Actual

Six additional errors, all in the two new test files.

## Disposition

Open, low severity. Cheapest fix is typing the four `vi.fn` mocks with their real
parameter lists and widening the test store's `preloadedState`/middleware generics
(`configureStore<RootState>` or a cast). Belongs to whoever next edits those files — the
verifier removing the `it.fails` markers is the natural moment.
