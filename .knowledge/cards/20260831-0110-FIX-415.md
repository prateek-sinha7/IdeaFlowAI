## What changed

A module constant names the three agents, and every `engine.execute(...)` call
in the file passes it:

```python
_GATED_AGENT_IDS = ["prototype-specify", "prototype-plan", "prototype-analyze"]
...
gate_agent_ids=list(_GATED_AGENT_IDS),
```

This is the mechanism the engine already documents
(`agents/execution_engine/engine.py`): *"Effective set = the per-run
`gate_agent_ids` passed to `execute()` when given, else the STATIC set"* — and
the static set is now empty, so the opt-in is the only thing that can open a
gate. It is also the path the wizard itself uses, which is what makes these
tests exercise real behaviour rather than a removed default.

The precondition assertion was INVERTED rather than deleted: it now asserts
that no spec carries an inline gate, so a static default silently coming back
fails here.

`test_default_run_single_gate_per_agent_with_real_payload` was renamed
`test_opted_in_run_gates_each_agent_once_with_a_real_payload` — it is no longer
a default run, and a name that says otherwise would mislead the next reader.
The WR-02 one-pause-per-agent and real-payload assertions are unchanged.

Not done here: `test_agents_api_real_registry.py` (×2) and
`test_phase6_frontend_consistency.py` (×1) still assert `'Human_Gate'` from the
same cause. They are logged as T6-07 in `bug-hunter/open-bugs.md`.
