## What is wrong

[FIX-327](20260828-1845-FIX-327.md) extracted the "which file is this run's
deliverable" rule into `resolveRunDeliverable` (`frontend/src/lib/api.ts`) and
routed the Files tab, the History browser's Files tab and the base-version
section through it. The surface that ORIGINATED the rule —
`PreviewPanel.tsx:844-910`, the header Download button's `useEffect`
([FIX-318](20260827-0055-FIX-318.md)) — was left on its own inline copy: it
still reads `pipelineState?.deliverableFilename`, falls back to `getWorkflow`,
calls `getRunSandbox`, and builds the same `[<stem>.pptx, declared]` /
`[declared, <stem>.html]` candidate list by hand.

Two implementations of one rule is exactly the drift that produced
[ISS-214](20260828-1633-ISS-214.md) and [ISS-215](20260828-1633-ISS-215.md):
a future change to the sibling preference applied in one place and not the
other means the header Download and the Files tab hero hand the user two
different files for the same run.

## Why it was deferred, not fixed

`frontend/src/components/preview/PreviewPanel.test.tsx:21-28` mocks
`@/lib/api` as a whole module with an explicit five-key object, and its five
header-Download specs assert on `mockGetRunSandbox` / `mockGetRunSandboxFileBlob`
being CALLED with specific paths (`:246, 270, 305, 329, 354`). Move the logic
behind `resolveRunDeliverable` and those calls happen inside a function the mock
replaces, so all five go red and the only way to make them green again is to
rewrite them into assertions on a mocked resolver — which deletes the coverage of
the sibling-preference rule itself and puts nothing in its place. That is a test
change with no defect behind it, so it was not made under a fix card.

## What a fix looks like

Collapse `PreviewPanel.tsx:846-910` to a `resolveRunDeliverable` call, and move
the sibling-preference specs down to a `frontend/src/lib/api.*.test.ts` that
exercises the resolver directly against a stubbed listing — same assertions,
one level lower, where they cover every caller instead of one.

Found while fixing BUG-20260828-012900-runs-id-files (`bug-hunter/ledger.md`).
