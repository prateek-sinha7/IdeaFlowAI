# ISS-724

Register entry: **QA-PS-031** (`BUGS.md`), filed as a sibling of [ISS-723](20260922-1245-ISS-723.md).

## Why the root cause implies this

[ISS-723](20260922-1245-ISS-723.md) establishes that `git show vN:presentation.html` is frozen
at v1's bytes for the whole `ppt_revision` family (and, by the same mechanism, any streamed-
strategy revision workflow). `SandboxTab.tsx` (the Workspace tab) is a caller of the identical
ref-scoped read functions Preview uses, and it deliberately threads `selectedRef` through every
one of them:

```
SandboxTab.tsx:1046   getRunSandbox(token, runId, selectedRef ?? undefined)          — listing
SandboxTab.tsx:1085-1086  getRunSandboxFile(token, runId, file.path, ref)            — text open
                          / getRunSandboxFileBlob(token, runId, file.path, ref)      — binary open
SandboxTab.tsx:1106    getRunSandboxFileBlob(token, runId, active.path, selectedRef ?? undefined)  — download
SandboxTab.tsx:1119    getRunSandboxZip(token, runId, selectedRef ?? undefined)      — ZIP download
```

All four resolve, backend-side, through the same `ref=` mechanism `read_sandbox_file` (
`backend/app/api/run_files.py:1080-1153`, `git show <ref>:<path>`) and
`download_sandbox_zip` (`:976-1043`) — both suffer [ISS-723](20260922-1245-ISS-723.md)'s Layer 1
+ Layer 2 identically, since they read the same frozen commit tree.

## Expected vs actual

- **Expected**: opening `presentation.html` in the Workspace tab under a pinned v2, or clicking
  its download button, or downloading the whole-workspace ZIP under v2, returns v2's own revised
  bytes.
- **Actual**: all three silently return v1's original bytes — same content [ISS-723](20260922-1245-ISS-723.md)
  already proves the Preview tab gets wrong, via a different UI surface.

## Distinct from ISS-720 / ISS-703 / ISS-704

Those three cards are exhaustively about `list_sandbox`'s ref branch hardcoding `"size": 0`
(`run_files.py:930`) — a metadata gap, explicitly unconditional on file content (ISS-720's own
"Why this is neither Defect A, B1, nor B2" section proves it reproduces even with correct
per-tag content). This card is the CONTENT itself being wrong, which none of the three checked
(ISS-720: "Confirmed NOT broken: `GET .../sandbox/file?ref=` … serves raw bytes" — true only in
the sense that the SIZE bug doesn't touch it; it says nothing about whether those bytes are the
right version's, which is exactly this card's claim). Both defects are real, independent, and
both need fixing for the Workspace tab to be trustworthy under a pinned version.

## Fix location

Same as [ISS-723](20260922-1245-ISS-723.md) — this card needs no separate backend change. Once
the deliverable is actually written to sandbox root and captured by the per-step commit (ISS-723's
Piece 1), `git show <ref>:<path>` starts returning the right bytes for every one of the four call
sites above, with zero change to `SandboxTab.tsx` itself.

## Validation 2026-10-01 — QA-KB-027 (Test mode, 3/3 cold runs, no browser)

QA-KB-027 asks whether Workspace file CONTENT under a pinned ref is guarded by a regression test. Validated 3/3:

- Guard exists but is DEAD: `backend/tests/unit/test_sandbox_ref_scoped_endpoints.py:159-180` (`test_different_refs_return_different_bytes`, v1 vs v2 bytes) cannot execute. `pytest tests/unit/test_sandbox_ref_scoped_endpoints.py -q` gives `1 xfailed, 5 errors` all three runs; error is `tests.unit.conftest.UnitIsolationError: Unit test opened a real database connection` (its `env` fixture binds the DB). Test needs `@pytest.mark.allow_io` or a move to tests/integration.
- Still uncovered: `download_sandbox_zip` with two tags of distinct bytes (`tests/agents/test_revision_routes_v3.py:365` uses one tag and a dirtied tree only); `read_sandbox_file` for `user_stories_revision`; fresh parent with no `presentation.html` under a pinned ref (404 vs 500 vs stale). `test_iss720_ref_scoped_sizes.py` covers sizes and the over-cap zip, not content.
- Verification: static + test run. Card stays `open` until a runnable guard lands.

## Analysis 2026-10-01 — QA-KB-027 (analyzer): the product is fixed, the guard is dead, the cause is test infrastructure

**Verdict.** No product decision is needed. The product half is closed and I re-checked it: [FIX-601](20260922-1319-FIX-601.md)
is in the tree and its guards run (`tests/agents/test_ppt_revision_writes_deliverable.py`, 4 passed;
`tests/agents/test_streamed_text_payload_v3.py`, 8 passed). What stays open is the *guard*. Two independent
test-infrastructure faults stack on the one test written to lock this behaviour in, and the file the validator counted
as existing zip coverage dies on the second fault alone. The agreed minimal fix is accepted in substance and
overruled in placement (see "The agreed minimal fix").

### Root cause — CONFIRMED (ran it and read it)

1. **Placement: the guard is filed in the one directory that forbids what it does.**
   `backend/tests/unit/conftest.py:90-179` is an autouse fixture (`_unit_io_guard`) that, unless the test carries
   `allow_io`, installs `_deny_db_connect` (`:79-87`, a SQLAlchemy `Engine` "connect" listener), `_deny_popen`
   (`:127-136`) and `_deny_connect` (`:152-159`). `backend/tests/unit/test_sandbox_ref_scoped_endpoints.py` builds an
   in-memory SQLite engine and calls `Base.metadata.create_all(bind=db_engine)` at `:61`, which fires the listener:
   `tests.unit.conftest.UnitIsolationError: Unit test opened a real database connection`, 5 errors at setup. Its
   `_make_tagged_sandbox` (`:133-153`) also runs real `git`, which `_deny_popen` would refuse next. The file has no
   `allow_io`, and `backend/tests/README.md:74-81` (rules 7 and 8) sends "TestClient plus a DB session" and "spawns
   git" to `tests/integration/<pkg mirror>/`.
2. **Fixture drift: behind the guard, the seed no longer works.** `_seed_user` (`:95`) calls
   `User(..., password_hash="x")`. The model has no such column since the Cognito-only migration
   (`backend/app/models/user.py:46-51`, `cognito_sub` NOT NULL; `grep -rn password_hash backend/app` finds nothing;
   last touched by `b2a621f84`, 2026-09-17). With the guard lifted, setup raises
   `TypeError: 'password_hash' is an invalid keyword argument for User`. The same kwarg is in ten other test files:
   [ISS-891](20261001-2120-ISS-891.md).
3. **Consequences.**
   - Five route guards never run: `test_different_refs_return_different_bytes` (`:159-180`, the v1/v2 file-bytes test
     the BUGS.md fix asks for, so it already exists), no-ref-serves-HEAD, unknown-ref 400, `/sandbox/refs` equals
     git's tags, and ref-scoped sizes (QA-PS-032).
   - The `xfail(strict=True)` pin for [ISS-697](20260922-1000-ISS-697.md) (`:312-314`) is **vacuous**: it reports `x`
     because setup errors, not because ISS-697 is unfixed. With the fixture working, `--runxfail` shows its real
     failure (`assert 'v1' in []`). It could never XPASS when ISS-697 is fixed.
   - The validator's "existing" zip coverage, `tests/agents/test_revision_routes_v3.py:365`, is dead too: 12 of 12
     tests in that file fail with the same `TypeError` (`:90`). No test that drives these routes against real git
     under a ref runs today.
4. **Proof by lifting each fault** (a scratch pytest plugin outside the repo adds `allow_io` and swaps `_seed_user`
   for a `cognito_sub` seed; no repo file touched): the dead file goes from `1 xfailed, 5 errors` to
   `5 passed, 1 xfailed`; `test_revision_routes_v3.py` from `12 failed` to `12 passed`;
   `test_run_files_ref_family_scope.py` ([ISS-892](20261001-2120-ISS-892.md)) from `2 errors, 1 failed` to `3 passed`.
   The dead tests encode behaviour that is currently correct.
5. **Why nobody saw it (INFERRED).** `backend/tests/README.md:183-186` records 63 files / 599 tests as red-by-design
   under this guard, and CI runs the whole tree (`.github/workflows/ci.yml:336`), so six more errors were
   indistinguishable from the baseline. From `git log`: model change 2026-09-17 (`b2a621f84`), the guard
   (`09270703b`) 2026-09-22, and this file landed 2026-09-22 in `9ceccf84f` (the FIX-601 commit). Its docstring
   ("landed concurrently on this branch during authoring") suggests it was written on a branch that predates both.

**Not the cause: the product.** `read_sandbox_file`'s ref branch (`backend/app/api/run_files.py:1162-1196`) and
`download_sandbox_zip`'s (`:1050-1089`) return `git show` / `git archive` output, and the probes below return the
right bytes.

### The agreed minimal fix: accepted in substance, overruled in placement

**Accepted**: its assertions are right and feasible. A scratch probe that direct-calls `rf.read_sandbox_file` and
`rf.download_sandbox_zip` with a real `RunSandbox` and `RUNS_ROOT` at `tmp_path` returns v1/v2 bytes and a v2 zip with
no DB, no `TestClient` and no user seed.

**Overruled**: (a) its read half duplicates `test_different_refs_return_different_bytes` (`:159-180`) verbatim;
(b) adding it to `tests/agents/test_iss720_ref_scoped_sizes.py` (a sizes file whose `_Sandbox` stub cannot exercise
`RunSandbox` or chain-root resolution) leaves the five dead guards, the vacuous ISS-697 pin and the 12 dead sibling
tests exactly as they are, which is the root cause the validator told us to scope to; (c) the card must not flip to
`resolved` on FIX-601 plus one new test, because the card's own claim is revision workflows and edge cases guarded
under a pinned ref.
