# ISS-131

## Title

A fan-out step's DECLARED human gate is deduped against an inline gate that no longer fires. engine.py:2470 passes inline_gated=self._should_gate(spec, ectx) into _evaluate_gates at the step boundary; the dedupe exists so a step that both declares gates:[human] and has its agent in gate_agent_ids does not double-prompt (pre-step with an empty payload, then post-step with the real output). After FIX-242 the inline gate no longer fires for a fan-out step — workers opt out and the step's own agent is never inline-invoked, because the strategy replaces the L7 dispatch — so inline_gated=True there is now a stale prediction and the declared gate is skipped for a gate that never opens: that step gets no gate at all. Strictly better than the pre-fix behaviour (which HUNG on the same combination) but still a silent loss of a gate the author declared. Not reachable from any file manifest today — verified: the only two fan-out/wave steps in agents/workflows/ (sample_fanout, sample_wave) both declare gates: [] — so it is reachable only via composed selections, which can set gates and strategy: fanout_batch on the same agent.

## Source / evidence

Found 2026-08-12 by the ISS-097 fix (quick-260812-syf) as a second-order effect, and deliberately left byte-unchanged so FIX-242's INV-3 dormancy argument stayed exact. Fix shape is a DESIGN decision, not a patch: :2470 needs to know whether this step runs its agent inline, which the kernel must NOT infer from a strategy-name list (that would be exactly the capability-name branch the Ports-and-Adapters rule forbids). The clean shape is for the strategy capability to declare it — e.g. a runs_agent_inline property on the strategy port that the dispatch loop reads generically.
