## Symptom

Clicking any model in the analytics filter dropdown (e.g. "Sonnet 5") showed all-zero
KPIs, empty daily chart, and no pipeline/agent breakdown. Only the "unknown" filter
returned data.

## Root cause

`backend/app/api/analytics.py` `get_analytics_summary`:

```python
# Before fix
query = query.filter(WorkflowRun.model_id == model)
```

`WorkflowRun.model_id` is `nullable=True` and is only written by
`_apply_terminal_output_columns` at completion time (CWF-002 fix). Historical runs
and runs where the driver path differs have `model_id = NULL`. The model IDs shown in
the dropdown come from the RFN-002 two-pass `agent_outputs` merge — but the filter
query looked only at the run-row column. Result: exact equality against a real model
ID on a NULL column → 0 rows.

## Fix

`backend/app/api/analytics.py`:

Added `from sqlalchemy import or_` to module-level imports. Extended the model filter
with a two-path OR:

```python
from sqlalchemy import or_
...
query = query.filter(
    or_(
        WorkflowRun.model_id == model,
        (
            WorkflowRun.model_id.is_(None)
            & WorkflowRun.agent_outputs.contains(model)
        ),
    )
)
```

The substring match on `agent_outputs` is safe: model ID strings (e.g.
`eu.anthropic.claude-sonnet-5`) are long, unique, and cannot produce false positives
in a JSON blob. Works identically on SQLite (dev) and PostgreSQL (prod) via
SQLAlchemy's `.contains()`.

The `unknown` path is unchanged: `WorkflowRun.model_id.is_(None)` (no `agent_outputs`
clause, since unknown means no real model anywhere in the run).
