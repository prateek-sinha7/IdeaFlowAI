# FIX-721

## What was wrong

This fix is for bug report QA-KB-058. The root cause comes from the 2026-10-02 analysis on
[ISS-917](20261001-2220-ISS-917.md) and its sibling [ISS-982](20261002-0427-ISS-982.md). It was not re-derived here;
every cited line was re-read before editing, and the card held.

- The header Back was a bare navigation, `onClick={() => goBackOr(router, () => router.push(routes.home()))}`
  (HEAD `LaunchWizard.tsx:1093`; the card's `:1078` had moved).
- "Open in full canvas" was a bare `router.push(...canvas)` (HEAD `:1491-1494`).
- The wizard keeps the brief, template, design system, Discovery answers, attachments and roster in component state
  and persists none of it before Continue.
- It mounts outside `DashboardLayout` (`[...view]/page.tsx:4121`, `workflow/create/page.tsx:48`), so the shared
  `hasUnsavedWork` guard and its dialog (`DashboardLayout.tsx:1855-1897`, `:3488-3527`) never reach it. Both exits
  dropped typed input with no dialog. The validator reproduced Back 3/3 (`evidence/qa-kb-058/01..06-*.png`).

## What changed, and why there

Both mounts render this one component, so a guard inside it covers every wizard route and all four modes. Nothing
changed in the pages, in `goBackOr` (four call sites, two already behind the shared guard) or in `DashboardLayout.tsx`.
Line numbers are as of this fix, in the uncommitted tree.

1. `LaunchWizard.tsx:280` `userEditedRef = useRef(false)`, a latch, and `:282` `pendingLeave`, the exit the dialog is
   holding.
2. The latch is set by the user writers the card lists:
   - the textarea `:1265`, "Use template example" `:1329` and the dictation effect `:722` (inside `if (transcript)`);
   - `handleSelectTemplate`/`handleSelectCustomTemplate` `:807`/`:812` and the two design-system handlers
     `:817`/`:822`;
   - `handleModeChange` `:756`, and roster add/remove/reorder `:770`/`:793`/`:798`;
   - `handleUserSelectionsChange` `:367-370`, a wrapper passed only to `ReviewGatesSection` (`:1416`) and
     `AgentsPopup` (`:1548`).

   `handleSelectionsChange` itself is untouched: the draft restore, override overlay and toggles also call it, so
   latching there would prompt on an untouched wizard. `handleGatesChange` is not latched either. A gate toggle
   already reaches the wrapper through `onSelectionsChange`, and its mount reports carry `touched=false`.
3. `requestLeave` `:1105-1110` reads `userEditedRef.current`, attachment presence and `!isDiscoveryEmpty(discoveryAnswers)`
   at click time. If any is true it holds `go` in `pendingLeave`; otherwise it runs `go` at once. Back (`:1130`) and
   `onOpenInCanvas` (`:1530`) pass their navigation in. `handleLaunch` is unchanged and never prompts.
4. `handleSaveWorkflow` clears the latch after `createUserWorkflow` resolves (`:985`). That save persists the brief,
   template, design system, roster and selections. `handleSaveAsOverride` does not clear it. Attachments and Discovery
   are never saved, so they still count after a save.
5. New `frontend/src/components/ui/UnsavedChangesDialog.tsx` (`onStay`, `onLeave`) on the existing `ui/Modal`
   primitive, with role dialog, focus trap, Escape and scroll lock. It carries the shipped strings and `ui/Button`.
   Escape, a backdrop click and Stay all call `onStay`. It lives in `components/ui`, so `workflow/` imports nothing from
   `layout/`. `DashboardLayout`'s inline copy was left where it is: optional per the card, and that file is under
   concurrent edit.

ISS-982 says "prompt or carry the state" is a product call and recommends prompting as the smaller change. Prompting is
what shipped: the canvas exit reuses the same signal and dialog. Carrying the brief to the canvas remains possible later
and is not done here.

## Not fixed

- The known ceiling from [FIX-352](20260828-2346-FIX-352.md) and ISS-917's last section is unchanged. Browser Back,
  refresh, the address bar and a tab close bypass any in-app guard, and there is no `beforeunload`. That is a
  separate product call.
- A latch cannot un-dirty. Typing then clearing, or editing in Advanced then Cancel, still prompts. This is the safe
  direction, and the card accepts it.
- An image attach counts once its FileReader `onload` lands, not synchronously like a document (`attachedFiles` is set
  before the async read).
- `DashboardLayout.tsx:3488-3527` still carries its own inline copy of the dialog. Moving it onto
  `UnsavedChangesDialog` is optional (ISS-917) and was not done.
- Pre-existing debt, not touched: `LaunchWizard.test.tsx` has 2 failing chain tests at HEAD (QA-KB-062 /
  [ISS-347](20260828-2058-ISS-347.md) territory), and raw ESLint on `LaunchWizard.tsx` reports 10 problems at HEAD.

## Invariants

- Nothing under `backend/` changed, so SC-001/INV-1, the import-linter contracts and the additive-migration rule are
  not in play.
- The guard keys on edit state only, never on `mode` or a workflow name.
- `PreviewPanel.tsx` and `RunHeader.tsx` were not touched.
