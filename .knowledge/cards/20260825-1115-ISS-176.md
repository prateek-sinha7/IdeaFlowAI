## Symptom

Cosmetic. Within one gate's fan, an external workflow (divert) node's centre
does not line up with the step targets sharing its column.

Measured on the 14-node / 5-gate case:

```
DUTCH GREETER  cx=304    t1, m1, l1  cx=314
SPANISH GREETER cx=717   m-ok        cx=727
```

A consistent ~10px leftward offset.

## Root cause (probable — not yet confirmed in code)

An external node is `EXTERNAL_NODE_W` wide while a step card is `NODE_W = 260`.
Both are positioned from the same column x, which is a LEFT edge, so the
narrower box's CENTRE lands left of the wider box's centre by half the width
difference. Confirm against the external-node render site
(`CanvasView.tsx`, `left={wf.x}`) before changing anything.

## Fix direction

Position fan members by CENTRE rather than left edge, or offset an external
node by `(NODE_W - EXTERNAL_NODE_W) / 2`. Prefer centre-based positioning — it
generalises if further node widths appear, and it matches the minor-axis rule,
which is already centre-based.

## Priority

Low. Purely visual; no overlap, no incorrect edges. Worth folding into the
[ISS-175](20260825-1115-ISS-175.md) work since that pass already moves every
coordinate.

## Resolution (2026-08-25)

Confirmed the cause: `EXTERNAL_NODE_W = 190` (`CanvasNode.tsx:299`) against
`NODE_W = 260`, both positioned from the column's LEFT edge, so the narrower box
sat 35 stage-px left of centre.

Fixed in `CanvasView.tsx`'s `externalSlotById` by offsetting
`(NODE_W - EXTERNAL_NODE_W) / 2`. Applied at the slot source rather than the
render site so the amber route edge endpoint (`ex: wf.x - ARROW_INSET`) follows
automatically.

Verified on A3: `SPANISH GREETER`, `a-english` and `DUTCH GREETER` all report
`cx = 1030` exactly (was 901 / 930 / 901).
