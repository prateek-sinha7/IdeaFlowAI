## Description

The settled "Task plan · N planned" card rendered the number COMPLETED, not the number planned — wrong at the latest version and frozen under the artifact version picker (ISS-087). deriveArtifactCardModel derived the card's rows and count from protoCompletedTasks/protoCompletedTaskCount — the BUILD agent's task_progress stream (useWorkflow.ts:966-995) — while the label claimed "planned". The ISS-087 row was wrong on two of its three decision-relevant claims and understated the defect (see the corrected row). Measured read-only on backend/dev.db: run d5dbc9f2's plan holds 7 tasks and the card rendered "6 planned" with no picker interaction at all; run 6e38b9a7 kept showing 11 after selecting a 10-task v1; prototype-plan is multi-version on 5 of 6 run-groups, so the picker is visible on most prototype runs — the opposite of the row's "one version on most runs". Fix (owner decision D1): the card parses the <tasks> body ON SCREEN. Because the panel already passes displayed (AgentDetailPanel.tsx:753, FIX-226's thread), the card follows the picker with no second threading added. parseTasks was EXTRACTED verbatim from TasksPreview into artifactPreview.tsx:80-104 beside parseSpecSections/parseSpecOverview, mirroring how those were lifted from SpecPreview — no third parser (INV-12). useWorkflow.ts was deliberately left untouched: its regex is line-anchored and tolerates \s*:, is NOT equivalent, and feeds ConstructionBlock; filed as ISS-115 rather than silently unified. The dead protoCompletedTasks/protoCompletedTaskCount props were deleted, not left inert — the build's completed tasks still reach the ConstructionBlock via construction.tasks (AgentThinkingTab.tsx:195-202), where the label matches the data. dagEdges closed as NOT-a-defect (a DAG edge is constant within a run); the validation badge NOT version-threaded because it is dead (ISS-116). 3 pinned 42-09 tests reconciled — none deleted, skipped or loosened; 2 encode owner-approved behaviour changes (the count is the plan's size; a single_shot <tasks> agent now shows its plan).

## Root cause

A card was fed a truthful count of the WRONG QUANTITY: "completed" rendered under a "planned" label. The version bug ISS-087 was filed for was a symptom — the rows never came from the artifact at all.
