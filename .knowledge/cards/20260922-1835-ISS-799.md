# ISS-799

## Description

INFERRED sibling of [ISS-801](20260922-1834-ISS-801.md), derived from QA-PS-035's
root cause, not yet reproduced. QA-PS-035's own measurement
([ISS-781](20260922-1630-ISS-781.md)) only captured `/settings/profile`
(the default tab) — BUGS.md's repro step 5 says "click any other settings
tab... and observe" but the report's "Actual" table lists only the Profile
numbers. Two of Account Settings' other four tabs have their own
independent mount-time GET, in the same unguarded shape ISS-801 confirms
doubles under `next dev`, and neither has been measured:

**Security tab** — `frontend/src/components/settings/SecuritySection.tsx:103-105`:
```tsx
useEffect(() => {
  void load();
}, [load]);
```
`load` (line 75-94) calls `getMfaStatus(token)` ->
`frontend/src/lib/api.ts:507` `GET /api/auth/mfa`. No `AbortController`, no
in-flight guard — same empty-guard shape as ISS-801's AccountSettings.tsx
effect and ISS-794's page.tsx effect.

**Constitution tab** — `frontend/src/components/settings/AccountSettings.tsx`'s
local `ConstitutionSection` function, mount effect at line 597, fetching
`GET /api/settings/constitution` (`authedFetch` call at line 603). This one
is not a new discovery: [ISS-581](20260829-0241-ISS-581.md) named the
double-fire explicitly back on 2026-08-29 ("React StrictMode double-invokes
the mount effect, so the GET can fire twice") and its fix,
[FIX-421](20260831-FIX-421.md), added a `userHasEdited` ref — but that ref
only blocks the late response from overwriting a typed draft; it does not
cancel or dedupe the request. The wasted duplicate GET itself was never
fixed, so it should still reproduce today.

## Condition

Navigate to `/settings/security` (or click the Security tab from
`/settings/profile`) — expect `GET /api/auth/mfa` x2. Navigate to
`/settings/constitution` (or click the Constitution tab) — expect `GET
/api/settings/constitution` x2.

## Expected vs actual (predicted, not yet measured)

- Expected: each tab's own GET fires once per mount.
- Actual (predicted from the confirmed mechanism, not measured): each fires
  twice — Security joining ISS-801's family as a new site; Constitution
  already named in ISS-581 but left unfixed for the network-waste half of
  that finding.

## Why the root cause implies this

Both effects share every trait ISS-801/ISS-794 already tie to the
`next dev` mount -> unmount -> remount double-invoke: a plain `useEffect`
with a stable/empty dependency list, no `AbortController`, no
mounted/in-flight ref. ISS-801 confirms that shape doubles for two other
effects in this exact component tree; nothing about the Security or
Constitution effects is different in a way that would exempt them — this
is an unreproduced lead, not yet confirmed by a capture on either tab.

## What would settle it

Load `/settings/security` and `/settings/constitution` directly (cold,
fresh tab) and read `performance.getEntriesByType('resource')` or the
Network tab, same method ISS-781/794 used, filtered to `/api/auth/mfa` and
`/api/settings/constitution`.
