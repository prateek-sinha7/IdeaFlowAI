# ISS-072

## Title

**Collapse the doubled analyze gate by suppressing the IN-PASS firing `[1]`, not the re-opened one.** One "Update the Specs" click still costs four approvals. FIX-220 made the firings identifiable but suppressed nothing. The evidence says the redundant firing is `[1]`, the analyze re-run INSIDE the sub-pipeline: it shows content the user is about to be shown again (live `5ecb990f` seq 24652/24655 — same 11,974 bytes, sha1 `0136795fc392`), it offers a strictly SMALLER action set than `[2]` (no "Update the Specs", by FIX-218's design), and approving it has no externally visible effect (approve seq 24654 -> gate 24655; only the SECOND approval reached `agent_start prototype-build`). Suppressing `[2]` instead — what ISS-052's own text proposed — is disqualified: it is the only `update_specs_eligible=True` firing, so it deletes the sole entry to a second cycle and regresses ISS-064. **Fix shape (from the ISS-052 investigation, use it):** in `_run_spec_revision_sub_pipeline`, set a generic `ectx` suppression marker around the THIRD loop iteration using OBJECT IDENTITY (`sub_spec is analyze_spec`) — the same name-free idiom already used for `spec_revision_prior_artifact` at `engine.py:5281-5283` — and have `_should_gate` honour it. Do NOT key it on `ectx.revision_attempt` alone: that also kills the specify and plan in-pass gates, which ISS-052 says are WANTED and which the live data shows the user genuinely uses (seq 13640/23221 both approved). **Why it needs its own brief, not a rider:** it rewrites all six assertions in `test_spec_revision_cycles.py` (`:84-88`, `:219-224`, `:253-265`, `:293-297`); by INV-12 it forces DELETION of condition 2 of `_update_specs_eligible` (`engine.py:6649`, the one-day-old FIX-218 fence — with `[1]` gone that condition is unreachable, since the specify/plan in-pass gates are already ineligible by KIND); it must decide what happens on the empty-analysis backstop path (`engine.py:5214-5222` returns silently when `index < 2`, after which `[2]` is the ONLY human checkpoint before the build); and the underlying question — is the in-pass analyze review wanted at all? — is a PRODUCT call nobody has stated a position on. Saves 3 `run_events` + one approval per cycle.
