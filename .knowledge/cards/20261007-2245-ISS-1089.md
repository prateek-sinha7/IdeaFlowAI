# ISS-1089

Found while fixing QA-KB-076 ([FIX-756](20261007-2245-FIX-756.md)), not fixed there. No card in that bug's set covered it.

## What is wrong

`09270703b` (2026-09-22, "Fix/testcases (#9)") renamed 326 files, moving backend tests into `tests/unit/app/`,
`tests/unit/services/`, `tests/integration/agents/`, `tests/integration/api/`, `tests/e2e/agents/` and similar. Many of
those test modules open their docstring with their own path. The move did not update that text. 71 of the renamed
`.py` files that still exist name the old path on line 1. For example:

- `backend/tests/unit/app/test_iss102_live_model_guard.py`, line 1: `tests/unit/test_iss102_live_model_guard.py`
- `backend/tests/integration/agents/test_resume_marker_workspace_db.py`, line 1: `tests/agents/test_resume_marker_workspace.py`
  (the file was renamed as well as moved)
- `backend/tests/e2e/agents/test_live_harness.py`, line 1: `tests/agents/test_live_harness.py`

The full list, with the method, is in `evidence/qa-kb-076/13-fix-stale-self-path-docstrings.txt`. It counts first lines only,
so a path written further down a docstring is not counted.

[ISS-903](20261001-2145-ISS-903.md) found two such lines in `test_shutdown_reachability.py`, and FIX-756 corrected those
two. [ISS-1084](20261007-2216-ISS-1084.md) names the same mechanism: a path written as text does not follow a move.

## Impact

Trivial. Nothing executes these strings. A reader who copies the path from the docstring into `pytest` gets
"file not found" and has to search for the file instead.

## Disposition

Open. The fix is comment-only: replace each first-line path with the file's current path, or drop the self-path,
because the filename already says it. It was not done in FIX-756. That fix was scoped to QA-KB-076's cards, and a
71-file sweep across unrelated suites belongs in its own reviewed change. A guard would have to compare each test
module's first line with its own path relative to `backend/`. That check is cheap, but nothing asks for one yet.
