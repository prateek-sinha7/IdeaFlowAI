## What was wrong

`LibraryPage.tsx` read `agentsStatus`/`skillsStatus`/`hooksStatus` from Redux but
only ever special-cased `=== "loading"`. Every other status value — including
`"failed"` — fell through to the bare `filteredAgents.map(...)` / `activeSkills.map()`
/ `filteredHooks.map()` calls. On a failed fetch the arrays are empty (the thunk
never populated them), so the grid rendered identically to a zero-result search —
blank content area, no messaging, no way to distinguish "the API is down" from
"your filter matched nothing."

Root cause confirmed by [ISS-330](20260828-2041-ISS-330.md): `agentsSlice.ts:9`
types `status` as `"idle" | "loading" | "succeeded" | "failed"` but only `"loading"`
was branched at the render sites (`LibraryPage.tsx:732`, `793`, `815`, `893`, `911`
pre-fix).

## What changed and why there

One file, `frontend/src/components/library/LibraryPage.tsx`:

1. Added `FetchErrorState` component (above `SkillDetailModal`) — renders a
   `col-span-full` message "Failed to load {noun}. Please refresh and try again."
   Visually distinct from `EmptyGridState`, no "clear search" affordance (the error
   is not filter-driven).

2. Inserted `agentsStatus === "failed" ? <FetchErrorState noun="agents" />` between
   the `loading` branch and the `filteredAgents.length === 0` branch in the Agents
   grid (was `LibraryPage.tsx:805`).

3. Same pattern for Skills grid: `skillsStatus === "failed" ? <FetchErrorState noun="skills" />`.

4. Same pattern for Hooks grid: `hooksStatus === "failed" ? <FetchErrorState noun="hooks" />`.

The change is in `LibraryPage.tsx` rather than in the three slices because this is
a render-path decision — how the page presents each status — not a data-layer
concern. One guard per grid, three lines added.

## Not fixed here

ISS-335 (category filter alone hitting the same blank grid) was already addressed
by the existing `EmptyGridState` component checking `filteredAgents.length === 0`
unconditionally — confirmed by code read, no further change needed.
