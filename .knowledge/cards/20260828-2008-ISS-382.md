## Sibling of ISS-274 — INFERRED, not yet reproduced in the browser

[ISS-274](20260828-1854-ISS-274.md)'s own "Expected" statement asks — at minimum — that
"the Overrides row should visibly flag when an agent has a non-default tool-grant
restriction set elsewhere in the same composer session, so the two views never silently
disagree about what capabilities an agent actually has." That ask was scoped to Simple
view's `AgentRow.tsx` row. The identical gap exists one level closer to the root, inside
Canvas view itself.

`frontend/src/components/workflow/composer/CanvasNode.tsx` — the node card rendered on the
canvas BEFORE a user clicks into it and opens `CanvasConfigRail` — computes its own
at-a-glance override-chip booleans directly off `selection` (`CanvasNode.tsx:484-489`):
`validatorOn`, `gateOn`, `retryOn`. There is no `toolsOn`/`toolsRestricted` boolean anywhere
in the file (confirmed: `grep -n "tools" CanvasNode.tsx` returns nothing). The chip row
itself (`CanvasNode.tsx:763-802`) is introduced by the comment "override chips — Validator
(brand) · Gate (amber) · Retry (brand)" (`CanvasNode.tsx:763`) and renders exactly those
three chips — nothing for Tools. (Skills is not a gap by the same measure — it has its own,
separate "attached-skill chips" block further down the card, per `CanvasNode.tsx:859`.)

So even a user working entirely inside Canvas view, who sets `sel.tools.write_files =
false` for one agent via the rail's Tools tab (`CanvasConfigRail.tsx:550-613`,
confirmed real and persisting — see [ISS-274](20260828-1854-ISS-274.md)'s own
Reproduction step 2-3), gets no visual signal on that agent's own node card afterward.
The only way to rediscover the restriction is to reselect the node, open the rail, and
click into its "Tools" tab specifically — the same "must go looking for it" shape ISS-274
already names for Simple view, just one surface earlier.

## Expected vs actual

- **Expected:** a node carrying a non-default tool grant (e.g. `write_files: false`) shows
  some at-a-glance signal on its own canvas card — consistent with Validator/Gate/Retry
  already getting one apiece.
- **Actual:** `CanvasNode.tsx`'s override-chip row computes and renders exactly three
  booleans (`validatorOn`/`gateOn`/`retryOn`); no fourth chip, and no other visual cue,
  reflects `selection.tools` anywhere in the card.

## Why this is INFERRED, not CONFIRMED

The absence of a Tools chip in the card's source is confirmed by reading the full
`CanvasNode.tsx` chip-row block and grepping the file for `tools`. What is NOT yet verified
is a live-browser screenshot showing a restricted node's card next to an unrestricted one
with no visible difference — the natural next validation cycle: repeat
[ISS-274](20260828-1854-ISS-274.md)'s Reproduction step 2 (toggle "Write files" off for one
agent in the rail), then, WITHOUT opening the rail again, visually compare that node's card
to the other agent's card on the canvas.

## Evidence

`CanvasNode.tsx:763-802` (chip row JSX, three chips only).
