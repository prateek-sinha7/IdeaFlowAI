## Symptom

The Analytics page "By Agent" section did not exist. The "By Model" breakdown showed
only the `unknown` sentinel (NULL run-row `model_id`) with all token volume, even when
runs used real models like Haiku 4.5 or Sonnet 5, because only `WorkflowRun.model_id`
(the run-row column) was used for model attribution — which is NULL until
`_apply_terminal_output_columns` writes it at completion.

## Root cause

`backend/app/api/analytics.py` `_aggregate()` only read `r.token_usage` (run-level totals
blob). `r.agent_outputs` — a JSON array already carrying `input_tokens`, `output_tokens`,
`total_tokens`, `model_id`, `agent_id`, and `name` per agent (persisted by
`run_commands._apply_terminal_output_columns` via ISS-165) — was never parsed.

## Fix

`backend/app/api/analytics.py`:

1. Added `AgentRollup` Pydantic model (`agent_id`, `agent_name`, counts, tokens, cost).
2. Added `agents: list[AgentRollup]` field to `AnalyticsSummary` (`default_factory=list`
   so existing callers are unaffected — purely additive).
3. Extended `_aggregate` with three new dicts: `agents_acc`, `agent_names`,
   `models_agent`. Inner loop parses `r.agent_outputs` with `try/except → []` DoS guard,
   accumulates per-agent token/cost, and tracks `run_ids` set per agent-level model_id.
4. Post-loop: `models_agent` merged into `models` dict — token/cost replaced by
   agent-level totals; run count set to `len(run_ids)` when the run-row bucket had
   count=0 (NULL model_id). Shrinks the `unknown` bucket.
5. `agent_rollups` built sorted by `total_tokens` descending.
6. Added `from agents.capabilities.model_pricing import estimate_cost_usd` and
   `from app.core.config import settings` imports.
