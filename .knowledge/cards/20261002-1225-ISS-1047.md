# ISS-1047

**Deferred, not fixed.** Filed by [FIX-715](20261002-1225-FIX-715.md) under book-keeping Step 3. This is the second of the
"two independent defects" in [BUG-127](20260918-BUG-127.md) ("What a fix must do", item 2). FIX-715 fixed the first one, the
`newline=` `TypeError` at `tools/knowledge/build_context.py:431`. That was the only trigger anyone observed. The mechanism
below is unchanged.

## Mechanism

Read from the tree on 2026-10-02. The QA-KB-051 analysis reproduced it with the old trigger.

- `tools/knowledge/rebuild_knowledge.py:57-62`: `STAGES` runs `index` before `context`.
- Stage `index` writes the card `## Related` blocks (`build_index.py:308`), then `INDEX.md` (`:333`), then `state.yaml`
  (`:378-381`).
- `rebuild_knowledge.py:322-327`: when a stage fails, the loop prints `Aborted at stage 'context'. Nothing further was run.`
  (`:326`) and returns 1. Nothing is restored, and the message does not say that `index` has already written its files.
- Sandbox proof from before FIX-715 (`evidence/qa-kb-051/analysis-sandbox-repro.out.txt`, step 3): `INDEX.md` and
  `state.yaml` at 1699 cards, `CONTEXT.md` still at 1698, and `validate` never ran.

## Triggers left after FIX-715

These were read from the code, not run.

- `MissingInput` from `build_context.load_modules()` (`build_context.py:201-226`), raised when `modules.json` is missing or
  unreadable.
- Any other exception in `build_context.main()`, including the next 3.10+ API called under a bare `python3`.

## Why low

- `skills/velocity/cli.md:67-76` already documents the behaviour ("Fail-fast is not atomic ... There is no rollback").
  The recovery it gives is to re-run, because the stages are idempotent. The `rebuild_knowledge.py` docstring (`:4-5`,
  "cannot be run half-way") still promises the opposite.
- The sync-watermark half of the same mechanism is [ISS-971](20261002-0342-ISS-971.md), which is also open.

## Disposition

Open. [BUG-127](20260918-BUG-127.md), section "Fix (where it belongs)" item 2, lists three options and does not choose
one:

- (a) Make the abort message name the stages that already wrote.
- (b) Run `context` before `index`. This also closes ISS-971, but it needs the `load_state()` precondition relaxed
  (`build_context.py:163-198`) and the stage diagram updated.
- (c) Roll back what the failed run wrote.

The two `locked_constraints` above apply whichever option is chosen. No test exists yet. ISS-971's section "For the
test-writer" describes the hermetic harness: copy `tools/knowledge/` into a temporary tree, `git init` it, and use a
`context` stub that exits 1.
