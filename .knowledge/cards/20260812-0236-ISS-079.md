# ISS-079

## Title

**2 further reds in the shared baseline that ISS-068 never recorded: `backend/tests/agents/test_phase6_frontend_consistency.py`.** `TestPrototypeAndPptSpecifics::test_prototype_real_ids_and_human_gate` (extra item in the left set: `'prototype-analyze'`) and `TestPipelineCategoryCounts::test_ppt_and_prototype_counts_reconciled` (`assert 5 == 4`, "prototype category count must be 4 (spec-kit)"). **Re-baselined as pre-existing with evidence, not labelled:** measured identically (2 failed / 15 passed, same 2 ids) in a **detached worktree at `f5f2f7c6`** — so they are not a FIX-223/224 regression. Cause is a **stale test, not a defect**: commit `5c947270` added the `prototype-analyze` Spec-Kit step to the prototype workflow (present on `dev`, so shared, not branch-local), making the prototype category 5 while the test still hardcodes the pre-analyze 4-agent id set and count. Fix is to update the expected id set + count to include `prototype-analyze` — but **verify first** that 5 is the intended membership (check `registry.PIPELINE_AGENTS["prototype"]` and the prototype manifest) rather than editing the number to match reality, which is the mistake this whole ISS-068 family exists to prevent. Same consequence as ISS-068 while it stands: this suite cannot serve as a clean pass/fail gate.
