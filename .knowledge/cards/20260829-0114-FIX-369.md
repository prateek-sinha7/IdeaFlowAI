## What was wrong

`/preview-fullscreen?error=quota` always rendered the "Project too large for full screen"
dead end, even when `sessionStorage["__app_preview__"]` still held a valid, renderable payload
that the plain (no-param) route rendered correctly moments earlier in the same tab.

`AppBuilderPreview.handleFullscreen()`
(`frontend/src/components/preview/AppBuilderPreview.tsx:406-421`) writes that key and calls
`window.open(..., "_blank")` **without** `"noopener"` on purpose, so the new tab shares the
opener's browsing context and its sessionStorage. `sessionStorage.setItem` is atomic: the
`QuotaExceededError` that opens `?error=quota` leaves an earlier, smaller, successful write
untouched. So the quota tab frequently has a perfectly good preview available and refused to
look at it.

## Root cause

`frontend/src/app/preview-fullscreen/page.tsx:46-50` (pre-fix):

```tsx
// Check for quota error flag from opener
if (params.get("error") === "quota") {
  setState("quota");
  return;
}
```

That `return` sits ahead of the `setTimeout` at `page.tsx:54-73` which performs the
`sessionStorage.getItem("__app_preview__")` read/parse the no-param path uses. Pure branch
order: the quota flag short-circuited the only code that could have found the cached payload.
The page's own docstring (`page.tsx:27-29`) already claimed the read-then-fall-back precedence
the code did not implement.

## What changed and why there

One file, one `useEffect`. The early return became a `const quota = params.get("error") === "quota"`
flag, and the sessionStorage read now runs for both entry paths. The three "nothing usable"
exits inside the timeout (`!raw`, empty `files`, parse throw) route through a single `giveUp()`
that shows the quota dead end when the flag is set and redirects to run history otherwise —
which is exactly the pre-existing behaviour for each path, minus the short-circuit.

This is where all callers converge: `handleFullscreen` is the only producer of `?error=quota`
and this page is its only consumer (`grep '__app_preview__\|error=quota' frontend/src` returns
those two files and nothing else), so the guard belongs in the consumer's read, not at the
call site.

**Conscious decision, flagged by the analysis:** `__app_preview__` carries no run/project
identity ([ISS-412](20260828-2343-ISS-412.md)), so the quota path can now display a payload
from an earlier Full Screen click. That is not a new risk class — the plain route has always
rendered "whatever is cached" from the same unscoped key — and this change only makes the
quota path consistent with it. Scoping the key to a run stays with ISS-412.
