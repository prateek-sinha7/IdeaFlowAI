## Relationship to the root bug

Sibling of [ISS-230](20260828-1805-ISS-230.md) — a different consumer of the same "version
pin" concept with the same net effect, via a THIRD, independent mechanism that has nothing to
do with the URL/tab-router path ISS-230 and [ISS-294](20260828-1725-ISS-294.md) describe. This
one reproduces purely through the click-driven Version-menu path, with no navigation involved
at all.

## Root cause (INFERRED from static reading — not yet re-driven through the browser this pass)

- `PreviewPanel` already computes version-aware content once a pin is active via
  `viewingVersion` (`frontend/src/components/preview/PreviewPanel.tsx:590-594`):
  ```ts
  const overrideActive = viewingVersion != null;
  const overrideContent = viewingVersion?.content;
  const effUserStoryContent = overrideActive && (renderType === "user_stories" || renderType === "app_builder") ? overrideContent : userStoryContent;
  const effPptContent = overrideActive && renderType === "ppt" ? overrideContent : pptContent;
  const effPrototypeContent = overrideActive && renderType === "prototype" ? overrideContent : prototypeContent;
  ```
  These correctly substitute the pinned revision's fetched output — and are what the Preview
  tab itself renders.
- The `<FilesTab>` mount (`frontend/src/components/preview/PreviewPanel.tsx:1280`) is passed
  the RAW props instead: `userStoryContent={userStoryContent} pptContent={pptContent}
  prototypeContent={prototypeContent}` — the un-overridden values — never
  `effUserStoryContent`/`effPptContent`/`effPrototypeContent`.
- `FilesTab` derives its file list — including the "Final output" size shown to the user —
  purely from those raw props: `deriveDeliverableFiles(workflowType, { userStoryContent,
  pptContent, prototypeContent })` (`frontend/src/components/results/FilesTab.tsx:625`), with
  `size: formatSize(userStoryContent.length)` / `formatSize(pptContent.length)` /
  `formatSize(prototypeContent.length)` computed directly off them
  (`FilesTab.tsx:389,397,414,422`).
- Contrast with the Workspace tab, which correctly threads the pin:
  `workspaceRunId = viewingVersion?.id ?? pipelineState?.pipelineRunId ?? activeRunId ?? null`
  (`PreviewPanel.tsx:682`), prioritizing `viewingVersion?.id` first. FilesTab has no equivalent
  — it is the one tab whose content wiring bypasses the override PreviewPanel already built.
  (Steps/`AgentThinkingTab` and Audit tabs take `pipelineState`/`agents`/`hookRuns` — live
  pipeline-reducer state keyed on the tracked run, not a content prop at all — so they don't
  share this particular raw-vs-`eff*` gap; their behavior is fully explained by ISS-230 /
  ISS-294 instead.)

## Expected vs actual

- **Expected:** pinning an older version via the Version menu and opening the Files tab shows
  that version's deliverable (name/size/content), matching what the Preview tab already shows
  for the same pin.
- **Actual:** the Files tab always shows the live/latest (root-tracked) deliverable's size and
  content, regardless of any active version pin — reproducible purely by clicking through the
  UI, independent of the URL/routing mechanism ISS-230 and ISS-294 describe.

## Why this is a separate card, not a duplicate

Fixing ISS-230 and ISS-294 together (URL preserves the segment, and something resolves it to
the right run on arrival) would make `contentSourceRunId` itself point at the pinned run,
which would incidentally fix the raw `userStoryContent`/`pptContent`/`prototypeContent` props
too for that URL-driven path. But the Version-menu click path (this card) never touches
`contentSourceRunId` at all — it only sets `viewingVersion` — so FilesTab stays wrong for that
interaction even after ISS-230/ISS-294 are fixed. The two failure families are independent and
need independent verification.

## Fix direction (not applied — analysis/fix only)

Pass `effUserStoryContent`/`effPptContent`/`effPrototypeContent` (or equivalent version-aware
values) into `<FilesTab>` instead of the raw props, mirroring how `workspaceRunId` already
prioritizes `viewingVersion?.id` for the Workspace tab.

## Evidence

Derived from code reading only; no independent browser reproduction performed by this pass. To
confirm: pin an older version via the Version ▾ menu on a 2+-member run, open Files, and
compare the "Final output" byte size against the Preview tab's own content for that same pin.
