# FIX-763

## What was wrong

This fix is for bug report QA-KB-097. The root cause is the 2026-10-08 analysis on [ISS-1104](20261008-0016-ISS-1104.md) and
[ISS-1105](20261008-0016-ISS-1105.md). It was not re-derived here.

**This is a test-only change. No application code changed for these cards. Audit it as a test edited to fit the app.** The
cards show the expected behaviour was misstated. `3e09aef2c` (Phase Z, 2026-09-12) deliberately removed the "Planning Context"
paste from `_compose_context_message`. The replacement comment is at `engine.py:16578-16582`, and
`tests/agents/test_seam2_gate_v3.py:72` pins `## Planning Context` absent. Two tests still asserted the paste:

- `test_restart_resume_db.py::test_resume_dispatch_carries_rehydrated_planning_context` (red at `:5027`). It looked for
  `SPINNAKER-SENTINEL` in the first composed message. The report read that failure as "a resumed dispatch drops the
  clarification answers". They are not dropped. The resumed run writes them to `PLANNER.md` (`engine.py:5681-5734`, before the
  `generating` transition at `:5739`).
- `tests/unit/agents/test_agent_input_event.py::test_planning_context_injected_into_context_message` (red at `:143`).

## What changed, and why there

1. `test_resume_dispatch_carries_rehydrated_planning_context`. After the resume, it reads
   `RunSandbox(owner, run_id).root / "PLANNER.md"`, the helper `test_failed_run_resumes_skips_completed_tasks` already uses. It
   asserts three things there: `_REHYDRATE_ANSWER`, `_REHYDRATE_INTENT`, and the absence of the `user_message[:200]` stub intent.
   The `composed` spy stays only to prove a dispatch happened. The docstring now names PLANNER.md.
2. `test_rehydrate_planning_context_rebuilds_planner_and_answers`. The `_compose_context_message` call and its
   `if not _is_migrated:` block are dropped. The block asserted nothing for `domain-analyst`, a migrated agent, and would fail
   for any other agent. The `load_agent_spec` import that only it used goes with it. The rehydrator assertions are unchanged.
3. `test_agent_input_event.py`. The positive test is renamed `test_planning_context_not_pasted_into_context_message`, so its name
   no longer states the opposite of what it checks. It now asserts `"test brief"` present, and `"## Planning Context"` and
   `"Build a login feature"` absent. The timed-out neighbour `test_planning_context_not_injected_when_timed_out` is deleted, as
   the card suggests: it had been vacuous since the paste was removed for every input, and the full-context case now asserts
   absence. The module docstring line and the section comment that described the paste are corrected. Both are in this file
   only.

Not done, per the cards: putting the paste back into `_compose_context_message`. That breaks Phase Z, `test_seam2_gate_v3.py`
and the byte-pinned prompts (INV-3).
