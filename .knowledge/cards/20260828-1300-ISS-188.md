## Description

Validated from bug register entry **BUG-20260827-234030-create**. `HomeLaunchGrid`
(`frontend/src/components/catalog/HomeLaunchGrid.tsx`) caches the "Jump back in"
recent-runs list in `sessionStorage` under a single global key, `CACHE_KEY_RECENTS =
"vlc_home_recents_v1"` — no user id, account id, or token component in the key. React
state initializes directly from this cache on mount (`useState(() =>
readCache(CACHE_KEY_RECENTS))`), and the two effects that can overwrite the cached value
both gate on the freshly-fetched list being **non-empty**
(`recentRunsProp.length > 0` / `reduxRecentRuns.length > 0`). Neither has an "else"
branch to clear the cache when the live API genuinely returns zero runs, so a real empty
result is indistinguishable from "not fetched yet" and can never invalidate a previously
cached non-empty value from a different account.

## Reproduction (validated 2026-08-28, 3/3 cold starts, all cycles)

Each cycle from a cold start: cleared `localStorage`+`sessionStorage`, fresh navigation to
`/login`.

1. Sign in as `qa-admin@flowinqa.com`, navigate to `/create` — confirmed
   `sessionStorage['vlc_home_recents_v1']` is written with qa-admin's real run objects
   (titles, `tokenUsage`, `estimated_cost_usd`, etc.).
2. Clear only `localStorage.removeItem('auth_token')` (mirrors the app's own documented
   corrupt-token/expiry recovery path — `sessionStorage` is deliberately left untouched).
3. Sign in as `qa-basic@flowinqa.com` (zero real run history for this account).
4. Direct fetch to `GET http://localhost:8000/api/runs?limit=50` with the qa-basic
   session's own token returns `200` with an empty array (`count: 0`) — confirmed live,
   not assumed.
5. Navigate to `/create`. The "Jump back in" section still renders qa-admin's cached run
   ("zz-hunt test brief for dead link canvas run", `Compose a custom workflow`) to the
   qa-basic session, even though that session's own live API call just returned zero
   runs.

Reproduced identically on all 3 cycles (cold start each time, same steps) — deterministic,
not a race. No axis variation was needed; the defect fires every time step 2-5 is
performed.

## Expected

Cached recents must be scoped to the authenticated user (keyed by user id, or cleared on
sign-out / sign-in as a different account), and a live fetch that genuinely resolves to an
empty list must overwrite (clear) any stale cached entries rather than leaving the cached
value in place.

## Actual

`vlc_home_recents_v1` is a single unscoped `sessionStorage` key shared by whichever
account is signed in during a tab's lifetime; a zero-run account is shown another
account's cached run titles, workflow type, and (for completed runs) exact token-usage
and dollar-cost figures.

## Root cause pointer

`frontend/src/components/catalog/HomeLaunchGrid.tsx` — `CACHE_KEY_RECENTS` constant has
no per-user component; `readCache`/`writeCache` operate on a single global key; the two
`recentRuns`-refresh effects both require `.length > 0` to write, so they can never clear
a stale non-empty cache with a genuine empty result. `FIX-100` (linked above) is the
originating card that introduced this stale-while-revalidate sessionStorage cache
mechanism for instant first-render; it did not scope the key per user, which is the root
cause validated here.
