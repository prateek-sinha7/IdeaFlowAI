## What is broken
[FIX-788](20261103-1705-FIX-788.md) made `GET /api/workflows/{id}` return the file manifest's `context_providers`, and
`builtinAuthoringSeed` in `frontend/src/store/api/userWorkflows.ts` maps that list onto the Composer's single
`contextProvider: "opendesign"` lever. `context_providers` is in `MODELED_MANIFEST_KEYS`, so the passthrough skips it and
the saved copy is rebuilt from that lever alone. A built-in that lists another provider, for example `chain_context` on
`prototype`, loses it in the copy. `ISS-876` listed `context_providers` as an extra loss beyond `limits` and
`input_providers`; this is the part that remains.
## Why it was left
The frontend step (`.agents/tasks/workflow-gaps/frontend-record.md`) judged that carrying the other providers could make
Save fail for tiers whose manifests compile as untrusted, because some providers are not `user_allowed`. Whether a copy
should inherit them, and for which tiers, is a product decision. Claim status: read from the code, not reproduced by saving
a copy and re-running it.
