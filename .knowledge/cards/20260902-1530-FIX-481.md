## What was wrong

`DashboardLayout.tsx` `handleBackNav` (the shared Back handler passed to
`WorkflowHistory`, `AccountSettings`, `AnalyticsPage`, `IdeaInputPage`, and
`ComposerPage`) contained:

```tsx
if (
  hasUnsavedWork.current &&
  typeof window !== "undefined" &&
  !window.confirm("You have unsaved changes. Leave anyway? Your work will be lost.")
) {
  return;
}
```

`window.confirm` is a native browser blocking dialog. The product standard
(S-19-17 source assertion) bans native `confirm`/`prompt` calls outside of
file-download failure affordances. This regression was introduced by a prior
fixer agent while closing ISS-275.

## What changed and why there

Replaced the `window.confirm` guard with an inline React confirmation dialog:

1. **State** — added `const [confirmingBackNav, setConfirmingBackNav] = useState(false)` near `hasUnsavedWork`.

2. **`handleBackNav`** — when `hasUnsavedWork.current` is true, sets
   `confirmingBackNav(true)` and returns early instead of calling
   `window.confirm`. When no unsaved work, navigates immediately (unchanged path).

3. **`commitBackNav`** — new `useCallback` that clears the dialog state and
   executes the original navigation logic (reset questionnaire/pipeline, then
   `router.back()` or `router.push(routes.home())`).

4. **`cancelBackNav`** — new `useCallback` that simply sets
   `confirmingBackNav(false)`, leaving the user where they are.

5. **Dialog JSX** — rendered conditionally at the bottom of the component's
   return (above the closing `</div>`) as a fixed-position backdrop overlay
   with a modal card containing "Stay" and "Leave anyway" buttons. Uses
   `role="dialog"`, `aria-modal="true"`, `aria-labelledby` for accessibility.
   Click-outside (`onClick={cancelBackNav}` on backdrop, `e.stopPropagation()`
   on card) closes the dialog without navigating.

The navigation logic inside `commitBackNav` is identical to the original
post-confirm body — no behavioral change for the proceed path.

## Scope note

`AccountSettings.tsx` has two separate `window.confirm` calls (lines 237 and
592) that were introduced by FIX-386 and FIX-385 respectively, and are
deliberately kept for the native-dialog e2e test paths those fixes target. This
fix is scoped to `DashboardLayout.tsx` only (the ISS-622 registration site).
