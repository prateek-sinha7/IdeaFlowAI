## What was wrong

Bug report QA-KB-029. The fix covers two cards that share one root cause. Neither card's analysis was re-derived here.

- [ISS-077](20260812-0212-ISS-077.md), the root card. The frontend `ArtifactNode` was written against the wrong shape and has never matched the wire. Before this change, `frontend/src/lib/api.ts:1502,1508,1509` declared `task_id: string`, `derived_from: string[]` and `children: string[]`, and declared no `retention`. The backend's `_build_lineage_tree._node` (`backend/app/api/runs.py:1377-1395`) sends:
  - a nullable `task_id`;
  - a nullable single-id `derived_from`;
  - `children` filled with nested node dicts (`:1448-1452`);
  - a non-null `retention`.

  A second hand-kept copy at `frontend/src/store/api/runs.ts:40-59` had the same errors. The docstring cited `runs.py:590-608`, which had drifted.
- [ISS-869](20261001-2106-ISS-869.md), the sibling. The wrong `children: string[]` hid the nesting from the only live consumer of the tree. `ArtifactVersionPicker.tsx` looped over the top level only: `collapseVersions` at `:70` (fed `resp?.artifacts` at `:124`) and `select()`'s `rows.find` at `:162`. A version written with `derived_from` was never counted. Gate Redo writes one at `engine.py:10730`; gate Edit writes one at `engine.py:9337` and other sites. With only one version left, the picker rendered nothing (`:177`). In a chain of three, the middle version could not be opened either.

## What changed, and why there

1. `frontend/src/lib/api.ts:1494-1515`:
   - `task_id` is now `string | null`.
   - `derived_from` is now `string | null`.
   - `children` is now `ArtifactNode[]`.
   - `retention: string` was added as required, because every node has it.
   - `derived_from` gets one line of JSDoc: it may name a PARENT run's artifact, which is then absent from the response.
   - `children` gets one line of JSDoc: nested nodes, not ids.
   - The stale `runs.py:590-608` cite now names the function, which does not drift.
   - The backend is unchanged. Its shape is the pinned contract (`backend/tests/integration/api/test_runs_api_artifacts_api.py:176-193`).
2. `frontend/src/store/api/runs.ts`: the duplicate `ArtifactNode` and `RunArtifactsResponse` are deleted. `:42` re-exports them (`export type { ... } from "@/lib/api"`), and `:2` imports the response type for `runsApi.artifacts`. This follows the precedent at `store/api/admin.ts:2`. One declaration means the drift cannot happen again (ISS-077 amendment 2).
3. `frontend/src/components/results/ArtifactVersionPicker.tsx`: a module-local, pre-order `flattenArtifacts` (`:50-54`) is used at both read sites.
   - Inside `collapseVersions` (`:76`), so the exported function is correct for any caller that passes the raw tree.
   - Where `select()` fills its per-kind content cache (`:165`), so the `find` at `:168` reaches nested versions.

   Pre-order keeps a parent ahead of the versions derived from it. Nodes carry no `created_at`, so nothing is re-sorted (ISS-869 caveats 1 and 2). The stale `runs.py:907-925` cite at `:272` now names the function.
4. Two test files changed. ISS-077's fix text prescribes both edits. No assertion changed.
   - `frontend/src/lib/api.getRunArtifacts.test.ts:40,43`: the fixture's `derived_from: []` became `null`, and the fixture gained `retention` (amendment 4). Its `toEqual(wire)` compares the mock's own payload, so it is green both before and after.
   - `frontend/src/components/results/ArtifactVersionPicker.test.tsx:29`: a comment only, the stale `runs.py:907-925` cite (amendment 3).

**One deliberate deviation from ISS-869's suggested placement.** The card suggested exporting `flattenArtifacts` from `lib/api.ts` "so a later tree consumer routes through it". It stays local to the picker instead.

- Every test that mounts the picker mocks `@/lib/api` with a factory that exports only `getRunArtifacts` and `getToken`: `ArtifactVersionPicker.test.tsx:24-27`, `.iss869.test.tsx:11-14`, `.iss802.test.tsx:18-21` and `AgentDetailPanel.artifactVersions.test.tsx:16-19`.
- vitest throws when code reads any other export of such a mock, as observed with `getCapabilities` in [ISS-895](20261001-2126-ISS-895.md). An imported helper would make the picker render nothing under test.
- Taking the suggested placement would therefore have meant editing four test mocks to fit the code.

The mechanism is the card's own: a pre-order `flatMap` on the consumer side, not inside `getRunArtifacts`, which is where the `MOD-frontend-src-lib` card wants it. Move the helper to `lib/api.ts` if a second tree consumer appears. The only other reader today, `WorkflowHistory.tsx:441` via `parseClarificationArtifacts`, reads `clarifications` rows. Those never carry `derived_from`, and the card leaves that reader alone.
