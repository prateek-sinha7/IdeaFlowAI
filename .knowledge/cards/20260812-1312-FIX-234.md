## Description

The local backend could not be stopped by SIGTERM while any run was streaming, so the entire graceful-shutdown half never ran on a developer machine — and even when reached it did not stop the run. Measured on a throwaway server: no flag → alive past 31.25s with only startup_complete recorded, kill -9 the only way out; with --timeout-graceful-shutdown 5 → clean exit in 5.82s with the shutdown body running to completion. Added the flag to the ten dev-facing documented commands (and both out-of-repo memory notes), dropped --reload (untreated it leaves two stuck processes and watchfiles is absent so it polls), kept port 8000 with evidence, deleted the double close_checkpointer(), corrected the under-counting teardown budget, and made SHUTDOWN_STOP_RUNS environment-differentiated (ON in ENV=development, OFF everywhere else). Does NOT close the money hole: a production run still resumes and finishes after a restart — that is ISS-089.

## Root cause

uvicorn's timeout_graceful_shutdown defaults to None (uvicorn/config.py:215) and H11Protocol.shutdown() does NOT close a connection whose response is still streaming — it only clears keep-alive (h11_impl.py:328-337). A live EventSourceResponse therefore never leaves server_state.connections, _wait_tasks_to_complete() spins forever (server.py:294-310) and await self.lifespan.shutdown() is never reached. Production had the flag since KAN-151 D8; no in-repo doc did. Second cause: main.py:302-307 closed the checkpointer pool BEFORE shutdown_run_infrastructure(), whose step 4 closed it again where the docstring promises it runs LAST — idempotent, so silent, but the ordering guarantee was false and it blocked stop-runs. Third: the "under 25s" budget comment omitted both cancel-and-wait escalations and the pump drain. Settled the blocking open question and REVERSED the prior hypothesis — asyncio.run's teardown does NOT already mark runs cancelled under SIGTERM, because capture_signals() restores the default disposition and re-raises the captured signal inside serve() (server.py:326-330), killing the process before Runner.close() → _cancel_all_tasks. Under SIGINT it DOES (KeyboardInterrupt unwinds normally), which is ISS-103.
