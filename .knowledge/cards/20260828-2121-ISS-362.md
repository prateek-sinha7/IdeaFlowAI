## What happened (inferred, not yet reproduced)

[ISS-247](20260828-1637-ISS-247.md) reproduced and root-caused one direction of this desync:
checking an agent in the "Review gates" checklist does not update that agent's `Gate`
combobox in the Advanced modal. The underlying mechanism — two disjoint state
representations with zero synchronization code — is direction-agnostic, so the reverse
action should fail the same way:

- `CanvasConfigRail.tsx:254-276` (`selectGate`, called from the `Gate` `<select>`'s
  `onChange` at `:680`) ends by calling `patch({ gates: [...] })`.
- `CanvasConfigRail.tsx:354-357` — `patch` is `applyLeverPatch(sel, p)` followed by
  `onSelection(agent.id, next)` — `onSelection` is a prop into the `selections` map
  (`AgentsPopup.tsx`'s `liveSelections`/`AgentCapabilitiesModal` state, per ISS-247's own
  trace). Neither `selectGate` nor `patch` references `gateSelectionRef`,
  `handleGatesChange`, or any setter `ReviewGatesSection.tsx` owns (`checkedIds`, `touched`)
  — there is no import, prop, or callback connecting the two.
- `ReviewGatesSection.tsx` has no effect or prop that reads `selections`/`agent.gates` after
  mount — its checked state is seeded once from `initialGateIds` or `isDefaultGated`
  (`ReviewGatesSection.tsx:41,53-57`) and thereafter only changes via its own `toggle`
  (`:88-96`), which never fires from a `CanvasConfigRail` edit.

## Why the root cause implies this

ISS-247 already isolated the missing piece as "no synchronization between them" in either
direction — the card's own root-cause section describes both sides (`ReviewGatesSection`
writing `gateAgentIds`, `CanvasConfigRail` reading/writing `agent.gates`) without citing any
code that reconciles one from the other. Having now read `patch`/`selectGate`'s full body
(`CanvasConfigRail.tsx:254-276,354-357`) confirms the write side of that absence directly:
setting the combobox has exactly one effect (`onSelection` into the selections map), and nothing
downstream of it reaches `ReviewGatesSection`'s state.

## Expected vs actual (predicted)

Expected: opening the Advanced modal, selecting an agent's Config tab, and setting `Gate` to
"Human gate" should update that same agent's checkbox in the Review-gates checklist to
checked (both controls agreeing, as ISS-247 argues they should).

Actual (predicted, unverified): the Review-gates checklist stays exactly as it was before the
Advanced-modal edit — unchecked for that agent, or checked/unchecked independent of whatever
was just set in Config — because no code path connects `CanvasConfigRail`'s `patch` to
`ReviewGatesSection`'s `checkedIds`.

## What would confirm or refute this

From a fresh `/create/app` (or `/create/ppt`/`/create/prototype`, see
[ISS-361](20260828-2120-ISS-361.md)) load: open Advanced, select an agent with no gate, set
its `Gate` combobox to "Human gate", close the modal, and open the Review-gates checklist —
check whether that agent is now ticked. Ticked would refute this card; unchecked (or
unchanged) confirms it.
