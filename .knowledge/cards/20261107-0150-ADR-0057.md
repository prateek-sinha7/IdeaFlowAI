## Decision
Users build workflows by chatting with a dedicated deep agent on `/workflows/new` and `/workflows/{id}/edit`. The agent
follows the `velocity-workflow-creator` skill (in `backend/app/agents/workflow_builder/skills/`, its only copy, amended below),
reads it through a read-only `/skills/` route, runs allow-listed scripts through `run_skill_script`, and submits a
manifest with `propose_draft`. Source of truth for the design: `.kiro/specs/ai-workflow-builder/design.md` and
`specs/023-ai-workflow-builder/requirements.md`.

## Why this shape
- Outside the kernel keeps SC-001 intact: the engine stays workflow-agnostic and the builder only produces manifests.
- Reusing `_validated_manifest` (`gate.py`, via `GatePort`) means a draft the builder accepts is one Save accepts. The
  gate also applies `builder_rules.check` and `_model_entitlement_error` before the compiler, then picks the least
  trust that works (db trust only when the tier allows it).
- Stateless turns: history is replayed as prior messages (design D-01, because deepagents evicts a single
  HumanMessage over 200,000 characters), so no checkpointer is needed.
- Model flags (`Reasoning.display`, builder fields) are added to the existing `ModelEntry` rows, so INV-12 (one model
  list) still holds.

## Amendment (2026-11-10)

The skill is no longer copied from `.kiro/skills/`. Its only copy is `backend/app/agents/workflow_builder/skills/velocity-workflow-creator/`, edited in place and shipped with `app/`. This amends the Decision above and the "Shipped in" commits, which describe the earlier copy.

- No `SKILLS.lock.json`, no sync command and no copy comparison in CI. The skill hash and line counts are computed from the files on disk (`skill_package.read_skill_facts`).
- The path is fixed in code. `BUILDER_SKILLS_ROOT` and `BUILDER_SKILL_IDS` were removed. The skill id is `BUILDER_SKILL_ID` in `script_policy.py`.
- A missing mandatory skill file makes only the builder unavailable (503 `builder_unavailable`). The rest of the app keeps serving.
- CI runs the skill's `selftest.py` (plain and with `--compiler .`), the `--step-models` check and the per-pattern fixtures check. The catalog rebuild comparison (`--drift`) and the pin warning (`--deps`) were removed.
- The decisions about the kernel, the read-only `/skills/` route, the reuse of the Save validator and migration 0051 are unchanged.

The spec in `.kiro/specs/ai-workflow-builder/` (requirements 32 and 33, design §3.8 and decisions 19 and 20, tasks 1 and 2) records the same change.
