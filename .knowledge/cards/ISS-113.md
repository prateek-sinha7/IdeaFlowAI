# ISS-113

## Title

runMeta is dormant on AuditTab, so the audit header's owner and workspace are permanently null. Declared AuditTab.tsx:59, destructured :443, consumed :649-655 — runMeta?.startedAt ?? first, runMeta?.durationMs ?? derived, runMeta?.owner ?? null, runMeta?.workspace ?? null. Neither mount passes it: PreviewPanel.tsx:1172-1176 sends hookRuns / workflowRunId / isRunning, and WorkflowHistory.tsx:796 sends workflowRunId only. grep -rn "runMeta=" src returns nothing at all — not even a test. So owner and workspace are always null and the timings always fall back to values derived from the rows. Unlike ISS-083 this is a genuine data gap rather than a duplicate: nothing else supplies owner/workspace to that header, so the honest fix is to wire it, not delete it. A second, opposite defect on the same component, found in the same read: hookRuns is declared at AuditTab.tsx:51 and passed by PreviewPanel.tsx:1173, but it is not destructured at :443 — so it is supplied and silently ignored. That is the mirror image of the dormant-prop shape and worth fixing in the same pass. (Note the neighbouring ISS-110 / FIX-235 finding that hook_run's payload never reaches the reducer at all — settle that first, or a wired hookRuns will carry defaults.)
