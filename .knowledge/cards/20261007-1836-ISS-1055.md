# ISS-1055

## What happened

While verifying [FIX-726](20261007-1833-FIX-726.md) (register bug QA-KB-063), S-18-08 was run
three times, one test at a time, against the same data on `:3000`/`:8000`:

| run (`tests/integration/test-runs/`) | outcome | run selected |
|---|---|---|
| `2026-10-07T18-26-qa-kb-063-fix-before-s18-08` | failed (the stale literal, fixed by FIX-726) | `b40eabd0-d7e2-4bc2-bc42-99ef6a147bff` |
| `2026-10-07T18-29-qa-kb-063-fix-after-s18-08` | **skipped**, 68.70s: "no completed run shows a duplicated clarification exchange" | none |
| `2026-10-07T18-30-qa-kb-063-fix-after-s18-08-rerun` | passed, 46.50s | `b40eabd0-d7e2-4bc2-bc42-99ef6a147bff` |

Output: `evidence/qa-kb-063/fix-05-s18-08-after.txt` (the skip) and `fix-06-s18-08-after-rerun.txt`
(the pass). The skip message comes from `a_run_with`, `test_chat_lane.py:96-107`, after none of
the first eight completed rows satisfied `get_by_text(CLARIFY_ASK).count() > 1`.

## Suspected mechanism (INFERRED, not instrumented)

`_open_row` calls `settle_transcript` (`test_chat_lane.py:55-80`). It returns as soon as
`[data-testid="chat-message"]` has held a non-zero count for `quiet_ms=1200`. The lane seeds from
the whole revision family, one `/events` fetch per member, as that function's docstring says. The
selected run `b40eabd0` is a revision with no clarify messages of its own. Its four clarify pairs
come from the family root `78e185fb-c032-4154-8552-774781b6e5df`, whose events number 107,409
(read-only API, `evidence/qa-kb-063/fix-07-family-clarify-texts.txt`). If the root's fetch takes
longer than 1.2s after the revision's own messages render, the count looks settled without the
asks, the predicate is false, and the loop moves on.

Every `a_run_with` caller that reads family-seeded text is exposed: S-18-07, S-18-08, S-18-10,
S-18-11, S-18-17 and S-18-18.

## Disposition

Open, test-infra only; no product defect is claimed. Settle it by logging the message count and
the `/events` responses for each row inside `a_run_with`. A skip whose count stopped before the
root's response arrived confirms this mechanism. A fix would wait on the family's fetches, for
example the responses themselves, rather than on a quiet period. Until then, re-run a skip of
S-18-08 with this message once before treating it as a regression.
