# ISS-754

## Register entry

Sibling of [ISS-753](20260922-1413-ISS-753.md) (root card, full mechanism there), filed from the
same investigation. No separate QA-PS row names this specific manifestation.

## Root cause — CONFIRMED (identical mechanism, different consumer)

- `FilesTab` receives `runInput={runInput}` at `PreviewPanel.tsx:1745` — the exact same raw,
  non-version-derived prop [ISS-753](20260922-1413-ISS-753.md) identifies (not
  `viewingVersion?.runInput ?? runInput`).
- `runInputFileRows(runInput, clarifications)` (`FilesTab.tsx:92-94`, invoked at `FilesTab.tsx:866`:
  `const runInputRows = runInputFileRows(runInput, clarifications);`) parses this prop via
  `parseRunInput` (`FilesTab.tsx:12`) and builds the synthetic "prompt.md" (and, when clarify
  rounds exist, "clarifications.md") file card shown in the Files tab's file list
  (`FilesTab.tsx:1049-1053`, rendered at `:1155`/`:1223`).
- Same root cause as [ISS-753](20260922-1413-ISS-753.md): `VersionView`/`versionViewFrom`
  (`PreviewPanel.tsx:536-575`) never captures the selected member's own `run.input`, so there is
  no version-aware value available to thread into `FilesTab` either — this is the second, and
  only other, production JSX site inside `PreviewPanel.tsx` that consumes the raw `runInput` prop
  (confirmed by grepping `runInput=` across the file: `:1745` and `:1783` are the only two).

## Confidence

CONFIRMED at the code level — identical prop, identical missing derivation, same source file,
same line-1745/1783 pattern. **Not independently screenshot-verified** in the Files tab
specifically this pass — the two sweeps supplied by the dispatch focused on the Steps "Starting
point" text and the Preview heading, not the Files tab. The user-visible manifestation (Files tab
showing the WRONG version's prompt.md/clarifications.md card while a different version is
selected) is INFERRED from the shared mechanism, not separately observed. What would settle it:
open the Files tab on a non-latest family member and compare the prompt.md card's text against
that member's own submitted input/revision instruction.

## Fix direction (not applied — issue only)

Same single shared place as [ISS-753](20260922-1413-ISS-753.md): once `VersionView` carries a
`runInput` field (populated in `versionViewFrom`), thread
`viewingVersion?.runInput ?? runInput` at `PreviewPanel.tsx:1745` as well as `:1783` — one fix in
`versionViewFrom` closes both call sites; no separate fix is needed here beyond wiring the same
derived value into this second consumer.

## Blast radius

`FilesTab`'s prompt.md/clarifications.md synthetic rows only. No further blast radius beyond what
[ISS-753](20260922-1413-ISS-753.md) already documents for the shared `runInput` prop (the same
grep found no third consumer).
