# FIX-602

## Title

**QA-PS-032** — selecting any version in the Workspace tab showed every file as
`0 B`, while "Latest (live)" showed real sizes. Fixed at the one place the ref-scoped
listing gets its data, which also closes the ref-scoped zip's missing size cap.

## What was wrong

`list_sandbox` (`backend/app/api/run_files.py:889-968`) has two branches. The live branch
spreads `sandbox.list_files()` entries, which carry a real `size` from `full.stat()`
(`sandbox.py:793,796`). The ref branch built its payload from
`sandbox.list_files_at_ref(ref)` — a `list[str]` produced by
`git ls-tree -r <ref> --name-only` (`local.py:1090`) — and wrote **`"size": 0`** as a
literal at `run_files.py:930`. `--name-only` drops mode/type/sha/size, so no blob size was
ever fetched for this branch; the `0` was a placeholder for data nobody plumbed, not an
arithmetic error. Root cause per [ISS-720](20260922-1232-ISS-720.md).

The same missing data had a second, non-display consequence
([ISS-704](20260922-1234-ISS-704.md)): `download_sandbox_zip`'s ref branch `return`ed at
`run_files.py:1036`, before the live path's `total = sum(...)` /
`_SANDBOX_MAX_ZIP_BYTES` check at 1045-1047. That check was structurally unreachable for
every ref-scoped request, so a workspace of any size was archived and served — the cap
FIX-316 locked in applied to one branch only.

## What changed, and why there

1. **`backend/app/agents/runtime/local.py`** — new `LocalWorkspace.file_sizes_at_ref(ref)`
   returning `{relpath: size}`, read with **one** `git ls-tree -r -l <ref>` for the whole
   tree (the long format appends the object-size column that `--name-only` drops). A
   per-file `git cat-file -s` loop would also be correct but puts N subprocesses on a hot
   endpoint. It runs through the same `env=self._git_env()` as every other git call here,
   so `GIT_CEILING_DIRECTORIES` still confines it to its own sandbox — the containment
   [FIX-522](20260917-1449-FIX-522.md) closed. Non-blob entries (submodules, mode `160000`)
   print `-` in the size column and are omitted rather than coerced; keys are formatted
   exactly as `list_files_at_ref` returns them, so the two line up key-for-key even for
   git-quoted non-ASCII names.

   **Sibling call, not a widened one.** `list_files_at_ref`'s `list[str]` return is pinned
   by `run_commands.py:4546` and five test files (ISS-720's "Fix risk" section); changing
   it would have broken all of them for a field only `run_files.py` wants.

2. **`backend/app/agents/sandbox.py`** — `RunSandbox.file_sizes_at_ref` delegates to the
   workspace by `getattr` duck-typing and returns `{}` on absence or error, mirroring
   `list_files_at_ref`'s best-effort shape exactly.

3. **`backend/app/api/run_files.py`** — the ref branch of `list_sandbox` looks each path up
   in that map (`int(sizes.get(p, 0))`), and the ref branch of `download_sandbox_zip` sums
   it against `_SANDBOX_MAX_ZIP_BYTES` and raises the same 413, with the same message, as
   the live branch. The cap is checked **before** `archive_at_ref` runs: the point of the
   ceiling is not assembling a runaway workspace in memory, not discarding it afterwards.

**The no-ref path is untouched.** Across all three files the diff deletes exactly one line
— `"size": 0,` inside the ref branch — and adds nothing outside a `if ref is not None:`
block or a new method. No imports were added anywhere.

[ISS-703](20260922-1233-ISS-703.md) (the open-file viewer header, `SandboxTab.tsx:1404`)
needed no code of its own: it renders `active.size` off the same payload, so it is cured by
change 3. No frontend file was touched.

### Evidence from the real family (read-only, no writes, no run)

`runs/c6b9b61f-183d-4662-ae84-d7fd5a052571/4d55165d-59b5-4571-b5ac-1ce7aebc3cbf/`, whose
`presentation.html` genuinely differs between tags:

```
v1: 8 paths, 8 sizes, keys match=True   presentation.html -> 27549
v6: 8 paths, 8 sizes, keys match=True   presentation.html -> 13963
```

Both match `git show v1:presentation.html | wc -c` / `v6` exactly — two different numbers,
so the fix is reading each tree rather than reporting one size twice.
