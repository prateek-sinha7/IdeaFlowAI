# ISS-112

## Title

**`attachmentRefs` is dormant on `StartingPointCard`, so the "image not retained" placeholder can NEVER render.** Declared `StartingPointCard.tsx:44`, destructured `:47`, consumed `:55-57` as `(attachmentRefs ?? []).filter(...)` → `notRetainedImageCount`. The **sole production mount**, `AgentThinkingTab.tsx:222-226`, passes only `input`, `originalBriefRootRunId` and `revisionParentVersion` — verified by reading the mount, and `grep -rn "attachmentRefs=" src` returns **only** `StartingPointCard.test.tsx` (4 sites, all feeding the prop to itself — the same self-feeding blind spot that hid ISS-083). `notRetainedImageCount` is therefore always **0**, so the placeholder at `:246-250` ("Image not retained" / "N images not retained") is dead, **and** — the part that makes this more than cosmetic — it also gates `hasContent` at `:59-64`, whose false value early-returns `null` at `:78`. This is the honest signal that an attached image was dropped, which connects directly to the known image-input gap; a user whose image was silently dropped is told nothing. **Fix shape:** thread the refs from wherever the run's attachment metadata already lives to `AgentThinkingTab`'s mount — but **first confirm the data exists on the FE at all**, since a prop with no available source is the ISS-083 shape and would want deletion instead. Whichever way it goes, the closing test must start from a frame or a fixture and end at the pixel — feeding `attachmentRefs` directly proves nothing.
