## ISS-423 — Text attachment truncation note

`LaunchWizard.tsx:onFilesPicked` `isTextFile` branch stored
`content.slice(0, ATTACH_MAX_CHARS)` with no indication — the same unflagged truncation
ISS-312 documented for IdeaInputPage, and the same file FIX-374 explicitly deferred because
`LaunchWizard.tsx` is a forked copy, not a caller of `useBriefAttachments`. Fixed by:

1. `import { ATTACH_MAX_CHARS, truncateAttachmentText } from "@/lib/constants"` (the
   `truncateAttachmentText` helper FIX-374 placed there).
2. `content.slice(0, ATTACH_MAX_CHARS)` → `truncateAttachmentText(content)` on the isTextFile
   branch. One guard, two call sites, cannot drift again.

## ISS-384 — savedName in header

`savedName` state was restored from the session draft at `LaunchWizard.tsx:311` but only ever
passed to the closed AgentsPopup modal (`:1168-1169`). The page header always rendered
`cfg.eyebrow / cfg.title`, so a saved workflow's panel was visually identical to a new one.

Fixed by substituting `savedName` for the `cfg.title`/`cfg.chainingTitle` in the `<h1>`:

```tsx
{savedName ?? (isChaining ? cfg.chainingTitle : cfg.title)}
```

`cfg.eyebrow` stays unchanged — the pipeline type label is always shown. `savedName` is
`undefined` on a plain new-workflow open, so fresh opens are byte-identical to before.

## ISS-429 (Mechanism A) — Manifest-declared gate seed

FIX-377 fixed the ReviewGatesSection seed for IdeaInputPage via the `selections` prop.
`LaunchWizard.tsx` was explicitly called out in FIX-377 as "NOT fixed: LaunchWizard.tsx:248
initialises liveSelections to {} and only ever calls handleSelectionsChange from
override/draft branches."

On a plain `/create/ppt` or `/create/prototype` load (no override), `agentsFromManifest`
now extracts its `selections` result and seeds `liveSelections` (display state only):

```tsx
const planProj = agentsFromManifest(detail, pipeline);
setPlanAgents(planProj.agents);
if (!detail.has_override || !detail.is_overridden) {
  if (planProj.selections && Object.keys(planProj.selections).length > 0) {
    setLiveSelections(planProj.selections);
  }
}
```

`selectionsRef` is NOT touched — the INV-3 contract (untouched run omits `selections` from
the launch payload) is preserved exactly. The override branch below already calls
`handleSelectionsChange` (which writes both), so the guard stops the manifest seed from
overwriting a real override.
