# FIX-739

Bug report QA-KB-082. The root cause and blast radius come from [ISS-915](20261001-2219-ISS-915.md) and
[ISS-1020](20261002-0632-ISS-1020.md). They are not re-derived here, except for one field the ISS-1020 crash table did not
list (`ext`, below). Frontend only: no backend, engine, migration or import-linter surface is touched.

(This card was first written as FIX-738 at 19:58. A concurrent fixer for QA-KB-083 took the same id and filename in the same
minute, so this fix was re-issued as FIX-739. The QA-KB-083 card owns FIX-738.)

## What was wrong

`frontend/src/app/preview-fullscreen/page.tsx:70` read the payload with `JSON.parse(raw) as PreviewPayload`. That is a
compile-time assertion, and `:71` `if (!data.files?.length)` was the only runtime check. Anything with a truthy `.length`
passed (`{files:"abc"}`, `[null]`, `[{}]`, `{length:1}`, `[1]`). Then `setPayload(data)` mounted
`<AppBuilderPreview files={payload.files}>`, and `buildTree` threw during render (`AppBuilderPreview.tsx:93`
`a.path.localeCompare`, `:96` `file.path.split`). That throw is outside the page's `try/catch`, so `giveUp()` never ran
and `frontend/src/app/error.tsx` replaced the page (ISS-915). Payloads whose files had a string `path` got past
`buildTree` and crashed later (ISS-1020):

- a file without a string `content` crashed at the CodeViewer `file.content.split("\n")` (`:295`);
- an object `projectName` crashed as a JSX child (`:502`);
- a file without `name` crashed in `fileMatchesQuery` (`:119`, via `:371`) once a search was typed.

## What changed, and why there

All the changes are in the one guard the cards name (`page.tsx:70-95`). That is the only place where untrusted storage data
reaches `AppBuilderPreview`. Its other render sites (`PreviewPanel.tsx:170`, `WorkflowHistory.tsx:1058`/`:1097`) pass typed
arrays from `parseAppBuilderFilesForIDE` / `parseFilesForIDE`, so the component itself is unchanged. `giveUp()` is still the
single exit.

- `:73-84`: the payload is parsed without a cast. `files` must be an array (`Array.isArray`) and non-empty, and every element
  must have a string `path` and a string `content`, with `ext` either a string or falsy. Anything else calls `giveUp()`.
  A `null` payload now reaches `giveUp()` through `data?.files` instead of through the `catch`.
- `:85`, `:91`: `projectName` is kept only when it is a string. Otherwise it is `undefined`, so the component default
  `"Project"` (`AppBuilderPreview.tsx:358`) and the `"Project — IDE Preview"` title apply. `PreviewPayload.projectName`
  became optional (`:11`) to allow that.
- `:88`: a file without a string `name` gets the last `path` segment as its name. ISS-1020 offered two options: require
  `name` and change the ISS-298 fixture, or derive it. Deriving it keeps
  `tests/integration/e2e/suites/07_run_detail/test_iss298_preview_fullscreen_quota_ignores_cache.py:25-30`
  (`{path, content}` only) unchanged and accepted, and it also closes the search-box crash.

### One field beyond the ISS-1020 crash table: `ext`

To check the predicate was complete, every file field `AppBuilderPreview` dereferences was read. `ext` reaches
`getFileIcon(node.file?.ext || "")` (`:243`, `:607`), whose body is `map[ext.toLowerCase()]` (`:69`), and
`{file.ext || "txt"}` (`:304`) is rendered as a JSX child. So a truthy non-string `ext` (`5`, `{}`) throws at render. ISS-1020's
stated Expected ("any payload the component cannot render and use without throwing takes the same giveUp() exit") covers
it, so the predicate also requires `ext` to be a string or falsy. An absent `ext`, as in the ISS-298 fixture, still passes.
`language` needs no check: its only use is `highlightCode` (`:164-172`), which wraps the `hljs` calls in `try/catch`.

## Notes for the verifier

- `restartNeeded` is false. This is a `.tsx` change, and the Next dev server hot-reloads it.
- Browser re-run: seed `sessionStorage.__app_preview__` with `{files:'abc',projectName:'x'}`, `{files:[null]}` and
  `{files:[{}]}`, then open `/preview-fullscreen`. Each should land on `/runs`, not on "Something went wrong".
- Harness trap in `page.previewPayloadShape.test.tsx`: its `useRouter: () => ({ push: vi.fn(), replace })` mock returns a new
  router object on every render, and the page effect depends on `[router]`. So any re-render re-runs the effect, and the
  page cycles back to "Loading preview...". The five `giveUp()` rows are unaffected, because nothing re-renders after
  `giveUp()`. A render assertion added to that file needs a stable router (`vi.hoisted`, as the fix-03 matrix does), or it
  never sees the rendered preview.
