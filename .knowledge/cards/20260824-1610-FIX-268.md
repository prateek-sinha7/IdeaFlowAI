## Related

**Referenced by:** [ISS-170](20260824-1610-ISS-170.md)

<!-- /RELATED -->

Two stacked bugs, both surfaced while getting spec-014's `ex_A*` conditional-gate fixtures
launchable from the catalog UI (any pipeline type outside the hardcoded `app_builder`/
`user_stories` cases).

## Bug 1 — click did nothing

`DashboardLayout.tsx`'s `createRouteForType(type)` fell back to bare `routes.create()`
("/create") for every type except `app_builder`/`user_stories`. That URL parses to
`{screen:"create"}` -> `mainView:"home"` via `page.tsx`'s `initialMainViewFor`. The T9
URL-sync effect (`if (initialMainView && initialMainView !== mainView) setMainView(initialMainView)`)
then used that truthy `"home"` to stomp the optimistic `setMainView("input")` the click
handler had just set, one render earlier — silently bouncing the click back to the
dashboard with no error.

**Fix:** route to a per-type path instead — `` `/create/${encodeURIComponent(type)}` ``
(`DashboardLayout.tsx`, `createRouteForType`).

## Bug 2 — the per-type URL then 404'd (downstream of the fix above)

`parseViewPath` (`frontend/src/lib/routes.ts`) had no case for an unrecognized
`/create/{type}` segment — it fell through to `{screen:"unknown"}`, which `page.tsx`
(`if (parsedView.screen === "unknown") notFound();`) turns into a client-side 404. That
falsy `"unknown" -> undefined` mapping is exactly what let Bug 1's fix work for an in-app
click (the URL-sync guard skips a falsy `initialMainView`), but a **cold load** of the
same URL (typed, refreshed, shared) has no in-memory `mainView` to fall back on and hit
the 404 directly.

**Fix (landed concurrently, in the same working tree, by a parallel session — confirmed
correct and re-verified live this session):** `parseViewPath` now returns
`{screen:"create-workflow", pipelineType}` instead of falling through to `"unknown"`;
`initialMainViewFor` maps `"create-workflow"` straight to `"input"`. Strictly better than
Bug 1's patch alone: it also survives a cold load, which the optimistic-state trick never
covered.

## Related bug — `IdeaInputPage.tsx` crash on the same class of type

`config: PageCopy` did `TYPE_CONFIG[effectiveType]` with no fallback, throwing
`TypeError: Cannot read properties of undefined (reading 'tag')` for any type outside the
hardcoded map — i.e. every fixture Bug 1/2 exist to unblock. Fixed (parallel session) by a
new `useWorkflowCatalogEntry()` hook (`frontend/src/hooks/useWorkflowMetadata.ts`) that
derives `tag`/`subtitle` from the live catalog row (`display_name`/`description`) when no
curated `TYPE_CONFIG` entry exists.
