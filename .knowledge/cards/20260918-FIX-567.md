## The symptom

Six wave builders running concurrently in one process shared a single
Playwright `BrowserContext`. Whichever worker bound last owned the browser for
all of them — each one screenshotting and editing inside another's page, with
no error anywhere to trace it by.

## The root cause

`app/agents/tools/playwright.py` held the run sandbox and the agent key in
module-level globals, set by `bind_sandbox` at factory time. That is fine for a
single-agent step. Inside a wave it is not: every worker in a wave is an
instance of the same agent template, so they all share one `agent_id`
(`"custom-agent:pb-build"`), and `PlaywrightSession.acquire(agent_key)` handed
them all the same context. The last binder won, silently.

## What changed

The binding moved into ContextVars:

```python
_SANDBOX_VAR: contextvars.ContextVar[Any | None] = contextvars.ContextVar(
    "playwright_sandbox", default=None)
_AGENT_KEY_VAR: contextvars.ContextVar[str] = contextvars.ContextVar(
    "playwright_agent_key", default="unknown")
```

`bind_sandbox(sandbox, agent_id, worker_key=None)` sets both, and every one of
the nine tools reads `_SANDBOX_VAR.get()` for its path resolution and
`_AGENT_KEY_VAR.get()` for `session.acquire(...)`. The factory
(`agents/factory.py:1234`) passes `worker_key=thread_id`, so each fan-out worker
gets a distinct key and therefore its own `BrowserContext` — spec 018 FR-010.

## The propagation rule a future author must keep

ContextVar values propagate **into** a worker's asyncio task, but a write made
inside that task does **not** escape it. Every worker runs in its own task, which
is exactly why this works — and also why every bind path must go through
`bind_sandbox` rather than assigning a module global. A tenth tool added to the
browser pack that reads a module-level handle would reintroduce the shared
browser, and nothing would fail loudly enough to notice.

## What this does not fix

This is the resource-isolation sibling of two other problems, and it closes
neither:

- [ISS-130](20260812-2116-ISS-130.md) — N parallel fan-out workers share one
  `ExecutionContext`'s scratch fields, an unverified interleaving hazard masked
  only by lucky await timing. **Still open.** Different shared resource.
- [FIX-555](20260901-FIX-555.md)'s shallow context copy is the same family of
  defect, fixed separately.

Say so plainly rather than letting the browser fix read as closing the
concurrency story.
