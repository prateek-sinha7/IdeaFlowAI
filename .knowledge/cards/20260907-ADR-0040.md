## Decision

A run's sandbox is a git repository, initialised on creation and committed by
the engine. History is the versioning mechanism — there is no separate
snapshot store.

**The unit is the revision family, not the run.** A revision writes into its
root's directory and keeps its own run id, so the whole family shares one
history and one set of tags. The root is found by walking `parent_run_id`. A
**chained** run is different in kind: it starts a new family with its own
sandbox, and receives the source run's payload as input.

**Only the engine writes git.** `commit_in_sandbox` is the one primitive; the
step loop calls it at every boundary and the terminal finalizer calls it once
more. No agent can reach git — there is no tool to do so, and the reserved
path registry refuses the paths that would let one forge a payload.

**Tags mean completion.** Every terminal run gets an internal ref so its tree
is addressable, but only `completed` earns `vN`. The ordinal is the run's
position among all descendants of the family root, by creation order — the
same rule the interface uses to render the number, so the two cannot drift.

## Why this shape

Three alternatives were rejected. A snapshot directory per version duplicates
the tree and cannot express "what changed". Letting agents commit makes the
history a function of prompt behaviour. Tagging every terminal run makes `vN`
meaningless — a user reads `v3` as "the third thing that worked".

## Consequences

- Deliverable, `spec.md`/`tasks.md`/`PLANNER.md`, `src/**` and the three
  `.chain/` files are tracked. Agent transcripts are not.
- A cancelled or failed run still commits what it has, so the next revision
  starts from a clean tree with the abandoned work attributed in history.
- Disk grows with history; `git_bytes` and `chain_depth` are reported in the
  run's disk metrics.

## Known gaps at time of writing

- The reserved-path guard for **agent tool calls** normalises `/` and `./`
  but not an embedded `..`, so `sub/../.chain/x` reaches the payload
  directory. Tracked on branch `feat/git-versioning` as bug B17.
