# ISS-896

Found while verifying [FIX-682](20261001-2128-FIX-682.md), the QA-KB-043 fix: I ran the test callers that [ISS-105](20260812-1312-ISS-105.md) lists in
its blast radius. This failure has nothing to do with that fix. It is raised before any shutdown code runs.

**Claim status: CONFIRMED by running it (2026-10-01). Whether the test passes once allowed to spawn is NOT
established here.**
(Analyzed 2026-10-08 under QA-KB-099: see "Analysis" at the end of this card. That open point is now settled: the test passes once
allowed. The line numbers in this original text predate commit `9ef547e74`, which shifted them; the Analysis gives the current ones.)

## Condition (observed)

`cd backend && .venv/bin/python -m pytest tests/unit/services/test_shutdown_reachability.py -q -p no:cacheprovider`:

```
FAILED tests/unit/services/test_shutdown_reachability.py::test_sigterm_reaches_the_lifespan_shutdown_half_while_a_stream_is_live
1 failed, 7 passed, 1 warning in 3.49s
```

Run alone, the traceback ends at the test's own `proc = subprocess.Popen(` (`test_shutdown_reachability.py:187`):

```
E       tests.unit.conftest.UnitIsolationError: Unit test spawned a subprocess: ['.../backend/.venv/bin/python', '-m', 'uvicorn', 'reachability_probe_app:app', '--host', '127.0.0.1', '--port', '53650', '--timeout-graceful-shutdown', '5', '--log-level', 'error']. Move it to tests/integration/ (suffix _external), or assert against the command it would have built instead of running it. Deliberate exception: @pytest.mark.allow_io("reason").
tests/unit/conftest.py:129: UnitIsolationError
```

## Why

The autouse fixture `_unit_io_guard` (`backend/tests/unit/conftest.py:90-91`) installs `_deny_popen` (`:127`) over
`subprocess.Popen.__init__` (`:136`) for every test under `tests/unit/` without an `allow_io` marker. The module
docstring states the rule (`:17`): "Opting out requires an explicit reason: ``@pytest.mark.allow_io("why")``". This
test is decorated only with `@pytest.mark.skipif(sys.platform == "win32", ...)` (`:163`), so the guard refuses its
first real step.

## What is lost

The test is the end-to-end proof for [ISS-088](20260812-0604-ISS-088.md). Its docstring (`:173-177`) says that
without `--timeout-graceful-shutdown` it "hangs to the wait budget and fails with only ``startup_complete``
recorded — which is the defect ISS-088 describes." The static check
`test_docker_entrypoint_still_passes_timeout_graceful_shutdown` (`:252-256`) still runs and passes, so the flag in
`docker-entrypoint.sh` is still guarded. The unit tier no longer proves that SIGTERM with a live stream actually
reaches the lifespan shutdown body. The failure is also a standing red in this file, and a regression of the real
defect would show up as the same red.

## Disposition

Open. The guard's message names two remedies: `@pytest.mark.allow_io("<reason>")` on this test, or move it to
`tests/integration/` with the `_external` suffix. Which one to use is test-placement policy and outside the
QA-KB-043 cards, so nothing was changed. It was not re-run with the guard lifted, because that needs a marker or a
test edit.

### Root cause (CONFIRMED)

The test does real I/O in the tier that forbids it, and carries no opt-out.

- `backend/tests/unit/conftest.py:90-91`: the autouse `_unit_io_guard`. Unless the node has an `allow_io` marker (`:118-121`, an early
  `yield; return`), it replaces `subprocess.Popen.__init__` (`:127-136`) and `socket.socket.connect` / `connect_ex` (`:152-171`) with
  functions that raise `UnitIsolationError`.
- The test uses both. `subprocess.Popen([sys.executable, "-m", "uvicorn", ...])` at `test_shutdown_reachability.py:180`;
  `socket.create_connection(("127.0.0.1", port))` in `_wait_for_health` (`:135`) and in `_open_live_stream` (`:149`).
  `create_connection` ends in `sock.connect(sa)` (CPython 3.13 `socket.py:853`), which the guard also refuses. The test is decorated
  only with `skipif(win32)` (`:156-164`) and lives in `tests/unit/services/`.
- Reproduced at HEAD 3af414bc6 and f06129262: `1 failed, 7 passed`; traceback `test_shutdown_reachability.py:180: in test_sigterm_...`
  then `tests/unit/conftest.py:129: in _deny_popen` (`evidence/qa-kb-099/analysis-01-reproduce-at-head.txt`; the validator's three
  runs are `evidence/qa-kb-099/01-*.txt` to `03-*.txt`). It is a call-phase FAILED, not a setup ERROR, because the exception is raised
  inside the test body.

### Fix, and where it belongs: this one test (recommended), not the guard

The guard is correct and is the shared mechanism for 4061 unit tests; the fault is one test's annotation. Do not change
`_unit_io_guard`: a Popen-only workaround would still die at the socket refusal (`conftest.py:152-171`), and a loopback or uvicorn
carve-out would weaken it for the whole tier (`tests/unit/test_unit_io_guard.py` pins the refusals).

Recommended (smallest diff, same-family precedent): decorate the test with `allow_io` and an audit note in
`backend/tests/unit/services/test_shutdown_reachability.py`, above the existing `skipif`:

```python
# Audit note: README rule 8 puts a test that spawns a process under tests/integration/ (suffix
# _external); relocating needs an approved migration plan, so it stays here under an explicit,
# reasoned exemption.
@pytest.mark.allow_io(
    "ISS-088 end-to-end proof: spawns a real uvicorn subprocess, talks to it over 127.0.0.1 "
    "sockets and sends it a real SIGTERM; nothing outside this process tree and loopback"
)
```

Why this one: the same family already does it (`tests/unit/app/test_run_stream_pool_leak.py:59-64`, the file this test's docstring
names at `:21-24`, plus `test_run_sandbox_api.py:40` and `test_ci_bounded_runner.py:37`), it touches nothing else, and the marker
disables all three guard layers at once. The wording above was run through the citation guard's own regexes: 0 hits
(`analysis-08-fix-hazards-citation-guard-and-path-depth.txt`). Keep `line N`, `name.ext:N` and a bare `:NNN` out of anything added to
this file.

Alternative (the README's first-choice remedy, `backend/tests/README.md:76-78`): relocate to `tests/integration/<dir>/..._external.py`.
It is larger, because it must:

- keep the file exactly two folders under `backend/tests/` (`REPO_ROOT = Path(__file__).resolve().parents[4]` at `:41`;
  `tests/integration/<dir>/` works, `tests/integration/x.py` resolves one level too high);
- decide whether the 7 static tests move too, since `_uvicorn_graceful_window_seconds()` (`:51`) is shared with three of them;
- repoint BOTH hard-coded paths in `test_run_shutdown_stale_citations.py` (`:23` and `:90`) rather than delete the entry, because
  deleting it silently drops the file's cite protection (the same blind spot as [ISS-1084](20261007-2216-ISS-1084.md));
- fix the path comments at `app/main.py:411-412` and `app/core/config.py:309`, and refresh nine cards' globs.

Relocation precedents exist: [FIX-758](20261007-2338-FIX-758.md) (QA-KB-088) and commit `14a675db4` ([ISS-892](20261001-2120-ISS-892.md)).

Either way, also correct the stale path in `app/main.py:411-412` (comment only: `tests/unit/services/test_shutdown_reachability.py`, or
the new path).

Not a product decision: the bug report's Expected and the guard's own message both name either remedy, so nothing is escalated. The
policy text that muddies the choice is [ISS-1110](20261008-1410-ISS-1110.md).
