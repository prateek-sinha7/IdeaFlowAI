# ISS-948

## Description

Observed while regression-testing [FIX-705](20261002-0107-FIX-705.md); unrelated to it.
`tests/security/test_route_contract.py::test_all_routes_are_protected_or_allowlisted` fails with:

```
AssertionError: These endpoints have NO authentication dependency and are not allow-listed:
    GET /s/{token}
```

## Evidence

- `backend/app/main.py:625` registers `@app.get("/s/{token}")` → `view_shared_run`, whose
  docstring reads "Return the deliverable for a public share token — NO auth required". It landed
  in `b69f25696` (2026-08-28, "Option B public share link").
- `backend/tests/security/public_routes_allowlist.txt` has no `/s/` line. Neither file, nor the
  test, is modified in the working tree, so the test is red at HEAD `024c03ef8` (read, not
  re-run at HEAD).

## Fix direction

The route is public by design ([ADR-0035](20260828-0644-ADR-0035.md)). Add one allow-list line
with its reason. The file's own format requires the reason. For example:
`GET /s/{token}  # ADR-0035 share link: the opaque 30-day token is the credential; serves the deliverable only, 404 on a missing or expired token`.

## Analysis (2026-10-02, QA-KB-089)

### Root cause

CONFIRMED. The route and its contract were authored on two lines of work and joined by a merge that git could not flag, because the two sides touched different files.

- `GET /s/{token}` entered this branch's first-parent line in `b69f25696` (2026-08-28, "Option B public share link").
- `tests/security/test_route_contract.py` and `public_routes_allowlist.txt` were added together in `b2a621f84` (2026-09-17, merge of PR #8 "Fix/cognito login"), the only commit that touches either file. That tree has no share route (`git show b2a621f84:backend/app/main.py` has no `@app.get("/s/{token}")`), so the allow-list was written without it. It has never contained a `/s/` line on any branch (`git log --all -S'/s/{token}' -- backend/tests/security/` is empty).
- They first met in `1d95275b4` (2026-09-23, "Merge origin/dev into feat/stable"). Parent 1 (`cae0c8adf`) has the route and no test; parent 2 (`09270703b`) has the test and no route; the merge result has the route and no allow-list line. There was no textual conflict, so nobody had to reconcile them.

The failing assertion is `test_all_routes_are_protected_or_allowlisted` (`backend/tests/security/test_route_contract.py:158-176`, the `assert` at `:170`): every endpoint must carry a name from `_AUTH_DEPENDENCIES` (`:44`) or appear in `_load_allowlist()` (`:96`). `view_shared_run(token: str)` (`backend/app/main.py:625-626`) has no dependency at all, and `public_routes_allowlist.txt` (58 lines, 22 entries) has no `/s/` line.

### Reproduction (CONFIRMED, executed)

From `backend/`, one file, offline (the root conftest pins `DATABASE_URL` to a temp SQLite file): `./.venv/bin/python -m pytest tests/security/test_route_contract.py -q -p no:cacheprovider` at HEAD `024c03ef8` gives `1 failed, 3 passed`, with `GET /s/{token}` the only name in the failure. Using the test's own helpers: 130 endpoints walked, 23 with no auth dependency, 22 allow-listed, one not. This replaces the "read, not re-run at HEAD" caveat in Evidence above.

### Blast radius

- Consumers of the broken thing (CONFIRMED, `grep -rn public_routes_allowlist`): exactly one, `test_route_contract.py:62`. Nothing else reads the file.
- Other un-listed public routes: none. The other three tests in the file pass, so all 22 existing entries are live and genuinely unauthenticated.
- Merge gate (CONFIRMED read, effect INFERRED): `.github/workflows/ci.yml:336-337` runs `pytest tests -m "not live and not requires_api_key and not requires_postgres and not requires_postgres_populated_migration"`, which includes this file, and `backend-offline` is a mandatory signal (`backend/tools/ci/signal_registry.py:324-334`, and part of the `ci-required` aggregate at `:634-665`). The workflow triggers are `pull_request`, `push` to `main`, manual dispatch and `workflow_call` (`ci.yml:47-51` and below); there is none for a direct push to `dev` or a feature branch, so a merge like `1d95275b4` is not evaluated when it lands. The first PR to `main` carrying this tree should fail `backend-offline` until the line lands. INFERRED: I did not see a CI run.
- Other branches: `dev` and `origin/dev` (`97f3dde36`) carry the same route and the same allow-list without it, and their two test files are byte-identical to this tree's (`git diff --stat dev -- <both files>` is empty). Static equivalence, not executed there.
- Same family, already carded: `tests/security/test_no_projection_reads.py` arrived in the same merge and is also red at HEAD (`1 failed, 1 passed`, `app/api/settings.py:341/388`), tracked as [ISS-1029](20261002-0705-ISS-1029.md). `test_cognito_client_boundary.py` is green (3 passed). Fixing this card turns `test_route_contract.py` green; it does not turn `backend-offline` green on its own.

### Where the fix belongs

CONFIRMED. One line in `backend/tests/security/public_routes_allowlist.txt`; no application source change. It is the only registry the contract reads. The file's own pre-check (header, lines 9-13: does the route authenticate by a means the scanner cannot see?) comes out the other way: the token lookup is an inline call in the handler body (`main.py:636-649`) with no injected dependency, so there is nothing to teach `_AUTH_DEPENDENCIES`, and giving the route an auth dependency would break the feature ADR-0035 exists to provide.

The reason text is the file's only safeguard, so each clause was checked against code (CONFIRMED, read). Opaque token: `secrets.token_urlsafe(32)` (`backend/app/api/runs.py:2284`). 30-day: `_SHARE_TTL_DAYS = 30` (`:2160`, `:2285`). 404 on a missing or expired token: `get_shared_run_by_token` returns `None` (`:2328-2337`) and `view_shared_run` raises 404 (`main.py:648-649`). Serves the deliverable only: the response bodies at `main.py:676-699`, plus the serve-time reserved-path guard (`runs.py:2338-2354`).

Suggested text, as a new section after the authentication entry points:

```
# --- Public share link (ADR-0035) -------------------------------------------
GET /s/{token}  # ADR-0035 share link: the opaque 30-day token is the credential; serves the deliverable only, 404 on a missing or expired token
```

What a naive fix gets wrong, all enforced by the same file's other tests:

- `HEAD /s/{token}` is not registered (observed with the test's own helpers: `HEAD /s/{token}` and `HEAD /health` are absent, `HEAD /docs` is present, which is why the file lists HEAD only for the framework routes). A HEAD line fails `test_allowlist_has_no_stale_entries` (`:179`).
- The signature must match the live path text exactly, braces included, and the `#` reason is mandatory (`:110-119`, `pytest.fail`).
- Do not copy ADR-0035's "the ONLY unauthenticated route" into the reason. It is not true: the allow-list approves 22 others (login x4, `/health`, template previews x6, installers x3, framework docs x8). ADR cards are corrected by supersession, not edited, and that wording is knowledge drift, not part of this fix.
- Do not weaken `_AUTH_DEPENDENCIES` or the test to get green.
