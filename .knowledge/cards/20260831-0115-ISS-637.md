## Symptom

```
test_alembic::TestAlembicMigrations::test_upgrade_then_check_reports_no_drift
  alembic.util.exc.AutogenerateDiffsDetected: New upgrade operations detected…
```

## Why this is its own card

It arrived as one line in a list of unrelated singles, but it means something
specific and serious: a model changed without a migration, so a database built
from the migration chain does not match what the ORM expects. That is a
deployment problem, not a test problem — and it stays silent until someone
provisions a fresh environment.

Run the autogenerate and read the diff it reports to find which table.

## Resolution (FIX-434)

The diff the card asked for was read: the table is `workflow_runs` and the
object is the sparse unique index `uq_workflow_runs_share_token`. The
direction is the opposite of the register's paraphrase — migration 0040
**does** create the index (`0040_workflow_run_share_token.py:44-51`); the
**model** never declared it, so `Base.metadata` was missing an index every
chain-built database has and autogenerate proposed `remove_index`.

Fixed in `backend/app/models/workflow.py` by declaring the index (with 0040's
partial `share_token IS NOT NULL` WHERE clause) in
`WorkflowRun.__table_args__`. No migration was added or changed. See
[FIX-434](20260831-1907-FIX-434.md).
