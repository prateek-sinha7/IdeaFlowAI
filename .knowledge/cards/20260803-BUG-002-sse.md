# BUG-002 — Run History row-tap opens a degraded static detail (no chat lane / no revise / stale QUEUED / No agent data / No preview) instead of the shared run...


### BUG-002 — Run History row-tap opens a degraded static detail (no chat lane / no revise / stale QUEUED / No agent data / No preview) instead of the shared run screen  [🟠 major] [FIXED ✅]
- **RESOLVED:** FIXED (quick 260716-j1u, e8a22842) — live-proven

- **Found:** 2026-07-16 · test history-open path (top-nav "Run History" / a run's "Back to history" → tap a run row) · surface Run History detail vs the shared run screen.
- **Symptom:** Two paths open a past run and render COMPLETELY DIFFERENT UIs.
  - **Home "Jump back in" recents → tap run (GOOD):** the FULL run screen — left conversation lane (`data-testid="execution-chat-lane"`) with the Steer/revise composer, working concierge, live Steps trace + deliverable. Tab set Preview / **Steps** / Files / Audit. Shots: `~/.claude/jobs/e660aea4/tmp/shots-qa/{recents-open-run,concierge-reply2}.png`.
  - **Top-nav "Run History" → tap a run row (BAD):** a DIFFERENT, degraded detail — **NO left chat lane, NO composer, NO revise affordance**; WRONG status ("QUEUED" for an actively-generating run); empty **"No agent data"** left panel + **"No preview available"** main area; a DIFFERENT tab set Preview / Files / **Thinking** / Audit. Run tapped = the live app_builder run `bb6dc438` ("A URL shortener web app"). Shot: `~/.claude/jobs/e660aea4/tmp/shots-qa/history-row-tap.png`.
  - User expectation: "when you go to workflow history, and tap, the left chat panel should be there to help revise." It is not.
- **Root cause (investigation agent — read `.planning/IMPLEMENTATION-REGISTER.md` global + FE run-screen/history phase sections 21/31/32/**36**/39/42/44; grep-confirmed no run-open architecture in the backend engine phases):**
  - **The two open paths physically diverge into two different components.**
    - **Home recents (GOOD):** `frontend/src/components/layout/DashboardLayout.tsx:1475` — `onOpenRun={(run) => { onSelectWorkflowRun?.(run); setMainView("execution"); }}`. `onSelectWorkflowRun` (prop `DashboardLayout.tsx:76`, destructured `:211`) is wired to `page.tsx`'s `handleSelectWorkflowRun` (`frontend/src/app/dashboard/page.tsx:1444`). `handleSelectWorkflowRun` (`page.tsx:1165`) fetches the run, sets the VIEWED-run identity `setContentSourceRunId(fullRun.id)` (`page.tsx:1187`), and — when the opened run differs from the live launched run (`page.tsx:1198`) — **seeds the Steps pipeline reducer from the durable `run_events` and sets `submittedBrief = fullRun.input`** (`page.tsx:1202-1219+`, the DEF-44-12-4 Piece 1 seed) and attaches the live SSE tail for a non-terminal run (DEF-44-12-3). Then `setMainView("execution")` mounts the shared run screen whose left column is `RunChatLane` (`frontend/src/components/chat/RunChatLane.tsx`, `data-testid="execution-chat-lane"`) — live-bound, with the concierge/steer/revise composer.
    - **Run History (BAD):** `DashboardLayout.tsx:1506-1508` mounts `<WorkflowHistory … activeRunId={pipelineState?.pipelineRunId ?? null} onViewRunningPipeline={() => setMainView("execution")} />` — and passes **NO `onSelectWorkflowRun`/`onOpenRun`**. A run row's tap (`WorkflowHistory.tsx:953` `onSelectRun={handleSelectRun}`) runs `handleSelectRun` (`WorkflowHistory.tsx:155`): a KAN-96 guard (`:156-161`) routes to the live execution view **only when `run.id === activeRunId`** (i.e. equals the single `pipelineState.pipelineRunId`); for every other run it falls through to `setSelectedRun(run)` (`:162`), which triggers the `if (selectedRun)` branch (`:362`) that renders WorkflowHistory's OWN internal two-column detail: left `<RunDetailPage runId={selectedRun.id}>` (`:424`) + a main deliverable panel with tabs `["preview","files","thinking","audit"]` (`:547`). `handleSelectWorkflowRun` is **never called**, so `contentSourceRunId`, the durable-event Steps seed, the SSE attach, and `RunChatLane` are all skipped.
  - **Symptom-by-symptom:**
    - **(a) No chat lane / composer / revise.** `RunDetailPage.tsx` is a static summary page (header + KPI strip + Agents/Timeline tabs) — it contains no `RunChatLane`, no textarea, no steer. The only revise on this surface is a small left-footer textarea gated on `WorkflowHistory.tsx:438` `selectedRun.status === "completed"` — so an actively-generating (non-completed) run shows **no revise at all**. The `RunChatLane` conversation lane (concierge/steer) is never mounted on this path.
    - **(b) "QUEUED" for a generating run.** `RunDetailPage` is fed by a **one-shot** `getRunSummary(jwt, activeVersionId)` (`RunDetailPage.tsx:102`, `useEffect` deps `[activeVersionId]` `:119`) rendered via `<Badge status={summary.status}>` (`:224`). No SSE attach, no reducer, no poll → the badge is a snapshot taken at open-time and never advances. The row-tap didn't reach the live view because `bb6dc438 !== pipelineState.pipelineRunId` (the last-launched run — od_prototype `4cd2f478` per BUG-001 — held `activeRunId`). (The exact persisted status value returned by `/summary` = *unverified* — did not read the endpoint; the not-live-bound mechanism = *verified*.)
    - **(c) "No agent data" + "No preview available".** `RunDetailPage.tsx:343-346` renders "No agent data" when `summary.agents.length === 0` (the one-shot summary of a just-started run has no agents yet). "No preview available" is WorkflowHistory's own deliverable-panel empty state (`WorkflowHistory.tsx:626` / `:646`) shown when `selectedOutput`/`selectedRun.output` is empty (a generating run has no output yet). Both are static — no durable-event seed (DEF-44-12-4) and no SSE tail (DEF-44-12-3) that the execution path now has.
    - **Tab-set difference confirms two implementations.** The run screen relabels the thinking tab to "Steps" (`PreviewPanel.tsx:356` `{ id: "thinking", label: "Steps" }`); WorkflowHistory's internal detail keeps raw order/labels Preview/Files/**Thinking**/Audit (`WorkflowHistory.tsx:547`).
  - **Pre-existing verdict — PRE-EXISTING, not introduced by the SSE/DEF-44 work; the SSE work made the contrast starker.** `git blame`: `handleSelectRun → setSelectedRun` (the internal-detail branch) = `09c7609bf` Prateek Sinha **2026-05-07** — the original History behavior, long pre-dating the run-screen/`RunChatLane` work. The narrow KAN-96 live-route guard = `71eec1b25` **2026-07-06**. `RunDetailPage.tsx` created `fb0b5e9c` **2026-07-09** (Phase 36-04, promoting the in-panel detail into a page). The Home-recents path was *separately* fixed to route into the run screen (`ba159678` "fix(dashboard): Home recents chip opens the run in the execution view"), but the **symmetric History path was never rewired**. The SSE cutover + DEF-44-12-4 seed + DEF-44-12-3 SSE-attach all landed **only** on `page.tsx handleSelectWorkflowRun` (the execution path); the History path never received live binding, so as the execution path got much richer the History detail stayed static and the divergence became glaring. Same class as BUG-001 / DEF-44-12-4 ("a run-open surface not brought up to the execution path's viewed-run/live binding").
- **Fix (PROPOSED — investigation only, not applied):** route the History row tap through the SAME wiring as Home recents so the shared run screen (`RunChatLane` + `contentSourceRunId` + DEF-44-12-4 durable seed + DEF-44-12-3 SSE attach) is used everywhere. Two edits:
  1. **`WorkflowHistory.tsx`** — add an optional prop `onOpenRun?: (run: WorkflowRun) => void` to `WorkflowHistoryProps` (near `:45`) and destructure it (`:108`). In `handleSelectRun` (`:155`), when `onOpenRun` is provided call `onOpenRun(run); return;` in place of the `setSelectedRun(run)` internal-detail branch (`:162`). (The KAN-96 `activeRunId` guard can fold away — the shared run screen already handles a live run via the same seed.)
  2. **`DashboardLayout.tsx:1506`** — pass `onOpenRun={(run) => { onSelectWorkflowRun?.(run); setMainView("execution"); }}` to `<WorkflowHistory>` — **byte-identical to the Home-recents wiring at `DashboardLayout.tsx:1475`** (`onSelectWorkflowRun` and `setMainView` are already in scope; `onSelectWorkflowRun` destructured `:211`). SC-001-safe: keys only on generic run identity, zero workflow-name literal.
  - **Must-verify / carry-over before RETIRING the internal detail** (`WorkflowHistory.tsx:362-730` + `RunDetailPage.tsx`, per INV-3/INV-12 no-dual-implementation — grep shows `RunDetailPage` is mounted only by `WorkflowHistory`):
    - **Cross-workflow chaining** ("Suggested next steps", `onChainPipeline`/`availableChainTargets`, `WorkflowHistory.tsx:450`/`:518`) — grep-confirmed **absent** from the run screen (0 hits for `availableChainTargets|onChainPipeline` in `RunChatLane.tsx`/`PreviewPanel.tsx`). The one genuinely History-only capability: add it to the run screen's complete-state affordances or keep it reachable before deleting the internal detail.
    - **Version-family switch column** (`VersionTimeline`, `RunDetailPage.tsx:262`) — also **absent** from the run screen (0 hits), BUT each family member is already its own row in the History LIST (`RevisionFamilyView` family expansion), so every version stays reachable by tapping its list row → run screen. Confirm that list-level reachability suffices.
    - **Per-agent KPI breakdown / terminal-failure banner** (RunDetailPage Agents tab + `DegradedRunAffordance`) — covered by the run screen's Steps + Audit (P26 token telemetry) + its own terminal cards (Phase 32/42). Low risk.
    - **Delete** = list-level kebab (not in the detail) — preserved. **Back nav** — run screen already has "Back to history" (`LaneRunHeader.tsx:219`, `RunChatLane.tsx:155 onBackToHistory`) — no regression.
  - Retiring the internal detail is a *follow-up*; the minimal fix is only the 2-point rewiring above.
- **Verify (fail-before / pass-after):**
  1. **Fail-before:** with a run that is NOT `pipelineState.pipelineRunId` (any completed historical run, or a second generating run), open it from top-nav Run History → assert NO `data-testid="execution-chat-lane"`, RunDetailPage summary visible, tabs = Preview/Files/Thinking/Audit. (Reproduced live: `bb6dc438` → no lane, QUEUED, "No agent data"/"No preview available".)
  2. **Pass-after:** same tap → `data-testid="execution-chat-lane"` present with the composer + concierge/steer; live status/agents/preview render (parity with `recents-open-run.png`); tabs = Preview/Steps/Files/Audit.
  3. **No-regression:** Home recents tap still opens the run screen; the active-run KAN-96 case still lands on the live view; "Back to history" returns to the list; chaining + version switch still reachable (list-level).
  4. **Unit:** a `WorkflowHistory` vitest asserting a row tap calls `onOpenRun(run)` (not `setSelectedRun`); `tsc --noEmit` clean.
