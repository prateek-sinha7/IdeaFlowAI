# FIX-735

## What was wrong

This fix is for bug report QA-KB-078 ("app_builder characterization goldens still expect .family.lock block; both
contract tests fail"). The root cause and the blast radius come from the 2026-10-02 analysis on
[ISS-906](20261001-2200-ISS-906.md) and its siblings [ISS-1014](20261002-0605-ISS-1014.md) and
[ISS-1015](20261002-0605-ISS-1015.md). They were not re-derived here. The quoted lines were re-read on the working tree
(branch `feat/stale-bug-fixes`) before anything was written. The user's own commits moved HEAD from `b898a3b97` to
`2997acb71` while this fix ran (19:16-19:26). `git diff --stat b898a3b97 2997acb71` over `backend/agents`,
`backend/app/agents`, `backend/tests/agents/characterization`, `backend/tests/contract/agents`, `_scripted_model.py` and
the three card test files is empty, so the before and after runs below measure the same code.

- **[ISS-906](20261001-2200-ISS-906.md).** `golden/app_builder.txt` (last written `e7305f9dd`) and
  `golden/app_builder.events.json` (last written `bd3ca6e68`) open the deliverable with a `filename: .family.lock` block.
  Since `f9df3737c` ([FIX-647](20260929-1024-FIX-647.md)) the deliverable walk drops that file:
  `sandbox.py:68` `".family.lock",  # revision-family lock file (family_lock_path) — engine plumbing` sits in
  `_DELIVERABLE_EXCLUDE` (`:65`), which `is_deliverable_relpath` (`:1560`) applies. Both app_builder SAFE-01 / SAFE-02
  tests were red.
- **[ISS-1014](20261002-0605-ISS-1014.md).** `golden/app_builder.wsframes.json:1204` carried the same block, and only
  `test_wire_parity.py::_record_golden` (`:80`, called at `:122`) writes that file. So
  `test_wire_parity_matches_golden[app_builder]` was a third red test, and the bug's own regeneration sketch would have
  left it red.
- **[ISS-1015](20261002-0605-ISS-1015.md).** `golden/sample_subagents_parallel.events.json` (last written `bd3ca6e68`)
  lacks the worker-identity keys `fanout.py` now puts on fan-out events: `task_id` / `task_author_id` on
  `subagent_spawned` (`:769-770`, `:790-791`) and `subagent_result` (`:717-718`), plus `worker_index` / `task_id` /
  `task_author_id` on every side-channel worker event (`:576-578`). `stream_fanout` always supplies that side channel.
  The cause is independent of `sandbox.py`; it is the same failure class.

## What changed, and why there

Four golden data files, written by each test's own `SNAPSHOT_UPDATE=1` writer, one scoped invocation per card, from
`backend/`:

    SNAPSHOT_UPDATE=1 .venv/bin/python -m pytest tests/contract/agents/test_characterization_app_builder.py -p no:cacheprovider
    SNAPSHOT_UPDATE=1 .venv/bin/python -m pytest tests/integration/agents/test_wire_parity.py -k app_builder -p no:cacheprovider
    SNAPSHOT_UPDATE=1 .venv/bin/python -m pytest tests/agents/test_characterization_sample_subagents_parallel.py -k event_snapshot -p no:cacheprovider

The fix is a regeneration because the goldens recorded behaviour that the product deliberately changed after they were
pinned. The engine is right and the expected data was stale. Each diff was reviewed against the card's prediction
before it was accepted:

- **`app_builder.txt`**: 120 -> 88 bytes. One hunk, the first four lines (the `.family.lock` block, its empty body and
  the blank line after it).
- **`app_builder.events.json`** (29523 -> 29487 bytes, line `:1013`) and **`app_builder.wsframes.json`** (34423 -> 34387
  bytes, line `:1204`). Parsed, both 100-event streams keep an identical type sequence. Exactly one leaf changed in
  each, `$[95].data.final_output`, and the change is the dropped block.
- **`sample_subagents_parallel.events.json`**: 35 -> 35 events with an identical type sequence. 0 leaves removed,
  0 changed, 66 added: 24 `task_author_id` (all `None`), 24 `task_id` (all `None`), 18 `worker_index` (all `int`). These
  are 3 per worker on `subagent_spawned`, `subagent_result`, `agent_start`, `agent_input`, `agent_skills`, `agent_chunk`,
  `agent_complete` and `artifact_fallback`, with `worker_index` on the six worker-side types only. That is exactly
  ISS-1015's list.
- md5 over all 20 files in `golden/`, taken before and after: only these four changed.

## ISS-1015: the choice the card left to the picker-up

ISS-1015 offered two ways forward: (1) re-pin, or (2) make `fanout.py` stamp a key only when its value is not `None`
(the [FIX-277](20260824-1616-FIX-277.md) precedent). Option 2 also required confirming that no consumer relies on a
present-but-`None` key. This fix took **option 1**, for three reasons:

1. **Option 2 cannot make the test pass on its own.** `fanout.py:576` is `_data["worker_index"] = idx`, a worker
   position and never `None`. A "stamp only when not None" rule still adds the 18 `worker_index` leaves, so the golden
   has to be re-pinned in either case. Option 2 only adds an engine edit on top of the re-pin.
2. **The keys were added on purpose.** `git log -S` puts the `worker_index` stamp at `1e329e47b` (2026-09-04,
   "wave scheduler stamps per-worker identity"). It puts `task_author_id` at `5af898322` / `05b7bce54` (2026-09-10,
   "wave-worker identity and UI"). The code comment at `fanout.py:571` reads "RESUME-06 companion: stamp worker identity
   at PUSH time". `git merge-base --is-ancestor` shows that none of the three commits is an ancestor of `bd3ca6e68`, the
   golden's last write. They reached this line through merge `1d95275b4` (2026-09-23). This corrects ISS-1015's
   INFERRED attribution: `390edbaa6` re-indented those lines under its retry loop and did not introduce them.
3. **No consumer tells `null` apart from an absent key.** `frontend/src/hooks/useWorkflow.ts` tests `task_id` by
   truthiness: `if (taskId) {` at `:896` (agent_start) and `:1124` (agent_complete), and `if (chTaskId) {` at `:1091`
   (chunk). It reads `worker_index` only inside `upsertWaveWorker` (`:476`, `:496`), which runs only when `task_id` is
   set. So option 2 would change engine source with no consumer-visible effect.

## Deliberately not done

- **`backend/app/agents/sandbox.py` is not edited.** Reverting `:68` would reopen the leak FIX-647 closed.
  `test_family_lock_is_never_a_deliverable` still passes.
- **`backend/agents/execution_engine/fanout.py` is not edited** (see above). Its comment at `:568-570` ("Optional side
  channel (additive, default-off) ... None for every existing caller — dead branch, zero behavior change") has been
  false since `stream_fanout` began passing the queue. No card asks for a source edit, so it is recorded as
  [ISS-1062](20261007-1927-ISS-1062.md) and left for whoever next edits `fanout.py`.
- **No test file was edited.** The three `xfail(strict=True)` markers (`ISS-906 unfixed` x2, `ISS-1014 unfixed`,
  `ISS-1015 unfixed`) stay for the 6-verifier to remove.
- **No other golden was regenerated.** `prototype.events.json` / `prototype.wsframes.json` had a fresh mtime (17:30)
  but no content diff against HEAD, and they were not touched.
