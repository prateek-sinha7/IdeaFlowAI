## Sibling of

Derived sibling of [ISS-329](20260828-1838-ISS-329.md), filed during root-cause analysis of
`BUG-20260828-021300-library-skills`. **Latent, not currently reproducible** — every hook in the
corpus has a valid `event` today (confirmed by reading all 8 `HOOK.md` files, see below). Filed
because the code SHAPE that produces ISS-329 exists verbatim in the Hooks catalog's own API
handler, one file over, and would produce the identical symptom the moment a `HOOK.md` ever
carries an empty (not absent) `event`.

## Why the root cause implies this

`backend/app/api/hooks.py` docstring (line 30) states it "mirrors GET /api/skills/library", and
the code backs that up almost line-for-line:

- `backend/app/api/skills.py:35` — `categories = sorted({e.category for e in entries if e.category})`
- `backend/app/api/hooks.py:33` — `events = sorted({e.event for e in entries if e.event})`

Both comprehensions drop any entry whose filter-axis field is falsy from the pill/chip list the
frontend renders, and both catalogs render the raw field verbatim into a badge/label
(`LibraryPage.tsx` — `skill.category` at lines 928/965, `hook.event` via the `copyText` template
at line 349 and presumably the hook detail header) and filter by strict equality against the pill
`id` (`LibraryPage.tsx:706` for skills; the hooks-tab equivalent uses `hookEvent === "all" ||
h.event === hookEvent` at line 717). This is the exact "falsy value silently drops out of its own
filter's pill list, but the record carrying it still renders" shape that makes ISS-329's skill
unreachable.

The two catalogs differ in how permissive the LOADER is about the field going missing:

- Skills: `skills_catalog.py:112` — `category=metadata.get("category", "")` — an **absent**
  `category` key silently becomes `""`. This is what ISS-329 hit.
- Hooks: `hooks_catalog.py:83-88` — `required = ("id", "name", "description", "event",
  "trigger")`; `missing = [f for f in required if f not in metadata]` raises `GlobalHookError`
  (and the entry is dropped entirely by `list_global_hooks()`'s `except GlobalHookError: ...
  continue`, confirmed at lines 146-149) when `event` is **absent**.

But the required-field check only tests key PRESENCE (`f not in metadata`), not
non-emptiness. A `HOOK.md` frontmatter block declaring `event: ""` (present, empty string) —
or `event:` with no value, which YAML parses as `None`, also present as a key — passes this
check unchanged (the key IS in `metadata`), so `event=metadata["event"]` becomes `""`/`None`
rather than raising. That entry then survives into `list_global_hooks()`'s returned list, and
`hooks.py:33`'s `if e.event` drops it from `events` the same way `skills.py:35` drops an empty
`category` — reproducing ISS-329's exact reachability gap for the Hooks tab instead of the
Skills tab.

## Expected vs actual (once triggered)

Expected: every hook has a real `event`, so its card is reachable through the pill corresponding
to that event.

Actual (INFERRED, unreproduced — no `HOOK.md` in the corpus currently has an empty `event`): a
hook whose frontmatter declares `event: ""` would render under "All" with a blank event
label/icon (`_get_icon_for_event("")` falls back to "Webhook", so the icon would look plausible
even though the value is empty) and disappear the instant any specific event pill is clicked.

## What would confirm or refute this

Add a fixture `HOOK.md` with `event: ""` (present, empty) under a test hooks directory, call
`list_global_hooks()` / `GET /api/hooks/library`, and confirm: (1) the entry survives the
required-field check rather than being dropped, (2) `""` is absent from the response's `events`
list, (3) the fixture hook is present under "All" and absent under every specific event pill in
`/library?tab=hooks`.

## Fix

If ever triggered, belongs in `backend/app/agents/hooks_catalog.py`'s `_load_one` (mirroring
whatever fix lands for [ISS-329](20260828-1838-ISS-329.md) in `skills_catalog.py`) — but the more
precise mirror here is validating `event` is *non-empty* (not just present) at load time and
raising `GlobalHookError` for a blank value the same way a missing key already does, since
`event` is meant to be one of a small closed set (`PreToolUse`/`PostToolUse`/`Stop`/
`SessionStart`/`SessionEnd`) rather than an open text field like `category`.
