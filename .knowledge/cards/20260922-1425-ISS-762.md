# ISS-762

## Description

Sibling of [ISS-721](20260922-1242-ISS-721.md) (bug QA-PS-027,
`BUGS.md#qa-ps-027`), derived from its root cause rather than independently
reproduced.

`backend/app/api/run_commands.py` reads the engine's `pipeline_complete`
event's `status` / `published_status` fields at THREE independent call
sites, confirmed by direct read:

- `_reconcile_terminal_status` (`:762-890`) — `_latest_complete.payload_json.get("status") == "degraded"`
  (`:818`, `:839`, `:858`, `:890`)
- `_drive_launch_to_queue` (`:3818-4011`) — `elif utype == "pipeline_complete":`
  at `:3947`, `if update["data"].get("status") == "degraded":` at `:3949`
- `_drive_revision_to_queue` (`:5221-5327`) — `if etype == "pipeline_complete":`
  at `:5272`, `if event.get("data", {}).get("status") == "degraded":` at
  `:5274`

All three read the identical field the engine computed with zero content
awareness (ISS-721's finding). `_drive_revision_to_queue` is the driver for
every `*_revision` pipeline (`ppt_revision`, `prototype_revision`,
`user_stories_revision`, `custom_revision`) — a revision run whose agent
edit produces only conversational/placeholder text (no real edit to the
seeded original) would be marked `"completed"` through this same path,
exactly as ISS-721 documented for a forward `custom` run.

## Why the root cause implies this

A revision run still executes through `_execute_impl` (ISS-721's root
cause site) — it is the SAME kernel path, distinguished only by
`ectx.revision_original_html` being seeded (see `single_file.py`'s branch 2,
which ISS-721 also cites). `_drive_revision_to_queue` then persists
`WorkflowRun.status` from the SAME `pipeline_complete` event structure the
launch driver reads, so nothing about the revision path adds a check the
forward-run path lacks.

## What would confirm or refute this

A live revision run (e.g. `prototype_revision`) where the editing agent
responds with hedging/conversational text instead of editing
`prototype.html`, then checking whether `_drive_revision_to_queue` persists
`"completed"`. Not attempted by this card.
