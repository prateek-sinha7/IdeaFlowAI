## What is broken

A chained run launches and its first agent starts with no `summary.md`,
no `logs.jsonl`, and no source deliverable in `.context/`. The source run
correctly writes its `.chain/` payload; the admission gate correctly stamps
`ectx.chain_source_run_id` and `ectx.chain_selection`; but nothing ever
copies those bytes into the receiving sandbox.

`ChainContextProvider.load()` is dead code in production. The observable
discriminator: `chain_context_installed` on the family endpoint stays
`null`/`false` — `_mark_chain_context_installed` only fires after a
successful copy (chain_context.py:510), and its column is already projected
onto the response.

Why nothing caught it: `test_phase5_chaining.py` constructs
`ChainContextProvider()` directly and calls `load()` on a mock context
(line 488). The component is tested; the wiring is not. There is no test
that a chainable manifest actually lists the provider.

Why it fails silently: `_seed_workflow_context` swallows unresolvable names
(`except (KeyError, RuntimeError): continue` at engine.py:13816-13817), so
a missing provider, a misspelled one, and a workflow that legitimately
declares none are indistinguishable at runtime. `ChainContextProvider.load()`
itself returns `{}` at every gate rather than raising, so even if it were
called on a misconfigured run it would degrade silently.

## Root cause — CONFIRMED

`backend/agents/execution_engine/engine.py:13812`:

```python
for name in (compiled.context_providers or []):
    try:
        provider = _CAPABILITY_REGISTRY.resolve("context_provider", name)
    except (KeyError, RuntimeError):
        continue
    ...
    await provider.load(ectx)
```

`compiled.context_providers` is copied verbatim from the manifest field
`context_providers:` (compiler.py:397). The three chainable manifests
declare:

- `prototype/workflow.yaml:47-49` → `context_providers: [opendesign]`
- `ppt_v2/workflow.yaml:61-63`    → `context_providers: [opendesign]`
- `user_stories/workflow.yaml:36` → `context_providers: []`

None of them names `chain_context`. The provider is registered at
`registry.py:149` and `:318` (the `@register("context_provider", "chain_context")`
decorator in `chain_context.py:93`), but no manifest's loop ever reaches it.

`user_stories` is the only chainable workflow safe to fix today without
first landing BUG-126, because its `context_providers` list is empty and
adding `chain_context` would not collide with any pre-existing seed file.
`prototype` and `ppt_v2` both declare `opendesign`, which writes
`.context/design/` and `.context/selections.json` before the provider loop
runs — adding `chain_context` there while `_atomic_write_context_dir` still
does `rmtree(dest_dir)` would delete those files on every chained run.

## Fix plan

**Order: fix BUG-126 first, then apply this fix.**

**Step 1 — Manifest edits (after BUG-126 is landed)**

Add `chain_context` to the `context_providers` list of all three chainable
manifests. Because BUG-126 will have changed `_atomic_write_context_dir` to
merge into `.context/` rather than replace it, the opendesign seed files are
safe:

```yaml
# prototype/workflow.yaml
context_providers:
  - opendesign
  - chain_context

# ppt_v2/workflow.yaml
context_providers:
  - opendesign
  - chain_context

# user_stories/workflow.yaml
context_providers:
  - chain_context
```

`chain_context` must come AFTER `opendesign` in the list so the opendesign
seed is written before the chain payload is merged in. Order is preserved by
the compiler (compiler.py:397 verbatim copy) and honoured by the engine loop
(engine.py:13812 sequential `for name in`).

**Step 2 — Wiring test**

Add a test asserting that every manifest declaring `chains_from: true` also
declares `chain_context` in its `context_providers` list. The existing suite
cannot see this class of defect because it tests the component directly, not
its wiring. Shape:

```python
def test_every_chainable_manifest_declares_chain_context_provider():
    from agents.workflows.compiler import load_all_manifests
    for manifest in load_all_manifests():
        if getattr(manifest.deliverable, 'chains_from', False):
            assert 'chain_context' in (manifest.context_providers or []), \
                f"{manifest.id} declares chains_from but not chain_context"
```

**Step 3 — Discriminator test**

Add an integration-level test (extending `test_phase5_chaining.py` or a new
`test_chain_wiring.py`) that drives a chained run end-to-end with a mock
sandbox and asserts `chain_context_installed` is truthy on the run row after
`_seed_workflow_context` completes.
