# ISS-1099

## Description

QA-KB-097 reports `update_wave_run_merge_state … 'ScopedStore' object has no attribute '_acquire'` in the log of every resume test. It is a real defect and the only product defect behind that bug, but it is not why any of the four resume tests is red: with only this fixed all four stay red, and the three that share a separate cause pass while it keeps firing ([ISS-1061](20261007-1914-ISS-1061.md), Analysis section).

`ScopedStore.update_wave_run_merge_state` (`backend/agents/authz.py:1528`) still opens its session with a helper that no longer exists:

```python
# backend/agents/authz.py:1546-1549
        from app.models.wave_run import WaveRun

        session, owned = self._acquire()
        try:
```

The raise is `authz.py:1548`. The `kernel_services.py:754` of the report is only the `logger.warning(` of the handler that swallows it: `:745` awaits the store call and `:753` is `except Exception as exc:  # noqa: BLE001 — audit must NEVER abort the run`.

- Direct, no engine (`evidence/qa-kb-097/analysis-plugins/probe_store_direct.py`, `DATABASE_URL=sqlite:///:memory:`): `record_wave_run -> ok`, then `update_wave_run_merge_state -> RAISED AttributeError 'ScopedStore' object has no attribute '_acquire'` and `write_provenance_audit -> RAISED` the same ([ISS-1100](20261008-0016-ISS-1100.md)).
- The same script on a scratch `git archive HEAD` copy with the fix below: `update_wave_run_merge_state -> OK, merge_state = clean strategy = git_3way` and the provenance row is inserted.
- Structural scan of `class ScopedStore` (every `self._x` a method uses must exist on the class, `evidence/qa-kb-097/analysis-plugins/scopedstore_missing_self_attrs.py`): exactly two methods fail, this one and `write_provenance_audit` (`:1245`, `self._acquire()` at `:1266`). Nothing else in the repo calls `_acquire`; it survives only in comments (`tests/unit/app/test_run_stream_pool_leak.py:12,186`, `tests/integration/agents/test_revision_intelligence.py:130`).
- Dev database, read-only transaction (`evidence/qa-kb-097/analysis-13-db-selects.txt`): `wave_runs` has 73 rows, 0 with `merge_state`; 25 of the 26 runs that own wave rows have a `merge_completed` event (77 events, last 2026-10-01). The merges happened, the outcome was never stored.
- Independence from the four red tests: with the fix below applied to a scratch copy and nothing else, the four are still 4 red; with the state-machine cause removed and this left broken, three pass (`evidence/qa-kb-097/analysis-02-sm-evict-4-tests.txt`).

## Cause (CONFIRMED)

`1e329e47b` (2026-09-04, "feat(workflows): pdf_to_prototype wave build + stabilization pass", whose body lists "bounded off-loop DB calls in authz … (A12, A16)") deleted `ScopedStore._acquire` and converted every method that used it to `_run_bounded` (`authz.py:120`; the module docstring at `:32-48` says why: the session-less engine path froze the whole event loop for 5h19m). `e7305f9dd` (2026-09-10, "feat: implement sandbox-git-versioning-v2 spec (102 tasks)") was written on a branch that did not have that change and added two methods that call `self._acquire()`. Neither commit is an ancestor of the other (`git merge-base --is-ancestor` is false both ways). Walking `git rev-list --topo-order --ancestry-path e7305f9dd..HEAD`, the first commit that also contains `1e329e47b` is the merge `4ebd98e8f` (2026-09-16, "Merge branch 'feat/git-versioning' into feat/file-extract-tools"); there `authz.py` has no `def _acquire` and still has the two callers (`:1262`, `:1544`). A textually clean merge that is semantically broken: no conflict marker, no import error, and both callers sit behind best-effort handlers, so nothing failed loudly for three weeks.

## Blast radius

- Sole caller of the store method: `KernelServices.update_wave_run_merge_state` (`kernel_services.py:727`), reached from `fanout._persist_merge_state` (`fanout.py:1125`) at `fanout.py:1204, 1346, 1394, 1418, 1449, 1541, 1640`: every merge outcome (`clean`, `conflict`, `aborted`, `partial`) of every fan-out and wave step. Each is scheduled with `asyncio.ensure_future` and dies in the handler: one WARNING per merge.
- The four columns it writes (`app/models/wave_run.py:55-58`, migration 0045) have no reader in `backend/app` or `frontend/src` (grep: only the model and this writer), so today the loss is audit data, not behaviour.
- Same missing helper, different feature (provenance audit rows): [ISS-1100](20261008-0016-ISS-1100.md).

## Fix (product, one file)

`backend/agents/authz.py` only. Move the body of `update_wave_run_merge_state` into a `_body(session)` and `return await self._run_bounded("update_wave_run_merge_state", _body, run_id=run_id)`, exactly like `update_wave_run` (`:1507`) and `read_wave_runs` (`:1566`). Keep `self._scope_owner_ws(query, WaveRun)`. The probe diff for both methods is `evidence/qa-kb-097/analysis-05-authz-probe.diff`; do both in one commit.

Probe on a scratch `git archive HEAD` copy: with that diff `tests/agents/test_provenance_audit.py` goes from 13 failed / 4 passed to 17 passed, and the direct script above passes.

Regression guards to write (4-test-writer):
1. A real-store test: `record_wave_run`, then `update_wave_run_merge_state` on an in-memory SQLite session; assert the four columns on the row, and that a store with another owner leaves them untouched. Nothing exercises the real method today: its only other mention is a hand-written fake in `tests/agents/test_crash_recovery_v2.py:442`.
2. A structural test that every `self._name` used inside `ScopedStore` methods exists on the class (the scan above, about ten lines of `ast`). It would have failed on `4ebd98e8f` and it covers the next method someone merges in. No I/O, so it belongs in `tests/unit`.

What a naive fix would break:
- Giving `ScopedStore` an `_acquire` shim restores the pre-A16 behaviour, a synchronous session open on the event loop with no timeout, on the path whose stall froze the process for 5h19m.
- Catching the AttributeError, or `getattr(store, "update_wave_run_merge_state", None)`, hides the same hole a third time (two BLE001 handlers already hide it).
- Bypassing the store with a raw `SessionLocal()` in `kernel_services.py` violates AUTHZ-01 (`ScopedStore` is the one enforced read/write path).
