# ISS-1082

**Register source:** `QA-KB-076` in root `LEDGER.md` / `BUGS.md` (sibling, derived during its analysis on 2026-10-07).
**Root card:** [ISS-903](20261001-2145-ISS-903.md) holds the mechanism (the guard's `_LINE_CITE` is a closed-world matcher applied one physical line at a time) and the fix. This card is what stays blind after the fix that card proposes.

**Claim status: INFERRED (sibling).** I ran the candidate patterns over a shape corpus and over the six scanned files (`evidence/qa-kb-076/01-analyze-widened-pattern-hits.txt`, `02-analyze-shape-corpus.txt`), so the misses below are measured. No failing test exists yet, and QA-KB-076 does not report them.

## What is wrong

The widening the QA-KB-076 triage sketch proposes is a colon-terminated `name.(py|yml|sh) ?:N` pattern plus a bare `:NNN` alternative. Run per physical line, as the guard does (`test_run_shutdown_stale_citations.py:39`, `path.read_text().splitlines()`), it still passes these shapes as "not a cite":

| Shape | Example | Why it escapes |
|---|---|---|
| prose line number | `on line 292` | no colon, no extension |
| wrapped across a line break | `on line` at the end of one line, `292` at the start of the next | each physical line is scanned alone |
| other extensions | `agents/workflows/prototype/workflow.yaml:12`, `backend/pyproject.toml:174` | the extension list is closed again: `py`, `yml`, `sh` |
| short bare cite | `see :95` | the bare alternative needs three digits (`\d{3,}`) so that `:80`-style ports and times do not match |

Measured on the corpus: adding `yaml` to the list catches the first extension case; a general `\.[A-Za-z]{1,5}` extension class catches both; no line-oriented pattern catches the prose shape. The three-digit floor is a tuning edge in both directions: `see :95` escapes, and a port written with a leading space (`host :8000`) is flagged. Neither occurs in the six scanned files today.

**Live case, CONFIRMED by reading the file:** `backend/tests/unit/services/test_shutdown_reachability.py` lines 10-11 read `... and ``await self.lifespan.shutdown()`` on line` / `292 is never reached.` That is a file-line cite into the pinned `uvicorn==0.34.0` (`uvicorn/server.py:292` is `await self.lifespan.shutdown()`, the last statement of `Server.shutdown`). It is accurate for the pin, so it is not a stale-cite defect today. It is the one cite in the six scanned files that even the widened pattern cannot see. The ISS-903 fix, as analysed on that card, rewrites that same paragraph (lines 6, 8 and 10 trip the widened pattern), so the live case goes away as a side effect and only the blind spot remains.

Over the six scanned files, a general-extension pattern flags the same 6 lines as the sketch, so it adds no false positives today, and a whole-text `\blines?\s+\d+` matches exactly one place: the wrapped `line` / `292` above.

## Why the root cause implies it

Same mechanism as [ISS-903](20261001-2145-ISS-903.md): the guard decides what a cite looks like from a closed list. The sketch swaps one closed list (ten module names) for two others (three extensions, one syntax). The reporter's three shapes (`name.ext:N`, `name.ext :N`, bare `:NNN`) are exactly what the sketch covers. A fourth shape is already live in the same file.

## Expected vs actual

- Expected: any `file:line` cite shape in a scanned file fails the guard, however it is written or wrapped.
- Actual (after the ISS-903 fix as sketched): prose, wrapped and other-extension cites pass.

## Fix

In `backend/tests/unit/test_run_shutdown_stale_citations.py`:

1. Replace the `py|yml|sh` extension list with a general extension class (`\.[A-Za-z]{1,5}`).
2. Scan the file as one text instead of per line, and add a `\blines?\s+\d+` alternative. Derive the reported line number from `text.count("\n", 0, m.start()) + 1`.

Or accept the residual and say so in the guard's docstring. Either is a test-hygiene call, not a product decision. ponytail: stays regex-only; no tokenizer. The ceiling is a cite written as words ("the third line of ...").
