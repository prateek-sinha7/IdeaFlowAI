## What happened (inferred, not yet reproduced)

[ISS-247](20260828-1637-ISS-247.md) traced BUG-20260828-000100-create-app's root cause to
`/create/app`, whose launch panel is `IdeaInputPage.tsx`. That page is one of two components
that render `<ReviewGatesSection>` — `LaunchWizard.tsx` is the other, and it wires the
identical pattern:

- `LaunchWizard.tsx:1046` — `<ReviewGatesSection agents={pipelineAgents}
  onChange={handleGatesChange} />`, the same shared component ISS-247 found has no code path
  into `agent.gates`.
- `LaunchWizard.tsx:583-584` — `handleGatesChange` writes only to a local
  `gateSelectionRef.current = { ids, touched }` (ref declared at `LaunchWizard.tsx:243`) —
  byte-identical to `IdeaInputPage.tsx:912-915`.
- `LaunchWizard.tsx:685-690` and `:773-783` — that ref is read only at submit time
  (`gateAgentIds`/`gate_agent_ids` on the run-launch and save-workflow payloads), never at
  render time by anything the Advanced modal reads.
- `LaunchWizard.tsx:1112-1125` — the SAME "Advanced" modal chain as `/create/app`:
  `<AgentsPopup isOpen={showAgents} .../>`, which imports `CanvasView`
  (`AgentsPopup.tsx:12`), which renders `CanvasConfigRail` (`CanvasView.tsx:11,2291`) — the
  exact component whose `Gate` combobox reads `sel.gates ?? []` (`CanvasConfigRail.tsx:248`),
  never `gateSelectionRef`/`checkedIds`.

`LaunchWizard.tsx` is reached only by the `ppt` and `prototype` pipeline types (per its own
comment: "The LaunchWizard has carried this since T8, but only `ppt` and `prototype` ever
reach that component") — `/create/ppt` and `/create/prototype` were not part of this bug's
original hunt run (BUG-20260828-000100-create-app tested `/create/app` only).

## Why the root cause implies this

ISS-247's root cause is that `ReviewGatesSection`'s checked-agent state and
`CanvasConfigRail`'s per-agent `Gate` combobox state are two disjoint representations with no
synchronization code in EITHER caller — the missing sync lives in how the shared
`ReviewGatesSection` component reports state upward (`onChange(gateAgentIds, touched)`,
`ReviewGatesSection.tsx:36,83-86`), not in anything specific to `IdeaInputPage.tsx`.
`LaunchWizard.tsx` consumes that exact same component via the exact same
ref-then-submit-only pattern, so the same desync should reproduce with no additional
mechanism needed — the bug is in the shared piece, not the caller.

## Expected vs actual (predicted)

Expected: on `/create/ppt` or `/create/prototype`, checking an agent in the Review-gates
checklist and then viewing that same agent's `Gate` combobox in the Advanced modal's Config
tab should agree.

Actual (predicted, unverified): the checklist will report the agent as gated while the
`Gate` combobox continues to read "No gate" — identical to ISS-247's `/create/app`
repro, cycles 1-3.

## What would confirm or refute this

Repeat ISS-247's exact repro steps on a fresh `/create/ppt` (or `/create/prototype`) load:
check one agent in the Review-gates checklist, open Advanced, select that agent's node, open
its Config tab, read the `Gate` combobox. Agreement would refute this card (meaning
`LaunchWizard.tsx` has some sync `IdeaInputPage.tsx` lacks, which the file:line evidence
above does not show); disagreement confirms it.
