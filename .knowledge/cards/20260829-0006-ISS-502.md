## Condition

Boundary case of [ISS-332](20260828-2041-ISS-332.md): a search query that matches zero files
anywhere in the tree (e.g. a nonsense string), pushing the same root cause to its extreme.

Read directly in `frontend/src/components/preview/AppBuilderPreview.tsx`, lines 538-551: the
sidebar's file-tree region maps `tree` unconditionally —
`{tree.map(node => <FileTreeNode key={node.path} ... searchQuery={searchQuery} />)}` — with no
conditional branch for "zero visible nodes after filtering." There is no "No files match your
search" (or similar) fallback anywhere in the component.

## Expected vs actual

Expected: a query matching no files shows some empty-state affordance (a "no results" message, or
at minimum a visibly empty sidebar) rather than a tree of non-functional folders.

Actual (INFERRED, not yet reproduced in a browser): because the folder branch is unconditional
(ISS-332's root cause), EVERY folder in the tree stays rendered even though every file fails the
leaf match check — the whole sidebar becomes a stack of folders that each expand to nothing, with
no messaging at all to tell the user the search found nothing. This is the same defect as ISS-332
but total rather than partial: instead of one or two orphaned folders alongside a valid result, the
entire explorer is dead weight.

## Why the root cause implies it

ISS-332 already established the folder branch never checks `searchQuery`. At the zero-match
boundary, that omission stops being a partial cosmetic issue (a couple of empty folders next to a
real result) and becomes total: nothing in the visible tree is functional, and reading the render
block confirms there is no fallback path for this case at all — it was never designed for.

## What would settle it

Repeat ISS-332's repro with a query guaranteed to match nothing (e.g. `zzzznomatch`) against the
same 4-file seeded payload; confirm every folder (`src`, `styles`, `utils`) still renders and
expands to empty, the footer still reads the unfiltered total, and no empty-state message appears
anywhere in the sidebar.

## Resolution

Fixed by [FIX-394](20260829-0127-FIX-394.md). Its `ISS-502` case in
`AppBuilderPreview.searchFilter.test.tsx` XPASSes.
