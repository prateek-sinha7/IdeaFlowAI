# ISS-102

## Title

**[TWO CORRECTIONS TO THIS ROW, both verified by re-running it at `d31a5a7b` — read these before trusting anything below.] (1) It is TWO tests, not three.** `test_terminal_routes_to_revision` never reaches a model: it dies earlier at `app/api/run_commands.py:2497` with `AttributeError: '_FakeUser' object has no attribute 'tier'` (the KAN-161/ISS-055 entitlement gate; the `_FakeUser` double at `:33` is stale). Only `test_clarify_waiting_routes_to_answers_seam` and `test_gate_paused_routes_to_gate_seam_approve` reach the wire — proven by per-test log attribution, where the `ExpiredToken` lines appear under those two ids and not under the third. **(2) It is TWO calls, not "four attempts per run".** The original "4" was a grep miscount: 2 ERROR log lines plus the same 2 exceptions repeated inside their own tracebacks. **[SCOPE CORRECTION]** the defect was also far wider than this row's framing: a full four-tree sweep found **10** offline tests constructing a live client, 6 of them via paths `build_model()` never touches — so the row's suggested "guard that fails any offline test which reaches `build_model()`" would have been theatre. See FIX-238 for the chokepoint analysis and ISS-118 for the remaining 8. **[FIXED AS]** `TestRouting` got a class-placed autouse `_resolve_concierge` patch, and `backend/tests/conftest.py` got an autouse guard over the three provider classes' `__init__`. `ExpiredTokenException`/`ConverseStream` grep hits in that file: **4 → 0**. The two tests remain red, deliberately — ISS-119. **ORIGINAL ROW TEXT FOLLOWS, uncorrected, for provenance:** **Three offline unit tests attempt a REAL Bedrock model call; they only 'pass as failures' because the SSO token was expired.** `tests/unit/test_chat_messages_endpoint.py::TestRouting::{test_clarify_waiting_routes_to_answers_seam, test_gate_paused_routes_to_gate_seam_approve, test_terminal_routes_to_revision}` do NOT monkeypatch `run_commands._resolve_concierge` (unlike `TestConciergeStreaming`, which does), so the endpoint resolves the real `ConciergeCapability`, whose ctx carries `model=None` → `build_model()` → `ChatBedrockConverse`. Observed verbatim: `DeepAgentRunner.astream_events failed: An error occurred (ExpiredTokenException) when calling the ConverseStream operation` — four attempts per run. **The cost today is zero only because the credentials are stale; on a machine with a fresh `aws sso login` these tests spend real money every time the suite runs**, and the three are already red for an unrelated reason, so nobody looks at their output. Suggested fix: monkeypatch `_resolve_concierge` in `TestRouting` exactly as `TestConciergeStreaming` already does, and add a suite-level guard that fails any offline test which reaches `build_model()`.
