# FIX-779

**Register source:** `QA-KB-109` (`LEDGER.md`), 5-fixer, 2026-10-09. Resolves [ISS-1153](20261009-1340-ISS-1153.md) (root) and its

Line numbers are HEAD `9cd0d6c5a` plus this change. The whole change is `evidence/qa-kb-109/fix-04-change.patch`: `page.tsx` +22/-7,

## What was wrong

The causes are on the cards and are not re-derived here. `AdminPage` stopped keeping the signed-in admin's id in `b2a621f84`, so its
row render could not tell the own row from any other: Delete, Disable, Reset password, the role pill and the plan dropdown were all live
on it ([ISS-1153](20261009-1340-ISS-1153.md), [ISS-1168](20261009-1621-ISS-1168.md)). The server refused four of those with a 400, but
`reset_user_password` had no self check and accepted one, revoking the admin's own session
([ISS-1170](20261009-1621-ISS-1170.md)). Separately, `handleUpdateTier` swallowed the error that `TierDropdown.handleSelect` waits for
to revert its optimistic badge, so a refused plan change kept showing the refused plan ([ISS-1169](20261009-1621-ISS-1169.md)).

## What changed, and why there

`frontend/src/app/admin/page.tsx`, the single row render every own-row control comes from ([ISS-1153](20261009-1340-ISS-1153.md), [ISS-1168](20261009-1621-ISS-1168.md), [ISS-1170](20261009-1621-ISS-1170.md) UI half):

- `:137` `const [currentUserId, setCurrentUserId] = useState<string | null>(null)`, the state `b2a621f84` removed, and `:229`
  `setCurrentUserId(user.id)` in the existing `getMe().then`, before `loadUsers(token)`, so no row renders without it. No second
  `/api/auth/me` call; `getMe` is the page's existing shared-GET.
- `:521` `const isSelf = user.id === currentUserId` once per row. A `getMe()` with no `id` (the T14 mocks) leaves no own row.
- `:598` and `:634` `{!isSelf && <div ...>...</div>}`: the actions group (Reset password, Disable/Enable, Delete) is not rendered on
  the own row. Two changed lines; the block inside is untouched. The spec's S-11-04 wants Delete absent; S-19-14 accepts absent.
- `:561-570` role pill: `disabled={rolePending.includes(user.id) || (isSelf && user.is_admin)}` with the pre-`b2a621f84` class
  (`disabled:cursor-not-allowed disabled:opacity-60`) and title ("You cannot remove your own admin access").
- `:58-62`, `:93-94` and `:552` `TierDropdown` takes `disabled` (trigger `disabled={loading || disabled}`, title "You cannot change
  your own plan"); the row passes `disabled={isSelf}`.
- `:254` ([ISS-1169](20261009-1621-ISS-1169.md)) `throw err;` after the error toast in `handleUpdateTier`. Its only caller is `TierDropdown.handleSelect`, which
  already catches and reverts, so nothing becomes an unhandled rejection.

`backend/app/api/admin.py:523-530` ([ISS-1170](20261009-1621-ISS-1170.md)): `reset_user_password` refuses `user_id == admin.id` with 400 "You cannot reset your own
password here. Change it from your account settings." before the lookup, in the shape of its four siblings (tier `:301`, role `:365`,
disable `:575`, delete `:695`). The sentence names a path that exists: `AccountSettings.tsx:327-365` has the Change Password card. The
frontend client sends `{}` (`lib/api.ts` `adminResetUserPassword`), so the guard is reachable from any client, not only the hidden Key.

Not changed: another admin's row keeps every control (the T14 contract, `admin.actions.test.tsx:169-185`,
`admin.reskin.test.tsx:224-231`); no API shape changed; no import added anywhere.

## For the 6-verifier

- Backend changed (`admin.py`). `:8000` runs this worktree's backend with `--reload`, so the change reloads by itself. `:8001` also
  serves this worktree's backend but WITHOUT `--reload`, and `:3001` serves a scratchpad copy of the frontend
  (`.../5bcc53cb-.../scratchpad/fe3001`): the validate-bugs stack, where the live S-11-04 and S-19-14 e2e tests run, has neither half
  of this fix until its owner restarts and re-syncs it.
- Do not call `reset-password` with `admin@velocity.ai`'s own id on any server that has not reloaded: unfixed, it revokes the shared
  admin session. On the fixed `:8000` it answers 400. The Key is no longer on the own row.
- The live repro is safe: load `/admin` as `admin@velocity.ai`; the own row shows no Key, Disable or Delete, and its role pill and
  plan trigger are disabled with their titles.
