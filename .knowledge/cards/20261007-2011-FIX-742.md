# FIX-742

Bug report QA-KB-084 (Low). The root cause, blast radius and candidate diff come from [ISS-941](20261001-2240-ISS-941.md).
They are not re-derived here. The sibling card [ISS-1026](20261002-0700-ISS-1026.md) is a different mechanism in `page.tsx`
and is fixed separately by [FIX-743](20261007-2011-FIX-743.md). Frontend only: no backend, engine, migration or import-linter
surface is touched.

## What was wrong

`frontend/src/lib/routes.ts`, the [ISS-230](20260828-1805-ISS-230.md) `/versions/{v}` lift in the `runs` branch of `parseViewPath`:

- `if (segments.length <= 4) { return { screen: 'run-version', runId, version }; }` also admitted length 3. So
  `/runs/{id}/versions` returned `run-version` with `version: undefined`, although `ParsedView` declares `version: string`
  for that screen (`:221`). `tsc` cannot see it, because the repo has no `noUncheckedIndexedAccess`.
- The `stream` arm and the `preview/full` arm never looked at the lifted `version`. So `/runs/{id}/versions/{v}/stream` and
  `/runs/{id}/versions/{v}/preview/full` parsed to the un-pinned `run-stream` and `run-preview-full` screens under a pinned URL.

## What changed, and why there

This is the ISS-941 candidate diff, applied as written. All of it is inside `parseViewPath`, because [FIX-696](20261001-2235-FIX-696.md)'s locked rule
says arity is enforced there and never per caller. One guard in the shared parser reaches every caller. Line numbers are
after the edit:

- `:378`: `segments.length <= 4` became `segments.length === 4`. At length 3 the `tail` rebuild yields `['runs', id]`, so
  `subpath` is `undefined` and control reaches the final `return { screen: 'unknown' }`.
- `:417`: the `stream` arm gained `&& version === undefined`.
- `:422`: the `preview/full` arm gained `&& version === undefined`.
- `:372-373`: two comment lines under the existing ISS-230 note say which forms are now `unknown`.

`unknown` was chosen over carrying the pin, for the reasons in ISS-941's "Why this is not an escalation": the route-map
contract has no such routes, and no builder or backend emits them. `unknown` reaches `notFound()` at `page.tsx:4066`.

## Callers, re-grepped 2026-10-07

ISS-941 listed four production callers. A fifth has landed since then, in `14a675db4` (2026-10-06): `DashboardLayout.tsx:861`,
the [BUG-024](20260827-BUG-024.md) live-run funnel. It runs `const here = parseViewPath(window.location.pathname...)` and skips the
`routes.runStream(id)` push when `"runId" in here` names the incoming run. For the three forms it now sees `unknown`, so a
live run's funnel pushes the canonical `/runs/{id}/stream` instead of keeping the bogus URL. That is what it already did for
every other unknown run URL, so no change was needed there. The other callers are unchanged in kind:

- `page.tsx:437`: the three forms now reach `notFound()`.
- `LibraryPage.tsx:465`: parses library screens only.
- `error.tsx:24` and `global-error.tsx:24`: the telemetry label for these three URLs becomes `unknown`.
