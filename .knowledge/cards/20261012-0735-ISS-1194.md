## Reproduction (3/3, each a fresh login, cold request)

Against the dev backend on :8000, admin@velocity.ai:

1. `GET /api/runs?limit=100&type=prototype` returns `[]` on attempts 1, 2 and 3.
2. Paging `GET /api/runs?limit=100&offset=0..` (69 runs total) shows the prototype family is only
   `prototype_v2` (8 completed, 5 cancelled, 3 failed), `prototype_v2_revision` (2 completed),
   `prototype_v2_feature_revision` (3 completed), `prototype_revision` (2 completed, 2 failed,
   2 cancelled) and `prototype_large_revision` (1 degraded). No run has type exactly `prototype`.

The Prototype chip on /runs (`framework/locators/run_history.py:43`, `"Prototype": "prototype"`) filters on
`type=prototype`, an exact match, so it selects nothing in this data set.

The report names 4 affected tests; the three above were the ones located here, the fourth was not
identified from the report alone. This is a data gap, not an app defect.

### Root cause (one mechanism)

Three tests find "a completed prototype run" by clicking the Run History "Prototype" chip. The history holds no run that chip counts, so the chip is not rendered, and the tests click it before the data-absence skip they carry, so the gap surfaces as a 30 s locator timeout instead of a skip. A fourth test (ISS-289) reads a breakdown that the same gap collapses to one row, which its locator cannot parse.

CONFIRMED chain:

1. **Click first, skip after.** `tests/integration/e2e/suites/07_run_detail/test_run_detail.py:843-848`:
   ```python
   RH.chip(page, "Prototype").first.click()
   page.wait_for_url("**type=prototype")
   page.wait_for_timeout(settings.SETTLE_MS // 2)
   done = [label for label in RH.rows(page) if RH.status_of(label) == "completed"]
   ```
