# ISS-1100

## Description

Sibling of [ISS-1099](20261008-0016-ISS-1099.md) (the same deleted helper, a different feature), found by the structural scan of `ScopedStore` that [ISS-1099](20261008-0016-ISS-1099.md) describes. Reproduced here, so it is not a lead.

`ScopedStore.write_provenance_audit` (`backend/agents/authz.py:1245`) opens its session with `session, owned = self._acquire()` at `:1266`. `ScopedStore` has no `_acquire` ([ISS-1099](20261008-0016-ISS-1099.md) has the history), so every call raises `AttributeError: 'ScopedStore' object has no attribute '_acquire'`.

## Evidence (observed 2026-10-08, HEAD `5e22d3238`; one file at a time)

- `tests/agents/test_provenance_audit.py`, run alone: **13 failed, 4 passed** (`evidence/qa-kb-097/analysis-10-test_provenance_audit-at-HEAD.txt`). Every failure is `AttributeError … '_acquire'` at `authz.py:1266`, and the observer logs `ProvenanceAuditObserver.handle failed for run=… 'ScopedStore' object has no attribute '_acquire' — commit stands; observer failure is isolated`. Red: `test_completed_run_writes_snapshot_commit_row`, `test_degraded_run_writes_snapshot_commit_row`, `test_legacy_chain_read_writes_chain_payload_installed_row`, `test_restore_writes_row_and_lookup_idempotent_restore`, `test_crash_recovered_run_writes_recovery_commit_row`, `test_audit_row_has_only_typed_columns_no_raw_content`, `test_cross_owner_cannot_read_audit_rows`, `test_bidirectional_reconstruction_via_source_ref`, and `test_each_audited_operation_class_writes_a_row[...]` for all five operation classes.
- A scratch `git archive HEAD` copy with the fix of [ISS-1099](20261008-0016-ISS-1099.md) (`evidence/qa-kb-097/analysis-05-authz-probe.diff`): the same file is **17 passed**.
- Dev database, read-only (`evidence/qa-kb-097/analysis-13-db-selects.txt`): `run_provenance_audits` holds 2 rows in total, both `chain_source_selected` (written by the API layer with its own ORM insert, `run_commands.py`); `snapshot_commit`, `recovery_commit`, `fragment_merge`, `merge_agent_commit` and `chain_payload_installed` have never been written, in a database whose 26 runs with wave rows ran 77 merges (the class that should leave `fragment_merge` rows).
- Caller chain, read: `ProvenanceAuditObserver.handle` (`hooks/provenance_audit.py:130-150`, a system hook, `user_allowed=False`) and `chain_context._write_chain_payload_installed_audit` (`chain_context.py:573-615`) call `runner.record_provenance_audit`, i.e. `KernelServices.record_provenance_audit` (`kernel_services.py:490`), whose `except Exception  # noqa: BLE001` at `:527` logs and returns None; the observer adds a second blanket handler. Two layers of "audit must never abort" turn a missing method into silence.

## Cause (CONFIRMED)

Same as [ISS-1099](20261008-0016-ISS-1099.md): `1e329e47b` deleted `_acquire`, `e7305f9dd` (written before it) added this method calling it, merge `4ebd98e8f` joined them.

## Blast radius

- Every audited commit class the engine writes (`snapshot_commit`, `recovery_commit`, `fragment_merge`, `merge_agent_commit`, through the post-commit observer) plus `chain_payload_installed` (chain-context install): the git provenance trail of Requirement 19 is not being recorded. INFERRED, not checked here: that every workflow's `commit_in_sandbox` dispatches `post_commit` with a non-None `audit_operation`; the dev DB shows no engine-written row for any run either way.
- Not affected: operations the API layer inserts itself (`restore`, `chain_source_selected`, `chain_context_unavailable`, `run_ref_*`; `run_commands.py:2711, 3078-3109, 5125`) and the `chain_unavailable_reason` reader (`runs.py:568`).

## Fix

Same commit and file as [ISS-1099](20261008-0016-ISS-1099.md): move the body of `write_provenance_audit` into `_body(session)` and `return await self._run_bounded("write_provenance_audit", _body, run_id=run_id)`; keep `owner_id=self._owner_id, workspace_id=self._workspace_id` on the row. The 13 tests above are the regression guard, so no new test is needed for this method, only the ones listed in [ISS-1099](20261008-0016-ISS-1099.md).

What a naive fix would break: the same three things as [ISS-1099](20261008-0016-ISS-1099.md). Deleting or xfail-ing the 13 tests would also remove the only coverage of the five audit operation classes.
