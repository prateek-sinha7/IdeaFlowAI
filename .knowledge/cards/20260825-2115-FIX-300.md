## Symptom

Every `ppt` run — with or without a user override — produced a deliverable the preview rejected
with **"Invalid presentation output"**. The deck had no `<!DOCTYPE`, no `<html>`, and 0 slides.

## Root cause

`backend/app/agents/model_factory.py:60` built the local-dev client as
`ChatOllama(model=..., base_url=..., reasoning=True)` — **no `num_ctx`, no `num_predict`**.

Ollama does not honour the model's advertised context. `qwen3.5` reports
`qwen35.context_length = 262144`, but the runtime applies its own default (4096) unless told
otherwise. A deck agent's prompt (template + design system + the previous step's full deck) fills
that window, and generation is cut off mid-token.

Measured on baseline run `190d2263` (no override, so this was never an override defect):

| step | before | after |
|---|---|---|
| `ppt-composer` | 3446 chars, ended `style="height` | 10782 chars, `<!DOCTYPE`, 6 slides |
| `ppt-validator` | 5286 chars, ended mid-attribute | complete |
| run total | 17.9K tokens | 283K tokens |

All three ppt agents declare `max_tokens: 32768`, so the AGENT.md ceiling was never the limit.

## Fix

Pass `num_ctx` (default 32768) and `num_predict` (default 16384), overridable via
`OLLAMA_NUM_CTX` / `OLLAMA_NUM_PREDICT`. Confirmed live in `ollama ps`: the loaded model went
from the implicit 4096 to `32768 ctx`.
