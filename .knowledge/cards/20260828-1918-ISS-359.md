## Summary

In the composer's per-agent Skills tab (`/workflows/new` → agent config panel → Skills tab →
"View details" on any skill card), the modal that opens shows the skill's markdown body as raw
source text — literal `#`/`##` characters visible, no heading elements rendered — instead of
formatted HTML. The skill's own detail page at `/library/skills/<id>` renders the identical
markdown body correctly (`<h2>`/`<h3>` headings etc), so this is a defect in the composer's
preview-modal component, not the skill content.

Register entry: `BUG-20260828-093400-library-skills-id-r2` in `bug-hunter/ledger.md`.

## Reproduction — CONFIRMED 3/3, cold start each time

Cycle 1, 2, and 3 all reproduced, each from a fresh `/dashboard` → `/workflows/new` navigation
(no soft re-click), with a different skill each time:

1. Go to `/workflows/new`, click "Add agent", add "Domain Discovery Agent" to the canvas, click
   the node to open its config panel.
2. Click the "Skills" tab (`[data-testid='tab-skills']`).
3. Type a skill name into `input[data-testid='agent-skills-search']`, click its "View details"
   button (`[aria-label="View <skill name> details"]`).
4. Modal opens (`[role=dialog]`) showing raw markdown.

- Cycle 1: skill "Windows Desktop E2E Testing" — `dialog.querySelectorAll('h1,h2,h3,h4').length === 0`,
  `/^#{1,3} /m.test(dialog.innerText) === true`.
- Cycle 2: skill ".NET Backend Expert" — same result (`# .NET Backend Expert`, `## When to Use`
  visible as literal text).
- Cycle 3: skill "Accessibility (WCAG 2.2)" — same result.

No axis narrowing was needed — reproduced identically on account `qa-admin`, light theme, every
skill tried, every cold load.

## Expected vs Actual

- **Expected:** the modal renders `detailSkill.content` as formatted HTML — headings as
  `<h2>`/`<h3>`, lists as `<ul>`/`<li>` — matching `/library/skills/<id>`.
- **Actual:** the modal dumps the raw markdown string verbatim inside a `<pre>` block; the DOM
  has zero heading elements.

## Root cause

`frontend/src/components/workflow/composer/AgentSkillsPicker.tsx` — the `detailSkill` modal
(around the `role="dialog"` block) renders the skill body as:

```tsx
{detailSkill.content ? (
  <pre className="whitespace-pre-wrap rounded-[8px] border border-line-divider bg-surface-warm p-3 font-mono text-[11px] leading-relaxed text-ink-700">
    {detailSkill.content}
  </pre>
) : (
  ...
)}
```

`detailSkill.content` is the same raw markdown string `/library/skills/<id>` runs through a
markdown renderer. Here it is placed directly as text content of a `<pre>` — no markdown parsing
step exists in this component at all, so every heading/list/bold marker is shown as literal
source characters instead of being interpreted.
