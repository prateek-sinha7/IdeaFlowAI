## Description

duplicate "Run started" card in chat after Run Again

## Root cause

narrator _reply_event_id used source_event_id as idempotency key; resumed run's pipeline_start has new event_id → new card. Fix: pipeline_start cards key on pipeline_start:{run_id} so all pipeline_start events for the same run collapse to one card
