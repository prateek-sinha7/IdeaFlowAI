## What was wrong

`handleVersionMenuSelect` (PreviewPanel.tsx) was wired as `RunHeader.onSelectVersion`
but only called `setSandboxSelectedRef(tag)`. It correctly flipped the Workspace tab
to show the git-tagged snapshot, but never touched `viewingVersion`, so
`effAgents`, `effPipelineState`, and `effAgentOutputs` (the FIX-411 pipeline-data
layer) kept falling back to the raw live-run props. The Steps tab, agent list,
agent-output cards, and AuditTab fetches all continued showing the live run,
regardless of which version was shown in the Workspace and Preview tabs.

This was a regression of ISS-606/608/609 (fixed by FIX-411): Task 11.6 introduced
`handleVersionMenuSelect` as a tag-aware handler to replace the broken original
wiring (`handleSelectVersion` expected a UUID, not a git tag), but re-introduced
the desync on the menu path. The URL path (`/runs/{id}/versions/1`) continued to
work correctly throughout.

A sequencing hazard had to be resolved: `handleSelectVersion` calls
`setViewingVersion`, which changes `activeRunId`, which fires the reset effect
(`useEffect(() => { setSandboxSelectedRef(null); }, [activeRunId])`). Without
a guard, the reset would clear `sandboxSelectedRef` the moment `handleSelectVersion`
completed — killing the Workspace ref immediately after setting it.

Root cause card: [BUG-124](20260915-1300-BUG-124.md).

## What changed

**`frontend/src/components/preview/PreviewPanel.tsx`** — three hunks:

**1. New `intendedSandboxRef` ref** (after `sandboxSelectedRef` declaration):
```tsx
const intendedSandboxRef = useRef<string | null>(null);
```
Carries the intended git tag through the `activeRunId`-change reset without
threading it through `VersionView` or changing `handleSelectVersion`'s signature.

**2. Narrowed reset effect** (was one line, now guarded):
```tsx
useEffect(() => {
  if (intendedSandboxRef.current !== null) {
    setSandboxSelectedRef(intendedSandboxRef.current);
    intendedSandboxRef.current = null;
  } else {
    setSandboxSelectedRef(null);
  }
}, [activeRunId]);
```
When `intendedSandboxRef.current` is non-null, the reset restores the tag
instead of clearing it, then clears the ref. All other `activeRunId` change
paths (URL-pin deep-link, `liveRunId` supersession, `handleBackToLatest`)
leave `intendedSandboxRef.current === null` so they clear `sandboxSelectedRef`
normally — no behavior change on those paths.

**3. Fixed `handleVersionMenuSelect`**:
```tsx
const handleVersionMenuSelect = useCallback((tag: string | null) => {
  if (tag === null) {
    intendedSandboxRef.current = null;
    setSandboxSelectedRef(null);
    if (latestId) void handleSelectVersion(latestId);
    return;
  }
  const member = sortedMembers.find((m) => m.git_tag === tag);
  if (member) {
    intendedSandboxRef.current = tag;
    setSandboxSelectedRef(tag);
    void handleSelectVersion(member.id);
  } else {
    // Fallback: tag not yet on any member (in-progress run, pre-tagging).
    intendedSandboxRef.current = null;
    setSandboxSelectedRef(tag);
  }
}, [latestId, sortedMembers, handleSelectVersion]);
```

**`frontend/src/components/preview/PreviewPanel.sandboxRef.test.tsx`** — one new
`describe` block appended:

`B22 regression guard — version menu calls handleSelectVersion with the member UUID`
- Mounts `PreviewPanel` with a `runFamily` prop carrying two members with `git_tag`
  fields (`"v1"`, `"v2"`).
- Selects `v1` via the VersionMenu.
- Asserts `getWorkflow` is called with the **v1 member UUID** (not the string `"v1"`),
  proving `handleSelectVersion` was reached.
- Asserts `getRunSandboxFile` is called with `ref=v1`, proving `intendedSandboxRef`
  preserved the tag through the reset.
- Asserts the read-only banner renders and no restore control exists.
