## Description

Found, not fixed, while running regression files for [FIX-684](20261001-2129-FIX-684.md) (QA-KB-009). It is
unrelated to that fix: the revision driver path calls neither symbol FIX-684 changed.

`backend/tests/integration/api/test_rest_revisions_api.py::test_driver_happy_path_persists_output_columns`
fails at `test_rest_revisions_api.py:412`, `outputs = json.loads(row.agent_outputs)`:
`TypeError: the JSON object must be str, bytes or bytearray, not NoneType`. The run row is `completed` and its
`output` is set (the two asserts before it pass); `agent_outputs` is NULL.

## Evidence (observed)

- Shared working tree with FIX-684 applied: file result 1 failed, 24 passed.
- Scratch copy of the shared tree with `backend/app/api/run_commands.py` and `backend/agents/registry.py`
  restored from HEAD: same single failure.
- Clean export of HEAD `024c03ef8` (`git archive 024c03ef8 backend`), run with `backend/.venv/bin/python`:
  1 failed, 24 passed, the same test. So it is red at HEAD and predates the 2026-10-01 QA-KB fixes.

## Mechanism (INFERRED from reading, not run in isolation)

The outputs collector in `backend/app/api/run_commands.py` (`agent_outputs_collector`, around `:3916-4019`)
keys every row on `(data["agent_id"], data["task_id"])`, opens it on `agent_start`, and appends a row on
`agent_complete` only `if row.get("agent_id")` (`:3999-4000`). The test's stub sends `agent_id` on
`agent_start` only; its `agent_chunk` and `agent_complete` events carry no `agent_id`, so they land on a
`(None, "")` row that is never appended, and `wr.agent_outputs` is never written (`:4018-4019`). Either the stub
is stale (the engine now emits `agent_id` on every agent event) or the collector lost the "current agent"
behaviour the test was written against. Which one has not been established.

## Disposition

Open, not analyzed. The test file was last touched in `09270703b` (2026-09-22, "Fix/testcases (#9)"). The
analyzer should settle the direction before anyone edits the test or the collector.

## Analysis (QA-KB-073, 2026-10-02)

**Verdict (CONFIRMED): the stub is stale; the collector is right.** Fix the test. `backend/app/api/run_commands.py` is not
touched. [ISS-949](20261002-0107-ISS-949.md) (QA-KB-061, cause C) reached the same verdict from the launch side; this
analysis re-derives it independently, bisects it, and finds two more tests with the same fault
([ISS-1013](20261002-0547-ISS-1013.md)).

### Root cause (CONFIRMED, every line read on the working tree)

1. **The collector keys each row on the event's own ids.** `_apply_terminal_output_columns`
   (`backend/app/api/run_commands.py:3919`) keeps one open row per `(agent_id, task_id)` (`:3945-3949`, key at `:3958`), closes it
   on `agent_complete` / `agent_error` (`:3978-3981`, `:4017-4034`) and appends it only `if row.get("agent_id")` (`:4028`,
   `:4033`). `wr.agent_outputs` is written only when that list is non-empty (`:4046-4047`, the sole writer of the column).
2. **The stub names the agent once.** `test_rest_revisions_api.py:362-371` gives `agent_start` an `agent_id`; the `agent_chunk`
   (`:373`) and `agent_complete` (`:374-384`) carry none. They land on a `(None, "")` row that the complete closes and drops, and
   the real row opened by `agent_start` is never closed. The list stays empty, `agent_outputs` stays NULL, and
   `json.loads(None)` raises at `:412`.
3. **It worked until one commit, measured.** `77b52bb3d` (2026-09-29, "per-model pricing and the cache split in run usage",
   [FIX-652](20260929-1022-FIX-652.md)) replaced a single `current_agent` slot with the keyed `open_agents` dict
   (`git show 77b52bb3d -- backend/app/api/run_commands.py`). With the slot an id-less chunk or complete inherited the open
   agent, which is what this stub relies on. `git archive 77b52bb3d^ backend` (`a56c90506`, `open_agents` appears 0 times): the test
   PASSES. `git archive 77b52bb3d backend` (4 times): it FAILS with the same `TypeError`. The test file was last touched on
   2026-09-22 (`09270703b`), before the commit.
4. **Why the collector is the right side.**
   - Every real producer stamps `agent_id` on every event the collector reads: `engine.py:9594` agent_start, `:9955` agent_input,
     `:10192` agent_chunk, `:10205` agent_thinking, `:10238` tool_call, `:10288` tool_result, `:10886` agent_complete, and all six
     agent_error sites (`:7339`, `:10529`, `:10582`, `:11093`, `:11126`, `:14345`); the capability emitters
     (`assemble_step.py:890-925`, `publish_step.py:134-172`, `prototype_ui_extract.py:377-405`, `backlog_assemble.py:2010-2065`),
     `wave_scheduler.py:370` and `:643`, and `revision_analyzer.py:127-183`. A read-only AST pass over `backend/agents` and
     `backend/app` finds 33 literal events of the collector's vocabulary, 32 with `agent_id`; the 33rd (`engine.py:9973`) carries
     a dict built with it at `:9955`.
   - The characterization goldens, recorded from real engine runs, hold 68 agent_chunk, 42 agent_input, 42 agent_complete, 42
     agent_start, 17 tool_call and 17 tool_result events (`backend/tests/agents/characterization/golden/*.events.json`); none
     lacks `agent_id`.
   - An id-less event cannot be attributed when members run in parallel. `run_commands.py:3945-3948` records why the slot went
     (run c4cbd381 kept 55 of 63 workers) and `backend/tests/unit/app/test_run_row_token_usage.py::test_every_parallel_member_keeps_its_own_row`
     (3 passed) pins the keyed behaviour. Wave-worker events get `task_id` stamped on every pushed child event
     (`backend/agents/execution_engine/fanout.py:574-579`), so the key holds for them as well.
   - The revision driver hands the engine's events on unchanged (`run_commands.py:5771`), so a real revision is unaffected.

**INFERRED, not run.** [FIX-652](20260929-1022-FIX-652.md) lists five unit files in `verification.test_files` and none of the
integration files that went red, so they were most likely never run after the commit (red from 2026-09-29 until the
2026-10-01 sweep). A future capability emitter that omits `agent_id` would lose its row without a log line (the guard at `:4028`
is silent); no producer does today and no card is filed, because nothing is broken.

### Fix, and where it belongs (test-only)

In `backend/tests/integration/api/test_rest_revisions_api.py`, inside `_rich`: add `"agent_id": "user-stories-revision-agent"`
to the `agent_chunk` data (`:373`) and to the `agent_complete` data (`:376-383`). Keep every assertion, including
`outputs[0]["agent_id"]` (`:414`): it is the real contract. Optionally drop the "RED today" sentence from the docstring
(`:355-356`), which describes the pre-ISS-152 driver and is wrong once this is green.

Probe (a scratch copy of the working tree, repo untouched): with exactly those two keys the file goes from 1 failed, 24 passed to
25 passed, with `run_commands.py` unchanged.

It belongs in the stub because that is the only side that has drifted from the emit contract, and no product caller needs a
change. No shared stub helper is added (skipped: one more abstraction for five hand-rolled stubs; add it when a sixth drifts).

**Shared edit with ISS-949.** Its fix plan item 3 also adds `agent_id` to this test ("fix it once, in whichever bug's fix reaches
it first, and do not have both edit it"). Whichever fixer arrives second finds the test green: run the single test, record it,
and do not edit again. The globs of this card are the test file only; `run_commands.py` is read-only evidence here, so this card
does not serialize behind every other fixer that edits it.

**What a naive fix would break.**
- Restoring a "current agent" slot, or inheriting the last open agent for an id-less event, in the collector re-breaks
  parallel-member attribution: `test_every_parallel_member_keeps_its_own_row` fails and the c4cbd381 loss (55 of 63) returns.
- Tolerance added inline in one driver violates INV-12 (one shared event-to-column mapping, `run_commands.py:3926`, `:3937-3941`).
- Dropping the `agent_id` assertion at `:414` hides the contract instead of restoring it.
