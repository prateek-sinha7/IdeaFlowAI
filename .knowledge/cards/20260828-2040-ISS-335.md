## Root cause (traced, same mechanism as ISS-231)

`filteredAgents` (`LibraryPage.tsx:601-609`) is `ALL_AGENTS_COMBINED.filter(agent => matchesCategory
&& matchesSearch)`, and `matchesSearch` is `!searchQuery || ...` — trivially `true` whenever the
search box is empty. So `activeCategory` alone, with **no text typed**, can drive `filteredAgents`
to `[]` just as effectively as a non-matching search string.

The Agents category pills render a **live, real count per category**
(`{cat.label}<span className="opacity-50">{count}</span>`, computed at `LibraryPage.tsx:714-715`
from the same `ALL_AGENTS_COMBINED.filter(a => agentMatchesPipelineType(...))` predicate). That
count is visible and correct today — the bug's own evidence text names one directly: "the category
pills (All 94, App Builder 15, Retry Loop 0, …)". A category already advertising `0` is a normal,
always-rendered, clickable pill (`CATEGORIES` at `LibraryPage.tsx:437-446` has no `count > 0`
filter). Clicking it sets `activeCategory` and the grid renders through the exact same unguarded
`filteredAgents.map(...)` at `LibraryPage.tsx:735` that ISS-231 already proved has no
`length === 0` branch — so the identical blank-grid symptom reproduces via a different, arguably
more discoverable trigger (a user can see "0" printed on the pill and still get a silent blank
grid instead of "No App Builder... wait, Retry Loop agents match", i.e. no confirmation the 0 they
saw is what they now see).

The same shape holds for the other two tabs: `skillCategory` narrows `filteredSkills`
(`LibraryPage.tsx:620-626`, rendered via `activeSkills.map` at `818`) and `hookEvent` narrows
`filteredHooks` (`LibraryPage.tsx:631-637`, rendered at `914`) — both through the identical
`matchCat && matchSearch` shape with an empty search string. The Skills/Hooks category pills
(`SKILL_CATEGORIES.map` at `796`, `HOOK_EVENTS.map` at `896`) do not print a live count the way the
Agents pills do, so those two paths are less immediately discoverable, but the code path is the
same unguarded map.

## Expected vs actual

- **Expected:** selecting a category/event pill that yields zero matches shows the same
  empty-state messaging a zero-result search is expected to show (the fix ISS-231 calls for).
- **Actual (inferred):** the grid renders blank with no messaging — reachable without ever typing
  into the search box.

## Why the root cause implies this

ISS-231's root cause is "no `length === 0` render branch on `filteredAgents`/`activeSkills`/
`filteredHooks`." That array's emptiness is driven by **two independent inputs** —
`matchesCategory` and `matchesSearch` — not just the search box. A fix keyed narrowly on "was
there a search string" (e.g. `searchQuery && filteredAgents.length === 0 ? <Empty/> : ...`) would
close ISS-231's literal repro while leaving this path silently broken. This card exists so the fix
is verified against the array's actual `length`, not against the search-input's presence.

## Reproduction (to confirm)

1. Cold-load `/library` (Agents tab, default).
2. Do NOT type in the search box.
3. Click a category pill whose count already reads `0` (e.g. "Retry Loop 0", per the bug's own
   evidence) — or any category pill if the seed data's zero-count category has since changed.
4. Expect: same blank grid, no empty-state messaging, as ISS-231's Cycle 1-3.
