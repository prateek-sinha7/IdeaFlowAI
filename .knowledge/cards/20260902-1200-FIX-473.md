## What was wrong

`computeRootLayout` (graphLayout.ts) built its edge set from exactly two sources:
chain edges where `hasChainEdge(i)` holds and `trigger:"step"` route outcomes.
`depends_on` entries from a step's manifest declaration were never read.

This is latent for canvas-authored workflows, where the composer keeps array order
aligned with the chain so `depends_on` and adjacency agree. It bites workflows
authored through the API or a hand-written `workflow.yaml`, where `depends_on` is
the real graph — the same assumption class that produced ISS-175. ADR-0004 establishes
that a declared `depends_on` OVERRIDES the inferred DAG; the canvas layout did not
honour that.

Observed on the "EDGE 5-outcome fan + two gates converging" fixture
(`23a9ec7b-2ec0-4a98-8eaf-de816dec7d03`): `gate-b` declares
`depends_on: [custom-agent:w2]` and is a plain array successor of `gate-a`; no
chain edge and no route outcome pointed at it, so it ranked at column 0.

## Root cause

Three files:

1. **`frontend/src/types/index.ts`** — `AgentDef` had no `depends_on` field.
2. **`frontend/src/store/api/userWorkflows.ts`** — `manifestStepToAgent` did not
   propagate `step.depends_on` onto the reconstructed `AgentDef`.
3. **`frontend/src/components/workflow/composer/graphLayout.ts`** —
   `computeRootLayout` had no pass that reads `agent.depends_on`.

## What changed and why there

### `frontend/src/types/index.ts`

Added optional field to `AgentDef`:
```ts
/** Declared upstream dependencies — mirrors ManifestStep.depends_on.
 *  Populated by manifestStepsToAgents from a saved/API manifest.
 *  Used by computeRootLayout as a third edge source (ISS-178). */
depends_on?: string[];
```

### `frontend/src/store/api/userWorkflows.ts`

Added propagation in `manifestStepToAgent`, after the `agent.route` assignment:
```ts
agent.depends_on = step.depends_on?.length ? [...step.depends_on] : undefined;
```

### `frontend/src/components/workflow/composer/graphLayout.ts`

Added a third edge-source pass after the route-outcomes loop:
```ts
// ISS-178 — declared depends_on as third edge source (ADR-0004).
for (const agent of pipelineAgents) {
  if (!agent.depends_on?.length) continue;
  for (const depId of agent.depends_on) {
    if (!depId || from === to) continue;
    if (!allNodeIds.has(from) || !allNodeIds.has(to)) continue;
    if (inEdges.get(to)?.has(from)) continue; // already present
    outEdges.get(from)?.add(to);
    inEdges.get(to)?.add(from);
  }
}
```

Skips: self-loops, ids not in `allNodeIds` (guards against a stale/dangling reference
in an API-authored manifest), and edges already established by chain/route passes
(de-duplication, not override).

`depends_on` is never written by `agentsToManifestSteps` for canvas-authored nodes
(`it is DERIVED at serialise time`) so this field is always `undefined` on
canvas-authored `AgentDef`s — the new pass is a no-op for normal usage.
