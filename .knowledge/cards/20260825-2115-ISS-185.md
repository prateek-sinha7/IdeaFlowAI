Observed repeatedly during ppt runs:

```
tool_call: ls args={'path': '/skills/html-ppt'}                              -> []
tool_call: ls args={'path': '/skills/html-ppt/templates/full-decks/pitch-deck'} -> []
```

`ppt-composer`'s own output preamble read: *"Based on my analysis, the filesystem paths in the
SKILL.md don't exist."*

This is the mount-point mismatch the `ppt/workflow.yaml` header comment already documents — a
skill staged at `/skills/html-ppt/SKILL.md` resolves its sibling references skill-relative, while
the seeded files sit at `/references/`. The manifest works around it by attaching no skills and
delivering the same content through `injects: [template, template_example]`.

**Impact:** not fatal — decks render, because the template pipe supplies the content — but each
agent burns turns on failed lookups, and the model reasons out loud about missing files.

**Disposition:** resolved by [FIX-431](20260831-1829-FIX-431.md) — the first option: `stage_skills`
now copies the catalog folder's sibling files (SKILL.md excluded) next to the staged copy.
