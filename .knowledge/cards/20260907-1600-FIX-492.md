## Symptom

In the Model Details panel, clicking the collapse arrow on the first model (Haiku 4.5)
did not collapse it. The arrow appeared to be unresponsive. Only the second click
would collapse it. Sonnet 5's arrow worked correctly on the first click.

## Root cause

`frontend/src/components/analytics/AnalyticsPage.tsx`:

```tsx
// Broken logic
const isExpanded = expandedModels.size === 0 ? idx === 0 : expandedModels.has(m.id);
const toggle = () => setExpandedModels(prev => {
  const next = new Set(prev);
  if (next.has(m.id)) next.delete(m.id);
  else next.add(m.id);           // ← first click: set was empty → add → still open
  return next;
});
```

When `expandedModels` is empty (initial state), `idx === 0` makes Haiku appear
expanded. But Haiku's id is NOT in the set. Clicking the toggle sees
`!next.has(haiku_id)` = true → calls `next.add(haiku_id)` → set size becomes 1 →
`expandedModels.has(haiku_id)` = true → still expanded. A second click then removes
it correctly.

## Fix

Removed the implicit fallback entirely. Added a `useEffect` that seeds `expandedModels`
with the top model's id whenever `summary` loads:

```tsx
useEffect(() => {
  if (!summary) return;
  const firstId = (summary.models ?? [])
    .filter(m => m.model_id !== "unknown")
    .sort((a, b) => b.total_tokens - a.total_tokens)[0]?.model_id;
  if (firstId) setExpandedModels(new Set([firstId]));
  else setExpandedModels(new Set());
}, [summary]);
```

`isExpanded` is now purely `expandedModels.has(m.id)`. First click on Haiku:
`next.delete(haiku_id)` → set empty → `has(haiku_id)` = false → collapses correctly.

Also removed the `idx` parameter from the map callback (now unused) and replaced the
`idx > 0 ? "pt-2" : ""` padding with `border-t border-line-faint-row first:border-t-0`.
