# FIX-187

**Phase / trigger:** Phase 32 (OD wizard), ISS-052

## Description

When a user uploads a custom HTML template via `CustomTemplateModal` and launches
an `od_prototype` or `od_ppt` run, the uploaded HTML is silently discarded.
The run appears to succeed but uses a generic catalog template's instructions
instead of the user's own reference.

## Root Cause

Both `load_prototype_context` and `load_ppt_od_context` in `od_context.py`
check `custom_template_body` only for truthiness to select a catalog fallback:

```python
# load_prototype_context (lines 62-74, BEFORE):
if custom_template_body:
    template = od_loader.get_template("web-prototype")  # ← catalog loaded
    # user's HTML is never referenced again

# load_ppt_od_context (lines 214-220, BEFORE):
if custom_template_body:
    template = dict(od_loader.get_ppt_template("html-ppt") or {})
    template["id"] = template_id  # just relabels dict
```

The returned dict's `template_body` key always contained the fallback catalog's
`SKILL.md` content. Both downstream injection sites (`factory._compose_injection`,
`OpenDesignProvider.load`) only read `od.get("template_body")` — so the catalog
content, not the user's HTML, reached the agents.

## Fix

**Edit 1 — New helper `_synthesize_custom_template(template_id, custom_template_body)`**
(inserted before `load_prototype_context`):
- Strips and caps the raw HTML at `EXAMPLE_MAX_CHARS` (the single authoritative cap, INV-12)
- Returns a minimal template-dict-shaped object with the HTML embedded in `"body"` under
  a short instruction preamble directing the agent to use it as a reference

**Edit 2 — `load_prototype_context`**: Replace the `web-prototype` catalog fallback branch
with `_synthesize_custom_template(template_id, custom_template_body)`. Log `info` instead
of `warning`. The rest of the function (DS loading, craft rules, return statement) unchanged.

**Edit 3 — `load_ppt_od_context`**: Replace the `html-ppt` catalog fallback branch with the
same `_synthesize_custom_template` call. `ds_requires` derivation from `template.get(...)` 
stays correct — synthesized dict has no `"design_system"` key, evaluates `False` same as
`html-ppt`'s `design_system: requires: false` (confirmed equivalent behavior).

## Invariants Verified

- **INV-3** — golden-neutral by construction: the new code path only fires when
  `get_template(template_id)` returns `None` AND `custom_template_body` is truthy.
  No golden or existing pinned test constructs this combination (all pass `custom_template_body=None`)
  — goldens unaffected ✅
- **INV-12** — old catalog-fallback branches deleted (not kept alongside); single
  `_synthesize_custom_template` helper ✅
- **INV-1/SC-001** — no `pipeline_type` branch; fix uses only existing function params ✅
- **INV-13** — no agent-runtime code touched ✅
