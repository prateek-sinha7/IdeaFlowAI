# ISS-027

## Title

"Skip all & run directly" does not skip clarification. handleQuestionnaireSkip (DashboardLayout.tsx:932) sends submit_questionnaire with empty responses — identical to answering nothing — so the clarify engine (clarify_engine.py) re-evaluates, finds info still missing, and re-asks. It issues up to 3 rounds before clarification_limit_reached → pipeline_start. A user clicking the button once sees a NEW "Quick Setup" panel appear (looks like the skip failed); they must click it ~3×. Behavior contradicts the button's label. FIX (Option A, proper force-proceed): the skip button now sends a distinct skip_clarification: true on submit_questionnaire; the WS handler (websocket.py:1046) threads it to ArtifactStore.set_questionnaire_responses(..., skip_clarification=True) which records a per-run _questionnaire_force_proceed flag; ClarifyEngine.run reads it right after event.wait() and returns execution_gate=PROCEED immediately (no re-ask). Generic (SC-001 — no pipeline_type branch); INV-3-safe because the goldens compile clarify.mode="off" so ClarifyEngine.run is never reached — proven: the 5 characterization goldens stay byte-identical + banned-patterns gate green. FE: useWorkflow.submitQuestionnaire + DashboardLayout.handleQuestionnaireSkip pass skipClarification=true; ordinary answer submits leave it False (byte-identical default). Tests added: test_execution_engine.py::test_clarify_engine_skip_clarification_force_proceeds_round_1 (drives the real engine: asks once → PROCEED, no limit-reached) + ::test_clarify_engine_empty_submit_without_flag_still_loops (regression guard: no flag ⇒ still 3 rounds) + test_artifact_store.py flag tests. Not a functional break — was bounded at 3 rounds. Evidence: live WS probe 2026-06-14 — run_pipeline(user_stories) → questionnaire_ready ×3 (each needing a submit) → clarification_limit_reached → pipeline_start → agent_start. Surfaced during the live E2E pass (TS-V-01 deadlocked on round 2; the live spec's single-shot dismiss was fixed to loop — dismissClarifyRounds). Live re-confirm (1× questionnaire_ready then pipeline_start on skip) deferred to the next live pass.
