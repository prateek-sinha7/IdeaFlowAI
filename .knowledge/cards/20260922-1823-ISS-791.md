## Summary

Found while applying [FIX-609](20260922-1822-FIX-609.md) (bug QA-PS-023). Deferred,
not fixed — it is outside the three cards that bug carried, and changing it alters
the materialized bytes (and therefore the mint/tag decision) for **every**
`streamed_text` run, which needs its own validation.

## The divergence

`backend/agents/execution_engine/engine.py:1337-1348` materializes the flat payload
for a `streamed_text` deliverable with no transform at all:

```python
_raw_streamed = getattr(ectx, "last_streamed", "") or ""
if _raw_streamed:
    _streamed_text = _raw_streamed
```

`StreamedTextResolver.resolve()`
(`backend/agents/capabilities/deliverables/streamed_text.py:46-50`) applies two:

```python
return strip_pre_document_prose(unwrap_artifact(last_streamed))
```

The sibling `ppt` block immediately below (`engine.py:1364-1389`) DOES mirror its
resolver's chain — its comment says so explicitly ("same functions
`PptResolver.resolve()` calls (PARITY-07, move-don't-copy)") and FIX-609 kept that
mirror in parity. The `streamed_text` block has no such mirror and never did.

## Consequence

`_streamed_text` is written to `_output_basename` at `engine.py:1459-1468`. So for a
`streamed_text` run whose last agent emitted an `<artifact>` wrapper, or reasoning
prose ahead of its HTML, the **materialized payload file** keeps bytes the
**Preview tab** no longer shows. That payload feeds git versioning and the chain
admission gate, so a chained downstream run ingests the preamble the user was told
had been removed.

## Status

Confirmed by direct read of both call sites (quoted above); reachability of the
divergence itself is certain (the two code paths are unconditionally different).
NOT reproduced end-to-end — that needs a completed `streamed_text` run whose last
agent wrapped or prefixed its output, then a diff of the materialized file against
the run's `final_output`.

## Fix direction (not applied)

Either give the `streamed_text` block the same two-call mirror the `ppt` block has,
or — better, and the reason this is deferred rather than patched — have
`build_flat_payload` materialize from the resolver itself instead of keeping two
hand-maintained copies of each chain. The second removes the whole class of
divergence but is a real refactor of the payload path, not a bug fix.
