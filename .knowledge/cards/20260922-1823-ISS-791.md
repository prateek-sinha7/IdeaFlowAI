## Summary

Found while applying [FIX-609](20260922-1822-FIX-609.md) (bug QA-PS-023). Deferred,
not fixed — it is outside the three cards that bug carried, and changing it alters
the materialized bytes (and therefore the mint/tag decision) for **every**
`streamed_text` run, which needs its own validation.

## The divergence

`backend/agents/execution_engine/engine.py:1337-1348` materializes the flat payload
for a `streamed_text` deliverable with no transform at all:

```python
_raw_streamed = getattr(ectx, "last_streamed", "") or ""
if _raw_streamed:
    _streamed_text = _raw_streamed
```

`StreamedTextResolver.resolve()`
(`backend/agents/capabilities/deliverables/streamed_text.py:46-50`) applies two:

```python
return strip_pre_document_prose(unwrap_artifact(last_streamed))
```

The sibling `ppt` block immediately below (`engine.py:1364-1389`) DOES mirror its
resolver's chain — its comment says so explicitly ("same functions
`PptResolver.resolve()` calls (PARITY-07, move-don't-copy)") and FIX-609 kept that
mirror in parity. The `streamed_text` block has no such mirror and never did.

## Consequence

`_streamed_text` is written to `_output_basename` at `engine.py:1459-1468`. So for a
`streamed_text` run whose last agent emitted an `<artifact>` wrapper, or reasoning
prose ahead of its HTML, the **materialized payload file** keeps bytes the
**Preview tab** no longer shows. That payload feeds git versioning and the chain
admission gate, so a chained downstream run ingests the preamble the user was told
had been removed.

## Status

Confirmed by direct read of both call sites (quoted above); reachability of the
divergence itself is certain (the two code paths are unconditionally different).
NOT reproduced end-to-end — that needs a completed `streamed_text` run whose last
agent wrapped or prefixed its output, then a diff of the materialized file against
the run's `final_output`.

## Fix direction (not applied)

Either give the `streamed_text` block the same two-call mirror the `ppt` block has,
or — better, and the reason this is deferred rather than patched — have
`build_flat_payload` materialize from the resolver itself instead of keeping two
hand-maintained copies of each chain. The second removes the whole class of
divergence but is a real refactor of the payload path, not a bug fix.

### 2. Why two copies exist (CONFIRMED)

The finalizer runs in the `finally` of `_execute_impl` — `finalize_terminal_run(...)` at
`engine.py:7651`, reaching `build_flat_payload` at `engine.py:2323` — BEFORE the terminal block
sets `ectx.last_streamed` and resolves `final_output` (`engine.py:7808-7819`). The engine says
so itself at `engine.py:8163-8168`: "the finalizer ran in the `finally` ABOVE — before the
deliverable was resolved". `build_flat_payload` therefore cannot reuse `final_output`, and each
strategy branch re-derives the bytes from `ectx` by hand. The `ppt` branch copied its
resolver's chain when it was written; the `streamed_text` branch never did, and every later
resolver change (FIX-609's prose strip, FIX-623's format render) has to be mirrored by hand.
`build_flat_payload` has exactly one production caller, `finalize_terminal_run`
(`engine.py:2323`); the only other code that turns `ectx.last_streamed` into bytes is the
`streamed_text`, `ppt` and `single_file` resolvers and the `ppt` block at `engine.py:1513`
(the human gate reads it too, `gates/human.py:128`, but only to show a reviewer).

### 5. Where the fix belongs, and what shapes it

**One place: `build_flat_payload`** (`engine.py:1480-1491`), the function every consumer above
reads through — not the consumers.

```python
_resolved = _CAPABILITY_REGISTRY.resolve("deliverable", "streamed_text").resolve(ectx)
if _resolved:  # empty AFTER the transforms is not a claim (the rule the ppt block already applies)
    _streamed_text = _resolved
```

- **Take the resolver, not the two-call mirror.** The "Fix direction" above and
  `BUGS.md#qa-kb-056`'s "minimal alternative" both mirror `strip_pre_document_prose(
  unwrap_artifact(raw))`. That leaves [ISS-979](20261002-0409-ISS-979.md) open and adds a third
  hand-copied chain (the `ppt` block is the second; FIX-609 had to patch both by hand). Importing
  the helpers into the kernel is not an import-linter violation — the `ppt` block already does
  it — but MOD-backend-agents "Why this shape" is that the kernel resolves capabilities by
  `(kind, name)`, and `_artifact.py`'s own header cites INV-12, move-don't-copy.
- **The "real refactor" above is smaller than the card feared for these two strategies.**
  `StreamedTextResolver.resolve` is pure over `ectx.last_streamed` and `ectx.deliverable.name`
  — no runner, no sandbox, no write — and `_CAPABILITY_REGISTRY` is a module global
  (`engine.py:3464`). Verified in a bare process: `resolve("deliverable","streamed_text")` ->
  `StreamedTextResolver`, `resolve("deliverable","ppt")` -> `PptResolver`. The unit-test `ectx`
  stubs carry both attributes.
- **Do NOT route `single_file` or `serialized_sandbox` through the registry in the same
  change.** `SingleFileResolver.resolve` can WRITE to the sandbox (`publish_from_glob`,
  `single_file.py:116-131`), which a finalizer must not trigger, and the bundle has to be
  computed before the staging dir exists (`engine.py:1452-1454`).
- **Optional, same pattern:** collapse the `ppt` block (`engine.py:1507-1534`) onto
  `resolve("deliverable","ppt")`; parity is verified today, so it is behaviour-neutral and
  removes the second copy.
- **Preserve** the disk-file-wins precedence (`not (sandbox.root / _output_basename).is_file()`,
  `engine.py:1484`), the best-effort contract (the function documents that it never raises,
  `engine.py:1389-1391` — wrap the call as the `ppt` block wraps its transform), and the
  three-file allowlist.
- **Behaviour changes to call out in the FIX card** (both are the point, neither is incidental):
  `.html`-declared streams change from markdown to the rendered document
  ([ISS-979](20261002-0409-ISS-979.md)); a stream that resolves to empty
  (`<artifact></artifact>`) changes from `completed` + `v1` to `degraded`
  (`output_unmaterializable`), no tag ([ISS-980](20261002-0409-ISS-980.md)). That is the
  "alters the mint/tag decision" warning in this card, now with an exact input.

### 6. Reviewed and deliberately NOT filed

- **`serialized_sandbox` narration guard.** `SerializedSandboxResolver.resolve` withholds a
  narration-only bundle (`serialized_sandbox.py:58`, [ISS-763](20260922-1426-ISS-763.md) /
  [FIX-612](20260922-1838-FIX-612.md)); the `_bundle_text` branch (`engine.py:1456-1469`) has
  no such check. Not filed: the engine's completion gate already degrades such a run
  (`engine.py:8111-8114`), and aligning the payload would mean following the engine's
  fall-through to `streamed_text`, i.e. materializing the narration anyway — a behaviour
  decision, not a bug fix.
- **`repo_diff`** (`sample_brownfield`): no branch in `build_flat_payload`, and its resolver
  returns a dict, so by reading it ends `output_unmaterializable` (INFERRED, not executed). A
  sample workflow, and a missing branch rather than a wrong one; not implied by this root cause.
- **Strategy `None`.** `DeliverableSpec.strategy` is Optional (`plan.py:361`) and the engine
  resolves a missing one as `streamed_text` (`engine.py:7810`), while `build_flat_payload`
  reads `""` (`engine.py:1425-1427`) and has no branch. No in-tree manifest omits `strategy`
  (surveyed), so it is latent.
- **`_write_chain_payload`** (`engine.py:1115`, the v1 nested writer): no production caller
  (only tests; comment at `engine.py:7624-7625`), and it copies a sandbox file, never
  `last_streamed`. It is the mechanism [ISS-838](20260922-2024-ISS-838.md) names, which is why
  that card does not describe the live path — see ISS-979.
