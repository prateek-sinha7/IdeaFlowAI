# ISS-802

## Description

Confirmed for bug **QA-PS-049** (see `LEDGER.md` / `BUGS.md#qa-ps-049`).
Clicking any agent in a completed run's Steps tab (`/runs/{id}/steps?agent={agent-id}`)
fires `GET /api/runs/{id}/artifacts` twice, back-to-back, with identical
parameters and identical 13.4 KB responses.

## Reproduction (3/3, cycle 1)

3/3 cold-start cycles — each a fresh navigation to `/dashboard` then a fresh
`page.goto()` to a completed run's `/steps` URL, clearing network state
between cycles, then clicking a different agent each time:

- Cycle 1: run `8088430c-32aa-4551-ad24-f5fd806e872b`, clicked "Emoji Picker"
  → `GET .../artifacts` ×2 (requests #89, #90)
- Cycle 2: run `8091de6b-3350-41fa-9ae1-b19c6ca422a9`, clicked "Greet"
  → `GET .../artifacts` ×2 (requests #91, #92)
- Cycle 3: run `6f38a566-8f7a-45ee-bdda-30e6564ebbfe` (a 9-agent pipeline),
  clicked "Security Audit Agent" → `GET .../artifacts` ×2 (requests #91, #92)

100% reproducible on every agent, every run, every cycle — not intermittent,
no axis-narrowing needed.

Evidence: `evidence/qa-ps-049/01-validate-attempt1-agent-detail-open.png`,
`evidence/qa-ps-049/02-validate-attempt1-artifacts-call1.txt`,
`evidence/qa-ps-049/03-validate-attempt2-agent-detail-open.png`,
`evidence/qa-ps-049/04-validate-attempt3-agent-detail-open.png`.

## Root cause

`frontend/src/components/results/ArtifactVersionPicker.tsx:104-119`:

```tsx
useEffect(() => {
  contentCache.current.clear();
  if (!runId) { setVersions([]); return; }
  let cancelled = false;
  (async () => {
    try {
      const { getRunArtifacts, getToken } = await import("@/lib/api");
      const resp = await getRunArtifacts(getToken() || "", runId);
      if (!cancelled) setVersions(collapseVersions(resp?.artifacts ?? [], agentId));
    } catch { if (!cancelled) setVersions([]); }
  })();
  return () => { cancelled = true; };
}, [runId, agentId]);
```

`ArtifactVersionPicker` is mounted once per agent selection, from
`AgentDetailPanel.tsx:1425` (the only `<ArtifactVersionPicker>` call site —
confirmed by `grep -n "ArtifactVersionPicker" frontend/src/components/results/AgentDetailPanel.tsx`).
This is a SINGLE component with a SINGLE list-fetch effect, not the "two
components independently call `getArtifacts` on mount" the report's Root
Cause section guessed (`AgentThinkingTab.tsx`/`StepsOverviewSpine.tsx` were
checked — neither imports or calls `getRunArtifacts`).

The doubling is `next dev`'s React StrictMode: this frontend runs via
`next dev` on port 3000 (confirmed — `ps -p $(lsof -ti:3000) -o ppid=` walks
to `node .../frontend/node_modules/.bin/next dev`), and `next.config.ts`
sets no `reactStrictMode` override, so Next 16.2.4's default (`true`)
applies. StrictMode mounts every component twice in dev
(mount → unmount → remount) specifically to surface effects with no
cleanup/dedupe guard; this effect's `cancelled` flag guards against setting
state after unmount but does nothing to prevent the fetch itself firing
twice, so both mounts each call `getRunArtifacts` once — exactly the
24ms-apart, byte-identical pair the report captured. This is the same
shape already catalogued for other unguarded mount effects in this
codebase (`[ISS-784](20260922-1812-ISS-784.md)` —
`HomeLaunchGrid.tsx`'s `analytics/summary` effect;
`[ISS-794](20260922-1827-ISS-794.md)` — `[...view]/page.tsx`'s
`signedIn`/`getMe` effect), applied here to a third, previously
undocumented call site.

Because the double-mount is a `next dev`-only diagnostic behaviour, a
production build (`next build && next start`) would not exhibit this
specific doubling — but this environment (and the one the QA tier signs
into) runs `next dev`, so it is a live user-facing defect here.

## Expected vs actual

- Expected: selecting an agent fires `GET /api/runs/{id}/artifacts` once.
- Actual: fires twice, doubling the 13.4 KB payload to 26.8 KB per agent
  click.

to whether the route's client fiber tree gets a genuine fresh mount vs. a
soft client-side transition reusing it; not a selector/fixture failure
either time it reproduced.

Previously: manual verification only, via the MCP network-request log
across 3 independent cold-start cycles on 3 different runs and 3 different
agents, all three showing the identical duplicate-GET pattern.

## Fix (fixer pass, 2026-09-22) — [FIX-636](20260922-2352-FIX-636.md)

Fixed in the effect this card names. `ArtifactVersionPicker.tsx:120` now runs
`if (cancelled) return;` right after `await import("@/lib/api")`. StrictMode's
mount, cleanup and remount all finish before that `await` resumes, so the first
mount, which React throws away, returns before it fetches. One request remains.

- e2e test above: `XPASS(strict)` on 3 of 3 runs. The marker is left in place for
  the 6-verifier.
- New test `frontend/src/components/results/ArtifactVersionPicker.iss802.network.test.tsx`,
  added to `test_files` above. It counts requests at `fetch`: 2 with the guard
  removed, 1 with it in place. It has no `xfail` marker, so it should simply pass.
- Live check in real Chrome, 3 cold deep-links: 1 request each, including run
  `8088430c-32aa-4551-ad24-f5fd806e872b` from this card's cycle 1.

**Do not remove `.fails` from `ArtifactVersionPicker.iss802.test.tsx`.** It is not a
test of this fix, and its result points the wrong way: it reported
`Expect test to fail` with the bug present and `1 expected fail` after the fix. Why is
in [ISS-852](20260922-2352-ISS-852.md).
