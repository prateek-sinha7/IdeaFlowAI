# FIX-751

## What was wrong

Register entry QA-KB-070 (Low, code-level). The root card is [ISS-897](20261001-2127-ISS-897.md) and the
sibling is [ISS-1078](20261007-2150-ISS-1078.md). There is no production defect. Two lines that keep a ticked
step's review-gate count right had no regression test:

- `backend/agents/capabilities/strategies/task_loop.py:364` passes `invocation_gated=False` on the only per-task
  `runner.run_agent(...)` call (`:357-365`). Deleting it changed no result in 9 offline files. In a real run, a
  ticked 2-task step went from 1 review gate to 3, which is N+1. The analyzer measured this with
  `evidence/qa-kb-070/02-analyze-gate-count-drive.py`.
- `backend/agents/capabilities/strategies/wave_scheduler.py:245` declares `runs_agent_inline = False`. Deleting it
  changed no result in 13 offline files. A ticked wave worker with a declared human gate went from 1 gate to 0,
  measured with `evidence/qa-kb-070/03-analyze-wave-declaration-drive.py`.

## Root cause (from ISS-897's analysis, re-checked on this tree before editing)

Every test that reaches the real `TaskLoopStrategy.run` uses `_FakeRunner`. Its call record
(`backend/tests/unit/agents/test_strategies.py:181-188`) held `task_number`, `total_tasks`, `task_block` and
`skeleton`, but not `invocation_gated`, so no test could assert the flag. For ISS-1078, no test read the
`runs_agent_inline` declaration of `wave_scheduler` at all.

The blast radius was re-grepped before the edit:

- `task_loop.py` still has exactly one `run_agent(` call, at `:357`, with the keyword at `:364`. The declaration
  is at `:164`, and `wave_scheduler.py:245` and `fanout_batch.py:71` are unchanged.
- Two other files import `_FakeRunner`: `tests/integration/agents/test_sc001_reconcile.py:112` and
  `tests/integration/agents/test_restart_resume_db.py:2450`, `:2533` and `:2575`. Every consumer reads
  `run_agent_calls` by key (`c["task_number"]`), and none compares a whole record, so a new key does not
  affect them.

## What changed, and why there

One line, test-only, as item 1 of ISS-897's "Where the fix belongs" directs. `_FakeRunner.run_agent` now appends
`"invocation_gated": invocation_gated` to its call record (`test_strategies.py:187`). The parameter default stays
`True`, so a deleted keyword at `task_loop.py:364` records `True` and the pin fails.

No production line changed. Nothing under `backend/agents`, `backend/app`, `backend/alembic` or `tools` differs
from HEAD `8a0128685`. The fake is test infrastructure, and the card names it as the fix site, so this is not
the app bent to a test. The assertions came from the 4-test-writer, and neither was edited:

- `test_task_loop_opts_every_task_out_of_the_inline_gate` (`test_strategies.py:388-407`,
  `@pytest.mark.issue("ISS-897")`). A 2-task step makes 2 `run_agent` calls, each with `invocation_gated is
  False`. Its `xfail(strict=True)` marker is left in place for the 6-verifier.
- `test_spawn_only_strategy_declares_not_inline` (`test_runs_agent_inline_pairing_iss1078.py`,
  `@pytest.mark.issue("ISS-1078")`, green from birth). For `task_loop`, `fanout_batch` and `wave_scheduler` it
  checks `ExecutionEngine()._strategy_runs_agent_inline(strategy, CapabilityRegistry()) is False`. It reads the
  fact through the kernel's own reader, so no strategy-name list exists under
  `backend/agents/execution_engine/` (INV-1). ISS-1078 needed no edit from the fixer, because its pin is the
  whole fix.
