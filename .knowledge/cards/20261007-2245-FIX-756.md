# FIX-756

Fixes QA-KB-076 (register `LEDGER.md`, detail `BUGS.md#qa-kb-076`). It resolves the root card
[ISS-903](20261001-2145-ISS-903.md) and all four siblings the analysis filed:
[ISS-1082](20261007-2216-ISS-1082.md), [ISS-1083](20261007-2216-ISS-1083.md), [ISS-1084](20261007-2216-ISS-1084.md) and
[ISS-1085](20261007-2216-ISS-1085.md). One finding is deferred to a new open card,
[ISS-1089](20261007-2245-ISS-1089.md).

No application behaviour changed. Every edit is in a test file, a comment, a docstring or a failure-message string.

## What was wrong

The guard [FIX-690](20261001-2145-FIX-690.md) relies on (`test_no_line_number_cites_in_shutdown_path_files`) was green
while `test_shutdown_reachability.py` still carried stale `file:line` cites. `main.py:238` appeared twice and pointed at an
import, not the `restore_non_terminal_runs()` call. `test_run_stream_pool_leak.py:196-238` pointed at a section banner. The
module docstring's first and third lines named paths that `09270703b` had moved. A bare `registers the queue at :1734` or
`run_commands.py :399` in any scanned file would also have passed.

## Root cause (ISS-903's analysis, re-checked on this tree before editing)

The guard decided what a cite looks like from a closed list, one physical line at a time, over a hand-listed set of files.
All line numbers below are from HEAD `cb8edba2c`, before the edit:

- `_LINE_CITE` (`test_run_shutdown_stale_citations.py:25-28`) matched only ten module basenames, then `.py`/`.yml`, then
  `:` with no space. `main.py`, `server.py`, `.sh`, `x.py :N`, a bare `:NNNN`, and `test_run_stream_pool_leak.py` (where
  `\b` fails inside the name) all escaped it.
- The scan went line by line (`:39`), so a cite wrapped across a line break was never seen ([ISS-1082](20261007-2216-ISS-1082.md)).
- A missing scanned path was skipped with `if not path.exists(): continue` (`:37-38`), so the guard read nothing and still
  passed ([ISS-1084](20261007-2216-ISS-1084.md)).
- Nothing checked that the symbols which replaced the line numbers still exist ([ISS-1085](20261007-2216-ISS-1085.md)).
- Nothing read cites into the guarded modules written in other files ([ISS-1083](20261007-2216-ISS-1083.md)).

The blast radius was re-grepped before the edit. `_LINE_CITE` and `_SCANNED` each have one definition. Their consumers are
the lint plus the two shape tests the test-writer added, all in the same file, and no other file references either name.
Baseline at the time: guard file `6 passed, 7 xfailed`; `test_shutdown_reachability.py` `1 failed, 7 passed`. The one failure
is [ISS-896](20261001-2127-ISS-896.md)'s `UnitIsolationError`.

## What changed, and why there

**1. The guard, `backend/tests/unit/test_run_shutdown_stale_citations.py`** (ISS-903, ISS-1082, ISS-1084). Every check
routes through the one constant and the one loop, so both changes are made there:

- `_LINE_CITE` is now `[\w./-]+\.[A-Za-z]{1,5} ?:\d+|(?<![\w/.]):\d{3,}|\blines?[\s#]+\d+`. The first two alternatives are
  the shape ISS-903's analysis recommended, which is also the test-writer's `wide` pattern. Its general extension class
  covers ISS-1082 step 1 (`workflow.yaml:12`, `pyproject.toml:174`). The third alternative is ISS-1082 step 2.
  **One deliberate difference from that card:** ISS-1082 wrote `\s+`. This fix uses `[\s#]+`, so a prose cite wrapped
  across a `#` comment break (`# ... on line` / `# 292`) is caught as well as one wrapped inside a docstring. The card's
  stated expectation is "however it is written or wrapped", and `\s+` alone misses the commonest wrap in a `.py` file.
- The lint reads each file as one text and derives the line number from `text.count("\n", 0, m.start()) + 1`.
- `if not path.exists(): continue` became `assert path.exists(), f"scanned file moved or deleted: {path}"`.

**2. `backend/tests/unit/services/test_shutdown_reachability.py`**, comments and docstring only, following ISS-903's
inventory row by row:

- First line: its own path is now `tests/unit/services/`.
- Third line: `tests/unit/app/test_run_shutdown.py`.
- The pinned-uvicorn cites (`config.py:215`, `h11_impl.py:328-337`, `server.py:294-310`) are dropped. The symbols are
  already named in the same sentences. The wrapped `on line` / `292` became "the last statement of
  `uvicorn.Server.shutdown`", which was re-checked in the installed 0.34.0: `shutdown()` spans 262-292 and ends with
  `await self.lifespan.shutdown()`.
- `test_run_stream_pool_leak.py:196-238` now reads "the in-process `uvicorn.Server` that
  `tests/unit/app/test_run_stream_pool_leak.py` starts in `test_stream_endpoint_returns_connections`".
- The first copy of the duplicated "1. Reachability" banner and its comment (seven lines, above `_stop_grace_period_seconds`)
  is deleted. The helper itself is kept, since two tests call it. This follows the analysis's correction of the triage
  sketch's "64-~79".
- The kept copy's `main.py:238` now reads "`restore_non_terminal_runs()` in its lifespan", where "its" is `app.main`, named on
  the line above.

No assertion is touched.

**3. ISS-1085, the anchor test.** It adds `_ANCHORS` (cited file -> anchor strings) and
`test_symbols_named_by_shutdown_path_comments_still_exist`, using plain `in` checks with no `ast`. Plain text is required
because `runs_left_for_boot_restore` is a dict key. The entries are not invented here. They come from:

- [ISS-104](20260812-1312-ISS-104.md)'s anchor list (its guard step 1);
- ISS-104's "Name instead" column;
- ISS-1085's `runs_left_for_boot_restore`;
- the two anchors this fix wrote (`restore_non_terminal_runs()` in `app/main.py`, `test_stream_endpoint_returns_connections`).

Each entry was checked to be named in a `_SCANNED` comment. That check dropped `concierge.converse`, which no scanned comment
names. `read_timeout` and `stop_grace_period` overlap the ISS-888 test and the reachability helper. They are kept so the
table matches its stated purpose.

**4. ISS-1083, cites into the guarded modules from five other files.** The six sites in its table were renamed to the
card's "Name instead" text:

- `test_checkpointer_shutdown_budget.py`, a failure-message string;
- `test_sse_stream_api.py` (two comment lines);
- `agents/authz.py` (one docstring line, `ScopedStore.last_event_of_types`);
- `tests/conftest.py` (two comment lines);
- `test_iss102_live_model_guard.py` (docstring).

The card's optional step 2 was taken too: `_INBOUND_CITE` and
`test_no_line_number_cites_into_shutdown_path_files_from_elsewhere`. It walks `backend/` as text (`.py .sh .yml .md
.toml`, skipping `.venv`) for the card's guarded basenames, with `core/config` qualified. Without it nothing would test
ISS-1083. It found exactly the six sites on their pre-edit text and finds none now (evidence 12). It runs in about 0.75 s over
1,435 files. `authz.py` is `backend/agents/`, not the execution kernel, so SC-001 and INV-1 are untouched. `authz.py` had
been edited minutes earlier by [FIX-754](20261007-2233-FIX-754.md) (QA-KB-074), at other docstrings. This edit waited until
that bug's row read `FIXED`, and it does not overlap those lines.

## Not changed

- [ISS-1089](20261007-2245-ISS-1089.md) (new, open): 71 test files moved by `09270703b` still name their old path on
  line 1, including `test_iss102_live_model_guard.py`, which this fix edited on lines 5-7 only. It was found here and not
  swept, because it is outside every card in this bug.
- The roughly 191 other `name.ext:NNN` lines under `backend/app` and `backend/agents` that [ISS-885](20261001-2114-ISS-885.md)
  said not to sweep are still unswept. The inbound lint covers only the guarded basenames.
- Ceilings, marked `ponytail:` in the file:
  - a cite spelled out in words ("the third line of ...") still escapes;
  - `_SCANNED` and `_ANCHORS` are hand-kept lists;
  - the bare `:NNN` alternative would also flag a Python slice such as `x[:500]` in a scanned file. There is none today.
