# ISS-823

## Sibling of ISS-794 (QA-PS-044) — entry-path axis not yet tested

INFERRED — derived from this card family's own already-confirmed entry-path
finding, not yet reproduced for `/create/ppt` specifically.

[ISS-794](20260922-1827-ISS-794.md) measured `/create/ppt`'s duplicate-GET
counts (`auth/me` x3, `workflows` x2, `runs?limit=50` x2) from 3 **cold**
loads only (`navigate to about:blank`, then
`goto('http://localhost:3000/create/ppt')` while already signed in). Two
independent cards in this same family already proved that, for the
identical "unguarded mount effect on the shared catch-all" defect shape, a
**client-side (SPA) navigation** into the route — e.g. clicking "+ Create"
from an already-mounted `/dashboard`, rather than a hard URL load — raises
the duplicate count further, not just repeats it:

- [ISS-788](20260922-1816-ISS-788.md) (QA-PS-041, `/workflows`): a cold
  hard nav measured `GET /api/user-workflows` 2x / `GET /api/auth/me` 1x
  (3/3, reproducible); a click-through SPA nav from `/dashboard` measured
  4x / 2x instead on the identical page — named as its own "entry path"
  axis, confirmed reproducible.
- [ISS-817](20260922-1932-ISS-817.md) (derived from
  [ISS-816](20260922-1931-ISS-816.md), QA-PS-042's blast-radius trace):
  `LaunchWizard.tsx:371`'s own `getMe` call — the SAME call site
  `/create/ppt` reaches, and the SAME call site ISS-794 already blamed for
  its own "third" `auth/me` — is predicted to double-fire only on SPA nav,
  since [ISS-790](20260922-1821-ISS-790.md) (QA-PS-043,
  `/create/user-stories`, cold load only) measured this pattern's `auth/me`
  at a plain 1x, not doubled.

`/create/ppt` is reached both ways in real usage — a cold URL/bookmark, and
clicking "+ Create > Presentation" from an already-mounted `/dashboard`
while signed in — and every existing measurement of it
([ISS-794](20260922-1827-ISS-794.md), 3/3 cycles) is cold-load only. By the
pattern above, an SPA-nav entry into `/create/ppt` is predicted to push
`auth/me` past 3x and/or raise `workflows`/`runs?limit=50` past 2x, not
merely repeat ISS-794's cold-load counts.

## Expected vs actual

- Expected: request counts for `/create/ppt` do not depend on how the user
  arrived at the route.
- Actual (predicted, not yet measured): an SPA-nav entry (e.g.
  `/dashboard` -> click "+ Create" -> "Presentation") produces a HIGHER
  duplicate count than [ISS-794](20260922-1827-ISS-794.md)'s cold-load
  3x/2x/2x, matching the multiplier increase
  [ISS-788](20260922-1816-ISS-788.md) already measured for the same defect
  shape on `/workflows`.

## What would settle it

Reproduce via `goto('http://localhost:3000/dashboard')`, wait for it to
settle, then click through to `/create/ppt` via its real launcher (not a
direct `page.goto`), and compare
`performance.getEntriesByType('resource')` counts against
[ISS-794](20260922-1827-ISS-794.md)'s cold-load baseline — the same method
ISS-788/816/817 already used for their own routes.

## Fix

No new mechanism — the same shared fix
[ISS-794](20260922-1827-ISS-794.md)/[ISS-816](20260922-1931-ISS-816.md)/
[ISS-817](20260922-1932-ISS-817.md) already converge on (a URL-keyed
in-flight dedupe generalized into `request()`/`fetchWithAuth()`,
`frontend/src/lib/api.ts:332-375`, mirroring the single-flight
`inFlightWorkflows` pattern that function already uses for `getWorkflows()`
at `frontend/src/lib/api.ts:789-813`) closes this entry-path variant too,
since it removes the duplicate network call regardless of which
effect-timing triggered the second one.

## TEST COVERAGE — ISS-823

TEST-WRITER 2026-09-22: reproduced the exact scenario in "What would settle
it" — `qa-admin`, `goto('/dashboard')`, waited 2s, cleared
`performance.getResourceTimings()`, clicked "Pitch an idea" (SPA nav, not a
direct `page.goto('/create/ppt')`), waited 3s,
`performance.getEntriesByType('resource')`. Result: `auth/me` 0x (absorbed
entirely by ISS-801's `cachedGet()` 30s TTL from the dashboard's own recent
call — no new request at all), `GET /api/workflows/ppt` 1x, `runs?limit=50`
1x. None of the three counts exceeded ISS-794's cold-load baseline, let
alone the higher count this card predicted — this card's prediction does
NOT reproduce on the current tree. Matches
[ISS-836](20260922-2018-ISS-836.md)'s own flag that this prediction is
"most likely moot" now that all three mechanisms are time/in-flight guarded
rather than cold-vs-warm. No test shipped: a test asserting these counts
stay low would pass today for the right reason but prove nothing about a
live defect, and a test asserting the predicted regression would be
asserting something this measurement already contradicts. Not escalated —
this is a corrected/superseded prediction, not a product decision.

## Resolution

Verified fixed in the current code on 2026-10-01 (feat/user-stories-v2 @ 3b08b2ba8) by static review: a first-pass check and an independent adversarial re-check both found every claim of this card fixed. No tests were run for this closure.

**Fixed by:** fa559d08f (one owner per fetch, introduced cachedGet and inFlightWorkflows) plus [ISS-801](20260922-1834-ISS-801.md) cachedGet, [ISS-783](20260922-1615-ISS-783.md) inFlightWorkflows, [ISS-830](20260922-2002-ISS-830.md)/831 single-flight for run reads and workflow detail

**Evidence:** Card's only defect: SPA entry to /create/ppt predicted to raise auth/me, workflows, runs?limit=50 above cold-load counts. Checked in source. auth/me: both getMe callers (page.tsx:941, LaunchWizard.tsx:372) go through api.ts:941 cachedGet (30s TTL, shared promise, key api.ts:636-653), so SPA nav reuses the dashboard's call. workflows/ppt: getWorkflowDetail (api.ts:2402-2437) is single-flight keyed by token+path; callers LaunchWizard:508/590. runs?limit=50: getWorkflows (api.ts:1198-1222) is single-flight, and RunConnectionProvider.loadRecentRuns (:370-373) only refetches when token differs from recentRunsTokenRef, so a remount or SPA nav adds none. SSE refetches are patched in place (page.tsx:1074). All guards are time or in-flight based, not cold-vs-warm.

**Left over (outside this card's claims):** none for the card's claims. Static reading only, nothing was run. Not covered by the card: the ppt-type run lists (type=ppt&limit=5/20) in PreviewPanel.tsx:2034, PPTPreview.tsx:70 and FilesTab.tsx:802 use raw authedFetch with no dedupe. Those are different URLs and were never part of [ISS-794](20260922-1827-ISS-794.md) or [ISS-823](20260922-1938-ISS-823.md).
