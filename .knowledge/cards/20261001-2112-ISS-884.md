## Found while

Evaluating whether [ISS-693](20260918-ISS-693.md) could be fixed by recomputing the DOMAIN signature live in
`status.py` instead of degrading the row. It cannot today, because the live path is not equivalent to the
build. This is not a consequence of ISS-693's root cause. It is the reason the principled fix is unavailable,
and it has victims of its own.

## Condition

A DOMAIN card whose prose names a file by bare basename that exists more than once in the tree (`registry.py`,
`store.py`, `workflow.py`, `api.ts`), where the build resolved the name through the card's import seam.

## Mismatch (MEASURED, clean tree, HEAD 024c03ef, no uncommitted source)

| card | `watched_files` stamped by the build | `live_watch_set()` |
|---|---|---|
| DOMAIN-auth-and-entitlements | 31 | 30 |
| DOMAIN-context-assembly | 28 | 27 |
| DOMAIN-deliverables-and-artifacts | 30 | 29 |
| DOMAIN-execution-strategies | 20 | 19 |
| DOMAIN-hitl-gating | 20 | 19 |
| DOMAIN-workspace-isolation | 20 | 19 |

The other ten cards match exactly, for example agent-runtime 18 and 18, validation-and-quality 34 and 34.

Reproduced with the shipped CLI, no harness: `python3 tools/knowledge/build_architecture.py --explain` on this
clean tree prints, for exactly those six cards, `symbols_signature <stored> -> <live>` followed by "no symbol
moved -- the signature differs for another reason (a watched file was added or removed)". Nothing was added or
removed. The command is read-only.

## Cause (INFERRED, strongly supported)

Two call sites of the same function pass different `prefer` arguments:

- Build, `build_architecture.py:1161-1162`: `domain_watch_set(card, members, basename_idx, prefer=set(link_scope))`.
  `link_scope` is members plus the inbound and outbound import seam (`:1156`).
- Live, `:1458-1459`: `domain_watch_set(card, sorted(members), _basename_index(files))`. `prefer` defaults to
  the members alone (`:1047-1048`).

`resolve_trace_file` (`:995-1021`) breaks a basename tie only toward a candidate inside `prefer`, and otherwise
returns None, so the file is dropped. The build can pick `backend/agents/capabilities/registry.py` over
`backend/agents/registry.py` when the first is in the domain's seam. The live path cannot. A probe over all
16 cards shows each of the six mismatching cards has at least one ambiguous prose basename that the live path
cannot resolve (for example `DOMAIN-hitl-gating`: `api.ts`, `registry.py`, `store.py`; stamped 20, live 19, so
the build resolved exactly one of the three). Six other cards also have references the live path cannot
resolve, yet their counts match, which fits the build not resolving those either because they are outside
those domains' seams. So an ambiguous basename is necessary for a mismatch, not sufficient.

Not reproduced: `link_scope` needs `file_imports` from the extractor run (about 40 seconds), so the build's
exact watch set was not rebuilt. What would settle it: pass the files listed under the card's generated
`Imports` and `Imported by` blocks as `prefer`, and check that the counts equal the stamped ones.

## Consequences (INFERRED from reading)

1. The refresh gate, `build_architecture.py:1598-1617`, compares `stored = prose_symbols_signature` with
   `live = symbols_digest(live_watch_set(...))`. For these six cards `stored != live` even right after a
   `--stamp`, because the stamp copies the build's digest (`:1973-1978`). So the "unchanged shape, skipping"
   branch (`:1620`) cannot fire for them, and any commit touching one of their files re-authors the card.
   The gate exists to prevent exactly that (comment at `:1590-1594`).
2. `--explain` (`explain_domains`, `:1411-1442`) prints the false "a watched file was added or removed"
   explanation shown above.
3. Exposure is limited today: the hook that runs `--refresh-affected` is `stages: [manual]`
   (`.pre-commit-config.yaml:185`).

## Where the fix belongs

`build_architecture.py:1445-1460`, `live_watch_set`. The design choice is the owner's: persist what the live
path needs on the card (the resolved watch list, or `link_scope`), or recompute `link_scope` without the
extractor. Until then no check should treat `live_watch_set` as ground truth, which is why
[ISS-693](20260918-ISS-693.md) is fixed by degrading the row rather than recomputing it.

## Fix phase (QA-KB-026, 2026-10-01): not fixed, left open

[FIX-685](20261001-2130-FIX-685.md) fixed [ISS-693](20260918-ISS-693.md) and [ISS-883](20261001-2112-ISS-883.md) in
`status.py`. It left this card alone on purpose, because the source of the seam is the owner's decision (see "Where
the fix belongs" above). Status stays `open`, and `test_live_watch_set_passes_prefer_seam` stays XFAIL.

Cause, now MEASURED (no longer INFERRED). This is the settling check named above, run read-only on 2026-10-01 against
the stamped cards in this tree. For each DOMAIN card it computed members from `_tracked_files()`, then
`prefer = members | Depends on | Depended on by`, with the edges read from each member's per-file card under
`architecture/files/`. It then called `domain_watch_set(card, members, index, prefer=prefer)`. Script
`scratchpad/kb026_884_seam_probe.py`, output `scratchpad/kb026_884_seam_probe.out`:

```
live==stamped 10/16; seam==stamped 16/16
auth-and-entitlements 31/30/31, context-assembly 28/27/28, deliverables-and-artifacts 30/29/30,
execution-strategies 20/19/20, hitl-gating 20/19/20, workspace-isolation 20/19/20   (stamped/live/seam)
```

With the build's seam passed, the six mismatching cards reproduce their stamped `watched_files` exactly. The decision
needed is where `live_watch_set` reads the seam from:

- (a) Persist `link_scope` (or the watch list) in the DOMAIN frontmatter. This changes the generated card schema and
  takes effect only after an architecture rebuild. The new key must sit after the signature keys, because
  `status.py` and `read_signatures` read only the first 2000 characters.
- (b) Rebuild it at read time from the per-file cards' Depends on / Depended on by blocks, as the probe did. This
  needs no rebuild, but it makes `live_watch_set` depend on the generated body format of the `files/` tier.

Test note: the test asserts only `prefer is not None`. `prefer=set(members)`, which equals today's default, would
satisfy it without changing behaviour. Whoever fixes this should assert the stamped count instead.
