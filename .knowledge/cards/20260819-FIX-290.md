# FIX-290

**Phase / trigger:** `hotfix/permissions-issues`, merged to `dev` (`0520e2f44`,
2026-08-19). Squashed commit `ec1ea70f5`, "Fix universal filesystem-grant
permission bug, retire stale od_prototype workflows, and restore a green
frontend/backend test suite."

## Description

Every compiled step could receive filesystem write access at runtime even
when its `AGENT.md`/`workflow.yaml` step declared no `tools:` grant at all —
a universal grant, not scoped by request. Reproduced deterministically on
`user_stories`: its 6 agents all declare `tools: []` (text-only, meant to
*return* their output, not write files) yet were handed read+write anyway.
`story-estimator` sometimes wrote its backlog to the run sandbox instead of
returning it, where `deliverable: streamed_text` could never see it —
non-deterministic data loss (one run wrote 1 orphan file and still delivered
correctly; a sibling run wrote 10 and lost the deliverable entirely).

## Root cause

`compiler.py`'s per-step permission ceiling was built as
`ToolPermissions(exec=trusted, spawn_subagents=trusted)` — it never set
`write_files` explicitly. `ToolPermissions.write_files` defaults to `False`
on the dataclass, but the STEP-level grant path was not being gated through
this ceiling correctly for every step; a step declaring no `tools:` block at
all had no explicit deny in the actual manifests (most `workflow.yaml` steps
across `app_builder`, `ppt`, `user_stories`, `dotnet_to_azure`,
`mulesoft_to_springboot`, `custom_revision`, `prototype`, `prototype_revision`
had NO `tools:` key at all before this fix — see this commit's diff on those
files, each step gained an explicit `tools: {read_files: true}` or
`{read_files: true, write_files: true}`).

## Fix

New module `backend/agents/workflows/permission_caps.py` (256 lines) is now
**the single place a permission is decided** — cap, intersection, and trace
all live there. `compiler.py::_compile_tool_grant` now calls
`permission_caps.apply_cap(step_grant, trust, workflow, agent)` instead of
constructing an ad-hoc ceiling inline; `_ALLOWED_TOOLS_KEYS` is now derived
from `permission_caps.ALLOWED_GRANT_KEYS` rather than a hand-maintained
frozenset (so a new permission slot cannot be silently missed). Every step
across the 8 affected manifests now explicitly declares its `tools:` grant
instead of relying on the (buggy) implicit default.
