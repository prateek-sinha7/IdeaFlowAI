## Why this must also be broken

[ISS-363](20260828-2129-ISS-363.md) traced the root cause of the reported route/outcome-editor
bug to `pipelineAgents`/`onReorder`, and separately confirmed that `AgentsPopup.tsx:2242-2248`'s
`handleSelectionsChange` chain — the one [ISS-258](20260828-1650-ISS-258.md) had originally (and
incorrectly, for the route case) implicated — is real, independently broken code, just wired to a
different edit surface: the flat per-agent levers.

`ConfigLeversFlat.tsx:1640-1647` (`updateLever`, the writer behind every Model/Validators/
Gates/Retry control in the modal's "Config tab") calls `onSelectionsChange(next)` on every patch.
That prop is `AgentsPopup.tsx:2242-2248`'s `handleSelectionsChange`
(`setLiveSelections(next); onSelectionsChange?.(next);`), forwarded to whichever host mounted the
modal. Both confirmed hosts write it straight into a plain ref with no staging:

```tsx
// IdeaInputPage.tsx:937-942 (onSelectionsChange={handleSelectionsChange} at :1915)
const handleSelectionsChange = useCallback((selections) => {
  selectionsRef.current = selections;
}, []);
```

`LaunchWizard.tsx:580-582` is the identical pattern (`onSelectionsChange={handleSelectionsChange}`
at :1159). The Cancel button (`AgentsPopup.tsx:2492-2493`, `onClick={onClose}`) restores neither
`liveSelections` nor `selectionsRef.current` — same as [ISS-363](20260828-2129-ISS-363.md), just
one prop chain over (`onSelectionsChange` instead of `onReorder`) and a ref instead of state.
Nothing in the code distinguishes "this lever's edit gets discarded on Cancel" from "that lever's
edit doesn't" — every lever in this modal writes live and nothing rolls any of them back.

## Expected vs actual

**Expected:** changing a step's Model, Validators, Gates, or Retry count inside the Advanced
modal, then clicking Cancel, should leave that step's levers exactly as they were before the edit.

**Actual (INFERRED — not yet independently reproduced):** the edit should persist across
Cancel + reopen, identically to the route-outcome case, because it is written by the same
"propagate on every keystroke into unstaged parent state" pattern.

## What would confirm or refute this

Repeat [ISS-258](20260828-1650-ISS-258.md)'s exact repro shape but on a flat lever instead of the
route editor: `/create/ex_A2_branch` (or any workflow), open "Advanced", pick any agent's Config
tab, change its Model dropdown (or toggle a Validator/Gate, or change Retry), click Cancel,
reopen. A miss (the lever reverts) would mean `ConfigLeversFlat` has a staging layer this
analysis did not find and would refute this card specifically, without affecting
[ISS-363](20260828-2129-ISS-363.md)'s route-editor finding.

## Where the fix belongs

Same place as [ISS-363](20260828-2129-ISS-363.md): inside `AgentsPopup.tsx`, as part of the same
staged-draft-with-restore-on-Cancel fix. `liveSelections` already gets a one-time mount snapshot
(`AgentsPopup.tsx:2233-2241`) — Cancel needs to reset it to that snapshot (and re-emit to the
host's `selectionsRef` via `onSelectionsChange`) before calling `onClose`, the same rollback the
tree/route state needs. One fix, one component, both channels — not two separate patches in
`IdeaInputPage.tsx` and `LaunchWizard.tsx`.
