# ISS-1109

## Description

INFERRED sibling of [ISS-896](20261001-2127-ISS-896.md) (QA-KB-099). `backend/tests/unit/agents/test_phase3_cutover_verify.py::TestV2EventTypesAreEmittedByTheirProducers::test_run_finalization_failed_is_emitted_on_a_degraded_finalization`
fails today with `UnitIsolationError: Unit test spawned a subprocess: ['git', 'init', '-b', 'main']`. It is the same guard branch as
ISS-896 (`_deny_popen`, `backend/tests/unit/conftest.py:127-136`), reached one hop further: the test spawns nothing itself, it
calls a helper that runs real git. The other three tests in the file pass (`1 failed, 3 passed`).

## Why the root cause of QA-KB-099 implies it

The root cause of ISS-896 is a test that performs real I/O, sits in the tier `_unit_io_guard` polices, and carries neither an
`allow_io` reason nor a place in `tests/integration/`. This test has the same shape, and the same origin: commit `09270703b`
(2026-09-22) added the guard and, in the same commit, moved `tests/agents/test_phase3_cutover_verify.py` to
`tests/unit/agents/` (git reports R081), exactly as it moved the reachability test (R099).

The repository's own failing-test report, `UNIT-TESTS.md` (run 2026-09-23), lists three "spawned a subprocess" rows: 280 (this
test), 325 (ISS-896's test) and 330 (`test_run_files_ref_family_scope.py`, relocated by commit `14a675db4` to
`backend/tests/integration/api/test_run_files_ref_family_scope_api.py`, R098; carded as [ISS-892](20261001-2120-ISS-892.md), resolved).
Two of the three are fixed or carded; this one was neither: before this card was filed, `grep` for its name across
`.knowledge/INDEX.md`, `LEDGER.md` and `BUGS.md` found 0 hits.

## Mechanism (CONFIRMED by reading, then by run)

- `test_phase3_cutover_verify.py:496-519`: the docstring says the test "Drives the real finalizer against a real git sandbox"; it skips
  only when git is missing (`:506`), imports `_make_ectx`, `_plant_logs`, `_plant_output` and `_setup_sandbox` from
  `tests.agents.test_finalizer_v2` (`:511-516`), and calls `_setup_sandbox(tmp_path)` at `:519`.
- `backend/tests/agents/test_finalizer_v2.py`: `_setup_sandbox` (`:300`) calls `_git_init(repo)` (`:306`); `_git_init` (`:102`) calls
  `_run_git("init", "-b", "main", cwd=repo)` (`:103`); `_run_git` (`:89`) calls `subprocess.run(["git", *args], ...)` (`:90`).
- `subprocess.run` -> `Popen.__init__` -> `_deny_popen` (`tests/unit/conftest.py:127-134`) raises. Run alone at HEAD f06129262:
  `1 failed in 1.37 s`; whole file `1 failed, 3 passed in 1.71 s` (`evidence/qa-kb-099/analysis-09-sibling-phase3-cutover-still-red.txt`).
- It is the only test under `tests/unit` that reaches the helper: `grep -rn "_setup_sandbox\|test_finalizer_v2 import" backend/tests/unit`
  returns the three lines above and nothing else.
- The helper lives in `backend/tests/agents/`, a suite folder `backend/tests/conftest.py:456` marks "legacy, to be removed in Batch 6".
  `backend/tests/README.md:127-129` says a harness two suites need belongs in `tests/fakes/` or `tests/plugins/`, not in a test
  module, and calls a unit test importing from another test module "a layering break".

## Observed with the guard lifted (CONFIRMED by probe)

Adding `allow_io` to that one node from a scratch plugin (collection hook; the test body is untouched; copy in
`evidence/qa-kb-099/analysis-plugins/allow_io_probe_phase3.py`): `4 passed, 2 warnings in 1.86 s`. So the only defect is placement,
as in ISS-896.

## Expected vs actual

Expected: the test runs and checks that a degraded finalization emits exactly one `run_finalization_failed` event whose data is
`{run_id, reason}` with `reason == "payload_blocked"` and `published_status == "degraded"` (assertions at `:538-559`, "Req 20 AC 5").
Actual: it errors at the helper's `git init`, before reaching any of them, so that contract has had no unit-tier check since the
guard landed.

README `Known debt` (`backend/tests/README.md:178-182`) says `tests/unit/agents/` "was cleared of all of this in Batch 6". This
test is a counter-example (see [ISS-1110](20261008-1410-ISS-1110.md)).

## What is INFERRED, and what settles it

- INFERRED: that it has been red since `09270703b`. That is read from the move and from the 2026-09-23 report row, not run at that
  commit.
- The red itself was reproduced by the analyzer (node alone, then the whole file), not yet by a validator three times from cold.
  Three cold runs of that node settle it.
- Settled on 2026-10-08 by the 5-fixer before any edit. The node was run alone three times from cold, and all three runs failed with
  `UnitIsolationError` on `['git', 'init', '-b', 'main']` (`evidence/qa-kb-099/fix-03-phase3-cutover-before-and-after.txt`).
  [FIX-765](20261008-1436-FIX-765.md) resolved it with the `allow_io` remedy below. Afterwards the whole file printed `4 passed`.

## Fix direction (only once reproduced)

The guard stays as it is. Either remedy the guard's own message names applies to this test alone:

- `@pytest.mark.allow_io("<reason>")` on the test, with the reason stating that it drives the real finalizer against a git sandbox in
  `tmp_path` and nothing else. Smallest diff; the probe above shows it turns the test green.
- Move the test to `backend/tests/integration/agents/` (README rule 8: git is an external binary). Then the real-git helpers should
  not stay importable only from a legacy test module; that is a larger change than this bug needs.

Do not touch `test_finalizer_v2.py`'s own tests: they sit in the legacy `tests/agents/` folder, not under the unit guard.
