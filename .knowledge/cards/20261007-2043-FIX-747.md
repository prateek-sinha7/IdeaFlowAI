# FIX-747

## What was wrong

Bug QA-KB-092, code-level, root card [ISS-953](20261002-0154-ISS-953.md).
`cd frontend && npx vitest run src/components/history/WorkflowHistory.test.tsx` reported
`Tests  1 failed | 16 passed (17)`. The case "the row's Chain menu action reaches the chain panel (bypassing onOpenRun)
and fires onChainPipeline with the source run id" opened "Run actions" and then failed with
`TestingLibraryElementError: Unable to find role="menuitem" and name /chain/i` (`WorkflowHistory.test.tsx:384`).

## Root cause (from ISS-953, re-checked on this tree before editing)

`e4eecb705` added the run-actions "Chain" menuitem and this test case in the same commit. `dfd167387`
([FIX-584](20260922-0925-FIX-584.md)) removed the item on purpose but left the test file alone. FIX-584's locked
constraint says the run-actions RowMenu carries only actions that act on the row. The query is a string, so `tsc`
had nothing to report.

Re-checked before editing:
- `RowMenu` renders one `role="menuitem"`, Delete (`RevisionFamilyView.tsx:477`).
- All three `RowMenu` call sites pass only `runId, openMenuId, onToggleMenu, onDeleteClick`
  (`RevisionFamilyView.tsx:621, 688, 734`).
- `grep -rnE "onChainClick|handleChainAffordance" frontend/src frontend/e2e` returns nothing.
- The production render site passes both `onChainPipeline` and `onOpenRun` (`DashboardLayout.tsx:3042, 3061` at
  HEAD 9e6450abc; another fixer is editing that file in this tree, so the working-tree lines drift).

The test was stale and the app was right.

## What changed, and why there

Only `frontend/src/components/history/WorkflowHistory.test.tsx`, which is where ISS-953 puts the fix:

- The case at `:373` is rewritten, not deleted. Deleting it would leave FIX-584's constraint with no guard. The new
  case renders as production does (`onOpenRun` and `onChainPipeline`, plus the chain catalog), opens "Run actions",
  waits for the Delete menuitem to prove the menu is open, and then asserts
  `getAllByRole("menuitem")` has length 1 (`:389`) and `queryByRole("menuitem", { name: /chain/i })` is null (`:390`).
  The `onChainPipeline` / "Suggested next steps" assertions are dropped as ISS-953 directs, because the
  `renderAndOpenRun` cases above still cover that panel. `mockGetRunSummary.mockResolvedValue(summaryFor(run))` is
  dropped too: it fed only the internal detail that the old case opened.
- The describe title (`:356`), the block comment (`:347-355`) and the catalog-helper comment (`:187-190`) now say that
  FIX-584 removed the Chain item. The block comment no longer mentions `opts.forChain`.

**This edits a test, and the card is what makes that legitimate.** ISS-953 establishes that the expectation was
misstated: the item was removed on purpose, and chaining is still offered from the run screen. Restoring the item to
turn the case green would have bent the app to the test and broken FIX-584's locked constraint. No application file
was touched.

## Not changed

- [ISS-1030](20261002-1026-ISS-1030.md) stays **open**. `handleSelectRun`'s unused `opts.forChain` parameter and its
  stale comment (`WorkflowHistory.tsx:341, 354, 358`) are production source, and ISS-1030 itself says "Keep this out of
  QA-KB-092's change. That bug's contract is 'no app change'". It needs its own pass.
- The first case of the describe ("a plain row click still calls onOpenRun") is untouched and green.
- `specs/019-sandbox-git-versioning/bugs/GIT_VERSIONING_GAP.md:110` is a dated gap record and is left as history
  (ISS-953).
- There is no `it.fails` marker, because the test-writer did not add one. Per ISS-953, the red case already existed.
  The rewritten guard asserts the post-FIX-584 contract and passes as soon as it is written, as expected for a
  stale-test fix.
