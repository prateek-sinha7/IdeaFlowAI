A `trigger: workflow` outcome could start a child run but could not tell it anything. The
child inherits `parent_run_id`, owner, workspace and the budget aggregate — but not the
parent's message, and there was no other channel.

## Root cause

`run_trigger_workflow` passed `content=""` to `_launch_run_core` unconditionally. The
child therefore always began with an empty brief, so its prompt had to be entirely
self-contained.

## Fix

The matched outcome's `feedback` (already carried on `RouteOutcome` by
[FIX-273](20260824-1615-FIX-273.md)) is threaded down as the child's `content`. Defaults to
`""`, so every existing divert is byte-identical.

Verified live: `ex_A3_divert` sends a Spanish instruction to `ex_A3_b_spanish`, whose own
prompt says nothing about jokes, and the child replied
`"¡Hola! ¿Sabes por qué cruzó la gallina la carretera?…"` — the instruction demonstrably
crossed the run boundary. The two outcomes carry instructions in DIFFERENT languages
sharing no substring, so the assertion also proves the RIGHT outcome's feedback reached
the right child.

## Limit

`feedback` is a static manifest string. A human's own words cannot cross a divert — only
which outcome they selected does.
