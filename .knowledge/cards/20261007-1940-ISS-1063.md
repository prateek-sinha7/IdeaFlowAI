## What the code says

- `backend/tests/agents/test_per_run_paths_v3.py:427` saves `_orig_sandbox = playwright_tools._SANDBOX`, and `:444` writes it
  back in a `finally`.
- `backend/app/agents/tools/playwright.py:46` holds the binding in `_SANDBOX_VAR: contextvars.ContextVar[...]`. The module
  defines no `_SANDBOX` (`grep -n "_SANDBOX\b"` finds only `_SANDBOX_VAR`).
- `git log -S "_SANDBOX" -- backend/app/agents/tools/playwright.py` lists `5af898322` (2026-09-10, "fix(engine): harden
  prototype runs ... per-worker browser ...") as the latest change to that symbol. INFERRED: that commit moved the module
  global to the ContextVar and did not update this test.
- The same file's pptx test saves `pptx_tools._SANDBOX` (`:313`) and passes, so the pptx module still has the global.

## Open questions for the analysis

- Is dropping the save/restore enough? `bind_sandbox` sets the ContextVar, so the test may need a ContextVar reset instead.
- The test drives real Chromium (it skips when the browser is unavailable). `backend/tests/README.md` rule 8 puts a test that
  needs Chromium under `tests/integration/`, not `tests/agents/`.

## Analysis (QA-KB-098, 2026-10-08, HEAD 165c40316)

Done by the 3-analyzer. Everything below is CONFIRMED unless it says INFERRED. No application or test source was changed; the
probes ran from scratch plugins whose copies are kept in `evidence/qa-kb-098/analysis-plugins/`.

### Root cause (CONFIRMED)

The test pins a name that a refactor on another branch deleted, and merging the two branches raised no conflict.

- `test_revision_browser_dir_writer_driven` saves and restores `playwright_tools._SANDBOX`
  (`backend/tests/agents/test_per_run_paths_v3.py:427`, `:444`). Reproduced alone at HEAD 165c40316:
  `AttributeError: module 'app.agents.tools.playwright' has no attribute '_SANDBOX'` at `:427`, 1 failed in 1.26 s
  (`evidence/qa-kb-098/analysis-01-reproduce-at-head.txt`); the whole file is `1 failed, 4 passed`
  (`analysis-09-whole-file-at-head.txt`).
- `5af898322` (2026-09-10) is [FIX-567](20260918-FIX-567.md): it deleted the module global `_SANDBOX` (and its companion
  `_AGENT_ID`) and added the `_SANDBOX_VAR` / `_AGENT_KEY_VAR` ContextVars (`playwright.py:46-51`; `bind_sandbox` writes them at
  `:67-68`). It entered this line of history through `4d6151a3a` (2026-09-10, merge of `feat/pdf-workflow` into
  `feat/file-extract-tools`).
- The test file's first commit is `acd36b798` (2026-09-12). At that commit `playwright.py` still had `_SANDBOX: Any = None` (`:43`)
  and `global _SANDBOX, _AGENT_ID` (`:54`), so the test was green on its own line. The correction to the INFERRED bullet above: the
  test did not go stale under `5af898322`, it was written against the old shape on a branch that never contained the refactor.
  `acd36b798` and `5af898322` are not ancestors of each other (merge-base `b38dffcc0`, 2026-08-27).
- The two met in `4ebd98e8f` (2026-09-16, "Merge branch 'feat/git-versioning' into feat/file-extract-tools"), verified as the
  unique earliest commit containing both. There `playwright.py` has no bare `_SANDBOX` and the test pins it at `:427` / `:444`.
  The files differ, so git saw no textual conflict: a semantic merge conflict. The test has been red since.
- Second pass (2026-10-08, HEAD 3af414bc6; `evidence/qa-kb-098/analysis-10-reverify-at-head-3af414bc6.txt`): `git diff --stat
  165c40316 HEAD -- backend frontend` is empty, so every file:line in this card still holds. The merge's parents were re-read
  directly: the first, `66bf725ba` (feat/file-extract-tools), has no `tests/agents/test_per_run_paths_v3.py` and 0 bare `_SANDBOX`
  lines in `playwright.py`; the second, `36617b824` (feat/git-versioning), has the test and 18. `4ebd98e8f` auto-combined the two
  sides of `playwright.py` (the first parent's ContextVar binding plus the second parent's `browser_dir` change to
  `playwright_take_screenshot`: 12 insertions, 3 deletions against the first parent) and took the test verbatim from the second
  parent (`git diff --stat 36617b824 4ebd98e8f -- <test>` is empty), which is the whole conflict. The one node, run alone at this
  HEAD: `1 failed in 1.21 s`, `AttributeError` at `:427`. The removed name is reached from exactly two lines, `:427` and `:444`; the other 11 bare
  `_SANDBOX` test pins name pptx_tools / file_extract_tools, which still own the global ([ISS-1108](20261008-0123-ISS-1108.md)).

### The rest of the test is sound (CONFIRMED by probe)

Supplying only the missing attribute (scratch plugin `kb098_global_shim.py`: `monkeypatch.setattr(playwright, "_SANDBOX", None,
raising=False)`; the test body is untouched) turns the test green: `1 passed in 3.01s`, not skipped. Real Chromium launched, the
real `playwright_navigate` and `playwright_take_screenshot` ran against two `file://` pages, and both screenshots exist and are
non-empty at the two distinct `.browser/{run_id}/` paths (`analysis-02-probe-shim-global.txt`). The AttributeError is the only
defect in the test.

### Answers to the open questions above

1. Is dropping the save/restore enough? Yes. `bind_sandbox` writes ContextVars, and a write made inside an `async def` test stays
   inside that test's task ([FIX-567](20260918-FIX-567.md): "a write inside that task does NOT escape it"). Verified: a recorder
   around the test shows `_SANDBOX_VAR` is `None` and `_AGENT_KEY_VAR` is `'unknown'` at the test's teardown and at the next
   test's setup (`analysis-03-probe-contextvar-leak.txt`; pytest 9.0.3, pytest-asyncio 1.4.0, `asyncio_mode = "auto"`). No
   ContextVar reset is needed. Keep `playwright_close.invoke({})` in the `finally`: it is real cleanup, and the root and revision
   bindings share ONE browser session because it is keyed by the sandbox directory name (see
   [ISS-1107](20261008-0123-ISS-1107.md)).
2. Placement. `backend/tests/README.md:76-78` (rule 8) does put a Chromium test under `tests/integration/`. But `tests/agents/`
   is a recognised legacy suite folder ("legacy, to be removed in Batch 6", `backend/tests/conftest.py:456`), the rest of this file
   already breaks rules 7 and 9 (`isolated_db`, `drive_engine_pipeline`), and the file computes
   `_BACKEND_ROOT = Path(__file__).parent.parent.parent` (`:75`; the README's "Known debt" says a move must recompute such roots).
   Relocation is the Batch 6 migration's job, not this bug's. INFERRED from CI config: the backend job installs no Chromium
   (`.github/workflows/ci.yml:727` installs it in the frontend job only), so after the fix this test should take its own
   documented skip in CI and run for real only on a machine with Chromium. Verify it locally.

### Blast radius (CONFIRMED by grep, `analysis-08-blast-radius-test-side.txt`)

- The removed name is reached from exactly two lines in the repository: `test_per_run_paths_v3.py:427` and `:444`. Every other
  private-name reach into the module from tests (`_SANDBOX_VAR` x13, `_AGENT_KEY_VAR` x7, `_get_session` x2, `_BROWSER_DIR` x1, in
  `test_playwright_tools.py` and `test_playwright_session.py`) names a symbol that exists.
- Production never reads the removed name. The only binder is `backend/agents/factory.py:1285`, the only exit-time release is
  `backend/agents/execution_engine/engine.py:7641`. This is a test defect, not an application defect.
- The one gate that consumes the node: `.github/workflows/ci.yml:336-337`, job `backend-offline`, runs `pytest tests -m "not live
  and not requires_api_key and not requires_postgres and not requires_postgres_populated_migration"`. The node carries only
  `@pytest.mark.asyncio` (`:382`) and the folder hook's `agents` marker (`conftest.py:484`), so it is collected, and the AttributeError
  at `:427` fails that job on every run of this line whether or not Chromium is installed: it is raised before the browser or the
  documented skip is reached. Read from the workflow file; no CI run was inspected
  (`evidence/qa-kb-098/analysis-11-refactor-removed-names-and-ci-consumer.txt`, sections 5-6).
- The refactor leaves no second stale pin (same file, sections 1-4). `git show 5af898322 -- backend/agents backend/app` removes four top-level definitions:
  `_SANDBOX` and `_AGENT_ID` (both gone from `playwright.py`) and the old signatures of `bind_sandbox` and
  `factory._resolve_runner_tools`, which only gained an optional parameter (`worker_key` / `thread_id`), so every existing call
  (`bind_sandbox(sb)`, `(sb, agent_id=...)`, `(sb, agent_id=..., worker_key=...)` in the tests; `_resolve_runner_tools(spec, ctx)`)
  still binds. No test reads the playwright module's `_AGENT_ID`: the other `_AGENT_ID` hits in `backend/` are unrelated test-local
  constants (`_AGENT_ID = "domain-analyst"` and similar).

### Fix, and where it belongs: the test only

In `backend/tests/agents/test_per_run_paths_v3.py::TestPerRunPathsDistinct::test_revision_browser_dir_writer_driven`, delete
`_orig_sandbox = playwright_tools._SANDBOX` (`:427`) and `playwright_tools._SANDBOX = _orig_sandbox` (`:444`); keep the
`try`/`finally` with `playwright_close`. Do NOT add a `_SANDBOX` alias or shim to `playwright.py`. The pptx save/restore at `:313`
and `:323` is correct today (pptx_tools still has the global) and is left alone; it is the next stale pin, see
[ISS-1108](20261008-0123-ISS-1108.md).
