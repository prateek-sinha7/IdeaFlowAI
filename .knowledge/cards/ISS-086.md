# ISS-086

## Title

"Request changes" (redo) at an agent's own gate re-runs that agent WITHOUT injecting its prior output, so the agent returns only the delta and the previous work is destroyed. Owner asked the Task Planner to "add 2 more pages"; it came back with one task. Measured on run a0d17afa-7292-4bc9-88d9-681437d315bb: task_list v1 → v2 = 12,542 → 3,495 chars (−72.1%), headings 7 → 1, 0 of 7 kept. All six real tasks were destroyed (Task 1: HTML Shell & Navigation Chrome, Task 2: Dashboard Overview, Task 3: Feature Analytics, Task 4: User Cohorts, Task 5: System Health, Task 6: Settings Page) and replaced by the single heading Task 1: Extend Dashboard with Two Additional Pages — i.e. the model wrote ONLY the requested change, because it could not see what it was changing. Prompt-level proof: the redo dispatch (agent_input seq 5552, 02:57:09, matching the gate_events redo row exactly) is 80,306 chars and contains neither Task 2: Dashboard nor HTML Shell — versus 80,200 chars on the first dispatch (seq 4099). The redo added 106 characters — the instruction alone — and no prior artifact. The contrast that localises the bug: on the SAME run the update_specs path at the analyze gate behaved CORRECTLY — spec v1 → v2 went 53,288 → 25,988 chars but kept 12 of 12 headings (100%) and added 2, i.e. compaction, not loss. So FIX-217's spec_revision_prior_artifact injection works for update_specs → specify, and the redo path at every agent gate has the same hole FIX-217 closed for one path only. Judging this by length alone would have mis-read it in both directions — the healthy path shrank 51% and the broken path is the one to fix. Scope note (owner's framing, and it is correct): re-running from a specific agent (redo) and re-running the specify→plan→analyze sub-pipeline (update_specs) are different code paths with different context assembly, and only the second was ever fixed or tested. Every per-agent iteration path needs coverage.

## Source / evidence

Found by the owner during manual testing of the "apple design website" run and reported in their own words ("i tried to change spec in the first iteration to task planner agent to add 2 more pages and it came back with only 1 task"). I confirmed it from artifact_refs (version-by-version char/heading diff), gate_events (the redo row at prototype-plan, 02:57:09) and the durable agent_input prompts — mechanism proven at the prompt, not inferred.
