## 5-fixer: measured each row, one real defect

Re-ran all five files with `--runxfail` to see the underlying red. **One of the
six is a production defect; one was already cured upstream; the other four are
stale test expectations that the app deliberately outgrew.** The card's own
"grouped only because nothing links them" holds — the four stale ones do not
share a cause either.

| row | verdict | evidence |
|---|---|---|
| `phase8_live::…offline_chained` | **DEFECT — fixed, [FIX-437](20260831-1925-FIX-437.md)** | `previous_run` re-seeded `prototype.html` from the PARENT sandbox on the per-agent `load`, over the edit the revision step had just made; `edit_file → "String not found in file: '<h1>Dashboard</h1>'"`. Node now XPASSes. |
| `phase5::TestFixPolicyEndToEnd::…` | already cured by [FIX-433](20260831-1859-FIX-433.md) | passes today with `--runxfail`; nothing left to fix, marker still on. |
| `tool_grant_invariants::…writers_keep_write` | **stale test — NOT fixed** | flags `ppt_v2:ppt-code-generator`. Its `tools: [pptx]` is not a filesystem tool set (`agents/capabilities/tools/pptx.py` returns `render_pptx`/`verify_pptx_layout`/… and `exclude_builtin=False`), and `ppt_v2/workflow.yaml:74-77` sets `write_files: false` **deliberately, with the reason in a comment**: the pptx tools write the binary, the agent never calls `write_file`. The test's heuristic — any non-empty `tools:` frontmatter means "declares a filesystem tool set" — was written at `ec1ea70f5` (2026-08-19) when `workspace` was the only value; `planning`, `playwright`, `pptx` and `prototype_emit_only` all violate it now. Granting write to silence it would undo a deliberate narrowing. |
| `phase5::…no_phantom_second_agent` | **stale count — NOT fixed** | asserts `agent_start == 2`; the run emits 3. The invariant (the internal `:fix` sub-agent emits no extra `agent_start`) still HOLDS — 3 is the declared roster since `e0f6beeed` made `prototype-revision-analyzer` step 0, which [FIX-433](20260831-1859-FIX-433.md) then locked in as correct. The `2` was authored at `416341b0f` (KAN-108) and never re-pointed. |
| `text_only_prompt_hygiene::…strips_fabricated_xml…` | **stale fixture — NOT fixed** | the fixture drives `engine.execute(agents=get_pipeline_agents("user_stories")[:2])` and asserts the polluted agent's output IS `final_output`. The ADR-0008 roster seam (`engine.py:1720-1722`) expands a caller roster that is a strict SUBSET of the plan back to the full 6-step plan, so `backlog-compiler` is last and its clean output is the deliverable. Both sanitizer assertions the test exists for — the `agent_chunk` stream and `agent_complete.output_length` — PASS. |
| `workflows_api::…chained_from_and_short_name` | **stale set — NOT fixed** | expects `prototype.chained_from == {user_stories, ppt}`; the API returns those plus `ppt_v2`, which `prototype/workflow.yaml:15` authors deliberately (added with the pipeline at `bab17c0b9`). The API is reporting the manifest correctly. |

The four stale rows need a decision this card does not carry — re-point the
expectation, or change the app. Every one of them would be "fixed" by editing
the assertion, which is the inversion this line does not do unprompted. They
are left `xfail(strict=True)` and red-for-a-stale-reason.

Adjacent, found while tracing FIX-437 and NOT fixed: `previous_run.load` also
re-writes the parent's `spec.md` / `design.md` / `tasks.md` into the sandbox on
every per-agent invocation, not just at run entry. Harmless today (read-only
reference material) but the same non-idempotent shape.
