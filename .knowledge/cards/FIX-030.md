## Description

d4v: POST /api/prototype/run rejected any brief over 8000 chars (422) — blocked large briefs and attached-file content

## Root cause

RunRequest.brief was declared max_length=8000, a legacy straggler from the prototype era; the app-wide BRIEF_MAX_CHARS (450k, ~150k tokens) already governs the other ingest paths but this endpoint was never aligned, so long briefs 422'd before reaching the engine. Fix: source the field cap from settings.BRIEF_MAX_CHARS instead of the hardcoded 8000; added a unit test pinning the cap to the setting.
