## What changed

**S-18-05** maps role to the id shapes that role may legitimately carry:

```python
shapes = {
    "user":      ("client-",),
    "narrator":  ("chat_reply:", "chat-reply:"),
    "assistant": ("chat_reply:", "chat-reply:"),
}
```

Kept role-scoped rather than collapsed into one regex, so a user turn wearing a
reply's id — or the reverse — is still a failure. Uniqueness across the whole
transcript is unchanged.

**S-05-07 inverted, in the feature file as well as the test.** The scenario is
now *"The detail view resolves agent IDs to display names"*, keeping tag
`@S-05-07` — the scenario↔test link is checked on the marker id, not the title,
and a spec that documents a fixed bug as desired behaviour is worse than no
spec. The test asserts the resolved name appears, the raw id does NOT appear
beside it, and an id the catalog cannot name still appears as itself.
`OVERRIDE_AGENT_IDS`/`OVERRIDE_DISPLAY_NAMES` became one
`AGENT_DISPLAY_NAMES` mapping; two parallel lists could not express which id
maps to which name.

**S-05-06 and S-05-10 read counts instead of hardcoding them.** A new
`saved_row()` helper fetches the record from `/api/user-workflows` through the
page's own session, so the module's stated principle — *"Counts are read, never
assumed"* — now covers the roster too. D-05 (S-05-10) compares the roster count
against the launch panel's and SKIPS with a message naming the lost override
when they agree, so it starts running again by itself once T5-01 is decided.

**S-03 launch panels** matches `"no gates|pause for review"` — the section must
exist and report its state; which state is FIX-323's call, not this test's.
