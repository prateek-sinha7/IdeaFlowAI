# FIX-609

Bug **QA-PS-023** (`BUGS.md#qa-ps-023`) — the Preview tab at `/runs/{id}` rendered
the last agent's stream-of-thought above the deck: *"The composer file contains no
artifact. Let me check what files exist in the `.agents/` directory…"* appeared as
visible text nodes before slide 1.

## What was wrong

No deliverable resolver removed narrative prose a model emitted **ahead of** its
HTML document. `unwrap_artifact`
(`backend/agents/capabilities/deliverables/_artifact.py:34-38`) only strips a
*literal* `<artifact>…</artifact>` wrapper:

```python
if text and "<artifact" in text:
    m = re.search(r"<artifact[^>]*>\s*([\s\S]*?)\s*</artifact>", text, re.IGNORECASE)
    if m:
        return m.group(1).strip()
return text
```

When the agent skipped the wrapper and emitted prose immediately followed by a bare
`<!DOCTYPE html>`, the `if` never matched, the function fell through to
`return text`, and prose + HTML both survived into `final_output`. `page.tsx` sets
`genericDeliverable.content = finalOutput` verbatim and
`PreviewPanel.tsx:243` hands it to `srcDoc={withDarkIframeDefault(content, …)}`,
so the browser rendered the preamble as document text.

Three resolvers shared the gap ([ISS-700](20260922-1230-ISS-700.md) root,
[ISS-736](20260922-1404-ISS-736.md) and [ISS-737](20260922-1405-ISS-737.md) siblings):

| Resolver | Before | Why the existing transforms missed it |
|---|---|---|
| `streamed_text.py:48` | `unwrap_artifact(last_streamed)` | wrapper-strip only |
| `ppt.py:74-78` | `unwrap_artifact(strip_pre_slide_body_text(sanitize_carousel_deck_html(strip_code_fence(x))))` | `strip_pre_slide_body_text` only cleans **inside** `<body>`; `sanitize_carousel_deck_html` needs `<style`; `strip_code_fence` needs a fence at position 0. Prose before `<!DOCTYPE` survives all four. Base `ppt`'s `presentation.pptx` filename also skips `PPTPreview`'s own DOCTYPE-slice, so it lands in the unguarded iframe. |
| `single_file.py:165` | `return last_streamed` | the forward-build fallback made **no** call at all — not even `unwrap_artifact` |

## Root cause

`backend/agents/capabilities/deliverables/_artifact.py` had no transform that
inspects anything **before** `<!DOCTYPE` / `<head>`. Every resolver composes its
chain from that one module, so the gap was single-homed — and so is the fix.

## What changed and why there

**`_artifact.py:41-83`** — new `strip_pre_document_prose(text)`, placed beside
`unwrap_artifact` because it is the same job (get the deliverable out of the
model's chatter) and because every resolver already imports from here. It is
deliberately narrow, for the reason `unwrap_artifact`'s own docstring gives about
`<artifact>`: a markdown/text deliverable may legitimately QUOTE an `<html>`
example mid-body, and slicing there would discard the real deliverable. **Both**
conditions must hold before anything is dropped:

1. there is non-whitespace content before the first `<!DOCTYPE html` / `<html`, and
2. the stream **ends** at that document's `</html>` close — i.e. the tail IS the
   whole deliverable, not an embedded example.

Composed at four call sites, all of which route through that one helper:

- `streamed_text.py:48-50` — `strip_pre_document_prose(unwrap_artifact(x))`.
  Unwrap runs FIRST on purpose: slicing to `<!DOCTYPE` *inside* an `<artifact>`
  wrapper would drop the opening tag and strand its `</artifact>` close.
- `ppt.py:74-82` — wraps the existing chain outermost, same ordering reason.
- `single_file.py:167` — the forward-build fallback gets the call it never had.
  Tiers (0)/(1) read a real file and tier (2)'s `looks_like_html` check already
  routed prose-prefixed streams to the seeded original, so only tier (3) changed.
- `engine.py:1376-1389` — `build_flat_payload`'s ppt materialization, whose own
  comment declares it calls the *same functions `PptResolver.resolve()` calls
  (PARITY-07, move-don't-copy)*. Left alone it would have written prose-prefixed
  HTML into the materialized payload file while the preview rendered clean —
  a silent divergence into git-versioning and run chaining.

**Not changed, deliberately:** the engine's `streamed_text` materialization
(`engine.py:1337-1348`) captures `last_streamed` raw by design and calls no
transform at all — a pre-existing divergence no card covers. Recorded as
[ISS-791](20260922-1823-ISS-791.md) rather than fixed here.

No frontend change was needed: the fix is upstream of `PreviewPanel`, so the
`srcDoc` branch and `PPTPreview`'s filename routing are untouched.
