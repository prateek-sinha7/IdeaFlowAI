# ISS-852

Found during [FIX-636](20260922-2352-FIX-636.md) (QA-PS-049). These are defects in
**test files** that the 4-test-writer left for [ISS-802](20260922-1638-ISS-802.md),
not in application code. Every file named here is untracked (`git status` shows `??`).

## 1. `ArtifactVersionPicker.iss802.test.tsx` points the wrong way

The test mounts `<ArtifactVersionPicker>` under `<React.StrictMode>` and asserts
`expect(getRunArtifacts).toHaveBeenCalledTimes(1)`, where `getRunArtifacts` is a
spy behind `vi.mock("@/lib/api", () => ({ ... }))`. The component loads the api
module with a dynamic `import("@/lib/api")` in each mount. Under vitest, the second
concurrent dynamic import resolved to the **real** module, not the factory mock, so
the spy never sees the second mount's request.

Observed (each run is `npx vitest run <file>` from `frontend/`):

| Component state | This test | Requests counted at `fetch` |
|---|---|---|
| HEAD `cae0c8adf` (bug present) | `Error: Expect test to fail` (the spy counted 1) | **2** |
| after FIX-636 | `1 expected fail` | **1** |
| after FIX-636, `.fails` removed (temp copy, deleted) | `AssertionError: expected "vi.fn()" to be called at least once` (the spy counted 0) | 1 |

The fetch-level count comes from `ArtifactVersionPicker.iss802.network.test.tsx`
(FIX-636), which stubs `fetch` and leaves `api.ts` unmocked.

How it happens, taken from the test-writer's own probe
`debug802e.test.tsx`, which I re-ran:
`Received: "1: cancelled after import|2: error ApiError: Not authenticated"`.
The second mount's import produced the real `request()`. With no token set, it threw
`Not authenticated` instead of calling the mock.

**Disposition.** Never remove this file's `.fails` marker. If it runs as a plain
`it`, it fails against fixed code, and the 6-verifier could then REOPEN a correct
fix. Delete the file, or rewrite it to count at `fetch` (which the network test
already does). This file is not in any card's `verification.test_files`.

## 2. Five debug probes that always fail

`frontend/src/components/results/debug802.test.tsx`, `debug802b`, `debug802c`,
`debug802d` and `debug802e` are print-debugging scratch files. Each one asserts a
value that can never match, only so vitest prints the received value:
`toBe(-1)` in `debug802`, `debug802b` and `debug802c`, and `toBe("X")` in
`debug802d` and `debug802e`. `debug802.test.tsx` imports the
component by absolute path:
`/Users/bilala/Developer/Projects/VELOCITY-AI/frontend/src/...`. Any vitest run over
`src/components/results/` fails on all five. **Disposition:** delete them. They
assert nothing about the product.

## Scope check

Only ISS-802's test has this problem. `AuditTab.iss800.test.tsx` and
`SandboxTab.iss830.test.tsx` also mock `@/lib/api` with a factory, but their
components import it statically: `grep -c 'await import("@/lib/api")'` returns 0
for `AuditTab.tsx` and `SandboxTab.tsx`. `AgentThinkingTab.tsx` does use two dynamic
imports, but `AgentThinkingTab.iss829.test.tsx` leaves `api.ts` unmocked and stubs
only `fetch`.
