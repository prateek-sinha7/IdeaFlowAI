## Related

## What was wrong

`_read_decision` in `conditional.py` ran `json.loads` over the agent's entire
streamed reply. A tool-using decision agent reasons in prose first, so the parse
failed on every such reply, the gate recorded "no decision", and the run fell
through to `default_next`. Live: a Coverage Check returned
`{"decision": "incomplete"}` after about 4 KB of analysis and the run continued
on a synthesis its own checker had rejected. Commit 127b20a3d listed this as
"not addressed here".

## The fix (commit 97717eb9f)

`_trailing_json_object` walks backwards from the final `}` (a closing code fence
is stripped first), honouring string escapes, and returns that object only when
nothing but whitespace follows it. The deliberate boundary is documented in the
function and pinned by the fail-closed test.
