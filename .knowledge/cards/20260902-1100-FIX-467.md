## What was wrong

`frontend/src/components/history/WorkflowHistory.tsx` had the same defect shape as [ISS-302](20260828-1734-ISS-302.md) fixed by [FIX-372](20260829-0141-FIX-372.md) on `/workflows`. ISS-414 was explicitly named as the sibling in FIX-372's card.

`const [deleteConfirmId, setDeleteConfirmId] = useState<string | null>(null)` stored only the run's id when a row's Delete menu item was clicked. The `DeleteModal` component received no name or title, so its body text was fully static: "The workflow run and all its output will be permanently deleted." — indistinguishable across every run in the list, including near-identical titles.

## Root cause

The identifying data was dropped at the point of capture (the click handler stored only `row.id`) rather than lost at render. The modal had nothing to display because nothing was passed to it, not because it failed to look it up.

The pattern correct one function away: the `onRename`/`renameRow` pattern in `SavedWorkflowsPage.tsx` (which FIX-372 used as its reference) had the right shape — store the whole row.

## What changed and why there

One file: `frontend/src/components/history/WorkflowHistory.tsx`. Exactly the FIX-372 shape applied here:

- **State:** `const [deleteConfirmId, setDeleteConfirmId] = useState<string | null>(null)` → `const [deleteRow, setDeleteRow] = useState<WorkflowRun | null>(null)`. The state now holds the whole run row, not just its id.

- **handleDeleteClick:** was `setDeleteConfirmId(runId)` → now finds the run from `runs` and calls `setDeleteRow(run)`. Fallback `{ id: runId } as WorkflowRun` guards the edge case where the run is not in the loaded array (e.g. detail-view delete).

- **handleDeleteConfirm:** reads `deleteRow?.id` and `deleteRow` guard instead of `deleteConfirmId`. Also gained the ISS-209 fix (see FIX-466) in the same handler.

- **DeleteModal component:** added optional `runName?: string` prop; body text branches:
  - With name: `"${runName}" and all its output will be permanently deleted.`
  - Without name (fallback): original static text unchanged
  Using `&ldquo;`/`&rdquo;` to match the JSX text encoding convention in this file.

- **Both call sites** (detail-view `AnimatePresence` and list-view `AnimatePresence`) updated to pass `runName={deleteRow.title ?? undefined}` and `onCancel={() => { setDeleteRow(null); setDeleteError(null); }}`.

The heading "Delete workflow" was deliberately kept unchanged — the dialog title is a role label, not the place to embed variable data, and the existing unit test asserts it.
