# FIX-429

**Phase / trigger:** bug-hunt domain 15 (backend·other), batch B1 — ISS-118

## Description

[FIX-238](20260812-1612-FIX-238.md) installed the only thing standing between the offline
suite and a real AWS bill: `_forbid_live_model_clients`, an autouse fixture that patches
`__init__` on `ChatAnthropic` / `ChatBedrockConverse` / `ChatMistralAI` so constructing a
live provider client is a loud failure. It shipped with an escape hatch —
`_CONSTRUCTS_BUT_NEVER_INVOKES`, an exact-nodeid dict — carrying eight tests that build a
real client but never invoke it (a ninth, ISS-120's, was added later by
[FIX-427](20260831-1813-FIX-427.md)). For those nodeids the fixture returns BEFORE patching
anything, so the guard is fully disarmed for the whole test, not just for the construction.
That is a hole, not a fix: `.ainvoke` / `.astream` added to any of the nine later would be
live spend with the guard already opted out. [ISS-118](20260812-1612-ISS-118.md) filed it
deliberately rather than folding it into the money fix.

This card closes it. Every one of the nine now stubs its own construction seam, and the dict
is empty. Nothing about the guard's mechanism changed — the exemption branch
(`tests/conftest.py:310`) is still there and still fails closed; it simply has nothing left
to exempt, and `tests/unit/test_iss118_construct_only_exemptions.py` fails the moment an
entry reappears.

Three seams, one per construction shape:

**1. `SmartPlanner` (5 of the 9) — a shared `stub_provider_classes` fixture.**
`SmartPlanner.__init__` calls `_build_llm()` (`agents/planner/smart_planner.py:150`), which
imports its provider class lazily INSIDE the function and constructs it without ever going
through `build_model()` — the bypass that made the provider classes, not the factory, the
guard's chokepoint. Because the import is function-local, replacing the class attribute on
the source module is picked up at call time and the real class is never reached; that is the
pattern `tests/unit/test_model_factory.py:77/83/89` already uses, and
`_forbid_live_model_clients`'s own docstring already names it as unaffected by the guard.
The fixture went in `tests/conftest.py` next to the guard rather than being duplicated in two
files, because the two callers sit in different trees (`tests/unit/`, `tests/agents/`) and a
future construct-only test needs one obvious thing to reach for instead of a dict entry. It
stubs BOTH providers, since which branch `_build_llm` takes depends on whether
`ANTHROPIC_API_KEY` happens to be configured on the machine (`smart_planner.py:158` vs `:184`).

**2. `tests/unit/test_cached_invoke.py` (3 of the 9) — `model_construct`.**
All three route through one helper, `_make_recording_bedrock()` (`:71`, called at `:116`,
`:146`, `:337`), so this is one edit, not three. The helper cannot use shape 1: it needs a
GENUINE `ChatBedrockConverse` subclass or the `isinstance` gate in
`cached_invoke._bedrock_cache_control` (`cached_invoke.py:79`) stops firing and the test
becomes vacuous. `model_construct` is pydantic's own no-validation constructor, so the class
identity is real while `ChatBedrockConverse.__init__` — the seam that resolves credentials
and builds the boto3 `bedrock-runtime` client — never runs. Verified: `isinstance` True,
`client` None, `cached_invoke` returns `("ok", {...cache_read: 80...})` with
`cache_control` recorded. `model_id=` is passed rather than `model=`, since `model` is the
field's alias and `model_construct` takes field names.

**3. `tests/agents/test_mcp_client.py` (1 of the 9) — a local `BaseChatModel` instance.**
This one is different in kind: `create_deep_agent(model="anthropic:claude-3-5-haiku-latest")`
made langchain's `init_chat_model` construct a real `ChatAnthropic` inside the LIBRARY, from
a string the test passed. There is no seam in the test to stub — the fix is to stop handing
over a string. `create_deep_agent` accepts an instance, so the test now passes
`_NeverInvokedChatModel()`, whose `_generate` raises `AssertionError`. Strictly better than
the exemption it replaces: the old form would have billed if the graph were ever run; this
one fails the test.

## Root cause

`backend/tests/conftest.py:206` (pre-fix) — `_CONSTRUCTS_BUT_NEVER_INVOKES` exempted nine
nodeids from `_forbid_live_model_clients` (`:310`, `if nodeid in ...: return`), which disarms
the guard for the ENTIRE test rather than for the one construction it was granted for. The
nine were there because their construction seams had never been stubbed: five build through
`SmartPlanner._build_llm` (`agents/planner/smart_planner.py:158/:184/:191`), which bypasses
`build_model()`; three build a real `ChatBedrockConverse` subclass in
`tests/unit/test_cached_invoke.py::_make_recording_bedrock`; one hands `create_deep_agent`
a provider string that the library resolves into a live `ChatAnthropic`.

## What changed

- `backend/tests/conftest.py` — `_CONSTRUCTS_BUT_NEVER_INVOKES` emptied (`{}`), its comment
  rewritten to say KEEP IT EMPTY and point at the three seam-stub shapes; new
  `stub_provider_classes` fixture (non-autouse) that `MagicMock`s `ChatAnthropic` and
  `ChatBedrockConverse` on their source modules. The guard itself, its exemption branch,
  `LiveModelClientConstructed` and `_guarded_classes` are untouched.
- `backend/tests/unit/test_brief_max_chars.py` — the 2 planner tests request
  `stub_provider_classes`.
- `backend/tests/agents/test_iss056_clarify_quality_fixes.py` — the 3
  `TestH3SmartPlannerDesignNote` tests that call `_make_planner` request it; `_make_planner`
  gains a docstring saying so, so the next test added to that class does the same.
- `backend/tests/unit/test_cached_invoke.py` — `_make_recording_bedrock` builds via
  `_RecordingBedrock.model_construct(...)`.
- `backend/tests/agents/test_mcp_client.py` — `_NeverInvokedChatModel` added; the
  `create_deep_agent` call takes the instance instead of `"anthropic:..."`.

No production source changed. `agents/planner/smart_planner.py` appears in ISS-118's globs
but the card's prescribed fix is entirely test-side, and it was left alone.

## Verified independently of the card

The card's blast radius was re-checked before editing, not assumed. Every construction site
in the suite: `grep -rn "ChatBedrockConverse(\|ChatAnthropic(\|ChatMistralAI(\|init_chat_model("
tests/` returns only `test_iss102_live_model_guard.py:28/:41`, which WANT the raise;
`SmartPlanner(` returns 4 sites (2 + 1 + the guard test); `create_deep_agent(` returns 1
test site. The dict had grown from 8 entries to 9 since the card was written — ISS-120's,
added by FIX-427 — and the ninth is covered by the same `_make_recording_bedrock` edit as
its two siblings. Removing exemptions can only narrow the guard's allow-list, so no test
outside those nine can be affected by this change.
