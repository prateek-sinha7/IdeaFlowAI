# ISS-1050

**A product decision, not a confirmed defect.** [ISS-973](20261002-0346-ISS-973.md) raised this as an open question and did
not decide it. [FIX-717](20261002-1243-FIX-717.md) left the Workspace tab alone because of that. This card records the
question so it is not lost.

## What happens today

Take an older family member opened at its own `/runs/{id}`, with no `/versions/{n}` pin. Run History and Home
recents both open members this way.

- The Workspace tab gets `selectedRef={sandboxSelectedRef}` (`PreviewPanel.tsx`, the `<SandboxTab>` mount).
- `sandboxSelectedRef` is set only by a pin, so here it is `null`.
- With `null`, SandboxTab lists the live tree. Every family member shares one sandbox, so the live tree holds the
  NEWEST member's files.

Since FIX-717, the other tabs on the same page all read the member's own tag:
- the Files row,
- the Files Download,
- the header Download,
- the PDF preview.

So the Workspace tab is now the only surface on that page that shows another member's files.

## Why it is a decision

[FIX-604](20260922-1635-FIX-604.md) defines the version menu's "Latest (live)" entry as the uncommitted working tree.
For the Workspace tab, "live" can be a deliberate default. Someone has to decide which of these is wanted:

1. **(a)** An older member's Workspace opens at that member's tag. Pass PreviewPanel's `displayRef` instead of
   `sandboxSelectedRef`. The version menu then needs to show that tag as selected.
2. **(b)** The Workspace tab stays on the live tree by design. Label it so the user can tell it is not this
   member's snapshot.
