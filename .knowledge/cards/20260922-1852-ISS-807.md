# ISS-807

## Description

Sibling of **QA-PS-039**'s root cause work ([ISS-784](20260922-1812-ISS-784.md),
completed by [ISS-808](20260922-1850-ISS-808.md)). One of the two calls
[ISS-808](20260922-1850-ISS-808.md) pins to `page.tsx:990-1007` —
`getWorkflowDefinitions(currentToken)` — fetches `GET /api/workflows` on
every `/dashboard` load and stores the result in `homeWorkflows` state,
purely to hand it down. That hand-off is broken: the value is read by
nothing. This is a distinct defect from the StrictMode doubling — the
fetch is 100% wasted even on a SINGLE, non-doubled call.

## Root cause

`frontend/src/app/[...view]/page.tsx:1004-1006`:

```tsx
getWorkflowDefinitions(currentToken)
  .then((rows) => setHomeWorkflows(rows.filter((w) => w.user_launchable)))
  .catch(() => { /* non-fatal — HomeLaunchGrid falls back to its own fetch */ });
```

`homeWorkflows` is threaded to `DashboardLayout` as a prop
(`page.tsx:4291`: `homeWorkflows={homeWorkflows}`). `DashboardLayout.tsx`
declares and destructures it —

```tsx
// DashboardLayout.tsx:114-117
/** Pre-fetched user-launchable workflow definitions from page.tsx. When supplied,
 *  HomeLaunchGrid uses them as initial state and skips its own getWorkflowDefinitions
 *  fetch, so the card grid appears instantly alongside the recents strip. */
homeWorkflows?: WorkflowSummary[];
...
// DashboardLayout.tsx:458 (destructured from props)
homeWorkflows,
```

— but that is the ONLY other place `homeWorkflows` appears in the file
(`grep -n "homeWorkflows" frontend/src/components/layout/DashboardLayout.tsx`
returns exactly these two lines). It is never passed to `<HomeLaunchGrid>`
(`DashboardLayout.tsx:2894`, whose actual JSX props are
`onSelectFeature`/`onLaunchSaved`/`userTier`/`brief`/`onBriefChange`/`onBuild`/
`recentRuns` — no `homeWorkflows`/`workflows`), and
`HomeLaunchGridProps` (`HomeLaunchGrid.tsx:77-89`) has no such field to
receive it even if it were. `HomeLaunchGrid` sources its `workflows` list
exclusively from `useAppSelector((state) => state.global.workflows)`
(`HomeLaunchGrid.tsx:128`), never from a prop.

The comment at `DashboardLayout.tsx:114-116` describes a design
("HomeLaunchGrid uses them as initial state and skips its own
`getWorkflowDefinitions` fetch") that the code does not implement — either
stale from a prior refactor or never wired up. Either way, the fetch's
result is discarded on every `/dashboard` load, independent of whether
StrictMode doubles the call.

## Expected vs actual

- Expected: either `homeWorkflows` genuinely seeds `HomeLaunchGrid` (per the
  comment's stated intent), or the fetch does not happen at all.
- Actual: `GET /api/workflows` fires (once per mount, twice under
  StrictMode per [ISS-808](20260922-1850-ISS-808.md)) and its response is
  computed into `homeWorkflows`, then dropped on the floor.

## Impact

Pure waste, additive to the doubling [ISS-808](20260922-1850-ISS-808.md)
already accounts for — this is not a third multiplier on the request count,
it is dead weight on calls that already happen. Deleting this call
(rather than caching/deduping it) is the correct fix for this specific
site, since nothing reads the result.
