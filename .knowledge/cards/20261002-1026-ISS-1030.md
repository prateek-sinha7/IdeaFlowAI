# ISS-1030

Sibling of [ISS-953](20261002-0154-ISS-953.md), found while analysing QA-KB-092. It is the other half of the same
incomplete removal: [FIX-584](20260922-0925-FIX-584.md) deleted the run-actions "Chain" item, and the stale test is one
leftover, this option is another.

**Confidence.** Marked INFERRED as a sibling lead, but every static fact below was read or grepped on 2026-10-02
(CONFIRMED). The only inferred part is the future-caller risk at the end.

## Condition

`handleSelectRun` in `frontend/src/components/history/WorkflowHistory.tsx` (`:341-378`), and anyone reading it.

## Expected

After FIX-584, `handleSelectRun(run)` takes one argument, and its comment says only what the code still does: route a row
tap through `onOpenRun` when the caller wires it, else fall back to the legacy internal detail.

## Actual

- `:341` still declares `opts?: { forChain?: boolean }`, and `:358` still reads it: `if (onOpenRun && !opts?.forChain) {`.
- The comment at `:348-357` still says "opts.forChain is the row's explicit "Chain" menu action opting OUT of the
  redirect so that panel is reachable again". No such menu action exists.
- Nothing sets the option. `grep -rnE "forChain" frontend/src` finds the declaration (`:341`), the comment (`:354`), the
  read (`:358`) and one comment in the test file (`WorkflowHistory.test.tsx:351`), and nothing else.
- The only wiring into the list is `onSelectRun={handleSelectRun}` (`WorkflowHistory.tsx:1459`, working tree). It feeds
  `FamilyGroupCard`, whose prop type is `onSelectRun: (run: WorkflowRun) => void` (`RevisionFamilyView.tsx:561`), and every
  call passes one argument (`RevisionFamilyView.tsx:540, 593, 597, 647, 651, 719`).

## Why the root cause implies it

`e4eecb705` (2026-09-12) added both halves in one commit: `handleChainAffordance`, which called
`handleSelectRun(run, { forChain: true })`, and the `forChain` option it needed. `dfd167387` (FIX-584, 2026-09-22)
deleted the handler and the menu item (`git show dfd167387 -- frontend/src/components/history/WorkflowHistory.tsx`
shows the whole `handleChainAffordance` block removed) and left the option. TypeScript has no check for an optional
property nobody passes, so nothing forced the removal. That is the same reason the string role query in the test
([ISS-953](20261002-0154-ISS-953.md)) was not forced either.

## Impact

- **No runtime effect.** The `!opts?.forChain` side of the condition is always true.
- **The stale comment has already misled two investigations.** [ISS-940](20261001-2233-ISS-940.md)'s first
  "Reachability" paragraph named "a row's Chain action" as the way into the History detail pane, and its fixer had to
  correct that. [FIX-711](20261002-0215-FIX-711.md) records "ISS-940's reachability claim was wrong".
  [ISS-835](20260922-2011-ISS-835.md) (closed as not a defect) reached the same finding independently: the
  `setSelectedRun` pane cannot be reached from the live app.
- **INFERRED, not observed.** A future change could follow the comment and pass `{ forChain: true }`, which would
  re-open a pane that no normal user path mounts (the only render site, `DashboardLayout.tsx:3034-3053`, always passes
  `onOpenRun`). The closing note of [ISS-835](20260922-2011-ISS-835.md) calls this "latent".

## Fix direction

Surgical, in the one function:

- Drop the `opts` parameter and the `&& !opts?.forChain` term.
- Cut the comment `:348-357` down to its first sentence (route a row tap into the shared run screen instead of the
  internal detail).
- Leave the dependency array `[activeRunId, onViewRunningPipeline, onOpenRun]` alone.

Do NOT remove the body after the redirect (`:362-377`), even though [ISS-940](20261001-2233-ISS-940.md) and
[FIX-711](20261002-0215-FIX-711.md) call it the "forChain branch". Only the `forChain` opt-out has no caller. That body is
the fallback for an absent `onOpenRun`, which is an optional prop: no production caller omits it, but the
`WorkflowHistory*.test.tsx` files do. Removing the whole legacy pane is a separate decision, out of scope here; both
cards already describe it as unreachable from any user path.

Keep this out of QA-KB-092's change. That bug's contract is "no app change", and its fix is the test-only edit in
[ISS-953](20261002-0154-ISS-953.md). `WorkflowHistory.tsx` also carries uncommitted edits from other fixes in this
working tree, so edit by hunk.

Check after the change: `grep -rn forChain frontend/src` returns only comments in test files; `npx tsc --noEmit` is
clean; each `src/components/history/WorkflowHistory*.test.tsx` file passes when run on its own.
