# FIX-680

## What was wrong

This is bug report QA-KB-030. A user can tick a task_loop agent for review, for example "Build
Agent" under Review gates in either launch wizard. The tick writes `gates: ["human"]` onto the step
and puts the agent in `gate_agent_ids`. The run then opened no review gate at all. There was no
event and no error, and the wizard still said the agent pauses for review.
[ISS-132](20260812-2116-ISS-132.md) has the full analysis and the offline proofs
(`evidence/qa-kb-030/`).

## Root cause

Two facts have to agree, and they did not:

- **Invocation scope.** `task_loop.py:367` (it was `:360` before this edit) passes
  `invocation_gated=False` on every per-task `runner.run_agent` call. Commit `ff37f777a` added that
  flag. `_should_gate(..., invocation_gated=False)` is therefore False at the inline gate sites, and
  the inline review gate never opens for a task_loop step.
- **Step scope.** The step-boundary dedupe predicts whether the inline gate will fire:
  `inline_gated=self._should_gate(spec, ectx) and _runs_agent_inline` (`engine.py:6309` pre-step,
  `:6721` post-step). `_strategy_runs_agent_inline` returns
  `bool(getattr(strategy, "runs_agent_inline", True))` (`engine.py:11474`). `TaskLoopStrategy`
  declared nothing, so the kernel read `True`. `_evaluate_gates` then skipped the declared gate as
  "already covered" by an inline gate that never fires.

[FIX-424](20260831-1652-FIX-424.md) added `runs_agent_inline` for the spawn-only strategies
(`fanout_batch.py:70` and `wave_scheduler.py:245`). At that time task_loop still gated inline.
`ff37f777a` later suppressed task_loop's inline gate but did not declare the matching step-scope
fact.

## Change

The change is one class attribute in
[backend/agents/capabilities/strategies/task_loop.py](../../backend/agents/capabilities/strategies/task_loop.py),
lines 159-164. It sits directly under `name = "task_loop"`, where the fan-out siblings put theirs:

```python
    # ISS-132: ``run`` DOES call ``ctx.runner.run_agent`` for the step's own agent,
    # but every per-task call passes ``invocation_gated=False`` (ff37f777a), so the
    # inline review gate never opens for this step. Declared ``False`` so the
    # step-boundary dedupe runs the step's declared ``gates:[human]`` /
    # ``before-human`` gate instead of skipping it for an inline gate that never fires.
    runs_agent_inline = False
```

The comment explains why the value is `False` even though `run` calls `run_agent`: every call opts
out of the inline gate, so the declared gate has to run. Effects:

- A ticked task_loop step that declares a post-step `human` gate gets exactly one review, after
  the whole loop, not one per task.
- A declared pre-step `before-human` gate also fires once.
- An unticked agent, or a step with no declared human gate, is byte-identical. The predicate was
  already False for those.

## Why there

The kernel already reads the flag off the resolved capability. The strategy is the only place
that knows its own dispatch shape. The change needs no `engine.py` line, no strategy-name branch
(INV-1 / SC-001, and FIX-424 locked constraint 1), no new import and no migration. Every workflow
on task_loop resolves the same class: `prototype`, `prototype_large_revision`,
`prototype_feature_revision`, a composed `prototype-build`, and the `sc001_task_loop` fixture. One
declaration covers all of them.

ISS-132 rejected two alternatives:

- Reverting `invocation_gated=False` would bring back one gate per task.
- Gating only the final task inline is not what the recorded decision (Option A) chose.

## Not addressed

- **Port docs.** Two docs still describe the flag as "does `run` dispatch the step's own agent
  inline": the port comment at `capabilities/base.py:48-55` and the `_strategy_runs_agent_inline`
  docstring (`engine.py:11454-11469`). task_loop is the first strategy that dispatches inline yet
  declares `False`, and its class comment explains why. ISS-132 listed rewording those docs as an
  optional, comment-only companion. It is outside this fix's file scope, which is the task_loop
  class attribute only, so neither file was edited.
- **Call-site test.** The call-site half (`invocation_gated=False`, `ff37f777a`) still has no test.
  `_FakeRunner.run_agent` (`tests/unit/agents/test_strategies.py:168-177`) accepts the flag and
  drops it. Recorded as [ISS-897](20261001-2127-ISS-897.md).

## For the verifier

This is a pure `*.py` change. The backend runs with `--reload`, so it needs no restart. ISS-132
also recommends one manual pass on the newly live path: approve, reject and edit at a declared gate
on a task_loop boundary, including a restart while the run is parked at that gate. That needs a live
run, which this fixer did not start.
