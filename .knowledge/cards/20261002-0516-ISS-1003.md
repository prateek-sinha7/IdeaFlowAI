# ISS-1003

## Description

INFERRED sibling of [ISS-868](20261001-2106-ISS-868.md) (root of QA-KB-068). A hardening lead, not a
failing behaviour: nothing is wrong with the eviction today except the part ISS-868 reports. What this
card records is that nothing would tell anyone if the eviction broke again. The mechanism below was
observed offline; whether it is worth fixing is a judgement, which is why the card stays INFERRED.

**Swallowed.** `backend/app/api/run_engine.py:133-144`, the D4/D5 wiring [FIX-152](20260730-1825-FIX-152.md)
added to `_cleanup_pipeline`:

    try:
        from agents.artifact_store.store import get_artifact_store

        get_artifact_store().forget_run(pipeline_run_id)
    except Exception:  # noqa: BLE001 — best-effort, never block cleanup
        pass
    try:
        from agents.execution_engine.state_machine import get_state_machine

        get_state_machine().forget_run(pipeline_run_id)
    except Exception:  # noqa: BLE001 — best-effort, never block cleanup
        pass

Observed offline (2026-10-02, in-process: `ArtifactStore.forget_run` monkeypatched to raise
`RuntimeError`, restored in a `finally`, no source edited): `_cleanup_pipeline("probe-run")` returned
normally and the only log line that mentioned the run was the StateMachine's own success line,
`StateMachine: evicted state entry for run=probe-run`. Nothing, at any level, about the failure.
The neighbouring best-effort hook does log: `engine._fire_resume_cleanup` catches the same way but
emits `logger.warning("resume_run(%s): bridge cleanup failed: %s", ...)` (`engine.py:15496-15501`).
`run_engine.py` already has a `logger` (`:37`).

**Unpinned.** `grep -rn forget_run backend/tests` finds one hit, `tests/integration/agents/
test_restart_resume_db.py:5350`, where `get_state_machine().forget_run(run_id)` is a "simulate a
restart" step and asserts nothing about eviction. `tests/unit/app/test_artifact_store.py` (11 tests,
all passing on 2026-10-02) covers resume events, questionnaire answers, force-proceed and review
round-trips; none of them calls `forget_run`. The tests that do call `_cleanup_pipeline`
(`tests/integration/api/test_sse_stream_api.py`, `tests/unit/app/test_run_shutdown.py`) assert queue
and sentinel behaviour and never import the store or the state machine. There is no state-machine test
file. FIX-152's own verification line is "code-read + diagnostics (0 errors)".

## Why the root cause implies it

[ISS-868](20261001-2106-ISS-868.md) is a half-closed D4: the review-key scan at `store.py:219-225` iterates `_resume_events` only,
while `set_review_response` writes `_questionnaire_responses` (`:162-163`). FIX-152 is dated
2026-07-30 and the gap was found on 2026-10-01, 63 days later. It lasted that long because both usual
catches are missing: no test reads the store after a run ends, and a failure inside the eviction is
discarded without a trace. The same two blind spots cover `StateMachine.forget_run`
(`state_machine.py:138-148`), so a later edit to either, including the ISS-868 fix itself (a loop that
pops from the live `_questionnaire_responses` dict raises `RuntimeError: dictionary changed size during
iteration`), would ship unseen.

## Expected vs Actual

- **Expected:** a failing run-end eviction leaves a WARNING with the traceback (still never blocking
  cleanup), and a test pins that after `_cleanup_pipeline(run_id)` the singleton store holds nothing for
  that run (events, clarify answers, force-proceed flag, review events, review responses) while another
  run's entries survive, and that `get_state_machine().get_state(run_id)` is `None`.
- **Actual:** the failure is silent and neither eviction has a regression guard.

## Where the fix belongs

`run_engine.py:137-138` and `:143-144`: replace `pass` with `logger.warning("... forget_run failed for
run=%s", pipeline_run_id, exc_info=True)`. Keep both `try/except` blocks so cleanup still never raises.
Tests: the `ArtifactStore.forget_run` unit test belongs with the ISS-868 fix in
`backend/tests/unit/app/test_artifact_store.py`; the wiring test (seed the singletons, call
`_cleanup_pipeline`, assert both empty; then make `forget_run` raise and assert cleanup returns and a
WARNING is logged via `caplog`) belongs beside `tests/unit/app/test_run_shutdown.py`, which already
drives `_cleanup_pipeline` under the offline tier.

If the owner decides a silent best-effort cleanup is intended, close this as won't-fix and keep only the
tests.

## Fix phase (5-fixer, 2026-10-07, QA-KB-068): not fixed, left open

[FIX-728](20261007-1848-FIX-728.md) fixed the root, [ISS-868](20261001-2106-ISS-868.md), inside
`ArtifactStore.forget_run`. Its loop iterates a list copy of each registry, so the dict-mutation hazard this card
predicts for that fix cannot fire. `run_engine.py:137-138` / `:143-144` still `pass` silently, and no wiring test
exists. This card has no red test and calls itself a judgement call, so the fixer left it alone. Status stays `open`.
