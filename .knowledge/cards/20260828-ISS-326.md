## What happened

Validated from `BUG-20260827-221400-dashboard`. On `/dashboard`, clicking "Inspect <card title>
details" on any catalog card (`frontend/src/components/catalog/HomeLaunchGrid.tsx:326-327`, the
`setInspectId(row.id)` handler) opens `WorkflowDialog`
(`frontend/src/components/catalog/HomeLaunchGrid.tsx:392`,
`{inspectId && <WorkflowDialog workflowId={inspectId} onClose={...} />}`) — a `role="dialog"
aria-modal="true"` overlay (`frontend/src/components/workflow/WorkflowDialog.tsx:134-135`)
showing the workflow's Context Providers, Capabilities and Compaction sections.

Pressing Escape while the dialog is open does nothing: the dialog stays open and the page stays
dimmed behind the backdrop. Only the explicit "Close" (X) button dismisses it.

## Reproduction — 3/3, every cycle, cold start

Each attempt started from a fresh navigation to `/dashboard` (not a soft re-click):

1. Cycle 1 & 2: clicked "Inspect Retry Until It Passes details" -> "Retry Loop" workflow dialog
   opened -> pressed Escape -> dialog (`role="dialog" "Retry Loop workflow"`) still present in
   the accessibility tree.
2. Cycle 3: clicked "Inspect Build an end-to-end application details" -> "App Builder" workflow
   dialog opened -> waited 1s for the page to settle -> pressed Escape -> dialog (`role="dialog"
   "App Builder workflow"`) still present.

Expected: Escape closes the dialog, matching the `role="dialog"`/`aria-modal="true"` semantics
already declared on the element.

Actual: Escape is a no-op in all 3 cycles; the dialog only closes via the Close (X) button.

## Root cause

`frontend/src/components/workflow/WorkflowDialog.tsx` declares `role="dialog"` and
`aria-modal="true"` (lines 134-135) but contains no Escape/keydown handling anywhere in the file
— `grep -n "Escape\|onKeyDown"` returns zero matches. The component's only `useEffect` (line 63)
is a data-fetch effect for `getWorkflowDetail`/`getCapabilities`, not a key listener. The dialog
is dismissed only via the Close `<button>`'s `onClick={onClose}`.

## Distinct from ISS-272

[ISS-272](20260828-1852-ISS-272.md) covers the same class of defect (a `role="dialog"` modal with
no Escape handler) but in `SkillDetailModal`/`HookDetailModal`
(`frontend/src/components/library/LibraryPage.tsx`), reached from the Library page. That card
explicitly scopes `AgentsPopup.tsx` out as a separate investigation and does not mention
`WorkflowDialog.tsx` at all. `WorkflowDialog` is a third, independent component (SHELL-04/SURF-03)
reached only from the dashboard catalog's Inspect affordance — not a duplicate of ISS-272, but the
same missing-Escape-handler pattern recurring in a third modal component.
