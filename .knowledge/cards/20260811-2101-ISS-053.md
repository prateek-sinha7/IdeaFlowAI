# ISS-053

## Title

`update_specs_eligible` is an FE affordance only — `_run_review_gate` (`engine.py:5470`) acts on the gate action WITHOUT ever consulting it. A replayed or hand-crafted POST can therefore trigger a revision from a gate where the UI does not offer one, bypassing whatever eligibility rule is in force.

## Severity / Tag / Status (original row)

- Sev: major
- Tag: agents,auth
- Status: **FIXED** — FIX-253 (ex-FIX-219) / quick-260812-12t (2026-08-12)

## Source / Evidence

Found by the si4 planner while evaluating whether suppressing the affordance would be a sufficient fix for ISS-064. **si4's disposition was reversed on evidence.** T-si4-01 accepted the gap on the premise that a crafted or replayed POST "causes a REDUNDANT revision, never a corrupted one"; that premise is false in three independent ways. (1) **Corruption, not redundancy** — the sub-pipeline picks targets POSITIONALLY, so at the two DEFAULT-gated agents (`prototype-specify` idx 0, `prototype-plan` idx 1, both `gate: Human_Gate`) the `index < 2` early-return revises NOTHING yet still sets `spec_revision_pending_output=""`, blanking the agent's `results` output and re-opening the gate empty — every stock prototype run exposed with zero configuration. (2) **Cost** — at an inline gate on `prototype-build`/`prototype-validate` (both selectable in the shipped "Review gates" wizard control) one POST re-runs three agents INCLUDING the build; measured on live run `5ecb990f` that is ≈$3.68 vs ≈$0.03 for the revision cycle si4 reasoned about (~127×), with no rate limiting anywhere in the API layer. (3) **It already happened** — live run `d5dbc9f2` seq 20360 advertised `eligible=0` and a durable `gate_events` row records `prototype-analyze / human / update_specs` **6.05s later**. Also: `gate_key = f"{run_id}:{agent_id}"` names a gate SLOT, not a FIRING, so no crafting is needed — replaying a legitimate earlier click suffices. **Fixed as two layers over ONE rule** (the rule stays solely in `_update_specs_eligible`): the engine refuses an ineligible action and KEEPS WAITING (never approve — fail-open, the Phase-23 F1a hole, against WR-07; never reject — that cancels the run), and all THREE `set_review_response` ingresses answer 409 `update_specs_not_offered` by reading the engine's own published verdict back off `review_gate_ready`. The declared-gate `_gate_update_specs` silent-PASS + wire leak (`gates/human.py`, `gates/approval.py`) closed in the same pass. si4's nesting safety is retained and still tested as defence in depth.
