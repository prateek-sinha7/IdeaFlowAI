state has not been observed on a real tree. Found by the QA-KB-026 analysis of [ISS-693](20260918-ISS-693.md),
which is the root card.

Reference base: `build_architecture.py` line numbers are at HEAD 024c03ef. The QA-KB-004 change
([BUG-129](20260918-BUG-129.md), in the working tree, not committed) adds 7 lines at `:132` and 1 at `:159`, so in a
tree that has it add 8 to every reference at or below `:160`.

## Condition

A `DOMAIN-*.md` file in `.knowledge/architecture/` whose first 2000 characters carry no `code_signature:`
line. `build_architecture.py` writes that field on every DOMAIN card it processes (`:1186`). It skips,
without writing the field, a card whose frontmatter will not parse, has invalid YAML, or has no `members:`
list (`:1105`, `:1110`, `:1114`, each a `problems.append(...)` followed by `continue`). So the field is
absent on (a) a hand-authored card nobody has built yet and (b) a card the build skipped.

## Expected vs actual

- Expected: the row cannot vouch for a card it has no stamp for. That card should be counted as unbuilt or
  unknown, not as verified current.
- Actual: `tools/knowledge/status.py:322-323` does `continue` on a missing `code_signature`, so the card
  enters neither `stale_domains` nor `unauthored_domains`. `:328` then sets `n_domains` to the count of every
  `DOMAIN-*.md` file, and `:330` reports `found` as `n_domains - len(stale_domains) - len(unauthored_domains)`.
  The skipped card is inside `found`, and the verdict at `:332` is `OK`.

## Why the root cause implies it

[ISS-693](20260918-ISS-693.md) locked constraint 3 says a check whose inputs are stale must not verdict OK.
Here the input is absent rather than stale, through the same OK-by-default shape in the same block. Fixing
the verdict at `:332` for an overdue architecture build does not touch this case, because `source files
covered` and `source files changed` can both be OK while a card has no stamp.

## Evidence (simulated, no repo file edited)

Harness on a throwaway copy of the DOMAIN cards, with `status.K` pointed at it (scenario S3 of the QA-KB-026
analysis): the four stamp lines (`code_signature`, `prose_signature`, `symbols_signature`,
`prose_symbols_signature`) were stripped from the copy of `DOMAIN-hitl-gating.md`, then `status.main()` was
run with `--json`. Result: `source files covered OK`, `source files changed OK`, `domain prose 16 16 OK`.
The unsigned card is counted as one of the 16 verified.

The real tree does not have this state today: all 16 DOMAIN cards carry `code_signature`, and the largest
offset of `prose_signature` inside the 2000-character read window is 1034.

What would settle it: add a DOMAIN card without running the architecture build, run `status.py`, and expect
`N+1 N+1 OK`. A hermetic test can do the same with a temporary `K` directory.

## Where the fix belongs

`tools/knowledge/status.py:322-323` and `:328-333`. Collect cards with no `code_signature` into a third list,
subtract it from `found`, and give the row a non-OK verdict that names them. `build_architecture.py:327-328`
(`stale_prose_report`, `--stale-prose`) has the same skip. Treat that as a follow-up, not part of this card:
its output is labelled "known-stale" by `diagrams.md`, so it does not claim a card is current.

of the same function. This region starts at `:322`, directly after, so edit against a fresh read of the file.
