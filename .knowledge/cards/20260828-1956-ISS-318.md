## Summary

On the Library agent detail drawer (`/library/agents/<agentId>`), the Skills tab's "+"
add button gives full success feedback — filled checkmark on the row, count badge on the
"SKILLS" header — for a change that fires zero network requests and has no Save/Cancel
affordance anywhere on the tab. A reload of the same URL silently wipes the selection back
to zero with no warning.

## Root cause

`AgentSkillsPicker` (`frontend/src/components/workflow/composer/AgentSkillsPicker.tsx:44-49`)
documents its own contract explicitly:

> `readOnly` exists for the mounts with nowhere to write back — the Library page's agent
> drawer (a catalog agent belonging to no pipeline) and the wizard popup ... Showing the
> real, correctly-filtered list disabled is honest; showing live checkboxes that silently
> discard the click is not.

`AgentCapabilitiesModal` computes `readOnly={!onSkillsChange}`
(`frontend/src/components/workflow/AgentsPopup.tsx:861-864`) — readOnly is only true when
the caller supplies no `onSkillsChange`.

`LibraryPage.tsx:947-967` (`AgentCapabilitiesModal` mount inside the agent detail
`AnimatePresence` block) DOES pass an `onSkillsChange` callback:

```tsx
onSkillsChange={(agentId, skills) => {
  savedSkillsRef.current[agentId] = skills;
}}
```

`savedSkillsRef` is a plain `useRef` living in `LibraryPage`'s component instance — not
persisted to the backend, not written to `localStorage`, not seeded into the initial
`agent.skills` from any API. It survives only while the `LibraryPage` component instance
stays mounted (so a reopen of the same drawer without a navigation/reload restores it —
matching the comment "the drawer restores it on reopen"), and is discarded on any full
reload or fresh navigation to the route, which is exactly the reload-wipe symptom in
BUG-20260828-092630-library-agents-id.

So this is a wiring bug against the component's own documented contract: `LibraryPage` is
named by `AgentSkillsPicker`'s comment as one of the mounts with "nowhere to write back"
that should render `readOnly` (disabled `+`/checkbox, no false affordance), but it supplies
`onSkillsChange`, which flips `readOnly` to `false` and lets `AgentSkillsPicker` render its
full interactive/success UI (checkmark + badge, `frontend/src/components/workflow/composer/AgentSkillsPicker.tsx:245`
"readOnly && compatible.length > 0" empty-state branch is skipped when not readOnly).

## Reproduction (3/3, cold start each cycle)

Each cycle: fresh navigation to `http://localhost:3000/library/agents/material-analyzer`
(qa-admin session), open Skills tab, click "+" on a skill, confirm no new
`/api/agents*` or `/api/skills*` request via `browser_network_requests`, screenshot the
checkmark+badge, then reload the same URL and re-open Skills tab.

- **Cycle 1** — added ".NET Backend Expert". Checkmark + "SKILLS 1" badge appeared
  immediately, zero new network requests. Reload: badge gone, skill shows unchecked "+"
  again.
- **Cycle 2** — added ".NET Development Patterns" on a fresh navigation. Same result. (An
  unrelated `ReferenceError: pinnedVersion is not defined` error-boundary crash fired on
  this cycle's reload before the Skills tab was reachable — recovered via "Try again"; not
  part of this bug, noted for the register/hunters as a separate defect worth a look.)
- **Cycle 3** — added "Accessibility Auditor" on a fresh navigation. Same result, no error
  this time.

All three cycles reproduced identically: instant checkmark/badge feedback, zero network
calls, complete loss on reload. No axis variance was needed — this is a straightforward
3/3 CONFIRMED from BUG-20260828-092630-library-agents-id.

## Expected vs Actual

**Expected:** either the Library agent drawer's Skills tab renders `readOnly` (as its own
component contract specifies for this exact mount, matching the disabled state already
correct on e.g. the wizard popup path with no `onSkillsChange`), or the add action actually
persists (a real save call, surviving reload) with a visible Save/unsaved-changes affordance
like the Config tab has.

**Actual:** `LibraryPage.tsx` supplies `onSkillsChange`, so the picker renders as if this
were a durable, interactive surface — full checkmark/badge success feedback — while the
target of that write is a component-lifetime-only `useRef`, giving no persistence and no
warning that the change is not saved.
