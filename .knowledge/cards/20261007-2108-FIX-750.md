# FIX-750

## What was wrong

Register entry QA-KB-094 (Low, developer tooling). The root card is [ISS-1042](20261002-1100-ISS-1042.md).
`tools/api/runs/run.ex_A4_human_gate_auto.http:94` approved the routed human gate with
`"edited_content": "spanish"`, a bare word. Since `0b6570b85` / [ADR-0026](20260825-1600-ADR-0026.md) the fixture
routes on `condition_agent: ask` (`workflow.yaml:111`), so that raw edit IS the routing decision.
`ConditionalGate._read_decision` (`conditional.py:208-267`) accepts only JSON `{"decision": ...}`. The bare word
matched no outcome, the gate returned GATE_BLOCK, and the run ended `pipeline_failed` (live run
`9eb70b6e-5a70-41e8-9d5f-fbb05e11440d`, `evidence/qa-kb-094/analyze-db-select.txt`).

Two siblings come from the same drift. Both runners were last edited the day before ADR-0026 landed.

- [ISS-1045](20261002-1204-ISS-1045.md): the interactive twin printed the same bare-word curl hint
  (`run.ex_A4_human_gate.http:95`).
- [ISS-1046](20261002-1204-ISS-1046.md): both assertion blocks modelled the engine as it was before ADR-0026 and
  [ISS-170](20260824-1610-ISS-170.md). A `✗` was keyed on pick-language's own reply, which the gate no longer
  reads, and a conditional block was reported as "fell through" although it now fails the run.

## Root cause (from ISS-1042's analysis, re-checked on this tree before editing)

Client drift; the server is right. The decision source moved to the human's raw edit, and neither scripted
client moved with it. Strict JSON is the documented contract (`specs/014-conditional-gates/contracts/manifest-route-schema.md:60-68`).
The fixture's own header still said `condition_agent` was "deliberately ABSENT" and that pick-language "routes on
the line it just generated". That is the text a runner author copies.

Blast radius, re-grepped before editing: `grep -rln edited_content tools/ tests/ scripts/ specs/ velocity.json`
(logs excluded) returns exactly the two A4 runners. The UI (`InlineGateActions.tsx:320`) and T26
(`test_conditional_human_gate_source_t26.py:187`) already send the JSON object.

## What changed, and why there

Only the client side changed. The engine, the gate and the manifest logic are untouched, and the strict
`_read_decision` stays.

1. **`run.ex_A4_human_gate_auto.http` (ISS-1042).**
   - The body at `:98` is `"edited_content": "{\"decision\": \"spanish\"}"`, on one line.
   - The log line at `:104` prints `edited_content={"decision": "spanish"}`.
   - The header at `:7-9` says the answer is a JSON decision object sent as a string, and a bare word blocks the
     gate and fails the run.
2. **`run.ex_A4_human_gate.http` (ISS-1045).**
   - The hint at `:97` prints `"edited_content":"{\"decision\":\"spanish\"}"` through a `String.raw` template.
   - The box text at `:94` says to keep the `{"decision": ...}` object, because a bare word blocks the gate.
3. **Both assertion blocks (ISS-1046).**
   - Check 3 ("pick-language decided … does not match decision") is gone, and checks 4 and 5 are renumbered 3
     and 4. The auto runner keeps its `EXPECT` branch check (`:165-172`). The twin stays choice-agnostic.
   - The block line now reads "the run FAILED at the gate instead of routing". Its comment is rewritten for
     ISS-170 and `condition_agent: ask`.
   - The twin's header (`:5-6`, `:12-14`, `:22-25`) no longer claims its checks read "the decision the engine
     actually recorded".
4. **`backend/agents/workflows/ex_A4_human_gate/workflow.yaml` header (ISS-1042 item 3), comments only.**
   - `:10-15`, `:27-29` and `:35-38` now say the gate routes on `ask`'s artifact and needs `{"decision": ...}`.
   - `yaml.safe_load` of the file equals HEAD's (checked), so the compiled plan is unchanged and no restart is
     needed.

### One deviation from ISS-1045's wording (the printed text is identical)

ISS-1045 says the JS source needs its backslashes doubled. That form prints the right text. The test's `_edits`
regex (`test_ex_a4_runner_gate_answer_qa_kb_094.py:48`, `(?:[^"\\]|\\.)*`) cannot read it, though: it
captures only `{\\` and fails.

A `String.raw` template prints byte-identical output. Node, both candidates:
`-d '{"gate_key":"K","action":"approve","edited_content":"{\"decision\":\"spanish\"}"}'`, and `edited_content`
parses to `{"decision":"spanish"}`. Its source carries single `\"` escapes, which the test decodes.

The test was not edited. Note for the verifier: the regex would still reject ISS-1045's doubled-backslash
spelling. The module-level `_EDIT` regex (`:20`), which looks written for that case, is never used.
