# ISS-097

## Title

Gating a fan-out step's own agent may open an inline review gate in EVERY worker. kernel_services.py:971-984 builds the per-worker step view with gates=[], which reads as "this worker has no gates" — but the inline review gate is not driven by step.gates at all. _should_gate (engine.py:4861-4864) reads ectx.gate_agent_ids, the per-run selection, and a fan-out worker runs the SAME agent_id as its parent step (fanout: agent: self). So if a user ticks that agent in the per-run gate selector, every one of the N workers independently reaches _should_gate → True and opens its own review_gate_ready — N simultaneous review gates for one logical step, each awaiting a human. The gates=[] on the worker step view is a false reassurance: it suppresses only the DECLARED gate path, not the inline one. Not exercised by any test found (every fan-out test passes gate_agent_ids=None or []), and unreachable from the static AGENT.md defaults for the sample fan-out agents — it needs the per-run gate selector, i.e. a real user ticking the box in the launch wizard. Not verified live (that would cost a real build); this is a code-read finding with a named reachability path, so treat the *severity* as provisional and the *mechanism* as evidenced. Suggested first step: an offline test that fans out with gate_agent_ids=[<the fan-out step's agent>] and counts review_gate_ready events — 1 is correct, N is the bug.
