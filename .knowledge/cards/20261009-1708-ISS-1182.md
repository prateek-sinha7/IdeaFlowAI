# ISS-1182

**Register source:** sibling derived during the `QA-KB-124` analysis on 2026-10-09 (root [ISS-1156](20261009-1445-ISS-1156.md)). Not its own bug row.

**Confidence:** INFERRED. CONFIRMED part: the plan shape (write grant + `route` + `produces: ["route_decision"]`) fails offline through the real engine and factory (`evidence/qa-kb-124/analysis-03-offline-repro.txt`, scenario 2); a Composer manifest compiles to the same fields. NOT run: a decision step drawn on the Composer canvas and launched on Bedrock Haiku. What would settle it: compose that workflow in the UI, Run once on the default model, then read `run_events` for a `write_file` tool_call on the decision step followed by `gate_blocked`.

## Condition

A workflow composed on the canvas (`/workflows/new`, or an inline `manifest` Run once of an unsaved composition) whose decision step has a conditional Review gate with step-target outcomes and no `default_next`, with the step's Tools left at the Composer default (Read files and Write files both ON: `userWorkflows.ts:336-339`), run on the default Claude Haiku 4.5. The route fixtures hide it because they declare their decision steps tool-free.

## Expected vs actual

Expected: the decision step's reply carries the decision and the run routes (the gate's contract: "the artifact is the decision agent's WHOLE streamed reply", `conditional.py:237`; [FIX-526](20260901-2232-FIX-526.md) recovers a trailing JSON object). Actual (predicted from the root): the model obeys `## How to deliver ... Call write_file ... Its content is your answer` (`factory.py:727-731`), writes the decision to `<step>-<topic>.md`, replies with prose, and the gate blocks.

## Why the root cause implies it

The root's mechanism needs a write-granted step that is a gate's decision source, and nothing else. A saved override was only how `ex_A1_loop` acquired the grant ([ISS-1181](20261009-1708-ISS-1181.md)); the Composer grants it by default.

## Evidence that the hazard is known and has been patched by hand, not at the source

- `ex_A2_branch/workflow.yaml:66`, `ex_A3_divert/workflow.yaml:76`, `ex_A4_human_gate/workflow.yaml:98` and `ex_A4_human_divert/workflow.yaml:81` each tell the decision step "reply with the JSON as your text answer - this must be your reply, not a file". `ex_A1_loop`'s `check` does not.
- `factory.py:719-726` documents the same failure for a write-LESS step ("a write-less step's final reply going empty because it wrote its real answer to a file instead, which the conditional gate can't read route_decision from") and guards only that case.
- The sentence is not enough. In the A2 override run `41f50ae1` (Bedrock Haiku) the decision step still wrote `{"decision": "spanish"}` to its file; it routed only because its reply ALSO ended with the JSON. `evidence/qa-kb-124/analysis-02-live-runs-override-vs-builtin.txt` section 7.
- The engine already treats a decision step's reply as special in one place: the single_file readback is skipped when `"route_decision" in spec.produces` (`engine.py:10651-10668`). The factory's delivery block has no such exemption.

## Fix direction

The same function as the root: `_compose_system_prompt`, custom-agent branch (`factory.py:727`). One predicate, shared by every authoring path (override, Composer saved and inline, API manifests); the four hand-written prompt sentences then become redundant. Nothing to change in this card's callers.

## Test notes

Backend unit, no model, next to `backend/tests/unit/agents/test_custom_agent_prompt.py`: `dataclasses.replace(load_agent_spec("custom-agent:check"), produces=["route_decision"])` composed with `_compose_system_prompt(spec, AgentContext(user_request=..., topic=...), no_tools=False)` must not contain `How to deliver`, while the same spec without `produces` still does (the existing tests pin that). To settle the INFERRED part, drive the Composer-style manifest through `tests.agents._scripted_model._drive` with `compile_for_run` patched, as `evidence/qa-kb-124/analysis-03-offline-repro.py` does.

## Evidence

`evidence/qa-kb-124/analysis-03-offline-repro.txt`, `analysis-02-live-runs-override-vs-builtin.txt`.

## Fix stage (5-fixer, 2026-10-09)

The fix direction above shares the flaw recorded on [ISS-1156](20261009-1445-ISS-1156.md) under "Fix stage". At run time `_compose_system_prompt` gets the spec that `create_runner` reloads by id (`factory.py:350`), and that spec has no `produces` for a `custom-agent:<id>` step. A predicate on `spec.produces` therefore never fires, and the decision step's declared `route_decision` has to be threaded to the factory. Evidence: `evidence/qa-kb-124/fix-01-card-predicate-inert.txt`.

## Re-analysis (QA-KB-124, 2026-10-09)

**Fix direction.** "The same function as the root" above is right about WHERE the guard lives and wrong about its input: `spec.produces` is empty at `factory.py:727` for every composed step, so the engine has to thread the step's declared `produces` into `AgentContext` first. The corrected direction, the 11-line scratch diff and the tests that discriminate a working fix from an inert one are on [ISS-1156](20261009-1445-ISS-1156.md) ("Re-analysis"). The test notes above (a hand-built spec through `_compose_system_prompt`) are superseded by the engine-driven candidate there: the hand-built form XPASSes against the inert predicate.

**Evidence moved.** The plan shape is now reproduced offline on the Composer's own defaults rather than on the stored override: the built-in's edges (`produces`, `consumes`, `depends_on` all intact) with every step's grants flipped to read+write. The composed `check` prompt carries `## How to deliver ... Call write_file`, and a Haiku-like model that obeys it ends `gate_blocked` (`evidence/qa-kb-124/analysis-07-candidate-fix-probe.txt`, third scenario, HEAD block). With the threaded fix the same plan runs emoji, greet, check, greet, check, done and completes. So the wiring is CONFIRMED; what stays INFERRED is only whether Haiku obeys the block on a Composer-drawn plan as it did on the stored override (4 of 4).

**Why the fixtures hide it, measured.** The 7 shipped workflows that have a decision step hold 9 of them, and none holds a write grant (`evidence/qa-kb-124/analysis-10-builtin-decision-step-grants.txt`); every one is tool-free or read-only.

**A second wall for composed loops.** Once the decision step routes, a looped write-granted step meets [ISS-1192](20261009-1832-ISS-1192.md) on its second pass.

## Fix (FIX-783, 2026-10-09)

The root's fix covers this card, as its "Fix direction" predicted: one predicate in `_compose_system_prompt`
for every authoring path, with nothing to change in the callers. The engine now threads the compiled step's
declared `produces` into `AgentContext.step_produces`. The factory skips `## How to deliver` for a
`route_decision` step whatever its grants. `backend/tests/agents/test_decision_step_delivery_via_engine_iss1156.py`
drives exactly this card's plan shape: the built-in edges with read+write on every step, the Composer default.
It gives XPASS(strict) on the fixed tree. The `analysis-07` probe's ISS-1182 scenario, run on the fixed tree,
reaches `pipeline_complete`. Still INFERRED and not run: a canvas-drawn decision step on live Haiku. The four
route fixtures keep their hand-written sentence; it is now redundant but harmless. See [FIX-783](20261009-1855-FIX-783.md).
