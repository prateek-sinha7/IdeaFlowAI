# ISS-075

## Title

Reopening a run resets the whole Steps trace to idle. The trailing resume pipeline_start carries resume_offset = 0 (run d5dbc9f2 seq 24791 — verified in run_events: both of that run's pipeline_start frames read "resume_offset": 0), and useWorkflow.ts:234-240 seeds status: idx < resumeOffset ? "done" : "idle". With the offset at 0 every agent is rebuilt as "idle", so a completed 5-agent run that is reopened — or any live session whose SSE connection reattaches and replays from seq 0 — should repaint its Steps spine as if nothing had ever run. Note the frame is emitted ~24 minutes after the last agent finished (21:25:42 vs 21:01:19), i.e. it is not part of the original execution. Same invisibility family as ISS-063/ISS-065: durable state is correct, the screen contradicts it. Suspected cause is the resume path computing the offset before the completed-agent count is known, or defaulting it; not traced.

## Source / evidence

Found 2026-08-12 during the ISS-063 investigation and re-verified from backend/dev.db while fixing it (quick-260812-2ci). Confirmed in code and data; NOT observed on screen — that observation is the first thing a fixer should do, because if it reproduces it is arguably more serious than the banner defect it was found beside. FIX-221 is independent of it: the revision count is now carried across a same-run pipeline_start precisely so this frame cannot erase it.
