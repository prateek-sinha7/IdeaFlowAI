## What happened

On a completed run's Steps tab, expanding an agent row's "Tool calls" panel shows a collapsed
one-line summary per call in the form `<tool_name>  <args preview>  ok`. When a tool argument's
value is an array of objects — e.g. the `write_todos` tool's `todos` array, an array of
`{content, status}` items — the collapsed summary literally renders
`todos: [object Object],[object`, the raw output of JavaScript's default
`Array.prototype.toString()`/string coercion applied directly to the object array, instead of a
readable preview. The fully expanded "Arguments" panel underneath the same row renders the
identical data correctly as pretty-printed JSON, confirming the data itself is intact and the
defect is isolated to the collapsed summary's own formatting.

Confirmed **CONFIRMED, 3/3, cold start every cycle** on 2026-08-28: each cycle logged in fresh
(cleared `localStorage`/`sessionStorage`, re-authenticated as `qa-admin@flowinqa.com`), navigated
to `/dashboard`, then cold-navigated to
`/runs/b9feac1c-ec21-4531-8ba7-bb391786993e/steps`, and expanded the "Deck Engineer Agent" row via
`element.click()` (per the `stepsTabRowBlocked` automation quirk in `bug-hunter/velocity.json`).
All three cycles produced the identical collapsed text `write_todos   todos: [object Object],[object   ok`
on all three `write_todos` calls in that row's "Tool calls 4" panel. The sibling `write_file`
call in the same panel, whose argument is a plain string, renders its collapsed preview correctly
(`write_file  file_path: /tmp/kindred-pitch-deck., content: <!DOCTYPE html> <html la  ok`),
showing the bug is specific to non-string (array/object) argument values, not the summary
mechanism generally.

## Root cause

`frontend/src/components/results/AgentDetailPanel.tsx:412`:

```tsx
{Object.entries(tc.args || {}).map(([k, v]) => `${k}: ${String(v).slice(0, 24)}`).join(", ") || "no args"}
```

`String(v)` on a non-string `v` uses JavaScript's default coercion. For a plain object this
yields `[object Object]`; for an array of objects it yields each element's `[object Object]`
joined by literal commas (`Array.prototype.toString()` calls `toString()`/coerces each element),
producing `[object Object],[object Object],[object Object]` — truncated by `.slice(0, 24)` to the
`[object Object],[object` seen in the UI. Primitive values (strings, numbers) coerce correctly,
which is why `write_file`'s string `content`/`file_path` args render fine. The fix belongs in
this one line — e.g. `JSON.stringify(v)` (or a type check that stringifies objects/arrays as JSON
before truncation) instead of the bare template-literal coercion — since every collapsed
tool-call preview on the Steps tab routes through this same expression.

## Expected vs actual

- **Expected:** the collapsed tool-call summary shows a readable preview of any argument value —
  a truncated JSON string, item count, or similar — regardless of whether the argument is a
  string, array, or object.
- **Actual:** array/object argument values are coerced with JavaScript's default
  `String()`/`toString()` behaviour, producing the literal text `[object Object],[object` in the
  collapsed summary row, on all 3/3 `write_todos` calls observed in the reproduction run, and on
  every cold-start reproduction cycle.

## Reproduction (worked on cycle 1, 2, and 3 — cold start each time)

1. Clear `localStorage`/`sessionStorage`, sign in fresh as `qa-admin@flowinqa.com`.
2. Cold-navigate to `/dashboard`, then to `/runs/b9feac1c-ec21-4531-8ba7-bb391786993e/steps`.
3. `element.click()` the "Deck Engineer Agent" lane row (direct DOM `.click()`, not a Playwright
   mouse click — the `stepsTabRowBlocked` quirk).
4. Its "Tool calls 4" section auto-expands; all three `write_todos` calls show the collapsed
   summary `todos: [object Object],[object` instead of a readable preview.
5. Expanding any one `write_todos` call's "Arguments" panel shows the same data correctly
   pretty-printed as JSON — confirming the defect is presentation-only.

Conditions: tier `qa-admin`, light theme (default), standard viewport, run state `completed`
(pre-existing run, populated with real tool-call history — not a live/generating run), reproduced
identically on both first visit and every subsequent cold revisit. No timing or entry-path
variance was needed; the trigger is simply: any tool call whose argument value is an array or
plain object.
