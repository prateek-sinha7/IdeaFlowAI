## What happened

On `/handoff/settings`, the "API key name" field defaults its React state to
`"Default"` (`useState("Default")` at `IntegrationsCard.tsx:61`) and falls
back to `"Default"` on submit only when the value is empty/falsy
(`keyName || "Default"` at `IntegrationsCard.tsx:147`). A name made of only
whitespace (e.g. three spaces) is a non-empty, truthy string, so it bypasses
the fallback entirely and is sent to `POST /api/settings/api-keys` verbatim.
The backend accepts it as-is with no trim/validation, and the new key renders
in the "VelocityAI API keys" list with a name area that is visually blank —
every other row shows a name like `Default` or `e2e-handoff-fixture` before
the token-prefix line; this row shows nothing. The blank name is permanent:
revoking the key just swaps in a "revoked" badge, the name area stays blank
forever, and the only way to identify the row afterward is its token prefix.

## Reproduction (3/3, cycle 1)

Confirmed CONFIRMED on the first cold-start cycle, and reproduced identically
on cycles 2 and 3 (3/3 total, no narrowing needed):

1. Sign in as `qa-admin@flowinqa.com`, navigate fresh to `/handoff/settings`
   (cold nav each cycle, not a soft re-click).
2. Click the "API key name" field, clear the pre-filled `"Default"` text
   (real `Backspace` keystrokes), then type three literal space characters
   via real keystrokes (`Backspace` then `pressSequentially('   ')`) —
   confirmed `el.value === "   "` before submit. (Setting `.value` directly
   plus a bare synthetic `input` event does NOT reproduce this — React's
   controlled-input tracking ignores it and the fallback correctly applies;
   only genuine keystroke input, matching a real user typing spaces, drives
   `keyName` state to the whitespace-only string.)
3. Click "Create key".
4. `POST /api/settings/api-keys` returns 201; the new key appears at the top
   of the "VelocityAI API keys" list with `textContent` on the name element
   equal to the literal three-space string — verified via
   `Array.from(listEl.children)[0].textContent === "   flowin_X··· · never used..."`
   across all three cycles, each with a distinct newly-created key/token.
5. Revoked each test key afterward (cleanup) — name area stays blank, only
   the badge changes to "revoked", confirming persistence.

## Expected vs actual

- Expected: either the frontend trims `keyName` before the `||` fallback
  check (so a whitespace-only submission also defaults to `"Default"`), or
  the backend rejects/trims whitespace-only names — every key in the list
  should always show a human-readable, non-blank label.
- Actual: a whitespace-only name is accepted verbatim by both the client
  fallback and the backend, producing a permanently blank-named, unfixable
  (from the UI) key list entry.

## Root cause

`frontend/src/components/handoff/IntegrationsCard.tsx:147` —
`const created = await createApiKey(token, keyName || "Default");` uses `||`
against the raw (untrimmed) `keyName` state, so any non-empty string —
including one that is only whitespace — is truthy and skips the `"Default"`
fallback. No trim/validation exists on the backend side either (the API
accepts and stores the name as-is).
