# ISS-1172

## Description

Found while applying [FIX-775](20261009-1625-FIX-775.md), and left unfixed because it is outside the QA-KB-125 cards,
which are about agent HTML.

CONFIRMED by reading:

- `frontend/src/components/preview/PreviewPanel.tsx:1592-1606`, `handlePreviewOpen`. After FIX-775 a `text/html`
  deliverable goes through `openAgentHtmlInNewTab` (`:1598-1601`). Every other mimetype still runs
  `new Blob([content], { type: mimetype })`, `URL.createObjectURL` and `window.open(url, "_blank")` (`:1602-1605`). The
  result is a top-level document on the app origin, where `auth_token` sits in `localStorage`
  (`frontend/src/lib/api.ts:21`).
- The mimetype is `effGenericDeliverable?.mimetype`, else `text/html` for ppt and prototype, else `text/markdown`
  (`:1595-1597`). The generic value is the author-declared `DeliverableSpec.mimetype`, or the default from
  `backend/agents/capabilities/deliverables/_mimetype.py:53-78` (`engine.py:7965-7967`). The defaults are only `text/html`,
  `text/markdown`, `application/pdf`, `application/zip` and `application/octet-stream`. None of the non-HTML ones runs
  script as a top-level document.
- The in-app renderer already refuses unknown types: `GenericDeliverablePreview` gives anything other than HTML,
  markdown, zip and PDF "a safe download affordance — never inline/execute an unknown type (T-18-06)"
  (`PreviewPanel.tsx` header comment).

INFERRED, not driven: a workflow whose manifest declares a scriptable type, such as `image/svg+xml`,
`application/xhtml+xml`, or `text/xml` carrying XHTML elements, would get an agent-written document opened by this
button on the app origin, where its script runs. That relies on browser semantics for those types; it was not measured.
It needs the workflow author to declare the type, and the viewer is the run's owner.

## Expected vs actual

- Expected: the open button never gives agent content a script-capable top-level document on the app origin, matching
  T-18-06 in-app.
- Actual: any non-HTML declared type is opened as itself.

## Fix direction (not decided)

Open non-HTML types as `text/plain`, which Chrome shows as it shows `text/markdown` today. Or route them through a helper
in `frontend/src/lib/agentHtml.ts`. Either way, the source guard allowance for `components/preview/PreviewPanel.tsx` in
`frontend/src/lib/agentHtml.test.ts` drops from 1 to 0.
