## What happened

Spec 014/015 added eight workflow directories — the seven `ex_A*` conditional-gate
examples plus `sc001-test-fixture`. Because ADR-0005 derives
`SUPPORTED_PIPELINE_TYPES` from disk, all eight enrolled themselves in every
invariant test that iterates it, and 41 assertions failed at once across five
files. None of it was a defect in the workflows.

## What each list was, and what moved

| test | mechanism | fix |
|---|---|---|
| `test_allowed_step_keys` | `_DISPOSITIONS` must enumerate `_ALLOWED_STEP_KEYS` exactly | `route` / `produces` / `consumes` had been allow-listed with no disposition; added. `route` lands on the RAISES branch — R-03 rejects `route:` without `gates: [conditional]`, and the harness declares one key at a time |
| `test_id_alias_resolver` | `_PLANNER_SKIP_IDS` + `_EXPECTED_CLARIFY_DEFAULTS` | the seven `ex_A*` declare `planner: skip` and `clarify.defaults: []`; both lists extended |
| `test_manifest_parity` | the same two lists, duplicated | same edit — the file's own "sibling trap" comment demands lockstep |
| `test_manifest_coverage` | `len(_MANIFEST_BACKED_IDS) == 20` | → 28 |
| `test_compiled_plan_runs` | `len(_DISPATCHABLE) == 15` **and** every compiled agent must run | → 23, plus the real change below |

## The one that was not a count

`test_compiled_plan_runs::test_runs_from_compiled_plan` asserted
`set(started) == set(compiled_ids)` — every compiled agent must have run. A
conditional-gate workflow compiles EVERY branch and runs ONE: `ex_A2_branch`
declares `say-hello`/`say-hola`/`say-hallo` and runs exactly one of them. Equality
is the wrong shape for those, but the guard it exists for still holds as a subset:
no agent may run that the compiled plan does not declare.

The conditional case is detected from the compiled plan's own `route` property,
never a name list — the same rule the file already states for
`_every_step_agent_loads` (SC-001). Five of the 23 dispatchable pipelines are
conditional by that test, and they are exactly the five that were failing.

## Frontend half

`test_entitlement_parity` compares `backend/app/core/entitlements.py::TIER_PIPELINES`
against `frontend/src/lib/entitlements.ts`. The drift there was NOT the `ex_A*`
workflows (both sides list them) — it was `prototype_large_revision` and
`prototype_feature_revision`, which the backend entitled and the UI hid, so the
backend allowed a launch the catalog never offered. Added to the three tiers that
carry `prototype`.

## Two invariants that were genuinely too strict

Recorded here rather than as silent edits:

- `test_pipeline_workflows::test_every_consumes_is_satisfied_upstream` demanded
  EVERY `consumes` entry have an upstream producer. A shared agent declares both
  producers (`prototype-plan` consumes `prototype-specify` AND
  `prototype-revision-feature-specify`), so in any one pipeline the other entry has
  none — by design. Runtime is an INTERSECTION (`plan.py:439`), so the honest
  invariant is at-least-one, which still catches an agent fed by nothing.
- `test_workflow_resolver` expected one error per unresolved artifact type; the
  resolver deliberately emits one per AGENT (`resolver.py:171`) for the same
  shared-agent reason. `unresolved_edges` still carries every type, and the tests
  now assert that instead.

**Baseline:** every file above was verified failing identically at `HEAD`
(`d6a870fc2`) in a `git archive` scratch tree before any edit.
