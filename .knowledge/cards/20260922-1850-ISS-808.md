# ISS-808

## Description

Root-cause completion for **QA-PS-039** (`LEDGER.md` / `BUGS.md#qa-ps-039`),
whose root card [ISS-784](20260922-1812-ISS-784.md) already confirmed the
`analytics/summary` x2 mechanism (`HomeLaunchGrid.tsx`'s own unguarded
`fetchAnalytics` effect) but only guessed at the `runs?limit=50` x2 and
`workflows` x2 mechanism: "The same double-invoke pattern applies to
whatever populates `reduxRecentRuns` (the `runs?limit=50` call) and the
workflows catalog fetch on the same dashboard mount — none of them carry a
dedupe guard either" — no file:line given. This card supplies it, and shows
that guess was aimed at the wrong call site.

## Root cause

`frontend/src/app/[...view]/page.tsx:990-1007`:

```tsx
useEffect(() => {
  if (!isAuthenticated) return;
  const currentToken = getToken();
  if (!currentToken) return;

  getWorkflows(currentToken, { limit: 50 })
    .then(({ runs }) => setRecentRuns(runs))
    .catch(() => { /* Silently fail ... */ });

  // Pre-fetch the user-launchable workflow catalog so HomeLaunchGrid can seed
  // its card grid instantly from state instead of making its own fetch.
  getWorkflowDefinitions(currentToken)
    .then((rows) => setHomeWorkflows(rows.filter((w) => w.user_launchable)))
    .catch(() => { /* non-fatal — HomeLaunchGrid falls back to its own fetch */ });
}, [isAuthenticated]);
```

No `AbortController`, in-flight guard or cache. `getWorkflows()`
(`frontend/src/lib/api.ts:770-782`) builds `GET /api/runs` despite its name
(already established by [ISS-781](20260922-1630-ISS-781.md)), so
`getWorkflows(currentToken, { limit: 50 })` is the literal
`GET /api/runs?limit=50` call the bug report names, and
`getWorkflowDefinitions()` (`frontend/src/lib/api.ts:1731-1738`) is a plain
`request<T>("/api/workflows", { method: "GET" })` — the `workflows` call.
`page.tsx` is the app's catch-all `[...view]` route (CONTEXT.md invariant:
every URL routes through one catch-all), so this effect runs on every route
once authenticated, not just `/dashboard` — [ISS-782](20260922-1610-ISS-782.md)
already cited this same 990-1006 range as one of two always-firing sources
of unused `runs`/`workflows` traffic on `/analytics`. This card is the first
to pin it as the confirmed root of `/dashboard`'s OWN `runs?limit=50` +
`workflows` doubling specifically.

**Why ISS-784's guess was wrong, not just vague:** `reduxRecentRuns`
(`state.global.recentRuns`) is populated by a *different* call —
`fetchRecentRuns` (`frontend/src/store/slices/globalSlice.ts:40-45`):

```ts
const RECENT_RUNS_LIMIT = 6;
...
export const fetchRecentRuns = createAsyncThunk("global/fetchRecentRuns", async () => {
  const token = getToken();
  if (!token) throw new Error("Not authenticated.");
  const { runs } = await getWorkflows(token, { limit: RECENT_RUNS_LIMIT });
  return runs;
});
```

That is `GET /api/runs?limit=6` — a distinct URL from `limit=50`, already
separately itemized in [ISS-794](20260922-1827-ISS-794.md)'s own
reproduction table for a different route (`runs?limit=6 x1`). It is not
what the `runs?limit=50` line in this bug's report or in
[ISS-784](20260922-1812-ISS-784.md)'s own validation refers to.
`HomeLaunchGrid.tsx` itself never calls `getWorkflows`/`getWorkflowDefinitions`
at all — grepped directly, its only outbound call is `getAnalyticsSummary`
(already ISS-784's confirmed finding).

The doubling itself is StrictMode's dev mount → cleanup → remount cycle,
the same mechanism [ISS-794](20260922-1827-ISS-794.md) already confirmed
for this identical file (`ps aux` showing `next dev`, no
`reactStrictMode: false` override) — not independently re-verified with a
fresh browser capture by this card, so that specific link is CONFIRMED by
citation to ISS-794's evidence rather than a new repro of my own.

## Expected vs actual

- Expected: `runs?limit=50` and `workflows` each fire once per `/dashboard`
  load, from one call site each.
- Actual: both fire twice, every load — from this one effect, doubled, not
  from `reduxRecentRuns`/the `signedIn` listener as originally guessed.

## Impact

Same measured impact [ISS-784](20260922-1812-ISS-784.md) already recorded
(74.4 KB / 2 for the extra `runs?limit=50` call); this card only corrects
which code produces it, so the fix in [ISS-784](20260922-1812-ISS-784.md)'s
`applies_to.globs` (`HomeLaunchGrid.tsx`, `DashboardLayout.tsx`) would not
have touched the actual source — a fix aimed only at those two files closes
`analytics/summary` but leaves `runs?limit=50`/`workflows` broken.
