# ISS-1142

**Register source:** found by the 5-fixer for `QA-KB-107` while baselining [FIX-772](20261009-0335-FIX-772.md), 2026-10-09. It is not a
register bug row. [ISS-1136](20261009-0258-ISS-1136.md) covers the same leak for `USE_LOCAL_OLLAMA`; this card is the bearer token, which no
card names.

## Observed (CONFIRMED by run, offline, this machine)

`backend/.env` holds a Bedrock bearer token that expired `2026-10-08T23:40Z` and sets `USE_LOCAL_OLLAMA=1`
(`evidence/qa-kb-107/fix-01-preflight-probe-post-fix.txt`). Command:
`cd backend && PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m pytest tests/integration/api/test_rest_run_launch_api.py -q -p no:cacheprovider -W ignore`.

| tree | env | result |
|---|---|---|
| HEAD `8fb136808` (`git archive` copy, the same `backend/.env`) | as-is | 8 failed, 19 passed |
| HEAD + FIX-772 | as-is | 27 passed |
| HEAD + FIX-772 | `USE_LOCAL_OLLAMA=0` exported | 8 failed, 19 passed |

Every failure is `503` with `model_provider_unavailable`, "Bedrock bearer token expired at 2026-10-08T23:40Z". The eight are
`test_nonempty_brief_still_launches`, `test_basic_tier_allowed_for_basic_pipeline`, `test_launch_mints_run`, `test_owned_source_links_the_child`,
`test_foreign_source_drops_the_link_but_still_launches`, `test_unknown_source_drops_the_link_but_still_launches`,
`test_launch_run_core_called_directly_matches_http_endpoint_shape` and `test_launch_run_mints_workspace_before_ingest_staged_uploads`. Runs are in
`evidence/qa-kb-107/fix-02-test-runs.txt`.

So the file's result on a checkout depends on two values in that checkout's `backend/.env`: the token's expiry and the override. FIX-772 made
it pass here only because the override is on.

## Condition

- The file's `env` fixture (`test_rest_run_launch_api.py:89-134`) patches the database seams and the engine. It leaves
  `settings.AWS_BEARER_TOKEN_BEDROCK` alone. Neither `backend/tests/conftest.py` nor `backend/tests/integration/conftest.py` mentions the token.
- `settings` loads the token from `backend/.env`, and `preflight_check_provider` (`backend/app/agents/model_factory.py:119`) refuses an expired
  one wherever `build_model` would reach Bedrock. That refusal is correct product behaviour. Only the test's input is wrong.
- The one test that wants a token, `test_expired_bedrock_token_rejected_pre_mint`, sets its own (`:295`) and pins the override off (`:298`).

## Expected vs actual

Expected, as [ISS-1136](20261009-0258-ISS-1136.md) puts it: the offline tier gives the same result on every checkout, whatever a developer keeps
in `backend/.env`. Actual: eight launch tests fail on any checkout whose `.env` holds an expired bearer token with the override off.

## Fix direction (INFERRED, not applied)

Test-only: blank the token in the `env` fixture (`monkeypatch.setattr(settings, "AWS_BEARER_TOKEN_BEDROCK", "")`). The pre-mint test already
sets its own. No product change. It was left out of FIX-772 because no card asked for it, and its input (a credential) is not the flag
ISS-1136 describes.
