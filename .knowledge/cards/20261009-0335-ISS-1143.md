# ISS-1143

**Register source:** split out of [ISS-1134](20261009-0258-ISS-1134.md) by the 5-fixer for `QA-KB-107`, 2026-10-09. ISS-1134's title and
Condition name two missing planner rungs: `USE_LOCAL_OLLAMA` and Mistral. Its Expected and Fix direction cover only the override, and
[FIX-772](20261009-0335-FIX-772.md) applied exactly that. This card keeps the other half from being lost when ISS-1134 is resolved.

## Observed (CONFIRMED by an offline probe)

`evidence/qa-kb-107/fix-06-planner-mistral-gap-probe.txt` (HEAD `8fb136808` + FIX-772, constructors replaced by recorders, no network).
Config: override off, no `ANTHROPIC_API_KEY`, both Bedrock ids blank, `MISTRAL_API_KEY` set.

```
build_model()           -> ['ChatMistralAI']
SmartPlanner()          -> ['ChatBedrockConverse']
SmartPlanner() model= ''
```

## Condition

- `build_model` falls back to `ChatMistralAI` when `_bedrock_configured()` is false and `MISTRAL_API_KEY` is set
  (`backend/app/agents/model_factory.py:475-490`).
- After FIX-772, `SmartPlanner._build_llm` (`backend/agents/planner/smart_planner.py:346`) defers to `build_model` only for the override
  (`:353-354`). Otherwise it goes straight to its Anthropic exit, or to `ChatBedrockConverse` with
  `model = self.model_id or BEDROCK_INFERENCE_PROFILE_ID or BEDROCK_MODEL_ID`, which is `''` here.
- Reach is narrow, as with [ISS-1135](20261009-0258-ISS-1135.md). `Settings` ships non-empty Bedrock defaults, so this needs an operator who
  blanked both ids or the region. INFERRED, not driven: the planner call then fails and `plan()` falls back to its canned default context
  (`smart_planner.py` `_default_context`, `CLARIFY_REQUIRED`), so the run degrades rather than fails.

## Expected vs actual

Expected: the planner plans on the provider `build_model` would pick. Actual: in a Mistral-only configuration it builds a Bedrock client with
an empty model id.

## Fix direction (INFERRED, not applied)

Mirror the rung the way FIX-772 mirrored the override. When there is no `ANTHROPIC_API_KEY`, `_bedrock_configured()` is false and
`MISTRAL_API_KEY` is set, return `build_model(...)`. Keep the Anthropic and Bedrock exits as they are (INV-3). One decision is open: which
model id to pass. `build_model`'s Mistral branch uses `model or MISTRAL_MODEL_ID`, and the planner's `self.model_id` is the run's
selection. Settle that before writing it.
