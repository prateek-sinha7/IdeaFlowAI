## Problem

When opening a completed `od_prototype` run from Run History, the version dropdown in the detail panel showed **only "Version v1"** (the root run itself) — regardless of how many revisions existed. The history LIST correctly showed e.g. "v4" on the family card, but the detail's `VersionTimeline` was hidden (or showed 1 chip only).

## Root Cause

FIX-173 added a cross-family isolation guard in `_owned_family_members` (BFS walking the revision tree). The guard compared canonical base types to prevent a prototype revision accidentally appearing in a PPT family.

The normalization stripped only the `_revision` suffix:

```python
root_base_type = root_row.type.removesuffix("_revision")  # "od_prototype" → still "od_prototype"
# …
if child.type.removesuffix("_revision") != root_base_type:  # "prototype" != "od_prototype" → SKIP
    continue
```

For an `od_prototype` root:
- `root_base_type = "od_prototype"` (no `_revision` to strip)
- `prototype_revision` child → `"prototype"` after stripping `_revision`
- `"prototype" != "od_prototype"` → **ALL revisions excluded**

Result: `_owned_family_members` returned only the root run (1 member). `get_run_summary` returned `members=[root_only]`. `RunDetailPage` built `family.members.length === 1` → `VersionTimeline` returned `null` (hidden).

## Fix

Extended `_canonical_base` to also strip the `od_` variant prefix after stripping `_revision`:

```python
def _canonical_base(t: str) -> str:
    """Strip generic ``_revision`` suffix then ``od_`` variant prefix."""
    return t.removesuffix("_revision").removeprefix("od_")
```

Normalization results:
- `"od_prototype"` → strip `_revision` → `"od_prototype"` → strip `"od_"` → `"prototype"` ✓
- `"prototype_revision"` → strip `_revision` → `"prototype"` → strip `"od_"` → `"prototype"` ✓  
- `"od_ppt"` → `"ppt"` ✓, `"od_ppt_revision"` → `"ppt"` ✓
- `"ppt"` → `"ppt"` ✓, `"ppt_revision"` → `"ppt"` ✓

SC-001: fully generic, no literal workflow-name branches.
