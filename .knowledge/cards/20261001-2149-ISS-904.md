# ISS-904

Found during the QA-KB-027 fix ([FIX-691](20261001-2149-FIX-691.md)). [ISS-891](20261001-2120-ISS-891.md) listed this file as one of
11 stale `password_hash` seeds. It is not one, so the seed swap that fixed the other ten does not apply.

## Condition

`backend/tests/unit/test_iss401_reset_password_message.py:52-65` (`_make_local_user`) builds:

```python
User(id="break-glass-user", email="breakglass@example.com", cognito_sub=None,
     auth_provider="local", password_hash="bcrypt$fake-hash-not-used-by-this-test",
     tier="enterprise", is_admin=True)
```

and the test expects `admin_mod.reset_user_password(...)` to raise a 409 whose detail does not say "outside the
application" ([ISS-401](20260828-2121-ISS-401.md), status `resolved`).

None of that exists any more:

- `backend/app/models/user.py:51`: `cognito_sub = Column(String, nullable=False)`. The model has no `auth_provider` and
  no `password_hash` column (migration 0038; `tests/integration/db/test_migration_0038_preflight.py:231-232` asserts both are
  dropped).
- `backend/app/core/identity.py:15-17`: "local bcrypt/HS256 authentication and the break-glass local-admin exemption
  have been removed entirely."
- `backend/app/api/admin.py:502-530`: `reset_user_password` looks the user up and calls
  `cognito_admin.reset_password(db, user)` for every account. There is no 409 branch for a local account.

Observed (offline, `backend/`, `.venv/bin/python -m pytest tests/unit/test_iss401_reset_password_message.py -q`,
2026-10-01): `1 error` (`UnitIsolationError` from `tests/unit/conftest.py:91` fires first). Lifting that guard would
then fail on the removed kwargs, and lifting those would leave a test for a branch that was deleted.

## Why this was not fixed in FIX-691

The ISS-891 fix is a seed swap. Here a swap would change what the test is about (it would turn the break-glass
account into a Cognito one), which is bending a test, not reviving it. Deleting it is a disposition decision that
ISS-891 did not cover.

## Disposition (proposed)

Retire the file. The guarantee ISS-401 asked for (a local account's 409 must not claim external credential
management) has no subject left: there are no local accounts and no 409. If any part of ISS-401 is judged to still
apply to the Cognito-only reset path, rewrite the test against `cognito_admin.reset_password` instead of keeping this
one.

## Analysis (QA-KB-077, analyzer, 2026-10-02)

Every claim above was checked against the working tree and the file was run. One citation is corrected, a fourth layer the card did not
list is added, and the disposition is settled. Evidence: `evidence/qa-kb-077/04-analyze-layers-under-the-guard.txt`.

### Root cause (CONFIRMED)

The file guards a behaviour the Cognito-only migration deleted, and the commit that deleted it retired the neighbouring tests but not this one.

- Authored in `d027f16bd` (2026-08-29) against dual-auth code.
- `b2a621f84` (2026-09-17, "Fix/cognito login (#8)") removed the local/break-glass account type: `password_hash` and `auth_provider` dropped
  (`backend/alembic/versions/0038_cognito_only_users.py:165-166`), the local-account 409 and the `new_password` field gone from
  `backend/app/api/admin.py`, and the break-glass tests deleted by name: `backend/tests/unit/test_break_glass_invariant.py`,
  `backend/tests/unit/test_bootstrap_admin.py`, `backend/tests/integration/test_bootstrap_admin_postgres.py`
  (`git show b2a621f84 --diff-filter=D --name-only`). This file stayed. That its name carries an ISS id and "reset_password_message" rather
  than "break_glass" is the likely reason (INFERRED); that its neighbours were deleted and it was not is CONFIRMED.
- `09270703b` (2026-09-22, "Fix/testcases (#9)") added `_unit_io_guard`. From then on the fixture's own SQLite engine fails at setup, so the
  test has never reached its assertion and the staleness stayed invisible.

### Four layers, in the order they fail (each observed)

1. Setup. `db_session` runs `Base.metadata.create_all(bind=engine)` (`test_iss401_reset_password_message.py:42`); the guard raises
   `UnitIsolationError` at `backend/tests/unit/conftest.py:81` (`_deny_db_connect`), armed by `_unit_io_guard` (def `:91`, `event.listen`
   `:123`). This card and the bug report cite `:91`, the fixture's def line; the raise is `:81`.
2. Seed. `User(auth_provider="local", password_hash=...)` raises `TypeError: 'auth_provider' is an invalid keyword argument for User`
   (model columns are in the evidence file; `user.py:51` makes `cognito_sub` NOT NULL, so `cognito_sub=None` would also fail at flush). Seen
   by running a copy outside `tests/unit`.
3. Request body (not in the list above). `ResetPasswordRequest` (`backend/app/api/admin.py:197-205`) has no fields and `extra="forbid"`, so
   line 96, `ResetPasswordRequest(new_password="a-new-password-123")`, raises `ValidationError: Extra inputs are not permitted`. This is by
   design: `backend/tests/integration/api/test_admin_privilege_atomicity_api.py:231-245` pins that a body carrying `permanent` is refused, and
   the class docstring says "No password is supplied by the admin". A reseeded test still could not be built.
4. Subject. `reset_user_password` (`admin.py:502-545`) looks the user up and calls `cognito_admin.reset_password(db, user)` (`:530`) for every
   account. There is no `auth_provider` branch and no 409 for a local account; the other 409s in the file are last-admin, conflict and
   already-disabled / not-disabled states. `grep -rn "managed outside" backend/app backend/agents frontend/src` is empty, so no production
   string makes the claim ISS-401 guarded.

### Blast radius

- Production: none, and no source needs to change. `reset_user_password` has one caller (the router, `admin.py:501`) and
  `cognito_admin.reset_password` has one (`admin.py:530`).
- Tests: this is the last test in `backend/tests` that seeds a removed `User` kwarg (AST scan of 73 `User(...)` calls: only this file's two,
  lines 53 and 69). The other `auth_provider` / `password_hash` hits are raw-SQL migration tests at pre-0038 revisions (legitimate) and the
  deploy-gate script tests.
- Cards that cite this file as verification: [ISS-401](20260828-2121-ISS-401.md) (`verification.test_files`, status passed),
  [FIX-367](20260828-2256-FIX-367.md) (`test_files`; coverage block line 121) and [BUG-079](20260829-1508-BUG-079.md) (`test_files`). They stay as
  history.
- Config, CI, inventories: nothing names the file (grep over md/txt/json/yaml/yml/toml/cfg/ini outside `.knowledge`, `evidence`, the ledger and
  `UNIT-TESTS.md`). `UNIT-TESTS.md:229` is a dated snapshot and keeps the old path, as [FIX-691](20261001-2149-FIX-691.md) left it.

### Where the fix belongs

Delete the file. No replacement test is needed.

- The Cognito-only reset path is already covered in the integration tier: `backend/tests/integration/api/test_admin_privilege_atomicity_api.py:230-295`
  `TestPasswordResetAtomicity` (refuses a body with `permanent`; temporary-only `Permanent=False`; advances `tokens_valid_from` and signs the user
  out). It ran 3 passed on 2026-10-02. Its module docstring (`:1-10`) says why it lives there: the unit-suite guard "correctly refuses a real
  engine there".
- ISS-401's guarantee, that a 409 must not claim external management, has no subject: no 409, no account type, no string.
- The same commit made the same call for the neighbouring break-glass tests: deleted, not rewritten. So this is not a product decision.

Do not: relocate it to `tests/integration/` as the guard's message and README rule 7 suggest (it then fails on layers 2-4); swap the seed to
`cognito_sub` (turns it into a different test, as FIX-691 said); put `password_hash` / `auth_provider` back on `User` or a 409 back in
`admin.py` (revives the removed credential path; ISS-891 locks this); touch `tests/unit/conftest.py`. Plain `rm`, as FIX-691 did for
`test_sandbox_ref_scoped_endpoints.py`; no git.

For the test phase: the failing signal is the pytest error at setup. Retirement has no product behaviour to turn red, so a cheap pin is a
pure-AST guard (no I/O) that fails today and passes once the file is gone: no `User(...)` call in `backend/tests` may pass a keyword that is
not a column of `app.models.user.User`. The scan in the evidence file is the starting point. It encodes the rule FIX-691 already locked: a
seeded `User` carries `cognito_sub`, never `password_hash`.
