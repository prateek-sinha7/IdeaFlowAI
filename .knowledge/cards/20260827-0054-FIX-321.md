## The four tools

| Tool | Answers |
|---|---|
| `render_pptx` | Does the PptxGenJS source compile, and is the deck shippable? |
| `verify_pptx_layout` | Which shapes overlap, overflow their box, or leave the canvas? |
| `extract_pptx_shapes` | What positions are ACTUALLY in the built file? |
| `screenshot_pptx` | Does the file open at all, and how many slides came out? |

`extract_pptx_shapes` exists for the case where a violation does not match what
the agent believes it wrote — the file is the truth, the source is the intention.

## Why the keys are strings

`agents/capabilities/` is import-fenced away from `app/`. A provider that returned
tool objects would have to import the implementations and break the fence, so it
returns names and the factory resolves them. `_resolve_custom_tool_keys` gained a
`ctx` parameter to reach the run sandbox; the four pre-existing tool sets resolve
byte-identically (parity snapshots green).
