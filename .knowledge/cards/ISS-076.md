# ISS-076

## Title

The mocked Playwright suite has a 33-red baseline, not the "132 green" the records claim. Measured on bugfix/spec-revision-context-loss at b13d5c33: 33 failed / 43 skipped / 108 passed. The "123–132 green" figure in TEST-REGISTER.md and in session memory is feat/ui-2 data and is stale on this branch. Failing clusters include ts-chat (4), ts-e.model-picker (5), ts-u.revisions (4), ts-t.history (4), ts-l.token-usage (3), ts-k, ts-m, ts-h, ts-chat-cards. Same consequence as ISS-068 for the goldens: while it stands, the mocked suite cannot serve as a pass/fail CI gate, and a change can only be checked by diffing failing IDs against a hand-captured baseline. Includes a methodology trap worth as much as the count: playwright.config.ts sets reuseExistingServer: true on :3000, so running the suite from a baseline worktree silently tests the MAIN tree's code through the already-running dev server and returns a *confirmatory* answer no matter what — it nearly produced a false "pre-existing" claim here. A real baseline needs its own server on another port, and a symlinked node_modules will not do (Turbopack: *"Symlink [project]/node_modules is invalid, it points out of the filesystem root"*) — clone it with cp -Rc instead (~6 s on APFS).

## Source / evidence

Measured 2026-08-12 during quick-260812-2ci, both at b13d5c33 (own server on :3100) and after the change, comparing failing IDs. That comparison is what proved FIX-221/222 introduced 0 new failures.
