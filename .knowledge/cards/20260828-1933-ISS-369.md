## What happened

On `/analytics` (range = All), every number rendered on the page — KPI tiles (`97.3M`,
`$52.82`, `349.8K`), the By Pipeline Type list (`38.3M`, `19.9M`, ...), By Model
(`90.0M`, `7.3M`), and the Token Breakdown card — is formatted through
`formatTokens()`/`formatCost()` (K/M abbreviation, `$` + 2 decimals). The one exception
is the per-bar hover tooltip on the Daily Activity bar chart: it shows the raw,
unformatted JS number with no thousands separators and no K/M suffix, e.g.
`Aug 24: 2364478` and `Aug 27: 28246062`, instead of `Aug 24: 2.36M` /
`Aug 27: 28.2M`. The underlying value is correct — this is a pure formatting
inconsistency, not a data-accuracy defect.

Reported as BUG-20260828-102900-analytics-r2 in `bug-hunter/ledger.md`.

## Reproduction (3/3, cycle 1)

Reproduced on every one of 3 cold-start attempts (fresh navigation to `/analytics?range=all`
each time, session reused but page freshly loaded — no soft re-click), no timing or axis
variation needed:

1. Sign in as `qa-admin`, navigate to `/analytics?range=all`.
2. Wait for the page to finish loading (`GET /api/analytics/summary?range=all` can be slow —
   the first attempt observed a 30s client-side abort/timeout before a page reload succeeded;
   this is a separate perf concern, not part of this defect).
3. Hover/inspect the "Aug 24" bar in the Daily Activity chart.
4. Tooltip text reads `Aug 24: 2364478` on all 3 cycles — same for `Aug 27: 28246062`.
5. Compare to the KPI tiles on the same load: `TOTAL TOKENS 97.3M`, `EST. COST $52.82`,
   `AVG / RUN 349.8K` — all K/M-formatted, no raw 7-8 digit integers appear anywhere else on
   the page.

## Root cause

`frontend/src/components/analytics/charts/BarChart.tsx:85-89`:

```tsx
const tip =
  d.tip ??
  (hasValues
    ? `${d.label}: ${d.value}`
    : `${d.label}: ${d.value} run${d.value !== 1 ? "s" : ""}`);
```

`BarChart` is a generic, data-prop-driven presentation primitive (Phase 38, SC-1) with no
formatting opinion of its own — it accepts an optional per-datum `tip` string (`BarDatum.tip`,
line 39) and falls back to a raw `label: value` composition when the caller does not supply
one. The caller, `frontend/src/components/analytics/AnalyticsPage.tsx:399-403`, builds
`dailyData` (line 236) and passes it to `<BarChart data={dailyData} ... />` without ever
setting `tip` on each datum — every other number on the page routes through `formatTokens()`
(`AnalyticsPage.tsx:64-66`) before display, but the Daily Activity series' tooltip does not,
so it falls through to `BarChart`'s raw-number default.

## Expected vs actual

- **Expected:** tooltip formats the token count the same way as every other number on the
  page, e.g. `Aug 24: 2.36M` (or at minimum `2,364,478` with thousands separators).
- **Actual:** tooltip renders the raw JS number with no formatting: `Aug 24: 2364478`.
