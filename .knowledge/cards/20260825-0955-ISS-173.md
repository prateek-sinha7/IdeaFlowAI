Found while validating [ISS-170](20260824-1610-ISS-170.md)'s fix. Both files fail
IDENTICALLY at `be1533e11` with the fix reverted, so this is not a regression from that
work — but it is this branch's doing.

## Symptom

```
test_conditional_divert_v4_validation.py    1 failed
test_conditional_human_gate_source_t26.py   2 failed
```

Both die the same way: the scripted decision step emits generic default prose,
`ConditionalGate._read_decision` cannot parse it, the gate fails closed, and no route
happens. `gate_blocked` is present in both event traces.

## Root cause

`c9ec0149c` ("Renames them `sample_conditional_*` -> `ex_{A1..A4}_*`") restructured the
fixtures — new step `instance_id`s, new outcome names, new target workflow ids. Two test
files were not migrated with them and still describe the old shape:

| test expects | tree actually has |
|---|---|
| step `decide`, outcome `divert`, target `ex_A3_target` | step `language`, outcomes `english`/`spanish`/`dutch`, targets `ex_A3_b_spanish` / `ex_A3_c_dutch` |
| `greet` / `review` / `revise-check` / `done`, `condition_agent: review` | `ask` / `pick-language` / `say-*` — no earlier-step `condition_agent` anywhere |

`test_conditional_human_gate_source_t26.py` points `_PIPELINE = "ex_A4_human_gate"`, which
is a language-picker; the fixture it was written against is
`sample_conditional_human_input/workflow.yaml`, present at `887ccfe96` and removed by the
rename. `git log -S'revise-check' -- backend/agents/workflows/` confirms both commits.

A THIRD file of this family, `test_conditional_branch_route_t25.py`, had the same defect in
its milder form (only the step id drifted: `pick` vs `language`) and was repaired under
[ISS-170](20260824-1610-ISS-170.md). It had been PASSING one of its two cases for the wrong
reason — the fall-through ran the branch it happened to want.

## Why it matters beyond the red

T26 is the only coverage of `condition_agent` naming an EARLIER step as the decision source
(the manifest-route-schema capability "may name an EARLIER step"). No current `ex_*` fixture
exercises it, so deleting the test silently drops a real feature from the suite.

## Disposition — needs a product decision

1. **Port the old fixtures** into the `ex_*` naming (`sample_conditional_human_input`,
   `sample_conditional_launch_new`, `sample_conditional_target` all recoverable at
   `887ccfe96`). Keeps the coverage. Preferred for T26.
2. **Rewrite the tests** against the current fixtures. Works for the divert case
   (`spanish`/`dutch` are `trigger: workflow`); does NOT work for T26, whose whole purpose
   disappears.
3. **Delete them** as obsolete. Loses the `condition_agent`-names-an-earlier-step coverage.
