## What happened

A diverted run never produces a deliverable — confirmed via the backend API on the diverted runs
checked: `output: null`, `deliverable_filename: null`, the Preview tab shows the empty "Output
will appear here" placeholder, the Files tab lists only agent-intermediate outputs plus the run
input (no deliverable file), and the toolbar's "Download the deliverable" button is correctly
`[disabled]`. Despite this, the Workspace tab's "Workspace expired" empty state unconditionally
states: "Run workspaces are cleared after a retention period. The deliverable is still on the
Preview and Files tabs — only the raw working files are gone." That claim is false for a diverted
run — there never was a deliverable on either tab, and the run's own header badge reads
"Diverted", not completed.

Confirmed **CONFIRMED, 3/3, cold start every cycle** — each cycle navigated fresh to
`/dashboard` then directly to `/runs/{id}/workspace` (not a soft tab-click from another screen):

| cycle | run id | result |
|---|---|---|
| 1 | `940ca699-b21b-4666-8e44-3370a08a4561` | "Workspace expired" + false deliverable claim shown |
| 2 | `277bc03a-d2ba-4405-876d-d0aa861bc9ed` (different run) | identical message shown |
| 3 | `277bc03a-d2ba-4405-876d-d0aa861bc9ed` (fresh cold reload) | identical message shown |

All three cycles produced byte-identical copy, "Download the deliverable" `[disabled]`, and header
badge "Diverted" — no timing or entry-path variation was needed, the message is unconditional
static text with no state dependency.

## Expected vs actual

- **Expected:** The Workspace-expired message should not assert a deliverable exists on
  Preview/Files when the run's own data shows none was ever produced — either condition the
  message on whether a deliverable exists, or give a diverted run copy explaining the handoff
  (e.g. pointing at the successor run) instead of the generic completed-run wording.
- **Actual:** The message unconditionally claims the deliverable is available elsewhere on the
  run, actively misleading a user who has not yet checked Preview/Files into believing output
  exists that was never generated.

## Conditions established

- Route: `/runs/{id}/workspace` on a run whose status badge reads "Diverted".
- Tier: qa-admin (not varied — reproduces at 3/3 without needing other tiers).
- Entry path: cold direct navigation to `/runs/{id}/workspace`; not tab-flow dependent — the
  message is static regardless of how the tab is reached.
- Not a timing/race condition: the message renders synchronously with the empty state, no delay
  or settle needed.

## Root cause

`frontend/src/components/results/SandboxTab.tsx:1037-1043`:

```tsx
if (expired) {
  return (
    <div className="flex h-full flex-col items-center justify-center gap-1.5 p-6 text-center">
      <p className="text-[13px] font-medium text-ink-700">Workspace expired</p>
      <p className="max-w-[380px] text-[12px] leading-relaxed text-ink-400">
        Run workspaces are cleared after a retention period. The deliverable is
        still on the Preview and Files tabs — only the raw working files are gone.
      </p>
    </div>
  );
}
```

The `expired` branch is reached purely from `res.expired` (set at `:915`, a workspace-retention
API flag) with no check on the run's `output`/`deliverable_filename`/status. The copy is a
generic completed-run message reused unconditionally for every `expired` case, including a
diverted run that never had a deliverable in the first place.
