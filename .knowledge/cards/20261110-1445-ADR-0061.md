## Decision

User request (2026-11-10): clicking "Build with AI" must not open a popup; it opens the chat panel on the left of the canvas, where the user types the prompt. The builder's colours and design must match the rest of the app. User decisions: place the panel under the Composer header next to the canvas; match the run chat's 360 px width; when a workflow is already open (saved or being edited), Build with AI opens the panel on that canvas instead of a new empty one.

- `BuilderPopup` is deleted. `BuilderEmptyState` (intro, the four example prompts, five recent conversations) is what an open panel shows before a session exists. An example fills the box and does not send (G-25 unchanged).
- Composer: `BuilderComposerHost.handleAiButton` toggles `panelOpen`. The first message creates the session (`startSession`): edit mode on `/workflows/{id}/edit` (no navigation, canvas kept), create mode with the current canvas on `/workflows/new`.
- My Workflows: `BuildWithAiLauncher` keeps only the availability probe. A click sets `markNewConversationPending()` and runs the "New workflow" navigation (`handleSelectFeature("custom")`). That path mounts the host once on `/workflows` and again after the page remounts on `/workflows/new`, so the host clears the flag only once it first stands on a builder route (`handoffSettledRef`).
- Layout: `ComposerPage` gained `builderPanel?: ReactNode` and renders `[builderPanel][notes + body + save error]` under the header. The binding gained optional `panelId`. `BuilderPanel` is 360 px, docks from 1280 px, and moves focus to the message box on open.
- First message: shown at once with "Sending"; Send and New conversation are held until its send settles; a failed create puts the text back; a stream that closes for good before the snapshot puts it back; a create that finishes after the user opened another conversation is not adopted (`startGenerationRef`).
- Look: `surface-warm` panel, `line-divider` borders, a one-row header (title plus History, New conversation and Collapse icons, floating Conversations menu), the shared `AssistantMark` and user bubble, the three-dot working indicator, cards for activity and "What changed", the run chat's message bar with the Model and Thinking chips in its toolbar, and follow-scroll (`useFollowScroll`, 120 px gate as in `ChatPanel`). The Composer AI button and `BuildWithAiButton` share one brand-tinted style.

## Why this shape

- The panel already existed and could start a session from its own box ("New conversation" did), so removing the popup was mostly rewiring. The popup had hidden two defects on that path: a second Enter during `createSession` created a second session, and the first message vanished until the stream's snapshot.
- Placing the panel inside `ComposerPage` under the header keeps the header on one row at 1280 to 1440 px (left of the whole Composer it lost 380 px and wrapped). The host still owns the stream, so the `components/workflow` boundary holds.
- 1280 px leaves the canvas 576 px between the 360 px panel and the 344 px config rail; docking from 1024 px would have left about 320 px.

## Not changed
