# FIX-746

## What was wrong

Bug QA-KB-090, code-level, root card [ISS-950](20261002-0134-ISS-950.md). For a `workflow_runs` row
with no `manifest_json`, `resume_run` logged `at step offset 1/1` and `all steps complete — nothing to
re-drive` while two of the three `prototype_v2_revision` steps were still to run.
`prototype_v2_feature_revision` (1 of 5) logged the same way. Execution was right, because
`_execute_impl`'s seam re-expanded the roster; only the two INFO records were wrong. The worst reader
is a user's POST /resume, where the log said there was nothing left to do.

## Root cause (from ISS-950, re-checked on this tree before editing)

- `resume_run` built a manifest-less roster from the registry,
  `get_pipeline_agents(resolve_alias(pipeline_type))` (`engine.py:15699`), and completed it from the
  plan only when it was EMPTY (was `if not agents:`, `engine.py:15705`). The registry skips the
  `custom-agent` template, so these two workflows got a 1-agent roster that is never empty.
- `_compute_resume_offset` rebuilds `agents` from `compiled.steps` before it counts, so the offset is
  plan-relative.
- `engine.py:15752-15763` printed that offset over `len(agents)` and tested `offset >= len(agents)`.
- `_replay_clarify_run` had the same empty-only fallback (was
  `if not agents and resumed_compiled is None:`, `engine.py:16186`) and handed the same 1-agent roster
  to the shared drive.

Re-checked before editing: the registry-vs-plan split over all 41 supported types still matches
ISS-950: 18 equal, 19 empty, 2 with no workflow.yaml (`file_analyst`, `spec_kit`), 2 strict subsets
(the two above), `evidence/qa-kb-090/fix-02-roster-probe.txt`. The callers are still the carded ones:
`engine.py:12868` (restart auto-resume), `engine.py:12999` (gate re-arm), `run_commands.py:792`
(POST /resume), and `engine.py:13006` for `_replay_clarify_run`.

## What changed, and why there

`backend/agents/execution_engine/engine.py`, two seams, one rule:

- `resume_run` (`engine.py:15705-15730`). The seam now runs when the roster is empty OR the run has no
  persisted manifest (`resumed_compiled is None`). It compiles the plan (`compile_for_run` is
  `lru_cache`d, and `_compute_resume_offset` compiles the same plan next) and swaps in
  `_specs_from_plan(plan_steps)` when the roster is empty or
  `{a.id for a in agents} < {s.agent_id for s in plan_steps}`, the `execute()` seam's predicate
  (`engine.py:5017`). Offset, denominator and the all-complete test now share one coordinate system
  by construction.
- `_replay_clarify_run` (`engine.py:16186-16207`). The same change in its twin seam, scoped to
  `resumed_compiled is None` as before. `_specs_from_plan`'s docstring requires the two resume seams
  to agree.
- On a compile failure, both abort (warning plus `_fire_resume_cleanup`) only for an empty roster,
  as before. A non-empty roster keeps going with `plan_steps = []`, so `file_analyst` and `spec_kit`
  resume exactly as they did.

Why the seam and not the log line: it is the one place all three resume callers share, the roster is
what executes, and resume no longer relies on `_execute_impl`'s seam to re-expand a roster that resume
itself built, which is the question [ISS-966](20261002-0320-ISS-966.md) is deciding. Why the set rule
and not `launch_run`'s length rule: it keeps the roster before the engine seam equal to the roster
after it, so that seam becomes a no-op on resume. The two rules agree on all 41 types today.

Expected side effect: the INFO line `roster expanded from plan` from
[FIX-707](20261002-0134-FIX-707.md) no longer prints when one of these two workflows is resumed,
because nothing is left to expand. The roster `_execute_impl` finally runs is unchanged (INV-3).

## Not changed

- The `xfail(strict=True)` markers in `test_resume_run_offset_log.py`; the 6-verifier removes them.
- `launch_run`, the trigger path and `_mint_revision_row`, which already size from the plan, and the
  `execute()` seam itself.
- No shared `_complete_roster` helper: ISS-950 calls it optional. The rule is spelled the same way in
  both resume seams, beside the engine seam it copies.
- Pre-existing reds met on the way are recorded, not fixed: [ISS-1068](20261007-2034-ISS-1068.md).
