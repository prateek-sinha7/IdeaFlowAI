# FIX-716

## What was wrong

This fix is for bug report QA-KB-052. The root cause comes from the analysis on [ISS-472](20260829-0110-ISS-472.md); I did not re-derive it.

- `IdeaInputPage` had no input for the user's tier and imported none of the entitlement helpers.
- `DashboardLayout` rendered it without a tier, at what was then `:3159`.
- Nothing on the panel checked the plan: not `handleRun` (`:1566`), not the Run button's `disabled` (`:2009`), and not the brief box's Cmd/Ctrl+Enter shortcut (`onSubmitShortcut={handleRun}`, `:1952`).
- So on `/create/app`, a `basic` account got a fully usable panel. Only the backend refused the launch: `run_commands.py:3510`, `_require_tier_entitlement`, which returns 403.

[ISS-970](20261002-0339-ISS-970.md) was a precondition for this fix. The `enterprise` set in `frontend/src/lib/entitlements.ts` was missing `sample_subagents_parallel`. A comment at `:92` introduced it, but no entry followed. Because of that, `test_same_pipelines_per_tier[enterprise]` was red. With this lock in place, the gap would also have locked an entitled account out of that route.

## What changed, and why there

Line numbers are for the working tree after the change.

1. **`frontend/src/lib/entitlements.ts:93`**: added `"sample_subagents_parallel",` under the orphaned comment. Only the frontend changed, because the backend map is the authority (see the file header at `:5`).
2. **`IdeaInputPage.tsx`**: this is where the analysis placed the fix. The panel has one render site, but many routes reach it (a cold `/create/<type>` URL, `handleLaunchSaved`, `handleEditBrief`). The change follows [FIX-497](20260829-0242-FIX-497.md) in `LaunchWizard`:
   - `:784`: a new optional prop, `userTier?: Tier | null`. `null` or absent means the tier is unknown, which never locks.
   - `:996-997`: `locked = userTier != null && !canRunPipeline(userTier, effectiveType)`, plus `upgradeTo` from `getUpgradeTier`. These are the same helpers `HomeLaunchGrid` and `LaunchWizard` call. `effectiveType` is used rather than `workflowType`, which reads `"migration"` until the user picks a sub-path.
   - `:1576`: `handleRun` returns early when `locked`. This one guard covers the Run button and the Cmd/Ctrl+Enter shortcut.
   - `:2018`: the Run button is disabled when `locked`. Its label stays "Run workflow".
   - `:1992`, `:2007`: "Save workflow" and "Save as my version" are also disabled when `locked`. This is the Input-panel half of [ISS-968](20261002-0338-ISS-968.md). `create_user_workflow` applies the same check (`backend/app/api/user_workflows.py:703`, `can_run_pipeline(effective_tier(...), body.base_pipeline_type)`), so a save would 403 after the user had named the workflow.
   - `:2032-2041`: a lock banner. It uses the same classes, Lucide `Lock` icon and wording as `LaunchWizard.tsx:1389-1396`: "Requires {TIER_LABELS[upgradeTo]} plan — your plan does not include this deliverable."
3. **`DashboardLayout.tsx:572`**: `profileTier = useAppSelector((s) => s.auth.user?.tier ?? null)`, passed down as `userTier={profileTier}` (`:3171`).
   - The value is the profile that `page.tsx:952-956` dispatches through `userLoaded`. It is `null` until `getMe` resolves and stays `null` if it fails.
   - I did not pass `DashboardLayout`'s own `userTier`. That value is `page.tsx`'s `user?.tier ?? "basic"`, so an `enterprise` account would see a locked panel while its profile loads.

**Which tier source.** The analysis offered three: (a) Redux inside `IdeaInputPage`, (b) a nullable prop, (c) the panel's own `getMe`. I took (b), with the value read from Redux one level up.
- The red test supplies the tier as a `userTier` prop (and as a `getMe` mock). It does not preload `auth`. So (a) would leave the test unable to see the fix unless the test were edited.
- (c) would need `getMe` added to every `vi.mock("@/lib/api")` factory in the 12 other `IdeaInputPage` test files, as [FIX-497](20260829-0242-FIX-497.md) found.
- I changed no test files.

**Not touched:** `page.tsx`, `LaunchWizard.tsx`, `ComposerPage.tsx` and the backend. The other surfaces are covered by their own open cards (see "Left open").

## For the verifier

- The change is frontend only. `restartNeeded` is false: the backend is untouched, and the Next dev server hot-reloads.
- To reproduce by hand, sign in as `basic@velocity.ai` and open `/create/app`, or `/create/backlog`. The `admin@velocity.ai` account is `enterprise`, and `/create/user-stories` never locks for any tier.
  - While the profile loads, the panel stays unlocked for a moment. Then the banner appears and Run and both Saves are disabled.
