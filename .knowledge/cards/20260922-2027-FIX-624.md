## What was wrong

`handleWebSocketMessage` (`frontend/src/app/[...view]/page.tsx:1048`) is the one
router every pipeline frame goes through, and eight of its branches end in

```ts
const <x>Token = getToken();
if (<x>Token) getWorkflows(<x>Token, { limit: 50 }).then(({ runs }) => setRecentRuns(runs))
```

— `pipeline_complete` (immediate + the KAN-120 2s-delayed one), `pipeline_failed`,
`pipeline_diverted`, `pipeline_cancelled`, `questionnaire_ready`,
`questionnaire_complete`, `review_gate_ready`, `review_gate_approved`. They exist
to refresh the recents list/badge when a **live** run's status genuinely changes.

Three call sites feed a run's **durable event log** back through that same
router, frame by frame, with no signal that the frames are historical:

- `handleSelectWorkflowRun` — history reopen (`page.tsx:3084`), ISS-785's path;
- `handleSwitchToLiveRun` — the header "N Running" badge (`page.tsx:2836`), ISS-803's path;
- the T11 post-launch remount replay (`page.tsx:3643`), a third caller neither card names.

So replaying a run that terminated days ago re-fired every one of those
refetches, for a run list that cannot have changed because of a frame from the
past.

## What changed and why there

One parameter on the shared router, not eight edits and not a guard per caller:

```ts
const handleWebSocketMessage = useCallback((msg: StreamMessage, sourceRunId?: string, isReplay?: boolean) => {
    const recentsToken = () => (isReplay ? null : getToken());
```

Every one of the eight bindings now reads `recentsToken()` instead of
`getToken()`; during replay it returns null and the existing `if (token)` guard
each site already had skips the refetch. The three replay loops pass
`true`. Live SSE (`page.tsx:2414`) passes nothing and is untouched, so a real
status change still refreshes the badge exactly as before.

Deliberate consequence: a status change that happened while this tab was not
listening is no longer picked up by replaying it — the run list is refreshed by
mount, by `RunConnectionProvider`'s `visibilitychange`/`online` handlers and by
every live frame instead. That window is [ISS-143](20260813-0205-ISS-143.md)'s
territory, not this refetch's.
