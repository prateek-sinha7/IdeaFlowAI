## What was wrong

`frontend/src/app/workflow/page.tsx` only ever passed `pipelineType`, `userMessage`,
and `onClose` to `<WorkflowView>` — never `pipelineState`, `onStartPipeline`,
`onResetPipeline`, or `onViewResults`. Because the step-transition effect in
`WorkflowView` gates on `pipelineState.isRunning` (default `false`) and
`pipelineState.agents.length` (default 0), the step was structurally frozen at
`"build"` and Steps 3/4 (running, complete, View Results, Run Another) were
unreachable dead code on this route.

## What changed

`frontend/src/app/workflow/page.tsx`:

- Added `INITIAL_PIPELINE_STATE` constant matching `WorkflowView`'s own fallback.
- Added `pipelineState` local state initialised to it.
- Added `handleStartPipeline`, `handleResetPipeline`, `handleViewResults` callbacks.
- Wired all four into `<WorkflowView>`.
- Removed unused `token` state variable.

`frontend/src/app/workflow/page.test.tsx`:

- Removed `it.fails` marker — test now passes with real `onStartPipeline` and
  `pipelineState` props present.
