Every cross-workflow divert showed a "Reconnecting…" warning in the UI, and the handoff
appeared only afterwards.

## Root cause

`pipeline_diverted` was added as an additive event (spec 014 T38) and never added to the
sets that decide which frames END a stream:

```
backend   run_stream.py   _STREAM_TERMINAL_TYPES
frontend  types/index.ts  STREAM_TERMINAL_TYPES
```

Both listed only `pipeline_complete`, `pipeline_cancelled`, `pipeline_failed`,
`budget_aborted`, `error`. The engine yields the divert frame and returns; nothing
recognised it as terminal, so the connection dropped unclean, the client reconnected, and
the durable replay delivered the divert AFTER a spurious warning.

## Fix

Added to both sets and to the `expected` set in `TestSSETerminalTypesSyncWithFrontend`,
which fails if the two sides drift.

It is UNIONED IN at the stream level rather than added to `_GATE_RESOLUTION_TYPES` — that
set also derives `_GATE_REARM_TYPES`, so widening it there would have changed gate re-arm
semantics as a side effect. Verified `_GATE_REARM_TYPES` unchanged.

## Rule for next time

A new terminal frame must be added to all three places in the same change.
