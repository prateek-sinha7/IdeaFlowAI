# ISS-088

## Title

The local backend cannot be stopped by SIGTERM while any run is streaming, so shutdown_run_infrastructure() never executes locally at all — and even where it does execute it does not stop the runs. Two independent facts, both verified 2026-08-12. (1) docker-entrypoint.sh:35 passes --timeout-graceful-shutdown 5, but the local invocation does not: ps -o command= -p 91032 → python -m uvicorn app.main:app --host 127.0.0.1 --port 8010. uvicorn's timeout_graceful_shutdown therefore defaults to None, and H11Protocol.shutdown() does NOT close a connection whose response is still streaming — so a live SSE stream never leaves server_state.connections, _wait_tasks_to_complete() spins forever, and lifespan.shutdown() is NEVER reached. run_shutdown.py:8-13 documents exactly this and it is why kill -9 was the only thing that worked on run d5dbc9f2. Consequence beyond the stuck stop: no local shutdown behaviour is exercised the way production exercises it — the Concierge drain, the pump teardown and close_checkpointer() have never run on a developer machine. (2) SHUTDOWN_STOP_RUNS defaults False (config.py:215, KAN-151 D8 §I11), so even a reachable shutdown deliberately leaves in-flight runs non-terminal for the next boot's auto-resume — meaning a deploy cannot stop a 21M-token build either. That default is a real trade (it is what keeps the Phase 45-50 resume tier working) and is a product decision, not a bug; the missing local flag is not. Fix shape: add --timeout-graceful-shutdown 5 to the documented local run command so dev and prod exercise the same path; then re-open the SHUTDOWN_STOP_RUNS default as a product question with cost, not as an engineering default.
