## What happened

`git commit` with only `backend/` staged. pre-commit stashed the rest, the
knowledge hook spent 43s regenerating `.knowledge/`, then the restore failed on
~30 `.knowledge/` files. The abort took the frontend hunks with it: the tree went
back to HEAD and the untracked `prompt-gallery/` route was gone.

Recovered with `git reset`, `git checkout -- .knowledge/` to restore the patch's
pre-image, then `git apply --3way` on the stash at
`~/.cache/pre-commit/patch<id>`.

## Contributing cause

`.pre-commit-config.yaml` still carries the comment "Off by default during the
soft-rollout window: `git commit` will NOT run this hook… To make it auto again,
delete this line" — but the `stages: [manual]` line it describes is gone, while
the `ruff` hook directly above still has its own. The parked hook is firing.

The same file states the principle it breaks: "no --fix. We do not auto-modify
code in a hook; the developer must decide."

## Options

- Restore `stages: [manual]` on the knowledge hook.
- Or make it CHECK and fail with an instruction, instead of rebuilding in place.
- Until then: `git add -A` before every commit, or `SKIP=knowledge`.
