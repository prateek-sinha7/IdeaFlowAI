# ISS-898

Found while running the QA-KB-005 tests for [FIX-683](20261001-2128-FIX-683.md). It is carded because at least five fix cards have
re-measured it as "pre-existing" ([FIX-621](20260922-2009-FIX-621.md), [FIX-631](20260922-2154-FIX-631.md),
[FIX-633](20260922-2229-FIX-633.md), [FIX-635](20260922-2335-FIX-635.md), [FIX-640](20260923-0207-FIX-640.md)), and
so did this run's test phase. Nobody carded it, so every fixer re-derives it.

## Condition

Run `frontend/src/app/[...view]/terminalReopenReconcile.source.test.ts` alone, from `frontend/`, with
`./node_modules/.bin/vitest --run <file>`.

## Expected

The `ISS-126 reopen reconciles a terminal run (source-lock)` block is green. It pins the reopen reconciliation for
[ISS-126](20260812-1852-ISS-126.md), from [FIX-245](20260813-0005-FIX-245.md).

## Actual

5 of its 9 cases fail:

- "gates the reconciliation on the EXISTING REOPEN_TERMINAL_STATUSES set": `expected '"use client";…' to contain
  'applyTerminalStatus(prev, fullRun.sta…'`
- "reconciles BOTH containers — the store AND the legacy reducer state": `expected '"use client";…' to contain
  'reconcileTerminalStatus(fullRun.statu…'`
- "writes to the run STORE — the state the UI actually reads": `expected -1 to be greater than -1`
- "runs AFTER the durable replay loop, never before it": `expected -1 to be greater than -1`
- "stays inside the reopen handler, after the durable fetch": `expected -1 to be greater than 168149`

All five depend on two exact strings, `applyTerminalStatus(prev, fullRun.status)` and
`reconcileTerminalStatus(fullRun.status);`, and `page.tsx` no longer contains either one. The calls now read as
follows (lines as of 2026-10-01, uncommitted tree):

```ts
// frontend/src/app/[...view]/page.tsx:3108-3111
reconcileTerminalStatus(fullRun.status, undefined, fullRun.tokenUsage);
runStore.updatePipelineState(fullRun.id, (prev) =>
  applyTerminalStatus(prev, fullRun.status, undefined, fullRun.tokenUsage),
);
```

The ISS-304 comment just above them (`:3102-3107`) says `fullRun.tokenUsage` is passed into both containers on purpose
([ISS-304](20260828-1600-ISS-304.md)).

## Evidence

- A/B at HEAD `024c03ef8`. That commit's own test file, run against that commit's `page.tsx`, gives
  `Tests 5 failed | 4 passed (9)`, the same five. Both files were read-only `git show` copies in an isolated scratch
  directory: `evidence/qa-kb-005/fix-04-HEAD-024c03ef8-terminalReopenReconcile.source.txt`.
- On the working tree, the same five fail, plus the ISS-870 `it.fails` case:
  `evidence/qa-kb-005/fix-03-after-terminalReopenReconcile.source.txt`.
- `git log -S'applyTerminalStatus(prev, fullRun.status)' -- 'frontend/src/app/[...view]/page.tsx'` lists
  `7f9be3d60 2026-09-22 fix(composer): send a launch to the surface the workflow actually uses` and
  `2b25d3d05 2026-08-12 fix(dashboard): render a reopened TERMINAL run as terminal (ISS-126)`.
  `reconcileTerminalStatus(fullRun.status);` returns the same two commits. The anchors left `page.tsx` in `7f9be3d60`.
- A re-anchoring experiment, done on a scratch copy only (the repo test was not edited): replacing the two anchors with
  the current call shapes (5 occurrences of the first, 1 of the second) gives `Tests 9 passed (9)` against today's
  `page.tsx`. The ordering and position cases pass too. So the behaviour ISS-126 pins still holds, and only the anchors
  are stale.

## Disposition

The fix belongs in the test, not the app, because the app change was deliberate (ISS-304). Fix direction: re-anchor
the five cases on the current call shape, or on a prefix that survives extra arguments (for example
`applyTerminalStatus(prev, fullRun.status`). That edits a test, so it needs the test owner's sign-off. It is outside
QA-KB-005's scope, and no test was edited here.

## Analysis — QA-KB-071, 2026-10-02

Root cause: CONFIRMED. Read or run on 2026-10-02 in `feat/user-stories-v2` at `024c03ef8` plus uncommitted edits. The repo
test file and `page.tsx` were not edited; every experiment ran on scratch copies
(`evidence/qa-kb-071/02-analyze-scratch-ab.out.txt`).

### Mechanism

[ISS-304](20260828-1600-ISS-304.md) gave `applyTerminalStatus` a fourth parameter, `usage`, at
`frontend/src/hooks/useWorkflow.ts:411-433`, and `reconcileTerminalStatus` a third at `:39` and `:193-195` (commit
`16864bb05`, 2026-09-22 08:46:50). Fourteen seconds later commit `7f9be3d60` (subject "fix(composer): send a launch to the
surface the workflow actually uses") changed the two reopen call sites in `page.tsx` to

```ts
reconcileTerminalStatus(fullRun.status, undefined, fullRun.tokenUsage);       // page.tsx:3128
applyTerminalStatus(prev, fullRun.status, undefined, fullRun.tokenUsage),     // page.tsx:3130
```

(`:3105` and `:3107` at HEAD; the lines move because other work edits `page.tsx`.) Neither commit touched the test. The
lock matches the whole call text, closing `)` or `;` included, so six literals went stale at once:
`applyTerminalStatus(prev, fullRun.status)` at test lines 38, 60, 70, 77, 85 and `reconcileTerminalStatus(fullRun.status);`
at line 48. `git log -S` on both literals in `page.tsx` returns `7f9be3d60` as the commit that removed them.

| case in the ISS-126 block | how it reads the stale anchor | result |
|---|---|---|
| gates the reconciliation on the EXISTING REOPEN_TERMINAL_STATUSES set | `toContain` (line 38) | fails |
| reconciles BOTH containers | `toContain` (line 48) | fails |
| writes to the run STORE | `indexOf`, then `lastIndexOf(..., -1)` (lines 70-72) | fails, `-1` |
| runs AFTER the durable replay loop | `indexOf` above -1 (lines 77-79) | fails, `-1` |
| stays inside the reopen handler, after the durable fetch | `indexOf` above `fetchAt` (lines 85-87) | fails, `-1` |
| does NOT clear reviewGateData | `indexOf`, then `slice` (lines 60-62) | passes on an empty window, see [ISS-1009](20261002-0540-ISS-1009.md) |

The app behaviour is intact. The structure the lock guards is at `page.tsx:3111-3147` (reconcile after the replay loop,
both containers, store write, questionnaire clear), and the behavioural tests are green:
`terminalStatusReconcile.test.ts` 14 of 14, `bridgeTerminality.source.test.ts` 11 of 11.

### Blast radius

- Every `*.source.test.ts` under `src/app/[...view]/` (the page.tsx source locks) was run alone: 16 files, and this is
  the only red one. The 13 `useWorkflow*` and `terminalStatusReconcile` test files are green too.
- The two stale literals appear nowhere else in `frontend/`, `tests/` or `backend/tests/` (grep).
- At risk, green today, not carded: `bridgeTerminality.source.test.ts:51` pins `return applyTerminalStatus(snapshot, storeTerminal);`
  and `:67` pins `}, [pipelineState, reopenedRunStatus]);`, both closing-paren anchors like the broken ones. They break the
  same way the day an argument is added to those lines. No failure mode exists today, so no card.
- The other callers of the two functions are not affected by the new arguments: the bridge call (`page.tsx:2381`) works
  on the legacy snapshot that `reconcileTerminalStatus` already corrected, and `useWorkflow.ts:1516` handles a
  `pipeline_reconnected` frame with `live: false`, which carries no usage.
- Two more defects in the same file, found while checking every anchor the block uses: [ISS-1009](20261002-0540-ISS-1009.md)
  (a case that passes on an empty string) and [ISS-1010](20261002-0540-ISS-1010.md) (the ordering case compares against the
  wrong loop, blind since 2026-08-12).

### Where the fix belongs, and what it is

In `terminalReopenReconcile.source.test.ts` only. The app change is deliberate and measured (the replayed agent sum
undercounted run 26a7e162: header 13.6M against a persisted 19.7M), so the test follows the app, not the reverse. No
product decision is open.

1. Re-anchor on prefixes that survive extra arguments: `applyTerminalStatus(prev, fullRun.status` (no `)`) at lines 38,
   60, 70, 77, 85, and `reconcileTerminalStatus(fullRun.status` (no `);`) at line 48. Each is unique in `page.tsx` (one
   hit, `:3130` and `:3128`). Two constants at the top of the file turn the next argument change into a one-line edit.
   Validated on a scratch copy: `Tests 10 passed (10)` (9 cases plus the ISS-870 block).
2. In the same edit close [ISS-1009](20261002-0540-ISS-1009.md) (one guard line) and
   [ISS-1010](20261002-0540-ISS-1010.md) (search the loop from the reopen fetch). Validated together on a scratch copy:
   10 of 10 on today's `page.tsx`, and exactly one red case on a copy with the reconcile moved before the reopen loop.
3. Do not loosen to bare `applyTerminalStatus(`. Its first hit in `page.tsx` is the bridge at `:2381`, ahead of the reopen
   fetch, which would break the position cases. Do not delete or `.skip` the five red cases either: they hold ISS-126's
   ordering rule.
4. Edit in place with targeted replacements, anchoring on strings and never on line numbers. The working-tree test file
   already carries another bug's uncommitted ISS-870 block (9 lines at the end), and `page.tsx` has uncommitted edits too.
5. A prefix is blind to the arguments, so after step 1 nothing offline pins that `fullRun.tokenUsage` reaches both
   containers. The only guard is the live e2e
   `tests/integration/e2e/suites/07_run_detail/test_iss304_header_token_total_mismatch.py`, which skips when no suitable
   run exists. If an offline pin is wanted, add one tolerant case, for example
   `/reconcileTerminalStatus\(fullRun\.status,[^)]*fullRun\.tokenUsage\)/` and its `applyTerminalStatus` twin. It would be
   green on arrival, so it is optional and not carded.

### Invariants at risk

INV-12 (one terminal vocabulary): case 1 of this lock pins the `applyTerminalStatus` import from `@/hooks/useWorkflow` and is
green; dropping the lock loses that guard. Reverting the `fullRun.tokenUsage` arguments would re-open
[ISS-304](20260828-1600-ISS-304.md). SC-001 and the import-linter contracts are not touched (frontend test only).

## Resolution — FIX-731 (2026-10-07)

Resolved by [FIX-731](20261007-1908-FIX-731.md), for register entry QA-KB-071, as step 1 of the analysis above:
`APPLY_CALL` and `RECONCILE_CALL` are prefix-anchor constants at `terminalReopenReconcile.source.test.ts:27-28`, and the
six stale literals read them. The edit is test-only. `page.tsx` still passes `fullRun.tokenUsage` into both calls
(ISS-304). The lock gives `Tests 10 passed (10)`. The meta-lock's ISS-898 `it.fails` case now fails with "Expect test to
fail", which is the pass signal. The marker is left for the 6-verifier (`evidence/qa-kb-071/fix-04`, `fix-05`). Step 5,
the optional tokenUsage pin, was not added. A fourth blind case in the same block is carded as
[ISS-1060](20261007-1908-ISS-1060.md).
