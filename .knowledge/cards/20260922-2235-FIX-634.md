# FIX-634

Resolves [ISS-850](20260922-2155-ISS-850.md) — the residual detection gap left on
**QA-PS-021** (`LEDGER.md` / `BUGS.md#qa-ps-021`) after
[FIX-608](20260922-1820-FIX-608.md), [FIX-612](20260922-1838-FIX-612.md) and
[FIX-615](20260922-1854-FIX-615.md) closed the bug's other two compensation modes.
Does **not** close [ISS-733](20260922-1353-ISS-733.md) (root),
[ISS-734](20260922-1354-ISS-734.md) or [ISS-735](20260922-1355-ISS-735.md) — see
"What this does NOT cover" below and `ESCALATIONS.md#qa-ps-021`.

## What was wrong

QA-PS-021's compensation **mode 2**: a validator/QA-role step (`ppt-validator`,
`prototype-validate`) finds no upstream artifact to validate and regenerates the ENTIRE
deliverable itself, under its own attribution instead of the builder's. The run publishes
`completed`, the user downloads a deliverable the pipeline never really produced, and no
signal anywhere records that it came from the wrong step.

Neither content signal the shared completion gate had could see that shape, both by
their own documented design:

- `backend/agents/capabilities/deliverables/_placeholder.py:57-73` —
  `placeholder_narration_reason` returns `None` above `_MAX_NARRATION_CHARS` (2000,
  line 68) and needs one of 12 literal first-person markers (lines 26-40). A
  self-generated substitute deliverable is long-form content and carries none.
- `backend/agents/capabilities/deliverables/_coverage.py` (pre-fix, lines 75-93) —
  `dropped_section_reason` diffs the deliverable's headings against an upstream
  SOURCE's. When the declared source produced nothing at all,
  `_top_level_titles(sources[agent_id] or "")` returns `[]`,
  `len(titles) < _MIN_SECTIONS` short-circuits the loop with `continue`, and the
  function returns `None`. **There was nothing to diff against, so nothing was
  flagged** — mode 2's own trigger is precisely what blinded the check.

## Root cause — file:line

`backend/agents/capabilities/deliverables/_coverage.py:75-93` (pre-fix). The loop's
first statement was

```python
titles = _top_level_titles(sources[agent_id] or "")
if len(titles) < _MIN_SECTIONS:
    continue
```

A blank source and a source with two headings were treated identically: "too small a
sample, say nothing". But they are not the same question. Two headings is a sample
problem; **zero content is an attribution fact** — the declared producer contributed
nothing, so a substantial deliverable cannot have been built from it.

## What changed and why there

One file, one branch: `backend/agents/capabilities/deliverables/_coverage.py`.

`dropped_section_reason` now answers both halves of the module's own stated question
("is this deliverable actually covered by its declared upstream sources?") in one pass
over the same `sources` map:

```python
source = sources[agent_id] or ""
if not source.strip():
    if len(text) > _MIN_UNSOURCED_CHARS:
        return (
            f"deliverable is {len(text)} characters but upstream agent "
            f"{agent_id!r}, one of its declared sources, produced no "
            "content at all — it was not built from the input this step "
            "declares it consumes"
        )
    continue
```

**Why here and not a third helper + a third engine call.** The signal ISS-850 asks for
is an attribution check — "the completing step is not the declared producer for what a
downstream `consumes` was supposed to feed, yet emitted substantial content anyway" —
and `dropped_section_reason` already receives exactly those two inputs: the deliverable,
and the compiling step's DECLARED upstream sources keyed by producer agent id
(`engine.py:7477-7490` builds that map from the `produces`∩`consumes` registry routing).
A new module would have needed a fourth signal wired into the same gate for data the
existing call already carries. The engine was NOT touched: SC-001 holds trivially (no
`pipeline_type` / `spec.id` branch added anywhere), and the one shared call site keeps
covering `custom`, `custom_revision` and every native pipeline alike.

**Why the 2000-char bound.** `_MIN_UNSOURCED_CHARS` is deliberately equal to
`_placeholder.py`'s `_MAX_NARRATION_CHARS`. Below it, a short output with an empty
upstream IS narration and `placeholder_narration_reason` already owns it; above it, this
check owns it. The two signals partition the range rather than contending for the same
text, and neither widened.

**Doctrine kept.** Same bar both existing signals set — a false positive flips a
user-visible success badge, so the check fires only on a shape that is unambiguous: the
last step DECLARES `consumes`, an upstream step that DECLARES it produces that kind
recorded no output at all, and the deliverable is nonetheless substantial. Dormant
everywhere else.

## What this does NOT cover (stated, not hidden)

- An upstream step that streamed prose but never wrote its FILE still records that prose
  as its output, so its source entry is non-empty and this check stays quiet. That shape
  is covered for the narration case by [FIX-612](20260922-1838-FIX-612.md) and for the
  raw-prose-into-the-deliverable case by [FIX-609](20260922-1822-FIX-609.md).
- A declared producer that never ran at all is absent from `results`, so it never reaches
  `sources`. Deliberate: conditional routing legitimately skips steps
  (`ex_A2_branch`, `ex_A3_divert`, `ex_test_transitive_skip`), and flagging a skipped
  branch would be exactly the false positive both modules forbid.
- [ISS-733](20260922-1353-ISS-733.md) (root), [ISS-734](20260922-1354-ISS-734.md) and
  [ISS-735](20260922-1355-ISS-735.md) remain open — each needs a decision, not a fix.
  See `ESCALATIONS.md#qa-ps-021`.
