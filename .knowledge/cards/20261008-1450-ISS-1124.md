# ISS-1124

**Register source:** sibling derived during the `QA-KB-102` analysis on 2026-10-08 (root [ISS-1103](20261008-0016-ISS-1103.md)). Not its own bug row.

**Confidence:** CONFIRMED by reading the tests and by the probe (the real engine returns normally in every scenario the stub would have raised in).

## Condition

The user-resume contract has one test of its failure branch, and it cannot see the defect.

- `test_rest_resume_api.py:82-109`: `_StubEngine.resume_run` records the call and, when `resume_behavior` is set, awaits it.
- `:426-446`, `test_resume_arm_failure_flips_back_to_failed`: sets `resume_behavior` to a coroutine that raises `RuntimeError("scripted arm failure")`, calls `_drive_user_resume`, and asserts the row is `failed` with that text in `.error`.

That is the contract T-50-06 states, and it passes. But the real `resume_run` does not raise for the manifest, plan, roster and row exits, and `_drive_resumed_stream` does not raise for anything out of `_execute_impl`. The probe's scenario G shows the one place it does (before the funnel's `try`), and scenarios A, B2 and C show the real engine returning `None` where the stub raises. A green test over a path the engine does not take is the pattern the owner's rule calls a missing check: the feature is broken and the check passes.

Nothing else covers the exits. A search of `backend/tests` for the log strings (`cannot resolve agents`, `empty agent list`, `cannot compile plan`, `no workflow_runs row`, `refusing to resume`, `failed mid-drive`) finds only comments (`test_restart_resume_db.py:3779`, `tests/agents/_resume_child.py:252`). The one test that mentions an uncompilable run, `test_restart_resume_db.py:1233`, checks the restart CLASSIFICATION (`resume_called["n"] == 0`), which is branch (c), not the exits inside `resume_run`.

## Expected vs actual

Expected: one test per exit family, each driving the real engine and asserting the failure is recorded (a terminal event after the `run_resuming` marker, a `failed` row whose `.error` is the reason, a frame on the live queue). Actual: none.

## Why the root cause implies it

The swallow and the bare returns survive because nothing fails when they do. The red tests the 4-test-writer adds for [ISS-1103](20261008-0016-ISS-1103.md) are this gap's closing; the stub test should keep passing as the narrow "a raise is recorded" check, and a comment on it should say it does not prove the real engine ever raises.

Harness helpers: `_ResumeHarness`, `_make_session`, `_seed_workflow_run`, `_wire_user_resume_drive` from `test_restart_resume_db.py`; a valid composed manifest at `:5657`; hooks as `app/main.py:159-190`.
