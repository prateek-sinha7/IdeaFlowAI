## What is left

[FIX-361](20260829-0029-FIX-361.md) closed the security half of
[ISS-292](20260828-1918-ISS-292.md): `PUT /api/settings/preferences` now 403s
when the account's tier may not use the requested model, so an unauthorised
`preferred_model` can no longer be persisted or reach
`engine.execute(model_id=...)`.

The **affordance** half is deliberately still open:

- `backend/app/api/settings.py`'s `get_preferences` returns the full
  `AVAILABLE_MODELS` catalog to every tier (unchanged), and the response
  carries no per-model entitlement flag.
- `frontend/src/components/settings/AccountSettings.tsx:373-376` therefore
  still renders every option unconditionally — no lock icon, no "requires Pro"
  label, no `disabled`, unlike `HomeLaunchGrid.tsx:288`'s
  `disabled={!allowed}` launch cards.

A basic-tier user's first signal is the red banner after clicking Save:
"This model requires Pro or higher. Upgrade your plan to unlock it."

## Why it was deferred rather than fixed

The failing test written for ISS-292
(`tests/integration/e2e/suites/09_settings/test_settings.py::test_basic_tier_cannot_persist_a_powerful_model`)
asserts the Opus option IS offered, then selects it, waits for Save to become
ENABLED, clicks, and asserts the value does not survive a reload. Hiding or
disabling the option breaks that test at its guard rather than at its
assertion — and a disabled `<option>` specifically makes Playwright's
`selectOptions` return `error:optionnotenabled`
(`playwright/driver/package/lib/coreBundle.js`), i.e. a timeout, not a pass.

## What a fix would look like

Not a frontend-side policy table — the repo already carries one hand-kept
mirror (`frontend/src/lib/entitlements.ts`) whose drift needed
`backend/tests/unit/test_entitlement_parity.py` to police it; a second mirror
for models would need the same. Instead let the API say it:

1. `get_preferences` (and `update_preferences`'s response) project
   `AVAILABLE_MODELS` per request as
   `[{**m, "allowed": can_use_model(user.tier, m["id"])[0]} for m in AVAILABLE_MODELS]`.
   The module-level `AVAILABLE_MODELS` constant must stay exactly
   `{id, name, description, tier}` — `test_available_models_is_projection`
   (`backend/tests/agents/test_model_catalog.py:147`) asserts that key set.
2. Add `allowed?: boolean` to `ModelOption` (`frontend/src/lib/api.ts:1377`,
   and the currently-unwired `frontend/src/store/api/settings.ts:3`).
3. Render the lock in `AccountSettings.tsx` — and update the ISS-292 e2e test
   in the same change, since the chosen affordance decides whether that test's
   "option offered / Save enabled" preconditions still describe the product.
