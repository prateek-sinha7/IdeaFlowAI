# ISS-676

## Status: INFERRED, not reproduced

The 5-fixer found this while adding [FIX-521](20260917-1447-FIX-521.md)'s ISS-648 bridge to the
same block. It is read from code only. Confirm it live before treating it as a defect.

## What the code does (line numbers as of FIX-521)

`page.tsx:1722-1740`:

```ts
if (msg.type === "pipeline_cancelled" || msg.type === "pipeline_failed") {
  if (!isForeignFrame) {
    ...
    if (frameRunId) runStore.update(frameRunId, { questionnaireData: null });
    setReviewGateData(null);
    setQuestionnaireData(null);
    setActivePipelineRunId(null);
```

The block's own KAN-125 comment says its purpose is that "a FOREIGN concurrent run cancelling/failing
must not clear THIS tab's questionnaire/reviewGate/activePipelineRunId". But `isForeignFrame`
(`page.tsx:1370`) is false for every run in `launchedRunIdsRef`, meaning every run this tab
launched. A BACKGROUND run from this tab that fails or is cancelled therefore still runs the three
page-level resets, which belong to whichever run is on screen.

The store write (`runStore.update(frameRunId, ...)`) is correctly per-run. The three setters are not.

## Why it probably matters

- `activePipelineRunId` feeds `trackedRunIdRef` (`page.tsx:2203`,
  `activePipelineRunId ?? contentSourceRunId ?? trackedRunIdRef.current`) and `useRunChat`'s run id
  (`page.tsx:2322`). While the viewed run is clarify-paused, before its own `pipeline_start`, it has
  no `pipelineRunId`. That makes `activePipelineRunId` the only thing holding it.
- `page.tsx:618-626` (BUG-005) documents the same failure class for a different trigger: a foreign
  run's `pipeline_start` nulled `activePipelineRunId` and "the lane fell clarify→building".
- The legacy `setReviewGateData(null)` / `setQuestionnaireData(null)` may be invisible, since the
  block's own comment says the lane reads the store. That half is uncertain.

## What would confirm this

Launch run A and navigate away while it is still building. Launch run B and stay on its
clarification questions. Cancel run A without viewing it, for example with
`POST /api/runs/<A>/cancel`. Check whether
run B's lane leaves the clarify state or its chat lane re-points. No UI path for cancelling a
non-viewed run was checked.

## Likely fix shape (for the analyzer, not decided)

Gate the three page-level setters on the frame being for the tracked run
(`frameRunId === trackedRunIdRef.current`), the axis FIX-203 and FIX-521 already use for
"background". Leave the per-run store write as it is.
