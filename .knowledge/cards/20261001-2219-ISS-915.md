## Validation (QA-KB-082)

Reproduced 3/3 from cold navigation on 2026-10-02 as admin: {files:'abc'}, {files:[null]}, {files:[{}]} each land on the error boundary (console: TypeError ... 'localeCompare' in AppBuilderPreview). Evidence: evidence/qa-kb-082/01-03-*.png.

## Summary (INFERRED from code; now reproduced in a browser)

`frontend/src/app/preview-fullscreen/page.tsx` decides whether the cached `__app_preview__`
payload is usable with a single test, `!data.files?.length` (:71), after a bare type assertion
`JSON.parse(raw) as PreviewPayload` (:70) that checks nothing at runtime. Anything with a truthy
`.length` passes: a string (`{"files":"abc"}`), an array of non-objects (`{"files":[null]}`), an
array of objects with no `path` (`{"files":[{}]}`), or an object that merely has a `length`
(`{"files":{"length":1}}`). The page then runs `setPayload(data)` and `setState("ready")`
(:75-77) and mounts `<AppBuilderPreview files={payload.files}>` (:118-119).

That component evaluates `useMemo(() => buildTree(files), [files])` at
`frontend/src/components/preview/AppBuilderPreview.tsx:369`. `buildTree` (:89-114) runs
`[...files].sort((a, b) => a.path.localeCompare(b.path))` (:93) and `file.path.split("/")` (:96);
each shape above throws a `TypeError` there (undefined `path`, a null element, or a non-iterable
spread). The throw happens while React renders the child, so it is outside the page's
`try/catch` (:64-80) and never reaches `giveUp()` (:57-63). It propagates to the app-level
error boundary, `frontend/src/app/error.tsx`.

Real producers never write such a shape: `AppBuilderPreview.handleFullscreen` (:436-451)
stringifies `{ files, projectName }` built from `ParsedFile[]`. The shape is reachable only
through a hand-edited or version-skewed `sessionStorage` value, which is the same "corrupt
sessionStorage" condition QA-KB-032 exercises, with a different corruption (invalid JSON and
`{"files":[]}` are the two it covers). Severity: Low.

## Why it is a sibling of ISS-407

Same function, same documented intent. The page's docblock (:27-29) promises a fallback "if that
payload is also missing/unparseable", and `giveUp()` is the one exit for that. The guard that
decides "unusable" is narrower than that promise, so an unusable-but-truthy payload skips the
exit. It is independent of the ruling on [ISS-407](20260828-2343-ISS-407.md) (silent redirect
kept, in-place panel, or redirect plus notice): under every option these payloads should reach
the same exit instead of the generic crash page.

## What would move this from INFERRED to CONFIRMED

In a signed-in tab: `sessionStorage.setItem('__app_preview__', JSON.stringify({files:"abc",projectName:"x"}))`,
then open `/preview-fullscreen`. Predicted: the branded application error page from `error.tsx`
rather than the fallback exit. Repeat with `{files:[null]}` and `{files:[{}]}`. A jsdom test is
cheaper: render `PreviewFullscreenPage` with `useRouter` mocked, seed the key, advance fake timers
100 ms, and assert the exit is taken (no vitest spec exists for this page today).

## Expected / Actual

Expected: any payload that is not a non-empty array of objects with a string `path` takes the
same fallback exit as a missing payload. Actual (predicted): the child throws at render and the
error boundary shows.

## Where the fix belongs

In the page's guard (page.tsx:70-74): one shape check before `setPayload`, for example
`Array.isArray(data.files) && data.files.length > 0 && data.files.every(f => typeof f?.path === "string")`,
so `giveUp()` stays the single exit. Not in `AppBuilderPreview`: its other render sites
(`PreviewPanel.tsx:170`, `WorkflowHistory.tsx:1053` and `:1092`) pass typed props, and only this
page feeds it `JSON.parse` output read from storage. No SC-001 or import-linter contract is
touched (frontend only).

## Analysis (QA-KB-082 analyzer, 2026-10-02)

This section adds the blast radius and the one refinement the analysis found. The Summary, Validation and "Where the fix belongs" sections above stand, except where the last subsection below widens the example guard. The Summary's "INFERRED from code" label is now settled: reproduced in a browser (Validation) and re-read at file:line below.

### Root cause (CONFIRMED)

1. `frontend/src/app/preview-fullscreen/page.tsx:70`: `const data = JSON.parse(raw) as PreviewPayload;` is a compile-time assertion. Nothing checks the shape at runtime.
2. `:71`: `if (!data.files?.length) {` is the only shape test. Any value with a truthy `.length` passes: a string, an array of non-objects, an array of objects without `path`, `{length:1}`. Values without one already exit through `giveUp()`: `null` (the `null.files` TypeError lands in the `catch`, `:78-79`), `[]`, `"abc"`, `123`, `{}`, `{files:[]}`, `{files:5}`, `{files:{}}`, `{files:true}` and invalid JSON (replayed in Node against verbatim copies of the lines).
3. `:75-77`: `setPayload(data)` and `setState("ready")`; `:118-119` then mounts `<AppBuilderPreview files={payload.files} projectName={payload.projectName} />` on the unchecked value.
4. `frontend/src/components/preview/AppBuilderPreview.tsx:369`: `const tree = useMemo(() => buildTree(files), [files]);` runs during render. `buildTree` throws at `:93` (`[...files].sort((a, b) => a.path.localeCompare(b.path))`) for a string or a multi-element array. For a one-element array the comparator never runs, so the throw is at `:96` (`file.path.split("/")`). `{files:{length:1}}` throws at the spread (`files is not iterable`).
5. The page's `try/catch` (`:64-80`) wraps only the synchronous body of the `setTimeout` callback. The throw happens afterwards, inside React's render of the child, so it can never reach `giveUp()` (`:57-63`). `frontend/src/app/preview-fullscreen/` contains only `page.tsx` (no `error.tsx`), so the nearest boundary is `frontend/src/app/error.tsx`: "Something went wrong", Error code 500, buttons "Try again", "Back to dashboard", "Back to login". That is what `evidence/qa-kb-082/01-validate-attempt1-files-string-error-boundary.png` (and `02`, `03`) show.

INFERRED, persistence: nothing removes `__app_preview__` (only `getItem` at `page.tsx:65` and `setItem` at `AppBuilderPreview.tsx:441` touch the key), so "Try again" should remount the page, re-read the same value and throw again; the tab stays on the error page until it is closed or the key is overwritten. Settled by: reproduce, click "Try again", observe.

### Where the fix belongs (widens the example guard above)

Location unchanged: the single guard at `page.tsx:70-74`, so `giveUp()` stays the only exit and no caller is touched. The predicate must be wider than the `path`-only example above: it must also reject a file without a string `content` and a non-string `projectName`. See [ISS-1020](20261002-0632-ISS-1020.md) for the crash sites, and for the constraint that the ISS-298 e2e fixture (`{path, content}` only, `tests/integration/e2e/suites/07_run_detail/test_iss298_preview_fullscreen_quota_ignores_cache.py:25-30`) must still be accepted unless the fixture is changed in the same edit. ## Resolution (QA-KB-082 fix, 2026-10-07)

Fixed by [FIX-739](20261007-1959-FIX-739.md), in the guard named above (`page.tsx:70-95`, no change to `AppBuilderPreview`).
The payload is parsed without a cast. `files` must be a non-empty array whose elements all have a string `path` and a string
`content` (and an `ext` that is a string or falsy), otherwise `giveUp()` runs. `projectName` is kept only when it is a
string, and a missing `name` is derived from `path`. `page.previewPayloadShape.test.tsx` went from 5 expected fail to 5 ×
"Expect test to fail" ([XPASS(strict)]); its `it.fails` marker is left for the verifier. The wider 19-case matrix went from
11 failed | 8 passed to 19 passed (`evidence/qa-kb-082/fix-03-*`).
