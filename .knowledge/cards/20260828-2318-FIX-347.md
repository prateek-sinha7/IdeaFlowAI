## What was wrong

`/workflow/create` with no query string, or with `?mode=` (key present, empty value), stayed
live and uncanonicalized: the URL never changed and the prototype wizard rendered underneath
the legacy route. Reproduced 3/3 from cold start by the validator; register entry
`BUG-20260828-001420-workflow-create-ppt`.

## Root cause

`frontend/src/proxy.ts:8` (pre-fix) —

```ts
const mode = request.nextUrl.searchParams.get("mode");
if (mode) {
  return NextResponse.redirect(new URL(`/create/${encodeURIComponent(mode)}`, request.url));
}
// If mode is missing, pass the request through unchanged
```

`URLSearchParams.get("mode")` returns `null` when the key is absent and `""` when it is
present but empty — both falsy, both taking the passthrough branch, which had **no fallback
destination at all**. This edge middleware, not
`frontend/src/app/workflow/create/page.tsx`, is the canonicalization layer for this route
(`matcher: ["/workflow/create"]`); `CreateRoute()` is the passthrough content renderer for
whatever the middleware declines to redirect, and it defaults any unresolved `mode` to the
prototype wizard in place with no navigation. Full analysis, including the stale
`next.config.ts` attribution in `[...view]/page.tsx:3583-3592`, is on
[ISS-250](20260828-1645-ISS-250.md).

## What changed, and why there

`frontend/src/proxy.ts` — the falsy branch is gone. `mode` now defaults before the
destination is built:

```ts
const mode = request.nextUrl.searchParams.get("mode") || "prototype";
return NextResponse.redirect(new URL(`/create/${encodeURIComponent(mode)}`, request.url));
```

Chosen because `proxy.ts` is the single choke point for this route and already performs the
redirect for every truthy `mode` — extending the SAME mechanism keeps one canonicalization
path instead of adding a divergent client-side `router.replace` inside `page.tsx`, which
would also paint a full page under the uncanonicalized URL before correcting it. `"prototype"`
is the family `CreateRoute()` already renders for an unresolved mode, so the content a visitor
lands on is unchanged — only the URL is now canonical (`/create/prototype`, handled by
`wizardModeFor` at `[...view]/page.tsx:301-316`, which returns `"prototype"` for the
`create-prototype` screen and renders the same `LaunchWizard`).

The hardcoded default is a literal, not interpolated query input, so
[ISS-227](20260828-1554-ISS-227.md)'s `encodeURIComponent` traversal guard on the truthy path
is untouched and still covers every attacker-controlled value.

Blast radius re-checked before editing: every in-app caller of this route passes a hardcoded
truthy mode — `CreationHub.tsx:31,35`, `DashboardLayout.tsx:1547,1574`,
`globalSlice.ts:220-222,250-252` — so none could reach the falsy branch and none change
behaviour. The only entry into it is external (bookmark, hand-typed URL, stale link).

`frontend/src/app/workflow/create/page.tsx` was deliberately NOT changed: its lack of a
fallback of its own is [ISS-376](20260828-2152-ISS-376.md), a separate INFERRED card with no
reproduction.
