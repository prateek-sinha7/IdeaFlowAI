## Bug

- One stuck or throttled model call failed a whole fan-out step with every other worker done (run 2867387c: 67/68 workers).
- An expired provider credential failed every later step within a second each (run 715c1279: 8 steps), then a missing-file error hid the cause.
- Resume read every mechanical step as incomplete (they write files, not typed artifacts), so it restarted the run from step 0 (run 2867387c).
- Every model ran at the global 32K output cap. A model writing a whole file in one tool call ran out mid-call and the call arrived with no content (run 7ef4faf8: three 32K `write_file` attempts). Bedrock's 600 s read timeout also cut calls off at ~36K tokens.

## Fix

- `engine.py`: `TRANSIENT_AGENT_ERRORS` names the retryable categories, and a provider 5xx gets its own message ("temporarily unavailable") instead of the generic "rejected". A credential error ends the run with `pipeline_failed` naming the step, so a resume after the credential is fixed starts there. On resume, a mechanical step's `agent_complete` is its completion evidence.
- `fanout.py`: a worker that failed on a transient error is re-run up to `_TRANSIENT_WORKER_RETRIES = 2` times, each on a new checkpoint thread.
- `model_catalog.max_output_tokens()` holds per-family output ceilings; `model_factory.build_model` uses it when the caller sets no cap. Bedrock `read_timeout` 600 s -> 1800 s.
- `deep_agent_runner._TruncatedWriteGuardMiddleware`: a `write_file`/`edit_file` call with no content after a `max_tokens` stop returns an error telling the model to write the file in parts.
- The backlog synthesizer prompt writes its output in parts.
