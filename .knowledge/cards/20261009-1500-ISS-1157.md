# ISS-1157

Register entry QA-KB-116 (Low). Reported as "checking a review gate in the Advanced modal times out" (e2e 03 test_checking_a_review_gate_sets_that_agents_gate_in_the_advanced_modal, tests/integration/e2e/suites/03_launch_panels/test_launch_panels.py:344).

## Reproduction (validated 3/3, cold start each, 2026-10-09, admin@velocity.ai, light theme, 1280x720)

Navigate to `http://localhost:3000/create/user-stories`, click "Review gates". Rows read "domain-analyst / Market & Persona Research", "epic-architect / Epic & Story Composition", etc. `page.get_by_text("Domain Discovery Agent", exact=True).click()` waits forever (8s timeout in all 3 attempts; the test's own timeout is the reported symptom).

## Conditions and what narrowing established

- Not a gate-sync failure: clicking the row labelled "domain-analyst" gives the pill "1 agent pause for review"; opening Advanced, selecting canvas-node-domain-analyst, Config tab, Gate select = "human" (probe 10-12). The ISS-247 behaviour the test guards is working.
- The Advanced modal canvas nodes also show "domain-analyst" as their title (nodeText in probe 11).
- AgentLibraryData.ts:18 and backend/agents/prompts/domain-analyst/AGENT.md:12 both declare name "Domain Discovery Agent"; run chat still prints that name. The raw id comes from the manifest-derived roster, `frontend/src/lib/manifestAgents.ts:98` `name: st.name || st.agent_id` (suspected: the user_stories workflow steps carry no `name`). Unconfirmed guess for analysis.
- INTEGRATION_TESTS.md:231 classifies this as "UI-CHANGED / agent no longer in roster, update expected agent" - the agent is in the roster, only its label degraded to the id, so changing the test alone would bake in the regression; whether ids-as-labels is intended is for analysis/owner.

**Verdict.** Root cause CONFIRMED. The reported "times out" is the e2e waiting 30 s for a label the page never renders:
the Review gates row and the Advanced canvas node are titled with the agent id. The gate sync the test guards
([ISS-247](20260828-1637-ISS-247.md) / [FIX-346](20260828-2314-FIX-346.md)) is intact. The suspected line in "Conditions"
above (`manifestAgents.ts:98`) is NOT the branch that runs: it is the fallback for a payload with no `manifest_steps`, and
even there `st.name` is the compiled step's name ("Domain Discovery Agent"). Three siblings filed, all reproduced at the
component tier: [ISS-1175](20261009-1653-ISS-1175.md), [ISS-1176](20261009-1653-ISS-1176.md),
[ISS-1177](20261009-1653-ISS-1177.md). No product decision is needed: every other surface that lists these agents shows
names ([FIX-390](20260829-0303-FIX-390.md) fixed the same raw-id class on `/workflows/{id}`), and the code showed names
until `1e329e47b`.

### Root cause (CONFIRMED)

One mechanism: the seam that turns a workflow payload into roster rows drops the agent's display name.

1. **The seam calls the converter without a lookup.** `frontend/src/lib/manifestAgents.ts:157`:
   ```ts
   const agents: AgentDef[] = manifestStepsToAgents(raw).map(decorate);
   ```
2. **Without a lookup a built-in step is named by its id.** `frontend/src/store/api/userWorkflows.ts:713-718`:
   ```ts
   const base = !isCustom ? lookup?.(id) : undefined;
   const agent: AgentDef = base ? { ...base } : { id, name: step.name ?? id, ...
   ```
   and `:728` `if (step.name) agent.name = step.name;`. The same literal also fixes `estimated_duration: 60` (`:724`), the
   icon `""` and `has_skill: false` (see [ISS-1177](20261009-1653-ISS-1177.md)).
3. **`decorate` repairs everything except the name.** `manifestAgents.ts:135-156` looks the step up in the compiled
   projection (`detail.steps.find(...)`, `:141`) and restores `role` (`:145`), `description`, `order`, `gate` and `route`;
   `...a` carries the id-as-name through untouched.
4. **It is a regression.** `1e329e47b` (2026-09-04, an ancestor of HEAD) replaced the hand-rolled projection with the
   delegation above. The line it removed was `name: st.name || compiled?.name || id`
   (`git show 1e329e47b^:frontend/src/lib/manifestAgents.ts`, line 118). `manifestAgents.test.ts` covers only custom-agent
   steps that carry an explicit `name` (its fixture), so nothing failed.
5. **The payload has what is needed.** Live `GET /api/workflows/user_stories` as admin: every `manifest_steps[].name` is
   `null`, every compiled `steps[].name` is the display name (`evidence/qa-kb-116/analysis-02-live-override-state.txt`).
   The backend fills it: `backend/app/api/workflows.py` `name=(getattr(step, "display_name", "") or (spec.name if spec else
   step.agent_id))`.

### Fix: where it belongs

In `agentsFromManifest` and nowhere else: all five callers go through it, so no call site changes. Smallest shape (reuses the
converter's own `lookup` parameter, which is how every other caller supplies names): build the lookup from the payload's
compiled steps and pass it at `manifestAgents.ts:157`:

```ts
const compiled = new Map(detail.steps.map((c) => [c.agent_id, c]));
const fromCompiled = (id: string): AgentDef | undefined => {
  const c = compiled.get(id);
  return c && { id, name: c.name, role: c.role, description: c.role, pipeline_type: pipelineType,
                order: c.order, icon: "", estimated_duration: 0, has_skill: false };
};
// ... manifestStepsToAgents(raw, fromCompiled).map(decorate)
```

`manifestStepToAgent` then spreads it as `base`, an explicit `step.name` still wins (`userWorkflows.ts:728`), custom-agent
steps are untouched (the lookup is skipped for them, `:713`), and `estimated_duration: 0` restores the pre-`1e329e47b`
behaviour for [ISS-1177](20261009-1653-ISS-1177.md) as a side effect. The fuller shape forwards an optional library lookup
from the five callers (`lookup?.(id) ?? fromCompiled(id)`) so icon and duration also match the system roster; that is a
five-site edit and is only needed if ISS-1177 should show the real "~35s" rather than no estimate. A `decorate`-only variant
(`name: a.name === a.id ? compiled?.name ?? a.name : a.name`) also fixes the name but leaves ISS-1177.

Traps:

- Do not change `manifestStepToAgent`'s `name: step.name ?? id` default. The Composer passes a lookup and a custom step
  legitimately falls back to its instance id.
- An explicit manifest `name` must keep winning over the compiled one (the removed formula had `st.name` first).
- Do not special-case a workflow or agent id (SC-001; the same page states the rule at `IdeaInputPage.tsx:1496`,
  "name-free by construction"). Names come from the payload or the library.
- Do not add a third copy of the projection (INV-12). `IdeaInputPage.tsx:1286-1312` is already a dual implementation of the
  seam (and carries its own duplicated `normaliseRoute`, `:1267-1268`); it is correct today, and the regression is how that
  duplication was supposed to be avoided. Leave it, or retire it in a separate change.
- Do not edit the e2e expectation to the id (`INTEGRATION_TESTS.md:231` calls this "UI-CHANGED / agent no longer in the
  roster, update the expected agent"; the agent is in the roster, only its label degraded, so that edit would bake the
  regression in).
- Do not "fix" the gate sync: it works (probes 10-12, ISS-247 / FIX-346).
