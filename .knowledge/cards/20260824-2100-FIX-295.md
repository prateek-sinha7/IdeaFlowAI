The merge re-homed this branch's `0031`/`0032` to `0036`/`0037` to make room for dev's
Cognito `0031`-`0035`, but missed `0033`: both sides had added a NEW file under a
DIFFERENT filename, so git saw no conflict and landed both.

```
0033_add_diverted_at_step_id.py   ours   revision 0033 <- 0032
0033_user_api_key_expiry.py       dev's  revision 0033 <- 0032
0034_mfa_verified_at.py           dev's  down_revision = "0033"   <- ambiguous
```

`alembic heads` reported `0033` and `0037`. Ten migration tests failed.

Ours re-homed to `0038` with `down_revision = "0037"`. The migration is additive and
order-independent, so moving it later changes nothing about what it does. Verified by a
from-scratch `0001 -> 0038` upgrade on a fresh Postgres database.

**The general lesson:** two branches adding differently-NAMED files that claim the same
logical id produce no git conflict. Alembic revisions and knowledge-card ids both have
this shape — see [FIX-296](20260824-2100-FIX-296.md).
