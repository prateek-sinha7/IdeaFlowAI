## What was wrong

This is bug report QA-KB-039. [ISS-860](20260923-0229-ISS-860.md) holds the analysis.

`test_native_prototype_pipeline_placeholder_output_not_marked_completed`
([ISS-761](20260922-1424-ISS-761.md)) says its build agent "only streams placeholder text, then
reports the task complete". The fixture did not do that. `_prototype_placeholder_scripts` gave
`prototype-build` one `_ScriptedTurn`, and that turn carried a `report_task_complete` tool call.
`ScriptedFakeChatModel._next_turn` replays the last turn once a script runs out
(`backend/tests/agents/_scripted_model.py:166`,
`turn = turns[idx] if idx < len(turns) else turns[-1]`). So after every tool result the model
called `report_task_complete` again, until `AGENT_RECURSION_LIMIT` (2500) raised
`GraphRecursionError` and the engine marked `prototype-build` failed.

The test still passed. It asserts only `published_status`, and
[FIX-612](20260922-1838-FIX-612.md)'s placeholder gate degrades that on its own. So the run it
exercised was "the build agent failed", not "the build agent cleanly reported completion without
writing". Each run took 35-96 s (ISS-860's measurements).

## Root cause

A tool-calling turn was the last turn of a scripted agent. The shared harness replays the last
turn by design, and only a text-only AI message ends the graph. Every other tool-calling script
in `backend/tests` ends on a text-only wrap-up turn, for example
`_scripted_model.py:441`, `_ScriptedTurn(texts=["Done."], usage=(10, 5))`. ISS-860's AST scan
found one offender among 34 tool-calling turns: this one.

## Change

One file, test code only. In `_prototype_placeholder_scripts`, the `prototype-build` branch of
`backend/tests/agents/test_qa_ps_027_placeholder_completion.py` (`:138-156`) now appends
`_ScriptedTurn(texts=["Task complete."], usage=(5, 3))` after the `report_task_complete` turn
(`:155`). A two-line comment above it names the replay rule (`:153-154`). This is the agreed fix
from BUGS.md, which the ISS-860 analysis accepted, applied as written.

Left as they were, as ISS-860 required:

- The `prototype-validate` script still streams `PLACEHOLDER_TEXT`. `single_file` branch 3 reads
  `ctx.last_streamed` from the last agent to run, which is validate. So the ISS-761 test's
  `final_output` precondition still holds.
- The exact-equality `final_output` precondition and the `published_status` assertion
  (`:187`). [FIX-641](20260923-0229-FIX-641.md) locked both.
- The ISS-860 regression test `test_iss761_fixture_models_clean_task_completion` and its
  `xfail(strict=True)` marker. The 6-verifier removes the marker after it confirms the fix.

## Why there

The defect is in the fixture, so the fix is in the fixture. ISS-860 rejected a guard in the
shared `_next_turn`. Only one of 34 tool-calling turns breaks the convention. A guard would change
the replay semantics that about 60 test files build on, and it would not reach the three private
copies of the rule. No application code changed, so SC-001, the import-linter contracts and the
migrations are not touched.
