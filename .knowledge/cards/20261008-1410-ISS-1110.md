# ISS-1110

## Description

INFERRED sibling of [ISS-896](20261001-2127-ISS-896.md) (QA-KB-099). The text that tells an engineer where a guard-tripping unit
test must go disagrees with the suite on three points, and the list that was meant to track those tests cannot be opened. All three
facts below are CONFIRMED by grep; that they matter to ISS-896's fix is the inference.

1. **"Exactly ONE" is false.** `backend/tests/README.md:102-105`: "`@pytest.mark.allow_io("why")` disables the guard for one test. There
   is exactly ONE in the suite (the guard's own escape-hatch test). Adding a second
   needs a reason that survives review — usually the honest answer is `tests/integration/`." `backend/tests/unit/test_unit_io_guard.py:109-110`: "This is the suite's ONLY allow_io
   marker. Any other one is a test that should have moved to tests/integration/ instead." Actual, under `backend/tests/unit`
   (excluding the guard's own message strings in `conftest.py`): 25 applications of `pytest.mark.allow_io` in 14 files, 13 of them
   outside `test_unit_io_guard.py` (`evidence/qa-kb-099/analysis-06-policy-text-vs-practice-allow-io.txt`). Three of the 13 carry an
   "Audit note" saying the test belongs in `tests/integration/` and that relocating it "needs an approved migration plan"
   (`test_run_sandbox_api.py:40`, `test_ci_bounded_runner.py:37`, `test_run_stream_pool_leak.py:59`); the other ten give a reason only.
2. **The eviction inventory is not in the repository.** `backend/tests/README.md:183-186`: "63 files / 599 tests are known to trip the
   unit I/O guard and are queued for
   eviction — inventory in `unit-test-prompt/test-files/_structure/03-migration-log.md` §7.3".
   `git ls-files | grep -c unit-test-prompt` is 0 and `git log --all --oneline -- unit-test-prompt backend/unit-test-prompt` is empty
   (same evidence file). So no committed list says which red unit tests are queued, where they are meant to go, or whether the
   "approved migration plan" the audit notes mention exists.
3. **"Cleared" is false.** `backend/tests/README.md:178-182` says `tests/unit/agents/` "was cleared of all of this in Batch 6".
   [ISS-1109](20261008-1410-ISS-1109.md) is a test under `tests/unit/agents/` that fails today with `UnitIsolationError` on a git spawn.

## Why the root cause of QA-KB-099 implies it

ISS-896's test was written down as failing on 2026-09-23 (`UNIT-TESTS.md` row 325), one day after the guard landed, and is still
failing on 2026-10-08. In between it was carried as a baseline by three bug lines (QA-KB-042, QA-KB-043 and QA-KB-076; see
`evidence/qa-kb-042/08-fix-test-runs.txt` and the notes in [ISS-896](20261001-2127-ISS-896.md)) without anyone owning it. A committed eviction list would have named it. Instead the fixer has
to choose between the two remedies the guard's message offers (`allow_io` or a move) using text that says "exactly one exemption,
usually move it" next to a suite that holds 25 exemptions and a same-family sibling that keeps its exemption on purpose.

The ISS-896 fix will itself add a 26th marker if the exemption is chosen, so the README sentence gets more wrong the moment the bug
is fixed that way.

Update 2026-10-08 ([FIX-765](20261008-1436-FIX-765.md), QA-KB-099). That happened, and twice: both ISS-896's test and ISS-1109's
test now carry `allow_io`. `grep -rn 'pytest.mark.allow_io' tests/unit` (conftest excluded) prints 28 lines in 16 files. The
analyzer's run of the same grep printed 26 lines in 14 files (`evidence/qa-kb-099/fix-06-lint-and-invariants.txt`). ISS-1109's test
is no longer red, but `tests/unit/agents/` still holds a test that needs real git. It now runs under an exemption, so point 3 still
needs a text change. This card stays `open`: the owner's answer below decides the wording.
