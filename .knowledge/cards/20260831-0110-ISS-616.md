## What happened

The full backend suite reported `8 failed, 488 passed, 3734 errors` — nearly
every test erroring at SETUP with:

```
tests/conftest.py:352: in _isolate_compiled_plan_cache
    compile_for_run.cache_clear()
E   AttributeError: 'function' object has no attribute 'cache_clear'
```

`compile_for_run` IS decorated (`agents/execution_engine/engine.py:644`,
`@_functools.lru_cache(maxsize=None)`) and has `cache_clear` on a plain import.
Something replaced it mid-session and never put it back.

## Root cause

`backend/tests/agents/test_declared_gate_streaming.py` patched it by bare
assignment at three sites and restored it in each test's `finally`:

```python
engine_mod.compile_for_run = _patched_compile_for_run   # ~line 97 / 314 / 458
...
finally:
    engine_mod.compile_for_run = _orig_compile_for_run  # ~line 218 / 394 / 530
```

The precondition assertion sits BETWEEN the patch and the `try` — at line 321,
while the restore is at 394. When that assertion started failing (see
[ISS-617](20260831-0110-ISS-617.md)), the restore never executed and the module
was left holding an un-cached plain function for the rest of the session.

The blast radius came from `conftest.py`'s autouse `_isolate_compiled_plan_cache`
fixture, which clears that cache at the setup of every test. One leak, 3734
setup errors — and the 3600 tests they belonged to never ran at all, which is
why the suite looked like it finished in 216s.

Ordering made it invisible: the file sits at 11% of the run, so everything
before it passed normally.
