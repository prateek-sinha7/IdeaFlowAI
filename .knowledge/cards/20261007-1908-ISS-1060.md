# ISS-1060

Found while fixing QA-KB-071 with [FIX-731](20261007-1908-FIX-731.md). It belongs to the same class as
[ISS-1010](20261002-0540-ISS-1010.md): the anchor still matches, but it matches the wrong place. Confidence: CONFIRMED by
a mutation on a scratch copy. The repo `page.tsx` was not edited.

## Condition

The `writes to the run STORE — the state the UI actually reads` case, after FIX-731 (test lines 70-78):

```ts
const call = pageSource.indexOf(APPLY_CALL);
const storeWrite = pageSource.lastIndexOf("runStore.updatePipelineState(", call);
expect(storeWrite).toBeGreaterThan(-1);
```

## Expected

The lock goes red when the ISS-126 reopen reconcile stops writing to the run store, which is the state the UI reads
(`page.tsx:4158`, `displayedPipelineState = runStore.viewed.pipelineState`).

## Actual

`page.tsx` has 6 `runStore.updatePipelineState(` calls before the reopen call. The first is at `:2173` and the nearest is
at `:3005`, in another handler. `lastIndexOf` returns whichever one precedes `call`, so the case only proves that some
store write exists earlier in the file. The neighbouring "gates the reconciliation" case has the same weakness: it
checks `toContain("runStore.updatePipelineState(")` against the whole file.

## Evidence

`evidence/qa-kb-071/fix-06-negative-control.txt`, section "nostore". A scratch copy of `page.tsx` had
`runStore.updatePipelineState(fullRun.id, (prev) =>` before the reopen `applyTerminalStatus(prev, fullRun.status, ...)`
(`:3129-3130`) replaced with `setLegacyPipelineState((prev) =>`. The FIX-731 lock then gives `Tests 10 passed (10)`, and
the run-STORE case is marked `✓`. The nearest earlier store write is reported at line 3005.

## Fix direction

The fix belongs in the lock only, with no `page.tsx` change. Assert that the store write wraps the reopen call: the text
between `storeWrite` and `call` should be the updater head alone, for example
`expect(pageSource.slice(storeWrite, call)).toMatch(/^runStore\.updatePipelineState\(fullRun\.id, \(prev\) =>\s*$/)`.
The `nostore` mutation above is the negative control, and with the fix in place it must turn the case red. That
assertion was checked as a bare node expression, not as a vitest case. It holds on the current copy (a 67-character
gap) and fails on the `nostore` copy (an 8305-character gap). The result is at the end of the same evidence file. Out of
FIX-731's scope because no card named it.
