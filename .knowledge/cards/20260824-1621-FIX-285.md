`ex_A1_loop`'s `check` step has a conditional gate and two route outcomes, and rendered as
a plain node with no diamond and no branch edges.

## Root cause

`CanvasView`'s own test needs two things:

```js
const branches = (a) =>
  (selections[a.id]?.gates ?? []).includes("conditional") &&
  Object.keys(a.route?.outcomes ?? {}).length > 0;
```

Gates live in `selections` — in the composer they are a user-TOGGLED lever — not on
`AgentDef`. A workflow opened from its manifest has them DECLARED instead, and nothing
populated that half, so the second condition passed and the first never did.

## Fix

Seed `selections` from the manifest's own `gates`, merged UNDER any saved or user
selection so a user-set lever for the same step still wins.

The composer had the mirror of this bug already solved for saved workflows —
`manifestStepsToGateSelections` exists precisely because "route restored but every step's
gate dropdown showed Off and its route editor stayed hidden". Same trap, two surfaces.
