## What happened

A COMPOSED workflow — one whose agents come from the user's selections rather than
a file manifest — silently dropped every agent that the base manifest did not also
declare. The run emitted `pipeline_complete`, so it read as a success:
`agents_completed: 1, agents_total: 2`, zero workers spawned.

## Root cause

Two collections that spec 014 assumed were 1:1.

`compiler._compute_is_leaf` (`backend/agents/workflows/compiler.py:1674`) sets
`is_leaf` over `compiled.steps`:

```python
step.is_leaf = (i + 1 >= len(steps)) or ((i + 1) in jump_target_idx)
```

The execution loop walks `ordered_agents` — the ROSTER — and consumed that flag as
a terminator (`backend/agents/execution_engine/engine.py:3351`):

```python
cursor = len(ordered_agents) if step.is_leaf else cursor + 1
```

For every file-manifest run the two are the same length, which is why this held.
They are NOT for Path B: an agent present only in the selections has no step in the
base plan (`_user_steps_by_agent`, engine.py:2714). With a 1-step plan and a
2-agent roster, `is_leaf` on step 0 is `0 + 1 >= 1` → True, and the cursor jumped
straight past the composed agent.

Verified directly: compiling a single-step manifest yields `is_leaf: True` on its
only step.

## The fix

`is_leaf` only ever claims that nothing in the COMPILED GRAPH follows. When the
next roster entry has no compiled step, the graph has no opinion about it and
plain array-adjacency — the pre-014 behaviour — must win:

```python
_next_spec = ordered_agents[cursor + 1] if cursor + 1 < len(ordered_agents) else None
_leaf_ends_the_walk = getattr(step, "is_leaf", False) and (
    _next_spec is None or _next_spec.id in _steps_by_agent
)
cursor = len(ordered_agents) if _leaf_ends_the_walk else cursor + 1
```

The three cases this must satisfy, all confirmed: a linear pre-014 workflow still
terminates at its last step (`_next_spec is None`); `ex_A2_branch`'s forward-branch
targets still terminate (the next roster entry IS in the plan — the T25
mutual-exclusivity fix is preserved); a composed run advances.

## Second, separate defect found in the same test

Once the worker was dispatched, its file writes still did not land:
`write_file DENIED at execution — not granted by this step's permissions`. The
composed selection declared `strategy`/`task_source`/`fanout` but no `tools`, so
the synthesized step sat at the least-privilege default. That is correct engine
behaviour — the fixture had to grant them, as the composer does on a real run.
