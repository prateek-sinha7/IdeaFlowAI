# ISS-067

## Title

`.kiro/steering/velocity-ai-fix.md` carries five facts that are wrong on this machine and will mislead any agent that follows it: (1) it prescribes `uv run --no-sync pytest` but `backend/.venv` does NOT exist, so every command in it fails — use `python3.11`; (2) it asserts lint-imports is `4 kept / 0 broken`, actual is `3 kept / 1 broken`; (3) migration head `0026`, actual `0030`; (4) it implies the characterization goldens are green, actual is 5 failed / 5 passed on `dev`; (5) Playwright live on `:8002`, actual `:8010`. Separately, a **0-byte stale `dev.db` sits at the repo root** while the live 160MB database is `backend/dev.db` — a read-only query from the repo root silently returns an empty database with no error.

## Severity / Tag / Status (original row)

- Sev: minor
- Tag: test-infra
- Status: **FIXED 2026-08-12 (commit `cb55a498`) — except the `dev.db` clause, deliberately left; see below.** Seven wrong facts were corrected, not the five filed. Beyond the five listed here: (6) the doc's **"Next FIX-ID = highest in INDEX.md + 1"** rule (line ~485) is the single-source rule that re-issued a live id and forced the ISS-050→ISS-064 renumber — replaced with the four-source rule; and (7) **`lint-imports` must be run from `backend/`** (its config is in `backend/pyproject.toml`); from the repo root it prints "Could not read any configuration" and exits, which reads like a pass. Claim (1) was also wrong in a more dangerous way than filed: `uv run --no-sync` does **not** fail loudly here — it silently CREATES an empty CPython 3.12 venv, skips the dependency install, then dies on the first import, leaving a stray `backend/.venv` that shadows the working interpreter (reproduced and cleaned up). The stale migration head appeared in **three** files, not one (`velocity-ai-fix.md`, `velocity-ai-analyze.md`, `backend-models-migrations.md`) — all corrected. **Fix approach:** correcting the numbers alone would only reset the clock, so every brittle point-in-time assertion was replaced with the command that yields the current value plus a compare-to-baseline rule; a new "Step 0 — Local environment facts" block states that the whole document was written for CI (`ci.yml:95-121` provisions a synced env) and that local differs. `.claude/skills/velocity-ai-bookkeeping/SKILL.md` Step 0 was re-verified and updated too. **NOT done — the `dev.db` clause:** the 0-byte repo-root `dev.db` still exists. It is untracked and gitignored (`.gitignore:25 *.db`), and the cause is `backend/app/core/config.py:322` defaulting to the RELATIVE `sqlite:///./dev.db`, so it resolves against the process cwd. Deleting it would make a wrong-directory query fail loudly instead of silently returning zero rows, which is better — but deletion is destructive and was left for the owner to decide. The trap itself is now documented in the steering file, which addresses the actual harm of misleading an agent.

## Source / Evidence

All five verified 2026-08-11 while extracting `.claude/skills/velocity-ai-bookkeeping/SKILL.md`, whose Step 0 documents the corrections. The steering source itself is unfixed.
