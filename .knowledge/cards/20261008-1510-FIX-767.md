# FIX-767

**Register source:** `QA-KB-101` (`LEDGER.md`), 5-fixer, 2026-10-08. Resolves [ISS-1094](20261007-2337-ISS-1094.md).

## What was wrong

`TestList::test_list_carries_launchable_flags` pins each launchable catalog row's `display_name` as hand-typed literals in its
`authored` dict (`backend/tests/integration/api/test_workflows_api.py:215-222`). Two of them, `:217` "Build an interactive prototype"
and `:218` "Pitch an idea", were the text from before `1a1b720b7` ([FIX-645](20260925-1201-FIX-645.md)) renamed
`backend/agents/workflows/prototype/workflow.yaml:5` and `backend/agents/workflows/ppt/workflow.yaml:22` to "... (Fast)" on purpose.
The route serves the manifest label verbatim (`backend/app/api/workflows.py:398`,
`display_name=(manifest.display_name if manifest else None)`), so the assertion at `:225` failed:
`AssertionError: prototype must carry its authored display_name verbatim (got 'Build an interactive prototype (Fast)')`.
The unit I/O guard (`09270703b`) made the file error at setup, so the rename's own test run never showed it;
[FIX-758](20261007-2338-FIX-758.md) moved the file out of the guard's reach and it surfaced. The root cause, and the evidence that
the manifests are the intended side, are on [ISS-1094](20261007-2337-ISS-1094.md) (Analysis); not re-derived here.

## What changed, and why there

`backend/tests/integration/api/test_workflows_api.py:217-218`, two string literals and nothing else:

```
-            "prototype": "Build an interactive prototype",
-            "ppt": "Pitch an idea",
+            "prototype": "Build an interactive prototype (Fast)",
+            "ppt": "Pitch an idea (Fast)",
```

- This edits a test because the card says its expected values were misstated (stale), not because the assertion was red.
  ISS-1094's analysis settles the direction: the rename commit's message, FIX-645's locked constraint, the e2e launchable list
  (`tests/integration/e2e/framework/locators/home_catalog.py:52,54`) and the screens spec
  (`tests/integration/screens/02-home-catalog.feature.md:46,48`) all say "(Fast)". Only this test disagreed.
- Both lines change in one edit: the loop at `:223-229` raises at the first mismatch, so `ppt` was a second red behind `prototype`.
- No production file changed. There is no shared function to fix: the one route every label consumer uses (`workflows.py:398`) is
  right. The manifests and the route are untouched; the diff is one file, 2 insertions, 2 deletions.
- Literals rather than a manifest-derived expectation: the card offered both. Literals are this file's pattern (six of them), the
  smaller diff, and they still catch an accidental label edit.
- The test carried no `xfail` marker (the test stage recorded "the existing red test is the failing test"), so the pass signal is a
  plain pass, not an XPASS. There is no marker for the verifier to remove.

## Consequences and what is left

- [ISS-1094](20261007-2337-ISS-1094.md) is resolved by this card.
- [ISS-1115](20261008-1438-ISS-1115.md) stays open and is not fixed here. It is the same mechanism one rename later, in the live e2e
  tier: "Pitch an idea (Detailed)" against a `ppt_v2` manifest that says "(Depth)" since `87903ab3b`. It is INFERRED, its own fix
  direction is "only once reproduced", and its tests are the live tier (Cognito login, a real model run), which this line does not start.
- The mechanism stays: a catalog label is authored once in a manifest and re-typed as a literal by each test layer, and nothing makes
  a rename reach the copies. A label rename has to grep `backend/tests`, `tests/integration/e2e` and `tests/integration/screens` for
  the old text in the same change.
