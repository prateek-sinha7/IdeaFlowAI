# ISS-640

## Title

**The agent-runtime half of ISS-120 is still a single process-wide switch.**
[FIX-427](20260831-1813-FIX-427.md) gave the direct-invoke path
(`app/agents/cached_invoke.py`) a per-call `enable_cache` opt-out, closing ISS-120 for
the five callers that route through `cached_invoke`. The OTHER flag-read site ISS-120
names — `_BedrockCachePointsMiddleware._maybe_apply`
(`app/agents/deep_agent_runner.py:283`) — is unchanged: it still reads
`settings.BEDROCK_PROMPT_CACHE_ENABLED` and nothing else, so every deep-agent step in
every run caches or does not cache together.

## Why it was not fixed with FIX-427

The middleware has exactly ONE construction site
(`deep_agent_runner.py:463`, `_BedrockCachePointsMiddleware()`), and **no per-step
signal reaches it**. Giving it a constructor parameter nobody can set would be dead
flexibility; giving it a real one means declaring a per-step capability flag in
`workflow.yaml`, resolving it through the manifest compiler, and threading it into
`create_runner` — which is exactly ISS-120's candidate shape (b).

ISS-120 lists three mutually exclusive shapes and picks none:

- (a) leave it global and document it;
- (b) suppress the cache point when the step is **declared** single-turn — a
  manifest-declared capability flag, no kernel edit, SC-001-safe;
- (c) a heuristic that only writes cache points once a run has exceeded N model calls.

That is a product decision, not a defect with one correct answer, so a fixer choosing
one would be picking the product decision rather than proving it. **Whichever shape is
chosen, it must NOT be keyed on workflow name (INV-1 / SC-001).**

## Cost of leaving it

Measured in ISS-120, read-only against `backend/dev.db` through the shared
`estimate_cost_usd`: 6 of 11 persisted runs cost MORE with caching on
(-4.98% .. -8.86%), because a cache entry bills at `cache_write_5m = 1.25x` the input
rate (`agents/capabilities/model_catalog.py:82`) and a turn that writes an entry
nothing later re-reads pays a pure 25% surcharge. The discriminator is run LENGTH, not
workflow type — and the deep-agent runner path is where the short runs live.
