## Recurring failure patterns

1. **Save paths that discard or misreport.** "Save as my version" drops the brief and template
   on both wizards (same root cause, confirmed across two pages); the built-in "Save as copy"
   persists `manifest: null`, turning a PPTX workflow into generic markdown; empty-name save,
   agent-config save and library skill "Add" are silent no-ops with false success feedback.
2. **Constraints displayed but never enforced.** No tier gating on model choice; a 4000-char
   limit that is display-only; requirement pills nothing on the page can satisfy; a plan button
   with no handler; a direct-URL bypass into a wizard the dashboard shows as locked.
3. **Silent no-op / swallowed-error controls.** Six primary actions fire no request or discard a
   real backend error: legacy Run, diverted Start-new-run, agent Config Save, Manage plan,
   empty-name Save, and the admin duplicate-email 409.
4. **Figures that disagree across surfaces.** Run history caps at 50 of 273 while labelling it
   the total; header token counts contradict the API; the Steps footer breakdown does not sum;
   a version picker mislabels v2 as v1; file sizes count characters instead of UTF-8 bytes.
5. **Unsanitised params reaching the router.** `?mode=../admin` escapes its namespace onto the
   live admin console; a pinned `/versions/2` silently reverts to v1 data when a tab is clicked.
6. **Status and audit records that misreport reality.** The audit log fabricates 96 governance
   rows the backend has no gate events for; a run's status stays `cancelled` after it genuinely
   failed; a live view freezes on "Running" after the backend already failed the pipeline.

## Coverage limitations

- **Serialized execution.** All subagents share one `@playwright/mcp` server and one Chrome
  profile, so pages were hunted one at a time. Parallel lanes would have stomped each other's
  tabs and manufactured false positives.
- **Live runs were unavailable for the first ~10 hours.** Bedrock credentials were invalid until
  ~08:05 UTC, so every live-execution surface was tested against dead seeded data until then.
  Four bugs were found only after the fix, including two that exist solely on runs the hunt
  itself produced.
- **`/admin` grant-admin was never exercised**, by design — D-31 would 401 every admin
  credential product-wide and require a database write to recover.
- **One fixture mutated legitimately.** A "Reopen & fix from the failed step" test resumed and
  then stopped seeded run `d6e425b6…`, flipping it from `failed` to `cancelled`. The registry
  and brief were updated to `a85e46a6…`; 11 genuinely failed runs remain.
- **Transcript mtime is not a liveness signal.** An early "stalled" diagnosis was wrong — a
  worker ran 42 minutes with a frozen mtime. Two workers briefly ran on one page as a result;
  the ledger lock held and both entries are distinct. The watchdog no longer declares stalls.
