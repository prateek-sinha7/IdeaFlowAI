# Design DNA · Structured Design Identity Layer (for visual cloning / content overhaul)

Turn "make it feel like that site" from a vague feeling into a **versionable, reusable, comparable JSON spec**.
Used in the two modes "visual cloning" and "content overhaul" — after recon, before building the project, produce one more `design-dna.json`,
so Step 6 "swap in the user's own stuff" has something to go on: **keep the DNA, swap out the content**.

> Method and schema adapted from [zanwei/design-dna](https://github.com/zanwei/design-dna) (MIT), trimmed to web-clone's standard.

## Boundary of applicability (read this first)

Design DNA's generative philosophy is **"approximate style"** — what it produces is a "stylistically consistent new site," not a byte-for-byte copy.
That's the *opposite* direction from web-clone's rule #1, "true source above all / byte-for-byte fidelity." So:

| Mode | Use DNA? |
|---|---|
| Faithful clone (real source obtained / single-file native site / byte-for-byte WebGL restoration) | **No.** Real source is the ground truth — don't let DNA dilute it into an "approximation" |
| Visual clone (reproduce the look and feel but simplify the implementation) | **Yes.** DNA is the main deliverable for this path |
| Content overhaul (keep information architecture + rhythm + visual grammar, swap in the user's content) | **Yes.** DNA defines "what to keep," content can change freely |

In one line: **DNA is for "build my own site," not for "copy it exactly."**

## Three-layer structure

The DNA JSON has three layers, corresponding to "measurable / perceptible / special rendering":

1. **`design_system`** — measurable tokens: color / typography / spacing / layout / shape / elevation / iconography / motion / components
2. **`design_style`** — subjective perception: aesthetic (mood/genre/era) / visual_language / composition / imagery / interaction_feel / brand_voice_in_ui
3. **`visual_effects`** — rendering beyond plain CSS: background / particles / 3d / shader / scroll / text / cursor / image / glass-neu / canvas / svg

`design_system` maps directly to CSS variables; `design_style` guides subjective judgment calls; `visual_effects` determines whether Canvas/WebGL/GSAP is needed, and interfaces with this skill's "WebGL reverse-engineering branch."

## Three-step workflow

1. **Structure** — First look at the schema (below + the skeleton generated by `dna-scaffold.mjs`), confirm which dimensions need filling in, and drop the ones that don't apply.
2. **Analyze** — Extract from the recon artifacts:
   - Color: `cssVariables` from `<label>-recon.json` (values starting with `--`) + `backgroundColor` / `color` from `sections[].style`; decide primary by area coverage, accent by CTA usage.
   - Fonts: the `fonts` array + `sections[].style.fontFamily`, split into heading / body / mono.
   - Spacing/layout: measure rhythm and max width from screenshots + `sections[].rect`.
   - Effects: `frameworks.three/gsap/lenis` + `canvases` + `counts.canvas` → fill in `visual_effects.overview.primary_technology` and the various `enabled` flags.
   - Style/perception: look at the three screenshot breakpoints (1440/768/390) and manually judge mood, genre, composition, whitespace.
   - **Fill every field with a real value, don't leave empty strings**; if you can't fill something in, mark it `TODO` and note what evidence is missing.
3. **Generate** — Parse the DNA → generate CSS custom properties → make subjective calls per `design_style` → pick the implementation tier per `effect_intensity` (lightweight = CSS/SVG/vanilla; medium = Canvas2D/GSAP/Lottie; heavy = Three.js/GLSL/Pixi) → output the page → pour in the user's own content. **Prefer pulling real assets from the original site first (via `asset-harvest.mjs`) — don't have AI redraw approximations.**

## Scaffold

```bash
node "$WEB_CLONE_SKILL_DIR/scripts/dna-scaffold.mjs" \
  --recon "$WEB_CLONE_PROJECT/RECON/original-recon.json" \
  --out   "$WEB_CLONE_PROJECT/RECON/design-dna.json"
```

The script outputs the full DNA skeleton and **best-effort pre-fills** the fonts, CSS color variables, and framework/effect signals detected during recon;
the remaining fields are left as `""` (to be completed manually during Analyze). It also runs without `--recon`, producing a pure empty skeleton.

## Division of labor with the WebGL reverse-engineering branch

- For sites where `visual_effects` marks `heavy-immersive` / `WebGL/Three.js` / `shader_effects.enabled=true`, **don't use DNA to "approximate" that effect** — that's `effect-extraction.md` + `reverse-engineering.md`'s job; reverse-engineer the real implementation.
- On such sites, DNA is only responsible for the design layer "outside of the effects" (color/typography/layout/ordinary motion); the effects themselves go through reverse engineering or get delegated to web-shader-extractor.
