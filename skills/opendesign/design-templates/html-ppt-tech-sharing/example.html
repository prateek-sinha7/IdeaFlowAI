deep-dive · 1 / 2

Goroutine 其实只是一个结构体。

编译器把 go func() 变成一个 g 结构体，挂到某个 P 的本地队列上。运行时只做一件事：反复调度它，直到它让出或退出。

deep-dive · 2 / 2

GMP 是一个偷任务的小工。

GOMAXPROCS = N 个 P，每个 P 绑定一个 M 运行，有自己的本地队列。空闲的 P 会去别人队列里"偷"任务。

✦ local queue · 256 slots
✦ global run queue
✦ work-stealing @ 50% steal ratio
✦ runnext slot for cache locality

scheduler tick loop

1. pop from runnext slot
2. else pop from local queue
3. else drain global queue (every 61 ticks)
4. else steal from random victim
5. else park the M

mini-sched.go · ~40 LOC

手写一个最小 scheduler。

src/main.go
import (
    "container/list"
    "sync"
)

type Task struct { fn func() }

type Sched struct {
    mu    sync.Mutex
    queue *list.List
}

func (s *Sched) Spawn(fn func()) {
    s.mu.Lock(); s.queue.PushBack(&Task{fn}); s.mu.Unlock()
}

func (s *Sched) Run() {
    for s.queue.Len() > 0 {
        s.mu.Lock()
        t := s.queue.Remove(s.queue.Front()).(*Task)
        s.mu.Unlock()
        t.fn() // 就是这一行
    }
}

// takeaways

三件事带回去。

1 · goroutine 是廉价抽象

初始栈只要 2KB，按需增长，没有线程切换那么贵。

2 · P 是调度的心跳

G 不主动抢资源，调度器靠 P 决定"下一个跑谁"。

3 · 别在 goroutine 里裸调 syscall

一行阻塞式 syscall.Read 能让整个 M 停摆。让 netpoller 接管。
