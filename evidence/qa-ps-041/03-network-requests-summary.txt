Trigger identified: entry path. Reaching /workflows via an in-app client-side navigation
(clicking the "My Workflows" nav button from another route) doubles the duplicate-fetch count
vs. a cold hard URL load — 4x user-workflows / 2x auth-me on click-through vs 2x/1x on hard
nav — because the SPA route change causes DashboardLayout/nav components to re-mount data
fetchers in addition to the destination page's own fetchers, on top of whatever the previous
page had already fetched. In both entry paths, /api/runs?limit=50 fires even though the My
Workflows page renders only saved workflow cards with no run history, recents, or "Jump back
in" section — matching the reporter's report exactly (unneeded 37KB/22-37KB runs payload).

Core defect present on 3/3 attempts: user-workflows list fetched more than once per page view,
and /api/runs?limit=50 fetched despite not being displayed on /workflows.
