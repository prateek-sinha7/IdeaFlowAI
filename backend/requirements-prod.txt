# langchain-mcp-adapters — the net-new MCP *client* layer (09-05 / MCP-01). The
# backend was an inbound MCP server only (app/api/mcp.py, no SDK); this adds the
# OUTBOUND `MultiServerMCPClient` that connects to external MCP servers, lists
# their tools, and binds the allowed ones INTO the deepagents tool set (augment,
# never replace — INV-13). Human-verified LEGITIMATE at the package-legitimacy
# checkpoint (2026-06-10): official github.com/langchain-ai/langchain-mcp-adapters
# (LangChain org, author Vadym Barda); transitive `mcp` is the reference MCP SDK
# (github.com/modelcontextprotocol/python-sdk, Anthropic PBC) providing FastMCP/stdio
# for the offline stub fixture.
#
# VERSION-PIN DECISION — SUPERSEDED, kept for context. The original note here
# explained that `langchain-mcp-adapters` had to stay on 0.2.x and `mcp` on
# 1.27.2 because newer versions pulled starlette past `fastapi==0.115.6`'s
# `starlette<0.42` cap. That cap is GONE: fastapi is now 0.141.1
# (`starlette>=0.46.0`, no upper bound) and starlette is pinned at 1.3.1 above,
# so the starlette ceiling is no longer the binding constraint.
#
# `mcp` moves 1.27.2 -> 1.28.1, the fix for its advisory. It is deliberately NOT
# taken to the current 2.1.1, which switches its HTTP stack to `httpx2>=2.5.0` —
# a second, parallel HTTP client alongside the httpx the rest of this tree uses.
# That is a bigger change than a CVE fix warrants; 1.28.1 is the minimum that
# clears the advisory.
#
# `langchain-mcp-adapters` is now pinned EXACTLY at 0.2.2 rather than as
# `>=0.2.2,<0.3`. A floating range is not reproducible — the resolved version
# could differ between two builds of the same commit, which is the thing the rest
# of this file exists to prevent. 0.2.2 is the top of the 0.2 line and is what
# that range already resolved to, so this pin changes nothing at runtime.
#
# The `<0.3` half of the old constraint is no longer load-bearing (the starlette
# cap it protected against is gone), but 0.3.x is not required by any advisory,
# so moving to it is a behavioural change with no security payoff. Left for a
# deliberate upgrade rather than folded in here.
langchain-mcp-adapters==0.2.2
