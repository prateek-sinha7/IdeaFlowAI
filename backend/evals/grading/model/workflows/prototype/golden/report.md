# Golden Artifact Quality Report

Scored 2026-07-30 against the pinned stage rubrics. Every claim below is
machine-verified — nothing in this report is asserted from memory.

## Method — three verification layers per brief

1. **Structural gate** (deterministic): each artifact through its stage's full
   precheck — generic wrapper/section/forbidden checks plus the stage's
   `validate:` hook (nav↔section route matching, task-sequence integrity,
   verdict/findings parsing, static_check).
2. **Code track** (deterministic): `code_grader` over each `prototype.html`
   with headless render and the interaction sweep — static issues/warnings,
   console errors, uncaught exceptions, per-route nav activation, coverage,
   and clicked/typed controls. Score formula is the production one
   (100 minus flat penalties).
3. **Functional suite** (Playwright, beyond the harness): scripted assertions
   against the behaviours the briefs demand — distinct records per dynamic-route
   id, unknown-id fallbacks, combined filters + search, empty states, every
   state mutation and its cross-page propagation, inline validation errors,
   and zero console/page errors across the whole scripted session.

Judge-dimension ratings below are reference ratings against each rubric's
0–100 anchors (95 = "reference quality"), stated per dimension with the
evidence that supports them. A live judge's number will vary; the deterministic
columns will not.

## Process conformance — the goldens ARE the pipeline's baked-in structure

The prototype structure is not a template picked from anywhere: every
structural element traces to a contract the pipeline itself injects or
enforces, and a 23-rule audit (derived line-by-line from
`agents/guardrails/html-prototype.md`, `agents/prompts/prototype-build/AGENT.md`
and the validators) verifies each golden against them:

- **Guardrail rules** — single self-contained file, no external requests,
  semantic regions with `data-od-id`, SPA `<section data-page>` per route with
  `data-page` on sections ONLY, single `<style>` opening with the `:root`
  token block, no raw hex outside `:root`, no Tailwind default indigo/violet,
  inline `style=` only for dynamic JS values, single `<script>` with a central
  `store`, router scoped to `section[data-page]` (never bare `[data-page]`),
  nav anchors as `href="#/{id}" data-page-link class="nav-link"`, 220px
  surface sidebar with right border, no lorem/emoji-icons/generic rows.
- **Build-agent (Task 1 / blank-canvas) rules** — shared chrome + all
  sections present with exactly the first `is-active`, routes declaration
  covering every page id, ≥5-row realistic tables, every handler defined,
  DS tokens mapped to `:root` including fonts.
- **Validator rules** — the routes declaration parses via the production
  `route_table.parse_routes_table`, and every href in the document resolves
  through it (`resolve_route`), parametric `:id` routes included.

All four goldens: **conformant on every rule** (2026-07-30). The audit
initially caught four deviations — badge-tint hexes outside `:root` in all
four files (including both pre-existing goldens), a Tailwind indigo-700
accent (`#4338ca`) in property_ops, and static inline styles in
fleet/property — all fixed (tints hoisted to `:root` tokens, accent swapped
to `#3d47c2` in spec/tasks/html together, inline styles replaced with
classes) with zero gate or score regressions.

**One deliberate divergence, documented:** the goldens declare routes as the
array table (`{ pattern: 'trip/:id', page: 'trip-detail' }`) rather than the
AGENT.md router template's object map (`{ pageId: '#/pageId' }`). The object
map cannot express the parametric `:id` detail routes every one of these
briefs demands — exactly the failure the live agents exhibited — while the
array form is first-class in the production resolver
(`app/agents/route_table.py`, "B's fixed router"). Per this folder's README,
the goldens are the prompt-improvement target the build prompt should steer
toward, so they carry the fixed router, not the failing one.

**Contrast fixture:** `example.html` (in this folder, not a golden) is an
artifact from the inline-styled craft/template surface: `<button>` nav with a
`state` object and display toggles, no `data-page` sections, no hash router,
no `:root` tokens, ~379 inline styles. Run through the pipeline gates it
**fails both the build and validate prechecks** (zero `<section data-page>`
elements), its routes are unparseable to `route_table`, and its "100.0" code
score is vacuous — static_check and render_check found nothing they know how
to exercise (0 sections, 0 nav targets). It demonstrates precisely why the
goldens must follow the baked-in structure: an off-process file, however
polished, is rejected by the harness before grading.
