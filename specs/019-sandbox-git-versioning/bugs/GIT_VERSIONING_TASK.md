## 3. Migration recipe (per `AGENT.md`)

1. **Policy:** `prompt_policy: governance` if the frontmatter has a non-empty `guardrails`, `hooks` or `constitution`; otherwise `prompt_policy: body_only`. Never leave it unset.
2. **Reading guide:** a `## Sandbox Reading Guide` section directly after the frontmatter (the six `user_stories` prompts are the exemplar; `backend/agents/prompts/domain-analyst/AGENT.md` is the richest). Say which step of which workflow the agent is. Step 1: "your brief arrives in the task message; write `<durable artefact>` — later steps read it". Step ≥2: "nothing is pasted into your prompt; read what you need", then only the bullets that apply: `.agents/NN-<agent-id>.md` (step-ordered; read the previous step's file first; `-p{visit}` retry passes, `-t{task}` task passes); `.context/design/{design-system.md,craft.md,template/SKILL.md,template/example.html}` and `.context/selections.json` (agents that declared `injects` of template/design_system/craft); `.uploads/<file>` + `.uploads/<file>.txt` (agents that declared `uploaded_files`); `.context/summary.md`, `.context/logs.jsonl`, `.context/<output>` (workflows with `chains_from`); `PLANNER.md` (workflows with `planner: run`); the previous revision's files in the tree (revision workflows). End with: "Reading is your job — the engine no longer pastes these into your message."
3. **Injection-era text:** delete or reword every sentence that promises pasted content ("You will receive the ACTIVE TEMPLATE", "the design system below", "uploaded files context", "output from the previous agent is provided"). Keep every instruction about *what to produce* byte-for-byte; the rewrite touches only *where inputs come from*.
4. **Tools:** if the agent must read any file listed in its guide and its `AGENT.md` has `tools: []` (or none), confirm in `backend/agents/factory.py` how a read tool is bound (`read_files: true` on the workflow.yaml step, or a tool set) and make the smallest change that binds it. Journal what you found.
5. **Shared prompts** (`ppt-brief-analyst`, `ppt-composer`, `prototype-*`, `custom-agent`) move in the batch that lists them and are not touched again.
6. Keep `injects:` declarations in the frontmatter (they still drive the `.context/design/` files and `.uploads/` sidecars); only the pasting stops.

## 4. Live-run checks (the verifier's vocabulary)

- **C-msg:** for every `agent_input` event in the run log except the first agent's, `data.context_message` contains none of the markers; `data.system_prompt` is present.
- **C-commits:** `git log --oneline` in the family root has ≥ (1 initial + one per step boundary) commits; no commit touches `.agents/`, `.logs/`, `.uploads/`, `.context/`, `.git*` (`git show --stat` per commit), except `.chain/{summary.md,logs.jsonl,<output>}` in the finalizing commit.
- **C-tag(vN…):** `git tag` lists exactly the named tags; each points at a commit whose tree has the deliverable.
- **C-chain:** `git ls-tree -r --name-only <tag> .chain/` is exactly `summary.md`, `logs.jsonl`, `<output>`.
- **C-agents:** `.agents/01-<first>.md` … exist on disk in step order; `git ls-files .agents` is empty.
- **C-pill:** the UI version pill text equals the newest tag.
