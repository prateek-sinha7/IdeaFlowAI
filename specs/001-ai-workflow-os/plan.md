# Implementation Plan: IdeaFlowAI — Universal AI Workflow Orchestration Engine

**Branch**: `001-ai-workflow-os` | **Date**: 2026-05-29 | **Spec**: [spec.md](spec.md) | **Version**: 3.0

---

## Summary

Replace three bespoke execution runners with one universal Execution_Engine grounded in the GitHub Spec Kit methodology. Add a mandatory Deep_Planner_Agent that proactively infers hidden constraints before any domain agent runs. Introduce a persistent, versioned, lineage-tracked Artifact_Store replacing ephemeral summaries. Adopt typed Produces/Consumes contracts replacing `context_from` wiring. Deliver Spec_Kit_Agents as reusable runtime agents, declared Gates, declared Injection_Capability, a full Workflow State Machine, cross-session Constitution Memory, custom composable Workflows, revision intelligence, and an Agent Thinking tab.

## Implementation Phases

### Phase 1 — Foundation (zero behavior change)

**Goal**: Schema-debt resolved, new AGENT.md fields added, Artifact_Store scaffolded in-memory. All 14 pipelines work identically.

**Backend**:
1. Alembic migration `0009_schema_debt.py`: add `users.tier`, `users.is_admin`, `users.preferred_model`, `workflow_runs.token_usage`, `workflow_runs.model_id` with downgrades
2. `agents/loader.py`: add optional AGENT.md fields — `produces: list[str] = []`, `consumes: list[str] = []`, `gate: str | None = None`, `injects: list[str] = []` — all optional with defaults; existing AGENT.md files load unchanged
3. `agents/artifact_store/store.py`: in-memory `ArtifactStore` class with methods matching the contract in `contracts/artifact-store-api.md`: `store`, `retrieve_latest`, `retrieve_version`, `list_by_type`, `list_lineage`, `get_resume_event`, `set_questionnaire_responses`, `get_questionnaire_responses`; module-level singleton `get_artifact_store()`
4. `agents/execution_engine/resolver.py`: `WorkflowResolver` class with `validate(workflow_def)` method — validates DAG, detects cycles, reports unmatched types; stub only (does not yet gate execution)
5. `app/agents/orchestrator_v2.py`: extend `WorkflowState` with new optional fields (`session_id`, `pipeline_run_id`, `parent_run_id`, `execution_gate`, `execution_strategy`, `artifact_refs`); generate `pipeline_run_id = uuid4()` at `execute()` start; `session_id = user_id`. Also move `WorkflowState` and `TokenUsage` to a new shared `app/agents/types.py` module and update all imports — this prevents import errors when `orchestrator_v2.py` is deleted in Phase 2.

**Tests**: Unit tests for ArtifactStore round-trip, loader new fields backward compat, WorkflowResolver validation (satisfiable + unsatisfiable + cycle cases)

---

### Phase 2 — Universal Engine + Planning Gate

**Goal**: Single Execution_Engine replaces all three runners. Deep_Planner_Agent gates every pipeline. Clarify_Engine supports pause/resume. All 14 pipelines migrated to Workflow definitions.

**Backend**:
1. `agents/execution_engine/engine.py`: `ExecutionEngine.execute(agents: list[AgentSpec], user_message: str, websocket_send_fn, pipeline_run_id: str)` — single entry point. In Phase 2, `agents` is a `list[AgentSpec]` resolved at request time from `PIPELINE_AGENTS[pipeline_type]` (ephemeral — the `workflows` table for persisted definitions is Phase 3). Before running any agent, MUST call `WorkflowResolver.validate(agents)`; if `ValidationResult.satisfiable == False`, emit `workflow_validated` WS event with errors and halt without running any agent. Then runs Deep_Planner_Agent first, evaluates gate, invokes Clarify_Engine if CLARIFY_REQUIRED, then runs domain agents in topological order; emits all WS events.
2. `agents/execution_engine/clarify_engine.py`: `ClarifyEngine.run(pipeline_run_id, planning_context, websocket_send_fn)` — runs Clarify_Agent, emits `questionnaire_ready`, awaits `asyncio.Event`, retrieves responses, merges into planning_context; max 3 rounds; emits `clarification_limit_reached`
3. `agents/planner/tools.py`: implement `analyze_request`, `infer_constraints`, `assess_readiness`, `build_execution_plan`, `store_planning_context`, `retrieve_planning_context` as `@tool` functions
4. `agents/prompts/deep-planner/AGENT.md`: `agent_type: planner`, `tools: ["planning"]`, `max_iterations: 20`, `planning_required: false`; prompt: proactively infer constraints, produce Planning_Context JSON, issue gate verdict
5. `agents/prompts/{constitution,specify,clarify,research,plan,tasks,analyze}-agent/AGENT.md`: 7 Spec_Kit_Agent AGENT.md files with correct produces/consumes contracts and gate declarations
6. `agents/factory.py`: handle `gate` field (Human_Gate/Validation_Gate); handle `injects` field — compose system prompt with critical rules → design system → craft rules → template skill body → role prompt (byte-for-byte match to od_runner.py); deck agent conditional for design system. **Before deleting `od_runner.py` and `od_ppt_runner.py`, capture golden-reference system prompts for the prototype and deck agents using the current runners for a fixed set of test inputs (template, design system, brief, discovery). These golden references are stored as test fixtures and used to verify the `injects` implementation in `factory.py` produces byte-for-byte identical output.** In Phase 2, Constitution injection is a no-op placeholder (Workflow_Memory is Phase 3) — `_inject_constitution()` returns empty string until Phase 3 activates it.
7. All 76+ existing AGENT.md files: add `produces`/`consumes` contracts using the following mapping algorithm: for each agent with `context_from: [agent-ids]`, set `consumes` to the union of `produces` values of those named agents; for agents with `context_from: []`, set `consumes: []`; for agents with `context_from: ['$previous']`, set `consumes` to the `produces` of the immediately preceding agent in the pipeline. The `planning_context` type is exempt — do not add it to any `consumes` list (it is cross-cutting and supplied automatically).
8. `app/api/websocket.py`: replace `_handle_pipeline_execution`, `_handle_od_prototype_execution`, `_handle_od_ppt_execution` with single `_handle_workflow_execution` calling `ExecutionEngine.execute()`; add `submit_questionnaire` message handler; remove 15-second questionnaire timeout. Delete `_handle_questionnaire()` — the Clarify_Engine (invoked by the ExecutionEngine) replaces it entirely. The `generate_questions` WebSocket message type is retired; `questionnaire_ready` is the new event.
9. Delete `orchestrator_v2.py`, `od_runner.py`, `od_ppt_runner.py` after migration verified and golden-reference tests pass

**Frontend**:
1. `useWorkflow.ts`: handle `planner_start`, `planner_complete`, `gate_status`, `questionnaire_ready`, `questionnaire_complete` events; track `pipeline_run_id` from `planner_start`; add `submitQuestionnaire(pipeline_run_id, responses)` function
2. `DashboardLayout.tsx`: remove 15-second timeout; route `questionnaire_ready` to QuestionnairePanel

**Tests**: Unit tests for ExecutionEngine gate logic, ClarifyEngine pause/resume, all 14 pipeline types regression suite, Spec_Kit_Agent AGENT.md contract validation

### Phase 3 — Artifact_Store, State Machine, Thinking Tab, Lineage

**Goal**: DB-backed Artifact_Store, full State_Machine, backend-restart resumability, Workflow_Memory, planning_context system prompt injection, Thinking tab, Visual Dependency Graph, revision intelligence, custom Workflow UI.

**Backend**:
1. Alembic migrations `0010_artifact_store.py`, `0011_workflow_tables.py`, `0012_workflow_run_extended.py`: create `workflow_artifacts`, `workflow_clarifications`, `workflow_memory`, `workflows` tables; add `parent_run_id`, `status` (extended), `session_id`, `pipeline_run_id`, `execution_gate`, `execution_strategy` to `workflow_runs`
2. `app/models/artifact.py`, `workflow_clarification.py`, `workflow_memory.py`, `workflow_definition.py`: SQLAlchemy models
3. `agents/artifact_store/store.py`: migrate from in-memory to DB-backed; public interface unchanged
4. `agents/workflow_memory/memory.py`: per-user key/value store; `get_constitution(user_id)`, `set_constitution(user_id, content)`, `get_entry(user_id, key)`, `set_entry(user_id, key, value)`
5. `agents/execution_engine/state_machine.py`: `StateMachine.transition(run_id, new_state)` — in Phase 2, persists to in-memory dict (created in Phase 2 alongside `engine.py`); Phase 3 upgrades the write target to DB. Handles all 10 lifecycle states. Persists before returning so that a crash mid-transition leaves the run in the new state (safer failure mode).
6. `agents/execution_engine/engine.py`: inject `planning_context` into system prompt (standard pipelines) or user message (`od_prototype`/`od_ppt`); emit `agent_input` WS event per agent; write agent outputs to Artifact_Store; build lineage via `derived_from_artifact_id`; restore WorkflowRun from DB on startup via `ExecutionEngine.restore_non_terminal_runs()` called from a FastAPI `@app.on_event('startup')` handler in `backend/app/main.py` — scans `workflow_runs` for non-terminal states and re-registers their asyncio.Events in the ArtifactStore
7. `agents/factory.py`: `_inject_planning_context(planning_context, pipeline_type)` — system prompt for standard, user message for od pipelines
8. `app/api/websocket.py`: read `source_workflow_run_id` from `run_pipeline` message; set `WorkflowRun.parent_run_id`; persist `session_id` and `pipeline_run_id` to DB
9. Revision intelligence: `ExecutionEngine._handle_revision(parent_run_id, target_artifact_type, instruction)` — retrieves original Artifact, version history, and instruction as three separate structured inputs; stores result as new Artifact version. Triggered by a new `run_revision` WebSocket message type: `{type: 'run_revision', parent_run_id, target_artifact_type, instruction}`. The WebSocket handler calls `ExecutionEngine._handle_revision()`. The frontend sends this from the existing revision buttons in `DashboardLayout.tsx` (replacing the current `=== EXISTING ... ===` text injection pattern).

**Frontend**:
1. `types/index.ts`: add `AgentRunState.inputPrompt`, `AgentRunState.contextSources`, `AgentRunState.toolCalls`, `AgentRunState.thinkingText`; add `ContextSource`, `ToolCallEntry` interfaces; add `WorkflowDefinition` interface; add `dagEdges: DagEdge[]` and `unresolvedEdges: UnresolvedEdge[]` to `PipelineRunState`
2. `useWorkflow.ts`: handle `agent_input` event; accumulate `tool_call`/`tool_result` into `toolCalls`; capture `agent_thinking` into `thinkingText`; handle `workflow_validated` event — store `dag_edges` and `unresolved_edges` in `pipelineState.dagEdges` and `pipelineState.unresolvedEdges`
3. `AgentThinkingTab.tsx`: per-agent cards with thinking text, tool calls, input prompt, context sources; auto-expands running agent; renders within 1s
4. `PreviewPanel.tsx`: add Thinking tab (third tab); pass `pipelineState.agents` to `AgentThinkingTab`
5. `WorkflowHistory.tsx`: add Thinking tab to detail view; extend `detailTab` state type to `"preview" | "files" | "thinking"`; map `agentOutputs` to `AgentRunState[]`
6. `DependencyGraph.tsx`: render DAG nodes and edges from `pipelineState.dagEdges`; unsatisfied edges (from `pipelineState.unresolvedEdges`) visually distinct from satisfied edges
7. `workflowChaining.ts`: add `CHAIN_SOURCE_RUN_ID_KEY`; wizard pages pass `source_workflow_run_id`

**Tests**: Alembic migration tests, Artifact_Store DB round-trip, StateMachine persistence, backend-restart resumability, Thinking tab renders within 1s, revision section-level targeting, lineage graph integrity
